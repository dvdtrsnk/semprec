# Value-link relation mutations use nonblocking admission and scoped lock waits

## Context

[[2026-09-10-single-writer-ownership-model]] permits the declared `valueLinks` handoff to a user-owned property only while its link is active. [[2026-11-01-value-link-item-updates-lock-item-before-handoff]] repairs an isolated item/link cycle and explicitly leaves relation ordering open. This decision extends relation handoff without changing that item protocol or either historical ADR body.

Three supported production-call schedules were reproduced under tenant-scoped non-bypass runtime roles: link SHARE versus the seeded Inbox type hook's source row; link SHARE versus a paired Files/Projects definition advisory; and link SHARE versus a populated rollup job key. Both orders of the first two produced `40P01`. In the third, a user item update held a real keyed enqueue and then deleted another edge, waiting to break its link; the system relation held that link and waited in `graphile_worker.add_job`. PostgreSQL reported opposing transaction ShareLock waits. These are bounded measurements, not universal claims about locks or every caller.

A source-first blocking order conflicts with proposals that already hold definition/edge locks; a definition-first blocking order conflicts with source-first callers. Late link NOWAIT alone does not protect a blocking prefix. Named admission alone does not address the measured later queue wait. A global mutex, private Graphile lock manipulation, checking authorization after mutation and automatic partial retries are rejected. A short PostgreSQL lock-wait limit accepts explicit contention refusal rather than promising all otherwise valid operations succeed concurrently.

## Decision

### Protected calls and authorization

Apply this protocol only to actual create, metadata update and delete calls with `context.ownerProcess = "valueLinks"` against a caller-side `owner: "user"` relation property. Ordinary writers, other system properties/processes, item handoff and unrelated transaction work keep their existing contracts. Do not create a link, implement future gh-1593 or change isolation levels.

1. Read-only context discovery may identify the protected case. Before its early handoff prediction, hooks or admission, require a client owned by the current active `withTransaction` invocation. Fail closed with a fixed internal diagnostic on an unmanaged client. Existing ordinary supplied-client calls are unaffected; no public barrel export is needed for this ownership machinery. Preserve context, archive and property-owner checks in their existing relative order. At the former handoff position make an RLS-scoped **nonlocking prediction** of an active caller-side link. Missing, broken and tenant-invisible links remain indistinguishable `403 owner_violation`. This prediction does not authorize mutation. A concurrently uncommitted new active link may be refused rather than waited for.
2. Preserve create/update endpoint checks before admission; delete still permits missing/trashed endpoints.
3. Before taking a handoff lease, run the applicable existing domain validation/hooks with nonblocking acquisition of their exact item/source row locks. Reuse the domain-owned predicates, row modes and missing/deleted behavior; do not interpret zero rows as busy or prelock arbitrary endpoints. Inbox type write/delete reserves its source (`delete` permits Trash; proposed nil stays special). Transcript speakers validates metadata before attempting its transcript row lock. Library rating validation keeps its existing reads. The choke point must not acquire new domain imports. Hooks must run once, with their validations retained; these current hooks only read, validate and lock. A future side-effecting or locking hook requires renewed protocol review.
4. Before an INSERT, including ON CONFLICT replay, try the exact transaction advisory used by the cardinality trigger/proposal: `pg_try_advisory_xact_lock(hashtextextended(definition_id::text, 0))`. False is busy, with no blocking acquisition. Reserve an existing exact normalized edge with `FOR UPDATE NOWAIT` before create/replay, update or delete. Absence retains the original later DML outcome. Do not add definition locks to ordinary callers or metadata/delete paths that do not insert. Own previously held locks must be reentrant.
5. After these admissions, capture the same connection's effective `lock_timeout` and install transaction-local `1ms`. The owned protected body starts with the authoritative active caller-side `FOR SHARE NOWAIT` and includes all remaining actual mutation, triggers/constraints, link handling and transactional rollup enqueue. No row at the authoritative check is still 403. Do not leave an unprotected gap before the last queue statement. The lease and admitted row/advisory locks remain until transaction end.
6. Keep original DML, normalized A/B behavior and after-commit effects: only actual user/agent edge insert/delete breaks the applicable links, the first breaker remains recorded, metadata/replay/absent delete does not break links, and SYSTEM writes leave them on. Preserve cardinality enforcement and current missing-edge update 404. No new relation replacement feature is introduced.

`assertRelationCreatableWithClient` uses nonlocking handoff prediction, never a link SHARE lease; it is not a concurrency-equivalent promise of later success. Its ordinary hook validation remains, and the actual mutation always repeats authoritative checks. The distinct proposed-target/nil validator retains its existing behavior. Read-only predictions are not protected mutations and do not acquire this timeout or require a managed mutation owner.

### Busy errors, settings and transaction ownership

- Use a dedicated `ChokePointError` subclass with status **409**, code **`value_link_busy`**, fixed message **`Value-link relation is busy`**, and no dynamic details. Do not reuse `ConflictError`'s `version_conflict`. A false try-advisory and an actual `pg.DatabaseError` with SQLSTATE `55P03` from the owned NOWAIT admissions or protected body select this error. Inspect the typed driver error; an arbitrary thrown object with a `code` field is not sufficient.
- Within the narrowly owned body, this maps **any actual PostgreSQL 55P03**, not a claim that each one came from the timer. Audit callees for other intentional uses. `40P01`, `57014`, constraints, setup/restoration failures, hook failures and unknown errors retain their original identity/meaning. Do not parse message text or map a broad surrounding transaction. An earlier permission/endpoint/metadata error wins; busy admission can precede later edge-not-found or cardinality results. Busy is neither an authorization result nor evidence about another tenant.
- Set the GUC with parameterized transaction-local configuration, never session SET. On success, including replay/absent-delete returns, restore the exact captured effective setting, including `0` or an outer custom value, before returning. Nested protected calls restore their own captured value in stack order; no nested code may silently disable the budget. Setup/restoration failure is not success. On failure do not run restoration SQL against a potentially failed transaction: the owner must roll back. This is not a finally block that can replace the original failure.
- `db/pool.ts` owns an invocation-scoped rollback-only marker. Any dedicated busy, including a false try-advisory that did not abort PostgreSQL, marks the active owner; all failures after installing the local setting also mark it so a caught error cannot leak the setting or prior work. A first recorded failure is retained by identity. Before sending COMMIT after a fulfilled callback, `withTransaction` checks the marker and instead rejects/rolls back and discards callbacks. The marker survives an SQL savepoint rollback; no savepoint/partial retry may clear it. Active/rollback state is removed on every exit/release so the next borrower is clean.
- Error precedence is explicit: if the callback later throws an unrelated error, that escaping error stays primary and propagates unchanged through rollback. If it returns after catching one or more recorded errors, the first recorded error prevents commit and is rethrown. Rollback/release failure must preserve the primary failure and discard a broken connection under the existing policy. Audit all supplied-client production owners; do not assume that throwing alone rolls back earlier proposal writes. A caught-busy followed by attempted owner commit, including a rollback-to-savepoint case, must not commit earlier state, jobs or callbacks.
- Raw COMMIT inside a managed callback, hand-rolled ownership, another connection and external effects cannot be constrained by a JavaScript marker and are outside the sanctioned transaction API. Protected calls on unmanaged clients fail before protected work. No internal retry is added. An explicit caller retry is a fresh complete transaction after rollback.

### Scope and limits

The 1ms value limits **each PostgreSQL lock acquisition wait** while installed; it is not an end-to-end deadline, a CPU/IO/network/pool bound, fairness guarantee or universal deadlock prevention. Brief harmless contention can now cause 409 and sustained contention can starve callers. Record this availability trade-off rather than silently increasing the value. A deadlock detected elsewhere or first remains an unmapped `40P01`.

Work before admission or after restoration can still block while an outer transaction retains earlier leases and other locks. This decision does not establish a global hierarchy or whole-transaction deadlock freedom. The admitted operations must fix the three reproduced schedules, including queue waiting, and supported pre-held proposal/source/edge compositions. Any newly confirmed in-scope remaining cycle is another design decision, never an implied waiver. Future link producers must honor both the item-before-link insertion rule and a separately reviewed complete relation composition.

## Verification and consequences

Permanent real runtime-role tests must replace the deadlock-expecting diagnostics with the selected commit/403/busy outcomes, exact operation PIDs, observed blockers where waiting is intended, bounded settlement and owned cleanup. Cover both measured source/advisory orders and the populated-rollup cycle, source/definition/edge/final-link contention, both normalized A/B sides, replay/ON CONFLICT, update/delete, concurrent insert/update/delete, rollback release, hook validation and pre-held proposal locks. Verify state, first-break identity, jobs and exactly committed invalidations; refusal rolls back the complete operation, including prior steps.

Test missing/broken/foreign prediction, a concurrent breaker before the final lease, normal/trashed/missing/delete/nil behavior, cardinality and missing-edge precedence, all registered hook modes, active admission success and unrelated tenant/item progress. Preserve ordinary writer behavior and the existing item/transform authorization tests.

Test effective setting 0/custom, success/no-op restoration, nesting, post-error whole rollback and next borrower cleanliness; typed 55P03 versus arbitrary objects, unchanged 40P01/57014/unknown/setup/restore errors, false advisory, caught errors, savepoint recovery and primary-versus-cleanup precedence. Test the managed-owner marker lifecycle and unmanaged refusal through actual transaction boundaries. Use public queue APIs for queue contention; no production dependence on private Graphile tables. Source review, named execution evidence and complete final gates remain required; this decision alone accepts no batch.
