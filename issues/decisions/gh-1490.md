# gh-1490 decision

## Question

Can the synchronous item-read registry select the owner from ItemRow, and can the synchronous error adapter resolve that owner without a client or pool?

## Options considered

- Approve unchanged: rejected. ItemRow has only databaseId; ownerModuleId belongs to DatabaseRow. toErrorResponseBody has neither a client nor a pool.
- Pass the owner explicitly, resolve ownership in a shared batch helper on the existing tenant-scoped client, and project the conflict in the public update wrapper: selected. itemsStore raises the version conflict in JavaScript after a successful locked read, so the callback can still resolve ownership before withTransaction rolls back.
- Add ownership to ItemRow, make the transport adapter perform database reads, or cache database ownership globally: unnecessary scope and coupling; a global ownership cache also bypasses transaction-local tenant resolution.

## Decision

DEFECT — approve after the minimal specification correction below; no Task implementation.

The sole blocker gh-1436 is closed in the repository issue list, and its handover was read. No external precondition or protected-path change is needed. The correction preserves the per-process registry and composition point (2026-09-30 choke-point domain hooks), shared helper ownership (2026-09-24 choke-point composition), neutral transport boundary (2026-09-17 generic application port), additive REST error envelope (2026-09-11), single-writer ownership (2026-09-10), and tenant-scoped RLS (2026-10-03 and 2026-10-05). No accepted ADR is contradicted or changed.
