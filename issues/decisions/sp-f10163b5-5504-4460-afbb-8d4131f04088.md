# Decision: editing times of an Event with its own time zone

- Question: The synced-event-times issue (sp-c659fbbb-bb9a-4a8e-a463-7daada4fc91a) stores Event times in the Event's own `timeZone` but clients show and send tenant wall-clock times, so a user's edit of a zoned Event would move it. Convert the input, or clear `timeZone`?
- Options considered: (a) convert the edited values from the tenant zone to the Event's zone in the Events pre-write transform; (b) clear `timeZone` on a user edit, which makes users a second writer of a `calendarSync`-owned field and changes the Event's zone at the provider.
- Decision: (a). The Event keeps its zone and its instant; only the sync writes `timeZone`.
- Spec change (sp-f10163b5-5504-4460-afbb-8d4131f04088, Task): added item 6 "A user's or agent's edit of `date`, `endDate`, `timeFrom` or `timeTo` on an Event with a `timeZone` is read in the tenant's time zone and converted to the Event's zone in the Events pre-write transform before it is stored, so the Event keeps its zone and does not move; `calendarSync` writes are stored as sent."; renumbered the docs item to 7; added the acceptance criterion "Editing an Event stored at 09:00 America/New_York to 16:00 from a Europe/Prague tenant stores 10:00 America/New_York."
