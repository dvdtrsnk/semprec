# Decision: gh-1422 (per-module pre-write property transform at the choke point)

## Question

The implementation proposal gh-1422 (a per-process registry of pre-write
property transforms, one or more per owning module, with the Tasks `time`
derivation moved out of `itemWrites.ts` into a registered transform) is open
without `spec:approved`. Approve it, or make the minimal correction that makes
it approvable.

## Options considered

- Approve unchanged (SOUND): rejected, for four defects against the
  integration tip.
  1. Task item 4 required that a `system` key a transform adds has an
     `ownerProcess` equal to the transform's `moduleId`. Tasks `time` is
     seeded (`backend/packages/data/src/seed/seedTenDatabases.ts`) as
     `owner: "system", locked: true` with no `ownerProcess`, so the column is
     `null`; `ownerProcess` is a process name everywhere it is set
     (`TRANSCRIPTION_OWNER_PROCESS = "transcribe"`,
     `VALUE_LINKS_OWNER_PROCESS = "valueLinks"`), never a module id, and seven
     seeded system properties (Tasks `time` and Events `time` among them)
     declare none. The Tasks transform of item 5 would therefore have ended
     every Tasks create and every Tasks update touching `timeFrom`/`timeTo` in
     `403 owner_violation`, and `__tests__/tasksTime.test.ts` would have
     failed instead of passing unchanged.
  2. Task item 6 and the last Touches line required editing the `tasks/`
     paragraph in the body of
     `docs/adr/2026-09-30-choke-point-domain-hooks-through-a-per-process-registry.md`,
     an accepted ADR. `issues/README.md` (section "Autonomy": accepted ADR
     bodies are never edited), `docs/adr/README.md` (section "Superseding a
     decision") and `review-rules/rules.md` (editing an accepted ADR's body is
     a high-severity finding) forbid that, and `adr-conventions` states that
     even a narrow amendment counts as an edit.
  3. Task item 3 listed `triggerOnItemEventHeartbeats` among the functions
     that receive the transformed patch; its signature
     (`backend/packages/data/src/scheduler/schedulerStore.ts`) takes
     `(client, databaseId, event, itemId, queueAffinity)` and no patch.
  4. The Context's fourth decision includes `writerKind` in the transform
     context "if it is already on the item write options when this lands
     (#1415)"; #1415 is closed (`af1ea069`) and `writer: WriterIdentity` is on
     `CreateItemWithClientOptions`, `UpdateItemWithClientOptions` and both hook
     contexts, while #1415's own spec deferred the transform context to this
     issue. The Out-of-scope line "The writer kind in the transform context:
     #1415" therefore contradicted the resolved condition and left the field
     with no owning issue.
- Set `ownerProcess: TASKS_MODULE_ID` on the seeded Tasks `time` property
  instead of relaxing item 4: rejected. It adds a seed change and a data
  migration of existing `properties` rows (the issue's Out of scope excludes
  the data migration of stored Tasks values), widens Touches, and still
  leaves Events `time` (needed by #1598) undeclared.
- Drop the `ownerProcess` check on added keys entirely: rejected. The third
  acceptance criterion (a transform adding a `system` key of another
  `ownerProcess` ends in `403 owner_violation`) would become untestable and
  the single-writer ownership model
  (`docs/adr/2026-09-10-single-writer-ownership-model.md`) would lose its
  check at the new write seam.
- Write the superseding ADR now (ADR CONFLICT): rejected. No accepted ADR
  forbids the registry; the new ADR records the pattern the implementation
  introduces and belongs to the implementation PR per `adr-conventions`. A
  decision agent never implements the Task.
- Minimal spec correction (DEFECT): chosen. Item 4 allows a `null`
  `ownerProcess` (the database's owning module is the single writer of its
  undeclared derived keys, as it was for the inline derivation the superseded
  ADR records) and keeps a declared process a violation; item 6 and the
  Touches line call for a new ADR with
  `supersedes: [2026-09-19-derived-system-properties-computed-inline-at-choke-point]`,
  a frontmatter-only change on that ADR, and a cross-reference to the
  per-process-registry ADR whose body and frontmatter stay untouched; item 3
  no longer names `triggerOnItemEventHeartbeats` as a patch receiver; item 1
  carries `writer` in the context and the Out-of-scope line names what is
  still excluded (reading `writer` for a rule).

Checks run on the integration tip (a8bcf732): Blocked-by #1402 and #1415 are
both closed (`completed`). `createItemWithClient`, `updateItemWithClient`,
`assertWritableProperties`, the `TASKS_MODULE_ID` / `deriveTaskTime` imports
and both inline Tasks branches exist in
`backend/packages/data/src/chokePoint/itemWrites.ts` as the Context describes
(the update branch locks only when `timeFrom` or `timeTo` is in the patch);
`chokePoint/hooks.ts` holds the create, update, edge write and edge delete
registries, `clearHooksForTests` and `writer: WriterIdentity` on the hook
contexts; `domainWriteHooks.ts` is the registration point;
`itemsStore.lockItemById(client, databaseId, itemId)` returns `ItemRow | null`
and `insertItemWithReplay` reports `created: false` on a replay;
`deriveTaskTime(timeFrom, timeTo)` exists in
`backend/packages/data/src/tasks/deriveTaskTime.ts` and
`tasks/tasksItemPreWriteTransform.ts` does not yet exist (new);
`ForbiddenError(message, details, code)` yields status 403 and
`ValidationError` status 400 with code `validation_failed`
(`backend/packages/data/src/errors.ts`); `EVENTS_MODULE_ID = "events"` and
`TASKS_MODULE_ID = "tasks"` exist in `seed/tenDatabaseKeys.ts`;
`backend/packages/data/src/index.ts` does not export `chokePoint/hooks.ts`,
so the conditional Touches line resolves to no barrel change;
`chokePoint/__tests__/hooks.unit.test.ts`, `__tests__/tasksTime.test.ts` and
`__tests__/deriveTaskTime.unit.test.ts` exist (vitest, `createChokePoint`,
`seedSystem`, `getTestPool`, `resetDatabase`), and
`__tests__/itemPreWriteTransform.test.ts` is new; the two ADRs named in the
Task exist and are `accepted`, and
`docs/adr/2026-10-09-item-create-domain-hooks.md` is the precedent for
extending the registry ADR by cross-reference without editing it. No
protected path is touched. `node .github/scripts/issues.mjs validate`
reports zero errors.

## Decision

DEFECT: relax the ownership rule on transform-added keys to accept a `null`
`ownerProcess`, replace the edit of the accepted per-process-registry ADR
with a cross-reference from the new superseding ADR, drop the heartbeat
trigger from the patch receivers, and carry `writer` in the transform
context. Approved and queued.
