# Decision: let a removed password account be added again and sign in again in place

- Question: After the cutover the carried iCloud and generic mail accounts have no credential, show a generic sync error and cannot sign in again; removing and adding them again fails with 409 because the duplicate rule counts trashed mailboxes. Options: only drop trashed mailboxes from the duplicate rule, or also add a route that replaces the password of the existing account and classify a missing credential as reauthorization.
- Decision: both. The duplicate rule counts live mailboxes only, a restore that would duplicate a live mailbox's address is refused, `PUT /api/mail/mailboxes/:id/password` replaces the password on the existing account (mail, folders and threads stay), and a missing credential is a reauthorization case that the sweep and the IMAP IDLE discovery stop retrying until the credential is replaced. This keeps the owner's decision of 2026-11-20 to carry production data with the epic's features working.
