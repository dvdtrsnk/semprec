# Decision: gh-1601 (item delete and restore hooks at the choke point)

## Question

The implementation proposal gh-1601 (`[choke-point-hooks 04/04]`: add an item
delete hook and an item restore hook to `chokePoint/hooks.ts`, call them from
the trash and restore cascades in `chokePoint/itemTrash.ts` inside the same
transaction, narrow the `chokepoint-knows-no-domain` exemption of
`itemTrash.ts`, and record the decision in an ADR) is open without
`spec:approved`. Approve it, or make the minimal correction that makes it
approvable.

## Options considered

- Approve unchanged (SOUND): rejected, for three reasons.
  1. Task item 4 and the last Touches line required amending the
     `itemTrash.ts` exception paragraph of
     `docs/adr/2026-09-30-choke-point-domain-hooks-through-a-per-process-registry.md`,
     an accepted ADR. `issues/README.md` (section "Autonomy": accepted ADR
     bodies are never edited), `docs/adr/README.md`, `review-rules/rules.md`
     (editing an accepted ADR's body is a high-severity finding) and
     `adr-conventions` (a narrowing or carve-out is a new standalone ADR that
     references the old one by `[[slug]]`; even a narrow correction counts as
     an edit) forbid that, so the implementation would have been blocked in
     review. The sibling gh-1422 (02/04) already carries the same correction
     in its Touches ("cross-referenced, not edited").
  2. Task item 3 told the implementer to keep `itemTrash.ts` exempt "only for
     the blobs/docs/library cascade imports it still needs". On the
     integration tip `itemTrash.ts` imports six modules from folders the
     rule lists: `blobs/blobsStore`, `docs/docsStore`,
     `inbox/inboxAttachmentsStore`, `inbox/itemOriginsStore`,
     `library/itemAutomationStore` and
     `transcription/transcriptionComputedKeys` (`inbox/` and
     `transcription/` are in the rule's `to.path`; `tasks/` and
     `scheduler/`/`rollup/` are not). A rule written to the spec's list would
     fail on the `inbox` and `transcription` imports, so the acceptance
     criterion "dependency-cruiser validation passes" could not be met as
     written.
  3. The Blocked-by line named only #1599 (a `domainWriteHooks.ts` overlap),
     while the Context states that "the three hook issues share `hooks.ts`
     and `domainWriteHooks.ts`, so they land in order" and that this issue
     builds on #1530. gh-1422 (02/04) and gh-1530 (03/04) are both open,
     approved and queued, and both list `chokePoint/hooks.ts`,
     `domainWriteHooks.ts`, `index.ts` and
     `chokePoint/__tests__/hooks.unit.test.ts` in their Touches, the same
     files this issue edits. `.github/ISSUE_FORMAT.md` requires a shared-file
     overlap that cannot be split to be a `Blocked by:` entry; without it
     Relay may dispatch gh-1601 concurrently with either and the registries
     collide in `hooks.ts`.
- Write a new ADR now (ADR CONFLICT): rejected. The 2026-09-30 ADR does not
  forbid a delete or restore registry; it records that the cascade was
  "deliberately left without a hook" and the 2026-10-09 create-hook ADR is the
  precedent for adding a registry through a standalone ADR with
  `supersedes: []`. Task item 4 already asks the implementation to write the
  ADR in the same PR; a decision agent never implements the Task, so the ADR
  belongs to the implementation.
- Rename the context members `writerKind, agentRunId?, actingUserId?` to the
  `writer: WriterIdentity` shape the existing hook contexts use: rejected. The
  approved sibling gh-1530 uses the identical wording ("`writerKind` and the
  agent fields come from the shape introduced by #1415"); the `writer?:
  WriterIdentity` option exists on both trash entry points on the tip, and
  the implementer of 03/04 fixes the representation this issue then follows.
  Not a defect against the tip.
- Minimal spec correction (DEFECT): chosen. Add #1422 and #1530 to Blocked-by,
  name the six imports the exemption must keep and the `pnpm
  check:boundaries` script, and replace the amendment of the accepted ADR
  with a standalone ADR that narrows its `itemTrash.ts` exception by
  cross-reference.

## Decision

imports the `itemTrash.ts` exemption must keep, and replace the amendment of
the accepted 2026-09-30 ADR with a standalone ADR that narrows it by
cross-reference. Approved and queued.
