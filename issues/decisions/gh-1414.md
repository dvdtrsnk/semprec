# Decision: gh-1414 (per-tenant context for module data migration converters)

## Question

The implementation proposal gh-1414 (pass a per-tenant context
`{ timezone, itemId, log }` to module data migration converters) is open
without `spec:approved`. Approve it, or make the minimal correction that makes
it approvable.

## Options considered

- Approve unchanged (SOUND): rejected. Task item 4 and the fourth Touches line
  required adding a "context" section to the body of
  `docs/adr/2026-09-28-two-pass-skip-locked-module-data-migration.md`, an
  accepted ADR. `issues/README.md` (section "Autonomy": accepted ADR bodies are
  never edited), `docs/adr/README.md` (section "Superseding a decision") and
  `review-rules/rules.md` (editing an accepted ADR's body is a high-severity
  finding) all forbid that, and `adr-conventions` states that even a narrow
  addition counts as an edit, so the implementation would have been blocked in
  review.
- Write a new ADR now that supersedes the two-pass ADR (ADR CONFLICT):
  rejected. The two-pass ADR does not forbid the context; its decision
  (two row-locked passes over idempotent converters) stays intact and is not
  superseded. The context is an extension of the mechanism that ADR
  introduced, which `adr-conventions` records as a new standalone ADR that
  cross-references the old one, written in the same PR as the pattern. A
  decision agent never implements the Task, so the ADR belongs to the
  implementation, not to this decision.
- Document the context only on the converter type's doc comment (DEFECT, no
  ADR): rejected. The context shape, the once-per-tenant time-zone load and
  the rule that `log` never carries a property value are a contract every
  future converter (#1797 first) follows; a contract recorded only in a code
  comment is the repository's most repeated review finding.
- Minimal spec correction (DEFECT): chosen. Task item 4 and the Touches line
  now call for a new standalone ADR that references
  `[[2026-09-28-two-pass-skip-locked-module-data-migration]]`, states what the
  extension adds and leaves the accepted ADR's body and frontmatter untouched.
