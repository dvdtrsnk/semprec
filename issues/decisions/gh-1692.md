# Decision: gh-1692 (Tasks of a mail thread)

## Question

The acceptance receipt of gh-1692 asked two product questions: a task without a status sorts among the done tasks, and a trashed project or person is left out of a task.

## Decision

A task always has a status, so a task without one must not occur and no read sorts it specially. A trashed project or person is not left out: it is replaced by a marker alone that says the original object was deleted, without its name.

## Consequence

The change needs code, so it is a new source (the task status guard and cutover, and the marker in the thread detail). gh-1692 itself stays completed as delivered.
