# Decision: gh-1550 (host IMAP IDLE lifecycles by sync mode)

## Question

The implementation of gh-1550 (`[mail-accounts 16/30]`: replace the noop
lifecycle factory in `serve.ts` with a dispatcher by sync mode and host the
IMAP IDLE lifecycle in the api process) was refused as BLOCKED on the
integration tip 6a1b6470: Task item 2 cannot be implemented as written, and
the Touches list is incomplete for items 1 and 2. Resolve the refusal so the
implementation can be retried once on a corrected specification.

## Options considered

- Approve unchanged (SOUND): rejected. The refusal is correct. Task item 2
  says `createClient` "opens the connection with the address-checked factory
  and the stored settings, applying `maxIdleTime` and `socketTimeout`".
  `createImapFlowIdleTransport(createClient)`
  (`backend/packages/data/src/mail/imapIdleClient.ts`) types `createClient`
  as `CreateIdleTunedImapFlowClient = (mailboxItemId, credential, idleOptions)
  => Promise<ImapFlow>`, a raw client the transport then connects itself
  (`await client.connect()` in `resolveFolders` and `connect`) and listens to
  (`exists`, `expunge`, `flags`, `error`, `close`). The address-checked
  factory `openImapConnection` (`mail/mailServerConnections.ts`) connects
  before returning, returns `ImapFlowMailClient` whose `ImapFlow` is
  `private readonly client` (`mail/imapFlowClient.ts`), passes no
  `maxIdleTime` or `socketTimeout` to `new ImapFlow({...})` and has no
  option for them. imapflow 1.7.6 reads both at construction
  (`this.options.maxIdleTime`, `this.options.socketTimeout`), so a caller
  cannot set them on a client it receives. In addition, nothing item 2 needs
  is reachable from the api service: `backend/packages/data/src/index.ts`
  exports neither `getDecryptedCredential`, nor
  `createBoundedImapIdleLifecycleFactory`, `createImapFlowIdleTransport`,
  `ImapIdleFlowOptions`, `imapConnectionLimitForProvider` or
  `sharedImapConnectionLimiter`, and the package's `exports` map allows no
  deep import. None of these files was in Touches.
- Let the composition root build its own `new ImapFlow(...)` with the policy
  lookup: rejected. `docs/adr/2026-10-29-mail-connections-through-the-outbound-address-policy.md`
  (accepted) decides that a connection to a tenant-chosen IMAP host is opened
  only through `openImapConnection()`; a third client would skip the
  `MailServerUnreachableError` mapping and the logging rules, and
  `createPolicyLookup` is not exported from the data package on purpose.
- Run IDLE over the sync wrapper (`ImapFlowMailClient` gains IDLE events and
  `waitForEnd`, the transport is rewritten against it): rejected. It puts
  IDLE plumbing on a class whose contract is one reconcile pass and rewrites a
  tested transport for no gain; the sync wrapper still exposes no IDLE
  options.
- Expose the raw client from `ImapFlowMailClient`: rejected. The wrapper
  exists so the reconcile pass sees a narrow surface.
- Split the connect step out of `openImapConnection` as the exported
  `openImapFlow()` (returns the connected `ImapFlow`, takes optional
  `maxIdleTime` and `socketTimeout`), make `openImapConnection` wrap it, and
  change `CreateIdleTunedImapFlowClient` to return a connected client that
  the transport never connects: chosen. It keeps one connect path, one
  mapping and one logging rule. Because the accepted ADR's letter names two
  factories only, this is a narrowing of that decision and needs a new ADR
  (option c, ADR CONFLICT), written standalone and cross-referencing the
  accepted one, whose body is not edited. The spec corrections (Context, Task
  items 1, 2 and 4, Touches, one acceptance criterion) are the minimal
  defect fixes that make the Task implementable and its Touches complete.

Checks run on the integration tip (6a1b6470): Blocked-by #1510 is closed
(`spec:approved`); #1473 and #1478, which the Context relies on, are closed.
`createMailLiveSyncRoot`, `createNoopMailLiveSyncLifecycleFactory`,
`MailLiveSyncAccount { mailboxItemId; syncMode }` and
`MailLiveSyncLifecycleFactory` exist in `mail/mailLiveSyncRoot.ts` and are

as the default limiter and the capped reconnect backoff; `onError` receives
the raw error from the connection's `waitForEnd()`, so the spec now tells
the implementation to log name and code only (the mail connections ADR keeps
the resolved address out of logs). `getDecryptedCredential(client, {
itemId, actorType, actorId?, purpose })` with a free-form `purpose` exists in
`credentials/externalCredentialsStore.ts`; `mailSyncJob.ts` passes `pool`

that. `imapConnectionLimitForProvider(provider, configuredLimit)` exists in

mailboxItemId)` returns `{ username, imap: MailServerEndpoint | null, ... }
| null`, and `mailSyncAdapters.ts` is the precedent for the configuration

`createNoopMailLiveSyncLifecycleFactory(pool)`; `shutdown.ts` stops
`mailLiveSync` before `queueRuntime` and `pool.end()`, and the bounded IDLE
lifecycle's `stop()` awaits every folder loop, which closes its connection,
so acceptance criterion 3 holds through the existing order. The named test
files are a `*.test.ts` (integration tier, `vitest.integration.config.ts`)
and a `*.unit.test.ts` (`vitest.unit.config.ts`);
`mailServerConnections.test.ts` already runs a fake loopback IMAP server
under `allowLoopbackOutboundForTests()` with `stubDnsLookup`, and
`imapIdleClient.unit.test.ts` already uses a `FakeImapFlow` that tracks
`connectCalls`. `node .github/scripts/adr.mjs --all --json` validates the new
ADR's metadata. No protected path is touched. The `createPolicyLookup`
non-export and the private `client` field were checked in the source, not
assumed.

## Decision

ADR CONFLICT: wrote
`docs/adr/2026-10-29-imap-idle-connections-through-the-shared-imap-connect-step.md`
(standalone, `supersedes: []`, narrows the accepted mail connections ADR by
one exported connect step, `openImapFlow()`, that `openImapConnection()`
wraps and that IMAP IDLE uses with the IDLE options; the transport never
connects), pointed the spec at it, and made the minimal corrections to
Context, Task items 1, 2 and 4, Touches and the acceptance criteria.
Approved and queued.
