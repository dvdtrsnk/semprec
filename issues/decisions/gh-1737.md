# Decision: gh-1737 (Search Semp threads by title and preview)

## Question

gh-1737 is the second member of chain `e1-020-semprec-api`. Its two medium
findings (one defect, reported by both reviewers) and its two low findings
were fixed, and the focused recheck confirmed the fixes. It is held only
because a chain lands as one merge and the recheck holds gh-1729. The recheck
left two notes on gh-1737 that are not findings: (1) the fix decides that a
`q` of which folding leaves nothing, such as a lone combining mark, is no
filter; (2) the order the fix removed, escaping in JavaScript and then
`unaccent` over the finished pattern, remains in
`backend/packages/data/src/mail/personEmailIndexStore.ts`, for which the fixer
proposed a follow-up. Decide whether either needs a change before the chain
lands.

## Options considered

- Correct gh-1737 to state the rule for a `q` that folds to nothing: rejected.
  The issue does not state the case, so there is no defective line to correct.
  The implemented rule follows from the issue's own decisions: matching is
  without regard to diacritics, so a text that is only a diacritic has nothing
  to search for, and a blank `q` is no filter. The alternative the first
  version had, a pattern of `%%`, returned every thread with text and was the
  reported defect. The rule is documented in both docstrings of
  `sempThreadsListStore.ts` and has its own test.
- Fix `searchMailContacts` in this chain: rejected. It is code of gh-1507
  (closed), outside the diff and outside Touches of gh-1737, and correct code
  of this chain does not depend on it.
- Record nothing: rejected. The defect is real and confirmed in the code:
  `searchMailContacts` binds a pattern escaped by `escapeContactSearchPattern`
  and compares `... ILIKE unaccent($1) ESCAPE '\'`, so a fullwidth or
  small-form percent sign, low line or backslash in `q` reaches `ILIKE` as a
  live pattern character.
- A follow-up source after the chain lands: chosen. The source is written in
  full in the decision output
  (`[parallel-delivery-contact-search 01/01] Escape the mail contact search pattern after it is folded`).

## Decision

No spec change and no code change for gh-1737. It lands with gh-1729 at
`420277b26`. A follow-up source for the mail contact search is proposed for
after the landing.

## Spec change

None. `issues/items/gh-1737.md` and its approval are unchanged.

## What stays open

- Until the follow-up lands, `GET /api/mail/contacts?q=` with a fullwidth or
  small-form percent sign returns every contact of the caller's tenant, a
  fullwidth low line matches any one character, and a `q` that is only a
  combining mark returns every contact. The result never leaves the caller's
  tenant. The controller approves and schedules the follow-up.
- The owner may overrule the rule for a `q` that folds to nothing; it is one
  `CASE` in the list query and one test.
- gh-1737 defines the searched preview as the first 140 code points of the
  last message text, and the list shows the text with Markdown removed. For a
  message with Markdown the two differ: a link target inside the window can
  match without being shown, and a shown phrase that syntax interrupts is not
  found. The requirements reviewer judged this as following the issue's
  literal definition and its third acceptance criterion and did not report it.
  Whether search should follow the displayed text instead is a product
  decision for the owner; it is not decided here.
