# Decision: gh-1478 (mail connections through the outbound address policy)

## Question

The implementation proposal gh-1478 (connect to tenant-chosen IMAP and SMTP
hosts through the outbound address policy: resolve once, connect only to the
vetted address, keep the host name as TLS server name, report a refused
address as `mail_server_unreachable`) is open without `spec:approved`.
Approve it, or make the minimal correction that makes it approvable.

## Options considered

- Approve unchanged (SOUND): rejected, for two reasons.
  1. Task item 3 and the fourth Touches line required appending a dated note
     to the "Known gap" paragraph of
     `docs/adr/2026-10-16-connect-time-outbound-address-checks.md`, an
     accepted ADR. `issues/README.md` (section "Autonomy": accepted ADR
     bodies are never edited), `docs/adr/README.md` (section "Superseding a
     decision") and `review-rules/rules.md` (editing an accepted ADR's body
     is a high-severity finding) forbid that, and `adr-conventions` states
     that even a narrow addition counts as an edit, so the implementation
     would have been blocked in review.
  2. The SMTP bullet of Task item 1 relied on "a `lookup` option set to the
     policy lookup". `nodemailer@9.0.6` (the installed version) never copies
     a `lookup` option into the options it passes to `net.connect` or
     `tls.connect`: `lib/smtp-connection/index.js` builds
     `{ port, host, allowInternalNetworkInterfaces, timeout }`, resolves the
     name itself through `shared.resolveHostname` (its own `dns.resolve4`/
     `resolve6` with a cache and fallback addresses) and only in `secure`
     mode merges `options.tls` — after its own resolution has already
     replaced `host` with an address, so Node's lookup would never run. As
     written, SMTP connections would bypass the policy and the acceptance
     criteria "no connection is made" and "resolved exactly once" could not
     hold for SMTP.
- Write a new ADR now (ADR CONFLICT): rejected. The connect-time ADR does
  not forbid routing mail through the policy; its "Known gap" paragraph
  invites it ("Until a later decision routes those connections through one",
  "adopts the policy lookup or records why it cannot"). Delivering what an
  ADR deferred and adopting a security stance later routes must respect
  (`adr-conventions`) is a new standalone ADR cross-referencing the old one,
  written in the same PR as the pattern. A decision agent never implements
  the Task, so the ADR belongs to the implementation.
- Keep the SMTP bullet and let the implementer discover nodemailer's
  behaviour: rejected. The spec named a mechanism that does not exist in the
  installed library; the implementation runs on a cheaper model and the
  acceptance criteria would be met only by accident.
- Minimal spec correction (DEFECT): chosen. The SMTP bullet names the hook
  nodemailer offers (`getSocket`, typed by `@types/nodemailer@8.0.1`, which
  hands nodemailer a socket opened through `net.connect` with the policy
  lookup; nodemailer then runs TLS or STARTTLS on it with the host name as
  `servername`, see `_upgradeConnection`). Task item 3 and the Touches line
  call for a new standalone ADR that references
  `[[2026-10-16-connect-time-outbound-address-checks]]` and leaves that ADR's
  body and frontmatter untouched.

Checks run on the integration tip (7c085434): Blocked-by is none; the issues
it builds on are closed (#1473 `spec:approved`, closed: `MailServerSettings`,
`MailServerEndpoint`, `MailServerSecurity = "tls" | "starttls"` exist in
`backend/packages/data/src/mail/mailServerSettingsStore.ts` and are exported
from `backend/packages/data/src/index.ts`; #1034 closed). In
`backend/packages/data/src/net/outboundAddressPolicy.ts`:
`createPolicyLookup` exists at module scope and is not exported (so the
"export it if it is not exported" instruction is accurate),
`OutboundAddressNotAllowedError` (message names the host only),
`isOutboundAddressNotAllowed`, `allowLoopbackOutboundForTests` (throws unless
`NODE_ENV=test`) and `currentOutboundAddressPolicy` exist.
`ImapFlowMailClient(client: ImapFlow)` exists in
`backend/packages/data/src/mail/imapFlowClient.ts`;
`MailSyncAdapterFactory.createImapClient(mailboxItemId, credential: string)`
in `mail/mailSyncJob.ts` fixes the credential as the decrypted password
string, which is how #1510 calls the factory. `MailServerUnreachableError`
and `mail_server_unreachable` occur nowhere in `backend/`, so they are
explicitly new; `providerTypes.ts` holds the other mail error classes.
`imapflow@1.7.6` types `tls?: ConnectionOptions` and `servername?: string`
and `connect()` merges `options.tls` into the options it passes to
`net.connect`/`tls.connect`, so `tls.lookup` is the pinned-lookup hook and
the IMAP bullet is implementable as written (the STARTTLS upgrade reuses the
connected socket with `host` and `servername` set). The named test file is a
`*.test.ts`, which `backend/vitest.integration.config.ts` runs (vitest);
`backend/packages/data/src/testSupport/dnsLookupStub.ts` (`stubDnsLookup`,
`.calls`) supports the "resolved exactly once" and "resolves to an internal
address" tests, and `mcpConnectionFactory.test.ts` is the precedent for a
fake loopback server under `allowLoopbackOutboundForTests()`. The dependants
#1510, #1569 and #1634 are approved and name `openImapConnection`,
`MailServerUnreachableError` and the policy-checked connection consistently
with this spec. No protected path is touched.

## Decision

DEFECT: name nodemailer's real per-connection hook (`getSocket`) instead of
the unsupported `lookup` option, and replace the instruction to edit the
accepted connect-time ADR with a new standalone ADR that cross-references it.
Approved and queued.
