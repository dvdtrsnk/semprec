# gh-1520 decision

## Question

Which minimal additional Touches path permits the required Projects status/pinned regression through the real `/mcp` handler without violating `core-knows-nobody`?

## Options considered

- Add the existing `backend/services/semprec-api/src/mcp/__tests__/mcpGenericOperationsContract.test.ts`: selected. It already hosts real MCP generic item-write and REST/MCP parity cases, seeds Projects, and supports restricted agent credentials.
- Add a new API-level test file: rejected because the existing contract harness can express the required operations; another file would duplicate setup without resolving an additional requirement.
- Drop the `/mcp` criterion: rejected because Task 3 and the acceptance criteria explicitly require it, and the owner's instruction preserves it.
- Keep Touches unchanged and import the API handler from a data-package test: rejected because `core-knows-nobody` forbids the package-to-service dependency.

## Decision

DEFECT — add exactly one existing API test file to Touches, approve the corrected specification and queue it. Task, Acceptance criteria and Out of scope remain unchanged. The additional permission is solely for the existing `/mcp` regression requirement; this decision does not implement the Task.

Verified against integration tip `05d81ac1a16feeb1bd63fd11b0db313c93cd12b9` in the assigned shared worktree:

- `backend/.dependency-cruiser.cjs` loads `dependency-cruiser.rules.json`. Its `core-knows-nobody` error rule forbids imports from `^packages/[^/]+/src/` to `^services/[^/]+/src/`, including tests. The selected test is in the API service and already imports its own MCP handler and public package entry points.
- The selected file exists. `startServer` uses `createMcpRequestListener`; `rpc` sends HTTP POST `/mcp` JSON-RPC `tools/call` requests. Its `item.patch` case invokes `semprec.item.patch` with `{ itemId, properties, ifVersion }`. Both human-session and restricted run-credential cases already execute generic item writes through this path.
- `beforeEach` seeds the system and constructs the real generic operation gateway. `projectsDatabaseId` locates the seeded Projects database and `createProjectItem` uses the choke point. The seed declares user-owned `pinned` and `status` with `inProgress`, `done`, `archived`, and `longTerm`. The same harness can create a Projects fixture and pass `properties: { status: 'done' }`, `properties: { pinned: true }`, or both to `semprec.item.patch`, using the fixture's current `updatedAt` for `ifVersion`. No service import from the data package is needed.
- MCP uses POST as its transport for the item-patch operation. The existing adapter maps `ValidationError` to JSON-RPC `-32602` with public error details inside HTTP 200; the regression can assert the `pinned` field and unchanged stored values using that existing envelope. This does not require changing the transport or weakening the domain parity criterion.
- Blocker gh-1515 is closed with implementation commit `585f2d22d4dbd366cb2195b8dacf5891ac998603`; its local handover was read. No external precondition, protected-path edit or new architectural pattern is involved.
