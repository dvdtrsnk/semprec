This push addresses the round-3 code review finding on PR #330 (CI run `101919493397`):

**Medium correctness finding**: `buildStdioTransport` in `backend/packages/data/src/mcp/mcpConnectionFactory.ts` stripped `StdioClientTransport`'s default environment (`PATH`, `HOME`, etc.) whenever a credential was injected without an explicit `config.env`. The SDK only falls back to `getDefaultEnvironment()`'s safe allowlist when `env` is entirely `undefined` — any other defined object becomes the complete child environment with no merge. Since the credential-injection path always produced a defined object (`{ [credentialEnvVar]: credential }`), any stdio MCP server relying on ambient environment variables would break in that configuration.

**Fix** (commit `c610e8e`): import `getDefaultEnvironment` from the SDK's stdio module, and whenever a defined `env` object is needed at all (`config.env` present and/or credential injection), seed it from `getDefaultEnvironment()` first, then layer `config.env` and the injected credential on top — matching the reviewer's suggested fix.
