## Summary

Added the shared MCP client connection factory for issue #231:

- **`connectMcpServer`** (`backend/packages/data/src/mcp/mcpConnectionFactory.ts`) — opens a connection for an `mcpServers` item's `stdio`/`sse`/`http` `connectionConfig`, completes the `initialize` handshake, and returns a connected client with an explicit `close()`. This is the single shared entry point #125 (sync action) and #128 (invoke adapter) are meant to import instead of reimplementing transport handling.
- Credentials are decrypted only at connection time (via the existing `external_credentials` infrastructure) and injected transport-appropriately: stdio through the child process's env, sse/http through a minimal bearer-token `OAuthClientProvider` whose `tokens()` closure is the only place the plaintext ever lives — this avoids the SDK's default behavior of retaining `requestInit`/`serverParams` as plain, JSON-serializable transport properties, which would otherwise leak the credential into the returned client's serializable state.
- Malformed config and credential-decryption failures are rejected before any connection opens; connect/handshake failures map to the same safe `McpConnectionError` shape after releasing whatever was opened.
- No handler is registered for `notifications/tools/list_changed`, satisfying the structural non-reactivity requirement.
- Added minimal MCP contract test servers for all three transports (`testSupport/mcpContractServers`, a new package export subpath) for reuse by #125/#128's own tests.
- New integration test suite (`mcpConnectionFactory.test.ts`, 9 tests) covers per-transport connect/handshake/credential-injection, absence of the credential from the client's serializable state, resource cleanup after `close()` and after failed connects, the `list_changed` non-effect, and safe error mapping.

Verified: full monorepo build (`tsc`, all packages), unit suite (83 tests), integration suite (539 tests, includes the new 9), e2e suite (5 tests), and the dependency-boundary check all pass with no regressions.
