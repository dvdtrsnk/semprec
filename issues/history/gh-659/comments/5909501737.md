Spec amendment (ADR supersession). This issue was written on 2026-09-27, before `docs/adr/2026-09-28-module-transactional-side-effects-inline-at-choke-point.md` existed. That ADR was added the next day by the task-recurrence change and prescribes the inline `tasks/` call in `updateItemWithClient` that this issue's own Task moves behind `runItemUpdateHooks` (the "if the data-integrity task-recurrence change has merged" branch, which applies — PR #840 registers `taskRecurrenceItemUpdateHook`). Keeping `supersedes: []` and leaving the 2026-09-28 ADR `accepted` therefore leaves two accepted ADRs prescribing opposite shapes for the same decision, which is what the code review keeps flagging on #840 and what the fix rounds could not resolve without breaking the old acceptance criterion.

The Task, Touches and Acceptance criteria now allow exactly one extra change: the new ADR declares `supersedes: [2026-09-28-module-transactional-side-effects-inline-at-choke-point]`, and the 2026-09-28 ADR gets `status: superseded` and `superseded-by: <new ADR slug>` in its frontmatter only (body untouched). Nothing else about the ADR constraint changes.
