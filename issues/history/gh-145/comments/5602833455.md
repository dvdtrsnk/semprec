Implements issue #145: migrates every system `select`/`multi_select` property's `config.options` from a bare string array to `{ key: string, label?: string }[]`.

- **`types.ts`**: adds the `SelectOption { key, label? }` type.
- **`chokePoint/propertiesStore.ts`**: adds `assertValidSelectOptions`, wired into `createProperty` and `updatePropertyConfig`, rejecting the old bare-string shape on any new write.
- **Seed files** (`seedTenDatabases.ts`, `seedInboxPipeline.ts`, `seedMcpModule.ts`, `seedEmailModule.ts`, `seedLibraryModule.ts`): the shared `selectConfig` helper now emits `{ key }` (no `label`) for shipped catalog options.
- **`db/migrations/0029_select_option_keys.sql`**: backfills existing `properties.config.options` from bare strings to `{ key }`/`{ key, label }` objects. It carries a per-`(database owner_module_id, property key)` catalog of the exact values `seed/*.ts`'s `selectConfig()` calls ship — a bare string becomes `{ key }` with no label only when it matches its property's shipped catalog entry; anything else (a pre-existing user-added/renamed option, or an unrecognized property) becomes `{ key, label: <original string> }`, preserving its display text. Idempotent (already-migrated rows and manual overrides pass through untouched, and the `UPDATE` is skipped entirely when nothing changed), and aborts with the offending `properties.id` on malformed data.
- **Tests**: `inboxPipeline.test.ts` updated to the new options shape; new `selectOptionKeysMigration.test.ts` covers upgrade, idempotency, override preservation, the shipped-vs-user-added label distinction, multi_select, non-select exemption, both malformed-data abort paths, and validator edge cases (empty-string key, `null` element).

No serializer or `filterCompiler.ts` currently reads `config.options`, so per the issue's own scope note, no further changes are needed until #147 wires the real translation catalog; typed filters are unaffected since item property values were never touched.
