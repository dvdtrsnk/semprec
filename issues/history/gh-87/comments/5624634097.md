## Summary

Implements per-agent ownership enforcement for AI-created views (issue #87):

- Added a nullable, indexed `views.creator_project_item_id uuid` column via an additive migration (`0035_views_creator_project_item_id.sql`), safe for pre-existing "legacy" AI rows.
- Exposed `creatorProjectItemId: string | null` on the view row shape (`ViewRow`, `viewsStore.ts`).
- Introduced a server-derived `Actor` type (`{ type: CreatedBy; agentProjectItemId?: string }`) across all view/view-membership choke-point methods (`createView`, `patchView`, `deleteView`, `addViewItem`, `removeViewItem`, `reorderViewItem`), replacing the old bare `CreatedBy` string actor.
- Enforced agent identity validation (`assertAuthenticatedAgentIdentity`) against the "Projects" system database before any row or membership write, and ownership equality checks (`assertViewWritable`) for every mutating operation.
- Implemented atomic adoption: a user patch or curated-membership write on an agent-owned view flips `created_by = 'user'` and clears `creator_project_item_id` in the same transaction; user delete needs no adoption; system views never adopt.
- Legacy (pre-migration) AI rows are NULL-owned, unwritable by any agent (`legacy_creator_unknown`), but still user-adoptable.
- All failures return the exact `403 owner_violation` shape with `details = { field, viewId, reason }` (`creator_mismatch`, `legacy_creator_unknown`, `user_owned`, `system_owned`) or `{ field: 'agentProjectItemId', reason: 'missing_authenticated_agent_identity' | 'unknown_authenticated_agent_identity' }`, the latter always checked before any write.
- Added a dedicated migration test proving legacy-row safety, plus a full rewrite of `views.test.ts` covering the new ownership/adoption/identity rules.
