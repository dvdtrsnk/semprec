## [mailbox-experience 06/07] Implement compose and reply behavior

Closes #98. Everything lands in `web/`.

### Compose surfaces

Two independent surfaces sharing one form: a **floating, minimizable new-message window** that hovers over the mailbox (reading, triage and navigation continue underneath it) and an **inline reply** inside the thread being read.

All compose state lives in `MailboxClient`, not in the form. Minimizing the window unmounts the fields but not their content; replies are kept per message, so walking to another message and back returns to the reply half-written in it; a send the backend rejects leaves everything editable. Fields are frozen while a save or send is in flight, since the state that comes back is the one that was submitted.

### Recipients and sender

- **Structured To/Cc/Bcc.** A recipient field is parsed into `{name, address}` — a quoted display name containing a comma stays one recipient — and deduplicated by normalized address.
- **Reply and reply-all are derived from the stored envelope** (`mail_message_meta`), read through a new `email.message.envelope` operation: the user's own aliases are dropped, an address that was both a To and a Cc appears once, and replying to one's own sent message answers its recipients rather than the user. A message the mail module has no envelope row for (legacy, or `migrationStatus: 'partial'` from #93) still replies, from the derived display text.
- **From is a plain dropdown over the registered aliases** (`Mailboxes.addresses` — exactly the list the backend's send path validates against, so an address it would reject is not offerable). It defaults to the persisted `deliveredToAddress` of the message being replied to, then the account whose folder is open, then the primary address — a default only, overridable at any time.
- Replies carry `inReplyTo` and the `References` chain forward.

### Draft and send

Saving calls `email.draft.create`, sending calls `email.send`, both reached through a new `callOperation(operationId, input)` on the generic operations port (`POST /operations/<id>`) — the same named-module surface an agent calls, used only for the actions no generic read or write can express. A rejected send leaves the draft item in place, the window open and editable, and shows the backend's own refusal.
