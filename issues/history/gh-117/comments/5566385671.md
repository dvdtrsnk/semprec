## Summary

Implements issue #117: the live push hook and startup repair sweep that build on #228's `packages/agent-runtime` lifecycle adapter.

**Live push hook** — `runAgentSession` now publishes every message it observes, including `message_update` streaming deltas, as a new `agent_run_event` realtime NOTIFY (`@semprec/realtime`'s `RealtimeMessage` union). This is best-effort (a failed publish is logged, never fails the run) and happens for every message kind, while persistence to `agent_run_events` still skips `message_update` — so deltas are observable live but absent from Postgres, per the acceptance criteria.

**Startup repair sweep** — new `repairInterruptedRuns(pool)` exported from `@semprec/agent-runtime`, backed by a new `listRunningAgentRuns` query in `@semprec/data`. In one transaction it:
1. Closes every `agent_runs` row still `status='running'` as `status='error'`, `finished_at=now()`, `result='interrupted_by_restart'`.
2. For each such run whose last `agent_run_events` row is an unpaired `tool_use`, appends a synthetic `tool_result` (carrying over the original tool-call fields, marked `error: true`) so the transcript's tool-calling invariant holds.

This is a ready-to-call primitive; no `semprec-agents` service process exists yet in the repo to invoke it at boot or to wire the push into a live server, consistent with #228 also having no live caller yet.

**Testing**: added integration tests for both the push hook (via a real LISTEN/NOTIFY round trip) and the repair sweep (orphan detection, synthetic tool_result insertion/non-insertion, no-op cases).
