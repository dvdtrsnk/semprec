## What was implemented

- **`deliveredToAddress`** is now persisted once, at ingest (`mail_message_meta.delivered_to_address`, new migration `0007_mail_delivered_to_and_dsn.sql`), via `mail/deliveredTo.ts`'s `resolveDeliveredToAddress` — precedence: highest `Delivered-To` occurrence → `X-Original-To` → `Envelope-To` → first registered `Mailboxes.addresses` alias matching structured To/Cc → mailbox primary (first) address. Resolved centrally in `mail/ingest.ts`, never recomputed downstream. All three sync adapters (IMAP/Gmail/Graph) were extended to surface the raw header candidates needed for this (IMAP gained proper folded-header + repeated-header parsing in `imapFlowClient.ts`, since Delivered-To can appear multiple times per hop).
- **DSN/bounce detection** (`mail/dsn.ts`): a top-level `Content-Type: multipart/report; report-type=delivery-status` is detected across all three adapters and tagged `messageKind: 'dsn'` + `dsnOriginalMessageId` (from References/In-Reply-To) on `mail_message_meta` — still threaded normally via the existing `threading.ts`, just distinguishable from an ordinary human reply.
- **`People.emails`/`person_email_index`** were already fully implemented deterministically in issue #26 — this PR only adds regression tests confirming normalization/determinism (no reimplementation needed).
- **Legacy Emails migration** (`migrationJob/mailLegacyEmailMigration.ts`, queue task `mailLegacyEmailMigration`): backfills `mail_message_meta` for any Emails item that predates it (identified by having no meta row at all). Parses raw MIME via an injected `LegacyRawMimeFetcher` when a composition root supplies one (`migrationStatus: 'done'`, including correct DSN classification); otherwise reconstructs `envelope`/`threadId`/`messageId` as far as possible from legacy `sender`/`recipients` display text (`migrationStatus: 'partial'`). Idempotent/resumable via a `LEFT JOIN ... WHERE item_id IS NULL` filter (no persisted cursor needed, same pattern as `propertyTypeMigration.ts`), and guards against a recovered Message-ID colliding with an already-synced duplicate item by falling back to a synthetic id per item, with each item migrated in its own transaction.

## Notes for dependent issues

- No raw-MIME storage exists yet anywhere in the codebase — `LegacyRawMimeFetcher` defaults to a no-op (`noopLegacyRawMimeFetcher`), so the "raw MIME" migration path is real, tested code but currently unreachable in production until some future issue actually persists raw MIME and wires a real fetcher into `createCoreTaskList`.
- `Mailboxes.addresses` (seeded in issue #26, previously unconsumed) is now read by `mailSyncJob.ts` for `mailboxAliases`; no "primary address" field exists on Mailboxes, so the first line of `addresses` is treated as primary by convention — worth a real field if that assumption ever needs to change.
- `dsnOriginalMessageId` is a Message-ID string, not an item id — resolve it via `getMailMessageMetaByMessageId` if a future mailbox-UI issue needs to link to the actual outgoing Emails item.
