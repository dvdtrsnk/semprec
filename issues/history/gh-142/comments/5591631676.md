## Summary

Implements single-use password recovery over SMTP (issue #142):

- **Migration** `0027_password_reset_tokens.sql`: new `password_reset_tokens` table (user FK, unique `token_hash`, `expires_at`, `consumed_at`, `created_at`), mirroring `sessions.token_hash`'s "only the hash persists" pattern.
- **`passwordResetStore.ts`**: DB access, including `consumePasswordResetToken` — a single atomic `UPDATE ... WHERE consumed_at IS NULL AND expires_at > now() RETURNING` that both requires and marks single-use consumption in one statement, closing the double-consume race.
- **`passwordResetActions.ts`**: `requestPasswordReset` (resolves identically for a known and an unknown email — no disclosure of account existence; generates a high-entropy token and emails a reset link only for a real account) and `resetPassword` (atomic consume, new Argon2id hash, deterministic `PasswordResetTokenError` reason of `invalid`/`expired`/`consumed`).
- **`passwordResetMail.ts`**: a new app-level SMTP mailer (`NodemailerPasswordResetMailer`), reusing the SMTP infrastructure pattern from #27, independent of the per-mailbox draft/Sent-folder workflow (which doesn't apply to a system notification with no owning mailbox item).
- **HTTP surface** in `authHandler.ts`: `POST /api/auth/password-reset/request` and `POST /api/auth/password-reset/consume`, wired into `serve.ts` with `APP_BASE_URL`/`SMTP_*` env config (falls back to a `noop` mailer that throws if SMTP isn't configured, rather than silently pretending to send).
