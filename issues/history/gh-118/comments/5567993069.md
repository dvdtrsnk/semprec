## Summary

Implements issue #118: pause and re-wake semantics for Semp's own user conversation, with per-wake `agent_runs` bookkeeping.

Adds `SempConversation` in `backend/packages/agent-runtime/src/sempConversation.ts`, a sibling to issue #229's `DelegationRegistry`, using the same in-memory TTL-reuse pattern but as a singleton (Semprec is single-tenant — there's exactly one Semp/user conversation, so no per-caller key is needed) and with different TTL-expiry semantics:

- The first `send()` wakes a new `agent_runs` row (`triggered_by='user'`, `unit='session'`, `project_item_id` = Semprec's own project item) and an in-process `AgentSession`.
- Consecutive `send()` calls within the 24-hour TTL reuse the same session as new turns via `AgentSession.send()`, without opening a new run.
- On TTL expiry, the in-memory session is dropped and its wake run finished as `done` — but unlike a delegated session, this only *pauses* the conversation. There is no "closed" state for it, so the next `send()`, whenever it arrives, wakes a fresh run rather than being permanently gone.
- Each wake goes through a `reconstructHistory` port so a later wake can inherit prior wake runs' context; this part ships only a stub returning no prior history (`stubReconstructConversationHistory`) — #119 will fill it in with the full reconstruction and a context-size check.

New tests in `__tests__/sempConversation.test.ts` cover wake bookkeeping columns, session reuse, reconstructHistory invocation, TTL pause + fresh wake, no-pause-if-touched, busy rejection, and error handling on both first-turn and reused-turn failures.
