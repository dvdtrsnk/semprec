## Summary

Implements issue #118: pause and re-wake semantics for Semp's own user conversation, with per-wake `agent_runs` bookkeeping, plus fixes from CI code review.

`SempConversation` (`backend/packages/agent-runtime/src/sempConversation.ts`) is a sibling to issue #229's `DelegationRegistry`, using the same in-memory TTL-reuse pattern but as a singleton (Semprec is single-tenant — one Semp/user conversation, no per-caller key needed) with different TTL-expiry semantics:

- First `send()` wakes a new `agent_runs` row (`triggered_by='user'`, `unit='session'`, `project_item_id` = Semprec's own) and an in-process `AgentSession`.
- Consecutive `send()` calls within the 24-hour TTL reuse the same session as new turns, without opening a new run.
- On TTL expiry, the in-memory session is dropped and its wake run finished as `done` — but this only *pauses* the conversation, which has no "closed" state; the next `send()`, whenever it arrives, wakes a fresh run.
- Each wake goes through a `reconstructHistory` port for inheriting prior context; this part ships only an internal stub returning no prior history — #119 will fill it in.

Follow-up commit addressed CI code-review findings on this PR:
- **High**: fixed a concurrency race in `pause()` — it now claims the entry as `busy` synchronously before its first `await`, so a `send()` arriving mid-pause is rejected instead of reusing a session whose run is concurrently being finished as `done`. Added a regression test.
- **Medium**: stopped exporting the internal `stubReconstructConversationHistory` default from the package's public index (scope creep beyond what #118 asks for).
- **Low**: removed an unused `lastActivityAt` field that had no consumer.
