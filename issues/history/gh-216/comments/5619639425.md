## Summary

Implements issue #216: retained doc-history model for the Yjs CRDT persistence layer.

- **`doc_history_updates`** table mirrors every `doc_updates` append (same id/bytes/attribution/timestamp) in the same transaction, with its own `expires_at`.
- **`doc_snapshot_history`** gained `through_update_id`, `represented_at`, and a nullable `expires_at`; **`docs`** gained `history_available_from`. New docs atomically get a non-expiring baseline checkpoint (`through_update_id = 0`) at creation.
- **Compaction** now writes a checkpoint matching the exact contract (boundary = greatest merged update's id/`created_at`, `expires_at` = represented_at + retention) in the same transaction as the snapshot write and `doc_updates` delete, and never touches `doc_history_updates` or the NULL-expiry baseline. The old periodic squash sweep (`squashDocHistory`/`runHistorySquashSweep`/`handleDocHistorySquashTask`) is removed entirely, including its cron entry and task name.
- **`openDocVersionAt`** rejects future timestamps (`ValidationError`), returns the empty doc before the first update, selects the latest applicable checkpoint and replays `doc_history_updates` forward, and returns `HistoryNotRetainedError` (HTTP 410 `history_not_retained`) before `history_available_from` or before the retention cutoff.
- **`DOC_HISTORY_RETENTION_DAYS`** config (default 30) validates as a positive integer; retention math uses `make_interval(hours => 24 * days)` against `transaction_timestamp()` for DST/timezone-safe boundaries.
- **`0035_doc_history_retention.sql`** adds everything additively (nullable), per expand/contract migration discipline; **`docHistoryCutoverMigration.ts`** (JS, since it merges Yjs binary updates) runs once after `runMigrations` to delete every ambiguous pre-#216 checkpoint, install one valid cutover baseline per doc, and only then tighten the new columns to NOT NULL — covered by a populated-migration test.
