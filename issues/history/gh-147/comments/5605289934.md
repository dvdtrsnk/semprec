## Summary

Closes #147 ("[system-i18n 05/05] Localize API and agent-manifest projections").

`generatePermissionManifest` (`backend/packages/data/src/manifest/permissionManifest.ts`) now accepts an optional `{ moduleRegistry, locale }` and resolves database names, property names, and select/multi_select option labels through the `resolveCatalogLabel` fallback chain (explicit stored override → requested locale → English → raw key). A database's `owner_module_id` column stores the database *key*, not the owning `ModuleManifest.id`, so the resolver first builds a `key -> moduleId` map from `ModuleRegistry.getDatabases()` before loading catalogs. `createDriftCheckAction` threads the same options through so its resolvability check also validates catalog resolution when a registry is supplied. Callers that omit `moduleRegistry` (every existing call site) keep the exact pre-#147 raw-key placeholder behavior, so nothing regresses.

New integration tests cover cs/en catalog resolution, English fallback, raw-key fallback with no registry, override-always-wins across locales, and byte-for-byte preservation of user-authored content.
