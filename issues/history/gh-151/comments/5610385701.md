## Summary

Implements issue #151: delivering committed notifications through Web Push and APNs.

- **`writeNotification`** now enqueues one `notificationFanout` graphile-worker job per genuinely-new notification (dedup via `RETURNING id` on the existing `ON CONFLICT DO NOTHING` insert), keyed by the notification's own id so the job can never be duplicated even if the caller replays.
- **`notificationFanout` job handler** loads every active `push_subscriptions` registration for the notification's user and dispatches each through its channel's adapter — Web Push (VAPID, via the `web-push` package) or APNs (raw HTTP/2, ES256 provider JWT cached for up to 55 minutes, sandbox/production host selected from `apns_environment`).
- **`push_deliveries`** (new migration 0032) is the durable per-(notification, registration) dedup key: a unique index on `(notification_id, push_subscription_id)` plus a three-state status (pending/delivered/permanently-failed) guarantees a retried job run never re-sends a pair that already succeeded or was already ruled out.
- Transient provider/network failures leave the delivery row pending and rethrow so graphile-worker retries the whole job; a permanent rejection (404/410/`BadDeviceToken`) marks that one delivery failed and invalidates only that registration via #150's `revokePushSubscriptionByProviderInvalidation`.
- Notification payloads sent to providers are limited to `notification_id`, `title`, and `link_href` — no source content beyond the notification row.
