## Summary

Implements issue #151: delivering committed notifications through Web Push and APNs.

- **`writeNotification`** enqueues one `notificationFanout` graphile-worker job per genuinely-new notification, keyed by the notification's own id.
- **`notificationFanout` job handler** loads every active `push_subscriptions` registration for the notification's user and dispatches each through its channel's adapter — Web Push (VAPID) or APNs (HTTP/2, cached ES256 provider JWT, sandbox/production host from `apns_environment`).
- **`push_deliveries`** (migration 0032) is the durable per-(notification, registration) dedup key guaranteeing exactly-once delivery across job retries.
- Transient failures retry via graphile-worker; permanent provider rejections (404/410/`BadDeviceToken`) invalidate only the reported registration via #150's invalidation mechanism.
- Payloads to providers are limited to `notification_id`, `title`, and `link_href`.

## Review fixes (this update)

Addressed all three findings from the automated code review on PR #362, in `apnsAdapter.ts`:
- **High:** `aps.alert.body` was set to the same string as `title`, duplicating the title as body on every iOS notification. `notifications` has no separate body/description column, so the alert now carries `title` only.
- **Medium:** `postApnsRequest` had no timeout — an unresponsive APNs host could hang the promise indefinitely, blocking a graphile-worker task slot. Added a 10s timeout that fails the request and tears down the HTTP/2 client.
- **Medium:** the HTTP/2 client-level error handler rejected without closing the session, leaking the socket on TLS/session-level failures. It now goes through the same cleanup path as every other failure, always calling `client.destroy()`.
