## Summary

Implements issue #239: extends `ModuleManifest` with an optional `customRoutes` array so a module can declare a named custom route (name, HTTP method, `/api` path, handler export, justification). `ModuleRegistry` fail-fasts on duplicate method+path registration, identifying both owning modules, and rejects any entry missing a `transactional-semantics`/`single-consumer-read` justification.

`semprec-api` mounts these routes at startup via `mountCustomRoutes`, built on the #238 REST adapter (shared auth, validation, status mapping, `{error:{code,details}}` error contract). - `POST /api/proposals/:id/confirm` and `GET /api/inbox-types` (owned by `inboxPipeline`)
- `POST /api/push-subscriptions` / `POST /api/push-subscriptions/:id/revoke` and `GET /api/ai-usage` (owned by `schemaCore`)

Their previous ad hoc prefix-routed handlers in `app.ts` (`aiUsageHandler.ts`, `pushSubscriptionsHandler.ts`) were removed.
