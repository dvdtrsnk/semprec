**Blocked by:** #1366
**Model tier:** medium

## Context

Model tier rationale: One well-specified TypeScript module with a clear contract from the ADR and Yjs-level tests, but it defines the persisted block format and its read-time repair rules, which later issues depend on.

#1366 records the block model: a closed type registry, document order in the top-level `doc.getArray('order')`, block text as `Y.Text` with inline attributes, strict validation on server writes and read-time normalization for whatever arrives through `WS /api/sync`. This issue implements that ADR as a pure TypeScript module over `yjs`, in the directory the ADR fixes (it must not import `pg` or Node-only dependencies, so the browser editor can use it).

Today `backend/packages/data/src/docs/blocks.ts` offers `putBlock`, `getBlock`, `listBlocks` and `deleteBlock` over a flat `doc.getMap('blocks')` with free-form `sys:flavour` and `sys:children`; it has no order and no validation. It is used by `docs/docStore.ts` (`putBlock`, `listBlocks`, `putBlockWithClient`), by `inbox/proposalActions.ts` (the `pageContent` confirm path) and by several tests that use a `root`/`page`/`paragraph` convention. That legacy API stays in place and keeps working in this issue. Retiring it belongs to the page-content proposal work (#1681), because that is the production caller.

What builds on this issue: atomic multi-block operations (#1610), Markdown conversion (#1608) and the page summary read (#1615).

Decisions made here where the ADR leaves room:

- Decision: a document with no blocks is read as a single empty `text` block flagged `synthetic: true` with `id: null`; reading writes nothing. The first real insert (in #1610) materializes it.
- Decision: blocks missing from `order` are appended in ascending id order, so two clients with the same state always derive the same order.
- Decision: the module returns plain data (`PageBlock[]`) and validation issues; mapping a validation failure to HTTP 400 happens in the data-layer caller (`ValidationError`), not inside the pure module.

## Task

Load `testing`. Follow the module location and storage contract in the ADR from #1366.

1. Create the block type registry: the closed set of type keys `text`, `h1`, `h2`, `h3`, `bullet`, `number`, `todo`, `quote`, `page`, with per-type field rules (`indent` integer 0-5 default 0 on every type; `done` boolean only on `todo`; `text` a `Y.Text` on every type except `page`; `pageId` string only on `page`) and the inline attribute names `bold`, `italic`, `code`, `link` (`{href}`).
2. Implement the document accessors on `Y.Doc`: `getOrderArray(doc)` (`doc.getArray<string>('order')`) and `getBlocksMap(doc)` (the existing `blocks` map). Blocks are `Y.Map` values keyed by id with `sys:id`, `sys:flavour` (type key), `indent`, `done`, `text`, `pageId`.
3. Implement `readPageBlocks(doc): PageBlock[]` with read-time normalization, never mutating the doc: first occurrence wins for an id repeated in `order`; unknown `sys:flavour` read as `text` (the stored value is untouched); `indent` clamped to 0-5 and non-integers treated as 0; `done` true only for `todo`; ids in `order` without a block skipped; blocks absent from `order` appended in ascending id order; an empty result becomes one synthetic empty `text` block. Each `PageBlock` carries `id`, `type`, `indent`, `done`, `text` (the `Y.Text` delta or a plain-text accessor) and `pageId`.
4. Implement strict validation for server-side writes: `validateBlockInput(input)` returns a list of issues (unknown type key, indent outside 0-5 or not an integer, `done` on a non-todo, `pageId` on a non-page or missing on a page, wrong field types, text on a page block). It never throws on bad input; it returns issues. Add `assertValidBlockInput` in `@semprec/data` that converts a non-empty issue list into the existing `ValidationError` (HTTP 400).
5. Implement the low-level write primitive `writeBlock(doc, block)` used by later operations: it creates or replaces the block `Y.Map` fields, sets the `Y.Text` content with attributes, and appends the id to `order` if it is not yet there. It validates through `validateBlockInput` and refuses invalid input. It must be called inside `doc.transact(...)`.
6. Mark the legacy flat-map API in `docs/blocks.ts` with a module comment pointing to the new model. No behavior change.
7. Export the new module's public surface from the barrel `backend/packages/data/src/index.ts` only if the ADR places the module inside `@semprec/data`; otherwise export it through the package the ADR names.
8. Tests (Yjs only, no database): two `Y.Doc` instances inserting the first block concurrently and exchanging updates end with both blocks in `order` and identical order on both; a doc with a duplicated id in `order`, an unknown flavour and `indent` 7 reads as one block of type `text` with indent 5 and `Y.encodeStateAsUpdate` is byte-identical before and after the read; a block missing from `order` appears last; a block of unknown type is rejected by `validateBlockInput`; an empty doc reads as one synthetic empty text block.

## Scope

### In scope

- The type registry, order array, normalization on read, strict validation, the single-block write primitive and their tests.

### Out of scope

- Split, merge, move, set type, indent change, duplicate and delete of blocks, and the invariants around them: #1610.
- Markdown conversion and fixtures: #1608.
- The HTTP page summary and the page operations: #1615, #1616.
- Removing or migrating the legacy `putBlock` API and its callers: #1681.
- Cleanup sweeps of existing documents: not planned; the ADR records that read-time normalization is enough.
- The WebView editor itself.

## Acceptance criteria

- When two clients insert their first block into an empty document concurrently and exchange updates, then both blocks are in `order` and both clients read the same order.
- When a document has a repeated id in `order`, an unknown type key and `indent` 7, then `readPageBlocks` returns that id once, as type `text`, with indent 5, and the Yjs state is unchanged by the read.
- When a block exists in the map but not in `order`, then `readPageBlocks` returns it after all ordered blocks.
- When a server-side write passes an unknown type key, then validation fails and the data-layer wrapper raises `ValidationError` (HTTP 400).
- When a document has no blocks, then `readPageBlocks` returns one empty `text` block and writes nothing.
