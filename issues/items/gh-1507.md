## Context

Model tier rationale: A read-only search route over existing People data with a defined output, using diacritic-insensitive matching and own-address exclusion, no write contract.

The compose window suggests recipients while the user types part of a name or an address. There is no contacts endpoint. `People.emails` (a long text with one address per line, user-owned, added by `backend/packages/data/src/seed/seedEmailModule.ts`) and `person_email_index` (address to person, unique per tenant, `backend/packages/data/src/mail/personEmailIndexStore.ts`) exist. The generic `contains` filter is `ILIKE` without `unaccent`, so "novak" would not find "Novák". The `unaccent` extension is installed by `0006_mail_sync.sql`. `Mailboxes.addresses` lists the tenant's own addresses.

Decision: the first phase suggests only People. Addresses from earlier mail that belong to no person are a later phase and are not built here.

Decision: sending accepts a manually typed valid address, so suggestions are an aid only and nothing validates against them.

Shared-file ordering: this issue also waits for #1501 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. Add `GET /api/mail/contacts?q=&exclude=&limit=` as a custom route of the mail module (justification `single-consumer-read`), authenticated and tenant-scoped, registered in the manifest and route matrix.
2. Match `q` case- and diacritic-insensitively (`unaccent`) as a substring of the person's name or of any address in their `emails` list. Return one row per address `{ personId, name, email, relationship }` (the person's `Relationship` select value when set), ordered by name then address.
3. Leave out the tenant's own mailbox addresses and every address in `exclude` (comma-separated, compared normalized). `limit` defaults to 10 with a maximum of 50. An empty `q` returns no rows.
4. Do not match with unbounded patterns: escape `%`, `_` and backslash in `q`.

## Scope

### In scope

- The contacts search route for People, with own-address and exclusion filtering.

### Out of scope

- Suggesting addresses from earlier mail that have no person (later phase; not planned yet).
- Creating people or changing `People.emails`.
- Validating recipients on send (#1896).

## Acceptance criteria

- When `q=novak` and a person "Petr Novák" has `petr@novak-web.cz`, then a row with that name and address is returned.
- When a person has two addresses, then each is a separate row.
- Addresses listed in `exclude` and the tenant's own addresses are not returned.
- When `q` contains `%` or `_`, then it matches literally.
- People of another tenant are never returned.
