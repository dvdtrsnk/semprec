**Blocked by:** #85, #23

## Context

Yjs compaction merges updates into the current snapshot and deletes the source rows. The current historical reader then refuses timestamps preceding a later compaction because the required intermediate updates are gone. A retained checkpoint is therefore not sufficient to guarantee that an arbitrary timestamp inside the retention window can be opened.

This first part introduces the retained history model: retention configuration, the mirrored `doc_history_updates` log, checkpoint boundaries on `doc_snapshot_history`, the populated cutover migration, checkpoint-writing compaction that no longer destroys history, and the `openDocVersionAt` selection contract. #86 builds on it with the per-document retention cleanup that re-baselines history and deletes only what the new baseline makes redundant.

## Task

Add `DOC_HISTORY_RETENTION_DAYS` as a positive-integer service configuration with default `30`; invalid values fail startup. One retention day is exactly 24 hours, independent of session timezone and DST. Compute the retention cutoff as `transaction_timestamp() - make_interval(hours => 24 * DOC_HISTORY_RETENTION_DAYS)`. Add `doc_history_updates(update_id bigint primary key, doc_id uuid not null references docs(id) on delete cascade, update bytea not null, created_by text not null, created_at timestamptz not null, expires_at timestamptz not null)`, its indexes, `doc_snapshot_history.through_update_id bigint not null default 0`, `doc_snapshot_history.represented_at timestamptz not null`, `doc_snapshot_history.expires_at timestamptz`, and `docs.history_available_from timestamptz`. New history rows use `expires_at = created_at + make_interval(hours => 24 * DOC_HISTORY_RETENTION_DAYS)`; rolling baseline checkpoints use NULL expiry. Pre-cutover history is explicitly unavailable. Each appended current update is mirrored with the same id, bytes, attribution, and timestamp into history in the same transaction. Current compaction may delete `doc_updates` but never history needed by the retained baseline/window. Boundary tests set the DB/session timezone to UTC and freeze the transaction clock.

New docs set history availability to `created_at`, which includes an atomic baseline write: new-doc creation inserts a full empty/current-state `doc_snapshot_history` row with `through_update_id = 0`, `represented_at = docs.created_at`, and `expires_at = NULL` in the same transaction, then sets `history_available_from = created_at`. This non-expiring baseline is used by selection and by the #86 cleanup until atomically replaced.

`openDocVersionAt(at)` rejects future timestamps with `validation_failed`; returns the empty initial doc between creation and first update; chooses the latest checkpoint whose `represented_at <= at` and replays history updates with `update_id > through_update_id` through `at` in `(created_at, update_id)` order. Equal timestamps include all rows in id order. A nonfuture time after latest update returns latest state. A time before `history_available_from` or before the configured retention cutoff returns 410 `history_not_retained`.

Every ordinary compaction reconstructs the full current state through the greatest compacted `doc_updates.update_id`, inserts `doc_snapshot_history` with `through_update_id` equal to that id, `represented_at` equal to that update's `created_at`, and `expires_at = represented_at + make_interval(hours => 24 * DOC_HISTORY_RETENTION_DAYS)`. If several compacted updates share the timestamp, the greatest id is the inclusive boundary. In one transaction under the document lock it writes the current snapshot, inserts this history checkpoint, and only then deletes current `doc_updates` through that id; mirrored `doc_history_updates` remain until retention cleanup. It never replaces/deletes the NULL-expiry rolling baseline. Reads immediately before `represented_at` cannot select this checkpoint, reads at it include every update through the boundary, and reads after it replay only greater ids. Any other existing writer of `doc_snapshot_history` rows (the periodic history squash sweep) must either write checkpoints satisfying this exact field contract under the same document lock or be removed; no checkpoint may exist without a valid `through_update_id`/`represented_at` boundary. The existing expiry-based cleanup continues to delete only `doc_snapshot_history` rows whose non-NULL `expires_at` has passed; `doc_history_updates` rows are never deleted in this part (#86 adds the re-baselining cleanup that removes them).

Populated-upgrade strategy is destructive only for already-unusable pre-cutover history: add the new checkpoint columns nullable, lock all docs, delete every existing `doc_snapshot_history` row, then insert exactly one full current-state cutover baseline per doc from `doc_snapshots` plus surviving `doc_updates`, with `through_update_id = greatest surviving update id or 0`, `represented_at = migration transaction timestamp`, and `expires_at = NULL`; set each `docs.history_available_from` to that timestamp. Only after all inserts succeed set `through_update_id`/`represented_at` NOT NULL. Pre-cutover timestamps already contractually return 410, so no old ambiguous checkpoint remains selectable. A populated migration test seeds multiple old checkpoints/updates, upgrades atomically, verifies only the cutover baseline remains, and reconstructs current state.

## Scope

### In scope

- `DOC_HISTORY_RETENTION_DAYS` configuration, `doc_history_updates`, the new `doc_snapshot_history`/`docs` columns, mirrored appends, the new-doc baseline, and the populated cutover migration.
- Checkpoint-writing compaction and the `openDocVersionAt` selection contract.

### Out of scope

- The per-document retention cleanup that reconstructs state at the cutoff, installs a new NULL-expiry baseline, advances `history_available_from`, and deletes redundant history updates/checkpoints; #86 delivers this.
- WebSocket transport, editor UI, Awareness, or business-tier retention.
- Restoring versions as the new current state; this work only reads old versions.

## Acceptance criteria

- Every timestamp at/after `history_available_from` inside the retained interval reconstructs exact state after any number of compactions; pre-migration timestamps return 410.
- Concurrent append and compaction cannot lose current or historical state.
- Requests outside retained history return a stable explicit not-retained result, not a misleading partial document; future timestamps return `validation_failed`.
- With the default configuration the read-side retention boundary is 30 days; configuration validation and just-before/at/just-after-cutoff read tests are deterministic under a fixed database clock.
- A document created after migration reconstructs its empty state before the first update and retains its NULL-expiry baseline through compaction.
- Ordinary compaction checkpoint fields and just-before/at/after read boundaries match the exact inclusive update-id contract above, and compaction never deletes `doc_history_updates` or the NULL-expiry baseline.
- Populated upgrade removes ambiguous pre-cutover history and installs one valid non-null cutover baseline per document before constraints tighten.
