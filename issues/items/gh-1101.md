Triage of harvest issue #1099, which collected two open review findings from merged pull requests. Both were verified against `develop` HEAD and both still hold.

## Specification

- Item writes made by the property type migration go through a choke-point-owned write primitive instead of raw `UPDATE items` statements in the migration job (PR #944).
- A redundant `mkdir` call and its unused import are removed from the tenant entity test (PR #1095).

## Decisions

- **Two drafts, not one.** The findings share no code, no test and no review surface; bundling them would make a finding on the larger change block the trivial one.
- **A new choke-point primitive instead of `updateItemWithClient` for #944.** `updateItemWithClient` merges patches with `||` and cannot remove a key, refuses soft-deleted rows, and fires hooks and heartbeats; using it would change the migration's behavior. The primitive lives in `chokePoint/`, so the choke-point stays the single owner of item writes, and it keeps the same SQL.
- **The same bypass in `moduleDataMigration.ts` is not covered.** The finding did not flag it, and the triage fixes only what was flagged.
- **#944 is not blocked on #1016 or #1077.** Both open issues edit `propertyTypeMigration.ts`, but in other regions (`enqueuePropertyTypeMigration` and a `console.error` line); the batch loop is untouched by either.

## Rejected and already-fixed findings

None: both findings were verified `valid`.
