## Behavior specification

Calendar ICS subscriptions.

## Decisions

Decisions adopted while drafting, and questions still open for the product owner (per chunk of the batch):

### Decisions: calendar-ics-1

#### (a) Adopted decisions
- Are ICS subscriptions part of v1? -> yes, as planned -> Decided by the product owner: ICS subscriptions are a general mechanism for custom calendar URLs. Czech public holidays are computed by code (calendar recurrence work), not a preset subscription, so the seeded holidays calendar has `kind` `system` (#1600). Adding a URL in the app comes with the interface design.
- Fetch interval and size limit -> hourly (minute 25), 20 s timeout, 5 MiB body cap, 100 subscriptions per tenant per run, redirects fail (#1960) -> Decided by the product owner: hourly with a 5 MiB cap and no user-triggered refresh; v1 stays lean.
- Accepted URL schemes -> Decided by the product owner: `webcal://` URLs are accepted and the server rewrites them to `https://` on save; they then pass the same SSRF protection (baseline outbound URL rule) as any other URL; every other scheme except `https:` is rejected (#1925).
- subscriptionUrl only on calendars of kind subscription; null/empty clears it.
- Feed state (ETag, Last-Modified, last status) -> new table `calendar_feed_state`; validators advance only after a successful import.
- Feed parsing -> `ical.js` pinned dependency (new).
- Floating times are treated as tenant wall-clock; all-day end stored inclusive.
- Disappeared events -> soft-deleted (30-day purge); a reappearing UID is a new item -> Decided by the product owner: they go to the trash for 30 days, because tasks and recordings may be linked to an event and deleting must be reversible.
- Split (one issue = one mechanism): #1962 now only adds the `subscribedEvents` database; importing a feed and showing subscribed events in the timeline are #2004 and #2005.
- Recurrence in the import -> RRULE ignored (single occurrence), RECURRENCE-ID rows skipped; #1966 adds recurrenceRule/exceptionDates/recurrenceId, supported RRULE parts FREQ, INTERVAL, COUNT, UNTIL, BYDAY, BYMONTHDAY, BYMONTH; unsupported rules show once.

#### (b) Open questions remaining for the product owner
- None.

#### (c) User-visible behavior
A user can add a subscription calendar by an https or webcal feed URL (a webcal URL is stored as https). The server periodically downloads the feed for each tenant and shows its events in the calendar timeline as read-only entries, converted to the user's own time zone (a 09:00 New York meeting shows at 15:00 in Prague). Events removed from the feed disappear from the calendar (they stay in the trash for 30 days), repeating events appear on the right days with exceptions and changed occurrences, and an unreachable or broken feed never removes events already shown.
