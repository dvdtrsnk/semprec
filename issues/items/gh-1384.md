## Context

Model tier rationale: One change to a single resolution function, but it alters how threads merge for every ingested message, so the existing threading fixtures and the cross-mailbox case both need careful verification.

The same message delivered to two of the user's mailboxes (a newsletter sent to a Gmail and an Outlook address, or the first message of a conversation) is stored as two Emails items, one per mailbox, keyed by `(mailbox_item_id, message_id)` in `mail_message_meta`. `resolveThreadId` (`backend/packages/data/src/mail/threading.ts`) only looks at ancestors named in `In-Reply-To`/`References` and at already-synced descendants. A copy with no ancestors and no descendants therefore starts a new thread in the second mailbox, so one conversation appears as two threads. Cross-mailbox threading was explicitly left out of scope in the original threading work.

Decision: a row with the same `message_id` in another mailbox is treated as the strongest evidence and consulted first; its `thread_id` is joined, and any other threads found through ancestors and descendants are merged into it with the existing `reassignThread`. If several other-mailbox rows carry different thread ids, the first by a stable order (lowest `thread_id`) wins and the rest are merged into it.

The thread list (#1567) depends on this so one conversation is one row. Existing data is repaired by #1570.

## Task

Load `state-writes` and `testing`.

1. In `resolveThreadId`, before the ancestor lookup, select `thread_id` from `mail_message_meta` where `message_id = input.messageId` and `thread_id IS NOT NULL` (any mailbox). Add those ids to the set of found thread ids, ordered so the target chosen for merging is deterministic.
2. Keep the ancestor and descendant lookups and the merge via `reassignThread` as they are; the same-message-id thread becomes the merge target when present.
3. Update the doc comment of `resolveThreadId` so it states that a same-`message_id` row in another mailbox is consulted first.
4. Add tests (new file `backend/packages/data/src/mail/__tests__/threadingCrossMailbox.test.ts`): a message with no ancestors ingested into mailbox B after mailbox A joins A's thread; a message whose copy in mailbox A is in a thread with an ancestor ends in that thread in mailbox B; two pre-existing separate threads bridged by this message are merged and the emptied `mail_threads` row is deleted; two messages with different ids are not merged.

## Scope

### In scope

- Same-`message_id` lookup across mailboxes inside `resolveThreadId`.

### Out of scope

- Merging threads that already exist in stored data: #1570.
- Threading messages sent from Semprec: #1474.
- Any change to the `(mailbox_item_id, message_id)` identity of Emails items.

## Acceptance criteria

- When the same newsletter (same `Message-ID`, no ancestors) is ingested into two mailboxes, then both `mail_message_meta` rows have the same `thread_id`.
- When the copy in the second mailbox also references an ancestor that lives in another thread, then both threads are merged into one and the unused `mail_threads` row is deleted.
- When two messages have different `Message-ID`s and no ancestry, then they stay in separate threads.
- Existing threading tests still pass.
