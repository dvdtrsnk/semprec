**Blocked by:** #143

## Context

Authentication supplies `users.locale`, while system labels are still stored as mandatory Czech text. This slice creates language-neutral storage for database and property names without translating user content: `databases` gains the stable `key` that `properties.key` already has, and system names become nullable overrides. #145 applies the same override pattern one level down to `select`/`multi_select` options, #146 ships the catalogs that translate the keys, and #147 wires the resolver into API and AGENT.md.

## Task

Add unique stable `databases.key` values using English camelCase. Make `databases.name` and `properties.name` nullable for system entities, while service validation requires names for `system=false` entities. Assign all ten system database keys and convert their built-in labels (the ten system databases' `name` and the `name` of their built-in properties) to null overrides. Update validators, serializers, and seeds for the new column and the nullable names. Until #147 wires the catalog resolver, a serializer that needs a display string for a null name emits the raw `key` — the last step of the fallback chain that #146 implements — as a placeholder, not a translation.

## Scope

### In scope

- Schema/data migration for `databases.key` and nullable names, all ten system database keys, conversion of built-in database and property names to null, validation of `system=false` names, seed/validator/serializer updates.

### Out of scope

- Conversion of `select`/`multi_select` options to `{ key, label? }` and the typed-filter updates — delivered by #145.
- Translation files and resolution, delivered by #146.
- Translation of user-created content.

## Acceptance criteria

- Every system database has a stable unique English camelCase key and null default name; user-created entities cannot be created nameless.
- Built-in properties of system databases have null names after migration; user-created properties keep their names unchanged.
- Migration tests cover the upgrade from the current schema and prove a duplicate `databases.key` is rejected.
