**Blocked by:** #146

## Context

Canonical storage and catalogs exist. All system-label projections must now use them consistently from the authenticated user's locale.

## Task

Resolve database names, property names, option labels, view-type names, and agent-tool labels in API response serializers using the authenticated user's `users.locale`; do not accept a locale query/body override. Preserve canonical keys and stable stored values in the response beside display labels where clients need both. Apply the same resolver and locale to runtime-generated AGENT.md permission manifests so the next generation reflects a locale change without persisted manifest edits. Ensure explicit stored overrides win in both API and AGENT.md. Leave user-authored content byte-for-byte unchanged.

## Scope

### In scope

- API and generated-manifest projections plus integration tests for cs/en/fallback/override behavior.

### Out of scope

- Frontend static chrome, locale settings UI, third languages, or translation of user content.

## Acceptance criteria

- The same authenticated user receives matching localized labels from API and generated AGENT.md.
- No request parameter can override `users.locale`; a later locale change affects the next response/generation.
- Snapshot tests prove user-authored names and content are unchanged and overrides win across locales.
