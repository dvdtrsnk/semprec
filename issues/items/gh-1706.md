**Blocked by:** #1655
**Model tier:** high

## Context

Model tier rationale: A second outbound integration that adds a per-service secret and a bearer-authenticated request, where a leaked key in an exception message would be a security defect, so the same hardening as the books source is required.

After #1655, the library job has a source dispatcher, a result outcome (`found | notFound | error`, `errorCode`, `source`, `candidates`) and a safe cover download. The Movies heartbeats are configured with `source: "tmdb"` by #1575, but no TMDB fetcher exists, so the dispatcher refuses that source.

TMDB provides the movie or series year, whether the title is a movie or a series, the poster, the vote average (stored as a percentage in `secondaryRating`, for example 79) and a page URL (`sourceUrl`). The Movies properties `year`, `type`, `cover`, `secondaryRating` and `sourceUrl` exist already (`seed/seedLibraryModule.ts`).

Decision: the label for the source rating is derived from the host of `sourceUrl` (so it is `themoviedb.org` for TMDB), not a hardcoded domain and not a new stored field; the client shows the host.
Decision: the source rating comes from TMDB, not from ČSFD.
Decision: the TMDB v4 read access token is sent in the `Authorization: Bearer` header, never as an `api_key` query parameter, because a query-string key ends up in exception text and logs. The token is read from the process environment variable `TMDB_READ_TOKEN`; when unset, the fetcher returns `error` with `sourceUnavailable` and the job is not crashed.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add `backend/packages/data/src/library/tmdbFetcher.ts` using the injected `fetch` and the safe cover download from #1655: search multi (movie and tv) by item `name` (and `year` when set), choose the best match by title and year, then read details. Map: `year` from release or first-air date, `type` `movie` or `series`, `secondaryRating` as `Math.round(vote_average * 10)` only when there are votes, `sourceUrl` the public TMDB page, cover from the poster path on the TMDB image host. Up to three other matches go to `candidates`.
2. Outcomes: no match is `notFound`; 401/403, 5xx, network errors and a missing token are `sourceUnavailable`; 429 is `rateLimited`; an unexpected body is `invalidResponse`. The token must not appear in any thrown error, result, log line or stored text; build errors from fixed strings and status codes only.
3. Register `tmdb` in the dispatcher in `libraryMetadataFetcher.ts`; pass the token from the environment in `backend/services/semprec-api/src/queueRuntime.ts` (and `worker.ts` if it composes its own fetcher).
4. Tests against recorded fixtures: "Duna: Část druhá" yields year 2024, `type: movie`, a `secondaryRating`, a `sourceUrl` and a cover; a series fixture gives `type: series`; a 401 fixture yields `sourceUnavailable` and the token string appears nowhere in the result or captured logs; a 429 fixture yields `rateLimited`; a poster URL on a private address is refused.

### Out of scope

## Acceptance criteria

- When the TMDB fixture for "Duna: Část druhá" is used, then the item gets `year` 2024, `type` `movie`, a `secondaryRating`, a `sourceUrl` on the TMDB host and a cover.
- When the fixture is a series, then `type` is `series`.
- When TMDB answers 401, then the result is `error` with `sourceUnavailable`, and the token appears in no error message, result, stored `item_automation.error` or log.
- When `TMDB_READ_TOKEN` is unset, then no request is made and the result is `error` with `sourceUnavailable`.
- When the poster URL resolves to a private or link-local address, then the cover is skipped and the other fields are still applied.
- When the item has a user-entered `year` or `type`, then those values are unchanged.
