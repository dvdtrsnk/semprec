## Context

Model tier rationale: One known mechanism (a new many-to-many relation added in the seed and in a per-tenant cutover) following an existing pattern, with a populated-install schema change that needs care.

A file can be attached to a calendar event (for example a proposal PDF attached to a client meeting). Today the relations of Files are `area`, `projects`, `companies` and `healthRecords` (`backend/packages/data/src/seed/seedTenDatabases.ts`), and Emails have `attachments` to Files; there is no relation between Files and Events. Because the Events and Files schemas are locked after seeding, populated installs need a code-level per-tenant cutover, the same shape as `transcription/transcriptsCatalogCutoverMigration.ts`.

Decision: the relation is `Events.files` many-to-many with the inverse `Files.events`, owned by the user (`owner: user`). The task attachment relation (`Tasks.files` with `Files.tasks`) is created by #1540 and is not touched here.

This issue only creates the relation. Attaching a file during upload is #1645. Skipping transcription of audio attached to an Event is #1698 and inheriting an attachment's project from its Event is #1756; both use the relation created here. Czech labels depend on #1413.

Shared-file ordering: this issue also waits for #1997 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `canonical-keys` and `testing`.

1. In `seedTenDatabases.ts`, add the relation Events `files` (name "Files") to Files with inverse `events` (name "Events"), cardinality `many_to_many`, owner `user`, using the same `relate` helper as the other Files relations.
2. Add i18n labels for the new properties to `seed/i18n/cs.json` and `en.json` following the existing `property.<module>.<key>` naming.
3. Add an idempotent per-tenant cutover `backend/packages/data/src/blobs/eventsFilesRelationCutoverMigration.ts` (pattern: `transcriptsCatalogCutoverMigration.ts`: lock `properties`, check, create the two properties, the relation definition and the config pointers with raw SQL because the locked schema rejects the normal helpers), register it in `runTenantCutoverMigrations`, and no-op when either database is missing.
4. Tests: a fresh seed has both sides; the cutover adds them on an install seeded before this change and a second run changes nothing; attaching a Files item to an Event through the relation is visible from both sides.

## Acceptance criteria

- When a fresh tenant is seeded, then Events has a `files` relation and Files has an `events` relation, both many-to-many.
- When the cutover runs on a tenant seeded before this change, then both properties exist; running it again changes nothing.
- When a file is linked to an event, then the event lists the file and the file lists the event.
- When the Events or Files database is missing, then the cutover does nothing and does not fail.
