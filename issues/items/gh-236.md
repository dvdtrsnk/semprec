**Blocked by:** #145, #115

## Context

System data now carries canonical keys and optional overrides (#235, #145). Translation resources belong beside each module manifest and must be loaded as immutable deploy-time state. This slice delivers the mechanism — catalog format, registry loading and validation, and the pure resolver — verified against the catalogs of one reference module. #146 then authors complete Czech and English catalogs for every system module, and #147 wires the resolver into API responses and AGENT.md.

## Task

Define `i18n/cs.json` and `i18n/en.json` beside a module manifest as flat JSON dictionaries whose keys are hierarchical strings using the canonical English keys: `database.<db>.name`, `property.<db>.<property>.name`, `property.<db>.<property>.option.<option>`, `viewType.<type>.name`, and `agentTool.<tool>.label`; values are strings. Extend `ModuleRegistry.loadModule()` to load and validate both catalogs into memory alongside the manifest and fail startup on malformed files, duplicate module resources, or non-string values; a module without an `i18n/` directory loads with empty catalogs until #146 adds them. Implement one pure resolver taking an explicit override, requested locale, English reference catalog, and raw canonical key, in that exact fallback order. Ship the `cs.json`/`en.json` of exactly one system module (the Tasks module) as the reference: move its existing Czech labels without semantic changes and add its English labels.

## Scope

### In scope

- Catalog format, registry loading/validation, the pure resolver, and the reference module's cs/en catalogs with their tests.

### Out of scope

- Catalogs for the remaining system modules and the exhaustive key-coverage tests — delivered by #146.
- Runtime-editable translation tables and third locales.
- API/AGENT.md integration, delivered by #147.

## Acceptance criteria

- Registry tests load the reference module's cs/en files and reject malformed resources, duplicate module resources, and non-string values deterministically.
- Resolver tests prove override, requested locale, English, and raw-key precedence.
- A module without catalogs still loads, and startup succeeds with the current set of modules.
