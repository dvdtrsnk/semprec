**Blocked by:** #237, #132, #137, #143, #147

## Context

Issue #237 delivers the durable `notifications` schema, kind catalog, transaction-bound writer, deduplication contract, and the heartbeat reference producer. The remaining state transitions that require user action still persist only their source state. This slice integrates the writer at each of them so every notifiable event is written atomically beside its source row; #150–#152 then register devices, deliver, and synchronize read state.

## Task

Integrate the writer from #237 at: approval request creation (`kind = 'approval_pending'`); every transition of `agent_runs.status` to `error` including startup sweep, budget rejection, and unrecoverable execution (`kind = 'agent_run_error'`); item automation error (`kind = 'automation_error'`); and mail sync error (`kind = 'mail_sync_error'`). Each integration runs in the same transaction as the source write, supplies the ready-made localized title and target link (approval queue, the specific item, or the mailbox), and identifies its transition instance per the #237 deduplication contract so a replay of the same transition does not duplicate the notification.

## Scope

### In scope

- Atomic producer integrations for approval creation, the three `agent_runs` error paths, item automation, and mail sync, with replay-deduplication tests for each.

### Out of scope

- Schema, kind catalog, writer, and the heartbeat producer — delivered by #237.
- Implementing observability or restore-check producers; their kinds are reserved only.
- Push registration and delivery.

## Acceptance criteria

- Rolling back any of these source transactions also rolls back its notification; committing exposes both.
- Tests cover every named producer and prove replay does not duplicate the same event.
- Together with #237, every kind in the initial (non-reserved) catalog has exactly one integrated producer path per source transition.
