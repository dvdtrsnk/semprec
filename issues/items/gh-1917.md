## Context

Model tier rationale: Moves a conversation's messages across accounts by rewriting system-owned folder edges and recording durable provider moves in one transaction, with provider-specific failure cases, and also switches a client path.

Archiving and deleting a conversation do not work today. The web triage (`web/src/views/mailbox/triage.ts`) changes the `Emails.folder` edges through the generic relation API, but that relation is system-owned by the Emails module (`chokePoint/relationEdgeContext.ts`), so the write fails with 403 `owner_violation`. Moves are not written to providers (#1746 adds the durable queue and the provider writes). Gmail archived mail needs the synthetic Archive folder (#1496). Flag state for moved messages is handled by earlier issues (#1893).

Decisions: both routes act on the counted messages of the thread in every account; `archive` moves only messages currently in an inbox folder, `trash` moves all of them; the target folder is the one with the matching `specialPurpose` in each message's own mailbox (for a Gmail API account the synthetic Archive); the local edge move uses `EMAILS_RELATION_CONTEXT` and the desired move is recorded in the same transaction; nothing is deleted permanently, and an archived or trashed thread can be restored to the inbox (decided by the product owner; the restore route is #2033, building on these routes). If a mailbox has no Archive folder (IMAP without an `\Archive` folder) the call fails with 409 `mail_archive_folder_missing` and nothing is changed; a trash of a thread whose messages are all already in Trash or Junk fails with 409 `mail_thread_already_trashed`; a mailbox without a Trash folder fails with 409 `mail_trash_folder_missing`. Each successful call sends one `mailThread` invalidation after commit.

Shared-file ordering: this issue also waits for #1912 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling` and `testing`.

1. Implement `POST /api/mail/threads/:threadId/archive` and `POST /api/mail/threads/:threadId/trash` in `mail/mailThreadRoutes.ts`, declared in `mailModuleManifest.ts` (`handlerExport` `createMailThreadArchiveRouteHandler` and `createMailThreadTrashRouteHandler`, justification `transactional-semantics`) with `routeMatrix.ts` entries. Resolve merged ids and return 404 for unknown or foreign ids, using the helpers of `mailThreadActions.ts`.
2. In one transaction: for each selected message find the target folder of its mailbox, remove its current folder edges and create the target edge (preserving nothing from the old UID metadata), and call `recordDesiredMailMessageMove`; then enqueue the account sync through `enqueueMailAccountSync`. Fail with the 409 codes above before writing anything.
3. Response `{ threadId, moved: <number of messages> }`.
4. Switch the web triage actions (`web/src/views/mailbox/triage.ts`, `web/src/views/mailbox/mailOperations.ts` as needed) from relation edits to these two routes.
5. Add tests: archive removes the thread from `box=inbox`; messages outside the inbox are not touched by archive; trash moves everything; Gmail uses the synthetic Archive; IMAP without an archive folder returns 409 and changes nothing; trash of an already trashed thread returns 409; move rows are recorded as pending; one invalidation per call; the web triage uses the routes.

## Scope

### In scope

- The archive and trash routes, local edge moves, desired-move recording and the web triage switch.

### Out of scope

- The durable queue and provider writes: #1746.
- Permanent deletion.
- Restoring a thread from Archive or Trash: #2033 adds the restore route.
- Creating a missing IMAP Archive folder; the decision is to fail.

## Acceptance criteria

- When a thread is archived, then it disappears from `box=inbox` and its inbox messages are in the Archive folder of their mailboxes.
- When a thread is trashed, then all its messages are in Trash and nothing is permanently deleted.
- When an IMAP mailbox has no Archive folder, then archive returns 409 `mail_archive_folder_missing` and no edge changes.
- When a thread is already only in Trash or Junk, then trash returns 409.
- When a call succeeds, then each moved message has a pending move row and exactly one `mailThread` invalidation is sent.
