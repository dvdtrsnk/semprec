## Context

Model tier rationale: One debounced background job over the existing doc-write and queue seams, but it reads a document into item state after commit and must tolerate moved, trashed and foreign references.

The title of a subpage is the text of its `page` block in the parent document (#1393), and clients edit that text directly through the sync socket, which writes Yjs updates and never touches items. The Pages item's `title` property is only a mirror that the trash list, breadcrumbs, export, item reads and search use without loading the parent document. #1725 keeps the mirror in step for renames made from the subpage screen; edits typed in the parent are not covered. Every document write goes through `appendDocUpdateWithClient` (`backend/packages/data/src/docs/docPersistence.ts`), where #1658 already enqueues a debounced page-text job (`jobKeyMode: "preserve_run_at"`, because the default `replace` mode would push the run time forward for as long as the user keeps typing). This issue adds a second, independent job in the same place.

Decisions:
- Debounce: the job runs 10 seconds after the first change (`preserve_run_at`), so a burst of typing yields one run with the original time.
- Direction: block text to the item only. The job never writes a document.
- A page block is mirrored only when the Pages item is live and its `parentItemId` equals the document's item; a moved or foreign reference is left alone.
- The mirrored title goes through `normalizePageTitle` truncated to the length limit instead of failing.

Decision (batch 38 R1 reconciliation): R1 reconciliation: reserve and recheck the live host before loading its page and writing child mirrors; host, document and child locks follow compatible existing owner order. A trash committed before reservation produces no mirror writes. Host-to-subpage trash cascade remains owned by later lifecycle work.

## Task

Load `state-writes`, `io-hardening` and `testing`.

1. In `appendDocUpdateWithClient`, after the existing enqueue of #1658, enqueue the task `pageTitleMirror` with the document id's item id, `jobKey` `page-title-mirror:<itemId>`, `jobKeyMode: "preserve_run_at"` and `runAt` 10 seconds ahead; skip documents of kind `canvas`. Register the task name, `api` affinity and tenant tenancy in `backend/packages/queue/src/index.ts` and its handler in `backend/packages/data/src/worker.ts`.
2. The handler loads the document of the item (a completed no-op when the item or document is missing or trashed), reads its blocks with `readPageBlocks`, collects the `page` blocks, loads the referenced Pages items in one query, and for each live item whose `parentItemId` equals the document's item id and whose `title` differs from the normalized plain block text, updates `title` through `updateItemWithClient` with the allowed system key.
3. Tests: typing a new title in the parent's page block updates the Pages item after the job runs; a burst of edits yields one job with its first run time; a block that points to a trashed page, to a page of another parent, or to an unknown id changes nothing; a title with a line break is stored with a space; a canvas document enqueues nothing; breadcrumbs and the trash read the new title afterwards.

## Scope

### In scope

- The debounced job that copies edited `page` block text onto the Pages items' `title`.

### Out of scope

- Renaming from the subpage screen: #1725.
- The page-text search job: #1658.
- Showing trashed pages with their title: #1855.
- Mirroring a title the other way (item to block).

## Acceptance criteria

- When a title is typed in a parent document and the job has run, then the Pages item's `title` equals the block text.
- When the parent is edited repeatedly within 10 seconds, then one job runs and its run time is that of the first edit.
- When a block references a trashed page, a page of another parent or an unknown id, then nothing is written for it.
- When a canvas document is written, then no job is queued.
