**Model tier:** medium

## Context

Model tier rationale: One queue-based fan-out mechanism over existing hook points and the backfill machinery from the first search issue, with several triggers but a single reindex path and existing fixtures.

#1397 writes an item's search document in the same transaction as its own write. That document also contains text that belongs to other items: the title of the project, area, people and company an item links to, the area derived through its project, and, for a Journal day, the text of its Inbox entries. When such text changes, the document of every item that shows it goes stale unless it is rebuilt. Today nothing does that, and the choke point's hooks do not fire for edge deletes, soft-delete or restore.

This issue adds the fan-out. It builds on the relation edge changed hook from #1530 (runs after an edge is written or deleted) and the item delete and restore hooks from #1601, and reuses the batch reindex task `itemSearchBackfill` and `indexItem` from #1397. The profile language change in #1704 will call the tenant-wide helper this issue exports.

Decisions:
- Reindex work is queued, not done inside the write: it runs on `tenantLane("item-search-index")` with `jobKey` set to the item id and `jobKeyMode: "replace"`, so repeated changes collapse into one run. Jobs that cover a set of items (a database, a tenant, the items of a project) use a key that names the scope, and chunk their work per `docs/adr/2026-09-28-chunked-transactions-for-large-background-sweeps.md`.
- Dependents are looked up when the job runs, not when it is queued, so a large referrer set is never expanded inside the write transaction.
- Emails are never reindexed here (mail owns its rows).

Shared-file ordering: this issue also waits for #1642 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `testing` and `io-hardening`.

1. Add a core task `itemSearchReindexDependents` (name, `api` affinity and tenant tenancy in `packages/queue/src/index.ts`, handler registered in `worker.ts`) with payloads `{ kind: "item", itemId }`, `{ kind: "referrers", itemId, afterItemId? }` and `{ kind: "projectItems", projectItemId, afterItemId? }`. `item` re-runs `indexItem`; `referrers` reindexes every non-deleted item that has a relation edge to `itemId`, in committed chunks; `projectItems` reindexes the items related to a project (tasks, events, files, health records) in chunks. Put the enqueue helpers and handler in `search/itemSearchFanout.ts`.
2. Register hooks in `domainWriteHooks.ts` that enqueue, all in the write transaction:
   a. after an edge is written or deleted (hook from #1530): `item` for both ends; when the edge is a Projects area edge, also `projectItems` for the project;
   b. on an item update that changes the `title` property: `referrers` for that item, and when the item is an Area, also `projectItems` for each of its projects (the rename must reach the tasks of those projects);
   c. after a soft-delete and after a restore (hooks from #1601): `referrers` for the item;
   d. on a create or update of an Inbox item: `item` for the Journal day it points at through `journalDay`.
3. On property create, patch and delete (`chokePoint/propertyOps.ts`), enqueue the existing `itemSearchBackfill` for that database with `onlyMissing: false` through the helper from #1397.
4. Export `enqueueTenantSearchReindex(client)` that enqueues the tenant-wide `itemSearchBackfill` with `onlyMissing: false`, for the profile language change (#1704) to call; this issue does not change how the language is stored.
5. Tests: each trigger enqueues the expected job and, after the job runs, the dependent's row reflects the change; repeated changes to one item collapse to one job.

## Scope

### In scope

- Queued reindex of items whose document depends on another item, on edge writes and deletes, title changes, soft-delete and restore, Inbox entry changes, project area changes, area renames, and schema changes of a database.
- The tenant-wide reindex helper.

### Out of scope

- The document builder, hooks for the item's own write, the backfill task and the deploy backfill: #1397.
- Changing `users.locale` itself and calling the tenant-wide helper from it: #1704.
- Making the edge, delete and restore hooks themselves: #1530, #1601.
- Reindexing on permanent purge: referrers were already reindexed when the item was soft-deleted, and purge removes the item's own row.
- Excluding trashed items from search results: #1842.

## Acceptance criteria

- When a project is renamed and the queued job has run, a search document of each of its tasks contains the new title and not the old one.
- When a project is moved to another area and the job has run, its tasks contain the new area title and not the old one.
- When an area is renamed, the items of its projects contain the new area title.
- When a person is removed from an event and the job has run, the event's document no longer contains the person's name.
- When a project is soft-deleted, the documents of its tasks stop containing its title; after restore they contain it again.
- When an Inbox entry changes, its Journal day's document is rebuilt.
- When a text property is added to a user-created collection and the job has run, existing items' values for it are searchable.
- Changing a project's title three times in a row leaves one queued job for that project.
