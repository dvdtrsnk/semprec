## Context

Model tier rationale: The existing Postgres fixture needs a same-backend check from a separate observer to distinguish idle connections from idle open transactions.

- PR #1114, finding `5af39c2f2e`, `backend/packages/data/src/__tests__/tenantScopePool.test.ts:123`: The syntax-error test selects an unused status column and checks tenant settings without directly establishing that the failed connection has no open transaction.

## Task

Repair the existing scoped-syntax-error cleanup test so it proves transaction cleanup on the same physical connection. Use the existing single-connection pool and record its backend PID before the scoped failure. After the rejection and reuse, require that PID to be unchanged, and observe that backend from a separate connection using `pg_stat_activity`: it must be `idle` with `xact_start IS NULL`. Preserve the original Postgres `42601` and tenant-setting reset assertions. Remove the unused `txid_current_if_assigned()` projection and its incorrect `status: string` type. Add a local control showing that the observer distinguishes an open read-only transaction from an idle backend, cleaning up the control transaction in all cases; an unassigned transaction ID alone is insufficient.

## Touches

- backend/packages/data/src/__tests__/tenantScopePool.test.ts (syntax-error cleanup test and its local observer/control only)

## Scope

### In scope

A direct, same-backend transaction-cleanup assertion and a control for that observation.

### Out of scope

Production pool behavior, changes to other pool tests or the tenant-scope contract.

## Acceptance criteria

- For finding `5af39c2f2e`, the scoped syntax error retains code `42601`; the reused backend has the original PID, no tenant setting, state `idle` and a null transaction start. The same observer identifies a deliberately open read-only transaction as non-idle/in-transaction, so an unassigned transaction ID cannot make the cleanup check pass accidentally.
