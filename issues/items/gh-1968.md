**Model tier:** medium

## Context

Model tier rationale: One conversion job following the metadata job's pattern, with a bounded external-tool call and an atomic blob swap, but its availability depends on a codec in the host's media tool.

HEIC is the iPhone's default photo format. Today the client converts to JPEG before upload and the backend does not accept HEIC at all (#1963's allowlist excludes it; #1410 only recognises HEIC bytes). This issue is implemented only if the product decides that the server converts: it is the server-side fallback for clients that cannot convert.

The job runs in `semprec-transcribe`, the only process allowed to run `ffmpeg` (`docs/adr/2026-09-22-ffmpeg-confined-to-semprec-transcribe.md`), after the metadata job of #1965. The Files collection and its upload (#1661, #1412, #1588) are unchanged by it.

Decisions:
- The conversion replaces the attachment's blob: a JPEG at quality 90 with the long side unchanged, the original bytes' orientation applied. The attachment keeps its `attachmentId`, `source` and position; the old HEIC blob is released if nothing else uses it.
- If the host's `ffmpeg` cannot decode HEIC, the job records `metadata.conversion = "unsupported"` and leaves the attachment as is; it never fails the capture. Deployment support for the codec is checked by a test that skips when the codec is missing.
- Once the attachment is converted, the metadata job of #1965 runs again on the JPEG (its job key includes the blob id).


Shared-file ordering: this issue also waits for #1965 because both edit the same files listed in Touches.

## Task

Load `io-hardening`, `state-writes` and `testing`.

1. Add `image/heic` to `INBOX_ATTACHMENT_MIME_TYPES` in `backend/packages/data/src/inbox/attachmentTypes.ts` and allow HEIC bodies at `POST /api/blobs` (detector from #1410).
2. Add the core task `inboxAttachmentHeicConvert` (affinity `transcribe`, tenant lane) in `packages/queue/src/index.ts`, enqueued from the capture transaction for an attachment whose blob is HEIC (job key `inbox-attachment-heic:<attachmentId>`), and register it in `backend/services/semprec-transcribe/src/queueRuntime.ts`.
3. Implement the handler in `backend/services/semprec-transcribe/src/inboxAttachmentHeicConvert.ts` using a new `convertHeicToJpeg` helper in `mediaNormalization.ts` (timeout, partial-output cleanup, validated output). In one transaction create the JPEG blob, point the attachment to it, release the HEIC blob, enqueue the metadata job for the new blob, and remove the old bytes after commit.
4. Tests: a HEIC attachment becomes a JPEG attachment with the same id and position and the HEIC blob is gone; the codec-missing case records `metadata.conversion = "unsupported"`; a rerun is a no-op; a corrupt HEIC records an error; a foreign tenant's attachment is untouched.

## Scope

### In scope

- The HEIC to JPEG conversion job for Inbox attachments and accepting HEIC at upload.

### Out of scope

- Converting HEIC uploaded to Files: not planned; Files keeps recognising the type only.
- The metadata job and previews: #1965.
- The upload and Files collection changes of #1661, #1412 and #1588.

## Acceptance criteria

- When a HEIC photo is attached, then the attachment ends with a JPEG blob, the same attachment id, and no HEIC blob remains.
- When the host cannot decode HEIC, then `metadata.conversion` is `unsupported` and the capture is unaffected.
- When the job is repeated, then nothing changes.
