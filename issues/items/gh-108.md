**Blocked by:** #106

## Context

Core needs one typed contract for modules without module-id branches or runtime discovery.

## Task

Define `ModuleManifest` with `id`, `version`, `name`, `removable`, `systemProject`, `databases`, `capabilities`, `agentTools`, optional `viewTypes`, `heartbeatActions`, `heartbeatRuleKinds`, `taskNames`, `workers`, and `migrations`. A task descriptor includes exactly `name`, `payloadSchemaExport`, and `handlerExport`; affinity-safe runtime ownership is deliberately added later by #91. Implement `ModuleRegistry.loadModule(path)` using an explicit known-path dynamic import. Validate duplicate identifiers and every named handler/schema export at load, failing startup loudly. Read `modules.active` at runtime. Expose only narrow typed projections for each aspect. Filter agent tools out entirely when their capability is absent.

## Scope

### In scope

- Types, loading, activation, structural validation, projections, and capability filtering.

### Out of scope

- Directory scanning, hot installation, task registration, and runtime worker hosting.

## Acceptance criteria

- Invalid exports and duplicate ids or names prevent startup; affinity validation is deferred to #91.
- Inactive modules disappear from every projection.
- No consumer API exposes the raw manifest.
- Ungranted tools are absent rather than present-but-denied.
