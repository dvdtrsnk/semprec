**Blocked by:** #157

## Context

JSON resources are complete. Files are the sole binary exception and must retain the same authenticated, deterministic discipline.

## Task

Implement `POST /api/files` as a raw streamed body with `Content-Type` and `X-Filename`. Enforce `maxFileSizeMb` first from `Content-Length` when present and always through a streaming byte counter; abort and clean partial state on overflow. Compute SHA-256 while streaming, deduplicate through the unique `content_hash`, and create blob metadata plus the Files database row transactionally. If existing rows already reference the blob, return the lowest-ID row deterministically. Implement authenticated `GET /api/blobs/:id` with byte ranges, `ETag=content_hash`, conditional responses, safe filename handling, and `Content-Disposition`; honor `?disposition=inline` only for a fixed safe MIME allowlist and always set `X-Content-Type-Options: nosniff`.

## Scope

### In scope

- Streaming upload/download, limits, hashing/dedup, transactional metadata, Range/ETag and response hardening.

### Out of scope

- Presigned URLs, resumable uploads, total-storage quota, and unauthenticated blob access.

## Acceptance criteria

- Unknown/chunked length cannot bypass the hard byte limit and failed uploads leave no partial blob or row.
- Concurrent identical uploads converge on one content hash and deterministic Files row.
- Range/ETag/download-name/inline-allowlist tests cover valid, invalid, and malicious inputs.
