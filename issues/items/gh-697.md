## Behavior specification (approved)

Make the backend's process lifecycle, its graphile-worker queue and the single-host deployment resilient to the ordinary failures a small production system meets every week: a deploy restart, a Postgres blip, a job re-enqueued while it is still running, an operator who ran `provision.sh` and expects the front door, the firewall and push delivery to work. After this batch: `semprec-api` shuts down in seconds with every sync client told to reconnect (1012), a dropped idle Postgres connection is a logged event rather than a process crash, a service that does crash-loop through a multi-minute database outage is still restarted afterwards, the queue runs several jobs at once while Inbox ticks stay serialized, a job superseded by its own re-enqueue can no longer dead-letter, permanently failed job rows are pruned and the alert that counts them recovers, every hosted mailbox beats its expected `mailsync:<id>` heartbeat, an all-failed doc sweep fails its job, `provision.sh` installs and enables the Caddy site and an nftables ruleset that leaves Docker's tables alone, the `semprec` user can read the APNs key, a missing push configuration fails one delivery clearly instead of ten times, a transcription in flight survives a restart at its next checkpoint, and `docker-compose.yml` runs only what is used, with only the variables it needs.

## Decisions

- **Sync server close placement** — Q: before or after `server.close()`? A: `syncServer.close()` runs immediately before `drainServer` (which owns `server.close()`), because `SyncServer.handleUpgrade` already rejects any upgrade once `close()` has run, so there is no window in which a new socket could attach. Reason: `drainServer` fuses "stop accepting" and "drain" into one promise; splitting it would change the ai-gateway-mirrored drain for no gain.
- **Pool error logging** — Q: inject the process logger into `createPool`, or log from the data package? A: `createPool` attaches its own listener logging through a package-private `createLogger("db")` (the `mail/logger.ts` precedent). Reason: keeps the fix out of the four `serve.ts` hotspots that #645, #650 and F1 edit, and covers the two CLIs for free.
- **Statement timeout** — 60 s default per connection; the migrations CLI opts out (`statementTimeoutMs: 0`) because contract-step cutovers may legitimately run longer. Connect timeout 10 s.
- **Restart limits** — `StartLimitIntervalSec=15min` / `StartLimitBurst=180` with `RestartSec=5s` unchanged: a crash loop shorter than 15 minutes never parks a unit; `RestartSec` stays so #624's `TimeoutStopSec` insertion in the gateway unit does not collide.
- **Tick serialization** — Q: one global `semprec-tick` queue or one queue per Inbox item? A: global, as `SEMPREC_TICK_QUEUE_NAME`'s existing contract states ("all Inbox ticks serialize against each other"). Reason: the Inbox is single-user capture; after #676 the tick holds no transaction across its LLM call; a per-item queue would add one `_private_job_queues` row per item forever. `createActionQueueAffinity()` becomes the real production map and is also `triggerOnItemEventHeartbeats`' default, so every write path routes ticks without plumbing.
- **Concurrency** — `QUEUE_CONCURRENCY` (default 4) is applied inside `runWorker`; explicit `concurrentJobs` wins, and the transcribe runtime pins 1 (one ffmpeg/ASR pipeline per host).
- **Superseded jobs** — Q: switch `jobKeyMode`? A: no — `preserve_run_at` has the same clearing behaviour; `unsafe_dedupe` would lose the "new information" re-run. Instead `registerTask` detects that the running job's key was cleared while it ran and completes it (log, no rethrow); the replacement job carries the work.
- **Failed-row retention** — a daily `queueFailedJobsPrune` completes (through graphile's `complete_jobs`) unlocked rows with `attempts >= max_attempts` and `updated_at` older than 7 days after logging them; `queue:permanentlyFailedJobs` counts only unlocked rows younger than 7 days.
- **Expected mail heartbeats** — `getActiveMailSyncProcessNames` joins `items` and ignores soft-deleted mailboxes, so the expected set equals the hosted set.
- **Push config missing** — a new `not-configured` send outcome marks the delivery `failed_permanently_at` with the reason and does *not* revoke the registration (the device is fine; the server is misconfigured).
- **Caddy environment** — `provision.sh` extracts `SEMPREC_DOMAIN` from `/opt/semprec/shared/.env` into `/etc/caddy/semprec.env` loaded by a `caddy.service` drop-in; Caddy never sees the whole secrets file. `PORT=8080` is documented in `.env.example` so `semprec-api` listens where the Caddyfile proxies.
- **nftables** — own `table inet semprec` with the `table`/`flush table` idempotence idiom, no `flush ruleset`, no `forward`/`output` chains (Docker owns forward policy for its bridges). No `Before=docker.service` drop-in: Debian's `nftables.service` is already `Before=network-pre.target` and Docker is `After=network-online.target`, and without a ruleset flush the order no longer matters.
- **Transcribe stop bound** — `TimeoutStopSec=960`: one ASR chunk worst case is ffmpeg extraction (5 min cap) + gateway call (10 min cap) + a checkpoint write. On abort the task re-enqueues itself under its own job key and completes, so no attempt is consumed.
- **Compose** — remove the `minio` service and volume outright (#649 leaves it "until a separate removal"); the `postgres` service gets only `POSTGRES_USER/PASSWORD/DB` via `environment:` interpolation from `--env-file /opt/semprec/shared/.env`. `postgres:16-alpine` stays as is.

## Out of scope

- Graph webhook rate limiting (unauthenticated endpoint with a per-notification transaction) — accepted as is.
- Release and rollback scripts (`deploy/deploy.sh` release handling verified correct), transcription ffmpeg handling (verified sound), per-tenant queue fairness (multi-tenant epic).
- Pinning `postgres:16-alpine` to a digest.
- The mail live-sync host itself (#650), blob storage paths and backup (#645, #649), the tick's transaction bracketing (#676), rollback-failure handling in `withTransaction` (#671).
