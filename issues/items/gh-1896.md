## Context

Model tier rationale: This is the user-facing send operation with an idempotency claim around an external side effect, several error outcomes the client must tell apart, and post-send state changes across threads, people and drafts.

A user sends a saved draft from the app. Today `sendDraftEmail` in `backend/packages/data/src/mail/send.ts` exists (authorization check, From check against `Mailboxes.addresses`, an atomic claim through `mail_message_meta`, SMTP, then moving the draft from Drafts to Sent) but nothing calls it, no route exists, and the web client calls an operation the backend does not have. After a double tap, a client timeout and retry must be able to learn whether the first send succeeded.

It builds on: custom routes with composition-root dependencies (#1460), the draft routes and the `mail_drafts` row (#1867), the transport interface and SMTP (#1634), the thread assigned to messages sent from Semprec (#1474), people linked to them (#1480) and mail-thread invalidations (#1816). Retiring a Semp draft once the user replies (#1902) and queuing agent sends for approval (#1913) build on it.

Decision: a mailbox in `needsReauthorization` answers an error and the draft is kept; the message is not queued for later delivery.

Decision: this route is for the user. Agent and MCP sends keep going through approval (#1913).

Shared-file ordering: this issue also waits for #1895 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `io-hardening` and `testing`.

1. Add `POST /api/mail/drafts/:id/send` (authenticated, justification `transactional-semantics`, registered in the manifest and route matrix). It loads the draft with its `mail_drafts` row and sends through `sendDraftEmail` using the transport for the mailbox's sync mode and the MIME from #1491 (with the draft's attachments), actor `user`.
2. Success returns `{ emailId, threadId, sentAt, mailbox: { id, name } }`. After the send, in the same finalizing transaction, set `mail_drafts.sent_at`, publish the mail-thread invalidation and let the thread, people-linking and Sent-folder steps of #1474 and #1480 run.
3. Errors: 400 without any recipient; 403 `from_address_not_registered`; 409 `mail_draft_already_sent` with `details { emailId, threadId }` for a repeated call (instead of `version_conflict`, so a client after a timeout can tell the outcome; nothing is sent again); 409 `mail_draft_not_editable` for a provider draft without a `mail_drafts` row; 409 `mail_reauthorization_required` when the mailbox needs reauthorization or the transport reports a revoked credential; 422 `mail_recipient_rejected`; 409 `mail_sent_folder_missing` (today a `ValidationError`); SMTP authentication failure as `mail_auth_failed` and an unreachable server as `mail_server_unreachable`. Add the codes that do not exist yet to `errorContract.ts`; `mail_auth_failed` and `mail_server_unreachable` are also added by the mailbox credential verification work, so reuse them if present.
4. A failure before or during delivery leaves the draft unsent and sendable again; the claim is undone as `sendDraftEmail` already does.

## Scope

### In scope

- The send route, its error contract, the draft's sent state and the post-send invalidation.

### Out of scope

- Sending as an agent or from MCP (#1913).
- Retiring a Semp draft after a reply (#1902).
- The web client's operation call.
- An outgoing queue for mailboxes needing reauthorization.

## Acceptance criteria

- When a reply from a Gmail or a Graph mailbox is sent, then it carries In-Reply-To and exactly one message is added to the thread both at the provider and in Semprec.
- When the send route is called twice for one draft, then one message is delivered and the second call answers 409 `mail_draft_already_sent` with `emailId` and `threadId`.
- When the mailbox needs reauthorization, then the answer is 409 `mail_reauthorization_required`, nothing is delivered and the draft remains.
- When no recipient is set, then the answer is 400; when the provider draft has no `mail_drafts` row, then 409 `mail_draft_not_editable`.
- When the send succeeds, then the draft's `sent_at` is set and a mail-thread invalidation is published.
- A draft of another tenant cannot be sent.
