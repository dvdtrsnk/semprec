## Context

Harvest issue #775 collected two findings of the same shape: a defensive branch that
can never execute given what its only caller already guarantees.

- PR #377's `inboxRouteHandlers.ts`: `parseConfirmCredential`'s
  `if (body === undefined || body === null) return undefined;` branch. Its only
  caller path is the adapter's `readJsonBody` (`adapterRoute.ts:38-51`), which
  returns `{}` for an empty body and never `undefined` — so the `undefined` half of
  this branch cannot fire in production. `readJsonBody` can still return `null`
  (a request body whose literal JSON text is `null`), so the `null` check must stay.
- PR #377's `customRouteMount.ts` dispatch logic (since moved to
  `routeTable.ts`'s `mountRoutes`): inside the `extractParams` closure,
  `if (!match) return {};`. `dispatchRoute` (`routeTable.ts:70-74`) already confirms
  `candidate.matcher.test(pathname)` before calling `route.listener`, the only caller
  of the listener that runs `extractParams` — so the re-match inside `extractParams`
  always succeeds.

## Task

- In `backend/packages/data/src/inbox/inboxRouteHandlers.ts`'s
  `parseConfirmCredential`, narrow
  `if (body === undefined || body === null) return undefined;` to
  `if (body === undefined) return undefined;`, removing only the `undefined` check —
  `body` can never be `undefined` when this function is reached through the adapter,
  but a literal JSON `null` body still can, so the `null` check must stay.
- In `backend/services/semprec-api/src/adapter/routeTable.ts`'s `mountRoutes`, inside
  the `extractParams` closure, remove the `if (!match) return {};` guard. Since
  `String.prototype.match` is typed as returning `RegExpMatchArray | null`, narrow
  `match` with a non-null assertion (`match!`) and a one-line comment noting
  `dispatchRoute` already tested the same pattern before calling this closure's
  enclosing listener.

Each change removes exactly the one unreachable branch named above — no other logic
in either function changes.

## Acceptance criteria
