**Blocked by:** #1470, #1624, #1627
**Model tier:** high

## Context

Model tier rationale: The transcription worker gains permission to write a user-owned relation, which needs an authorization ADR amendment and must not collide with value inheritance from the event.

A recording confirmed from the Inbox can name a project. #1470 gives Transcripts a `project` relation, and #1574 stores the choice in `recording_requests.project_item_id`. The worker's writes are limited by `docs/adr/2026-09-23-transcription-worker-writes-event-match-results.md`, and the create step (#1624) writes only the transcript's name, status and link.

This issue makes the create step write `Transcripts.project` from `recording_requests.project_item_id` as the transcript's own value (no inherited value link), when that project exists and is live. It builds on #1627, #1470 and #1624, and #1978 builds on it.

Decision (by the product owner): an explicitly chosen project is an own value; when the transcript is later linked to an event, inheritance from the event (#1697) does not replace it. The event's project is taken over only into an empty project.

## Task

Load `state-writes`, `adr-conventions` and `testing`.

1. In the create step, after the transcript row exists and when `project_item_id` is set and the project is live, write the `Transcripts.project` edge as a user relation with no value link, in the same transaction; a missing or trashed project writes nothing and does not fail the step.
2. The step stays idempotent: a repeated run adds no second edge.
3. Add an ADR file under `docs/adr/` amending the transcription-worker ADR: the worker may write the `project` edge in the create step, only from `recording_requests`.
4. Tests: project from the request appears on the transcript; trashed project writes nothing; repeated create keeps one edge.

## Acceptance criteria

- When a recording was confirmed with a project, then the transcript has that project right after the create step.
- When the project was deleted before the step runs, then the transcript is created without a project and the pipeline continues.
- When the step runs twice, then there is one project edge.
