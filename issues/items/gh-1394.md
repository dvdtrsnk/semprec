**Blocked by:** #1366
**Model tier:** medium

## Context

Model tier rationale: The change is a decision document, but it fixes the shape, capability and approval class of a whole operation family that several later issues implement, so a gap here propagates widely.

A page is the Yjs document of an item (`docs.item_id`, kind `page`, #1022) holding the block model recorded by #1366. Today a page cannot be reached over HTTP at all: `getDocByItemId` and `getOrCreateDoc` (`backend/packages/data/src/docs/docsStore.ts`) are internal, `docs/docsModuleManifest.ts` has no routes and no agent tools, and a document is only created by the `pageContent` confirm path, which no running process reaches. `WS /api/sync` (`backend/packages/realtime/src/docSync.ts`) is the only editing channel. The editor on iOS and macOS runs in a WebView with the shared JavaScript model; no native JSON block API is built.

Operations that clients, MCP and agents call go through the closed generic operation catalog: `GENERIC_OPERATION_NAMES` (`backend/packages/shared/src/genericOperations/operationNames.ts`, 29 names today), bound by `GENERIC_OPERATION_BINDINGS` (`bindings.ts`) and classified in `capabilities.ts`; REST, MCP and agent tools share them (`application/src/genericOperationGateway.ts`, `semprec-api/src/adapter/genericBinding.ts`). Custom routes in a module manifest are allowed only for `transactional-semantics` or `single-consumer-read`, never CRUD (`module-registry/src/manifest.ts`). Several later issues need one agreed set of page operations: reading a page as a summary or as Markdown, ensuring it exists, replacing and inserting content, creating subpages, duplicating, renaming, restoring a version and listing what Semp changed.

Decision: the page operations join the generic catalog (the recommended option) instead of custom routes in the docs module manifest, because reads and writes of a page are item sub-resources that all three transports (REST, MCP, agent tools) need with the same input validation. Each operation is implemented by its own issue.

What builds on this ADR: #1615 and #1616 (summary and ensure), #1678, #1679 (Markdown read and insert), #1676 (subpages), #1400 and #1617 (agent policy and version restore).

## Task

Load `adr-conventions`. Add one ADR under `docs/adr/` named `YYYY-MM-DD-<slug>.md` (date = the day it is written; for example `page-operation-family`), frontmatter per `docs/adr/README.md` (`status: accepted`, `area: [backend]`). It must build on the block-model ADR from #1366 and on `2026-09-17-generic-application-service-port.md` and must not contradict `2026-09-10-single-writer-ownership-model.md`.

Record, with the rejected alternative and the trade-off:

1. **The family.** Operation names and their transport shape, one operation per issue: `page.get` (`GET /api/items/:id/page`, `format: summary | markdown`, optional `limit`), `page.ensure` (`PUT /api/items/:id/page`), `page.replace`, `page.insert`, `page.createSubpage`, `page.duplicate`, `page.rename`, `page.restoreVersion` (`{itemId, at}`) and `page.changes` (`GET /api/items/:id/page/changes`). Give the HTTP path and method for every one, and state that the catalog count in `operationNames.ts` grows by one per implemented operation.
2. **Why the catalog.** Catalog versus custom routes in the docs manifest; the manifest rule that custom routes are never CRUD.
3. **Capability and approval class per operation.** Which existing capability each uses and whether a new page capability is introduced; reads need no approval; list which operations are destructive and need approval (whole-page replace, version restore, delete-like effects) and which are not. Agent grants and the page-write policy for Semp are decided in #1400 and #1844; this ADR only sets the initial classification they refine.
4. **Read semantics.** `page.get` has no side effects and never creates a document (a page without a document answers `docId: null` and zero counts); creation happens only through `page.ensure`, which is idempotent.
5. **Summary shape.** The fields of the summary response (document id, kind, title, blocks with id, type, indent, done, text, pageId, block count, subpage count, headings, last edited time and author, breadcrumbs) and which later issue fills each.
6. **Title.** The root page title is stored in a `Y.Map` named `meta` of the document and is not part of the Markdown; a project's root page defaults to the translated "Notes" title which is not stored.
7. **Errors.** 401 without a session, 404 for a foreign tenant's item, 400 for validation, 409 for a version conflict on replace.
8. **No native block JSON API** and the offline merge path (Yjs state vectors).
