**Model tier:** medium

## Context

Model tier rationale: One more additive list in the cache fed by two blockers' stores, plus recompute triggers on attachment add and remove, with a rule that the summary never exposes the original blob.

An Inbox item can carry attachments (a receipt photo, a scan, a file). The Journal day shows a small preview with a name, type and size, and for a PDF the page count. The cached day summary (`backend/packages/data/src/inbox/journalInboxCompute.ts`) has no attachments: the Inbox has no attachment store today. #1564 stores attachments as counted blob references; #1965 computes metadata (page count, a thumbnail of about 34 px) in the transcription worker, and converts HEIC photos so the preview is a JPEG. #1489 extends the same cache with the processing state and proposal summary.

Decision: the cache holds blob ids and metadata, never bytes; the preview is the thumbnail blob, not the original, so a list of items never downloads originals. The recompute is triggered where the attachment set changes, inside the attachment store's add and remove operations, so every caller (upload on capture, move into Files on confirm) is covered.

## Task

Load `state-writes`, `canonical-keys` and `testing`.

1. In `computeJournalInboxItems` add `attachments` to each summary element: `[{ attachmentId, blobId, name, mimeType, byteSize, pageCount, thumbnailBlobId, source }]` read from the store of #1564, with `pageCount` and `thumbnailBlobId` from the metadata of #1965 (`null` when not computed yet). `source` is the attachment's recorded source (for example camera, library, file); `[]` when none.
2. Call `enqueueJournalInboxRecomputeForInboxItem` in the same transaction from the attachment store's add and remove operations, so the day is recomputed when an attachment is added, removed or moved out.
3. Also recompute when the metadata of an attachment is completed (thumbnail written), so the preview appears without another edit.
4. Tests: an item with a PDF attachment lists `name`, `mimeType`, `byteSize` and `pageCount`; the preview field is `thumbnailBlobId` and never the original blob; adding and removing an attachment enqueue a recompute; an item without attachments has `[]`.

### Out of scope

- Processing state and proposal summary; #1489.

## Acceptance criteria

- When an Inbox item has a PDF attachment, then the cached element has an attachment with `name`, `mimeType`, `byteSize` and `pageCount`.
- When the item has a photo attachment, then the preview is its `thumbnailBlobId`, not the original blob.
- When an attachment is added or removed, then the day's cache is recomputed and the day item is announced.
