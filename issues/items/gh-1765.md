**Blocked by:** #1764
**Model tier:** high

## Context

Model tier rationale: Replacing a page applies a content diff under optimistic concurrency and, in the same transaction, trashes subpages whose links disappeared, so it combines concurrency control, id-preserving CRDT edits and destructive cascades.

Pages can be read as Markdown with a version token (#1678) but cannot be written back. Today all doc writes go through `mutateDocWithClient(client, docId, origin, fn)` in `backend/packages/data/src/docs/docPersistence.ts`; `getOrCreateDoc` in `backend/packages/data/src/docs/docsStore.ts` creates the doc lazily. Clients (web, desktop, the assistant) edit a page as one Markdown text and must not overwrite a concurrent edit.

This issue adds replacing the whole page body from Markdown, guarded by the ETag that #1678 returns. It builds on #1610 (atomic multi-block operations), #1676 (subpages: how a page link relates a block to a child page), #1725 (renaming a subpage, which a link-text change triggers) and #1723 (trashing a page with its subpages and parent block, which a vanished link triggers). #1844 classifies the operation for agents.

Decisions:
- A page link that disappears from the Markdown sends the subpage to the trash in the same transaction, using the trash operation of #1723. The sweep of orphaned subpages (#1749) remains a safety net only. Reason: the user removed the line, so the result must be visible immediately and atomic with the edit. Decided by the product owner: the client shows a toast with Undo for each trashed subpage, and the page stays restorable for 30 days; Undo is the restore of #1723 (`POST /api/items/:id/restore`), which puts the block back at its place.
- The title is never changed by replace. A leading `# Heading` is an ordinary `h1` block.
- A page link may only point to an existing subpage of this same page. A link to an unknown id or to a page with another parent is rejected with `400`; moving a page is not done through Markdown. Replace never creates a subpage.
- A link whose text changed renames the subpage through the rename operation of #1725.

Shared-file ordering: this issue also waits for #1764 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `canonical-keys`, `io-hardening`, `error-handling` and `testing`.

1. In `backend/packages/data/src/docs/pageMarkdown.ts` add `replacePageMarkdown(client, itemId, {markdown, expectedEtag, origin})`. In one transaction: lock and load the doc (`getOrCreateDoc`, then `mutateDocWithClient`), compare `docEtag(doc)` (from #1678) with `expectedEtag`, and fail without writing on mismatch.
2. Parse the Markdown with the parser of #1608 as consumed through #1610. Compute a block diff against the current blocks that preserves ids: pair blocks by order and content (unchanged blocks keep their id and are not rewritten; a changed paragraph in the middle keeps the ids of its neighbours); unpaired old blocks are deleted, unpaired new blocks are inserted with fresh ids. Apply the whole diff as one atomic multi-block operation.
3. Validate page links: each `semprec://page/<id>` must be a subpage of this page (per #1676); otherwise `400` and nothing is written.
4. For every subpage whose link vanished, trash it with the operation of #1723 inside the same transaction before the diff removes its block, so the trash records the block's position and a later restore puts it back at its place; then apply the rest of the diff. For every link with changed text, rename the subpage with the operation of #1725.
5. Invalid Markdown (a block type that is not allowed, a page block in a light host) returns `400`; nothing is written and no doc is created.
6. Add `PUT /api/items/:id/page.md` in `pageMarkdownHandler.ts`, body `text/markdown`, bounded body size. Missing `If-Match` returns `428`; a value that does not equal the current ETag returns `409` (the response carries the current `ETag`). Success returns `200` with the new `ETag` and the body `{ trashedPages: [{ pageItemId, title }] }` listing the subpages trashed by this request (empty when none), so the client can show a toast with Undo. Origin is `user` for a session and `ai_agent` for an agent run credential.
7. Register the operation in the generic operation catalog (name from the ADR of #1394), add the route to `routeMatrix.ts`, and export the function from the data package.
8. Tests: single-paragraph change keeps all other block ids; stale ETag `409`; no `If-Match` `428`; removing a page-link line trashes that subpage in the same transaction, lists it in `trashedPages`, and restoring it afterwards puts its block back at its former place (and a failure in the trash step rolls the text change back); a link to an unknown id or to another parent's page is `400`; changed link text renames the subpage; two concurrent PUTs with the same ETag end with one success and one `409`; a first PUT to an item without a doc creates it lazily.

## Scope

### In scope

- Replacing a page body from Markdown under If-Match, with an id-preserving diff, link validation, and same-transaction trash and rename of subpages.

### Out of scope

- Reading the Markdown and the ETag: #1678.
- Inserting at a placement: #1679.
- Creating subpages from Markdown (never done by replace); moving a page to another parent.
- Sweeping orphaned subpages as a general safety net: #1749.
- Agent capability classification, approval and grants: #1844.
- Restoring an earlier version of a page: #1617.

## Acceptance criteria

- When a PUT changes only one paragraph, then every other block keeps its id.
- When `If-Match` is missing, then the response is `428`; when it is stale, then `409` and the doc is unchanged.
- When the new Markdown drops the line `[Release checklist](semprec://page/X)`, then subpage X is in the trash after the same request, the text change is committed together with it, and the response lists X in `trashedPages`.
- When X is then restored (Undo), then its block is back at the position it had before the request.
- When a link points to an unknown id or to a page of a different parent, then the response is `400` and nothing changes.
- When a link's text changes, then the subpage title changes accordingly.
- When the item has no doc, then a PUT with the empty-doc ETag creates it and the content appears.
- When two PUTs race with the same ETag, then exactly one succeeds.
