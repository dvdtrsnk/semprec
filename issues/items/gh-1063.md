**Blocked by:** #996

## Context

`deploy/nftables.conf` filters inbound traffic only. It has one `input` chain and no `output` chain (`deploy/nftables.conf:13-27`), so every Semprec process may connect anywhere: loopback services, the private network the host sits on, and cloud metadata addresses (`169.254.169.254`). That matters because tenants supply outbound targets:
- remote MCP server URLs (`backend/packages/data/src/mcp/mcpConnectionConfig.ts:27-35`);
- web-push endpoints;
- IMAP/SMTP hosts.

`docs/adr/2026-09-27-ssrf-protection-for-stored-outbound-urls.md` validates stored URLs syntactically. It explicitly leaves DNS rebinding (a public name resolving to an internal address) to "egress filtering on the host that runs the sending process" (`:56-58`), and records that nothing in `deploy/` does so (`:66-69`). #1034 adds a connect-time address check in code; this issue adds the independent host layer.

All four long-running services, the timer scripts that run as `semprec`, and `deploy.sh`'s migration and seed runs (`deploy/deploy.sh:136`, `--uid=semprec`) run as uid `semprec` (`deploy/systemd/semprec-api.service:11`). Caddy, Docker, apt and root timers (`semprec-backup`, `semprec-restore-test`) do not. Their legitimate loopback destinations:
- Postgres at `127.0.0.1:5432` (`deploy/docker-compose.yml:18`);
- the gateway at `127.0.0.1:3002` (`AI_GATEWAY_PORT` default, `backend/services/semprec-ai-gateway/src/startupConfig.ts:61`; agents' `AI_GATEWAY_BASE_URL` default `http://127.0.0.1:3002/internal/pi`);
- the local DNS resolver.

The api (`127.0.0.1:8080`) and the gateway also answer loopback connections, so their reply packets must stay allowed.

#996 rewrote the same README and units. #1070 adds a second, stricter uid to this ruleset.

## Task

Load `io-hardening` (this is the network edge every outbound call of the services crosses) and `adr-conventions` (the SSRF ADR names egress filtering "a separate decision").

1. **Ruleset.** In `deploy/nftables.conf`, keep:
   - `table inet semprec`;
   - its own `flush table inet semprec`;
   - the `input` chain unchanged;
   - no `flush ruleset` (Docker's tables live in the same ruleset).

   Add:
   - Named interval sets:
     - `semprec_blocked_v4`: `0.0.0.0/8`, `10.0.0.0/8`, `100.64.0.0/10`, `127.0.0.0/8`, `169.254.0.0/16`, `172.16.0.0/12`, `192.0.0.0/24`, `192.168.0.0/16`, `198.18.0.0/15`, `224.0.0.0/4`, `240.0.0.0/4`.
     - `semprec_blocked_v6`: `::/128`, `::1/128`, `::ffff:0:0/96`, `64:ff9b::/96`, `64:ff9b:1::/48`, `100::/64`, `fc00::/7`, `fe80::/10`, `ff00::/8`.

     These cover RFC 1918, loopback, link-local and metadata, CGNAT (incl. `100.100.100.200`), ULA (incl. `fd00:ec2::254`), NAT64 and multicast.
   - `chain output { type filter hook output priority 0; policy accept; meta skuid "semprec" jump semprec_egress }`. Traffic of every other uid is untouched.
   - `chain semprec_egress`, in this order:
     1. `ct state established,related accept`: replies of the api and gateway listeners, and flows already admitted.
     2. DNS: tcp and udp destination port 53 accepted to any address. The resolver may be `127.0.0.53` or a provider resolver on a private address.
     3. TCP whose conntrack original destination is `127.0.0.1` port `5432` or `3002` is accepted. Match `ct original ip daddr` / `ct original proto-dst`, not the post-NAT `ip daddr`: Docker reaches the container through `docker-proxy` or through DNAT depending on its `userland-proxy` setting, and this rule must hold for both.
     4. Destinations in either blocked set:
        - logged at most 10 per minute with prefix `semprec-egress-deny ` (addresses only);
        - then rejected with `reject with icmpx type admin-prohibited`, so a blocked connection fails at once instead of waiting out a client timeout.

        The log rule and the reject rule are separate rules, since a `limit` that does not match would otherwise skip the reject.

   Update the header comment (`:1-8`) to describe both directions.
2. **Provisioning.** No change to `deploy/provision.sh`:
   - it already installs, checks (`nft -c -f`) and reloads the file (`:279-287`);
   - it creates the `semprec` user (`ensure_service_user`) before `apply_nftables`, so `meta skuid "semprec"` resolves.
3. **Tests.** Extend `deploy/provision.test.sh`'s nftables block (`:183-191`) to assert, in the installed `nftables.conf`:
   - the output hook line with `policy accept`;
   - the `meta skuid "semprec"` jump;
   - every element of both sets;
   - the established/related accept as the first rule of `semprec_egress`;
   - the port-53 accept;
   - the original-tuple loopback accept naming exactly ports 5432 and 3002;
   - the `admin-prohibited` reject;
   - still no `flush ruleset`.
4. **README.** In `deploy/README.md`, update the `nftables.conf` bullet (`:15-18`) and the "Host firewall (nftables)" section (`:244-250`) with:
   - what uid `semprec` can no longer reach;
   - the consequences for operators:
     - an SMTP relay, IMAP server or MCP server on a private or loopback address is unreachable;
     - `AI_GATEWAY_PORT` must stay `3002`;
     - `SEMPREC_DOMAIN` must resolve to a public address for the dead-man probe;
   - the host check after provisioning:
     - `sudo -u semprec curl -m 5 http://169.254.169.254/` and `sudo -u semprec curl -m 5 http://10.0.0.1/` fail immediately;
     - `sudo -u semprec timeout 5 bash -c '</dev/tcp/127.0.0.1/5432'` succeeds (the host has no `pg_isready`: `deploy/provision.sh:90-101` installs no Postgres client);
     - `sudo -u semprec curl -sS -o /dev/null https://example.com` succeeds;
     - `journalctl -k | grep semprec-egress-deny` shows the denials.
5. **ADR.** Add `docs/adr/<YYYY-MM-DD>-host-egress-filtered-by-service-uid.md` (`area: [cross-cutting]`), referencing `[[2026-09-27-ssrf-protection-for-stored-outbound-urls]]` without superseding it. Record:
   - the uid match;
   - the deny-list (not allow-list) shape and why: IMAP, SMTP and MCP ports are tenant-chosen;
   - the original-tuple loopback exception;
   - reject over drop;
   - the operator consequences above.

## Scope

### In scope
- The `output` chain, the two sets, the uid-scoped egress chain, its provisioning test, the README and the ADR.

### Out of scope
- The dedicated sandbox uid for stdio MCP servers and its stricter rules, which deny all loopback (#1070).
- The in-process connect-time address check for MCP and web push (#1034).
- systemd `IPAddressDeny=` or other unit sandboxing (#1071).
- Filtering traffic of root, Caddy, Docker containers or the `forward` path.
- Changing the input chain.

## Acceptance criteria

- The installed `nftables.conf` contains everything Task 3 lists, and still owns only `table inet semprec` without `flush ruleset` (shell test, `deploy/provision.test.sh`).
- `provision.sh` still runs `nft -c -f` on the installed file before `systemctl reload-or-restart nftables`, and the `semprec` user exists before that check (shell test, `provision.test.sh`: order of the recorded `useradd` and `nft -c` commands).
- On a provisioned host, uid `semprec` behaves as follows (manual host check, the README commands, run by the maintainer at deploy):
  - connections to `169.254.169.254` and to an RFC 1918 address are rejected immediately and logged with `semprec-egress-deny`;
  - `127.0.0.1:5432` and a public HTTPS host are reachable;
  - Caddy still reaches the api on `127.0.0.1:8080`;
  - the api still reaches the gateway on `127.0.0.1:3002`;
  - `deploy.sh` still reports every service's version.
- `deploy/README.md` documents the reachable set, the four operator consequences and the host check (review).
