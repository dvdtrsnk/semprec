**Blocked by:** #1682, #1727
**Model tier:** high

## Context

Model tier rationale: This reads many kinds of tenant data into a model prompt under size limits, and must keep that content out of persisted events and logs, so a mistake leaks user data or bloats every stored run.

#1682 stores validated refs on a Semp message. #1727 runs queued Semp thread turns in `semprec-agents`. Today there is no resolver: `SempConversation.send` (`backend/packages/agent-runtime/src/sempConversation.ts`) takes only a string and the turn goes into `agent_runs.task`. A turn that carries refs must give the model the referenced objects and their surroundings, so it can answer and edit them.

This issue adds the resolver that runs in `semprec-agents` before the prompt and renders each ref into a structured context block of that turn. It is the base for file text (#1740), images (#1752), and the ref kinds that other issues add: #1771, #1853, #1948 and #1849.

Decisions:
- The expanded block is built per turn and is not persisted. The user message stored for replay (#1566) keeps only the refs in their stored shape, with labels. After a thread wakes from idle, the agent reloads content with its read tools, which are added by #1623 and the domain read tool issues.
- Limits: at most 8000 characters per ref and 32000 per turn (decided by the product owner; keep them as named constants). A truncated ref is marked in the block with an explicit truncation notice.
- A trashed item is expanded with a `trashed` marker, not dropped. A purged one is rendered as "no longer exists".
- Ref contents are never written to logs (only counts and kinds).

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add a ref expander module in `backend/services/semprec-agents/src/` that takes the turn's refs and a tenant-scoped client and returns one text block, one section per ref, in order:
   - `item`: the item's properties plus the names of relation targets (project, company, people).
   - `block`: the block, its sibling blocks and the parent page (via `sys:children`).
   - `transcriptSegment`: the segment and up to three segments either side, with speaker names; a Transcripts `item` ref: summary, speakers and segments up to the limit.
   - Inbox item: the capture plus its proposal card; a proposal card: envelope, history and source.
   - `agentRun`: task, status and steps.
   - `approvalRequest`: its summary and status.
   - `mailAttachment`: its filename, content type and size (text and images are added by #1740 and #1752).
   - An `item` ref to an e-mail: the thread's newest messages up to the limit; if the mail thread read tool of #1927 is available, reuse its reader, otherwise read the thread's message items directly.
2. Apply the per-ref and per-turn caps with a visible truncation marker.
3. Call the expander when a thread turn starts and prepend its block to the user content sent to the model; do not write it into `agent_runs.task` or any `agent_run_events` row.
4. Expansion runs under the turn's tenant scope; an expansion failure for one ref renders that ref as unavailable and does not fail the turn.
5. Tests: each ref kind expands; a block shows its neighbours; an over-limit ref is cut and marked; `agent_runs.task` and the events table contain no expanded text; a trashed item is marked; a ref of another tenant yields nothing.

## Scope

### In scope

- The resolver, the limits, truncation and trashed markers, and wiring into the turn.

### Out of scope

- Text extraction from file and attachment blobs: #1740.
- Image attachments: #1752.
- Task occurrence refs (#1771), sleep night refs (#1853), draft refs (#1948) and one-run read access granted by a ref (#1849).
- The agent read tools used after a thread wakes: #1623.

## Acceptance criteria

- When a turn carries a ref to an e-mail item, then the model sees the thread's messages; with a block ref, the sibling blocks too.
- When a ref's content exceeds 8000 characters, then it is cut and marked as truncated; the whole block never exceeds 32000 characters.
- When the turn is stored, then `agent_runs.task` and every `agent_run_events` row contain no expanded ref content.
- When one ref cannot be read, then the turn still runs and that ref is marked unavailable.
