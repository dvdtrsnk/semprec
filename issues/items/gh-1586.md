## Context

Model tier rationale: One new system-owned property plus a few lines in the existing Projects transform, with a seed, i18n and cutover addition that follow the Areas pattern and no new authorization or concurrency contract.

The collection of projects shows, for finished projects, when they were completed or archived ("completed in March 2024"). Nothing records that today: `status` changes to `done` or `archived` leave no trace of when.

This issue adds `completedAt`, a date property that is `owner: 'system'`, written only by the Projects pre-write transform that #1520 registers (built on #1422); that transform belongs to the module `systemDatabases`, so the property's `ownerProcess` is `systemDatabases` and that id is added to `KNOWN_OWNER_PROCESS_IDS` in `backend/packages/data/src/manifest/knownActionIds.ts` (see `docs/adr/2026-09-10-single-writer-ownership-model.md`). The Projects database is schema-locked, so existing tenants get the property through the per-tenant cutover (`backend/packages/data/src/db/tenantCutoverMigrations.ts`, pattern `transcription/transcriptsCatalogCutoverMigration.ts`); the label depends on #1413, which also edits the Czech catalog.

Decisions:
- `completedAt` is set to the current date in the tenant's time zone (`getSystemTimezone` in `backend/packages/data/src/systemSettings.ts`) when the resulting status becomes `done` or `archived` from a different status that is not `done` or `archived`.
- Moving between `done` and `archived` keeps the existing value.
- Leaving to `inProgress` or `longTerm` sets it to null.
- Existing finished projects are not backfilled; their value stays empty.

Shared-file ordering: this issue also waits for #1576, #1584 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `state-writes`, `canonical-keys` and `testing`.

1. Add property `completedAt` (type `date`, `owner: 'system'`, `ownerProcess: 'systemDatabases'`) to the Projects database in `seedTenDatabases.ts`; export the owner process id as a constant next to the Projects transform and add it to `KNOWN_OWNER_PROCESS_IDS`.
2. Add a cutover step (new `backend/packages/data/src/seed/projectsCompletedAtCutoverMigration.ts`, registered in `runTenantCutoverMigrations`) that adds the property when missing, under `LOCK TABLE properties IN EXCLUSIVE MODE`, for every maintained tenant including suspended ones; a second run changes nothing.
3. Extend the Projects transform (`backend/packages/data/src/projects/projectWriteTransform.ts`) with the `completedAt` rules above, so the value is part of the same write and appears in the same response. A client or agent writing `completedAt` directly is refused by the system-owner rule.
4. Add i18n keys `property.projects.completedAt.name` to `seed/i18n/cs.json` ("Dokončeno") and `en.json` ("Completed at"); bump the `version` of `seed/systemDatabasesModuleManifest.ts`.
5. Tests: `PATCH status: done` returns `completedAt` with today's date in the tenant zone; `done` to `archived` keeps it; back to `inProgress` clears it; a direct write of `completedAt` is rejected; a pre-existing tenant gets the property after the cutover; a second cutover run is a no-op.

## Acceptance criteria

- When a project is patched to `done`, then the response contains `completedAt` equal to today's date in the tenant time zone; the same via `/mcp`.
- When it is then patched to `archived`, then `completedAt` is unchanged; when patched to `inProgress`, then it is null.
- When a client writes `completedAt` directly, then the write is rejected.
- After the cutover every tenant's Projects database has `completedAt`; a second run changes nothing.
- `GET /api/databases/:id/properties` for Projects lists `completedAt` with the label "Dokončeno" in Czech.
- The full backend `pnpm run verify` passes.
