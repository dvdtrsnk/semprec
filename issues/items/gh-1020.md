## Context

Model tier rationale: Two deletions and one given backfill statement replace the earliest-user lookups.

`getEarliestUserId` and `getEarliestUserLocale` (`backend/packages/data/src/auth/usersStore.ts:64-88`) return the first-created account in the global `users` table, as the stand-in for "the" single user. With tenants, that answer is another tenant's user.

Earlier issues moved every runtime caller off them:
- #1018: tenant events, agent-run attribution and the drift locale now use `getTenantUserId` / `getTenantUserLocale` (`users WHERE tenant_id = app_tenant_default()`).
- #1019: operator alerts go to `listAdminRecipients`, and the mailbox stall to the tenant's user.

Two things still reference the earliest user:
- **The cutover.** `runAgentRunsActorUserIdCutoverMigration` (`backend/packages/data/src/agentRuns/agentRunsActorUserIdCutoverMigration.ts:23-67`) is the one-time backfill of `agent_runs.actor_user_id`. It is run after migrations by `backend/packages/data/src/db/runMigrationsCli.ts:25` and by `backend/packages/data/src/testSupport/globalSetup.ts`. It attributes every root run with a NULL actor to the earliest account (`:49-63`). #1007 kept it as a global, schema-guarded step. The CLI and test setup run it on the migrating (table-owner) pool inside `runAsSystem`, and it returns at once when the column is already `NOT NULL` (`:29-33`). It left the earliest-account call to this issue.
- **Comments and tests:**
  - the comment at `backend/packages/data/src/manifest/permissionManifest.ts:98-101`;
  - the cutover's own doc comment (`agentRunsActorUserIdCutoverMigration.ts:16-21`);
  - the runtime-export list in `backend/packages/data/src/__tests__/publicSurface.test.ts:255-256`;
  - the `getEarliestUserLocale` test and import in `backend/packages/data/src/__tests__/manifest.test.ts:14`, `:373-382`.

`users` has no row-level security. A query by `tenant_id` across all tenants is correct only in a context that legitimately spans tenants, which a deploy-time cutover running as the migrating role is.

## Task

Load `db-migrations` (a backfill inside a post-migration cutover) and `error-handling` (the backfill's no-user branch).

1. **Delete the lookups.** Delete `getEarliestUserLocale` and `getEarliestUserId`, with their doc comments, from `usersStore.ts`. No `index.ts` edit is needed: the module is re-exported through `export *` at `backend/packages/data/src/index.ts:283`.
2. **Tests and comments.**
   - Remove both names from the runtime-export list in `publicSurface.test.ts`.
   - Remove the `getEarliestUserLocale` import and its test from `manifest.test.ts`, and any comment there that still points at it.
   - Rewrite the `permissionManifest.ts:98-101` comment: the drift check resolves the tenant's user's locale.
3. **Cutover.** In `agentRunsActorUserIdCutoverMigration.ts`, replace the earliest-account fallback (`:49-63`) with a set-based, tenant-correct backfill. It runs as the table owner, so row-level security does not hide any tenant's rows:
   ```sql
   UPDATE agent_runs AS r SET actor_user_id = u.id
   FROM users u
   WHERE u.tenant_id = r.tenant_id AND r.actor_user_id IS NULL
   ```
   - Keep the lock, the idempotency check, the parent-chain propagation loop before it, and the `SET NOT NULL` after it.
   - If any row is still NULL afterwards, throw `Cannot backfill agent_runs.actor_user_id: rows exist whose tenant has no user`. That rolls back the whole cutover, as the old no-account branch did.
   - Rewrite its doc comment (`:5-22`).
   - The new test file restores the column to `NOT NULL` in `finally`, after deleting the rows it inserted, so a failing case cannot leave the shared test database with a nullable column.
4. **Leftovers.** No file under `backend/` may still reference either name after this change. Accepted ADR bodies under `docs/adr/` keep their historical text.

## Acceptance criteria

- **Gone.** `getEarliestUserId` and `getEarliestUserLocale` are no longer runtime exports of `@semprec/data`. `publicSurface.test.ts` passes with both names removed. `git grep -n "getEarliestUser" -- backend` returns nothing. (integration, `publicSurface.test.ts`; typecheck through `pnpm run verify`)
- **Backfill per tenant.** Before running the cutover, the test makes `actor_user_id` nullable and inserts root runs with a NULL actor in tenant zero and in tenant B, created with #975's `createTestTenant()`. Each run then carries its own tenant's user, never the earlier-created account, and the column is `NOT NULL` again. (integration, `agentRunsActorUserIdCutoverMigration.test.ts`)
- **No user.** When a NULL-actor root run belongs to a tenant with no user, the cutover throws the new message. No row changes and the column stays nullable, because the transaction rolled back. (integration, `agentRunsActorUserIdCutoverMigration.test.ts`)
- **Idempotent.** On a database whose `actor_user_id` is already `NOT NULL`, the cutover returns without writing, as `globalSetup.ts` relies on. (integration, `agentRunsActorUserIdCutoverMigration.test.ts`)
- **Unchanged suite.** The integration suite passes with no test depending on the deleted functions. (integration)
