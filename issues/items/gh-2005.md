## Context

Model tier rationale: One new timeline source plugged into the existing extension point, mapping stored rows to the timeline item shape with the existing timeline fixtures; the risk is limited to range selection and ordering inside the shared read.

#1717 serves the calendar timeline (`readCalendarTimeline` in `backend/packages/data/src/calendar/timelineRead.ts`) and lets further sources plug into the ordered list in `backend/packages/data/src/calendar/timelineSources.ts` (`{ id, readItems(client, context) }`), so a new source never edits the core merge. #1962 adds the read-only `subscribedEvents` database (`uid`, `title`, `startsAt`, `endsAt`, `timeZone`, `allDay`, `place`, relation `calendar`), whose rows are written by the feed import (#2004) already converted to the tenant's wall-clock time. This issue makes those rows appear in the timeline, and through it in the agenda (#1762) and the Semp timeline tool (#1952). #1966 later feeds recurring subscribed events into the occurrence expansion.

Item mapping: `kind` `event` (an entry of a subscription calendar is shown like an Event and told apart by `readOnly` and its `databaseId`), `id` (the stored row id), `databaseId` (the `subscribedEvents` database), `title`, `type` null, `date` (the day of `startsAt`), `endDate` (the day of `endsAt` when it is a later day, else null), `timeFrom` and `timeTo` (the wall-clock times of `startsAt` and `endsAt`; null when `allDay`), `effectiveTo` and `hasEnd` as for Events, `allDay`, `calendarId` (the row's `calendar` edge; the colour comes from that calendar), `status` null, `place`, `project` null, `people` empty, `updatedAt`, and `readOnly` true. The compact shape carries the same subset as other items.

Selection: like Events, a row is included when its first day is on or before `to` and its last day is on or after `from`; a multi-day entry appears once, with its range. Trashed rows and rows of a trashed calendar are excluded. Ordering inside a day follows the timeline's groups (all-day entries with all-day Events, timed entries with timed Events). A row with an unreadable stored value is left out with a log line carrying only its id, never a 500.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add `backend/packages/data/src/calendar/timelineSubscribedEventSource.ts` with a source that reads the `subscribedEvents` rows overlapping the requested range in one batched query (plus one batched lookup of `calendar` edges), maps them as above, and returns them with the shared context of #1717.
2. Register the source in `backend/packages/data/src/calendar/timelineSources.ts`.
3. Tests: a stored subscribed event at wall-clock 15:00 on 2026-10-20 appears in the timeline for that day with `readOnly` true, `kind` `event`, the `subscribedEvents` `databaseId` and its calendar's id; an all-day entry spanning two days appears once for a range containing only its second day; a trashed row is absent; the entry is ordered among timed Events by `timeFrom`; a row with an invalid stored start is omitted and the response is 200; `shape=compact` carries `readOnly`; another tenant's rows never appear; the number of queries does not grow with the number of rows.

## Scope

### In scope

- The read-only timeline source for stored subscribed events and its mapping to the timeline item shape.

### Out of scope

- The `subscribedEvents` database: #1962. Importing feeds into it: #2004.
- Recurring subscribed events and their expansion: #1966.
- Hiding subscribed calendars on the server; the client hides by the calendar's `hidden` flag as for every timeline item.
- Editing, hiding or recoloring individual subscribed events.

## Acceptance criteria

- When the timeline covers a day with a stored subscribed event, then the entry is returned with `readOnly` true and the id of its calendar.
- When a subscribed event was imported from 2026-10-20 09:00 `America/New_York` for a tenant in `Europe/Prague`, then the timeline shows it at 15:00.
- When a subscribed event is in the trash, then it is not returned.
- When a stored row has an invalid start, then it is omitted and the response is 200.
- When another tenant reads the same range, then none of these entries appears.
- The full backend `pnpm run verify` passes.
