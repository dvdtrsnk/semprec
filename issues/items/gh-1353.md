## Context

Model tier rationale: One new manifest plus two catalog files and a registry list entry following the library and mail manifests exactly, with no data written and no tenant, authentication or concurrency contract.

Personal finance is a planned area of the product (Finance in the overview: this month's spending against a budget, categories, latest transactions, an expense detail), but the backend has nothing for it. There is no module manifest, no database and no migration; the word appears only in a comment in `backend/packages/data/src/seed/seedTenDatabases.ts`. The module registry loads a fixed list of manifests (`ALL_MODULE_IDS` and `MANIFEST_PATHS` in `backend/packages/data/src/manifest/fullModuleRegistry.ts`: schemaCore, views, docs, systemDatabases, library, mailSync, inboxPipeline). A manifest (`backend/packages/module-registry/src/manifest.ts`) requires `id`, `version`, `name`, `removable`, `systemProject`, `databases`, `capabilities` and `agentTools`; its labels are read from `i18n/cs.json` and `i18n/en.json` beside the manifest (`backend/packages/module-registry/src/catalog.ts`; see `backend/packages/data/src/library/i18n` for the shape). Note that `databases.owner_module_id` stores the database key, not the manifest id, which is how `manifest/catalogResolution.ts` finds a database's catalog.

This issue declares the Finance module and its two databases and their labels, so the schema projection (`/api/schema`) can name them in Czech and English. #1511 creates the databases and their properties for every tenant. #1585 adds the summary route and the agent tool to this manifest, and #1651 adds the expense link rules; none of those is declared here.

Decision: the module id is `finance`, the database keys are `transactions` and `financeCategories`, and the module is not removable and is a system project. The currency is fixed to CZK for now.

## Task

Load `canonical-keys` and `testing`.

1. Create `backend/packages/data/src/finance/financeModuleManifest.ts` exporting `manifest` with `id: "finance"`, a `version`, `name: "Finance"`, `removable: false`, `systemProject: true`, `databases: [{ key: "transactions", name: "Transactions" }, { key: "financeCategories", name: "Finance categories" }]`, `capabilities: []`, `agentTools: []`. Put the two database keys in a small constants file next to it, `backend/packages/data/src/finance/financeModuleKeys.ts` (`TRANSACTIONS_MODULE_ID`, `FINANCE_CATEGORIES_MODULE_ID`, `FINANCE_PROJECT_NAME`).
2. Add `"finance"` to `ALL_MODULE_IDS` and the manifest path to `MANIFEST_PATHS` in `fullModuleRegistry.ts`.
3. Create the catalogs `backend/packages/data/src/finance/i18n/cs.json` and `en.json` with the keys `database.transactions.name`, `database.financeCategories.name`, `property.<databaseKey>.<propertyKey>.name` for every property listed below, and `property.<databaseKey>.<propertyKey>.option.<optionKey>` for every select option. Properties of `transactions`: `name`, `amount`, `currency` (option `CZK`), `type` (options `expense`, `income`), `date`, `dueDate`, `paymentStatus` (options `unpaid`, `paid`), `paidAt`, `note`, `source` (options `manual`, `inbox`), `sourceInbox`, `category`, `company`, `project`, `document`. Properties of `financeCategories`: `name`, `icon` (options `house`, `bag`, `car`), `color`, `monthlyBudget`, `sortOrder`, `transactions`. Czech wording follows the product's existing terms (for example Transakce, Kategorie, Splatnost, Zaplaceno).
4. Tests: the full registry loads with the finance module and no cross-manifest collision (extend `moduleRegistryLoadAll.unit.test.ts`); every database and every property and option listed above resolves in both catalogs with no fallback to the raw key (extend the pattern of `systemI18nCatalogCoverage.test.ts`).
