## Context

Model tier rationale: Tenant-wide folder cleanup and concurrent Gmail placement must preserve mail visibility.

Legacy label folders need safe cleanup without losing archived mail or guessing types from provider ids.

Decision: a Folder is created only for the user labels (Gmail label `type` `user`) and for `INBOX`, `SENT`, `SPAM`, `TRASH`, `DRAFT`. A synthetic Archive folder (provider id `semprec:archive`, behavior `label`, `specialPurpose` `archive`, created only for Gmail API accounts) receives every message that has none of `INBOX`, `SPAM`, `TRASH`, `SENT`, `DRAFT`, so archived mail stays visible after the pseudo-folders disappear, and sent mail and drafts are not mistaken for archived. A message that carries only a user label and no `INBOX` is in that label's folder and in Archive. Existing pseudo-folders and their edges are removed per tenant by an idempotent job.

The folder list with counts (#1689) and archive or trash actions (#1917) build on it.

## Acceptance criteria

- When a Gmail account is synced, then it has no folders named `UNREAD`, `STARRED`, `IMPORTANT`, `CATEGORY_*` or `CHAT`.
- When a message has no `INBOX`, `SPAM`, `TRASH`, `SENT` or `DRAFT` label, then it is in the Archive folder; a sent message or a draft is not.
- When an archived message is moved back to the inbox, then its Archive edge is removed.
- When the cleanup runs, then the pseudo-folders and their edges are gone, no message loses all its folders, and a second run changes nothing.

- Cleanup removes provider-confirmed non-placement system labels including unfamiliar ids, preserves opaque user and unknown/absent ids plus Archive, and retries provider/validation failure without deleting that mailbox data. Production adapter wiring, runtime-role tenant separation and a second-run no-op are tested with fake providers.

- Concurrent Gmail sync and cleanup serialize per tenant/mailbox and preserve correct Inbox/Archive placement in both forced overlap orders, including no-flags input; another mailbox remains independent.
