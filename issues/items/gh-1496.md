## Context

Model tier rationale: Changes which messages Gmail sync ingests and into which folder, and rewrites existing folder edges for every tenant, so a mistake can hide or duplicate mail across all Gmail accounts.

`reconcileGmailAccount` (`backend/packages/data/src/mail/gmailReconcile.ts`) creates a Folder for every label from the Gmail labels list, including `UNREAD`, `STARRED`, `IMPORTANT`, `CATEGORY_*` and `CHAT`. Only `INBOX`, `SENT`, `SPAM`, `TRASH` and `DRAFT` get a `specialPurpose` (`inbox`, `sent`, `junk`, `trash`, `drafts`); every other label becomes a Folder with `specialPurpose` `none`. These are labels, not places a person puts mail, and they show up as folders. Archived mail has no `INBOX` label, so it is only ingested because it usually carries one of those pseudo-labels (`UNREAD`, `IMPORTANT`, `CATEGORY_*`); a message with no labels at all is not ingested.

Decision: a Folder is created only for the user labels (Gmail label `type` `user`) and for `INBOX`, `SENT`, `SPAM`, `TRASH`, `DRAFT`. A synthetic Archive folder (provider id `semprec:archive`, behavior `label`, `specialPurpose` `archive`, created only for Gmail API accounts) receives every message that has none of `INBOX`, `SPAM`, `TRASH`, `SENT`, `DRAFT`, so archived mail stays visible after the pseudo-folders disappear, and sent mail and drafts are not mistaken for archived. A message that carries only a user label and no `INBOX` is in that label's folder and in Archive. Existing pseudo-folders and their edges are removed per tenant by an idempotent job.

The folder list with counts (#1689) and archive or trash actions (#1917) build on it.

## Task

Load `state-writes`, `db-migrations` and `testing`.

1. In `reconcileGmailAccount`, create Folder items only for labels with `type` `user` and the five system ids above; map message labels only through those. Add the Archive folder through `ensureFolderItem` (`mail/folderDiscovery.ts`) for the account and include its id in a message's folder set when none of `INBOX`, `SPAM`, `TRASH`, `SENT`, `DRAFT` is present, including for a message with no labels at all.
2. Keep the existing edge removal: moving a message to the inbox removes its Archive edge, archiving it removes the `INBOX` edge.
3. Add a core task `mailGmailPseudoFolderCleanup` (`CORE_TASK_NAMES`, handler in `worker.ts`) that runs `forEachActiveTenant` and, for Gmail API mailboxes, in keyset pages with one transaction each: removes every Folder item of the mailbox whose provider id is not a user label and not one of the five system ids (including its folder edges), and for any message left with no folder edge adds the Archive edge. It is idempotent; enqueue it once at deploy under a fixed job key.
4. Add tests: a Gmail account has no folders for `UNREAD`, `STARRED` or `CATEGORY_*`; an archived message is in Archive; a sent message and a draft are not in Archive; a message with no labels is ingested into Archive; a message moved back to the inbox leaves Archive; the cleanup removes pseudo-folders, keeps archived mail visible through Archive, and a second run changes nothing.

## Scope

### In scope

- Which Gmail labels become folders, the synthetic Archive folder, and the per-tenant cleanup of existing pseudo-folders.

### Out of scope

- IMAP and Microsoft Graph folder handling.
- Folder lists with counts: #1689; archive and trash actions: #1917.
- Display names of folders (localization by `specialPurpose`): #1689.

## Acceptance criteria

- When a Gmail account is synced, then it has no folders named `UNREAD`, `STARRED`, `IMPORTANT`, `CATEGORY_*` or `CHAT`.
- When a message has no `INBOX`, `SPAM`, `TRASH`, `SENT` or `DRAFT` label, then it is in the Archive folder; a sent message or a draft is not.
- When an archived message is moved back to the inbox, then its Archive edge is removed.
- When the cleanup runs, then the pseudo-folders and their edges are gone, no message loses all its folders, and a second run changes nothing.
