## Context

Model tier rationale: This is a mechanical move of a security-relevant inventory across files with existing verification suites and no new lifecycle, authorization or persisted-data contract.

`backend/services/semprec-api/src/routeMatrix.ts` holds every HTTP route of the API in one exported array, `ROUTE_MATRIX`. The lint rule `max-lines` in `backend/eslint.config.mjs` caps every production TypeScript file at 900 counted lines, and `docs/adr/2026-09-24-choke-point-composed-from-domain-modules.md` rules out per-file exemptions. The file stands at 884 counted lines. The open backend requirements add about 94 further entries, so the file cannot take them: earlier work already exceeded the cap once and twice rewrote existing entries to make room.

The parallel delivery program (`docs/adr/2026-11-10-parallel-backend-delivery-through-a-serialized-merge-queue.md`) implements those requirements concurrently. Each can lint clean on its own branch while the merged file exceeds the cap, and Git reports nothing. The inventory therefore needs room before any of them lands.

Entries are looked up by `name` and filtered by surface, flags and path. Array position has no runtime meaning in the service, but `__tests__/tenantIsolationRoutes.test.ts` runs its cases in `ROUTE_MATRIX` order against fixtures that are seeded once, so the order of the existing entries must not change. Nothing asserts today that `name` or `method` plus `path` is unique; a duplicate `name` is caught only indirectly by the companion tests, and a duplicate `method` plus `path` is not caught at all.

## Task

Load `testing`.

1. Create the directory `backend/services/semprec-api/src/routeMatrix/` with slice modules. Each slice exports one array of `RouteMatrixEntry` that holds a contiguous run of today's `ROUTE_MATRIX` entries, moved verbatim: the same objects, the same comments attached to them, the same `// prettier-ignore` markers, the same order. Name each slice after the path family of its entries. No slice exceeds 400 counted lines.
2. `routeMatrix.ts` keeps the `RouteMatrixEntry` type, its documentation and the file comment, and exports `ROUTE_MATRIX` as the concatenation of the slices in the existing order. Every importer keeps importing `ROUTE_MATRIX` and `RouteMatrixEntry` from `routeMatrix.js`. If `pnpm run check:boundaries` or the build rejects the import shape, move the type into a module under `routeMatrix/` that the slices import and re-export it from `routeMatrix.ts`.
3. Add one sentence to the file comment of `routeMatrix.ts` that says where a new entry goes: at the end of the slice of its path family, or in a new slice appended to the concatenation when no slice fits.
4. Add `backend/services/semprec-api/src/__tests__/routeMatrixInventory.unit.test.ts`. It reports every `name` that two entries share and every `method` plus `path` pair that two entries share, proves both reports on small local lists that contain such a duplicate, and asserts that `ROUTE_MATRIX` has neither.
5. If any test or script reads `routeMatrix.ts` as text rather than importing it, point it at the slices so it still sees every entry.

## Scope

### In scope

- Moving the existing entries into slice modules without changing them.
- The uniqueness test for `name` and for `method` plus `path`.

### Out of scope

- Adding, removing, renaming, reordering or reclassifying any entry.
- The companion inventories `ROUTE_CASES` in `tenantIsolationRoutes.test.ts` and `ROUTE_HANDLER_FILES` in `chokePointWriteBoundary.unit.test.ts`.
- The count assertion in `bespokeListenerTenantScope.test.ts`.
- Any change to the `max-lines` rule or an exemption from it.

## Acceptance criteria

- `ROUTE_MATRIX` is element for element identical to the array before the change: the same length, the same order and deeply equal entries. The handover records the comparison command and its output.
- `routeMatrix.ts` has fewer than 200 counted lines and no slice module exceeds 400; `pnpm exec eslint services/semprec-api/src/routeMatrix.ts services/semprec-api/src/routeMatrix` passes.
- `routeMatrixInventory.unit.test.ts` fails for a list with a repeated `name` and for a list with a repeated `method` plus `path`, and passes for `ROUTE_MATRIX`.
- These suites pass without any change to their files: `routeMatrix.test.ts`, `tenantIsolationRoutes.test.ts`, `cacheControl.test.ts`, `adapterTenantScope.test.ts`, `bespokeListenerTenantScope.test.ts`, `adminHandler.test.ts` and `chokePointWriteBoundary.unit.test.ts`.
- `pnpm run lint`, `pnpm run format:check`, `pnpm -r run build` and `pnpm run check:boundaries` pass.
