## Context

Review follow-ups harvested in #728, both in module-contract runtime code in `backend/packages/data/src/`:

- PR #300 — `backend/packages/data/src/moduleWorkers.ts:117`: `reconcileOnce()` of `createModuleWorkerInstanceReconciler` has no guard against overlapping calls. Two calls made without awaiting the first both see `hosted.has(id) === false` before either records the instance, so `supervisor.start` runs twice for the same instance id.
- PR #306 — `backend/packages/data/src/manifest/driftCheck.ts:59`: the comment says the manifest generation and the orphan check "must see one schema snapshot", but `withTransaction` (`backend/packages/data/src/db/pool.ts:30-33`) issues a plain `BEGIN` — READ COMMITTED, where every statement takes its own snapshot — so the claim is false.

## Task

1. `moduleWorkers.ts`: serialize `reconcileOnce` within one reconciler — a call made while an earlier pass is running starts its own pass only after that pass settles (fulfilled or rejected), and each call's promise settles with its own pass's outcome. Update the `reconcileOnce` doc comment to say so.
2. `driftCheck.ts`: delete the comment sentence claiming the two reads see one schema snapshot (lines 59-61), keeping the following sentence about the orphan check and its notification being atomic.

## Touches

- backend/packages/data/src/moduleWorkers.ts (`createModuleWorkerInstanceReconciler` and the `reconcileOnce` doc comment only)
- backend/packages/data/src/__tests__/moduleWorkers.unit.test.ts
- backend/packages/data/src/manifest/driftCheck.ts (the comment at lines 59-61 only)

## Scope

### In scope

- The two changes above and the unit tests for the first.

### Out of scope

- Changing the drift check's transaction isolation level.
- Any change to `deriveDesiredWorkerInstances` or the instance id scheme.

## Acceptance criteria

- In `moduleWorkers.unit.test.ts`, two overlapping `reconcileOnce()` calls against a supervisor whose `start` resolves only when the test releases it result in exactly one `start` call per desired instance id.
- In `moduleWorkers.unit.test.ts`, when the first of two overlapping calls rejects (its `supervisor.start` throws), that call's promise rejects with that error and the second call still runs its pass and resolves.
- `driftCheck.ts` no longer contains the words "one schema snapshot".
