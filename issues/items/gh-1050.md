**Blocked by:** #991, #1018, #1042
**Model tier:** medium

## Context

Model tier rationale: The abort signal, registry and wiring are specified, but racing the session iterator against the signal and the shutdown order need async care.

When an account is suspended or deleted, its tenant leaves `active`, and no new work starts for it:

- its sessions are revoked;
- new queue jobs of a non-active tenant complete as no-ops (#982);
- per-tenant sweeps skip it.

An agent run that is **already executing** in `semprec-agents` keeps going, though. It keeps calling the AI gateway on the operator's budget and writing run events into the tenant's data until its session ends.

- **Where runs execute.** `createAgentRunTask` (the `agentRun` / `delegatedAgentRun` handler) and `createRunAgentForHeartbeats` (the `RunAgentFn` behind heartbeat runs) live in `backend/services/semprec-agents/src/agentRunTasks.ts:72-131`. Since #991 each runs inside its job's tenant, so `currentTenantScope()` is `{ kind: 'tenant', tenantId }` there.
- **No cancellation path.** Both drive a session through `runAgentTurn(client, agentRunId, messages, onEvent?)` (`backend/packages/agent-runtime/src/lifecycleAdapter.ts:91-117`) or `runAgentSessionForRun(client, run, input)` (`:156-200`). Leaving `runAgentTurn`'s `for await` early calls the session iterator's `return()`, and the pi session generator's `finally` then calls `agent.abort()` (`backend/services/semprec-agents/src/piAgentSession.ts:129-139`).
- **Closing a failed run.** `runAgentSessionForRun` already closes a run whose turn throws as `error` with its notification (`lifecycleAdapter.ts:176-195`). `createRunAgentForHeartbeats` (`agentRunTasks.ts:100-131`) rethrows, and `coreAgentRunAction` (`backend/packages/data/src/scheduler/actions.ts:77`) closes the run.
- **The signal** (#1042). `backend/packages/data/src/tenancy/tenantStatusSignal.ts` exports `startTenantDeactivationListener(pool, onDeactivated: (tenantId: string) => Promise<void>)`, which returns a listener with `close(): Promise<void>`.
  - It runs in system scope, LISTENs on `semprec_tenant_status` and validates each payload.
  - On every (re)connect it resyncs by calling `onDeactivated` for every `suspended` or `deleting` tenant.
  - It is exported from `@semprec/data`.
  - The ADR #1042 added requires every per-process registry keyed by tenant to subscribe to it.
- **The process.** `semprec-agents` composes its runtime in `backend/services/semprec-agents/src/serve.ts:22-57` and shuts down through `createGracefulShutdown({ queueRuntime, pool, logger })` (`backend/services/semprec-agents/src/shutdown.ts:56`), which stops the queue runtime and then ends the pool.

## Task

Load `io-hardening` (listener lifetime, shutdown ordering), `error-handling` (a cancelled run must close as a failure, never as success) and `state-writes` (the run close stays the existing single writer).

1. **Cancellable turn** — in `lifecycleAdapter.ts`:
   - `runAgentTurn` gains an optional trailing parameter `signal?: AbortSignal`, and `RunAgentSessionInput` gains `signal?: AbortSignal`, which `runAgentSessionForRun` passes to `runAgentTurn`.
   - When the signal is already aborted, or aborts while the loop waits for the next message, the loop stops consuming the session so the iterator's `return()` runs. It then throws a new exported `AgentRunCancelledError` (message `"account deactivated"`).
   - The existing catch in `runAgentSessionForRun` then closes the run as `error` with its notification, unchanged.
   - Export `AgentRunCancelledError` from `backend/packages/agent-runtime/src/index.ts`.
2. **Registry** — new `backend/services/semprec-agents/src/inFlightAgentRuns.ts` with `createInFlightAgentRuns()`. It returns:
   - `register(tenantId: string, controller: AbortController): () => void`, whose returned function unregisters;
   - `abortTenant(tenantId: string): number`, which aborts every registered controller of that tenant and returns how many.

   It holds no other state and is per process.
3. **Registration** — `createAgentRunTask` and `createRunAgentForHeartbeats` take the registry as a new parameter. Around the session they:
   - read the tenant from `currentTenantScope()`, throwing an `Error` if it is not a tenant scope, which would be a wiring bug;
   - register an `AbortController` and pass its `signal` down (`runAgentSessionForRun` input, or `runAgentTurn` directly);
   - unregister in `finally` on every path.
4. **Wiring:**
   - In `serve.ts`, create one registry, pass it to both factories, and start `startTenantDeactivationListener(pool, async (tenantId) => { registry.abortTenant(tenantId) })` after the queue runtime is created.
   - `createGracefulShutdown` takes the listener as a new option and closes it before `queueRuntime.stop()`. A failing `close()` is logged and shutdown continues.

## Scope

### In scope
- Aborting the in-flight `agentRun`, `delegatedAgentRun` and heartbeat agent runs of a deactivated tenant in `semprec-agents`.
- Closing those runs as `error`.
- The agents-process listener and its shutdown.

### Out of scope
- The deactivation signal itself, and the `semprec-api` consumers (sockets, mail live sync) and `SempConversation.dropTenant` (#1042).
- Sessions held in memory by `DelegationRegistry` or `SempConversation`. Neither is composed into a process today.
- Refusing new jobs of non-active tenants (#982).
- The per-tenant concurrent-run cap (#1047).
- Refusing gateway calls for non-active tenants.

## Acceptance criteria

- When the signal passed to `runAgentTurn` aborts while a fake session is still yielding, the session iterator's `return()` is called and `AgentRunCancelledError` is thrown. Through `runAgentSessionForRun`, the run is closed as `error` with its `agent_run_error` notification and a `run_status` `error` event. A signal that is already aborted throws before the first message is consumed (integration, `lifecycleAdapter.test.ts`).
- When no signal is given, `runAgentTurn` behaves exactly as before; the existing cases pass unchanged (integration, `lifecycleAdapter.test.ts`).
- When `abortTenant(B)` runs while one B controller and one A controller are registered, only B's aborts and the result is 1. After a registration's unregister function runs, `abortTenant` no longer counts it (unit, `inFlightAgentRuns.unit.test.ts`).
- When tenant B is suspended while a B `agentRun` job and a tenant A `agentRun` job are executing against slow fake sessions, B's session is aborted and B's run ends `error`, while A's run completes `done`. The registry is empty afterwards (integration, `agentRunCancellation.test.ts`, two tenants via `createTestTenant()` from `@semprec/data/testSupport`, #975).
- When `createAgentRunTask` runs outside a tenant scope, it throws before composing a session (integration, `agentRunCancellation.test.ts`).
- When the agents process shuts down, the listener's `close()` is awaited before `queueRuntime.stop()`. A rejecting `close()` is logged and the queue runtime and pool are still stopped (unit, `shutdown.unit.test.ts`).
