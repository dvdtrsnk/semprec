## Context

Nothing serves the web client in production. `deploy/Caddyfile` (line 40, `reverse_proxy 127.0.0.1:8080`) forwards every path of `{$SEMPREC_DOMAIN}` to `semprec-api`, and `semprec-api` serves no static files — `backend/services/semprec-api/src/routeMatrix.ts` line 9: "this service doesn't serve the SPA"; `app.ts`'s `createDispatcher` ends in the MCP agent-page listener's 404 for anything unmatched. `deploy/deploy.sh`'s `build_release` (lines 107-113) runs `pnpm install` and `pnpm -r run build` in `backend/` only; `web/` (its own pnpm workspace with `pnpm-lock.yaml`, `packageManager: pnpm@9.12.0`, `pnpm run build` = `tsc --noEmit && vite build` into `web/dist/`, `web/package.json`) is exported into the release by `git archive` but never built. So `https://<domain>/` answers the backend's JSON 404.

The client is a single-page app: `web/index.html` loads `/src/main.tsx`; every route is a query parameter on `/` (`?view=`, `?page=…`, `main.tsx` docblock), so any non-backend path must fall back to `index.html`. The client calls the backend same-origin under `/api` (`main.tsx` line 26, `VITE_API_BASE_URL ?? "/api"`), so no build-time API URL is needed. The backend-owned URL space is `/api/*` (including the `/api/sync` WebSocket upgrade, which Caddy's `reverse_proxy` forwards transparently, and `/api/mail/graph/webhook`), `/mcp` and `/healthz` — the same list sibling issue G1 of this batch proxies in `web/vite.config.ts`.

Depends on #702 (installs `/etc/caddy/Caddyfile` from `deploy/Caddyfile`, enables `caddy.service`, hands it `SEMPREC_DOMAIN`, documents `PORT=8080`, extends the `Caddyfile` bullet and appends a `## Front door (Caddy)` section to `deploy/README.md`) — this issue changes only the routing inside the site block and adds after #702's README text; and on #644 (adds `run_seed` next to `run_migrations` in `deploy/deploy.sh` and the seed assertions in `deploy/deploy.test.sh`, edits step 3 of the README's "Deploying a release") — this issue's build step sits in `build_release`, directly above. #650 (prod-wiring) also edits `deploy.sh`/`deploy.test.sh`/`README.md`, in the service-restart regions (`activate_release`, `report_versions`, the `mailsync-units` fixture, README line 27 and step 5); this issue does not touch those regions.

Caddy runs as user `caddy` and reads the release through `/opt/semprec/current` → `/opt/semprec/releases/<tag>` (`provision.sh` creates `/opt/semprec` and `releases/` with mode `0755`; `deploy.sh` `stage_release` `chmod 0755`s the staging directory and extracts as root, so the built `web/dist` is world-readable).

## Task

1. **Build step** — in `deploy/deploy.sh` `build_release`, after the backend subshell, add a second subshell: `cd "$staging_dir/web" && CI=true pnpm install --frozen-lockfile --package-import-method=copy && pnpm run build` with `|| fail "build of the staged web client failed"`. Update the function comment: the release carries the built `web/dist`; a failed web build is a pre-activation failure like the backend's. `write_release_env`, `run_migrations`, `run_seed` (#644) and everything after are unchanged.
2. **Caddyfile** — in `deploy/Caddyfile`, replace the bare `reverse_proxy 127.0.0.1:8080` with:
   ```
   # Backend-owned URL space — the same prefixes web/vite.config.ts proxies in development.
   @backend path /api/* /mcp /healthz
   handle @backend {
   	reverse_proxy 127.0.0.1:8080
   }

   # Everything else is the web client: static files from the current release, and the SPA's
   # index.html for any path it does not have a file for (every client route is a query
   # parameter on /).
   handle {
   	root * /opt/semprec/current/web/dist
   	try_files {path} /index.html
   	file_server
   }
   ```
   Keep `encode`, `header`, both `request_body` matchers and `log` as they are (`request_body @notfiles` still applies to static requests; harmless). Rewrite the header comment (after #702's line-6 fix): `semprec-api` serves `/api/*`, `/mcp` and `/healthz`; Caddy serves the SPA from the release; WebSocket upgrades on `/api/sync` pass through `reverse_proxy`.
3. **Test** — `deploy/deploy.test.sh`:
   - `commit_release_content`: also write `$AUTHOR/web/package.json` (`{"name":"@semprec/web","private":true}`) so every fixture release has a `web/` directory.
   - `pnpm` mock: when `$1 == run` and `$2 == build`, `mkdir -p "$PWD/dist" && printf '<!doctype html>\n' > "$PWD/dist/index.html"`; when `$1 == install` and `-f "$TEST_STATE/fail-web-build"` and `$PWD` ends in `/web`, `exit 1`.
   - After the first deploy: `test -f "$TEST_SEMPREC_ROOT/releases/v1.0.0/web/dist/index.html"` and `grep -qx 'pnpm run build' "$TEST_STATE/commands"`.
   - In the pre-activation-failure block: `touch "$TEST_STATE/fail-web-build"; expect_refused 'build of the staged web client failed' v1.1.0; rm "$TEST_STATE/fail-web-build"` before the migrate failure case; the existing `assert_current v1.0.0`, "no partial releases" and "no restart" assertions then cover it.
   - The rollback block's "only restarts" assertion is unchanged (no build on rollback).
4. **Validation** — run `caddy validate --config deploy/Caddyfile` with `SEMPREC_DOMAIN=example.test` locally (install `caddy` from its Debian package or the static binary) and paste the output into the PR description.
5. **README** — `deploy/README.md`: in "Deploying a release" step 2 (lines 55-57) add "and `pnpm install --frozen-lockfile` + `pnpm run build` in its `web/`, producing `web/dist`"; in the `Caddyfile` bullet (as extended by #702) replace "Proxies everything to `semprec-api` on `127.0.0.1:8080`" with "Reverse-proxies `/api/*`, `/mcp` and `/healthz` to `semprec-api` on `127.0.0.1:8080` and serves the web client from `/opt/semprec/current/web/dist` with an `index.html` fallback"; append a new `## Web client` section after #702's `## Front door (Caddy)` section: where the SPA is built, that Caddy serves it from the `current` symlink so a deploy/rollback switches the client together with the backend, and that the prefix list must stay in step with `web/vite.config.ts`.

## Acceptance criteria

- When `deploy.sh vX.Y.Z` succeeds, `/opt/semprec/releases/vX.Y.Z/web/dist/index.html` exists and `current` points at that release; when the web build fails, the deploy exits non-zero with `build of the staged web client failed`, no `releases/vX.Y.Z` exists, `current` is unchanged and no service restarted.
- When `https://<domain>/` or `https://<domain>/?page=login` is requested, Caddy answers `index.html` (200, `text/html`) from the current release; `https://<domain>/assets/<hashed>.js` answers the built asset.
- When `https://<domain>/api/auth/session`, `https://<domain>/healthz` or `POST https://<domain>/mcp` is requested, the response comes from `semprec-api` (the JSON body/status the backend produces, not `index.html`); a WebSocket upgrade on `/api/sync` reaches the backend.
- `caddy validate --config deploy/Caddyfile` succeeds with `SEMPREC_DOMAIN` set; `bash deploy/deploy.test.sh` passes.
