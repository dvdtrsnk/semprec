## Context

Model tier rationale: The spawn re-check, exact name lists and explicit environment are specified, with enumerated fixture updates.

`connectMcpServer` (`backend/packages/data/src/mcp/mcpConnectionFactory.ts:58-82`) is the only place an MCP server is spawned or connected. Its callers are:
- tool execution (`backend/packages/data/src/mcp/mcpToolExecution.ts:108`), from agent runs in `semprec-agents` and from the API's `approvalExecute` job;
- tool sync (`backend/packages/data/src/mcp/mcpSync.ts:150`).

Before spawning it only re-parses the config's shape (`parseConnectionConfig`, `:114-120`). It then decrypts the credential (`:122-147`) and runs `new StdioClientTransport({ command, args, env })` (`:177-203`).

#1030 confines `stdio` at write time: only a human REST writer whose user is `admin` in the current tenant may store it, checked by `tenantAllowsStdio(client, userId?)` in `backend/packages/data/src/mcp/stdioTransportPolicy.ts`. It does this inside the MCP server write hooks that #1029 added in `backend/packages/data/src/mcp/mcpServerWriteHook.ts`; those hooks validate every write path through `assertStorableMcpConnectionConfig`, which calls `assertValidMcpConnectionConfig`. A row can still hold `stdio` without that being true today:
- it was written before that guard;
- its tenant's user was later demoted (#1041);
- it was restored from the trash (a restore writes no properties).

The spawn site must re-check, because the spawn is the security boundary.

The child's environment comes from the MCP SDK (1.30.0). It always spawns with `{ ...getDefaultEnvironment(), ...env }`, where `getDefaultEnvironment()` copies only `HOME, LOGNAME, PATH, SHELL, TERM, USER` from the parent, with `shell: false`. Parent secrets such as `DATABASE_URL` or `CREDENTIALS_MASTER_KEY` therefore never reach the child. However:
- the user-controlled `config.env` (`backend/packages/data/src/mcp/mcpConnectionConfig.ts:15`) and `credentialEnvVar` (`:24`) may override those six names (e.g. `PATH`), or inject loader and interpreter hooks (`LD_PRELOAD`, `NODE_OPTIONS`, …);
- the comment at `mcpConnectionFactory.ts:181-185`, which says a non-undefined `env` strips the defaults, is wrong for this SDK version.

## Task

Load `io-hardening` (a spawned process is a resource crossing a trust boundary) and `error-handling` (refuse before any side effect).

1. **Transport re-check.** In `connectMcpServer`, for `transport: "stdio"`, call `tenantAllowsStdio(client)` (no user id: any `admin` user of `app_tenant_default()`) after `parseConnectionConfig` and before `resolveCredential`. When it is false, throw `new McpConnectionError("transport_not_allowed", "MCP server transport is not allowed for this account")`: no credential is decrypted, no `credential_access_log` row is written, and nothing is spawned. Add `"transport_not_allowed"` to `MCP_CONNECTION_ERROR_REASONS` (`backend/packages/data/src/mcp/mcpConnectionError.ts:10-17`). `sse` and `http` are unaffected.
2. **Environment name rule.** In `mcpConnectionConfig.ts`'s `stdio` schema, every `env` key and `credentialEnvVar` must:
   - match `^[A-Za-z_][A-Za-z0-9_]*$`;
   - not be one of the six inherited names `HOME`, `LOGNAME`, `PATH`, `SHELL`, `TERM`, `USER`;
   - not start with `LD_` or `DYLD_`;
   - not be one of `NODE_OPTIONS`, `NODE_PATH`, `PYTHONPATH`, `PYTHONHOME`, `PYTHONSTARTUP`, `PERL5OPT`, `PERL5LIB`, `RUBYOPT`, `RUBYLIB`, `BASH_ENV`, `ENV`, `SHELLOPTS`, `GCONV_PATH`.

   Because `assertValidMcpConnectionConfig` is shared, this one rule is enforced at write time by the MCP server write hooks through `assertStorableMcpConnectionConfig` (`ValidationError`, `field: "connectionConfig"`) and at spawn by `parseConnectionConfig` (`invalid_config`, nothing spawned).
3. **Explicit child environment.** `buildStdioTransport` always passes `env = { ...getDefaultEnvironment(), ...config.env }` plus the injected credential, so the child gets exactly the six inherited names, the config's own names and the credential name. Keep the post-connect scrub (`:201`). Rewrite the comment at `:181-185` to describe the SDK's actual merge.
4. **Tests.**
   - Extend `backend/packages/data/src/__tests__/mcpConnectionFactory.test.ts`.
   - Make the stdio contract fixture record the names (never values) of its environment variables: the child script `backend/packages/data/src/testSupport/fixtures/mcpStdioContractServerScript.mjs` writes them in `writeRecord` (`:51`), and `mcpContractServers.ts` exposes them through `readRecord`.
   - "Admin tenant" in tests means the test user is bound to the sole tenant with `role = 'admin'`; "member" means `role = 'member'`.
   - Add schema cases to a unit test of `mcpConnectionConfig`.
   - Every existing test that spawns a stdio contract server through `connectMcpServer` must first make its user `admin` of the sole tenant, with `createUser(…, { tenantId: <SELECT app_sole_tenant()>, role: "admin" })` (`createUser`'s options from #968): `mcpSync.test.ts`, `approvalRequestExecution.test.ts`, and `backend/packages/agent-runtime/src/__tests__/mcpInvokeTool.test.ts`.

## Acceptance criteria

- **Member refused at spawn.** When the tenant's user is `member`, `connectMcpServer` on a stored `stdio` item rejects with `McpConnectionError` reason `transport_not_allowed`. No child process starts (the fixture records no handshake), and no `credential_access_log` row is written. (integration, `mcpConnectionFactory.test.ts`)
- **Admin connects as before.** When the user is `admin`, the same item connects and receives its credential as before. (integration, `mcpConnectionFactory.test.ts`)
- **Exact child environment.** The child's environment names are exactly the six inherited names present in the parent, the config's own `env` names and `credentialEnvVar`. A variable set only in the test process's `process.env` (e.g. `SEMPREC_TEST_PARENT_SECRET`) is absent. (integration, `mcpConnectionFactory.test.ts`)
- **Forbidden names refused at spawn.** A stored config whose `env` contains `PATH`, `LD_PRELOAD` or `NODE_OPTIONS`, or whose `credentialEnvVar` is `PATH`, rejects with reason `invalid_config` before any spawn. (integration, `mcpConnectionFactory.test.ts`)
- **Forbidden names refused at write.** The same configs are refused at write time by the MCP server write hooks with `details.field = "connectionConfig"`. (integration, `mcpServerWriteHook.test.ts`)
- **Schema.** It accepts ordinary names such as `API_BASE`, `MCP_CONTRACT_CREDENTIAL_ENV_VAR` and `GITHUB_TOKEN`, and rejects each listed forbidden name, `LD_` and `DYLD_` prefixes, and names with `=`, `-` or a leading digit. (unit, `mcpConnectionConfig.unit.test.ts`)
- **Remote unchanged.** `sse` and `http` connections are unaffected by the user's role. (integration, existing tests)
