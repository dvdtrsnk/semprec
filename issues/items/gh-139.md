**Blocked by:** #137, #84

## Context

The core schema contains foreign keys to `users`, but the existing user row is only a placeholder. This issue establishes the persistent authentication model used by every later slice in this batch.

## Task

Create migrations for `users(id,email,password_hash,locale,created_at)`, `sessions(id,user_id,token_hash,platform,created_at,last_seen_at,expires_at,user_agent,revoked_at)`, and `login_attempts(id,email,ip,succeeded,attempted_at)` with the constraints and indexes needed for unique email, unique token hash, expiry/revocation lookup, and recent email-plus-IP failures. Preserve multiple sessions per user. Add shared primitives that hash passwords with Argon2id, generate cryptographically random opaque tokens, store only token hashes, and compare secrets without timing-sensitive string equality. Do not introduce JWTs.

## Scope

### In scope

- Schema, migrations, TypeScript types, repositories, Argon2id and opaque-token primitives.
- `users.locale` defaulting to `cs`; platforms restricted to `web`, `ios`, or `macos`.

### Out of scope

- HTTP login and session middleware, delivered by #140.
- Reset and setup flows.
- Multi-user authorization and `resource_grants` behavior.

## Acceptance criteria

- A migration from the current placeholder user schema preserves existing referenced user IDs and produces the complete schema.
- Two sessions can reference one user; duplicate email and duplicate token hash are rejected.
- Tests demonstrate Argon2id verification and that neither raw passwords nor raw session tokens are persisted.
