## Context
Review of pull request #430 found two defects in `backend/services/semprec-ai-gateway/src/shutdown.ts` and its test:
- `backend/services/semprec-ai-gateway/src/__tests__/shutdown.test.ts` (currently around lines 258-263) only asserts `expect(SHUTDOWN_DRAIN_TIMEOUT_MS).toBe(600_000)` and `expect(typeof create).toBe("function")`; it never actually invokes `createGracefulShutdown` without an explicit `drainTimeoutMs` to verify the real drain-timing behavior the constant is supposed to configure.
- `DRAIN_POLL_INTERVAL_MS` (`shutdown.ts` line 21) is exported but only ever used internally within the same file (line 41); it is never imported anywhere else in the repository.

## Task
- In `shutdown.test.ts`, add a test that invokes `createGracefulShutdown` without an explicit `drainTimeoutMs` and observes that it actually uses `SHUTDOWN_DRAIN_TIMEOUT_MS` as the effective drain timeout (e.g. by asserting on the shutdown's timing behavior with fake timers), rather than only asserting the constant's raw value.
- Remove the `export` keyword from `DRAIN_POLL_INTERVAL_MS` in `shutdown.ts`, keeping it as a module-local constant, since it has no external consumer.

## Touches
- backend/services/semprec-ai-gateway/src/shutdown.ts (the `DRAIN_POLL_INTERVAL_MS` declaration only)
- backend/services/semprec-ai-gateway/src/__tests__/shutdown.test.ts (the `SHUTDOWN_DRAIN_TIMEOUT_MS` test case only)

## Scope
### In scope
- The two items named above.

### Out of scope
- Any other constant, export, or test case in `shutdown.ts` / `shutdown.test.ts`.

## Acceptance criteria
- `DRAIN_POLL_INTERVAL_MS` is no longer exported from `shutdown.ts`, and the package still builds and its existing tests still pass.
- A test in `shutdown.test.ts` fails if `createGracefulShutdown`'s default drain timeout stops actually using `SHUTDOWN_DRAIN_TIMEOUT_MS`.
