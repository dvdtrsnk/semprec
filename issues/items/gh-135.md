**Blocked by:** #134

## Context

Project agents need configuration and recent outcomes without cross-project access or transcript inflation.

## Task

Register core AgentTools `heartbeat.list` and `heartbeat.history({heartbeatId,limit})` through ModuleRegistry. Derive the project exclusively from the persisted current `agent_run.project_item_id`; neither schema accepts a project id. List returns full rule, assignment/purpose, enabled state, and `last_fired_at` for both agent and deterministic heartbeats. Add nullable `agent_runs.heartbeat_id` and populate it for every agent run started by a scheduled, event, or later manual heartbeat. History validates ownership and returns last N (default 10, bounded maximum) status/timestamps/result records, never event transcripts. Deterministic actions that start no agent have no history rows.

## Scope

### In scope

- Two tools, migration/write propagation, scoping, bounds, and errors.

### Out of scope

- `heartbeat.inspect`, deterministic-action log table, and manual trigger.

## Acceptance criteria

- Cross-project ids are indistinguishable from unknown ids.
- Event-started agent runs appear in history.
- Results are bounded and contain no transcript.
