**Blocked by:** #510

## Context

Since #510, `backend/packages/data/src/chokePoint/viewOps.ts` holds all view writes. `addViewItem`, `removeViewItem` and `reorderViewItem` perform one-way adoption through `adoptIfUserWrite`: a user's write to an `ai_agent`-created view flips `createdBy` to `user` and clears `creatorProjectItemId`, in the same transaction and before the mutation. `patchView` instead has its own copy of that condition. It computes `adopt = input.actor.type === "user" && view.createdBy === "ai_agent"` and folds `createdBy` / `creatorProjectItemId` into its own `viewsStore.patchView` call. The rule therefore lives in two places that can drift apart.

## Task

In `patchView`, remove the inline `adopt` computation and the `createdBy` / `creatorProjectItemId` fields from its `viewsStore.patchView` call. Instead, call `await adoptIfUserWrite(client, view, input.actor, viewTypeRegistry)` after the existing `is_default` agent check and before the `viewsStore.patchView` call that applies `name`, `config` and `isDefault`.

Everything else in `patchView` stays as it is: the identity assertion, the not-found error, `assertViewWritable`, the `is_default` rejection for agents, the returned row, and the schema invalidation.

## Touches

- backend/packages/data/src/chokePoint/viewOps.ts (`patchView` only)
- backend/packages/data/src/__tests__/views.test.ts (new test cases in the adoption tests)

## Scope

### In scope
- Routing `patchView`'s adoption through `adoptIfUserWrite`, and the tests below.

### Out of scope
- Changing `adoptIfUserWrite` itself, or any other view method.
- Changing adoption semantics.

## Acceptance criteria

- `pnpm run verify` in `backend/` passes. `src/__tests__/publicSurface.test.ts` passes unmodified.
- `views.test.ts` covers `patchView`:
  - A user patching an agent-created view: the returned row has `createdBy: "user"`, `creatorProjectItemId: null`, and the patched `name`/`config`.
  - A user patching a user-created view, or a `system` view: `createdBy` is unchanged.
  - An agent patching its own view: it stays `ai_agent`-owned.
  - If the patch is rejected (e.g. an agent setting `isDefault`), nothing is adopted: the view reads back unchanged.
- `viewOps.ts` contains the condition `createdBy === "ai_agent"` for adoption only inside `adoptIfUserWrite`.
