## Behavior specification (approved)

Part of the multi-tenancy program specified in #950. Agents, MCP and approvals stay inside their tenant:

1. Only the user who owns a run may decide its approval requests; another user's request behaves like an unknown one.
2. An MCP server's connection configuration is validated on every write path (REST, agent tools, proposal confirm): `stdio` only from a human actor in an admin's tenant, never from an agent; remote transports only `https` to a public DNS host.
3. The transport is re-checked at spawn time; `stdio` children receive only an allowlisted environment; resolved outbound addresses (MCP and web push) are checked at connect time, defeating DNS rebinding.
4. Delegation targets must be projects of the run's tenant; project agent guidance can only be owned by the tenant's user.
5. Concurrently running agent runs are capped per tenant so one tenant cannot starve the others.

## Decisions

- **Why is `stdio` checked at write and at spawn?** → The configuration is read live at spawn; a demoted admin or a row written before the check must not spawn.
- **Why a connect-time address check?** → The SSRF ADR delegates DNS rebinding to egress filtering, which the host does not have; the connect-time check and the egress filter (#957) close it together.

## Out of scope

The stdio sandbox launcher and egress filter (#957); AI budgets (#955).
