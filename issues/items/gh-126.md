**Blocked by:** #125

## Context

Native and MCP tools require one availability pipeline and the same absence-of-capability behavior.

## Task

Adapt active MCP registrations into ModuleRegistry's `agentTools` projection. For a project run, include exactly active-server and active-registration tools whose `project_mcp_grants.granted=true`. Extend generated permission facts with this fourth source. Tool schemas/descriptions come from the synchronized snapshot. A grant controls visibility only; retain `requiresApproval` and `riskClass` for per-invocation approval. Deactivation or grant revocation removes discovery and invocation immediately without deleting registration history.

## Scope

### In scope

- Registry adapter, per-project intersection, manifest facts, and activation behavior.

### Out of scope

- Approval queue implementation and native core operation catalog.

## Acceptance criteria

- Ungranted/inactive tools are absent and unknown on invocation.
- Granted tools preserve approval metadata.
- Two projects can expose different subsets of one server.
