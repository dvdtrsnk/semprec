**Model tier:** medium

## Context

Model tier rationale: Prompt composition and a per-turn prefix in one service over known seams, plus a tool-set choice by thread kind; the behavior is covered by session composition tests but touches what every chat turn sees.

Semp chat runs on Semp threads. #1727 runs queued thread turns in `semprec-agents`, #1566 persists user turns as run events and replays them, and #1388 adds the answer-in-the-user's-language instruction to the agent session prompt.

Today every run, chat included, gets `AGENT_BASE_SYSTEM_PROMPT` in `backend/services/semprec-agents/src/agentSessionComposition.ts`: an English single-task prompt ("You are given one task...") with no date, time or timezone. `createAgentSessionFactoryForRun` appends the project's guidance through `createProjectAgentGuidanceSystemPromptOverride`. The system prompt is set once when a session is created (`piAgentSession.ts`), and a session lives up to 24 hours, so a date placed in the system prompt would go stale after midnight. The schema (databases, property keys, ids, localized names) is generated by `generateSchemaProjection` (`backend/packages/data/src/manifest/schemaProjection.ts`, served by `GET /api/schema`).

This issue gives thread runs a chat-oriented system prompt and a per-turn date prefix. #1751 builds on it to add project notes.

Decisions:
- The chat prompt is composed with the project's guidance (the override still wraps it), never replaces it.
- Current date, time and timezone go into the user message of every turn as a prefix, not into the system prompt.
- The timezone is the tenant timezone from the system settings (the `timezone` property of the System settings item, read with `getSystemTimezone` in `backend/packages/data/src/systemSettings.ts`), so the day rollover and the date in a turn use the same value. A device never supplies the zone for a turn; when the device's zone differs, the client only proposes changing the setting for the user to confirm.
- The thread kind selects the tool set: a plain chat thread gets today's generic operations; an item thread (a thread attached to one Inbox proposal card) gets only the read operations `database.list`, `database.get`, `property.list`, `property.get`, `property.getByKey`, `view.list`, `view.get`, `view.query`, `item.get` and `database.query`. The card-restricted revise tool is added by #1906.

## Task

Load `ai-gateway`, `canonical-keys` and `testing`.

1. In `agentSessionComposition.ts`, when the run belongs to a Semp thread, use a chat system prompt in place of the single-task base prompt. It states: Semp is the user's assistant over their tasks, calendar, notes and other data; the instruction to answer in the user's language (#1388); the data schema from `generateSchemaProjection` (database keys, ids, localized names, properties); approval rules (a tool that reports it needs approval has not run); deleting moves an item to the trash for 30 days and `item.restore` restores it; link objects in answers as `semprec://items/<id>`. The project guidance override is applied on top.
2. Prefix each thread turn's user message with the current date, time and the tenant timezone from the system settings (`getSystemTimezone`), computed per turn (in the place where #1566 builds the user message). The stored replay entry keeps what the user sent, with the prefix recomputed on replay only for the live turn.
3. Select the tool set by thread kind as decided above; the item-thread read set is a constant list checked against `GENERIC_OPERATION_NAMES`.
4. Tests: a thread run's system prompt contains the chat sections and the project guidance; two turns across midnight in one session carry different dates; the prefix uses the timezone stored in the system settings, and after that setting changes the next turn uses the new zone; an item thread session lacks every writing generic operation and a chat thread has them; a non-thread run keeps the old prompt.

### Out of scope

## Acceptance criteria

- When a user asks "what is on my plate today", then the model sees today's date in the timezone of the system settings in that turn.
- When the timezone in the system settings changes, then the next turn's prefix uses the new zone.
- When a second turn arrives in the same session after midnight, then it carries the new date.
- When the project has guidance, then it is still present in the system prompt of a thread run.
- When the thread is an item thread, then the session has no writing generic operation.
