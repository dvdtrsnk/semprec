## Context

Model tier rationale: A three-way merge of block documents down to characters with inline styles, a second persistent kind of offline data with its own write and conflict loop, and a change to the note editor's write contract and live updates; mistakes lose text a person typed.

The native note editor ([[2026-11-19-apple-apps-edit-pages-with-a-native-note-editor]]) reads `GET /api/items/:id/page.md` (canonical Markdown with a strong `ETag`) and writes `PUT /api/items/:id/page.md` with `If-Match` after a pause in typing (`NotePageStore` in `:shared:presentation`, the routes in `HttpJournalRepository`, used by `HttpNotePageRepository` too). A stale `ETag` (`409`) reads the page again and discards the local change, and without a connection nothing can be read or saved. A diary period gets its page on its first change through `PUT /api/journal/periods/:type/:period/doc`, which `[offline-first 03/07]` queues offline with a new id. The server sends `invalidate` frames of scope `doc` (`docId`, `itemId`, `databaseId`, `lastEditedAt`) when a page changes, which `SyncFrame` drops today, so an open note never shows what another device saved. Blocks are `NoteBlock` values (`NoteDocument.parse`, `NoteDocument.markdown`), the text of a block is a list of `InlineRun` (text with bold, italic, code, link, strike, underline, color, highlight). `[offline-first 01/07]` made the `OfflineStore` and its change signals; this issue keeps pages beside the answers, not among them.

## Task

Load `kmp-shared`, `shared-viewmodel`, `testing`, `error-handling`, `adr-conventions` and `mobile-verify`.

1. `NoteMerge.merge(base, local, remote)` in `:shared:domain` (`note/NoteMerge.kt`) merges three versions of a note's canonical Markdown into one:
   - Blocks are compared by their canonical Markdown alone; the blocks both sides kept unchanged (by the longest common subsequence against the base) are fixed points.
   - Between fixed points, a stretch only one side changed takes that side's blocks; one changed the same way on both takes it once; one changed differently is paired position by position: a block changed on both sides is merged (type, indent, done, toggle and page id: a side that changed a field wins, the local side when both did; the text: by character, below), a block deleted on one side and changed on the other keeps the change, and blocks one side added are kept, the local ones first.
   - Text is merged by character with each character's inline style: a stretch only one side changed takes that side's characters; both sides changing one stretch keep the local characters and then the remote ones.
   - Past 4,000,000 cells of a comparison table, the local side is taken for that part.
   - The result is canonical Markdown; a block taken unchanged from one side keeps that side's lines.
2. `PageWrite` gains `Merged(etag, markdown)` (the page now holds the merge, on the server or, until it can be reached, on the device) and `Kept` (the change is kept on the device and sent later). `NotePageRepository.replace` and `JournalRepository.replacePage` take `base`, the Markdown the change was edited from.
3. `KeptPages` in the `OfflineStore` keeps per page `<account>/pages/<fnv>.json` (the item id, the base Markdown and `ETag` last read or written, and the local Markdown while it is not on the server); cleared with the store. `HttpJournalRepository.page` and `replacePage` (and so `HttpNotePageRepository.read` and `replace`) go through it when the store exists:
   - A read returns the kept page (the local Markdown when there is one, else the base, with the base `ETag`) without a request while no change signal came since it was kept, and without a connection. Otherwise it reads the server: without a local change the answer becomes the base; with one, the local change is written as below and its outcome is read.
   - A write merges its Markdown three ways with the device's text of the page against `base` when the device holds another text by then (a write in the background or from another window), keeps the result first, then sends it with `If-Match` of the base (the `ETag` the caller gives, with `base` as its text, when no page is kept). A success makes it the base (`Saved`, or `Merged` when the text differs from what the caller sent), keeps the page fresh and makes the other kept answers stale. `409` reads the server, merges base, local and server with `NoteMerge`, sends the merge with the server's `ETag`, up to three rounds, and answers `Merged` (after three, `Conflict` as today; the merge stays on the device). No answer, a `5xx` or a `429` answers `Kept` (`Merged` when the device holds a merge). `404` forgets the page with its local text and answers `NOT_FOUND`, also for a read whose waiting text it was. Any other failure is returned as today, the text staying on the device.
   - Reads and writes of pages take one lock for every window of the process.
   - A page of a new id from the queue is written once the queue maps it to the server id; a page without a base reads the server first, writes the local text over an empty page and merges with an empty base otherwise.
   - Pages with a local change are written in the background when the connection comes back (the triggers of the queue replay), and every page whose write merged is announced on the page change bus (5).
4. `NotePageStore` passes the Markdown it last read or saved as `base`, shows a `Merged` page (blocks the merge left unchanged keep their editor ids, so the caret stays; no reload problem is raised) and treats `Kept` as saved on the device. Its KDoc says so instead of "the local change dropped".
5. `SyncFrame` keeps `invalidate` frames of scope `doc` (their `itemId`); `SyncSocket` raises them on a `PageChanges` bus of `:shared:domain` with the item id, as it raises topics; a `NoteEditorViewModel` showing that item runs its existing quiet reread when no change waits, and the reread keeps the ids of the blocks it holds unchanged (the server announces the device's own writes too). `NoteEditorViewModelFactory` takes the bus from the SDK.
6. Add the ADR `docs/adr/2026-11-23-note-edits-merge-three-ways-and-wait-on-the-device.md`: a new decision that narrows §4 of [[2026-11-19-apple-apps-edit-pages-with-a-native-note-editor]] (merge instead of discard, edits kept on the device) and leaves the rest of it and [[2026-11-21-a-note-write-outlives-its-editor-viewmodel]] in force.
7. Tests (commonTest): every branch of the merge (blocks and characters, styles, both added, delete against change, the size limit); every branch of the kept pages (fresh read, stale read with and without a local change, offline read, saved, merged, three rounds, kept, other failures, `404`, a write edited from a text the device no longer holds, a new id, a missing base, the background write); `NotePageStore` with `Merged` and `Kept` and the `base` it passes; the `doc` frame; the editor's reread on the bus, keeping the ids, and none while a change waits.

## Scope

### In scope

- Notes readable and editable without a connection, three-way merges instead of discarded edits, and live rereads of an open note.

### Out of scope

- Subpage operations (make, duplicate, rename, open) without a connection: they stay online only.
- Showing the status (`[offline-first 07/07]`).
- The web and WebView editors.

## Acceptance criteria

- A note opened before can be opened, read and edited without a connection; the edit is still there after a restart and reaches the server when the connection is back.
- An edit made while another device changed the same note keeps both changes: different blocks both stay, different words of one block both stay, and nothing typed is discarded.
- A Daily Note created offline for a day that another device created meanwhile ends with both texts.
- A change saved on another device appears in an open note without reopening it, unless a local change is waiting.
- With a connection and no concurrent change, a note reads and saves as today.
