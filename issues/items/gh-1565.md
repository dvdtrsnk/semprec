**Model tier:** high

## Context

Model tier rationale: It changes per-conversation concurrency state, timers and tenant teardown ownership in a long-lived process, where a leaked timer or a missed drop is a cross-thread or cross-tenant defect.

`backend/packages/agent-runtime/src/sempConversation.ts` keeps a `Map<tenantId, ...>` with one conversation per tenant, a `busy` flag, a 24-hour TTL (`DEFAULT_TTL_MS`), and `dropTenant(tenantId)`. With several threads per tenant that is wrong: a turn in thread A would reject thread B with `SEMP_BUSY_ERROR_MESSAGE`, and compression and TTL would be shared. `SempConversation.send(task)` also decides the wake run's `project_item_id` as the Semprec project.

#1560 keys persisted history by thread. This issue keys the in-memory registry the same way. Ordering of turns inside one thread is the job of the turn queue (#1370); this registry only protects one thread from a concurrent turn of its own.

Builds on this: #1727 runs queued turns through the registry, #1568 closes idle thread sessions.

Decision: a wake run gets `thread_id` of its thread and a `project_item_id` by thread kind: the heartbeat's project for a tick thread, the Semprec project for chat and item threads.

## Task

Load `state-writes`, `testing` and the ADR `tenant-deactivation-tears-down-in-process-state` (under `docs/adr/`).

1. Key the registry by `(tenantId, threadId)`. `busy`, the waking flag, the TTL timer and the dropped flag become per thread. A turn in thread A must not produce `SEMP_BUSY_ERROR_MESSAGE` for thread B; a second concurrent turn in the same thread still does.
2. `send` takes the thread identity (thread id, kind, and for tick threads the heartbeat's project item id) and passes `threadId` and the right `project_item_id` to the wake run creation, and the thread filter from #1560 to reconstruction and compaction.
3. TTL timers must enter the tenant context through `runInTenant` when they fire, as other tenant-scoped timers do, and be cleared when a conversation is dropped.
4. `dropTenant(tenantId)` drops every thread conversation of the tenant: in-flight turns are cancelled/closed the way the single conversation was, and all timers are cleared.
5. Keep the registry's public API change minimal and update its single constructor path; production wiring that supplies thread identity belongs to #1727.
6. Tests: two threads of one tenant run in parallel without SEMP_BUSY; same-thread concurrency is rejected; TTL expiry of one thread leaves the other; `dropTenant` closes all threads and leaves other tenants intact; a timer firing runs inside the tenant context.

## Scope

### In scope

- Registry keyed by tenant and thread; per-thread busy, waking, TTL and dropped state; tenant-wide drop.
- Passing thread id and project item id into wake run creation.

### Out of scope

- Queue and ordering of turns across processes: #1370, #1727.
- Persisting user turns: #1566.
- Graceful shutdown of idle thread sessions: #1568.

## Acceptance criteria

- When a turn runs in thread A, then a turn in thread B of the same tenant starts without a busy error.
- When a second turn arrives in a thread that is mid-turn, then it receives the busy error.
- When one thread's TTL expires, then only that conversation is closed.
- When a tenant is deactivated, then all its thread conversations are closed and no timer remains.
