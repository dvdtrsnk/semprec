**Model tier:** low

## Context

Model tier rationale: Three named log lines are rewritten to exact replacement calls with enumerated test assertions.

The logging contract is "identifiers may be logged, property values, mail bodies, tool arguments and decrypted credentials may not" (`backend/packages/shared/src/logger.ts:6-13`). Since #979, every record also carries the active `tenantId`. An operator reading the journal across many tenants must see identifiers only.

Three log lines carry a user's content.
- **Attachment filename.** `ingestAttachments` logs the attachment's filename when it skips an oversized attachment (`backend/packages/data/src/mail/attachments.ts:158-161`, `{ filename: attachment.filename, err: err.message }`). The filename is the sender's content.
- **Raw job error.** `pruneQueueFailedJobs` logs each pruned job's raw `last_error` (`backend/packages/data/src/observability/queueFailedJobsPrune.ts:62-72`). It is arbitrary error text from any task, e.g. a provider response echoing message data. The column is selected only to be logged (`:52`, row type `:13-21`).
- **MCP tool label.** `withUniqueNames` logs a skipped MCP tool's `label` (`backend/services/semprec-agents/src/agentSessionComposition.ts:107`). The label is built as `${grant.mcpServerName}: ${grant.toolName}` (`:79`), which includes the user's own name for the MCP server item.

#1008 and #1011 last edited the mail ingest path, and #993 (after #991) the agents composition. Line numbers above are as of this writing; the call sites are identified by their message strings.

## Task

Load `error-handling`: failure logs keep their diagnostic value through identifiers, never through content.

1. **Attachments.** The skip warning becomes `logger.warn({ messageItemId: input.messageItemId, contentType: attachment.contentType }, "Skipping attachment that exceeded the size cap")`. It carries no `filename` and no error text. Skipping behaviour is unchanged.
2. **Failed-job prune.**
   - Remove `lastError` from the warning, `last_error` from the `SELECT`, and the row type.
   - Keep `jobId`, `jobName`, `jobKey` (built from ids, e.g. `mailAccountSyncJobKey(mailboxItemId)`), `attempts` and `updatedAt`.
   - Update the function's docstring.
3. **Agent tools.**
   - The collision warning becomes `logger.warn({ toolName: tool.name }, "Agent tool name collides with an earlier tool; skipped")`.
   - Export `withUniqueNames` so a unit test can call it. Make no other change to the function.
4. **Tests.**
   - In `backend/packages/data/src/__tests__/mailSync.test.ts`, the oversized-attachment case (around `:940-985`): spy on the mail logger's `warn` (`backend/packages/data/src/mail/logger.ts`). Assert its first argument equals `{ messageItemId: result.itemId, contentType: "application/octet-stream" }`, and that no argument contains `huge.bin`.
   - In `backend/packages/data/src/__tests__/queueFailedJobsPrune.test.ts`: enqueue a failed job whose `last_error` holds a sentinel string. Assert the warning object has no `lastError` key and that no argument contains the sentinel.
   - New `backend/services/semprec-agents/src/__tests__/agentSessionComposition.unit.test.ts`: two tools share a `name` but have different `label`s. `withUniqueNames` keeps the first, and the spied warning carries `{ toolName }` only.

## Scope

### In scope
- Removing the three content fields above, and the tests.

### Out of scope
- Moving the realtime package and the remaining `console.*` calls onto the shared logger, and the `no-console` guard (#1077). Some of those calls also print storage keys that embed filenames.
- Adding `tenantId` to log bindings (#979).
- Content inside error objects' own messages, e.g. a Postgres `detail`.
- Caddy access-log query strings (#967).

## Acceptance criteria

- When an attachment exceeds the size cap during ingest, it is skipped as before, and the single warning names the message item id and content type but not the filename (integration, `mailSync.test.ts`).
- When a permanently failed job is pruned, the warning carries `jobId`, `jobName`, `jobKey`, `attempts` and `updatedAt`, and neither a `lastError` field nor the job's error text (integration, `queueFailedJobsPrune.test.ts`). The existing prune assertions still pass.
- When two agent tools share a name, the later one is skipped and the warning carries `{ toolName }` with no label and no MCP server name (unit, `agentSessionComposition.unit.test.ts`).
