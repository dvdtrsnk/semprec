**Blocked by:** #1690
**Model tier:** high

## Context

Model tier rationale: A wide soft-delete of a mailbox's folders, messages and drafts in chunked background transactions, with a thread rule that must spare other mailboxes' mail, is a destructive data change whose cleanup ownership spans the route and a queue job.

#1690 adds `DELETE /api/mail/mailboxes/:id`, which in one transaction soft-deletes the Mailboxes item and removes its credential and sync state. `softDeleteItem` (`backend/packages/data/src/chokePoint/itemTrash.ts`) cascades only into embedded databases, so the mailbox's Folders and Emails stay live and visible after the removal. A mailbox can hold many thousands of messages, so they are soft-deleted in chunks (`docs/adr/2026-09-28-chunked-transactions-for-large-background-sweeps.md`). #1501 defines which messages, drafts and threads a removal affects; this job must remove exactly what that report counts.

## Task

Load `state-writes`, `testing` and read `docs/adr/2026-09-28-chunked-transactions-for-large-background-sweeps.md`.

1. Add the core task `mailboxRemoval` (tenant lane) to `CORE_TASK_NAMES`, `CORE_TASK_AFFINITY` and the tenant mode in `backend/packages/queue/src/index.ts`, with the stable job key `mailbox-removal-<mailboxItemId>`, and its handler in `createCoreTaskList` (`backend/packages/data/src/worker.ts`).
2. In `backend/packages/data/src/mail/mailboxRemoval.ts`, enqueue the task inside the removal transaction of #1690, so it exists only when the removal commits.
3. Implement the handler in `backend/packages/data/src/mail/mailboxRemovalJob.ts`: soft-delete the mailbox's Folders and Emails, including drafts, in chunked transactions. The selection follows the counting rules of #1501: a thread that has a non-deleted message from another mailbox and its messages from other mailboxes are untouched, and the files of attachments are kept. Every row it soft-deletes gets the mailbox item's own deletion time (`deleted_at` of the Mailboxes item), so a restore of the mailbox can find exactly these rows. A rerun after a partial run continues without error and changes nothing already done.
4. Tests: after a removal the mailbox's folders, messages and drafts are soft-deleted and absent from lists; a thread with a message from another mailbox stays listed with that message; attachment files remain; the number of soft-deleted messages, drafts and threads equals the counts the removal impact report returned before the removal; a removal that rolls back enqueues no job; an interrupted run resumed by a rerun ends in the same state; a second tenant's mail is untouched.

## Scope

### In scope

- The chunked job that soft-deletes a removed mailbox's folders and messages and its enqueue from the removal transaction.

### Out of scope

- The removal route and transaction (#1690).
- Provider cleanup after commit, refusing a generic delete and restoring a removed mailbox (#2030, #2031 and #2032).
- Deleting rows when an item is permanently purged (#1691).

## Acceptance criteria

- When a mailbox is removed, then its folders, messages and drafts are soft-deleted and absent from lists.
- When a thread has a message from another mailbox, then that thread and that message remain.
- When the mailbox's messages had attachments, then the attachment files remain.
- When the removal impact was requested before the removal, then the job soft-deletes exactly the messages, drafts and threads it counted.
- When the removal transaction rolls back, then no job exists.
- Every folder and message soft-deleted by the job carries the mailbox's deletion time.
