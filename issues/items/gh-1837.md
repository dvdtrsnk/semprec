## Context

Model tier rationale: One read-only aggregation route that composes helpers delivered by seven blockers over existing manifest-route and tenant-isolation test patterns, with no new write, lifecycle or authorization contract.

The Overview screen shows badges and live counts: pending Inbox cards, unread mail, tasks for today, the number of active Semp problems, an item count per collection, an active-project count per area, and a link to today's Journal entry. Today the API has no summary route for it; the client would have to call five or more endpoints. `GET /api/system-health` (`backend/packages/data/src/observability/systemHealthRouteHandler.ts`) is the only existing aggregate route and is a technical snapshot without any of these numbers.

This issue adds one read route, `GET /api/overview`, owned by the `schemaCore` module as a manifest custom route with the `single-consumer-read` justification (`docs/adr/2026-09-11-module-manifest-custom-routes.md`), exactly like `systemHealthReport` in `backend/packages/data/src/chokePoint/schemaCoreModuleManifest.ts`. The route owns no counting logic. Every number is computed by its owner's own server-side function, the same one the owner's route calls, so the Overview can never disagree with the screen it links to.

Response body:

```
{
  inboxPending: number,
  mailUnread: number,
  tasksToday: number,
  areas: [{ id: string, activeProjectCount: number }],
  collections: [{ databaseId: string, ownerModuleId: string, itemCount: number }],
  problemCount: number,
  journalTodayItemId: string | null
}
```

Sources (each is delivered by a blocker; call the exported function, do not re-implement the query):

- `inboxPending`: the pending-card count behind #1823 (its `total`).
- `mailUnread`: the unread-inbox count of the mail summary from #1688 (`unreadInbox`).
- `tasksToday`: the open-task count of the Tasks `today` view from #1798 (`countTasksToday`, which counts only `notDone` tasks of the list).
- `collections`: one batched `item.count` call from #1709 over the tenant's collection databases, with the Projects collection counted without its system databases; `ownerModuleId` is the owning module of each database.
- `areas`: the area overview rule from #1760 (an `item.count` grouped by area, counting only active projects).
- `problemCount`: `activeCount` of the Semp status summary from #1631.
- `journalTodayItemId`: the id of the live (not trashed) Journal day item whose period key is today's date in the tenant timezone, or `null` when it does not exist yet. The key is built with the period-key helper from #1431 and the tenant timezone from `getSystemTimezone` (`backend/packages/data/src/systemSettings.ts`). The route only looks the item up; it never creates it (`getOrCreateJournalItem` in `backend/packages/data/src/journal/journalStore.ts` stays the only creation path).

Decision: the fields are additive. A field is added together with the blocker that provides its source, so the response shape above is the final one but each field is wired to its source function in this issue only because all sources are blockers of this issue.

Decision: `tasksToday` counts only open tasks of the Today list (7 in the design data, not 8): the badge shows what is left to do. Tasks completed today stay in the Today list but are not counted. The count is the one #1798 defines for the badge (`countTasksToday`); this route never applies its own filter.

Later issues build on this route: the Overview invalidation frame #1951 tells clients when to re-read it, and the Trash issues #1851, #1873 and #1904 follow it in the program.

Shared-file ordering: this issue also waits for #1835 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `testing`, `canonical-keys` and `io-hardening`.

1. Create `backend/packages/data/src/overview/overviewSummary.ts` exporting `getOverviewSummary(pool)`. It runs in the caller's tenant scope (it throws without one, like `getSystemHealthReport`), calls the source functions listed in Context, and returns the body above. It takes no request input.
2. Create `backend/packages/data/src/overview/overviewRouteHandler.ts` exporting `createOverviewRouteHandler(pool)` that returns `{ status: 200, body }` from `getOverviewSummary`; thin mapping only.
3. Register the route in `schemaCoreModuleManifest.ts`: re-export `createOverviewRouteHandler` and add a `customRoutes` entry `{ name: "overviewSummary", method: "GET", path: "/api/overview", handlerExport: "createOverviewRouteHandler", justification: "single-consumer-read" }`, with a comment naming the single consumer.
4. Add the route to `backend/services/semprec-api/src/routeMatrix.ts` (tenant-scoped, not public), its handler file to `ROUTE_HANDLER_FILES` in `backend/services/semprec-api/src/__tests__/chokePointWriteBoundary.unit.test.ts`, and a cross-tenant case to `backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts`.
5. Define the response shape as a zod schema next to the handler and validate the assembled body against it before returning.
6. Tests: a unit test per field asserting it equals the owner's route/function output on the same seed data (see Acceptance criteria), and the isolation test.

## Scope

### In scope

- `GET /api/overview` with all seven fields, tenant-scoped, read-only.
- The route-matrix entry and tenant-isolation test.

### Out of scope

- Realtime invalidation of the overview, including the midnight rollover producer: #1951.
- Creating today's Journal entry: the client does it through the lazy period request #1541; this route never creates it.
- The counting logic of any field; it stays with the owning issue listed in Context.
- Any scheduled job or change to the global worker crontab.

## Acceptance criteria

- When the route is called, then `inboxPending` equals `total` of `GET /api/inbox/cards/count`, `mailUnread` equals `unreadInbox` of `GET /api/mail/summary`, `problemCount` equals `activeCount` of `GET /api/semp-status/summary`, and `tasksToday` equals `countTasksToday` from #1798 (the `notDone` tasks of the Tasks `today` view), on the same data.
- When the Today list holds 7 open tasks and 1 task completed today, then `tasksToday` is 7.
- When the route is called, then each entry of `collections` and `areas` equals the corresponding `item.count` with the same filter.
- When today's Journal day item does not exist in the tenant timezone, then `journalTodayItemId` is `null`; when it exists and is live, then it is that item's id; a trashed day item is not returned.
- When the tenant timezone differs from UTC and the instant is near midnight, then `journalTodayItemId` uses the date in the tenant timezone.
- When tenant B calls the route, then nothing from tenant A appears in any field.
- The route is listed in the route matrix and rejects unauthenticated calls like the other tenant routes.
