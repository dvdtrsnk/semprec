**Blocked by:** #234, #233, #142

## Context

Authentication flows are complete and the only account can be bootstrapped through #233/#234. The last slice makes authentication universal rather than opt-in per route: every existing path goes through the shared middleware from #140, and only an explicit, documented exceptions list stays public.

## Task

Inventory every HTTP, WS-upgrade, module route, and view path delivered through #33 and place the shared middleware from #140 in front of it; keep only explicitly documented bootstrap/health-style exceptions public. The exceptions list is a single documented artifact and consists of the login endpoint (#140), the password-reset request and consume endpoints (#142), the `/setup` API and wizard (#233, #234), and health-style probes; nothing else is public. Add a route-matrix test that fails when a newly registered protected route lacks auth.

## Scope

### In scope

- Route inventory, the exceptions list, middleware placement across HTTP, WS-upgrade, module, and view paths, and the route-matrix test.

### Out of scope

- First-account setup API and wizard — delivered by #233 and #234.
- Provisioning the production secret file, delivered by the operations batch.
- Public signup, additional accounts, roles, TOTP, and login-screen localization.

## Acceptance criteria

- Automated route inventory proves all pre-existing non-bootstrap paths reject unauthenticated access.
- Every public path is in the documented exceptions list, and the route-matrix test fails when a newly registered route is neither protected nor listed.
