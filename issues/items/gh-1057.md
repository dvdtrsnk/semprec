**Blocked by:** #975, #993, #1035
**Model tier:** medium

## Context

Model tier rationale: Four defined AI gateway endpoints use the established tenant harness in a bounded test matrix.

Every model call goes through `semprec-ai-gateway`, which records each call in `ai_gateway_calls` (a tenant table) and enforces the AI budgets. Its dispatcher (`backend/services/semprec-ai-gateway/src/app.ts:14-53`) routes four endpoints through an `if` chain — `/internal/complete` (`:27`), `/internal/pi/messages` (`:31`), `/internal/diarize` and `/internal/transcribe` (`:35`, behind the audio concurrency limit) — and answers 404 for anything else (`:50-51`). There is no enumerable endpoint list, so a new endpoint can never be forced into an isolation test. The REST/MCP, realtime and background suites (#1053, #1054, #1056) do not cover the gateway; this issue does, and the release checkpoint #1058 requires it.

What the blockers established:

- #993: trusted callers send `x-semprec-tenant-id: <uuid>` taken from their own tenant scope. After the bearer-token check the gateway validates it (not one canonical UUID → 400) and runs the rest of the request in `runInTenant(<header>)`, so the `ai_gateway_calls` row is attributed by the column default. The reservation insert is conditional on the tenant being `active` and on the run id (pi messages, `x-semprec-agent-run-id`) or project id (complete, `projectItemId`) being visible in that tenant; otherwise it answers `403` with code `attribution_refused` and no details, so a foreign id and an unknown id give byte-identical bodies, and the provider is never called. A request without the header runs with no scope, which strict mode refuses.
- #1035: per-tenant caps from the global table `tenant_ai_budgets` (a missing row refuses) plus the global caps `AI_GLOBAL_DAILY_CAP_USD`/`AI_GLOBAL_MONTHLY_CAP_USD` (`GlobalAiCaps` in the handler options); every refusal is `403 { "error": "AI budget exceeded", "code": "budget_exceeded" }`, byte-identical whichever cap tripped, and writes no row.
- #975: `createTestTenant`, `createRuntimeRolePool` and `getTenantZeroId` through `@semprec/data/testSupport`. The gateway connects as `semprec_side`.

The existing route tests (`backend/services/semprec-ai-gateway/src/__tests__/completeHandler.test.ts:58-110`, `audioHandler.test.ts`, `piMessagesHandler.test.ts`) show how to drive `createDispatcher` with fake providers.

## Task

Load `ai-gateway` (the gateway contract; no real provider is ever called) and `io-hardening` (the dispatcher is an inbound edge).

1. **Endpoint table** in `app.ts`, behaviour unchanged: export `GATEWAY_ENDPOINTS = ["/internal/complete", "/internal/pi/messages", "/internal/diarize", "/internal/transcribe"] as const` and `type GatewayEndpoint = (typeof GATEWAY_ENDPOINTS)[number]`. `createDispatcher` builds a `Record<GatewayEndpoint, (req, res) => void>` (the two audio entries keep the concurrency limit and its 503 exactly as today) and dispatches by looking the pathname up in it; any other path keeps the 404. The docstring says every endpoint must be an entry of this table.
2. **Suite** `backend/services/semprec-ai-gateway/src/__tests__/tenantIsolationGateway.test.ts`. Its `beforeAll` sets `process.env.SEMPREC_TENANT_SCOPE = "strict"` (read on every call by `enforceTenantScope`, #978) and `afterAll` restores it.
   - **Fixture.** Tenants A and B from `createTestTenant(adminPool)`, provisioned with `provisionTenant(pool, id)` (#1005); in each, inside `runInTenant`, a Projects item and an agent run; a `tenant_ai_budgets` row per tenant inserted on the admin pool; a third tenant C with no budget row and a fourth created `suspended`. The dispatcher is `createDispatcher` over `createRuntimeRolePool(adminPool, "semprec_side")` with counting fake providers and test `globalCaps`.
   - **Exhaustiveness.** A case table declared `satisfies Record<GatewayEndpoint, GatewayCase>`, plus a test that its keys equal `GATEWAY_ENDPOINTS`. Each case states which id (run, project or none) the endpoint attributes.
   - **Comparison rule.** Equal status and equal body text after every requested id is replaced with `<id>`.
3. **Per endpoint:**
   - **Attribution.** With A's header (and A's run or project id where the endpoint takes one) the call succeeds; exactly one new `ai_gateway_calls` row is visible inside `runInTenant(A)`, carrying that id, and the rows visible in B and in tenant zero are unchanged.
   - **Foreign id** (endpoints that take a run or project id). B's header with A's id answers exactly as B's header with a random UUID (`403 attribution_refused`); no row is written in any tenant and the fake provider is not called.
   - **Tenant header.** A malformed header gets 400; the suspended tenant's id and a random UUID as header get identical responses; a request without the header gets a non-2xx response; none of them writes a row or calls the provider.
   - **Budgets.** With B's own cap exhausted, B is refused while the same call for A succeeds; B's refusal body is byte-identical to C's (no budget row) and to the refusal A gets once the global cap is exhausted; refusals write no row.
4. If a case fails because the gateway really leaks, do not change the handlers here: leave the failing case in the pull request and stop, reporting the endpoint and the leak — the fix belongs to #993's or #1035's area in a new issue.

## Scope

### In scope

### Out of scope

- REST/MCP routes (#1053), realtime (#1054), queue tasks (#1056).
- Changing the header contract, the attribution guard or the budget rules (#993, #1035); fixing any leak the suite finds (Task step 4).
- Admin views of spend (#1039).

## Acceptance criteria

- Integration: adding a path to `GATEWAY_ENDPOINTS` without a case fails `pnpm -r run build`; the keys test fails when the table and the cases differ.
- Integration: existing gateway route tests pass unchanged (the dispatch refactor changes no response, including the audio 503 and the 404).
- Integration: for every endpoint, A's call is attributed to A only — one new row inside `runInTenant(A)`, none in B or tenant zero.
- Integration: for every endpoint taking a run or project id, B naming A's id is answered byte-identically to B naming a random id, writes no row and never reaches the provider.
- Integration: malformed, missing, suspended-tenant and unknown-tenant headers are refused without a row or a provider call, and the suspended and unknown cases are byte-identical.
- Integration: budget refusals for an own cap, a missing budget row and the global cap are byte-identical `403 budget_exceeded` bodies, write no row, and do not stop the other tenant's calls.
- The suite runs on a `semprec_side` runtime-role pool with strict scope enforcement in effect.
