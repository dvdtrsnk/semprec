## Context

Model tier rationale: A test-configuration change in two vitest config files with an existing environment variable; no production code changes.

Relay's `verify-backend` step keeps at most 4,194,304 bytes of a command's output. Then it truncates with "[relay] output truncated at 4194304 bytes; the rest was discarded". On 2026-10-16 the backend verify output of the fix runs for #1175 and #1176 hit that limit. The implement run for #1033 then failed because the agent could not find the failing step in the truncated log; a rerun passed.

Nearly all of that output is `{"level":40,…,"msg":"tenant_scope_missing"}` lines. `enforceTenantScope` in `backend/packages/shared/src/tenantScope.ts` runs in warn mode when `SEMPREC_TENANT_SCOPE` is unset. Warn mode logs a `tenant_scope_missing` warning with the full stack for every distinct stack it has not seen, up to 1,000 per process. The integration tier runs many test files that reach the database outside any scope by design, and each line carries a stack of several kilobytes. A real failure is then buried, or cut off entirely.

`createLogger` in `backend/packages/shared/src/logger.ts` reads `LOG_LEVEL`, so the tests can raise the level without touching production code. `vi.spyOn(logger, "warn")` assertions intercept the method call, not the output, so they keep working at a higher level.

## Task

Load `testing`.

1. In `backend/vitest.integration.config.ts` and `backend/vitest.e2e.config.ts`, set `test.env` so `LOG_LEVEL` is `"error"` unless the developer already exported a `LOG_LEVEL` (`process.env.LOG_LEVEL ?? "error"`). Add a comment naming this issue's reason: warn-level output, chiefly `tenant_scope_missing`, would otherwise exceed Relay's output limit and hide real failures.
2. Run backend `pnpm run verify` and record two sizes in the pull request description: the byte size of its output with this change, and the size on `develop`, or the size of the integration tier alone on each.

## Touches

- backend/vitest.integration.config.ts
- backend/vitest.e2e.config.ts

## Scope

### In scope

- Quieter integration and e2e test output through `LOG_LEVEL`.

### Out of scope

- Changing `enforceTenantScope`'s warn mode or the logger itself.
- Putting the remaining scope-less test paths into a tenant scope (the tenant-scope enforcement batches).
- The unit tier (`vitest.unit.config.ts`), whose logger tests assert output at specific levels.

## Acceptance criteria

- Integration: with `LOG_LEVEL` unset, the integration and e2e tiers run with `LOG_LEVEL=error`; an exported `LOG_LEVEL` still wins.
- Integration: every existing test passes unchanged, including those that spy on `logger.warn`.
- The pull request description reports the verify output size before and after, and the after size is well below 4,194,304 bytes.
