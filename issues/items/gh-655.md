## Context

`docs/adr/2026-09-10-typed-rows-at-the-postgres-boundary.md` types what a query selects; a JSONB column arrives as `unknown`/`Record<string, unknown>` and still has to be parsed before it is trusted (`backend/review-rules/rules.md`: "no `any` at a module boundary — parse/validate at the edge"). `packages/data/src/dbRowValidation.ts` exists for exactly that (`assertKnownValue`, `assertShape`), and most JSONB readers use zod (`scheduler/rule.ts`, `views/viewConfig.ts`, `tasks/taskRecurrenceRule.ts`). Six readers in `packages/data` still cast instead:

- `mail/personLinkingActions.ts` line 30 `const config = actionConfig as unknown as PersonEmailReindexActionConfig;` and line 58 `… as unknown as LinkEmailToPeopleActionConfig;` — `actionConfig` is the heartbeat's `project_heartbeats.action_config` JSONB (`Record<string, unknown>`); a missing `peopleDatabaseId` / `emailsDatabaseId` / `senderPeopleKey` / `recipientsPeopleKey` reaches `itemsStore.getItemById` as `undefined`.
- `rollup/config.ts` line 145 `(property.config as { relationPropertyKey?: string }).relationPropertyKey` and line 148 `(relationProperty.config as { targetDatabaseId?: string }).targetDatabaseId` — `PropertyRow.config` is `Record<string, unknown>` (`types.ts` line 79); a non-string value is typed as a string here even though `validateRollupConfig` on line 149 then validates the whole config.
- `inbox/proposalActions.ts` line 148 and line 249 `proposal.properties.proposal as ProposalEnvelope | null` — the Processing proposal item's `proposal` JSONB property; `transcriptCardRole(current)` and `assertValidEnvelopeForCard` read `entityKind`, `target` and `properties` off it unchecked.
- `inbox/inboxTickAction.ts` line 201 `const existing = Array.isArray(history) ? (history as ProposalHistoryEntry[]) : [];` in `appendHistoryEntry` — only the array-ness is checked, the entries are not (its doc comment promises to tolerate "a missing/malformed stored value as empty").
- `systemSettings.ts` lines 35-38 `client.query<{ properties: { timezone?: string } }>` in `getSystemTimezone` and lines 64-67 `client.query<{ properties: SettingsProperties }>` in `readSettingsProperties` — the row type argument asserts the JSONB shape (`timezone` string, `dailyBudgetUsd` / `monthlyBudgetUsd` number-or-null) that nothing verifies; a `timezone: 42` would be returned as a string and fail later inside `Intl`.

Left as they are, on purpose: `scheduler/schedulerStore.ts` line 55 (`row.rule as AnyHeartbeatRule` only on the documented `tolerateUnknownRuleKind` fallback after `parseHeartbeatRule` has already failed), `scheduler/sweep.ts` lines 105-137 (validates the job payload field by field), `inbox/proposalActions.ts` line 304 (cast after `assertValidProposalEnvelope` has checked the same fields, with a comment saying so).

## Task

- `mail/personLinkingActions.ts`: add two module-level zod schemas next to the interfaces — `personEmailReindexActionConfigSchema = z.object({ peopleDatabaseId: z.string().min(1) })` and `linkEmailToPeopleActionConfigSchema = z.object({ emailsDatabaseId: z.string().min(1), senderPeopleKey: z.string().min(1), recipientsPeopleKey: z.string().min(1) })` — derive the two exported interfaces from them with `z.infer` (keep the exported names), and replace each `as unknown as` with a `safeParse`; on failure throw `new Error(\`Malformed action config for ${MAIL_REINDEX_PERSON_EMAILS_ACTION_ID}: ${result.error.message}\`)` (resp. `MAIL_LINK_EMAIL_TO_PEOPLE_ACTION_ID`) so the heartbeat sweep records it as that heartbeat's failure (`recordHeartbeatFailure`) instead of a `NotFoundError` from a query with `undefined`. `zod` is already a dependency of `@semprec/data`.
- `rollup/config.ts` `applyRollupConfig`: replace both casts with `typeof` narrowing — `const relationPropertyKey = property.config.relationPropertyKey; … p.key === relationPropertyKey` only when `typeof relationPropertyKey === "string"` (otherwise `relationProperty` is `undefined`), and `typeof relationProperty.config.targetDatabaseId === "string" ? relationProperty.config.targetDatabaseId : undefined`. `validateRollupConfig` stays the full validator.
- `inbox/inboxTickAction.ts`: add and export `proposalEnvelopeSchema` (zod: `entityKind: z.enum(["pageContent", "database", "relation"])`, `target: z.string().min(1)`, `properties: z.record(z.string(), z.unknown())` (zod 4)) and `parseStoredProposalEnvelope(value: unknown, proposalId: string): ProposalEnvelope | null` — `null`/`undefined` → `null`; a parse failure → `throw new Error(\`Malformed proposal envelope on proposal ${proposalId}\`)`; make `ProposalEnvelope` `z.infer` of the schema (same shape as today). Add `proposalHistoryEntrySchema` (`author: z.enum(["ai", "user"])`, `message: z.string()`, `at: z.string()`) and make `appendHistoryEntry` use `z.array(proposalHistoryEntrySchema).safeParse(history)`: success → its `data`, failure (including a non-array) → `[]`, which is the tolerance its doc comment already promises. Derive `ProposalHistoryEntry` from the schema.
- `inbox/proposalActions.ts` lines 148 and 249: `parseStoredProposalEnvelope(proposal.properties.proposal, proposal.id)` instead of the cast; the `if (!envelope) throw new ValidationError("Proposal has no computed envelope to confirm", …)` branch stays.
- `systemSettings.ts`: query `{ properties: Record<string, unknown> }` in both readers and add one private `toSettingsProperties(raw: Record<string, unknown>): SettingsProperties` that uses `assertShape` from `dbRowValidation.ts`: `timezone` absent or a string, `dailyBudgetUsd` and `monthlyBudgetUsd` absent, `null` or a finite number; anything else throws `assertShape`'s `Malformed system settings properties in database row`. `getSystemTimezone`, `readSettingsProperties`, `getAiBudgets` and `getAiBudgetsWithTimezone` keep their signatures and defaults (`DEFAULT_TIMEZONE`, `DEFAULT_DAILY_BUDGET_USD`, explicit `null` = uncapped).
- Tests (integration tier, `packages/data/src/__tests__/`, each against the embedded Postgres):
  - `mailSync.test.ts`: in `describe("person <-> email address linking (issue #26)")`, one case per action: running the handler with `actionConfig: {}` rejects with an `Error` whose message starts with `Malformed action config for` and writes nothing to `person_email_index`.
  - `rollupConfig.test.ts`: `applyRollupConfig` on a rollup property whose `config.relationPropertyKey` is a number throws the same `ValidationError` `validateRollupConfig` throws for a missing relation property (not a `TypeError`).
  - `proposalActions.test.ts`: confirming a proposal whose `proposal` JSONB was set (with a direct `UPDATE items SET properties = …` in the test) to `{ entityKind: "database" }` (no `target`) rejects with `Malformed proposal envelope on proposal <id>`; a proposal whose `history` holds one well-formed and one malformed entry gets, after `appendHistoryEntry`, exactly one entry (the new one) — documenting the tolerance.
  - `systemSettings.test.ts`: after `UPDATE items SET properties = jsonb_set(properties, '{timezone}', '42')` on the settings row, `getSystemTimezone` rejects with `Malformed system settings properties in database row`; after `jsonb_set(properties, '{dailyBudgetUsd}', 'null')`, `getAiBudgets` resolves `dailyBudgetUsd: null` (unchanged behaviour, now asserted).

## Scope

### In scope

- Replacing the six listed cast sites with parsed readers and the tests that prove a malformed stored value is reported as a named error (or tolerated where the reader already documents tolerance).

### Out of scope

- `scheduler/schedulerStore.ts` line 55, `scheduler/sweep.ts`, `proposalActions.ts` line 304 — already guarded (see Context).
- The `(value as { field?: unknown }).field` narrowing idiom in `services/semprec-ai-gateway`, `packages/ai-gateway-client`, `services/semprec-api/src/mcp/mcpHandler.ts`, `agentRunHandler.ts` and `packages/agent-runtime/src/lifecycleAdapter.ts` — those check the field with `typeof` right after and are not unchecked casts.
- Switching the `no-unsafe-*` lint rules on — #654 (different files).
- Moving the choke point's mail/transcription imports — #659 (`mail/mailMessageFlagSyncStore.ts`, `transcription/`, `chokePoint/`); this issue does not touch those files.
- Validating `timezone` as an IANA name on read (`assertValidTimezone` runs on write in `chokePoint/itemWrites.ts`; a read-side rejection is a separate decision).

## Acceptance criteria

- When a heartbeat whose `action_config` lacks `peopleDatabaseId` fires the `mail.reindexPersonEmails` action, the run fails with `Malformed action config for mail.reindexPersonEmails: …` and no `person_email_index` row is written.
- When `applyRollupConfig` sees a non-string `relationPropertyKey`, it throws `validateRollupConfig`'s `ValidationError`, never a `TypeError`.
- When a Processing proposal's stored `proposal` JSONB is not `null` and not `{ entityKind, target, properties }`, confirming it rejects with `Malformed proposal envelope on proposal <id>`; when it is `null`, the existing `Proposal has no computed envelope to confirm` `ValidationError` is unchanged.
- When the settings row's `timezone` is not a string, `getSystemTimezone` and `getAiBudgetsWithTimezone` reject with `Malformed system settings properties in database row`; when the key is absent they resolve `Europe/Prague` as today.
- When `grep -n "as unknown as" backend/packages/data/src --include=*.ts -r --exclude-dir=__tests__` runs, it matches nothing.
- Every existing case in the four touched test files and in `inboxTick.test.ts`, `inboxTickProposal.test.ts`, `rollup.test.ts` still passes unchanged.
