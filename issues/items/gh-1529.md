## Context

Model tier rationale: One new user-owned property with its seed, cutover, label and a write-time assignment rule reuses existing patterns across a defined seam, but it shares the pre-write transform file with the project rules, so correctness depends on that mechanism.

The overview lists the user's pinned projects in a deliberate order, not alphabetically. Today a project has only the `pinned` checkbox (`seedTenDatabases.ts`), so the order of pinned projects is undefined. The alternatives were a manually ordered system view or ordering by title; this issue takes the simplest explicit one.

Decision: add `Projects.pinnedOrder`, a number property owned by the user. When a project becomes pinned without an explicit `pinnedOrder`, it is placed last: highest `pinnedOrder` among currently pinned live projects plus one (1 when there is none). When a project is unpinned (by the user or by the automatic unpin of a finished project), `pinnedOrder` is cleared to null so pinning it again places it last. Existing pinned projects are numbered once by title (Czech collation as in the sort compiler, ties by id) in the cutover.

The rule is a pre-write transform of the Projects database, registered the same way as the rules of #1520 (mechanism #1422) in `backend/packages/data/src/projects/projectWriteTransform.ts`, and must run after them so a finished project that is unpinned by that rule also loses its order. Item create hooks cannot change an incoming patch; the transform can.

Shared-file ordering: this issue also waits for #1517 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `state-writes`, `canonical-keys` and `testing`.

1. Add property `pinnedOrder` (type `number`, `owner: 'user'`) to the Projects database in `seedTenDatabases.ts`.
2. Add a cutover step (new `backend/packages/data/src/seed/projectsPinnedOrderCutoverMigration.ts`, registered in `runTenantCutoverMigrations`) that, for each maintained tenant including suspended ones, adds the property under `LOCK TABLE properties IN EXCLUSIVE MODE` when missing and numbers existing pinned live projects without a value (1..n by title, ties by id), writing through `migrateItemPropertyWithClient`. A second run changes nothing.
3. Extend the Projects pre-write transform: on a write that results in `pinned: true` with no `pinnedOrder` in the patch and none stored, set `pinnedOrder` to max + 1 under a transaction-scoped advisory lock keyed by the Projects database id; on a write that results in `pinned` false or absent, set `pinnedOrder` to null. An explicitly supplied `pinnedOrder` on a pinned project is kept.
4. Add i18n keys `property.projects.pinnedOrder.name` ("Pořadí připnutí" in `cs.json`, "Pin order" in `en.json`) and bump the `version` of `seed/systemDatabasesModuleManifest.ts`.
5. Tests: pin three projects in turn and query pinned projects sorted by `pinnedOrder` ascending (they come back in pin order); unpin and re-pin moves a project last; marking a pinned project done unpins it and clears its order; the cutover numbers pre-existing pinned projects and is idempotent; concurrent pins get distinct orders.

## Scope

### In scope

- The `pinnedOrder` property, its assignment and clearing rules, the cutover numbering, the label and tests.

### Out of scope

- Unpinning finished and archived projects: #1520.
- Expanding the project's area on the pinned query: #1518.
- A UI or endpoint for reordering pinned projects.
- Hiding system projects from the overview.

## Acceptance criteria

- When three projects are pinned one after another, then querying pinned projects sorted by `pinnedOrder` returns them in pinning order.
- When a pinned project is unpinned and pinned again, then it is last.
- When a pinned project is set to `done`, then it is unpinned and its `pinnedOrder` is null.
- After the cutover, pre-existing pinned projects have consecutive orders by title; running it again changes nothing.
- Two concurrent pins never receive the same order.
- The full backend `pnpm run verify` passes.
