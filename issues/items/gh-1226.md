## Context

Model tier rationale: This is a focused test-only change in one existing integration test. It uses the current conversation lifecycle and real Postgres harness without changing any production contract.

The backend integration test `calls reconstructHistory on every wake and seeds the woken session's initialState from its result` in `backend/packages/agent-runtime/src/__tests__/sempConversation.test.ts` blocked the merge of PR #1225 for issue #1084: it expected two reconstruction calls but observed only one.

The test currently uses a 40 ms conversation TTL, sleeps for `ttlMs + 150`, then sends the second message. That delay does not await the asynchronous expiry work. `SempConversation.scheduleTtl()` starts `pause(tenantId)` without awaiting it; `pause()` sets the entry busy synchronously, performs the database close and run-status writes, then removes the in-memory entry. If the second send arrives before that promise settles, the existing busy guard correctly refuses the send, so no second reconstruction occurs. Increasing the delay would leave the same race under load.

This test must control expiry and await the actual pause operation before asserting the next wake. Nearby tests already exercise the internal `pause` method; no public API or production timer seam is needed.

## Task

Change only the named history-reconstruction integration test so its first pause and next wake are explicitly ordered:

1. Replace the fixed wall-clock sleep with deterministic control of the existing real `pause(tenantId)` operation and an explicit await of its completion before the second send. Reuse the internal pause test seam already exercised by this file. Keep all Postgres operations real. This test verifies reconstruction on a new wake; it does not need to prove when a real clock fires the TTL callback.
2. Keep the timer lifecycle correct: if pause is invoked directly, cancel its obsolete pending TTL callback; if a controlled callback is used instead, capture and await the promise from the real pause implementation. A test-local typed wrapper and narrowly scoped timeout control are permitted where needed. Do not introduce a production timer seam, new export, shared helper, `any`, or an unchecked `as unknown as` cast.
3. Assert that the first send succeeds with `first wake`, and preserve the exact first-wake reconstruction call, task, and initial-state assertions.
4. After the real pause has completed, send `hi again` once and assert success with `second wake`. Preserve the exact assertions for two reconstruction calls, tasks `["hi", "hi again"]`, and initial states `[undefined, { messages: [priorEntry] }]`. Do not use `conversation.clear()` to manufacture the second wake, poll or retry `send()`, or replace pause with a no-op stub.
5. Keep the pause await bounded by the integration test timeout and settle any deliberately started pause before resource cleanup. Use `finally` to cancel test-owned pending timers and restore any clock/timer overrides on assertion-failure paths as well as success. If fake timers are needed, fake only `setTimeout`/`clearTimeout`; keep `Date`, promises, `nextTick`, and database functions real.
6. Verify the test's regression value with a temporary local mutation that omits the reconstructed `initialState.messages` from session creation: the updated test must fail. Restore the production file before committing, then rerun the integration test file successfully. Describe the mutation result in the pull request body; do not commit the mutation.
