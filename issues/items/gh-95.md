**Blocked by:** #94

## Context

Drafting is safe for agents, while sending is an externally visible action requiring a project-level authorization decision.

## Task

Implement `email.draft.create` through the generic item-create path and make it AI-callable without confirmation. Implement `email.send` over SMTP using the existing mailbox OAuth2/app-password credentials. A server-derived authenticated user actor sends directly. An agent actor may send only when its generated permission manifest contains `capabilities.email.send.autonomous`; otherwise return 403 with no SMTP call and leave the draft unchanged. Do not create an approval request.

On accepted send, insert the outgoing message optimistically into the folder whose special purpose is `sent`. Generate/store its Message-ID and reconcile the optimistic row with the later synchronized server copy through `mail_message_meta.message_id`, producing one authoritative Email item.

## Scope

### In scope

- Draft creation, authorization, SMTP submission, optimistic Sent insertion, and deduplication.

### Out of scope

- Approval queue use, compose UI, and new credential mechanisms.

## Acceptance criteria

- User send and autonomously granted agent send submit exactly once.
- An ungranted agent receives 403, keeps its draft, and creates no approval row.
- Later IMAP synchronization merges rather than duplicates the optimistic Sent item.
