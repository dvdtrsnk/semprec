## Context

The removal of areas (epic `sp-7ff00d8e-6c3e-49f2-b5a8-89ca1157e807`, pull requests #2111–#2114) left follow-up debts
that the owner asked to resolve on 2026-11-28: a stale "ten databases" name, client code for server fields that no
longer exist, two integration tests that fail intermittently in CI, and managing project tags (rename, recolor,
delete) in the app.

## Decisions

- Question: Which debts are in scope?
  - Adopted answer: The stale name, the mobile dead code, the two intermittent integration tests, renaming,
    recoloring and deleting a project tag (deleting needs a new backend operation).
  - Reason: These are the follow-ups recorded when the areas removal landed.
- Question: What does deleting a tag do to projects holding it?
  - Adopted answer: The option is removed from the property and from every item value of that property, in one
    transaction through the choke point.
  - Reason: A value whose option no longer exists would be refused by `assertSelectValuesKnown` on the next write.

## Behavior specification

- The core database id list is named for what it is; no comment or test claims ten databases.
- The apps send no mail facet `projectId` and map no `count` search subtitle kind.
- `mailDraftRoutes.test.ts` and `tenantIsolationJobs.test.ts` pass reliably in CI.
- In project settings a person renames, recolors and deletes a tag; a deleted tag disappears from every project.
