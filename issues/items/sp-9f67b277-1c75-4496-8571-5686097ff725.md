### Requirement gh-1652: [global-search 03/09] Reindex dependents when edges, titles, trash state or schema change

#### Context

### Requirement gh-1656: [links 08/12] Detach links when their source is deleted

#### Context

Model tier rationale: One cleanup mechanism hooked into the existing delete transaction and the purge path using established hook and dependent-cleanup patterns, with a narrow tenant-scoped data contract.

A link points at its source items through `value_link_sources` (#1403). When a source item is moved to the trash, the items that inherited from it must keep their values as their own: the link and its source rows disappear, the values stay, and restoring the source does not link them again. When an item is purged for good, its own link rows and the rows that name it as a source go with it.

Today `itemDeleteWithClient` and `restoreItemWithClient` in `chokePoint/itemTrash.ts` leave relation edges in place and run no hooks; #1601 adds delete and restore hooks to the choke point, registered through `domainWriteHooks.ts` (ADR `docs/adr/2026-09-30-choke-point-domain-hooks-through-a-per-process-registry.md`) and run in the same transaction.
