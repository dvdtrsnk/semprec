## Context

Model tier rationale: One persisted-state change (a CHECK widening plus two columns) and the job and sweep behavior that use it, on existing fixtures, but the migration touches a tenant-keyed table and the error-text rule is security relevant.

`item_automation` (`backend/packages/data/src/db/migrations/0005_library_module.sql`) has `status` (`pending | done | error | locked`), `error` text, `attempts` and `last_attempt_at`; the store is `backend/packages/data/src/library/itemAutomationStore.ts`. The job (`library/libraryMetadataJob.ts`) writes `done` for any run that did not throw, so "the source found nothing" and "the source found something" are the same state, and on failure `markItemAutomationError` stores the exception message, which can contain URLs and secrets. The 04:00 retry sweep (`library/libraryMetadataActions.ts`, `listErroredItemAutomationForDatabases`) retries only `error` rows, so a title that was not found is never tried again.

After #1655 and #1706, fetchers return an outcome (`found | notFound | error`, `errorCode`, `source`). This issue records that outcome and retries what is worth retrying.

Decisions:
- The stored `done` value is kept and means "found" (the response mapping to `found` belongs to #1768); a new status `notFound` is added to the CHECK.
- `notFound` is decided by the source returning no match, not by a missing cover: a user may remove a cover, and a movie can have data without a cover; neither is `notFound`.
- The exception text is never stored or logged; an error code is stored instead.

Unsupported configured sources follow docs/adr/2026-11-05-library-retries-require-a-supported-live-source-config.md: reject through a fixed typed error before producer/sweep/job automation side effects; this recognized configuration refusal is not gh1708 provider failure mapping. Existing legacy queued jobs retain bounded maxAttempts=3; unsupported live config cannot enqueue another daily metadata batch. No new durable status/code/flag is added; corrected live config resumes ordinary retry, and missing TMDB token remains sourceUnavailable.

## Acceptance criteria

- When a source returns no match, then the row is `notFound` with the source, and the 04:00 sweep tries it again.
- When a source is unavailable (HTTP 503 fixture), then the row is `error` with `error_code` `sourceUnavailable` and `attempts` increased by one; neither the database nor the log contains the exception text.
- When a run finds data, then the row is `done` with the `source`, and the sweep does not retry it.
- When the user removed an item's cover but the source found the item, then the row is not `notFound`.
- When a row is `locked`, then no run or sweep changes it.
- When the migration is applied, existing rows keep their status; the exact local bridge B reader reads old and new W rows including all new codes. Actual previous-release compatibility requires deployed B immediately before W; unbridged old strict code is not claimed compatible, and production rollout/rollback remains NOT RUN.
