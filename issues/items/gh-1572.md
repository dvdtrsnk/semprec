## Context

Model tier rationale: A read-only custom route over existing tables and a pure derivation of status fields, with defined output and isolation tests, but no new write or authorization contract.

Mailbox list/detail reads need the specified DTO over the existing Mailboxes and sync-state owners. The existing imapConnectionLimiter lookup supplies Gmail5/iCloud3/Outlook3/other2 defaults, applicable only to IMAP.

It builds on #1497, which records last successful sync, failure start, failure kind and initial sync completion. The count of projects allowed to send autonomously is added by #1635. The range check on the connection limit is #1498.

Decision: the response never contains provider error text; reasons are the fixed set `reauthorization`, `connectionLimit`, `other`.

Decision: `syncStatus` is the stored property, except that it is reported as `never` when the property is missing and `initial_sync_completed_at` is null. The route does not write the property; the sync job stays its only writer.

Shared-file ordering: this issue also waits for #1567 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. Add `GET /api/mail/mailboxes` and `GET /api/mail/mailboxes/:id` as custom routes of the mail module (justification `single-consumer-read`), registered in `mailModuleManifest.ts` `customRoutes` and `routeMatrix.ts`. Both are authenticated and tenant-scoped; an unknown id, or one from another tenant or another database, answers 404.
2. Each mailbox object is `{ id, name, provider, primaryAddress, addresses, syncMode, syncStatus, initialSyncInProgress, lastSuccessfulSyncAt, failingSince, reason, connectionLimit: { value, default, applies } }`. `primaryAddress` is the first entry of the parsed address list (null if empty); `addresses` is the parsed list. `initialSyncInProgress` is true while `initial_sync_completed_at` is null. `reason` is the stored failure kind while the status is `error` or `needsReauthorization`, otherwise null. `connectionLimit.default` is the provider default, `value` the configured limit when valid or the default, and `applies` is true only when `syncMode` is `imap`.
3. Export the provider default lookup from `imapConnectionLimiter.ts` so the route and the sync job share it.
4. Soft-deleted mailboxes are not listed.

## Acceptance criteria

- When a sync pass fails after a success, then `lastSuccessfulSyncAt` is unchanged and equals the time every client shows.
- When a mailbox was just created and has never finished a pass, then `syncStatus` is `never` and `initialSyncInProgress` is true.
- When the mailbox syncs through the Gmail API or Microsoft Graph, then `connectionLimit.applies` is false.
- No field and no part of the response contains the provider's error text.
- A mailbox of another tenant answers 404 on `/:id` and is absent from the list.
