## Context

Model tier rationale: One schema addition plus a compiler-enforced parameter threaded through every run-closing call site, using existing store and test patterns, with no new authorization, tenant or concurrency contract.

When an agent run fails, the backend records only free text. `agent_runs.result` receives `err.message` from several places, and nothing stores a stable reason. Runs are closed as `error` in these places:

- `backend/packages/data/src/scheduler/actions.ts` (`coreAgentRunAction`, both the non-final attempt close through `finishAgentRun` and the final one through `finishAgentRunWithErrorNotification`);
- `backend/packages/agent-runtime/src/lifecycleAdapter.ts` (`runAgentSession` catch, including `AgentRunCancelledError`);
- `backend/packages/agent-runtime/src/sempConversation.ts` (`failRun`, and `closeDropped` with the "account deactivated" text);
- `backend/packages/agent-runtime/src/delegationRegistry.ts` (`failRun`);
- `backend/packages/agent-runtime/src/startupRepair.ts` (`interrupted_by_restart`);
- `backend/services/semprec-agents/src/agentRunTasks.ts` (`closeUncomposedRun`);
- `finishAgentRunWithErrorNotification` in `backend/packages/data/src/agentRuns/agentRunsStore.ts` itself.

A model failure reaches these as the error message that `assertModelSucceeded` in `backend/services/semprec-agents/src/piAgentSession.ts` throws from pi's `errorMessage`.

Clients that must show a short, localized reason (and the Semp reply failure codes) need one closed set of reasons on the run. This issue adds that set and makes it impossible to close a run as `error` without naming one. #1824 turns the code into localized summaries and stops storing raw exception text, #1547 recognizes the gateway's budget refusal as `budgetExceeded`, and #1907 and #1911 build on the same codes.

Decision: the closed set is `budgetExceeded | modelError | cancelled | interrupted | internal`, stored in English camelCase per the canonical-keys ADR. Rows that were closed as `error` before this change have no code and read as `internal`. `error_code` stays nullable in the database (a rolled-back release still closes runs without it), so the guarantee is enforced in code and by a test over every closing site.

## Task

Load `db-migrations`, `canonical-keys`, `state-writes`, `error-handling` and `testing`.

1. Migration `backend/packages/data/src/db/migrations/NNNN_agent_run_error_code.sql` (next free ordinal at commit time): `ALTER TABLE agent_runs ADD COLUMN error_code text CHECK (error_code IN ('budgetExceeded','modelError','cancelled','interrupted','internal'))` and `ADD COLUMN error_detail jsonb`. Both nullable; no backfill; no new `NOT NULL`.
2. In `agentRunsStore.ts`, export `AGENT_RUN_ERROR_CODES` and `AgentRunErrorCode`; add `errorCode: AgentRunErrorCode | null` and `errorDetail` to `AgentRunRow`, read with `assertKnownValue` at the row boundary, and a `status = 'error'` row with a null code maps to `internal`. Add the two columns to `AGENT_RUN_ROW_COLUMNS`.
3. Make `errorCode` a required parameter of `finishAgentRun` when `status` is `error` (use a discriminated signature so `done` takes none) and of `finishAgentRunWithErrorNotification`; an optional `errorDetail` (plain object, no user content) is stored in `error_detail`. Both write `error_code` in the same `UPDATE` as `status`.
4. Add a small classifier in a new `backend/packages/data/src/agentRuns/agentRunErrorCodes.ts`: `agentRunErrorCodeOf(err)` returns the value of an `agentRunErrorCode` property when the error carries a known one, otherwise `internal`. Give `AgentRunCancelledError` (`lifecycleAdapter.ts`) `agentRunErrorCode = "cancelled"`. Introduce `AgentRunError` (code + message) in the same file; `assertModelSucceeded` throws it with `modelError`. Use these at the catch sites of `lifecycleAdapter.ts`, `sempConversation.ts` `failRun`, `delegationRegistry.ts` `failRun`, `scheduler/actions.ts` and `agentRunTasks.ts` `closeUncomposedRun`.
5. Pass fixed codes where the reason is known: `startupRepair.ts` passes `interrupted`; `closeDropped` in `sempConversation.ts` (account deactivated) passes `cancelled`.
6. Keep writing the existing text into `result` exactly as before; changing it is #1824.

## Scope

### In scope

- The `error_code` and `error_detail` columns, the required code on both run-closing functions, the classifier, and a code at every existing closing site.

### Out of scope

- Localized summaries, the `errorSummary` read field, and replacing raw exception text in `result`: #1824.
- Recognizing the gateway's budget refusal (so `budgetExceeded` is produced): #1547. Until then no site produces it.
- Using the codes on Semp reply failures: #1907.
- Putting the code into notifications or problems: #1911.
- Adding a database constraint that requires a code on every `error` row (not rollback-safe).

## Acceptance criteria

- When any code path closes a run as `error`, then `agent_runs.error_code` is set; a test drives every closing site listed above and asserts a non-null code on each.
- When a run is stopped by `AgentRunCancelledError`, then its code is `cancelled`; when startup repair closes an orphaned run, then `interrupted`; when pi reports a failed model call, then `modelError`; any other thrown error gives `internal`.
- A row closed as `error` before this migration (null code) reads back with `errorCode` `internal`; a `done` run reads back `null`.
- Calling `finishAgentRun(..., "error", ...)` without a code does not compile.
- The migration is additive: the previous release's close statements still succeed against the new schema.
