**Blocked by:** #216, #85, #23

## Context

Issue #216 introduced `DOC_HISTORY_RETENTION_DAYS`, the mirrored `doc_history_updates` log, checkpoint boundaries (`through_update_id`, `represented_at`, NULL-expiry rolling baselines), `docs.history_available_from`, checkpoint-writing compaction, and the `openDocVersionAt` selection contract, but it never deletes history updates. Without a retention cleanup the mirrored log grows without bound, and a naive expiry-based delete would leave checkpoints whose advertised retained interval can no longer be reconstructed.

This final part adds the per-document cleanup that re-baselines history at the retention cutoff and deletes only what the new baseline makes redundant.

## Task

Cleanup runs per document in one transaction while excluding concurrent append/compaction with the document row lock. Let `cutoff = transaction_timestamp() - DOC_HISTORY_RETENTION_DAYS`, computed exactly as the retention cutoff defined in #216 (`transaction_timestamp() - make_interval(hours => 24 * DOC_HISTORY_RETENTION_DAYS)`). Reconstruct the exact document state at `cutoff` from the current rolling baseline plus history updates, create a new full baseline checkpoint with `represented_at = cutoff`, `through_update_id = greatest update_id whose created_at <= cutoff` (or the preceding baseline boundary), and NULL expiry, then set `docs.history_available_from = cutoff`. Only after that insert succeeds, delete history updates with `update_id <= through_update_id` and older checkpoints made redundant by the new baseline; keep every later update/checkpoint required for reconstruction. Delete the preceding NULL-expiry baseline only in that same transaction after the replacement is complete. If `cutoff` precedes the document's current `history_available_from` (including the initial migration boundary), retain the existing baseline and availability instead. Thus a complete non-expiring baseline always exists until a newer complete baseline atomically replaces it. This cleanup replaces the #216 interim rule that `doc_history_updates` rows are never deleted; the expiry-based deletion of expiring checkpoints remains subordinate to it and must never remove a checkpoint still required for reconstruction inside the retained interval.

Boundary tests follow the #216 convention (DB/session timezone UTC, frozen transaction clock) and cover just-before/at/just-after-cutoff cleanup and reconstruction with the default 30-day configuration.

## Scope

### In scope

- Per-document retention cleanup: cutoff reconstruction, new NULL-expiry baseline, `history_available_from` advancement, and deletion of redundant history updates and checkpoints.
- Cleanup boundary and concurrency tests.

### Out of scope

- Retention configuration, history tables/columns, mirrored appends, the new-doc baseline, the cutover migration, checkpoint-writing compaction, and `openDocVersionAt`; #216 delivered these.
- WebSocket transport, editor UI, Awareness, or business-tier retention.
- Restoring versions as the new current state; this work only reads old versions.

## Acceptance criteria

- Every timestamp at/after `history_available_from` inside the complete retained interval reconstructs exact state after any number of compactions and cleanups; timestamps before the advanced `history_available_from` return 410.
- Cleanup never leaves a checkpoint whose advertised retained interval is unreconstructible.
- Concurrent append, compaction, and cleanup cannot lose current or historical state.
- With the default configuration the exact retention boundary is 30 days; just-before/at/just-after-cutoff cleanup tests are deterministic under a fixed database clock.
- A document created after migration retains a complete NULL-expiry baseline through cleanup and compaction, and cleanup on a document whose cutoff precedes `history_available_from` changes nothing.
