## Context

Model tier rationale: It adds a persisted event kind that must stay consistent across the database CHECK, the store's known-value assertion, reconstruction, replay and the model history conversion, and a missed seam breaks replay or reconstruction for every run.

Persist wake and follow-up user turns as events, preserving their order through reconstruction, model history, agent:watch replay and live agent:event. Keep the event kind consistent across the database CHECK, validated store reads and runtime consumers.

Store only strict #1369 ref objects and their labels captured at send time, never expanded content. Expansion belongs to #1733 and images to #1752; no historical backfill. Builds on #1560 and is used by #1727/#1738.

## Acceptance criteria

- When a conversation is woken and reconstructed, then the user's first and later messages and the answers appear in order.
- When an event with kind `user_message` is read by reconstruction, `agent:watch` replay or startup repair, then nothing throws.
- When wake or follow-up refs are sent through the composed conversation/session path, then the same valid ref objects and labels are persisted before the prompt; absent context stores an empty array. Malformed refs, invalid labels and extra/expanded fields are rejected before an invalid user event or prompt, and the unlabeled ref schema stays unchanged.
- When logs of a turn are inspected, then they contain no message text.
