## Context

Model tier rationale: It adds a persisted event kind that must stay consistent across the database CHECK, the store's known-value assertion, reconstruction, replay and the model history conversion, and a missed seam breaks replay or reconstruction for every run.

A user's message is not stored as an agent event today. The text that wakes a conversation lives only in `agent_runs.task`; follow-up messages sent through the session are not stored at all. `services/semprec-agents/src/piAgentSession.ts` (`toAgentMessage`) persists only assistant messages, tool use/result and turn start/end. `conversationReconstruction.ts` reads only `AGENT_MESSAGE_KINDS` (no user message), and `services/semprec-agents/src/piConversationHistory.ts` (`toPiMessages`) converts only `message` and `tool_result`. So a reconstructed conversation contains answers without the questions.

This issue persists every user turn, wake and follow-up, as an agent run event and replays it into the model history. `agent_run_events.kind` is validated by a CHECK constraint (last changed in `0016_agent_run_events_compaction_kind.sql`), and `mapRow` in `agentRunEventsStore.ts` asserts every read row against `AGENT_RUN_EVENT_KINDS`, so an unknown kind would crash reconstruction, `agent:watch` replay and the startup repair listing.

The `context` refs stored with the turn are the objects defined by #1369 (for example item, block and transcript segment refs) plus a label captured at send time; expanded ref content is not stored (#1733 does the expansion). Image attachments in the turn are added by #1752. Builds on #1560; used by #1727 and #1738.

## Task

Load `state-writes`, `db-migrations`, `canonical-keys` and `testing`.

1. Migration: replace the `agent_run_events_kind_check` constraint to also allow `user_message` (pattern of `0016`).
2. Extend `AgentMessageKind` in `backend/packages/agent-runtime/src/types.ts`, `AGENT_MESSAGE_KINDS` in `conversationReconstruction.ts`, `AgentRunEventKind` and `AGENT_RUN_EVENT_KINDS` in `backend/packages/data/src/agentRuns/agentRunEventsStore.ts`, and `PERSISTED_EVENT_KINDS` in `lifecycleAdapter.ts` with `user_message`.
3. A `user_message` event payload holds `text`, `context` (the stored ref objects, each with its label as at send time) and nothing expanded. Add `toAgentMessage` support in `services/semprec-agents/src/piAgentSession.ts` and write the event before the prompt is sent, for the wake turn and for every follow-up turn. The watcher `agent:event` message receives it like any other persisted event.
4. In `piConversationHistory.ts`, convert `user_message` to a pi user message in `toPiMessages`. Earlier history is not backfilled.
5. Prepend pending system messages of the thread since the last turn (approval outcomes, see #1772) to the next prompt text; the hook is a parameter supplied by the caller, empty here.
6. Tests: a woken conversation reconstructs question then answer in order, including the first message; follow-up turns appear; `agent:watch` replay and `listAgentRunEvents` tolerate the new kind; the CHECK accepts it. Message text and refs never go to logs.

## Scope

### In scope

- The `user_message` kind end to end: persisted, validated, reconstructed, replayed and converted to model history.

### Out of scope

- Expanding refs into prompt content: #1733; file text: #1740; images: #1752.
- Producing system messages: #1772.
- Chat system prompt and per-turn date: #1738.
- Backfilling earlier history.

## Acceptance criteria

- When a conversation is woken and reconstructed, then the user's first and later messages and the answers appear in order.
- When an event with kind `user_message` is read by reconstruction, `agent:watch` replay or startup repair, then nothing throws.
- When a turn's refs are stored, then only ref objects and labels are persisted, not their expanded content.
- When logs of a turn are inspected, then they contain no message text.
