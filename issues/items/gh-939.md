## Context

Harvest issue #934 collected findings about tests whose assertions leave a branch unexercised or fail opaquely. Each is one added or adjusted test; none changes production code.

- PR #857, `backend/services/semprec-api/src/adapter/__tests__/errorContract.unit.test.ts:86`: the "falls through to the generic details branch" test removes both `computed` and `deletedAt` from `SAMPLE_ITEM`, so the `deletedAt` clause of the guard (`errorContract.ts:86`) is never the deciding one.
- PR #864, `web/src/views/mailbox/__tests__/MailboxTriage.test.tsx:151`: the test title says "in either resolution order" but the body only resolves email-1 before email-2.
- PR #873, `web/src/api/__tests__/aiUsageOperations.test.ts:22`: only an invalid `from` is rejected; `to`, which was changed in the same way to `z.iso.datetime()`, has no negative case.
- PR #876 and PR #876 (the same defect), `backend/services/semprec-api/src/__tests__/serveStartupConfig.test.ts:38`: the `SMTP_PORT` suite only covers a non-numeric value; the bounds checks at `serve.ts:70` (`<= 0`, `> 65535`) are untested, unlike the `PORT` suite above it, which covers 65536.
- PR #879, `backend/packages/data/src/__tests__/pushSubscriptions.test.ts:564`: `rowA` is destructured from a filtered list and dereferenced as `rowA!` with no prior `toBeDefined()`, so a missing row fails with an opaque `TypeError`.

## Task

1. `errorContract.unit.test.ts`: add a test (or split the existing one into two) where `current` lacks only `deletedAt`, and the existing one lacks only `computed`; both expect `body.error.details` to be undefined.
2. `MailboxTriage.test.tsx`: make the "two archive actions overlap" test run in both resolution orders (parameterise it with `it.each` over `["email-1", "email-2"]` as the first to resolve), each asserting the same final list.
3. `aiUsageOperations.test.ts`: add a test that `aiUsageReportSchema` rejects a report whose `to` is not an ISO-8601 datetime.
4. `serveStartupConfig.test.ts`: add `SMTP_PORT` cases `"0"` and `"65536"`, each expecting `SMTP_PORT is not a valid port number: <value>`.
5. `pushSubscriptions.test.ts`: add `expect(rowA).toBeDefined()` and `expect(rowB).toBeDefined()` before the dereferences at lines 570-571.
