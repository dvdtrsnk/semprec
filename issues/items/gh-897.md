## Context

Review follow-up from harvest issue #889. PR #466 (finding 30db062ca9), `backend/services/semprec-transcribe/src/transcriptionTask.test.ts:1067`: the `readMatch` helper joins `properties` with `WHERE p.key = 'event'` without restricting the property to the Transcripts database. If any other seeded database gains a property keyed `event`, the query would include extra relation definitions and the `eventIds` / `cards` assertions could pass or fail for the wrong reason.

## Task

In `readMatch`, restrict the matched property to the Transcripts database by adding `AND p.database_id = (SELECT id FROM databases WHERE owner_module_id = 'transcripts')` to its `WHERE` clause (the same subquery the file already uses for the Transcripts database in its deleted-transcripts `UPDATE`), leaving the rest of the query and the helper's return shape unchanged.

## Touches

- backend/services/semprec-transcribe/src/transcriptionTask.test.ts (the `readMatch` helper's query only)

## Scope

### In scope

The one query condition.

### Out of scope

Other helpers in the file and any assertion change.

## Acceptance criteria

- `readMatch`'s `properties` join only matches the Transcripts database's `event` property.
- Every test that calls `readMatch` still passes and `pnpm run verify` in `backend/` passes.
