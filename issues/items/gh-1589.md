## Context

Model tier rationale: One known text-search mechanism (a second text-search configuration plus a parameterised query builder) over the existing index table and the existing Hunspell test harness, with no new authorization or isolation contract.

Czech search has to match without diacritics and capitalisation, match inflected forms ("faktury" finds "Faktura"), and match a word that is still being typed ("odes fak" finds "Odeslat fakturu"), with every word required. Today:

- The text-search configuration `czech` is `unaccent` + `simple` (`0006_mail_sync.sql`). `0046_czech_hunspell_search.sql` rewrites its mapping to Hunspell `cs_cz` then `unaccent` then `simple` once the dictionaries are installed (`deploy/provision.sh` installs them; `db/runMigrationsCli.ts` calls `activateCzechHunspellSearch` on every deploy). Hunspell stores a recognised word as its lemma with diacritics, so an unaccented query term only matches through the fallback, and rows indexed before activation keep fallback lexemes.
- `searchItems` in `mail/search.ts` queries with `websearch_to_tsquery` (AND, no prefix) and has no production caller.
- CI has no Hunspell dictionary; only `__tests__/czechHunspellSearch.test.ts` copies a small `cs_cz` fixture into the `tsearch_data` of its own fresh database (`withFreshDatabase`, `installAssets`).

This issue gives the index one shape: a vector that combines lemma matches and diacritics-free prefix matches, and the query that reads it. It builds on the document builder and vector SQL owner from #1397 and on the People phone numbers from #1535. The search operation (#1842), the collection filter (#1857), the mail sender (#1591) and Semp message indexing (#1783) all use the vector and query defined here.

Decisions:
- One column, one vector: `search_vector = to_tsvector('czech', doc) || to_tsvector('czech_simple', doc)`. Two columns joined by OR would fail a query where one word matches by lemma and another only without diacritics ("faktury koupelne").
- The client-side habit of trimming the last character off long words is not carried to the backend: stemming plus prefix replace it.
- Phone numbers are normalised to digits in E.164 form with default country code 420 in both the document and the query.
- Emails rows keep the old single-configuration vector until #1591 and #1741 move them to the shared shape.

- Query values only reach the database as parameters: a test with `&`, `|`, `!`, `:`, `'` and parentheses neither errors nor changes matching semantics.
- Existing Emails rows are not deleted by the migration or rewritten by the reindex.
