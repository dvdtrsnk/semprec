**Blocked by:** #1608
**Model tier:** medium

## Context

Model tier rationale: Extends the Markdown parser and serializer of a blocker with one link scheme and a tenant-scoped existence check, with round-trip fixtures as the verification.

Pages are exchanged as Markdown by agents and the REST/MCP surface (#1608 defines the canonical serializer and parser with shared fixtures, and links to subpages as `semprec://page/<id>`). A journal day often refers to an item, typically a calendar event ("Standup"). Transcript text already links items with `semprec://items/<uuid>`: `backend/packages/data/src/transcription/transcriptionJob.ts` writes such links. Page Markdown has no item link: the link attribute exists in the block model but the parser does not recognize this scheme or check that the target exists.

Decision: an item reference in text is the inline link `[Title](semprec://items/<itemId>)`, stored as the link attribute of the text run. The parser and serializer do not write relation edges: the text link is plain content. The Journal `events` relation is derived from the event links in a day's page by #2016 (the text is the single source of truth).

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. In the Markdown parser from #1608 recognize the destination `semprec://items/<uuid>` on an inline link and store it as the link attribute; keep `semprec://page/<id>` as before.
2. When Markdown is parsed for a write, check that each referenced item id is a well-formed UUID and exists in the caller's tenant (live or not-deleted); an unknown id and an id from another tenant produce the same 400 `validation_failed` (field is the Markdown body), without revealing which.
3. In the serializer, write a link attribute with this scheme back as `[text](semprec://items/<id>)`.
4. Add shared fixtures: a link round trip is byte-identical; an unknown id and a foreign tenant id both fail with the same body.

## Touches

- the Markdown serializer and parser module delivered by #1608 (inline link handling)
- the shared Markdown fixtures delivered by #1608 (new item link cases)
- backend/packages/data/src/docs/ (item existence check used by the parser, only if the parser has no store access)

## Scope

### In scope

- The `semprec://items/<id>` inline link in page Markdown: parse, validate, serialize.

### Out of scope

- Deriving the Journal `events` relation from event links in the page: #2016.
- The Journal relations themselves; #1545 and #1609.
- Subpage links; they stay as defined by #1608.

## Acceptance criteria

- When Markdown contains `[Standup](semprec://items/<id of an event>)`, then it parses and serializes back unchanged.
- When the id does not exist in the tenant, or belongs to another tenant, then the response is the same 400.
- When Markdown with an item link is parsed and serialized, then the parser and serializer write no relation edge themselves.
