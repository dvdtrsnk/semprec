## Context

`semprec-ai-gateway` serves three routes — `POST /internal/complete` (single structured completion), `/internal/diarize`, `/internal/transcribe` (`backend/services/semprec-ai-gateway/src/app.ts:22-29`). None of them can drive an agent loop: an agent turn is a streamed assistant message with tool calls over a multi-message context, which `/internal/complete` (`completeHandler.ts`, one `system` + `messages` + `responseSchema`, JSON reply) does not express. `docs/adr/2026-09-10-ai-gateway-monopoly-on-provider-calls.md` makes this gateway the only process allowed to talk to a provider, so the agent runtime cannot call Anthropic itself. #647 — the consumer of this route — composes `semprec-agents`' pi session against pi's own wire protocol pointed at `AI_GATEWAY_BASE_URL=http://127.0.0.1:3002/internal/pi`, and lists this route as its prerequisite; until it exists every production agent run ends in a 404 from the gateway.

The protocol is `@earendil-works/pi-ai`'s `pi-messages` API (`dist/api/pi-messages.js`, `stream`, lines 241-306): the client sends one `POST <baseUrl>/messages` with headers `authorization: Bearer <apiKey>`, `accept: text/event-stream`, `content-type: application/json` and body `{ model: <model id>, context: { systemPrompt?, messages, tools? }, options: { temperature?, maxTokens?, reasoning?, cacheRetention?, sessionId?, toolChoice? } }`; the server answers an SSE stream where each event is `data: <JSON>\n\n` (`readPiMessagesEvents`/`parsePiMessagesEvent`, lines 175-210; `[DONE]` is ignored) and the JSON is a `PiMessagesEvent` (`dist/api/pi-messages.d.ts:24-90`): `start`, `text_start`/`text_delta`/`text_end`, `thinking_start`/`thinking_delta`/`thinking_end`, `toolcall_start`/`toolcall_delta`/`toolcall_end`, then exactly one terminal `done` (`reason`, `usage`, `responseId?`) or `error` (`reason`, `usage`, `errorMessage?`). These are pi-ai's own `AssistantMessageEvent`s (`dist/types.d.ts:410+`) minus the `partial` field, with `done`/`error` carrying `message.usage`/`error.usage` and `error.errorMessage` hoisted — so a server built on pi-ai's real provider stream needs only a serializer. pi-ai already bundles the Anthropic transport (its `anthropic-messages` API; `@anthropic-ai/sdk` is its dependency) and a built-in model catalog with USD-per-million-token costs (`dist/providers/data/anthropic.json`; `calculateCost(model, usage)` fills `usage.cost.total`). `backend/dependency-cruiser.rules.json`'s `no-model-provider-dependency-outside-gateway` rule (line 159-166) allows exactly this service to depend on a provider SDK; the `pi-only-in-agent-runtime` rule covers `pi-agent-core`, not `pi-ai`.

Budget and accounting: after #620, every provider call goes through `complete(pool, ctx, invoke)` in `backend/packages/ai-gateway/src/gateway.ts`, which reserves `ctx.estimatedCostUsd` under `pg_advisory_xact_lock(hashtext('ai_gateway_budget'))`, runs `invoke()`, then `settleTokenGatewayCall`/`failGatewayCall`. This route must use that exact path — one `ai_gateway_calls` row per `POST`, `reserved` before the provider is contacted, `settled` with the streamed usage or `failed`. #622 rewrites the dispatcher in `app.ts` (audio concurrency limit), which is why this issue waits for it; #642 refreshes `backend/pnpm-lock.yaml` (a dependency this issue also adds to), hence the third blocker. Auth mirrors `completeHandler.ts`'s `extractBearerToken`/`tokensMatch` (lines 76-90, `timingSafeEqual` against `AI_GATEWAY_INTERNAL_TOKEN`).

For `POST /internal/pi/messages` (anything else → 404 JSON, like `completeHandler.ts`):
   - bearer check → 401 `{ error, code: "unauthorized" }` as in `completeHandler.ts`;
   - read the JSON body with a `MAX_BODY_BYTES = 4 * 1024 * 1024` cap (413 on overflow) and validate at the edge with `zod` (add `"zod": "^4.1.11"`, the pin `packages/data` uses, to this package): `model` non-empty string; `context.messages` a non-empty array; `context.systemPrompt` optional string; `context.tools` optional array; `options` optional object with the six optional fields above (`temperature` finite number, `maxTokens` positive integer, `reasoning`/`cacheRetention`/`toolChoice`/`sessionId` passed through as-is after shape checks). Invalid → 400 `{ error, code: "validation_failed", field }`. Only the shape is validated here; message content is pi's own `Message` type and is handed to pi unchanged;
   - resolve the model with `options.models.getModel("anthropic", body.model)`; unknown → 400 `{ code: "unknown_model" }`. Only Anthropic models are accepted (the gateway holds only `ANTHROPIC_API_KEY`);
   - estimate: `estimatedInputTokens = Math.ceil(JSON.stringify(body.context).length / 4)`, `reservedOutputTokens = body.options?.maxTokens ?? Math.min(model.maxTokens, 8192)`, `estimatedCostUsd = estimatedInputTokens / 1_000_000 * model.cost.input + reservedOutputTokens / 1_000_000 * model.cost.output` (pi's `ModelCost` is USD per million tokens);
   - `complete(pool, { provider: "anthropic", model: model.id, agentRunId: <see below>, projectItemId: null, operation: "agent_turn", estimatedCostUsd }, invoke)`. `agentRunId`: read from an optional request header `x-semprec-agent-run-id` (UUID-validated; `null` when absent) — the #647 client sets it per run through pi's `headers` option so the row is attributed to the run like `GatewayCallContext.agentRunId` intends. ## Scope

### In scope
- The `POST /internal/pi/messages` route: auth, validation, model lookup, budget reservation and settlement through `complete()`, SSE serialization of pi-ai's Anthropic stream, and the tests above.

### Out of scope
- The consumer side (`semprec-agents`' pi session, `AI_GATEWAY_BASE_URL`, `AGENT_MODEL`) — #647.
- OpenAI or any second provider behind this route; model allow-listing beyond "an Anthropic model pi-ai knows".
- Retrying provider 429/5xx inside the stream (#626 covers the structured provider; a streamed turn is retried by the agent loop), settle-retry (#623), abort propagation for the other routes (#624), the audio concurrency limit (#622).
- Server-side prompt caching policy, session affinity, or any rewrite of the context (`rewrite` is never sent).
- Changing `/internal/complete` or `OPERATION_REQUIRES_PROJECT_ITEM`.

## Acceptance criteria

- When a valid `POST /internal/pi/messages` with the internal bearer token arrives, the response is a `text/event-stream` of `PiMessagesEvent`s ending in exactly one `done` or `error` event, and pi-ai's own `stream()` client, pointed at `<server>/internal/pi` with the token as `apiKey`, resolves an `AssistantMessage` equal to what the provider produced.
- When the stream completes, exactly one `ai_gateway_calls` row exists for it with `status='settled'`, `operation='agent_turn'`, the run id from `x-semprec-agent-run-id` (or NULL), and the provider-reported tokens and `usage.cost.total` as `cost_usd`; when the provider stream ends in `error` or the client disconnects mid-stream, that row is `status='failed'`, `cost_usd=0`.
- When the daily or monthly cap is reached, the route answers 403 `budget_exceeded` before contacting the provider and writes no `settled` row.
- When the bearer token is missing or wrong, the route answers 401 without reading the body; an unknown model answers 400 `unknown_model`; a body over 4 MiB answers 413.
- `ANTHROPIC_API_KEY` is read only in `semprec-ai-gateway` (`grep -rn ANTHROPIC_API_KEY backend --include=*.ts` outside this service's `src/` is empty) and `pnpm run check:boundaries` (in `backend/`) passes with `@earendil-works/pi-ai` imported only from this service and `packages/agent-runtime` tests.
