**Model tier:** medium

## Context

Model tier rationale: A read-only route and one extra field on an existing mailbox list, with tenant-isolation and route-matrix coverage, over a property that no code writes yet.

A project may be allowed to send mail without confirmation through the project property `emailSendAutonomous`, read as `capabilities.email.send.autonomous` in `backend/packages/data/src/manifest/permissionManifest.ts`. Nothing in the app writes the property; the permission is switched on per project on the server, and this issue does not add a way to turn it on. The account detail should show how many projects are allowed. The mailbox list with sync status comes from #1572.

Decision: the permission is per project (not per project and account), so every account shows the same count.

Shared-file ordering: this issue also waits for #1632 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. Declare `GET /api/mail/autonomous-send-projects` in the `customRoutes` of `mail/mailModuleManifest.ts` (justification `single-consumer-read`), handler in `mail/mailAutonomousSendRouteHandlers.ts`. Response: an array `[{ projectId, name }]` of not-deleted projects whose permission manifest grants `capabilities.email.send.autonomous`, ordered by name.
2. Add `autonomousSendProjectCount` (the length of the same list) to every mailbox returned by the mailbox list of #1572.
3. The tenant sees only its own projects. Add the route to `backend/services/semprec-api/src/routeMatrix.ts` and to the tenant-isolation route test.

## Scope

### In scope

- The read-only list of permitted projects and the count on mailboxes.

### Out of scope

- Any way to switch the permission on or off from the app; the product owner decided the permission is read-only in the app in v1, because switching on autonomous sending is a high-risk outbound action.
- Using the permission to decide on approval (#1913).

## Acceptance criteria

- With two projects granting the capability, the route returns both with names and each mailbox shows `autonomousSendProjectCount` 2.
- With no project granting it, the route returns an empty array and the count is 0.
- A user never sees projects of another tenant.
