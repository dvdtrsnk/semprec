## Context

Model tier rationale: This tightens an existing single-statement SQL attribution guard using known module metadata and the existing runtime-role integration harness.

- PR #1139, finding `71e6064677`, `backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts:174`: The projectItemId guard accepts any tenant-visible item, including a task or mail item, instead of requiring the system Projects database.

## Task

Within `reserveGatewayCall`'s existing conditional INSERT, constrain the optional project-item EXISTS probe to an item in the system database whose `owner_module_id` is the existing `PROJECTS_MODULE_ID` (`projects`). Join `items.database_id` to `databases.id`; keep the check inside the INSERT and let the existing RLS/ambient tenant scope apply to both relations. Use the existing canonical module constant, without new public exports or stored keys. A non-Projects item must get the same plain `attribution_refused` ForbiddenError as an unknown or foreign id and write no accounting row. Update only the reservation docstring to describe this domain restriction. Extend aiGatewayCallAttribution.test.ts with a real, same-tenant non-Projects item, using the existing runtime-role pool and production choke-point fixture creation; retain the existing Projects, null-id, unknown-id and cross-tenant cases.

## Touches

- backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts (PROJECTS_MODULE_ID import, reserveGatewayCall project probe and its docstring only)
- backend/packages/data/src/__tests__/aiGatewayCallAttribution.test.ts (project attribution cases and their item fixtures only)

## Scope

### In scope

The Projects-domain restriction in the existing reservation mechanism and tests for its admitted/refused sides.

### Out of scope

New tenant/authentication policies, schema/grant changes, budget calculations, provider handling, changes to the agentRunId probe, and new soft-delete or archive eligibility rules.

## Acceptance criteria

- For finding `71e6064677`, a real same-tenant non-Projects item is refused with the same error status/code/message and absent details as an unknown item, with zero inserted accounting rows. A same-tenant system Projects item and a null projectItemId remain accepted; existing foreign/unknown-id refusals still pass through the runtime-role harness. The domain check and reservation write remain one SQL statement.
