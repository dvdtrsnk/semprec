## Context

Model tier rationale: One validation mechanism over a new envelope shape with a coexisting old shape, using existing fixtures, but the old-shape compatibility and the page-host rule need careful verification.

Today a `pageContent` proposal envelope is `{entityKind: "pageContent", target, properties: {flavour, fields?, children?}}` (`assertValidProposalEnvelope` in `backend/packages/data/src/inbox/inboxTickAction.ts`). `target` may be any live item (checked through `getItemsByIds`), and confirm appends exactly one block with no position (`confirmProposalWithClient` in `backend/packages/data/src/inbox/proposalActions.ts`). Users want to put several lines of Markdown on a page, optionally under a chosen heading, for example "- Grey 60x120, **matte**" under a heading "Tiles".

This issue introduces a second `pageContent` shape ("v2") beside the old one, validation only:

`properties: { markdown: string (required, non-empty), placement: "end" | "start" | { afterHeading: <blockId> } | { afterHeadingText: <string> }, heading?: string }`

The shape is discriminated by the presence of `markdown`: an envelope with `flavour` and no `markdown` is the old shape and keeps validating and confirming exactly as today.

Rules:

- `markdown` must parse with the page-Markdown parser from #1608 and contain only allowed blocks; a `page` block is refused.
- `afterHeading` must be the id of an `h1`-`h3` block that exists in the target page; the headings are read with the non-creating page summary from #1615.
- `afterHeadingText` is accepted as input only from the tick, and is converted to `afterHeading` (or to `end` when nothing matches) by #1649; a stored v2 envelope never contains it. This issue therefore accepts it only in the write-side schema used by the tick and rejects it in revise.
- The target must be a page host: a project, an area, a Journal day, or a sub-page of Pages. Any other target (for example a task or a company item) gives 400. This tightens v2 only; the old shape keeps accepting any live item.
- A target that has no page document yet is valid; confirm creates it (#1681).

Decision: when the heading the user wants disappears before confirm, confirm answers 409 and the card is revised by the user (handled in #1681).

#1681 builds on this to write the content; #1649 builds on it for the tick; #1959 (options endpoint) builds on it.

## Task

Load `error-handling`, `state-writes` and `testing`.

1. Extend the `pageContent` schema in `inboxTickAction.ts` with the v2 shape and its types; keep the old shape typed and parsed unchanged. `parseStoredProposalEnvelope` accepts both.
2. In `assertValidProposalEnvelope`, branch on the shape: for v2 validate `markdown` (non-empty, parser from #1608, no `page` blocks), `placement` (known values only), `heading` (string up to a sensible length, no newline), `afterHeading` against the target's headings, and the page-host rule above. Throw `ValidationError` (400) with `field: "properties"` or `"target"`.
3. In `assertValidEnvelopeForCard` (`proposalActions.ts`) accept v2 on a non-transcript card and keep rejecting `pageContent` on a transcript card.
4. Revise (`reviseProposalWithClient`) accepts a v2 envelope and may switch between the old and the new shape.
5. Until #1681 lands, confirm of a v2 card answers 409 (explicit branch) rather than treating it as the old shape.
6. Tests in `proposalActions.test.ts` and `inboxTickProposal.test.ts`: v2 valid; markdown with a `page` block gives 400; `afterHeading` of a non-heading or foreign block gives 400; target that is not a page host gives 400; an old-shape envelope still validates and confirms as before.

## Scope

### In scope

- The v2 `pageContent` envelope shape, its validation, the page-host rule, revise acceptance, coexistence with the old shape.

### Out of scope

- Writing content at the placement on confirm: #1681.
- Converting `afterHeadingText` and computing placements in the tick: #1649.
- The options endpoint listing headings for the card: #1959.
- HTTP route for manual edits: #1892.

## Acceptance criteria

- When a v2 envelope has an empty `markdown`, a `page` block or invalid Markdown, then writing it by the tick and by revise gives 400.
- When `placement.afterHeading` is not an `h1`-`h3` block of the target page, then 400.
- When the target is not a project, area, Journal day or Pages sub-page, then a v2 envelope gives 400.
- When the target has no page document yet, then a valid v2 envelope is accepted.
- When an envelope in the old shape is written, revised or confirmed, then the behavior is identical to today.
- When a v2 card is confirmed before the write issue lands, then the answer is 409 and nothing is written.
