## Context

Model tier rationale: One query mechanism (filters, cursor, search, two partial indexes) across a store, a handler and one migration with existing queue and tenant fixtures, adding no new authorization contract because owner scoping is reused.

Product behavior: the approvals screen shows two lists, pending requests and decided ones, newest first, filtered by where the request came from, with search. The chat screen counts and filters only chat-sourced pending requests.

Today `GET /api/approval-requests` (`backend/services/semprec-api/src/approvalRequestsHandler.ts`, routed by hand in `backend/services/semprec-api/src/app.ts`) takes no parameters and returns `{rows}` with only the owner's pending requests, oldest first (`listPendingApprovalRequests` in `backend/packages/data/src/mcp/approvalRequestsStore.ts`, joined to `agent_runs.actor_user_id`). Decided requests have `decided_at` but cannot be listed. `approval_requests` has indexes only on `(status)` and `(agent_run_id)`.

This issue builds on #1766 (the derived `source`) and #1683 (the stored `description.params` that search reads).

Decision: with no parameters the response is byte-compatible with today's (pending, oldest first, `{rows}` only); the new behavior is opt-in (`docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`). Decided by the product owner: the approvals list is one general list that shows all sources by default; filtering by source is optional.

Decision: search is a plain `unaccent` + `ILIKE` substring match, not full text.

## Task

Load `db-migrations`, `canonical-keys`, `state-writes` and `testing`.

1. Migration `backend/packages/data/src/db/migrations/NNNN_approval_requests_list_indexes.sql` (next free ordinal at commit time): index `(tenant_id, status, requested_at DESC)` and index `(tenant_id, decided_at DESC) WHERE status <> 'pending'`. Create the `unaccent` extension if the target database does not have it (`CREATE EXTENSION IF NOT EXISTS`).
2. Extend `GET /api/approval-requests` with query parameters `status=pending|decided`, `source=chat,tick,mcp` (comma list), `q`, `order=desc|asc`, `cursor`, `limit` (default 50, max 100; invalid values answer 400). When any of `status`, `source`, `q`, `order`, `cursor` or `limit` is present the response is `{rows, nextCursor}`; with none present it is exactly the current `{rows}`.
3. `status=pending` orders by `requested_at`, `status=decided` by `decided_at DESC`; the cursor is an opaque keyset token over (order timestamp, id). Rows of decided requests additionally carry `status`, `decidedAt`, `executionStatus` and `conflictReason` (the field delivered by #1437; return `null` until it exists).
4. `source` filters by the kind derived in #1766. Because the kind is derived, filter in a way that stays correct with the cursor (derive the source in SQL or over-fetch and filter, but a page never returns fewer rows than `limit` while more exist).
5. `q` matches `unaccent`-insensitively, case-insensitively, as a substring of the thread title, heartbeat name, the tool or operation name, and the string values inside `description.params` (including nested strings). Do not search `payload` or argument values.
6. Keep all results owner-scoped exactly as `listPendingApprovalRequests` does today.

## Acceptance criteria

- When `GET /api/approval-requests` is called without parameters, the response is `{rows}` with the owner's pending requests oldest first, as before.
- When `status=decided` is requested, only the owner's decided requests are returned, newest decision first, each with `status`, `decidedAt` and `executionStatus`.
- When `source=chat` is requested, requests from chat and item threads (including delegated runs) are returned and none from ticks or MCP.
- When `q=nalada` is requested, a request whose description names the property "Nálada" is returned.
- When more rows exist than `limit`, `nextCursor` is set and following it returns the rest without duplicates or gaps; the last page has `nextCursor: null`.
- When `limit` is 0, 101 or not a number, or `status` is unknown, the response is 400.
- A request owned by another user or tenant never appears.
