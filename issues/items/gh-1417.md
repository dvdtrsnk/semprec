## Context

Model tier rationale: One new optional manifest field with a zod schema, a registry accessor and one concrete declaration plus an ADR, across known seams with an existing manifest test pattern, and no persisted-data or authorization contract.

The Inbox card shows one editor per proposal: a control for each field (text, Markdown, date, date with time, select, multi value chips, toggle, segmented choice, color, secret, read-only info, choice, tile), fields in groups, localized labels and placeholders, required fields, and fields that appear only under a condition (for example the time part of a date is hidden when the item is all-day, the due date of a project is hidden when it is long term, a follow-up task step's fields are hidden when that step is switched off). Today nothing on the server knows this: required-ness is not known to the schema or the choke point (the comment in `backend/packages/data/src/inbox/inboxStore.ts` says so), `confirm` only checks status, envelope shape and target, and `moduleManifestSchema` (`backend/packages/module-registry/src/manifest.ts`) has no field for editors. The MCP server database has no module manifest of its own, so its card schema has no natural home other than the Inbox manifest (`backend/packages/data/src/inbox/inboxModuleManifest.ts`).

This issue records the decision and adds the declaration mechanism; it does not build the resolver that turns a declaration into a card response (#1825) or any validation that uses it (#1928, #1934).

Decision: the editor schema is declared by the manifest of the module that owns the card's target database, keyed by the card's base kind (the kind of thing the card creates: task, event, project, area, company, person, file, health record, journal entry, page, mcp, and so on). The server owns the schema because required-ness and conditions must be enforced on confirm with the same rules the client renders; the alternative (the client hard-codes forms) would let the two drift and leave confirm unable to enforce anything. Labels and placeholders are catalog keys in the module's own `i18n/{cs,en}.json`, resolved by the server per the caller's `users.locale`; canonical stored keys stay English camelCase.

Shared-file ordering: this issue also waits for #1414 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `adr-conventions`, `canonical-keys` and `testing`.

1. Add the ADR `docs/adr/2026-10-25-server-driven-inbox-editor-schema.md` (frontmatter per `docs/adr/README.md`, area `backend`). It records: why the schema is server-driven; where it is declared (module manifest, keyed by base kind; for MCP, the Inbox manifest until an MCP manifest exists); the shape below; the rule that a field hidden by a condition is neither validated nor written; that required-ness is evaluated on confirm (error) and on edit (warning only, so a work-in-progress card can be saved); and that localized strings are resolved from catalogs, never sent as keys.
2. Define the shape in `backend/packages/module-registry/src/manifest.ts` as an optional manifest field `editorSchemas: Record<baseKind, EditorSchemaDescriptor>` with a zod schema:
   - `groups`: ordered array of `{ key, fields }`.
   - field: `key` (a property key, a relation key, or one of the closed set of pseudo field keys: `allDay`, `due`, `followupTask`, `followDate`, `credential`, `transport`, `access`, `mcpProjects`, `lang`, `speakers`, `recordedAt`, `day`, `page`, `placement`, `heading`; a module added later extends this set with its own step keys), `control` (enum: `text`, `area`, `date`, `datetime`, `select`, `multi`, `toggle`, `seg`, `color`, `secret`, `info`, `choice`, `tile`), optional `inputType` (`text`, `email`, `url`, `tel`; only for `text`), `labelKey`, optional `placeholderKey`, optional `required` (boolean), optional `when` (`{ field, equals }` or `{ field, notEquals }`; hides the field when false), optional `timeHiddenWhen` (same shape; only for `datetime`: hides only the time part), optional `optionsSource` (the field name accepted by the options route #1959), and for `info` rows `infoKey` with optional `params`.
   - Reject a `timeHiddenWhen` on a non-`datetime` control, an `inputType` on a non-`text` control, and an empty group.
3. Export the types and schema constants from `backend/packages/module-registry/src/index.ts`. In `registry.ts` add an accessor `getEditorSchemas()` returning `{ moduleId, baseKind, schema }[]` for active modules and make loading fail when two active modules declare the same base kind.
4. Declare the MCP server card schema in `inboxModuleManifest.ts` under base kind `mcp`: `name` (text, required), `transport` (seg, options `http` and `stdio`), `url` (text with `inputType: "url"`, required, `when transport equals http`), `command` (text, required, `when transport equals stdio`), `credential` (secret, required, `when transport equals http`), `mcpProjects` (multi, `optionsSource: "mcpProjects"`). Add the label and placeholder catalog entries to `backend/packages/data/src/inbox/i18n/en.json` and `cs.json`.
5. Tests in `registry.unit.test.ts` and a manifest schema unit test: accepts a valid declaration, rejects the three invalid shapes above, rejects duplicate base kinds; a test that every `labelKey`/`placeholderKey`/`infoKey` of the MCP declaration exists in both Inbox catalogs.

## Scope

### In scope

- The ADR, the manifest field, the registry accessor and the MCP card declaration.

### Out of scope

- Resolving a declaration into a localized editor schema on card responses and declaring schemas for the other base kinds (#1825).
- Required-field and condition evaluation (#1928, #1934).
- Validating select values against their option catalog (a separate write-path concern, not part of this batch's editor schema).
- Transcript Event and speaker choice controls (`eventChoice`, `speakerChoice`): not planned yet; they are added together with the design of the recording card (decided by the product owner).

## Acceptance criteria

- When a manifest declares `editorSchemas` with a valid declaration, then `moduleManifestSchema` accepts it and `getEditorSchemas()` returns it.
- When a field declares `timeHiddenWhen` on a `text` control, then manifest validation fails.
- When two active modules declare the same base kind, then registry loading fails with an error naming both modules.
- When the Inbox manifest is loaded, then `getEditorSchemas()` includes base kind `mcp` with the six fields above.
- The ADR exists with valid frontmatter and states the hidden-field and required-field rules.
