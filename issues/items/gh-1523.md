**Model tier:** high

## Context

Model tier rationale: This decides which module tools and capabilities every agent session is granted, an authorization contract for all agent runs, and it reaches into the session factory, the permission manifest and the module registry.

Modules declare agent tools in their manifest (`ModuleAgentToolDescriptor = { name, handlerExport, capability? }` in `backend/packages/module-registry/src/manifest.ts`; Schema Core declares `heartbeat.list`, `heartbeat.history` and `heartbeat.trigger` in `backend/packages/data/src/chokePoint/schemaCoreModuleManifest.ts`). Today none of them reaches an agent: `createAgentSessionFactoryForRun` in `backend/services/semprec-agents/src/agentSessionComposition.ts` composes only the generic operations and the project's MCP grants, and `ModuleRegistry.getAgentTools(grantedCapabilities)` is called only by `generateSchemaProjection`. Also `generatePermissionManifest` (`backend/packages/data/src/manifest/permissionManifest.ts`) lets only the core `CAPABILITY_IDS` into `grantedCapabilities`, so a capability declared by a module (for example the sleep read capability) can never be granted.

This issue is the single owner of "module tools appear in agent sessions". Other issues add tools and approval behavior on top: #1623, #1906, #1927, #1949, #1731, #1952, #1580, #1957, #1840, #1846. #1791 adds deferral of tools that require approval. The grant rules follow the ADR recorded by #1385.

Decisions:
- `resolveCallingProjectItemId` in `scheduler/heartbeatAgentTools.ts` is not widened by this issue, so every run sees only its own project's heartbeats here. The product owner decided that Semp chat runs read the heartbeats of every project of the tenant (read only, sensitive projects without a grant left out); that widening is #2018, built on this one.
- Module capabilities are granted by the same rule as core ones: as the ADR from #1385 defines for the run's project.

Shared-file ordering: this issue also waits for #1460, #1517 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `ai-gateway`, `error-handling` and `testing`.

1. Let `generatePermissionManifest` include capabilities declared by active modules in `grantedCapabilities` (no longer filtering to `CAPABILITY_IDS`), following the grant rules of the ADR from #1385. Core capability handling and its tests stay unchanged.
2. In `createAgentSessionFactoryForRun`, add one `AgentTool` per module agent tool returned by `ModuleRegistry.getAgentTools(grantedCapabilities)`: resolve `handlerExport` to the handler, expose its argument schema as the tool parameters, name it with `toModelToolName` and run the list through `withUniqueNames` together with generic and MCP tools.
3. Tool calls record the same run events as generic operation tools do, and a handler error is returned to the model as an error result, not thrown.
4. A tool whose `capability` is not granted does not appear; a tool with a granted module capability does.
5. Tests: a session sees `heartbeat.list` and `heartbeat.trigger` and can call them; a tool without its capability is absent; a module capability (a test module declaring one) passes through the manifest into the session; a name collision keeps the first tool and logs.

## Scope

### In scope

- Composition of module agent tools into sessions and passing module capabilities through the permission manifest.

### Out of scope

- Approval-gated module tools: #1791.
- Exposing module tools over `POST /mcp`: #1580.
- New tools; each domain issue adds its own.
- Widening heartbeat visibility to every project for chat runs: #2018.

## Acceptance criteria

- When a session is created for a run, then it contains `heartbeat.list` and `heartbeat.trigger` and calling them works.
- When a module tool names a capability the run does not hold, then the tool is absent from the session.
- When a module declares a capability the run's project is granted, then its tool is present.
- When two tools share a model name, then only the first stays and a warning is logged.
