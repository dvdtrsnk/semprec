## Behavior specification (approved)

Part of the multi-tenancy program specified in #950. This epic removes every single-user assumption and every global identity from the data layer:

1. Database keys, idempotency keys, person email addresses, provider message ids, mail threads, blob content hashes, notification dedupe keys and manifest drift findings are unique **per tenant**; the same value in two tenants creates two independent records, and no error, status or timing reveals the other tenant.
2. Each tenant's system databases, Semprec project and settings are provisioned in that tenant's scope (`provisionTenant`); module data migrations and post-migration cutovers run per tenant.
3. Blobs are deduplicated and stored per tenant (`<tenantId>/` storage prefix); a blob download for a foreign id is indistinguishable from an unknown id, even with a matching `If-None-Match`.
4. Events, agent runs and notifications that used to go to "the earliest user" go to the tenant's own user; operator alerts go to every admin without tenant content; the earliest-user lookups are deleted.
5. Re-registering a push endpoint used by another account silently moves it; a password reset revokes the user's push registrations.
6. The partition DDL functions refuse a database outside the current tenant; id-only item lookups touch only the tenant's partitions.
7. Serialized and bulk queue work runs on per-tenant lanes; there is one Semp conversation per tenant; stored item and database references (parent item, heartbeat trigger database, view configuration ids) are validated inside the tenant.

## Decisions

- **Why re-key instead of relying on RLS alone?** → Unique and foreign-key checks ignore RLS; a global key is an oracle (a 409 or a returned foreign id), a collision or a silent cross-tenant link.
- **Order of a re-key?** → Composite key added first (expand, #950), code and `ON CONFLICT` arbiters switched here, legacy key dropped in a later release (#960).
- **Who receives operator alerts?** → Every admin, as content-free rows written in each admin's own tenant.

## Out of scope

Realtime (#953), approvals and MCP (#954), dropping the legacy keys and composite foreign keys (#960).
