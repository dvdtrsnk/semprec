## Context

Authenticated sessions exist, but a forgotten password needs a supported recovery path that reuses outbound mail.

## Task

Add a password-reset token table with user, unique token hash, expiry, consumed timestamp, and creation timestamp. Implement request and consume endpoints. The request endpoint returns the same response for known and unknown email, generates a high-entropy token only for a known account, stores only its hash, and emails a signed application link through the SMTP infrastructure from #27. Consumption requires an unexpired, unused matching token, writes a new Argon2id password hash, and atomically marks the token consumed. Use a 30-minute default expiry and deterministic invalid/expired/consumed responses.

## Scope

### In scope

- Reset schema, mail request, one-time consumption, and password replacement.

### Out of scope

- Operator SQL recovery, SMS recovery, or changing `external_credentials`.

## Acceptance criteria

- Raw reset tokens never appear in PostgreSQL and can be consumed exactly once before expiry.
- Request responses do not disclose whether an email exists.
- Successful reset changes the password, consumes the reset token, and rejects every later reuse of that token.
