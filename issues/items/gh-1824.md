## Context

Model tier rationale: One read-side mechanism (a localized summary function plus the removal of raw text from stored results) over existing store, catalog-loading and handler patterns, with no new tenant or authorization contract.

After #1446, every failed run has a stable `errorCode`, but what clients see is still the old free text. `agent_runs.result` for a failed run holds `err.message` (or a restart or deactivation sentence), which can be an English provider message, can echo request content, and is not localizable. The run detail (`GET /api/agent-runs/:id`, `backend/services/semprec-api/src/agentRunHandler.ts`) returns the stored row as-is. #1805 extends that detail with run metadata.

Clients show short Czech or English reasons ("AI budget used up", "Interrupted by a restart") and never the raw error. The prefix words around a reason ("failed - ", "last failed: ") are composed by the client, so the backend returns the bare reason only. Lists of recent runs, automatic tasks and Semp status problems read the same reason, so there must be exactly one place that turns a code into text. #1909, #1910 and #1555 call it.

Decision: summaries are resolved at read time from a catalog, using the reading user's `users.locale` (Czech or English, falling back to the default locale used by the notification catalogs), so a locale change applies to old runs too. Nothing localized is ever stored. The stored `result` of a newly failed run becomes the canonical `errorCode` itself, so no exception text and no user content remain in the row (per the canonical-keys ADR, `docs/adr/2026-09-10-english-canonical-keys-with-i18n-labels.md`). Existing rows keep their old text; the `result` field stays in the API response because the web client reads it.

## Task

Load `canonical-keys`, `error-handling`, `io-hardening` and `testing`.

1. Make `finishAgentRun` and `finishAgentRunWithErrorNotification` (`backend/packages/data/src/agentRuns/agentRunsStore.ts`) write `result = errorCode` for status `error` and drop the free-text `result` argument for that status (a `done` close keeps its result snapshot). Update every caller listed in #1446 so none passes `err.message` or any text; the cancelled, interrupted and account-deactivated paths pass only their code.
2. Add a catalog `backend/packages/data/src/agentRuns/i18n/cs.json` and `en.json` with one entry per code under `agentRun.error.<code>.summary` (`budgetExceeded`, `modelError`, `cancelled`, `interrupted`, `internal`), short bare phrases without a trailing period, loaded the way `notifications/notify.ts` loads its catalogs. Add the directory to the `build` copy step in `backend/packages/data/package.json`.
3. Add `agentRunErrorSummary(errorCode, locale)` in a new `backend/packages/data/src/agentRuns/agentRunErrorSummary.ts` (exported from the barrel), returning the localized phrase, and a helper that, for an `AgentRunRow`, returns `{ errorCode, errorSummary }` with both `null` unless `status` is `error` (a null stored code reads as `internal`).
4. In `agentRunHandler.ts`, add `errorCode` and `errorSummary` to the `GET /api/agent-runs/:id` response, using the authenticated user's locale. Keep `result` in the response.
5. Failure paths that log a failed run (the lifecycle, delegation, conversation and queue-task close sites) log `agentRunId` and `errorCode`, never the exception message or the task text. Add a test that captures the logger output for each of the three code paths that previously logged or stored the message.

## Scope

### In scope

- Storing the canonical code instead of exception text, the catalog and summary function, and exposing `errorCode` and `errorSummary` on the run detail.
- Keeping exception text and task text out of the log lines of failed runs.

### Out of scope

- Adding the summary to the run list, the automatic-tasks list and the Semp status problems: #1909, #1910 and #1555.
- Summaries for a Semp reply that left a failed tool call: #1890.
- Rewriting the text of rows closed before this change.
- The text of the `agent_run_error` notification and its push: #1555 and #1466 use the summary; the notification kind itself is unchanged.
- The queue's own `last_error` for a failed job.

## Acceptance criteria

- When a run fails with a model error, then its stored `result` equals `modelError` and contains no exception text.
- When the detail of a failed run is read by a user with locale `cs`, then `errorSummary` is the Czech phrase for its code; with locale `en`, the English phrase; for a `done` run both fields are `null`.
- A failed row closed before this change (null code, legacy text) reads as `errorCode` `internal` with the `internal` summary, and `result` still returns its legacy text.
- A failing run whose exception message and task contain a sentinel string leaves that string out of every captured log line and out of `result`.
- `pnpm run verify` builds a `dist` that contains the copied catalog files.
