## Context

Model tier rationale: One known wiring mechanism (call the existing `wireRealtimeHooks` at process start) in a second composition root, but the test must prove that a write made by an agent run reaches the realtime publisher with the correct tenant binding.

Realtime fan-out is driven by in-process hooks in `backend/packages/data/src/realtimeHook.ts` (`setInvalidationHook`, `setAgentRunEventHook`, `setNotificationCreatedHook`, and so on). Their defaults are no-ops. `wireRealtimeHooks(pool)` in `backend/packages/realtime/src/wireHooks.ts` replaces them with Postgres NOTIFY publishing, and today only `backend/services/semprec-api/src/serve.ts` (and `semprec-transcribe`'s `serve.ts`) call it. `backend/services/semprec-agents/src/serve.ts` does not, although that process hosts the choke point in-process (see `docs/adr/2026-10-03-agents-worker-choke-point-access.md`) and runs every agent run: heartbeat ticks (`heartbeatFireAgent`), approval requests raised from `mcpInvokeTool` and `genericOperationGateway`, and agent run events. As a result an item write, a notification or an `agent_run_event` produced by an agent run never reaches any connected device.

This issue wires the hooks in the agents process so that every realtime message the data layer emits during an agent run is published. It builds nothing user-visible by itself. Later issues depend on it: approval request invalidations, Semp thread invalidations, writing heartbeat runs into their tick thread, and the Inbox card invalidations (#1811) all need the agents process to publish.

## Task

In `backend/services/semprec-agents/src/serve.ts`, import `wireRealtimeHooks` from `@semprec/realtime` and call `wireRealtimeHooks(pool)` once, right after `assertRuntimeRole(pool)` and before the queue runtime is created, mirroring the call order in `backend/services/semprec-api/src/serve.ts`. Add `@semprec/realtime` as a dependency of `backend/services/semprec-agents/package.json` (it is not one today), and keep the module-boundary rules (`backend/packages/module-boundaries`) green.
2. Add a test under `backend/services/semprec-agents/src/__tests__/` (for example `realtimeWiring.test.ts`) that proves the wiring. It must exercise the real hooks, not a mock of `wireRealtimeHooks`: open a Postgres `LISTEN` on the realtime channel with a test pool, perform an item write through the agents process's choke-point composition inside a tenant scope (the same composition `agentSessionComposition.ts` uses), and assert that an `invalidation` message for that item is received with the writing tenant's id and that a second tenant's listener-side filter does not match it. Follow the existing agents composition tests (`agentsTenantScope.test.ts`, `startupRepairComposition.test.ts`) for fixtures.
3. Because `serve.ts` runs at import time, also assert wiring order in the existing startup-composition style: the hooks are wired before the queue runtime can claim a job (a regression test against moving the call below `createAgentsQueueRuntime`).

### In scope

### Out of scope

- Wiring hooks in any other process.

## Acceptance criteria

- When an agent run in `semprec-agents` writes an item, a client socket of that tenant receives the item invalidation; a socket of another tenant does not.
- When an agent run raises an `agent_run_event` or a notification, the corresponding realtime message is published from the agents process.
- The agents process still refuses to start under a superuser database role (existing `serveRuntimeRole.test.ts` keeps passing).
- `wireRealtimeHooks` is called before the queue runtime is created.
