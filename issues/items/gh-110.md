**Blocked by:** #109

## Context

Some module workers scale per active database row, but process hosting belongs to operations/runtime composition.

## Task

Consume `workers()` descriptors and relevant active module rows to derive a deterministic desired set of worker instance identities, including forms such as `semprec-mailsync@<mailboxId>`. Reconcile activation/deactivation changes into registration/start-stop intents through an injected supervisor port. Keep this layer free of systemd commands and queue Runner ownership. Validate that every desired instance names one active descriptor and stable row id.

## Scope

### In scope

- Desired-state derivation, reconciliation, per-row scaling, and supervisor port.

### Out of scope

- systemd unit files and actual API/agents graphile-worker composition roots.

## Acceptance criteria

- Activating/deactivating a row adds/removes exactly its instance intent.
- Reconciliation is idempotent and stable across ordering.
- Inactive modules produce no worker instances.
