## Context

Model tier rationale: Two additive columns written by existing ingest and send paths plus a chunked per-tenant backfill, following existing migration and job patterns.

The thread list needs a short plain-text preview of each message and the time it entered Semprec. Neither is stored. `mail_message_meta` (migration `0006_mail_sync.sql`, per-mailbox identity from `0053`) has no timestamp, and `items.updated_at` changes on every read or flag update, so it cannot stand in for arrival time. The only plain-text conversion is the private `htmlToSearchText` in `backend/packages/data/src/mail/ingest.ts` (it strips tags with `sanitize-html`). `Emails.date` is set only when the message carries a Date header (`mail/ingest.ts`), so a message without one needs `ingested_at` as its sort time. `sendDraftEmail` (`mail/send.ts`) claims a draft by upserting `mail_message_meta` without any of this.

#1567 (the thread list) reads these columns and is the only consumer.

Decision: `ingested_at` for rows that exist before this change is `items.updated_at`, the best available estimate; `preview_text` for them is derived from `Emails.body`.

## Task

Load `db-migrations`, `state-writes` and `testing`.

1. Add the migration `backend/packages/data/src/db/migrations/NNNN_mail_message_meta_preview_ingested_at.sql` (next free ordinal at commit time): `ALTER TABLE mail_message_meta ADD COLUMN preview_text text, ADD COLUMN ingested_at timestamptz` (both nullable; no backfill in SQL).
2. Export the HTML-to-text conversion: create `backend/packages/data/src/mail/mailPlainText.ts` with `htmlToPlainText(html)` (the current `htmlToSearchText` logic) and `buildMailPreview(text)` that collapses whitespace and truncates to at most 200 characters without splitting a UTF-16 surrogate pair. `ingest.ts` imports the shared function instead of its private one.
3. Add `previewText` and `ingestedAt` to `MailMessageMetaRow`, `UpsertMailMessageMetaInput` and the SQL in `mail/mailMessageMetaStore.ts`. On conflict keep an existing non-null value (`COALESCE(mail_message_meta.x, EXCLUDED.x)`), so the sent claim and the later Sent-folder sync converge on the first value.
4. `ingestEmailMessage` stores `previewText` (from `bodyText`, else the converted `bodyHtml`) and `ingestedAt = now()`; `sendDraftEmail` does the same from its `bodyText`/`bodyHtml` when it claims the draft.
5. Add a core task `mailMessagePreviewBackfill` (`CORE_TASK_NAMES`, handler in `worker.ts`) that runs `forEachActiveTenant` and, in keyset pages with one transaction each (`docs/adr/2026-09-28-chunked-transactions-for-large-background-sweeps.md`), fills rows where `preview_text IS NULL OR ingested_at IS NULL`: `ingested_at` from `items.updated_at`, `preview_text` from the item's `body` property. Enqueue it once at deploy under a fixed job key. It is idempotent.
6. Add tests for ingest, send, the backfill (run twice, two tenants) and the 200-character limit.

## Scope

### In scope

- The two columns, their population on ingest and send, and the per-tenant backfill.

### Out of scope

- Reading them in the thread list: #1567.
- Previews for drafts, which have no `mail_message_meta` row.

## Acceptance criteria

- When a message is ingested, then `preview_text` is its plain text collapsed to at most 200 characters and `ingested_at` is set.
- When a message is sent from Semprec, then both columns are set on its claim row and a later Sent-folder sync does not change them.
- When the backfill runs on a tenant with older rows, then they get `ingested_at` from the item and a preview from the body; a second run changes nothing.
- When HTML-only mail is ingested, then the preview contains no tags.
