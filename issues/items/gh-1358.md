## Context

Model tier rationale: The change is small, but it is inside the Inbox tick's three-phase staleness-checked transaction bracket and adds a tenant-scoped read to its snapshot, so it must not break the fingerprint and locking behavior.

The Inbox tick (`createSemprecTickAction` in `backend/packages/data/src/inbox/inboxTickAction.ts`) reads a snapshot of the source item in a repeatable-read transaction, calls the injected `computeProposal` (`ComputeSemprecProposalFn`) outside any transaction, and writes the proposal in a second transaction. `ProposalComputationInput` carries `sourceItem`, `type`, `entityKind` and `targetDatabaseId`; it carries nothing about language, so the model writing the proposal's texts has no way to know which language the person uses. The person's language is `users.locale`, readable per tenant with `getTenantUserLocale` (`backend/packages/data/src/auth/usersStore.ts`).

Decision: the locale is passed to the injected function as a new input field; this issue does not implement or change the LLM-backed function itself (it is injected and prompt engineering is outside this repository seam).

Decision: a locale change does not invalidate existing proposals. The fingerprint (`computeInboxFingerprint`) is unchanged, so an existing `proposed` card keeps its language and only the next computed proposal uses the new one.

Decision: when no locale resolves (no bound user), the tick uses `cs`, the column default of `users.locale`.

#1704 lets the person change the locale.

## Task

Load `testing`.

1. Add `locale: string` to `ProposalComputationInput`, documented as the language the proposal's person-facing texts must be written in.
2. In `readTickSnapshot`, read the locale with `getTenantUserLocale(client)` inside the existing read transaction, default it to `cs` when `null`, store it in `TickSnapshot`, and pass it as `locale` in the `computeProposal` call in `createSemprecTickAction`.
3. Update the existing test doubles of `computeProposal` only as far as the new field requires, and add tests: the function receives `locale: 'en'` for a user with locale `en`, and `locale: 'cs'` when the tenant has no bound user.

## Scope

### In scope

- Passing the user's locale to `computeProposal` from the tick's read snapshot.

### Out of scope

- The LLM prompt implementation behind `computeProposal`.
- The English text of the tick's own `needsClarification` and history messages.
- Recomputing existing proposals after a locale change.
- The agent session base prompt: #1388.

## Acceptance criteria

- When the tenant's user has locale `en`, then `computeProposal` is called with `locale: 'en'`.
- When the tenant has no bound user, then it is called with `locale: 'cs'`.
- The proposal fingerprint and the locked, unchanged and stale-source behaviors of the tick are unchanged (existing tests pass).
- The full backend `pnpm run verify` passes.
