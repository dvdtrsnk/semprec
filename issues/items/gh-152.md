**Blocked by:** #151

## Context

External delivery works, but connected clients need immediate in-app events and a durable recovery/read-state protocol.

## Task

Expose authenticated unread fetch ordered deterministically by creation and ID. When a notification commits, publish a live message containing the full notification row to every active socket for its user; implement the minimal user-scoped fanout needed now and keep the adapter separable for absorption by #38. On client connection, fetch unread rows before trusting live messages. Implement a visit operation that validates the notification belongs to the authenticated user, atomically marks `read_at` if still null, and returns/navigates to `link_href`; optionally expose mark-all-read as an explicit convenience. Broadcast read-state invalidation to all active user sessions so badges converge. The notification row never becomes the source of truth for the linked workflow.

## Scope

### In scope

- Unread recovery, live user-scoped fanout, visit-and-read, optional mark-all, cross-device read invalidation.

### Out of scope

- Full multiplexed WS protocol, delivered by #38.
- Notification panel UI and generic CRUD endpoints from #37.

## Acceptance criteria

- A reconnecting client obtains every unread notification even if all live frames were lost.
- A notification is never delivered to another user, and reading it on one device clears other-device badge state.
- Repeated visit/read calls are idempotent and return the same target without changing source workflow state.
