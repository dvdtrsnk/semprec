**Model tier:** low

## Context

Model tier rationale: Two small validation hooks that follow the existing choke-point hook pattern, with no new lifecycle, tenant or persisted-data contract.

The library databases (Books and Movies/TV, seeded by `backend/packages/data/src/seed/seedLibraryModule.ts`) have a user-owned `rating` number property. Nothing validates it: any number or string can be stored. The user's own rating is a whole number of stars from 1 to 5, with 0 meaning "no rating". Movies also store a per-person rating for "watched with" on the relation edge to People (`item_relations.metadata { rating }`), which is upserted today by `PUT /api/items/:id/relations/watchedWith/:personId` with a free-form `{ metadata }` body and no validation.

The choke point offers write hooks in `backend/packages/data/src/chokePoint/hooks.ts` (`registerItemCreateHook`, `registerItemUpdateHook`, `registerRelationEdgeWriteHook`). A validation hook that runs before the write is the right place for both rules.

Shared-file ordering: this issue also waits for #1397 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `error-handling` and `testing`.

1. Register an item create hook and an item update hook for the databases whose `ownerModuleId` is the Books or Movies module: when `rating` is present in the written properties it must be an integer from 0 to 5; otherwise throw `ValidationError` with `field: "rating"`. `null` clears the value and is accepted. The update hook validates only keys present in the patch.
2. Register a relation edge write hook for the Movies `watchedWith` relation: when `metadata.rating` is present it must be an integer from 1 to 5, otherwise `ValidationError` with `field: "metadata.rating"`. Other metadata keys are not validated here. Edges without `metadata.rating` stay valid.
3. Register the hooks in `backend/packages/data/src/domainWriteHooks.ts`, next to the existing registrations, with the hook functions in a new library file.
4. Tests in `backend/packages/data/src/__tests__/library.test.ts`: rating 7 and 2.5 on create and update give 400 with field `rating`; 0 and 5 pass; `watchedWith` edge metadata rating 9 gives 400; rating 4 passes; a non-library database with a `rating` property is unaffected.

## Touches

## Scope

### In scope

- Validation of `rating` on Books and Movies items and of `metadata.rating` on the `watchedWith` edge.

### Out of scope

- Number comparison filters and the "no rating" preset: #1622.
- Reading edges and metadata back with the item: not part of this issue.
- Migrating already stored invalid ratings; the hooks apply to new writes only.

## Acceptance criteria

- When an item PATCH sets Books `rating` to 7 or 2.5, then the response is 400 with field `rating`.
- When `rating` is set to 0, 1 or 5, then the write succeeds.
- When `PUT /api/items/:id/relations/watchedWith/:personId` is called with `metadata.rating` 9, then the response is 400.
- When it is called with `metadata.rating` 4 or without a rating, then it succeeds.
- When the same keys are written on a database of another module, then no new validation applies.
