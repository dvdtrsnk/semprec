**Model tier:** medium

## Context

Model tier rationale: One small route over an existing store function with a single new authorization check on the origin marker, using the established custom-route pattern.

The app shows a switch for each of the project's own automations. `setHeartbeatEnabled` (`backend/packages/data/src/scheduler/schedulerStore.ts`) already flips the flag: disabling clears `next_fire_at`, enabling recomputes it from now so missed fires are not caught up. There is no HTTP route for it. System automations (seeded ones, the transcription requeue sweep, the project guidance drift check) must not be switchable by a person. The marker is added by #1438; the listing that shows the switch is #1910.

Decision: changing the name or rule is done by Semp through approval (#1846), not by this route; the route accepts only `{enabled}`.

Shared-file ordering: this issue also waits for #1523, #1548 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `io-hardening` and `testing`.

1. Add `PATCH /api/heartbeats/:id` with body `{enabled: boolean}` (strict: any other key is a validation error). Apply it with `setHeartbeatEnabled` in one transaction and respond with the heartbeat in the shape of #1910's list item.
2. A heartbeat with `origin = 'system'` returns 403 `owner_violation` and nothing is written. An unknown heartbeat or one of another tenant returns not found.
3. After enabling, `next_fire_at` is computed from now and missed fires are not caught up; after disabling it is empty.
4. Register as a custom route in `schemaCoreModuleManifest.ts`, add it to the route matrix, `ROUTE_HANDLER_FILES` and the tenant isolation test.
5. Tests: disable then enable recomputes `next_fire_at` from now; PATCH of a system heartbeat returns 403 `owner_violation`; an extra key returns 400; an `onItemEvent` heartbeat can be enabled and keeps no `next_fire_at`.

## Scope

### In scope

- `PATCH /api/heartbeats/:id` for `enabled`, with the origin check.

### Out of scope

- Origin column: #1438. Listing: #1910. Manual run: #1453.
- Changing name, rule or task: #1846.
- Switching off an automation automatically after failures: decided not to be done; the system only reports a failing automation as a problem, whose "Disable" action calls this route (#1555).

## Acceptance criteria

- PATCH `{enabled: false}` on a user automation clears `next_fire_at`; PATCH `{enabled: true}` sets it from now without catching up missed fires.
- PATCH on a system automation returns 403 `owner_violation` and changes nothing.
- A body with any key other than `enabled` returns 400.
- A heartbeat of another tenant is answered as not found.
