## Context

Model tier rationale: The adapter, route, page states and session-end plumbing are all specified exactly in the existing web patterns.

Every user can download a complete export of their own data and delete their own account; deletion asks for the password again.

- #1043 delivered export: an asynchronous job that writes an archive of the tenant's data, and an authenticated, expiring download.
- #1049 delivered deletion:
  - the tenant goes to status `deleting`;
  - sessions and push registrations are revoked at once;
  - the tenant key is shredded;
  - the tenant's rows and files are later purged (#1055).

  The last admin can never be deleted.

This issue adds the web page for both. It builds on the session-end rule from #1075: a session end runs `setSession({ status: "ending" })` in `web/src/App.tsx`, which leads to one `window.location.replace("/")`. A 401 from any session-bound adapter takes the same path. For that reason, a wrong re-authentication password must not be answered with 401: #1049 answers it with 403.

What exists in the web client:

- `?page=` routing in the composition root (`web/src/main.tsx:28-66`). Session-bound adapters use the shared `fetchImpl` (`main.tsx:36`).
- `RoutedContent` (`web/src/App.tsx:229-271`) chooses the routed content. The header (`App.tsx:212-222`) has the admin link for admins (#1079) and no link for members.
- The adapter pattern: `docs/adr/2026-09-29-web-client-calls-the-api-through-operations-adapters.md`, with `web/src/api/adminOperations.ts` as the nearest example of request/error mapping.

The backend contract below comes from #1043 and #1049. Their merged handler (`backend/services/semprec-api/src/accountHandler.ts`) and PR descriptions are authoritative. If a path or field differs, bind to the merged handler and say so in your PR description.

Both route families are adapter routes, whose error body is `{ error: { code, details? } }` (`backend/services/semprec-api/src/adapter/errorContract.ts:113-126`).

`TenantExport = { id: string, status: "pending"|"running"|"ready"|"failed", createdAt: string, completedAt: string|null, expiresAt: string|null, byteSize: number|null }`

- `POST /api/account/exports` returns `202 { export }` when it creates an export, and `200 { export }` with the existing one when an export is already pending or running.
- `GET /api/account/exports` → `200 { exports: TenantExport[] }`. It lists only non-expired exports, newest first. A ready export expires 7 days after completion.
- `GET /api/account/exports/:id/download` streams the ZIP as an attachment, authenticated by the session cookie. An export that is missing, foreign, not ready or expired gets `404 { error: { code: "not_found" } }`.
- `POST /api/account/delete` with `{ password }` → `202 { status: "deleting" }`. All of the user's sessions are revoked.
  - Wrong password or login lockout → `403` `reauthentication_failed`.
  - Last active admin → `409` `last_admin`.
  - Empty password → `400` `validation_failed`.

## Task

Load `canonical-keys` (route key `account`, labels) and `error-handling` (status mapping, deletion failures).

1. **Adapter** — add `web/src/api/accountOperations.ts` with `createAccountOperations({ baseUrl, fetchImpl })` and an `AccountOperations` interface:
   - `listExports()`, `requestExport()`, `deleteAccount(password)` — all zod-parsed;
   - `exportDownloadUrl(exportId): string` — returns `${baseUrl}/account/exports/${encodeURIComponent(exportId)}/download`. It makes no request: the download is a plain link the browser follows with its cookie.

   Status mapping:
   - `401/403/404/501` → `unavailable`, carrying the status;
   - any other non-2xx, a transport failure or a parse failure → `retryable`.
   - A non-2xx's message is `error.code` when the body `safeParse`s as `{ error: { code: string } }`, otherwise `Request to <path> failed with <status>`.
2. **Route** — in `web/src/main.tsx`, when `page === "account"`, build `account = { operations: createAccountOperations({ baseUrl: apiBaseUrl, fetchImpl }) }` (session-bound `fetchImpl`) and document `?page=account`.
3. **App** — in `web/src/App.tsx`:
   - add `export interface AccountRoute { operations: AccountOperations }` and an `account?` prop;
   - `RoutedContent` renders `<AccountPage operations={…} onAccountDeleted={…} />`, where `onAccountDeleted` sets the session to `{ status: "ending" }`. Pass it down from `App`, which owns `setSession`. Do not call `window.location` from the page;
   - the header shows a link `?page=account` labelled `account.link` for every authenticated user.
4. **Page** — add `web/src/views/account/AccountPage.tsx`, all labels from i18n:
   - **Export section:**
     - a **Request export** button calls `requestExport()` and then reloads the list, whether the export was created (202) or already in progress (200). A rejection is shown in a `role="alert"` element;
     - a **Refresh** button reloads the list;
     - the list loads through `useAsyncResource` (`web/src/views/mailbox/useAsyncResource.ts`) with loading, error (with retry) and empty states;
     - each row shows the created time, a status label and, for `ready`, a download link (`href={operations.exportDownloadUrl(id)}`, `download` attribute) with its expiry time (`formatDateTime`, `web/src/i18n/format.ts:3-8`).
   - **Delete section:**
     - a text explaining that deletion is permanent and signs out every device;
     - a password field (`type="password"`, `autoComplete="current-password"`, required) and a **Delete my account** button, disabled while pending;
     - on success, call `onAccountDeleted()`;
     - a rejection with status 403 shows `account.delete.wrongPassword` and clears the password field;
     - a rejection with message `last_admin` shows `account.delete.lastAdmin`. Any other rejection shows `account.delete.failed` with the message;
     - both failure messages appear in a `role="alert"` element, and the session stays.
5. **i18n** — add the `account.*` keys to `en` and `cs` in `web/src/i18n/messages.ts`.

## Acceptance criteria

- `requestExport` issues `POST /api/account/exports` and accepts both 202 and 200. `listExports` issues `GET /api/account/exports`. Both send same-origin credentials and parse the documented bodies. `exportDownloadUrl("a b")` returns `/api/account/exports/a%20b/download` without calling fetch (web unit, `accountOperations.test.ts`).
- `deleteAccount("pw")` posts `{ password: "pw" }` to `/api/account/delete` and resolves on 202. A 403 rejects as `unavailable` with status 403. A 409 `{ error: { code: "last_admin" } }` rejects as `retryable` with message `last_admin`. A network failure rejects as `retryable` (web unit, `accountOperations.test.ts`).
- The header of every authenticated session shows the `account.link` link. With the `account` route, the page renders (web unit, `App.test.tsx`).
- Requesting an export calls `requestExport` and reloads the list. A rejected request shows its message in an alert. A `ready` row renders a download link whose `href` is the adapter's URL. Other statuses render their label and no link. Refresh reloads the list, a failed list load shows the error state whose retry reloads it, and an empty list shows the empty state (web unit, `web/src/views/account/__tests__/AccountPage.test.tsx`).
- Submitting the delete form with a password calls `deleteAccount` with it. On success, `window.location.replace` is called once with `"/"` and the page is no longer rendered (web unit, `App.test.tsx` with a stubbed `location`).
- A 403 rejection shows `account.delete.wrongPassword` and clears the field. A `last_admin` rejection shows `account.delete.lastAdmin`. In both cases no navigation happens (web unit, `AccountPage.test.tsx`).
- Every new key exists in `en` and `cs`, and `pnpm run verify` passes in `web/`.
