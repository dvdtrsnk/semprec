**Model tier:** medium

## Context

Model tier rationale: One known mechanism (mapping known failure causes to a closed code set on a stored message and a read-time user text) across the turn handler, a migration and the history endpoint, with no new authorization or concurrency contract; the main risk is leaking raw exception text, which the tests pin.

When a Semp reply fails, the chat has to say why in plain words ("The calendar connection timed out, so I could not load the meeting record.") and show which step failed. Today a failed turn is closed through `failRun` in `backend/packages/agent-runtime/src/sempConversation.ts`, which stores the raw `err.message` in `agent_runs.result` and raises an `agent_run_error` notification (`finishAgentRunWithErrorNotification` in `backend/packages/data/src/agentRuns/agentRunsStore.ts`). A model failure is a final assistant message with `stopReason: error` turned into a thrown error by `assertModelSucceeded` (`backend/services/semprec-agents/src/piAgentSession.ts`). An exhausted budget is a 403 `budget_exceeded` of the AI gateway (`backend/services/semprec-ai-gateway/src/piMessagesHandler.ts`) that surfaces to the agent as a model error with text. A failing MCP tool does not fail the turn at all: `executeMcpInvocation` (`backend/packages/data/src/mcp/mcpToolExecution.ts`) returns `{ error: true, result }` as ordinary model input.

This issue gives an assistant message two kinds of failure information:

- A reply that the agent finished, but where a tool call failed and was never succeeded by a later successful call of the same tool, is "incomplete". Whether a reply is incomplete is derived when the history is read, by the shared function of #1890; the history returns `incompleteReason` (`toolTimeout`, `toolUnavailable`, `toolError` or `null`). The text shown on the card is the agent's own answer.
- A reply whose turn threw is `error`, with `error_code` and `error_params` stored on the message. `error_code` uses the single closed set of #1446 (`budgetExceeded`, `modelError`, `cancelled`, `interrupted`, `internal`), shared between runs and messages.

It builds on the queued turn handler (#1727), the step summary stored on the message (#1860, whose failed step this issue references), the MCP failure kinds (#1444), the typed budget refusal (#1547) and the tick thread run model (#1557). #1931 and #1926 build on the stored code.

Decision: no raw exception text is stored or logged for a message failure. `error_params` hold only `{ connectorName?, failedStep?: { key, params }, timeoutMs? }`, never user content. The user-facing text is rendered from the code and params at read time from an i18n catalog, in the locale of the user.

Decision: `budgetExceeded` is recognized from the typed budget error of #1547, never by parsing the error text.

Decision: `interrupted` (a restart in the middle of a turn) is written by the recovery of #1732; this issue only makes sure that the code is part of the set and is rendered.

## Task

Load `error-handling`, `state-writes`, `db-migrations`, `canonical-keys` and `testing`.

1. Migration `backend/packages/data/src/db/migrations/NNNN_semp_messages_error.sql` (next free ordinal at commit time): add `error_code text` and `error_params jsonb` to `semp_messages`, with a check that `error_code` is one of the closed set of #1446 (reuse its exported constant to generate the list in the test; do not duplicate the values).
2. In the turn handler (`backend/services/semprec-agents/src/sempMessageTask.ts`), when the turn throws, classify the error with the helper of #1446/#1547 and store status `error` with `error_code` and `error_params` in one transaction with the status change. An abort by the user or a tenant deactivation maps to `cancelled`; a model stop reason `error` to `modelError`; the typed budget refusal to `budgetExceeded`; anything else to `internal`. Fill `error_params.failedStep` from the last step with status `error` of the step summary (#1860), `connectorName` and `timeoutMs` from the MCP failure details (#1444) when the failing tool is an MCP tool.
3. Do not write the exception text to the message, to `error_params` or to the log of the handler; log the code, the message id and the run id only.
4. Add `backend/packages/data/src/semp/i18n/cs.json` and `en.json` with one text per error code and per incomplete reason, and a renderer that takes `(code, params, locale)`. In the history response of #1543 (the message mapper), return for an `error` message `error: { code, message }` with the rendered text, and for every assistant message `incompleteReason` as derived by the function of #1890.
5. Tests: a turn stopped by an exhausted budget has `status` `error` and `error_code` `budgetExceeded` without any text parsing; a turn where the agent answers after an MCP timeout is `done` and its history entry has `incompleteReason` `toolTimeout`, with the failed step carrying `failureKind` `timeout`, and no raw tool message in the response; an aborted turn is `cancelled`; the log output of a failing turn contains no exception text; the rendered text is localized for Czech and English users.

## Scope

### In scope

- `error_code` and `error_params` on the message, classification of a thrown turn, the read-time user text, and `incompleteReason` in message history.

### Out of scope

- The shared error code set and the run-level classification (#1446, #1547) and localizing run error summaries (#1824).
- The MCP failure kinds and the derivation function themselves (#1444, #1890).
- Writing `interrupted` after a restart (#1732).
- Raising a problem in the status view and its recovery (#1931) and the retry action (#1926).
- The banner above the chat; it is served by the status summary (#1631).

## Acceptance criteria

- When a turn is stopped because the budget is exhausted, then the reply has status `error` and `error_code` `budgetExceeded`, and the code was not derived from message text.
- When Semp answers after a timeout of an MCP tool, then the reply is `done`, its history entry has `incompleteReason` `toolTimeout`, the failed step has `failureKind` `timeout`, and the user sees no raw exception message.
- When a turn is cancelled, then the reply is `cancelled`; when it throws unexpectedly, then it is `internal`.
- When a turn fails, then the log lines of that turn contain no exception text.
- When the history of a failed reply is read, then `error.message` is in the user's locale and contains no user content.
