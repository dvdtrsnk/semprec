## Context

Model tier rationale: This introduces a new write-path contract that every module's item writes can pass through (ownership enforcement on keys a transform adds, a row lock, replay behavior, and a behavior-preserving move of the Tasks time derivation), so a mistake would corrupt or mis-attribute writes across modules.

Today the choke point can only reject a write, never change it. `createItemWithClient` and `updateItemWithClient` (`backend/packages/data/src/chokePoint/itemWrites.ts`) run `runItemCreateHooks` / `runItemUpdateHooks` (`chokePoint/hooks.ts`) after the row is written, and those hooks return `void`. The single pre-write transformation that exists is an inline branch gated on `database.ownerModuleId === TASKS_MODULE_ID` that calls `deriveTaskTime` (`tasks/deriveTaskTime.ts`); on update it takes `lockItemById` only when `timeFrom` or `timeTo` is in the patch. That inline branch is the exception the ADR `2026-09-19-derived-system-properties-computed-inline-at-choke-point` documents and `2026-09-30-choke-point-domain-hooks-through-a-per-process-registry` carves out for `tasks/`.

This issue adds the missing mechanism: a per-process registry of pre-write transforms, one or more per owning module, that receive the incoming patch and return a new patch (or throw `ValidationError`) before anything is written. Several later features need it: normalizing Events times (#1598), validating Tasks titles and dates (#1536), recording a task's completion day (#1544) and first planned day (#1602), recurring-series identity (#1605, #1668), unpinning finished projects (#1520), select-option validation (#1802), sleep validation (#1784), iCalendar identity (#1599) and task visibility (#1780). They each register a transform instead of editing `itemWrites.ts`. The next hook mechanism, #1530, builds on this issue because both edit the hook registry file.

Decisions:
- A transform is attached to a module id and runs only for databases whose `ownerModuleId` equals that id.
- The row lock is taken whenever the database has at least one registered transform (the contract hands `stored` to the transform). For Tasks this means every Tasks update now locks the row, not only updates that touch `timeFrom`/`timeTo`; the resulting values are unchanged.
- Keys of an update that rollup dependency lookup and the timezone check inspect are taken from the transformed patch, so a key a transform adds (for Tasks, `time`) is treated like any other written key.
- `writerKind` is not part of this issue. If it is already on the item write options when this lands (#1415), include it in the transform context; otherwise that issue adds it.

Shared-file ordering: this issue also waits for #1402, #1415 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `testing` and `adr-conventions`.

1. In `chokePoint/hooks.ts` add `registerItemPreWriteTransform(moduleId, fn)`, the exported types `ItemPreWriteTransformContext` and `ItemPreWriteTransform`, `hasItemPreWriteTransform(moduleId)` and `runItemPreWriteTransforms(moduleId, context)`. The context is `{ client, database, stored, patch, humanWriterUserId }`, where `stored` is the locked current `ItemRow` on update and `null` on create. `fn` returns the new patch (`Record<string, unknown>`) or throws `ValidationError`. Several transforms for one module run sequentially in registration order, each receiving the previous output; registering the same `(moduleId, fn)` twice is a no-op. Extend `clearHooksForTests` to clear the new registry.
2. In `createItemWithClient`, run the transforms for `database.ownerModuleId` after `assertWritableProperties` and before `insertItemWithReplay`. Insert and pass the transformed properties to `runItemCreateHooks`. If `insertItemWithReplay` reports `created: false` (idempotent replay), return the existing item and discard the transform result: nothing new is written and no hook runs.
3. In `updateItemWithClient`, after `assertWritableProperties`, when `hasItemPreWriteTransform(database.ownerModuleId)` is true take `itemsStore.lockItemById` (throw `NotFoundError` for a missing or trashed row), then run the transforms and use the result as the patch passed to `updateItemProperties`, `runItemUpdateHooks`, the rollup-dependency loop and the timezone check. Heartbeats keep database/event/item/affinity triggering, without a patch argument. Ordinary updates without transforms take no new preliminary lock; gh-1516 moves the valueLinks update's existing item lock before handoff.
4. Enforce added keys (output keys absent from input): unknown key throws ValidationError (400 validation_failed); rollup throws ForbiddenError (403 computed_readonly); relation throws ValidationError (400 validation_failed). An added system key whose ownerProcess is neither null nor the transform moduleId throws ForbiddenError (403 owner_violation). These are the existing distinct registry-ADR guards; no rejected key is accepted. Caller-supplied keys keep assertWritableProperties results. Reapply existing color and applicable title guards to final create/update/prepared user patches, preserving writer/module exemptions.
5. Move the Tasks `time` derivation out of `itemWrites.ts` into a Tasks-owned transform in a new file `backend/packages/data/src/tasks/taskPreWriteTransform.ts` that calls `deriveTaskTime`, and register it in `domainWriteHooks.ts` under `TASKS_MODULE_ID`. Remove the `TASKS_MODULE_ID` and `deriveTaskTime` imports and both inline branches from `itemWrites.ts`. Create writes `time` always; update writes it when the patch contains `timeFrom` or `timeTo`, computed from the patch merged over `stored`. Preserve derivation for valid schedules; the included gh-1536 defines the stricter validation, date-clear behavior and final transform filename.
6. Reuse `docs/adr/2026-10-29-item-pre-write-transforms-per-module-registry.md` and verify the existing 2026-09-19 supersession metadata; keep accepted historical bodies unchanged. The registry is module-neutral and Tasks derivation/imports leave `itemWrites.ts`. Preserve its existing Transcripts title exemption and mail observation handoff/lock functions; relocating them is outside this issue. No broader domain exemption or implementation compliance is inferred from ADR reuse.
7. Tests: unit tests in `chokePoint/__tests__/hooks.unit.test.ts` for the registry (order, duplicate registration, clear); an integration test that a transform's patch is what is stored and gives one `updatedAt`, that a replay with the same `Idempotency-Key` writes nothing and runs no hook, and that a transform adding an owner `system` key of another `ownerProcess` ends in `403 owner_violation`. Retain valid derivation assertions in `__tests__/tasksTime.test.ts`, using fixtures valid under included gh-1536; expectations that explicitly conflict with its stricter rules become refusal plus unchanged-row assertions. The pure `__tests__/deriveTaskTime.unit.test.ts` remains unchanged.

## Acceptance criteria

- When a transform registered for Events turns `"9:00"` into `"09:00"`, the stored row contains `"09:00"`, the row has exactly one `updatedAt` change, and the update hooks receive the transformed patch.
- When the same create is repeated with the same `Idempotency-Key`, the existing item is returned, nothing is written, and no transform result, create hook or heartbeat is applied a second time.
- When a transform adds an `owner: system` key whose `ownerProcess` is another module, the write ends in `403 owner_violation` and nothing is stored.
- When a transform throws `ValidationError`, the write fails with `400 validation_failed` and rolls back. Invalid transformed color or applicable blank title is refused on create/update and read-only user-patch preparation, without mutation.
- Without a registered transform, ordinary non-valueLinks updates take no extra preliminary row lock and otherwise retain existing behavior.
- Existing valid Tasks time derivation assertions pass with gh-1536-compatible fixtures; its newly invalid schedules are refused without a write. The pure deriveTaskTime unit suite remains unchanged, and `itemWrites.ts` no longer imports from `tasks/`.
