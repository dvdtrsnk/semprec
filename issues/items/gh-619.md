## Behavior specification (approved)

`semprec-ai-gateway` is the only process that talks to AI providers (`docs/adr/2026-09-10-ai-gateway-monopoly-on-provider-calls.md`, unchanged by this batch). This batch makes what that monopoly is supposed to guarantee actually hold: the daily/monthly budget caps cannot be jointly overshot by concurrent calls, a call the provider has already billed is never lost from `ai_gateway_calls` (neither by a failed accounting write nor by a shutdown or a client disconnect), a malformed provider response becomes a diagnosable 502 rather than a 500 or a silently free row, transient provider errors (429/529/5xx) are retried inside the route's own deadline, and the audio routes cannot exhaust process memory through unbounded concurrency. Every provider call is reserved against the budget in one locked transaction before it starts and settled with its real cost after it returns; every `ai_gateway_calls` row records which operation produced it.

## Evidence

- `backend/packages/ai-gateway/src/gateway.ts` (`assertWithinBudget`, `withTokenAccounting`, `withAudioAccounting`): check-then-act with no lock, documented in the file's own comment — N concurrent calls at the cap all pass.
- `gateway.ts` `withTokenAccounting`/`withAudioAccounting`: the provider result is discarded and `completeHandler.ts` answers 500 when the `ai_gateway_calls` INSERT after the provider call fails — the call is paid for and unrecorded.
- `backend/services/semprec-ai-gateway/src/shutdown.ts` `SHUTDOWN_DRAIN_TIMEOUT_MS = 60_000` is derived from the completion client's timeout only; `semprec-transcribe/src/audioGatewayClient.ts` waits 10 minutes and `pyannoteProvider.ts` polls up to 300 × ~56 s, so `closeAllConnections()` cuts in-flight audio calls. No `AbortSignal` reaches any provider `fetch`, so a client that gave up leaves the provider work running.
- `audioHandler.ts` `readJsonBody`/`validateBody`: up to 150 MiB per body held in three to four copies, with no cap on how many such requests run concurrently.
- `ai_gateway_calls` rows written by the audio routes carry `operation = NULL` (`aiGatewayCallsStore.ts` `recordAudioGatewayCall`); `getGatewaySpend` filters on `at` with no index (`0018_ai_gateway_calls.sql` indexes only `agent_run_id`).
- `structuredProviders/anthropicProvider.ts`: `isAnthropicMessagesResponse` only checks that `content` is an array, so a `null` block throws `TypeError` (→ 500); a missing `usage` is silently recorded as zero cost; a non-2xx response body is never consumed or cancelled.
- `anthropicProvider.ts` and `packages/ai-gateway-client/src/httpAiGatewayClient.ts` fail fast on every non-2xx, including 429 and 529.

## Decisions

- Where does the budget reservation live? → A `status` column (`reserved` | `settled` | `failed`) on `ai_gateway_calls` itself, `NOT NULL DEFAULT 'settled'`, plus a `pg_advisory_xact_lock` around read-spend-then-insert-reservation. Reason: the reservation is the audit row; a separate table would need a sweep to reconcile the two, and `DEFAULT 'settled'` keeps the previous release's INSERT (which omits the column) both valid and semantically right (expand/contract, `docs/adr/2026-09-10-expand-contract-forward-only-migrations.md`).
- What does a failed provider call leave behind? → The reserved row flipped to `failed` with `cost_usd = 0`. Reason: no sum over `cost_usd` (budget or usage report) has to learn a new filter, and the row still records that the attempt happened.
- Settle write fails after the provider returned? → Retry the UPDATE up to three attempts with short backoff, then log at error with the call id and return the provider result anyway; the row stays `reserved` with its estimate. Reason: a paid-for result is worth more than a clean ledger; the estimate keeps counting against the cap until someone reconciles it. A reconciliation sweep is out of scope.
- The `(at)` index goes with the reservation issue, not the provenance issue. Reason: the spend query now runs inside the advisory-locked critical section, so its cost is what serializes every gateway call.
- Send `agentRunId` from the client? → No. Reason: no current caller of `/internal/complete` (`driftAction.ts`, `transcriptionTask.ts`) runs inside an agent run; a field nothing sets is speculative generality (`docs/adr/2026-09-10-no-speculative-generality-beyond-issue-scope.md`).
- Drain timeout → `Math.max` of the two route timeouts the gateway owns (60 s completion, 600 s audio), with `TimeoutStopSec` raised in the systemd unit so systemd does not SIGKILL the drain at its 90 s default.
- Concurrency cap for audio → a fixed in-process limit of 2 enforced in the dispatcher (`app.ts`), answering 503 with `Retry-After: 1`; `semprec-transcribe` already retries its job with graphile-worker's backoff, so no client change is needed.
- Retries → only in the gateway's Anthropic adapter, bounded by one 55 s deadline shared across attempts and by the client-disconnect signal; the HTTP client keeps failing fast so a request is never retried at two layers.
- Non-2xx bodies → `res.body.cancel()` rather than `res.text()`, so releasing the connection never buffers an unbounded error body.

## Out of scope

- Per-user budgets and a user column on `ai_gateway_calls` (multi-tenant work).
- Trusting the caller-asserted `audioSeconds` for audio cost (the gateway does not measure the audio it receives).
- Replacing the `as`-style response casts in `httpAiGatewayClient.ts` with parsed types (pre-tenancy typed-boundaries work).
- A sweep that reconciles rows left in `reserved` after a settle failure.
- Retries in the audio provider adapters (DeepInfra, pyannoteAI) and in the HTTP clients.
