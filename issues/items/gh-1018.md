## Context

Model tier rationale: The nine production call sites are enumerated, but binding fixtures in dozens of test files to the right tenant needs per-test judgment.

Background producers with no request session pick "the" user with `getEarliestUserId` / `getEarliestUserLocale` (`backend/packages/data/src/auth/usersStore.ts:64-88`): the first-created account in the global `users` table. With tenants, that is tenant A's user receiving tenant B's events, and B's runs attributed to A. These are the call sites for tenant events and run attribution:

| Site | Use |
|---|---|
| `backend/packages/data/src/agentRuns/agentRunsStore.ts:112` | `resolveActorUserId` fallback for a root run with no `userId` |
| `agentRunsStore.ts:190` | `agent_run_error` recipient in `finishAgentRunWithErrorNotification` |
| `backend/packages/data/src/scheduler/sweep.ts:37` | `heartbeat_error` recipient |
| `backend/packages/data/src/mail/mailSyncJob.ts:371` | `mail_sync_error` recipient |

| `backend/packages/data/src/manifest/driftCheck.ts:67-69` | locale of the drift manifest |

What earlier issues provide:
- `users` is a global identity table without row-level security. Each user is bound 1:1 to a tenant by `users.tenant_id` (UNIQUE).
- The SQL functions:
  - `app_current_tenant()` = `NULLIF(current_setting('app.tenant_id', true), '')::uuid`;
  - `app_tenant_default()` = `COALESCE(app_current_tenant(), app_sole_tenant())` until #1067 makes it `app_current_tenant()` alone.

  Tenant-table row-level security uses exactly `app_tenant_default()`.
- `withTransaction` and the pool set `app.tenant_id` from the `@semprec/shared` scope (`runInTenant`, `runAsSystem`, `currentTenantScope()`). The blockers run every one of these producers inside its tenant:
  - heartbeat sweep and fires (#984);
  - mail sync (#989);
  - agents process (#991);
  - transcribe process (#992);
  - library metadata and blob storage (#1008);
  - startup repair (#988).

The operator alerts, `observabilityCheckSystem.ts` and `restoreTestResult.ts`, move to #1019. Deleting the earliest-user functions is #1020.

## Task

Load `state-writes` (recipients written inside the source write's transaction) and `error-handling` (a tenant with no user keeps today's "no account yet" outcomes).

1. **Lookups.** In `usersStore.ts`, add two functions.
   - `getTenantUserId(client: Pool | PoolClient): Promise<string | null>` runs `SELECT id FROM users WHERE tenant_id = (SELECT app_tenant_default())`.
   - `getTenantUserLocale(client: Pool | PoolClient): Promise<string | null>` runs the same query for `locale`.
   - Both return `null` when the tenant has no bound user, and in a system scope once more than one tenant exists. That is the same visibility tenant rows have.
   - Each docstring states the rule: the recipient of a tenant event is the user of the scope's tenant.
   - Both are re-exported by the existing `export * from "./auth/usersStore.js"` (`backend/packages/data/src/index.ts:283`).
2. **Switch the call sites.** Replace every call site in the table above with `getTenantUserId` / `getTenantUserLocale`, keeping each one's "no user" branch as it is:
   - skip the notification;
   - log the warning in `transcriptionTask.ts`;
   - fall back to `"en"` in `driftCheck.ts`.

   `resolveActorUserId` keeps throwing when there is no user. Its message becomes `Cannot create an agent run: the current tenant has no user`.
3. **Docs.** Rewrite every doc comment that names the earliest account or `getEarliestUserId` as the stand-in:
   - `agentRunsStore.ts:28-35`, `:82-90`, `:92-101`, `:174-175`;
   - `sweep.ts:29-30`;

4. **Public surface.** Add `getTenantUserId` and `getTenantUserLocale` to the runtime-export list in `backend/packages/data/src/__tests__/publicSurface.test.ts`.
5. **Test fixtures.** An account created with `createUser` is the tenant's user only once `users.tenant_id` points at the tenant. Without `tenantId`, `createUser` leaves the binding NULL (#968). In each existing integration or e2e test that relied on the earliest-account fallback, create the owner account with `createUser(..., { tenantId: getTenantZeroId() })`, using `getTenantZeroId()` from `@semprec/data/testSupport` (#975). Bind only one account per tenant, since `users.tenant_id` is unique. This covers creating root agent runs without `userId`, and expecting one of the notifications or the drift locale above. Fixture edits only; no assertion changes, except:

   The `syncServer.test.ts` block and the `agentRunHandler.test.ts` comment describe the earliest-account fallback and now describe the tenant's user.

## Acceptance criteria

- **Lookups.** `getTenantUserId` / `getTenantUserLocale` return:
  - tenant A's user and locale inside A's scope, and B's inside B's;
  - `null` inside `runAsSystem` while two tenants exist;
  - the sole tenant's user with no scope while only tenant zero exists;
  - `null` for a tenant with no bound user.

  (integration, `tenantUser.test.ts`)
- **Run actor.** In tenant B, `createAgentRun` for a root run without `userId` sets `actorUserId` to B's user. With no user bound to the tenant it throws the new message. A delegated run still inherits its parent's actor, and an explicit `userId` is still used. (integration, `agentRunsStore.test.ts`)
- **Run error.** In tenant B, `finishAgentRunWithErrorNotification` writes `agent_run_error` for B's user with B's `tenant_id`. With no tenant user it closes the run and writes nothing. (integration, `agentRunErrorNotification.test.ts`)
- **Producers in tenant B.** Each notification goes to B's user and never to A's, the earlier-created account:
  - `heartbeat_error`, from a heartbeat failing in B (integration, `scheduler.test.ts`);
  - `mail_sync_error` (integration, `mailSync.test.ts`);
  - library `automation_error` (integration, `library.test.ts`);
  - transcription `automation_error` (integration, `transcriptionTask.test.ts`).
- **Approvals.** A generic-operation approval request and an MCP-invoke approval request created in tenant B notify B's user. The `linkHref` names B's user id. (integration, `genericOperationGateway.test.ts`, `mcpInvokeTool.test.ts`)
- **Drift locale.** The drift check action in tenant B, whose user's locale is `cs` while A's is `en`, completes. With no user in the tenant it falls back to `en` and completes. The locale value itself is asserted through `getTenantUserLocale` in the Lookups criterion. (integration, `manifest.test.ts`)
- **Unchanged suites.** Every listed existing suite passes with only the fixture binding changed. (integration and e2e)
