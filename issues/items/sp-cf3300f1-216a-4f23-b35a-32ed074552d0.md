### Requirement gh-1452: [semp-threads 05/19] Link agent runs to Semp threads

#### Context

Model tier rationale: One known mechanism (a nullable column with a tenant-composite foreign key added in two migrations) across the run store and delegation seam, following the existing 0083/0084 pattern, with no new isolation model.

#1367 adds `semp_threads` and `semp_messages`. Agent runs are not yet tied to a thread: `agent_runs` (created in `0001_core_schema.sql`) has no thread column, so a run, its events and the compaction checkpoint of a conversation cannot be attributed to a thread. This issue adds that link, and the single index every thread-scoped read of runs will use.

Run-to-thread rules (the store records them; the callers that start runs apply them):

- a chat or item run belongs to the thread of the message that started it;
- a delegated run (supervisor with `parent_run_id`) inherits the `thread_id` of its parent run;
- a heartbeat run belongs to the tick thread of its heartbeat, even when a chat started it through the heartbeat trigger;
- an MCP run has no thread (NULL).

Later issues build on this: #1560 keys conversation reconstruction by thread, #1557 sets the tick thread on heartbeat runs, #1729 reads the latest run per thread, #1766 and #1805 read the thread of a run, and #1772 posts outcomes into the requesting thread.

Decision: the index is `(tenant_id, thread_id, wake_seq)`; no second thread index is added by anyone.

Migration A: `ALTER TABLE agent_runs ADD COLUMN thread_id uuid NULL;` plus a composite foreign key `(tenant_id, thread_id)` referencing `semp_threads (tenant_id, id)` with `ON DELETE SET NULL (thread_id)` (column-list `SET NULL`, Postgres 16, so `tenant_id` is never nulled), added `NOT VALID`; and `CREATE INDEX agent_runs_thread_wake_idx ON agent_runs (tenant_id, thread_id, wake_seq)`.
2. Migration B (separate file, following `0083`/`0084`): `VALIDATE CONSTRAINT` for that foreign key. `agent_runs` is a full (non-partitioned) table, so `NOT VALID` plus a later validate is the correct pattern.

When `parentRunId` is given and no `threadId` is passed, the store copies the parent run's `thread_id` (inheritance happens in the store so every delegation path gets it).
4. Make the delegated-run creation path in `packages/agent-runtime` pass nothing extra: it relies on the store inheritance. Make no change to the MCP run creation path (it leaves `threadId` unset).
5. Tests: a run created with `threadId` stores it; a delegated run created with a `parentRunId` carries the parent's `thread_id`; an MCP run has NULL; deleting a thread sets the runs' `thread_id` to NULL and leaves `tenant_id` intact; a run cannot reference a thread of another tenant; the existing agent run tests still pass.
