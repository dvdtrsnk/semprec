## Context

Model tier rationale: The migration statements and index names are given exactly, with a pre-flight grep and enumerated two-tenant test cases.

Foreign-key and unique checks ignore row-level security, so a unique index on a tenant table that does not lead with `tenant_id` lets one tenant collide with, or detect the existence of, another tenant's row. The rule (tenant-isolation ADR, #968): every unique index on a tenant table leads with `tenant_id`, except a server-generated surrogate key. #974 added a tenant-leading twin beside each legacy global uniqueness and listed the legacy ones in `LEGACY_GLOBAL_UNIQUES` in `backend/packages/data/src/__tests__/tenancyCatalog.test.ts`; the blockers switched every reader and `ON CONFLICT` arbiter to the twins, and the checkpoint release (#1058) carrying those switches runs in production. This is the contract step: it must ship in a release after that one, so a one-release rollback lands on code that no longer uses the legacy keys.
