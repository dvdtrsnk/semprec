## Context

Model tier rationale: One known mechanism (a factory and a callback on an existing class) across a few runtime seams with existing conversation tests, but it changes how a session is bound to its run, so it needs care with ordering and cancellation.

Bind Semp tools to the chosen run before prompting, report the first stored event per turn and propagate cancellation. #1727 consumes these seams for queued replies; add no task, queue behavior or message write here. Preserve the leading send arguments; thread registry work is #1565 and persisted user turns are #1566.

## Task

Load `state-writes` and `testing`.

1. In `sempConversation.ts` and `types.ts`, replace the `createAgentSession` option of `SempConversationOptions` with `createAgentSessionForRun: (run: AgentRunRow) => Promise<CreateAgentSession>`, called by `send()` after it has created (or chosen) the run and before the first prompt, so tools bind to that run's id. Update every existing caller and test to the new option (a test double can return a constant factory).
2. Add a trailing options argument to `SempConversation.send(...)`: `{ signal?: AbortSignal; context?: readonly UserTurnContextRef[]; onTurnStart?: (turn: { agentRunId: string; firstEventId: string }) => Promise<void> | void }`. Keep the leading parameters of `send()` as they are in the code you start from (the thread-keyed registry is a separate issue, #1565).
   - `context` uses the strict labeled-ref contract of #1566. Validate before dispatch, pass it to wake session options and continuation `send(task, context)`, and use an empty array when absent; do not reuse a prior turn's refs. No leading argument or queue/message producer is added.
   - `signal` is passed to the session options and to `runAgentTurn` so an abort cancels a prompt blocked on its next event and the run is closed as errored through the existing `failRun` path.
   - `onTurnStart` is awaited exactly once per turn, after the run is `running` and the first `agent_run_events` row of the turn has been written and before the model is prompted further; `firstEventId` is that row's id. For a continuation on an open entry, `agentRunId` is the entry's run and `firstEventId` is the first row written by this turn. If the callback throws, the turn is not started, the run is closed through `failRun`, and the error propagates.
   - To expose the first event id, add an optional `onFirstEvent` hook to `runAgentTurn` in `lifecycleAdapter.ts` (called with the stored event row id right after the first event insert); `send()` bridges it to `onTurnStart`.
3. In `backend/services/semprec-agents/src/agentRunTasks.ts` and `agentSessionComposition.ts`, keep `createAgentSessionFactoryForRun` as the factory and expose it in the shape task 1 needs (`(run) => createAgentSessionFactoryForRun(pool, moduleRegistry, gateway, run)`). Do not add a new task or producer here.
4. Thread the new option through the composition seams that construct a `SempConversation` or pass the agent-run handlers, so the project still builds: `packages/data/src/agentWorker.ts` and `services/semprec-agents/src/queueRuntime.ts` only if their signatures reference the changed type.

## Acceptance criteria

- When `send()` starts a turn, the factory receives that turn's run row and tools bind to that run id; its optional validated context reaches both wake and continuation with the leading parameters unchanged, and omission supplies an empty array.
- When a turn starts, `onTurnStart` is called once with the run id and the id of the first event stored for the turn, before the reply finishes; for a continuation turn it reports the same run with a larger first event id.
- When the passed `signal` aborts during a prompt, `send()` rejects, the run is closed as errored and the conversation entry is dropped as after any broken turn.
- When `onTurnStart` throws, no prompt runs and the run is closed as errored.
- All existing `SempConversation`, delegation and agent-run tests pass with the renamed option.
