**Blocked by:** #965, #978

## Context

#978 added the tenant scope, exported from `@semprec/shared`:
- `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()`, which returns `{ kind: "tenant", tenantId } | { kind: "system", reason } | undefined`.
- `enforceTenantScope(site)`, which returns the current scope. With none, it either logs `tenant_scope_missing` and returns `undefined` (`warn`, the default), or throws `TenantScopeMissingError` (`SEMPREC_TENANT_SCOPE=strict`).
- Every database access on a `createPool` pool applies the scope through the GUC `app.tenant_id`.
- Socket callbacks of pooled connections run in system scope.

#968 added `tenants(id, status ∈ provisioning|active|suspended|deleting, …)` (global, readable by both runtime roles) and `app_sole_tenant()`. That function returns the only tenant's id while exactly one `tenants` row exists, and NULL otherwise.

The queue is the other way work moves around, so it must carry the tenant too. Facts about the code (`backend/packages/queue/src/index.ts`):
- The envelope is `{ traceId, payload }` (`:19-22`). `enqueueJob` (`:209-236`) stamps `traceId` from the producer's trace. A producer cannot set top-level fields.
- `registerTask` (`:275-310`) unwraps the envelope, restores the trace and runs the handler. A raw, non-envelope payload (graphile-worker crontab ticks, the 11 sweeps in `backend/packages/data/src/worker.ts:81-92`) runs with a fresh trace.
- The supersession catch (`:285-308`) must keep working.
- Callers of `registerTask`:
  - `backend/packages/data/src/worker.ts:234`
  - `backend/packages/data/src/agentWorker.ts:41`
  - `backend/packages/data/src/moduleTasks.ts:91,117`
  - `backend/services/semprec-transcribe/src/queueRuntime.ts:33`
  No module manifest declares tasks today.
- `runWorker` (`:331`) and `runOnce` (`:344`) start graphile-worker. Its own polling and completion queries run in whatever async context `run()` was started in.
- `ensureQueueSchema` (`:135`) and `grantQueueSchemaPrivileges` (`:158`) run at service startup.
- `queueJobEnvelopeSchema` is a non-strict `z.object`, so the previous release ignores an extra top-level key. That keeps rollback safe.

## Task

Load `error-handling` (job failure vs. no-op), `state-writes` (enqueue inside the producer's transaction) and `io-hardening` (the runner's pooled connections).

1. **Envelope.** `queueJobEnvelopeSchema` gains `tenantId: z.string().uuid().nullable().optional()`. `.optional()` is what lets a legacy envelope without the key still parse.
2. **Task tenancy catalog.**
   - Add `export type TaskTenancy = "tenant" | "system"`.
   - Add `export const TASK_TENANCY: Record<CoreTaskName | AgentTaskName, TaskTenancy>`, next to `CORE_TASK_AFFINITY` and keyed the same way.
     - **`system`:** `heartbeatSweep`, `docCompactionSweep`, `docHistoryCleanup`, `mailAccountSyncSweep`, `mailSearchReindexSweep`, `itemTrashPurgeSweep`, `trashPurge`, `observabilityCheckSystem`, `mcpRunCredentialExpirySweep`, `agentRunEventsRetention`, `queueFailedJobsPrune`.
     - **`tenant`:** every other core name, plus `heartbeatFireAgent`, `agentRun` and `delegatedAgentRun`.
   - A task name outside the catalog (a module task) is `tenant`.
3. **`enqueueJob`.** The new top-level `tenantId` comes only from `currentTenantScope()`:
   - in a tenant scope, its id;
   - in a system scope, `null`;
   - with no scope, `enforceTenantScope("enqueueJob")`: `null` in warn mode, and in strict mode the error is thrown before any SQL is sent.

   The signature and `EnqueueJobOptions` do not change. A `tenantId` inside `payload` is business data and is never read.
4. **`registerTask`.** Inside the restored trace:
   - **System task:** run the handler in `runAsSystem(\`task:${name}\`)`. Ignore any envelope `tenantId`.
   - **Tenant task.** Resolve the tenant id:
     - Take the envelope's `tenantId` when it is a string.
     - Otherwise (legacy envelope, `null`, or a raw payload), run `SELECT app_sole_tenant()` via `helpers.query` and log at warn level `tenant_task_without_tenant` with `jobName` and `jobId`. A NULL result throws an `Error`, so the job fails and is retried. This sole-tenant fallback stays until #1061.

     Then read `SELECT status FROM tenants WHERE id = $1` via `helpers.query` (typed row, status checked against the four values).
     - **No row, `suspended` or `deleting`:** log at info level (`jobName`, `jobId`, `tenantId`, the status or `missing`) and return without calling the handler. The job completes as a no-op.
     - **`active` or `provisioning`:** run the handler in `runInTenant(tenantId, …)`. Provisioning runs too, so jobs that provisioning itself enqueues are not lost.

   The supersession catch keeps its current behaviour. It wraps the whole of the above.
5. **Runner and schema scope.**
   - `runWorker` and `runOnce` call graphile-worker inside `runAsSystem("queue-worker")`. Contexts the runner creates are then system, and per-job `runInTenant` is entered from system.
   - The `Runner` that `runWorker` returns runs `stop()` inside the same system scope, so a stop called from a signal handler with no scope still releases jobs through scoped queries.
   - `ensureQueueSchema` and `grantQueueSchemaPrivileges` run their queries inside `runAsSystem("queue-schema")`.
6. **Tests.**
   - Update `backend/packages/queue/src/__tests__/traceEnvelope.unit.test.ts`: tenant tasks now need a `query` on their fake helpers, and the "no traceId" case keeps failing.
   - Update `backend/packages/data/src/__tests__/moduleTasks.unit.test.ts`. Its fake helpers at `:110,139` need a `query` that answers the sole-tenant and status lookups.
   - Add `backend/packages/queue/src/__tests__/tenantEnvelope.unit.test.ts`, with fake helpers and no Postgres.
   - Add `backend/packages/data/src/__tests__/queueTenantEnvelope.test.ts`, on a real pool with `runOnce`.

## Acceptance criteria

- **Unit (`tenantEnvelope.unit.test.ts`) — enqueue stamping.**
  - `enqueueJob` inside `runInTenant(T)` sends an envelope whose top-level `tenantId` is `T`.
  - Inside `runAsSystem` it is `null`.
  - With no scope in warn mode it is `null` and one `tenant_scope_missing` record is written.
  - With `SEMPREC_TENANT_SCOPE=strict` and no scope it rejects with `TenantScopeMissingError`, and `client.query` is never called.
- **Unit — producers cannot set the tenant.** A payload `{ tenantId: U }` enqueued inside `runInTenant(T)` produces an envelope with top-level `tenantId: T` and `payload.tenantId: U` unchanged.
- **Unit — tenant tasks.**
  - A tenant task with envelope `tenantId: T` and status `active` (or `provisioning`) runs its handler with `currentTenantScope()` equal to `{ kind: "tenant", tenantId: T }` and the unwrapped payload.
  - With status `suspended`, `deleting` or no row, the handler is not called and the wrapper resolves.
- **Unit — sole-tenant fallback.**
  - A tenant task with a legacy envelope (no `tenantId`), `tenantId: null` or a raw payload runs in the tenant returned by `app_sole_tenant()` and writes one `tenant_task_without_tenant` record.
  - When that lookup returns NULL, the wrapper rejects.
- **Unit — system tasks.** A system task (`heartbeatSweep`) runs in a system scope even when its envelope carries a `tenantId`.
- **Unit — catalog.** Every `CORE_TASK_NAMES` and `AGENT_TASK_NAMES` value has a `TASK_TENANCY` entry, and exactly the 11 sweep names listed above are `system`.
- **Unit — rollback safety.** An envelope produced by the new `enqueueJob` parses under the previous schema `z.object({ traceId: z.string().uuid(), payload: z.unknown() })`. A legacy envelope parses under the new one.
- **Unit — supersession unchanged.** A handler that throws on a job whose key was cleared is still swallowed. Any other handler error still propagates.
- **Integration (`queueTenantEnvelope.test.ts`).**
  - A job enqueued with `enqueueJob` inside `runInTenant(<tenant zero>)` is stored in `graphile_worker.jobs` with that `tenantId`.
  - Run by `runOnce`, its handler's `withTransaction` reads `app_current_tenant()` as tenant zero.
- **Integration — suspended tenant.** With tenant zero set to `suspended` (restored afterwards), that job completes without calling the handler, and its row is gone from `graphile_worker.jobs`.
- **Integration — unknown tenant.** A job enqueued inside `runInTenant(<random UUID>)` completes without calling the handler.
- **Integration — runner scope.** With `SEMPREC_TENANT_SCOPE=strict`, `ensureQueueSchema`, `runWorker` and the returned runner's `stop()` all succeed when called from a test body with no scope, on a `createPool` pool.
- **Integration — existing suites.** Queue-driven suites (`queueSupersession.test.ts`, `scheduler.test.ts`, `rollup.test.ts`, `services/semprec-transcribe/src/transcriptionTask.test.ts`) pass unchanged.
