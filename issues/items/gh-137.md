## Context

The runtime's responsibility split is a compatibility boundary, not merely an implementation detail.

## Task

Document in the agent-runtime package README/code ownership map: SRP (`pi` single-run/compaction, Semprec orchestration, gateway egress/budget, registry allowlist, agent-run audit with unit); OCP (`systemPromptOverride` and AgentTools); LSP (same session construction for supervisor/project agents); ISP (capability-filtered tool arrays, explicit MCP sync, per-call approval); and DIP (orchestration depends on prompt/tool/gateway ports, never pi/provider internals). Add architecture tests or dependency rules for the enforceable import directions.

## Scope

### In scope

- Exact five-principle mapping, ownership table, public extension points, and enforceable boundaries.

### Out of scope

- Runtime refactors unrelated to a documented violation and sandboxing.

## Acceptance criteria

- A maintainer can locate the owner of lifecycle, orchestration, egress, registration, and audit.
- Dependency checks prevent runtime policy from importing pi/provider internals.
- Documentation matches actual composition roots and types.
