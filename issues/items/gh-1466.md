**Model tier:** medium

## Context

Model tier rationale: A new notification kind with a database constraint change and one producer hook, relying on the problem writer from its blocker, so exact call sites carry some uncertainty.

Assistant problems (failed sync, a stuck assistant, repeated failures) are tracked as deduplicated problems by #1459: one problem per source, raised through `raiseProblem`, each with a `severity` stored in `semp_problems`. The source events still write their own notifications (for example `mail_sync_error` on every failed job), so four sync failures of one mailbox would send four pushes. The design wants one push per problem.

Decisions: a new kind `semp_problem` is written by `raiseProblem` only when a problem is created or when an existing problem's severity increases; its severity comes only from `semp_problems.severity` (an expired sign-in is a critical problem like any other); its `transition_instance` is the problem id plus the severity so a repeat at the same severity is a replay and writes nothing; its category is `problems` and the push filter of #1443 applies to it. Source notifications of problem kinds are still stored but are no longer pushed (`push: false` in the kind policy of #1440 for problem kinds other than `semp_problem`).

## Scope

### In scope

- The `semp_problem` kind, writing it when a problem is created or its severity increases, and disabling push for source problem notifications.

### Out of scope

- Persisting problems and raising them from the sources: #1459.
- Filtering and interruption level: #1443.
- Collapse ids so a repeated push replaces the earlier one: #1829.

## Acceptance criteria

- When a problem is created, then exactly one `semp_problem` notification is written and pushed according to its severity and the user's preferences.
- When four sync failures of one mailbox occur, then one push is sent.
- When the same problem is raised again at the same severity, then nothing is written.
- When a problem's severity rises, then one new notification is written.
- When a `*_resolved` notification is written, then it is never pushed.
