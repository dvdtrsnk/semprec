## Context

Model tier rationale: One resolution function used by several readers plus a create-step change and a per-tenant backfill, on existing seams, but it changes a user-visible name chain and must never leave an event proposal without a name.

Today `runCreateStep` (`backend/services/semprec-transcribe/src/transcriptionTask.ts`) copies the upload's `X-Filename` into `Transcripts.name`, which is a user-owned property that nothing later changes. So a recording shows as `IMG_0042.m4a` everywhere that reads `name`: the generic views, Semp's `item.get`, search and the result label of Inbox cards. The event match (`transcription/transcriptEventMatch.ts`) proposes a new event named after the transcript, so an empty `name` would yield an event without a name. The pipeline's text templates live in `transcription/i18n/cs.json` and `en.json`.

This issue derives the title a user sees from one function, `resolveTranscriptDisplayName` in `transcription/`, in this order: the user-entered `name`; otherwise the name of the live linked event (follows a rename); otherwise the translated "Recording D. M. HH:MM" built from `date`, both while the transcript is processing and after it is done, and for an imported file the same as for a recording made in the app. The generated meeting-notes title (#1695) is not part of the chain: it is returned as `suggestedName`, a name Semp proposes that the app shows on the recording's card for the user to edit and confirm; confirming writes the user-owned `name` through the existing item update. The detail endpoint (#1576), the list endpoint (#1636), the Semp read tool (#1832) and the event match all call the function. The create step (#1624) stops copying the filename. The match proposes the event name "Meeting D. M." (#1818), never an empty name.

Decisions:
- By the product owner: a finished transcript without an event gets an AI-generated name only as a proposal (`suggestedName`); until the user confirms it, it is shown as "Recording D. M. HH:MM".
- By the product owner: there is no separate placeholder for processing or for imports (no "New recording", no "Dictaphone - import"); every recording without a name or event uses the one pattern "Recording D. M. HH:MM".
- `suggestedName` is the generated title when the transcript has no user-entered `name`, no live linked event and a non-empty generated title; otherwise `null`.
- `Files.name` keeps the filename; only `Transcripts.name` stops receiving it.
- The create step writes only `recording_requests.name` (when the intake set one), because the pipeline must not invent a user-owned field (single-writer ownership ADR).
- By the product owner: the Transcripts `name` may stay empty, because a transcript takes its title from its event or its recording date; the general rule that requires a non-empty title applies to the other collections and not to Transcripts.

Shared-file ordering: this issue also waits for #1817 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

Add `transcription/transcriptDisplayName.ts` exporting `resolveTranscriptDisplayName` implementing the chain above and `resolveTranscriptSuggestedName` implementing the `suggestedName` rule, with the i18n template `transcript.displayName.recorded` ("Nahrávka D. M. HH:MM" / "Recording D. M. HH:MM") in `transcription/i18n/cs.json` and `en.json`.
2. Use them in the detail and list endpoint projections (`displayName`, `suggestedName`) and expose `resolveTranscriptDisplayName` for the Semp read tool.
3. In the create step stop writing `name` from the filename; write `Transcripts.name` only from `recording_requests.name` when set.
4. In `matchTranscriptToEvent` build the proposed event name from the transcript's `name`, else the generated title, else the translated "Meeting D. M." fallback; assert it is non-empty.
5. Add a per-tenant cutover (registered in `db/tenantCutoverMigrations.ts`) that clears `Transcripts.name` where it equals the source file's `Files.name`; idempotent.
6. Tests: precedence of the chain including event rename; a processing transcript without name or event shows "Recording D. M. HH:MM"; a file `IMG_0042.m4a` without an event shows "Recording D. M. HH:MM" with the generated title as `suggestedName`, and `Files.name` is unchanged; after the user saves a name, `displayName` is that name and `suggestedName` is `null`; no event proposal has an empty name; backfill idempotency.

## Acceptance criteria

- When a transcript is linked to an event, then `displayName` is the event's current name, also after a rename; a name typed by the user wins.
- When a recording `IMG_0042.m4a` recorded on 14 Oct at 13:52 has no event and processing is done, then `displayName` is "Recording 14. 10. 13:52", `suggestedName` is the generated title and `Files.name` is still the filename.
- When the user saves the suggested (or an edited) name, then `displayName` is that name and `suggestedName` is `null`.
- When a recording without a name or event is still processing, imported or recorded in the app, then `displayName` is "Recording D. M. HH:MM".
- When the match proposes a new event, then its name is never empty.
- When the backfill runs, then transcripts whose name equals the filename have no name; a second run changes nothing.
