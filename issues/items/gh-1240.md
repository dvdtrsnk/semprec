## Context

Model tier rationale: One unit test file; the fix copies the pattern #1237 established for the module-manifest unit tests.

#1237 found that the module-manifest unit tests spend nearly all their time on the one-time cold import of each manifest's module graph, which under host load exceeds vitest's 5 s default. It moved that import into a `beforeAll` with an explicit, measured hook timeout. During its verification, `backend/packages/data/src/__tests__/systemDatabasesCatalog.unit.test.ts`, test "loads the Tasks database's cs/en catalog entries", hit the same 5 000 ms timeout under load: it imports the systemDatabases manifest (`loadModule`) inside the test body. That file was outside #1237's Touches.

## Task

Load `testing`.

1. Measure the test's phases as #1237 did, and report the before and after times in the pull request.
2. If the cost is the cold manifest import, warm it once in a `beforeAll` with an explicit hook timeout, sized from the measurement, and add a one-line comment naming the measured time and margin. This is the pattern in `moduleRegistryLoadAll.unit.test.ts` after #1237. Every test stays on the 5 s default, and no assertion changes.

## Touches

- backend/packages/data/src/__tests__/systemDatabasesCatalog.unit.test.ts

## Scope

### In scope

- This file's cold-import cost.

### Out of scope

- Other test files, the global vitest configuration, and production module-registry code.

## Acceptance criteria

- The pull request reports measured runtimes before and after.
- No test in the file runs longer than 1 s when run alone with `-t`.
