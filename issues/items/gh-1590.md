**Blocked by:** #1521
**Model tier:** medium

## Context

Model tier rationale: One transactional write across the item insert, edge insert and idempotency paths with existing fixtures, extended with an all-or-nothing contract that touches the shared create schema.

`item.create` accepts `{ databaseId, properties, idempotencyKey? }`, and `assertWritableProperties` in `backend/packages/data/src/chokePoint/itemWrites.ts` rejects any relation property key, because edges are written through `relation.put`. A client that saves a new item with its links (a file with its project, a task with its project and people, an event with its attendees) therefore has to create the item, then issue one `PUT` per edge. A failure in between leaves an item without its links, and an agent or MCP caller faces the same sequence of calls.

This issue lets `item.create` carry additive relations and writes the item and all edges in one transaction. It builds on #1521, whose single-valued handling it reuses. #1621 publishes the invalidations the edges produce; #1661, #1777, #1767 and #1724 use it.

Decisions:
- `relations` is additive: only the listed keys receive edges; nothing is removed or replaced on a new item.
- A single-valued relation key accepts exactly one target; two targets for it are a `400`.
- The `Idempotency-Key` covers the whole call: a replay returns the already created item and writes no further edges.

## Task

Load `state-writes`, `error-handling`, `io-hardening`, `canonical-keys` and `testing`.

1. Extend `ItemCreateInputSchema` with `relations?: { propertyKey: string, targetItemIds: string[] }[]` (strict, at most 10 entries, at most 50 targets per entry, no duplicate `propertyKey`). The REST body, the agent tool and the MCP tool all take it through the same schema; the REST route continues to read the `Idempotency-Key` header.
2. In the application service, resolve each `propertyKey` against the target database's properties to a relation property id (unknown key or non-relation property is `400 validation_failed` with `field: "relations"`).
3. Add a choke point entry point that runs, in one transaction: item insert (the existing `createItemWithClient`), then one `createRelationWithClient` call per edge with the new item as caller. Relation keys stay forbidden in `properties`. The checks of `createRelationWithClient` apply per edge: archived databases, endpoint validity, system-owner properties (`403 owner_violation`), edge hooks. Cardinality violations surface as `409 cardinality_violation`. Any failure rolls the whole call back; no item and no edge remains.
4. Idempotent replay: when `createItemWithClient` returns an already created row, no edge is written, and the existing item is returned unchanged.
5. Tests: a file created with `relations` for its project gets the item and the edge; an invalid target creates nothing; a system-owned relation key returns `403`; a second target for a single-valued key returns `400`; a replay with the same idempotency key creates no second item or edge; the agent and MCP tool schemas include `relations`.

## Scope

### In scope

- Additive `relations` on `item.create`, resolved and written in the same transaction as the item, for REST, agent and MCP callers.

### Out of scope

- Replacing or clearing a relation: #1521.
- Realtime invalidation for the created edges: #1621.
- Inherited relations derived from other items at create time: handled by the issues that need them (for example #1724 and #1777).
- Relation changes in `item.patch`.

## Acceptance criteria

- When a file is created with `relations` naming a project, then the item and its edge exist after one call.
- When any target is invalid, deleted, in an archived database, or violates cardinality, then no item and no edge are created and the matching error is returned.
- When a relation key appears in `properties`, then the call is rejected as before.
- When the key names a system-owned relation, then the call returns `403 owner_violation` and creates nothing.
- When the same `Idempotency-Key` is replayed, then the original item is returned and no further edge is written.
- When an agent calls the tool, then the schema accepts `relations`.
