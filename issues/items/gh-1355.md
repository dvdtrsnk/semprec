## Context

Model tier rationale: A tiny unauthenticated route returning a constant body, wired exactly like the existing health probe and registered in the route matrix; no data access, session or tenant logic.

When a user types a server address on the sign-in screen, the app cannot tell whether a Semprec server answers there. The public routes today (`GET /healthz`, login, password reset, `POST /api/setup`, the mail webhook; see `backend/services/semprec-api/src/routeMatrix.ts`) none says that Semprec runs at the address. `GET /healthz` only returns a status word and is a deployment probe, and the REST contract deliberately has no version (`docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`).

This issue adds a public identity route. The client calls it before login and shows a server-address error for any other answer. Nothing else depends on it.

Decision: the body carries only the product name, never a version, build, tenant or deployment detail, because the route is reachable without a session.

## Task

Load `io-hardening` and `testing`.

1. Add `GET /api/server-info` answering 200 `{ "product": "semprec" }` and nothing else. Implement it as a small listener beside `healthzHandler.ts` (for example `createServerInfoRequestListener` in a new `serverInfoHandler.ts`), with no `authenticateRequest`, no database access, and 404 for other methods on that path following the `healthzHandler.ts` pattern.
2. Dispatch it in `backend/services/semprec-api/src/app.ts` next to the `/healthz` branch in `dispatchTraced`.
3. Register it in `routeMatrix.ts`: name "server identity", `GET /api/server-info`, `surface: "api"`, `public: true`, `tenancy: "anonymous"`, with a `publicReason` stating that the client must be able to confirm a server address before it has a session and that the body is only the product name. Add its case to `__tests__/tenantIsolationRoutes.test.ts` (the response names nothing of tenant A) and map it in `ROUTE_HANDLER_FILES` of `__tests__/chokePointWriteBoundary.unit.test.ts`.
4. Add a handler test: 200 with exactly that body without a session, and 404 for `POST`.

## Scope

### In scope

- The public route, its dispatch, route-matrix registration and tests.

### Out of scope

- Any version, build, feature or tenant information in the body.
- Client behavior (calling the route before login, the address error).
- Changes to `GET /healthz`, login, or the reverse-proxy configuration (`/api/*` is already proxied).

## Acceptance criteria

- When `GET /api/server-info` is called without a session, then the response is 200 with the body `{"product":"semprec"}`.
- When it is called with another method, then the response is 404.
- The route needs no database connection to answer.
- The route matrix lists it as public and anonymous, and the route-matrix tests pass.
