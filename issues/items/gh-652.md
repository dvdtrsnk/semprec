## Behavior specification (approved)

None of the items in this batch is a runtime bug. They are the structural debts a later cross-cutting workspace/multi-tenant refactor (its own epic, with its own ADR) would otherwise have to touch blind: the `@typescript-eslint/no-unsafe-*` rules still switched off for the whole backend although the typed-row convention of `docs/adr/2026-09-10-typed-rows-at-the-postgres-boundary.md` is applied, thirteen copies of `sendJson` and seven of `readJsonBody` at the API edge, the generic choke point importing the mail and transcription domain folders, five import-boundary rules that match nothing because `backend/modules/` holds only a README, a handful of unchecked JSONB casts in `packages/data`, and an integration tier that runs 143 files serially for ~13 minutes and leaks its embedded Postgres directory whenever a run is interrupted. After this batch: `pnpm run lint` enforces `no-unsafe-*` on every production file; every bespoke `semprec-api` handler uses one HTTP helper module; `chokePoint/**` reaches mail and transcription only through a hook registry that a dependency-cruiser rule enforces; the `modules/` workspace entry and its dead rules are gone; JSONB-backed values are parsed, not cast; an interrupted test run tears its Postgres down and a stale `semprec-pg-*` directory is swept; the CI integration job runs as three shards behind the unchanged `integration` required check.

## Decisions

- Typed row reader (a `queryRows(client, zodSchema, sql)` wrapper) or the existing convention? → The convention: `client.query<…DbRow>` plus `requireSingleRow`, as `docs/adr/2026-09-10-typed-rows-at-the-postgres-boundary.md` already decided ("a convention over a wrapper"). → The ADR explicitly rejected a wrapper, the convention is already applied (0 `no-unsafe-*` findings in `chokePoint/`, 24 in the whole backend), and a second pattern would have to supersede an accepted ADR for no gain. The four-issue reader programme from the audit collapses into one issue that switches the rules on for production code and fixes the 24 findings.
- Switch `no-unsafe-*` on for test files too? → Not in this batch. → 245 findings in 46 test files, all test-only; the enablement is scoped to production files by an ignore list, and the test half is left for a batch of its own.
- Switch `require-await` back on? → Not in this batch. → 7 production findings, but the config comment records the deliberate reason (port implementations matching a Promise-returning interface); reversing that is a separate decision, not a lint chore.
- Where do the choke-point domain hooks get registered? → A per-process registry in `chokePoint/hooks.ts` populated by `packages/data/src/domainWriteHooks.ts`, which `packages/data/src/index.ts` imports for its side effect. → About sixty call sites across every domain call `createItemWithClient`/`updateItemWithClient`/`createRelationWithClient` directly with a client, so a registry threaded through `ChokePointDeps` would not reach them; every service imports the barrel, so the barrel is the composition point. Tests that import choke-point modules by deep path import `domainWriteHooks.js` explicitly.
- Does `modules/` remain a planned workspace? → No: the vertical slices live in `packages/data/src/<domain>/` with their `*ModuleManifest.ts`, and that is the architecture, not a transitional state. → Every module written since #29 landed there; the empty workspace entry and its rules only mislead readers and tools.
- One issue or two for the integration tier? → Two: the teardown/sweep is backend code, the sharding is a workflow change under a protected path and is maintainer-implemented. → A reviewer can approve either without the other; keeping them together would make the code half maintainer-only for no reason.
- Extra cross-epic edges beyond B7/B8? → `#639` on the HTTP helper issue (it edits `mcp/mcpHandler.ts`'s `resolveActor`, which calls the `extractBearerToken` the helper issue moves), and `#626` (transitively `#621`, `#624`) on the lint-enablement issue (they rewrite `anthropicProvider.ts`, where three of the 24 findings sit). → Both are real shared-file overlaps with issues that are eligible at the same time.

## Out of scope

- The workspace/multi-tenant refactor itself, any `workspace_id` column, per-user authorization.
- Enabling `no-unsafe-*` for test files, or `require-await` anywhere.
- Moving the scheduler heartbeat triggers, rollup recompute, view filter compilation, task time derivation or seed key imports out of `chokePoint/` — they stay direct imports.
- Unifying the bespoke handlers' `{ error, code, details }` shape with the adapter envelope; routing the bespoke listeners through `adapterRoute.ts`.
- Sharding the e2e tier; parallelising test files inside one shard.
