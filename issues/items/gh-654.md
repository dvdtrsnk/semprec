## Context

`backend/eslint.config.mjs` lines 18-36 switch off `@typescript-eslint/no-unsafe-assignment`, `no-unsafe-member-access`, `no-unsafe-argument`, `no-unsafe-return` (`no-unsafe-call` was never switched off) with a comment that `pg`'s `QueryResult.rows` is `any[]` and that the rules would report "the same known gap hundreds of times (233)" until a typed row layer exists. That layer exists: `docs/adr/2026-09-10-typed-rows-at-the-postgres-boundary.md` decided on the convention `client.query<…DbRow>(…)` plus `requireSingleRow` (`packages/data/src/db/pool.ts` line 70), and it is applied — 259 of the 424 `.query(` call sites carry a row type argument, the other 165 are writes, DDL and `BEGIN`/`COMMIT` that read no rows. A full backend lint with the four rules switched on (2026-09-27, `develop` HEAD `c395b22`) reports 24 findings in 9 production files, none of them a `pg` row, and 245 findings in 46 test files. Nothing today stops a new untyped boundary from being added; switching the rules on for production code is the regression guard the ADR anticipated ("`no-unsafe-*` can be switched back on per package as each one stops reporting the known gap").

The 24 findings, by mechanism:

- Six `fetch` body readers where `res.body?.getReader()` is typed `ReadableStreamDefaultReader<any>` by `@types/node`'s undici types, so `value` in `const { done, value } = await reader.read()` is `any` (three findings each: the destructuring, `.byteLength`, and the `decode`/`push` argument): `packages/data/src/mail/gmailPubSubClient.ts` lines 59-66, `packages/data/src/mail/graphSubscriptionClient.ts` lines 30-37, `packages/ai-gateway-client/src/httpAiGatewayClient.ts` lines 41-48, `services/semprec-ai-gateway/src/audioProviders/httpUtils.ts` lines 21-29, `services/semprec-ai-gateway/src/structuredProviders/anthropicProvider.ts` lines 45-52, `services/semprec-transcribe/src/audioGatewayClient.ts` lines 87-94.
- `packages/data/src/seed/seedInboxPipeline.ts` line 267: `Object.values(all)` on the `InboxPipelineDatabases` interface (no index signature) resolves to `any[]`, so `database.id` / `database.name` are `any` (four findings).
- `packages/shared/src/guidanceDrift.ts` line 139: `manifestFacts` is `any[]` after `Array.isArray` on an `unknown`, assigned to a `string[]` field.
- `packages/module-boundaries/src/index.ts` line 54: `JSON.parse(result.output)` assigned to `output: ICruiseResult`.

`#626` (with `#624` and `#621` before it) rewrites `anthropicProvider.ts`'s response reading; this issue is sequenced after it so the two edits to that file do not collide.

## Task

- In `backend/eslint.config.mjs`: delete the four `"@typescript-eslint/no-unsafe-*": "off"` lines and the `no-unsafe-*` paragraph of the comment above them (keep the `require-await` line and its paragraph; rewrite the comment's opening so it speaks of one family, not two). Add a config block placed after the `max-lines` block:
  ```js
  {
    // Test files still trip the no-unsafe-* family in ~245 places (fixtures, mocks, untyped
    // JSON); switching them on there is a separate batch. Production code is clean.
    files: ["**/*.test.ts", "**/__tests__/**", "**/testSupport/**"],
    rules: {
      "@typescript-eslint/no-unsafe-assignment": "off",
      "@typescript-eslint/no-unsafe-member-access": "off",
      "@typescript-eslint/no-unsafe-argument": "off",
      "@typescript-eslint/no-unsafe-return": "off",
    },
  },
  ```
  so the `recommendedTypeChecked` preset's `error` level applies to every other `.ts` file (`no-unsafe-call` was never switched off and stays on everywhere).
- Fix the 24 findings without a single `eslint-disable` comment and without adding an `as` cast:
  - The six body readers: annotate the reader at its declaration — `const reader: ReadableStreamDefaultReader<Uint8Array> | undefined = res.body?.getReader();` (assigning from `ReadableStreamDefaultReader<any>` needs no cast) — so `value` is `Uint8Array`. Behaviour, caps and error messages stay identical.
  - `seedInboxPipeline.ts` line 265: iterate `[all.inbox, all.inboxItemTypes, all.processingProposals]` instead of `Object.values(all)`.
  - `guidanceDrift.ts`: give the `every` callback a type predicate — `manifestFacts.every((fact): fact is string => typeof fact === "string" && fact.length > 0)` — and narrow `manifestFacts` through a `const` that TypeScript can type as `string[]` (e.g. `const facts: unknown[] = manifestFacts; if (!facts.every(isNonEmptyString)) throw …; return { …, manifestFacts: facts }` with `isNonEmptyString` a local predicate).
  - `module-boundaries/src/index.ts` line 54: declare `const parsed: unknown = typeof result.output === "string" ? JSON.parse(result.output) : result.output;` and narrow it with a local `isCruiseResult(value: unknown): value is ICruiseResult` predicate (an object whose `modules` is an array), throwing `new Error("dependency-cruiser returned an unexpected result shape")` otherwise.
- Tests: no new test file — `pnpm run lint` (the `ci` job's "Backend — lint" step) is the check. Every existing unit, integration and e2e test stays unchanged; the six reader edits and the seed edit are type-only.
