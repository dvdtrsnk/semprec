## Context

Model tier rationale: A mapping from the thread search to the shape another issue defines for grouped search results, with the registration seam supplied by the blocker, so the unknowns are small but not zero.

Global search shows results grouped by kind; the "Mail" group lists conversations such as "Re: Nabídka na web · Petr Novák · yesterday". #1842 adds the generic search operation with grouped results and the way a module contributes a group. #1639 provides the thread search this group is built from. Mail rows are the Emails items of the last message of each matching thread; the item shape of every group entry is: the item and database ids, the database key, a title, subtitle parts and a snippet.

Decision: results are grouped per thread (never one row per message); the representative item is the Emails item of the thread's last message; `total` counts threads.

## Task

Load `canonical-keys` and `testing`.

1. Contribute a `mail` group to the generic search operation using the contribution seam delivered by #1842, backed by the thread search of #1639 with the group's query text as `q` and the group's limit.
2. Each entry has: `itemId` and `databaseId` of the last message's Emails item, `databaseKey` of Emails, `title` the thread subject, `subtitleParts` `[{ kind: "sender", value: <name of lastSender>, itemId: <personId, when known> }, { kind: "date", value: <lastMessageAt> }]`, `snippet` the matching text fragment (or the preview when there is none), and `threadId`.
3. `total` is the number of matching threads.
4. Add tests: one thread with several matching messages appears once; the entry has the fields above; deleted mail is absent; another tenant's mail is absent.
