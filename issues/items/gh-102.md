**Blocked by:** #101

## Context

Hardcoded label comparisons cannot express stable processing behavior.

## Task

Add `processingMethod` with values `pageContent` and `database`, plus nullable relation `targetDatabase`. Require a target database exactly for `database` and clear/reject it for `pageContent`. Archived types disappear from `GET /api/inbox-types` but remain valid references for existing items. Deleting a referenced type must route affected unlocked Inbox items through the same unknown-type processing path as a missing type; do not leave a dereferenced special case. Runtime target-project/page choice remains content-driven, not stored on the type.

## Scope

### In scope

- Type validation, active picker behavior, archive, delete, and unknown-type semantics.

### Out of scope

- LLM prompt engineering and target-selection implementation.

## Acceptance criteria

- Invalid method/target combinations fail validation.
- Archived types are absent from new capture but old relations remain readable.
- Deleted references deterministically enter clarification processing.
- Type decisions use id and method, never localized label text.
