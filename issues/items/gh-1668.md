## Context

Model tier rationale: A schema option change plus one transform rule across the existing cutover and write-transform seams, with defined fixtures, but it depends on the transform's ownership checks working as the choke-point issue defines them.

Task status is a select with the options `notDone`, `done` and `wontDo` (seeded in `backend/packages/data/src/seed/seedTenDatabases.ts`, labels in `backend/packages/data/src/seed/i18n/cs.json` and `en.json`; Czech `notDone` is "Nesplněno", `wontDo` is "Nebude splněno"). There is no state for an occurrence that was skipped because the next one came. The status property is owned by `user`, so a background process cannot write a new value without an ownership handover (`docs/adr/2026-09-10-single-writer-ownership-model.md`).

The recurrence model is #1365 and the series data is #1605; the Tasks schema cutover is #1540; the per-module pre-write transform is #1422. This issue adds the `missed` status option, renames the label of `notDone`, and enforces who may write `missed`. The nightly job that writes it for stale occurrences is #1677; the projection that reports it for virtual days is #1672.

Decision: the missed state is stored, written by the nightly job (#1677) in line with the day rollover rule, and readers (the timeline in #1884 and #1886) show the stored value without computing it; there is no read-model computation of missed. The labels: `missed` is "Nesplněno" in Czech and "Missed" in English; `notDone` becomes "Nehotovo" in Czech and "Open" in English.

Shared-file ordering: this issue also waits for #1664 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `state-writes`, `canonical-keys` and `testing`. Follow the pattern of `backend/packages/data/src/transcription/transcriptsCatalogCutoverMigration.ts`.

1. Add the option `missed` to the Tasks `status` select in the seed (`seedTenDatabases.ts`) and in `seed/i18n/cs.json` and `en.json` (`property.tasks.status.option.missed`), and change the `notDone` labels as in the Context.
2. Add a per-tenant cutover that adds the `missed` option to the existing Tasks `status` property `config.options` with `jsonb_set`, idempotently (no duplicate option on a second run), and register it in `runTenantCutoverMigrations`. Bump the Tasks schema version only as #1540 defines.
3. In the Tasks transform of #1422: a user-origin write with `status: "missed"` is rejected with a 400 validation error; a write by the Tasks module itself or by the nightly job's process is allowed; a user write that changes status from `missed` to `done` is allowed (sets completion as for any `done`).
4. In the same transform: when an occurrence that has a `seriesId` is changed from `done` to `notDone`, and the next occurrence by the rule after its `occurrenceDate` is on or before today, the stored status becomes `missed` and `completedOn` is cleared. The next date is computed with the existing rule helpers in `nextDueDate.ts`, using the occurrence date as the reference.
5. Tests: the cutover is idempotent; user PATCH `missed` returns 400; `missed` to `done` works; done to notDone of an old daily occurrence yields `missed`, of today's occurrence yields `notDone`.

### Out of scope

## Acceptance criteria

- After the cutover the Tasks status select offers `missed` once, and running it again changes nothing.
- A client PATCH with `status: "missed"` returns 400; `missed` to `done` is accepted.
- Changing a done daily occurrence dated 13 October back to `notDone` on 16 October stores `missed` with `completedOn` empty; doing so for the 16 October occurrence stores `notDone`.
- The Czech label of `notDone` is "Nehotovo" and of `missed` is "Nesplněno"; the English labels are "Open" and "Missed".
