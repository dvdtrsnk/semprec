## Context

Model tier rationale: The new signatures, tenant checks and three wiring points are specified exactly in one registry.

`agent:watch` subscribes a socket to one agent run's durable events and ephemeral typing deltas, through the process-wide `createAgentRunWatchRegistry` (`backend/packages/realtime/src/agentRunWatch.ts:47-246`). Its parts today:
- **Authorization.** `watch` reads the run with `getAgentRun(pool, runId)` (`:139`). It registers a watcher only when `run.actorUserId === userId` (`:144`); an unknown run and a foreign run are already indistinguishable (`:132-136`).
- **Replay.** It replays `listAgentRunEventsAfter` (`:169`) and drains queued ids through `getAgentRunEventById` (`:182`).
- **Live events.** `forwardEvent(runId, eventId)` (`:218-233`) fetches the row once and delivers it to every live watcher of `runId`.
- **Deltas.** `forwardDelta(message)` (`:235-244`) sends to every watcher of `message.agentRunId`.

Watchers are keyed by run id only (`watchersByRun`, `:48`). Neither the watch path nor delivery knows a tenant. `syncServer.ts` calls `watch(ws, identity.userId, frame.runId, frame.afterEventId)` (`backend/packages/realtime/src/syncServer.ts:172-176`) outside any tenant scope.

What earlier issues provide:
- RLS hides other tenants' `agent_runs` and `agent_run_events` rows once `app.tenant_id` is set. It is set by `runInTenant(tenantId, fn)` from `@semprec/shared`.
- #1025 gave every socket `SyncIdentity.tenantId`. It delivers `agent_run_event` and `agent_run_delta` messages as envelopes `{ tenantId, message }`, with the tenant computed by Postgres from the publisher's scope. It handles each envelope inside `runInTenant(envelope.tenantId, …)`, and its ADR (`docs/adr/<date>-tenant-scoped-realtime-fan-out.md`) records that `agent:watch` resolves inside the socket's tenant, narrowing `docs/adr/2026-09-12-per-process-agent-run-watch-registry.md`'s "setup-account owner" check. No new ADR is needed.
- #1026 established the same pattern for doc sync in the same files.
- #1018 set every run's `actor_user_id`, heartbeat and system runs included, to the tenant's own user (`getTenantUserId`). The kept `actorUserId` check therefore authorizes the tenant's user for every run in the tenant.

## Task

Load `io-hardening` (frames and NOTIFY references are untrusted boundary input).

1. **Tenant on the watcher.** `Watcher` (`agentRunWatch.ts:8-14`) gains `tenantId`. Change the interface (`:22-28`) to:
   - `watch(ws, tenantId, userId, runId, afterEventId)`
   - `forwardEvent(tenantId, runId, eventId)`
   - `forwardDelta(tenantId, message)`
2. **Authorize in the socket's tenant.** `watch` runs `getAgentRun`, `listAgentRunEventsAfter` and `getAgentRunEventById` inside `runInTenant(tenantId, …)`. A watcher is registered only when the run is visible in that tenant and `run.actorUserId === userId`. A foreign run, an unknown run and a run of another user all take the same silent path (`:144-147`): no frame, no log line naming the reason, and the pending intent is finished.
3. **Deliver only within the tenant.**
   - `forwardEvent` fetches the row inside `runInTenant(tenantId, …)` and delivers it only to watchers whose `tenantId` matches.
   - `forwardDelta` sends only to watchers whose `tenantId` matches. A message stamped with another tenant reaches nobody, even if it names a watched run id.
   - A replaying watcher queues an event id only from a message of its own tenant.
4. **Wire it in `syncServer.ts`.**
   - The `agent:watch` case passes `identity.tenantId`.
   - `enqueueAgentEvent` (`:280-296`) carries `envelope.tenantId` into `forwardEvent`.
   - The agent stream handler (`:301-311`) passes `envelope.tenantId` to `forwardDelta`.
5. **Tests.** Update `syncServer.test.ts`'s watched-runs block (`:842-1106`):
   - The heartbeat "earliest account" case at `:1009` becomes "the tenant's user".
   - Add the criteria below using the two-tenant runtime-role harness of #975 (`createTestTenant`, `createRuntimeRolePool`, `getTenantZeroId` from `@semprec/data/testSupport`). The superuser test pool bypasses RLS.

## Scope

### In scope

### Out of scope

- Doc sync (#1026).

- The Origin check on the upgrade (#1044).

- Replacing the `agent_run_events.id` cursor with an opaque one; it stays as is.

## Acceptance criteria

- **Foreign run ≡ unknown run.** When a tenant-B socket sends `agent:watch` for a tenant-A run, it receives no `agent:event` replay. When that run later emits durable events and deltas, the socket receives nothing. The behaviour is byte-for-byte the same as for a random run id. (integration, `syncServer.test.ts`, runtime-role harness)
- **Own runs still watched.** A tenant-A socket of the tenant's user watching its own run, heartbeat-triggered runs included, receives the replay, then live `agent:event` frames and `agent:delta` frames in order. (integration, `syncServer.test.ts`)
- **Forged durable reference.** With a tenant-A socket watching run R, a raw `pg_notify` of an `agent_run_event` envelope stamped with tenant B for run R and a real event id of R delivers nothing. (integration, `syncServer.test.ts`)
- **Forged delta.** The same socket receives nothing from an `agent_run_delta` envelope stamped with tenant B. (integration, `syncServer.test.ts`)
- **Replay handoff kept.** The existing tests still pass:
  - replay/live handoff (`:895`);
  - unwatch during pending authorization (`:961`);
  - a replacement watch that fails to authorize keeps the live watcher (`:1031`);
  - a failed replay keeps the existing watcher (`:1054`).
