## Context

Model tier rationale: One decoding table at the data boundary, a result type on nine mail ports and a mapped state field on three ViewModels, mirrored in CoreKit and the Mail feature's copy; no new module, route or screen.

The backend refuses mail writes with specific codes in an error document nested under `error` (`{ "error": { "code": "…", "details": { … } } }`), listed in `backend/services/semprec-api/src/adapter/errorContract.ts` and thrown in `backend/packages/data/src/mail/`:

- drafting (`POST /api/mail/drafts`, `PATCH /api/mail/drafts/:id`): 409 `mail_drafts_folder_missing` (the mailbox's server has no Drafts folder; `issues/handovers/sp-01cb2670-f7d1-4013-ba52-8bf7d1bfaaf1.md`), 409 `mail_draft_already_sent`, 409 `mail_draft_not_editable`, 413 `mail_attachment_too_large`;
- sending (`POST /api/mail/drafts/:id/send`): 409 `mail_sent_folder_missing`, 409 `mail_reauthorization_required`, 409 `mail_disabled`, 422 `mail_recipient_rejected`, 400 `mail_auth_failed`, 400 `mail_server_unreachable`;
- thread read and flag (`POST /api/mail/threads/:id/read`, `/flag`): 409 `mail_thread_no_received_message`;
- thread moves (`/archive`, `/trash`, `/restore`): 409 `mail_archive_folder_missing`, `mail_trash_folder_missing`, `mail_inbox_folder_missing`, `mail_sent_folder_missing` (a restored own copy), `mail_move_source_unverified`, `mail_thread_already_trashed`, `mail_thread_not_archived_or_trashed`.

The mobile app reads none of these. `HttpMailDraftRepository` and `HttpMailRepository` turn every error answer into a bare `FailureKind`, so the compose screen says "The server refused the message. Check the recipients and the account." for a mailbox without Drafts, the thread screen shows "The change could not be made. Try again." for every refused flag or move, and a reply in such a mailbox fails to open with a generic error. The Internet accounts flow already decodes codes at the boundary: `HttpMailboxRepository.connectOutcome()` reads `error.code` (or a flat `code`) into `MailConnectRefusal`, answered as content `MailConnectOutcome.Refused`, which `PasswordSignInFlow` maps to the presentation enum `InternetConnectFailure` that Swift renders. Android has no mail screens.

The agent-tool codes (`mail_agent_draft_exists`, `mail_draft_edited_by_user`) and the transport classes' own codes (`mail_send_auth_failed`, `mail_transport_unavailable`) never reach a person's REST call and are not mapped.

## Task

Load `kmp-shared`, `shared-viewmodel`, `apple-swiftui`, `canonical-keys`, `testing` and `mobile-verify`.

1. Domain: an enum `MailRefusal` with one case per code above (the three move-target folders, Drafts and Sent each their own case) and `MailOutcome<T>` (`Done(value)` or `Refused(refusal)`). `MailDraftRepository.create`, `createPrefilled`, `update`, `send` and `MailRepository.setRead`, `setFlagged`, `archive`, `trash`, `restore` answer `RepositoryResult<MailOutcome<T>>`.
2. Data: one table from wire code to `MailRefusal`, applied to those calls' error answers; an error document's code is read from `error.code` or a flat `code` by one shared decoder (the one `HttpMailboxRepository` has, moved, not copied). An unknown code, a missing or unreadable body stays its `FailureKind`.
3. Presentation: an exported enum `MailRefusalReason` mirroring `MailRefusal`. `MailComposeState` gains `refusal` (a reply or forward whose draft could not be made) and `sendRefusal`; `MailThreadState` gains `sendRefusal` and `actionRefusal` (a flag or move); `MailThreadsState` gains `actionRefusal` (a read mark). A refusal sets the failure it stands for as `FailureKind.REJECTED` alongside, and a later attempt or dismissal clears it with the failure.
4. Apple: CoreKit mirrors the enum and the fields through the bridges; the Mail feature shows `mail.refusal.<case>` instead of the generic text in the compose error, the compose and Semp draft send failures and the action alerts of the thread and thread list. Every key in `en` and `cs` and listed in the policy.

## Scope

### In scope

- Decoding the listed codes, carrying them to the three mail ViewModels and showing a specific message for each on Apple.

### Out of scope

- Backend changes; web; Android (no mail screens).
- Acting on a refusal (opening Internet accounts, retrying a sync) or reading `details`.
- `version_conflict` on a draft update, the task creation and the agent-tool codes.

## Acceptance criteria

- Each listed code, in the nested `error` document, decodes to its `MailRefusal` on the call that can receive it; a flat `code` decodes too; an unknown code and an unreadable body stay a `FailureKind`.
- A new message in a mailbox without Drafts shows "drafts folder missing" text on send; a reply there shows it as the screen's error; a send without Sent shows the Sent text; a refused flag or move shows its own text in the thread's alert; a refused unread mark in the list shows its text.
- A retried send or a dismissed alert clears the refusal.
- Every `mail.refusal.*` key has `en` and `cs` text.
