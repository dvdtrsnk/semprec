## Context

Model tier rationale: Three new filters on an existing list query with join paths over the relation tables, needing partition-aware lookups and the existing list fixtures but no new contract.

The mail thread list `GET /api/mail/threads` (#1633 adds box, folder, mailbox and unread filters) cannot yet narrow by project, area or person. After #1573 a thread is an item with the relation Threads.project; a project belongs to an area through `Projects.area`; and a person is linked to messages through `Emails.senderPeople` and `Emails.recipientsPeople` (a person may be sender of many emails after #1457). Mail belongs to a project only when the thread has a project edge, and to an area only through that project.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. Add the optional query parameters `projectId`, `areaId` and `personId` (uuid; a malformed value is a validation error) to `GET /api/mail/threads`.
2. `projectId`: threads that have a Threads.project edge to that project. `areaId`: threads whose Threads.project target has `Projects.area` equal to that area (one hop through the project; a thread without a project never matches). `personId`: threads that have at least one not-deleted message whose `senderPeople` or `recipientsPeople` edge points at that person.
3. The filters combine with AND with each other and with the filters of #1633.
4. Pin `database_id` in every item and relation lookup, using the lateral subquery shape described in `backend/packages/data/src/scheduler/itemRelationFilter.ts`, so partition pruning works.

## Touches

## Scope

### In scope

- The three filters, their validation and combination.

### Out of scope

- Counts per area and project (#1747); the Souvislosti counts (#1874).
- Giving a thread its project or company (#1573, #1869).

## Acceptance criteria

- `areaId` of an area returns only threads whose project is in that area and never a thread without a project.
- `projectId` returns only threads with that project.
- `personId` of a person returns the thread that contains a message from or to them, once, however many messages match.
- Combining `areaId` with the unread filter returns the intersection; a malformed id returns a validation error.
