**Blocked by:** #1034, #1064, #1063
**Model tier:** high

## Context

Model tier rationale: A host sandbox launcher combines dedicated UID, socket transport, systemd and nftables in one lifecycle.

A `stdio` MCP server today is a child of the service that connects to it. `buildStdioTransport` (`backend/packages/data/src/mcp/mcpConnectionFactory.ts:177-203`) hands `command`/`args`/`env` to the SDK's `StdioClientTransport`, which `spawn`s it with the parent's uid (`@modelcontextprotocol/sdk` 1.30 `dist/esm/client/stdio.js`, `start()`). Two processes do this:
- semprec-api, through `syncMcpServerTools` (`backend/packages/data/src/mcp/mcpSync.ts:132`) and approval replays (`backend/packages/data/src/worker.ts:40-42`);
- semprec-agents, through `backend/packages/agent-runtime/src/mcpInvokeTool.ts:161,240`.

Running as uid `semprec`, the child can:
- read its parent's `/proc/<pid>/environ`, which holds the `semprec_data` URL and `CREDENTIALS_MASTER_KEY`;
- read `/opt/semprec/shared/apns-key.p8` and every tenant's blobs under `/opt/semprec/data`;
- reach Postgres on loopback, which #1063 deliberately allows for that uid.

#1030 and #1033 confine stdio to a human in an admin's tenant, re-check that at spawn, and give the child an allowlisted environment. #1034 last edited this file. This issue moves the process itself out of the service's uid, filesystem and network reach. #1071 then hardens the api and agents units; they only need to connect to a UNIX socket for this, so they can keep `NoNewPrivileges=`.

## Task

Load `io-hardening` (a new socket edge and child-process lifecycle), `error-handling` (fail-closed refusal, cleanup on a failed connect) and `adr-conventions`.

1. **Sandbox user.** `deploy/provision.sh` creates system user `semprec-mcp`:
   - own group, home `/var/lib/semprec-mcp`, shell `/usr/sbin/nologin`, not a member of `semprec`;
   - created idempotently next to `ensure_service_user` and before `apply_nftables`;
   - add `jq` to `install_host_packages` (`:90-101`).
2. **Launcher.** Add `deploy/bin/semprec-mcp-launch` (bash). `provision.sh` installs it to `/usr/local/libexec/semprec-mcp-launch` (`root:root 0755`). stdin/stdout are one accepted connection:
   - **Header.** Read exactly one header line (at most 65536 bytes, never a byte past its `\n`, e.g. `read -r -n 65536`). The header is the JSON `{"command": string, "args": string[], "env": {NAME: string}}`.
   - **Validation** with `jq`:
     - no other fields;
     - `command` is non-empty and contains no NUL and no `=`;
     - no string contains NUL;
     - every env name matches `^[A-Za-z_][A-Za-z0-9_]*$`.
   - **Refusal.**
     - It refuses unless `id -un` prints `semprec-mcp`.
     - On an invalid or oversized header, a missing newline or a wrong uid: exit 64 and execute nothing.
     - The stderr message never contains the header, which may hold a credential.
   - **Exec.** Otherwise `exec` `command` with `args` as separate argv entries and working directory `/var/lib/semprec-mcp`. The environment is exactly:
     - `PATH=/usr/local/bin:/usr/bin:/bin`, `HOME=/var/lib/semprec-mcp`, `LANG=C.UTF-8`, `USER=semprec-mcp`, `LOGNAME=semprec-mcp`;
     - overridden by the header's `env`.

     The bytes after the header reach the server's stdin unchanged.
3. **systemd.**
   - `deploy/systemd/semprec-mcp-launch.socket`: `ListenStream=/run/semprec-mcp-launch.sock`, `SocketUser=root`, `SocketGroup=semprec`, `SocketMode=0660`, `Accept=yes`, `MaxConnections=16`, `WantedBy=sockets.target`.
   - `deploy/systemd/semprec-mcp-launch@.service`:
     - identity and I/O: `User=`/`Group=semprec-mcp`, `StandardInput=socket`, `StandardOutput=socket`, `StandardError=journal`, `SyslogIdentifier=semprec-mcp-launch`, `ExecStart=/usr/local/libexec/semprec-mcp-launch`;
     - state and limits: `StateDirectory=semprec-mcp` (mode `0700`), `WorkingDirectory=/var/lib/semprec-mcp`, `RuntimeMaxSec=300`, `MemoryMax=1G`, `TasksMax=64`, `UMask=0077`;
     - sandboxing: `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `PrivateDevices=yes`, `ProtectKernelTunables=yes`, `ProtectKernelModules=yes`, `ProtectKernelLogs=yes`, `ProtectControlGroups=yes`, `ProtectClock=yes`, `ProtectHostname=yes`, `ProtectProc=invisible`, `RestrictNamespaces=yes`, `RestrictRealtime=yes`, `RestrictSUIDSGID=yes`, `LockPersonality=yes`, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6`, `CapabilityBoundingSet=`;
     - `InaccessiblePaths=-/opt/semprec/shared -/opt/semprec/data -/var/backups/semprec -/etc/caddy`;
     - no `MemoryDenyWriteExecute=`: Node-based servers JIT.
   - `provision.sh`:
     - installs and verifies both units with the others (`install_systemd_units`, `verify_systemd_units`, `:213-241`; the template the same way as `semprec-failping@.service`);
     - runs `systemctl enable --now semprec-mcp-launch.socket`.
   - `semprec-api.service` and `semprec-agents.service` gain:
     - `Wants=` and `After=semprec-mcp-launch.socket`;
     - `Environment=SEMPREC_MCP_LAUNCH_SOCKET=/run/semprec-mcp-launch.sock`.
4. **Egress.** In `deploy/nftables.conf`, the `output` chain also jumps `meta skuid "semprec-mcp"` to a new `semprec_mcp_egress` chain:
   - established/related accept;
   - port 53 accept;
   - everything in `semprec_blocked_v4`/`semprec_blocked_v6`, including all of `127.0.0.0/8` and `::1` (no Postgres or gateway exception), logged with prefix `semprec-mcp-egress-deny ` (at most 10 per minute) and rejected `admin-prohibited`.
5. **Client transport.** Add `backend/packages/data/src/mcp/sandboxedStdioTransport.ts`: `SandboxedStdioClientTransport implements Transport` (`@modelcontextprotocol/sdk/shared/transport.js`), built from `(socketPath, { command, args, env })`.
   - `start()`:
     - connects with `net.createConnection(socketPath)`;
     - writes the header as one JSON line;
     - then drops its reference to the header;
     - rejects if the connection fails.
   - Framing uses `ReadBuffer`/`serializeMessage` from `@modelcontextprotocol/sdk/shared/stdio.js`.
   - `close()` ends the socket, waits at most 2 s for it to close, then destroys it. `onclose` fires exactly once.
6. **Factory.** In `mcpConnectionFactory.ts`, for `transport: "stdio"`, keep #1033's spawn-time check first, then:
   - **Socket set:** if `SEMPREC_MCP_LAUNCH_SOCKET` is non-empty, use `SandboxedStdioClientTransport`. The header `env` carries only `config.env` plus the decrypted credential under `credentialEnvVar`, never anything from `process.env`.
   - **Test mode:** else if `NODE_ENV === "test"`, keep the in-process spawn.
   - **Otherwise:** throw `McpConnectionError("stdio_sandbox_unavailable", …)` before `resolveCredential`, so nothing is decrypted or spawned. Add the reason to `MCP_CONNECTION_ERROR_REASONS` (`backend/packages/data/src/mcp/mcpConnectionError.ts:10-17`).

   A failed connect still maps to `handshake_failed` after closing the transport (`:68-73`).
7. **Docs and ADR.**
   - `deploy/README.md` gets a "stdio MCP sandbox" section, appended directly after "Host firewall (nftables)" (the file's last section), so it does not touch the backup and restore-test sections #1064 and #1078 edit. It covers: the user, socket, unit, egress rules, and a host check:
     - `ps -o user= -p <server pid>` is `semprec-mcp`;
     - `sudo -u semprec-mcp cat /opt/semprec/shared/apns-key.p8` and `sudo -u semprec-mcp timeout 5 bash -c '</dev/tcp/127.0.0.1/5432'` fail.
   - Add `docs/adr/<YYYY-MM-DD>-stdio-mcp-servers-run-in-a-socket-activated-sandbox.md`. Rejected alternatives:
     - `sudo` to a second uid: setuid forbids `NoNewPrivileges=` on the api and agents;
     - bubblewrap: same uid, so nftables cannot tell the child apart;
     - spawning as `semprec`: today's leak.

## Scope

### In scope
- The sandbox user, launcher, socket-activated unit, egress chain, client transport, fail-closed factory branch, tests, README and ADR.

### Out of scope
- Who may configure or spawn a stdio server (#1030, #1033); remote-transport address checks (#1034).
- Sandboxing directives on the api, agents, transcribe and gateway units (#1071).
- Per-tenant isolation between two stdio servers. Only an admin's tenant can run them.
- Changing `sse`/`http` transports.

## Acceptance criteria

- The launcher, run with `id` mocked to `semprec-mcp` and a header piped on stdin (shell test, `deploy/bin/semprec-mcp-launch.test.sh`):
  - execs the command with exactly the base environment overlaid by the header's `env`;
  - passes args containing spaces and quotes unchanged;
  - delivers the bytes after the header to the command's stdin byte-for-byte.
- With a wrong uid, non-JSON, an extra field, a NUL, an invalid env name, `=` in `command`, no newline or more than 65536 bytes, the launcher exits 64, runs nothing, and its stderr does not contain the header's values (shell test, same file).
- `provision.sh` (shell test, `deploy/provision.test.sh`):
  - creates `semprec-mcp` once across reruns, before the `nft -c` check;
  - installs `jq`, the launcher (`0755`) and both units;
  - enables `semprec-mcp-launch.socket`;
  - adds the socket's `Environment=`, `Wants=` and `After=` lines to the api and agents units;
  - writes a `semprec-mcp` chain into `nftables.conf` with no loopback port exception.
- With `SEMPREC_MCP_LAUNCH_SOCKET` pointing at an in-test fake launcher (a UNIX-socket server that reads the header line and spawns the command with it), `connectMcpServer` completes the stdio contract server's handshake, and the server observes the credential (integration, `sandboxedStdioTransport.test.ts`). In the same test:
  - the received header's `env` has exactly the configured env plus the credential, and lacks a sentinel variable set in the test process;
  - `safeStringify(handle.client)` does not contain the credential;
  - `handle.close()` gives the child EOF and it exits.
- When the socket path does not exist, or the fake launcher closes without answering, `connectMcpServer` rejects with `McpConnectionError` `handshake_failed` and leaves no open socket (integration, same file).
- With `NODE_ENV=production` and `SEMPREC_MCP_LAUNCH_SOCKET` unset, a stdio connect rejects with `stdio_sandbox_unavailable`. No `credential_access_log` row is written and no process is spawned. `sse`/`http` connects are unaffected (integration, same file).
- With `NODE_ENV=test` and no socket, the existing stdio tests in `mcpConnectionFactory.test.ts` pass unchanged (integration).
- On a provisioned host, the README host check shows the server running as `semprec-mcp` and unable to read `/opt/semprec/shared` or reach `127.0.0.1:5432` (manual host check by the maintainer).
