## Context

Model tier rationale: A new ref kind plugged into the generic message-ref validation and the turn-context expansion of the Semp chat, reusing the segment reading of the transcript tools; the surface is small, but it depends on two contracts (ref validation hooks and turn expansion) owned elsewhere, so the integration seams are the risk.

A user can drag the Semp bubble onto a stretch of a transcript to give it to Semp as context, and Semp receives a reference, not text. A message ref is stored with the message (validated and stored by #1682); this issue defines everything specific to a transcript segment ref `{ kind: "transcriptSegment", itemId, startsAt, endsAt }`, where `itemId` is a Transcripts item and `startsAt` and `endsAt` are seconds on the recording's timeline. It builds on the read tools of #1832, whose segment reading (names, bounded ranges, surrounding segments) it reuses.

Three things are specific to this kind: validating that the ref points at a transcript and a sensible range, expanding it into the text given to the model when a turn is prepared, and giving it a label and a state for the message history. The generic validation checks that the item exists in the tenant and that the pair item/database matches; the history shows a trashed transcript as recoverable and a purged one as gone; both are generic behaviors of the ref machinery and apply here unchanged.

Decisions:

- Validation is per kind: the item must be a live item of the Transcripts database of the tenant; `0 <= startsAt <= endsAt`; the range must not exceed the limit of `transcript.segment.get` (200 segments or 15 minutes). A range reaching past the end of the recording is accepted and clamped when expanded.
- Expansion gives the model the segments of the range with the speakers' names plus three segments of context on each side, using the same function as `transcript.segment.get`; the stored message keeps only the ref (with its label), never the expanded text. The text is never logged.
- The label of the ref is the transcript's display name with the time range (for example "Client meeting 5:12-6:30"); the history resolves it from the current name, so a renamed transcript shows its new name.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add `backend/packages/data/src/transcription/transcriptSegmentRef.ts` exporting `validateTranscriptSegmentRef`, `expandTranscriptSegmentRef` and `labelTranscriptSegmentRef`. The expansion calls the segment reading shared with #1832 (extract it into one function if it is not yet reusable) and returns the structured block the turn builder puts into the model's context.
2. Register the kind with the ref validation, label and state resolution of #1682 and with the step that expands refs when a Semp turn is prepared, using the per-kind hooks those provide; if they offer no per-kind hook, add the smallest one there and register this kind through it. Trashed and purged states are reported by the generic machinery (a trashed transcript is "in recently deleted", a purged one "no longer exists").
3. The validation error for a bad ref is the generic one for the message route, with the offending index of the ref (`context[i]`).
4. Tests in `backend/packages/data/src/transcription/__tests__/transcriptSegmentRef.test.ts`: a valid ref; a ref to an item that is not a transcript, to another tenant's transcript, to a trashed transcript (valid but reported as trashed in history), an inverted range, an over-limit range; expansion returns names and context; the expanded text is absent from the stored message and from logs; a renamed transcript changes the label.

## Scope

### In scope

- Validation, label and expansion of the `transcriptSegment` ref kind.

### Out of scope

- The generic ref schema, the limit of 20 refs, duplicates merging, tenant checks of the item and the stored `context` of a message: #1682.
- Resolving labels and states in thread history for all kinds: the generic machinery.
- The read tools themselves: #1832.
- Refs to a whole recording (an item ref).

## Acceptance criteria

- When a message carries a segment ref to a stretch of a transcript, the model's context for that turn contains the segments of the stretch and three on each side, with speaker names; the stored message contains only the ref.
- A ref to an item that is not a transcript, to another tenant's item, or with an inverted or over-limit range is rejected with `400` naming the ref's index, and nothing is stored.
- A ref to a transcript in the trash is accepted and shown as recoverable in history; after the transcript is purged, as no longer existing.
- Renaming the transcript changes the ref's label in history.
