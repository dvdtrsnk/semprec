## Context
Review of pull request #459 found that `backend/packages/data/src/transcription/transcriptsCatalogCutoverMigration.ts` (currently around lines 39-41) contains `if (ownerProcessUpdate.rowCount === 0) { // Intentionally no-op. }` — an empty conditional block with no action in either branch.

The block was added in commit 257d4b8, which bound the result of the `owner_process` `UPDATE` to `const ownerProcessUpdate` and added the empty `rowCount` check to satisfy the `rowCount` rule in `backend/review-rules/rules.md` ("A targeted `DELETE`/`UPDATE` ... must check how many rows it actually affected"). That rule covers targeted writes; this `UPDATE` is a bulk, idempotent backfill over up to three properties (`key = ANY($3::text[])` with `owner_process IS DISTINCT FROM $2`), where zero affected rows is a legitimate outcome once every field already names the process. Deleting the block alone would leave `ownerProcessUpdate` unused, which fails `noUnusedLocals` (`backend/tsconfig.json`) and `@typescript-eslint/no-unused-vars`, and without an explanation the review bot is likely to raise the `rowCount` finding again.

## Task
- Remove the empty `if (ownerProcessUpdate.rowCount === 0) { // Intentionally no-op. }` block in `backend/packages/data/src/transcription/transcriptsCatalogCutoverMigration.ts`, since it has no effect.
- Drop the now-unused `const ownerProcessUpdate =` binding, so the `owner_process` `UPDATE` becomes a plain `await client.query(...)`.
- Replace the existing comment above the removed block (`// Zero is the expected idempotent outcome ...`) with a one-line comment stating that this is a bulk, idempotent `UPDATE` rather than a targeted one, where zero affected rows is a legitimate outcome, so `rowCount` is deliberately not checked.
