## Context

Model tier rationale: One in-memory throttle extension following an existing documented pattern, applied to one route, with defined tests.

The route that creates a password mailbox (#1736) opens connections to hosts the user chooses and tries a password there. Without a limit it could be used to test passwords against third-party servers. The repository already throttles its public authentication routes per client address: `backend/services/semprec-api/src/clientIpThrottle.ts` keeps a sliding window in process memory and the routes answer 429 `rate_limited` with a `Retry-After` header (`docs/adr/2026-10-17-per-ip-auth-throttles-held-in-process.md`). That throttle keys on the client address; this route is authenticated, so the key here is the user.

Decision: at most 10 attempts per 15 minutes per user; every attempt that reaches the network check counts, successful or not, while a request rejected for an invalid body is released and does not count. The state stays in process memory under the single-process assumption of the existing ADR.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Extend `clientIpThrottle.ts` with an action `mailboxCredentialVerification` limited to 10 events per 900 seconds, keyed by user id (a generic key is accepted for it instead of the IP grouping function), reusing the existing `tryAcquire` and release behavior.
2. In the create route of #1736, reserve a slot after body validation and before calling the verification; on refusal answer 429 with code `rate_limited` and a `Retry-After` header, as `authHandler.ts` does. Release the reservation only when the body failed validation.
3. Share one throttle instance between the composition root and the route handler through the dependencies that custom routes receive.

## Scope

### In scope

- The per-user limit on the password-mailbox create route.

### Out of scope

- Limits on the OAuth routes or on any other authenticated route.
- A database-backed or multi-process throttle.
- Changes to the per-address limits of the public auth routes.

## Acceptance criteria

- When a user makes the 11th attempt within 15 minutes, then the response is 429 `rate_limited` with `Retry-After`, and no outbound connection is made.
- When another user makes an attempt, then their budget is independent.
- When a request body is invalid, then it does not consume an attempt.
- When 15 minutes have passed since the earliest counted attempts, then the user can try again.
