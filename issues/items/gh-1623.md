**Model tier:** medium

## Context

Model tier rationale: One read-only agent tool over existing Inbox proposal data, but it must be limited to the thread's own card and shaped to what the model needs.

An Inbox item thread is a Semp thread attached to one proposal card (a card in Processing proposals). The turn's first context comes from the ref resolver (#1733), but after the thread has been idle and wakes, the agent needs a way to read the card again. Today the Inbox module (`backend/packages/data/src/inbox/inboxModuleManifest.ts`) declares `agentTools: []`, and module agent tools are not yet part of agent sessions; #1523 composes them.

The card is an item whose properties hold the proposal envelope (`entityKind`, `target`, `properties`), `status`, `history` and the user-edited keys (see `backend/packages/data/src/inbox/proposalActions.ts`). The card's source is the Inbox item (the capture and its attachments). Which parts of a card a thread may see is defined by the thread-revision rules of #1938.

## Task

Load `state-writes`, `canonical-keys` and `testing`.

1. Add an `inbox.proposal.get` module agent tool to the Inbox module manifest (`agentTools` entry with `handlerExport`), with arguments `{ proposalId }` (strict, UUID).
2. The handler returns, for the card, the capture text, its attachments (names and ids), the effective envelope, `userEditedKeys`, the status and the `history`. It follows the content rules of #1938.
3. The tool answers only for the card of the calling run's own thread: the run's thread is resolved from persisted run data (as `heartbeatAgentTools.ts` resolves the calling project), never from arguments beyond the id, and any other card id gives a not-found style error that does not reveal whether the card exists.
4. The tool writes nothing and is not approval-gated.
5. Tests: the tool returns the full card for its thread; another card of the same tenant is refused with the same error as a missing one; a card of another tenant is refused; arguments with extra keys are rejected.

## Scope

### In scope

- The read tool, its manifest entry and its own-card restriction.

### Out of scope

- Composing module tools into sessions: #1523.
- The writing tool `inbox.proposal.revise`: #1906.
- The initial context of a turn: #1733.
- Card context rules for item threads: #1938.

## Acceptance criteria

- When the agent of a card thread calls `inbox.proposal.get` with its card id, then it receives capture, attachments, effective envelope, user-edited keys and history.
- When it passes the id of any other card, then it gets the same error as for a missing card.
- When the call is made, then no item is modified.
