**Blocked by:** #248, #84

## Context

Second of two parts of the retry/recovery slice, completing the `batch-transcription` batch (approved behavior in #179). #248 delivered the queue retry policy, the `item_automation` state machine, and the transactional failure notification. This part adds the two paths that bring a permanently failed transcription back into the pipeline: a daily heartbeat and a manual rerun route, both honoring the `locked` opt-out.

## Task

- Add a daily deterministic heartbeat (scheduled from actual execution time per #84) that re-enqueues every Transcriptions row with `item_automation.status = 'error'` in a fresh batch, using the original key `jobKey: transcription-job:${fileItemId}` with `fileItemId` derived from the row's `link`. The heartbeat repeats daily until the row succeeds or someone sets `locked`; the heartbeat never sets `locked` itself and skips locked rows.
- Add the action route `POST /api/transcriptions/:id/rerun` (registered by the same manifest rule as `POST /api/transcriptions` from #180): it enqueues the same job with the same `jobKey` and performs no item write; a row with `item_automation.status = 'locked'` returns 403 on the standard error contract.
- Both paths reuse the existing row and the paid checkpoints from #182/#183; neither creates a second row or repeats a paid stage.

## Scope

### In scope

- Daily requeue heartbeat, rerun action route with 403 on locked rows, tests, and necessary documentation.

### Out of scope

- Retry policy, state machine, and failure notification — #248.
- Meeting bot, live captions, watch folder, voiceprints — never (see #179).

## Acceptance criteria

- The daily heartbeat requeues every `error` row with the original `jobKey` and does not requeue `done`, `pending`, or `locked` rows; repeated heartbeat runs collapse onto one job per row.
- `POST /api/transcriptions/:id/rerun` enqueues the same `jobKey` for a `done` or `error` row and returns 403 for a `locked` row.
- Daily and manual retry reuse the same row, key, and paid checkpoints: a fake gateway sees no repeated call for checkpointed stages.
- Locked rows are never rerun by either path.
