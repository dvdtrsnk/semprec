**Blocked by:** #1658
**Model tier:** medium

## Context

Model tier rationale: A derived cache key recomputed from page content after document updates, depending on blockers' serializer and trigger, with a bounded and well-defined text rule.

A Journal entry's stored `name` is an emoji and the period key (for example `2026-W41`), which is language neutral but unusable as a title in generic surfaces such as tables, search and export. The collection view of the Journal shows entries by their period; users and the weekly clean-up also want a short human subtitle drawn from what was written. The Journal schema is locked, so adding a user property needs a per-tenant cutover migration and seed change, and manual edits of such a title would compete with the page.

Decision: the title is derived, not typed, and the user does not override it. Each Journal entry gets `computed.journalSummary`, the first heading of its page, otherwise its first non-empty line, as plain text of at most 80 characters, and `null` when the entry has no page or no text. The stored `name` stays unchanged and is not shown by clients. This avoids a schema change on a locked system database. The computed key is reserved so that no property of that name can collide.

#1608 provides the page-to-Markdown serializer used to read the text; #1658 adds the trigger that runs after a document update to reindex page and journal text, which this issue uses to recompute the summary as well.

## Task

Load `state-writes`, `canonical-keys` and `testing`.

1. Add the computed key `journalSummary` as `JOURNAL_SUMMARY_COMPUTED_KEY` in the journal module and register it in the process's computed key registry in `seed/seedSystem.ts`, so a property with that key is refused.
2. Add `computeJournalSummary(markdown)`: the first heading's text if the page has a heading before any other text, otherwise the first non-empty line; strip Markdown syntax to plain text; collapse whitespace; truncate to 80 characters; `null` for empty input.
3. After a document update of a Journal entry's page (the trigger of #1658), recompute the summary from the page's Markdown (#1608) and write it with `writeComputedAndAnnounce`; the write is skipped when the value did not change.
4. Entries that exist before this issue get their summary at their next page edit; no backfill is part of this issue.
5. Tests: a page starting with `## Cíle kvartálu` yields `journalSummary = "Cíle kvartálu"` within one trigger run; a page with only a paragraph yields its first line; an 120-character first line is truncated to 80; an empty page or no page yields `null`; a property with key `journalSummary` is refused; an unchanged recompute announces nothing.

## Scope

### In scope

- The derived `computed.journalSummary` of Journal entries and its reserved key.

### Out of scope

- A user-editable title property on Journal; it is not planned, because the title is the derived summary.
- Allowing user properties on system collections; not in v1, the schema of system collections is governed by the manifest.
- Czech labels of the Journal properties; #1413.
- Backfilling existing entries.

## Acceptance criteria

- When a quarter page starts with `## Cíle kvartálu`, then `computed.journalSummary` is `Cíle kvartálu` after the next trigger run.
- When the page is empty or does not exist, then `journalSummary` is `null`.
- When a property with key `journalSummary` is created on the Journal database, then it is refused.
- When the page is edited without changing its first line, then no new announcement is sent.
