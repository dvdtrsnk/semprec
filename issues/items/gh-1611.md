**Blocked by:** #1548
**Model tier:** medium

## Context

Model tier rationale: One known mechanism (move a single consumer from a property to an API and then remove the property) across a web view, a seed and a data migration, with an existing contract-migration precedent and existing web test fixtures.

The web AGENT page (`web/src/views/agentPage/AgentPage.tsx`) renders the project item's `agents` property as one read-only paragraph (`GuidanceBlock`). The agent itself reads `project_agent_guidance`, so the text the page shows and the text the agent follows are different stores. #1449 copied every existing `agents` text into `project_agent_guidance`, and #1548 serves it as four Markdown sections with `GET` and `PUT /api/projects/:id/agent-guidance` (optimistic concurrency through `expectedUpdatedAt`; 409 `version_conflict` with the current content in `error.details.current`).

This issue switches the page to that API and then removes the now unused `agents` property (expand/contract, `docs/adr/2026-09-10-expand-contract-forward-only-migrations.md`). No backend code reads the property, and an agent writing it through `item.patch` has no effect on anything, so removal is safe once the page no longer reads it.

Decisions:

- The page shows four cards (Purpose, Allowed, Not allowed, General instructions). Each card edits its Markdown in a plain multi-line text field; the repo has no shared rich Markdown editor, and introducing one is not part of this issue.
- Autosave: 800 ms after the last keystroke the page sends the full `sections` with the last known `expectedUpdatedAt`. The header shows "Saving..." while a request is in flight and "Saved" afterwards (user-facing strings through i18n in Czech and English). The `updatedAt` from each response becomes the next `expectedUpdatedAt`; saves are sent one at a time.
- On 409 the page shows a conflict notice, replaces the fields with `details.current` and keeps the unsaved local text available in the notice's copy action; it never retries automatically. On 403 `owner_violation` the cards are read-only with an explanation. Other errors use the existing error state with retry.
- The contract migration is the intentionally breaking cleanup the ADR permits only when the issue's Task calls for it: it ships in the same release as the page switch because the single reader is the page itself; a rollback to the previous release shows the Instructions card as empty (the data is still in `project_agent_guidance`). The migration comment and the PR description say so.

## Scope

### In scope

- The page reading and editing the four sections through the API, with autosave, conflict and read-only handling.
- Removing the property from the seed, i18n and existing data.

### Out of scope

- The API itself and its concurrency rules: #1548.
- Showing and resolving instruction drift on the page: #1630, #1685.
- A rich Markdown editor, live refresh of an open page when another device saves, and any change to the Tools or heartbeats blocks.

## Acceptance criteria

- When the page opens for a project with guidance, then each card shows its section; for a project without guidance all four cards are empty.
- When the user stops typing for 800 ms, then one save is sent with the previous `updatedAt`, the header shows "Saving..." and then "Saved", and a reload shows the text.
- When the server answers 409, then the page shows the conflict notice with the server's current text and sends no further automatic save.
- When the caller is not the guidance owner, then the cards are read-only.
- After the migration no Projects database has an `agents` property or item key, a re-run changes nothing, and a freshly seeded tenant has no `agents` property while its system projects still have guidance rows.
