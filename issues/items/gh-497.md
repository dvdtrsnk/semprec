**Blocked by:** #496

## Context

The batch moves rollup helpers out of `backend/packages/data/src/chokePoint/chokePoint.ts` into `backend/packages/data/src/rollup/`, and splits the choke point into modules under `backend/packages/data/src/chokePoint/`. Moving code between two directories that import each other is how cycles appear, and a cycle there would make module initialization order-dependent. This issue forbids cycles in both directories before the moves happen.

`pnpm run check:boundaries` enforces `backend/dependency-cruiser.rules.json`. Rule tests live in `backend/packages/module-boundaries/src/__tests__/module-boundaries.unit.test.ts` with fixtures under `backend/packages/module-boundaries/src/__tests__/fixtures/`. #496 added the first rule of this batch to the same files.

## Task

Append the rule **`no-choke-point-rollup-cycle`** (severity `error`) to the end of the `forbidden` array. It forbids circular dependencies (`"circular": true` in `to`) for any module under `packages/data/src/chokePoint/` or `packages/data/src/rollup/`. Give it a `comment` naming this batch.

Add fixture-based unit tests:
- a cycle `chokePoint/x.ts → rollup/y.ts → chokePoint/x.ts` is reported, naming the rule;
- a non-circular `chokePoint → rollup` import is not reported.

If `check:boundaries` reports an **existing** cycle in these directories on today's tree, do not weaken the rule and do not fix the cycle here. Stop with `Relay-Step-Status: blocked` and give the cycle path: fixing it is a decision outside this issue.

## Touches

- backend/dependency-cruiser.rules.json (one new entry appended at the end of `forbidden`)
- backend/packages/module-boundaries/src/__tests__/module-boundaries.unit.test.ts (new test cases)
- backend/packages/module-boundaries/src/__tests__/fixtures/ (new fixture subtree for these cases)
