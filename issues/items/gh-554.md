## Context

The choke-point-split batch (#494) moves code verbatim out of `backend/packages/data/src/chokePoint/chokePoint.ts`, and its issues forbid changing the moved code. The code-review bot reviews moved lines as newly added lines, so it reports defects the code already had (e.g. PR #550: two unchecked `as` casts in `applyRollupConfig`, reported HIGH and blocking even though the bot's own summary noted they were moved verbatim and that a code change would break the issue). Each such finding costs a fix-review round (~30 minutes) that can only end in a reasoned dismissal.

This is a maintainer change to `review-rules/`, not dispatched to Relay.

## Task

Add a rule to `backend/review-rules/severity.md`: when the linked issue's Task requires a verbatim move, a defect in an added line that is byte-identical to a line the same diff removes is pre-existing — report it at most as **low**, say it is pre-existing, never block on it. Anything the move itself changes (imports, an added `export`, signatures, check order, behavior) keeps its normal severity. This deliberately lowers the severity of that one class of finding.

## Touches

- backend/review-rules/severity.md

## Scope

### In scope
- The one rule above.

### Out of scope
- Fixing the pre-existing defects themselves (a separate issue, if wanted).
- Any other review rule.

## Acceptance criteria

- `backend/review-rules/severity.md` contains the rule, limited to issues whose Task requires a verbatim move and to byte-identical moved lines.
- Changes introduced by a move are explicitly excluded from the cap.
