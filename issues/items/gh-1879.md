**Blocked by:** #1838, #1858, #1891
**Model tier:** high

## Context

Model tier rationale: A new cross-process contract (debounced job plus a silent push to devices) triggered from several write seams, where a missed or duplicated trigger silently breaks the phone's local reminders.

Reminders are scheduled on the phone from the feed in #1858. When something changes the feed on the web (a new time, a toggled reminder, a muted calendar, a trashed event, a new time zone), the phone would otherwise learn about it only the next time the app opens. This issue makes the server tell the phone to refetch, without showing anything.

Today there is no such mechanism for reminders. #1445 adds `sendApnsBackgroundPush` (in `backend/packages/data/src/push/apnsAdapter.ts`), a push with no notification row. #1838 uses it for sleep with a debounced job; this issue follows the same shape for reminders. The queue (`backend/packages/queue/src/index.ts`) supports `enqueueJob` with `jobKeyMode: "replace"` and `runAt`, so repeated enqueues under one key collapse into one pending job. Item create and update hooks (`backend/packages/data/src/chokePoint/hooks.ts`, composed in `backend/packages/data/src/domainWriteHooks.ts`) run inside the write's transaction; item trash and restore go through `backend/packages/data/src/chokePoint/itemTrash.ts`, which #1803 extends to trash a calendar with its events; a tenant time zone change is handled in `backend/packages/data/src/chokePoint/itemWrites.ts` (it already calls `recomputeAllForTimezoneChange`).

Decision: the debounce is 30 seconds with job key `reminders-resync:<tenantId>` and replace mode, so two quick edits produce one job and one push. Reason: this matches the sleep resync debounce and keeps pushes rare.

Shared-file ordering: this issue also waits for #1838 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `testing` and `canonical-keys`.

1. Add a core task `remindersResync` (`CORE_TASK_NAMES.REMINDERS_RESYNC` with affinity `api`) in `backend/packages/queue/src/index.ts` and register its handler in `backend/packages/data/src/worker.ts`, next to the notification fan-out handler.
2. Add `backend/packages/data/src/calendar/remindersResync.ts` with `enqueueRemindersResync(client, tenantId)` (`jobKey` `reminders-resync:<tenantId>`, `jobKeyMode: "replace"`, `runAt` now + 30 seconds) and the job handler. The handler sends `sendApnsBackgroundPush` to the tenant's user's registered devices with `kind: "remindersResync"` and no notification text, and does nothing when no device is registered.
3. Call `enqueueRemindersResync` in the same transaction as any write that can change a fire time: create or update of an Event or Task changing `date`, `endDate`, `timeFrom`, `alertMinutes`, `travelMinutes`, `notifications` or `status`; a calendar `notify` change; trash or restore of an Event, Task or calendar; and a tenant time zone change. Writes that change none of those fields enqueue nothing. Implement the Event/Task/calendar part as item create and update hooks registered in `backend/packages/data/src/domainWriteHooks.ts`.
4. Tests: two Event time changes within 30 seconds leave exactly one pending job and, after it runs, one push; renaming an Event enqueues nothing; trashing a calendar enqueues one job; a time zone change enqueues one job; a rolled-back write leaves no job; a tenant with no devices sends nothing.

## Scope

### In scope

- The debounced `remindersResync` job, its silent push, and enqueueing it from every write that changes a fire time.

### Out of scope

- The push transport itself: #1445.
- The feed the phone refetches: #1858.
- Visible server-side reminder notifications, a reminders table and a minute sweep: deferred, not in v1; the silent push only triggers a resync.
- Resync for sleep changes: #1838.
- Client handling of the push.

## Acceptance criteria

- When an Event's start time is changed twice within 30 seconds, then one `remindersResync` job is pending and one silent push is sent with `kind` `remindersResync`.
- When only an Event's name changes, then no job is enqueued.
- When a calendar is trashed or its `notify` is turned off, then one job is enqueued for the tenant.
- When the tenant time zone changes, then one job is enqueued.
- When the transaction of a triggering write rolls back, then no job exists.
- When the tenant has no registered device, then the job completes and no push is attempted.
