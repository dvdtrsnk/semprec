## Context

Model tier rationale: three defects of the one shared HTTP and WebSocket client, each in a failure path; no exported API changes and no native consumer changes.

Review of PR #2089 (findings 17, 18, 19), `mobile/shared/data`:

- **A job per socket stays behind.** `ApiClient.openSocket` runs each socket in `http.async(SupervisorJob(http.coroutineContext[Job]))`. Nothing completes that `SupervisorJob`, so after its socket ended it stays an active child of the client's job: one more per reconnect, for the life of the app.
- **A refused handshake retries forever.** `WS /api/sync` refuses an unknown or expired session with a raw `HTTP 401` before any socket exists (`backend/packages/realtime/src/syncServer.ts`). `ApiClient.runSocket` maps the handshake failure to `SocketEnd.Failed`, and `SyncSocket.run` reconnects; only the close code 4401 of an open socket runs `onSessionRejected`. The window is never signed out and keeps reconnecting with backoff. Ktor does not report the handshake's status the same way on every engine (OkHttp, Darwin).
- **A 401 can become UNAVAILABLE.** `ApiClient.send` reads an error answer's body inside the same `try` as the request; `http.request` also saves the whole body before returning. A body that breaks off turns a `401` into `Failure(UNAVAILABLE, null)`, so `AuthenticatedApi` never runs `onSessionRejected`. `upload` and `download` lose the status the same way.

## Task

Load `kmp-shared`, `error-handling`, `io-hardening`, `testing`, `mobile-verify`.

1. `ApiClient.openSocket`: complete the socket's supervisor right after starting the socket, so it ends with it.
2. `ApiClient.send`, `upload`, `download`: stream the answer (`prepareRequest { … }.execute { … }`); the status decides the failure before any body is read, and an error body that cannot be read is `null` (cancellation rethrown).
3. `AuthenticatedApi.openSocket`: when a socket fails before it opened, check the session with `GET /api/auth/session` through `send` (whose `401` runs `onSessionRejected`); return `null` (nothing reconnects) when the session was refused this way or by the close code 4401.
4. `SyncSocket.run`: stop on `null` only.

## Acceptance criteria

- Three sockets opened and ended on one client leave its job with as many active descendants as before them.
- A handshake answered `401` whose session check also answers `401` runs `onSessionRejected` once and no second handshake follows; a handshake refused with `503` while the session is valid is retried and signs nothing out.
- A `401` answer whose body breaks off is `Failure(UNAUTHORIZED, 401)` from `send`, `upload` and `download`, and each runs `onSessionRejected`.
- `sharedJvmTest` and `detektAll -PdetektAutoFix=false` pass.
