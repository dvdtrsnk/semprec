**Blocked by:** #89, #99, #198

## Context

Mail search currently parses `from:`, `has:attachment`, and date operators, but leaves `is:unread` in free text. Issue #27 introduces the canonical read/flagged properties and #72 keeps those values synchronized with providers. Search must consume that finished surface rather than pretending the operator is message text.

## Task

Extend the mail-query parser with the closed structured operators `is:read`, `is:unread`, `is:flagged`, and `is:unflagged`. Compile them over #27's canonical boolean property keys `read` and `flagged`; remove recognized operators from full text. Missing `read` means unread (`false`) and missing `flagged` means unflagged (`false`) for legacy rows. Identical repeats collapse. `is:read is:unread` returns `validation_failed` with `{ field: 'is:read', conflict: ['read','unread'] }`; flagged contradiction does the same with field `is:flagged`. Read and flagged dimensions compose independently with AND. Combine them with existing operators/ranking and add parser plus real-Postgres tests.

## Scope

### In scope

- Structured mail read/flag search parsing, SQL compilation, validation, and tests.

### Out of scope

- Provider flag synchronization or UI actions, owned by #72/#27.
- New general-purpose filter condition types.
- Search dictionary changes, owned by #74.

## Acceptance criteria

- `is:unread` and the other three operators filter on structured state and never enter `websearch_to_tsquery`.
- Structured operators compose correctly with free text, sender, attachment, and date filters.
- Contradictory operators fail predictably rather than returning arbitrary results.
- Legacy messages with no state follow one documented, tested default.
