## Context

Model tier rationale: A single additive migration and a same-transaction write in one function with an established pattern, but it touches the hot path every document write takes (WebSocket and API), so it needs regression coverage.

The client shows "Edited <date>" beside page previews (a project's notes card, journal weeks, journal rows) and in the full-screen editor. The backend cannot answer that today. A `docs` row only has `id`, `item_id`, `kind` and `created_at` (`DocDbRow` in `backend/packages/data/src/docs/docsStore.ts`). `doc_updates` rows are deleted by compaction, `doc_history_updates` expire after 30 days, and `doc_snapshots.updated_at` is the compaction time, so none of them gives a reliable last-edit time.

Every document write, including a WebSocket sync update, goes through `mutateDocWithClient`, which calls `appendDocUpdateWithClient` (`backend/packages/data/src/docs/docPersistence.ts`) inside the transaction; after commit it publishes `notifyDocUpdate({docId, updateId, createdBy})`. That function is the single place to record the edit. `createdBy` is `user`, `ai_agent` or `system` (`CreatedBy` in `types.ts`).

Decision (decided by the product owner): no backfill and no migration of existing documents. Production currently has no documents (the only producer is unreachable), and a speculative backfill from `doc_history_updates` is not built (ADR `2026-09-10-no-speculative-generality-beyond-issue-scope.md`). A document without a recorded edit reads its `created_at` as the last edit time.

#1625 builds the realtime invalidation on the column added here. The page summary read (#1615) returns these two values.

## Task

Load `db-migrations`, `state-writes` and `testing`.

1. Add the migration `backend/packages/data/src/db/migrations/NNNN_docs_last_edited.sql` (next free ordinal at commit time): `ALTER TABLE docs ADD COLUMN last_edited_at timestamptz NULL, ADD COLUMN last_edited_by text NULL` with `CHECK (last_edited_by IN ('user', 'ai_agent', 'system'))`. Both columns stay nullable; no backfill. Follow the repository's expand/contract rules for the table's row-level security and grants (the existing `docs` policies and role grants already cover new columns; confirm and do not change them).
2. In `appendDocUpdateWithClient` (`docs/docPersistence.ts`), in the same transaction as the `doc_updates` insert, `UPDATE docs SET last_edited_at = <the inserted row's created_at>, last_edited_by = <createdBy> WHERE id = <docId>`. Use the `created_at` returned by the insert so the two agree. This covers writes through `mutateDocWithClient`, `mutateDoc` and the WebSocket path.
3. In `docs/docsStore.ts`, read the two columns and extend `DocRow` (`types.ts`) with `lastEditedAt` (ISO string; equals `createdAt` when the column is NULL) and `lastEditedBy` (`CreatedBy | null`), validating the stored value with `assertKnownValue`.
4. Page summary wiring: if the `page.get` operation of #1615 already exists when you implement this, return `lastEditedAt` and `lastEditedBy` from the `DocRow` there (for an item with no document, `null`). If it does not exist yet, leave it and say so in the pull request description; #1615 reads the same `DocRow` fields when it lands after this issue.
5. Tests: a write with origin `user` sets `last_edited_at` and `last_edited_by = 'user'`; a write with origin `ai_agent` sets `'ai_agent'`; a `docs` row with NULL columns reads `lastEditedAt` equal to `createdAt`; a mutation that changes nothing (no `doc_updates` row) leaves the columns untouched; a WebSocket-applied update moves `last_edited_at`.

## Scope

### In scope

- The two columns, recording them in the same transaction as every document update, and exposing them on `DocRow`.

### Out of scope

- A backfill from `doc_history_updates`: not planned; production has no documents.
- Realtime notification of document edits: #1625.
- The page summary response schema: #1615.
- Whether the project's "Edited" label includes edits of subpages (open product question).

## Acceptance criteria

- When a document is written through the WebSocket sync, then `last_edited_at` moves to that update's time and `last_edited_by` is `'user'`.
- When the write has origin `ai_agent`, then `last_edited_by` is `'ai_agent'`.
- When a document row has no recorded edit, then `DocRow.lastEditedAt` equals `createdAt` and `lastEditedBy` is null.
- When a mutation produces no update, then `last_edited_at` is unchanged.
- The full backend verification passes including the migration numbering check.
