## Context

Review follow-ups from harvest issue #889, both in `withFreshDatabase` of `backend/packages/data/src/__tests__/czechHunspellSearch.test.ts`:
- PR #472 (finding 28c2fdacc2), line 39: the `admin` pool is created at line 36 and `CREATE DATABASE` runs at line 39 outside any `try`/`finally`; if that query throws, `admin.end()` is never reached and the pool leaks.
- PR #472 (finding b2b231c1e5), line 46: the `finally` block awaits `pool.end()`, `DROP DATABASE` and `admin.end()` sequentially; if `pool.end()` rejects, the other two are skipped, so the fresh database is left behind and the admin pool is leaked.

## Task

In `withFreshDatabase`:
1. Wrap the `CREATE DATABASE` statement in a `try`/`catch` that, when the query rejects, calls `admin.end()` and then rethrows the original error. Do not end `admin` on success: the later `DROP DATABASE` in the cleanup `finally` still runs on it. If `admin.end()` itself rejects in that catch, the original `CREATE DATABASE` error is still the one thrown (a cleanup failure must not replace it).
2. Make the cleanup `finally` run `pool.end()`, `DROP DATABASE` and `admin.end()` such that a rejection of one does not skip the others, and rethrow the first error once all three have been attempted (a cleanup failure must not replace the real error from `fn`).

## Touches

- backend/packages/data/src/__tests__/czechHunspellSearch.test.ts (`withFreshDatabase` only)

## Scope

### In scope

The two cleanup changes inside `withFreshDatabase`.

### Out of scope

The rest of the file, other test helpers that create databases, extracting `withFreshDatabase` into shared test support, and a test exercising `withFreshDatabase`'s failure paths.

## Acceptance criteria

- When `CREATE DATABASE` rejects, `admin.end()` is still called and the original rejection propagates, even if `admin.end()` also rejects; on success `admin` stays open for the cleanup's `DROP DATABASE` (verified by reading the code).
- When `pool.end()` rejects, `DROP DATABASE` and `admin.end()` are still attempted, and the `pool.end()` error propagates after them (an error thrown by `fn` itself is not replaced by a cleanup error) (verified by reading the code).
- With no failure, the file's existing tests pass unchanged and `pnpm run verify` in `backend/` passes.
