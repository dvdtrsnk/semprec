## Context

**Mail database ids are captured at boot.** `createApiQueueRuntime` resolves the four mail databases once at startup (`backend/services/semprec-api/src/queueRuntime.ts:55`). `resolveMailModuleIds` (`backend/packages/data/src/mail/mailModuleIds.ts:14-34`) calls `getDatabaseByModuleId` for `emails`, `files`, `folders` and `mailboxes`. The result is passed as `createCoreTaskList`'s fifth parameter, `mailModuleIds?: MailModuleIds` (`backend/packages/data/src/worker.ts:101-112`), and two handlers use it:
- `mailAccountSync` (`worker.ts:164-173`) passes it to `handleSyncMailAccountTask` (`backend/packages/data/src/mail/mailSyncJob.ts:159-167`), whose prologue reads properties and the Mailbox item by those ids (`:178-191`);
- `mailSearchReindexSweep` (`worker.ts:174-180`) passes `emailsDatabaseId` to `handleMailSearchReindexSweepTask` (`mailSyncJob.ts:94-105`).

Under row-level security, ids captured at boot belong to whichever tenant was visible then (tenant zero). In any other tenant's job those databases are invisible, so the prologue fails with "Email module schema is missing an expected relation property" (`mailSyncJob.ts:185-189`).

**The sweeps run unscoped.** `mailAccountSyncSweep` runs every 5 minutes (`worker.ts:84`). `handleMailAccountSyncSweepTask` (`mailSyncJob.ts:77-83`) calls `listAccountsDueForSync` (`backend/packages/data/src/mail/mailAccountSyncStateStore.ts:307-312`) and then `enqueueMailAccountSync` per due account. `mailSearchReindexSweep` runs daily and calls `findEmailsMissingSearchIndex` (`backend/packages/data/src/mail/search.ts:43-55`, 200 rows) and then `reindexItemSearch` per item.

Tenancy state this issue builds on:
- Every tenant table carries `tenant_id` under a RESTRICTIVE RLS policy `tenant_isolation`: `tenant_id = (SELECT app_tenant_default())`, with `app_tenant_default()` = `COALESCE(app_current_tenant(), app_sole_tenant())` over the GUC `app.tenant_id`.
- `withTransaction`, autocommit `pool.query` and `pool.connect()` clients set that GUC from the ambient scope: `runInTenant(tenantId, fn)` sets the tenant and `runAsSystem(reason, fn)` sets `''` (`@semprec/shared`).
- In system scope, rows are visible only while exactly one tenant exists.
- Since #982, the queue envelope is `{ traceId, tenantId: string | null, payload }`, and `enqueueJob` stamps `tenantId` from the current scope. The task runner calls a `tenancy: 'system'` task (both sweeps) inside `runAsSystem`, and a `tenancy: 'tenant'` task (`mailAccountSync`) inside `runInTenant(envelope.tenantId)`.
- #983 added `forEachActiveTenant` (`backend/packages/data/src/tenancy/forEachActiveTenant.ts`, exported from `@semprec/data`). Called from a system scope, it runs the callback inside `runInTenant(tenantId, …)` for each `active` tenant, starting at a rotating offset. A throwing tenant does not stop the others. After all tenants were attempted, the failures are rethrown as one `AggregateError`.
- This issue calls it as `forEachActiveTenant(pool, async () => …)`. If the merged signature differs, use the merged one.

**Startup behaviour changes.** The `queueRuntime.ts` docstring (`:36-39`) and `mailSyncComposition.test.ts:70-76` promise that the API rejects at startup on an unseeded database. There is no single set of ids to check at startup any more, so the resolver's existing message now fails the job that needs the ids.

#990 removes the same boot capture from the live-sync root (`backend/services/semprec-api/src/serve.ts:125`).

## Task

Load `state-writes` (the reindex writes `item_search_index`; the sweep enqueues jobs) and `error-handling` (per-tenant failures, and a missing module failing the job loudly).

1. **Fan out the account sweep (`mailSyncJob.ts`).** Wrap the body of `handleMailAccountSyncSweepTask(pool)` in `forEachActiveTenant`. Each tenant's due accounts are listed in its own transaction and enqueued from its scope, so every `mailAccountSync` envelope carries the mailbox's tenant.
2. **Fan out the reindex sweep (`mailSyncJob.ts`).** Change the signature to `handleMailSearchReindexSweepTask(pool: Pool): Promise<void>`, dropping `emailsDatabaseId`.
   - Per tenant, in one `withTransaction`, call `const { emailsDatabaseId } = await resolveMailModuleIds(client)` and then run the existing find-and-reindex loop.
   - A tenant without mail databases fails only its own pass, with the resolver's message.
   - `mailModuleIds.ts` already imports `MailModuleIds` from `mailSyncJob.ts` as a type only; keep that import type-only so no runtime cycle appears.
3. **Resolve ids per job (`worker.ts`).** Edit only the parameter list, these two handler entries and the docstring; leave `CORE_CRONTAB` alone.
   - Remove the `mailModuleIds` parameter from `createCoreTaskList`. `createApiCoreTaskList` follows through `Parameters<>`.

   - Delete both "requires createCoreTaskList's mailModuleIds argument" guards. The `mailSearchReindexSweep` handler calls `handleMailSearchReindexSweepTask(pool)`.
4. **Resolver docstring (`mailModuleIds.ts`).** It now resolves in the caller's tenant scope per job or per tenant pass, and a missing database fails that job.

## Acceptance criteria

All of these are integration tests (`*.test.ts`), with two tenants under the runtime role unless stated otherwise.
- **Per-tenant account sweep.** Tenant zero (seeded) and tenant B (minimal fixture) each have one due `mail_account_sync_state` row. One `mailAccountSyncSweep` run enqueues exactly one `mailAccountSync` job per due mailbox, and each job's envelope `tenantId` is its mailbox's tenant.
- **Per-tenant reindex.** Tenant zero's and tenant B's Emails databases each hold one item without an `item_search_index` row. One `mailSearchReindexSweep` run indexes both, and each new row carries its item's `tenant_id` and its own tenant's Emails database id.
- **Reindex failure isolation.** Tenant B has no mail databases. Tenant zero's unindexed item is still indexed, and the run rejects with an error naming the missing module ids.
- **Per-job resolution.** Tenant B has no mail databases. A `mailAccountSync` job enqueued inside B's scope fails with `Mail module databases are not seeded (missing: emails, files, folders, mailboxes) — run packages/data/dist/db/runSeedCli.js`. A tenant zero `mailAccountSync` job in the same drain gets past module resolution and fails at the adapter step as today (`No IMAP adapter configured for this composition root`).
- **No boot capture.** `createApiQueueRuntime` resolves on a database without the mail module seeded, and the existing "fails at the adapter step" composition case passes unchanged.
- **Single tenant unchanged.** With only tenant zero, the existing `mailSync.test.ts` cases pass with the new reindex signature.
