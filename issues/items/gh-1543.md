## Context

Model tier rationale: Two read routes on an existing route-table pattern with established tenant-isolation fixtures, but cursor correctness and the closed error contract need care.

#1367 adds the durable tables for Semp threads and messages. Nothing exposes them yet. There is no `/api/semp/*` route in `backend/services/semprec-api/src/routeMatrix.ts`. Route families in this service are `RouteDefinition[]` lists mounted through `mountRoutes` in `app.ts` (see `createAccountRoutes` in `accountHandler.ts`); `createAdapterRequestListener` gives them authentication, tenant scope and the closed error contract (`toPublicErrorBody`), so no route has its own auth or error path.

This issue adds the read side: one thread's header and its message history, so the app can reopen a thread with its full history, including threads older than the 30-day event retention. It also fixes the pattern all later `/api/semp/*` routes follow.

Later issues extend the response: #1620 adds the write route in the same file, #1684 adds resolved ref labels, #1562 adds the tick-thread header and active run, #1563 adds run timing for tick messages.

Decision: the active thread is held by the client. The server stores no "last opened" marker; the client falls back to the list route from #1729 when its remembered thread is missing or returns 404.

Shared-file ordering: this issue also waits for #1541 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `error-handling`, `canonical-keys` and `testing`.

1. Create `backend/services/semprec-api/src/sempThreadsHandler.ts` exporting `createSempThreadRoutes(pool): RouteDefinition[]`, modelled on `createAccountRoutes`, and mount it in `app.ts` through `mountRoutes`.
2. `GET /api/semp/threads/:id` returns `{ id, kind, title, subject, createdAt, lastActivityAt }`, where `subject` is `{ inboxItemId, proposalId } | null` (non-null only for `item` threads; the same shape the thread list uses in #1729). Fields for tick threads (`heartbeat`, `activeRun`) are not returned yet (#1562).
3. `GET /api/semp/threads/:id/messages?before=&limit=` returns `{ rows, nextCursor }`, newest first, with an opaque cursor over `(created_at, id)` so that rows with the same `created_at` are neither skipped nor repeated. Each row: `{ id, role, text, system: { key, params } | null, context, replyToMessageId, agentRunId, eventFromId, status, createdAt }` (`eventFromId` is what the client passes as `afterEventId` to `agent:watch`). `limit` has a default and a hard maximum; a malformed `before` or `limit` is a 400 in the closed contract.
4. `assertUuid` on `:id`. A thread of another tenant and a non-existent thread both answer 404 in the closed error contract, on both routes (the messages route checks the thread first).
5. Register both routes in `routeMatrix.ts` with tenancy `tenant`, and cover them in `tenantIsolationRoutes.test.ts`.
6. Tests: header shape per kind, paging returns every message exactly once with identical `created_at`, a message older than 30 days is returned after the event retention job ran, foreign and unknown thread ids return identical 404 bodies, malformed cursor is 400. Message text is never logged.

## Acceptance criteria

- When a thread of another tenant or an unknown id is requested on either route, then the response is 404 in the closed error contract with an identical body for both cases.
- When a thread has several messages sharing one `created_at`, then paging through `nextCursor` returns each message exactly once.
- When a message is older than 30 days and the event retention job has run, then it is still returned.
- When the routes are inspected, then both are in `routeMatrix.ts` with tenancy `tenant` and covered by the isolation test.
