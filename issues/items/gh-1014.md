## Context

`push_subscriptions` is a global identity-plane table (no `tenant_id`, no row-level security), user-scoped in code like `sessions`. Its registration path breaks the rule that no user may infer anything about another account:

- An endpoint, or an APNs device token, may be active for one account only. The partial unique indexes are `push_subscriptions_active_endpoint_idx` and `push_subscriptions_active_device_token_idx` (`backend/packages/data/src/db/migrations/0031_push_subscriptions.sql:46-52`).
- `upsertWebPushSubscription` (`backend/packages/data/src/push/pushSubscriptionsStore.ts:57-89`) and `upsertApnsSubscription` (`:99-126`) refresh a same-owner row in place.
- When the active row belongs to another user, they throw `ConflictError("'endpoint' is already registered to another account")` or the `deviceToken` equivalent (`:85-87`, `:122-124`). `POST /api/push-subscriptions` (`backend/packages/data/src/push/pushRouteHandlers.ts:40-57`) returns that as a 409.
- So any caller learns that some other account uses this browser or device. The documented recovery, that the old account must revoke first (`pushSubscriptionsStore.ts:63-67`), cannot be performed by the new owner.

The fix: a registration silently takes the endpoint or token over and revokes the previous owner's row. The route answers exactly as for a fresh endpoint.

## Task

Load `state-writes` (a targeted displacement and an upsert that must commit together) and `io-hardening` (a response must not reveal another account).

1. **Silent rebind.** Change `upsertWebPushSubscription` and `upsertApnsSubscription`. Do it identically for both, keyed on `endpoint` and on `device_token` respectively. The caller's own active row is still refreshed in place, keeping the same `id`.
   - **a. Displace.** Revoke any active row for the same endpoint or token owned by another user: `UPDATE push_subscriptions SET revoked_at = now(), updated_at = now() WHERE endpoint = $1 AND revoked_at IS NULL AND user_id <> $2`, with `device_token = $1` for APNs. Zero rows is the normal case.
   - **b. Upsert.** Run the existing `INSERT ... ON CONFLICT ... DO UPDATE ... WHERE push_subscriptions.user_id = EXCLUDED.user_id RETURNING ...` unchanged.
   - **c. Race.** If (b) returns no row, a concurrent registration of the same endpoint by a different account committed between (a) and (b). Repeat (a) and (b) once. If the second attempt still returns no row, throw a plain `Error` naming the race. It must not be `ConflictError` and must not name another account.
   - **d. Atomicity.** Both statements run on one transaction-scoped client. When a caller passes a bare `Pool`, open the transaction inside the function with `if (client instanceof Pool) return withTransaction(client, (c) => upsertX(c, input))`. This is the same pattern as `finishAgentRunWithErrorNotification` (`backend/packages/data/src/agentRuns/agentRunsStore.ts:185-187`).
   - Remove both `ConflictError` throws.
   - Rewrite the two docstrings (`:57-68`, `:99-106`): an endpoint or token moves silently to the account registering it, and the previous owner's row is revoked.
   - The route keeps answering 200 `{ subscription }`.
2. **Tests.**
   - Replace the two "rejects another user's registration" tests in `backend/packages/data/src/__tests__/pushSubscriptions.test.ts:234-267` and `:304-335` with rebind tests.
   - Add the identical-response case to `backend/packages/data/src/push/__tests__/pushRouteHandlers.test.ts`.

## Scope

### In scope
- Silent displacement of another account's active registration, for web push and APNs, with its atomicity, race handling, docstrings and tests.

### Out of scope
- Revoking a user's push registrations on password reset (#1024).
- Revoking push registrations when an admin suspends an account (#1041).
- Resolving outbound push addresses at send time (#1034).

## Acceptance criteria

- **Web push rebind.** Account A holds an active `web_push` registration for endpoint E. When account B registers E:
  - the call resolves to B's new active row (a new id, `userId` B, B's keys);
  - A's row is `revokedAt` non-null with its keys unchanged;
  - exactly one active row exists for E.

  (integration, `pushSubscriptions.test.ts`)
- **APNs rebind.** The same holds for an `apns` device token. (integration, `pushSubscriptions.test.ts`)
- **Same-owner refresh.** Re-registering A's own active endpoint still refreshes the row in place with the same id. The existing test at `pushSubscriptions.test.ts:175` passes. (integration)
- **Identical responses.** Through `createRegisterPushSubscriptionRouteHandler`, a registration of an endpoint another account holds and a registration of a fresh endpoint both return status 200 with a body of the same shape. Neither response contains A's id or user id. (integration, `backend/packages/data/src/push/__tests__/pushRouteHandlers.test.ts`)
- **Atomic displacement.** When the upsert fails after the displacement statement, A's registration is still active afterwards. Force the failure, for example with a test-created trigger that raises on insert for B. (integration, `pushSubscriptions.test.ts`)
- **Bare pool.** Called with a bare `Pool`, both functions still displace and insert in one transaction: the forced-failure case above holds when the test passes `pool` rather than a client. (integration, `pushSubscriptions.test.ts`)
