**Blocked by:** #641

## Context

`createCoreTaskList` (`backend/packages/data/src/worker.ts:95-108`) takes an 11th parameter, `genericOperationApprovalReplay?: GenericOperationApprovalReplay`, and hands it to `handleApprovalRequestExecuteTask` for every `approvalExecute` job (lines 180-186). The api composition root, `backend/services/semprec-api/src/queueRuntime.ts:48-57`, calls `createApiCoreTaskList(pool, actionRegistry, undefined, undefined, undefined, undefined, undefined, moduleRegistry)` — eight arguments, so `pushSenders` and `genericOperationApprovalReplay` are both `undefined`. Without a replay, `handleApprovalRequestExecuteTask` (`backend/packages/data/src/mcp/approvalRequestExecution.ts:68-84`) takes the "No replay handler configured" branch for every generic-operation payload and records the outcome `{ error: true, result: "No generic-operation approval replay handler is configured for this worker." }`: an approved `item.delete` / `relation.delete` / any of the five destructive operations gated by `docs/adr/2026-09-18-exactly-once-execution-of-approved-destructive-operations.md` never executes, and the request lands in `execution_status='conflict'`.

The real replay exists: `replayApprovedGenericOperation(pool, request)` in `backend/packages/application/src/genericOperationGateway.ts:342` (exported through `@semprec/application`'s barrel), whose signature already matches `GenericOperationApprovalReplay`, and `backend/packages/application/src/__tests__/genericOperationGateway.test.ts:660-671` proves it works when injected into a task list. `semprec-api` already depends on `@semprec/application` (`backend/services/semprec-api/package.json:13`). It cannot live in `packages/data` (an `application -> data -> application` cycle), which is exactly why the parameter is injected by the composition root.

This issue depends on #641 only because both edit `backend/services/semprec-api/src/queueRuntime.ts`; after #641 the `createApiCoreTaskList(...)` call is the region to change.

## Task

1. In `backend/services/semprec-api/src/queueRuntime.ts`, import `replayApprovedGenericOperation` from `@semprec/application` and pass it as the `genericOperationApprovalReplay` argument of `createApiCoreTaskList` (position 11; `pushSenders` at position 10 stays `undefined`, with a comment naming it). Update the function's docstring: the approval replay is now wired; the remaining no-op defaults are the library metadata fetcher, mail transports and push senders.
2. Composition test, new file `backend/services/semprec-api/src/__tests__/approvalReplayComposition.test.ts` (integration, embedded Postgres): seed the system, create an item and an approved generic-operation approval request exactly the way `genericOperationGateway.test.ts`'s `createPendingDeleteAndApprove` helper does (invoke `item.delete` through `createGenericOperationGateway(pool)` with a persisted agent-run actor, catch `ApprovalRequiredError`, then `decideAndEnqueueApprovalRequest(..., decision: "approved")`), start `createApiQueueRuntime(pool, await loadFullModuleRegistry())` with `AI_GATEWAY_INTERNAL_TOKEN` set, and wait (the file's `waitFor` pattern from `queueRuntime.test.ts`) until the request's `execution_status` is terminal. Assert `execution_status = 'succeeded'`, `executed_at` set, `execution_result.result.id` equals the item id, and the item is no longer found. Do not add this case to `queueRuntime.test.ts` (edit that file).

## Acceptance criteria

- When an approved generic-operation approval request's `approvalExecute` job runs under `createApiQueueRuntime`, the operation executes (the item is deleted) and the request row reads `execution_status='succeeded'` with the operation's result; the text `No generic-operation approval replay handler is configured` never appears in `execution_result`.
- When the same job is redelivered, the request row is unchanged and no second mutation happens (already guaranteed by `replayApprovedGenericOperation`; the composition test may assert it by enqueueing `approvalExecute` twice for the same request).
