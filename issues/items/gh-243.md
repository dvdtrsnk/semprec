## Context

This issue establishes the first implementation slice of the `operations` batch. The rule "only the choke-point writes `items`" is a two-layer control: a runtime layer of Postgres roles (this slice) and a static CI layer of dependency-cruiser rules (#173). #174 builds on the completed #173 pair. This prerequisite intentionally precedes #91.

## Task

Create separate Postgres roles and give each service only its least-privileged connection:

- `semprec_data`: full privileges on the choke-point tables (`items`, `databases`, `properties`, `views`, `item_relations`, and the other tables the generic choke-point writes), sufficient to complete every generic transaction. Its connection string is known only to `packages/data`.
- `semprec_side`: `GRANT SELECT` on the choke-point tables, plus full privileges on module side tables and on the queue (graphile-worker schema).
- Deliver the roles and grants as migrations, and give each service (`semprec-api`, `semprec-agents`, `semprec-mailsync@`, `semprec-transcribe`, `semprec-ai-gateway`) only its least-privileged URL — the `semprec_data` string reaches only the choke-point in `packages/data`, everything else connects as `semprec_side`. The distinct connection strings are the "Postgres connection strings (separate roles)" entries later provisioned in `shared/.env` by #175.
- Privilege integration tests against a real database.

## Scope

### In scope

- Role/grant migrations, per-service connection configuration, privilege tests, and necessary documentation.

### Out of scope

- The dependency-cruiser dependency matrix — #173.
- CI execution — #188.
- No feature behavior changes.

## Acceptance criteria

- `semprec_side` cannot mutate choke-point item tables (INSERT/UPDATE/DELETE fail) but can operate side tables and the queue.
- `semprec_data` completes generic transactions.
- No service outside `packages/data` is configured with the `semprec_data` connection string.
