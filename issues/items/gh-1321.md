## Decisions

Decisions adopted while drafting, and questions still open for the product owner (per chunk of the batch):

### Decisions: project-mcp-1

#### (a) Adopted decisions
- Should "asks before use" be overridable per project? -> Decided by the product owner: no; v1 has only the one global setting on the tool (requires_approval per registration, all projects); a per-project override is deferred.
- Is web search an MCP server seeded by us or added by the user? -> Decided by the product owner: it is not pre-created for any tenant; the user adds it, because searching sends data out and that must be a conscious decision. No issue seeds it.
- Count tasks/tools: effective = granted + active registration + active server; server offline only because of a failed last connection still counts -> stated in the grants-list issue and reused by the project summary.
- MCP annotation mapping: readOnlyHint true -> read/no approval; else destructiveHint not explicitly false -> destructive; else openWorldHint explicitly true -> outbound; else write; no annotations -> unclassified with approval. openWorldHint counts only when explicitly true (the MCP default would otherwise classify nearly everything as outbound).
- Existing registrations at migration time: untouched defaults become classification_source=annotation, everything else manual (never lose a person's choice).
- mcp_server_connection_state primary key leads with tenant_id (repo tenancy rules) instead of the server id alone as in the notes.
- Connection result recorded only for connections made by tool calls (not by sync); a tools/call error after a successful connect counts as connected.
- display_label fallback: requesting locale, then the other locale, then tool name.
- AI label suggestion requires both cs and en; fills only empty labels; never fails the sync.
- Which signals light the attention dot? -> Decided by the product owner: all three (active drift finding, failing user heartbeat, pending approval); one dot means "needs attention" and the project detail tells the reason apart (one general mechanism).
- GET /api/projects/:id/agent-summary registered in the schemaCore manifest (owner of project agent system tables).
- touches_hint for #1447 listed mcp/mcpAgentTools.ts: not touched (the filter on mcpServerOnline in createMcpTools is sufficient); #1935 hint mcpAgentPageHandler.ts: not touched because the route is a manifest custom route.

#### (c) User-visible behavior
In a project's Semp tools, only tools of switched-on MCP servers are offered to the agent, each under a stable name that includes its server so GitHub and Linear tools with the same name no longer clash. Newly synced tools get a sensible default (read-only tools do not ask before use, destructive or outbound ones do) that a person can override and that later syncs respect. Each tool can have a Czech and English label, suggested by AI after a sync when none exists. The tool list shows each server as connected or offline with the last connection error code, and a header like "3 of 5 enabled". The project detail shows a Semp row with instructions, tool and task counts and an attention dot when instructions drift, a task fails or an approval waits.
