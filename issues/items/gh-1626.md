**Model tier:** medium

## Context

Model tier rationale: One new route over an existing thread store and the speech adapter from the gateway issue, with a cache keyed per message; the tenant and thread ownership checks are standard patterns with existing fixtures.

Under each Semp answer the client offers "Read aloud". It plays one stored message, independent of the voice mode. The ADR from #1372 chose the gateway for speech, and #1399 added the streaming text-to-speech route (`/internal/tts/stream`, accounted in `ai_gateway_calls` as `voice_synthesize`). #1543 serves thread detail and message history as route definitions in `semprec-api`.

Decisions:
- Route: `POST /api/semp/threads/:threadId/messages/:messageId/speech`, returning the audio of that message's text, optional `voice` query parameter from a closed list (default voice from the ADR).
- A message that is not in that thread, or a thread of another user or tenant, answers 404 with the same body, whichever is the cause.
- Only messages with text can be read (Semp's and the user's own); other kinds give 400.
- Cache: the synthesized audio of a (message id, voice) pair is stored once and later requests return it without calling the provider. The cache lives in the blob store as a tenant-scoped blob referenced from a small table row (key: tenant, message id, voice), removed when the message or thread is deleted.

Shared-file ordering: this issue also waits for #1620 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `ai-gateway`, `io-hardening`, `state-writes`, `db-migrations` and `testing`. Register the route in `routeMatrix.ts` and the tenant isolation test.

1. Migration `backend/packages/data/src/db/migrations/NNNN_<name>.sql` (next free ordinal at commit time): table `semp_message_speech` (tenant, message id, voice, blob id, audio seconds, created at) with composite tenant foreign keys, row level security like the other tenant tables, and cascade on message deletion.
2. A store function that returns a cached row or null, and one that stores a row after synthesis.
3. The route handler: authenticate, check the thread is the caller's and the message belongs to it, build the text, return the cached audio or call the gateway speech route, store the blob and row, and stream the audio to the client. Concurrent requests for the same key synthesize once.
4. Map gateway budget exhaustion to the usual budget error response.
5. Tests: first call synthesizes and a second call returns the cache with no gateway call; another user's thread and a message of a different thread both give 404 indistinguishably; a tenant's budget refusal is surfaced; two parallel first calls make one gateway call; deleting the message removes the cached row.

### Out of scope

## Acceptance criteria

- When a user requests the speech of a message of their own thread, then audio is returned and one gateway call is recorded.
- When the same message and voice are requested again, then no provider call is made.
- When the thread or message belongs to another user or tenant, or the message is not in that thread, then the response is the same 404.
- When the tenant's budget is exhausted, then the standard budget error is returned.
