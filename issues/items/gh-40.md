## Context

Semprec is a system running on a single self-hosted Linux server for a single user — journal, inbox, agent layer, CRDT-based sync, email integration, meeting transcription. Issues 1–19 built the entire software stack: the data model, modules, processes (`semprec-api`, `semprec-agents`, `semprec-mailsync@`, `semprec-transcribe`, `semprec-ai-gateway`), the API contract, the sync layer, notifications, the deploy tree, and the transcription pipeline.

This task (20 of 22) is the last layer of enforced boundaries around that finished software — operations. Its goal is to close four remaining open points left by earlier decisions:

1. **Caddy/TLS configuration** — the proxy layer must serve exactly the surface earlier issues defined (HTTP/2 API, WS `/api/sync`, the Graph webhook) and nothing more.
2. **Backup strategy** — what actually counts as state, how it is stored, and how a monthly mechanical test proves it can be restored.
3. **Bootstrap secrets** — up to now there were three different half-answers to the same question (an OpenBao mention, "env variable or root-owned file outside git/backups", and the `shared/.env` file already used in practice) — these are unified into a single policy here.
4. **Extending CI boundaries** — dependency-cruiser previously only guarded `modules/X` ↛ `modules/Y`; here it is closed into a complete matrix between `packages`/`modules`/`services`.

The follow-up issue #41 ("Batch meeting transcription") is out of scope for this task — addressing an unrelated concern (batch transcription of recorded meetings), with no dependency in this direction.

**Division of labor around deployment:** `provision.sh` in *this* issue creates the bare `/opt/semprec` directory tree (`releases/`, `shared/`, …) itself; `deploy.sh`, the CI gate, and the release/symlink mechanics are delivered by issue #50 ("Deployment process", 22/22), which runs on top of the tree provisioned here. This issue also defines only the *static* dependency matrix (dependency-cruiser rules); wiring those checks into a pipeline belongs to issue #50's CI gate.

## Task

Implement the operational infrastructure that puts the finished software (issues 1–19) into production on a single Linux server, as four independent pieces of work:

**1. Caddy reverse proxy**
One domain, one proxy point (`127.0.0.1:8080`), a single public-facing process (`semprec-api`). No subdomains, no CORS, no rate-limiting/auth/IP filtering at the proxy level — all of that stays in the application. A two-tier request body size limit (16 MB default, 2 GB for `POST /api/files`). The firewall (nftables) opens only 22/80/443; all internal listeners (API, gateway, Postgres, MinIO) bind to `127.0.0.1` — explicitly in the Docker compose file, not just by relying on the firewall.

**2. Backups**
An inventory of what is and isn't state to back up. Daily `pg_dump -Fc` plus `restic backup` into a single off-site S3-compatible repository, in a fixed order (dump before the MinIO directory). Retention via `restic forget --keep-daily 14 --keep-weekly 8 --keep-monthly 12 --prune`. Encryption of the entire repository by restic, with a hard rule that `SECRETS_MASTER_KEY` must never end up in the backup. A monthly systemd timer that actually restores the backup into an ephemeral environment and mechanically verifies it with a set of assertions, plus a dead-man-switch ping to an external monitor.

**3. Bootstrap secrets**
A single root-owned file `/opt/semprec/shared/.env` (mode 0600) as the sole location for every secret that must exist before the system can start at all. Complemented by `shared/apns-key.p8` for the APNs key. Distribution into processes via systemd `EnvironmentFile=` and Docker `env_file=`. A sharp boundary against `external_credentials` (runtime secrets, encrypted with the master key from this file).

**4. CI boundaries (static enforcement)**
Extend `.dependency-cruiser.cjs` with a complete forbidden-dependency matrix between `packages/`, `modules/`, and `services/` — seven new rules on top of the existing `no-module-to-module`, including enforcement of "the API process never runs the agent loop" and visibility of the privileged SQL layer restricted to inside `packages/data`.

**5. Provisioning**
A single idempotent `provision.sh` in the implementation repo (alongside `deploy.sh`, which itself ships in issue #50) that takes a bare Linux server to a state ready for its first deploy — with no manual improvisation by the operator.

## Scope

### In scope

- `Caddyfile` — the complete production configuration: automatic TLS via Let's Encrypt, HSTS without `includeSubDomains`/`preload`, compression, two mutually exclusive `request_body` matchers, `reverse_proxy 127.0.0.1:8080`, JSON access log to stderr → journald.
- Firewall configuration (nftables, ports 22/80/443) and explicit `127.0.0.1` binding of all internal listeners (Docker compose `ports:` directives, application listen addresses).
- The backup systemd unit + timer (daily at 03:30): `pg_dump -Fc` into `/var/backups/semprec/`, followed by `restic backup` over the dump directory and the MinIO data directory into the off-site repository.
- The restic retention policy (`--keep-daily 14 --keep-weekly 8 --keep-monthly 12 --prune`) and the explicit exclusion of the `shared/` directory from restic sources.
- The `semprec-restore-test` systemd timer (monthly) — an actual restore into an ephemeral environment, a set of binary assertions (see Reference), writing a `notifications` row with `kind = 'backup_restore_failed'` on step failure, and an HTTP ping to `HEALTHCHECKS_RESTORE_PING_URL` on success.
- `/opt/semprec/shared/.env` (0600, root:root) holding every bootstrap secret: `SECRETS_MASTER_KEY`, `SETUP_TOKEN`, the VAPID key pair, `APNS_KEY_PATH` plus Team/Key ID, provider API keys (Claude/DeepInfra/pyannoteAI/Voyage), OAuth client id/secret (Gmail/Graph applications), Postgres/MinIO connection strings (separate roles), `RESTIC_PASSWORD` plus off-site credentials, `HEALTHCHECKS_PING_URL`, `HEALTHCHECKS_RESTORE_PING_URL`. A values-free `.env.example` template committed to git.
- Separate Postgres roles: `semprec_data` (full privileges on choke-point tables, its connection string known only to `packages/data`) and `semprec_side` (`GRANT SELECT` on choke-point tables, full privileges on module side tables and the queue) as the runtime layer alongside the static CI check.
- `.dependency-cruiser.cjs` extension: `no-service-to-service`, `no-service-to-module`, `no-module-to-service`, `core-knows-nobody`, `pi-only-in-agent-runtime`, `agent-runtime-only-in-agents`, `no-deep-imports`, `items-store-private` — all rules matching the exact `from`/`to` path patterns given in the specification.
- `provision.sh` — an idempotent script covering: Node LTS + pnpm, Docker + Compose, Caddy, restic, `ffmpeg`/`ffprobe`, systemd unit files for all five services and all timers (dead-man switch, monthly restore test, trash purge, backup), journald configuration (`Storage=persistent` plus limits — the provisioning-level application of the retention values issue #39 defines at the app/logging level), the service user, the bare `/opt/semprec` directory tree (`releases/`, `shared/`, … — populated later by `deploy.sh` from issue #50), and a `shared/.env` template listing the required keys (without values).

### Out of scope

- **The CI pipeline and the Git→test→deploy process are not part of this task** — they are delivered by issue #50 ("Deployment process", 22/22). This issue delivers only the static dependency-cruiser matrix (rules that can be run locally or in that pipeline), not the CI system that enforces them on every push.
- The specific off-site storage provider (Backblaze B2 vs. Hetzner Storage Box) — an operator's operational choice, not an architectural decision for this issue.
- WAL-G/pgBackRest continuous WAL archiving — deliberately rejected; a daily dump is sufficient for the accepted RPO.
- OpenBao or any vault-style secrets process — deliberately rejected in favor of the root-owned file.
- Configuration-management tooling (Ansible, Nix) — deliberately rejected in favor of an idempotent shell script.
- Rate-limiting, IP allowlisting, or authentication at the proxy level — stays exclusively in the application (issue #31/#34 and earlier).
- Anything inside `services/*` processes or `modules/*` — that was built by issues 1–19; this issue only bounds their mutual communication statically.
- Issue #41 ("Batch meeting transcription") — a separate item, with no dependency in this direction.

## Dependencies

- **Email/Graph integration (#26)** — the Graph webhook `/api/webhooks/graph` as a default route behind the same proxy, `external_credentials` encryption and its boundary against bootstrap secrets.
- **Module contract / process topology (#29)** — the complete list of the five processes and their communication rule (Postgres only), which both the Caddy proxy decision and the new `services/*` dependency-cruiser rules rest on.
- **pi-agent-core / agent runtime (#30, #31)** — the `packages/agent-runtime` ↔ `semprec-agents` boundary enforced by the new `pi-only-in-agent-runtime` / `agent-runtime-only-in-agents` rules.
- **Auth/authz, `/setup`, session cookie (#34)** — `SETUP_TOKEN`, the data-layer `login_attempts` rate limit (the reason Caddy needs no rate limit of its own), and the `SameSite=Lax` cookie (the reason a single domain is sufficient).
- **Deployment process (#50)** — `deploy.sh`, the CI gate, and the releases/symlink mechanics ship in issue #50, which runs *after* this one: `provision.sh` here creates the bare `/opt/semprec` directory tree (`releases/`, `shared/`, …) itself, and issue #50's deploy mechanism must stay consistent with that tree and the `.env` location established here.
- **Notifications (#36)** — the `notifications.kind` catalog (extended here with `backup_restore_failed`), the VAPID key pair, and the APNs `.p8` key as bootstrap-secret entries.
- **Generic endpoints / WebSocket sync (#37, #38)** — the exact surface the Caddy proxy serves (HTTP/2, WS upgrade on `/api/sync`), and the choke-point write rule for `items`, which gets both a CI layer and a DB-role layer here.
- **Observability (#39)** — the existing 5-minute `HEALTHCHECKS_PING_URL` dead-man-switch mechanism and the journald log pipeline, which this issue extends (not duplicates) with a monthly restore-test channel.
- **Batch meeting transcription (#41)** — `ffmpeg`/`ffprobe` as a system dependency in `provision.sh`, `POST /api/files` as the shared binary-upload path.

This issue introduces no new data or application functionality — it is purely the operational layer over what issues 1–19 already defined, so it depends on effectively the entire queue, but almost nothing in the queue depends back on it (issue #41 merely runs on top of the infrastructure from this issue, with no architectural coupling; issue #50 deploys onto the server this issue provisions).
