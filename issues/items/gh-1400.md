## Context

Model tier rationale: A documentation-only change (one ADR) with no code, but its content is later enforced by approval metadata, so it must be precise.

Semp (the assistant) will read and edit pages through the page operation family defined by #1394. The binding ADR `docs/adr/2026-09-10-agent-writes-are-proposals-not-direct-writes.md` requires agent changes to go through the approval queue, and `docs/adr/2026-09-18-non-destructive-generic-operations-bypass-agent-approval.md` lets operations that are easy to reverse with another catalog write skip approval. Today `docs/docStore.ts` allows the `ai_agent` origin directly as a documented exception "until an approval queue exists for CRDT docs"; only a user-confirmed `pageContent` proposal writes it (`inbox/proposalActions.ts`). Page history is kept for 30 days (`openDocVersionAt` in `docs/docHistory.ts`), but there is no operation to restore a version yet (#1617 adds it).

This issue records the policy for Semp's writes to pages, so the issues that implement it (#1844, #1680) have a stable reference.

Decision: inserting blocks is allowed directly, authored as `ai_agent` (so the changes can be listed and traced); replacing a page and deleting blocks or pages require approval. `page.replace` keeps requiring approval also once version restore (#1617) exists, because it is a large destructive change.

Decision: blocks written by a proposal the user confirmed are authored `user`, because confirming makes them the user's decision; that Semp proposed them is recorded on the Inbox card (per-step block ids, #1648). `created_by` `ai_agent` therefore means exactly what Semp wrote on its own.

3. State that blocks written by a user-confirmed proposal are authored `user` (Semp's proposal is recorded on the Inbox card), so a listing filtered on `ai_agent` shows only Semp's own writes; and that `page.replace` keeps requiring approval after version restore exists.
