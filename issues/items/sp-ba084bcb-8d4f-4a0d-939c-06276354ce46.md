## Context

Model tier rationale: Removes one system database and its consumers across nine backend subsystems and three API
contracts while keeping the Event company derivation, the mail positional SQL and the Journal Inbox working.

Areas are removed (parent epic). The database is recreated from the baseline before deploy and the baseline has no
area DDL, so no migration is written. Consumers: the seed (`areas` database, its relations `projects.area`,
`events.area`, `companies.area`, `healthRecords.area`, `files.area`, `journal.area`, `sleepSettings.area`, the
`(unplanned)` area, `AREAS_MODULE_ID` in `TEN_DATABASE_MODULE_IDS`); `data/src/areas/` (write hook and
`GET /api/areas/:id/overview`); the `areaFilter` manifest contract (module-registry, `views/areaFilter.ts`,
collection metadata, related routes, facets incl. the project facet color taken from the area, schema endpoint); the
derived area (`derived/`, `valueLinkReads`, `derived.area` in `rows.ts`, `projectAttachmentAreaHook`); mail
(`areaId` filter in list/delta/facets, `areas` facet group, the area branch of the change hook); search (group and
subtitle kind `area`, area project counts, area titles, `projectItems` fan-out); inbox (target `areas`, card kind
`area`, proposal option field `area`, areas as page hosts, workspace context areas and project `areaId`, the journal
entry `areaId` with its AI prompt and response schema, `JournalInboxProposalSummary.areaItemId/areaName`,
`journalInboxCompute` returning null without an Areas database); sleep settings `areaId`; `area` in
`EVENT_RELATION_KEYS`; i18n; tests and `testSupport/tenantScopeWarnFiles*.json`.

## Task

1. Remove each consumer listed in Context, consumers before the seed, keeping the Event company derivation, its guard
   and its invalidation job.
2. Project facet values use the project's own `color`.
3. Tests that used Areas only as a convenient fixture use another database; tests of area-only behavior are deleted.
4. Update `docs/architecture/` (derived values, transactions, mail and inbox) to the new state.

## Touches

- backend/packages/data/src (seed, areas, derived, chokePoint, views, manifest, mail, search, inbox, sleep,
  calendar, agentRuns, domainWriteHooks.ts, index.ts, i18n, testSupport, __tests__)
- backend/packages/module-registry/src, backend/packages/shared/src/genericOperations, backend/packages/queue/src
- backend/services/semprec-api/src (routeMatrix, schemaHandler, journalEntryProposal, proposalContext,
  proposalComputation, searchHandler) and tests
- backend/packages/application, agent-runtime, services/semprec-agents tests that use area fixtures
- docs/architecture/

## Scope

### In scope

- Removing every backend area dependency.

### Out of scope

- Mobile (siblings 02/04, 03/04).
- Filtering tasks or mail by project tags.

## Acceptance criteria

- A new tenant has no `areas` database and no relation property keyed `area` on any database.
- `GET /api/areas/:id/overview` is no longer routed; `GET /api/schema` has no `areaFilter`.
- Search, mail facets, proposal options, inbox cards and the sleep settings response carry no area field or kind.
- The Journal Inbox computes proposals without an Areas database.
- Mail list, delta and facets filters for project, person, thread, changed and search still return the right threads.
- An Event linked to a project still reads its company derived through the project.
- A Projects facet value carries the project's own color.
- `pnpm run verify` passes in backend and web.
