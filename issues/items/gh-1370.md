## Context

Model tier rationale: The decision fixes a cross-process queue concurrency and tenant fairness contract that every later Semp turn, recovery and capacity issue builds on, so a wrong choice is expensive to reverse and the tier is raised for that uncertainty.

Every message a user sends in a Semp chat must get its own reply, a user may write in another thread while one is still being answered, and automatic ticks must not block chat. Today nothing in the queue is shaped for this. `backend/packages/queue/src/index.ts` closes the agents runtime's task catalog in `AGENT_TASK_NAMES` (`heartbeatFireAgent`, `agentRun`, `delegatedAgentRun`), and `EnqueueJobOptions` has `jobKey`, `jobKeyMode`, `maxAttempts`, `runAt` and `queueName` but no priority. A worker process runs 4 jobs at once (`QUEUE_CONCURRENCY`). `docs/adr/2026-10-08-per-tenant-queue-lanes.md` serializes work on a `<lane>:<tenantId>` queue built by `tenantLane()` (`backend/packages/data/src/tenancy/tenantLane.ts`), and heartbeat agent fires already run on their own `agent-run:<tenantId>` lane (`resolveAgentRunLane` in `backend/packages/data/src/scheduler/actions.ts`). A process that stops without a graceful stop leaves a queue's lock held until graphile-worker treats it as stale (4 hours), so the number of queues a design creates also decides how much recovery work a crash can leave behind.

The next issue (#1727) adds a `sempMessage` task that runs one thread turn. It needs to know which queue that task is enqueued on. This issue records that decision as an ADR and changes no code.

Decision: serialize Semp thread turns per tenant on one lane named through `tenantLane('semp-chat')` (first option below), not on one queue per thread. It is the conservative choice: it keeps the existing lane convention, adds no new queue per thread, needs no per-tenant cap and no cleanup of empty queues, and cannot let several threads of one tenant fill every slot of a process. Its cost is that two threads of the same tenant answer one after the other; threads of different tenants and ticks (which stay on their own lane) still run in parallel.

## Task

Load `adr-conventions`.

1. Add `docs/adr/2026-10-25-semp-thread-turns-run-on-a-per-tenant-chat-lane.md` (use the date of the day it is written; frontmatter per `docs/adr/README.md`, `area: [backend]`). It records:
   - Context: the facts above and the user-visible requirement (every sent message gets its own reply, no "busy" rejection, ticks and chat do not block each other).
   - Decision: Semp turns are enqueued with `queueName = tenantLane('semp-chat')`, giving FIFO per tenant; within a tenant the order of the queue is the order of the sent messages; tick lanes are untouched; outside a tenant scope no `sempMessage` job can be enqueued (the producer throws rather than falling back to an unnamed queue, because an unnamed queue would run turns of one tenant in parallel and break ordering).
   - Retry policy: a `sempMessage` job is enqueued with `maxAttempts: 1` and `jobKeyMode: 'unsafe_dedupe'` keyed per assistant message, because a repeated attempt would repeat tool writes, and a replacing re-enqueue would start a second run beside a running one. Retrying a failed reply is a manual user action, not a queue retry.
   - Consequences: the lane lock left by a killed process (4 hours) is handled by the recovery issue #1732; reserving worker capacity for chat is handled by #1755; the turn task itself is #1727.
   - Rejected alternatives: one queue per thread (`semp-thread:<threadId>`) with a per-tenant cap and cleanup of empty graphile_worker queues (more parallelism for one tenant, but needs a cap mechanism, queue cleanup and a larger crash-recovery surface; can be adopted later by a superseding ADR that narrows this one); no queue name (unbounded parallel turns per tenant, unordered replies); using the tick lane (a long tick would block chat).
2. State in the ADR that it does not supersede `2026-10-08-per-tenant-queue-lanes`; it adds one lane to the list of lanes that ADR describes (the ADR is append-only, so list it in `supersedes: []` as empty and link the earlier ADR in the text).
