## Context
Review of pull request #429 found that in `backend/services/semprec-api/src/__tests__/genericOperationsContract.test.ts`, both the `property.delete` case (currently around lines 195-203) and the `view.delete` case (currently around lines 235-239) assert only `expect(res.status).toBe(200)`, with no assertion on the response body. `OutputByOperation["property.delete"]` and the equivalent output shape for `view.delete` both define a full response shape, so a regression that returns the wrong shape (or an empty body) on either operation would pass these tests undetected.

## Task
- In the `property.delete` test case in `genericOperationsContract.test.ts`, add an assertion on the response body matching the shape defined by `OutputByOperation["property.delete"]`.
- In the `view.delete` test case in the same file, add an assertion on the response body matching the equivalent output shape for `view.delete`.

## Touches
- backend/services/semprec-api/src/__tests__/genericOperationsContract.test.ts (the `property.delete` and `view.delete` cases only)

## Scope
### In scope
- The two named test cases' body assertions.

### Out of scope
- Any other operation case in `genericOperationsContract.test.ts`, including the ones already covered by open issue #788.

## Acceptance criteria
- The `property.delete` test case fails if the handler returns a body missing a field from `OutputByOperation["property.delete"]`.
- The `view.delete` test case fails if the handler returns a body missing a field from the equivalent `view.delete` output shape.
