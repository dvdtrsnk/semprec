## Context

Model tier rationale: It fetches user-supplied URLs server side (SSRF and outbound-address contract), sends image content to the AI gateway, and writes a proposal whose confirm creates a tenant item, so it crosses several trust boundaries and must be right the first time.

The Inbox turns a captured item into a processing proposal that the user confirms (`inbox/inboxTickAction.ts`, `inbox/proposalActions.ts`; proposal envelope kinds `database`, `pageContent`, `relation`). The Inbox item type catalog names the `targetDatabase` of each type; types and targets are validated and extended by #1973, which this issue relies on for allowing `recipes` as a target. Today no proposal can create a recipe: the Recipes database does not exist until #1707, an Inbox item cannot carry an image until #1963, and the AI gateway (`services/semprec-ai-gateway`, `POST /internal/complete`) accepts no image content until #1381.

This issue adds a recipe proposal: when a captured Inbox item contains a link to a recipe page, or an attached photo of a recipe, the proposal computation extracts a name, ingredients, method, preparation time, servings and a photo, and offers to create a Recipes item. On confirm the item is created in the `recipes` database with the extracted properties, and its page gets an "Ingredients" bulleted list and a "Method" numbered list. The proposal shape follows the proposal contract maintained by #1471, #1892, #1912 and #1920, so the user can edit the proposed values before confirming; this issue needs that contract from #1471, #1892, #1912 and #1920 to be delivered first.

Decisions:
- The page-fetch uses the same outbound address policy as other server-side fetches (`net/outboundAddressPolicy.ts`, `docs/adr/2026-10-16-connect-time-outbound-address-checks.md`); a URL failing the baseline check (`net/storedOutboundUrl.ts`) never leaves the process.
- Extraction failure (unreachable page, no recipe found) yields no recipe proposal; the Inbox item falls back to its existing handling instead of creating an empty recipe.
- Ingredients are text on the recipe page only. Adding them to a shopping list is outside this version; there is no shopping list.

Shared-file ordering: this issue also waits for #1942 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `ai-gateway`, `io-hardening`, `error-handling`, `state-writes`, `canonical-keys` and `testing`.

1. Add a `sourceUrl` property (type `url`, owner user) to the `recipes` database for existing and new tenants through the same seeding path #1707 uses, and a create/update write hook in `backend/packages/data/src/recipes/recipeSourceUrlHook.ts` (registered in `domainWriteHooks.ts`) that rejects a `sourceUrl` failing `isBaselineOutboundUrl` with `ValidationError` on field `sourceUrl`, following `docs/adr/2026-09-27-ssrf-protection-for-stored-outbound-urls.md` and `mcpServerItemCreateHook`.
2. Add `backend/packages/data/src/inbox/recipeExtraction.ts`: for an Inbox item whose text contains an `https:` URL, fetch the page with the outbound address policy (size cap, timeout, content-type allow-list, no redirects to disallowed addresses) and send the readable text to the AI gateway; for an item with an image attachment, send the image content. The gateway call uses a response schema for `{ name, ingredients: string[], steps: string[], prepMinutes, servings, photoUrl? }`.
3. When extraction succeeds, register a `recipe` proposal writer that creates a database-kind proposal targeting `recipes`: properties `name`, `prepMinutes`, `servings`, `sourceUrl` (when from a link) and, for an image attachment, `photo` pointing at the attachment's existing blob; and page content with the ingredients as bulleted blocks under an "Ingredients" heading and the steps as numbered blocks under a "Method" heading. A `photoUrl` found on a page is fetched with the same outbound checks, stored as a blob and referenced as `photo` only when it is an image.
4. Make the `recipe` type selectable as a classification target wherever #1973 defines the allowed target list, so the Inbox can route to this writer; the seeded catalog entry is not changed here.
5. Tests: link with a recipe, photo of a recipe, URL on a loopback or private address (no fetch happens), non-recipe page, gateway failure, confirm creating the item and page blocks, and `sourceUrl` hook rejection.

## Scope

### In scope

- Link-based and photo-based recipe proposals, the `sourceUrl` property and its outbound-URL check, and writing ingredients and method to the page on confirm.

### Out of scope

- The Recipes module, its other properties and the photo write check: #1707.
- Standalone image uploads and unused-blob cleanup: #1401.
- Image support in the gateway and Inbox attachments themselves: #1381 and #1963.
- Canonical Markdown serialization of the page: #1608.
- "Ingredients to shopping" and structured ingredients: not in this version.

## Acceptance criteria

- When an Inbox item contains a link to a recipe page, then a recipe proposal appears with name, time, servings and `sourceUrl`; when confirmed, a Recipes item exists with an Ingredients bulleted list and a Method numbered list on its page.
- When an Inbox item has a photo of a recipe attached, then the proposal's `photo` references that photo's blob and confirm writes it to the new item.
- When the URL resolves to a loopback, private or link-local address, then no request is sent and no recipe proposal is created.
- When a page has no recipe or the gateway call fails, then no recipe proposal is created and the item is handled as before.
- When a recipe is written with a `sourceUrl` that is not an `https:` URL on a public host name, then the response is 400 with field `sourceUrl`.
