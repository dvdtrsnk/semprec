**Blocked by:** #230, #119

## Context

Issue #230 records every gateway call in `ai_gateway_calls`. This part uses those records to enforce two independent global caps and makes sure every agent session is structurally forced through the gateway, so no `Agent`/`AgentSession` can bypass the check. #121 reads the same table and the daily cap for the utilization report.

## Task

- **Routing.** At agents-service startup, register the existing AI gateway as the provider `baseUrl` for all supported pi models (`pi.registerProvider("anthropic", { baseUrl })` and the same for `"openai"`) exactly once — not per session, not per call — so every session (Semp's, delegated, any future type) goes through the same egress point.
- **Settings.** Add user-owned System Settings under Semprec: `dailyBudgetUsd` (default 50) and nullable `monthlyBudgetUsd` (default unlimited); null means uncapped for either.
- **Budget check.** Before each provider call, compute calendar-day and calendar-month spend in one query:
  ```sql
  SELECT
    SUM(cost_usd) FILTER (WHERE at >= date_trunc('day', now()))   AS spent_today,
    SUM(cost_usd)                                                  AS spent_month
  FROM ai_gateway_calls
  WHERE at >= date_trunc('month', now())
  ```
  and reject the call outright when either non-null cap is already exceeded, rather than letting it proceed.
- **Failure propagation.** A rejected call drives the originating `agent_run` to `status='error'` the same way as any other unrecoverable runtime error, visible in the audit trail; it is resolved by raising the cap (or setting it to unlimited) or waiting for the window to roll over.
- **Accepted imprecision.** Concurrent calls near the cap may jointly overshoot slightly (check-then-act, no lock); do not serialize gateway calls.

## Scope

### In scope

- Gateway routing, both settings, both global caps, and failure propagation.

### Out of scope

- The `ai_gateway_calls` DDL and accounting (#230).
- Per-project budgets, exact serialized ceilings, and the read endpoint/graph (#121).

## Acceptance criteria

- Each cap independently blocks later calls once exceeded, and a null cap never blocks.
- A rejected call marks its originating run as error; calls outside a run are rejected without touching `agent_runs`.
- Agent sessions send their provider requests to the gateway `baseUrl` registered at startup.
