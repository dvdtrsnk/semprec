**Model tier:** low

## Context

Model tier rationale: Four mechanical comparison operators following the existing condition pattern in the two filter-tree copies and the compiler, with no lifecycle, tenant or persisted-data contract.

The filter tree can match a number only as text: `equals` compares `properties ->> key` with a string, so "preparation time at most 30 minutes" or "rating at least 4" cannot be expressed. This issue adds numeric `lt`, `lte`, `gt` and `gte`. It builds on #1522 because both change the same two filter-tree files and the compiler, and the facet counts for number presets (#1759) and the quick filters declared in manifests (#1647) build on it.

Decision: an item without a number, or with a stored non-number, never matches any of the four (null does not satisfy a comparison, including `lt`).

## Task

Load `error-handling` and `testing`.

1. Add `lt`, `lte`, `gt`, `gte` to `FILTER_CONDITION_TYPES`, `FilterCondition` and the zod schema in `backend/packages/data/src/views/filterTree.ts` and `backend/packages/shared/src/genericOperations/filterSort.ts`, shape `{ type, property, value: number }`; `value` must be a finite number, otherwise a 400 with `field: "filter"`.
2. In `filterCompiler.ts` compile them for `number` properties and for numeric rollups (a rollup whose aggregation is not `earliest`/`latest`, read from `computed`, as `sortKeyCast` in `sortCompiler.ts` decides). Guard the cast so a stored non-number cannot raise a cast error: compare only when `jsonb_typeof(column -> key) = 'number'`, then `(column ->> key)::numeric <op> $N::numeric`. Any other property type is a 400 with the property as `field`.
3. Tests: `prepMinutes lte 30` returns the 10 and 25 minute recipes, not 35 and not the one without a time; `gte 4` on ratings; a stored non-number never matches and does not error; a non-number `value` is a 400; a date or text property is a 400; a numeric rollup is filterable.

### In scope

- The four numeric comparison conditions for number properties and numeric rollups.

### Out of scope

- Storing numeric filter presets on properties: #1622.
- Facet counts by preset: #1759.
- Relative date conditions: #1522.

## Acceptance criteria

- When `prepMinutes lte 30` is applied, then recipes with 10 and 25 minutes match and one with 35 and one without a time do not.
- When `rating gte 4` is applied, then items rated 4 and 5 match.
- When a non-finite or non-number `value` is sent, then the request fails with a 400 on `filter`.
- When the property is not a number or numeric rollup, then the request fails with a 400.
- When an item holds a non-numeric stored value, then it does not match and the query does not fail.
