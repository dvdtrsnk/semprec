**Blocked by:** #135

## Context

A project agent may advance its own time-based work, but event heartbeats have no meaningful execution without an item.

## Task

Register `heartbeat.trigger({heartbeatId})`, scoped from the current persisted run exactly like list/history. For `dailyTime`, `weekly`, `interval`, and `everyNDays`, enqueue the existing heartbeat execution payload `{heartbeatId,triggeredByRunId}`; the handler writes `triggered_by='heartbeat'`, `heartbeat_id`, and `parent_run_id=triggeredByRunId`. Use manual key `heartbeat-fire:manual:${heartbeatId}` distinct from scheduler key `heartbeat-fire:${heartbeatId}`. An event rule returns 409 `heartbeat_event_triggered` and enqueues nothing. Do not require capability or approval beyond the tool's project-scoped availability. Manual execution must not modify schedule timestamps; audit fix #84 later adds scheduled occurrences while preserving this discriminator branch.

## Scope

### In scope

- Tool, rule validation, payload attribution, distinct dedup key, and canonical error.

### Out of scope

- Run-now UI, event trigger without item, approval, and scheduled-occurrence generation.

## Acceptance criteria

- Manual and pending scheduled work cannot overwrite attribution.
- Repeated pending manual triggers collapse to one job.
- Event rule returns the exact 409 without side effects.
- Child run history identifies the invoking parent.
