**Blocked by:** #95

## Context

Mailbox navigation and reading require a dedicated registered view while still consuming generic database operations.

## Task

Register `mailbox-client` as a view type and implement a folder/label sidebar with unread counts, message list, and reading pane. On narrow layouts and iOS-sized viewports, show one pane at a time with an explicit back action. Filter through the Emails-to-Folders relation and use generic query/item operations; do not add a mailbox-only read data path. Follow the existing client tokens, i18n, loading, empty, and error conventions.

## Scope

### In scope

- Registered view, responsive pane state, folder selection, list selection, reading display, and unread counts.

### Out of scope

- Triage shortcuts, compose/reply, sending logic, and copying Roundcube code.

## Acceptance criteria

- The view resolves through the registered view mechanism.
- Desktop shows three panes; narrow layout provides navigable single-pane behavior.
- Folder filtering and message loading use generic operations.
- Loading, empty, unavailable, and retryable-error states are tested.
