## Context

Model tier rationale: A new aggregate read route over the central mail tables with cross-mailbox deduplication, a keyset cursor and a constant-query-count requirement, where wrong predicates silently miscount mail for every user.

The Mail screen shows one row per conversation, newest first. The backend has no such route: the only mail route is the Microsoft Graph webhook (`backend/services/semprec-api/src/routeMatrix.ts`), and a client can only list single messages through `POST /api/databases/:id/query`. Threads exist as `mail_threads` and `mail_message_meta.thread_id` (`0006_mail_sync.sql`), and messages sent from Semprec and copies of one message in several mailboxes now share threads (#1474, #1384); drafts and sent mail are read, so they do not count as unread (#1461). The preview and arrival time come from #1468.

Facts the query relies on: the same message in two mailboxes is two Emails items sharing a `message_id`; `Emails.date` is set only when the message has one (otherwise `mail_message_meta.ingested_at` is used); folders are Folders items related to Emails with a `specialPurpose` (`inbox|sent|junk|trash|drafts|archive|all|none`); people are found by address in `person_email_index`; the `People` database has `name` and `relationship`; the user's own addresses are `Mailboxes.addresses`.

All mail routes are custom routes declared in `backend/packages/data/src/mail/mailModuleManifest.ts` with a `routeMatrix.ts` entry (justification `single-consumer-read`). Filters (box, folder, mailbox, unread) are added by #1633; the thread detail by #1632; project and company by #1897; the Semp draft flag by #1694.

Decisions: until those land, the list returns every thread that has at least one counted message, `project` and `company` are `null` and `hasSempDraft` is `false`; `participants` is the distinct `{ name, address }` pairs over from/to/cc of the counted messages in order of first appearance; `flagged` is true when any counted message is flagged.

Shared-file ordering: this issue also waits for #1559 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `canonical-keys` and `testing`.

1. Add the migration `backend/packages/data/src/db/migrations/NNNN_mail_message_meta_tenant_thread_idx.sql` (next free ordinal at commit time) with an index on `mail_message_meta (tenant_id, thread_id)` (use `CREATE INDEX CONCURRENTLY` if the migration runner allows it, otherwise a plain `CREATE INDEX IF NOT EXISTS`).
2. Implement the aggregate in `backend/packages/data/src/mail/mailThreadListQuery.ts` as one SQL statement grouped by `thread_id`, over counted messages: Emails items that are not deleted, not only in a Drafts folder, distinct by `message_id` (a message in several mailboxes counts once). Per thread return the fields below.
3. Response of `GET /api/mail/threads`, with query `limit` (1 to 200, default 50) and `cursor`: `{ threads: [...], nextCursor: string | null }`. Each thread: `threadId`, `subject`, `lastMessageAt`, `lastSender { name, address, personId | null }`, `participants`, `messageCount`, `preview` (of the last message), `hasAttachment`, `unread`, `flagged`, `mailboxes [{ id, name, provider }]` (all mailboxes holding a counted copy), `senderPerson { id, name, relationship } | null`, `project` (null), `company` (null), `hasSempDraft` (false).
4. Rules: `lastMessageAt` is the latest counted message's `Emails.date`, falling back to its `ingested_at`; `messageCount` includes own sent messages; own means the envelope sender address is in the `addresses` of any of the tenant's mailboxes; `unread` is true when an incoming (not own, not in Sent or Drafts) counted message has `read` not true; `senderPerson` is found through `person_email_index` by the address of `lastSender`, not through `senderPeople` edges.
5. Order by `lastMessageAt` descending, then `threadId` descending. The cursor is an opaque string encoding `(lastMessageAt, threadId)`; an invalid cursor or limit is a validation error (400).
6. Declare the route in `mailModuleManifest.ts` (`handlerExport` `createMailThreadListRouteHandler`, exported from the manifest module) and add it to `ROUTE_MATRIX` in `routeMatrix.ts` with tenancy `tenant`. The handler reads the query string from `ctx.req.url`.
7. Add tests with the fixture thread "Re: Nabídka na web" style conversation: four messages, two sent by the user, an attachment on a sent one, returning `messageCount` 4, the last incoming sender and the preview of the last message; a message in two mailboxes counted once with both mailboxes listed; a provider draft and a Semprec draft changing neither `lastMessageAt` nor `messageCount`; 50 threads fetched with a constant number of queries; a second tenant's threads absent; paging over a cursor with equal timestamps.

## Scope

### In scope

### Out of scope

- Box, folder, mailbox and unread filters: #1633.
- Text search and operators: #1639.
- Project and company values: #1897; the Semp draft flag: #1694.
- The thread detail: #1632.

## Acceptance criteria

- When a conversation has four messages including two sent by the user, then its row has `messageCount` 4, the last incoming sender as `lastSender` and the last message's preview.
- When one message exists in two mailboxes, then it counts once and `mailboxes` lists both.
- When a provider draft or a Semprec draft is added to a thread, then `lastMessageAt`, `messageCount` and `preview` do not change.
- When 50 threads are listed, then the number of SQL statements does not depend on the number of threads.
- When there are more threads than `limit`, then `nextCursor` returns the next page without gaps or repeats.
- A request for another tenant's data returns nothing from this tenant's threads.
