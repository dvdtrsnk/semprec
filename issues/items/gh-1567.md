## Context

Model tier rationale: Cross-mailbox deduplication, keyset paging and aggregate counts require precise SQL and tenant isolation.

Mail needs one newest-first row per thread. Tables come from 0006; sends and cross-mailbox copies share threads (#1474/#1384), drafts/sent are read (#1461), preview/arrival metadata is #1468.

Facts the query relies on: the same message in two mailboxes is two Emails items sharing a `message_id`; `Emails.date` is set only when the message has one (otherwise `mail_message_meta.ingested_at` is used); folders are Folders items related to Emails with a `specialPurpose` (`inbox|sent|junk|trash|drafts|archive|all|none`); people are found by address in `person_email_index`; the `People` database has `name` and `relationship`; the user's own addresses are `Mailboxes.addresses`.

All mail routes are custom routes declared in `backend/packages/data/src/mail/mailModuleManifest.ts` with a `routeMatrix.ts` entry (justification `single-consumer-read`). Filters (box, folder, mailbox, unread) are added by #1633; the thread detail by #1632; project and company by #1897; the Semp draft flag by #1694.

Decisions: until those land, the list returns every thread that has at least one counted message, `project` and `company` are `null` and `hasSempDraft` is `false`; `participants` is the distinct `{ name, address }` pairs over from/to/cc of the counted messages in order of first appearance; `flagged` is true when any counted message is flagged.

Shared-file ordering: this issue also waits for #1559 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

Per thread return the fields below.
3. Response of `GET /api/mail/threads`, with query `limit` (1 to 200, default 50) and `cursor`: `{ threads: [...], nextCursor: string | null }`. Each thread: `threadId`, `subject`, `lastMessageAt`, `lastSender { name, address, personId | null }`, `participants`, `messageCount`, `preview` (of the last message), `hasAttachment`, `unread`, `flagged`, `mailboxes [{ id, name, provider }]` (all mailboxes holding a counted copy), `senderPerson { id, name, relationship } | null`, `project` (null), `company` (null), `hasSempDraft` (false).
4. Rules: `lastMessageAt` is the latest counted message's `Emails.date`, else its `ingested_at`, else that counted copy's `items.updated_at` for legacy nulls (the #1468 backfill approximation); `messageCount` includes own sent messages; own means the envelope sender address is in the `addresses` of any of the tenant's mailboxes; `unread` is true when an incoming (not own, not in Sent or Drafts) counted message has `read` not true; `senderPerson` is found through `person_email_index` by the address of `lastSender`, not through `senderPeople` edges.
5. Order by `lastMessageAt` descending, then `threadId` descending. The cursor is an opaque string encoding `(lastMessageAt, threadId)`; an invalid cursor or limit is a validation error (400). Preserve PostgreSQL timestamp precision; paging is not a cross-request snapshot.
6. Declare the route in `mailModuleManifest.ts` (`handlerExport` `createMailThreadListRouteHandler`, exported from the manifest module) and add it to `ROUTE_MATRIX` in `routeMatrix.ts` with tenancy `tenant`. The handler reads the query string from `ctx.req.url`.
7. Add tests with the fixture thread "Re: Nabídka na web" style conversation: four messages, two sent by the user, an attachment on a sent one, returning `messageCount` 4, the last incoming sender and the preview of the last message; a message in two mailboxes counted once with both mailboxes listed; a provider draft and a Semprec draft changing neither `lastMessageAt` nor `messageCount`; 50 threads fetched with a constant number of queries; a second tenant's threads absent; paging over a cursor with equal timestamps; date/ingest/legacy-update priority with both legacy values null.

## Acceptance criteria

- When a conversation has four messages including two sent by the user, then its row has `messageCount` 4, the last incoming sender as `lastSender` and the last message's preview.
- When one message exists in two mailboxes, then it counts once and `mailboxes` lists both.
- When a provider draft or a Semprec draft is added to a thread, then `lastMessageAt`, `messageCount` and `preview` do not change.
- When 50 threads are listed, then the number of SQL statements does not depend on the number of threads.
- When there are more threads than `limit`, then `nextCursor` returns the next page without gaps or repeats.
- A request for another tenant's data returns nothing from this tenant's threads.
