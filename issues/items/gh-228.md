**Blocked by:** #115, #83

## Context

Agent runs need a durable protocol log before sessions can be resumed or observed. This part introduces `packages/agent-runtime` as a thin wrapper over the external `pi-agent-core` loop and creates the turn-level log `agent_run_events`, mapping pi's lifecycle sequence onto `agent_runs` and that log. The sibling part #117 builds on this adapter to add the live push hook and the startup repair sweep. #118 uses the `unit='session'` handling defined here for delegated and user sessions, #119 reconstructs conversations from the rows written here, and #120 links gateway calls to the run rows.

## Task

- **Wrapper.** Build the `packages/agent-runtime` wrapper around public `createAgentSession()` and the `systemPromptOverride` hook from `pi-agent-core`.
- **DDL.** Create `agent_run_events` as a numbered structural migration applied by the runner from #224:
  ```sql
  CREATE TABLE agent_run_events (
    id bigserial PRIMARY KEY,                 -- monotonic cursor: resume and Entry[] reconstruction ordering
    agent_run_id uuid NOT NULL REFERENCES agent_runs(id),
    kind text NOT NULL,                       -- 'turn_start' | 'message' | 'tool_use' | 'tool_result' | 'turn_end' | 'run_status'
    payload jsonb NOT NULL,                   -- full message (AgentMessage shape) -- source for reconstruction, not just display
    at timestamptz NOT NULL DEFAULT now()
  );
  CREATE INDEX agent_run_events_run_idx ON agent_run_events (agent_run_id, id);
  ```
  Verify that `agent_runs` already carries `heartbeat_id`, `parent_run_id`, `triggered_by`, and `unit` (present in `backend/packages/data/src/db/migrations/0001_core_schema.sql`); do not duplicate that DDL.
- **Lifecycle mapping.** `agent_start` → `INSERT agent_runs (status='running', started_at=now(), triggered_by, project_item_id, parent_run_id)`. `turn_start`, each completed `message`, `tool_use`/`tool_result`, `turn_end`, and run-status changes → one `agent_run_events` row each, with the full `AgentMessage` payload. `agent_end` → `UPDATE agent_runs SET status='done'|'error', finished_at=now()`; the `task`/`result` columns hold only the first request and the last response as a snapshot.
- **Unit handling.** Set `unit='invocation'` for one-shot runs (heartbeat/MCP-triggered) and `unit='session'` for managed conversations; expose the choice as a parameter of the adapter so #118 can mark the sessions it manages.
- **Deltas.** Never persist `message_update` streaming deltas in any table. The push hook that makes them observable live is added by #117; in this part the adapter exposes an event callback with no subscriber.

## Scope

### In scope

- The wrapper, the `agent_run_events` DDL and index, the lifecycle adapter, final snapshots on `agent_runs`, and `unit` handling.

### Out of scope

- The live push hook and the startup repair sweep (#117).
- WebSocket replay protocol, session reuse (#118), reconstruction (#119), MCP, and persistent deltas.

## Acceptance criteria

- A completed run's transcript reconstructs from `agent_run_events` in monotonic event-id order and contains every turn start/end, completed message, tool use/result, and run-status change.
- `message_update` deltas are absent from PostgreSQL after a run.
- Runs created through the adapter carry the `unit` value the caller chose, with `invocation` as the default.
