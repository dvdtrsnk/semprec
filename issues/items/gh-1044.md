## Context

Model tier rationale: The origin rule, its two enforcement points and the ADR content are specified exactly.

Browser sessions authenticate with the cookie `Path=/; HttpOnly; Secure; SameSite=Lax` (`backend/services/semprec-api/src/authHandler.ts:66`). `SameSite=Lax` keeps the cookie off cross-*site* subresource requests, but not off requests from a different origin on the same site, such as a sibling subdomain. Neither entry point checks `Origin`:
- `dispatch` (`backend/services/semprec-api/src/app.ts:104-106`) routes every method straight to its listener;
- the `WS /api/sync` upgrade goes from `server.on("upgrade")` (`backend/services/semprec-api/src/serve.ts:140-149`) through `createSyncUpgradeHandler` (`backend/services/semprec-api/src/syncHandler.ts:13-26`) to authentication.

So a page on another origin can drive state-changing requests and open a cookie-authenticated socket (cross-site WebSocket hijacking). Once several users exist, that is one user's page acting as another user.

There is no configured public origin to compare against. `APP_BASE_URL` defaults to `http://localhost:3000` (`serve.ts:61`) and is declared in `deploy/shared/.env.example` by #977 but not enforced. In development the web client runs on the Vite dev server, whose proxy forwards `/api` (with `ws: true`) and `/mcp` to the API without rewriting `Host` or `Origin` (`web/vite.config.ts:16-19`). In production Caddy's `reverse_proxy` passes `Host` through (`deploy/Caddyfile`). In both, a same-origin browser request arrives with `Origin`'s host equal to the request's `Host`.

Non-browser clients send no `Origin`:
- native clients;
- MCP clients on `/mcp` with a bearer token;
- the Microsoft Graph webhook (`POST /api/mail/graph/webhook`);
- `curl`.

Browsers send `Origin` on every WebSocket handshake and on every non-GET/HEAD request.

What earlier issues provide: #1025 wired the tenant into the sync server. #1043 is the earlier edit of `app.ts`'s dispatcher.

## Task

Load `io-hardening` (an inbound edge check) and `adr-conventions` (new cross-cutting rule).

1. **The rule.** New `backend/services/semprec-api/src/originCheck.ts` exports `isAllowedOrigin(req: IncomingMessage): boolean`:
   - `true` when the request has no `Origin` header;
   - otherwise `true` only when `Origin` parses as an `http:` or `https:` URL whose `host` (hostname plus port, lowercase) equals the request's `Host` header (lowercase);
   - `false` for `Origin: null`, an unparseable value, another scheme, a missing `Host`, or a mismatch.

   It never reads `X-Forwarded-Host` or any other client-settable forwarding header.
2. **Unsafe methods.** In `dispatch` (`app.ts:104-106`), before any routing, every method other than `GET`, `HEAD` and `OPTIONS` that fails `isAllowedOrigin` is answered `403` with `sendJson(res, 403, { error: { code: "origin_not_allowed" } })`. No listener runs. One `logger.warn({ method, path }, "origin_not_allowed")` is logged without headers or the origin value. Requests that pass are routed exactly as today.
3. **WebSocket upgrade.** `createSyncUpgradeHandler` returns a `SyncServer` whose `handleUpgrade` checks `isAllowedOrigin(req)` before delegating to the sync server's own `handleUpgrade`. On failure it writes `HTTP/1.1 403 Forbidden\r\nConnection: close\r\nContent-Length: 0\r\n\r\n` and destroys the socket, without calling `authenticate`. Build the wrapper as `{ ...syncServer, handleUpgrade }`, so `close()` and any member added to `SyncServer` later (e.g. #1042's `closeTenant`) are forwarded unchanged. `serve.ts` and `backend/packages/realtime` are not changed.
4. **ADR.** Add `docs/adr/<YYYY-MM-DD>-same-origin-check-on-unsafe-requests.md`. It records:
   - the Host-comparison rule and the accepted absence of `Origin` for non-browser clients;
   - the methods covered and the upgrade;
   - rejected alternatives: an `APP_BASE_URL` allowlist (wrong in development behind the Vite proxy), CSRF tokens (a client protocol change), and `SameSite` alone (same-site, cross-origin pages).
5. **Tests.**
   - Unit-test `isAllowedOrigin`.
   - Write integration tests over `createDispatcher` for the HTTP rule, as `backend/services/semprec-api/src/__tests__/itemsHandler.test.ts` does.
   - Extend `backend/services/semprec-api/src/__tests__/syncHandler.test.ts` for the upgrade.

## Scope

### In scope
- The same-origin rule, its enforcement on unsafe HTTP methods and on the `WS /api/sync` upgrade, and the ADR.

### Out of scope
- `Cache-Control: no-store` on API responses (#1072).
- Throttling login, password reset and invitation acceptance (#1073).

## Acceptance criteria

- **The rule.** `isAllowedOrigin` returns:
  - `true` for no `Origin`, and for `Origin: https://app.example` with `Host: app.example`;
  - `true` for `http://localhost:5173` with `Host: localhost:5173`;
  - `false` for a different host or port, for `Origin: null`, for an unparseable value, for `file://…`, and for an `Origin` present with no `Host`.

  (unit, `originCheck.unit.test.ts`)
- **Foreign origin refused.** A `POST /api/databases/:id/items` with a valid session cookie and `Origin: https://evil.example` gets `403` with `{"error":{"code":"origin_not_allowed"}}`, and no item is created. The same holds for `PATCH`, `DELETE` and `POST /api/auth/logout`. (integration, `originCheck.test.ts`)
- **Allowed requests untouched.** The same requests with a matching `Origin`, or with no `Origin`, behave exactly as before. A `GET` with a foreign `Origin` is not refused. (integration, `originCheck.test.ts`)
- **Upgrade with foreign origin.** It receives `403` before authentication: no socket opens, and the `authenticate` callback is not invoked, even with a valid session. (integration, `syncHandler.test.ts`)
- **Upgrade allowed.** A `WS /api/sync` upgrade with a valid session and a matching `Origin`, or with no `Origin`, opens a socket as before. (integration, `syncHandler.test.ts`)
- **Existing suites unchanged.** The existing API integration suites pass unchanged: they send no `Origin`. (integration)
- **Log and ADR.** A refused request logs exactly one `origin_not_allowed` warning with `method` and `path` and no header or origin value (integration, `originCheck.test.ts`); the ADR exists and records the Host rule, the covered methods and the upgrade, and the rejected alternatives (review).
