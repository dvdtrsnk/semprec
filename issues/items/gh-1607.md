## Context

Model tier rationale: One create hook and one update hook on a single database following the Events validation hooks and existing fixtures, with no new lifecycle, tenant or persisted-data contract.

Nothing checks a transaction's values today. #1511 creates the `transactions` database with `amount` (number) and `currency` (select); #1553 links it to companies, projects and documents. Without validation a client could store a zero or negative amount (the sign is carried by `type`, expense or income, not by the number) or a transaction without a currency, and the monthly summary of #1585 would add garbage.

Item hooks (`backend/packages/data/src/chokePoint/hooks.ts`, registered in `backend/packages/data/src/domainWriteHooks.ts`) run inside the write's transaction and can reject by throwing `ValidationError` (`backend/packages/data/src/errors.ts`), which becomes HTTP 400 `validation_failed` with `details.field`. REST, the assistant's `item.patch`, MCP and the Inbox confirm all go through the choke point and get the same error.

Decision: a transaction's `amount` must be a finite number greater than zero for both expense and income. Reason: the type states the direction; storing signed numbers would make two ways to say the same thing.
Decision: only `CZK` is accepted as currency for now; the select options already restrict this, so the hook checks presence, not the value.
Decision: validation applies only to keys present in an update, so editing a note on an existing row never fails.


Shared-file ordering: this issue also waits for #1603 because both edit the same files listed in Touches.

## Task

Load `error-handling`, `state-writes` and `testing`.

1. Create `backend/packages/data/src/finance/transactionValuesHook.ts` exporting a create hook and an update hook for the `transactions` database (matched by the database's `owner_module_id`).
2. On create: `amount` is required and must be a finite number greater than 0, otherwise `ValidationError` with `field: "amount"`; `currency` is required, otherwise `field: "currency"`. On update, check each of these only if it is in the patch (a patch that sets `amount` to `null`, 0, a negative or a non-number fails the same way; clearing `currency` fails).
3. Register both hooks in `domainWriteHooks.ts`.
4. Tests for REST, an agent `item.patch` and MCP (identical error body): `amount` 0, -5, `"12"`, `null` and a missing amount fail with `field` `amount`; a missing currency fails with `field` `currency`; a valid expense and a valid income are stored; a patch that changes only `note` succeeds on a row with stored values; a write to another database is unaffected.

## Scope

### In scope

- Required, positive `amount` and required `currency` on transaction create and update, on every write path.

### Out of scope

- The links to companies, projects and documents: #1553.
- Validating `dueDate`, `paymentStatus` and `paidAt` relationships, such as requiring `paidAt` for paid expenses; not planned yet.
- Several currencies; not planned yet.

## Acceptance criteria

- When a transaction is created with `amount` 0 or -5, then the response is 400 `validation_failed` with `details.field` `amount`.
- When a transaction is created without `currency`, then the response is 400 with `details.field` `currency`.
- When a transaction with `amount` 4820, `currency` `CZK` and `type` `expense` is created, then it is stored.
- When a patch changes only `note` on an existing transaction, then it succeeds.
- When an assistant `item.patch` or an MCP write sends `amount` 0, then it receives the same error body as REST.
