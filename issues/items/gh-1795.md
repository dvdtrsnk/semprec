## Context

Model tier rationale: One known mechanism (two user-owned properties on a locked system database, a validating write hook and a per-tenant cutover) across defined seed, hook and cutover seams, with the People.emails and transcripts cutovers as fixtures.

The People database has `name`, `relationship` and `contact` (`backend/packages/data/src/seed/seedTenDatabases.ts`) and `emails` (added by `seedEmailModuleInTransaction`). There is no birthday, and People is `schema_locked`, so an existing tenant can receive a property only through a code-level cutover that writes SQL directly (`transcription/transcriptsCatalogCutoverMigration.ts` is the pattern). Date filters and sorts cast a `date` value to `timestamptz` (`views/filterCompiler.ts`, `views/sortCompiler.ts`), so a value that is not a full valid date, such as `--MM-DD`, would break a People view sorted or filtered by it.

This issue adds the data the calendar needs to show birthdays: `People.birthday` (a full valid date `YYYY-MM-DD`) and `People.birthdayYearKnown` (checkbox), both owned by the user. The timeline source that turns them into calendar entries is #1800.

Decision: when the year is not known, the client stores a placeholder leap year (2000) with `birthdayYearKnown` false, so a birthday on 29 February is storable; the calendar uses only month and day. The backend does not rewrite the year; it only requires a real calendar date.

Decision: an empty `birthday` (null or absent) is valid and clears it.

Shared-file ordering: this issue also waits for #1793 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `canonical-keys`, `state-writes` and `testing`.

1. In `backend/packages/data/src/seed/seedTenDatabases.ts`, add to the People property list `birthday` (type `date`, owner user, no time) and `birthdayYearKnown` (type `checkbox`, owner user). Add their display names `property.people.birthday.name` ("Birthday" / Czech "Narozeniny") and `property.people.birthdayYearKnown.name` ("Year known" / "Rok znám") to `backend/packages/data/src/seed/i18n/cs.json` and `en.json`.
2. Add the cutover `backend/packages/data/src/calendar/peopleBirthdayCutoverMigration.ts` that inserts the two property definitions into each existing People database by direct SQL (identical to the seed; `LOCK TABLE properties IN EXCLUSIVE MODE` as the pattern does), idempotent, skipped when the tenant has no People database. Register it in `runTenantCutoverMigrations` in `backend/packages/data/src/db/tenantCutoverMigrations.ts`.
3. Add `backend/packages/data/src/calendar/personBirthdayHook.ts` with create and update hooks for the People database: when `birthday` is written and is not null, it must be a string `YYYY-MM-DD` that is a real calendar date (checked with luxon, round-trip equal), otherwise `ValidationError` (400 `validation_failed`, field `birthday`). Register them in `backend/packages/data/src/domainWriteHooks.ts`.
4. Tests: a fresh seed and a cut-over tenant have identical definitions; the cutover is idempotent and skips a tenant without People; `birthday` `2000-10-16` with `birthdayYearKnown` false is stored; `2026-13-01`, `2026-02-30` and `--10-16` are 400 with field `birthday`; `2000-02-29` is stored; `null` clears; a People view sorted by `birthday` does not fail; a person without a birthday is unaffected.

### Out of scope

- Birthday entries in the calendar timeline: #1800.
- Public holidays: #1804.
- Birthday reminders: they depend on the reminder issues and on the Birthdays calendar's `notify` flag.
- The People inverse of Events: #1664.

## Acceptance criteria

- When a person is saved with `birthday` `2000-10-16` and `birthdayYearKnown` false, then both are stored.
- When `birthday` is `2026-13-01` or any non-date, then the response is 400 `validation_failed` with field `birthday`.
- When a People view is sorted by `birthday`, then it succeeds.
- When the cutover runs for an existing tenant, then People gains both properties; a second run changes nothing.
