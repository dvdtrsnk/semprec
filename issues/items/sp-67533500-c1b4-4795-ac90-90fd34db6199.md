## Context

Model tier rationale: One constant and the tests and documents that state its value.

End-to-end finding: a manual calendar sync request within 60 s of the previous one is deferred to the end of a 60 s window (`MANUAL_CALENDAR_SYNC_DEBOUNCE_SECONDS` in `calendar/sync/calendarAccountSyncJob.ts`, applied by `recordManualCalendarSyncRequest`), so a person who edits an event at the provider and asks to sync twice waits up to a minute for the change.

Decision: the window becomes 15 s. Coalescing stays as it is: one upsert decides the run time, a request inside the window queues one deferred pass at its end, and while that pass is still ahead it serves every further request, so repeated taps queue at most one deferred pass.

## Acceptance criteria

- A request one second after a pass queues one deferred pass at the end of a 15 s window; a third request in that window keeps the same single job and run time.
- A request more than 15 s after the deferred pass runs at once.
