**Blocked by:** #1421
**Model tier:** medium

## Context

Model tier rationale: One extra ffmpeg rendition in the existing prepare step with a strict timeline-equality requirement and checkpoint extension, verified by fixtures rather than a new contract.

The app plays a recording from `GET /api/blobs/:id` (`backend/services/semprec-api/src/blobsHandler.ts`: Range, ETag, bearer or cookie; audio is always sent as an attachment; no signed URLs). The original is `Files.properties.file.blobId`; the normalized copy for ASR is `computed.prepare.normalizedBlobId` (Ogg Opus, 16 kHz mono, `mediaNormalization.ts`), which an iOS player cannot reliably seek in. Segment times (`startsAt`, `endsAt`) are on the normalized file's timeline. ffmpeg may run only in `semprec-transcribe` (`docs/adr/2026-09-22-ffmpeg-confined-to-semprec-transcribe.md`).

This issue makes the prepare step produce a file the app can play and seek, on the same timeline as the segments: the original when it is `audio/mp4`, `audio/mpeg` or `audio/wav`, otherwise an AAC m4a mono 64 kbit/s rendition created from the same decoded input, stored as `computed.prepare.playbackBlobId` and returned by the transcript endpoint as `playback { blobId, mimeType }` (#1576). The iOS client downloads it with an Authorization header to its cache; deep links by time are client work. It builds on #1421 (derived blobs are purged with their Files item).

Decision (by the product owner): no short-lived signed URL is added; the client uses the authenticated blob route with its local cache. A signed URL is added only if a real problem with the cache shows up. A token in a query or path would need a new ADR with an exception to `docs/adr/2026-10-17-secret-link-tokens-travel-in-the-url-fragment.md`.

## Task

Load `io-hardening`, `state-writes` and `testing`.

1. In `mediaNormalization.ts` add `renderPlaybackAudio` that encodes AAC m4a, mono, 64 kbit/s from the same decoded input as `normalizeAudio` and discards the container `start_time` exactly as the Opus path does, so both share one timeline. Stream to storage with the same cleanup on failure.
2. In `runPrepareStep` choose: original reused (no new blob) for `audio/mp4`, `audio/mpeg`, `audio/wav`; otherwise (video, Ogg, others) create the rendition and its blob row. Store `playbackBlobId` in the prepare checkpoint (extend the checkpoint schema, tolerate checkpoints without it).
3. Register the new blob for purge with the derived-blob mechanism of #1421.
4. Tests with fixtures: an iPhone m4a, a video whose audio track starts late, an Ogg file.

## Scope

### In scope

- The playback rendition, its checkpoint field and blob, and reuse of the original for supported types.

### Out of scope

- Exposing `playback` in the transcript endpoint: #1576.
- Purging derived blobs: #1421.
- Signed playback links: not in v1 (decided by the product owner).
- The iOS player and deep links.

## Acceptance criteria

- When a rendition is made, then its duration differs from `durationSeconds` by less than 0.1 s.
- When seeking to a segment's `startsAt`, then it matches the spoken word for an iPhone m4a and for a video whose audio starts late.
- When the original is `audio/mp4`, then no additional blob is created.
