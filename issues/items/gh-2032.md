## Context

Model tier rationale: An item restore hook that recreates sync state and brings back a whole mailbox's folders and messages inside the restore transaction is a wide data change, checked end to end through the reauthorization flow.

#1690 removes a mailbox: the item goes to the trash with `syncStatus` `needsReauthorization`, and its credential and sync state are deleted. The removal job of #2029 then soft-deletes the mailbox's Folders and Emails, stamping them with the mailbox's own deletion time; they are not children of the mailbox in the item tree, so the trash restore does not bring them back by itself. Items in the trash can be restored within 30 days, but a restored mailbox would have no `mail_account_sync_state` row, so the sync job and the reauthorization flow would find no state. #1601 adds item restore hooks to the choke point (`registerItemRestoreHook` in `backend/packages/data/src/chokePoint/hooks.ts`), composed per process in `backend/packages/data/src/domainWriteHooks.ts`. #1742 lets the user sign in again; it accepts the signing-in address when the stored provider address is null and no other mailbox of the tenant holds it.

Decision (made by the product owner): restoring a removed mailbox brings back the mailbox and its messages with `syncStatus` `needsReauthorization` and a default sync state for its provider; the user then signs in again.

Shared-file ordering: this issue also waits for #1723 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `testing`.

1. Add `backend/packages/data/src/mail/mailboxRestoreHook.ts`: an item restore hook for the Mailboxes database that, in the restore transaction, recreates the default `mail_account_sync_state` row for the mailbox's provider (the same defaults a newly connected mailbox gets) and keeps `syncStatus` `needsReauthorization`. If a sync state row already exists, it changes nothing. In the same transaction it restores the mailbox's Folders and Emails whose deletion time equals the mailbox's (the rows the removal job soft-deleted), through the choke point restore; rows trashed independently at another time stay in the trash.
2. Register the hook in `domainWriteHooks.ts`.
3. Tests: restoring a removed mailbox creates the default sync state, the mailbox shows `syncStatus` `needsReauthorization`, and its folders and messages are listed again while a message trashed separately before the removal stays in the trash; restoring it twice creates one row; a failing hook leaves the mailbox in the trash; after the restore, reauthorization through #1742 resumes sync and the messages restored with the mailbox are not duplicated; a second tenant is untouched.
