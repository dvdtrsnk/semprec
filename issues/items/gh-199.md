## Context

Second of two parts of the write-back slice, completing the `mail-live-sync` batch (approved behavior in #194). #251 delivered the mutation-event consumer, the desired/current state persistence with echo suppression, and the IMAP adapter, leaving Gmail and Graph as pending stubs. This part fills those stubs using the Gmail history sync of #197 and the Graph webhook sync of #198, and proves convergence across all three providers.

## Task

- Implement the Gmail adapter: `users.messages.modify` adding/removing the `UNREAD` and `STARRED` labels for the four transitions, updating the current state on success.
- Implement the Graph adapter: `PATCH` on the message setting `isRead` and the flag status for the four transitions, updating the current state on success.
- Flush desired states left pending by #251 for Gmail and Graph accounts once the adapters are available.
- Provider failure uses the existing sync error/retry; a later reconcile (history for Gmail, delta for Graph) converges on the desired state without oscillation between our state and the provider's.

## Scope

### In scope

- Gmail and Graph write-back adapters, pending-state flush, convergence/oscillation tests for all providers, cross-client round-trip verification, and necessary documentation.

### Out of scope

- Consumer, state persistence, IMAP adapter — #251.
- Schema and UI controls — #90 / #27.

## Acceptance criteria

- All four transitions work for the fake Gmail and Graph providers and the current state is updated.
- A provider-originated update arriving through history/delta reconcile does not echo-loop for any provider.
- Retries and reconcile converge for all three providers with no oscillation.
- A second Gmail or Graph client sees a change made in our UI within one live round trip.
