## Context

Model tier rationale: Mechanical removal across eight call sites, but each one is on a tenant-resolution path for authentication, administration, deletion or realtime, so every changed query needs its existing tests re-checked against the strict schema.

#1067 makes `users.tenant_id` `NOT NULL` and `app_tenant_default()` strict. Its Out of scope keeps `app_sole_tenant()` and the single-tenant guard until go-live (#1087). Several queries still resolve a user's tenant as `COALESCE(u.tenant_id, app_sole_tenant())`, and one handler still branches on a `null` tenant id. After #1067 the fallback can no longer take effect, and after #1087 drops the single-tenant guard it would return NULL anyway. The review of the prepared #1067 branch (`mt/1067-strict-tenant-enforcement`) found these sites:

- `backend/packages/data/src/tenancy/tenantsStore.ts` — the user-to-tenant lookups (`COALESCE(u.tenant_id, app_sole_tenant())` in the status/role read, the `LEFT JOIN tenants`, and the `FOR KEY SHARE` read), plus the docstring that calls the fallback "the transitional contract";
- `backend/packages/data/src/tenancy/accountsAdminStore.ts` — three `JOIN tenants t ON t.id = COALESCE(u.tenant_id, app_sole_tenant())`;
- `backend/packages/data/src/tenancy/deleteAccount.ts` — three uses;
- `backend/packages/data/src/tenancy/tenantPurgeJob.ts` — two uses;
- `backend/packages/realtime/src/pgNotifyPublisher.ts` — the session-to-tenant subquery;
- `backend/services/semprec-api/src/adminHandler.ts` — the `if (tenantId === null)` branch, whose test #1067 removed because the branch became unreachable.

`getSoleTenantId` in `tenantsStore.ts`, used by `bootstrapFirstAccount` (`authActions.ts`) to bind the very first account to tenant zero, is a different use and stays.

## Task

Load `state-writes`, `error-handling` and `testing`.

1. At every site above, replace `COALESCE(u.tenant_id, app_sole_tenant())` (or `COALESCE(tenant_id, app_sole_tenant())`) with the column itself. Narrow the row types that carried `string | null` for the tenant id to `string`, and validate with the row type at the read.
2. In `adminHandler.ts`, remove the `tenantId === null` branch and its `ValidationError`. The type of the value it checked becomes non-null through step 1.
3. Update the `tenantsStore.ts` docstrings that describe the fallback as a transitional contract. Update `backend/review-rules/context.md` where it says the transitional default falls back to the sole tenant.
4. Run `git grep -n app_sole_tenant -- backend ':!*.sql'`. Only `getSoleTenantId`, the test harness (`globalSetup.ts`) and the `strictDefault` invariant check in `tenancyInvariants.ts` (#1085) may remain. Record the result in the pull request.
5. Keep every existing test of these paths passing. Where a test still creates a user without a tenant in order to reach the fallback, it can no longer exist under `NOT NULL`; delete it and name it in the pull request.
