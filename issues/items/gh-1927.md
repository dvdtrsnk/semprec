**Model tier:** medium

## Context

Model tier rationale: Three tools following the module-tool contract and reusing the draft store and thread read model, with the authorization rules fixed by the ADR, so the risk is mainly correct attribution and grants.

The Semp agent has no mail tools: `agentTools` in `backend/packages/data/src/mail/mailModuleManifest.ts` is empty, and module tools reach a session only once #1523 composes them (an ungranted tool is absent). The rules for classifying and granting module tools are in the ADR of #1385. The thread read model is #1632, draft storage and creation over HTTP is #1867, and starting a reply, reply-all or forward draft is #1899. Sending is a separate tool (#1949).

Decision: draft tools need no approval (nothing leaves the account); `mail.thread.get` returns text, not HTML.

Shared-file ordering: this issue also waits for #1923 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `io-hardening`, `canonical-keys` and `testing`.

1. Declare in `agentTools` of `mail/mailModuleManifest.ts` the tools `mail.thread.get` (capability `mail.read`), `mail.draft.create` and `mail.draft.update` (capability `mail.draft`), with handler exports in `mail/mailAgentTools.ts`.
2. `mail.thread.get { threadId }`: returns the thread as in #1632 rendered as text (messages with sender, recipients, date and plain-text body, attachments by name), with the people, the company and the project of the thread. A merged-away thread id resolves to the current thread.
3. `mail.draft.create { mode, threadId?, sourceEmailId?, mailboxId?, to?, cc?, bcc?, subject?, body }` creates a draft through the draft store with `createdBy` agent and the run's `agentRunId` and `conversationId`. `mode` is `new`, `reply`, `replyAll` or `forward`. `new`: `mailboxId` is required and `from` is the mailbox's primary address. The other modes: `mailboxId` and `from` come from the delivered-to address of the source message (#1899). A new draft that starts no thread has no thread; when writing to several companies, one draft per recipient group is created by repeated calls.
4. `mail.draft.update { draftId, body, subject? }` updates an open draft and sets `last_edited_by` to agent; it fails for a sent or deleted draft.
5. Validate all inputs; an unknown mailbox, thread or message is a not-found error; the tools write nothing else.

## Scope

### In scope

- The three tools and their manifest entries.

### Out of scope

- Composing module tools into sessions (#1523); the classification ADR (#1385).
- Sending (#1949); exposing the tools over MCP (#1956).
- Rewriting a draft from chat (#1948); the thread ref kind (#1933).
- Drafting triggered by incoming mail (#1941).

## Acceptance criteria

- A run in a project with the mail grants sees `mail.thread.get`, `mail.draft.create` and `mail.draft.update`; a project without them does not see them.
- `mail.draft.create` with mode `new` creates a draft without a thread from the mailbox's primary address; with a thread and mode `reply` it creates a reply draft with `In-Reply-To` of the source message.
- `mail.draft.update` changes the body and marks the draft as last edited by the agent; it rejects a sent draft.
- `mail.thread.get` on a merged-away thread id returns the current thread.
