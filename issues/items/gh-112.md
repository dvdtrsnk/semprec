**Blocked by:** #111

## Context

Load-time validation cannot detect manual live-DB drift introduced after startup.

## Task

Register standalone core heartbeat action `moduleRegistry.checkDrift`. On each run compare distinct live `project_heartbeats.action_id` values with active heartbeat actions and system-owned `properties.owner_process` values with active process/module ids. Publish findings through the established notification/findings channel and resolve prior findings when repaired. Make concurrent runs idempotent. This check is mechanical only and must not compare prose guidance to permissions.

## Scope

### In scope

- Periodic registration, both live checks, deduplication, and resolution.

### Out of scope

- Semantic AGENT guidance analysis, supplied by the audit-fix batch.

## Acceptance criteria

- Unknown action and orphan owner process produce explicit findings.
- Repair resolves findings on the next successful run.
- Concurrent checks do not duplicate active findings.
