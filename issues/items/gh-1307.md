## Behavior specification

Semp voice mode, read aloud and dictation.

This batch was planned from the reviewed design of the iOS app: every issue below states the backend behavior the app needs that `develop` does not provide yet. The issues are linked as sub-issues; their order follows the dependency graph across all batches, foundations first.

Status: drafts awaiting the `/define-behavior` Phase 5 audit. No issue in this batch carries `spec:approved` or `agent:ready` yet.

## Decisions

Decisions adopted while drafting, and questions still open for the product owner (per chunk of the batch):

### Decisions: semp-voice-1

#### (a) Adopted decisions
- Pipeline (speech-to-speech vs chain) -> chain: speech-to-text, normal agent turn, text-to-speech -> reuses queue, tools, approvals, steps; keeps all provider calls in the gateway.
- Provider -> Decided by the product owner: dictation uses the device's speech recognition (Apple Speech); read-aloud and the spoken answers use a gateway text-to-speech provider with high-quality Czech (OpenAI TTS or ElevenLabs), chosen by a listening test in Czech that the ADR of #1371 records; Czech is the primary language. The live voice streaming speech-to-text provider is picked in the same ADR by Czech quality, streaming, latency and price.
- Audio transport -> authenticated WS in semprec-api (`/api/voice`), binary audio + JSON control frames; gateway side uses loopback `/internal/stt/stream` and `/internal/tts/stream` unless the ADR says otherwise.
- Budget for unknown-length streams -> reserve fixed chunks of seconds, one ai_gateway_calls row per chunk, exhaustion ends the stream.
- Link audio rows to run or thread -> Decided by the product owner: yes, voice calls are attributed to the thread turn and the run like every other gateway call, and appear as their own Voice activity in AI usage reports -> usage is recorded by one general mechanism (#2020 for the attribution; the Voice label of the usage report is an addition to #1477).
- Interruption by user speech -> stops speech output only; agent turn keeps running; next message queues.
- Can voice cancel a running agent turn? -> Decided by the product owner: yes, but only on an explicit stop command of the user ("Stop", "Zruš"), as an ordinary cancellation of the turn; a write waiting for approval is never executed without the approval (#2019).
- Client display in voice mode -> Decided by the product owner: the client shows only listening and mute for now; a "Semp is speaking" state, the answer text and interruption are added when the design provides them. The backend protocol keeps its `speaking` control messages.
- Voice message origin -> user message marked source `voice`; migration only if the message store has no origin field.
- Read-aloud and dictation on device vs gateway -> Decided by the product owner: dictation on the device (cheap and private, no backend endpoint, so #1628 is not built); read-aloud through the gateway, because provider calls go only through the gateway for limits and audit (#1372 records it, #1626 builds it).
- Read-aloud route -> POST /api/semp/threads/:threadId/messages/:messageId/speech, returns audio.
- Read-aloud cache -> tenant-scoped blob + table `semp_message_speech` keyed (message, voice).

#### (b) Open questions for the product owner
- None remaining for this chunk.

#### (c) Behavior delivered
A user can talk to Semp live: they speak, see their words appear as they talk, and the final text becomes a message in the thread (a new chat creates the thread). Semp answers as in typed chat, with the same tools and approval cards, and the answer is spoken sentence by sentence while it is still being written; speaking over Semp silences it without stopping the work, and only an explicit "Stop" or "Zruš" cancels the running turn. Muting stops sending audio and ending the session leaves the thread intact. Separately, a user can have one stored answer read aloud (cached per message); dictation into the message field runs on the device without the backend. All backend speech counts against the tenant's AI budget, is attributed to the thread and run it served and shows as Voice in AI usage, nothing audio is stored, and an exhausted budget ends the session with a clear error.
