## Context

Model tier rationale: The migration, store functions, mailer, routes and lock are all specified exactly with existing patterns to copy.

Accounts are created only by an admin's invitation. There is no public signup, and the setup token stays the only way to create the very first account. Today `bootstrapFirstAccount` (`backend/packages/data/src/auth/authActions.ts:174-190`) is the only path to `createUser`.

This issue lets an admin issue, list and revoke invitations. Accepting one (creating the tenant and the member user) is #1087, which ships only after the security sign-off. Until then an invitation is inert: creating one before go-live is allowed and grants nothing.

Decisions this issue implements:

- **Table.** A global `invites` table: `(id, email, token_hash, invited_by, created_at, expires_at = created_at + 7 days, accepted_at, revoked_at)`.
- **Token.** Only the token's hash is stored, the same way password-reset tokens work. `generateOpaqueToken()` returns `{ token, tokenHash }` and `hashToken(token)` hashes a presented one (`backend/packages/data/src/auth/token.ts:18,23`).
- **Link.** The link is `<APP_BASE_URL>/?page=invite#token=<token>`. The token sits in the URL **fragment**, which browsers never send to the server and Caddy therefore never logs. It is returned to the admin **once**, in the create response, and mailed to the invitee when SMTP is configured.
- **Validity.** An invitation can be accepted only while it is pending: not accepted, not revoked and not expired. #1087 relies on exactly these columns and that definition.

What exists to build on:

- **Email.** `normalizeEmail` (`backend/packages/data/src/auth/emailNormalization.ts:2`, trim + lowercase). The account email rule is `EMAIL_PATTERN` (`backend/packages/data/src/auth/authActions.ts:32`), which is module-private today.
- **Mail.** Transactional mail follows `PasswordResetMailer` / `NodemailerPasswordResetMailer`, which applies a send timeout (`backend/packages/data/src/auth/passwordResetMail.ts:8-79`). `requestPasswordReset` dispatches the mail from `runAfterCommit` without awaiting it, so a rollback sends nothing (`backend/packages/data/src/auth/passwordResetActions.ts:63-88`).
- **SMTP wiring.** `semprec-api` builds the mailer from `SMTP_HOST`/`SMTP_FROM_ADDRESS`/`SMTP_PORT`/`SMTP_SECURE`/`SMTP_USER`/`SMTP_PASSWORD`, and falls back to a throwing no-op when unset (`backend/services/semprec-api/src/serve.ts:58-80`). `APP_BASE_URL` reaches the dispatcher as `AppOptions.appBaseUrl` (`backend/services/semprec-api/src/app.ts:27`).
- **Admin plane** (#1037): `createAdminRoutes(pool, options)` receives the dispatcher's `AppOptions`. `admin: true` routes return 403 `admin_required` to members and run in `runAsSystem`. `recordAdminAction(client, { actorUserId, action, targetTenantId, details })` writes `admin_audit_log` in the caller's transaction, and `inviteCreated` / `inviteRevoked` are reserved for this issue.
- **Grants.** Identity tables follow the convention that `semprec_side` gets `SELECT` only and `semprec_data` gets DML.

## Task

Load `state-writes` (insert, update and audit in one transaction, mail after commit), `db-migrations`, `io-hardening` (secret token handling, body validation), `error-handling` and `canonical-keys` (new error codes and status values).

1. **Migration** (take the next free migration ordinal at commit time; additive). Also add `invites` to the grant-coverage exceptions in `backend/packages/data/src/__tests__/leastPrivilegeRoles.test.ts` (#962's assertion; `SELECT` only for `semprec_side`), the way #1004 does for `tenant_ai_budgets`:
   ```sql
   CREATE TABLE invites (
     id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
     email text NOT NULL,
     token_hash text NOT NULL,
     invited_by uuid REFERENCES users(id) ON DELETE SET NULL,
     created_at timestamptz NOT NULL DEFAULT now(),
     expires_at timestamptz NOT NULL,
     accepted_at timestamptz,
     revoked_at timestamptz
   );
   CREATE UNIQUE INDEX invites_token_hash_key ON invites (token_hash);
   CREATE INDEX invites_email_idx ON invites (email);
   COMMENT ON TABLE invites IS 'semprec:tenancy=global';
   GRANT SELECT ON invites TO semprec_side;
   GRANT INSERT, UPDATE, DELETE ON invites TO semprec_data;
   ```
   `invited_by` is nullable with `ON DELETE SET NULL`, so deleting the inviting admin's account later is never blocked.
2. **Store** — new `backend/packages/data/src/tenancy/invites.ts`:
   - `INVITE_TTL_SECONDS = 7 * 24 * 60 * 60`.
   - `InviteStatus = "pending" | "accepted" | "revoked" | "expired"`, derived in SQL in that precedence order.
   - `InviteSummary = { id, email, invitedBy: string | null, createdAt, expiresAt, acceptedAt, revokedAt, status }`. It never contains `token_hash`.
   - `buildInviteUrl(appBaseUrl, token)` returns `${new URL(appBaseUrl).origin}/?page=invite#token=${token}`.
   - `createInvite(client: PoolClient, input: { email; invitedBy; appBaseUrl; mailer: InviteMailer | null }): Promise<{ invite: InviteSummary; inviteUrl: string }>`:
     - Normalize the email and validate it with `EMAIL_PATTERN`. Export the existing constant from `authActions.ts`; do not copy it. On failure throw `ValidationError` with `{ field: "email" }`.
     - Take `pg_advisory_xact_lock(hashtext('semprec_invite:' || $email))`.
     - If a `users` row has that email, throw `ValidationError("'email' already belongs to an account", { field: "email" })`.
     - Set `revoked_at = now()` on every pending invite for the same email. A re-invite supersedes the old link.
     - Insert the new row with `expires_at = now() + INVITE_TTL_SECONDS`.
     - When `mailer` is non-null, register `runAfterCommit(client, …)` that calls `mailer.sendInviteEmail({ to, inviteUrl, expiresAt })`, not awaited. Its rejection is logged with the invite id only, never the token or the URL.
   - `listInvites(client: Queryable): Promise<InviteSummary[]>`, newest first.
   - `revokeInvite(client: PoolClient, id): Promise<InviteSummary>`. One `UPDATE … SET revoked_at = now() WHERE id = $1 AND accepted_at IS NULL AND revoked_at IS NULL AND expires_at > now() RETURNING …`. On zero rows, an unknown id is `NotFoundError` (404). Anything else is `new ChokePointError(409, "invite_not_pending", "Only a pending invite can be revoked")`.
   - Export the module, and `EMAIL_PATTERN`, through `backend/packages/data/src/index.ts`, and update `EXPECTED_RUNTIME_EXPORTS`.
3. **Mailer** — new `backend/packages/data/src/tenancy/inviteMail.ts`: `InviteMailer { sendInviteEmail(input: { to: string; inviteUrl: string; expiresAt: string }): Promise<void> }` and `NodemailerInviteMailer`. It is the same shape and timeout as `NodemailerPasswordResetMailer`, HTML-escapes the URL, and says the link expires in 7 days.
4. **Composition** — in `serve.ts`, factor the SMTP transport construction into one helper used by both mailers, keeping the existing `SMTP_PORT` validation and message (`__tests__/serveStartupConfig.test.ts` covers it). Pass the `NodemailerInviteMailer` through a new optional `AppOptions.inviteMailer?: InviteMailer` field. Omit it when `SMTP_HOST` or `SMTP_FROM_ADDRESS` is unset; an absent mailer means no mail is sent.
5. **Routes** in `createAdminRoutes`, all `admin: true`, each mutation in one `withTransaction` together with its `recordAdminAction` (`targetTenantId: null`, `details: { inviteId }`, never the email):
   - `POST /api/admin/invites`, body `{ "email": string }`, answers `201 { "invite": InviteSummary, "inviteUrl": string, "emailed": boolean }`. `emailed` is whether `options.inviteMailer` is present; delivery is not awaited.
   - `GET /api/admin/invites` answers `200 { "invites": InviteSummary[] }`.
   - `POST /api/admin/invites/:id/revoke` answers `200 { "invite": InviteSummary }`. `:id` is checked with `assertUuid`.
   - Add the three route-matrix entries (`admin: true`) and their `ROUTE_HANDLER_FILES` mappings.

## Acceptance criteria

- When an admin posts `{ "email": " New@Example.COM " }`, the response is 201:
  - `invite` has `email: "new@example.com"`, `status: "pending"` and `expiresAt` exactly 7 days after `createdAt`.
  - `inviteUrl` matches `^https://app\.example\.test/\?page=invite#token=[A-Za-z0-9_-]+$` for `appBaseUrl: "https://app.example.test"`.
  - The stored `token_hash` equals `hashToken(<token from the URL>)`, and no column of the row contains the token.
  - One `admin_audit_log` row records `inviteCreated` with `details = { inviteId }` and no email.
  
  (integration, `adminHandler.test.ts`)
- When a fake `InviteMailer` is configured, `sendInviteEmail` is called once, after the commit, with the normalized address and the same `inviteUrl`, and the response has `emailed: true`. When no `inviteMailer` is configured, nothing is sent and `emailed` is `false`. When creation fails validation, nothing is sent (integration, `invites.test.ts`).
- When the mailer rejects, the 201 response is unaffected, and the logged error contains neither the token nor the URL (integration, `invites.test.ts`).
- When the email already belongs to a user, or is malformed, the response is 400 `validation_failed` with `field: "email"`, and no `invites` or audit row is written (integration, `adminHandler.test.ts`).
- When a second invite is created for the same email, the first one's status becomes `revoked` and only the second is `pending` (integration, `invites.test.ts`).
- When `GET /api/admin/invites` runs with one pending, one accepted (`accepted_at` set by the test), one revoked and one expired invite, each carries the matching `status`, and no body contains `token_hash` or a token (integration, `adminHandler.test.ts`).
- When a pending invite is revoked, the response shows `status: "revoked"` and an `inviteRevoked` audit row exists. Revoking an accepted, revoked or expired invite answers 409 `invite_not_pending`, an unknown id answers 404, and neither writes an audit row (integration, `adminHandler.test.ts`).
- When a `member` calls any of the three routes, the response is 403 `admin_required`. Without a session it is 401 (integration, `adminHandler.test.ts`, `routeMatrix.test.ts`).
- When connected as `semprec_side`, `INSERT` into `invites` fails with a privilege error (integration, `invites.test.ts`, `createRuntimeRolePool` from `@semprec/data/testSupport`, #975).
- When `SMTP_PORT` is invalid with SMTP configured, `serve.ts` still fails startup with the existing message (integration, `serveStartupConfig.test.ts`, unchanged).
