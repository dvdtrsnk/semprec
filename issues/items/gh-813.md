## Context
Review of pull request #434 found that in `backend/services/semprec-ai-gateway/src/startupConfig.ts` (currently around lines 44-50), `requireEnv(env, "DATABASE_URL")`'s thrown error message is only `"DATABASE_URL is not set"`, never mentioning `SEMPREC_SIDE_DATABASE_URL` — even though the comment directly above explains that `SEMPREC_SIDE_DATABASE_URL` is the primary variable (checked first, via `env.SEMPREC_SIDE_DATABASE_URL ?? requireEnv(env, "DATABASE_URL")`) and `DATABASE_URL` is only its fallback for local development. An operator debugging a missing-configuration startup failure sees only the fallback variable's name, not the primary variable this service actually expects in production.

## Task
- In `backend/services/semprec-ai-gateway/src/startupConfig.ts`, update the error message thrown when neither `DATABASE_URL` nor `SEMPREC_SIDE_DATABASE_URL` is set, so it names both variables (e.g. `"DATABASE_URL (or SEMPREC_SIDE_DATABASE_URL) is not set"`).

## Touches
- backend/services/semprec-ai-gateway/src/startupConfig.ts (the `DATABASE_URL` / `SEMPREC_SIDE_DATABASE_URL` error message only)
- backend/services/semprec-ai-gateway/src/__tests__/startupConfig.unit.test.ts (the "throws when neither SEMPREC_SIDE_DATABASE_URL nor DATABASE_URL is set" test's assertion only)

## Scope
### In scope
- The single error message named above.

### Out of scope
- Any other environment variable's error message in `startupConfig.ts`, and the fallback resolution logic itself.

## Acceptance criteria
- When neither `DATABASE_URL` nor `SEMPREC_SIDE_DATABASE_URL` is set, the thrown error message names both variables.
- The existing test "throws when neither SEMPREC_SIDE_DATABASE_URL nor DATABASE_URL is set" in `startupConfig.unit.test.ts` (currently around line 39) asserts `/DATABASE_URL is not set/`, which a message such as the example above no longer matches; it is updated to assert the new message, including both variable names.
