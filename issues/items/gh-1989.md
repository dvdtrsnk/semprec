**Blocked by:** #1987
**Model tier:** medium

## Context

Model tier rationale: One deterministic external lookup inserted into an existing bracketed computation, with injectable client tests; the failure handling (never fail the card) is the only subtle part.

A company the user captures with a Czech registration number (IČO) should get its official registered name from the public company register (ARES), so the card is not left with whatever spelling the text or the model produced. Nothing in the backend calls ARES today. The host egress filter is a deny-list of private ranges (`docs/adr/2026-10-03-host-egress-filtered-by-service-uid.md`), so the public host `ares.gov.cz` is reachable from the `semprec-api` process.

The proposal computation is built by #1434 (a `computeProposal` function in `semprec-api`, run by the Inbox tick) and receives its bounded context from #1987. The tick follows `docs/adr/2026-09-10-bracket-non-transactional-calls-with-staleness-checked-transactions.md`: a read transaction, then the non-transactional computation, then a write transaction that re-checks staleness. The ARES call belongs to the middle step only: it runs outside any transaction and never writes. This is the one deterministic lookup the computation makes besides the model call; agent sessions keep using their own tools.

The ARES URL is operator configuration of the service, not a user-supplied URL, so the connect-time address check for stored user URLs does not apply. The URL is a fixed `https://` constant.

Decision: only the registered name is taken over. Registered address and tax id are not stored, because no company property holds them.

Decision: the lookup is best effort. A timeout, a non-2xx answer, an unparseable answer or "not found" leaves the computed properties unchanged and is logged; it never fails the tick, never makes the card `needsClarification` and is never retried by the queue.

Decision: the IČO is checked for format only (eight digits after trimming spaces and left-padding with zeros), not for the check digit, so a number ARES knows is never skipped.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add `backend/services/semprec-api/src/aresClient.ts` with a small `AresClient` interface (`lookupCompanyByIco(ico: string): Promise<{ ico: string; name: string } | null>`) and an HTTP implementation: `GET <ARES base>/ekonomicke-subjekty/<ico>` against the constant base URL `https://ares.gov.cz/ekonomicke-subjekty-v-be/rest`, a 3 second timeout, a response size cap, and a zod schema for the fields it reads (`ico`, `obchodniJmeno`). A 404 returns `null`; every other failure throws a typed error that the caller catches.
2. In the proposal computation module introduced by #1434 (`proposalComputation.ts`), after the model result is available and only when the target database is Companies and the computed `properties.ico` is present, call the client. On a hit set `properties.name` to the registered name and `properties.ico` to the normalized eight digits. On `null` or any error leave the properties untouched and log at info or warn without the IČO's surrounding card content.
3. The client is injected into the computation factory so tests stub it; the production wiring in `actionRegistryComposition.ts` passes the HTTP client. No network call happens in tests.
4. Tests: a stubbed hit overrides the model's name; "not found", timeout and a malformed body each leave the computed properties unchanged and the proposal is still written; a non-Companies target never calls the client; the call happens outside a transaction (the stub observes no open transaction).

## Scope

### In scope

- The ARES client, the name verification step and its tests.

### Out of scope

- Detecting that a company with this IČO already exists (#1992).
- Storing registered address or tax id.
- Any lookup by company name, and any ARES call from agent sessions.
- Caching ARES answers.

## Acceptance criteria

- When a Companies proposal is computed with IČO `27419363` and ARES returns the registered name, then the stored proposal carries that name.
- When ARES is unreachable, answers slowly, returns 404 or returns a malformed body, then the proposal is still written with the computed values and the tick does not fail.
- When the computed target is not Companies, then ARES is not called.
- The ARES request is made with no database transaction open.
