## Context

Model tier rationale: This replaces a live credential for a mailbox whose sync lifecycle is already running, which needs a new restart operation on the live-sync root with concurrency and cleanup ownership, plus an account-identity check.

When a Google or Microsoft token has been revoked or has expired, the mailbox shows "sign in again". The user signs in at the provider, the server verifies that it is the same account and replaces the stored refresh token, and mail resumes.

The new-mailbox flow (#1686) already provides the provider redirect, the one-time state with an optional mailbox id (`mail_oauth_states.mailbox_item_id`) and the authenticated `POST /api/mail/mailboxes/oauth/complete`. The server-owned provider address on the sync state is `provider_account_address`.

A hosted lifecycle receives its decrypted credential once in `start()` (`getCredential` in `gmailWatchLifecycle.ts`, `graphWebhookLifecycle.ts` and `imapIdleLifecycle.ts`) and reuses it for every watch registration, subscription renewal and IDLE reconnect. The live-sync root (`backend/packages/data/src/mail/mailLiveSyncRoot.ts`) skips an account that is already hosted with the same sync mode, so after storing a new token the old lifecycle would carry on with the old one; `reconcileOnce()` does not replace it, even after a failed `start()`.

Decision: the mailbox keeps its history cursor and delta link. If a cursor is no longer valid, the existing full reconcile recovers without losing messages.

Decision: if the stored `provider_account_address` is null (for example a mailbox restored from the trash or created before addresses were recorded), the signing-in address is accepted when no other mailbox of the tenant holds it, and is then stored.

Shared-file ordering: this issue also waits for #1736 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `io-hardening` and `testing`. Follow `docs/adr/2026-09-10-bracket-non-transactional-calls-with-staleness-checked-transactions.md`.

1. `POST /api/mail/mailboxes/:id/reauthorize` (authenticated, justification `transactional-semantics`) answers `{ authorizeUrl }` for the mailbox's provider, creating a state that carries the mailbox id. Unknown or foreign mailboxes and password-based mailboxes answer 404 and 400 respectively.
2. Extend `POST /api/mail/mailboxes/oauth/complete` to handle a state with a mailbox id: after the exchange and the provider's address lookup, if the address differs from the stored `provider_account_address` answer 400 `mail_reauth_wrong_account` (add to `ITEM_ERROR_CODES`) and change nothing.
3. In one transaction replace the `oauth2_refresh_token` with `storeCredential` and call `enqueueMailAccountSync`. `Mailboxes.syncStatus` is not written here; the next successful pass writes `ok`.
4. After the commit call a new `restartAccount(mailboxItemId)` on the live-sync root: it stops the hosted lifecycle (the same path a deactivated account takes) and starts it again from the root's dependencies, whether or not the old `start()` succeeded. Concurrent discovery passes must neither double-host nor leave the account unhosted. Expose the root to the route through the composition-root dependencies.

## Scope

### In scope

- The reauthorization route, the completion branch with the account check, the token replacement and the lifecycle restart.

### Out of scope

- Creating new mailboxes (#1686).
- Making a refresh token rotated by the provider reach a hosted lifecycle (#1481); it may reuse `restartAccount` once available.
- Writing `syncStatus` or the sync problem (#1497, #1506).
- Reauthorizing password mailboxes.

## Acceptance criteria

- When the user signs in with a different account, then the response is 400 `mail_reauth_wrong_account` and the stored credential is unchanged.
- When the same account signs in, then the credential is replaced, a sync is queued in the same transaction and new mail arrives within a minute using the new token.
- After the restart, exactly one lifecycle is hosted for the mailbox, and it holds the new credential, also when the previous `start()` had failed.
- The refresh token, code and verifier appear in no response, log or tenant export.
