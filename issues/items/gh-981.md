## Context

#978 added the tenant scope, exported from `@semprec/shared`:
- `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()`.
- Every database access on a `createPool` pool applies the scope through the GUC `app.tenant_id`.
- An unscoped access logs `tenant_scope_missing` (`warn`), or throws `TenantScopeMissingError` when `SEMPREC_TENANT_SCOPE=strict`.

#980 did three things:
- `AuthenticatedIdentity` now carries `tenantId` (an active tenant) and `role`.
- `authenticateRequest` verifies the session in its own system scope.
- Every adapter-mounted route (generic resources and module custom routes) runs in `runInTenant(identity.tenantId, …)`.

The listeners `backend/services/semprec-api/src/app.ts:80-98` builds outside the adapter still run unscoped. Each one authenticates by hand and then does its work on the pool:

| Listener | Authenticates at | Scope after this issue |
|---|---|---|
| `notificationsHandler.ts` | `:36` | tenant |
| `approvalRequestsHandler.ts` | `:49` | tenant |
| `agentRunHandler.ts` | `:58` | tenant |
| `mcpAgentPageHandler.ts` | `:41` (identity discarded) | tenant |
| `filesHandler.ts` | `:51` (identity discarded) | tenant |
| `blobsHandler.ts` | `:119` (identity discarded) | tenant |
| `schemaHandler.ts` | `:33` | tenant |

`mcpHandler.ts` has two authentication paths. `resolveActor` (`mcp/mcpHandler.ts:88-113`) first looks up a restricted MCP run credential with `withTransaction(pool, … resolveMcpRunCredential …)` at `:94`, and only then falls back to the session at `:111`. The run-credential path is reworked by #994. Until then, `agent_run_mcp_credentials` is a global table (classified by #971) without row-level security, so the lookup itself can run as system.

`handleGraphChangeNotification` resolves the subscription through `mail_account_sync_state`. Under system scope it sees the sole tenant today. #997 replaces it with a router function that resolves the tenant per notification.

## Task

Load `io-hardening` (every listener edge) and `error-handling` (the listeners' catch paths must stay unchanged).

1. **Tenant-scoped listeners.** In each of the eight tenant-scoped listeners in the table, keep `authenticateRequest` first, outside any scope. Run everything after it inside `runInTenant(identity.tenantId, async () => { … })`: path matching, body parsing, every `withTransaction` and pool call, and writing the response. Where the identity is currently discarded (`mcpAgentPageHandler.ts:41`, `filesHandler.ts:51`, `blobsHandler.ts:119`), bind it. Each listener's existing `try/catch` and `handleRequestSafely` wrapper stay outside the scope and are unchanged.
2. **`mcp/mcpHandler.ts`.**
   - Run the run-credential lookup at `:94` inside `runAsSystem("mcp-run-credential-lookup")`.
   - Make `resolveActor` also return `tenantId` for a session-derived actor.
   - In `handleRequest`, run everything after `resolveActor` inside `runInTenant(tenantId, …)` when the actor came from the session.
   - A run-credential actor's request is served inside the credential owner's tenant: resolve it with `getUserTenantBinding` (from #980, exported from `@semprec/data` for this) and answer 401 when the owner has no active binding. This interim lookup keeps `/mcp` working once tenant scopes are enforced; #994 later replaces it with the credential row's own `tenant_id`.
3. **System-scoped listeners.**
   - `healthzHandler.ts`: run the `withClient` probe inside `runAsSystem("healthz")`.
   - `setupHandler.ts`: run the `bootstrapFirstAccount` call inside `runAsSystem("setup")`.
   - `graphWebhookHandler.ts`: run the body-processing loop inside `runAsSystem("graph-webhook")`. The `validationToken` echo touches no database and stays outside. The always-202 behaviour is unchanged.
4. **Test.** Add `backend/services/semprec-api/src/__tests__/bespokeListenerTenantScope.test.ts`. It drives `createDispatcher` (`app.ts:55`) on a `createPool(process.env.TEST_DATABASE_URL)` pool. Build the dispatcher under `warn`, then set `SEMPREC_TENANT_SCOPE=strict` for the requests and restore it afterwards. The test user is created with `createUser` and resolves to the sole tenant (per #980).

## Scope

### In scope
- Explicit tenant or system scope for every listener in the table above.

### Out of scope

## Acceptance criteria

All criteria are integration tests in `bespokeListenerTenantScope.test.ts` unless they name another file.

- **Strict mode, tenant routes.** With `SEMPREC_TENANT_SCOPE=strict` and an authenticated session, every `surface: "api"`, `public: false` `ROUTE_MATRIX` entry (`backend/services/semprec-api/src/routeMatrix.ts`) served by one of the eight tenant-scoped listeners returns the same status as under `warn`, never a 500 from `TenantScopeMissingError`. Those entries are:
  - notifications ×3, schema, approval queue ×2;
  - `POST /mcp` (session Bearer), agent runs ×2, MCP agent page ×3;
  - `POST /api/files`, `GET /api/blobs/:id`.
- **Recorded scope.** A spy on `pg`'s `Client.prototype.query` records `currentTenantScope()` for every statement sent while serving those requests. Every statement passes through this method whatever pool path sent it. For each request, the recording is:
  - first, the session lookup's statements, of kind `system`;
  - then only statements equal to `{ kind: "tenant", tenantId: <caller's tenant> }`, at least one of them.
- **Strict mode, public routes.** With `SEMPREC_TENANT_SCOPE=strict`, `GET /healthz`, `POST /api/setup` (first account, and the 404 after it) and `POST /api/mail/graph/webhook` (a valid-looking notification batch, and the `validationToken` echo) return the same status and body as under `warn`. Every statement they send is recorded as kind `system`.
- **Unauthenticated requests.** An unauthenticated request to each tenant-scoped route still gets 401, and no statement is recorded inside a tenant scope.
- **Run credential.** `POST /mcp` with a valid restricted run credential returns the same JSON-RPC response as before this change. The credential lookup is recorded as `system`.
- **Existing suites.** The existing listener test files still pass unchanged: `notificationsHandler.test.ts`, `approvalRequestsHandler.test.ts`, `agentRunHandler.test.ts`, `mcpAgentPageHandler.test.ts`, `filesAndBlobsHandler.test.ts`, `schemaHandler.test.ts`, `setupHandler.test.ts`, `healthzHandler.test.ts`, `graphWebhookHandler.test.ts` and `mcp/__tests__/mcpHandler.test.ts`.
