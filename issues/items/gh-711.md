**Blocked by:** #649, #709

## Context

`deploy/docker-compose.yml` runs two containers. `minio` (lines 21-35) is `minio/minio:latest` — an unpinned, floating image — and after #649 nothing in the system uses it: the application has no S3 client, blobs live under `/opt/semprec/data` (#645), the backup snapshots those directories and the restore test reads them from the restored snapshot (#649, whose `.env.example` rewrite says MinIO "is kept in `deploy/docker-compose.yml` only until a separate removal"). Both services load the *entire* `/opt/semprec/shared/.env` via `env_file:` (lines 10-11 and 25-26): the Postgres container's environment carries `CREDENTIALS_MASTER_KEY`, `SETUP_TOKEN`, `RESTIC_PASSWORD`, `AWS_SECRET_ACCESS_KEY`, `ANTHROPIC_API_KEY`, the APNs ids and every other secret, visible to `docker inspect` and to anything that can read the container's `/proc/1/environ`, while it needs exactly `POSTGRES_USER`, `POSTGRES_PASSWORD` and `POSTGRES_DB`.

Compose can pass single variables with `environment:` and `${VAR}` interpolation; interpolation reads the invoking process's environment first and then the file named by `--env-file`. The backup script (`deploy/systemd/scripts/semprec-backup.sh`, `docker compose -f "$COMPOSE_FILE" exec -T postgres pg_dump ...`) runs under `semprec-backup.service`, which loads the shared `.env` as `EnvironmentFile=`, so its environment already carries the values; `provision.sh` calls `docker compose -f ... ps` (line 148) without them. `POSTGRES_USER`/`POSTGRES_DB` stay in `.env` because the backup script reads them from there too. Depends on sibling issue F8a, which rewrites the README "Bootstrap secrets" section this issue also edits (line 159 mentions the `minio` service).

## Task

1. **Compose** — in `deploy/docker-compose.yml`: delete the `minio` service and the `minio_data` volume; replace the `postgres` service's `env_file:` block with
   ```yaml
   environment:
     POSTGRES_USER: ${POSTGRES_USER}
     POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
     POSTGRES_DB: ${POSTGRES_DB}
   ```
   Rewrite the header comment (lines 1-5): PostgreSQL only, bound to `127.0.0.1`, receives exactly these three variables interpolated from `/opt/semprec/shared/.env` (`docker compose --env-file /opt/semprec/shared/.env -f deploy/docker-compose.yml up -d`), never the file itself.
2. **provision.sh** — the single `docker compose` invocation in `install_postgresql_hunspell_assets` (line 148) gains `--env-file "$SEMPREC_ROOT/shared/.env"` so it runs without "variable is not set" warnings. `deploy/provision.test.sh`'s `docker` mock already accepts any `compose` arguments; add one assertion, directly after F8a's block, that the recorded `docker compose` call contains `--env-file`.
3. **Environment template** — in `deploy/shared/.env.example`, delete the `MINIO_*` block as rewritten by #649 (the `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`/`MINIO_BLOB_BUCKET` entries and their comments), rename the section header `# ---- Distinct Postgres + MinIO values ----` (line 41) to `# ---- Postgres values ----`, and in the header comment (lines 6-8) replace "`deploy/docker-compose.yml`'s `postgres`/`minio` services already load it via `env_file:`" with: the `postgres` service receives only `POSTGRES_USER`/`POSTGRES_PASSWORD`/`POSTGRES_DB` from it, interpolated by `docker compose --env-file`.
4. **README** — `deploy/README.md`: the `docker-compose.yml` bullet (lines 12-13) → PostgreSQL only, the `--env-file` invocation, and that no other variable reaches the container; line 99-100 ("PostgreSQL and MinIO use the Docker Compose `journald` driver") → PostgreSQL; line 159 (in the "Bootstrap secrets" section F8a rewrote) → the `postgres` service receives three interpolated values, not the file. `deploy/nftables.conf`'s header comment no longer mentions MinIO after F7b; `deploy/Caddyfile` is unaffected.
5. **Validation** — run `docker compose --env-file <(printf 'POSTGRES_USER=u\nPOSTGRES_PASSWORD=p\nPOSTGRES_DB=d\n') -f deploy/docker-compose.yml config` locally and paste the rendered `environment` block into the PR description; it must list exactly the three keys.
