## Context

Model tier rationale: A new read route that returns message bodies and attachment references across mailboxes and folders, where sanitization and merged-id translation must hold on the one path that reads raw HTML inside the data layer.

After #1567 a client has the thread list but nothing to open a conversation. The Mail detail shows the header (subject, sender person, mailbox and message count) and all messages in chronological order, own sent messages included, with the newest expanded.

Facts: messages are Emails items with `Emails.body` holding HTML (or text), `Emails.date` possibly absent (fall back to `mail_message_meta.ingested_at` from #1468); the same message in two mailboxes is two items sharing a `message_id`; `mail_attachments` holds `blob_id`, `filename`, `content_type` and `byte_size` per message item, and attachments are also Files items related to the Email; a merged thread's old id resolves through the alias table of #1493. The generic read paths return a sanitized body (#1490), but this route reads inside the data layer where the body is raw, so it sanitizes itself with `sanitizeMailHtml` (`mail/htmlSanitize.ts`), which strips scripts, `on*` attributes and remote images unless remote images are allowed.

The link state (person, project, company and attachment project state) is added to this response by #1897, #1922 and the thread's tasks by #1692; replying and forwarding build on it (#1899, #1927).

Decision: all folders and mailboxes are included (Drafts included, marked by `folderPurpose`), duplicate `message_id` appears once, and the header aggregates are the same as the list row but computed over this single thread.

Shared-file ordering: this issue also waits for #1631 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `state-writes` and `testing`.

1. Implement `GET /api/mail/threads/:threadId` with optional `?allowRemoteImages=true` in `backend/packages/data/src/mail/mailThreadDetail.ts`, declared in `mailModuleManifest.ts` (`handlerExport` `createMailThreadDetailRouteHandler`, justification `single-consumer-read`) with a `routeMatrix.ts` entry.
2. Validate `threadId` as a UUID (400). Translate it with `resolveMergedThreadId` from #1493; a merged id answers with the target thread (the response's `threadId` is the target's); an unknown id answers 404 `not_found`, identically for another tenant's id.
3. Response: the header with the same fields as a list row of #1567 (`threadId`, `subject`, `lastMessageAt`, `lastSender`, `participants`, `messageCount`, `unread`, `flagged`, `mailboxes`, `senderPerson`) plus `messages` ordered by date ascending. Each message: `emailId`, `messageId`, `mailboxId`, `folderPurpose`, `isOwn`, `from`, `to`, `cc`, `replyTo`, `date`, `bodyHtml`, `bodyText`, `read`, `flagged`, `attachments [{ fileItemId, blobId, filename, contentType, byteSize }]`.
4. `bodyHtml` is the body passed through `sanitizeMailHtml` with `allowRemoteImages` true only when the query asks for it; `bodyText` is the plain text of the HTML (`htmlToPlainText` from #1468) when the message has no text body.
5. Add tests: the four-message fixture returns attachments of the first (sent) and last message with `blobId`; a body with `<script>`, `on*` attributes and remote images is sanitized, and remote images only appear with `allowRemoteImages=true`; a duplicate copy in two mailboxes appears once; a merged thread id returns the target thread; an unknown or foreign id is 404; drafts appear with `folderPurpose` `drafts`.

## Acceptance criteria

- When the thread "Re: Nabídka na web" is requested, then it returns four messages in date order, the sent message's attachment and the last message's two attachments, each with a `blobId`.
- When a body contains scripts, `on*` attributes or remote images, then `bodyHtml` has none of them, and remote images appear only when `allowRemoteImages=true`.
- When a message exists in two mailboxes, then it appears once.
- When the id of a merged thread is requested, then the target thread is returned.
- When the id is unknown or belongs to another tenant, then the response is 404.
