**Model tier:** medium

## Context

Model tier rationale: The signatures and keying are specified, but every async doc read and write path must keep the socket's tenant scope.

`WS /api/sync` carries Yjs document sync through `createDocSyncRegistry` (`backend/packages/realtime/src/docSync.ts:67-282`). Its state is process-wide:
- `subscribersByDoc` (`:68`) is a `Map<docId, Set<WebSocket>>`;
- `doc:open`'s only precondition is that `getDocById` finds the row (`:145-149`);
- binary update frames are accepted only for a doc the socket opened (`:198`) and persisted through `mutateYDoc` (`:243-245`);
- a `doc_update` reference fans out to every subscriber of `docId` (`:255-280`).

The update bytes are fetched by `getDocUpdateById(pool, updateId)` (`backend/packages/data/src/docs/docPersistence.ts:144-147`): `SELECT update FROM doc_updates WHERE id = $1`. It never checks that the update belongs to the `docId` named in the same reference. A reference naming doc A with an update id of doc B therefore sends B's bytes to A's subscribers.

`syncServer.ts` dispatches doc frames with no tenant (`backend/packages/realtime/src/syncServer.ts:151-171`). `docs/adr/2026-09-12-per-process-doc-sync-subscription-registry.md` records "no new authorization boundary" because a second user did not exist.

What earlier issues provide:
- RLS hides other tenants' `docs`, `doc_snapshots` and `doc_updates` rows once `app.tenant_id` is set. It is set by `runInTenant(tenantId, fn)` from `@semprec/shared`, through `withTransaction` and pools created with `createPool`.
- #1025 gave every socket `SyncIdentity.tenantId`. It wraps each received `doc_update` in an envelope `{ tenantId, message }`, with the tenant computed by Postgres from the publisher's scope. It handles each envelope inside `runInTenant(envelope.tenantId, …)` and records in its ADR (`docs/adr/<date>-tenant-scoped-realtime-fan-out.md`) that doc sync resolves inside the socket's tenant. That ADR covers this issue; no new ADR is needed.
- #985 made doc compaction per tenant in `docPersistence.ts`.

## Task

Load `io-hardening` (socket frames and NOTIFY references are untrusted) and `state-writes` (doc writes run in the socket's tenant).

1. **Socket tenant into doc sync.** `DocSyncRegistry` methods take the tenant explicitly:
   - `handleOpen(ws, tenantId, docId)`
   - `handleBinaryFrame(ws, tenantId, docId, payload)`
   - `fanOutDocUpdate(tenantId, docId, updateId)`

   Each runs all of its database work (`getDocById`, `loadYDoc`, `mutateYDoc`, `getDocUpdateById`) inside `runInTenant(tenantId, …)`. In `syncServer.ts`, the doc frame dispatch (`:151-171`) passes `identity.tenantId`. The `doc_update` envelope handler passes `envelope.tenantId`. Add `@semprec/shared` imports only; #1025 already added the dependency.
2. **Tenant-keyed subscriptions.** Key `subscribersByDoc` by `${tenantId}:${docId}`. `fanOutDocUpdate(tenantId, docId, …)` reaches only sockets that opened `docId` under that tenant. A reference stamped with tenant A therefore never reaches a tenant-B socket, whatever `docId` it names. The per-socket open set, the 32-document cap (`:119-129`) and the rate limit (`:72-84`) are unchanged.
3. **Foreign doc behaves like an unknown doc.** `handleOpen` runs `getDocById` in the socket's tenant. A doc of another tenant is invisible, so it takes the existing unknown-doc path (`:145-149`):
   - the reservation is released;
   - nothing is sent;
   - no error frame or log line distinguishes it from a nonexistent id.

   A binary frame for such a doc is then dropped by the existing opened-doc check (`:198`).
4. **Update bound to its doc.** Change `getDocUpdateById(pool, updateId)` to `getDocUpdateById(pool, docId, updateId)`, which runs `SELECT update FROM doc_updates WHERE id = $1 AND doc_id = $2`. A reference whose update belongs to another doc resolves to `null` and takes the existing full-resync branch of the named doc (`docSync.ts:263-274`). The barrel export (`backend/packages/data/src/index.ts:241`) and the name list in `backend/packages/data/src/__tests__/publicSurface.test.ts:254` stay unchanged.
5. **Tests.** Extend `backend/packages/realtime/src/__tests__/docSync.test.ts` and `syncServer.test.ts` with the criteria below. Use the two-tenant runtime-role harness of #975 (`createTestTenant`, `createRuntimeRolePool`, `getTenantZeroId` from `@semprec/data/testSupport`). The superuser test pool bypasses RLS and proves nothing.

## Scope

### In scope
- The socket tenant threaded into every doc-sync entry point, tenant-keyed subscriptions, foreign doc behaving like an unknown doc, and binding an update reference to its doc.

### Out of scope
- The NOTIFY envelope, socket tenant and tenant-only delivery of invalidations and notifications (#1025).
- Agent-run watching (#1027).
- Composite `(tenant_id, doc_id)` foreign keys on `doc_updates` and the other doc tables (#1066).
- Doc compaction and history cleanup per tenant (#985).
- The exhaustive realtime frame suite (#1054).

## Acceptance criteria

- **Foreign doc ≡ unknown doc.** When a tenant-B socket sends `doc:open` for a tenant-A doc id:
  - it receives exactly what it receives for a random UUID: no frame;
  - its open-doc reservation is released;
  - a following binary update frame for that id writes no `doc_updates` row in either tenant.

  (integration, `docSync.test.ts`, runtime-role harness)
- **Same-tenant behaviour unchanged.** A tenant-A socket that opens its own doc receives SyncStep1, and its update is persisted with tenant A's `tenant_id`. Another tenant-A subscriber receives the update. (integration, `docSync.test.ts`)
- **No cross-tenant fan-out.** `fanOutDocUpdate(B, docA, updateA)` sends nothing to a tenant-A subscriber of `docA`. `fanOutDocUpdate(A, docA, updateA)` delivers it. (integration, `docSync.test.ts`)
- **Forged cross-doc reference.** A `doc_update` reference naming `docA1` with an update id belonging to `docA2` (same tenant) gives subscribers of `docA1` a full resync of `docA1`. They never receive `docA2`'s update bytes. (integration, `docSync.test.ts`)
- **Envelope path.** A raw `pg_notify` of a `doc_update` envelope stamped with tenant B and naming a tenant-A doc reaches no socket. (integration, `syncServer.test.ts`)
- **Compaction recovery unchanged.** The existing recovery when the referenced update was compacted away (`docSync.test.ts:176`) still passes with the new signature. (integration)
