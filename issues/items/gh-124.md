**Blocked by:** #123

## Context

Discovered availability and per-project visibility are independent facts.

## Task

Create `mcp_tool_registrations` with server item id, tool name/schema/description snapshot, active state, `requires_approval` default true, `risk_class` default `unclassified`, timestamps, and unique `(mcp_server_item_id,tool_name)`. Create `project_mcp_grants` primary keyed by `(project_item_id,mcp_tool_registration_id)` with user-owned `granted` default false. Provide user-only mutations for grant, risk class, and approval requirement. Agents, including proposal confirmation, have no write path to grants.

## Scope

### In scope

- Tables, constraints, defaults, reads, and authenticated human mutations.

### Out of scope

- Automatic risk classification and approval execution.

## Acceptance criteria

- New tool/project pairs are ungranted by default.
- Duplicate server/tool identity cannot exist.
- Agent actors cannot mutate grant or classification rows.
