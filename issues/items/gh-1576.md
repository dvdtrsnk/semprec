## Context

Model tier rationale: One new read route that composes data the repository already stores, following the existing `GET /api/transcripts/:id/speakers` handler and its tests; the only sensitive seam is that a foreign and an unknown id must answer identically.

A client that shows a transcript today needs four calls: the item (`GET /api/items/:id`, which returns `computed.segments`, `computed.language` and `computed.summaryByInstruction`), the speaker labels (`GET /api/transcripts/:id/speakers`, `backend/packages/data/src/transcription/transcriptionRouteHandlers.ts`), the source Files item through the `link` property, and the linked Event through a query. The transcript screen and the recording view of an Event need all of it at once, and the speaker labels must change as soon as a speaker is mapped to a person, without reprocessing.

This issue adds `GET /api/transcripts/:id`, one read-only route that returns everything a transcript screen needs. It is a custom route of the systemDatabases module (`backend/packages/data/src/seed/systemDatabasesModuleManifest.ts`, justification `single-consumer-read`), next to `listTranscriptSpeakers`; per the single-writer ownership model (`docs/adr/2026-09-10-single-writer-ownership-model.md`) routes over Tasks and Events belong to that module, and so does this one. It builds on the duration and finish time written by #1469 and on the error code stored by #1386. Later issues add to the response: #1695 fills `meetingNotes`, #1830 changes how `displayName` is derived, #1767 adds the state of each action item. Several later routes in the same manifest (#1636, #1770, #1697, #1642, #1832, #1757) are ordered after this one because they edit the same manifest and route matrix.

Decisions:

- `displayName` returns the transcript's `name` property for now; #1830 replaces the derivation.
- `meetingNotes` is `null` until #1695 produces structured notes; this issue only reserves the field.
- `playback` points at the original uploaded file (the source Files item's blob and mime type). A later change may point it at a playable rendition (#1577).
- The whole `segments` array is returned (no paging): client-side search over the text needs all of it.
- `notes` (the user's own `notes` property) is returned separately and never mixed into the generated content.

Shared-file ordering: this issue also waits for #1574 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add `backend/packages/data/src/transcription/transcriptDetail.ts` with `readTranscriptDetail(client, transcriptId, locale)`, and a route handler `createTranscriptDetailRouteHandler(pool)` in `transcriptionRouteHandlers.ts` (duck-typed context like the speakers handler; locale from `ctx.identity.user.locale`). Refactor the speaker-label composition of the speakers handler (mapped person name, or the localized `transcript.speaker.unmappedLabel` with the ordinal) into one function used by both routes, so the two never disagree.
2. The response body (all keys always present, `null` where the data does not exist yet):
   - `id`, `displayName`, `date` (the recording time as stored), `durationSeconds` and `finalizedAt` (from `computed` as written by #1469), `language` (`computed.language`, a code or `null`), `speakerCount`;
   - `speakers`: `[{ speaker, ordinal, label, personId, firstStartsAt }]` in order of first appearance, `label` as in the speakers route, `firstStartsAt` the start of that speaker's first segment;
   - `segments`: `[{ index, speaker, label, text, startsAt, endsAt }]`, `index` the stable position in `computed.segments`, `label` the speaker's resolved label;
   - `meetingNotes`: `null`;
   - `notes`: the `notes` property or `null`;
   - `event`: `{ id, name, date }` of the live Event linked through Transcripts `event`, or `null` (no edge, or the Event is in the trash);
   - `playback`: `{ blobId, mimeType }` of the source Files item's file (found through the transcript's `link`, see `readTranscriptionSourceFileItemId`), or `null` when there is no source file;
   - `automation`: `{ status, attempts, lastAttemptAt, errorCode }` from the transcript's `item_automation` row (`library/itemAutomationStore.ts`), `errorCode` from the column added by #1386; the free-text error message is never returned;
   - `openQuestions`: `{ count, first }` over the transcript's cards in Processing proposals with `kind = transcript`, `status = proposed`, linked through `sourceTranscript`, whose stored envelope is a speaker mapping (a `relation` envelope on the `speakers` property); `count` is their number and `first` is `{ proposalId, speaker, ordinal }` of the one with the lowest speaker ordinal, or `null` when `count` is 0.
3. A transcript still being processed (no segments yet) returns empty `speakers` and `segments` and `speakerCount: 0`, not an error.
4. A malformed id answers `400 validation_failed` like the speakers route. A foreign tenant's id, an unknown id and a trashed transcript answer with the identical `404` body (row-level security already hides foreign rows; do not add a branch that reveals the difference).
5. Register the route in `systemDatabasesModuleManifest.ts` (`customRoutes`: name `getTranscript`, `GET /api/transcripts/:id`, `handlerExport: "createTranscriptDetailRouteHandler"`, justification `single-consumer-read`), re-export the handler in the export block at the top of that manifest file (the way the other transcript handlers are), add the entry to `backend/services/semprec-api/src/routeMatrix.ts`, the case to `backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts` (its per-route case table and its request list) and the handler-file mapping to `backend/services/semprec-api/src/__tests__/chokePointWriteBoundary.unit.test.ts`.
6. Tests in `backend/packages/data/src/transcription/__tests__/transcriptDetail.test.ts`: a finished transcript with two speakers, one mapped; label changes after mapping the other without any reprocessing; a transcript without segments; an Event link, a trashed Event; open speaker cards counted; foreign and unknown ids return byte-identical 404 bodies.

## Scope

### In scope

- The read-only `GET /api/transcripts/:id` route and the response shape above.
- Sharing the speaker-label composition with the existing speakers route.

### Out of scope

- Filling `meetingNotes` and replacing speaker tokens in generated text: #1695.
- Deriving `displayName` from the Event and the recording date, and the suggested name from the generated title: #1830.
- The per-action-item state: #1767.
- A playable audio rendition: #1577.
- A lightweight transcript list: #1636.
- Speaker cards that carry no stored envelope: #1640 extends `openQuestions`.
- Writing anything; mapping speakers still goes through the generic relation endpoint.

## Acceptance criteria

- When a transcript is requested, one call returns its header, speakers, all segments, notes, linked Event, playback source and automation state.
- When a speaker is mapped to a person afterwards, the next call returns the person's name as that speaker's `label` in `speakers` and in every segment, with no reprocessing.
- When a transcript has failed permanently, `automation.status` is `error` and `automation.errorCode` is set; the exception text appears nowhere in the response.
- When the id belongs to another tenant or does not exist, the response is the same `404` as for an unknown id.
- When the transcript has two speaker cards waiting, `openQuestions.count` is 2 and `first` names the lower-ordinal speaker.
- `pnpm run verify` passes in `backend`, including the route matrix and tenant isolation tests.
