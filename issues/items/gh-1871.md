## Context

Model tier rationale: One read-time derivation registered in the established status problem mechanism, with localized texts and a time-zone-aware reset time; no new process, table, lifecycle or refresh ownership.

The Semp status endpoint (`GET /api/semp-status`, introduced by #1555) lists the problems that stop Semp from working, each with localized text and actions, and clients refresh it when they receive a Semp status invalidation (#1868). It has no notion of AI budget. Today, when a tenant has no budget row, or its daily or monthly cap is used up, the AI gateway silently refuses every call (`assertWithinBudget` in `backend/packages/ai-gateway/src/gateway.ts`, which only logs the cause and throws the same `BudgetExceededError` for all causes; the tenant check reads `tenant_ai_budgets`). The user then sees failing agent runs with no explanation of the underlying state.

This issue makes the status report two problems: "AI has no limit set" and "Limit exhausted, resets at {time}". The figures come from the summary of #1456, so the status shows the same numbers the gateway enforces. The problems are derived at read time: nothing is stored in a table and no nightly job re-evaluates them. Pushing a status refresh to connected clients when the gateway first refuses a call because of the tenant's cap, and again when the window resets, are #2023 and #2024; this issue only makes every status read correct.

Decisions: (1) the problem keys are `aiBudgetMissing` and `aiBudgetExhausted`. (2) Only the tenant's own caps produce a problem; a refusal caused by an operator-wide cap is not the tenant's state and must not be revealed. (3) New accounts get no default cap: a tenant without a budget row has no AI (fail-closed) and shows `aiBudgetMissing` until an administrator sets its limits (decided by the product owner).

## Task

Load `canonical-keys` and `testing`.

1. In the status problem mechanism delivered by #1555, add two problem sources evaluated on each `GET /api/semp-status`, following that issue's registration pattern: `aiBudgetMissing` when the summary of #1456 reports `hasBudget` false, and `aiBudgetExhausted` when it reports `exhausted` `daily` or `monthly`, with the reset time as a parameter of the text. Texts are i18n catalog entries in the catalog used by that mechanism (cs and en, canonical English keys), the reset time is formatted in the tenant's time zone and the user's locale. No new table row is written.
2. Tests: status contains `aiBudgetMissing` for a tenant without a row; after spending past the cap it contains `aiBudgetExhausted` with the correct reset text in cs and en; after the window rolls the problem is gone on the next read; when only an operator-wide cap is reached, neither problem is listed.

## Acceptance criteria

- When a tenant has no budget row, then the Semp status lists the "no limit" problem; after an admin sets limits, the problem disappears on the next status read.
- When a cap is exhausted, then the status lists the exhausted problem with the reset time in the tenant's time zone and the user's locale.
- When the reset instant has passed, then the next status read no longer lists the exhausted problem.
- When only an operator-wide cap refuses a call, then no budget problem is shown.
- No row is written to any table when the status is read.
