**Blocked by:** #1896
**Model tier:** medium

## Context

Model tier rationale: One read-model extension across the list and detail endpoints using the existing link shape, with a batched query to keep the list free of per-row lookups.

The thread list (#1567) and the thread detail (#1632) do not yet say which company and project a thread has or whether they are inherited. After #1573 the values are edges Threads.company and Threads.project, and after #1869 they may be inherited. The value-link read shape defined by #1403 describes inheritance as `valueKind` `inherited` or `inheritedBroken`, `sources` and `brokenBy`.

Shared-file ordering: this issue also waits for #1896 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. Extend the list rows and the detail response of the mail threads routes with `company` and `project`, each `{ id, name } | null`. A soft-deleted company or project reads as `null`.
2. Add `links` to both responses in the shape of #1403: an object keyed `company` and `project` that contains an entry only for a property that has a value-link row, with `valueKind` (`inherited` | `inheritedBroken`), `sources` (item sources and the `senderDomain` variant `{ kind: 'senderDomain', domain }` added by #1869) and `brokenBy`.
3. Resolve all values for a page of threads with one query per concern (edges, names, links), not one per row; pin `database_id` in item lookups.
4. Add the cases to the tenant-isolation route test for the changed routes; no new route is added.

## Scope

### In scope

- `company`, `project` and `links` on the thread list rows and the thread detail.

### Out of scope

- Computing inheritance (#1869) and assigning a project by Semp (#1872).
- Attachment project and links in the detail (#1922); tasks in the detail (#1692).
- The unlink and relink operations (#1587).

## Acceptance criteria

- A thread with an inherited company and project returns both names and `links.company.valueKind` and `links.project.valueKind` equal to `inherited` with their sources.
- After a user sets the project by hand, the response shows the project with `links.project.valueKind` equal to `inheritedBroken` and a `brokenBy` entry; a thread with an own value that never had a link has no `links` entry for it.
- A thread without company or project returns `null` for both and an empty `links` object.
- Loading 50 threads runs a constant number of queries, independent of the count.
