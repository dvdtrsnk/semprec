**Blocked by:** #1721, #1877
**Model tier:** medium

## Context

Model tier rationale: Mostly pass-through and tests over blockers' behavior, but it spans recurrence expansion, day-boundary arithmetic and calendar assignment, so wrong assumptions about the timeline surface only as day-edge errors.

#1721 puts the day's events, read through the shared calendar timeline function, into the Journal day response. Three kinds of event need the guarantee that the day shows them correctly: a recurring event (a stand-up every working day, expanded into virtual occurrences by #1877), an event that spans midnight or several days, and the calendar the event belongs to (#1761 assigns every Event to a calendar through a default-calendar create hook).

The id of a virtual occurrence has the form `<seriesId>@<date>` (defined with the occurrence expansion); the Journal passes it through unchanged so the client can open or reference the occurrence.

Decision: the colour of a row is the colour of the calendar the event belongs to, resolved by the client from `calendarId` against the calendars database; the response does not carry a colour of its own.

## Task

Load `testing`.

1. Ensure the Journal day response keeps, for every event element, `calendarId`, `endDate` and the occurrence id as given by the timeline, with no filtering that would drop virtual occurrences or the second day of a multi-day event.
2. Add tests with fixtures: an event from 2026-10-16 23:30 to 2026-10-17 00:30 appears in the day response of both days; a stand-up recurring Monday to Friday appears on 2026-10-19 and not on 2026-10-17, with an occurrence id of the form `<seriesId>@2026-10-19`; every returned event carries the `calendarId` of its calendar (for example the default one).
3. Fix any gap found in how the Journal handler maps timeline items (for example a dropped field), not in the timeline.

## Touches

- backend/packages/data/src/journal/journalRouteHandlers.ts (mapping of timeline items, only if a field is dropped)
- backend/packages/data/src/journal/__tests__/ (recurring, overnight and calendar tests)

## Scope

### In scope

- Guaranteeing and testing recurring, overnight/multi-day and calendar-assigned events in the Journal day.

### Out of scope

- The day's events themselves; #1721.
- Occurrence expansion and its materialization; #1877.
- The default-calendar create hook; #1761.
- A colour field on the response.

## Acceptance criteria

- When an event runs from 16 Oct 23:30 to 17 Oct 00:30, then it appears in the events of both days.
- When a Monday-to-Friday stand-up is read for 2026-10-19, then it appears with an occurrence id of the form `<seriesId>@2026-10-19`; for 2026-10-17 (Saturday) it does not appear.
- When any event is returned, then it carries the `calendarId` of its calendar.
