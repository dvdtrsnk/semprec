**Model tier:** high

## Context

Model tier rationale: It adds a system-owned property to a schema-locked database for all tenants and a new cross-process write into the Inbox from the media process, with single-writer ownership and a gateway audio call that must stay idempotent.

A short voice note ("at the doctor: blood pressure 135/85, measure it for two weeks") should become the text of the Inbox item so the assistant can read it and the card can quote it. Today the Inbox has `text`, which the person owns (`backend/packages/data/src/seed/seedInboxPipeline.ts`), and the single-writer rule (`docs/adr/2026-09-10-single-writer-ownership-model.md`) forbids the server from writing it. Audio is transcribed only for Files items (#1965 classifies an audio attachment as `voiceNote` below `INBOX_RECORDING_MIN_SECONDS`, `recording` at that boundary or longer). `semprec-transcribe` already calls the gateway's transcription route through `audioGatewayClient.ts`.

This issue adds the system-owned property `Inbox.transcribedText` and a job that fills it from the voice-note attachments. The assistant reads `text ?? transcribedText`; that choice, and the fingerprint, are made by #1987 and #1606.

Decisions:
- `transcribedText` is a `text` property, owner `system`, owner process `transcribe` (`TRANSCRIPTION_OWNER_PROCESS`), with the Czech label "Přepis" and English "Transcribed text".
- The job collects every `voiceNote` attachment of the item in position order and writes their transcripts joined by a blank line; it is keyed per Inbox item and replaces itself, so a second attachment re-runs it over all.
- A transcript is written even when `text` is non-empty; `text` is never changed.
- A recording at or above the shared threshold of #1965 is not transcribed here (#1985).

## Task

Load `db-migrations`, `state-writes`, `canonical-keys`, `io-hardening` and `testing`.

1. Add `transcribedText` to the Inbox properties in `seedInboxPipeline.ts` (owner `system`, owner process `TRANSCRIPTION_OWNER_PROCESS`) and its labels to the Inbox catalogs (`backend/packages/data/src/inbox/i18n/cs.json` and `en.json`).
2. Add the per-tenant cutover `backend/packages/data/src/seed/inboxTranscribedTextCutoverMigration.ts` (raw SQL after `LOCK TABLE properties IN EXCLUSIVE MODE`, pattern `transcription/transcriptsCatalogCutoverMigration.ts`; skips a missing Inbox database or an existing property), registered in `runTenantCutoverMigrations`.
3. Add the core task `inboxVoiceNoteTranscribe` (affinity `transcribe`, tenant lane) in `packages/queue/src/index.ts`, enqueue it from the end of the metadata job of #1965 when an attachment's `audioKind` is `voiceNote` (job key `inbox-voice-note:<inboxItemId>`, replace mode), and register it in `backend/services/semprec-transcribe/src/queueRuntime.ts`.
4. Implement the handler in `backend/services/semprec-transcribe/src/inboxVoiceNoteTranscribe.ts`: read the item's `voiceNote` attachments, transcribe each through `audioGatewayClient.transcribe` (audio bytes from storage, `audioSeconds` from the metadata), join the texts, and write `transcribedText` through the choke point as the `transcribe` owner process. Unchanged text writes nothing. A gateway failure fails the job for retry and never alters `text`.
5. Tests: a 40-second voice note fills `transcribedText` and leaves `text` unchanged; two voice notes are joined in order; a recording above 120 seconds is not transcribed; a rerun with the same text writes nothing; a gateway failure retries; a user cannot write `transcribedText` (403 `owner_violation`); a second tenant is untouched; the cutover adds the property to an existing tenant and a second run changes nothing.

## Scope

### In scope

- The `Inbox.transcribedText` property for new and existing tenants and the short-voice-note transcription job.

### Out of scope

- Classifying audio and the metadata job: #1965.
- Routing long recordings: #1985.
- Using `text ?? transcribedText` in the assistant input: #1987.
- The fingerprint including `transcribedText` and attachments: #1606.
- Dictated text sent by the client as `text`; it needs no server work.

## Acceptance criteria

- When a 40-second voice note is attached, then `transcribedText` holds its transcript and `text` is unchanged.
- When two voice notes are attached, then `transcribedText` holds both transcripts in order.
- When an attachment is a recording (including exactly 120 seconds), then nothing is transcribed by this job; test 119, 120 and 121 seconds using the classification of #1965.
- When a user tries to write `transcribedText`, then the write is refused as an ownership violation.
- When the job runs twice with the same result, then the second run writes nothing.
