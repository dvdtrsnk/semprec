## Context

Model tier rationale: The same hook mechanism as for pages applied to every other database, with an existing helper for the subtree and trash fixtures, but it runs on every deletion in the system so the no-subpage path must be cheap and safe.

Pages that hang under a host item (a project's notes, an area, an event, a Journal day) are items of the hidden `pages` database with a `parentItemId` pointing at the host (#1676). The generic cascade of `itemDeleteWithClient` (`backend/packages/data/src/chokePoint/itemTrash.ts`) knows only inline databases, so deleting a host leaves its subpages live and reachable by link, and restoring it restores nothing of them. #1723 registers delete and restore hooks for Pages items and a helper that collects a page's subtree; the hooks of #1601 run for every row of the cascade, including the rows of a host's inline databases.

This issue extends the same hooks to every other database so that deleting a host trashes its subpages (with the host's `deletedAt`), and restoring the host restores the subpages trashed with it. Each trashed subpage removes its block from the host's document and records its position, exactly as #1723 defines, so after the restore the host's notes look as before.

Decisions:
- The hooks run for items of every database except `pages` (that case is #1723) and exit immediately when the tenant has no `pages` database or the item has no live subpages; no schema change or index is added because the `pages` partition is small.
- A subpage that was already in the trash before the host was deleted stays there when the host is restored.

Shared-file ordering: this issue also waits for #1761 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

### Out of scope

- Deleting and restoring a page itself and its nested pages: #1723.

- The impact preview of a host's deletion: #1856.
- Permanent purge of hosts (it runs no hook).

## Acceptance criteria

- When a project with two subpages is deleted, then both subpages and their nested pages are hidden and their blocks are gone from the project's notes; restoring the project returns them and the blocks.
- When a subpage was trashed before its host, then restoring the host leaves it in the trash.
- When a project without subpages is deleted, then the behavior and the number of queries on the delete path are the same as before for the page hooks (no extra write).
- When a hook fails, then the host and its subpages stay live.
