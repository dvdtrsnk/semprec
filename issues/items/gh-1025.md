## Context

Model tier rationale: The envelope SQL is given, but the scope changes span publishers, the listener, socket routing and many test assertions.

Every realtime message rides two Postgres channels, `semprec_events` and `semprec_agent_stream` (`backend/packages/realtime/src/pgNotifyPublisher.ts:10-12`), and is published as the bare message JSON (`publishRealtimeMessage`, `:46-48`; `publishAgentRunDelta`, `:63-91`). No payload says which tenant it belongs to. The listener in `createSyncServer` (`backend/packages/realtime/src/syncServer.ts:298-383`) routes an `invalidation` to the acting user's sockets when `userId` is present and otherwise **broadcasts it to every connected socket** (`:347-353`, `broadcast` at `:241-245`). The fallback is documented in `backend/packages/data/src/realtimeHook.ts:15-20` and decided in `docs/adr/2026-09-12-thin-user-scoped-realtime-invalidations.md`. Background writes fire invalidations without a user (e.g. `backend/packages/data/src/rollup/recompute.ts:136`, `backend/packages/data/src/inbox/journalInboxCompute.ts:221`), so with two tenants this fallback would send one tenant's item ids to every other tenant's sockets.

Postgres row-level security keyed on the GUC `app.tenant_id` already exists, and so does the tenant scope from #978: `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()` in `@semprec/shared`. A tenant may be entered from a system scope; `runAsSystem` inside a tenant throws `TenantScopeConflictError`. `withTransaction`, autocommit `pool.query` and `pool.connect()` clients set `app.tenant_id` from that scope. `app_tenant_default()` returns `COALESCE(app_current_tenant(), app_sole_tenant())` until #1067 redefines it to `app_current_tenant()` alone. #980 adds the tenant id to the identity `authenticateRequest` returns and answers 401 for a non-active tenant. #991 runs agent jobs inside their job's tenant.

Sessions are global identity rows, and they are revoked from scopes that are not the session owner's tenant: password reset, and later the admin plane under `runAsSystem`. Their tenant must therefore come from the session's user, not from the publisher's scope.

This issue supersedes the broadcast ADR. #1026 (doc sync) and #1027 (agent-run watching) build their per-registry tenant checks on the envelope and socket tenant added here.

## Task

Load `io-hardening` (NOTIFY payloads are untrusted boundary input), `error-handling` (drop-and-log paths) and `adr-conventions` (supersession).

1. **Envelope built by Postgres.** In `pgNotifyPublisher.ts`, both publishers send a fixed envelope `{ "tenantId": <uuid|null>, "message": <message> }`. The tenant is computed in the same statement from the publisher's own scope, never taken from the message body:
   `SELECT pg_notify($1, json_build_object('tenantId', app_tenant_default(), 'message', $2::json)::text)`.
   - For `session_revoked`, the tenant expression is `(SELECT COALESCE(u.tenant_id, app_sole_tenant()) FROM sessions s JOIN users u ON u.id = s.user_id WHERE s.id = $3::uuid)` (the same binding #980's `getUserTenantBinding` gives the socket), with `$3` the message's `sessionId`. Both tables are global.
   - `publishAgentRunDelta` keeps its chunking and its constants (`:13-14`). `MAX_AGENT_STREAM_NOTIFY_BYTES = 7_500` plus the envelope (under 100 bytes; `json_build_object` embeds the `json` argument verbatim) stays below Postgres's 8000-byte cap.
   - `RealtimeMessage` and `AgentStreamMessage` themselves do not gain a tenant field.
2. **Parse the envelope.** Add `parseRealtimeEnvelope(raw)` and `parseAgentStreamEnvelope(raw)`. Each returns `{ tenantId: string; message }` only when `tenantId` passes `isUuid` and `message` passes the existing `parseRealtimeMessage` or `parseAgentStreamMessage`; otherwise it returns `null`.
3. **Socket tenant.** `SyncIdentity` (`syncServer.ts:20-23`) gains `tenantId: string`. `backend/services/semprec-api/src/syncHandler.ts:18` fills it from `identity.tenantId`, which #980 added to `AuthenticatedIdentity`.
4. **Tenant-only delivery.** In `syncServer.ts`:
   - Delete `broadcast`.
   - Replace `sendToUser` with `sendToTenant(tenantId, frame, userId?)`, which sends to open sockets whose `identity.tenantId === tenantId` and, when `userId` is given, whose `identity.userId === userId`.
   - Item and schema invalidations use it with the optional `userId`.
   - `forwardNotification` uses it after its existing ownership re-check (`:273-276`).
   - `session_revoked` closes only sockets matching both `sessionId` and `tenantId`.
5. **Drop and log.** An envelope that fails to parse is dropped with one `logger.warn({ channel, type }, "realtime_message_without_tenant")`. `type` is the inner message's `type` when readable. Use `createLogger("realtime")` from `@semprec/shared`; the line carries no payload content.
6. **Scopes in the listener.**
   - Open the LISTEN connection (`connectListenClient`, `:224-234`, including reconnects) inside `runAsSystem("realtime:listen", …)`.
   - Handle every parsed envelope inside `runInTenant(envelope.tenantId, …)`. This covers the `getNotificationById` fetch, `enqueueAgentEvent`, `docSync.fanOutDocUpdate` and `agentRunWatch.forwardDelta`, so their row reads run under the message's tenant.
   - Run `options.authenticate` (`:443-444`) inside `runAsSystem("realtime:upgrade", …)` and `options.revalidateSession` (`:205-206`) inside `runAsSystem("realtime:revalidate", …)`. Both read only global identity tables.
7. **Dependency.** Add `"@semprec/shared": "workspace:*"` to `backend/packages/realtime/package.json` and update `backend/pnpm-lock.yaml`.
8. **ADR.** Add `docs/adr/<YYYY-MM-DD>-tenant-scoped-realtime-fan-out.md` with `supersedes: [2026-09-12-thin-user-scoped-realtime-invalidations]`. It records:
   - thin payloads, the full-row notification exception, the ownership re-check and no-replay all stay;
   - the Postgres-computed tenant envelope;
   - tenant-only delivery, with `userId` as an optional narrowing inside the tenant;
   - drop-and-log;
   - that `doc:open`, doc writes and `agent:watch` resolve inside the socket's tenant (#1026, #1027), which narrows the "no authorization boundary" statements of `[[2026-09-12-per-process-doc-sync-subscription-registry]]` and `[[2026-09-12-per-process-agent-run-watch-registry]]` without superseding them.

   In the old ADR, edit the frontmatter only: `status: superseded`, `superseded-by: <new slug>`. Rewrite the stale comment at `realtimeHook.ts:15-20`.
9. **Tests.** Update the payload assertions in `backend/packages/realtime/src/__tests__/realtime.test.ts`, `backend/packages/agent-runtime/src/__tests__/lifecycleAdapter.test.ts:145-195` and `backend/services/semprec-transcribe/src/transcriptionTask.test.ts:1216-1250` to the envelope. In `syncServer.test.ts`, every `SyncIdentity` gains a `tenantId`, and the broadcast test at `:424-443` is replaced.

## Acceptance criteria

- **Envelope from scope.** When `notifyInvalidation` fires inside `runInTenant(T)` on a pool from `createPool`, the `semprec_events` payload is `{"tenantId": T, "message": {...}}`. A `tenantId` key placed inside the message body does not change the envelope's `tenantId`. (integration, `realtime.test.ts`)
- **Sole-tenant fallback.** When a hook fires with no scope while exactly one `tenants` row exists, the envelope carries that tenant's id. (integration, `realtime.test.ts`)
- **Delta envelope.** `publishAgentRunDelta` inside `runInTenant(T)` produces envelopes with `tenantId` T. A delta that needs chunking still yields only payloads under the 8000-byte cap. (integration, `syncServer.test.ts`)
- **Revocation tenant.** A `session_revoked` published inside `runAsSystem` carries the tenant of the session's user. (integration, `realtime.test.ts`)
- **Invalidation delivery.** With sockets authenticated as tenant T and tenant U:
  - an invalidation enveloped for T without `userId` reaches only T's sockets;
  - one with `userId` reaches only that user's T sockets;
  - U's sockets receive nothing.

  (integration, `syncServer.test.ts`)
- **Notification delivery.** A `notification_created` enveloped for U, naming T's user and notification, delivers nothing. Enveloped for T, it reaches T's user's socket. (integration, `syncServer.test.ts`, with a runtime-role pool from the #975 harness so RLS applies)
- **Revocation delivery.** A `session_revoked` enveloped for U, naming a T socket's session, closes nothing. Enveloped for T, it closes that socket with 4401. (integration, `syncServer.test.ts`)
- **Drop and log.** A raw `pg_notify` on either channel whose envelope lacks `tenantId`, has `null` or a non-uuid value, or is the bare pre-envelope message shape reaches no socket. Exactly one `realtime_message_without_tenant` warning is logged, naming the channel and type and no content. (integration, `syncServer.test.ts`)
- **Envelope parsing.** `parseRealtimeEnvelope` and `parseAgentStreamEnvelope` accept a valid envelope. They reject a missing, `null` or non-uuid `tenantId` and an invalid inner message. (unit, `protocolV1.unit.test.ts`)
- **Strict mode.** With `SEMPREC_TENANT_SCOPE=strict` set after the test session was created:
  - a WS upgrade with a valid session opens a socket;
  - a revoked session is closed by heartbeat revalidation;
  - no `TenantScopeMissingError` is thrown.

  (integration, `syncHandler.test.ts`, with the server's pool built by `createPool`)
- **ADR.** The new ADR exists with `supersedes`. The old ADR differs only in `status` and `superseded-by`. (review)
