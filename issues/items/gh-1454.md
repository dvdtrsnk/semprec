## Context

Model tier rationale: This changes the ownership of a locked system property across all existing tenants via a cutover and adds a schema column other mechanisms rely on for identity, so an error affects sending checks, routing and duplicate detection.

The `Mailboxes.addresses` property is declared `owner: "user"` in `backend/packages/data/src/seed/seedEmailModule.ts`. The generic item PATCH and the agent's `item.patch` can therefore change it without approval. The sender check in `backend/packages/data/src/mail/send.ts` compares the `from` address against this list, which is why Gmail Pub/Sub routing (`gmailWatchLifecycle.ts`, migration `0071_gmail_watch_address_routing.sql`) was built on `mail_account_sync_state.gmail_watch_email_address` rather than on `addresses`.

Mailbox connection (#1686 for Google and Microsoft, #1736 for iCloud and generic IMAP) needs an address that comes from the provider and cannot be edited by the user, plus a place to remember it for duplicate detection and for checking that a reauthorization signs in the same account. Gmail watch lifecycles (#1739) also need it to be the routing address.

This issue makes the address server-owned and provider-verified; it does not create any mailbox.

Decision: `provider_account_address` is a new nullable, normalized column, unique per tenant when set. Existing Gmail rows are backfilled from `gmail_watch_email_address` using the existing 0125 migration: within each tenant and normalized non-null Gmail-watch address group the lowest item id is the deterministic survivor; duplicate losers remain NULL. Preserve the original watch column and all mailbox rows; do not rewrite applied 0125 or merge accounts. other existing rows stay null until the next reauthorization or edit by the connect flows, and null never blocks anything.

Shared-file ordering: this issue also waits for #1407, #1451 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Acceptance criteria

- When authenticated REST `PATCH` or agent `item.patch` sets `Mailboxes.addresses`, the underlying domain refusal is 403 `owner_violation` in fresh and cut-over tenants. REST returns HTTP 403; the agent preserves its native error tool envelope containing `owner_violation`. Assert persisted no effect and a same-owner user-field positive control through both actual transports.
- When the cutover runs twice, then the second run changes nothing; a tenant without a Mailboxes database is skipped.
- When two mailboxes of one tenant get the same provider address (any letter case), then the second write conflicts; the same address in two tenants is allowed.
- After actual 0125 migration, every distinct per-tenant normalized Gmail watch-address group has its value on the lowest-item-id survivor; duplicate losers remain NULL, retaining their old watch values and rows. Nonduplicate rows are copied and equal addresses in different tenants remain allowed. This explicitly replaces the impossible universal-copy criterion for historically permitted duplicates.
- Reading and sending with the existing `addresses` value keeps working for mailboxes created before the change.
