## Context

Model tier rationale: It changes the runtime resolution contract of eight workspace packages that every service and the three test tiers consume, and adds a guard to the production deploy script that runs before a release is promoted. A wrong export condition fails loudly only in a built artifact, never in the source-level test tiers, so a correct fix needs exact consumer analysis and tests that run the real compiled entries as child processes.

Source sp-62b97861-bb73-46ec-83d7-2dcfd881b16a repaired the native resolution of the migration entry only. It changed four workspace roots (`@semprec/shared`, `@semprec/queue`, `@semprec/module-registry`, `@semprec/block-model`) so that plain Node selects `dist/index.js` while types, browser-aware consumers and the three backend Vitest tiers keep the source entry. Its accepted ADR (`docs/adr/2026-11-03-native-workspace-root-exports.md`, referenced as `[[2026-11-03-native-workspace-root-exports]]`) says that this is not proof that every compiled service starts and that any newly reached workspace root needs concrete analysis and a decision instead of a wildcard manifest change. That analysis was made at commit `30753cc6e` by building the backend in a private export of the tree (`pnpm install --frozen-lockfile --package-import-method=copy`, then `pnpm -r run build`, as `deploy/deploy.sh` `build_release` does) and running every compiled entry that the deploy scripts, the systemd units and the restore runbook start as a plain `node <dist entry>` from `backend/`, with a scrubbed environment, under Node 22.19.0 and Node 26.12.1:

- Start from plain Node (they stay as they are): `packages/data/dist/db/runMigrationsCli.js`, `runSeedCli.js`, `verifyTenancyCli.js`, `packages/data/dist/tenancy/validateRestoreLedgerCli.js`, `restoreTenantKeysCli.js`, `replayTenantDeletionsCli.js` and `packages/data/dist/observability/restoreTestResultCli.js`. Each reaches only the four repaired roots.
- Fail before any application code, with `ERR_MODULE_NOT_FOUND`: `services/semprec-api/dist/serve.js`, `services/semprec-agents/dist/serve.js`, `services/semprec-ai-gateway/dist/serve.js` and `services/semprec-transcribe/dist/serve.js` (the four units that `deploy.sh` restarts after it moves `current`). Examples: `Cannot find module '.../packages/data/src/mail/mailSearchTextReindexJob.js' imported from '.../packages/data/src/index.ts'` and `Cannot find module '.../packages/agent-runtime/src/types.js' imported from '.../packages/agent-runtime/src/index.ts'`. The cause is that eight workspace roots still have `"main": "src/index.ts"` and, for seven of them, no `exports` map: `@semprec/data` (its root export is `./src/index.ts`), `@semprec/realtime`, `@semprec/application`, `@semprec/notifications`, `@semprec/ai-gateway-client`, `@semprec/ai-gateway`, `@semprec/agent-runtime` and `@semprec/credentials`.
- Experiment: applying the ADR's pattern to exactly these eight manifests and rebuilding made `semprec-ai-gateway` log `semprec-ai-gateway listening`, and `semprec-agents` and `semprec-transcribe` log `... queue runtime started`, against a scratch database as the runtime roles, each exiting 0 after SIGTERM. A static walk of the compiled import graphs of all eleven entries finds exactly twelve workspace packages (those eight plus the four already repaired) and no `@semprec/*` subpath import in any compiled file. The packages `e2e`, `module-boundaries`, `realtime-client` and `release` are reached by no entry.

`deploy.sh` runs the migration, seed and tenancy steps in the staged release and only afterwards moves `current` and restarts the four services, so today a release whose services cannot start is promoted and the failure appears after the switch.

One further defect was found by the same run and is not part of this source: `semprec-api` exits at start with `TenantScopeMissingError: No tenant scope is active at withTransaction` under the production default of strict tenant scope (`SEMPREC_TENANT_SCOPE` unset), because `createApiQueueRuntime` in `services/semprec-api/src/queueRuntime.ts` calls `runHeartbeatFireQueueSplitMigration(pool)` outside any scope. It is a data-layer scope defect that needs its own source. This source therefore proves the API only up to its own configuration refusal (see Task step 6) and does not claim that the API starts.

## Task

Load `testing`, `adr-conventions` and `io-hardening` before writing the child-process test and the checker.

1. Apply the contract of `[[2026-11-03-native-workspace-root-exports]]` literally to these eight manifests and no other: `backend/packages/data/package.json`, `backend/packages/realtime/package.json`, `backend/packages/application/package.json`, `backend/packages/notifications/package.json`, `backend/packages/ai-gateway-client/package.json`, `backend/packages/ai-gateway/package.json`, `backend/packages/agent-runtime/package.json` and `backend/packages/credentials/package.json`. In each, `main` becomes `dist/index.js`, `types` stays `src/index.ts`, and the root export becomes the ordered object `{ "types": "./src/index.ts", "browser": "./src/index.ts", "default": "./dist/index.js" }`. `@semprec/data` keeps `./testSupport` and `./testSupport/mcpContractServers` exactly as they are. Add no `exports` entry for any subpath (no compiled or source file imports a `@semprec/*` subpath except the `@semprec/data/testSupport*`, `@semprec/queue/testSupport` and `@semprec/shared/src/logger.js` spellings that already exist). Change no tsconfig and no build script: all eight packages already emit their JavaScript to `dist` (the whole backend build was verified with these manifests).
2. In `backend/vitest.unit.config.ts`, `backend/vitest.integration.config.ts` and `backend/vitest.e2e.config.ts` add one exact alias per new root to its source entry, spelled like the existing ones: `find: /^@semprec\/<name>$/` and `replacement: fileURLToPath(new URL("./packages/<name>/src/index.ts", import.meta.url))` for the eight names above. Alias no other `@semprec/*` import and no subpath. The tiers must keep testing source, never `dist`.
3. Add `backend/scripts/check-native-entrypoints.mjs`, a plain ESM script with no dependency, run as `node scripts/check-native-entrypoints.mjs [--root <backend directory>]` (the default root is the parent of the script's own directory). It holds one table of the eleven compiled entries listed in Context (paths relative to the backend directory) and runs each one in turn as `process.execPath <entry>` with the working directory set to the root and an environment of `PATH` and `HOME` only (so no `NODE_OPTIONS`, `NODE_PATH`, loader or secret reaches it), no extra argument, a 30-second limit per entry (SIGKILL on expiry) and a 1 MB cap on collected output (kill on excess). It does not wait on a child that it did not start and settles every child before it returns. An entry passes when its output contains its own application refusal and contains no module-resolution failure. The expected refusal is `/ is not set/` for the three database CLIs, the replay CLI, the restore-result CLI, the API, agents, gateway and transcribe entries, `Restore ledger validation failed` for `validateRestoreLedgerCli.js` and `Offline key restore failed` for `restoreTenantKeysCli.js`. A module-resolution failure is any of `ERR_MODULE_NOT_FOUND`, `ERR_PACKAGE_PATH_NOT_EXPORTED`, `ERR_UNKNOWN_FILE_EXTENSION`, `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`, `ERR_UNSUPPORTED_DIR_IMPORT` or `Cannot find module`. The script prints one line per entry (`ok <path>` or `FAIL <path>: <reason>`, never the child's environment and never more than the first 500 characters of its output) and exits 1 if any entry failed or could not be started, otherwise 0. With no configuration every entry refuses before it connects or writes anything, so running it is safe on the staged release.
4. In `deploy/deploy.sh` add a function `verify_native_entrypoints` and call it in `deploy()` directly after `build_release` and before `write_release_env`, so a failure leaves `current` and the running services untouched like a build failure. It runs `systemd-run --quiet --wait --pipe --collect --uid=semprec --gid=semprec --working-directory="$staging_dir/backend" /bin/sh -c 'exec node scripts/check-native-entrypoints.mjs'` with no `EnvironmentFile` property (the check must see no secret) and ends in `|| fail "native entrypoint check failed"`. Update the header comment of `deploy.sh` and the deploy section of `deploy/README.md` with one sentence each. In `deploy/deploy.test.sh` extend the `systemd-run` mock and the existing assertions: the check runs once, after the build and before the migration, with no `EnvironmentFile`; with a state flag the mock fails the check, and then the deploy exits nonzero with `native entrypoint check failed`, no migration, seed or verify command is recorded, `current` is unchanged and the staging directory is removed.
5. Prove source identity of the new roots in the existing style: add the identity of every new root to the unit tier where it can be proved without the PostgreSQL graph and to the e2e tier otherwise. Unit: a new `backend/services/semprec-agents/src/__tests__/workspaceSourceResolution.unit.test.ts` asserts that `createHttpAiGatewayClient` from `@semprec/ai-gateway-client` is the same object as the one exported by `backend/packages/ai-gateway-client/src/index.ts`, loaded with a dynamic `import()` of `fileURLToPath(new URL("../../../../packages/ai-gateway-client/src/index.ts", import.meta.url))` as `packages/data/src/__tests__/workspaceSourceResolution.e2e.test.ts` does (a static relative import across packages fails `tsc` with TS6059 under the service's `rootDir: src`). E2e: extend `backend/packages/data/src/__tests__/workspaceSourceResolution.e2e.test.ts` with `@semprec/credentials`; add `backend/services/semprec-api/src/__tests__/workspaceSourceResolution.e2e.test.ts` for `@semprec/data`, `@semprec/realtime`, `@semprec/application`, `@semprec/notifications` and `@semprec/ai-gateway-client`; add `backend/services/semprec-agents/src/__tests__/workspaceSourceResolution.e2e.test.ts` for `@semprec/agent-runtime`; add `backend/services/semprec-ai-gateway/src/__tests__/workspaceSourceResolution.e2e.test.ts` for `@semprec/ai-gateway`. Each asserts, by one stable exported value per root and an `import()` of the source path, that the alias resolved to source and not to `dist`. Each file imports only packages its own `package.json` declares. Do not overwrite `dist` to prove anything.
6. ## Scope

### In scope

- The root-export contract of the eight named workspace packages, its test aliases and source-identity tests.
- A native, scrubbed-environment check of the eleven compiled entries, in a test and in `deploy.sh` before activation.
- An owned-database start of the gateway, agents and transcribe services in the test.
- The records that state the actual evidence.

### Out of scope

- `semprec-api` starting under strict tenant scope (`runHeartbeatFireQueueSplitMigration` called without a scope in `createApiQueueRuntime`), and any claim that the API starts: a separate source.
- Any change to the four roots of `[[2026-11-03-native-workspace-root-exports]]`, to `e2e`, `module-boundaries`, `realtime-client` or `release`, to a tsconfig or a build script, or an `exports` entry for a subpath.
- A deployment loader, a condition override, a test resolver in deploy, a global host setting, copying source JavaScript or any change of `NODE_OPTIONS`.
- Production services, credentials, a real deployment, the systemd sandbox, the Docker stage of `restoreTenantKeysCli.js`, the real `semprec-mcp-launch` and any claim about a deployed host; the production Security gate stays BLOCKED.
- Provider or network calls (the owned-database start uses placeholder keys and makes none), the mail, restic and backup scripts, and any change of the service code beyond what the Task names.

## Acceptance criteria

- When the backend is built and each of the eleven compiled entries is run as a plain `node <entry>` with an environment of `PATH` and `HOME` only, then none fails with a module-resolution error: each ends in its own application refusal (`... is not set`, `Restore ledger validation failed` or `Offline key restore failed`), and the checker `node scripts/check-native-entrypoints.mjs` exits 0 naming all eleven.
- When the checker is pointed at a root where one entry imports a missing module, then it exits 1 and names that entry only.
- When `semprec-ai-gateway`, `semprec-agents` or `semprec-transcribe` is started from its compiled `serve.js` against an owned database as the runtime role, then it reaches its listening or runtime-started log line, and after SIGTERM it exits 0 within 20 seconds; the scratch database is dropped and absent, and no child outlives the test.
- When `deploy.sh` stages a release, then the native check runs after the build and before the migration without an `EnvironmentFile`; when the check fails, then the deploy stops with `native entrypoint check failed`, no migration, seed or verify command runs, `current` and the running services are untouched and the staging directory is removed. This is proved by `bash deploy/deploy.test.sh` on Linux with GNU coreutils, and the handover reports it as run or NOT RUN.
- When a path of a compiled entry named by `deploy/deploy.sh`, a unit, a script or `deploy/README.md` is not in the checker's table, then the coverage case fails.
- Each of the eight new roots resolves to its source module in the tiers where the identity tests exist, and `dist` is not modified to prove it; the existing four roots, the `testSupport` subpaths and the existing logger-mock alias are unchanged; the complete unit, integration and e2e tiers, the build, the lint and `pnpm run test:repo-scripts` pass.
- The follow-up file and the F5 bullet state exactly what was proved natively, keep the historical failure text, say that the API start under strict scope is open and claim no production readiness.
