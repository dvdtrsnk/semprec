**Blocked by:** #1676
**Model tier:** medium

## Context

Model tier rationale: One read-side extension of an existing path walk and of the page summary read, over the parent link #1676 stores, with a cycle guard and existing fixtures; no writes or new persistence.

A subpage opens full screen with breadcrumbs (for example "Notes > Release checklist"). #1676 stores each subpage as an item of the hidden `pages` database with the system-owned text property `parentItemId` pointing at the host item or parent page, and the mirrored `title`. `getItemPath` (`backend/packages/data/src/chokePoint/itemReads.ts`) follows only `databases.parent_item_id`, so for a Pages item the chain stops at the item itself, and `page.get` (#1615) returns `breadcrumbs: null` for items outside an inline-database chain. This issue was split out of #1676 so that each issue carries one mechanism.

Decision: breadcrumbs are composed from item state only (the Pages `title` mirror and the host's title), never by loading a parent document.

## Task

Load `canonical-keys`, `error-handling` and `testing`.

1. Extend `getItemPath` so that for an item of the Pages database (owner module id from `PAGES_MODULE_ID` of #1676) the chain continues with `parentItemId`, up to the host item and then along the host's own path, guarding with the set of visited item ids (a cycle ends the walk) and a bound of 1000 elements.
2. Make `page.get` (#1615) return `breadcrumbs` for Pages items instead of null, with the same element shape `{itemId, title, databaseKey, journal?}` as for other items; a Journal host keeps its `journal` element.
3. Tests: a subpage "Notes for version 0.4" under "Release checklist" under a project's notes returns breadcrumbs project > Release checklist > Notes for version 0.4 with their titles; a subpage under a Journal day starts with the day element carrying `journal`; the reads load no parent document; a stored cycle in `parentItemId` ends the walk without an error; a foreign tenant's page is a 404.

## Touches

- backend/packages/data/src/chokePoint/itemReads.ts (getItemPath through parentItemId)
- backend/packages/application/src/genericApplicationService.ts (getPage breadcrumbs for Pages items; hotspot)
- backend/packages/data/src/__tests__/ (path and breadcrumb tests)

## Scope

### In scope

- The path walk through `parentItemId` and the `page.get` breadcrumbs of Pages items.

### Out of scope

- Creating subpages and the Pages database: #1676.
- The trash row path of a deleted page: #1855.
- Renaming a subpage: #1725; mirroring titles: #1715.

## Acceptance criteria

- When breadcrumbs of a nested subpage are requested, then they show the host and parent pages with their titles without loading any parent document.
- When the subpage lives under a Journal day, then the first element carries `journal` with the day.
- When `parentItemId` values form a cycle, then the walk ends and the read still succeeds.
