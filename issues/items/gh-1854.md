## Context

Model tier rationale: One additive group contribution to an existing operation, over a new table with a defined shape, reusing the shared query builder, but it introduces a result entry that is not item-backed and a per-actor visibility rule.

The global search operation (#1842) has a `chat` group but no source for it: Semp conversations are not items. The Semp thread tables (`semp_threads`, `semp_messages`) are delivered by #1367. This issue lets a user find a conversation with Semp by its title or preview from the global search. Searching message text is a separate decision (#1783), and the thread list's own search is #1737.

Decisions:
- Matching uses the combined lemma-or-prefix query from #1589 applied on the fly to `title` and the stored preview of each thread (a user's thread count is small, so no new index).
- Only a human actor receives the `chat` group; an agent actor (Semp itself or an MCP client) gets none, because conversations are not part of any granted database.
- Threads are not deleted or archived in v1 (decided by the product owner), so every thread of the human's tenant is a candidate; the match rule and visibility are exactly those of the thread list (#1729, #1737).
- Entries are thread-backed: `{ threadId, title, subtitleParts, snippet }` without `itemId`, `databaseId` or `databaseKey`; `subtitleParts` carries the last activity as `date` and `time` parts in the user's time zone, the same convention the item groups use.

## Task

Load `canonical-keys`, `io-hardening` and `testing`.

1. Add `search/sempThreadSearch.ts`: given the sanitised query and the paging inputs, return the user's matching threads (title or preview), ordered by last activity descending, with `total`, in `runInTenant` scoped to the acting user.
2. Register it as the `chat` contributor in the search operation's group assembly (`search/searchItemsQuery.ts`, extended by #1842), honouring `perGroupLimit`, `cursor` (single-type scope) and the human-actor rule.
3. Keep `snippet` `null`.
4. Never log or echo the query text.
5. Tests: a title match, preview match, diacritic-free and prefix match, `scope=["chat"]` paging, another user's and another tenant's threads excluded, hidden thread excluded, no `chat` group for an agent actor.

## Scope

### In scope

- The `chat` group contribution from Semp thread titles and previews.

### Out of scope

- The thread tables and the thread list: #1367.
- The thread list's own search parameter: #1737.
- Searching message text, and the index for it: #1783.
- The search operation, route and schema (including the thread-backed entry shape): #1842.
- An agent tool for search: the generic search operation already serves agents and MCP, no separate tool is added.

## Acceptance criteria

- A search whose words match a thread's title returns it in the `chat` group with `threadId`, title and last-activity `date` and `time` parts.
- A word that appears only in the thread preview also finds it; a word without diacritics or a partial word matches.
- `scope=["chat"]` returns all matches with paging; without scope the group has at most 4 entries and the real `total`.
- Another user's or tenant's threads, and hidden threads, are never returned.
- An agent actor's response has no `chat` group.
- Neither logs nor errors contain the query text.
