**Blocked by:** #2029
**Model tier:** high

## Context

Model tier rationale: It handles a mailbox's refresh token after the credential row is gone, coordinates a running live-sync lifecycle across the composition root and makes best-effort calls to two providers, where a leaked secret, a failing removal or a lifecycle that keeps running are each easy mistakes.

#1690 adds `DELETE /api/mail/mailboxes/:id`, which removes the mailbox's credential and sync state in one transaction. After the commit three things still run outside Semprec's database: the hosted live-sync lifecycle of the mailbox (IMAP IDLE, Gmail watch or Graph subscription, hosted by the live-sync root in `backend/packages/data/src/mail/mailLiveSyncRoot.ts`, which discovers mailboxes every 60 seconds), the Gmail watch or Graph subscription at the provider, and the OAuth grant the provider still honors. Side effects follow the commit (`docs/adr/2026-09-10-side-effects-follow-the-commit.md`). Route dependencies come from the composition root (#1460).

Decision: the cleanup is best effort and never fails the removal; the removal has already committed when it runs.

## Task

Load `error-handling`, `io-hardening` and `testing`.

1. In `backend/packages/data/src/mail/mailboxRemoval.ts`, inside the removal transaction and before the credential is deleted, read what the provider cleanup needs (the provider, the Gmail watch or Graph subscription id and, for OAuth mailboxes, the refresh token) into memory only. It is never written to the database, a job payload or a log.
2. After the commit, in `backend/packages/data/src/mail/mailboxRemovalProviderCleanup.ts`: stop the hosted lifecycle through the route dependencies (otherwise discovery stops it within 60 seconds), cancel a Gmail watch or Graph subscription, and revoke the token at the provider. Each step runs even if an earlier one failed.
3. A failure of any step is logged with a fixed classification only (no provider error text, no token) and the route still answers success.
4. Tests: after a removal the live-sync lifecycle is stopped at once; the Gmail watch stop, the Graph subscription delete and the token revocation are called for the matching provider with stubbed clients; a provider failure or timeout still returns success and logs only the classification; the token never appears in logs, rows or job payloads; a password mailbox makes no OAuth revocation call.

## Touches

- backend/packages/data/src/mail/mailboxRemovalProviderCleanup.ts (new)
- backend/packages/data/src/mail/mailboxRemoval.ts (read before delete, call after commit)
- backend/packages/data/src/__tests__/mailboxRemovalProviderCleanup.test.ts (new)

## Scope

### In scope

- The best-effort cleanup after a mailbox removal: stopping the hosted lifecycle, cancelling the Gmail watch or Graph subscription and revoking the provider token.

### Out of scope

- The removal route and transaction (#1690).
- Soft-deleting folders and messages, refusing a generic delete and restoring a removed mailbox (#2029, #2031 and #2032).

## Acceptance criteria

- When a mailbox is removed, then the live-sync worker no longer runs for it.
- When a Gmail or Outlook mailbox is removed, then its watch or subscription is cancelled and its token is revoked at the provider.
- When a provider call fails, then the removal still succeeds and the log carries only a fixed classification.
- The refresh token is never stored, queued or logged by the cleanup.
