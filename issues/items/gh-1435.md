## Context

Model tier rationale: Two small store functions in one file following the existing update pattern, with no new table, lifecycle or authorization contract.

The scheduler store `backend/packages/data/src/scheduler/schedulerStore.ts` has `createHeartbeat`, `updateHeartbeatRule` (changes the rule only), `setHeartbeatEnabled` and `listHeartbeatsByProject`. No function changes a heartbeat's name (`project_heartbeats.name`, the assignment text shown as the title of an automation) or its task text (`action_config.task`, the instruction an agent run receives). Users and Semp need to rename an automation and change what it does. The approval-gated agent tools that call these functions are #1846. `project_heartbeats` has no `updated_at`, version or origin column; the origin column is added by #1438 and this issue does not depend on it.

## Task

Load `state-writes`, `error-handling` and `testing`.

1. Add `updateHeartbeatName(client, id, name)`: the name is trimmed, non-empty and at most 200 characters; otherwise a validation error. Returns the updated row or null when the heartbeat does not exist (in the caller's tenant).
2. Add `updateHeartbeatTask(client, id, task)`: sets `action_config.task` (jsonb set, other keys of `action_config` kept) for a heartbeat whose action is `core.agentRun`; for another action it is rejected with a validation error. The task is a non-empty string within a reasonable bound (4000 characters).
3. Both accept a `Pool | PoolClient`, matching the other store functions, and do not change `next_fire_at`, `enabled` or `rule`.
4. Tests: rename; empty and over-long name rejected; task change keeps other `action_config` keys; non-`core.agentRun` rejected; unknown id gives null; another tenant's heartbeat is not found.

## Scope

### In scope

- `updateHeartbeatName` and `updateHeartbeatTask` in the scheduler store.

### Out of scope

- The agent tools that call them and their approval: #1846.
- Distinguishing user from system heartbeats: #1438.
- Enabling and disabling over HTTP: #1551.

## Acceptance criteria

- Renaming a heartbeat changes only `name`; an empty or over-200-character name is rejected.
- Changing the task keeps all other `action_config` keys.
- Changing the task of a heartbeat with another action is rejected.
- A heartbeat of another tenant cannot be changed.
