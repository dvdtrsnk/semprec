## Context

Model tier rationale: One field's source changes to an existing store call with exactly specified fallback values.

`GET /api/ai-usage` is a `schemaCore` custom route (`backend/packages/data/src/chokePoint/schemaCoreModuleManifest.ts:72-73`). Its thin handler (`backend/packages/data/src/aiGateway/aiUsageRouteHandler.ts:23-33`) returns `getAiUsageReport` (`backend/packages/data/src/aiGateway/aiUsageReport.ts:104-185`), which builds four parts:

- rows aggregated from `ai_gateway_calls` left-joined to `agent_runs` (`:108-125`);
- a daily cost and token series in the settings timezone (`:106`, `:139-165`);
- the total;
- `budgets`, read from the settings item's `dailyBudgetUsd`/`monthlyBudgetUsd` through `getAiBudgets` (`:174`).

Earlier issues already scope most of this:

- Since #981, custom routes run in the caller's tenant scope. Every query therefore runs under row-level security for that tenant: the aggregates contain only the caller's own calls and runs, and `getSystemTimezone` reads the caller's own settings item.
- Since #1035, the gateway enforces the caps in `tenant_ai_budgets` and no longer those settings properties. Its rules: a missing row refuses every call; a `NULL` cap means no per-tenant cap for that window; an operator-wide safety cap also applies, and a refusal never says which cap tripped. `getCurrentTenantAiBudget(client)` (`backend/packages/data/src/aiGateway/tenantAiBudgetsStore.ts`, from #1004) reads the current tenant's row.

So the report still shows the wrong caps. The web client renders `budgets.dailyBudgetUsd`/`monthlyBudgetUsd` as typed in `web/src/api/aiUsageOperations.ts:44-47` and displayed in `web/src/views/aiUsage/UtilizationPage.tsx:191-200`, where `null` reads as "No daily budget set" / "uncapped". The response shape must therefore stay exactly as it is (`docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`).

## Task

Load `state-writes` (a read model over tenant-scoped rows) and `error-handling`.

1. In `aiUsageReport.ts`, take `budgets` from `getCurrentTenantAiBudget(client)` instead of `getAiBudgets`:
   - a row gives `{ dailyBudgetUsd: row.dailyCapUsd, monthlyBudgetUsd: row.monthlyCapUsd }`;
   - no row gives `{ dailyBudgetUsd: 0, monthlyBudgetUsd: 0 }`. That is the effective fail-closed cap, since #1035 refuses every call. Never return `null` here, which the UI would show as uncapped.
2. Replace the `AiBudgets` import from `systemSettings.ts` with a local exported `interface AiUsageBudgets { dailyBudgetUsd: number | null; monthlyBudgetUsd: number | null }`, and drop the `getAiBudgets` import. #1059 can then delete both from `systemSettings.ts` without touching this file.
3. The report must not reflect the global safety cap or any other tenant's spend:
   - add no field;
   - add no cross-tenant read;
   - keep relying on the caller's tenant scope and row-level security for the aggregates.
4. Update the doc comments that say "the system's configured timezone" (`:37`, `:44`) to say the caller's tenant's settings timezone.
5. Extend `backend/packages/data/src/__tests__/aiUsageReport.test.ts`. Its existing expectation `budgets: { dailyBudgetUsd: 50, monthlyBudgetUsd: null }` (`:107`) now comes from a `tenant_ai_budgets` row the test inserts. `resetDatabase` empties that table.

## Acceptance criteria

All cases are integration tests using the harness from #975: `createTestTenant(pool)`, `createRuntimeRolePool(adminPool, "semprec_data")`, and calls inside `runInTenant` from `@semprec/shared`.

- Calls are recorded in tenants A and B. A's report has `rows`, `totalCostUsd`, `dailyCostUsd` and `dailyTokenUsage` built from A's calls only, and B's report from B's calls only.
- With A's row at `daily 7, monthly NULL`, A's `budgets` is `{ dailyBudgetUsd: 7, monthlyBudgetUsd: null }`.
- With no row for B, B's `budgets` is `{ dailyBudgetUsd: 0, monthlyBudgetUsd: 0 }`.
- With A's settings timezone different from B's, each report's daily buckets follow its own tenant's timezone.
- The response has exactly the keys `from, to, rows, totalCostUsd, dailyCostUsd, dailyTokenUsage, budgets`, and `budgets` has exactly `dailyBudgetUsd` and `monthlyBudgetUsd`. Nothing reveals the global cap or global spend.
- The existing aggregation, range-validation and daily-series cases in `aiUsageReport.test.ts` still pass.
