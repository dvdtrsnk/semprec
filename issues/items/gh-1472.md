## Context

Model tier rationale: One additional grouped query and response field in a file already in this chain, reusing the display-name catalog, with fixtures that already exist for the report.

The AI usage report (`backend/packages/data/src/aiGateway/aiUsageReport.ts`) returns `rows` split by provider, model, unit and run unit (`invocation` or `session`). A usage screen needs one line per model with a readable name and the activities the model was used for, without the client merging run units and without knowing raw model ids, which change with each model version.

This issue adds `byModel` to `GET /api/ai-usage`. It builds on #1467 (correct units, failed calls excluded, `estimated`) and on the display-name catalog from #1442, and #1477 adds the per-operation breakdown after it. Today the agent model, Whisper and speaker diarization are the only model families in use; there is no embedding or mail-triage model call, so no line for them appears until such calls are recorded.

Decision: a model line shows the operations it was used for as raw operation keys; their human labels belong to the per-operation breakdown in #1477. Decision: the display name uses the caller's `users.locale`, so the route handler passes the locale into the report.

## Task

Load `testing` and `canonical-keys`.

1. In `aiUsageRouteHandler.ts` pass `toManifestLocale(ctx.identity.user.locale)` to `getAiUsageReport` (the handler context from the adapter already carries `identity`; extend the duck-typed context interface in that file accordingly).
2. In `aiUsageReport.ts`, add `byModel` to `AiUsageReport`: `[{provider, model, displayName, callCount, inputTokens, outputTokens, audioSeconds, costUsd, operations}]`, one entry per `(provider, model)` over `[from, to)`, with run units merged on the server (do not return `runUnit` here). Use the same unit and counting rules as #1467 (failed excluded; token fields null for an audio model and `audioSeconds` null for a token model; numbers otherwise). `operations` is the sorted list of distinct operation keys the model was used for, a NULL operation reported as `other`. `displayName` comes from `resolveModelDisplayName` of #1442. Order by `costUsd` descending, then `model`.
3. Keep `rows` and every existing field unchanged.
4. Tests: one entry for a model used by an `invocation` run and a `session` run; Sonnet versions show "Claude Sonnet" in cs and en per user locale; an unknown model id shows its raw id; Whisper shows only `audioSeconds` and no token numbers; `operations` lists each operation once.

## Scope

### In scope

- The `byModel` array with display names and operation keys.

### Out of scope

- Labels and shares per operation: #1477.
- A per-trigger or per-project breakdown, which is not planned yet.
- A separate model for heartbeat ticks (decided: v1 uses the one configured agent model for every trigger) and any model line for embeddings or mail triage, which have no recorded calls today.

## Acceptance criteria

- When a model was called by both an invocation and a session run, then `byModel` has one entry for it with the summed numbers.
- When the user's locale is `cs` and the model is a Sonnet version, then `displayName` is "Claude Sonnet"; for an unrecognized model id it is the raw id.
- When a model is an audio model, then its entry has `audioSeconds` and null token fields.
- When a call failed, then it is not in `callCount`.
- The sum of `byModel[].costUsd` equals `totalCostUsd`.
