**Blocked by:** #1624
**Model tier:** high

## Context

Model tier rationale: It widens what the transcription worker may write (a relation edge in the create step), which changes an accepted authorization ADR and triggers downstream rules in a second process, and it must stay correct when the event is deleted in between.

A recording made next to an event should belong to it from the start. Today the event is attached only by the match at the end of the pipeline (`transcription/transcriptEventMatch.ts`), by time window; a transcript that already has an `event` edge makes the match return `alreadyLinked`. `suggestSpeakers` takes its candidates only from `Events.people` of the linked event (`transcriptSpeakerSuggestion.ts`). `runCreateStep` (`backend/services/semprec-transcribe/src/transcriptionTask.ts`) writes only `name`, `status` and `link`, and `docs/adr/2026-09-23-transcription-worker-writes-event-match-results.md` limits worker writes to the edge and card produced by the match ("any further write it needs is a new decision").

This issue makes the create step write the `Transcripts.event` edge when the upload named a live event (`recording_requests.event_item_id` from #1574), in the same transaction as the transcript row. The match then returns `alreadyLinked`, speaker suggestion sees the event's participants, and the project, company and people inheritance rules of #1697 run in this process too, through the post-edge-write hook. It builds on #1574 and #1624 (the same `runCreateStep` is now called from the fast task).

Decision: the ADR is amended so the worker may write the `event` edge in the create step, only from `recording_requests`.

## Task

Load `state-writes`, `adr-conventions`, `error-handling` and `testing`.

1. In `runCreateStep`, after the transcript row is created and when `recording_requests.event_item_id` is set, check the event is live (not trashed, exists in the tenant) and write the `Transcripts.event` edge with `createRelationWithClient` in the same transaction. When the event is gone or trashed, write no edge and leave the transcript to the normal match.
2. The step stays idempotent: a repeated run does not duplicate the edge or the row.
3. Ensure the relation hooks registered for edge writes run in `semprec-transcribe` (the hook wiring in `serve.ts`), so rules attached to the edge fire there.
4. Amend the ADR above with a new addendum ADR file stating the added permission and its limit.
5. Tests: upload with `X-Event-Id` yields an edge during processing and no pairing card (speaker cards may still appear); event deleted between upload and create writes no edge and the transcript goes through matching; repeated create does not duplicate the edge.

## Scope

### In scope

- Writing the event edge in the create step from the upload's recorded event, and the ADR addendum.

### Out of scope

- The upload route and `recording_requests`: #1574.
- Moving row creation to the fast task: #1624.
- Inheriting project, company and people from the event: #1697.
- Matching transcripts without an event: #1813.

## Acceptance criteria

- When a recording is uploaded with a live `X-Event-Id`, then the transcript has the `event` edge while it is still processing, and no pairing card (kind transcript on Events or an `event` relation) is created.
- When the event is deleted between the upload and the create step, then no edge is written and the transcript is matched normally.
- When the create step runs twice, then there is one edge.
