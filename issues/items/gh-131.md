**Blocked by:** #130

## Context

The user decision must have one database source of truth and must not resume an already completed agent turn.

## Task

Add authenticated-user approve and reject actions using one atomic `UPDATE ... WHERE id=? AND status='pending'`. Rejection creates no job. Approval atomically records `approved`, `decidedAt`, `decidedBy` and enqueues reserved `approvalExecute` with the request id. The handler reloads the stored payload and performs only that deferred choke-point call, recording the outcome in the audit trail; it creates no AgentSession, reconstructs no conversation, and injects no message into the originating run. Repeated decisions are deterministic no-ops. Keep pending requests indefinitely. Design the handler/store boundary so #89 can add snapshot conflict and exactly-once transaction semantics without replacing the user-facing state machine.

## Scope

### In scope

- Atomic decisions, approval-only enqueue, deferred call, audit outcome, and authorization hook.

### Out of scope

- Chat decisions, expiry, notification delivery channels, sandboxing, and #89 evolution.

## Acceptance criteria

- Concurrent approve/reject yields exactly one winning decision.
- Rejected requests never execute.
- Approved execution does not alter/reopen the source run.
- Retry cannot create a second decision transition.
