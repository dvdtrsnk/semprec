## Context
Review of pull request #391 found two clarity defects in `.claude/skills/finish/SKILL.md`:
- The sentence "Do not end your turn believing the work is done while that wait is still armed" (currently around line 143) is ambiguous: it can be read as "do not end your turn at all while the background command is running" instead of the intended "end your turn normally, but do not declare the PR merged while the wait is still armed."
- The line `gh pr checks <n> --watch --interval 30   # run_in_background: true` (currently around line 140) uses a trailing comment, `# run_in_background: true`, that is a convention mapping to the Bash tool's `run_in_background` parameter — not a literal shell comment. This is not explained inline, so an agent unfamiliar with the convention could pass the command including the comment text, or fail to actually set `run_in_background: true` on the tool call.

## Task
- Reword the sentence at `.claude/skills/finish/SKILL.md`'s "Do not end your turn believing the work is done while that wait is still armed" so it unambiguously states that the turn itself ends normally, and what must not happen is declaring the work/merge done while the background wait is still armed.
- Add a short inline note next to the `# run_in_background: true` example explaining that the trailing comment is a convention meaning "invoke this command with the Bash tool's `run_in_background: true` parameter", not literal text to pass to the shell.

### In scope

## Acceptance criteria
