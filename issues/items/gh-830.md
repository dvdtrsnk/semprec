## Context

The `integration` and `e2e` required checks report success even when tests fail.
- `backend/packages/data/src/testSupport/globalSetup.ts` imports `embedded-postgres`. That import registers `async-exit-hook`, whose `beforeExit` handler runs the shutdown hook and then calls `process.exit(0)`.
- vitest signals a failed run by setting `process.exitCode = 1` and letting the event loop drain. The explicit `process.exit(0)` overwrites that code, so `pnpm run test:integration` and `pnpm run test:e2e` exit 0 with failing tests.
- Evidence: develop's CI run 36628903406 on `16bc764` reports `Test Files 1 failed | 163 passed (164)` and `Tests 2 failed | 1995 passed (1997)`, yet its `integration` job concluded `success`. PR #829's `integration-shard (1)` shows the same result.
- A local reproduction on `origin/develop` behaves the same: `vitest run --config vitest.integration.config.ts packages/data/src/__tests__/inboxTickProposal.test.ts` prints `2 failed` and exits 0.

The gate hole has already let a regression through.
- 5f3a326 (PR #792, issue #676) moved the Inbox tick's bracketing transactions to `repeatable read`.
- At that isolation level, `FOR UPDATE` on a proposal card written after the transaction's snapshot fails with `40001 could not serialize access due to concurrent update` instead of returning the newer row.
- `lockUnlockedProposal` in `backend/packages/data/src/inbox/inboxTickAction.ts` documents that such a concurrent write is logged and skipped. Instead the error escapes the tick.
- Two #662 tests have failed on develop ever since: `deleted-source path: a reject committed before the tick locks the card wins` and `deleted-source path: a card soft-deleted before the tick locks it is skipped without writing or throwing`.

The two fixes have to land together. Restoring the exit code alone turns `integration` red on every pull request until the tick is fixed.

## Task

- In `lockUnlockedProposal`, take the `FOR UPDATE` lock under a savepoint.
  - On a Postgres `serialization_failure` (SQLSTATE `40001`), roll back to the savepoint, log the skip with reason `changed`, and return `null`.
  - Let every other error propagate.
- Add `backend/packages/data/src/testSupport/preserveFailingExitCode.ts`.
  - It records `process.exitCode` in a prepended `beforeExit` listener and restores it in an `exit` listener when something set the code back to 0.
  - Call it from `globalSetup`.
- Tests:
  - The two failing #662 tests pass.
  - A new integration test: a lock failure other than a serialization conflict propagates and writes nothing.
  - A unit test that runs a child Node process which loads `embedded-postgres` and sets `process.exitCode = 1`. It asserts that the process exits 0 without the guard and 1 with it.

## Scope

### In scope

- The tick's lock under `repeatable read`, and the test tiers' exit code.

### Out of scope

- Changing the tick's isolation level, or the bracketing ADR.
- Upgrading or patching `embedded-postgres` / `async-exit-hook`.
- Any `.github/workflows/**` change.

## Acceptance criteria

- `pnpm run test:integration` (and `test:e2e`) exit non-zero when any test fails. Verified locally with a deliberately failing test file.
- `packages/data/src/__tests__/inboxTickProposal.test.ts` passes in full.
- The pull request's `integration` check is green, and the shard logs report no failed test.
