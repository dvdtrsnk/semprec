**Model tier:** medium

## Context

Model tier rationale: One agent tool that calls the send flow built elsewhere; the approval and permission logic is not re-implemented here, but the tool must route to the right path for every actor.

Semp needs to send a prepared draft. The send path and its approval kind are #1913: without project permission it queues an approval request, with permission it sends through `sendDraftEmail` (`backend/packages/data/src/mail/send.ts`). Module tools reach a session through #1523, and a tool that may need approval is deferred by #1791. The other mail tools are #1927.

Decision: the tool takes only `{ draftId }`, and the name `mail.draft.send` is used, which also names the operation in approval cards.

Shared-file ordering: this issue also waits for #1933 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling` and `testing`.

1. Declare `mail.draft.send` in `agentTools` of `mail/mailModuleManifest.ts` (capability `mail.send`) with the handler in `mail/mailAgentTools.ts`, input `{ draftId }`, and the descriptor `requiresApproval` exactly as defined in #1913.
2. The handler calls the permission evaluation and send flow of #1913 with the run's agent as the actor: with permission it sends and returns the sent message id; without it, it returns the pending approval request result in the shape #1791 defines for deferred tools.
3. A draft that is sent, deleted or in another tenant is a not-found or conflict error.

### Out of scope

## Acceptance criteria

- A run in a project without send permission that calls the tool gets a pending approval request and no mail leaves.
- A run in a project with permission sends the draft once and a repeated call is a conflict.
- A project without the `mail.send` grant does not see the tool.
