## Context

Model tier rationale: Three new user-owned properties plus a validating hook and a per-tenant cutover copy existing patterns, but assigning the next position at create time needs a transaction-scoped lock to stay correct under concurrent creates, which raises it from low to medium.

The Areas system database (`seedTenDatabasesInTransaction` in `backend/packages/data/src/seed/seedTenDatabases.ts`) has only `name` (title), `active` (checkbox) and `note` (text). The product shows every area with an icon and a color (on the overview, in the page header, in search and in the area tags of collections) and lists areas in a deliberate order (for example Work, Health, Home, Family), not alphabetically. None of that is stored today: there is no icon, no color and no position, and the seed creates no areas.

Because the Areas database is schema-locked after seeding (`assertDatabaseSchemaUnlocked` in `propertiesStore.ts`), an existing tenant only gets new properties through the per-tenant cutover in `backend/packages/data/src/db/tenantCutoverMigrations.ts` (`runTenantCutoverMigrations`, which iterates every maintained tenant, suspended ones included, in that tenant's scope under row-level security, per `docs/adr/2026-09-10-app-code-post-migration-steps.md`). `backend/packages/data/src/transcription/transcriptsCatalogCutoverMigration.ts` is the pattern: one transaction, `LOCK TABLE properties IN EXCLUSIVE MODE`, an idempotency check, then raw SQL inserts. Do not copy `0019_settings_ai_budgets.sql`; since the strict tenant enforcement migration an INSERT without `tenant_id` fails.

Item create and update hooks run inside the write's own transaction for every writer (REST, `/mcp`, agent tools); `mcpServerItemCreateHook` in `backend/packages/data/src/mcp/mcpServerWriteHook.ts`, registered in `backend/packages/data/src/domainWriteHooks.ts`, is the pattern (see `docs/adr/2026-10-09-item-create-domain-hooks.md`).

Czech labels for these properties depend on #1413, which also edits the Czech catalog; this issue adds its keys after that merges. #1554 (default `active` and backfill) and #1556 (cardinality) both register further steps in the same cutover file and build on this one.

Decisions: `icon` and `color` accept `null`, meaning "use the client's default icon and color". A new area created without a `position` is placed last: the create hook sets `position` to the highest `position` among live areas plus one (1 when there is none). An explicitly supplied position is kept as given. Item create hooks cannot change the incoming properties (`docs/adr/2026-10-09-item-create-domain-hooks.md`), so the hook writes the position onto the just-inserted row inside the same transaction, after taking `pg_advisory_xact_lock` keyed by the Areas database id so two concurrent creates get different positions.

Shared-file ordering: this issue also waits for #1498, #1514 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `state-writes`, `canonical-keys`, `error-handling` and `testing`.

1. Add three properties to the Areas database, all `owner: 'user'`: `icon` (type `text`), `color` (type `color`), `position` (type `number`). Declare them in `seedTenDatabases.ts` for fresh tenants (names are `null`, labels come from i18n).
2. Add a cutover step (new file `backend/packages/data/src/seed/areasPropertiesCutoverMigration.ts`, registered in `runTenantCutoverMigrations`) that, for each tenant with an Areas database, takes `LOCK TABLE properties IN EXCLUSIVE MODE`, checks per key whether the property already exists, and inserts only the missing ones with the same type, owner and config as the seed. A second run changes nothing. A tenant without an Areas database is a no-op.
3. Add i18n keys `property.areas.icon.name`, `property.areas.color.name`, `property.areas.position.name` to `seed/i18n/cs.json` ("Ikona", "Barva", "Pořadí") and `en.json` ("Icon", "Color", "Position").
4. Bump the `version` of `seed/systemDatabasesModuleManifest.ts` (and update the tests that assert the current version).
5. Add an item create and update hook for the Areas database (new file `backend/packages/data/src/areas/areaWriteHook.ts`, registered in `domainWriteHooks.ts`) that validates only the keys present in the written properties:
   - `icon` must be `null` or one of the closed set `briefcase`, `heart`, `house`, `people`, `money`, `chart`, `shield`, `star`; anything else is a `ValidationError` with `field: 'icon'` (HTTP 400);
   - `color` must be `null` or exactly one of `#5856D6`, `#FF2D55`, `#FF9500`, `#30B0C7`, `#007AFF`, `#AF52DE`, `#FF3B30`, `#34C759`, `#8E8E93` (compared case-insensitively, stored as given); anything else is a `ValidationError` with `field: 'color'`.
   Keep the two lists as exported constants next to the hook.
   On create only: when `position` is absent or `null`, assign the next position as described in Context.
6. Add a test that `database.query` on Areas with filter `active equals true` and sort `position` ascending then `name` ascending returns areas in position order, areas without a position last, ties by name.

## Scope

### In scope

- The three properties for fresh and existing tenants (suspended ones included), their labels, the icon and color validation on create and update, and the ordered overview query test.

### Out of scope

- Defaulting `active` to true and backfilling missing values: #1554.

## Acceptance criteria

- `GET /api/databases/:id/properties` for Areas returns `icon`, `color` and `position` with Czech labels "Ikona", "Barva", "Pořadí" under a Czech locale.
- `PATCH /api/items/:id` on an area with `{ icon: "briefcase", color: "#5856D6" }` stores both values; `icon: "rocket123"` answers 400 with `field: "icon"`; `color: "#123456"` answers 400 with `field: "color"`; `icon: null` and `color: null` are accepted.
- The same validation applies to `item.create` and to writes made through `/mcp` and agent tools.
- After the cutover, a tenant created before this change (including a suspended one) has the three properties; running the cutover again changes nothing.
- When an area is created without a position, then it receives the highest existing position plus one; two areas created concurrently receive different positions; an explicit position is kept.
- A query of active areas sorted by `position` then name returns them in position order with unpositioned areas last.
- The full backend `pnpm run verify` passes.
