## Context

The persistent model and cryptographic primitives now exist. This slice creates the one verification path used by browser and native requests.

## Task

Implement email/password login, logout, remote single-session revocation, and shared request authentication. Login verifies Argon2id, creates one session row per login, returns one newly generated opaque token, and never exposes its hash. Verification accepts either the web cookie or `Authorization: Bearer`, hashes the presented token, requires a matching unexpired and unrevoked session, updates `last_seen_at`, and attaches the user and session identity to the request. Logout/revocation sets only the selected session's `revoked_at`; other sessions remain valid. Define deterministic 401 error responses for missing, invalid, expired, and revoked credentials without revealing which condition applied.

## Scope

### In scope

- Login/logout/revoke endpoints and reusable authentication middleware.
- Independent multi-device sessions and expiry enforcement.

### Out of scope

- Rate limiting and platform-specific delivery, delivered by #141.
- Route-wide adoption, delivered by #143.

## Acceptance criteria

- Successful login creates a session and the returned opaque token authenticates a later request.
- Logout or remote revocation immediately invalidates only that session.
- Invalid credentials produce the same public 401 contract regardless of the failure reason.
