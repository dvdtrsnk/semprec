## Context

Model tier rationale: One known mechanism (a catalog-backed renderer feeding two mailer interfaces) across mailer, action and build-script seams with existing mailer fixtures, and no change to token, rate-limit or authentication behavior.

The two transactional emails the backend sends are hard-coded in English. `NodemailerPasswordResetMailer.sendPasswordResetEmail` in `backend/packages/data/src/auth/passwordResetMail.ts` sends "Reset your password", and `NodemailerInviteMailer.sendInviteEmail` in `backend/packages/data/src/tenancy/inviteMail.ts` sends "You have been invited to Semprec". The app is bilingual (Czech default, `users.locale` is `cs` or `en`), and other backend text is already localized through per-area catalogs such as `notifications/i18n/{cs,en}.json` loaded with `loadModuleCatalogs` and resolved with `toManifestLocale` and `resolveCatalogLabel` (`backend/packages/data/src/notifications/notify.ts`). `data/auth` has no catalog yet.

This issue moves the two emails' subject, plain text and HTML into a catalog and renders them in the recipient's language. It does not change when mail is sent, token lifetime, rate limits, or the links (`buildPasswordResetUrl`, `buildInviteUrl`).

Decisions:
- A password-reset email uses the locale of the account that requested the reset (`users.locale`).
- An invitation email uses the locale of the admin who created the invitation, because the invited person has no account yet.
- An unknown locale falls back to English through `toManifestLocale`.

## Task

Load `canonical-keys`, `io-hardening` and `testing`.

1. Create `backend/packages/data/src/auth/i18n/cs.json` and `en.json` with the keys `mail.passwordReset.subject|text|html` and `mail.invite.subject|text|html`. Templates use `{url}` placeholders. The English values reproduce today's wording exactly; the Czech values are natural translations. Add a small renderer `backend/packages/data/src/auth/authMailCatalog.ts` that loads the catalogs once per process (`loadModuleCatalogs(import.meta.url)`), resolves with `toManifestLocale` and `resolveCatalogLabel`, and substitutes placeholders; the URL is HTML-escaped (reuse each mailer's existing `escapeHtml`) before substitution into the `html` templates.
2. Add `locale: string` to `SendPasswordResetEmailInput` and `SendInviteEmailInput`. Update both Nodemailer implementations to render subject/text/html through the renderer instead of the literals, keeping the send timeout logic untouched. `noopPasswordResetMailer` is unchanged.
3. In `passwordResetActions.ts` (`requestPasswordReset`) pass `user.locale`. In `invites.ts` (`createInvite`) read the creating admin's locale (`getUserById(client, input.invitedBy)`) and pass it; if the admin row cannot be read, pass `en`.
4. Make the build copy the new catalog: add `cp -r src/auth/i18n dist/auth/i18n` to the `build` script of `backend/packages/data/package.json`. `backend/services/semprec-api/src/serve.ts` only constructs the mailers and needs no change.
5. Add tests: Czech and English renderings of both emails (subject, text and html) with a link that must contain the URL exactly once, HTML escaping of the URL, English fallback for an unknown locale, and the reset and invite flows passing the right locale (existing `passwordResetActions.test.ts` and `invites.test.ts` fixtures).

## Scope

### In scope

- The catalog, the renderer, the `locale` field on both mailer inputs, both Nodemailer implementations and the two call sites.

### Out of scope

- Accepting an invitation, and collecting a language for the invited person.
- Any other email or notification text.
- Link format, token and rate-limit behavior, SMTP configuration.

## Acceptance criteria

- When a user whose locale is `cs` requests a password reset, then the mailer receives `locale` `cs` and the sent email subject, text and html are Czech; for `en` they are the current English texts.
- When an admin whose locale is `cs` creates an invitation, then the invitation email is Czech, regardless of the invited address.
- An unknown locale value renders English.
- The reset or invitation URL appears in both the text and the html body and is HTML-escaped in the html body.
- After `pnpm run build` of the data package, `dist/auth/i18n/cs.json` and `en.json` exist.
