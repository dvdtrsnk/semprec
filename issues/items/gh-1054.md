## Context

Model tier rationale: The suite layout and sentinel technique are specified, but deterministic socket assertions across every frame type need careful test engineering.

No user may see, infer or be notified about another user's data, and a foreign id must behave exactly like a non-existent one. The realtime surface is `WS /api/sync`: `backend/services/semprec-api/src/syncHandler.ts:13-26` wires `@semprec/realtime`'s `createSyncServer` to the same `authenticateRequest` every HTTP route uses. Its closed protocol catalog is:

- inbound text frames `doc:open`, `doc:close`, `agent:watch`, `agent:unwatch` (`InboundFrame`, `backend/packages/realtime/src/protocolV1.ts:20-24`) and binary Yjs frames prefixed with a 16-byte doc id (`protocolV1.ts:94-108`);
- outbound frames `invalidate` (item and schema scope), `notification`, `agent:event`, `agent:delta` (`OutboundFrame`, `protocolV1.ts:71-83`) plus binary doc updates;
- NOTIFY messages on `semprec_events` — `invalidation`, `doc_update`, `agent_run_event`, `notification_created`, `notification_read_state`, `session_revoked` (`RealtimeMessage`, `backend/packages/realtime/src/pgNotifyPublisher.ts:24-38`) — and `agent_run_delta` on `semprec_agent_stream` (`AgentStreamMessage`, `pgNotifyPublisher.ts:50-52`).

Before this epic an invalidation with no acting user was broadcast to every socket (`backend/packages/realtime/src/syncServer.ts:347-353`). #1025 made every NOTIFY carry the publisher's `tenantId`, delivers only to that tenant's sockets, drops a payload without a tenant, and removed the broadcast; #1026 resolves `doc:open` and doc writes inside the socket's tenant; #1027 authorizes `agent:watch` by tenant visibility; #1044 requires a same-origin `Origin` on the upgrade. All `@semprec/realtime` types above are exported from `backend/packages/realtime/src/index.ts`. This suite proves the whole surface at once and fails when a new frame or message type appears without a case; it is one of the three proofs the release checkpoint #1058 requires. It lives in `semprec-api` because the real identity resolution and upgrade check are there and `@semprec/realtime` may not import service code.

## Task

No production behaviour changes; no topic skill applies beyond `implement-issue`.

Create `backend/services/semprec-api/src/__tests__/tenantIsolationRealtime.test.ts`. Its `beforeAll` sets `process.env.SEMPREC_TENANT_SCOPE = "strict"` (`enforceTenantScope` from #978 reads it on every call) and `afterAll` restores it.

1. **Fixture.** Two tenants A and B from `createTestTenant(adminPool)` (`@semprec/data/testSupport`, #975), provisioned with `provisionTenant(pool, id)` (#1005); A's user with two web sessions, B's user with one. One HTTP server built from `createDispatcher` and `createSyncUpgradeHandler` over a `createRuntimeRolePool(adminPool, "semprec_data")` pool with `wireRealtimeHooks(pool)`, exactly as `backend/services/semprec-api/src/serve.ts:94-149` composes them. Sockets A1 and A2 (A's two sessions) and B1, each sending a same-origin `Origin`. In A: an item with a doc, an agent run with events, and a notification.
2. **Absence without sleeps.** To prove a socket received nothing, trigger the event under test, wait for its delivery to the socket that should receive it, then trigger a sentinel event in the other tenant and assert the checked socket's next frame is that sentinel — delivery is ordered over the server's single LISTEN connection (`syncServer.ts:227-228`).
3. **Exhaustive case tables**, each declared with `satisfies Record<…, Case>` so a new type without a case fails `pnpm -r run build`: one over `RealtimeMessage["type"]`, one over `AgentStreamMessage["type"]`, one over `InboundFrame["type"]`, one mapping every `OutboundFrame["type"]` to the case that produces it, plus one binary-frame case.
4. **NOTIFY cases** (A's event; A's sockets receive, B1 receives nothing):
   - `invalidation`, item and schema scope, both from a REST write by A's user and from a background write performed inside `runInTenant(A)` with no acting user;
   - `doc_update` for A's doc opened by A1;
   - `agent_run_event` and `agent_run_delta` for A's run watched by A1;
   - `notification_created` and `notification_read_state` for A's notification;
   - `session_revoked` for A's second session closes A2 only — A1 and B1 stay open;
   - a raw `pg_notify` on `semprec_events` whose payload lacks `tenantId` reaches no socket.
5. **Inbound cases** (B1 names A's ids):
   - `doc:open` of A's doc behaves exactly like `doc:open` of a random UUID (no frame back) and B1 can still open its own doc afterwards;
   - `doc:close` of A's doc leaves A1's subscription receiving A's updates;
   - `agent:watch` of A's run behaves exactly like watching a random run id; `agent:unwatch` of A's run leaves A1's watch receiving events;
   - binary frames prefixed with A's doc id — sent without `doc:open` and after a refused `doc:open` — create no `doc_updates` row for A's doc (read inside `runInTenant(A)`) and reach no socket.
6. If a case fails because the server really leaks, do not change production code here: leave the failing case in the pull request and stop, reporting the frame and the leak — the fix belongs to the owning issue.

## Scope

### In scope

- One exhaustive two-tenant suite over every NOTIFY message type, every inbound and outbound frame type and binary doc frames.

### Out of scope

- REST and MCP routes (#1053); queue tasks (#1056).
- The `Origin` check's own negative cases (covered by #1044's tests; this suite only sends a valid `Origin`).
- Fixing any leak the suite finds (Task step 6).

## Acceptance criteria

- Integration: deleting any entry from one of the four case tables, or adding a member to one of the four unions without a case, fails `pnpm -r run build`.
- Integration: for every NOTIFY message type, A's sockets receive the expected frame and B1 receives nothing, proven by the sentinel technique of Task step 2.
- Integration: a background invalidation produced inside `runInTenant(A)` with no acting user reaches A's sockets only; a payload without `tenantId` reaches no socket.
- Integration: revoking A's second session closes only A2, with close code 4401.
- Integration: every inbound frame type sent by B1 with A's ids behaves as with a random id and leaves A's state and A's sockets unaffected; no `doc_updates` row is written for A's doc by B1.
- The suite runs on runtime-role pools only, with strict scope enforcement in effect.
