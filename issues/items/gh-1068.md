**Blocked by:** #1059, #1062, #1067

## Context

**This issue is maintainer-implemented and must never be labelled `agent:ready`.** It is the second release gate of this epic. The first (#1058) proved a context-complete release in production so the strict switch could follow; this one proves the **strict** release in production, so that contract steps whose rollback target must already be strict, or must already write the per-tenant credential scheme, can follow — in particular retiring the master-key-only credential scheme (#1069). The one-release rollback rule (`docs/operations/migrations.md`, `docs/adr/2026-09-24-rollback-one-release-back-with-checked-migrations.md`) makes that release the target of any rollback from the contract release.

What the release must contain and why:

- #1067: `app_tenant_default()` returns `app_current_tenant()` only, `users.tenant_id` is `NOT NULL`, and an unset `SEMPREC_TENANT_SCOPE` means `strict`, so any query without a tenant or system scope throws `TenantScopeMissingError` instead of falling back to the sole tenant.
- #1060 and #1062: every credential write uses the per-tenant key (`external_credentials.scheme = 'tenant'`, added by #1032 with values `'master' | 'tenant'`), and the re-encryption job has converted every existing `'master'` row.
- #1059: the AI budget properties are gone from the settings item; caps come only from `tenant_ai_budgets` and the global caps.

Production logs go to journald (`deploy/systemd/journald-semprec.conf`, 90 days); releases are tagged and deployed per `docs/operations/releases.md`. `docs/operations/tenancy.md` was created at #1058.

## Task

Checklist for the maintainer:

- [ ] Promote `develop` (containing #1067, #1060, #1062 and #1059) to `main`, tag and deploy it. Record the tag and deploy time.
- [ ] Confirm no service environment sets `SEMPREC_TENANT_SCOPE` (or that it is `strict`): check each unit's effective environment and environment files.
- [ ] Confirm the schema is strict: `SELECT pg_get_functiondef('app_tenant_default()'::regprocedure);` shows only `app_current_tenant()`, and `SELECT is_nullable FROM information_schema.columns WHERE table_name = 'users' AND column_name = 'tenant_id';` returns `NO`.
- [ ] Re-encryption complete: `SELECT count(*) FROM external_credentials WHERE scheme = 'master';` returns `0` (run as the migrating role, which sees every tenant).

Any hit: open an issue for the logged path, fix it, deploy, and restart the seven days.
