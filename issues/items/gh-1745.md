## Context

Model tier rationale: The third use of an established lifecycle-hosting pattern with an existing webhook receiver and subscription client, differing only in configuration and the notification URL.

After #1739, the lifecycle dispatcher in `backend/services/semprec-api/src/mailLiveSyncLifecycles.ts` hosts IMAP IDLE and Gmail watch; Graph accounts still get the noop lifecycle and rely on the sweep. The Graph pieces exist: `createGraphWebhookLifecycleFactory` (`backend/packages/data/src/mail/graphWebhookLifecycle.ts`) keeps one subscription per account alive (register, renew, re-register after a 404), `createGraphSubscriptionRestClient` (`mail/graphSubscriptionClient.ts`) talks to `/subscriptions`, and the public receiver `POST /api/mail/graph/webhook` is already routed in `backend/services/semprec-api/src/app.ts` (handled by `mail/graphWebhookNotifications.ts`). Graph accepts only a public HTTPS `notificationUrl`.

The Graph sync transport is #1508 (it also provides the refresh with rotation).

Decision: `notificationUrl` is `APP_BASE_URL` plus `/api/mail/graph/webhook`. When the Graph OAuth client is configured but `APP_BASE_URL` is not an `https://` origin without a path (the local default is `http://localhost:3000`), the Graph lifecycle is not hosted, the lifecycle logs one warning, and Graph accounts stay on the noop lifecycle and authenticated periodic sweep. When the Graph OAuth client is missing, the process still starts and the lifecycle is not hosted, but Graph accounts cannot sync: the existing mail sync adapter owns the single provider startup warning and the lifecycle adds no second warning. No credential-free sync fallback is introduced.

4. Tests with a fake Graph transport: a Graph account gets a subscription created with the right `notificationUrl`; renewal after a 404 registers a new subscription; stopping the root stops the lifecycle; with an `http://` or path-bearing `APP_BASE_URL` and OAuth configured, the Graph lifecycle is not hosted, one lifecycle warning is logged and the authenticated sweep completes a sync; with no OAuth client, the adapter emits the single provider startup warning, the lifecycle adds none and sync is refused; other sync modes are unaffected.

## Acceptance criteria

- When a Graph account is active, then a subscription pointing to the deployment's `/api/mail/graph/webhook` is created and renewed, and a notification enqueues a sync without waiting for the sweep.
- When `APP_BASE_URL` is not a plain `https://` origin but the Graph OAuth client is configured, then the process starts, logs one lifecycle warning, and Graph accounts are synced by the authenticated sweep. When the OAuth client is missing, the process starts and the lifecycle is not hosted; exactly one provider startup warning comes from the existing mail sync adapter, the lifecycle adds none, and Graph sync fails with the existing missing-adapter error rather than claiming sweep success.
- When the process stops, then the Graph lifecycles are stopped with the root before the pool ends.
- When logs are inspected, then no token appears.
