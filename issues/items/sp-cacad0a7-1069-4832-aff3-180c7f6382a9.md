## Context

Model tier rationale: A test-infrastructure change that decides whether the REST/MCP isolation suite covers every route. It changes no runtime behaviour, but a matcher that is too loose would let an uncovered route pass silently, which is the defect it closes.

Finding R2-APP-3 (low) of the gh-1086 external review: the REST isolation suite of #1053 (`services/alldots-api/src/__tests__/tenantIsolationRoutes.test.ts`) and `routeMatrix.test.ts` drive the entries of the hand-maintained `ROUTE_MATRIX` (`services/alldots-api/src/routeMatrix.ts`, slices under `routeMatrix/`). `routeMatrixInventory.unit.test.ts` checks only duplicate names and duplicate method/path pairs, and `adapterTenantScope.test.ts` filters `ROUTE_MATRIX` by the mounted definitions, the opposite direction. The doc comment of `ROUTE_MATRIX` itself says "a newly added route that's never added here simply isn't covered". At `e6387779b` (identical tree to the integration tip) the review's probe compared all 130 module custom routes and account, semp-thread and admin routes with the `surface: "api"` entries and found none missing, so the inventory is complete today; nothing fails when a later route is mounted without an entry.

`createDispatcher` in `services/alldots-api/src/app.ts` mounts two kinds of route definitions: `mountCustomRoutes(pool, await options.moduleRegistry.getCustomRouteDefinitions(), ...)` and `mountRoutes(pool, [...createAccountRoutes(...), ...createSempThreadRoutes(...), ...createAdminRoutes(...), ...createDatabaseRoutes(...), ...createPropertyRoutes(...), ...createViewRoutes(...), ...createItemRoutes(...), ...createPageChangesRoutes(...), ...createSearchRoutes(...)])`. It also routes a fixed set of paths by prefix in its listener chain (`/api/server-info`, `/api/schema`, `/mcp`, `/api/approval-requests`, `/api/agent-runs/`, `/api/auth/`, `/api/notifications`, `/api/setup`, `/api/invitations/accept`, `/api/recordings`, `/api/files`, `/api/blobs`, `/api/account/exports/.../download`, `/api/mail/graph/webhook`, the mail OAuth callback); those are not enumerable as definitions and stay out of this source, as recorded in `issues/decisions/gh-1086.md`.

## Task

Load `testing` and `io-hardening`.

1. In `services/alldots-api/src/app.ts`, move the array passed to `mountRoutes` into an exported function `createResourceRouteDefinitions(...)` that takes exactly the values those nine factories take today and returns the concatenated array; `createDispatcher` calls it and passes the result to `mountRoutes`. No route, order, handler or option changes.
2. Add `services/alldots-api/src/__tests__/routeMatrixCoverage.unit.test.ts`:
   - A pure helper in the test file, `findUnmatchedRoutes(definitions, matrix)`, returns every `(method, path)` of `definitions` for which no `ROUTE_MATRIX` entry with `surface: "api"` has the same method and a path (query string removed) that matches the definition's path pattern (each `:param` segment matches one non-empty segment without `/`, every other segment literally; the same rule as `pathPatternToRegExp` in `adapterTenantScope.test.ts`).
   - Unit cases of the helper: a definition with a matching entry is not reported; a definition with no entry is reported; an entry with the same path but another method does not match; a `surface: "view"` entry does not match; a pattern `/api/x/:id` does not match an entry `/api/x/1/y`.
   - The coverage case: build the module registry the way `adapterTenantScope.test.ts` does (`loadFullModuleRegistry`) and collect `getCustomRouteDefinitions()` plus `createResourceRouteDefinitions(...)` called with stub arguments that the factories do not use at construction (no pool connection is opened). `findUnmatchedRoutes` over them returns `[]`. If a factory does use an argument at construction, give it the minimal stub that lets construction finish; a factory that cannot be constructed without a database is a reason to stop and report, not to skip it.
3. Update the doc comment of `ROUTE_MATRIX` in `routeMatrix.ts`: a mounted route without an entry now fails `routeMatrixCoverage.unit.test.ts`; the prefix-routed paths of the listener chain are still covered only by their own entries.

## Scope

### In scope

- A unit test that fails when a mounted module custom route or resource route has no `surface: "api"` entry in `ROUTE_MATRIX`.
- The extraction of the resource route list that the test needs.

### Out of scope

- Turning the prefix-routed listener chain of `app.ts` into data, and any check of it.
- Any change of a route, a handler, an entry of `ROUTE_MATRIX` or the isolation suites.
- The strict-mode integration tier of `[security-gate 06/06]`.
- Any production deployment, any change to gh-1086 itself, any change under `web/` or `mobile/`, and web or mobile verification.

## Acceptance criteria

- When every mounted module custom route and resource route has a matching `surface: "api"` entry, then `routeMatrixCoverage.unit.test.ts` passes (as at the integration tip).
- When a definition has no entry with its method and a path its pattern matches, then the helper reports exactly that `(method, path)` and the coverage case fails naming it; an entry with another method or `surface: "view"` does not count.
- When `createDispatcher` serves requests after the extraction, then every existing route test passes unchanged.
