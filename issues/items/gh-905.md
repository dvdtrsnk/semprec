## Context

Review follow-up from harvest issue #889. PR #772 (finding 8df935c28f), `backend/packages/data/src/__tests__/rollup.test.ts:271-272`: in "serialises a recompute behind a lock on the target row ...", `expect(settled).toBe(false)` after a fixed 200 ms sleep is a timing heuristic, not a structural guarantee that `recomputeRollupCell` is blocked on the row lock: under CI load the recompute may simply not have run yet, so the assertion can pass without any lock wait having occurred.

## Task

In that test, replace the fixed 200 ms `setTimeout` with a wait for a backend that is blocked by the holder itself, following the established pattern in `backend/packages/data/src/__tests__/moduleDataMigration.test.ts` (the `vi.waitFor` on `pg_blocking_pids` after the `FOR UPDATE` lock):

1. Right after the holder's `SELECT ... FOR UPDATE`, read the holder's backend pid: `SELECT pg_backend_pid() AS pid` on `holder`.
2. After starting `recomputeRollupCell`, replace the sleep with `await vi.waitFor(async () => { ... }, { timeout: 10_000, interval: 20 })`, whose callback counts `pg_stat_activity` rows `WHERE $1 = ANY(pg_blocking_pids(pid))` with the holder's pid as `$1` (queried on `pool`) and asserts `expect(count, "recompute never blocked on the holder's row lock").toBe(1)`.
3. Keep `expect(settled).toBe(false)` after the wait succeeds. Change nothing else in the test.

## Touches

- backend/packages/data/src/__tests__/rollup.test.ts (the one test named above, plus the `vitest` import line, which adds `vi`)

## Scope

### In scope

The sleep replacement and the `vi` import it needs.

### Out of scope

Other tests in the file and any change to `recomputeRollupCell`.

## Acceptance criteria

- The test no longer contains the fixed 200 ms sleep; it proceeds only after `pg_stat_activity` shows exactly one backend blocked by the holder's pid (`pg_blocking_pids`).
- If no backend is blocked by the holder's pid within the 10 s `vi.waitFor` timeout, the test fails with the message "recompute never blocked on the holder's row lock".
- The test's final assertion (computed value 8) and the rest of the file pass, and `pnpm run verify` in `backend/` passes.
