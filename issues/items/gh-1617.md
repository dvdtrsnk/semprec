## Context

Model tier rationale: Restoring a CRDT document as a forward update must keep concurrent editors' state consistent and bounded by the history retention rules, which is easy to get subtly wrong.

Page history is kept for 30 days: `openDocVersionAt(pool, docId, at)` (`backend/packages/data/src/docs/docHistory.ts`) rebuilds the document as it was at a past time from the nearest checkpoint plus `doc_history_updates`, and raises `HistoryNotRetainedError` (410) outside the window and `ValidationError` (400) for a future time. It has no HTTP route and no operation. `createDocStore` (`docs/docStore.ts`) exposes `openVersionAt` read-only. Without a restore, a user or the assistant cannot undo a bad page edit, which is why the agent write policy (#1400) keeps page replacement behind approval.

This issue adds the operation `page.restoreVersion { itemId, at }`: it restores a page to its state at `at` by computing the difference between that historical state and the current state and applying it as a new update on the live document (history is never rewritten), authored `user` because the restore is an explicit user decision (an agent calling it goes through approval and the approver's decision is the user's). It builds on the operation family of #1394.

Decision: the operation is registered with capability `core.item.write` and `requiresApproval: true` for agent callers.

## Task

Load `state-writes`, `error-handling`, `io-hardening` and `testing`.

1. Add `restoreDocVersion(pool, docId, at)` in `docs/docHistory.ts` (or a sibling file) that opens the version with `openDocVersionAt`, then in one transaction under the document lock computes block-level changes against the current state and applies them through the existing doc mutation path with origin `user`. A block present now but not then is removed; a block present then but not now is re-created with its fields and children; changed blocks are reset.
2. Add the operation `page.restoreVersion` following the page operation family conventions of #1394: input `{ itemId, at }` (ISO 8601), output the new block ids summary; errors 404 for an unknown or non-page item, 400 for a future `at`, 410 `history_not_retained` outside the retention window. Register it in the shared operation catalog with its binding and REST route.
3. Tests: restore after an agent edit returns the page to its earlier blocks; a concurrent edit made after `at` by another client is not lost beyond the restored blocks; restoring to the current time changes nothing; a restore is itself restorable; retention errors.

## Acceptance criteria

- When `page.restoreVersion` is called with a time before an assistant edit, then the page returns to its blocks from that time and the restore is recorded as a new update authored `user`.
- When `at` is older than the retention window, then the response is 410 `history_not_retained`; when `at` is in the future, 400.
- When an agent calls the operation without approval, then it is held for approval.
