**Blocked by:** #963

## Context

semprec-api reads seven settings that the production secrets template `deploy/shared/.env.example` does not declare: `APP_BASE_URL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_FROM_ADDRESS`, `SMTP_USER` and `SMTP_PASSWORD`. The template's 45 keys (`:1-223`) do not include them. Only the local-development template `backend/services/semprec-api/.env.example:19-27` does.

What they drive:
- **`APP_BASE_URL`** is the public origin every emailed link is built against.
  - `const appBaseUrl = process.env.APP_BASE_URL ?? "http://localhost:3000"` (`backend/services/semprec-api/src/serve.ts:61`) is passed to the auth listener (`:109`, `backend/services/semprec-api/src/authHandler.ts:184`).
  - `buildPasswordResetUrl` resolves the reset link against it (`backend/packages/data/src/auth/passwordResetActions.ts:34-38`).
  - On a host provisioned from this template, every password-reset link therefore points at `http://localhost:3000`. #1040's invitation links and #1076's fragment-token reset links use the same value.
  - An *empty* value is worse than an absent one: `??` keeps `""`, so `new URL(…, "")` throws inside the after-commit mail callback (`passwordResetActions.ts:80-86`), which `withTransaction` only logs (`backend/packages/data/src/db/pool.ts:104`).
- **`SMTP_*`** configure the only outbound mail transport (`serve.ts:63-80`).
  - Without both `SMTP_HOST` and `SMTP_FROM_ADDRESS`, the api uses `noopPasswordResetMailer`, which throws on every send (`backend/packages/data/src/auth/passwordResetMail.ts:17-21`). The reset request still answers `200` while no mail leaves, and the failure is only logged (`passwordResetActions.ts:80-86`).
  - `SMTP_PORT` defaults to `587` when unset. An empty value becomes `0` and fails startup once SMTP is configured (`serve.ts:68-71`).
  - `SMTP_SECURE` is `true` only for the exact string `"true"` (`:76`).
  - `SMTP_USER`/`SMTP_PASSWORD` are sent only when `SMTP_USER` is non-empty (`:77`).

Provisioning copies the template to `/opt/semprec/shared/.env` only when none exists (`deploy/provision.sh:203-206`) and never edits an operator's file. It already warns rather than fails on another unset value, `SEMPREC_DOMAIN` (`render_caddy_environment`, `:258-265`). #996 later splits this template into per-service group files and must carry these seven keys into the semprec-api group.

## Task

No topic skill applies. Read `deploy/README.md` "Bootstrap secrets (issue #175)" (`:171-199`) and "Front door (Caddy)" (`:218-233`) first; this issue extends that contract.

1. **Template.** In `deploy/shared/.env.example`, add a section `# ---- Public URL and outbound mail (semprec-api) ----` directly after the "Reverse proxy" section (`:206-212`). Do not touch the database-URL comments at `:62-74`; #963 edits them. Add these lines, each with a comment that names semprec-api as its only reader and what it drives (from Context):
   - `APP_BASE_URL=`. The comment says it must be `https://<SEMPREC_DOMAIN>` with no path; it is the origin of every emailed link; an absent value means `http://localhost:3000` and an empty one breaks every link.
   - `SMTP_HOST=` and `SMTP_FROM_ADDRESS=`. Both are needed to send mail; otherwise reset requests answer `200` but nothing is sent. The relay must be reachable from the host.
   - `SMTP_PORT=587`. Non-empty on purpose: an empty value fails startup.
   - `SMTP_SECURE=false`. The comment says `true` is for implicit TLS on port 465.
   - `SMTP_USER=` and `SMTP_PASSWORD=`. The password is a secret, sent only when the user is set.
2. **Provisioning check.** In `deploy/provision.sh`, add `check_outbound_link_settings`, called in `main` right after `render_caddy_environment`. It reads (last occurrence wins, e.g. `sed -n 's/^KEY=//p' "$file" | tail -n 1`) `APP_BASE_URL`, `SEMPREC_DOMAIN`, `SMTP_HOST` and `SMTP_FROM_ADDRESS` from `$SEMPREC_ROOT/shared/.env`. It only writes warnings to stderr and returns 0:
   - when `APP_BASE_URL` is absent or empty: a warning naming the key and the `http://localhost:3000` consequence;
   - when `SEMPREC_DOMAIN` is set and `APP_BASE_URL` (one trailing `/` ignored) is not `https://$SEMPREC_DOMAIN`: a warning naming both values. Neither is a secret.
   - when `SMTP_HOST` or `SMTP_FROM_ADDRESS` is absent or empty: a warning that outbound mail is not configured, naming the keys only.

   It never prints any other value, and never writes the `.env`.
3. **Tests.** In `deploy/provision.test.sh`:
   - On a fresh run, assert the installed `.env` contains the seven lines exactly as in Task 1, and that stderr carries the `APP_BASE_URL` and SMTP warnings while provisioning still succeeds.
   - Then, with `SEMPREC_DOMAIN=example.test`, `APP_BASE_URL=https://example.test`, `SMTP_HOST=smtp.example.test`, `SMTP_FROM_ADDRESS=no-reply@example.test` and `SMTP_PASSWORD=<sentinel>` written into `.env`, a run prints none of the three warnings, does not print the sentinel, and leaves `.env` byte-identical.
   - With `APP_BASE_URL=https://other.test`, the mismatch warning names both `https://other.test` and `example.test`.
4. **README.** In `deploy/README.md`, add one paragraph after the `PORT=8080` note in "Front door (Caddy)" (`:232-233`), stating:
   - `APP_BASE_URL` must equal `https://$SEMPREC_DOMAIN`;
   - without `SMTP_HOST`/`SMTP_FROM_ADDRESS` no password-reset mail is sent;
   - `provision.sh` warns about both;
   - a host provisioned earlier needs the seven lines added to its `.env` by hand, then `systemctl restart semprec-api`.

## Scope

### In scope
- Declaring the seven keys in the production template, the non-failing provisioning check, its shell test, and the README paragraph.

### Out of scope
- Any change to `backend/services/semprec-api/src/serve.ts`: treating an empty value as unset, or requiring `APP_BASE_URL` at startup.
- The reset-link format (#1076) and invitation mail (#1040).
- Splitting the template into per-service files, which moves these keys into the semprec-api group (#996).
- Egress rules affecting the SMTP relay (#1063).
- Editing an operator's existing `.env`.

## Acceptance criteria

- On a fresh host, `provision.sh` installs a `.env` containing `APP_BASE_URL=`, `SMTP_HOST=`, `SMTP_PORT=587`, `SMTP_SECURE=false`, `SMTP_FROM_ADDRESS=`, `SMTP_USER=` and `SMTP_PASSWORD=`, each under a comment naming semprec-api and what it drives (shell test, `bash deploy/provision.test.sh`).
- When `APP_BASE_URL` or the SMTP host/sender are absent or empty, provisioning completes successfully and prints the corresponding warning to stderr. When they are set consistently with `SEMPREC_DOMAIN`, it prints none (shell test, `provision.test.sh`).
- When `APP_BASE_URL` differs from `https://$SEMPREC_DOMAIN`, provisioning warns and names both (shell test, `provision.test.sh`).
- Provisioning never prints `SMTP_PASSWORD`'s value and leaves an existing `.env` byte-identical (shell test, `provision.test.sh`).
- `deploy/README.md` documents the requirement, the warnings and the manual step for existing hosts (review).
