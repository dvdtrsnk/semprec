## Context

Model tier rationale: Pure label changes in two JSON catalogs following the existing key pattern, with no schema, lifecycle or persisted-data change.

The Czech catalog `backend/packages/data/src/library/i18n/cs.json` uses wording that differs from the app's visible text. Today it reads: the movies database is "Filmy/seriály", the books status option `toRead` is "K přečtení", the movies status option `watched` is "Zhlédnuto", the movies `secondaryRating` property is "Hodnocení kritiků", and the movies `watchedWith` property is "Sledováno s". The app calls these "Filmy a seriály", "Chci číst", "Viděno", "Hodnocení zdroje" and "Viděl jsem s". These names are what the schema endpoint returns to the Czech UI, so changing the catalog aligns the schema text with the product without any client mapping.

The key `property.movies.secondaryRating.name` is also referenced by `MOVIES_LIBRARY_CONTRACT.secondaryRatingLabel` in `library/libraryModuleContract.ts`; only its translation changes, the key stays.

#1514 adds more keys to the same catalogs and builds on this issue so the two do not conflict on the file.

## Task

Load `canonical-keys`.

1. In `backend/packages/data/src/library/i18n/cs.json` change the values of: `database.movies.name` to "Filmy a seriály", `property.books.status.option.toRead` to "Chci číst", `property.movies.status.option.watched` to "Viděno", `property.movies.secondaryRating.name` to "Hodnocení zdroje", `property.movies.watchedWith.name` to "Viděl jsem s".
2. Keep every key unchanged. Do not change `en.json` unless a value there contradicts the new meaning (the English "source rating" meaning of `secondaryRating` should read "Source rating"; check and align it).
3. If an existing test asserts the old Czech strings, update it.
