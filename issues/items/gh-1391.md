## Context

Model tier rationale: One nullable column with a user-only write path and a locale-aware read across the existing handler, store and migration seams, following the pattern of the risk class and approval columns, with no new lifecycle or cross-process contract.

The project's "Tools" list shows a human label under each tool ("Read issues and pull requests") with the technical name below it. The backend only has `mcp_tool_registrations.description`, which comes verbatim from the MCP server in English, and no human label. `GET /api/projects/:id/mcp-grants` (`backend/services/semprec-api/src/mcpAgentPageHandler.ts`, `listMcpToolGrantsForProject` in `backend/packages/data/src/mcp/mcpAgentPageGrants.ts`) returns the description and the tool name only.

This issue adds a user-editable, localized label per registration and returns it in the right language. Registrations are system-wide (one row per server tool, shared by all projects), so the label is too. The label is user content: only a human route writes it, through the same user-only wrappers as the risk class (`mcpGrantsAdminStore.ts` is not exported from the package; `mcpAgentPageGrants.ts` wraps it). A sync never writes it, because `upsertMcpToolRegistration` does not touch columns outside its list; this issue keeps that true.

Stored shape: `display_label jsonb` holding `{ "cs": string, "en": string }` where each key is optional, `NULL` when no label exists. The read returns `displayLabel` as a plain string chosen by the requesting user's locale (`users.locale`, `cs` by default): the label for that locale, else the other locale's label, else the tool name. Decision: falling back to the other locale before the tool name keeps a half-translated label useful.

#1983 fills labels automatically after a sync, only where none exists. #1455 adds server state and counts to the same list.

## Acceptance criteria

- When a user with locale `cs` has a registration labelled `{cs: "Číst issues a pull requesty", en: "Read issues and pull requests"}`, then the listing returns the Czech label as `displayLabel`; for locale `en`, the English one.
- When only one locale is set, then the listing returns it for both locales; when none is set, then `displayLabel` is the tool name.
- When PATCH sends `displayLabel: null`, then the label is cleared.
- When PATCH sends an unknown key, an empty string, a non-string or a label over 120 characters, then the response is 400 and nothing changes.
- When a sync runs after a label was stored, then the label is unchanged.
- The raw label setter is not exported from the package barrel; the authenticated human PATCH uses the exported `reclassifyMcpTool` wrapper. No current agent tool, generic/MCP operation, proposal-confirm path, sync or background job provides a label-mutation capability. Verify the actual exposed capabilities and call sites; an importable backend wrapper alone is not an agent capability or a runtime sandbox.
