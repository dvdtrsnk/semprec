**Blocked by:** #121

## Context

MCP connections are system resources similar to mailboxes, but secret material cannot live in item JSON.

## Task

Seed Semprec-owned system database `mcpServers` with name, strict connection configuration for `stdio`, `sse`, or `http`, `active`, `syncStatus`, and `lastSynced`. Extend `external_credentials` ownership to MCP server items and use the existing credentials package for encryption/decryption. Extend Processing proposal confirmation for database target `mcpServers`: Semp may propose non-secret name/config, while a logged-in human supplies the credential separately during the same confirmation transaction. Proposal JSON must reject credential fields. Neither proposal nor agent paths may synchronize tools.

## Scope

### In scope

- Database seed, transport config validation, credential ownership, and proposal/confirm integration.

### Out of scope

- Tool discovery, grants, invocation, and new encryption design.

## Acceptance criteria

- No plaintext credential appears in items, proposal history, or logs.
- Confirm atomically stores server and encrypted credential or neither.
- Agents can propose server metadata but cannot provide secrets or sync.
