## Context

Model tier rationale: An exhaustive REST/MCP security matrix needs representative fixtures and proof that no tenant data leaks.

The approved behaviour is that no user ever sees, infers or is notified about another user's data, and that **a foreign id behaves exactly like a non-existent id — same status, same body** — so global uniqueness or a different error can never act as an existence oracle. Every HTTP route is inventoried in `ROUTE_MATRIX` (`backend/services/semprec-api/src/routeMatrix.ts:53`; entry shape at `:31-49`), but the only test over it (`backend/services/semprec-api/src/__tests__/routeMatrix.test.ts:69-97`) checks that an unauthenticated request gets 401. Nothing proves cross-tenant behaviour, and a newly added route is never forced into such a test (`routeMatrix.ts:4-8`).

`POST /mcp` (`backend/services/semprec-api/src/mcp/mcpHandler.ts:83-113`) exposes the 29 generic operations (`backend/packages/shared/src/genericOperations/operationNames.ts:9-39`) as `semprec.<operation>` tools, with the actor resolved from an MCP run credential or a session bearer.

The blockers made every route and the MCP endpoint tenant-scoped (RLS plus an explicit scope) and added the admin routes (`/api/admin/*`, flagged `admin: true` in the matrix by #1037, answered 403 `admin_required` for a member) and the account routes. #975 provides `createRuntimeRolePool`, `createTestTenant` and `getTenantZeroId` through `@semprec/data/testSupport`. This suite is one of the three proofs the release checkpoint #1058 requires before strict enforcement; #1054 covers realtime and #1056 background work.

## Task

No production behaviour changes, so none of the topic skills applies beyond `implement-issue`; load `io-hardening` only to read its list of edges when classifying a route you are unsure about.

1. In `routeMatrix.ts`, add `export const ROUTE_TENANCIES = ["tenant", "account", "admin", "anonymous"] as const`, `export type RouteTenancy = (typeof ROUTE_TENANCIES)[number]`, and a **required** `tenancy: RouteTenancy` field on `RouteMatrixEntry`, documented as: `anonymous` — reachable without a session (`public: true`); `admin` — an entry with `admin: true` (#1037); `account` — reads or writes only the caller's own rows in global identity tables (logout, current session, revoke session, register/revoke push subscription); `tenant` — everything else, including `/mcp`, `/api/sync` and the account export/deletion routes. Classify every entry (`api`, `view` and `ws`).
2. Create `backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts`. Its `beforeAll` sets `process.env.SEMPREC_TENANT_SCOPE = "strict"` (`enforceTenantScope` from #978 reads it on every call) and `afterAll` restores it:
   - **Fixture.** Two tenants A and B from `createTestTenant(adminPool)` (`@semprec/data/testSupport`, #975), each provisioned with `provisionTenant(pool, id)` (#1005), each with a member user, a web session and a bearer session, plus one admin user. The dispatcher is `createDispatcher` (as `routeMatrix.test.ts:40-52` builds it) over a `createRuntimeRolePool(adminPool, "semprec_data")` pool. In A, create one row of every kind a route addresses — user database, property, view, curated view item, two items and a relation, an uploaded file and its blob, a notification, a project with a heartbeat, an agent run with an event and an approval request, an MCP server item with a tool registration and a project grant, a transcription and transcript item, a proposal item, a push subscription, a second session, and an export if the export routes exist — and record every id.
   - **Exhaustiveness.** A map keyed by `RouteMatrixEntry.name` holds one case per `surface: "api"` entry. A test fails, listing the names, when an `api` entry has no case or a case names no entry; another fails when an entry's `tenancy` is not in `ROUTE_TENANCIES`, when `tenancy: "anonymous"` and `public: true` disagree, or when `tenancy: "admin"` and `admin: true` disagree.
   - **Comparison rule.** Two responses are equal when their statuses are equal and their body texts are equal after every occurrence of the requested id(s) is replaced with `<id>`.
   - **`tenant` cases.** As B: a route with an id (path or body) answers A's id exactly as a random UUID; a mutation with A's id leaves A's row unchanged (re-read as A); a create referencing A's parent (database, view, item, relation target, project, MCP server) answers exactly as with a random parent; a list, query or count response contains none of A's ids.
   - **`account` cases.** B presenting A's session id or push-subscription id is answered exactly as a random id, and A's session and subscription stay active.
   - **`admin` cases.** A member gets the same 403 `admin_required` whether the path names A's id or a random one; for the admin, no response body contains any id of a tenant-owned fixture row of A or B.
   - **`anonymous` cases.** The response is identical whether the request names A's identifiers or random ones (e.g. the Graph webhook with A's subscription id versus a random one; login and reset requests for A's email versus an unknown one, as far as status and body).
   - **MCP.** A `satisfies Record<GenericOperationName, …>` case table; for every operation taking an id, `tools/call` as B — with B's session bearer and with an MCP run credential minted for B's own project — answers A's ids exactly as random ids, and every list/query operation returns none of A's ids.
3. If a case fails because a route really leaks, do not change the route here: leave the failing case in the pull request and stop, reporting which route and how — the fix belongs to the issue that owns that route.

## Acceptance criteria

- Integration: removing the case of any `surface: "api"` entry makes the exhaustiveness test fail naming that entry; an entry without `tenancy` fails `pnpm -r run build`.
- Integration: for every `tenant` entry with an id, B's request with A's id equals B's request with a random UUID under the comparison rule, and A's rows read back unchanged after every mutating case.
- Integration: no list, query or count response to B, over REST or MCP, contains any of A's recorded ids.
- Integration: `account`, `admin` and `anonymous` entries each pass their class's case as described in Task step 2.
- Integration: every one of the 29 generic operations has an MCP case, exercised under both a session bearer and an MCP run credential.
- The suite runs on runtime-role pools only (no superuser pool reaches the dispatcher) with strict scope enforcement in effect.
