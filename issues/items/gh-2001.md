**Blocked by:** #1827
**Model tier:** high

## Context

Model tier rationale: This changes what is persisted for every agent message after a sensitive read and must keep reconstruction and compaction consistent; an over-broad rule breaks resumed runs, a too narrow one leaks sensitive values, and the choice is not obvious from existing code.

#1827 replaces the stored `tool_result` of a content-bearing operation on a sensitive database with `[redacted: sensitive]` (`packages/agent-runtime/src/lifecycleAdapter.ts`). The same values still reach `agent_run_events` in three other ways: as arguments of the agent's tool calls (a value it writes into a health record), as assistant text that quotes what it read, and through a compaction checkpoint (`packages/agent-runtime/src/compaction.ts`, stored as a `compaction` event and used by `conversationReconstruction.ts`).

Decisions (decided by the product owner):
- Tool call arguments, assistant text and compaction summaries that carry sensitive values are redacted in the same way as the source; otherwise the values would leak past the permission.
- Tool call arguments: the stored arguments of a content-bearing write (`item.create`, `item.patch`) to a sensitive database, and of every tool call issued later in a turn that already has a marked result, are replaced by the marker; the tool name and call id stay, so every call still pairs with its result.
- Assistant text: once a turn has a tool result marked sensitive by #1827, the assistant text persisted after it in that turn is stored as the marker.
- Compaction: a compaction checkpoint is built only from the reconstructed, redacted history, so it never sees an unredacted value.
- The live session in memory is unchanged; only persisted events are redacted.

## Task

Load `state-writes`, `io-hardening` and `testing`.

1. Track, per turn in `lifecycleAdapter.ts`, whether a persisted tool result carried the sensitive mark of #1827.
2. When persisting a tool call event, replace its arguments with `[redacted: sensitive]` when the call is a content-bearing write to a sensitive database (same transaction-time lookup as #1827) or when the turn already has a marked result.
3. When persisting assistant text after a marked result in the same turn, store the marker instead of the text.
4. Make sure compaction is computed from the reconstructed, redacted entries (`conversationReconstruction.ts`), never from the live session, and that the stored checkpoint holds no unredacted value.
5. Tests: an `item.patch` to a health record is stored with redacted arguments and its result still pairs; an assistant reply quoting a health record value after a sensitive read is stored as the marker while a reply in a turn without a sensitive read is stored in full; a compaction after a sensitive turn contains no value of the record; a resumed run continues from the markers; no log or error message of this path carries item values.

## Touches

- backend/packages/agent-runtime/src/lifecycleAdapter.ts
- backend/packages/agent-runtime/src/conversationReconstruction.ts (compaction from redacted entries, if needed)
- backend/packages/agent-runtime/src/__tests__/ (new redaction tests)

## Scope

### In scope

- Redacting persisted tool call arguments, assistant text and compaction checkpoints that carry sensitive values, with call/result pairing kept.

### Out of scope

- Redacting tool results: #1827.
- Redacting events already stored.
- Shorter retention for runs that touched sensitive data.
- Classifying assistant text by its content.

## Acceptance criteria

- When an agent writes a value into a health record, then the stored tool call has `[redacted: sensitive]` as arguments and still pairs with its result.
- When the agent answers after reading a health record in the same turn, then the stored assistant text is the marker and the live reply is unchanged.
- When a turn read no sensitive item, then its assistant text and tool calls are stored in full.
- When a conversation is compacted after a sensitive turn, then the stored checkpoint contains no value of the sensitive item.
- When a run is resumed, then it continues from the markers.
