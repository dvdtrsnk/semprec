## Context

Model tier rationale: One new variant of an existing ref schema with validation and label resolution against a thread alias lookup, following the patterns of the other ref kinds.

A Semp chat message can carry references to things the user dragged in. A mail message and a draft are references to items of the Emails database; an attachment is a reference to its Files item (`mail/attachments.ts` creates it, so no separate attachment kind is needed). A thread is not an item the client may address by item id, because its public id is the thread id and the Threads item id is internal. The ref schema is #1369, validation and storage #1682, label and trash state in history #1684. Merged threads keep resolving through #1493. The agent reads a thread with `mail.thread.get` (#1927); the expansion of refs into the turn is #1733.

Decision: a thread ref that names a merged-away id is stored as given and translated when read or expanded; "trashed" means every message of the thread is in the Trash folder; "purged" means the thread id is unknown and has no alias.

Shared-file ordering: this issue also waits for #2035 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `canonical-keys`, `io-hardening` and `testing`.

1. Extend the ref schema with the variant `{ kind: "mailThread", threadId }` (uuid) (kind in camelCase as stored).
2. Validation (#1682): a `mailThread` ref must name a thread of the caller's tenant, directly or through an alias; otherwise it is rejected as `validation_failed`.
3. Translation: add `mail/mailThreadRef.ts` with a function resolving a `threadId` to the current thread id through the aliases; use it when the ref is expanded for the agent (so the agent receives the current thread through `mail.thread.get`) and when its label is resolved.
4. Label and state for history (#1684): label = the thread subject, state `trashed` for a thread whose messages are all in Trash, `purged` for an unknown id.
5. A ref `{ kind: "item" }` to a Threads item is not accepted by this issue's code path; it stays governed by ref validation.

### Out of scope

## Acceptance criteria

- A message with a ref to an existing thread is accepted; a ref to an unknown thread id is rejected.
- A ref to a thread that was merged away is accepted, and expanding it yields the current thread.
- In the thread history the ref label is the subject; a thread whose messages are all in Trash shows `trashed`, an unknown id shows `purged`.
