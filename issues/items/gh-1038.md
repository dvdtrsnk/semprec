## Context

Model tier rationale: The definer function SQL, report shape and single route are given exactly.

An admin sees operational health only as content-free counts. They never see another tenant's ids, text or errors. Today the single health report mixes operator data with tenant content: `getSystemHealthReport` (`backend/packages/data/src/observability/systemHealthReport.ts:171-191`) returns:

- process freshness for the four fixed processes plus one `mailsync:<mailboxItemId>` per mailbox (`getProcessHealthStatuses`, `:56-95`, via `getExpectedProcessNames`, `backend/packages/data/src/health/processHeartbeats.ts:107`);
- every alerting `observability_checks` row with its `detail` (`:98-103`);
- global queue counts over `graphile_worker.jobs` (`:113-127`);
- `item_automation` error counts per database id (`:134-144`);
- agent-run errors over 7 days (`:146-151`);
- every mailbox's `lastError` (`:153-162`).

It is served at `GET /api/system-health` to any session (`backend/packages/data/src/chokePoint/schemaCoreModuleManifest.ts:78-87`).

This issue adds the admin-only operator report. Its sibling #1052 then narrows `/api/system-health` to the caller's own tenant.

What the blockers delivered:

- The admin plane (#1037): `createAdminRoutes(pool, options)` in `backend/services/semprec-api/src/adminHandler.ts`. Routes with `admin: true` return 403 `admin_required` to members and run inside `runAsSystem(...)`, where row-level security shows no tenant rows. The route matrix carries an `admin` field.
- The NOLOGIN `BYPASSRLS` role `semprec_router` and the router-function convention (#997). Every cross-tenant read goes through a `SECURITY DEFINER` function that is:
  - owned by `semprec_router`;
  - backed by column-level `SELECT` grants only;
  - declared with `SET search_path = pg_catalog, public`;
  - `EXECUTE` revoked from `PUBLIC` and granted to exactly one runtime role;
  - returning only ids or numbers.
- Per-mailbox stall checks now live in the tenant table `tenant_observability_checks` (#999), and global `observability_checks` rows are content-free (no `lastError`). The status domain is the same `ok`/`alerting` (`0039_observability_checks.sql:10`).

## Task

Load `db-migrations` (definer function and grants), `io-hardening` (new admin route) and `state-writes` (it reads only, but confirm the route performs no write).

1. **Migration** (take the next free migration ordinal at commit time; additive, rollback-safe):
   ```sql
   CREATE FUNCTION ops_health_counts()
   RETURNS TABLE (agent_run_errors_7d bigint, item_automation_errors bigint, alerting_tenant_checks bigint)
   LANGUAGE sql STABLE SECURITY DEFINER SET search_path = pg_catalog, public AS $$
     SELECT
       (SELECT count(*) FROM public.agent_runs WHERE status = 'error' AND started_at >= now() - interval '7 days'),
       (SELECT count(*) FROM public.item_automation WHERE status = 'error'),
       (SELECT count(*) FROM public.tenant_observability_checks WHERE status = 'alerting')
   $$;
   ALTER FUNCTION ops_health_counts() OWNER TO semprec_router;
   GRANT SELECT (status, started_at) ON agent_runs TO semprec_router;
   GRANT SELECT (status) ON item_automation TO semprec_router;
   GRANT SELECT (status) ON tenant_observability_checks TO semprec_router;
   REVOKE EXECUTE ON FUNCTION ops_health_counts() FROM PUBLIC;
   GRANT EXECUTE ON FUNCTION ops_health_counts() TO semprec_data;
   ```
   The function returns counts only. `tenant_observability_checks.status` is `ok | alerting` (#999).
   Append one row for `ops_health_counts()` to the `## Cross-tenant router functions (semprec_router)` table in `docs/operations/database-roles.md` (#997): executing role `semprec_data`, returns three counts, and the columns read listed above.
2. **Report** — in `systemHealthReport.ts`, add `getOperatorHealthReport(client: Queryable): Promise<OperatorHealthReport>` next to the existing report, reusing its private helpers:
   ```ts
   interface OperatorHealthReport {
     generatedAt: string;
     processes: ProcessHealthStatus[];          // FIXED_PROCESS_NAMES only (processHeartbeats.ts:15), never mailsync:<id>
     alertingChecks: AlertingCheck[];           // global observability_checks rows with status 'alerting' only
     queue: QueueHealthCounts;                  // the existing global getQueueHealthCounts
     tenants: { provisioning: number; active: number; suspended: number; deleting: number }; // count(*) GROUP BY tenants.status, missing statuses = 0
     tenantAggregates: { agentRunErrors7d: number; itemAutomationErrors: number; alertingTenantChecks: number }; // one call to ops_health_counts()
   }
   ```
   - Read `alertingChecks` with its own query on `observability_checks` alone, not through `getAlertingChecks`. Since #999 that helper also unions the caller's `tenant_observability_checks` rows, and while tenant zero is the only tenant those would be visible even in system scope.
   - Factor `getProcessHealthStatuses` so the operator report passes the fixed list explicitly and never calls `getExpectedProcessNames`. In system scope that function would see no tenant mailboxes, or tenant zero's while it is the only tenant.
   - Validate every `pg` row with a type argument, and convert counts with `Number()` as the existing helpers do.
   - Leave `getSystemHealthReport` unchanged; #1052 owns it.
3. **Route** — add `GET /api/admin/health` (`admin: true`) to `createAdminRoutes`. It answers `200` with the `OperatorHealthReport` and performs no write. Add the route-matrix entry `{ name: "admin operations health", method: "GET", path: "/api/admin/health", surface: "api", public: false, admin: true }` and its `ROUTE_HANDLER_FILES` mapping.

## Acceptance criteria

- When an admin calls `GET /api/admin/health` with two tenants that each have one errored agent run in the last 7 days, one `item_automation` row in `error` and one alerting `tenant_observability_checks` row, `tenantAggregates` is `{ agentRunErrors7d: 2, itemAutomationErrors: 2, alertingTenantChecks: 2 }`. An agent-run error older than 7 days is not counted (integration, `operatorHealthReport.test.ts`, two tenants via `createTestTenant()` from #975).
- When the report is built, `processes` lists exactly `api`, `agents`, `transcribe` and `ai-gateway`, even while mailbox `mailsync:<id>` heartbeat rows exist (integration, `operatorHealthReport.test.ts`).
- When tenants exist in `active`, `suspended` and `deleting`, `tenants` reports each count, and `provisioning` is `0` when none exists (integration, `operatorHealthReport.test.ts`).
- When the serialized report body is searched for any tenant's mailbox item id, database id, item id or recorded `lastError` string, none occurs (integration, `adminHandler.test.ts`).
- When a `member` calls `GET /api/admin/health`, the response is 403 `admin_required`. Without a session it is 401 (integration, `adminHandler.test.ts`, `routeMatrix.test.ts`).
- When `ops_health_counts()` is called as `semprec_side` or as a role other than `semprec_data`, it fails with a privilege error. As `semprec_data` it succeeds while that role still sees no tenant rows directly in system scope (integration, `operatorHealthReport.test.ts`, `createRuntimeRolePool` from `@semprec/data/testSupport`, #975).
- When the catalog is inspected, `ops_health_counts` is owned by `semprec_router`, is `SECURITY DEFINER` and has a pinned `search_path`. `semprec_router` holds only the column-level `SELECT` grants listed above on those three tables (integration, `operatorHealthReport.test.ts`).
