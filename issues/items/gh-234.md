**Blocked by:** #233

## Context

Issue #233 exposes the `/setup` API that creates the first account under the empty-`users`-plus-`SETUP_TOKEN` gate. The operator still needs a usable way to drive it. This issue adds the `/setup` wizard page in the web client; it contains no account logic of its own. #143 then protects every other route and keeps the wizard and its API public.

## Task

Implement `/setup` as a wizard in the web client on top of the #233 API: the page is opened with the setup token as its query parameter, collects email and password, and submits them together with that token to the setup API. The wizard calls no special-case logic and performs no account creation itself. When the API answers 404 (a user already exists or the token does not match) the wizard renders a not-found state without a form. After a successful creation it leads to the existing login from #140; it does not create a session itself.

## Scope

### In scope

- The `/setup` wizard page, its form, and its success and not-found states.

### Out of scope

- Setup API, account-creation function, and race safety — delivered by #233.
- Route protection and the route-matrix test — delivered by #143.
- Localization of the wizard and other login screens (system-i18n batch), public signup, additional accounts, roles, TOTP.

## Acceptance criteria

- Opening the wizard with a valid token while `users` is empty shows the form; submitting it creates the account through the #233 API.
- When the API returns 404 the wizard shows the not-found state and offers no form.
- The wizard contains no account-creation logic of its own; only the #233 API inserts users.
