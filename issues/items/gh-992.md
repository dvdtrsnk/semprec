## Context

`semprec-transcribe` is a queue consumer for one task, `transcriptionJob`, registered through `registerTask` (`backend/services/semprec-transcribe/src/queueRuntime.ts:25-49`, `:33-37`) and run at `concurrency: 1`. Its handler, `createTranscriptionTask` (`backend/services/semprec-transcribe/src/transcriptionTask.ts:828-905`), keeps no state across jobs:
- it resolves the Files and Transcripts databases per job (`:854`, `:242`, `:320`), with nothing captured at boot;
- each step opens its own transactions between awaited ffmpeg work and gateway calls;
- it re-enqueues itself with `enqueueTranscriptionJob` when shutdown interrupts it (`:880-887`);
- it builds its gateway clients per job (`:839-850`, `:869-870`).

Its process-level work is the startup in `backend/services/semprec-transcribe/src/serve.ts:9-23`:
- realtime hook registration, which issues no query (`:14`);
- the heartbeat (`:15-19`);
- the runtime (`:21`).

Tenancy state this issue builds on:
- #978: `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()` come from `@semprec/shared`.
  - `withTransaction` and every query on a `createPool` pool apply the scope through the GUC `app.tenant_id`.
  - A query with no scope logs `tenant_scope_missing` under `SEMPREC_TENANT_SCOPE=warn` (the default until #1067), or throws `TenantScopeMissingError` under `strict`.
  - Pooled connections are opened detached.
- #982: `enqueueJob` stamps the envelope `tenantId` from the producer's scope. `TASK_TENANCY` marks `transcriptionJob` as `tenant`.
  - `registerTask` runs the job inside `runInTenant(envelope tenantId)`, and completes it as a no-op for a `suspended`, `deleting` or unknown tenant.
  - A legacy envelope falls back to `app_sole_tenant()` until #1061.
  - `runWorker`, the runner's `stop()` and the schema calls run inside `runAsSystem`.
- #990 runs every heartbeat tick in system scope.
- #965 replaced the in-callback `SET TRANSACTION` with `withTransaction`'s `isolation` option. Once #978 runs `set_config` right after `BEGIN`, the old form fails at step 1. The pipeline test below therefore depends on that fix.

So no production change is left for this process. What is missing is proof, in the transcribe composition itself, that a whole transcription runs in its envelope's tenant under `strict` enforcement:
- every step's transactions, including those after ffmpeg child processes and stream pipelines;
- every gateway call;
- the failure record;
- the shutdown re-enqueue, whose new envelope must carry the same tenant.

#993 reads `currentTenantScope()` inside the gateway clients to add the tenant header. This issue pins that behaviour with a strict-mode test.

## Task

Load `io-hardening` (child processes, streams and shutdown on the job path) and `error-handling` (the failure and interruption paths must keep the scope).

1. **No production change.** `serve.ts`, `queueRuntime.ts` and `transcriptionTask.ts` stay as they are. If a criterion below fails because a query on the transcription path runs outside the job's scope, stop and report the call site with its `path:line`, without fixing it here.
2. **Test.** Create `backend/services/semprec-transcribe/src/transcriptionTenantScope.test.ts` (integration). Keep it out of `transcriptionTask.test.ts`, which sibling issues edit.
   - Use a pool from `createPool(process.env.TEST_DATABASE_URL)`.
   - Set `SEMPREC_TENANT_SCOPE=strict` per case and restore it afterwards.
   - Tenant zero is `SELECT app_sole_tenant()`.
   - Build fixtures inside `runInTenant(<tenant zero>, …)` the way `transcriptionTask.test.ts` does: `seedSystem`, a user, and a Files item whose blob comes from `./__tests__/fixtures/mediaFixtures.js`.
   - Use small fake `AudioGatewayClient` and `AiGatewayClientPort` implementations that record `currentTenantScope()` on every call.
   - Run jobs like the retry test (`transcriptionTask.test.ts:1546-1589`): a `registerTask`-wrapped task list, `enqueueJob` inside tenant zero's scope, then `runOnce` from the test body with no scope.
   - Create the runtime with `createTranscribeQueueRuntime` for the lifecycle case.

## Acceptance criteria

All integration tier, in `transcriptionTenantScope.test.ts`, with `SEMPREC_TENANT_SCOPE=strict` unless stated otherwise.
- **Runtime lifecycle.** `createTranscribeQueueRuntime(pool, registry)` resolves and `runtime.stop()` resolves, both called with no ambient scope.
- **Whole pipeline.** A `transcriptionJob` for a fresh audio source, enqueued inside tenant zero's scope and run through `runOnce`, settles the transcript `done`.
  - Every recorded `diarize`, `transcribe` and `complete` call saw `{ kind: "tenant", tenantId: <tenant zero> }`.
  - No step raises `TenantScopeMissingError`, including the transactions after ffmpeg work.
- **Shutdown re-enqueue.** When the handler runs inside tenant zero's scope and its abort signal fires during ASR, it returns normally. The re-enqueued `transcription-job:<fileItemId>` row's payload envelope has `tenantId` equal to tenant zero.
- **Failure path.** When the summary fake throws on the last allowed attempt, the transcript ends `error` with one `automation_error` notification, and no `TenantScopeMissingError` occurs.
- **`warn` mode unchanged.** With `SEMPREC_TENANT_SCOPE=warn`, every existing test in `transcriptionTask.test.ts` and `queueRuntime.test.ts` passes unchanged.
