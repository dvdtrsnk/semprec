4. On replay, rebuild images from refs within the whole-request 4 MB budget; unloadable/over-budget images become placeholders after successful stream cleanup. Typed cleanup failure stops expansion.
5. Check that `piMessagesHandler.ts` passes image blocks to the provider unchanged, and adjust its message-shape validation if it rejects them.
6. ## Scope

### In scope

- Image blocks in turns and in replayed history, model image input flag, downscaling and the 4 MB budget.

### Out of scope

- Text from PDF, DOCX and other files: #1740.
- The upload endpoint or any client change; the client uploads through `POST /api/files` and attaches the ref.
- Storing images in events, or any persistent resized copy.

## Acceptance criteria

- When a message refs an image file, then the model receives it as an image block.
- When a thread whose history contains ten images wakes, then the request sent to the gateway is under 4 MB.
- When events are inspected after the turn, then none contains base64 image data.
- When an image cannot load for replay and owned-stream cleanup succeeds, a placeholder replaces it and the turn continues; cleanup failure stops expansion.
