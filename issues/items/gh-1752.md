## Context

Model tier rationale: ephemeral images cross agents/history/gateway with a 4 MiB whole-request cap and no binary persistence. #1733 supplies refs to Files/mail attachments; #1566 persists ref-only user turns. SempConversation and the real AgentSession/piAgentSession fresh/continuing prompts must carry optional images; replay reloads refs into temporary image blocks. Keep input text+image. Installed pi 0.85.1 generic transforms consult model.input, but pi-messages directly serializes context: the flag alone proves no delivery. Bound actual serialized payload, including tools/system/history/options. Use the scoped direct sharp dependency for genuine bounded decoding/resizing; no transitive canvas/host utility or persistent derivative.

## Task

Load `ai-gateway`, `io-hardening` and `testing`.

1. Declare image input on the gateway model in `modelComposition.ts` (`input: ["text", "image"]`) and verify against the pi version in use how `model.input` gates image blocks; record the finding in the PR.
2. Extend the turn input of `SempConversation.send` so a turn can carry text plus image blocks, and extend `toPiMessages` in `piConversationHistory.ts` to produce user messages with `ImageContent` blocks.
3. In the ref expander (#1733), for a ref whose blob is an image, load, downscale (longest side and byte budget as named constants) and return it as an image block for the turn.
4. When replaying history, rebuild image blocks from the stored refs with a total image budget that keeps the whole request under 4 MB; images that do not fit, or cannot be loaded, become a text placeholder.
5. Check that `piMessagesHandler.ts` passes image blocks to the provider unchanged, and adjust its message-shape validation if it rejects them.
6. Tests: a turn with an image ref reaches the model as an image block; a thread with ten images in history wakes and the serialized gateway request stays under 4 MB; `agent_runs.task` and `agent_run_events` contain no base64; an unloadable image becomes a placeholder; the gateway route accepts a message with an image block.

Use the actual local AgentSession options/send and piAgentSession prompt(input, images) overload for fresh and continuing turns, retaining refs only in user events. Enforce the complete UTF-8 JSON payload limit before fetch at the existing modelComposition onPayload boundary; replace oldest images with text placeholders, then newer images if necessary. Refuse before network if non-image content alone is too large; never truncate tools/system text or claim this refusal is provider success. The detailed finite image limits and dependency delta are in the batch reconciliation.

## Scope

### In scope

- Image blocks in turns and in replayed history, model image input flag, downscaling and the 4 MB budget.

### Out of scope

- Text from PDF, DOCX and other files: #1740.
- The upload endpoint or any client change; the client uploads through `POST /api/files` and attaches the ref.
- Storing images in events, or any persistent resized copy.

## Acceptance criteria

- When a message refs an image file, then the model receives it as an image block.
- When a thread whose history contains ten images wakes, then the request sent to the gateway is under 4 MB.
- When events are inspected after the turn, then none contains base64 image data.
- When an image cannot be loaded for replay, then a text placeholder replaces it and the turn continues.
