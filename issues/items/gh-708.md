**Blocked by:** #702

## Context

`deploy/nftables.conf` is documented (`deploy/README.md` line 11) as "the host firewall: only 22/80/443 reachable from outside the host", but `deploy/provision.sh` neither installs the `nftables` package (`install_host_packages`, lines 88-98) nor copies the file to `/etc/nftables.conf` nor enables `nftables.service`. A provisioned host therefore has no firewall at all beyond each listener's loopback binding.

Installing the file as it is would be worse than not installing it. Line 8 is `flush ruleset`: on Debian 12/13 Docker programs its rules through iptables-nft, so its `ip filter` / `ip nat` tables live in the same nftables ruleset and a `flush ruleset` deletes them — every published port mapping (`127.0.0.1:5432` for Postgres) and every container's masquerading disappears until `docker.service` is restarted, and `systemctl reload nftables` on a running host repeats the damage. Lines 26-28 declare a `forward` chain with `policy drop` at the same hook priority as Docker's own `FORWARD` chain: a verdict of `drop` in any base chain is final, so bridged container-to-container traffic (the monthly restore test's `--internal` network, `deploy/systemd/scripts/semprec-restore-test.sh`) would be dropped regardless of Docker's accept rules. Ordering relative to `docker.service` is not the problem once the flush is gone: Debian's `nftables.service` is `Before=network-pre.target` and `docker.service` is `After=network-online.target`, so the ruleset is always applied first, and without a flush a later reload cannot remove Docker's tables either.

This issue depends on sibling issue F7a, which adds the Caddy functions at the same place in `provision.sh` and the same test block in `provision.test.sh`; its functions and assertions go directly after F7a's.

## Task

1. **Ruleset** — rewrite `deploy/nftables.conf` to own exactly one table and touch nothing else:
   ```
   #!/usr/sbin/nft -f
   # (keep the issue #174 header comment, corrected: MinIO is gone, Docker's own tables are
   # deliberately left alone — this file never flushes the ruleset.)

   table inet semprec
   flush table inet semprec

   table inet semprec {
   	chain input {
   		type filter hook input priority 0; policy drop;
   		iif "lo" accept
   		ct state established,related accept
   		ct state invalid drop
   		tcp dport 22 accept
   		tcp dport 80 accept
   		tcp dport 443 accept
   		icmp type { echo-request, destination-unreachable, time-exceeded } accept
   		icmpv6 type { echo-request, nd-neighbor-solicit, nd-neighbor-advert, nd-router-solicit, nd-router-advert, destination-unreachable, time-exceeded, packet-too-big } accept
   	}
   }
   ```
   The `table` + `flush table` pair is the standard idempotence idiom (`nft -f` re-applies without duplicating rules and without touching any other table). No `forward` chain (Docker owns forward policy for its bridges) and no `output` chain (it only restated the default accept).
2. **provision.sh** — add `nftables` to the `apt-get install` list (line 88-98). After F7a's Caddy functions, add `install_nftables_config` (`install -o root -g root -m 0644 "$SCRIPT_DIR/nftables.conf" "$NFTABLES_CONFIG"` with a `readonly NFTABLES_CONFIG=/etc/nftables.conf` constant the test can redirect) and `apply_nftables`: `nft -c -f "$NFTABLES_CONFIG"` (syntax check; a failure aborts provisioning before anything is enabled), then `systemctl enable nftables` and `systemctl reload-or-restart nftables`. Call both from `main` after F7a's calls.
3. **README** — update the `nftables.conf` bullet (line 11) to say it is installed to `/etc/nftables.conf` and enabled by `provision.sh`, keeps its own `table inet semprec`, and never flushes Docker's tables; add a `## Host firewall (nftables)` section after F7a's `## Front door (Caddy)` section with the same three facts and the note that container-to-container traffic is governed by Docker's own chains.
4. **Tests** — `deploy/provision.test.sh`: add the `NFTABLES_CONFIG` `sed` redirection, an `nft` mock that records `nft $*` (placed directly after F7a's `caddy` mock), and — directly after F7a's assertion block — assert the installed file exists and contains `table inet semprec` and no line matching `^flush ruleset`, that `nft -c -f` and `systemctl enable nftables` and `systemctl reload-or-restart nftables` were recorded, and that `nftables` appears in the recorded `apt-get` command.

## Scope

### In scope
- The ruleset rewrite, its installation and enablement, README and tests.

### Out of scope
- Caddy installation (F7a) and `/opt/semprec/shared` permissions (sibling issue F8a).
- Rate limiting or per-port allowlists beyond 22/80/443.
- A `Before=docker.service` drop-in for `nftables.service` (not needed once the flush is gone; see Context).

## Acceptance criteria

- When `provision.sh` runs on a host with Docker running and containers up, `/etc/nftables.conf` is installed, `nftables.service` is enabled and active, `nft list tables` still shows Docker's `ip filter` / `ip nat` tables, and the Postgres port mapping keeps working.
- When the file is applied twice (`nft -f /etc/nftables.conf` or `systemctl reload nftables`), `nft list table inet semprec` shows each rule exactly once.
- From outside the host, only TCP 22, 80 and 443 answer; from the host itself, `127.0.0.1:5432` and `127.0.0.1:8080` are unaffected.
- `bash deploy/provision.test.sh` passes.
