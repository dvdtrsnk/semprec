**Blocked by:** #127, #231

## Context

Visible registrations need one runtime adapter that forwards calls and returns protocol results to pi. The stdio, SSE, and HTTP connections themselves — credential decryption and injection, cleanup, and the contract test servers — already exist in the MCP client connection factory from #231; this issue builds the invoke adapter on top of that factory and must not re-implement transports.

## Task

Implement the outbound MCP-invoke adapter inside `semprec-agents`. Resolve registration and project grant from server-derived run context, validate arguments against the synchronized schema, open the connection through the factory from #231 (which decrypts credentials only for connection use), and invoke over the configured stdio, SSE, or HTTP transport, closing the connection through the factory afterwards. Return MCP success/error content as a valid AgentTool result and account any model-side continuation through the existing runtime/gateway. Reject inactive, ungranted, unknown, or schema-invalid calls before transport. Feed approval metadata to the approval baseline; do not implement its waiting/execution state here.

## Scope

### In scope

- Three transports (via the #231 factory), lookup/authz/schema validation, connection cleanup, and result mapping.

### Out of scope

- Approval queue, tool sandbox, live tool-list changes.
- Re-implementing transports, credential handling, or contract servers — provided by #231.

## Acceptance criteria

- Contract servers for all transports receive identical validated calls/results.
- Spoofed project/tool identity cannot bypass grants.
- Secrets are absent from results and logs.
