## Context

Model tier rationale: A small additive field on an existing read projection that reuses the batched item lookup already in the same function and adds no persisted data, lifecycle or authorization contract.

Product behavior: an approval request for an external MCP tool call names the server and the tool in plain words, regardless of where the request came from.

Today the `mcpInvoke` variant of `ApprovalRequestSafeSummary` in `backend/packages/data/src/mcp/approvalRequestsQueue.ts` carries only `mcpToolRegistrationId`, `mcpServerItemId` and `argKeys`. The server's display name lives on the `mcpServers` item and the tool name on `mcp_tool_registrations.tool_name` (`mcpToolRegistrationsStore.ts`); the request's `toolName` is the tool name at request time. Argument values stay hidden by design and are not touched here.

Decision: the server and tool names belong to the operation, not to the request source, so they are added to `safeSummary` for every source.

Decision: the names are resolved at read time (a renamed server shows its current name); a deleted server or missing registration yields `null` for that field rather than an error.

## Task

Load `testing`.

1. Extend the `mcpInvoke` variant of `ApprovalRequestSafeSummary` with `mcpServerName: string | null` and `mcpToolName: string | null`. The `genericOperation` variant is unchanged.
2. Resolve the names in `listApprovalRequestsQueue` and in `toApprovalRequestDecisionView`'s caller path with batched reads: the `name` property of the `mcpServers` items (through `getItemsByIds`) and `tool_name` of the registrations. `safeSummaryOf` takes the resolved names as input and stays a pure function.
3. Keep every existing field and value of the response unchanged.

## Scope

### In scope

- `mcpServerName` and `mcpToolName` on the `mcpInvoke` safe summary of the list and the decision view.

### Out of scope

- The request source: #1766.
- A human description of the action: #1683.
- Argument values in any summary.
- Reading a single request or filtering the list: #1785 and #1786.

## Acceptance criteria

- When an `mcpInvoke` request is listed, its `safeSummary` contains `mcpServerName` equal to the server item's name and `mcpToolName` equal to the tool's name, whatever the request's source.
- When the server item has been deleted, the response is still 200 and `mcpServerName` is `null`.
- When a `genericOperation` request is listed, its `safeSummary` has no new fields.
- The response keeps all previous fields with unchanged values.
