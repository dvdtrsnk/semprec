## Context

`withTransaction` (`backend/packages/data/src/db/pool.ts:75-122`) is the sole sanctioned transaction opener (`docs/adr/2026-09-29-withtransaction-is-the-sole-transaction-opener.md`). It already accepts the isolation level as an option: `{ isolation: "repeatable_read" }` issues `BEGIN ISOLATION LEVEL REPEATABLE READ` (`pool.ts:56-59`, `:83-89`). That option is covered by `backend/packages/data/src/__tests__/pool.unit.test.ts:202-215`.

The transcription task does not use the option. Its private helper `withRepeatableReadTransaction` opens a plain `BEGIN` through `withTransaction` and then runs `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ` as the callback's first statement (`backend/services/semprec-transcribe/src/transcriptionTask.ts:205-216`). It is the only `SET TRANSACTION` in the backend. The helper wraps four transactions: step 1's read and write transactions (`:273`, `:305`) and the read transactions of steps 5 and 7 (`:564` in `runSummarizeStep`, `:632` in `runSuggestSpeakersStep`). These are the bracketing transactions of `docs/adr/2026-09-10-bracket-non-transactional-calls-with-staleness-checked-transactions.md`.

This works today only because `SET TRANSACTION` happens to be the first statement after `BEGIN`. Postgres rejects it after any other query in the transaction ("SET TRANSACTION ISOLATION LEVEL must be called before any query"). The multi-tenancy program's #978 makes `withTransaction` run `SELECT set_config('app.tenant_id', $1, true)` right after `BEGIN`. From then on this helper would fail on every call and stop every transcription at step 1.

The transcribe process's tenant work in #992 builds on this fix. It is one of the pre-existing defects fixed first in that program.

## Task

Load `error-handling`: the change sits on a rollback path, and `withTransaction`'s failure semantics must stay intact.

1. In `backend/services/semprec-transcribe/src/transcriptionTask.ts`, change the body of `withRepeatableReadTransaction` (`:211-216`) to a single delegation, `return withTransaction(pool, fn, { isolation: "repeatable_read" });`.
   - Update its docblock (`:205-210`) to say the isolation level is set by `withTransaction`'s option on the `BEGIN` itself.
   - Keep the helper's name and its four call sites unchanged. No step's logic changes.
2. In `backend/services/semprec-transcribe/src/transcriptionTask.test.ts`, inside the existing `describe("transcription step 1 (prepare)")`, add one test that runs `createTranscriptionTask` on a fresh source through a SQL-recording pool and checks what it issued.
   - The recording pool is a `Proxy` over the test pool whose `connect()` wraps each checked-out client's `query` once and records the SQL text, as `backend/packages/data/src/__tests__/mailSync.test.ts:3165-3188` does.
   - Assert that at least two statements equal `BEGIN ISOLATION LEVEL REPEATABLE READ`: step 1's read and write transactions.
   - Assert that no recorded statement matches `/SET\s+TRANSACTION/i`.
   - Assert that step 1's checkpoint (`computed.prepare`) is written, as the neighbouring tests check.
