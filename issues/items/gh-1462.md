**Blocked by:** #1376
**Model tier:** medium

## Context

Model tier rationale: One new query and request parameter on an existing report, with time-zone month boundaries and a changed range rule that need careful tests, but no new route or schema.

The AI usage report in `backend/packages/data/src/aiGateway/aiUsageReport.ts` (served by `GET /api/ai-usage`, `aiUsageRouteHandler.ts`) can only describe a range of at most `MAX_RANGE_DAYS` (366) days, with a daily cost series, so a view of the whole account history ("all time", cost per month) is impossible once the account is older than a year. #1376 adds `accountStartedAt` and `timezone` to the response; this issue uses them to return a month-by-month cost series. #1467 continues on the same file.

Decisions: (1) the default granularity stays `day` and its behavior is unchanged, so the existing web client keeps working. (2) With `granularity=month` the 366-day cap does not apply and the daily series is returned empty (`dailyCostUsd` and `dailyTokenUsage` are `[]`), because the monthly series replaces them and a multi-year range would otherwise build thousands of day points. (3) The month series starts at the later of the month of `accountStartedAt` and the month of `from`, so it stays bounded by the account's life.

## Task

Load `testing` and `io-hardening`.

1. In `aiUsageRouteHandler.ts` read the optional query parameter `granularity` (`day` default, or `month`); any other value is a `ValidationError` on field `granularity`. Pass it to `getAiUsageReport` as a new optional input field.
2. In `aiUsageReport.ts`, when `granularity` is `month`: skip the `MAX_RANGE_DAYS` check (keep the other `from`/`to` validation); return `monthlyCostUsd: [{month, costUsd}]`, one entry for every calendar month, `YYYY-MM` cut in the tenant's time zone, from the starting month described above through the month that contains the last instant before `to`, ascending, with `costUsd` 0 for months without calls (generate the months with `generate_series` and left join, like the existing daily query). Return `dailyCostUsd` and `dailyTokenUsage` as empty arrays. `rows`, `totalCostUsd` and `budgets` are computed over `[from, to)` as before.
3. When `granularity` is `day`, `monthlyCostUsd` is omitted from the response and nothing else changes.
4. Add the types to `AiUsageReport` (`monthlyCostUsd?: MonthlyCostPoint[]`) and tests: a continuous series across more than 366 days with a zero month in the middle; a call near a month boundary lands in the month of the tenant's time zone, not UTC; an invalid `granularity` returns a 400; the default request returns exactly the previous shape.

## Scope

### In scope

- The `granularity` parameter and the monthly cost series.

### Out of scope

- Unit classification, failed-call counts and the estimated flag: #1467.
- Breakdowns by model and operation: #1472, #1477.
- A monthly token series (only cost is returned per month).

## Acceptance criteria

- When `granularity=month` and the account is older than 366 days, then the request succeeds and `monthlyCostUsd` is a continuous list of months with zeros for empty months.
- When a call happens at 23:30 on the last day of a month in the tenant's time zone, then it is counted in that month even if it is already the next month in UTC.
- When `granularity` is omitted or `day`, then the response has no `monthlyCostUsd` and the daily series and the 366-day cap behave as before.
- When `granularity` is any other value, then the response is 400.
