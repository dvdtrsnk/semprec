## Context

Model tier rationale: Every call site, logger area and logged field is enumerated and the new lint rule catches any missed one.

Every backend process logs through `createLogger` (`backend/packages/shared/src/logger.ts:98-110`). It gives:
- newline-delimited JSON on stdout for journald;
- redaction of secret-shaped fields and error text (`:14-66`);
- the active trace context, including the `tenantId` #979 added (`:104-108`).

A `console.*` call gets none of that. 35 production call sites still use `console`.

- **Realtime: 21 calls.**
  - `backend/packages/realtime/src/syncServer.ts:144,157,166,174,211,290,358,365,376,416,430,435,460`;
  - `wireHooks.ts:27,38,43,48,53,58`;
  - `docSync.ts:81,138`.

  #1025 added `@semprec/shared` to this package and a `createLogger("realtime")` for its drop-and-log line. #1026, #1027 and #1042 last edited `syncServer.ts` and `docSync.ts`.
- **Data: 11 calls.**
  - `backend/packages/data/src/db/pool.ts:104,115`;
  - `mcp/mcpSync.ts:198,205`;
  - `blobs/fileUploadStore.ts:95,115`;
  - `trash/purgeExpiredTrash.ts:46,56`;
  - `scheduler/sweep.ts:293`;
  - `migrationJob/propertyTypeMigration.ts:243`;
  - `auth/passwordResetActions.ts:84`.

  Three of them also print a blob storage key: `fileUploadStore.ts:95,115` and `purgeExpiredTrash.ts:56`. A storage key embeds the sanitized original filename (`fileUploadStore.ts:64`, `mail/attachments.ts:87`), so it is user content.
- **Services: 3 calls.** The `shutdown()` rejection paths in `backend/services/semprec-api/src/shutdown.ts:151`, `semprec-agents/src/shutdown.ts:94` and `semprec-ai-gateway/src/shutdown.ts:143`.

These stay on `console`, because stdout and stderr are their interface:
- CLIs: `backend/packages/data/src/db/runSeedCli.ts:12`, `observability/restoreTestResultCli.ts:17`, and future `*Cli.ts` such as #1085's;
- the developer release tool: `backend/packages/release/src/cli.ts`, `githubReleaseHost.ts:127`;
- the client library `backend/packages/realtime-client`. It is not a server process; its consumer, today `backend/services/semprec-api/src/__tests__/reconnect.e2e.test.ts`, owns logging.

#1074 separately removes content fields from three logger calls.

## Task

Load `error-handling`: these are failure-path logs, and they must keep the original error visible without letting the log line replace it.

1. **Realtime.**
   - `backend/packages/realtime/src/logger.ts` exports `export const logger: Logger = createLogger("realtime")`. If #1025 created that logger inline in `syncServer.ts`, move it here.
   - Replace all 21 calls with `logger.error`/`logger.warn`, matching the original method and keeping each message string.
   - Pass an error as `{ err }` and add only identifiers already in local scope (`docId`, `agentRunId`, `sessionId`). Never pass a frame, payload or Yjs update.
2. **Data package.** Replace the 11 calls with `logger.error({ err, … }, "<same message without interpolated values>")`:
   - `db/pool.ts` uses the module's existing `logger` (`:3`).
   - The others use a module-level `const logger = createLogger("<area>")`, following `backend/packages/data/src/mcp/mcpToolExecution.ts:7`. Areas: `"mcp"` (mcpSync), `"blobs"` (fileUploadStore), `"trash"` (purgeExpiredTrash), `"scheduler"` (sweep), `"migration-job"` (propertyTypeMigration), `"auth"` (passwordResetActions).
   - Identifiers per site:
     - `mcpSync.ts:198`: `{ err: recordingErr, mcpServerItemId }`; `mcpSync.ts:205`: `{ err: closeErr, mcpServerItemId }` (the inner errors, not the outer `err` the caller already receives);
     - `fileUploadStore.ts:95`: `{ errCode, blobId: blob.id }`;
     - `fileUploadStore.ts:115`: `{ errCode }` (from `deleteErr`);
     - `purgeExpiredTrash.ts:46`: `{ err, itemId: candidate.id }`; `purgeExpiredTrash.ts:56`: `{ errCode, itemId: candidate.id }`;
     - `pool.ts:104`: `{ err }`; `pool.ts:115`: `{ err: rollbackErr }`;
     - `sweep.ts:293`: `{ err: closeOutErr, heartbeatId, occurrenceId }`;
     - `propertyTypeMigration.ts:243`: `{ err: settleErr, propertyId: payload.propertyId }`;
     - `passwordResetActions.ts:84`: `{ err }`.
   - At the three blob-delete sites (`fileUploadStore.ts:95,115`, `purgeExpiredTrash.ts:56`) log only the error code, narrowed without a cast (`errCode: err instanceof Error && "code" in err ? String(err.code) : undefined`), never the error object: a Node fs error's `message` and `path` carry the full path including the storage key (`backend/packages/data/src/mail/blobStorage.ts:123-124`), and the shared `err` serializer (`backend/packages/shared/src/logger.ts:58-65`) would write them out.
   - No call logs a storage key, a filename, an email address or a link.
   - Behaviour is otherwise unchanged: the swallow-and-continue and rethrow structure at each site stays.
3. **Services.** In each `registerShutdownSignals`, import the service's own `./logger.js` and replace the `console.error` with `logger.fatal({ err, signal }, "shutdown() rejected unexpectedly")`, then `process.exit(1)` as today. This is the same shape as `installFatalHandlers` (`backend/packages/shared/src/logger.ts:119-128`).
4. **Guard.** In `backend/eslint.config.mjs`, add a block with:
   - `files: ["packages/*/src/**/*.ts", "services/*/src/**/*.ts"]`;
   - `ignores: ["**/__tests__/**", "**/*.test.ts", "**/testSupport/**", "**/*Cli.ts", "packages/release/**", "packages/realtime-client/**"]`;
   - `rules: { "no-console": "error" }`;
   - a comment giving the reason (no redaction, trace or tenant bindings) and the reason for each exemption.
5. **Tests.** Switch every existing `vi.spyOn(console, "error")` that asserts one of the converted lines to a spy on that module's logger:
   - `backend/packages/data/src/__tests__/pool.unit.test.ts:114,138,240`;
   - `mcpSync.test.ts:276-293`;
   - `fileUploadStore.test.ts:132-155`;
   - `trash/__tests__/purgeExpiredTrash.test.ts:480`;
   - `passwordResetActions.test.ts:162`.

   The `fileUploadStore` and `purgeExpiredTrash` assertions also check that no logged argument contains the storage key or the fixture's error message.

## Scope

### In scope
- Moving the 35 production `console.*` calls onto the shared logger with identifier-only fields, the lint guard and its exemptions, and the spy updates.

### Out of scope
- The three content fields in existing logger calls (#1074).
- `tenantId` in log bindings (#979).
- The CLIs, the release tool and `backend/packages/realtime-client`, which are exempt.
- The web client's logging.
- Changing log levels or messages beyond dropping interpolated values.

## Acceptance criteria

- `pnpm run lint` passes, and fails when a `console.*` call is added to any non-exempt file under `backend/packages/*/src` or `backend/services/*/src`. A `console.log` in a `*Cli.ts` file, a test, or `backend/packages/realtime-client` is still accepted (lint, run by `pnpm run verify`).
- When the duplicate-bytes delete after an upload fails, the error is logged through the `blobs` logger with the blob id, and no logged argument contains the storage key or the fixture's error message. The upload still succeeds (integration, `fileUploadStore.test.ts`).
- When deleting a purged item's bytes fails, the error is logged with the item id and without the storage key or the fixture's error message, and the purge continues (integration, `purgeExpiredTrash.test.ts`).
- When an after-commit callback throws or `ROLLBACK` fails, `pool.ts` logs through its `db` logger, and the behaviour asserted today (other callbacks still run; the connection is discarded) is unchanged (unit, `pool.unit.test.ts`).
- The secondary-failure paths of `syncMcpServerTools` and the reset-mail send log through their area loggers and still never replace the original error or response (integration, `mcpSync.test.ts`, `passwordResetActions.test.ts`).
- The realtime suites (`syncServer.test.ts`, `realtime.test.ts`, `docSync.test.ts`) and the services' `shutdown` tests pass unchanged (integration and unit).
