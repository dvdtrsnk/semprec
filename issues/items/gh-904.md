## Context

Review follow-ups from harvest issue #889. Two assertions can never fail, so they document an intent they do not check:
- PR #748 (findings d02a0c6fd4, 4b719ca56f, dbf166d06f, one defect reported three times), `backend/services/semprec-agents/src/__tests__/startupRepairComposition.test.ts:37-43`: `order` is pushed to in two consecutive statements after two sequential `await`s, so `expect(order).toEqual(["repaired", "runtimeStarted"])` always passes whatever the implementation does.
- PR #759 (finding 0f8ee9b3d2), `backend/services/semprec-ai-gateway/src/__tests__/drainTimeout.unit.test.ts:7`: `expect(SHUTDOWN_DRAIN_TIMEOUT_MS).toBeGreaterThanOrEqual(AUDIO_ROUTE_TIMEOUT_MS)` is implied by the preceding `toBe(Math.max(COMPLETE_ROUTE_TIMEOUT_MS, AUDIO_ROUTE_TIMEOUT_MS))`.

## Task

1. In `startupRepairComposition.test.ts`, delete the `order` array, its two `push` calls and the `expect(order)` assertion, and drop the comment line above them that claims an ordering the test does not check; keep the awaited calls and every remaining assertion. Rename the `describe` from "semprec-agents startup repair ordering (issue #642)" to "semprec-agents startup repair (issue #642)" and the `it` from "repairs orphaned runs, skips mcp-credential runs, and only then starts the queue runtime" to "repairs orphaned runs, skips mcp-credential runs, and creates the queue runtime", so neither name promises an ordering check the test does not make.
2. In `drainTimeout.unit.test.ts`, delete the `toBeGreaterThanOrEqual(AUDIO_ROUTE_TIMEOUT_MS)` assertion.

## Touches

- backend/services/semprec-agents/src/__tests__/startupRepairComposition.test.ts (the `order` tracking and the `describe`/`it` names only)
- backend/services/semprec-ai-gateway/src/__tests__/drainTimeout.unit.test.ts (the one assertion named above)

## Scope

### In scope

The two deletions and the two test-name changes.

### Out of scope

Adding a new ordering test for `serve.ts`, and any other assertion in either file.

## Acceptance criteria

- `startupRepairComposition.test.ts` contains no `order` array and no assertion on it, neither its `describe` nor its `it` name mentions ordering or "only then", and it still asserts the repaired run ids, the run rows and the orphan and MCP run events.
- `drainTimeout.unit.test.ts` keeps only the `toBe(Math.max(...))` assertion.
- Both files' tests pass and `pnpm run verify` in `backend/` passes.
