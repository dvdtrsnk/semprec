## Context

`web/src` carries two parallel client stacks, and only one is mounted. `web/src/main.tsx` renders `App`, which composes `ViewHost` + `createDefaultViewRegistry()` (`web/src/views/registerViews.ts`) over `GenericOperations` (`web/src/api/genericOperations.ts` + `httpGenericOperations.ts`) and the typed catalogs in `web/src/i18n/messages.ts` via `I18nProvider`/`useTranslate` (`web/src/i18n/index.tsx`). Nothing in `main.tsx` or `App.tsx` imports:

- `web/src/view-types/GenericViewRoute.tsx`, `view-types/registerViews.tsx`, `view-types/registry.ts` (`ViewTypeRegistry`) and `view-types/library-grid/**` (`LibraryGridViewContainer`, `LibraryGridView`, `fallbackColor.ts`, `types.ts`, `libraryGrid.css`);
- `web/src/authenticatedWebContext.tsx` (`AuthenticatedWebProvider`, `useAuthenticatedWebContext` — line 18 throws "AuthenticatedWebProvider is required" outside the provider, so `LibraryGridViewContainer.tsx` line 44 can only render in its own test);
- `web/src/api/authenticatedApiClient.ts` (a second copy of the `View`/`Item` zod schemas, lines 3-33, duplicating `genericOperations.ts` lines 11-39, and a second `ViewRendererProps` shape `{ viewId, databaseId }` vs the live `{ view, operations }`);
- `web/src/i18n/cs.json`, `web/src/i18n/en.json` and `web/src/i18n/useLocalizedString.ts` (an untyped second i18n pipeline whose line 11 falls back to the raw key).

`grep -rln "view-types\|authenticatedWebContext\|authenticatedApiClient\|useLocalizedString\|cs.json\|en.json" web/src` lists only those files and their tests. Meanwhile the live registry `web/src/views/viewRegistry.ts` (`registerViewRenderer`, lines 23-25) is a bare `Map.set` with no duplicate guard, although `docs/adr/2026-09-14-view-type-renderers-register-once-in-web-client.md` decides that "Registration rejects a duplicate type". Both 2026-09-14 web ADRs (`2026-09-14-authenticated-api-boundary-in-web-client.md`, `2026-09-14-view-type-renderers-register-once-in-web-client.md`) describe the unmounted stack (`AuthenticatedApiClient`, `AuthenticatedWebContext`, `ViewTypeRegistry`, `{ viewId, databaseId }` props); they are `status: accepted` and their bodies must not be edited (`docs/adr/README.md`, "Superseding a decision"; root `review-rules/rules.md`).

Sibling issue G3 of this batch adds a login adapter following the live per-adapter pattern and notes that this issue retires the boundary ADR. Sibling G8a (locale from the session user) depends on this deletion so that the app has one locale source.

## Task

- **Delete** (with `git rm`, no replacement): `web/src/view-types/` (whole directory, including `__tests__/GenericViewRoute.test.tsx`, `library-grid/__tests__/*`), `web/src/authenticatedWebContext.tsx`, `web/src/api/authenticatedApiClient.ts`, `web/src/api/__tests__/authenticatedApiClient.test.ts`, `web/src/i18n/cs.json`, `web/src/i18n/en.json`, `web/src/i18n/useLocalizedString.ts`, `web/src/i18n/__tests__/useLocalizedString.test.tsx`. After the deletion `pnpm run verify` in `web/` must pass with no other source change than the ones below (`tsconfig.json`'s `resolveJsonModule` may stay).
- **Duplicate guard** in `web/src/views/viewRegistry.ts`: `registerViewRenderer(registry, clientComponent, renderer)` throws `Error(\`A view renderer is already registered for '${clientComponent}'\`)` when the key is present. `createDefaultViewRegistry` in `web/src/views/registerViews.ts` registers each renderer under two distinct keys (component id and view type), so it is unaffected; a repeated `createDefaultViewRegistry()` call builds a fresh `Map`, so it is unaffected too. Extend the file-level docblock to state the guard.
- **Test**: add to `web/src/views/__tests__/ViewHost.test.tsx` (its existing `view resolution` describe block already builds registries) a case that registering the same key twice throws with the message above, and one that registering a component id and a view type for the same renderer does not throw.
- **ADRs** (follow `.bb/skills/adr-conventions/SKILL.md`; the date in the filename and frontmatter is the day the files are created):
  - New `docs/adr/YYYY-MM-DD-web-client-calls-the-api-through-operations-adapters.md`, `area: [web]`, `status: accepted`, `supersedes: [2026-09-14-authenticated-api-boundary-in-web-client]`. Context: the `AuthenticatedApiClient`/`AuthenticatedWebContext` boundary was never mounted and duplicated the live schemas. Decision: the web client talks to the backend through operations adapters under `web/src/api/` — the generic `GenericOperations` port (`genericOperations.ts`) with its HTTP binding (`httpGenericOperations.ts`) for every item/view read and write, plus one `create*Operations({ baseUrl, fetchImpl })` factory per bespoke route family (`aiUsageOperations.ts`, `systemHealthOperations.ts`, `mcpAgentPageOperations.ts`, `approvalQueueOperations.ts`, `agentRunOperations.ts`, `setupOperations.ts`, and sibling G3's `authOperations.ts`); each adapter zod-parses at the edge, sends `credentials: "same-origin"`, and maps statuses onto `OperationError`'s `unavailable`/`retryable`; renderers receive operations as props (`ViewRendererProps { view, operations }`), never call `fetch`. Consequences: one place per route family for shape changes; a new screen adds an adapter or extends `GenericOperations`, not an inline fetch.
  - New `docs/adr/YYYY-MM-DD-web-view-renderers-resolve-through-one-registry.md`, `area: [web]`, `status: accepted`, `supersedes: [2026-09-14-view-type-renderers-register-once-in-web-client]`. Decision: `web/src/views/viewRegistry.ts` is the one `ViewRegistry`; `createDefaultViewRegistry()` registers every renderer under the backend's opaque `clientComponent` id and under the kebab-case view type; registration of an already-registered key throws; `ViewHost` resolves by `clientComponent` first, then by `type`, and renders `EmptyState` for an unregistered view; renderers receive `{ view, operations }`.
  - Edit only the frontmatter of the two 2026-09-14 ADRs: `status: superseded`, `superseded-by: <new slug>`. Bodies untouched.
- `.github/ISSUE_FORMAT.md`, "Touches and conflict hotspots" → the i18n bullet (line 185): drop `web/src/i18n/cs.json`, `web/src/i18n/en.json`, keep `web/src/i18n/messages.ts`. (Not a protected path; `.relay/config.yml` protects `.relay/**`, `.github/workflows/**` and `.github/scripts/check-protected-paths.mjs` only.)
