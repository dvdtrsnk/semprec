## Context

Harvest issue #934 collected three review findings that flag code in tests which has no effect.

- PR #818, `backend/packages/data/src/__tests__/agentRunEventsRetention.test.ts:60`: `beforeEach` calls `createUser()` and discards the result; `createUser` (line 16) is typed `Promise<string>` and returns the new user's id, but no caller uses it. The call itself is needed for foreign keys.
- PR #820, `backend/packages/data/src/__tests__/queueSupersession.test.ts:85`: lines 85-86 re-query `probeRows()` and assert `toHaveLength(0)` straight after the `vi.waitFor` block (lines 77-83) that polled until exactly that condition held, so the assertion cannot fail.
- PR #820, `backend/packages/data/src/__tests__/queueSupersession.test.ts:20`: `max_attempts` is selected (line 28) and typed in `probeRows()` (lines 20 and 24) but no assertion reads it.

## Task

1. In `agentRunEventsRetention.test.ts`, make `createUser` return `Promise<void>`: keep the `INSERT INTO users` statement, drop `RETURNING id` and the returned id.
2. In `queueSupersession.test.ts`, delete the `probeRows()` re-query and the `expect(rows).toHaveLength(0)` that follow the `vi.waitFor` block of the first test.
3. In `queueSupersession.test.ts`, remove `max_attempts` from the `SELECT` list and from the return type of `probeRows()`.

## Touches

## Scope

### Out of scope
