## Context

Model tier rationale: Adds several APNs request headers and payload fields with hard size limits to a shared adapter and passes the source through the fan-out job, with no new storage but protocol details that need exact tests.

A repeated push about the same thing should replace the earlier one on the phone, and pushes should group per source. The APNs request today (`backend/packages/data/src/push/apnsAdapter.ts`, `sendApnsNotification`) carries only `authorization`, `apns-topic` and `content-type`, with no `apns-push-type`, `apns-collapse-id`, `apns-priority` or `apns-expiration`, and the payload has no `thread-id`. Collapsing by the notification's own id would merge nothing, because every notification has a new id; the source is what identifies the thing.

Decisions: the collapse key and `aps["thread-id"]` are the notification's source id for sources that have a durable identity: a Semp problem (`semp_problems` id), an approval request (its id) and an invitation (its id); other kinds send neither. The key is limited to 64 bytes (`apns-collapse-id`); a longer key is replaced by the first 64 hex characters of its SHA-256. `apns-push-type: alert`, `apns-priority: 10` and `apns-expiration` = send time plus 24 hours (a stale alert has no value). Visible push for the problem repeat described in #1466 then replaces the earlier one. The silent dismiss (#1826) is a different push type and is unchanged.

Approval pushes with an actionable category (#1831) and the badge (#1891) build on these fields.

## Task

Load `io-hardening` and `testing`.

1. Extend `NotificationPushPayload` (`push/pushSenders.ts`) with `sourceTable`, `sourceId` and `kind`, filled by `handleNotificationFanoutTask`.
2. In `sendApnsNotification`, add the headers `apns-push-type: alert`, `apns-priority: 10`, `apns-expiration` and, when the source has an identity (rule above), `apns-collapse-id`, and add `aps["thread-id"]` with the same key.
3. Add a small pure function `apnsCollapseKey(payload)` with the 64-byte rule and unit tests for UUID, long and absent sources.
4. Add tests with an HTTP/2 fake in `apnsAdapter.unit.test.ts` asserting the headers and payload fields for an approval, a problem and a kind without identity.

## Scope

### In scope

- `apns-push-type`, `apns-priority`, `apns-collapse-id`, `apns-expiration` and `thread-id` on visible APNs pushes.

### Out of scope

- The actionable approval category and time-sensitive level of approvals: #1831; interruption levels: #1443.
- The badge: #1891; silent pushes: #1826.

## Acceptance criteria

- When a push is sent for an approval request, then `apns-collapse-id` and `thread-id` equal the request id.
- When a collapse key is longer than 64 bytes, then it is shortened deterministically.
- When a push has no durable source identity, then no collapse id or thread id is sent.
- Every visible push carries `apns-push-type: alert`, an expiration 24 hours ahead and priority 10.
