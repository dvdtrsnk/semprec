## Context

Model tier rationale: A pure date function with known fixture dates and one more timeline source in the existing extension point, with no persisted data, lifecycle or authorization.

The Calendars database has a system calendar (`kind` `system`) with system key `holidaysCz` (#1600); it is not an ICS subscription. The calendar timeline (#1717) is assembled from the sources listed in `backend/packages/data/src/calendar/timelineSources.ts`; #1800 added the birthday source and this issue adds the Czech public holidays. Nothing is downloaded: the holidays come from a function in code.

Public holidays of the Czech Republic: 1 Jan, Good Friday, Easter Monday, 1 May, 8 May, 5 Jul, 6 Jul, 28 Sep, 28 Oct, 17 Nov, 24 Dec, 25 Dec, 26 Dec. Easter Sunday is computed with the Gregorian algorithm (anonymous/Meeus-Jones-Butcher); Good Friday is two days before it and Easter Monday one day after.

Behavior: for a requested range the source returns one item per holiday date in the range with `kind` `holiday`, `id` `holiday:cz:<YYYY-MM-DD>`, `title` from the calendar module catalog, `date`, `allDay` true, `calendarId` (the `holidaysCz` calendar, null if absent) and `readOnly` true. Virtual entries are not items: their ids are not UUIDs, so the item routes reject them with 400.

Decision: the function supports the years 2016 to 2100 (Good Friday and 24 December became holidays in 2016); outside that range it returns no holidays.

Decision: holidays are a static function for this version, not an ICS subscription.

## Acceptance criteria

- When the timeline covers 28 Oct 2026, then a holiday entry for that day is returned with `allDay` true and `readOnly` true.
- When the timeline covers 3 Apr 2026 and 6 Apr 2026, then Good Friday and Easter Monday are returned.
- When a client patches or deletes a `holiday:...` id, then the response is 400 and nothing changes.
