**Blocked by:** #1487
**Model tier:** medium

## Context

Model tier rationale: One pure builder around an existing library with defined inputs and outputs, but attachment bytes streaming and header correctness must be verified against several real-world constraints.

Sending mail needs the complete message as MIME bytes, built once and handed unchanged to whichever transport the mailbox uses (SMTP, the Gmail API or Microsoft Graph, #1634, #1637, #1753) and to meeting invitations sent from a mailbox (#1774). Today `backend/packages/data/src/mail/send.ts` passes fields to the SMTP client, which has no attachments, and a private `generateOutgoingMessageId` in `send.ts` makes the Message-ID.

Attachment bytes come from the blob-reading helper that serves bytes from either storage root (#1487), because attachment blobs can live under the mail attachments root or the files root.

Decision: the body is `text/plain`. An optional calendar alternative with `method=REQUEST`, `CANCEL` or `REPLY` is accepted by the builder but not produced here.

## Task

Load `io-hardening` and `testing`.

1. Add `backend/packages/data/src/mail/outgoingMime.ts` exporting `buildOutgoingMime(input)` using nodemailer's `MailComposer`. Input: from, to, cc, bcc, subject, plain text body, `messageId`, `inReplyTo`, `references`, attachments as `{ filename, contentType, blobId }` and an optional `calendar: { method: "REQUEST" | "CANCEL" | "REPLY", content: string }`. Output: the raw bytes, the Message-ID and the envelope recipients (to, cc and bcc combined). Bcc recipients are in the envelope only, never in headers.
2. Move `generateOutgoingMessageId` out of `send.ts` into this module (exported), keeping `send.ts` behavior identical by importing it.
3. Read attachment bytes through the helper from #1487; a missing blob fails the build with a typed error. The calendar part is added as an alternative with `Content-Type: text/calendar; method=<METHOD>; charset=utf-8`.
4. Reject header values containing line breaks (subject, names, addresses) so a recipient or subject cannot inject headers.

## Scope

### In scope

- The MIME builder, the Message-ID generator move and header-injection checks.

### Out of scope

- Transports (#1634, #1637, #1753) and the send route (#1896).
- Producing calendar content (#1774).
- HTML bodies.

## Acceptance criteria

- When a message with In-Reply-To, References and two attachments is built, then parsing the output yields those headers, a `text/plain` body and both attachments with identical bytes.
- When a calendar part with method `REQUEST` is passed, then the output contains a part with `Content-Type: text/calendar; method=REQUEST`.
- When a bcc recipient is given, then it appears in the returned envelope but in no header.
- When a subject or display name contains a line break, then the builder throws.
- The Message-ID in the output equals the one passed in.
