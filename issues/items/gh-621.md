## Context

`backend/services/semprec-ai-gateway/src/structuredProviders/anthropicProvider.ts` accepts almost any 200 body as a valid Messages response:

- `isAnthropicMessagesResponse` (lines 29-31) only checks that `content` is an array. `body.content.find((block) => block.type === "tool_use")` (line 112) then dereferences every element, so a `null` or non-object element throws a `TypeError`. That is not a `ProviderCallError`, so `completeHandler.ts` rethrows it out of its provider `catch` (line 256) and the outer handler answers **500 "Internal server error"** for what is a malformed provider response.
- `usage` is optional in the interface (line 26) and read as `body.usage?.input_tokens ?? 0` / `?? 0` (lines 119-120). A response with no `usage`, or with non-numeric fields, is recorded in `ai_gateway_calls` as a call that cost **0 USD** — silently under-counting spend against the budget.
- On a non-2xx status the adapter throws at line 96 without ever reading or cancelling `res.body`. undici cannot return the connection to its pool until the body is consumed or the `Response` is garbage-collected, so every provider error holds a connection open for an unbounded time.

Sibling issues E3 (abort signal) and E6 (retries) edit the same file later; this one goes first.

## Task

- Add `"zod": "^4.1.11"` to `backend/services/semprec-ai-gateway/package.json` `dependencies` (the version every other workspace package uses) and refresh `backend/pnpm-lock.yaml`.
- In `anthropicProvider.ts` replace the `AnthropicContentBlock` / `AnthropicMessagesResponse` interfaces and `isAnthropicMessagesResponse` with a zod schema, module-level, e.g.:
  - `anthropicContentBlockSchema = z.looseObject({ type: z.string(), input: z.unknown().optional() })`
  - `anthropicMessagesResponseSchema = z.looseObject({ content: z.array(anthropicContentBlockSchema), usage: z.object({ input_tokens: z.number().int().nonnegative(), output_tokens: z.number().int().nonnegative() }) })` — `usage` and both token fields are **required**.
  - Parse with `safeParse`; on failure throw `new ProviderCallError("Anthropic response did not match the expected shape: <first issue path joined with '.'> <first issue message>")`. The message names the schema path only, never any response content (the file's existing contract: no provider body in errors). `completeHandler.ts` already logs the `ProviderCallError` at error level and answers 502 `provider_failed`; no handler change is needed.
  - After parsing, locate the `tool_use` block and require `input !== undefined`; a `tool_use` block with no `input` is a `ProviderCallError("Anthropic tool_use block carried no input")`.
  - Read `inputTokens`/`outputTokens` from the parsed `usage` with no `?? 0` fallback.
- On a non-2xx status (the `!res.ok` branch, line 95): before throwing, release the connection with `await res.body?.cancel()` wrapped so a failing cancel never replaces the `ProviderCallError` that follows (`.catch(() => {})` with a one-line comment saying why the cancel result is irrelevant). Use `cancel()` rather than `text()` so an error body is never buffered.
- Unit tests in `backend/services/semprec-ai-gateway/src/structuredProviders/__tests__/anthropicProvider.unit.test.ts` (`*.unit.test.ts`, no Postgres, `vi.stubGlobal("fetch", ...)` as the existing tests do), with inline JSON fixtures:
  - `content: [null, { type: "tool_use", input: {} }]` → rejects with `ProviderCallError` (not `TypeError`) whose message contains `content.0`.
  - well-formed `content` but no `usage` → rejects with `ProviderCallError` whose message contains `usage`.
  - `usage: { input_tokens: "12", output_tokens: 3 }` → rejects with `ProviderCallError`.
  - `tool_use` block without `input` → rejects with `ProviderCallError`.
  - a 529 response with a body: the adapter rejects with `ProviderCallError` and the fake `Response`'s body has been cancelled (build the `Response` over a `ReadableStream` whose `cancel` callback records that it ran, and assert it did).
  - the existing "well-formed response" test keeps passing unchanged.

## Acceptance criteria

- When Anthropic answers 200 with a `null` content block, `POST /internal/complete` answers 502 `provider_failed` (not 500) and the gateway log line for the failure names the offending schema path.
- When Anthropic answers 200 without `usage`, the route answers 502 `provider_failed` and no `ai_gateway_calls` row records that call as completed with zero tokens and zero cost.
- When Anthropic answers a non-2xx status, the adapter rejects with `ProviderCallError` and the response body stream has been cancelled before the rejection.
- A well-formed response still yields `{ content: <tool_use.input>, inputTokens, outputTokens }` exactly as before.
- `pnpm run test:unit` (in `backend/`) passes with the new tests.
