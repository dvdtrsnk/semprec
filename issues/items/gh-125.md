**Blocked by:** #231, #124

## Context

Reactive discovery permits a server to change an agent's tools after trust was granted. #231 provides the connection factory (transport handling, credential injection, cleanup, contract test servers); this issue adds the human-only discovery step on top of it, materializing `tools/list` into the `mcp_tool_registrations` table from #124. #126 projects the resulting registrations into ModuleRegistry and #128 invokes them.

## Task

Implement authenticated human-only `Synchronize tools`. Open the connection through the factory from #231 (do not re-implement transports or credential handling), call MCP `tools/list`, strictly validate the response, and transactionally materialize registrations. New names use default approval/risk values; existing human classification is preserved while advertised schema/description refreshes; missing names become inactive rather than deleting audit identity. Update server sync status and timestamp, recording a safe error on failure (the safe error shape from #231 for connection failures; an equivalent secret-free message for validation failures). Always close the connection through the factory, on success and on failure. Do not subscribe to or act on `notifications/tools/list_changed` (the #231 client registers no handler; sync must not add one), and expose no AgentTool/MCP operation that invokes sync.

## Scope

### In scope

- Explicit sync, reconciliation, defaults, status/error behavior, and structural AI exclusion.

### Out of scope

- The connection factory, transport implementations, and contract servers — delivered by #231.
- Reactive sync and automatic trust/classification.
- Tool invocation — #128.

## Acceptance criteria

- Only explicit authenticated action changes registrations.
- Sync failure leaves prior usable registrations authoritative and reports failure.
- New/removed/renamed tool cases reconcile deterministically.
- Sync tests run against the #231 contract servers for all three transports and prove the connection is closed after both successful and failed syncs.
