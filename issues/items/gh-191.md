## Task

Add rollback mode validating an existing prior release, atomically repointing current and restarting without build or schema unwind. Codify previous-release compatibility, expand-contract/two-release rename-removal, and fix-forward migrations; add mechanical examples/checks where possible.

## Scope

### In scope

- Task deliverables, migrations, integration, tests, and necessary documentation.

### Out of scope

- No down migrations or per-package rollback.

## Acceptance criteria

- Rollback uses existing release and no schema mutation.
- Invalid rollback leaves current unchanged.
- Accepted/rejected migration examples are concrete.
- Compatibility fixture runs previous code after additive migration.
