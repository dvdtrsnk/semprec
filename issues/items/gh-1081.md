## Context

Model tier rationale: The adapter methods, panel rows, validation rules and states are specified exactly in the existing admin patterns.

AI use is capped per tenant: a daily and a monthly cap that only an admin sets.

- A tenant **without a budget row is refused every AI call** (fail closed). That is the state of every newly created account.
- With a budget row, a `null` cap means "no cap for that period".
- A global safety cap from the environment also applies.

The caps live in the global table `tenant_ai_budgets` (#1004) and the gateway enforces them (#1035). #1039 added the admin routes that read and set them, together with per-tenant spend; every set is audit-logged. This issue adds the panel to the admin page that #1079 created (`?page=admin`, rendered only for `role === "admin"`).

#1079 delivered:
- `web/src/api/adminOperations.ts` — `createAdminOperations({ baseUrl, fetchImpl })` and `AdminOperations`. Responses are zod-parsed. `401/403/404/501` map to `unavailable`; everything else maps to `retryable`, with the adapter error body's `error.code` as the message when present.
- `web/src/views/admin/AdminPage.tsx`, which renders the admin panels in order (`AccountsPanel` first).
- The `admin.*` i18n namespace.

Money is formatted with `formatUsd(locale, amount)` (`web/src/i18n/format.ts:10-12`). Panels load through `useAsyncResource` (`web/src/views/mailbox/useAsyncResource.ts:13-43`) and render the shared states from `web/src/components/StateViews.tsx`.

**Backend contract** (#1039). If the merged handler (`backend/services/semprec-api/src/adminHandler.ts`) differs, bind to it and say so in your PR description.

- `GET /api/admin/ai-budgets` → `200 { spendWindow: "utc", accounts: AiBudgetAccount[] }`, ordered by account creation, where `AiBudgetAccount` is:
  ```
  { userId: string, email: string, hasBudget: boolean,
    dailyCapUsd: number|null, monthlyCapUsd: number|null,
    spentTodayUsd: number, spentMonthUsd: number }
  ```
  Spend is measured over the UTC day and the UTC month. An account with `hasBudget: false` has `null` caps.
- `PUT /api/admin/accounts/:userId/ai-budget` with `{ dailyCapUsd: number|null, monthlyCapUsd: number|null }`. Both fields are required; each is `null` or a finite number ≥ 0 within the column's precision.
  - Success: `200 { budget: { userId, dailyCapUsd, monthlyCapUsd, updatedAt } }`.
  - Invalid input: `400 { error: { code: "validation_failed", details } }`.
  - Unknown user: `404`.

## Task

Load `canonical-keys` (labels) and `error-handling` (save failures).

1. **Adapter** — extend `AdminOperations` in `web/src/api/adminOperations.ts` with:
   - `listAiBudgets(): Promise<AiBudgetAccount[]>`;
   - `setAiBudget(userId: string, caps: { dailyCapUsd: number | null; monthlyCapUsd: number | null }): Promise<void>` — a `PUT` whose JSON body always carries both fields, with `encodeURIComponent(userId)` in the path.

   Parse responses with zod and reuse the file's existing request and error mapping.
2. **Panel** — add `web/src/views/admin/BudgetsPanel.tsx`:
   - an `admin.budgets.title` heading and a note that spend is measured in UTC (`admin.budgets.utcNote`);
   - one row per account, showing email, daily cap, monthly cap, spent today and spent this month, all formatted with `formatUsd`;
   - a row with `hasBudget: false` shows `admin.budgets.noBudget` ("No budget — AI requests are refused") instead of its caps; a `null` cap on a row that has a budget shows `admin.budgets.uncapped`;
   - an **Edit caps** button that opens an inline form:
     - two number inputs (`min="0"`, `step="0.01"`), labelled `admin.budgets.dailyCap` and `admin.budgets.monthlyCap`, prefilled with the current caps (empty when `null`);
     - **Save** and **Cancel** buttons.
   - **Save** validates both inputs itself rather than relying on browser constraint validation. For each field:
     - empty → sent as `null`;
     - any other value that is not a finite number ≥ 0 after `Number(...)` → shows `admin.budgets.invalid` and sends no request.

     When both fields are valid, Save calls `setAiBudget`. On success the form closes and the list reloads. On failure the form keeps the typed values and shows `admin.budgets.saveFailed` with the message in a `role="alert"` element. Controls are disabled while saving.
3. **Mount** — render `<BudgetsPanel operations={…} />` in `web/src/views/admin/AdminPage.tsx` after the existing panels.
4. **i18n** — add the `admin.budgets.*` keys to `en` and `cs` in `web/src/i18n/messages.ts`.
5. **Test stubs** — add the two new methods to every existing `AdminOperations` test stub.

## Acceptance criteria

All criteria below are web unit tests.

- **Adapter** (`adminOperations.test.ts`):
  - `listAiBudgets` issues `GET /api/admin/ai-budgets` and parses the accounts.
  - `setAiBudget("u 1", { dailyCapUsd: 2, monthlyCapUsd: null })` issues `PUT /api/admin/accounts/u%201/ai-budget` with body `{"dailyCapUsd":2,"monthlyCapUsd":null}` and same-origin credentials.
  - A 400 rejects as `retryable` with message `validation_failed`; a 403 rejects as `unavailable`; a malformed list body rejects as `retryable`.
- **Panel rendering** (`web/src/views/admin/__tests__/BudgetsPanel.test.tsx`):
  - Every account is listed with its email, both caps and both spend values formatted as USD.
  - A `hasBudget: false` row shows `admin.budgets.noBudget`.
  - A `null` cap on a row that has a budget shows `admin.budgets.uncapped`.
- **Editing** (`BudgetsPanel.test.tsx`):
  - Entering `5` in the daily field, leaving the monthly field empty and saving calls `setAiBudget(userId, { dailyCapUsd: 5, monthlyCapUsd: null })`, closes the form and reloads the list.
  - Saving `-1` shows `admin.budgets.invalid` and makes no call.
  - A rejected save keeps the form and the typed values and shows the message in an alert.
- **Loading** (`BudgetsPanel.test.tsx`): a failed initial load shows the error state, and its retry reloads the list.
- The admin page renders the budgets panel.
- Every new key exists in `en` and `cs`, and `pnpm run verify` passes in `web/`.
