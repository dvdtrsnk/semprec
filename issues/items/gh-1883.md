## Context

Model tier rationale: A scheduled agent-run heartbeat created for new and existing tenants following the existing heartbeat seeding and cutover patterns, verified by seed tests; the behavior it triggers is built in blockers.

The assistant has no scheduled job to keep the journal tidy. Heartbeats belong to a project (`project_heartbeats.project_item_id NOT NULL`); there is no project called Journal, because Journal is a system database. The scheduler supports weekly rules (`scheduler/rule.ts`), the `core.agentRun` action runs a project's agent with a task (`scheduler/actions.ts`), and seeding of system heartbeats uses `createHeartbeat` in `seed/seedSystem.ts` (for example the transcription requeue sweep), with a cutover for populated tenants (`db/tenantCutoverMigrations.ts`). The heartbeat run is written into its tick thread by #1557 and its approval requests carry their source by #1766.

This issue schedules the "Weekly journal cleanup" heartbeat, every Sunday 21:00 in the tenant's time zone. The run (a) finds periods with duplicate entries and lets the assistant propose merging them (the merge is #1726; it changes links, so it never runs silently and waits for the user's approval), (b) writes the missing week summary (via the Journal period lookup of #1861) and (c) adds missing links to calendar events as item links in the day's text (#1614), from which the Journal `events` relation (#1609) is derived. Anything destructive, such as merging duplicates, is requested through the normal approval flow and shows in the Inbox as a request from the assistant.

Decisions:
- The heartbeat belongs to the system project "Semprec" (the assistant's home project), because no Journal project exists.
- The heartbeat uses a new action `core.journalWeeklyCleanup` that first finds every period (type and key) with more than one live Journal entry (deterministic, no model call, no write) and then runs the agent through the `core.agentRun` mechanism with the cleanup task text followed by the list of those periods. The agent proposes each merge through the approval-gated merge operation; nothing is merged before the user approves.

Shared-file ordering: this issue also waits for #1836 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `canonical-keys`, `db-migrations` and `testing`.

1. Register action `core.journalWeeklyCleanup` (handler in `journal/`, id in `manifest/knownActionIds.ts` and the action registry) that finds the duplicated periods and then delegates to the `core.agentRun` handler with the task text from `action_config.task`, with the duplicated periods appended to it; it never calls `mergeJournalDuplicates`.
2. Define the heartbeat constant (name "Weekly journal cleanup", rule weekly `sun` at `21:00`, task text in `journal/i18n/cs.json` and `en.json`) and create it in `seed/seedSystem.ts` for new tenants on the Semprec project, and in a per-tenant cutover registered in `db/tenantCutoverMigrations.ts` for existing ones; both idempotent by heartbeat name and action.
3. Tests: new and existing tenants each get exactly one such heartbeat; a second run adds none; firing it on a tenant with two live entries for one day leaves both entries live and starts one agent run on the Semprec project whose task names that day; a failure in the duplicate-finding step is recorded as a failed run and not silently skipped.

### Out of scope

- The merge function: #1726; the approval-gated merge operation: #2017; Journal period lookup and writes: #1861.
- Event relation and Markdown links: #1609 and #1614; deriving the relation from the links: the journal batch.
- Proposing deletion of a property on Journal: not planned; system collections have no user properties in v1, so there is no property to delete.
- The tick thread display: #1557.

## Acceptance criteria

- When a tenant is provisioned or upgraded, then exactly one "Weekly journal cleanup" heartbeat exists on the Semprec project, weekly on Sunday at 21:00.
- When the heartbeat fires on a tenant with two live entries for one day, then both entries stay live and an agent run on the Semprec project is created whose task names that day.
- When the cutover runs twice, then no second heartbeat is created.
