## Context

The completed library module registers a `library-grid` view type and stores `coverGlyph` plus `{ blobId }` cover values, but no client renderer exists, and no earlier issue selects a web framework at all. This issue is the first web implementation: it creates the minimal `web/` workspace plus only the shared foundations (authenticated API client, authenticated user context, i18n, design tokens, view-type registry, generic view route) that the library-grid renderer consumes. It builds on the authenticated REST contract (#158), the library module (#25), and the locale resolution rules of #147. #218 evolves the server-side property catalog route, and #88 implements the `library-grid` view component and container on top of the registry and client established here.

## Task

As the first web implementation, initialize `web/` as a React 19 + TypeScript + Vite workspace package with Vitest, Testing Library, and a minimal authenticated API client boundary; build no unrelated screens.

Provide the shared `AuthenticatedWebContext = { user: { locale: string }; api: AuthenticatedApiClient }`; the shared API client always sends the session cookie and exposes typed `getView`, `listProperties`, `queryView`, and `createItem` methods. The methods map to exactly these authenticated routes: `getView` → `GET /api/views/:viewId`; `listProperties` → `GET /api/databases/:databaseId/properties` (typed against the current response of that route; #218 adds resolved `label`/`options` and the type is updated there); `queryView` → `POST /api/views/:viewId/query` with `{ cursor: string | null, limit: number }`; `createItem` → `POST /api/databases/:databaseId/items` with `{ properties }`. The client surfaces query failures as the stable domain `{ code }` returned by the API so callers can drive an `error` state from it; unauthenticated responses remain #34's 401.

Add the i18n foundation: `web/src/i18n/en.json` and `web/src/i18n/cs.json` plus a hook that resolves a key for the locale selected from the authenticated user context per #35 (requested locale → English fallback → raw key). Ship the key `common.loading` in both files; the library-specific keys are added by #88.

Define `web/src/styles/tokens.css` variables `--library-fallback-1..6` as `#274C77`, `#3A5A40`, `#6D597A`, `#9C6644`, `#386641`, `#7F5539`.

Add `web/src/view-types/registry.ts`, a registry mapping a registered view type (kebab-case, as stored on the view row) to exactly one renderer component receiving `{ viewId, databaseId }`, and the generic view route that resolves `{ viewId, databaseId }` from the URL and dispatches through that registry. No library screen is built here: a minimal placeholder renderer registered for `library-grid` is acceptable and is replaced by #88, which registers `LibraryGridViewContainer` as the sole renderer for that type.

## Scope

### In scope

- `web/` workspace bootstrap (React 19, TypeScript, Vite, Vitest, Testing Library) and build/test wiring.
- Authenticated API client boundary, `AuthenticatedWebContext`, i18n files/hook, `tokens.css`, view-type registry, generic view route, and tests.

### Out of scope

- The `library-grid` view component, container, cover/fallback rendering, Add action, and library i18n keys, delivered by #88.
- Resolved `label`/`options` on the properties route, delivered by #218.
- External metadata providers, cover upload/edit UI, recommendations, a special library API, or any unrelated screens.

## Acceptance criteria

- `web/` builds and its Vitest suite runs green inside the workspace; no screen other than the generic view route with placeholder rendering exists.
- The API client sends the session cookie on every request and exposes typed `getView`, `listProperties`, `queryView`, and `createItem` bound to the routes above; a test proves a failing query yields the stable domain error code.
- `AuthenticatedWebContext` provides `user.locale` and `api`; the i18n hook returns the Czech or English string for a present key and falls back requested locale → English → raw key.
- `tokens.css` defines `--library-fallback-1..6` with exactly the six listed values.
- The generic view route resolves `{ viewId, databaseId }` and dispatches through `registry.ts`; a test proves the registered renderer for a type is mounted with those props.
