**Blocked by:** #98

## Context

New-mail attention must be provider-neutral and must not flood agents with spam or trash events.

## Task

Register the `newEmail` event rule as: creation of an Emails item with a relation to a Folder whose `specialPurpose = 'inbox'`. Exclude folders whose special purpose is `junk` or `trash`, including messages with multiple folder memberships. Dispatch through the existing heartbeat event mechanism using action `core.agentRun` and its `actionConfig`; do not create a separate mail scheduler. Ensure replay/reconciliation of an already-known message does not emit a second logical event.

## Scope

### In scope

- Inbox membership evaluation, exclusions, event deduplication, and core agent-run dispatch.

### Out of scope

- Parcel tracking itself and new heartbeat infrastructure.

## Acceptance criteria

- New Inbox mail emits one event with the Email item context.
- Junk/Trash-only mail emits none.
- Provider reconciliation does not duplicate the event.
- The rule can later be consumed by a project heartbeat without mail-specific scheduler code.
