## Context

Model tier rationale: A documentation-only decision, but it fixes what two later backend issues build, and it weighs quality, cost and offline behavior across the backend and the Apple client.

Two places in Semp chat need speech outside the live voice mode: reading one stored answer aloud, and dictating text into the message field without starting an agent turn. Both can run on the device (the iOS speech synthesizer and Czech speech recognition, with no backend work) or through the AI gateway, which would reuse the streaming speech adapters of #1396 and #1399 and count against the tenant's AI budget (`ai_gateway_calls.audio_seconds`). Today the backend has neither.

This issue records which one is used. #1626 (reading a stored message) is the gateway variant of read-aloud.

Decision to record (decided by the product owner):
- Dictation runs on the device, with the device's speech recognition (Apple Speech) in Czech, and has no backend involvement: it is cheap and the audio never leaves the device. No dictation endpoint is built.
- Read-aloud runs through the gateway at the same provisional OpenAI TTS engineering default as live voice; the comparative Czech listening qualification is NOT RUN and remains a pre-production-release condition tracked by #1399. Provider calls go only through the gateway because of budget limits and audit. #1626 builds it.
- Czech is the primary language for both.
