## Context

Model tier rationale: One recursive copy over existing creation, document-write and path seams in a single transaction with a size cap, verified with real documents, but identity remapping across a whole subtree needs care.

A user can duplicate a page: the copy is a sibling next to the original, titled with a "copy" suffix, and it contains a copy of every nested subpage. The design copied only one level and shared the nested pages between original and copy; the server must copy the whole tree so editing the copy never changes the original. #1676 created the `pages` database, the `page` block (whose `pageId` is the Pages item id and whose text is the title), `page.createSubpage` and the parent link `parentItemId`. The shared block model (#1539) reads a document with `readPageBlocks` and writes blocks with `writeBlock` and the operations of #1610, which refuse to duplicate `page` blocks (`page_conversion_required`) because copying a page needs database work; this issue is that database work. Page operations are generic catalog members (#1394).

Decisions:
- `page.duplicate` accepts a Pages item only; a host item (a project, an area, an event) is a `ValidationError` on `pageItemId`.
- Only the root of the copy gets the suffix, localized with the caller's locale through the docs i18n catalog (" (kopie)" for Czech, " (copy)" for English); nested copies keep their titles.
- The copy is placed in the parent document right after the original's `page` block; if the original is an orphan (no block references it), the copy goes to the end of the parent document.
- A `page` block whose page is trashed, purged or missing is not copied (the block is left out of the copy), and a page that appears twice in one tree is copied once per reference as an independent page; cycles are cut by a visited set.
- The copy is capped at 500 pages in total (`MAX_DUPLICATE_PAGES`); a larger tree is a `ValidationError` and nothing is written.
- Copies keep the block order, types, indent, `done` and inline formatting; every block id, page item id and document id is new.

Shared-file ordering: this issue also waits for #1720 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `io-hardening` and `testing`.

1. Add `page.duplicate` to the generic catalog (strict input `{ pageItemId }`, output `{ pageItemId, docId, blockId }` of the root copy, port method, binding, metadata as a non-destructive write on the item-write capability), the application service method, and the route and method recorded for it by the ADR of #1394, with `routeMatrix.ts` and tenant-isolation entries.
2. Add `duplicatePage` in `backend/packages/data/src/docs/pageOperations.ts`, in one transaction: lock and read the original (live Pages item, else 404); collect the subtree breadth first from `page` blocks of each document, applying the rules above and the cap; create the new Pages items (new ids, `title`, `parentItemId` mapped to the new parent, the root copy under the original's parent) through `createItemWithClient` with the allowed system keys; for each page create its document and write its blocks with fresh ids and remapped `pageId`, preserving text attributes; finally insert the root copy's `page` block into the parent document with `mutateDocWithClient` and the caller's origin.
3. Tests: duplicating a page that holds one nested page creates "Title (kopie)" plus a new nested copy, and the original and the nested original are byte-for-byte unchanged (documents, items, ids); editing the copy's nested page does not change the original's; formatting, todo state and indent survive; a trashed nested page is left out; a tree of 501 pages is rejected with nothing written; a host item is rejected; an orphan copy goes to the end of the parent; another tenant's page is a 404.

## Scope

### In scope

- `page.duplicate`: deep copy of a page and all its nested subpages, with the localized suffix, placement and cap.

### Out of scope

- Duplicating blocks within a page (the block model refuses page blocks there and clients call this operation instead): #1610.
- Creating and renaming subpages: #1676 and #1725.
- Impact previews: #1856.
- Agent approval classification: #1844.

## Acceptance criteria

- When "Release checklist" (holding one nested page) is duplicated, then "Release checklist (kopie)" exists next to it with its own copy of the nested page, and the original pages and documents are unchanged.
- When the copy's nested page is edited, then the original nested page does not change.
- When the tree has more than 500 pages, then the response is 400 and nothing is created.
- When a nested page is in the trash, then the copy contains no block for it.
- When a host item id is given, then the response is 400 with `field` `pageItemId`; for another tenant's page, 404.
