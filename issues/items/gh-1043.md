## Context

Model tier rationale: Tenant exports cross data, blobs, archive jobs, expiring authenticated downloads and cleanup.

A user can download a complete export of their own data. Nothing like it exists today. This issue adds the export request, the background job that builds the archive, the authenticated download and the removal of expired exports. The account page (#1083) is the web consumer.

Facts this builds on:

- **Tenant tables.** Every tenant-owned table carries `tenant_id` and the table comment `semprec:tenancy=tenant` (#971, #972). Row-level security limits every query to the current tenant scope.
- **Scope API.** `@semprec/shared` exports `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()`. `app_current_tenant()` returns the scope's tenant in SQL.
- **Blob storage.** Bytes live in two roots: `FILES_STORAGE_DIR` and `MAIL_ATTACHMENTS_DIR` (`resolveBlobStorageDir`, `backend/packages/data/src/mail/blobStorage.ts:62`), each behind a `LocalFsBlobStorageWriter` (`:78-131`; `writeStream`, `readStream`, `delete`).
  - A blob referenced by `mail_attachments.blob_id` lives under the mail root, written by `createCoreTaskList`'s `mailBlobStorage` (`backend/packages/data/src/worker.ts:107`). Every other blob lives under the files root (`backend/services/semprec-api/src/serve.ts:88`). The restore test resolves keys the same way (`deploy/systemd/scripts/semprec-restore-test.sh:175-187`).
  - Since #1008, new keys are prefixed `<tenantId>/` through `tenantBlobStorageKey(client, key)`.
- **Secrets.** Credential ciphertext lives in `external_credentials.ciphertext`/`nonce` (`backend/packages/data/src/db/migrations/0006_mail_sync.sql:99-106`), sealed under either the master key or the tenant data key in `tenant_keys` (#1032, #1060, #1062). Neither may leave the server.
- **Queue.**
  - Producers call `enqueueJob`, which stamps the envelope `{ traceId, tenantId, payload }` from the current scope. A task declared `tenancy: 'tenant'` runs inside `runInTenant(envelope.tenantId)` and completes as a no-op for a non-active tenant (#982).
  - Task names and affinities: `CORE_TASK_NAMES` / `CORE_TASK_AFFINITY` (`backend/packages/queue/src/index.ts:29-83`, `:95-119`).
  - Handlers and crontab: `createCoreTaskList` / `CORE_CRONTAB` (`worker.ts:81-92`, `:101-227`). The api runtime must register exactly its affinity set (`worker.ts:238-250`).
  - Per-tenant system sweeps use `forEachActiveTenant` (`backend/packages/data/src/tenancy/forEachActiveTenant.ts`).
  - Long tasks follow `docs/adr/2026-09-30-graceful-shutdown-for-long-running-graphile-worker-tasks.md`: check `helpers.abortSignal` between units of work, then re-enqueue by key and return normally.
- **Transactions.** `withTransaction(pool, fn, { isolation: "repeatable_read" })` (`backend/packages/data/src/db/pool.ts:75-92`) gives one consistent snapshot.
- **Streaming downloads.** `GET /api/blobs/:id` (`backend/services/semprec-api/src/blobsHandler.ts`) is the pattern: authenticate, then resolve inside the caller's tenant scope (#981), map errors through `statusForError`/`toErrorResponseBody`, and stream with `pipeline`.
- **No archive library.** `backend/packages/data/package.json` has none, so this issue adds `yazl`, a streaming ZIP writer that accepts entries of unknown length.

## Task

Load `db-migrations`, `state-writes` (enqueue in the request's transaction, bytes deleted after commit), `io-hardening` (new routes, streamed download, release on abort), `error-handling` and `adr-conventions`.

1. **Migration** (take the next free migration ordinal at commit time; additive):
   ```sql
   CREATE TABLE tenant_exports (
     id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
     tenant_id uuid NOT NULL DEFAULT app_tenant_default() REFERENCES tenants(id),
     requested_by uuid NOT NULL REFERENCES users(id),
     status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'running', 'ready', 'failed')),
     storage_key text,
     byte_size bigint,
     created_at timestamptz NOT NULL DEFAULT now(),
     completed_at timestamptz,
     expires_at timestamptz
   );
   CREATE UNIQUE INDEX tenant_exports_active_uq ON tenant_exports (tenant_id) WHERE status IN ('pending', 'running');
   CREATE INDEX tenant_exports_tenant_created_idx ON tenant_exports (tenant_id, created_at DESC);
   COMMENT ON TABLE tenant_exports IS 'semprec:tenancy=tenant';
   ALTER TABLE tenant_exports ENABLE ROW LEVEL SECURITY;
   CREATE POLICY tenant_isolation ON tenant_exports AS RESTRICTIVE FOR ALL
     USING (tenant_id = (SELECT app_tenant_default())) WITH CHECK (tenant_id = (SELECT app_tenant_default()));
   CREATE POLICY tenant_rows ON tenant_exports AS PERMISSIVE FOR ALL USING (true) WITH CHECK (true);
   GRANT SELECT, INSERT, UPDATE, DELETE ON tenant_exports TO semprec_side;
   ```
2. **Store** — new `backend/packages/data/src/tenancy/tenantExportsStore.ts`, typed rows, summary `{ id, status, createdAt, completedAt, expiresAt, byteSize }`:
   - `requestTenantExport(client: PoolClient, requestedBy)` returns `{ export, created }`.
     - It inserts with `ON CONFLICT (tenant_id) WHERE status IN ('pending','running') DO NOTHING`. On conflict it returns the existing active export with `created: false`.
     - On insert it calls `enqueueJob(client, CORE_TASK_NAMES.TENANT_EXPORT, { exportId }, { jobKey: \`tenantExport:${exportId}\`, maxAttempts: 1 })` in the same transaction.
   - `listTenantExports(client)` lists non-expired rows, newest first.
   - `getDownloadableTenantExport(client, id)` returns the row only when `status = 'ready' AND expires_at > now()`, otherwise `null`.
   - Status writers `markTenantExportRunning`, `markTenantExportReady(…, { storageKey, byteSize })` (`completed_at = now()`, `expires_at = now() + interval '7 days'`), `markTenantExportFailed` and `markTenantExportPending`. Each is a targeted update checked with `requireAffectedRows`.
   - `deleteExpiredTenantExports(client)` deletes rows past `expires_at`, and `failed` rows older than 7 days, `RETURNING storage_key`.
3. **Job** — new `backend/packages/data/src/tenancy/tenantExportJob.ts` with `handleTenantExportTask(pool, storages: { files: BlobStorageWriter; mailAttachments: BlobStorageWriter }, payload, helpers)`:
   1. Load the row. If it is missing or not `pending`, log and return. Otherwise mark it `running`.
   2. In one `repeatable_read` transaction, write the ZIP through `storages.files.writeStream(key, zip.outputStream)`, where `key = await tenantBlobStorageKey(client, \`exports/${exportId}.zip\`)` (#1008's prefix helper in `backend/packages/data/src/blobs/blobsStore.ts`). Entries are produced lazily and strictly in sequence on the transaction's client:
      - `account.json` holds `{ email, locale, role, createdAt }` of `users WHERE tenant_id = app_current_tenant()`, with no password hash.
      - `tables/<table>.jsonl` comes for every table found by `SELECT c.relname FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = 'public' AND c.relkind IN ('r','p') AND NOT c.relispartition AND obj_description(c.oid, 'pg_class') = 'semprec:tenancy=tenant' ORDER BY 1`, except `EXPORT_EXCLUDED_TABLES = ["external_credentials", "tenant_keys", "tenant_exports"]`. Each file has one line per `SELECT to_jsonb(t) FROM <quoted table> t WHERE t.tenant_id = app_current_tenant()`, read through a transaction-scoped cursor 500 rows at a time. The table name is quoted with `pg`'s `escapeIdentifier`.
      - `blobs/<blobId>` holds the bytes of each `blobs` row, read from the mail root when a `mail_attachments` row references it and from the files root otherwise. A missing file is recorded and does not fail the export.
      - `manifest.json`, written last, holds `{ formatVersion: 1, exportId, generatedAt, tables: [{ name, file, rowCount }], blobCount, missingBlobIds }`.
   3. On success, mark the row `ready` with the archive's byte size.
   4. On failure, delete the partial key (log a delete failure), mark the row `failed` and rethrow.
   5. Between entries, if `helpers.abortSignal?.aborted`: stop, delete the partial key, mark the row `pending`, re-enqueue with the same `jobKey` and return normally.
4. **Expiry sweep** — `handleTenantExportExpirySweepTask(pool, filesStorage)` runs `forEachActiveTenant`. For each tenant it runs `deleteExpiredTenantExports` in a transaction and then, after the commit, deletes each returned key. A storage failure is logged and skipped (`docs/adr/2026-09-28-blob-bytes-deleted-best-effort-after-the-commit.md`).
5. **Queue wiring:**
   - `CORE_TASK_NAMES.TENANT_EXPORT = "tenantExport"` (`TASK_TENANCY` `tenant`) and `TENANT_EXPORT_EXPIRY_SWEEP = "tenantExportExpirySweep"` (`TASK_TENANCY` `system`), both with `CORE_TASK_AFFINITY` `api`. Add the sweep to the system-name list asserted by #982's catalog case.
   - Both handlers go into `createCoreTaskList`, with a new trailing parameter `filesBlobStorage: BlobStorageWriter = new LocalFsBlobStorageWriter(resolveBlobStorageDir("FILES_STORAGE_DIR"))`.
   - Add the `CORE_CRONTAB` line `40 4 * * * tenantExportExpirySweep`, and add `tenantExportExpirySweep` to `EXPECTED_CRONTAB_IDENTIFIERS` in `backend/services/semprec-api/src/__tests__/queueRuntime.test.ts:12-24` (compared with `toEqual` at `:103`).
6. **Dependency** — add `yazl` to `backend/packages/data/package.json` dependencies and `@types/yazl` to its devDependencies, and update `backend/pnpm-lock.yaml`.
7. **API** — new `backend/services/semprec-api/src/accountHandler.ts`:
   - `createAccountRoutes(pool, options: AppOptions): RouteDefinition[]`, adapter routes in the caller's tenant scope. It receives the dispatcher's own options object; later account routes read from it.
     - `POST /api/account/exports` answers `202 { "export": … }` when one was created and `200 { "export": … }` when an active one already exists.
     - `GET /api/account/exports` answers `200 { "exports": [...] }`.
   - `createAccountExportDownloadListener(pool, { storage })` serves `GET /api/account/exports/:id/download`:
     - `assertUuid` on the id, then `authenticateRequest`, then everything else inside `runInTenant(identity.tenantId, …)`;
     - a missing, foreign, not-ready or expired export is the same `404 { "error": { "code": "not_found" } }`;
     - success streams with `pipeline` and the headers `Content-Type: application/zip`, `Content-Length`, `Content-Disposition: attachment; filename="semprec-export-<YYYY-MM-DD>.zip"` and `Cache-Control: no-store`.
   - Mount both in `createDispatcher`. Add three route-matrix entries and their `ROUTE_HANDLER_FILES` mappings. Export the store through `backend/packages/data/src/index.ts` and update `EXPECTED_RUNTIME_EXPORTS`.
8. **ADR** `docs/adr/<YYYY-MM-DD>-tenant-data-export-archive.md`. It records:
   - the catalog-driven table set and the explicit secret exclusions (a new tenant table is exported unless it is added to the exclusion list);
   - the archive layout and `formatVersion`;
   - one repeatable-read snapshot per export;
   - the 7-day expiry;
   - `yazl`.

## Scope

### In scope
- Requesting, building, listing, downloading and expiring a tenant export.

### Out of scope
- Account deletion and its purge (#1049, #1055).
- The account page (#1083).
- Admin-initiated exports, or any route giving an admin another tenant's export.
- `Cache-Control: no-store` on every other API response (#1072).
- The same-origin `Origin` check on unsafe methods (#1044).
- Importing an export back into Semprec.

## Acceptance criteria

- The API runtime installs `tenantExportExpirySweep` in its crontab (integration, `queueRuntime.test.ts`).

- When tenant A's user posts to `/api/account/exports`, the response is 202 with a `pending` export, and exactly one `tenantExport` job exists whose envelope `tenantId` is A. A second post while it is pending answers 200 with the same export id and enqueues nothing (integration, `accountHandler.test.ts`, two tenants via `createTestTenant()` from #975).
- When the job runs for A, with both tenants holding items, relations, docs, mail and blobs in both roots, the archive:
  - has `account.json`, `manifest.json` and one `tables/<name>.jsonl` per tenant-classified table except the three exclusions;
  - has, for each table, a manifest `rowCount` equal to A's `count(*)` and a matching line count in its `.jsonl`;
  - contains none of B's ids, emails or blob bytes anywhere;
  - contains no `ciphertext`, `nonce`, `tenant_keys` data or `password_hash`;
  - has a `blobs/<id>` entry whose SHA-256 equals the stored bytes for every blob, including one under the mail root.

  The row is then `ready`, with `byte_size` equal to the stored archive's size and `expires_at` 7 days after `completed_at` (integration, `tenantExport.test.ts`).
- When a blob row's file is missing, the export still completes and lists that id in `missingBlobIds` (integration, `tenantExport.test.ts`).
- When the storage write fails mid-archive, the row is `failed`, no file remains under the export key, and the job's error propagates (integration, `tenantExport.test.ts`).
- When `helpers.abortSignal` is aborted between entries, the partial file is removed, the row is `pending` again, a job with key `tenantExport:<id>` is queued, and the handler resolves (integration, `tenantExport.test.ts`).
- When A downloads a `ready` export, the response is 200 with the archive bytes and the four headers above. When B requests A's export id, and when A requests a random uuid, a `pending`/`failed` export or an expired one, each response is the identical 404 body. A non-uuid id is 400, and no session is 401 (integration, `accountHandler.test.ts`).
- When the client aborts mid-download, the read stream is destroyed (integration, `accountHandler.test.ts`).
- When the expiry sweep runs, A's expired export row and file are removed and B's unexpired export is untouched. A file-delete failure is logged and the row is still removed (integration, `tenantExport.test.ts`).
- When `routeMatrix.test.ts` runs, the three new entries answer 401 without a session (integration).
