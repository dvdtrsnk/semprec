## Context

Model tier rationale: One new read route with a single SQL join over existing tables and a derived pairing state, verified against fixtures, with tenant isolation covered by the existing route tests.

The generic query (`POST /api/databases/:id/query`, `services/semprec-api/src/itemsHandler.ts`) cannot serve the recordings lists: it returns whole `computed` values including `segments`, returns no relations, and an event name would need one query per transcript. The pairing state of a transcript (linked, waiting in the Inbox for an event, or none) is stored nowhere: an awaiting card is a Processing proposal of kind `transcript` with a `sourceTranscript` and a database envelope on Events or an `event` relation envelope; after a rejection no new card is created (`findIdempotentReplay` finds a card in any status). Routes are matched in declaration order with `:id` as `[^/]+` (`adapter/routeTable.ts`).

This issue adds `GET /api/transcripts` as a module-manifest custom route in the system-databases module (justification `single-consumer-read`, `seed/systemDatabasesModuleManifest.ts`; per the single-writer ownership ADR the Events and Tasks routes live there too), listed in `routeMatrix.ts`. Each item is `{ id, displayName, date, durationSeconds, status, pairing, event { id, name } | null, proposalId | null, shortSummary, openQuestions { count, first { proposalId, speaker, ordinal } }, automation { status, attempts, lastAttemptAt, errorCode } }`, with no `segments`, deleted transcripts omitted, default order `date` descending, keyset cursor. Query parameters: `eventId`, `personId`, `pairing`, `order`, `cursor`, `limit`. Filtering by project is #1581.

Pairing is derived at read time: `processing` when status is processing; else `event` when the `Transcripts.event` edge targets a live Event; else `awaitingEvent` with `proposalId` when a card of kind `transcript` is `proposed` or `needsClarification` with a database envelope on Events or an `event` relation envelope (not speakers); else `none`. Status `error` gives `none` (the label comes from `automation.status`); an event in Trash gives `none` and `event` again after restore. `personId` filters on the `speakers` edge today. `shortSummary` and `displayName` are added by #1695 and #1830; `openQuestions` counts speaker cards. The `proposalId` field also serves the Inbox card link for a waiting transcript and is created once, here.

It builds on #1386 and #1469 (automation state, duration) and #1576 (the shared manifest). #1693 and #1695 build on it.

Shared-file ordering: this issue also waits for #1635 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.
