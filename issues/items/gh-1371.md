## Context

Model tier rationale: This records the cross-process contract (audio transport, provider, budget accounting, interruption) that three implementation issues and the voice turn issue all build on, so a wrong or vague choice multiplies; hence the higher tier.

Semp should support a live voice mode: the user speaks, sees their words appear, and hears Semp answer, in a Semp thread. Today the backend has only batch transcription of recordings. `semprec-transcribe` calls the AI gateway routes `/internal/transcribe` (Whisper through `deepInfraWhisperProvider.ts`) and `/internal/diarize` (`pyannoteProvider.ts`) beside `/internal/complete` and `/internal/pi/messages`. All gateway routes are internal and token-protected, and only the gateway has network egress to providers (ADR `2026-10-03-host-egress-filtered-by-service-uid`; provider calls are monopolized by the gateway, ADR `2026-09-10-ai-gateway-monopoly-on-provider-calls`). There is no streaming speech-to-text and no text-to-speech. The realtime protocol (`backend/packages/realtime/src/protocolV1.ts`) has no audio frames; its binary frames are Yjs documents with a 16-byte prefix. Audio calls are recorded in `ai_gateway_calls` with `audio_seconds` and never carry an agent run id. Budgets are per tenant with a global safety cap, reserved under an advisory lock (ADRs `2026-10-16-per-tenant-ai-budgets-with-a-global-safety-cap` and `2026-09-27-ai-budget-reservations-under-a-global-advisory-lock`). Slow consumers are closed rather than buffered (ADR `2026-09-16-realtime-outage-and-backpressure-close-rather-than-buffer`).

This issue writes the ADR that fixes the voice design. #1396 (streaming speech-to-text), #1399 (streaming text-to-speech) and #1546 (the authenticated voice channel) implement the pieces according to it, and #1734 joins them to Semp threads.

Decisions to record in the ADR (the author may refine the details but must state each explicitly):
- Pipeline: speech-to-text, then a normal agent turn, then text-to-speech, not a speech-to-speech model. Reason: the turn reuses the thread queue, tools, approvals and step history unchanged, and every provider call stays in the gateway.
- Providers: Czech is primary. Retain OpenAI TTS as the provisional engineering default and ElevenLabs as the documented alternative; no comparative Czech listening test has been performed. Record this status and the ten-passage, two-listener blind protocol honestly. #1399 owns pre-production-release listening qualification; it does not block local backend implementation/integration. Fake-provider tests are not listening evidence. Keep the existing streaming speech-to-text choice and its alternatives; dictation remains device-only (#1372).
- Transport: audio goes to `semprec-api` over a new authenticated WebSocket (tenant from the session), with binary frames for audio and JSON text frames for control and transcripts; the API forwards audio to the gateway. The ADR states the frame format and audio encodings in both directions.
- Budget: audio of unknown length reserves budget in fixed chunks of seconds, one `ai_gateway_calls` row per chunk, settled with real `audio_seconds`; exhaustion ends the stream with a clear error. Voice audio rows are attributed to the Semp thread turn and the agent run they serve, in the same way as the other gateway calls of a turn, and appear as their own Voice activity in AI usage reports; they count against the tenant's budget.
- Audio is never stored.
- Interruption: user speech while Semp speaks stops the speech output only; it does not cancel the agent turn. The next turn waits in the thread's queue. Voice cancels a running agent turn only on an explicit stop command of the user ("Stop", "Zruš"), and then as an ordinary cancellation of the turn; a write waiting for approval is never executed without the approval.
- Backpressure: an overloaded voice channel is closed, not buffered.
