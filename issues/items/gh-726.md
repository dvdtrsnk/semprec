## Context

The app locale is the browser's, not the user's. `web/src/App.tsx` line 52 defaults `languages = navigator.languages` and line 97 renders `<I18nProvider locale={resolveLocale(languages)}>`; `users.locale` (`backend/packages/data/src/db/migrations/0025_auth_schema.sql` line 11, default `'cs'`, returned by `GET /api/auth/session` and `POST /api/auth/login` as `user.locale`) is never read — after sibling issue G3 of this batch it sits in `App`'s session state unused. Dates and money bypass the app locale entirely: `web/src/views/approvalQueue/ApprovalQueue.tsx` lines 20-23 `formatRequestedAt` and `web/src/views/agentRun/AgentRunDetail.tsx` lines 7-11 `formatTimestamp` call `Date.prototype.toLocaleString()` with no locale argument (browser default), and `web/src/views/aiUsage/UtilizationPage.tsx` lines 28-30 `formatUsd` hardcodes `$${amount.toFixed(2)}` (`docs/adr/2026-09-10-english-canonical-keys-with-i18n-labels.md`: labels are selected by `users.locale`).

`web/src/i18n/index.tsx` exposes only the translate function (`I18nContext` at line 32 holds a `Translate`), so a component cannot learn the active locale to format with. Depends on G3 (the session user), on sibling G4 (deletes the second locale source, `useLocalizedString.ts`, so this becomes the single one) and on sibling G7 (edits `App.tsx` and `ApprovalQueue.tsx` first). Sibling G8b (hardcoded labels) applies after this issue because both edit `UtilizationPage.tsx`.

## Task

- `web/src/i18n/index.tsx`: make the context value `{ locale: Locale; translate: Translate }`; keep `useTranslate()`'s signature; add `export function useLocale(): Locale`. `I18nProvider` unchanged in its props.
- `web/src/i18n/format.ts` (new): `formatDateTime(locale: Locale, iso: string | null): string` — `null` → `"—"`, an unparseable string → returned as is (today's behaviour), otherwise `new Intl.DateTimeFormat(locale, { dateStyle: "medium", timeStyle: "short" }).format(date)`; `formatUsd(locale: Locale, amount: number): string` — `new Intl.NumberFormat(locale, { style: "currency", currency: "USD" }).format(amount)` (`en` → `$3.55`, `cs` → `3,55 US$`).
- `ApprovalQueue.tsx`: delete the local `formatRequestedAt`; `PendingRow` reads `useLocale()` and calls `formatDateTime(locale, row.requestedAt)`. `AgentRunDetail.tsx`: delete the local `formatTimestamp`; the component reads `useLocale()` and calls `formatDateTime(locale, …)` where it did before. `UtilizationPage.tsx`: delete the local `formatUsd`; the components that render money (`CostByDayChart`, `UsageTable`, the summary block) read `useLocale()` and call `formatUsd(locale, …)`.
- `App.tsx`: the provider locale is `resolveLocale([session.user.locale])` when the session is `authenticated`, else `resolveLocale(languages)` (the login page and the setup wizard keep following the browser). Keep the `languages` prop.
- Tests:
  - `web/src/i18n/__tests__/format.test.ts` (new): `formatUsd("en", 3.55) === "$3.55"`, `formatUsd("cs", 3.55) === "3,55 US$"`; `formatDateTime` for `null`, for an unparseable string, and for a fixed ISO instant asserting equality with the same `Intl.DateTimeFormat` call (timezone-independent).
  - `web/src/i18n/__tests__/i18n.test.ts`: `useLocale()` returns the provider's locale (render a probe component under `I18nProvider locale="cs"`).
  - `web/src/__tests__/App.test.tsx` (from G3): with a session user whose `locale` is `"en"` and `languages={["cs"]}`, the header renders the English `login.signedInAs` text; before login it renders the Czech login page.
  - `UtilizationPage.test.tsx`, `ApprovalQueue.test.tsx`, `AgentRunDetail.test.tsx`: existing `en` assertions (`$3.55`, `Daily budget: $50.00`, `Monthly budget: $200.00`) keep passing; add one `cs` render per file asserting the Czech currency/date output.
