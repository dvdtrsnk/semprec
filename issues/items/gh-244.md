**Blocked by:** #175, #91

## Context

This issue builds on #175 (bootstrap secrets in `/opt/semprec/shared/.env`). It is the first half of provisioning: a single idempotent `provision.sh` that takes a bare Linux server to a state ready for its first deploy with no manual improvisation by the operator. #176 adds the systemd service units, timer skeletons, and journald configuration to the same script; #177 is the next slice of the batch. `deploy.sh`, the CI gate, and the release/symlink mechanics ship in #190 and run on top of the tree provisioned here.

## Task

Add an idempotent `provision.sh` in the implementation repo (alongside the future `deploy.sh`) that installs and configures:

- Node LTS and pnpm, Docker with Compose, Caddy, restic, `ffmpeg`/`ffprobe`.
- The service user.
- The bare `/opt/semprec` directory tree (`releases/`, `shared/`, …), populated later by `deploy.sh`.
- The `shared/.env` template listing the required keys without values, per #175, only if no `.env` exists — configured secrets and existing releases are preserved on rerun.

The script must be rerunnable: a second run creates no duplicates and overwrites nothing the operator configured. No Ansible/Nix.

## Scope

### In scope

- Package installation, service user, `/opt/semprec` tree, `.env` template placement, idempotence, tests, and necessary documentation.

### Out of scope

- The five service units, the four timer skeletons, journald persistence/limits, and the loopback/shared-env unit contracts — #176.
- `deploy.sh`/CI — #190/#188.
- Hunspell — #206.

## Acceptance criteria

- One run prepares a clean supported Debian/Ubuntu host with every listed package, the service user, and the `/opt/semprec` tree.
- Second run creates no duplicates and overwrites no secrets or releases.
- No interactive improvisation is required.
