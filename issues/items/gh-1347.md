Calendar reminders, travel time and muted calendars.

## Decisions

Decisions adopted while drafting, and questions still open for the product owner (per chunk of the batch):

### Decisions: calendar-reminders-1

#### Adopted from open questions
- Tasks calendar `notify` defaults to false and would mute every task reminder -> Tasks are never muted by the system Tasks calendar; only `Tasks.notifications` controls them (#1719) -> avoids silent loss of every task reminder without waiting for a seed change.
- Is the phone-scheduled feed enough, or is a server push needed -> only the feed plus a silent resync push is planned (#1858, #1879) -> Decided by the product owner: in v1 the phone schedules reminders from the feed and the silent push only triggers a resync; a server-side reminder push is deferred.
- Should a carried-over task remind every day -> only on its stored date (#1719) -> Decided by the product owner: a moved task is visible in Today as "moved from ...", so a daily reminder would be redundant.
- All-day hour -> 09:00, a single constant (#1719) -> Decided by the product owner: fixed at 09:00, no setting in v1.
- Debounce for resync -> 30 s, replace-mode job key per tenant (#1879).
- Feed bounds -> hours 1..168 default 48, at most 200 entries, only existing rows (virtual recurrence occurrences join later) (#1858).
- Feed route is owned by the systemDatabases module although it lives under /api/calendar (program decision on routes over Tasks and Events).

#### Open questions for the product owner
- Should the seeded Tasks system calendar get `notify` true (design note recommendation, belongs to the calendars seed issue)? Current drafts work either way.
- Do birthdays and holidays belong in the same feed (join when their generators land)?
- Should Reminder/Alert/Travel be editable in Details after creation (client-only today; no server change needed)?

#### Delivered behavior
A user can set an alert (at time, 5/15/60 minutes or 1 day before) and travel time (15/30/60 minutes) on an Event, and switch Reminder on for a Task. The server rejects any other values. The server computes when each reminder fires in the user's time zone (travel time moves it earlier; all-day items fire at 09:00), muted calendars, trashed items, done tasks and cancelled occurrences are skipped. The iPhone fetches a 48-hour feed of upcoming reminders and schedules them locally, and when the user changes something from the web, a silent push (debounced to one per 30 seconds) tells the phone to refetch.
