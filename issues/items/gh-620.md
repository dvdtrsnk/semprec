## Context

`backend/packages/ai-gateway/src/gateway.ts` enforces the daily/monthly AI budget with a check-then-act sequence and says so in its own comment above `assertWithinBudget` (lines 19-24: "Check-then-act, no lock — concurrent calls near the cap may jointly overshoot slightly"). `assertWithinBudget` (lines 25-38) runs two reads on the bare `Pool` — `getAiBudgetsWithTimezone` (`backend/packages/data/src/systemSettings.ts`, line 87) and `getGatewaySpend` (`backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts`, line 120) — then `withTokenAccounting` (lines 40-58) and `withAudioAccounting` (lines 60-74) call `invoke()` and only afterwards INSERT the `ai_gateway_calls` row via `recordTokenGatewayCall` / `recordAudioGatewayCall`. Nothing in the window between the read and the INSERT is serialized, so N concurrent calls that all read spend just under the cap all pass and the cap is overshot by N × the call's cost, not "slightly". The spend query itself (`getGatewaySpend`, `WHERE at >= date_trunc(...)`) has no index on `at` — `0018_ai_gateway_calls.sql` indexes only `agent_run_id` — so it is a sequential scan of the whole table on every call.

This issue introduces the reservation mechanism the rest of the batch builds on: sibling issues E2 (settle retry), E3 (abort propagation) and E4 (audio `operation` attribution) depend on the `status` column, the `reserveGatewayCall`/`settle*`/`failGatewayCall` store functions and the `estimatedCostUsd` context field delivered here.

## Task

Turn "check, call, record" into "reserve under a lock, call, settle":

- **Migration** `backend/packages/data/src/db/migrations/NNNN_ai_gateway_calls_status.sql` (take the next free ordinal at commit time; `0048` is free at the time of writing):
  - `ALTER TABLE ai_gateway_calls ADD COLUMN status text NOT NULL DEFAULT 'settled';`
  - `ALTER TABLE ai_gateway_calls ADD CONSTRAINT ai_gateway_calls_status_check CHECK (status IN ('reserved', 'settled', 'failed'));`
  - `CREATE INDEX ai_gateway_calls_at_idx ON ai_gateway_calls (at);` (plain `CREATE INDEX`; the migration runner wraps every file in a transaction, and the table is small.)
  - Expand-only: the previous release's INSERT omits `status` and gets `'settled'`, which is exactly what its rows are. No `expand-contract-exemption` marker is needed.
- **Store** (`backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts`):
  - `export type AiGatewayCallStatus = "reserved" | "settled" | "failed"`; add `status: AiGatewayCallStatus` to `AiGatewayCallRow` and `status: string` to `AiGatewayCallDbRow`; `mapRow` narrows it with `assertKnownValue` from `../dbRowValidation.js` (typed rows at the Postgres boundary, `docs/adr/2026-09-10-typed-rows-at-the-postgres-boundary.md`); every `RETURNING` list in the file gains `status`.
  - `reserveGatewayCall(client: Pool | PoolClient, input: ReserveGatewayCallInput): Promise<AiGatewayCallRow>` where `ReserveGatewayCallInput = { provider; model; estimatedCostUsd: number; agentRunId?: string | null; projectItemId?: string | null; operation?: string | null }`. INSERT with `status = 'reserved'`, `cost_usd = $estimatedCostUsd`, `input_tokens`, `output_tokens` and `audio_seconds` all NULL, the three attribution columns from the input (NULL when omitted).
  - `settleTokenGatewayCall(client, id: string, input: { inputTokens: number; outputTokens: number; costUsd: number })`: `UPDATE ai_gateway_calls SET status = 'settled', input_tokens = $2, output_tokens = $3, cost_usd = $4 WHERE id = $1 AND status = 'reserved' RETURNING ...`; unwrap with `requireSingleRow` so a row that is not `reserved` (or does not exist) throws instead of reporting success.
  - `settleAudioGatewayCall(client, id, input: { audioSeconds: number; costUsd: number })`: same shape, sets `audio_seconds` and `cost_usd`, leaves the token columns NULL.
  - `failGatewayCall(client, id: string): Promise<void>`: `UPDATE ai_gateway_calls SET status = 'failed', cost_usd = 0 WHERE id = $1 AND status = 'reserved'`, checked with `requireAffectedRows`. A failed reservation carries no cost so every existing `SUM(cost_usd)` (budget, usage report) already excludes it without a new filter.
  - `recordTokenGatewayCall` / `recordAudioGatewayCall` stay as they are (data-package tests seed rows with them; they now insert `status = 'settled'` through the default). Update the `getGatewaySpend` docblock to say reserved rows count at their estimate and failed rows at 0.
  - Add the four new runtime exports to the frozen list in `backend/packages/data/src/__tests__/publicSurface.test.ts`.
- **Gateway** (`backend/packages/ai-gateway/src/gateway.ts`, `types.ts`):

  - `complete`, `embed`, `transcribe`, `diarize` and the two `with*Accounting` helpers take `pool: Pool` instead of `client: Pool | PoolClient` — the reservation must open its own transaction, and every existing caller (both handlers, `gateway.test.ts`) already passes a `Pool`.

## Scope

### In scope

- The `status` column, its CHECK constraint and the `(at)` index.
- Reserve/settle/fail store functions and the locked reservation transaction in `gateway.ts`.
- `estimatedCostUsd` plumbing from both route handlers.
- Test updates listed above.

### Out of scope

- Retrying a failed settle UPDATE and returning the provider result when it keeps failing — sibling issue E2 of this batch.
- Passing an `AbortSignal` into provider calls, drain timeout changes — sibling issue E3.
- Recording `operation` for audio rows — sibling issue E4 (the reserve function delivered here already accepts it; the audio handler does not yet pass it).
- Any change to `aiUsageReport.ts` or the usage route; a reconciliation sweep for rows left `reserved`; per-user budgets.
- `NOT NULL` without default, renames, or edits to migrations `0018`/`0034`.

## Acceptance criteria

- When two `complete()` calls whose estimates each reach the daily cap start concurrently, exactly one reaches `invoke()` and the other rejects with `BudgetExceededError` before `invoke()` runs; exactly one `ai_gateway_calls` row exists afterwards.
- When `invoke()` rejects, the row created for that call has `status = 'failed'` and `cost_usd = 0`, the original error propagates to the caller, and that row does not count against the cap for the next call.
- When `invoke()` resolves, the row has `status = 'settled'` and its `cost_usd`, `input_tokens`/`output_tokens` (or `audio_seconds`) are the values `invoke()` returned.
- `POST /internal/complete` and both audio routes still answer 403 `budget_exceeded` with no `'settled'` row when the cap is already reached, and a provider failure on any route leaves one `'failed'` row instead of none.
- `SELECT indexname FROM pg_indexes WHERE tablename = 'ai_gateway_calls'` lists `ai_gateway_calls_at_idx` after migrations run; `pnpm --filter @semprec/data run check-migration-numbering` passes.
- `publicSurface.test.ts` passes with the four new exports listed.
