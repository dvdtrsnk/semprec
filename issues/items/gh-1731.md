**Model tier:** high

## Context

Model tier rationale: It makes the agents service run turns for a scheduled project automation with a different project scope and tool set than chat, which is an authorization and isolation boundary shared with queued-turn execution.

A tick thread is the conversation around one automation. The product lets a person ask a question there ("Why did the last run merge only 3 records?") and Semp answers with the knowledge of the automation and its recent runs. Today a heartbeat run is a one-shot agent run, and the heartbeat tools `heartbeat.list`, `heartbeat.history` and `heartbeat.trigger` (`backend/packages/data/src/scheduler/heartbeatAgentTools.ts`) see only the project of the calling run and are not part of any agent session (the session composition is in `semprec-agents/src/agentSessionComposition.ts`).

Messages sent to a thread go through the chat endpoint (#1620), are queued, and the agents service runs queued turns (#1727). Module agent tools are composed into agent sessions by #1523. Runs of tick threads are written by #1557. This issue makes a turn in a tick thread run with the heartbeat's context. The continuation after an approval (#1775) reuses it.

Decision: a turn in a tick thread runs scoped to the heartbeat's project (its `project_item_id`), so the heartbeat tools that already filter by the calling run's project see that automation; the context handed to the model contains the heartbeat's `name`, structured `rule`, `action_config.task`, `enabled` and its recent runs (listed with `listAgentRunsByHeartbeat`).

## Task

Load `ai-gateway`, `io-hardening`, `error-handling` and `testing`.

1. When a queued turn belongs to a thread of kind `tick`, create the run with `project_item_id` = the heartbeat's project and add a context block to the prompt: heartbeat `name`, `rule`, `action_config.task`, `enabled`, and the last runs (status, start, finish, result excerpt) of that heartbeat. Bound the block's size (last runs capped, excerpts truncated).
2. Compose `heartbeat.list`, `heartbeat.history` and `heartbeat.trigger` into the tick-thread session through the module tool composition of #1523, so they work for that project and for no other. A heartbeat that was deleted since the thread was created yields a turn with no heartbeat context and no heartbeat tools, not a failure.
3. Chat and item threads are unchanged: they get neither the context block nor these tools.
4. Tests: a question in a tick thread gets a run whose project is the heartbeat's project and whose prompt contains the last runs; heartbeat tools in that session cannot read another project's heartbeats; a chat thread session has no heartbeat tools; a deleted heartbeat does not fail the turn.

## Scope

### In scope

- Project scope, heartbeat context and heartbeat tools for turns in a tick thread.

### Out of scope

- Writing scheduled runs into the thread: #1557.
- Queueing and running thread turns in general: #1727.
- Starting a new turn after an approval is decided: #1775.
- Creating, renaming and changing automations: #1846.
- The manual-trigger HTTP route: #1453.

## Acceptance criteria

- A user message in a tick thread leads to a run with the heartbeat's project, and the prompt contains its name, rule, task and the last runs.
- `heartbeat.list` called in that session returns only that project's heartbeats.
- A message in a chat thread runs without the heartbeat context or tools.
- If the heartbeat no longer exists, the turn still completes without heartbeat context.
