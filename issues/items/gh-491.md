## Task

Bump the code-review-bot pin in `.relay/config.yml` (`review.bot.ref`) and
`.github/workflows/code-review.yml` (the `Checkout code-review-bot` step's
`ref:`) to `52497aca626b5b64f5c32e2344137502968d3d74` — the merge commit of
[dvdtrsnk/code-review-bot#25](https://github.com/dvdtrsnk/code-review-bot/pull/25),
which adds a fail-closed shortcut that cites an already-passing verdict
instead of running a full review when a rebase reproduces a diff
byte-identical (same diff hash, base SHA, and `review-rules/**` content hash)
to one already reviewed. This is useful now that `implement-issue` and
`merge-pull-request` both run more than one worker at a time
(`docs/adr/2026-09-24-issue-batches-as-dependency-dags.md`), which makes
rebase-triggered re-reviews more common.

Also reconcile the two pins, which had drifted apart (`96a0439...` in
`.relay/config.yml` vs `fc7d3fe...` in `code-review.yml`) to the same new SHA.

### Out of scope

Any other change to `.relay/**` or `.github/workflows/**` beyond the two pin
lines.

## Why a plain issue, not a Relay batch issue

This is a maintainer-only change: it edits `.relay/**` and
`.github/workflows/**`, which `implement-issue`'s own `protected-paths` guard
excludes from Relay's dispatch, so it ships as a human-authored pull request
rather than through Relay's issue-batch flow. It carries a `## Task` section
so the pull request that closes it has the authorization the `ci-workflows`
review rule requires.
