## Context

Model tier rationale: One text-building function shared with ingest and one added input to the existing index write, with no new lifecycle, tenant or schema contract.

Mail search finds a message by words in its subject, body and the text of PDF/DOCX attachments. The sender is not in the index: `ingestEmailMessage` (`backend/packages/data/src/mail/ingest.ts`) builds the indexed text as `[subject, body, ...extracted attachment texts]` and calls `reindexItemSearch` (`mail/search.ts`). The `from:` operator therefore works only as an `ILIKE` over the `Emails.sender` property, without accent folding. Searching for a person's name ("Petr", "Novák") should find the mail they sent without an operator.

#1589 changes the shared search vector so that queries match with and without diacritics and by word prefix. This issue adds the sender to the text that vector is built from, and extracts the text builder so the per-tenant reindex (#1741) builds it identically. Searching threads by text (#1639) builds on it.

Decision: the indexed sender text is the display name and the address of `envelope.from`, as written. Mail search owns the sender and the reindexing of mail; the generic item indexer does not index the sender of mail.
