## Context

Model tier rationale: Two unit test files; the fix is measuring the slow step and either removing redundant work or moving the test to the tier that matches its cost.

During full backend verifies on 2026-10-21 and 2026-10-22, with load average around 11–17 on the shared host, these unit tests repeatedly hit vitest's 5 000 ms default timeout:

- `backend/packages/data/src/__tests__/moduleRegistryLoadAll.unit.test.ts` — "loads every manifest from #226/#227 into one registry with no cross-manifest collisions";
- `backend/packages/data/src/__tests__/libraryMailInboxModuleManifests.unit.test.ts` — "loads the mail sync manifest…".

They pass at normal load. An earlier, never-merged attempt only raised one timeout to 30 s, which hides the cost instead of explaining it. These failures cost whole verify reruns for every agent and Relay job that shares the host.

## Task

Load `testing`.

1. Measure where these tests spend their time (manifest file reads, schema compilation, registry projection), for example with `vitest --reporter=verbose` and timers around each phase.
2. If one phase repeats work that can be shared across cases in the same file (for example compiling the same JSON schemas once per case), share it in a `beforeAll`, without changing what any assertion checks.
3. If the work is inherent, set an explicit per-test timeout on these tests only, sized from the measurement with a stated margin, in a one-line comment that names the measured time. Do not raise the global unit timeout.
4. Report the measured times before and after in the pull request.

## Touches

- backend/packages/data/src/__tests__/moduleRegistryLoadAll.unit.test.ts
- backend/packages/data/src/__tests__/libraryMailInboxModuleManifests.unit.test.ts

## Scope

### In scope

- The two named tests' runtime under load.

### Out of scope

- Production module-registry code, unless step 1 shows a defect there.
- The global vitest configuration.

## Acceptance criteria

- The pull request reports measured runtimes before and after.
- Neither test exceeds its timeout across 5 consecutive full unit-tier runs with another verify running in parallel.
