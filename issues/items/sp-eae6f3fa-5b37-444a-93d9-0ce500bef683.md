## Context

Model tier rationale: Changes the outcome of one route's post-commit step from an error to a logged failure behind a committed success.

Found in the local review of PR #2089. `PUT /api/mail/mailboxes/:id/password` (`createMailboxPasswordReplaceRouteHandler`, `mail/mailboxPasswordRouteHandlers.ts`) commits the new sealed password, the server settings, the cleared failure records and the queued syncs, and then awaits `mailLiveSync.restartAccount`. When the restart rejects, the route answers 500 although the replacement is saved; the client shows a failure for a password that is in effect, and a retry verifies and replaces it again.

Decision: a failed restart is logged (`mailboxItemId`, `errorName`, no message) and the route answers 200 with the item. The queued pass reads the new password; the hosted live sync picks it up at its next reconnect. The OAuth sign-in again (`mailOauthRouteHandlers.ts`) documents and tests the opposite (a 500 after the commit) and is left as it is.
