## Context

The api queue runtime registers the mail jobs `mailAccountSyncSweep`, `mailAccountSync` and `mailSearchReindexSweep` (`backend/packages/data/src/worker.ts:153-172`; all `queueAffinity: 'api'`, `backend/packages/queue/src/index.ts:98-101`) and installs the crontab lines `*/5 * * * * mailAccountSyncSweep` and `30 3 * * * mailSearchReindexSweep` (`worker.ts:81-82`). But `backend/services/semprec-api/src/queueRuntime.ts:48-57` passes `undefined` for `mailSyncAdapters`, `mailModuleIds`, `mailBlobStorage` and `legacyRawMimeFetcher`. With `mailModuleIds` undefined:

- the daily `mailSearchReindexSweep` throws `mailSearchReindexSweep job requires createCoreTaskList's mailModuleIds argument to be configured` (`worker.ts:166-171`) on every run, and graphile-worker retries it with its default 25 attempts and exponential backoff — a guaranteed daily error burst in the queue;
- any `mailAccountSync` job throws the same way (`worker.ts:157-158`) before reaching the adapter.

`MailModuleIds` (`backend/packages/data/src/mail/mailSyncJob.ts:48-53`) is four database ids — `emailsDatabaseId`, `filesDatabaseId`, `foldersDatabaseId`, `mailboxesDatabaseId` — which the seed creates with `owner_module_id` equal to `EMAILS_MODULE_ID`/`FOLDERS_MODULE_ID`/`MAILBOXES_MODULE_ID` (`backend/packages/data/src/seed/emailModuleKeys.ts`) and `FILES_MODULE_ID` (`seed/tenDatabaseKeys.ts`), readable through `getDatabaseByModuleId(client, ownerModuleId)` (`backend/packages/data/src/chokePoint/databasesStore.ts:125`). Nothing in `packages/data` resolves them yet (tests build the object by hand, `__tests__/mailSync.test.ts:1955-1960`).

The transport adapters stay on `noopMailSyncAdapterFactory` in this issue, deliberately: `ImapFlowMailClient`, `GmailRestClient` and `GraphRestClient` exist, but a Mailbox item carries only `name`/`provider`/`addresses`/`connectionLimit` (`seed/seedEmailModule.ts:116-135`) — no server host, port or login — no route stores a mailbox credential, and no OAuth authorization flow exists to obtain refresh tokens; there is nothing for a real adapter to connect with. When mailbox onboarding exists, wiring the adapters is the composition change that follows it. With module ids wired, a `mailAccountSync` job for a discovered account fails inside `handleSyncMailAccountTask`'s own error handling (`mailSyncJob.ts:302-380`: `syncStatus='error'`, `last_error` = `No IMAP adapter configured for this composition root`, one deduplicated `mail_sync_error` notification), which is the correct, visible state. `mailBlobStorage` stays on `createCoreTaskList`'s default parameter (`worker.ts:101-103`), whose environment policy #645 owns; `legacyRawMimeFetcher` stays `noopLegacyRawMimeFetcher` (no real fetcher exists).

This issue depends on #646 because both edit the same `createApiCoreTaskList(...)` call in `queueRuntime.ts`.

## Task

1. New `backend/packages/data/src/mail/mailModuleIds.ts` exporting `resolveMailModuleIds(client: Queryable): Promise<MailModuleIds>`: looks up the four databases with `getDatabaseByModuleId` and throws `new Error("Mail module databases are not seeded (missing: <ids>) — run packages/data/dist/db/runSeedCli.js")` when any is missing. Export it (and re-export the `MailModuleIds` type) from `backend/packages/data/src/index.ts` on a new line next to the `./mail/mailLiveSyncRoot.js` export block (lines 186-194) — not on line 246.
2. In `backend/services/semprec-api/src/queueRuntime.ts`, before building the task list, `const mailModuleIds = await withTransaction(pool, (client) => resolveMailModuleIds(client));` and pass it as the `mailModuleIds` argument of `createApiCoreTaskList`; keep `mailSyncAdapters` at `undefined` with a comment stating the onboarding prerequisite above in one sentence, and keep `mailBlobStorage`/`legacyRawMimeFetcher` at `undefined`. The runtime now fails fast at startup on an unseeded database (the error names the seed CLI).
3. Update the docstring of `createApiQueueRuntime` accordingly.
4. Tests:
   - `backend/packages/data/src/__tests__/mailModuleIds.test.ts` (new, integration): after `seedSystem`, `resolveMailModuleIds` returns ids whose `databases` rows carry the expected `owner_module_id`s; on an empty database it throws naming the missing module ids.
   - `backend/services/semprec-api/src/__tests__/mailSyncComposition.test.ts` (new, integration): with `seedSystem` and `AI_GATEWAY_INTERNAL_TOKEN` set, start `createApiQueueRuntime`, enqueue `mailSearchReindexSweep` `{}` and observe the job completing on its first attempt (no `last_error` on its `graphile_worker._private_jobs` row, row gone); then insert a Mailbox item with `provider: "generic"`, `ensureMailAccountSyncState` for it (a fresh row has `next_expected_activity_at IS NULL`, which `listAccountsDueForSync` treats as due), enqueue `mailAccountSyncSweep` `{}`, and observe a `mailAccountSync` job being enqueued for it (`jobCountFor` pattern) and, after it runs, `mail_account_sync_state.last_error` containing `No IMAP adapter configured` and the Mailbox's `syncStatus` = `error` — proving the job reached the adapter step instead of the `mailModuleIds` guard.
   - In the existing `backend/services/semprec-api/src/__tests__/queueRuntime.test.ts`, add `await seedSystem(pool)` to `beforeEach` (the runtime now requires the mail databases); the test file already imports `seedSystem`.

## Scope

### Out of scope
- Real IMAP/Gmail/Graph adapters, mailbox server settings, credential storage routes, OAuth exchange (separate finding — mailbox onboarding).

## Acceptance criteria

- When `mailSearchReindexSweep` fires under `createApiQueueRuntime` on a seeded database, it completes on its first attempt and no `requires createCoreTaskList's mailModuleIds` error is recorded.
- When an account is due, `mailAccountSyncSweep` enqueues `mailAccountSync` for it, and that job records the adapter-level failure (`No IMAP adapter configured for this composition root`) on `mail_account_sync_state` and `syncStatus='error'` on the Mailbox, rather than throwing before the adapter step.
- When the mail databases are missing, `createApiQueueRuntime` rejects with an error naming the missing module ids and the seed CLI, and `semprec-api` exits non-zero at startup.
