## Context

Model tier rationale: A small additive change in one function and one reader helper, with an existing test file, using a column that is already jsonb and overwritten on every run; no new contract beyond one extra field.

The Semp status view lists the backup service with "Last restore test: Oct 1". Today the time of the last test is only implicitly stored: `recordRestoreTestResult` (`backend/packages/data/src/observability/restoreTestResult.ts`) upserts the global `observability_checks` row `backup:restoreTest` with `detail` `{ runId }` (or `{ runId, failedCheck }`), and `changed_at` moves only when the status flips, so a series of passing tests leaves `changed_at` months old. The run id carries the start time in UTC (`YYYYMMDDTHHMMSSZ-<pid>`, generated by `deploy/systemd/scripts/semprec-restore-test.sh`), but nothing parses it.

This issue stores the time explicitly, so the services list (#1561) can report the date of the last test, whether it passed or failed.

Decision: `ranAt` (ISO 8601, UTC) is derived by `recordRestoreTestResult` from the run id's timestamp, so the shell script does not change. If a run id cannot be parsed, `ranAt` is the time of recording. The column is jsonb and is rewritten at every run, so no migration is needed. Rows written before this change are read through the same parser from `detail.runId`.

Decision: only the date and the pass/fail outcome are meant for tenants; `failedCheck` is operator detail and is never part of what the reader helper returns.

## Task

Load `testing`.

1. In `restoreTestResult.ts` add `ranAt` to the `detail` written for both passed and failed results.
2. Export `readRestoreTestOutcome(detail, status)` from the same file, returning `{ lastTestAt: string | null, ok: boolean }`: `lastTestAt` from `detail.ranAt`, else parsed from `detail.runId`, else `null`; `ok` is true when the check status is `ok`. It never returns `failedCheck`.
3. Tests: a passed run stores `ranAt` equal to the run id's time; a second passed run updates `ranAt` while `changed_at` stays; a failed run stores `ranAt` and the helper returns `ok: false` without `failedCheck`; an older row with only `runId` is read correctly; an unparsable run id falls back to the recording time.

## Acceptance criteria

- When a restore test passes, then `observability_checks.detail` of `backup:restoreTest` contains `ranAt` with the run's start time, even though `changed_at` did not change.
- When a restore test fails, then `ranAt` is also stored, and the reader helper returns `ok: false` and no failed-check name.
- When the row was written before this change, then the helper returns the time parsed from `runId`.
