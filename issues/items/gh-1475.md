**Blocked by:** #1469
**Model tier:** medium

## Context

Model tier rationale: One known mechanism (a pure mapping at the provider boundary) plus a per-tenant data cutover that rewrites two stored values, so the persisted-data contract needs care but every seam has an existing pattern and test fixture.

Whisper (served by DeepInfra) reports the language it detected as an English language name such as `czech`, not as a code. `backend/services/semprec-ai-gateway/src/audioProviders/deepInfraWhisperProvider.ts` returns that string unchanged in `TranscriptionResult.language`; `backend/services/semprec-transcribe/src/transcriptionTask.ts` (`runAsrStep`) stores it on the source Files item as `computed.asr.language`, sends it as the `language` request field for every later chunk, and `runMergeStep` copies it onto the Transcripts item as `computed.language`. The summarize step also puts it into the model prompt. Clients and the transcript detail endpoint (#1576) need a stable machine-readable value, so the stored language must be an ISO 639-1 code (`cs`, `en`, ...) or `null`.

Because the normalization happens in the gateway provider, the chunk-0 checkpoint, every later chunk request and the merged transcript all carry the code with no change to the pipeline code. Transcripts and Files items written before this change still hold the old name, so a per-tenant cutover converts them.

Decision: a language name that is not in the mapping becomes `null` (the same value as "Whisper reported none"), never a guessed or raw string. The pipeline already treats `null` as "let Whisper detect again", so this is safe.

Shared-file ordering: this issue also waits for #1469 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `testing` and `io-hardening`.

1. Add `backend/services/semprec-ai-gateway/src/audioProviders/whisperLanguageCodes.ts` exporting `normalizeWhisperLanguage(raw: string | null | undefined): string | null`. It lowercases and trims the input; accepts an input that already is a two-letter code from the mapping; maps every language name Whisper large-v3 can report (the full Whisper language list: name to ISO 639-1, including the aliases Whisper itself lists such as `castilian` for `es`, `flemish` for `nl`, `moldavian`/`moldovan` for `ro`, `letzeburgesch` for `lb`, `burmese` for `my`, `pashto`/`pushto` for `ps`, `panjabi` for `pa`, `sinhalese` for `si`, `haitian creole` for `ht`); returns `null` for anything else.
2. In `deepInfraWhisperProvider.ts`, apply `normalizeWhisperLanguage` in `parseResponse`, so `TranscriptionResult.language` is a code or `null`. The wire shape of the gateway response (`{ text, language, segments }`) does not change.
3. Add a per-tenant cutover `backend/packages/data/src/transcription/transcriptionLanguageCodeCutoverMigration.ts` (`runTranscriptionLanguageCodeCutoverMigration(pool)`) and register it in `runTenantCutoverMigrations` (`backend/packages/data/src/db/tenantCutoverMigrations.ts`), following `transcriptsCatalogCutoverMigration.ts`. For the tenant it runs in, it rewrites `computed.language` on every Transcripts item and `computed.asr.language` on every Files item that has an ASR checkpoint, replacing a stored language name by its code (or `null` when unmapped). Values that already are a code or `null` are left untouched, so a second run changes nothing. Write through the existing computed-cache writer used by the pipeline (`writeComputed` in `chokePoint/itemsStore.ts`), without announcing changes over realtime. The mapping is imported from one shared copy: put `normalizeWhisperLanguage` where both the gateway and the data package can import it (for example `backend/packages/shared/src/whisperLanguageCodes.ts`, exported from the shared package) instead of duplicating the table, and have the gateway provider import it from there.
4. Tests: unit tests for the mapping (names, aliases, already-a-code, unknown, null, mixed case and whitespace); extend `backend/services/semprec-ai-gateway/src/audioProviders/__tests__/deepInfraWhisperProvider.unit.test.ts` so a `czech` response yields `cs`; a data-package test for the cutover covering a populated tenant, an item with `null`, an item that already holds a code, an unmapped name, and a second run being a no-op.

## Scope

### In scope

- Normalizing the detected language to an ISO 639-1 code or `null` at the gateway provider boundary.
- Converting already stored `computed.asr.language` (Files) and `computed.language` (Transcripts) values once per tenant.

### Out of scope

- Returning the language to clients: the transcript detail endpoint (#1576) exposes it.
- Changing which language Whisper is asked for, or letting the user choose a language.
- Changing prompt wording in the summarize step; it receives the code instead of the name, which is accepted as is.

## Acceptance criteria

- When DeepInfra answers with language `czech`, the gateway transcribe response contains `language: "cs"`.
- When the answer carries an unknown language name or no language, the response contains `language: null`.
- After a new recording is transcribed, `computed.asr.language` on the Files item and `computed.language` on the Transcripts item are both `"cs"` for a Czech recording, and chunks after the first are requested with `language: "cs"`.
- After the cutover runs on a tenant holding transcripts stored with `czech`, both stored values read `cs`; running it again changes no row; rows already holding a code or `null` are untouched.
- The cutover only touches the rows of the tenant it runs for.
