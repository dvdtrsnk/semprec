## Context

`docs.item_id` has no Postgres FK (the partitioned `items` cannot be referenced; `backend/packages/data/src/db/migrations/0003_docs.sql`, lines 3-9 say so and add: "referential integrity for it is enforced at the application layer (the doc store)"). The doc store does not enforce it: `getOrCreateDoc` in `backend/packages/data/src/docs/docsStore.ts` (lines 46-104) inserts a `docs` row for any `itemId` it is handed (line 60-64) without checking that an `items` row exists or is live. Every caller — `putBlockWithClient` in `backend/packages/data/src/docs/docStore.ts` (line 34; used by `confirmProposalWithClient` for a `pageContent` proposal whose `target` page may have been trashed or purged since the proposal was computed) and `createDocStore(...).getOrCreateDoc`/`putBlock`/`putCanvasElement` (lines 64-104) — therefore creates a doc (plus `doc_snapshots` and the baseline `doc_snapshot_history` row) for a purged, never-existing or soft-deleted item, a doc that nothing owns and that the retention sweep re-baselines forever. `getItemsByIds` (`backend/packages/data/src/chokePoint/itemsStore.ts`, lines 326-334) is the existing live-row lookup that needs no `database_id` (docs do not know one).

## Task

1. `getOrCreateDoc`: on the create path only — after the `existing` check (lines 47-56) returns nothing and before the `INSERT` (line 58) — run `const [item] = await getItemsByIds(client, [itemId])` and throw `new NotFoundError(\`Item ${itemId} not found\`, { itemId })` when it is `undefined` (missing or soft-deleted). The check runs on the caller's `client`, i.e. inside the same transaction as the insert (`backend/review-rules/rules.md`: a pre-check guards only when it shares the write's transaction). An already-existing doc is still returned as before, so content of a trashed page stays reachable for restore. Update the doc comment (lines 35-45) and change the `0003_docs.sql` claim from aspiration to fact in that comment (do not edit the migration).
2. Tests in `backend/packages/data/src/__tests__/docs.test.ts` (integration): `getOrCreateDoc` for a random uuid rejects with `NotFoundError` and inserts no `docs` row; for a soft-deleted item rejects the same way; for a live item creates the doc; for a trashed item that already has a doc returns that doc.

## Touches

- backend/packages/data/src/docs/docsStore.ts (`getOrCreateDoc` only)
- backend/packages/data/src/__tests__/docs.test.ts

## Scope

### In scope
- The live-item check on doc creation and its tests.

### Out of scope
- Refusing writes to an existing doc of a trashed item (restore must keep working; a separate product decision).
- Deleting docs on purge (sibling issue C2) and the history rebaseline (sibling issue C13).
- Adding a Postgres FK (impossible on the partitioned parent; unchanged).

## Acceptance criteria

- When a doc is requested for an item id that does not exist or is soft-deleted and no doc exists yet, the call fails with 404 `not_found` and no `docs`, `doc_snapshots` or `doc_snapshot_history` row is written.
- When the item is live, or a doc already exists, behaviour is unchanged.
