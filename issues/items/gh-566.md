**Blocked by:** #494

## Context

This batch builds a pipeline that turns code-review findings left open on merged pull requests into proposed follow-up issues (epic #565). Its deterministic core — harvest, prepare, validate and publish — is a set of zero-dependency Node ES modules under `.github/scripts/review-followups/`, following the precedent of `.github/scripts/close-completed-epics.mjs`.

Today nothing under `.github/scripts/` is reviewed. The review bot assigns each file to the platform whose directory is the longest prefix of its path, so `.github/scripts/x.mjs` belongs to the repository-root platform, and `review-rules/scope.md` includes only `docs/adr/*.md`, `.claude/skills/**/*.md`, `.bb/skills/**/*.md`, `.bb/AGENTS.md`, `README.md`, `.github/workflows/**` and `review-rules/**`. A pull request that changes only `.github/scripts/check-write-safety.mjs` or `close-completed-epics.mjs` merges with a green `code-review` check and no agent having read it — the same gap #413 closed for `.github/workflows/**`. Every script issue in this batch is blocked by this one so that the pipeline's core is reviewed.

**Merge timing.** A change under `review-rules/` changes the rules hash the bot keys its stored verdicts on, so every open pull request's verdict stops being reusable and gets a full re-review. That must not happen in the middle of the choke-point-split batch: merge this only after epic #494 is closed.

## Task

1. In `review-rules/scope.md`, add `.github/scripts/**` to the `# Include` list. Remove nothing and add no `# Exclude` pattern.
2. In `review-rules/context.md`, add the repository scripts (`.github/scripts/`) to the "In scope here" sentence, next to the GitHub Actions workflows.
3. Add `review-rules/tasks/repo-scripts.md` — the review task for files under `.github/scripts/`. Follow the shape of `review-rules/tasks/ci-workflows.md` (an opening paragraph saying what the files are and to report nothing outside `.github/scripts/`, then numbered items, each with its severity and why it matters). Items, exactly these:
   1. A GitHub or other API call whose failure — a non-2xx response, a GraphQL `errors` array, a truncated listing or tree, a page that is not the expected shape — is treated as an empty or successful result — high. A half-read repository must never look like an empty one.
   2. A script with a dry-run mode that performs any write while in dry-run — high.
   3. A token or other secret written to stdout, stderr, a job summary, or an issue or comment body — high.
   4. Data from outside the repository's own code — an API response, an issue or comment body, a decoded payload, a CLI argument, a file another process or an agent wrote — used without being validated where it is read — medium. This is repository rule 6 in `.bb/AGENTS.md`.
   5. A sequence of writes whose header comment claims it is safe to re-run, but which a crash between two of its writes would leave in a state a re-run duplicates or loses — medium.
   6. New decision logic (a function that decides what gets written, skipped or reported) added without a `node:test` test in a sibling `*.test.mjs` file that covers each of its branches — medium.
   7. A header comment or doc comment that states inputs, environment variables or behavior the code contradicts — medium.
4. In `review-rules/severity.md`, add the repository scripts to the existing levels so the task's severities do not contradict it: under **high** — a failed API call treated as an empty or successful result, a write in dry-run mode, a secret written to output; under **medium** — unvalidated external input, a re-run-safety claim the write order breaks, new decision logic without a test, a comment that contradicts the code.
5. In `.bb/AGENTS.md`, extend the sentence "Changes to `.github/workflows/` are reviewed by the repository-root platform" so it names `.github/scripts/` as well.

## Scope

### In scope

- The root platform's scope, context, severity levels and a new task file for `.github/scripts/`.
- The one sentence in `.bb/AGENTS.md` that says which platform reviews what.

### Out of scope

- Any change to the scripts under `.github/scripts/` themselves, including adding tests to the existing ones.
- Running the scripts' tests in CI — separate issues in this batch.
- `.relay/**` review coverage.
- Any change to `backend/`, `web/` or `apple/` review rules, or to the review bot.

## Acceptance criteria

1. `review-rules/scope.md` includes `.github/scripts/**`, and every pattern it included before is still there, unchanged.
2. `node .github/scripts/check-review-scope.mjs` exits 0, and under the bot's matcher (`**` matches any characters including `/`, relative to the repository root for this platform) the new pattern matches `.github/scripts/close-completed-epics.mjs` and `.github/scripts/check-write-safety.mjs`.
3. `review-rules/tasks/repo-scripts.md` exists and contains exactly the seven items of Task 3, each with its severity and a reason, and says to report nothing for files outside `.github/scripts/`.
4. No severity in `review-rules/tasks/repo-scripts.md` disagrees with `review-rules/severity.md`.
5. `review-rules/context.md` names `.github/scripts/` among the files in scope.
6. `.bb/AGENTS.md` says `.github/scripts/` changes are reviewed by the repository-root platform.
7. No existing rule or task item in `review-rules/` is removed or weakened.
