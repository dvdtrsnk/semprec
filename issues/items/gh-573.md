**Blocked by:** #566

## Context

The review follow-ups pipeline (epic #565) has three scripts that talk to GitHub — the harvest (a daily GitHub Action), and the triage `prepare` and `publish` steps (Relay command steps). They run in two environments:

- **GitHub Actions**: the runner sets `GITHUB_API_URL`, `GITHUB_GRAPHQL_URL` and `GITHUB_REPOSITORY`; the workflow passes `GITHUB_TOKEN`.
- **Relay command steps**: Relay's loopback token proxy (dvdtrsnk/bb-plugin-relay#57) sets the same four variables — the API URLs point at `http://127.0.0.1:<port>`, and `GITHUB_TOKEN` is a placeholder the proxy replaces with the Relay App's real token.

So the scripts must reach GitHub only through those variables with `fetch`. The `gh` CLI would ignore `GITHUB_API_URL` for github.com and bypass the proxy. This issue is that access layer: one transport plus the thin endpoint functions the three scripts share, so none of them hand-rolls pagination or error handling. It follows the precedent of `.github/scripts/close-completed-epics.mjs` and `check-protected-paths.mjs`: a non-2xx response is a throw, because a half-read repository must never look like an empty one.

One GitHub quirk this layer must absorb: GraphQL reports a bot author's login **without** the `[bot]` suffix (`author { __typename: "Bot", login: "github-actions" }`), while REST reports `github-actions[bot]` — verified on #478's review thread. The pipeline compares authors against REST-style logins (`github-actions[bot]`, `bb-agent-relay[bot]`), so every author this layer returns must be in REST form.

## Task

Create `.github/scripts/review-followups/github.mjs`, a zero-dependency ES module with a header comment listing the environment variables it reads and the two environments above, exporting:

1. `createGitHubClient({ apiUrl, graphqlUrl, token, repository, fetchImpl = fetch })` returning `{ repository, request, paginate, graphql }`:
   - `request(method, path, { body } = {})` — sends `Accept: application/vnd.github+json`, `Authorization: Bearer <token>`, `X-GitHub-Api-Version: 2022-11-28`, and `Content-Type: application/json` when there is a body. Returns the parsed JSON, or `null` for 204. On a non-2xx response it throws an `Error` containing the method, the path, the status and at most 300 characters of the response text — never the token.
   - `paginate(path)` — follows `Link: <url>; rel="next"` until absent and returns the concatenated arrays; throws when a page is not a JSON array, on any non-2xx response, or after 100 pages.
   - `graphql(query, variables)` — POSTs to `graphqlUrl`; returns `data`; throws on a non-2xx response, a non-empty `errors` array (including its first message), or a missing `data`.
2. `clientFromEnv(env = process.env)` — `apiUrl` from `GITHUB_API_URL` (default `https://api.github.com`, trailing slashes removed), `graphqlUrl` from `GITHUB_GRAPHQL_URL` (default `<apiUrl>/graphql`), `token` from `GITHUB_TOKEN` and `repository` from `GITHUB_REPOSITORY` (`owner/name`). Throws naming a missing or malformed variable.
3. Read endpoints, each returning plain objects in exactly the listed shape:
   - `listIssuesWithLabel(client, label, state)` (`state`: `open` or `all`) → `[{ number, id, state, title, body, labels: string[] }]`, pull requests excluded, `body` `""` when GitHub returns `null`.
   - `getIssue(client, number)` → the same shape for one issue.
   - `listIssueComments(client, number)` → `[{ id, author, createdAt, body }]`.
   - `listMergedPullRequests(client, base)` → `[{ number, mergedAt, labels: string[] }]` for closed pull requests into `base` that have a `merged_at`, ascending by `number`.
   - `listReviewThreads(client, prNumber)` → `[{ isResolved, comments: [{ databaseId, author, body }] }]`, through GraphQL `pullRequest.reviewThreads`, paginated by cursor over threads; `author` in REST form (a `Bot` author gets `[bot]` appended; a deleted author is `"ghost"`); throws when a thread has more than 100 comments.
   - `listTreePaths(client, ref)` → a `Set` of every blob path in `GET /repos/{repo}/git/trees/{ref}?recursive=1`; throws when the response says `truncated: true`.
   - `listPullRequestCommits(client, prNumber)` → commit SHAs in the order GitHub lists them (GitHub returns at most 250).
   - `getCommitFiles(client, sha)` → every `filename` and `previous_filename` of the commit, across all pages of its files.
   - `listCommitsTouchingPath(client, { branch, path, since })` → the SHAs of `GET /repos/{repo}/commits?sha=<branch>&path=<path>&since=<since>`, all pages.
   - `listPullRequestsForCommit(client, sha)` → `[{ number, mergedAt }]` from `GET /repos/{repo}/commits/{sha}/pulls`.
4. Write endpoints:
   - `createIssue(client, { title, body, labels })` → `{ number, id }`;
   - `addLabels(client, number, labels)`;
   - `removeLabel(client, number, label)` — a 404 (the label is not on the issue) counts as done and is the only non-2xx this module does not throw on; document why at the function;
   - `closeIssue(client, number)` — `state: closed`, `state_reason: completed`;
   - `createComment(client, number, body)` → `{ id }`;
   - `addSubIssue(client, parentNumber, childId)` — `POST /repos/{repo}/issues/{parentNumber}/sub_issues` with `{ sub_issue_id: childId }` (the child's numeric `id`, not its number).
5. `github.test.mjs` next to it, using `node:test`, `node:assert/strict` and an injected fake `fetchImpl` (no network), covering every Acceptance criterion below.

## Scope

### In scope

- The transport, `clientFromEnv`, and the read and write endpoints listed in the Task, with tests.

### Out of scope

- Deciding what to read or write (harvest, prepare, publish) — later issues in this batch.
- Retries and rate-limit back-off — a failed call fails the run, which is re-run later.
- The Relay proxy itself — dvdtrsnk/bb-plugin-relay#57.

## Acceptance criteria

1. `request` sends the four headers (the content type only with a body) to `<apiUrl><path>`, returns parsed JSON, and returns `null` on 204.
2. `request` throws on a 403 and a 500 with the method, path and status in the message; a test whose fake response text contains the token asserts the token does not appear in the thrown message.
3. `paginate` follows two `rel="next"` links and returns all three pages in order; it throws when a page is an object instead of an array, and when the second page returns 502.
4. `graphql` returns `data`; it throws when the response has `errors: [{ message: "x" }]` (the message includes `x`), when `data` is missing, and on a non-2xx response.
5. `clientFromEnv` applies both defaults, strips a trailing slash from `GITHUB_API_URL`, and throws naming `GITHUB_TOKEN` or `GITHUB_REPOSITORY` when missing or when `GITHUB_REPOSITORY` has no `/`.
6. `listIssuesWithLabel` drops entries carrying `pull_request`, maps label objects to names, and maps a `null` body to `""`.
7. `listMergedPullRequests` drops closed pull requests with `merged_at: null` and returns the rest ascending by number, across pages.
8. `listReviewThreads` follows the threads cursor across two pages, maps `{ __typename: "Bot", login: "github-actions" }` to `github-actions[bot]`, keeps a `User` login unchanged, maps a `null` author to `ghost`, and throws when a thread's comments report `hasNextPage: true`.
9. `listTreePaths` returns only `type: "blob"` paths and throws on `truncated: true`.
10. `getCommitFiles` includes `previous_filename` of a renamed file and reads a second page of files; `listCommitsTouchingPath` sends `sha`, `path` (URL-encoded) and `since` as query parameters.
11. `removeLabel` resolves on 404 and throws on 500; `addSubIssue` sends `sub_issue_id` as a number; `closeIssue` sends `state_reason: "completed"`.
12. `getIssue` returns `{ number, id, state, title, body, labels }` for one issue, with label names and `""` for a `null` body.
13. `listIssueComments` returns `{ id, author, createdAt, body }` across pages, with `author` taken from `user.login` (for example `github-actions[bot]`) — the field the pipeline's trust checks compare.
14. `listPullRequestCommits` returns the commit SHAs in the order listed, across pages.
15. `listPullRequestsForCommit` returns `{ number, mergedAt }` for each pull request of the commit.
16. `createIssue` sends `title`, `body` and `labels` to the issues endpoint and returns `{ number, id }`.
17. `addLabels` sends `{ labels }` to the issue's labels endpoint.
18. `createComment` sends `{ body }` to the issue's comments endpoint and returns `{ id }`.
19. `node --test .github/scripts/review-followups/github.test.mjs` passes with no network access.
