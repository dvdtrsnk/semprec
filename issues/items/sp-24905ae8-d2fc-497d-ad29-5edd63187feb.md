**Model tier:** medium

## Context

Model tier rationale: One read-model extension in an existing store and route with existing fixtures; no write path, tenancy or migration change.

The owner wants to open the attachments of an Inbox item while processing Inbox cards in the mobile app. The diary's Inbox entries already carry their attachments (`JournalInboxAttachmentSummary` in `backend/packages/data/src/inbox/journalInboxCompute.ts`: `attachmentId`, `blobId`, `name`, `mimeType`, `thumbnailBlobId`, `source`), but a card of `GET /api/inbox/cards` whose `resolvedSource.kind` is `inboxItem` (`backend/packages/data/src/inbox/inboxCardsStore.ts`) names only the item's id, text, date, time and type, so the app cannot know the files. Bytes are served by `GET /api/blobs/:id`.

## Task

1. Add `attachments` to the `inboxItem` variant of `InboxCardResolvedSource`: the item's Inbox attachments in the order the diary lists them, each with the same fields as `JournalInboxAttachmentSummary`, read with the existing attachment store in the same transaction and tenant scope as the cards, with one query for all cards of a page (no per-card query).
2. Update the cards route's response schema or route matrix entry if one describes this shape, and the web types that decode a card, if any, so they accept the new field.

## Touches

- `backend/packages/data/src/inbox/inboxCardsStore.ts` and its tests
- `backend/packages/data/src/inbox/inboxAttachmentsStore.ts` (a batched read, if none exists)
- the route matrix or schema of `GET /api/inbox/cards`, if any
- `web/src/` card types, if any decode `resolvedSource`

## Scope

### In scope

- The `attachments` field of `inboxItem` sources of `GET /api/inbox/cards`.

### Out of scope

- Transcript sources, thumbnails generation, the mobile app (a sibling issue of this batch).

## Acceptance criteria

- A card whose source is an Inbox item with two attachments answers both, with `blobId`, `name`, `mimeType`, `thumbnailBlobId`, `source` and `attachmentId`, in the diary's order; one without attachments answers `[]`.
- Attachments of another tenant's item never appear (isolation test through the runtime role).
- A page of cards reads the attachments with one query; a test proves the count does not grow with the number of cards.
