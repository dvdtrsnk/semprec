**Model tier:** low

## Context

Model tier rationale: The exact directive block and writable paths are copied into seven units with grep assertions.

The Semprec units carry no sandboxing at all.
- The four long-running services (`deploy/systemd/semprec-api.service`, `semprec-agents.service`, `semprec-transcribe.service`, `semprec-ai-gateway.service`, each `[Service]` from `:9`) set only `User=`/`Group=semprec`, the environment files, `ExecStart=` and restart policy.
- The `semprec`-user oneshots `semprec-dead-man.service`, `semprec-failping@.service` and `semprec-trash-purge.service` (`:4-10`) do the same.

A compromised process can therefore:
- write anywhere `semprec` can: both blob roots for every tenant, the shared `/tmp`, `/var/tmp` and `/dev/shm`;
- see every process on the host;
- use any syscall, socket family or device node `semprec` may open.

This tenant-holding host now runs one process for many users, so one exploited parser — a mail attachment, an uploaded file through ffmpeg, a provider response — must not reach beyond what that process needs.

What each process writes:
- semprec-api writes `FILES_STORAGE_DIR` and `MAIL_ATTACHMENTS_DIR` (`/opt/semprec/data/files`, `/opt/semprec/data/mail-attachments`; `backend/packages/data/src/mail/blobStorage.ts:111`).
- semprec-transcribe writes and deletes blobs in `FILES_STORAGE_DIR` (`backend/services/semprec-transcribe/src/mediaNormalization.ts:62,283`) and temporary files under `os.tmpdir()` (`:74`).
- semprec-agents and semprec-ai-gateway write no files.
- The timer scripts only run `curl` (`deploy/systemd/scripts/semprec-dead-man.sh`, `semprec-failping.sh`) or nothing (`semprec-trash-purge.sh`).

#1070 moved stdio MCP servers into their own socket-activated sandbox. The api and agents now only connect to `/run/semprec-mcp-launch.sock` and spawn no setuid program, so `NoNewPrivileges=` is safe for them. #996 and #1070 edited the same unit files' environment and dependency lines.

## Task

Load `io-hardening` (process-level containment of every edge these services own).

1. **Baseline.** Add these lines to the `[Service]` section of `semprec-api.service`, `semprec-agents.service`, `semprec-transcribe.service`, `semprec-ai-gateway.service`, `semprec-dead-man.service`, `semprec-failping@.service` and `semprec-trash-purge.service`:
   ```
   NoNewPrivileges=yes
   ProtectSystem=strict
   ProtectHome=yes
   PrivateTmp=yes
   PrivateDevices=yes
   ProtectKernelTunables=yes
   ProtectKernelModules=yes
   ProtectKernelLogs=yes
   ProtectControlGroups=yes
   ProtectClock=yes
   ProtectHostname=yes
   ProtectProc=invisible
   RestrictNamespaces=yes
   RestrictRealtime=yes
   RestrictSUIDSGID=yes
   LockPersonality=yes
   RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK
   SystemCallArchitectures=native
   SystemCallFilter=@system-service
   SystemCallErrorNumber=EPERM
   CapabilityBoundingSet=
   AmbientCapabilities=
   UMask=0027
   ```
   Deliberately absent, each with a one-line comment in the unit:
   - `MemoryDenyWriteExecute=`: V8's JIT needs writable-executable pages;
   - `ProcSubset=pid`: it hides `/proc/cpuinfo` and `/proc/meminfo`, which Node's `os` module reads;
   - `PrivateUsers=`.
2. **Writable paths.** Only these units get write access:
   - `semprec-api.service`: `ReadWritePaths=/opt/semprec/data/files /opt/semprec/data/mail-attachments`;
   - `semprec-transcribe.service`: `ReadWritePaths=/opt/semprec/data/files`.

   Add a comment in each: the paths must equal `FILES_STORAGE_DIR` / `MAIL_ATTACHMENTS_DIR` from `/opt/semprec/shared/env/settings.env`, and changing either variable requires changing the unit. The directories are created by `provision.sh` (`ensure_release_tree`), so these lines need no `-` prefix.
3. **Untouched units.** Leave the root units `semprec-backup.service` and `semprec-restore-test.service`, which drive Docker and restic. Leave `semprec-mcp-launch@.service`, which #1070 already sandboxed.
4. **Tests.** In `deploy/provision.test.sh`, for each of the seven units, assert:
   - every baseline line (`grep -qx`);
   - the absence of `MemoryDenyWriteExecute`, `ProcSubset` and `PrivateUsers`;
   - the exact `ReadWritePaths=` line on the api and transcribe units, and none on the other five.
5. **README.** Append a "Service sandboxing" section to `deploy/README.md`, directly after #1070's "stdio MCP sandbox" section (the file's last), with:
   - the baseline, each writable path, and the three omissions with their reasons;
   - the host check after provisioning:
     - `systemd-analyze security semprec-api.service` (and each other unit) no longer reports `UNSAFE`;
     - `deploy.sh` reports every version;
     - a file upload and download work;
     - a transcription job completes (ffmpeg under the filter);
     - an admin's stdio MCP server still connects through the launcher.

## Acceptance criteria

- Each of the seven installed units contains every baseline line from Task 1 and none of `MemoryDenyWriteExecute`, `ProcSubset` or `PrivateUsers` (shell test, `deploy/provision.test.sh`).
- `semprec-api.service` has exactly `ReadWritePaths=/opt/semprec/data/files /opt/semprec/data/mail-attachments`, `semprec-transcribe.service` exactly `ReadWritePaths=/opt/semprec/data/files`, and the other five units no `ReadWritePaths=` (shell test, `provision.test.sh`).
- The existing unit assertions still hold (`OnFailure=`, `StartLimit*`, `TimeoutStopSec=`, `EnvironmentFile=`), and `systemd-analyze verify` still runs over every installed unit (shell test, `provision.test.sh`).
- On a provisioned host, the README host check passes (manual host check by the maintainer at the first deploy after this change):
  - every long-running service starts and `deploy.sh` reports its version;
  - uploads, downloads, a transcription and a stdio MCP tool call succeed;
  - `systemd-analyze security` reports no unit as `UNSAFE`.
- `deploy/README.md` documents the baseline, each writable path, the three omissions with reasons, and the host check (review).
