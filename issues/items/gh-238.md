## Context

The data choke-point (`createItem`, `updateItem`, `query`, …) already owns every business rule — `owner`, `locked`, idempotency, `ifVersion` — but it has no HTTP projection yet. This is the first of three slices that establish the HTTP adapter law before any endpoint family is mounted: it delivers the adapter foundation itself (authentication, validation, status mapping, serialization) and the two wire contracts every later endpoint speaks — the item envelope and the error contract. #239 builds the ModuleRegistry custom-route manifest and collision detection on top of this adapter, and #154 adds the static and contract-test enforcement that route handlers can never write core tables. #155, #156, #157 and #158 mount the concrete generic endpoint families through the adapter established here.

## Task

Create the `semprec-api` REST adapter as a thin adapter over the existing choke-point package — the adapter must contain no business logic of its own, only mapping of the HTTP request onto the service function and of the result onto the HTTP response. Deliver:

- **Shared authentication**: every route authenticates through the auth layer from #143 (httpOnly session cookie on the web, Bearer token for native clients); there is no third path and no per-route opt-out.
- **Shared request validation** of path parameters, query parameters, headers, and JSON bodies, failing with the `validation_failed` error defined below.
- **Status mapping and serialization** shared by all routes: a single place that maps choke-point results and choke-point errors (`ChokePointError` subclasses in `packages/data`) onto HTTP status codes and response bodies.
- **The item envelope**, defined exactly as `{ id, databaseId, properties, computed, updatedAt, deletedAt }`. `computed` is read-only (a write attempt is `computed_readonly`); `updatedAt` doubles as the `ifVersion` token for the next update — there is no separate `version` counter. Every successful write returns the full authoritative row state in this envelope, never an empty 204.
- **The error contract** `{ error: { code, details } }` with the closed enum of `code` values `owner_violation`, `computed_readonly`, `schema_locked`, `property_locked`, `version_conflict`, `validation_failed`, `not_found`, `approval_required`, and `heartbeat_event_triggered`. `code` is a stable, machine-readable enum (a contract primarily for agents); text localization happens client-side, the server sends no message text that a client is expected to display. Each code has one deterministic HTTP status and a documented required `details` shape, exported from the adapter as a single code→status table so later slices cannot drift. Fixed by the approved behavior: `version_conflict` → 409 and carries `details.currentItem` (the authoritative current item envelope); `approval_required` → 403 and `details` links to the resulting approval request (unlike the in-process AgentTool adapter, which translates it into a synthetic success instead); `computed_readonly`, `schema_locked`, `property_locked` → 403; `not_found` → 404. The remaining codes (`owner_violation`, `validation_failed`, `heartbeat_event_triggered`) each receive one deterministic status recorded in the same table.
- **Contract evolution rule**: there is no URL versioning (`/api/v1/…`); contract changes are additive only (new fields, endpoints, and error codes — never a breaking change without a transition period). Document this rule next to the adapter.

The adapter is mounted in the `semprec-api` process but ships no generic resource routes yet; contract tests exercise it through fixture handlers. Custom-route registration through ModuleRegistry manifests is added by #239.

## Scope

### In scope

- Adapter foundation in `semprec-api`: shared auth, validation, status mapping, serialization.
- The item envelope and the full-row-on-write rule.
- The error contract, the nine codes, their statuses and required `details`, and the exported code→status table.
- Contract tests for the above.

### Out of scope

- ModuleRegistry route manifests, mounting into flat `/api`, path-collision fail-fast, and the custom-route exception policy — #239.
- The dependency-cruiser choke-point write rule and the handler contract tests proving handlers cannot write core tables — #154.
- Concrete generic resource endpoints (#155, #156, #157) and file/blob endpoints (#158).
- WebSocket, MCP, and AgentTool adapters.

## Acceptance criteria

- Every error code/status/details mapping is covered by a test: each of the nine codes produces its documented status and `{ error: { code, details } }` body, `version_conflict` includes `details.currentItem`, and `approval_required` includes the link to the resulting approval request.
- Every successful write serializer returns a full row in the `{ id, databaseId, properties, computed, updatedAt, deletedAt }` envelope; no success path produces an empty 204.
- An unauthenticated request to any route mounted through the adapter is rejected by the shared auth layer before the handler runs; an invalid body/param produces `validation_failed`.
