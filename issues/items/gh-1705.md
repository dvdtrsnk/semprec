**Model tier:** low

## Context

Model tier rationale: A data-only addition of colors to four existing options through the color mechanism and cutover that already exist, with no new contract.

The Inbox card and the health-record filter show tags as colored chips: Blood pressure red, Prevention green, Medication purple, Blood tests orange. #1584 gives select options an optional `#RRGGBB` `color`, projects it through `GET /api/schema`, and adds a per-tenant cutover (`backend/packages/data/src/seed/selectOptionColorsCutoverMigration.ts`) that sets colors listed in a table on options that have none. #1700 adds the two new tag options (Blood pressure, Prevention). This issue only supplies the Health records tag colors to that mechanism, in the seed and in that cutover's table. Epilepsy and Dental hygiene have no color in the design and stay uncolored. The Health records `status` colors come from #1584 itself.

What builds on it: #1836 edits the same seed and cutover files.

Decision: colors are Blood pressure `#FF2D55`, Prevention `#34C759`, Medication `#AF52DE`, Blood tests `#FF9500`.

## Task

Load `db-migrations` and `testing`.

1. In `backend/packages/data/src/seed/seedTenDatabases.ts` set those four colors on the Health records `tags` options for new tenants, using the option shape from #1584.
2. Add the same four entries (Health records, `tags`, option key, color) to the color table of the cutover in `selectOptionColorsCutoverMigration.ts`, so existing tenants receive them. The cutover's rules are unchanged: only an option that has no color is colored, and a color a user has already set stays.
3. Tests: a new tenant's `GET /api/schema` returns the four colors on `tags` and none on `epilepsy` and `dentalHygiene`; an existing tenant after the cutover has the same; a pre-set color is preserved; a second run changes nothing.

- When an option already has a color, then the cutover leaves it unchanged; a second run changes nothing.
