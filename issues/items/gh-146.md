**Blocked by:** #236, #115

## Context

Issue #236 delivers the catalog format, registry loading and validation, and the resolver, verified on one reference module. Every other system module still lacks its catalogs. This slice completes the translation content so #147 can localize API responses and AGENT.md for every system database, property, option, view type, and agent tool.

## Task

Add `i18n/cs.json` and `i18n/en.json` beside every system module manifest, using the format and canonical keys defined in #236. Move the existing Czech labels without semantic changes and add complete English labels for every `database.<db>.name`, `property.<db>.<property>.name`, `property.<db>.<property>.option.<option>`, `viewType.<type>.name`, and `agentTool.<tool>.label` key the module owns. Add catalog coverage tests that enumerate every system database, property, option, view type, and agent tool key from the seeds and manifests and fail when a key is missing from either locale of the owning module.

## Scope

### In scope

- Complete cs/en catalogs for all system modules and the coverage tests.

### Out of scope

- Catalog loading, validation, and the resolver — delivered by #236.
- Runtime-editable translation tables and third locales.
- API/AGENT.md integration, delivered by #147.

## Acceptance criteria

- Registry tests load every module's cs/en files.
- Catalog coverage tests enumerate every system database/property/option/view/tool key and pass for both `cs` and `en`.
- Czech label text equals the pre-migration Czech labels for every key that existed before.
