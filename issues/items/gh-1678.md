## Context

Model tier rationale: One new read-only HTTP route with a version header over existing doc-loading and serialization seams, but the ETag must stay stable across compaction, which needs a careful, tested derivation.

Pages (docs of kind `page`) have no HTTP surface today: `backend/services/semprec-api/src/routeMatrix.ts` lists no doc route, and the only way to read a page is the realtime doc sync. A doc also has no version a client can compare: `DocDbRow` in `backend/packages/data/src/docs/docsStore.ts` is `{id, item_id, kind, created_at}`, and `backend/packages/data/src/docs/docPersistence.ts` compaction deletes the `doc_updates` ids, so row ids cannot serve as a version.

Clients (web, desktop, the assistant) need to read a page as Markdown and later write it back safely. This issue delivers the read half: the page body as canonical Markdown plus a version token. #1608 provides the serializer that turns the doc's blocks into canonical Markdown; #1394 records the page operation family (names, naming of the read operation, and the rule that a read never creates a doc). The write halves #1765 (replace, guarded by this token with If-Match) and #1679 build on it; #1844 and #1751 consume the read operation for agents.

The title is not part of the Markdown. A root page stores its title separately and a subpage's title is the link text in its parent, so the body never starts with the title.

Decision: the version is `base64url(sha256(Y.encodeSnapshot(Y.snapshot(doc))))`, sent as a strong quoted ETag. A Yjs snapshot is the state vector plus the delete set, so a write that only deletes text changes it (the state vector alone does not change on pure deletion), while compaction rewrites storage but not the logical doc and so leaves it unchanged.

Shared-file ordering: this issue also waits for #1676 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

Decision (batch 38 R1 reconciliation): R1 reconciliation: repeated page blocks referencing one page id retain each block's own caption. page.get with format markdown is the catalog read; page.md is its HTTP binding. Snapshot-hash equality is not equality of visible content across distinct CRDT histories.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. In `backend/packages/data/src/docs/`, add a read function (for example `readPageMarkdown(client, itemId)`) that: finds the item's page doc with `getDocByItemId` (never `getOrCreateDoc`), loads it with `loadDocWithClient`, and returns `{markdown, etag}`. With no doc it returns an empty body and the ETag of an empty doc (`new Y.Doc()` snapshot), so the same token applies once the doc is created lazily by a later write.
2. Add `docEtag(doc)` computing `base64url(sha256(Y.encodeSnapshot(Y.snapshot(doc))))`, exported for #1765 to reuse for the If-Match comparison.
3. Produce the Markdown with the serializer from #1608; the body contains no title and no `# ` line for it. A `# Heading` block in the doc is serialized as the blocks say (an `h1` block), unrelated to the title.
4. Add `GET /api/items/:id/page.md` in a new `backend/services/semprec-api/src/pageMarkdownHandler.ts`, wired into `app.ts` next to the other listeners. Authenticate with `authenticateRequest`, run in the caller's tenant, respond `200` with `Content-Type: text/markdown; charset=utf-8`, `ETag`, and `Cache-Control: no-store`. A missing or foreign item id returns the same `404` body as the existing item routes; an item that cannot host a page (a light host) returns `400`.
5. Register the operation under the name chosen in the ADR from #1394 in the generic operation catalog (`operationNames`, `schemas`, `capabilities`, `bindings`, `port`, and the application service), with the route above as its HTTP binding, so MCP and agents can reach the same read.
6. Add the route to `routeMatrix.ts` (`tenancy: "tenant"`) and to the tenant-isolation route test.
7. Tests: the ETag is identical across two reads with a compaction between them; a write that only deletes text changes it; a read of an item without a doc returns an empty body, `200`, and creates no `docs` row; a foreign tenant's item returns `404`.

## Scope

### In scope

- Reading a page as Markdown over HTTP, with the content-derived ETag, without ever creating a doc.

### Out of scope

- Replacing page content and the If-Match check: #1765.
- Inserting content at a placement: #1679.
- Agent capability classification, approval and grants for the operation: #1844.
- A last-edited time or editor on the doc: tracked by #1405.

## Acceptance criteria

- When a page is read twice with no change between them, then both responses carry the same `ETag`, even if a compaction ran in between.
- When a write only deletes text from the page, then the next read returns a different `ETag`.
- When an item has no doc, then `GET /api/items/:id/page.md` returns `200` with an empty body and no `docs` row exists afterwards.
- When the page contains blocks, then the body is the canonical Markdown of #1608 and does not contain the page title.
- When the item belongs to another tenant or does not exist, then the response is `404`.
- When the request is unauthenticated, then the response is `401`.
