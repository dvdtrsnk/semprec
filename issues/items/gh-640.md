## Behavior specification (approved)

Every mechanism below exists in the codebase, is unit/integration tested, and is never invoked by a production process. The production composition roots (`backend/services/semprec-api/src/serve.ts` + `queueRuntime.ts`, `backend/services/semprec-agents/src/serve.ts` + `queueRuntime.ts`, `deploy/deploy.sh`) pass empty registries or `undefined` adapters, so tests inject the real handlers and a green CI proves nothing about composition. The goal of this batch is that a fresh `deploy.sh` install of `develop` produces a system in which the seeded heartbeats execute, approved destructive operations replay, the mail crontab jobs run without throwing, crashed agent runs are repaired at startup, MCP-credential runs are closed when their credential lapses, the system databases exist, uploaded bytes live under `/opt/semprec` and are backed up. Each issue wires exactly one mechanism and adds a composition-level test (an integration test that builds the real runtime the way `serve.ts` does and asserts the handler/adapter is present, or an e2e test).

## Decisions

- **Register every seeded action id, not only `core.agentRun` and `core.agentGuidanceDrift`.** The audit named two; the code seeds ten (`KNOWN_HEARTBEAT_ACTION_IDS`), all failing identically. Registering two would leave the same error on eight heartbeats. `semprec.tick` is the one exception: its handler needs an injected LLM proposal computation (`ComputeSemprecProposalFn`) that no composition provides — it stays unregistered and is reported as a separate finding.
- **`core.agentRun` is registered with a placeholder `RunAgentFn` that throws** ("agent session runtime is not wired") rather than a silent no-op, so a fired `newEmail` heartbeat produces an `agent_runs` row in `error` with the real reason instead of a fake `done`. The real function arrives with the agent-session issue.
- **Startup repair ships before the agent runtime.** `repairInterruptedRuns` only needs the `@semprec/agent-runtime` dependency and `serve.ts`; the repair issue adds the dependency and the agent-session issue builds on it, instead of the other way around.
- **MCP-credential runs are closed by an hourly sweep on credential expiry.** No revocation path exists; the sweep is a new core task (`mcpRunCredentialExpirySweep`, api affinity) rather than a fold into an unrelated sweep. Startup repair excludes `triggered_by='mcp'` runs so a restart does not mass-error them.
- **Mail transports stay on the no-op adapter factory.** Only `mailModuleIds` (and the attachment storage default) are wired; a real IMAP/Gmail/Graph adapter has nothing to connect with until mailbox onboarding (server settings, credential storage, OAuth exchange) exists — a separate finding.
- **The agent-session issue targets pi's `pi-messages` wire protocol at the AI gateway.** `registerPiProviders` assumes the gateway proxies provider APIs; it does not. The session composition is written against `POST <AI_GATEWAY_BASE_URL>/messages`; that gateway route is a prerequisite owned outside this batch and is reported as a finding.
- **Blob storage directories are required in production, `/tmp` only under `NODE_ENV=test`.** A missing `FILES_STORAGE_DIR`/`MAIL_ATTACHMENTS_DIR` fails startup instead of silently writing to `/tmp`.
- **Persisting blob storage and backing it up are two issues.** Provisioning the directories and switching the code defaults is one mechanism; replacing the MinIO backup/restore-test with those directories is another and depends on the first.
- **Seeding is a `deploy.sh` step after migrations under `SEMPREC_MIGRATE_DATABASE_URL`**, via a new `runSeedCli.js` that mirrors `runMigrationsCli.js`; `seedSystem` takes `pg_advisory_xact_lock` inside its own transaction so two concurrent seeds cannot race.

## Out of scope

- The `mailsync:<id>` process-heartbeat expectation in `backend/packages/data/src/health/processHeartbeats.ts:93-101` (ops epic).
- Removing MinIO from `deploy/docker-compose.yml` (it stays, documented as unused).
- A pi-compatible streaming egress on `semprec-ai-gateway`, mailbox onboarding (server settings, credential route, OAuth), the `semprec.tick` proposal computation, and the api process registering its own view types (`temporal-switcher`, `mailbox-client`, ...) outside `seedSystem` — each reported as a separate finding.
- The Semp conversation / supervisor HTTP surface, delegation registry hosting, and the Gmail/Graph push lifecycles.
