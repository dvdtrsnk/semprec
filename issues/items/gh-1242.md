## Context

Model tier rationale: One test file; three fixed sleeps become polls on the state the test already asserts, using the file's existing `waitFor` helper.

`backend/packages/agent-runtime/src/__tests__/delegationRegistry.test.ts`, test "records the stored error run_status, not done, when its TTL fires on a run another writer already closed as error", failed in CI on pull request #1241 (`integration-shard (3)`, 2026-10-22). The failure was `expected [ 'running' ] to deeply equal [ 'running', 'error' ]` at line 350. A rerun of the same commit passed, and the PR changed only an unrelated unit test.

The test waits a fixed `ttlMs + 150` ms after the TTL is armed, then reads the `run_status` events that `expire()` writes asynchronously. Under CI load, 150 ms is not always enough. The file already has a `waitFor(predicate, message)` helper (a `vi.waitFor` wrapper with a 5 s timeout) for exactly this, and two other tests use the same fixed sleep before they observe `expire()`'s writes: the test at line 290 and the one at line 519 both wait for the run to become `done`.

## Task

Load `testing`.

1. In the three tests that sleep `ttlMs + 150` and then assert a write that `expire()` makes, replace the sleep with `await waitFor(…)` on that same observable state:
   - line 290: the run's `agent_runs.status` is `done`;
   - line 339: the run's `run_status` events are `["running", "error"]`;
   - line 519: the run's `agent_runs.status` is `done`.

   Keep every existing assertion after the wait unchanged.
2. Do not touch the sleeps that time a window on purpose (lines 388, 468, 653), or the one at line 703, where the asserted state already holds before the TTL fires and the sleep only lets the TTL elapse.
3. Run the test file 30 times in a row and report the result in the pull request.
