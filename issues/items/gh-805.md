## Context
Review of pull request #393 found that the skills table row for `adr-conventions` in `.bb/AGENTS.md` (currently around line 40) still says to load that skill when "introducing a cross-cutting pattern no ADR covers", while the `adr-conventions` skill's own description (`.bb/skills/adr-conventions/SKILL.md`) and `.bb/AGENTS.md`'s own line 17 state the actual threshold as "no rule and no ADR covers" / "no existing ADR and no review-rules/ line covers". The table row omits the `review-rules/` half of the threshold, so a reader following only the table could under-trigger the skill.

The same stale row exists verbatim in the skills table of `.bb/skills/implement-issue/SKILL.md` (currently around line 41). Fixing only `.bb/AGENTS.md` would leave the two tables contradicting each other, so both rows are fixed together.

Issue #653, which also touched `.bb/AGENTS.md`, is closed, so this issue has no remaining dependency.

## Task
- In `.bb/AGENTS.md`'s skills table, reword the `adr-conventions` row's trigger condition to match the threshold already stated on line 17 ("no rule and no ADR covers" / "no existing ADR and no review-rules/ line covers"), so the table and the prose agree.
- Apply the identical rewording to the `adr-conventions` row of the skills table in `.bb/skills/implement-issue/SKILL.md`, so both tables carry the same text.

## Touches
- .bb/AGENTS.md (the `adr-conventions` skills-table row only)
- .bb/skills/implement-issue/SKILL.md (the `adr-conventions` skills-table row only)

## Scope
### In scope
- The wording of the `adr-conventions` row's trigger condition in the skills tables of `.bb/AGENTS.md` and `.bb/skills/implement-issue/SKILL.md`.

### Out of scope
- Any other row or section of `.bb/AGENTS.md` or `.bb/skills/implement-issue/SKILL.md`.

## Acceptance criteria
- The `adr-conventions` skills-table row's trigger condition names both "no rule" and "no ADR" (or equivalently "no review-rules/ line and no ADR") as the threshold, matching line 17's wording.
- The `adr-conventions` row in `.bb/skills/implement-issue/SKILL.md`'s skills table carries the same trigger wording as the row in `.bb/AGENTS.md`.
