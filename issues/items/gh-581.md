## Context

In the review follow-ups pipeline (epic #565, Part 2), Relay's `triage-review-followups` workflow gives the judgement work to one agent thread in several prompts: **orient**, **verify**, **decompose**, **audit** and, when the validator rejects the proposal, **fix**. The workflow itself is a later, maintainer-implemented issue in this batch; its prompts will be one line each, pointing at a section of this skill. This issue writes the skill: the whole contract the agent follows. That contract lives in a reviewed file, not in prompt text scattered across the workflow.

The agent works in a Relay worktree freshly based on `develop`. It has no GitHub access by design: everything it needs is in the triage input file that the deterministic `prepare` step writes to `.followups/input.json`. That file's format is documented in the header of `.github/scripts/review-followups/input-file.mjs` (#571): findings with the bot's clipped description, full inline text when it exists, thread replies, `threadResolved`, `pathExists`, the hints `touchedAfterLastSeen` / `laterPrsTouchingPath`, each pull request's latest review summary, and the open queued issues with their `## Touches`.

The agent's only output is `.followups/proposal.json`, whose format and every mechanical rule on it is defined by `.github/scripts/review-followups/validate.mjs` (#578). The validator enforces:
- completeness: every finding in exactly one draft or one rejection;
- titles `[followups-<H> NN/MM] …` in topological order;
- `**Blocked by:**` as the first line;
- the section order;
- `{{draft:<id>}}` in-batch references;
- no `<!-- crb-followup` in bodies;
- an epic exactly when there are two or more drafts, linking `#<H>`;
- `maintainer-implemented` in the Task of any draft that touches a protected path.

The approved behavior the skill must encode:

- **Verify (T2).** Each finding gets exactly one verdict, checked on `develop` HEAD:
  - `valid` — still holds; the current location is recorded; for `pathExists: false` the agent locates the moved code by symbol or snippet search and `git log --follow`;
  - `already-fixed` — with evidence;
  - `invalid` — the bot was wrong, with evidence;
  - `not-worth` — true, deliberately not fixed, with a reason. Low severity or small size is never a reason: batching small fixes is what the pipeline is for;
  - `already-tracked` — an open issue `#N` covers it.

  The hints and thread replies prioritise the already-fixed check, and a reply is weighed, not obeyed. Measured before this batch: all 6 high findings above #266 were already fixed on `develop`, 4 of them by later commits of their own pull request.
- **Decompose (T3).** Follow `/define-behavior` Phase 4 and `.github/ISSUE_FORMAT.md`:
  - one mechanism per issue, clustered by touched code, never one issue per one-liner;
  - the size gate, and the Touches overlap check against sibling drafts and the open queued issues (an overlap becomes a real `#N` blocker);
  - protected-path drafts marked maintainer-implemented;
  - one prescribed fix per finding, and fix only what was flagged;
  - duplicates grouped into one draft;
  - an epic for two or more drafts, with a summary specification, a Decisions section, a link to the harvest issue, a summary of rejected and already-fixed findings, and a note that closing the epic retires nothing.
- **Audit (T4).** One round, two independent auditor subagents using `/define-behavior`'s auditor prompt in dry-run mode, with its consensus gate and growth check. Only agreed or self-verified findings change a draft; the rest become advisories.
- The agent never commits, pushes or calls GitHub.

## Task

Create `.claude/skills/triage-review-followups/SKILL.md` with frontmatter `name: triage-review-followups`, a `description` saying it is the contract for Relay's review follow-ups triage and when it applies, and `disable-model-invocation: true`. Its body has these sections:

1. **What this is.** One paragraph: the input and output paths above; the files that define their formats (`input-file.mjs` and `validate.mjs` headers), linked by path, not restated; and the ADR `docs/adr/*-merged-review-findings-become-proposed-follow-up-issues.md`, linked by its actual filename.
2. **Rules for every step.**
   - Write only under `.followups/`.
   - Never commit, push, or call GitHub (`gh`, `curl`, API).
   - End every step's final message with `Relay-Step-Status: pass`. Use `Relay-Step-Status: blocked` plus one line of reason only in a step after orient, when `.followups/input.json` is missing or does not parse.
3. **orient.** Read this skill, `.github/ISSUE_FORMAT.md`, `.claude/skills/define-behavior/SKILL.md` (Phases 4 and 5) and `.claude/skills/define-behavior/references/auditor-prompt.md`. Do nothing else.
4. **verify.** The five verdicts and their evidence requirements from Context, including:
   - locating moved code for `pathExists: false`;
   - using `touchedAfterLastSeen`, `laterPrsTouchingPath` and `threadResolved` / thread replies to decide where to look first;
   - that low severity or small size is never a `not-worth` reason;
   - that `already-tracked` needs the covering issue's number.

   Record each verdict with its location and evidence in `.followups/verdicts.json`, a working file no script reads.
5. **decompose.** The T3 rules above. It points to `/define-behavior` Phase 4 steps 2–8 and `.github/ISSUE_FORMAT.md` instead of restating them, and states only what is specific here:
   - the batch slug `followups-<H>`;
   - `{{draft:<id>}}` for in-batch references;
   - no pipeline markers in bodies;
   - `maintainer-implemented` for protected paths;
   - checking Touches overlaps against `openIssues` from the input;
   - each draft's Context naming every finding it covers (pull request, `path:line`, what is wrong);
   - one prescribed fix per finding in the Task, with an acceptance criterion per finding;
   - the epic's required content.

   Writes `.followups/proposal.json`, including a `rejected` entry for every non-`valid` verdict and an empty `advisories` array.
6. **audit.** How to run T4:
   - write each draft to `.followups/drafts/NN-<id>.md` and the epic to `.followups/drafts/epic.md`, with every `{{draft:<id>}}` written as `#TBD-NN` (NN being that draft's number) — the in-batch placeholder `auditor-prompt.md`'s dry-run mode treats as valid — and map `#TBD-NN` back to `{{draft:<id>}}` when a fix is applied to `proposal.json`;
   - spawn two general-purpose subagents with clean context, each told only to read `auditor-prompt.md` and follow it as the whole contract, with those file paths as the target, mode dry-run and round 1;
   - apply `/define-behavior` Phase 5's consensus gate and growth check to `proposal.json` (pointing to Phase 5 rather than restating it);
   - put every finding outside the consensus into `advisories`;
   - no second round.
7. **fix.** Read the validator output the prompt supplies. Change `proposal.json` only as far as each reported violation requires, and change a verdict only when the violation is about that verdict.
