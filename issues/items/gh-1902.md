**Blocked by:** #1896
**Model tier:** medium

## Context

Model tier rationale: One cleanup step called from the send path and the ingest path inside their existing transactions, with a precise rule about which drafts to leave alone.

If the user answers a thread on their own after Semp prepared a draft, the draft is outdated and must disappear. After #1504 an agent draft has a source message and a `created_by` in the draft metadata; sending a draft over HTTP is #1896 (`sendDraftEmail` in `mail/send.ts`); a message the user sent from another client arrives through ordinary ingest into the Sent folder.

Decision: only drafts with `created_by` agent are retired; the draft that is itself being sent is never retired.

## Task

Load `state-writes` and `testing`.

1. Add `retireSupersededSempDrafts(client, { threadId, ownMessageDate, excludeDraftItemId })` in `mail/draftRetirement.ts`: soft-deletes (through the choke point soft delete) every not-deleted unsent agent draft of the thread whose source message is older than `ownMessageDate`.
2. Call it in the same transaction from the finalize step of `sendDraftEmail` (excluding the sent draft), and from `ingestEmailMessage` when the ingested message is the tenant's own (sender address is one of the `Mailboxes.addresses`, or the message is in the Sent folder) and belongs to a thread.
3. Publish the usual thread invalidation for the affected thread.

## Touches

- backend/packages/data/src/mail/draftRetirement.ts (new)
- backend/packages/data/src/mail/send.ts (finalize step)
- backend/packages/data/src/mail/ingest.ts
- backend/packages/data/src/mail/__tests__/ (new tests)

## Scope

### In scope

- The retirement function and its two call sites.

### Out of scope

- Creating Semp drafts (#1941); counting them (#1694).
- Retiring drafts edited by the user.

## Acceptance criteria

- When the user sends their own reply in a thread, the thread's agent draft is soft-deleted and `hasSempDraft` becomes false.
- A reply the user sent from another client that is ingested later has the same effect.
- When the user sends the Semp draft itself, nothing else is affected; a draft with `created_by` user stays.
