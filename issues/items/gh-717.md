## Context

`web/vite.config.ts` (lines 11-19) proxies exactly five path prefixes to `semprec-api`: `/api/ai-usage`, `/api/system-health`, `/api/approval-requests`, `/api/agent-runs`, `/api/setup`. Every other request the client makes stays on the Vite dev server, which answers any unknown path with `index.html` (HTML, status 200):

- `web/src/api/httpGenericOperations.ts` requests `/databases/:id/items/query`, `/databases/:id/items/count`, `/databases/:id/items/:itemId`, `/views/:id`, `/operations/:id` under `baseUrl` `/api` (`main.tsx` line 26: `import.meta.env.VITE_API_BASE_URL ?? "/api"`), so every `ViewHost`/mailbox/journal read gets HTML and `response.json()` throws — the UI shows a `retryable` error for every view in development.
- `web/src/api/mcpAgentPageOperations.ts` requests `/projects/:id/mcp-grants` and `/mcp-tool-registrations/:id` — same failure on the AGENT page.
- `/api/auth/*` (needed by sibling issue G3 of this batch), `/api/blobs/:id`, `/api/files` and the `/api/sync` WebSocket upgrade are not proxied either, and no entry sets `ws: true`.

The backend (`backend/services/semprec-api/src/app.ts`, `createDispatcher`) serves everything under `/api/`, plus `/mcp` and `/healthz`, on `PORT` (default `3001`, `backend/services/semprec-api/src/serve.ts`). The file's header comment (lines 6-8) is already correct: the proxy forwards cookies as-is and attaches no secret. The stale contradicting comment in `web/src/main.tsx` lines 28-29 ("vite.config.ts's dev proxy attaches it") is removed by sibling issue G3, which rewrites that block of `main.tsx`; do not touch `main.tsx` here.

Sibling issue G2 of this batch mirrors the same prefix list in `deploy/Caddyfile` for production and references this file's comment.

## Task

- In `web/vite.config.ts`, replace the five-entry `server.proxy` table with exactly two entries:
  - `"/api": { target: process.env.SEMPREC_API_URL ?? "http://localhost:3001", ws: true }` — every REST route and the `/api/sync` WebSocket upgrade;
  - `"/mcp": { target: process.env.SEMPREC_API_URL ?? "http://localhost:3001" }` — the MCP JSON-RPC endpoint (`app.ts` line 118), so an MCP client pointed at the dev server reaches the backend too.
  Keep the `SEMPREC_API_URL` override and the default port `3001`. Extend the header comment: the two prefixes are the backend-owned URL space (`/api/*`, `/mcp`; `/healthz` is not needed in development), and `deploy/Caddyfile` carries the same list for production (sibling issue G2 adds it there).
- Add `web/src/__tests__/viteConfig.test.ts` (Vitest, jsdom, no backend — every web test is this tier): import the default export of `../../vite.config.js`, and assert that `config.server.proxy` has exactly the keys `/api` and `/mcp`, that the `/api` entry has `ws: true`, and that both targets are `http://localhost:3001` when `SEMPREC_API_URL` is unset (delete it from `process.env` in a `beforeEach`; Vitest evaluates the config module once, so import it inside the test after clearing the variable, or assert on the value the module saw — pick one and keep the test deterministic).
