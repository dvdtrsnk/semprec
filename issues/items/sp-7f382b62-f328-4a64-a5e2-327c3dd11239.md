## Context

Model tier rationale: Adds an app delegate, entitlement and permission flow and the token lifecycle against the existing backend.

The backend has APNs delivery and `POST /api/push-subscriptions`, but the app never registers. Calendar change notifications and invitation pushes need it.

## Task

Load `kmp-shared`, `shared-viewmodel`, `apple-swiftui`, `mobile-navigation`, `canonical-keys`, `testing` and `mobile-verify`.

1. `aps-environment` entitlement, background mode `remote-notification`, an app delegate adaptor in the App target.
2. Ask for notification permission when the user first enables a notification preference or connects an account with Calendars; register for remote notifications and upload the token through the shared layer (`/api/push-subscriptions`, environment by build configuration); revoke on sign-out.
3. Handle taps: calendar notifications open the event; invitation notifications open Invitations.
4. Silent reminders resync and local reminders: read `GET /api/calendar/reminders` and schedule local notifications; update the app icon badge from badge counts.

## Touches

- mobile/apple/Projects/App/ (entitlements, Info.plist, app delegate)
- mobile/shared/data/.../HttpPushRepository.kt (new)
- mobile/shared/presentation/ (push registration ViewModel or use case)
- mobile/apple/Modules/Features/Account/ (notification settings)

## Scope

### In scope

- APNs registration, tap routing, local reminders and badge.

### Out of scope

- Android FCM and web push.

## Acceptance criteria

- After permission, the backend has one active push subscription for the device.
- A calendar change push opens the event.
- Signing out revokes the subscription.
