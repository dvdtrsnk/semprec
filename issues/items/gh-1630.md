## Context

Model tier rationale: One read route over an existing findings store following the same custom-route and isolation-test pattern as the guidance routes, with a fixed response shape and no write path.

The owner needs to see, on the project's AGENT page, which instruction mismatches the nightly tick found. Findings live in `agent_guidance_drift_findings` (store: `backend/packages/data/src/guidanceDrift/agentGuidanceDriftFindingsStore.ts`, `listActive`), written by `core.agentGuidanceDrift` (#1629 adds behavior findings next to the permission ones). They are visible today only as notifications. Their fingerprint is deterministic since #1375. Guidance itself is served by #1548 and its routes sit in the systemDatabases module manifest (`backend/packages/data/src/seed/systemDatabasesModuleManifest.ts`, ownership per `docs/adr/2026-09-10-single-writer-ownership-model.md`); this route lives there too, as a `single-consumer-read` custom route (`docs/adr/2026-09-11-module-manifest-custom-routes.md`). Resolving a finding is #1685.

`GET /api/projects/:id/agent-guidance/drift` returns `{ guidanceUpdatedAt, findings: [...] }`, the project's active findings oldest first (`firstSeenAt`, then `id`):

- `id`, `kind` (`permission` or `behavior`), `claim`, `severity` (`blocking` or `warning`), `firstSeenAt`;
- `evidence`: for `behavior` `{ runIds, count }`; for `permission` `{ guidanceExcerpt, manifestFacts }`;
- `suggestedAllowedLine` and `suggestedNotAllowedLine`: strings for `behavior`, `null` for `permission` (no suggestion is generated for that kind).

`guidanceUpdatedAt` is the current guidance `updatedAt` (`null` without guidance); the client passes it back as `expectedGuidanceUpdatedAt` when resolving.

Decisions: a project without guidance or findings returns 200 with an empty list; an unknown project id is 404 `not_found`, a non-UUID id 400 `validation_failed`; any authenticated user of the tenant may read (tenants have one user); resolved and dismissed findings are not returned.

Shared-file ordering: this issue also waits for #1598, #1626 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Acceptance criteria

- When a project has an active `behavior` finding with 3 runs, then the response contains it with `evidence.count` 3, both suggested lines and `kind` `behavior`.
- When a project has an active `permission` finding, then `kind` is `permission`, the suggestions are `null` and `evidence` holds the excerpt and manifest facts.
- When there is no guidance or no finding, then 200 with an empty `findings` list.
- When a finding is resolved or dismissed, then it is absent from the list.
- Another tenant's project id answers 404 and leaks nothing.
