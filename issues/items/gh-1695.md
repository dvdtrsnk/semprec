**Blocked by:** #1636
**Model tier:** medium

## Context

Model tier rationale: One mechanism (a structured summarize step) across the existing pipeline step, computed-key registry, gateway call and two read handlers, all with existing fixtures; it changes what `finalize` requires, so the persisted contract and the idempotency of retries need care.

Today step 5 of the transcription pipeline (`backend/services/semprec-transcribe/src/transcriptSummary.ts`, run by `runSummarizeStep` in `transcriptionTask.ts`) asks the model for one free-text summary under the instruction key `meetingSummary` and caches it in `computed.summaryByInstruction` (`Record<string, string>`). Topics, decisions and action items are mixed in that single text, speakers appear as `SPEAKER_00`, and action items exist nowhere as data. `runFinalizeStep` only completes a transcript once that summary key exists.

This issue replaces the free text with structured meeting notes stored as a new Transcripts computed key `meetingNotes`: a title, a summary, a short summary, a list of decisions and a list of action items with owner, due date and position in the recording. The transcript detail endpoint (#1576) and the transcript list (#1636) return the notes and are changed here so that speaker tokens in the text are replaced by names at read time; the Semp transcript tools (#1832) reuse the same function. The display name issue (#1830) offers the generated title as a suggested name the user confirms, and the action-item state and tasks (#1754, #1767) and the event recommendation (#1848) build on the notes. Older transcripts are filled by #1712.

Decisions:

- Speaker naming in the generated text: a mapping counts only when a `speakers` edge to a person exists. A suggestion that is still an unconfirmed card is not used; the text then shows "Speaker N" (localized) for an unmapped speaker.
- In running text a mapped speaker shows the person's first name; as the owner of an action item the full name. A token that matches no speaker of the transcript is shown as the generic localized word for "Speaker" ("Mluvčí" / "Speaker").
- `meetingSummary` is no longer computed for new transcripts. Existing `summaryByInstruction` values stay stored and untouched.
- The relative dates the model resolves ("tomorrow") are validated by the server: a `due` that is not a valid `YYYY-MM-DD` calendar date is stored as `null`.

## Task

Load `testing`, `ai-gateway`, `state-writes` and `canonical-keys`.

1. In `transcriptSummary.ts` add the instruction `{ key: "meetingNotes", prompt }` and a `responseSchema` (JSON Schema accepted by `backend/services/semprec-ai-gateway/src/schemaValidation.ts`; nullable fields as `["string","null"]`) for `{ title: string, summary: string, shortSummary: string, decisions: string[], actionItems: [{ text, ownerSpeaker: string|null, due: string|null, startsAt: number|null }] }`. The gateway operation stays `transcript_summary`. The prompt tells the model to refer to speakers only through tokens in the form `{SPEAKER_00}` (the keys in the transcript), to put an action item's owner in `ownerSpeaker` as such a key, to write `due` as `YYYY-MM-DD` using the recording date it is given, and to set `startsAt` to the second in the recording where the item is stated. Parse the model output with zod (`parseMeetingNotesContent`).
2. Give the prompt the recording date in the tenant's time zone as `YYYY-MM-DD` plus the weekday name, computed from `Transcripts.date` (a UTC instant) and `getSystemTimezone` (`backend/packages/data/src/systemSettings.ts`). After parsing, normalize: `ownerSpeaker` is kept only when it is a speaker key that occurs in `computed.segments`, otherwise `null`; `due` is kept only when it is a valid calendar date, otherwise `null`; `startsAt` must be a finite number of at least 0, otherwise `null`. The action item id is its position in the stored `actionItems` array, which is never rewritten or reordered after it is written.
3. Add `TRANSCRIPT_MEETING_NOTES_COMPUTED_KEY = "meetingNotes"` to `backend/packages/data/src/transcription/transcriptionComputedKeys.ts`, register it in the computed key registry in `backend/packages/data/src/seed/seedSystem.ts` and export it from `backend/packages/data/src/index.ts`. `runSummarizeStep` skips when the `meetingNotes` key already exists, otherwise calls the gateway outside any transaction (as today), and writes the notes with `writeComputedAndAnnounce` in a second transaction that re-checks the key under the row lock. A transcript without segments gets empty notes without a paid call (empty title, summary and short summary, empty lists). `runFinalizeStep` now requires `meetingNotes` instead of `meetingSummary`; `DEFAULT_SUMMARY_INSTRUCTION` and `readSummaries` usage are replaced accordingly, and a transcript that is already `done` is still only settled.
4. Add `backend/packages/data/src/transcription/meetingNotesRendering.ts` with `renderMeetingNotes(notes, speakers, locale)`: replaces each `{SPEAKER_NN}` token in `title`, `summary`, `shortSummary`, `decisions` and action item `text` (first name, or "Speaker N" for an unmapped speaker, the generic word for an unknown token), and adds `ownerLabel` (full name, or "Speaker N") and `id` (array position) to each action item. Add the generic-word label to `backend/packages/data/src/transcription/i18n/{cs,en}.json`. Use it in the detail handler of #1576 (replacing the `null` placeholder with the rendered notes, or `null` when the key is absent) and in the list handler of #1636 wherever it returns notes text. Reading never calls the model, so mapping a speaker changes the text on the next read.
5. Tests: `transcriptSummary.unit.test.ts` (schema, parsing, normalization of owner, due and startsAt, "tomorrow" in a recording of 2026-10-16 resolved to 2026-10-17 by a stubbed model), `transcriptionTask.test.ts` (a finished transcript has all fields; no action items gives `[]`; a retry does not pay twice; finalize waits for `meetingNotes`), and rendering tests including a speaker mapped after the notes were written.

## Scope

### In scope

- The structured `meetingNotes` computed key, its prompt, schema, validation and normalization.
- Requiring it in `finalize` and no longer computing `meetingSummary`.
- Read-time replacement of speaker tokens in the detail and list handlers, as a function reusable by other readers.

### Out of scope

- Filling notes for transcripts that were processed before this change: #1712.
- The state of action items and tasks created from them: #1754, #1767.
- Offering `title` as the suggested transcript name: #1830.
- Using the rendering in the Semp transcript tools: #1832.
- Treating the user's own action items differently from other people's (needs the user's own person): see #1767.

## Acceptance criteria

- When a transcript finishes, its `meetingNotes` holds title, summary, short summary, decisions and action items; a recording without action items has `actionItems: []`.
- When SPEAKER_02 is mapped to Jana Kovářová after the notes were written, the detail endpoint returns "Jana" in the summary text and "Jana Kovářová" as the owner of her action item, without a new model call.
- When the model returns "tomorrow" for a recording made on 2026-10-16, the action item's `due` is `2026-10-17`; when it returns something that is not a calendar date, `due` is `null`.
- When the model names an owner that is not a speaker of the transcript, `ownerSpeaker` is `null`.
- When the pipeline is retried after the model call succeeded but before finalize, no second paid call is made.
