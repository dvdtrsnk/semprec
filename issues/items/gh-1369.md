## Context

Model tier rationale: A single zod module in the shared package, but it fixes a persisted wire contract that three later issues store, validate and expand, so the closed variants need care.

A user can attach objects (a task, an e-mail, a note block, a transcript passage, a file, a person and so on) to a message sent to Semp. Semp receives a reference, not text: it reads the whole object and its surroundings itself and may edit it. Today the backend has no message refs at all. The only existing link to an object is the `semprec://items/<fileItemId>` string in `Transcriptions.link` (`backend/packages/data/src/transcription/transcriptionJob.ts`), and the shapes of the referable objects differ: a note block is a `Y.Map` inside the item's document (`backend/packages/data/src/docs/blocks.ts`, document unique per `(tenant_id, item_id)`), an e-mail attachment is a `mail_attachments` row rather than a Files item, and a transcript passage is an entry of `computed.segments` (`{speaker, text, startsAt, endsAt}` in seconds) on a Transcripts item.

This issue defines the single, closed schema of a message ref. #1682 validates and stores refs with it, and several later issues extend or consume the same schema: #1936 (agent run refs), #1933 (mail thread refs), #1771 (task occurrence and trace refs) and #1853 (sleep night refs).

Decisions:
- A recording is referenced as an `item` ref to its Transcripts item, which carries the summary, speakers and segments; the audio file stays reachable from it. No separate recording kind.
- A person, company, recipe, invitation, Inbox item and proposal card are all plain `item` refs.
- An e-mail is an `item` ref to the Emails item. A mail thread kind is added by #1933, not here.
- Kinds whose data does not exist yet (sleep nights, task occurrences and traces, mail threads and drafts, event occurrences, birthdays, holidays, page property values, journal periods) are not defined here; the issue that introduces the data adds its variant to this same union.

## Task

Load `canonical-keys` and `testing`.

1. In `backend/packages/shared/src/`, add a message-ref module exporting a zod discriminated union on `kind` (strict objects, canonical camelCase keys) with these variants:
   - `{ kind: "item", itemId, databaseId }` (UUID strings)
   - `{ kind: "block", itemId, blockId }`
   - `{ kind: "transcriptSegment", itemId, startsAt, endsAt }` (seconds, finite numbers, `0 <= startsAt < endsAt`)
   - `{ kind: "mailAttachment", attachmentId }`
   - `{ kind: "agentRun", agentRunId, messageId? }`
   - `{ kind: "approvalRequest", approvalRequestId }`
2. Export the inferred `SempMessageRef` type, the list of kinds, and a pure `messageRefKey(ref)` function returning the dedup identity: kind plus the id fields, plus `blockId` for blocks and the range for segments. `messageId` of an agent run ref is not part of the identity.
3. Export the schema through the shared package index.
4. Unit tests: each variant accepts a valid value and rejects a missing field, an extra field, a non-UUID id and (for segments) an empty or reversed range; an unknown `kind` is rejected; `messageRefKey` is equal for two equal refs and different for refs differing in block id or range.

## Scope

### In scope

- The closed zod schema, its type, the dedup key function and unit tests.

### Out of scope

- Validating that a ref points at an existing object, the 20-ref limit, and storing refs: #1682.
- Resolving labels and trash state for the message history: #1684.
- Expanding refs into agent context: #1733.
- Variants for mail threads (#1933), task occurrences and traces (#1771) and sleep nights (#1853).
- Event occurrence, birthday, holiday, page property value and journal period refs; they are not planned yet and wait on the modules that own the data.

## Acceptance criteria

- When a value of an unknown `kind` is parsed, then parsing fails.
- When an `item` ref lacks `databaseId`, then parsing fails; when a `transcriptSegment` has `endsAt <= startsAt`, then parsing fails.
- When two refs differ only in `messageId`, then `messageRefKey` returns the same key.
- The new tests pass in the backend unit suite and the package builds.
