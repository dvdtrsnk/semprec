**Blocked by:** #132

## Context

Agent runtime behavior depends on external pi packages whose upgrades must be explicit and detectable.

## Task

Add `pi-ai`, `pi-agent-core`, and `pi-coding-agent` as exact versions without range prefixes and lock them. Add CI-running contract tests against the installed version proving: tool execution defaults to parallel; constructing Agent/AgentSession spawns no subprocess; `estimateContextTokens` and `shouldCompact` accept a bare message array without a running session; and low-level `compact()` requires a prepared compaction rather than a bare array. Production code may use only documented public exports such as `createAgentSession`, `resourceLoader.systemPromptOverride`, tool execution config, and compaction exports. Rewrite useful example patterns locally; never import example or internal paths.

## Scope

### In scope

- Exact dependencies, lockfile, named contract suite, and CI invocation.

### Out of scope

- Upgrading pi, AgentHarness, and tests of Semprec business logic.

## Acceptance criteria

- Routine install cannot silently change a pi version.
- Breaking any relied-upon behavior fails with a pi-contract-specific message.
- Source import lint finds no internal/example pi paths.
