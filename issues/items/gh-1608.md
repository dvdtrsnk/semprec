## Context

Model tier rationale: A new persisted text format with a hand-written parser and serializer must round-trip exactly, escape correctly, and be reproduced by a second runtime (the WebView editor), so ambiguity or an escaping gap silently corrupts user content.

Every editor hands its content to the host as Markdown, and Semp, the web client and the desktop client read and write pages as Markdown; the app itself never shows Markdown syntax. Today the backend has no Markdown parser or serializer: a block's text is a plain field in `backend/packages/data/src/docs/blocks.ts`, and the only text-in-Markdown storage is the `project_agent_guidance.markdown` column. #1539 adds the shared block model (type registry, order array, `Y.Text` with `bold`, `italic`, `code`, `link` attributes). This issue adds the conversion between that model and canonical Markdown, in the same shared module so the server and the WebView editor run identical code.

The canonical format:

- One non-empty line is one block (no CommonMark soft line wrapping or lazy continuation: two lines from Semp are two blocks). A blank line is written between blocks except between adjacent list items.
- Block markers: `# `, `## `, `### ` for h1-h3; `- ` bullet; `1. ` number (always written as `1.`); `- [ ] ` and `- [x] ` todo (on read also `[X]` and `* ` bullets); `> ` quote; two spaces of indentation per level for bullet, number and todo; a subpage with encoded ID as `[Title](semprec://page/<id>)` alone on its line.
- Inline: `**bold**`, `_italic_` (and `*italic*` inside a word), `` `code` ``, `[text](url)` (a URL without a scheme gets `https://` on read). An ordinary soft break is `<br>`; code-marked LF is `<code><br></code>`. Crossed bold and italic inside a word is written as `<strong>` and `<em>`; on read, inline HTML `strong`, `b`, `em`, `i` and `br` are accepted. Inline semprec://page/ links use [text](<semprec://page/id>); unwrapped standalone syntax denotes a page block.
- Characters `\ * ` [ ] <` and `_` at a word edge are escaped when written.

Decisions:

- Decision: line-start markers that appear in plain text (for example `16. 10. jsme...`, `# not a heading`, `- not a list`, `> not a quote`, `[ ] x`) are escaped on write (`16\. 10. jsme...`, `\# ...`, `\- ...`, `\> ...`, `\[ \]`) and unescaped on read, so a text block never changes type through a round trip or through text written by an agent. A naive serializer would not escape such prefixes; the WebView editor must adopt the same rule from the shared fixtures.
- Decision: the lossy parts (an unknown block type, and the indent of blocks that are not bullet, number or todo, which the model keeps for every type) are preserved as a comment line before the block: `<!-- semprec:block id=<id> type=<key> indent=<n> -->`. Without the comment, a block of an unknown type reads as `text` and indent on a non-list block reads as 0.
- Decision: an optional serializer mode writes the id comment before every block, for agents that need to address blocks by id (the Markdown page reads of #1678 can use it); the default mode writes no ids.
- Decision: the page block title is not stored in the model. The serializer takes a caller-supplied title resolver (`resolvePageTitle(pageId)`), writing an empty title when none is supplied; the parser reads only the id from the link and discards the title.
- Decision: no Markdown library is added. The format is a deliberate line-oriented subset and the code must run in a browser WebView.

## Task

Load `testing`. Implement in the shared block model module (location per the ADR from #1366).

1. `serializeBlocks(blocks, options?)` returns canonical Markdown from `PageBlock[]` (options: `resolvePageTitle`, `withIds`). `parseMarkdown(md, options?)` returns block inputs validated by the registry of #1539 (options: `allowPage`, default true; when false, a page-block line fails with a line-specific validation error; angle-destination inline links remain text). Both are pure functions.
2. Block mapping exactly as described in Context, including the indent rule (two spaces per level, clamped to 0-5 on read, written only for list blocks without a comment). Page IDs/captions follow the page-block encoding ADR.
3. Convert Y.Text deltas and Markdown with escaping/unescaping, ordinary soft breaks `<br>`, code-marked LF `<code><br></code>`, crossed in-word bold/italic `<strong>`/`<em>`, and scheme-less links defaulting to `https://`. Preserve significant whitespace per its ADR and interior CR/U+2028/U+2029 in structural content captures; only LF splits physical lines. Raw blank lines stay separators. Follow the inline-destination LF ADR.
4. Preservation comments and `withIds` follow the comment-field ADR.
5. `stripMarkdown(md, maxChars)` returns plain text (markers removed, emphasis removed, all links including page links reduced to their visible text, soft breaks to a space) truncated to `maxChars`, for subtitles and full-text indexing by later consumers. Preserve page-link labels here without changing parseMarkdown's deliberate title discard in page-model inputs. Embeddings are out of scope.
6. A shared JSON fixture file of Markdown to blocks vectors (including the cases below), stored in the module directory so both the server test and the WebView editor can load it, plus the server-side runner testing both semantic directions for every representable block vector: noncanonical accepted input serializes to its declared canonical form, and canonical Markdown parses and serializes back unchanged. Explicitly classify and test the synthetic-empty serialization case and parser refusals separately; do not materialize a physical block merely to claim their round trip.
7. Fixtures must include: a project-notes sample (h2, a second-level bullet, a done todo, a quote, inline code such as `` `0.4 (52)` ``, a link, a subpage link); `16. 10. jsme...` written as `16\. 10. jsme...` and read back as the same text; two lines without a blank line parsed as two text blocks; one block with `<br>` as a single block with a soft break; an unknown-type block and a non-list indented block each preserved through the comment; a page link with `allowPage: false` rejected.

## Acceptance criteria

- When the project-notes fixture is parsed and serialized again, then the output equals the input exactly.
- When a text block contains `16. 10. jsme...`, then `serializeBlocks` writes `16\. 10. jsme...` and `parseMarkdown` returns a `text` block with the original text.
- When two lines are separated by a single newline, then `parseMarkdown` returns two `text` blocks; when a block contains a soft break, then it serializes as one line with `<br>`.
- When the Markdown contains a subpage link and `allowPage` is false, then parsing fails with a validation error. Page IDs/captions follow their ADR.
- When a block of an unknown type or a non-list block with indent 3 is serialized and parsed again, then type and indent survive through the `semprec:block` comment. Comment fields follow their ADR.
- Every representable shared-fixture vector passes parse and canonical serialization checks, including canonical round trips for accepted aliases; synthetic-empty serialization and parser refusals have explicit separate assertions and are not claimed as physical-block round trips.
- Inline page links retain block type, text, href and marks through canonical round trips, with/without ids and allowPage; actual page blocks keep their syntax and allowPage:false refusal. LF hrefs follow the destination ADR.
- Leading/trailing and whitespace-only model content roundtrips exactly under the scoped encoding, including quotes, marks and literal escape-looking text.
- Code-marked LF retains its marks via the exact atom; ordinary breaks and fenced/escaped literals stay distinct. Interior CR/U+2028/U+2029 retain structural block type/content per the scoped ADR.
