**Model tier:** high

## Context

Model tier rationale: This ties a budgeted AI decision, run launch in another project, idempotence across concurrent runs of one thread, and a guidance cutover together, with several ways to create duplicate or overwritten drafts.

When a person writes and expects an answer, Semp prepares one reply draft in the thread. Prerequisites: the run receives the triggering message and only starts for known senders (#1552); the mail tools `mail.thread.get`, `mail.draft.create` and `mail.draft.update` exist (#1927) under the grant and approval rules of #1385; a thread has a project through its Threads item (#1869); and project guidance lives in the guidance store (#1449). Today the guidance text seeded for the Email project (`seed/seedEmailModule.ts`) names tools that do not exist (`email.draft.create`, `email.send`) and promises a 403 for sending without approval.

Decisions:
- The run starts in the thread's project when the thread has one, otherwise in the Email project.
- Deciding whether an answer is expected is a separate cheap AI call through the ai-gateway before any agent session is created; an exhausted tenant budget skips the draft silently, with no `agent_run_error`.
- Two quick messages of one thread are merged by a run-time check instead of a queue job key: a run exits when its message is no longer the newest inbound message of the thread, because the agent lane is serial.
- A draft whose `last_edited_by` is the user is never overwritten.

Shared-file ordering: this issue also waits for #1939 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `ai-gateway`, `state-writes`, `error-handling`, `testing` and `canonical-keys`.

1. Project selection: add an optional resolver step to `coreAgentRunAction` (config key `runProject: { resolver: "mailThreadProject" }`, resolver implemented in `mail/newEmailRunProject.ts`) that returns the Threads.project of the triggering message's thread, else the heartbeat's own project. Seed the key on `newEmail`, and add it to the existing `newEmail` heartbeat of existing tenants in `mail/newEmailDraftCutoverMigration.ts` (idempotent, same pattern as the cutover of #1552).
2. Answer-expected gate: `scheduler/answerExpectedFilter.ts` (config key `answerExpectedFilter`), run after the sender gate and before creating the run. It calls the ai-gateway outside any transaction with the thread's latest messages (cut to a fixed size) and the sender, schema `{ expectsReply: boolean }`; false, invalid output or an exhausted budget means no run and no error row.
3. Idempotence: skip when a draft with the same thread and source message already exists; skip when the message is not the newest inbound message of the thread.
4. One draft per thread: when the thread has an open agent draft whose `last_edited_by` is the agent, the task names its draft id and the agent must update it with `mail.draft.update`; when its `last_edited_by` is the user, no run starts. `mail.draft.create` in a reply mode for a thread that already has an open agent draft is rejected with a conflict naming the existing draft id (guard added in the tool code of #1927).
5. Guidance: change the seeded Email-project guidance to name `mail.draft.create`, `mail.draft.update` and `mail.draft.send`, and say that sending without project permission becomes an approval request. For existing tenants a cutover rewrites the Email project's guidance only when it equals the stored conversion of the original seeded text; an edited guidance stays.

## Scope

### In scope

- Project selection, the answer-expected decision, idempotence and one-draft-per-thread rules, and the guidance fix and its cutover.

### Out of scope

- The sender gate and passing the item (#1552); bulk detection (#1502).
- The mail tools themselves (#1927) and sending (#1949, #1913).
- Retiring a draft once the user replied (#1902).
- Per-account or per-project settings for drafting; the product owner decided drafting is always on and v1 adds no such setting.

## Acceptance criteria

- A message from a known person with a question creates exactly one draft in its thread with `In-Reply-To` and `created_by` agent; a second message updates that draft while the user has not edited it.
- A message without a question, a newsletter, a message from an unknown address, and a message when the tenant AI budget is exhausted create no draft and no `agent_run_error`.
- A draft the user edited is not overwritten and no further run starts for that thread.
- A thread with a project runs in that project; a thread without one runs in the Email project.
- After the cutover the unedited Email guidance names the real tool names; an edited one is unchanged.
