**Blocked by:** #1464
**Model tier:** medium

## Context

Model tier rationale: Two new computed cache keys written through the existing announce helper plus a per-tenant backfill, following established patterns, with tenant-scope care in the backfill.

The recording's length is stored only on the Files item (`computed.prepare.durationSeconds`, written by `runPrepareStep` in `backend/services/semprec-transcribe/src/transcriptionTask.ts`), and writes of Files checkpoints use `writeComputed`, which announces nothing. The Transcripts row has no duration and the finalize step stores no completion time. A client showing "Processing recording - 12:48" or a finished recording's length would have to follow `link` to the Files item.

This issue puts the duration on the transcript as soon as prepare has run and the completion time when finalize finishes, both through `writeComputedAndAnnounce` so other devices get a realtime invalidation. It unblocks #1576 and #1636, which return both values.

Shared-file ordering: this issue also waits for #1464 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `canonical-keys` and `testing`.

1. In `transcription/transcriptionComputedKeys.ts` declare Transcripts computed keys `durationSeconds` and `finalizedAt`, and register them in the `ComputedKeyRegistry` in `seed/seedSystem.ts` (beside the existing transcription keys).
2. In `runPrepareStep` write `durationSeconds` to the Transcripts item through `writeComputedAndAnnounce`, in the same transaction as the Files checkpoint.
3. In `runFinalizeStep` write `finalizedAt` (ISO 8601 UTC) through `writeComputedAndAnnounce`.
4. Add a one-time per-tenant backfill (registered in `db/tenantCutoverMigrations.ts`) that fills `durationSeconds` on existing transcripts from the linked Files item's `computed.prepare` (found through `Transcripts.link`), idempotent and skipping transcripts without a checkpoint.
5. Tests: the values are written and announced; a repeated prepare or finalize does not change them; the backfill is idempotent.

## Scope

### In scope

- The two computed keys, writing them in the pipeline, and the duration backfill.

### Out of scope

- Reading them from the transcript endpoint or list: #1576 and #1636.
- The error code and failure link: #1386.

## Acceptance criteria

- When the prepare step has run, then the transcript has `durationSeconds`, and another device receives an invalidation of Transcripts.
- When finalize finishes, then the transcript has `finalizedAt`.
- When prepare or finalize is retried, then the values are not rewritten with different results.
- When the backfill runs on a tenant with older transcripts, then they get `durationSeconds`; a second run changes nothing.
