## Context

Every `ai_gateway_calls` row written by `POST /internal/diarize` and `POST /internal/transcribe` has `operation = NULL` (and `agent_run_id`, `project_item_id` NULL). Before this batch that was structural: `RecordAudioCallInput` in `backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts` (lines 32-37) had no attribution fields and `recordAudioGatewayCall` (lines 99-100) inserted `NULL, NULL, NULL` for the three columns, while `POST /internal/complete` records the caller's `operation` (`completeHandler.ts`, line 215). An operator looking at the table therefore cannot tell audio spend by purpose, and the `ai-gateway` convention (every gateway call carries a purpose identifier so rows stay attributable) is not met on two of the three routes.

E1 (see the pull request that closed it) replaced `recordAudioGatewayCall` in the gateway path with `reserveGatewayCall`, which already accepts `operation` for every route — `audioHandler.ts` just does not pass one. E3 (see its pull request) edited the same handler; this issue lands after both so the edits do not collide.

## Task

- In `backend/services/semprec-ai-gateway/src/audioHandler.ts`, add module constants `DIARIZE_OPERATION = "transcription_diarize"` and `TRANSCRIBE_OPERATION = "transcription_transcribe"` (English camelCase/snake identifiers, matching the existing `agent_guidance_drift` / `transcript_summary` style of `completeHandler.ts`), and pass `operation: DIARIZE_OPERATION` / `operation: TRANSCRIBE_OPERATION` in the `GatewayCallContext` handed to `diarize()` / `transcribe()`. `agentRunId` and `projectItemId` stay unset (null): the only caller, `semprec-transcribe`, runs as a queue job outside any agent run and outside any project.
- Update the docblock above `createAudioRequestListener` (it currently says "no agent_run_id"; add that `operation` names the route). Leave `aiGatewayCallsStore.ts` untouched — its `RecordAudioCallInput` comment about `agent_run_id` stays true.
- Tests in `backend/services/semprec-ai-gateway/src/__tests__/audioHandler.test.ts`: the two "records the audio call" tests (lines 238 and 260) additionally assert `operation` is `'transcription_diarize'` / `'transcription_transcribe'` on the settled row, and `agent_run_id` / `project_item_id` are still NULL.
