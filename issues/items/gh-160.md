## Context

REST is authoritative and minimal realtime fanout exists, but the final protocol needs one authenticated connection and a closed message catalog before adding stream implementations.

## Task

Implement `WS /api/sync` in `packages/realtime` and mount it in `semprec-api`. Authenticate during HTTP upgrade with the same session cookie used by web or Bearer token used by native clients; invalid credentials return HTTP 401 and create no socket. Associate every socket with user/session identity. Define and validate protocol-v1 frames: inbound `doc:open`, `doc:close`, `agent:watch`, `agent:unwatch`; outbound `invalidate`, `notification`, `agent:event`, `agent:delta`; and binary frames prefixed by the 16-byte document UUID. Maintain one socket per client and one dedicated PostgreSQL LISTEN connection per API process, never per client. On session-revocation NOTIFY, close all sockets for that exact session with 4401; revalidate the session during heartbeat as a fallback.

## Scope

### In scope

- Upgrade/auth, identity registry, message codecs/validation, single LISTEN ownership, revocation closure.

### Out of scope

- Actual stream handlers, delivered by later siblings.
- Post-connect auth messages and connection-per-traffic-type designs.

## Acceptance criteria

- Cookie and Bearer clients reach the same authenticated socket identity; invalid/revoked credentials never create a socket.
- Protocol tests reject unknown/malformed text and binary frames without crashing other clients.
- Revoking one session closes its sockets with 4401 and leaves another session untouched.
