## Context

Model tier rationale: A new tenant-scoped table with a known RLS pattern, three read/write routes, and a guarded image download that reuses the hardened outbound client, all with existing fixtures.

After #1655 and #1706, the library fetchers can return up to three alternative matches as `candidates` (`{ title, author?, year?, coverUrl? }`) next to the best one, and no code stores them. After #1793, a user can set a manual cover through the user-owned `coverOverride` and `coverSource` properties. This issue lets the user see the stored alternatives and pick one as the manual cover.

Decision: candidates are stored by the job at the end of a run (replace the previous set for the item), not fetched when listing. `GET` reads only what is stored and never calls an external service; refreshing enqueues the job.
Decision: selecting a candidate downloads the image through the outbound address checks (`docs/adr/2026-10-16-connect-time-outbound-address-checks.md`, `createOutboundHttp()` in `backend/packages/data/src/net/outboundAddressPolicy.ts`; stored URL rules in `docs/adr/2026-09-27-ssrf-protection-for-stored-outbound-urls.md`), stores it as a blob, and writes `coverOverride` with `coverSource: "candidate"`.

Shared-file ordering: this issue also waits for #1809 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `state-writes`, `io-hardening`, `error-handling` and `testing`.

1. Migration `backend/packages/data/src/db/migrations/NNNN_library_cover_candidates.sql (next free ordinal at commit time)`: table `library_cover_candidates (item_id uuid NOT NULL, idx smallint NOT NULL CHECK (idx BETWEEN 0 AND 2), tenant_id uuid NOT NULL DEFAULT app_tenant_default() REFERENCES tenants(id), source text NOT NULL, title text, subtitle text, image_url text NOT NULL, fetched_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (item_id, idx))`, the `semprec:tenancy=tenant` comment, row-level security policies and grants exactly as in `0078_tenant_exports.sql`. Additive; the previous release never touches it.
2. Store: `backend/packages/data/src/library/coverCandidatesStore.ts` with replace-set and list for an item; `image_url` must pass the stored-URL validation (https, no userinfo, no port, DNS host) before it is stored; invalid entries are dropped. The job (`library/libraryMetadataJob.ts`) replaces the item's candidates from `result.candidates` at the end of every run that returns a status other than `error`.
3. Remove an item's candidates in `deleteItemDependents` (`backend/packages/data/src/chokePoint/itemTrash.ts`), alongside `deleteItemAutomation`, and make sure the tenant export and purge code (`backend/packages/data/src/tenancy/`) handle the new table the way the schema-classification check requires.
4. Custom routes in `libraryModuleManifest.ts` (justification `single-consumer-read` for the first, `transactional-semantics` for the others), handlers in `backend/packages/data/src/library/libraryCoverCandidateRouteHandlers.ts`, registered in `backend/services/semprec-api/src/routeMatrix.ts`:
   - `GET /api/items/:id/cover-candidates`: returns `[{ index, source, title, subtitle, imageUrl }]` from storage only, no network call;
   - `POST /api/items/:id/cover-candidates/refresh`: enqueues the metadata job like the retry route, responds 202, and does not clear the manual cover;
   - `POST /api/items/:id/cover-candidates/:index/select`: downloads the candidate image through `createOutboundHttp()` (size cap, image content type, private or link-local addresses refused with 400/422), stores the blob, writes `coverOverride` and `coverSource: "candidate"` and clears `coverRemoved` through the normal user update path in one transaction, then publishes invalidation. An unknown index or an item outside a library database or another tenant is 404.
5. The agent has no tool for these routes.
6. Tests: the job stores up to three candidates and replaces them on the next run; `GET` makes no network call (injected `fetch` asserts zero calls); selecting candidate 1 sets `coverOverride` and `coverSource: "candidate"` and a later job run leaves the override; a candidate URL resolving to 169.254.169.254 or 10.0.0.1 is refused; deleting and purging the item removes the rows; the routes are in the tenant isolation route test.

## Scope

### In scope

- `library_cover_candidates`, storing candidates from the job, listing, refresh, and selecting a candidate as the manual cover.

### Out of scope

- The manual cover properties, retry and removal: #1793.
- Producing candidates in the fetchers: #1655, #1706.
- Sources without a usable API (Databáze knih, ČSFD, IMDb): not in v1; they are added only once a usable API is verified (no scraping).

## Acceptance criteria

- When a job run returns more than one match, then up to three candidates are stored for the item, replacing the earlier set.
- When `GET /api/items/:id/cover-candidates` is called, then it returns the stored candidates and performs no outbound request.
- When candidate 1 is selected, then `coverOverride` and `coverSource: "candidate"` are written, `coverRemoved` is cleared, and a following job run does not replace the chosen cover.
- When a candidate image URL resolves to 169.254.0.0/16 or 10.0.0.0/8, then the selection is refused and nothing is written.
- When an item is purged, then its candidate rows are removed.
- When another tenant's item id is used, then every route answers 404.
