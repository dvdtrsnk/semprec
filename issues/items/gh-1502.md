## Context

Model tier rationale: One flag computed from message headers in all three provider adapters through a single shared detector, with an additive column and existing ingest fixtures, but it touches persisted data and three adapters.

Semp should draft replies only to mail from people, never to newsletters, notifications or automatic messages. Today nothing tells bulk mail apart: `FetchedMessage` in `backend/packages/data/src/mail/providerTypes.ts` carries no `List-Unsubscribe`, `List-Id`, `Precedence` or `Auto-Submitted`, and `mail_message_meta` (migration `0006_mail_sync.sql`) has no flag. The IMAP adapter (`imapFlowClient.ts`), the Gmail adapter (`gmailRestClient.ts`, which already reads several headers from the payload) and the Graph adapter (`graphRestClient.ts`, where a header must be a selected property) each normalize a message before `ingestEmailMessage` (`mail/ingest.ts`) writes it. The flag is consumed by #1552.

Decision: messages ingested before this change keep `is_bulk = false` (no backfill); the gate in #1552 also requires a known sender, which limits the effect.

## Task

Load `db-migrations`, `io-hardening` and `testing`.

1. Migration `backend/packages/data/src/db/migrations/NNNN_mail_message_meta_is_bulk.sql (next free ordinal at commit time)`: `ALTER TABLE mail_message_meta ADD COLUMN is_bulk boolean NOT NULL DEFAULT false`.
2. New `mail/bulkMail.ts` exporting `detectBulkMail({ listUnsubscribe, listId, precedence, autoSubmitted, senderAddress })`, true when any of: `List-Unsubscribe` present; `List-Id` present; `Precedence` (trimmed, case-insensitive) is `bulk`, `list` or `junk`; `Auto-Submitted` present with a value other than `no`; or the local part of the sender address matches `^(no-?reply|do-?not-?reply|mailer-daemon|notifications?)$` case-insensitively. Header values are untrusted: never throw on a malformed value.
3. Add the optional `bulkHeaders` object (the four raw header values) to `FetchedMessage` and make each adapter fill it from the headers it already fetches (add the headers to the IMAP header fetch list, read them from the Gmail payload, select `internetMessageHeaders` in Graph).
4. `ingestEmailMessage` computes the flag with `detectBulkMail` and passes it to `upsertMailMessageMeta` (`mail/mailMessageMetaStore.ts`), which stores and returns `isBulk`. A reconcile pass over an already-ingested message does not change the stored flag.

## Scope

### In scope

- The detector, the column and the header capture in the three adapters.

### Out of scope

- Using the flag to gate agent runs (#1552).
- Backfilling messages already stored.
- Hiding or sorting bulk mail in the mailbox.

## Acceptance criteria

- A message with `List-Unsubscribe`, with `List-Id`, with `Precedence: bulk`, with `Auto-Submitted: auto-generated`, or from `No-Reply@example.com` is stored with `is_bulk` true, through each of the three adapters' paths.
- A message with `Auto-Submitted: no` from an ordinary person is stored with `is_bulk` false.
- A repeated sync of the same message does not change `is_bulk`.
