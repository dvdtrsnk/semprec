## Context

Every long-running unit and three of the timer units run as `User=semprec` (`deploy/systemd/semprec-{api,agents,transcribe,ai-gateway}.service` line 11; `semprec-dead-man.service`, `semprec-trash-purge.service`, `semprec-failping@.service`). `deploy/provision.sh` `ensure_release_tree` (lines 188-198) creates `/opt/semprec/shared` as `0700 root:root` and `/opt/semprec/shared/bin` as `0750 root:root`, and `deploy/README.md` lines 153-156 plus the `deploy/shared/.env.example` header (lines 15-18) instruct the operator to place `apns-key.p8` there as `root:root 0600`. Two things a `semprec` process must read are therefore unreadable:

- `backend/packages/data/src/push/apnsAdapter.ts` `readPrivateKey` (line 22) does `fs.readFileSync(APNS_PRIVATE_KEY_PATH)` at send time from `semprec-api`'s notification fanout job → `EACCES` on the directory before the file mode even matters. Every APNs delivery fails.
- `semprec-dead-man.service`, `semprec-trash-purge.service` and `semprec-failping@.service` execute `/bin/bash /opt/semprec/shared/bin/semprec-*.sh` as `semprec` → the shell cannot open the script. The dead-man ping never runs (so the external monitor alerts permanently), the daily trash purge never runs, and the failure ping that should report an exhausted unit fails itself.

`/opt/semprec/shared/.env` stays `0600 root:root`: systemd reads `EnvironmentFile=` as root before dropping privileges, so no service user needs it. `ensure_directory` only creates a missing directory; a rerun on an already-provisioned host must correct the mode of the existing one, which is why the fix is a dedicated function rather than a changed creation mode. Sibling issue F8b handles what the adapters do when their configuration is missing; this issue only makes the files readable. Depends on sibling F7b because both append functions to `provision.sh` and assertion blocks to `provision.test.sh`, and on #645 because both edit `ensure_release_tree`'s neighbourhood and the `install` mock line of `provision.test.sh` (#645 makes that mock record `install $*`; reuse it).

## Task

1. **provision.sh** — add `ensure_shared_permissions` after F7b's functions and call it from `main` after `install_timer_scripts` (the scripts must exist before their directory's group is corrected) — idempotent `chown`/`chmod` each run:
   - `chown root:semprec "$SEMPREC_ROOT/shared"` and `chmod 0750` — group-traversable, not world-readable.
   - `chown root:semprec "$SEMPREC_ROOT/shared/bin"` and `chmod 0750`; the scripts installed by `install_timer_scripts` change from `-o root -g root -m 0750` to `-o root -g semprec -m 0750` (edit those `install` flags in place).
   - `"$SEMPREC_ROOT/shared/.env"` stays `root:root 0600` (assert it explicitly with `chmod 0600` + `chown root:root` so a rerun heals a hand-edited mode too).
   - If `"$SEMPREC_ROOT/shared/apns-key.p8"` exists: `chown root:semprec` and `chmod 0640`. If it does not exist, do nothing (the operator uploads it later; rerunning provisioning then fixes it).
2. **Documentation** — `deploy/README.md` "Bootstrap secrets" (lines 151-174): `.env` is `root:root 0600`; `apns-key.p8` is `root:semprec 0640` inside `/opt/semprec/shared` (`root:semprec 0750`), because the service user reads the key by path while systemd reads `.env` as root; note that `provision.sh` corrects these modes on every run. `deploy/shared/.env.example` header lines 15-18: change "same `root:root 0600` ownership" to `root:semprec 0640` with the same reason (one sentence). (The `apnsAdapter.ts` docstring that still says `root:root 0600` is rewritten by sibling issue F8b, which edits that function anyway.)
3. **Tests** — `deploy/provision.test.sh`: rely on the `install` mock recording `install $*` into `$TEST_STATE/commands` (#645 added that), add `chown`/`chmod` mocks that record `chown $*` / `chmod $*` and then perform the real `chmod` (skip the real `chown` — the test is unprivileged). Appended directly after F7b's assertion block: `shared` and `shared/bin` have mode `750`; `chown root:semprec .../shared`, `chown root:semprec .../shared/bin`, `chown root:root .../shared/.env`, `chmod 0600 .../shared/.env` were recorded; the timer scripts were installed with `-g semprec`; no `apns-key.p8` command was recorded on the first run; after `touch "$TEST_ROOT/opt/semprec/shared/apns-key.p8"` and a rerun, `chown root:semprec .../apns-key.p8` and `chmod 0640 .../apns-key.p8` were recorded and the file's mode is `640`.
