## Context

Model tier rationale: The exhaustive runtime-role route suite in #1053 found two tenant-boundary failures involving uniqueness and foreign-key checks, which bypass RLS. The repository owner requested resolution of all blocked PRs on 2026-10-18. PR #1213 must remain limited to the route inventory and proof, so these production corrections are delivered separately before it is rebased.

## Task

1. Relax the obsolete global blobs_content_hash_uq index in a new forward-only migration. Migration 0064 already installed blobs_tenant_content_hash_uq and findOrCreateBlob already uses targetless ON CONFLICT. Identical content must upload independently in two tenants while deduplication within a tenant remains unchanged.
2. Make setProjectMcpGrant resolve the registration through the caller's RLS scope, locked in the same SQL statement that upserts the grant. A foreign registration and a nonexistent registration must raise the same NotFoundError without writing or updating a grant. Preserve allowed grant/revoke behavior. Remove the unchecked foreign-key error cast made obsolete by this guard.
3. Add focused integration coverage on two tenants through a semprec_data runtime pool, proving independent identical-content blobs, same-tenant deduplication, allowed grant/revoke, foreign/missing registration refusal and no side effects. Also verify against the route suite on PR #1213.

## Scope

### In scope

The blob index relaxation, stale blob arbiter comment, MCP grant write guard and focused runtime-role integration tests.

### Out of scope

Changing the global push-device-token ownership/displacement contract, rewriting existing migrations, weakening or marking isolation cases as expected failures, and unrelated route changes.

## Acceptance criteria

- Identical bytes in tenants A and B create distinct tenant-owned blobs; repeating in either tenant reuses its own blob.
- Both grant and revoke reject A's registration when called as B exactly like an unknown registration; neither A's grant nor B's grants change.
- A can grant and revoke its own registration.
- Integration tests use createRuntimeRolePool and two createTestTenant fixtures, with no superuser pool used for isolation assertions.
- The new migration removes only the legacy global content-hash index and preserves the tenant-leading index.
- backend and web verify pass before merge.
