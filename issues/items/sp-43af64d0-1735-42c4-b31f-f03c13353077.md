## Context

Model tier rationale: A new provider API with incremental sync tokens, full-resync handling and OAuth refresh under the existing credential lock.

Google accounts with the calendar scope sync through Google Calendar API v3.

## Task

Load `state-writes`, `db-migrations`, `error-handling`, `io-hardening`, `canonical-keys` and `testing`.

1. `listCalendars` from `users/me/calendarList` (summary, backgroundColor, accessRole: reader/freeBusyReader → read-only).
2. `fetchChanges` with `events.list` (`singleEvents=false`, `showDeleted=true`, syncToken); on 410 Gone drop the token and fully resync the calendar.
3. Map Google events (start/end with timeZone or date, recurrence lines, originalStartTime overrides, reminders.overrides, attendees, organizer, status cancelled → deletion).
4. `putEvent` with `If-Match` etag (events.update / events.insert with the stored UID as `iCalUID`), `deleteEvent`.
5. Access tokens through `refreshAndPersistAccessToken`; 401 after refresh → `needsReauthorization`; 403 insufficient scope → `needsConsent`.

## Scope

### In scope

- Google listing, incremental fetch, mapping and writes.

### Out of scope

## Acceptance criteria

- A 410 response triggers a full resync of that calendar only.
- A reader calendar is read-only in the app.
- An all-day multi-day event and a time-zoned recurring event map correctly.
- A missing scope sets `needsConsent`.
