## Context

The following issues split `backend/packages/data/src/chokePoint/chokePoint.ts` (2000 lines) into per-domain modules. The split must not change what `@semprec/data` exports or which methods the object returned by `createChokePoint()` carries. This issue freezes that surface in a test **before** any move happens. Every later issue in the batch must pass this test unmodified: a failure means a move changed the public API.

## Task

Add the integration-tier test `backend/packages/data/src/__tests__/publicSurface.test.ts`. It uses the package's existing integration setup to get a pool, and asserts three things:

1. **Runtime exports.** `Object.keys(await import("../index.js")).sort()` equals a literal array written out in the test file: the exact, sorted list of runtime exports of `backend/packages/data/src/index.ts` as it is on `develop` when you implement this.
2. **Choke-point methods.** `Object.keys(createChokePoint(pool)).sort()` equals a literal array: the exact, sorted list of the method names on today's `createChokePoint` object, currently 45 or more.
3. **Type exports.** A type-level check that fails `tsc` if any of these type exports of `index.ts` disappears or stops being importable:
   - `ChokePoint`, `Actor`
   - `CreateItemInput`, `UpdateItemInput`, `UpdateItemWithClientOptions`
   - `CreateRelationInput`, `UpdateRelationInput`, `DeleteRelationInput`, `RelationEdge`
   - `ResourceSnapshot`, `ResourceSnapshotKind`, `DestructiveResourceProjection`, `DestructiveOperationCheck`

   Use `import type { … } from "../index.js"` together with a construct that references each one, so an unused-import rule cannot strip it.

Write both lists as literals, not as vitest snapshot files, so any future change to them shows up in a reviewed diff. Add a short comment at the top of the test file: it guards the choke-point split, and editing its lists is only legitimate in a pull request whose issue explicitly changes the public API.

## Touches

## Scope

### In scope
- The test file described above.

### Out of scope
- Any change to production code.
- Freezing internal exports of `chokePoint.ts` that `index.ts` does not re-export. They move during the batch on purpose.

## Acceptance criteria

- `pnpm run verify` in `backend/` passes with the new test.
- Removing any runtime export from `index.ts` locally makes assertion 1 fail. Renaming or removing any method of the `createChokePoint()` object makes assertion 2 fail. Removing any of the listed type exports makes `tsc` (the build) fail. Verify each of the three by hand once, then revert, and state in the pull request description that you did.
- The expected lists are literal arrays in the test file, sorted, with no vitest `toMatchSnapshot` / `toMatchInlineSnapshot`.
