**Blocked by:** #1729
**Model tier:** medium

## Context

Model tier rationale: One read-model change across a single store function with an iterative run-chain lookup and a thread resolver, backed by existing queue fixtures, with no new table, migration or authorization contract.

Product behavior: a request to approve an agent action is shown where it came from. A request raised during a chat with Semp belongs in that chat; a request raised by an automatic task (a heartbeat tick) or by an external MCP client belongs in the Inbox. Clients need the source on every approval request to route it.

Today `GET /api/approval-requests` (`backend/services/semprec-api/src/approvalRequestsHandler.ts`) calls `listApprovalRequestsQueue` in `backend/packages/data/src/mcp/approvalRequestsQueue.ts`, which returns `{id, toolName, riskClass, requestedAt, safeSummary, agentRunId, projectItemId, projectName}` for the owner's pending requests. The source can be derived but is not returned: `agent_runs` carries `triggered_by` (`user|heartbeat|supervisor|mcp`), `heartbeat_id` and `parent_run_id`, and #1452 adds the Semp thread link to runs. #1729 introduces the resolver that produces a thread title for the thread list; this issue reuses that same resolver.

Decision: no new column on `approval_requests`. The thread link is also present on delegated runs, so the source is computed at read time from the run (and its root run), not stored on the request.

Decision: a heartbeat that was started from a chat is still a tick. The kind follows the run that raised the request, not the run that started the heartbeat.

This issue builds on #1452 and #1729. #1785, #1786, #1787, #1807 and #1913 read the source; #1788 fills the MCP client name.

## Task

Load `testing` and `error-handling`.

1. Add `source` to `ApprovalRequestQueueEntry` and to the decision view in `approvalRequestsQueue.ts`: `{kind: "chat" | "tick" | "mcp", threadId: string | null, threadTitle: string | null, heartbeatId: string | null, heartbeatName: string | null, mcpClientName: string | null}`. Export the type.
2. Derive `kind` in `listApprovalRequestsQueue` in one batched pass over the page of requests:
   - the run has a thread: the thread's kind decides it (a chat or item thread gives `chat`, a tick thread gives `tick`); `threadId` and `threadTitle` are filled, `threadTitle` through the resolver from #1729;
   - the run has no thread: walk `parent_run_id` iteratively to the root run (the loop pattern of `docs/adr/2026-09-11-iterative-parent-chain-traversal-in-choke-point.md`, with a depth guard) and decide by the root's `triggered_by`: `mcp` gives `mcp`, `heartbeat` gives `tick`, anything else gives `chat`;
   - a `tick` source fills `heartbeatId` and `heartbeatName` (from `project_heartbeats.name`); a `mcp` source leaves `mcpClientName` as `null` until #1788 records it.
3. Fetch runs, parents, threads and heartbeats with batched queries (one query per level of the chain, not one per request).
4. Keep every existing field of the response unchanged (additive-only, `docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`).

## Scope

### In scope

- The `source` object on rows returned by `GET /api/approval-requests` and on the `PATCH` response view.
- Source derivation from the run's thread, or from the root run's trigger.

### Out of scope

- Filtering, paging or listing decided requests by source: #1785.
- Reading one request and counting pending requests: #1786.
- Recording the MCP client name: #1788.
- The MCP server and tool names in the safe summary: #1368.
- The Inbox card list and count built on this source: #1807 and #1823.
- Any new column or index on `approval_requests`.

## Acceptance criteria

- When a request comes from a chat thread or an item thread, including one raised by a delegated run, its `source.kind` is `chat` with `threadId` and `threadTitle` set.
- When a request comes from a tick thread, its `source.kind` is `tick`, including a heartbeat that was started from a chat; `heartbeatName` is set.
- When a request comes from a run with no thread whose root run was triggered by MCP, `source.kind` is `mcp` and `mcpClientName` is `null`.
- When a Semp chat run raises an approval for an outbound MCP tool call (for example Gmail `send_email`), `source.kind` is `chat`.
- When `GET /api/approval-requests` is called without parameters, the response contains all previous fields with unchanged values plus `source`.
- Listing N requests runs a bounded number of queries independent of N.
