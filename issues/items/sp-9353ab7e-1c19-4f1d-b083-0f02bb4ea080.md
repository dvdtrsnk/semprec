## Context

Model tier rationale: three public listeners gain an in-process per-address throttle that already exists, plus a deduplicated Graph batch; no schema, no transaction and no cross-module change.

Review of PR #2089 (finding 10): the routes reachable without a session that this branch adds have no rate limit.

- `GET /api/mail/oauth/callback` (`services/semprec-api/src/mailOauthCallbackHandler.ts`) runs the tenant routing query `route_mail_oauth_state` and the redirect-target read for every well-formed request.
- `POST /api/calendar/graph/webhook` (`calendarWebhookHandlers.ts`) looks up to 100 notifications of one unauthenticated POST up one after the other, each `route_graph_calendar_subscription` plus a tenant transaction for a known one, even when every entry names the same subscription.
- `POST /api/calendar/google/webhook` runs one routing query per POST.
- `createClientIpThrottle` (`clientIpThrottle.ts`) throttles login, password reset and invitation acceptance per client address, but none of these listeners, which `app.ts` dispatches by path.

## Task

Load `io-hardening`, `error-handling`, `testing`.

1. `clientIpThrottle.ts`: two public actions counted per client address, `mailOauthCallback` (30 per 15 minutes, like login) and `calendarWebhook` (300 per minute; a provider delivers every subscribed account's notifications from a few addresses).
2. `mailOauthCallbackHandler.ts`: options `{ trustProxy, clientIpThrottle? }`; every request counts first, before validation and any database read; over the limit `429 { error: { code: "rate_limited" } }` with `Retry-After` and the existing no-referrer headers.
3. `calendarWebhookHandlers.ts`: both listeners take the same options; every POST counts under `calendarWebhook` before its body is read (the Graph validation handshake included); over the limit an empty `429` with `Retry-After`. A Graph batch reads its first 100 entries, drops repeated `(subscriptionId, clientState)` pairs and looks at most 20 distinct pairs up.
4. `app.ts`: pass `trustProxy`; one limiter instance shared by the two calendar webhooks.
5. Update `docs/architecture/tenancy-and-security.md` (public throttles).

## Scope

### In scope

- The three listeners above, the two throttle actions, the Graph batch's distinct lookups, the document.

### Out of scope

- The mail Graph webhook `POST /api/mail/graph/webhook` (on develop before this branch).
- A shared or persistent limiter for more than one `semprec-api` process.
- Changing the existing actions' limits.

## Acceptance criteria

- Once an address is over its `mailOauthCallback` budget, the callback answers 429 `rate_limited` with `Retry-After` and makes no database call (a listener over an unreachable pool answers 429, not 500, and logs nothing more).
- Once an address is over its `calendarWebhook` budget, the Google webhook, the Graph webhook and the Graph validation handshake answer an empty 429 with `Retry-After` before any database call; the two webhooks share one budget.
- A Graph batch of 60 copies of one subscription and 30 distinct unknown subscriptions runs exactly 20 routing lookups and still queues the known subscription's account sync once.
- The existing webhook, callback, cache-control and tenant-isolation route tests stay green.
