## Context

Model tier rationale: This adds a new tenant-scoped, grant-checked read operation exposed through REST, MCP and agents, with a ranking and result-shaping contract that other issues extend, so an authorization or tenant-isolation mistake leaks data across tenants or databases.

There is no way to search across databases. `searchItems` (`mail/search.ts`) filters one database, is not exported from the `@semprec/data` barrel, and is called only by tests; no `/api/search` route exists in `semprec-api/src/routeMatrix.ts`. The generic operation layer (`shared/genericOperations/*`, dispatched through `dispatchGenericOperation`) already serves REST, MCP (`semprec.<operation>` tools are derived from it) and agents, so a new operation there reaches all three.

The index it reads comes from #1397 (documents) and the vector and query builder from #1589. Related item names for subtitles are loaded in batches with the relation expansion from #1518. For agent actors, only databases an agent has a grant for may be searched, using the per-database grant enforcement from #1810.

Decisions:
- Results are grouped by a fixed set of types, in this order: `task`, `event`, `project`, `area`, `contact` (People and Companies together), `journal`, `file`, `mail`, `chat`. A group is an allow-list of databases by owner module (`tasks`, `events`, `projects`, `areas`, `people` + `companies`, `journal`, `files`), so internal databases (inbox pipeline, mailboxes, folders, MCP servers, settings, processing proposals, the Inbox itself, subpage storage) are never searched. Inbox entries are covered by their Journal day. User-created collections and Health records, Library and Recordings databases are not part of global search in this version (a collection is searched with `q` in its own queries, #1857).
- `mail` and `chat` are accepted scope values; their groups are filled by #1864 and #1854 and are empty here. Thread-backed results carry `threadId` instead of `itemId`, `databaseId` and `databaseKey`, so the schema is a union on group.
- Subtitle data is structural (`subtitleParts`), never localised text: the client composes the Czech text, because relative words ("Dnes") depend on the clock and time zone and MCP clients need no text.
- A task is shown with its project, never with its area (a task has a project or none).
- A company has no kind subtitle: there is no company kind in v1 and no schema change for it.
- The calendar has no search of its own: it calls this operation with `scope` `["event", "task"]`, and the calendar agenda only lays the returned results out by date.
- Search text never reaches logs or error messages: log only the query length and result counts (`backend/review-rules/rules.md`).

Shared-file ordering: this issue also waits for #1841 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `canonical-keys`, `error-handling`, `io-hardening` and `testing`.

1. Add generic operation `search` in `shared/genericOperations/` (`operationNames.ts`, `schemas.ts` with `.strict()` input and output, `port.ts`, `capabilities.ts` as a non-destructive operation requiring `core.item.read`, `bindings.ts`). Input: `q` (1 to 200 characters), `scope` (non-empty subset of the group types, default all), `perGroupLimit` (default 4, maximum 50), `cursor` (only allowed with exactly one scope type). Output: `groups: [{ type, total, items, nextCursor }]` in the fixed order, empty groups omitted, `total` always the real count even when the list is cut. Item-backed entry: `{ itemId, databaseId, databaseKey, title, subtitleParts, snippet }` with `snippet` always `null` in this issue. The MCP tool `semprec.search` follows from the operation.
2. Implement `search/searchItemsQuery.ts` over `item_search_index` using the query builder from #1589, inside `runInTenant`: exclude soft-deleted items, projects with `systemActive` true, items of archived databases, and, for an agent actor, databases without a grant. Order by `ts_rank_cd`, then `updated_at` descending, then item id. Cursor is an opaque keyset token of that order. Wire it in `application/src/genericApplicationService.ts` and `genericOperationGateway.ts`.
3. Build `subtitleParts` as `[{ kind, value, itemId? }]`, `kind` one of `date`, `time`, `timeRange`, `place`, `recurrence`, `project`, `area`, `people`, `phone`, `relationship`, `status`, `count`, `sender`, `movedFrom`, `missedInEvent`. Per group: task date, time, recurrence, project; event date, timeRange, place (when the property exists), people; project area, status; area count of its projects; contact relationship, project, phone (People) or a company marker; file project, date; journal none. Values are canonical (ISO dates, `HH:mm`, stored keys, linked item ids with titles). `movedFrom`, `missedInEvent` are part of the schema but are emitted by later issues.
4. Add `GET /api/search?q=&scope=&perGroupLimit=&cursor=` in `semprec-api` (a handler dispatching through `dispatchGenericOperation`), register it in `routeMatrix.ts` and `__tests__/tenantIsolationRoutes.test.ts`, and map validation errors to the standard error response without echoing `q`.
5. Tests with a fixed clock (2026-10-16): see acceptance criteria; include a second tenant's data and an agent without grants.

## Scope

### In scope

- The `search` operation, REST route and MCP tool, grouping, paging, ranking, visibility rules, and structured subtitles for item-backed groups.

### Out of scope

- Excerpts: `snippet` stays `null` here; building it from stored text is #1996, on top of #1658.
- `journal { type, period }` on journal results: #1859.
- Mail thread results: #1864. Semp chat results: #1854, #1854.
- `q` on collection and view queries and item counts: #1857.
- Hiding tasks that belong to unfinished events and the `missedInEvent` part: a separate follow-up issue that waits on #1780 and #1798; `movedFrom`: #1602.
- Searching Library, Health records, Recipes, Recordings and user-created collections globally: not part of global search in v1.
- Storing recent searches: they stay on the device; the backend stores nothing.
- A company "kind" subtitle: not in v1; no schema change.

## Acceptance criteria

- Without `scope`, each group has at most 4 items and the real `total`; `scope=["task"]` returns all matching tasks with a working `nextCursor`.
- Groups come in the fixed order, empty groups are missing, and People and Companies both appear under `contact`.
- A soft-deleted item, a system project, an item of an archived database, and anything from another tenant are never returned; an agent without a grant on a database does not receive its items.
- A Task "Odeslat fakturu" due 2026-10-16 14:00 to 15:30 in project "Účetnictví a faktury" returns `date` 2026-10-16, `timeRange` 14:00 to 15:30 and `project` "Účetnictví a faktury".
- "klient schválil" returns the Journal day, not an Inbox entry.
- Neither logs nor error responses contain the query text; only its length and counts are logged.
- An invalid input (empty `q`, `q` over 200 characters, `cursor` with two scope types, `perGroupLimit` over 50) is rejected with a validation error.
