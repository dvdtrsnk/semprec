## Context

`web/src/api/approvalQueueOperations.ts` has two boundary defects:

1. Line 127 `const body = (await request("/approval-requests")) as { rows?: unknown[] };` — an unchecked cast at the API boundary (`web/review-rules/tasks/correctness.md` item 1, `web/review-rules/rules.md` "no `any`/unchecked cast at a module boundary"). Every other adapter parses its envelope (`mcpAgentPageOperations.ts` line 29 `mcpToolGrantsResponseSchema`); here a body that is `null`, a string or `{ rows: "x" }` reaches `.map` and throws a `TypeError` outside the adapter's error mapping.
2. Lines 87-91 `DecideApprovalRequestInput.decidedByUserId` and line 135 send `decidedByUserId` in the PATCH body. Its value comes from the URL: `web/src/main.tsx` line 41-47 routes `?page=approvals` only when `?user=<id>` is present and passes it as `decidedByUserId` through `App.tsx` (`ApprovalQueueRoute`, lines 29-31, 88) to `ApprovalQueue.tsx` (prop at lines 124-127, sent at line 143). Any visitor could attribute a decision to any user id. Issue #629 (auth-hardening) makes the backend derive `decided_by` from the session and **ignore** a body `decidedByUserId`; after #629 merges the field is dead weight and the `?user=` requirement only makes the page unreachable without a made-up id.

Also in `web/src/views/approvalQueue/ApprovalQueue.tsx` line 166: `key={entry.row.id ?? Math.random()}` — a new key on every render for a malformed row without an id, remounting that `<li>` each time; fixed here because this issue already edits the file.

Sibling issue G3 of this batch rewrites `main.tsx`/`App.tsx` for the session bootstrap; this issue applies on top of it. The backend still generates links of the form `?page=approvals&user=<id>` (`backend/packages/application/src/genericOperationGateway.ts` line 237, `backend/packages/agent-runtime/src/mcpInvokeTool.ts` line 186, and `?page=approvals&id=…` at `genericOperationGateway.ts` line 301); those keep working because the client simply ignores unknown query parameters — the backend links are the multi-tenant epic's to change, not this issue's.
