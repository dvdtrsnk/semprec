## Context

Model tier rationale: An additive view-config field that changes ordering and keyset cursor semantics of grouped queries, where continuity across pages and groups is the risk.

Grouped views sort first by the grouping property ascending and then by the view's own sort (`buildSortSpecs` in `backend/packages/data/src/views/viewQuery.ts`); the config has `groupBy` as a plain string with no direction (`backend/packages/data/src/views/viewConfig.ts`). The Journal collection must list groups in the order day, week, month, quarter, year, which is the reverse of the order of the options of the Journal `type` property (year, quarter, month, week, day, which matches the Journal switcher and `JOURNAL_PERIOD_TYPES`). Reordering the options is not an option: the schema is locked and the options mirror the switcher.

#1408 makes select groups sort by option order, with items without a value last, and the keyset cursor carry the sort values. This issue adds only the direction.

Decision: the field is optional and additive (ADR `docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`), default `asc`, so every existing view behaves as before.

## Task

Load `testing`.

1. Add optional `groupDirection: "asc" | "desc"` to the view config schema and the `ViewConfig` type (`views/viewConfig.ts`); reject other values with a validation error.
2. In `buildSortSpecs` (`views/viewQuery.ts`), use `groupDirection` (default `asc`) for the leading group sort. With `desc` the order of groups is reversed, items with no group value stay last, and the sort within a group is unchanged.
3. Ensure the keyset cursor encodes the effective direction of the group key so paging across a group boundary with `desc` returns each item exactly once and in order; a cursor produced under a different direction is refused as invalid.
4. Tests in the view pagination suite: grouping by an options-ordered select with `groupDirection: 'desc'` returns groups in reverse option order; a view without `groupDirection` returns the order of #1408; paging with a small limit across the boundary of two groups returns every item once; items without a value remain last.

### Out of scope

## Acceptance criteria

- When a view groups by Journal `type` with `groupDirection: 'desc'`, then groups come in the order day, week, month, quarter, year, and within weeks `2026-W41` comes before `2026-W40` when the view sorts `period` descending.
- When a view has no `groupDirection`, then groups come in option order as before.
- When a query is paged across a group boundary with `desc`, then every item appears exactly once.
