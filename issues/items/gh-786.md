## Context

PR #376 (`errorContract.ts`) flagged that `isVersionConflictDetails` checks
`current.id`, `current.databaseId`, `current.properties`, and `current.updatedAt` but
not `current.computed` or `current.deletedAt`. `ItemRow`
(`backend/packages/data/src/types.ts:93-100`) has all six fields, and
`toItemEnvelope` (`itemEnvelope.ts:20-28`) reads all six without its own validation.
A future `ConflictError` constructed with a `current` object missing `computed` or
`deletedAt` would pass this guard and be projected into a malformed `ItemEnvelope`
(e.g. `computed: undefined`) served to the HTTP client, instead of falling through to
the generic `details` branch as the guard's own docstring says it's meant to.

## Task

In `backend/services/semprec-api/src/adapter/errorContract.ts`'s
`isVersionConflictDetails`, add the same `typeof (current as Partial<ItemRow>).X`
check already used for the other four fields for `computed` (must be `"object"`) and
`deletedAt` (must be `"string"` or `null`).

## Touches

- backend/services/semprec-api/src/adapter/errorContract.ts
  (`isVersionConflictDetails`)

## Scope

### In scope

- Extending the guard to cover `computed` and `deletedAt`.

### Out of scope

- Any other guard or error-mapping function in this file.

## Acceptance criteria

- A `ConflictError` whose `details.current` has all six `ItemRow` fields still maps
  to a `VersionConflictDetails` response, unchanged from today.
- A `ConflictError` whose `details.current` is missing `computed` or has a
  non-object `computed` falls through to the generic `details` branch instead of
  being projected as an item.
- A `ConflictError` whose `details.current` is missing `deletedAt` or has a
  `deletedAt` that is neither a string nor `null` falls through to the generic
  `details` branch instead of being projected as an item.
