**Blocked by:** #621, #642, #647, #651, #696

## Context

Review follow-up harvested in #728, from PR #325: `backend/packages/ai-gateway/package.json:14` lists `pg` under `dependencies`, but the package only imports types from it (`import type { Pool, PoolClient } from "pg"` in `src/gateway.ts:1` and `src/__tests__/gateway.test.ts:2`), which are erased at compile time; `Pool`/`PoolClient` objects always come from the caller. `@types/pg` is already a dev dependency.

Removing the dependency changes `backend/pnpm-lock.yaml`, which #621, #642, #647, #651 and #696 also edit.

## Task

Remove `pg` from `dependencies` in `backend/packages/ai-gateway/package.json` and regenerate `backend/pnpm-lock.yaml` with `pnpm install`.

## Touches

- backend/packages/ai-gateway/package.json
- backend/pnpm-lock.yaml

## Scope

### In scope

- The dependency removal and the lockfile update.

### Out of scope

- Dependencies of any other package.

## Acceptance criteria

- `backend/packages/ai-gateway/package.json` has no `pg` entry under `dependencies` and keeps `@types/pg` under `devDependencies`.
- `pnpm install --frozen-lockfile` succeeds in `backend/`, and `pnpm run verify` passes.
