## Context

`backend/packages/data/src/chokePoint/chokePoint.ts` grew from 400 to 2000 lines in three weeks because nothing limits file size. After the split (#507–#516), no production source file in `backend/` exceeds 900 lines; the largest, `backend/services/semprec-transcribe/src/transcriptionTask.ts`, has about 860. The cap described in `docs/adr/2026-09-24-choke-point-composed-from-domain-modules.md` makes that permanent. #530 applies the same cap to `web/`.

## Task

Add `max-lines: ["error", { max: 900, skipBlankLines: true, skipComments: true }]` to `backend/eslint.config.mjs` for `**/*.ts`, excluding test files (`**/*.test.ts`, `**/__tests__/**`). Next to the rule, add a comment pointing to the ADR and saying why tests are exempt: they are not part of the runtime surface, and splitting the largest ones is a separate decision.

Do not add any per-file exemption. If a production file exceeds 900 counted lines when you implement this, do not raise the cap and do not exempt the file. Stop with `Relay-Step-Status: blocked` and name the file and its count.

- backend/eslint.config.mjs

## Scope

### In scope
- The rule and its comment.

### Out of scope
- `web/` (#530).
- Splitting any file, test files included (`mailSync.test.ts` is deliberately outside this batch).
- Any other lint rule.

## Acceptance criteria

- `pnpm run verify` in `backend/` passes.
- A production `.ts` file of 901 counted lines fails `pnpm run lint` with `max-lines`, and a test file of the same size does not. Check this by hand once, revert it, and say so in the pull request description.
- The config contains no `eslint-disable` and no per-file override for `max-lines`.
