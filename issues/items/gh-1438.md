## Context

Model tier rationale: One additive column with a default on an existing table, no data migration and no behavior change, following the standard expand-migration pattern.

A project's automations (ticks) are rows of `project_heartbeats` (`backend/packages/data/src/db/migrations/0001_core_schema.sql`). Every heartbeat that exists today is a system heartbeat: created by seeds (`backend/packages/data/src/seed/seedSystem.ts`), by the transcription requeue cutover and by the project-guidance drift upsert. Even the seeded new-email automation uses the action `core.agentRun`. The app will list only automations a person asked Semp to create, and will let a person switch only those on or off. Nothing in the table tells the two kinds apart.

The listing (#1910), the on/off route (#1551), the approval-gated creation tool (#1846) and the project agent summary (#1935) all depend on this marker.

Decision: the column is `origin text NOT NULL DEFAULT 'system'` with `CHECK (origin IN ('user','system'))`; no seed is changed and no data migration is written, so every existing row is `system`. Only `heartbeat.create` (#1846) writes `user`.
