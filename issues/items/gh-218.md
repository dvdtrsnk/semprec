**Blocked by:** #217, #87, #25, #115, #147, #158

## Context

The library-grid client of #88 must render field labels and select option labels without re-resolving them client-side, so the server must return an authoritative locale-resolved property catalog. #217 bootstrapped the `web/` workspace and typed `listProperties` against the current thin route; this backend-only issue evolves that route additively and prepares the library contract values the client consumes. #88 builds the container over this response.

## Task

Evolve #37's existing thin authenticated `GET /api/databases/:databaseId/properties` route; do not register a duplicate route. Preserve its raw authoritative fields and add resolved `label` plus `options`, yielding `{ properties: Array<{ id, databaseId, key, type, label, options?: Array<{ key, label }>, locked, owner, ownerProcess, migrationStatus }> }`. It calls the existing data/application `listProperties(databaseId)` and applies #35's resolver server-side using authenticated `users.locale`: explicit override → locale catalog → English → raw key. The client never re-resolves labels. Missing database remains #37's `404 not_found`, archived databases remain readable, and unauthenticated access remains #34's 401. This is an additive response evolution of the one #37 route. Update the `listProperties` response type of the `web/` API client from #217 to this shape; no other client change is made here.

ModuleRegistry runtime-validates and projects all eight `library-grid` contract fields (`coverKey`, `subtitleKey`, `ratingKey`, `secondaryRatingKey`, `secondaryRatingLabel`, `sourceUrlKey`, `statusKey`, `coverGlyph`).

`secondaryRatingLabel` is an i18n key, never literal display text. Migrate the Movies contract value from `Critics' rating` to `property.movies.secondaryRating.name`; Books omits it. Shipping that key in `web/src/i18n/en.json` and `cs.json` and resolving it in the renderer is done by #88.

## Scope

### In scope

- Additive evolution of `GET /api/databases/:databaseId/properties` with server-resolved `label`/`options`, its auth/not-found integration tests, the client type update, ModuleRegistry contract validation/projection, and the Movies `secondaryRatingLabel` key migration.

### Out of scope

- The web workspace bootstrap, view registry, and shared API client, delivered by #217.
- The `library-grid` view component, container, i18n keys, and all UI behavior, delivered by #88.
- Changes to the library backend contract beyond the above; external metadata providers or a special library API.

## Acceptance criteria

- The authenticated property-catalog route exists before container mounting and returns one authoritative server-localized schema with auth/not-found integration tests: a Czech user receives Czech labels/options, an English user English ones, an explicit override wins, and an untranslated key falls back English → raw key.
- All raw fields (`id, databaseId, key, type, locked, owner, ownerProcess, migrationStatus`) are preserved; `options` is present only for properties that define options.
- Missing database returns `404 not_found`, archived databases are readable, unauthenticated access returns 401, and exactly one route handler is registered for the path.
- ModuleRegistry rejects a `library-grid` contract with a missing/mistyped required field and projects all eight fields; the seeded Movies/TV contract carries `secondaryRatingLabel = 'property.movies.secondaryRating.name'` and Books carries none.
