## Context

Model tier rationale: One new authenticated read route over an existing table with a fixed response shape, whose only sharp edge (never exposing the token hash or another user's sessions) is covered by the existing route-matrix isolation tests.

The app shows the account's signed-in devices: "this device" first, then every other active login with its kind, client, last activity and sign-in date. No route returns this today. `listSessionsForUser` in `backend/packages/data/src/auth/sessionsStore.ts` has no HTTP route and returns revoked and expired sessions too, ordered by `created_at`, including `tokenHash`.

This issue adds the read route. It builds on #1354 (device columns) and #1512 (sessions that stay alive are the ones that show up with a recent `lastSeenAt`). #1650 adds the bulk sign-out next to it, and the account summary for the profile screen (#1903) reuses the active-session query to count devices.

Decision: the server returns structured data only (kinds, names, versions, timestamps). Labels such as "iOS app" or "Safari on macOS" and relative times such as "2 hours ago" are composed by the client, because they are user-facing strings.

Shared-file ordering: this issue also waits for #1576 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `testing` and `error-handling`.

1. In `sessionsStore.ts` add `listActiveSessionsForUser(client, userId)`: `revoked_at IS NULL AND expires_at > now()` for that user, `ORDER BY last_seen_at DESC, id`. Leave `listSessionsForUser` unchanged.
2. In `authHandler.ts` add `GET /api/auth/sessions`: authenticate with `authenticateRequest`, then respond 200 `{ "sessions": [ { id, current, platform, deviceKind, deviceName, osVersion, appVersion, createdAt, lastSeenAt } ] }`. `current` is `id === identity.session.id`. Never include `tokenHash`, `userId`, `userAgent`, `expiresAt` or `revokedAt`. Sessions created before #1354 have `null` device fields. The path must not match `REVOKE_SESSION_PATH`.
3. Register the route in `backend/services/semprec-api/src/routeMatrix.ts` as "list sessions" (`GET /api/auth/sessions`, `surface: "api"`, `public: false`, `tenancy: "account"`), add its case to `__tests__/tenantIsolationRoutes.test.ts` (another tenant's caller sees none of tenant A's session ids), and map it to `authHandler.ts` in `ROUTE_HANDLER_FILES` in `__tests__/chokePointWriteBoundary.unit.test.ts`.
4. Add tests in `authHandler.test.ts` and a store test: only active sessions, ordered by last activity, exactly one `current`, no `tokenHash`, no other user's sessions, a revoked and an expired session omitted.

## Scope

### In scope

- The active-sessions query and `GET /api/auth/sessions` with the response shape above, plus its route-matrix registration and tests.

### Out of scope

- Bulk sign-out of the other devices: #1650.
- Device counts on the profile: #1903.
- Signing out one device: the existing `POST /api/auth/sessions/:id/revoke` is unchanged.
- Returning an OS or app version label, or any localized text.

## Acceptance criteria

- When a user with three active sessions and one revoked session calls `GET /api/auth/sessions`, then exactly the three active sessions are returned ordered by `lastSeenAt` descending, and exactly one has `current: true`, the one whose token made the call.
- The response never contains `tokenHash` and never contains a session of another user.
- A session whose `expires_at` is in the past is not returned.
- Sessions created before device identity existed are returned with `null` device fields.
- An unauthenticated call gets 401.
