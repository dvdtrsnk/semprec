## Context

Model tier rationale: One refusal-ordering change in the gateway's reservation transaction plus a data-layer helper, verified with existing gateway and tenant fixtures; it touches a tenant-isolation contract, so it is above low.

This replaces #1190. #1190 waited on #1057 and also edited #1057's new test file, while #1057's own pull request (#1184) cannot merge until this leak is fixed: a cycle. This issue fixes the gateway alone. Once it merges, #1184 turns its `it.fails` case into a normal test in a later fix round.

The two-tenant gateway suite in #1184 found the leak. `reserve()` in `backend/packages/ai-gateway/src/gateway.ts` takes the budget advisory lock, then runs `assertWithinBudget`, then `reserveGatewayCall`:

- An unknown tenant id (a random UUID in `x-semprec-tenant-id`) has no `tenant_ai_budgets` row, so `assertWithinBudget` refuses it with `noTenantBudget`: `403 { "error": "AI budget exceeded", "code": "budget_exceeded" }`.
- A suspended tenant still has its budget row (migration `0070_tenant_ai_budgets.sql` seeds one per tenant and suspension does not remove it), so it passes the budget gate and is refused by `reserveGatewayCall`'s `status = 'active'` predicate (`backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts`): `403 attribution_refused`.

Any caller holding the internal token can therefore tell a suspended tenant id from one that does not exist. That is the existence signal the tenant-isolation rules forbid (`docs/adr/2026-10-03-tenant-isolation-through-row-level-security.md`). #993 introduced the attribution guard and #1035 the per-tenant budget gate; this issue fixes how the two combine. No ADR records the current order.

## Task

Load `state-writes`, `error-handling` and `testing`.

1. In `backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts`, add `assertGatewayTenantActive(client: Pool | PoolClient): Promise<void>`. It runs `SELECT EXISTS (SELECT 1 FROM tenants WHERE id = app_tenant_default() AND status = 'active') AS active`, read with a row type. When the result is false, it throws the same `ForbiddenError` that `reserveGatewayCall` throws today: message "AI gateway call is not attributable to the caller's tenant", no details, code `attribution_refused`. Its docstring says it exists so an inactive and an unknown tenant get one refusal, and that `reserveGatewayCall` keeps its own `status = 'active'` predicate as the write-time guard.
2. In `reserve()` in `backend/packages/ai-gateway/src/gateway.ts`, call `assertGatewayTenantActive(tx)` after the advisory lock and before `assertWithinBudget(tx, ctx.globalCaps)`, inside the same transaction. Update `reserve`'s docstring to state the order: lock, tenant-active check, budget check, conditional insert.
3. In `backend/services/semprec-ai-gateway/src/__tests__/callerTenant.test.ts`, replace the test "refuses a tenant that does not exist with 403 budget_exceeded, before attribution is checked" with one asserting that a tenant that does not exist gets `403` with exactly the body the suspended-tenant test there gets, writes no row and does not call the provider.
4. In `backend/packages/data/src/__tests__/aiGatewayCallAttribution.test.ts`, add tests for `assertGatewayTenantActive`:
   - an active tenant resolves;
   - a `provisioning`, a `suspended` and a `deleting` tenant, and an unknown tenant id under `runInTenant(randomUUID(), …)`, all reject with `attribution_refused` and no details.
