## Context

Model tier rationale: One new read route that answers two grouped counts in one query on top of the filters already built, with a defined counting rule and the route matrix and isolation test to extend.

The filter bar of the mailbox shows, per area and per project, how many threads match, and the counts must react to the other group: the chosen project narrows the area counts and the chosen area narrows the project counts. Counts must come from one call. The filters `projectId` and `areaId` exist after #1638. A thread is counted only when it has a visible message: not deleted and not in the Junk or Trash folder.

Decisions: the facet route is independent of the box, folder and mailbox filters (it counts across all visible threads). Thread without a project count only in `total`. Areas are returned even with count 0; projects only when the count is above 0.

Shared-file ordering: this issue also waits for #1742 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. Declare the route `GET /api/mail/threads/facets` in the `customRoutes` of `mail/mailModuleManifest.ts` with justification `single-consumer-read`, handler export in `mail/mailThreadRouteHandlers.ts`, query parameters `areaId` and `projectId` (uuid, optional).
2. Response `{ total, areas: { total, items: [{ id, count }] }, projects: { total, items: [{ id, areaId, count }] } }` computed by one query:
   - `total`: all visible threads, no filter.
   - `areas.items`: every area (also with count 0); each count is the number of visible threads whose project is in that area, narrowed by `projectId` when given; `areas.total` is the number of visible threads narrowed by `projectId` when given.
   - `projects.items`: only projects with count above 0, each with its `areaId`; counts are narrowed by `areaId` when given; `projects.total` is the number of visible threads narrowed by `areaId` when given.
3. Add the route to `backend/services/semprec-api/src/routeMatrix.ts` and to the tenant-isolation route test.

## Acceptance criteria

- On a fixture with threads in several areas and one thread without a project, `total` counts all visible threads and an area without threads has count 0.
- Passing `areaId` changes the project counts to that area's projects and passing `projectId` changes the area counts to that project's threads.
- A thread whose only messages are in Junk or Trash is counted nowhere.
- A user never sees counts of another tenant.
