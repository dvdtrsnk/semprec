**Model tier:** medium

## Context

Model tier rationale: Two hooks on the item delete and restore paths that recompute tasks and remove edges in the same transaction, using a recompute function and counts from blockers, with the product decision for restore recorded.

When an event is deleted, the tasks it hosted return to their own day, decided by the event that was added before it, or by their own date if there is none. When it is restored, the user's principle is that restoring a source does not link things again, so the tasks do not go back into the event. Deletion and restore of items cascade only through inline databases (#1601 adds delete and restore hooks to the choke point; hooks run in the same transaction for every row actually trashed or restored). A soft delete leaves relation edges in place. #1780 recomputes a task's derived state from its live host events (a trashed event does not count) with `recomputeTaskHostState`, and #1801 counts the tasks of an event per state.

This issue registers the delete and restore hooks for Events. The deletion confirmation shown to the user needs the number of tasks that return; the counts come from #1801.

Decisions:
- On delete: every live task hosted by the event is recomputed in the same transaction; the edges stay (the number of returning tasks can still be read from them while the event is in the trash).
- On restore (decided by the product owner, in line with the rule that restoring a source does not re-link): the tasks are not put back into the event. The hook removes the event's `hostedTasks` edges, which recomputes each task through the edge hook of #1780.
- Completed-in-event edges are not touched by either hook.

Shared-file ordering: this issue also waits for #1817 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling` and `testing`.

1. In `backend/packages/data/src/tasks/eventHostedTasksHooks.ts` add an item delete hook and an item restore hook (#1601), gated on the Events database and registered in `domainWriteHooks.ts`. Delete: read the hosted tasks of the trashed event (edges of `Events.hostedTasks`, live tasks) and call `recomputeTaskHostState` for each. Restore: for each such edge, delete it through `deleteRelationWithClient` with the system context `{ ownerProcess: "tasks" }` (the edge hook then recomputes the task).
2. Export `countTasksReturningFromEvent(client, eventId)` (the number of live hosted tasks that are not completed in the event, from the same reader as the counts of #1801) for the deletion confirmation, so clients and approval wording can show "Tasks in the event (N) return to their day".
3. Tests: deleting an event hosting a task returns the task to the day decided by the previous host event, or to its own date when there is none, and clears `hiddenUntil` when no live host event remains; the task receives an invalidation; restoring the event leaves the task out of it and removes the edge; an event with no hosted tasks adds no writes; a failing hook rolls back the deletion; `countTasksReturningFromEvent` equals the number of returning tasks.

## Scope

### In scope

### Out of scope

- The events' task list and counts: #1801.
- The wording of the deletion confirmation and of the approval request for an agent's event delete: not planned yet; it waits for the approval-description work (this issue only provides the count).
- The delete impact preview: #1856.

## Acceptance criteria

- When an event with a hosted task is deleted, then the task returns to the day decided by the previous host event, or to its own date, and is visible again if no live host event remains.
- When a deleted event is restored, then its hosted tasks are not linked to it again.
- When an event has no hosted tasks, then deleting and restoring it performs no extra task write.
- When a hook fails, then the event stays live and the tasks are unchanged.
- When the deletion confirmation asks for the count, then `countTasksReturningFromEvent` returns the number of tasks that will return.
