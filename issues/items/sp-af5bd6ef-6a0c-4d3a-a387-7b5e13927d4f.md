## Context

Model tier rationale: Four linked fixes across the password connect route, a new credential-replacing route with mail and calendar state transitions, the mailbox restore hook, the mail sync job, the sweep and the IMAP IDLE lifecycle; lock order, single-writer ownership and tenant isolation all apply.

Production was carried from v0.1.x without `external_credentials`, so the iCloud (app password) and generic (plain password) mail accounts have no credential. Mail showed "sync error" (`failureKind: "unexpected"` logged every minute, plus `IMAP IDLE lifecycle failed`), Calendars "sign in again", and there was no way to enter a password again. The owner removed both accounts (now trashed Mailboxes items); adding them again failed with 409 because `mailboxHoldsAddress` (`mail/mailboxPasswordRouteHandlers.ts`) reads the `addresses` of every Mailboxes item, trashed ones included.

Decisions: the duplicate rule counts live mailboxes only (a removal deletes the sync state row, so a trashed mailbox records no provider account address; the unique index keeps deciding the recorded address). Restoring a trashed mailbox whose address a live mailbox holds is refused with 409 `provider_account_already_connected`. A password account re-enters its password on the existing mailbox through a new route; mail, folders and threads stay. A missing credential is a reauthorization case for mail as it is for calendars; such an account is not swept again and its IMAP IDLE discovery stops until the credential is replaced.

The mobile agent builds against the route contract below in parallel (sp-fd844365-bc0a-46da-8429-3af7a1b2d230); it must not change.

## Task

Load `state-writes`, `io-hardening`, `error-handling`, `testing`, `adr-conventions`.

1. Duplicate rule: `mailboxHoldsAddress` reads only live Mailboxes items (`deleted_at IS NULL`), in the pre-check and in the in-transaction re-check of the password connect route. The OAuth connect path keeps deciding through the address unique index. `mailboxItemRestoreHook` refuses (409 `provider_account_already_connected`, rolling the restore back) a restore of a mailbox one of whose addresses another live mailbox lists or records.
2. `PUT /api/mail/mailboxes/:id/password`, mounted with the password connect route (same auth, throttle `mailboxCredentialVerification`, body caps). Request `{ "password": string (1..1024), "username"?: string }`, strict; `username` defaults to the stored `mail_account_server_settings.username`. A malformed or unknown id, another tenant's or a trashed mailbox → 404 `not_found`. A live mailbox whose provider is not `icloud`/`generic`, that has no IMAP/SMTP server settings or whose sync mode is not `imap` → 409 `mailbox_not_password`. Verify with `verifyPassword` against the stored IMAP/SMTP hosts and, with Calendars on and a CalDAV address (iCloud's fixed one, or the stored `caldav_url`), `verifyCalDav`; refusals answer 400 with the connect route's codes. On success, in one transaction under the sync state row lock then the Mailboxes item lock: replace the sealed credential, store the verified endpoints and the user name, clear the mail failure record (`last_error`, `last_failure_kind`, `failing_since`, `next_expected_activity_at`), set a calendar `needsReauthorization` status to `never`, enqueue a mail sync and (Calendars on) a calendar sync; after the commit restart the hosted live sync (`mailLiveSync.restartAccount`). Answer 200 `{ item }`. The password is in no response and no log line.
3. A mail sync pass with no stored credential fails with `MailReauthorizationRequiredError` whatever the `syncStatus` (`last_failure_kind` `reauthorization`, `syncStatus` `needsReauthorization`). `listAccountsDueForSync` leaves out accounts whose last failure is `reauthorization`. The hosted IMAP IDLE lifecycle stops its discovery, without retrying, when it meets `MailReauthorizationRequiredError`; the composition root's `getCredential` throws it for a missing credential.
4. Every refusal of the connect route and the new route answers `{ "error": { "code" } }` with a stable code; the handover lists every code with its HTTP status.
5. `docs/operations/production-cutover-to-develop.md` "Reconnect mail accounts": password accounts re-enter the password on the existing account. `docs/architecture/domain-mail-and-inbox.md`: the duplicate rule, the restore refusal, the password route, the missing-credential and sweep rules, the IDLE stop.

## Acceptance criteria

- After a mailbox is removed, connecting its address again succeeds; restoring the removed one is then refused with 409 `provider_account_already_connected`; a live duplicate is still refused with 409.
- `PUT /api/mail/mailboxes/:id/password` with the right password replaces the credential, queues a mail and a calendar sync, clears the mail failure record and the calendar `needsReauthorization`, and answers 200 `{ item }`; a wrong password answers 400 with the verification code and leaves the credential untouched; an OAuth mailbox answers 409 `mailbox_not_password`; another tenant's and a trashed mailbox answer 404.
- A password mailbox without a credential ends a sync pass with `last_failure_kind` `reauthorization` and `syncStatus` `needsReauthorization`, is not listed by the sweep, and its IMAP IDLE lifecycle makes no further attempt.
- The route catalogs, the tenant isolation route matrix and the public surface list the new route.
