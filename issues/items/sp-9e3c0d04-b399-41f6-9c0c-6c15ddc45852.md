## Context

Model tier rationale: Restructures one App Intent into a background intent that hands the scan to a second, foreground-only intent; known App Intents mechanisms, but the system's toggle behavior must be checked against the SDK.

The owner tested `AddToInboxIntent` (issues `sp-5440a887-f4a6-4c91-b8d8-64937880de5b`, `sp-1f163b60-cd6a-4f10-a92d-ccc37075ab3a`). Two changes:

1. The action shows an "Open When Run" toggle in Shortcuts. It must not: a text capture never opens the app, a scan always does. The toggle appears because the intent declares both background and foreground modes.
2. There must be no separate Text/Scan question. Instead the list of Inbox types offered first includes "Scan" (with "No type" and the server's types), so one pick opens the scanner directly.

## Task

1. `AddToInboxIntent` supports only the background mode. Its type parameter offers "Scan" first on iOS when `VNDocumentCameraViewController.isSupported`, then "No type", then the Inbox types; macOS and devices without the scanner do not offer "Scan". Remove the content parameter and `InboxContent`.
2. Picking a type or "No type" asks for the text and captures it as today, in the background.
3. Picking "Scan" returns, as the intent's result, a second intent `ScanIntoInboxIntent` (`supportedModes` foreground only, `isDiscoverable = false`) that the system runs, which opens the app on the scanner through the existing `ScanPresenter` and captures the PDF without a type and without text; it answers that the scan is saved or cancelled.
4. Check in the AppIntents SDK interface that neither intent is shown with an "Open When Run" toggle and record the finding, with the mode choice, in a new ADR that narrows `docs/adr/2026-11-27-apple-system-entry-points-run-in-the-app-over-a-headless-sdk.md` (load `adr-conventions`).
5. Update copy in English and Czech and the App Shortcut phrases if they mention the content choice.

## Scope

### Out of scope

## Acceptance criteria

- In Shortcuts the action has no "Open When Run" toggle.
- Running it lists Scan, No type and the types; a type leads to the text field and a background capture; Scan opens Semprec on the scanner and a finished scan is captured without type; cancelling captures nothing.
- On macOS the list has no Scan.
- Tests cover the type list composition per platform and the result choice (text vs scan intent).
