## Task

Bump the pinned `dvdtrsnk/code-review-bot` revision in `.relay/config.yml`
(`review.bot.ref`) and `.github/workflows/code-review.yml` (the
`Checkout code-review-bot (private)` step's `ref:`) to
`9e732e791c6bcdbfa4683d6ad93ed1f7441a3d61`.

That commit fixes a real bug in the cheap-reuse-after-rebase feature shipped
by the prior pin bumps (#489/#490/#492): `PrCommentMemoryStore.save()`
skipped persisting anything for a PR whose review found zero issues — "a
clean pull request should not collect a note" — which also silently dropped
`cmd_record_verdict`'s own save whenever the review was clean. A rebase that
reproduced the exact same diff on such a PR could therefore never find a
prior verdict to cite, and always fell through to a full review — the most
common case in practice, since most reviewed PRs pass clean. A PR with at
least one finding never hit this, since a memory note already existed by the
time the verdict was recorded.

Evidence from this repo: PR #531 (clean approve, no memory note) got a full
~7 min re-review after a rebase that reproduced an identical diff; PR #533
(one low finding, so a note existed) got "AI Review — Reused Prior Verdict"
in 26 s for the same kind of rebase. See `dvdtrsnk/code-review-bot#27` for
the fix itself.
