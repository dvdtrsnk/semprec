## Context

Model tier rationale: This writes per-tenant persisted data under row-level security during a deploy cutover and in the account-creation path, with an ownership rule (every guidance row needs the tenant's user) that has to hold for tenants that have no user yet, so a wrong step leaves guidance missing or foreign.

A project's agent instructions ("AGENT.md": purpose, what the agent may do, what it may not do, general instructions) live in two unconnected places today.

- The Projects database has a locked `longText` property `agents` (`backend/packages/data/src/seed/seedTenDatabases.ts`, `config.sections` = `purpose`, `allowed`, `notAllowed`, `generalInstructions`). The seeds fill it with one text of the form `Purpose: ...\nAllowed: ...\nNot allowed: ...\nGeneral instructions: ...` for the five system projects: Semprec (`seedSystem.ts`), MCP (`seedMcpModule.ts`), Email (`seedEmailModule.ts`), Books and Movies/TV (`seedLibraryModule.ts`). Only the web AGENT page reads it; no backend code does.
- The table `project_agent_guidance` (`project_item_id` primary key, `owner_user_id NOT NULL`, `markdown`, `updated_at`; migration 0033) is what the agent actually reads: `createProjectAgentGuidanceSystemPromptOverride` appends it under "## Project-specific guidance" in `backend/services/semprec-agents/src/agentSessionComposition.ts`, and `core.agentGuidanceDrift` compares it with the permission manifest. Nothing writes it: `createProjectAgentGuidanceService` (`backend/packages/application/src/projectAgentGuidance/service.ts`) has no caller. As a result no project's agent receives its instructions and the daily "Detect agent guidance drift" heartbeat is never created.

This issue makes `project_agent_guidance` the single source of truth by moving the existing text into it. The tenant zero seed runs at deploy (`runSeed` -> `provisionTenant` -> `seedSystem`) before `bootstrapFirstAccount` (`backend/packages/data/src/auth/authActions.ts`) creates the first user, so the seed has no owner to write; guidance therefore cannot be written by the seed and is written (a) once for existing tenants by a per-tenant cutover and (b) whenever an account is created. #1548 then serves and saves the rows over HTTP, and #1611 moves the web page onto that API and removes the `agents` property.

Decisions:

- Canonical Markdown has four reserved level-2 headings in this order: `## Purpose`, `## Allowed`, `## Not allowed`, `## General instructions`. Empty sections are omitted. Each section's text is trimmed; sections are joined by one blank line; the document ends with one newline.
- Legacy text is split on line-start markers `Purpose:`, `Allowed:`, `Not allowed:`, `General instructions:` (case-sensitive, optional single space after the colon; a section runs until the next marker). Text with no marker goes entirely into General instructions. Text before the first marker is prepended to General instructions. A repeated marker appends to its section.
- The owner of every created row is the tenant's user (`getTenantUserId`). A tenant without a user is skipped; its rows are created when its account is created.
- A converted document above `MAX_PROJECT_AGENT_GUIDANCE_MARKDOWN_BYTES` is skipped with a warning log that names the tenant and project ids only (never the text).
- Creating a row also creates the project's drift heartbeat through `guidanceDriftHeartbeatStore.upsertDriftHeartbeat` in the same transaction (only when the row was actually inserted), because migration 0035 backfilled heartbeats only for rows that existed at that time.
- The seed texts move into one exported constant map so that new accounts get the same text after #1611 stops seeding the property. A system project is identified by a stable key plus `systemActive = true`, never by its name, so renaming a system project does not break the assignment of its guidance (decided by the product owner). The stable key is the owner module id of the system database the project owns (`databases.system` and `databases.owner_module_id`, with `databases.owner_project_item_id` pointing at the project): `SYSTEM_SETTINGS_MODULE_ID` for Semprec, `MCP_SERVERS_MODULE_ID` for MCP, `MAILBOXES_MODULE_ID` for Email, `BOOKS_MODULE_ID` for Books and `MOVIES_MODULE_ID` for Movies/TV. These ids are written by the seeds and never change.

Shared-file ordering: this issue also waits for #1416 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Scope

### In scope

- The canonical Markdown composition and the legacy text conversion.
- The per-tenant cutover and the account-creation seeding, both idempotent.
- Creating the drift heartbeat with each inserted row.

### Out of scope

- Reading or saving guidance over HTTP and parsing Markdown back into sections: #1548.
- Switching the web AGENT page and removing the `agents` property, its seed values and its i18n names: #1611.
- Deleting guidance rows (nothing deletes them yet) and ownership transfer over HTTP.

## Acceptance criteria

- When the cutover runs for a tenant whose user exists and whose Projects item has `agents` = `Purpose: A\nAllowed: B\nNot allowed: C\nGeneral instructions: D`, then a guidance row exists for that project, owned by the tenant's user, whose Markdown has the four headings in order with the texts A, B, C, D, and the project has an enabled `core.agentGuidanceDrift` heartbeat.
- When `agents` has no markers, then the whole text is the General instructions section.
- When the cutover runs a second time, or after the user edited a guidance row, then no row is changed or overwritten.
- When a tenant has no user, then the cutover writes nothing for it and does not fail; one tenant failing does not stop the others.
- When the first account is created (and when an invited account is accepted), then each system project of the tenant has a guidance row from the seed texts.
- When a system project was renamed before the account-time seeding runs, then it still gets its guidance row from the seed text of its key; a user project that carries a system project's name but owns no system database gets none.
- When a project's next agent run starts after the cutover, then its prompt contains "## Project-specific guidance" followed by the converted text.
- A cutover test shows tenant A's rows are never written under tenant B's scope.
