**Model tier:** medium

## Context

Model tier rationale: A destructive purge cleanup registered through an existing hook registry, with a defined set of tables, but it must delete exactly the purged item's rows and nothing shared.

When an item is permanently deleted, `deleteItemDependents` in `backend/packages/data/src/chokePoint/itemTrash.ts` removes relations, view entries, the document, recurrence and search rows. It knows nothing about mail, so after a purge of an Email the rows keyed by that item remain: `mail_message_meta`, `mail_attachments` and `mail_message_flag_sync_state`; a purged Mailboxes item also leaves remainders of the removal (#1690).

Mail code must not be imported into `chokePoint/` (the `chokepoint-knows-no-domain` rule in `backend/dependency-cruiser.rules.json`; `docs/adr/2026-09-30-choke-point-domain-hooks-through-a-per-process-registry.md`). The purge hook registry and the cruiser exemption are created by #1601; this issue registers the mail module's hook in `backend/packages/data/src/domainWriteHooks.ts`.

Shared-file ordering: this issue also waits for #2031 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes` and `testing`.

1. Add a purge hook in the mail module that, inside the purge transaction and only for items of the Emails database, deletes the item's rows from `mail_message_meta`, `mail_attachments` and `mail_message_flag_sync_state`, and the `mail_threads` row when no other message references it.
2. For items of the Mailboxes database, the hook also deletes any remaining `external_credentials`, `mail_account_sync_state`, `mail_folder_sync_state` rows of its folders and the server settings row.
3. Register the hook in `domainWriteHooks.ts`. Blob bytes of attachments and the Files items created from them are not deleted here.

## Scope

### In scope

- Cleanup of the three message tables, the orphaned thread row and the mailbox remainders.

### Out of scope

- The hook registry itself (#1601).
- Tables introduced by later mail features.
- Deleting blob bytes or Files items.

## Acceptance criteria

- When an Email is purged, then no row of the listed tables keyed by its id remains.
- When a thread still has another message, then its `mail_threads` row remains.
- When a Mailboxes item is purged, then no credential, sync state or server settings of it remain.
- Purging an item of another database touches no mail table.
- No mail code is imported from `chokePoint/`; the dependency check passes.
