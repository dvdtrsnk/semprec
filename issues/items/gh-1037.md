## Context

Model tier rationale: The admin gate, scope selection, audit log and lint rule are specified, but the gate is a security-critical change to the shared adapter listener.

Semprec becomes multi-tenant: every user owns exactly one tenant, and an **admin** (`users.role = 'admin'`) manages accounts, invitations, AI caps and operational health. An admin never sees another user's content through the product, there is no impersonation, and every admin mutation is audit-logged. This issue builds the admin plane those features hang on: the route-level role gate, the system scope admin handlers run in, the append-only audit log, and the first admin read, the account list.

What exists today:

- Every adapter route is authenticated and nothing else: `createAdapterRequestListener` (`backend/services/semprec-api/src/adapter/adapterRoute.ts:78-107`) calls `requireAuthenticatedIdentity` (`:34-36`) and then the handler (`:88`). `RouteDefinition` (`backend/services/semprec-api/src/adapter/routeTable.ts:12-17`) carries only `method`, `path`, `handler`. `mountRoutes` (`routeTable.ts:56-78`) compiles every family, including module custom routes (`backend/services/semprec-api/src/adapter/customRouteMount.ts:22-32`).
- `createDispatcher` mounts the generic resource families through one `mountRoutes` call (`backend/services/semprec-api/src/app.ts:65-70`).
- `RouteMatrixEntry` (`backend/services/semprec-api/src/routeMatrix.ts:31-49`) records only `public`. `__tests__/routeMatrix.test.ts` requires a 401 for every non-public `api` entry, and `__tests__/chokePointWriteBoundary.unit.test.ts:16-77` requires every `api` entry to be mapped to its handler file in `ROUTE_HANDLER_FILES`.

What the blockers delivered, and what this issue relies on:

- `@semprec/shared` exports the tenant scope API (`backend/packages/shared/src/tenantScope.ts`): `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()`, which returns `{ kind: 'tenant', tenantId } | { kind: 'system', reason } | undefined`. Every transaction opened while a scope is active sets the `app.tenant_id` GUC (`''` for system scope). Row-level security on tenant tables then hides every row that is not in the current tenant.
- `authenticateRequest` returns an `AuthenticatedIdentity` that carries `tenantId: string` and `role: 'admin' | 'member'` (#980).
- `createAdapterRequestListener` runs body parsing, parameter extraction and the handler call inside `runInTenant(identity.tenantId, …)`, and leaves the error mapping outside (#980). Every bespoke listener runs in its caller's tenant or an explicit system scope (#981).
- Scope nesting: `runInTenant` may be entered from system scope, but `runAsSystem` inside a tenant scope throws `TenantScopeConflictError`.
- Global (non-RLS) identity tables: `users` (`id`, `email`, `role`, `tenant_id` UNIQUE, `created_at`), `sessions` (`user_id`, `last_seen_at`, …) and `tenants` (`id`, `status` ∈ `provisioning|active|suspended|deleting`, `created_at`, `status_changed_at`). Tenants are provisioned per tenant (#1005).

Note on the import restriction: dependency-cruiser rules are file-level (`backend/.dependency-cruiser.cjs`), and `@semprec/shared` resolves to its single entry file `backend/packages/shared/src/index.ts` (`backend/packages/shared/package.json` `main`). A rule therefore cannot forbid one named export such as `runInTenant`. ESLint's `no-restricted-imports` with `importNames` can, so the restriction lives in `backend/eslint.config.mjs`.

Later issues in this batch add routes to `createAdminRoutes` and call `recordAdminAction`: operator health (#1038), AI caps (#1039), invitations (#1040), suspension and role changes (#1041) and account deletion (#1049).

## Task

Load `io-hardening` (new routes and an auth gate), `state-writes` (the audit insert), `db-migrations` (new table), `error-handling` (new refusal path) and `adr-conventions` (new ADR).

1. **Route flag.** Add `admin?: true` to `RouteDefinition` in `routeTable.ts`. `mountRoutes` forwards it to `createAdapterRequestListener` via a new `admin?: boolean` field on `AdapterRequestListenerOptions`. `mountRoutes` throws at construction time (`Error` naming the path) for any route whose `path` starts with `/api/admin/` but whose `admin` is not `true`. This also covers module custom routes, because they compile through `mountRoutes`.
2. **Gate and scope.** In `createAdapterRequestListener`, when `options.admin` is true: after authentication and before reading the body, a caller whose `identity.role !== 'admin'` gets `ForbiddenError("Admin role required", undefined, "admin_required")`. The existing `ChokePointError` branch answers that as `403 { "error": { "code": "admin_required" } }`. For an admin, body parsing, parameter extraction and the handler run inside `runAsSystem("adminRoute", …)` and **not** inside `runInTenant`. Routes without the flag keep #980's tenant scope unchanged.
3. **Migration** (take the next free migration ordinal at commit time). It is additive and rollback-safe, because no previous-release code touches the new table:
   ```sql
   CREATE TABLE admin_audit_log (
     id bigserial PRIMARY KEY,
     actor_user_id uuid NOT NULL,
     action text NOT NULL,
     target_tenant_id uuid,
     details jsonb NOT NULL DEFAULT '{}'::jsonb,
     created_at timestamptz NOT NULL DEFAULT now()
   );
   CREATE INDEX admin_audit_log_created_at_idx ON admin_audit_log (created_at);
   COMMENT ON TABLE admin_audit_log IS 'semprec:tenancy=global';
   GRANT SELECT ON admin_audit_log TO semprec_side;
   GRANT INSERT ON admin_audit_log TO semprec_data;
   ```
   There are deliberately no FKs, so audit rows outlive deleted users and tenants. The table is append-only for the runtime roles (no `UPDATE`/`DELETE` grant), following the identity-table convention: `semprec_side` gets `SELECT` only and `semprec_data` gets DML. Add `admin_audit_log` to the grant-coverage exceptions in `backend/packages/data/src/__tests__/leastPrivilegeRoles.test.ts` (#962's assertion; `SELECT` only for `semprec_side`, no `UPDATE`/`DELETE` for `semprec_data`), the way #1004 does for `tenant_ai_budgets`. The sequence grant comes from the default privileges in `0047_side_role_default_sequence_privileges.sql`.
4. **Store** — new `backend/packages/data/src/tenancy/accountsAdminStore.ts`:
   - `listAccounts(client: Queryable): Promise<AdminAccountSummary[]>`, where `AdminAccountSummary = { userId, email, role, status, createdAt, lastSeenAt: string | null }`. It is one query over `users` JOIN `tenants ON tenants.id = COALESCE(users.tenant_id, app_sole_tenant())` (the binding rule of #980's `getUserTenantBinding`) LEFT JOIN `sessions` (`max(last_seen_at)`), ordered by `users.created_at, users.id`. The row type is validated with `assertKnownValue` for `role` and `status`.
   - `ADMIN_AUDIT_ACTIONS = ["tenantAiBudgetSet", "inviteCreated", "inviteRevoked", "accountSuspended", "accountReactivated", "accountRoleChanged", "accountDeletionRequested"] as const`, plus its `AdminAuditAction` type. These are the actions the sibling issues named above write.
   - `recordAdminAction(client: PoolClient, input: { actorUserId: string; action: AdminAuditAction; targetTenantId: string | null; details?: Record<string, string | number | boolean | null> }): Promise<void>`. It runs in the caller's transaction, so the audit row commits or rolls back with the mutation it records, and it re-checks `action` against `ADMIN_AUDIT_ACTIONS` at runtime. `details` must never carry content or an email address. Say so in the docstring.
   - Export the module from `backend/packages/data/src/index.ts` with one new `export * from "./tenancy/accountsAdminStore.js";` line, and add the new runtime names to `EXPECTED_RUNTIME_EXPORTS` in `backend/packages/data/src/__tests__/publicSurface.test.ts`.
5. **Handler** — new `backend/services/semprec-api/src/adminHandler.ts` exporting `createAdminRoutes(pool: Pool, options: AppOptions): RouteDefinition[]`. The options are the dispatcher's own options object, passed through for later admin routes. The first route is `GET /api/admin/accounts` (`admin: true`), which answers `200 { "accounts": AdminAccountSummary[] }` and nothing else (no tenant content). Mount the family in `createDispatcher` (`app.ts`) through `mountRoutes`.
6. **Route matrix.** Add `admin?: boolean` to `RouteMatrixEntry` and an entry `{ name: "admin account list", method: "GET", path: "/api/admin/accounts", surface: "api", public: false, admin: true }`. Map it in `ROUTE_HANDLER_FILES` (`chokePointWriteBoundary.unit.test.ts`).
7. **Import restriction.** Add an override block to `backend/eslint.config.mjs` for `services/semprec-api/src/adminHandler.ts` and `packages/data/src/tenancy/accountsAdminStore.ts`. It sets `no-restricted-imports: ["error", { paths: [{ name: "@semprec/shared", importNames: ["runInTenant"], message: "Admin code runs in system scope and never enters a tenant (docs/adr/<date>-admin-role-without-content-access.md)." }] }]`.
8. **ADR** `docs/adr/<YYYY-MM-DD>-admin-role-without-content-access.md` (`area: [backend]`). It records:
   - admin is a role on `users` and is checked per route by the `admin` flag;
   - admin handlers run in system scope and read only global tables and `semprec_router` aggregate functions, never tenant rows, and there is no impersonation route;
   - the single sanctioned exception: account deletion's data-layer function (#1049, outside the ESLint-restricted files) enters the target tenant only for the deletion transaction (status, revocations, deleting the tenant's key row), and reads no tenant content;
   - the ESLint restriction and why dependency-cruiser cannot express it;
   - `admin_audit_log` is append-only, holds ids and scalars only, and is written in the mutation's own transaction;
   - members get 403 `admin_required`.

## Acceptance criteria

- When `GET /api/admin/accounts` is called without a session or with a garbage bearer token, the response is 401 (integration, `routeMatrix.test.ts`).
- When a `member` session calls any `ROUTE_MATRIX` entry with `admin: true`, the response is `403` with body `{ "error": { "code": "admin_required" } }` and the handler is never invoked. The test iterates the matrix, so a later admin entry is covered automatically (integration, `adminHandler.test.ts`).
- When an admin calls `GET /api/admin/accounts` with two tenants present (each with a user, one with two sessions), the body lists both users. Each entry has exactly the keys `userId, email, role, status, createdAt, lastSeenAt`, with `lastSeenAt` equal to the newer session's `last_seen_at`, or `null` for a user without sessions (integration, `adminHandler.test.ts`, two tenants created with `createTestTenant()` from `backend/packages/data/src/testSupport/tenantFixtures.ts`, #975).
- When an admin route handler runs, `currentTenantScope()` is `{ kind: 'system', reason: 'adminRoute' }`. With two tenants present, `SELECT count(*) FROM items` inside it returns 0. A route without the flag still sees its caller's tenant (integration, `adapterRoute.test.ts`).
- When `mountRoutes` is given a route under `/api/admin/` without `admin: true`, it throws naming the path (integration, `adminHandler.test.ts`).
- When `recordAdminAction` runs in a transaction that commits, exactly one `admin_audit_log` row with the given fields exists. When that transaction rolls back, none exists. An action outside `ADMIN_AUDIT_ACTIONS` throws before any insert (integration, `accountsAdminStore.test.ts`).
- When connected as `semprec_data`, `UPDATE` and `DELETE` on `admin_audit_log` fail with a privilege error and `INSERT` succeeds. As `semprec_side`, `INSERT` fails (integration, `accountsAdminStore.test.ts`, `createRuntimeRolePool` from `@semprec/data/testSupport`, #975).
- When ESLint lints `import { runInTenant } from "@semprec/shared";` with `filePath` set to `adminHandler.ts` or `accountsAdminStore.ts`, it reports `no-restricted-imports`. The same snippet with any other `filePath` does not (unit, `adminScopeImports.unit.test.ts`, via the ESLint Node API and `backend/eslint.config.mjs`).
- The tenancy catalog test passes with `admin_audit_log` classified `global` (integration, existing `tenancyCatalog.test.ts`).
