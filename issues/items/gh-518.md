**Blocked by:** #515

## Context

Since #515, `backend/packages/data/src/chokePoint/itemTrash.ts` holds the trash code. `collectItemSubtree(client, root)` walks the cascade subtree under an item, guarding against a `parent_item_id` cycle. It is used by the soft-delete and restore paths. `purgeExpiredTrashSubtree(rootItemId, cutoff)` contains a second, hand-copied version of the same walk. The copy differs in one way: it only descends into rows whose `deletedAt` is set and older than `cutoff`, because a live or too-recently-trashed row blocks the purge of everything nested under it.

## Task

1. Give `collectItemSubtree` an optional third parameter `include?: (row: ItemRow) => boolean`. When it is provided, a row for which it returns `false` is neither added to the result nor descended into. The root is always included, as today. With the parameter omitted, behavior is identical to today. Document the parameter in its JSDoc.
2. In `purgeExpiredTrashSubtree`, replace the inline walk with `collectItemSubtree(client, root, (row) => row.deletedAt !== null && new Date(row.deletedAt) < cutoff)`. Use a predicate equivalent to the one the inline walk uses today, and keep the root eligibility check, the archived-database check, the delete loop and the return value unchanged.

## Touches

- backend/packages/data/src/chokePoint/itemTrash.ts (`collectItemSubtree` and `purgeExpiredTrashSubtree` only)
- backend/packages/data/src/trash/__tests__/purgeExpiredTrash.test.ts (new test cases)

## Scope

### In scope
- The optional predicate, its use in the purge, and the tests below.

### Out of scope
- `restoreItem` (#520) and `softDeleteItem`.
- Any change to what gets purged.

## Acceptance criteria

- `pnpm run verify` in `backend/` passes. `src/__tests__/publicSurface.test.ts` and the existing trash tests in `chokePoint.test.ts` (or `itemTrash.test.ts` once #521 has merged) pass unmodified.
- `itemTrash.ts` contains exactly one subtree-walking loop, inside `collectItemSubtree`.
- `purgeExpiredTrash.test.ts` covers, for the purge:
  - A subtree whose rows were all trashed before the cutoff is purged entirely.
  - A nested row that is live, or trashed after the cutoff, is kept together with everything under it, while its eligible siblings are purged.
  - A cycle in `parent_item_id` terminates.
