## Task

Bump the pinned `dvdtrsnk/code-review-bot` revision in `.relay/config.yml` (`review.bot.ref`) to `aa7d7e07f3bc3552887708a49dc319a3f4a2f640`, with a comment above it recording what that revision fixes.

That commit (`dvdtrsnk/code-review-bot#28`) makes cheap verdict reuse after a rebase key on a line-number-free diff identity. Until now the reuse identity was the SHA-256 of GitHub's raw per-file `patch` text, hunk headers included. A rebase onto a `develop` that changed the same file elsewhere shifts the `@@ -a,b +c,d @@` numbers without changing anything the pull request changes, so reuse never fired. Every pull request in the current choke-point-split batch (#494) touches `backend/packages/data/src/chokePoint/chokePoint.ts`, so this is the common case there. Hunk headers are now reduced to a bare `@@` before hashing. File paths and every `+`/`-`/context line still count, so a changed context line still forces a full review.

`.relay/**` is a protected path, so this is a maintainer change, not a Relay one.
