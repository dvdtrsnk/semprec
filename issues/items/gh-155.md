**Blocked by:** #240, #154

## Context

Issue #240 exposed databases and properties through the #154 adapter. This slice completes the metadata layer with views and curated view membership, again without introducing module-specific CRUD. #156 builds the item lifecycle on top of the completed metadata layer, and #157 exposes `POST /api/views/:id/query` over the views created here.

## Task

Implement the view endpoint family as thin mappings onto choke-point services:

- `POST /api/databases/:id/views`, `PATCH/DELETE /api/views/:id`.
- `PUT/DELETE /api/views/:id/items/:itemId` for curated view membership — add, reposition, and remove.
- All routes call choke-point services, use localized metadata from #35, authenticate through #34, and return authoritative resource representations or the #154 error contract. No successful mutation returns 204.

## Scope

### In scope

- View create/patch/delete and curated membership add/reposition/remove.

### Out of scope

- Database and property routes — delivered by #240.
- Item rows (#156), query execution over views and relations (#157), files (#158), realtime delivery.

## Acceptance criteria

- Tests cover every view route through create, patch, and delete.
- Curated membership add, reposition, removal, idempotence (repeating the same `PUT`), and missing references (unknown view or item → `not_found`) are deterministic.
- No handler bypasses the choke-point or returns 204 for a successful mutation.
