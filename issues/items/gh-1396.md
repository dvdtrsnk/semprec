## Context

Model tier rationale: A new long-lived streaming route in the gateway with budget reservations of unknown audio length, concurrency limits and disconnect propagation, touching the accounting path every provider call relies on.

Voice mode needs the user's speech turned into text as it is spoken. The gateway today transcribes only whole recordings: `POST /internal/transcribe` (`backend/services/semprec-ai-gateway/src/audioHandler.ts`) reads a base64 body, knows `audioSeconds` up front, reserves the exact price, calls the provider (`audioProviders/deepInfraWhisperProvider.ts`) and settles. Accounting lives in `backend/packages/ai-gateway/src/gateway.ts` (`transcribe`, `reserve`, settle with retry) and rows in `ai_gateway_calls` (`audio_seconds`, no agent run id). The decisions of the voice ADR written in #1371 (provider, chunk length, formats, limits) apply.

This issue adds a streaming speech-to-text adapter to the gateway. #1734 uses it for voice turns; dictation into the message field runs on the device and does not use it (#1372).

Decisions:
- Transport inside the host: a loopback WebSocket route `/internal/stt/stream`, authenticated with the internal token and carrying the caller's tenant exactly like the other internal routes. The ADR's choice prevails if it differs.
- The audio length is unknown, so the stream reserves budget in chunks of a fixed number of seconds (value from the ADR): one `ai_gateway_calls` row per chunk with operation `voice_transcribe_stream`, reserved before the chunk is consumed, settled with the seconds actually used. When the next chunk cannot be reserved (budget exceeded), the stream ends with an error message to the caller.
- Audio is held in memory only for the duration of forwarding and is never written to disk or logged.

## Task

Load `ai-gateway`, `io-hardening`, `error-handling` and `testing`.

1. Define a streaming transcription provider interface in `audioProviders/types.ts` (open a session with language; write audio chunks; emit partial and final transcript events; close or abort) and implement it for the provider chosen in the ADR.
2. Add the route `/internal/stt/stream` to `GATEWAY_ENDPOINTS` in `app.ts` and handle its WebSocket upgrade in `serve.ts`: check the token and the tenant, apply a dedicated concurrency limit (same pattern as `audioConcurrencyLimit.ts`, refused with a clear close code when full), and enforce the maximum duration and frame size from the ADR.
3. Add a streaming accounting helper in `packages/ai-gateway/src/gateway.ts` that reserves, settles and fails chunk rows with the existing lock, tenant-active check and settle retry.
4. Messages from gateway to caller are JSON: `{type: "partial", text}`, `{type: "final", text}`, `{type: "error", code}` (`budget_exceeded`, `provider_error`, `capacity`); inbound frames are audio binary frames and one JSON `{type: "end"}`.
5. If the caller disconnects, abort the provider session and fail or settle the open chunk row.
6. Add a client function for this route in `backend/packages/ai-gateway-client`.
7. Tests with a fake provider: partials then final reach the caller; chunk rows are reserved and settled with real seconds; the stream ends with `budget_exceeded` when a chunk cannot be reserved; a wrong token is refused; a disconnect aborts the provider and leaves no `reserved` row; the concurrency limit refuses the extra stream.

8. Apply `docs/adr/2026-11-01-streaming-transcription-provider-outbound-buffer-limit.md`: gate every provider configuration/audio/commit event by current bufferedAmount plus encoded UTF-8 frame bytes <=262144, fail before sending overflow, reject a failed pending open and preserve once-only teardown. Exercise local boundary controls and actual gateway provider_error/accounting cleanup; no live provider call is required.

9. Apply `docs/adr/2026-11-01-stt-stream-close-waits-for-accounting-ownership.md`: finish aborts input/provider immediately, but registry/slot and closeAll retain the final serialized frame queue through in-flight reservation, settlement/failure and retries, then final chunk close. Do not await cleanup from its own queue callback or change existing shutdown ordering or terminal accounting-failure policy. Prove actual blocked accounting before closeAll/pool closure, retry/failure and idempotent finish using gateway runtime role.

## Acceptance criteria

- When audio frames are streamed, then partial transcripts arrive while speaking and a final transcript after `end`.
- When the tenant's budget is exhausted mid-stream, then the caller receives `budget_exceeded` and the stream is closed.
- When the caller disconnects and database accounting succeeds, no `ai_gateway_calls` row stays `reserved`; terminal database failures retain the existing logged estimate/reconciliation policy and are not reported as successful accounting.
- When the concurrency limit is reached, then a new stream is refused without opening a provider session.
- No audio bytes appear in logs or on disk.
- Provider outbound configuration/audio/commit frames obey the 262144-byte projected buffer cap: equality sends, overflow or an oversized frame fails before send, no further frames are emitted, and the actual gateway reports provider_error with no reserved accounting row.
- CloseAll retains ownership of in-flight reservation, settlement/failure and retries before the existing shutdown hook ends the pool; healthy completion leaves no reserved row. Prove blocked reservation and settlement ordering, repeated finish, queue-internal finish and existing retry/terminal-failure semantics under semprec_side.
