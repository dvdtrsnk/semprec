**Blocked by:** #150

## Context

Active registrations exist. Delivery must share one durable queue path while honoring channel-specific provider behavior.

## Task

Enqueue one graphile-worker fanout job for each committed notification using a notification-level `jobKey`. The worker loads every active registration for the notification user and dispatches each through a Web Push or APNs adapter with a deterministic per-notification/per-registration delivery key so retries cannot send the same pair twice. Web Push uses VAPID configuration. APNs uses HTTP/2, selects production or sandbox from `apns_environment`, sends alert title/body plus `link_href` and `notification_id`, and caches an ES256 provider JWT for no longer than one hour. Treat transient failures as retryable and invoke #150 invalidation for permanent provider responses. Never include source content beyond the notification row.

## Scope

### In scope

- Queue registration, adapters, VAPID/APNs auth contracts, retry/dedup, permanent invalidation.

### Out of scope

- Provisioning VAPID/APNs secrets, delivered by operations.
- Email escalation.

## Acceptance criteria

- One notification fans out exactly once to each active registration across worker retries.
- APNs host, payload, and JWT reuse/expiry follow the subscription environment and one-hour maximum.
- Provider 404/410/BadDeviceToken revokes only the reported registration; transient failures retry.
