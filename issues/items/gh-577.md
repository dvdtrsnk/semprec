## Context

In the review follow-ups pipeline (epic #565), a harvest issue labelled `followups:ready` triggers Relay's `triage-review-followups` workflow. Its first deterministic step after an `integrity` check of the scripts is **prepare**: it turns the harvest issue into one local file holding everything the triage agent needs, so the agent never touches GitHub. That file is the triage input file defined in #571's `input-file.mjs` (`renderInputFile` / `parseInputFile`). This issue is that step's script. The Relay workflow that runs it is a later, maintainer-implemented issue; it runs `prepare` as a command step that reaches GitHub through Relay's token proxy (`GITHUB_API_URL`, `GITHUB_GRAPHQL_URL`, `GITHUB_TOKEN`, `GITHUB_REPOSITORY`, read by #573's `clientFromEnv`).

**Re-runs.** A Relay run that fails or parks is re-run from the start. If an earlier attempt already published some findings (as issues, or as rejections in a triage-result comment), they are in the **terminal ledger**: #569's `computeLedger(issues).terminal`, built from the bodies of `followups:issue` issues and from triage-result comments by `bb-agent-relay[bot]` on the harvest issue. `prepare` drops those findings, so a finding is never proposed twice.

**Full text.** The bot clips a finding's description to 300 characters in its memory. For medium and above it opens an inline review thread whose root comment carries the full text, in the format the bot writes (`code-review-bot` `publish.py`):

```
**<category> | <SEVERITY>**

<description>

**Suggested fix:**
```
<fix>
```
```

The `**Suggested fix:**` part is present only when the bot had a suggestion. Low findings have no thread, so their full text exists nowhere; the clipped description is all there is. The bot also posts one review summary per pull request, an issue comment by a trusted bot starting with `## AI Code Review Summary` (only the latest run's survives), which gives the agent more context for low findings.

**Cross-batch overlaps.** The triage must not propose an issue that collides with work already queued, so the input lists the open issues labelled `agent:ready`, `spec:approved` or `spec:proposed` with their `## Touches` section.

## Task

Create `.github/scripts/review-followups/prepare.mjs`, a zero-dependency ES module and CLI with a header comment describing its inputs, output and re-run behavior:

1. Export `prepareInput(api, harvestIssue)`. `api` is an object with the functions it needs, bound to a client: `getIssue(number)`, `listIssuesWithLabel(label, state)`, `listIssueComments(number)` and `listReviewThreads(prNumber)` — the #573 endpoints of the same names. It returns the triage input object:
   - It reads the harvest issue. It throws unless the issue is open and labelled `followups:harvest`. It parses the data block with #570's `parseHarvestBlock`.
   - It computes the terminal ledger with `computeLedger` over every `followups:issue` issue (any state, no comments needed) plus the harvest issue itself with its comments. It keeps only the findings whose `findingId` is not in `terminal`.
   - For each kept finding with a non-empty `discussionId`, it finds the thread whose root comment's `databaseId` equals it, fetching each pull request's threads at most once.
     - When the root's author is in #572's trusted set (`github-actions[bot]`, `bb-agent-relay[bot]`) and its body starts with a `**… | …**` header line, `fullText` is the text between that header and `**Suggested fix:**` (or the end), trimmed, and `suggestedFix` is the fenced content after `**Suggested fix:**`, or `null`.
     - When the root has another shape, `fullText` is the whole root body and `suggestedFix` is `null`.
     - `threadReplies` is every later comment as `{ author, body }`.
     - A finding without a thread gets `fullText: null`, `suggestedFix: null`, `threadReplies: []`.
   - `prSummaries` has one entry per pull request of a kept finding that has one: the newest comment by a trusted bot whose body starts with `## AI Code Review Summary`, as `{ pr, body }`.
   - `openIssues` is every open issue labelled `agent:ready`, `spec:approved` or `spec:proposed`, deduplicated by number, as `{ number, title, labels, touches }`. `touches` is the text after a line that is exactly `## Touches`, up to the next line starting with `## ` or the end, trimmed; `""` when there is no such section.
   - `harvestIssue` is the issue number, `version` is `1`, and `findings` keeps the data block's order.
2. Export `main(argv, api)`, and call `main(process.argv.slice(2))` only when the module is executed directly. The command line is `node prepare.mjs --harvest-issue <n> --out <dir>`. When `api` is omitted, `main` builds it from `clientFromEnv`.
   - It runs `prepareInput` and writes `<dir>/input.json` with #571's `renderInputFile` (creating `<dir>` if needed).
   - It prints how many findings are pending and how many were already published.
   - It exits 0, also when nothing is pending. It exits non-zero on a missing or non-numeric argument or on any error, and writes no file then.
3. `prepare.test.mjs` next to it (`node:test`, `node:assert/strict`, a fake `api`), covering every Acceptance criterion below.

### In scope

### Out of scope

- Deciding anything about a finding. Verdicts are the triage agent's.

## Acceptance criteria

1. A closed harvest issue, and an open issue without `followups:harvest`, make `prepareInput` throw; so does a harvest issue whose body has no data block.
2. A finding with a marker in a `followups:issue` issue's body (open or closed), or in a triage-result comment by `bb-agent-relay[bot]` on the harvest issue, is not in `findings`. A marker in a result comment by another author does not remove it.
3. For a thread root by `github-actions[bot]` in the bot's format with a suggested fix, `fullText` and `suggestedFix` are exactly the description and the fenced fix. Without the suggestion part, `suggestedFix` is `null`.
4. A root authored by a human, or not starting with the header line, gives `fullText` equal to its whole body. Later comments appear in `threadReplies` in order.
5. A finding with `discussionId: ""`, or whose thread is gone, gets `fullText: null`, `suggestedFix: null`, `threadReplies: []`. Two findings of one pull request cause one `listReviewThreads` call.
6. `prSummaries` takes the newest trusted `## AI Code Review Summary` comment, ignores one by another author, and has no entry for a pull request without one.
7. `openIssues` contains an issue carrying both `agent:ready` and `spec:approved` once. `touches` stops at the next `## ` heading and is `""` without a `## Touches` section.
8. The returned object passes #571's `parseInputFile(renderInputFile(...))`. `main` with a fake `api` and a temporary `<dir>` writes it to `<dir>/input.json`, including with zero pending findings.
9. `main` rejects without writing a file when `--harvest-issue` is missing or not a positive integer, or when a fake `api` throws; the process exits non-zero in those cases.
10. `node --test .github/scripts/review-followups/prepare.test.mjs` passes with no network access.
