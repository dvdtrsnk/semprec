## Context

Model tier rationale: One read-only custom route over existing relation and edge-metadata reads, following the calendar module's route pattern with the existing isolation fixtures; it writes nothing.

Deleting a calendar moves it and its live Events to the trash (#1803), and every trashed Event with invited people sends them a cancellation through the Event delete reaction of the invitation sending work (#1774). Cancellations are sent only after a confirmation: the client always asks before deleting a calendar, and the dialog states how many Events the calendar contains (from the delete-impact preview of #1856) and how many invited people will receive a cancellation. An agent can delete a calendar only through the approval that `item.delete` already requires. Nothing reports the second number today.

An invitation is stored on the edge of `Events.people` as `metadata.invitation` (`{ status, email, mailboxId, sentAt?, respondedAt? }`, #1757). The delete reaction of #1774 enqueues one cancellation for every participant edge of the Event that carries an `invitation`.

This issue adds `GET /api/calendar/calendars/:id/cancellation-impact`, a custom route of the calendar module with justification `single-consumer-read`, answering `{ eventCount, recipientCount, cancellationCount }`:
- `eventCount`: the live Events on the calendar's `Calendars.events` edges (the Events that a deletion trashes per #1803);
- `cancellationCount`: the participant edges of those Events that carry an `invitation` (one cancellation each);
- `recipientCount`: the distinct invitation `email` values among those edges (the number of invited people), compared case-insensitively.

Decision: the route only reports; it changes nothing and the delete itself requires no confirmation flag. A system or subscription calendar (which cannot be deleted) still answers with its numbers; an unknown, trashed or other-tenant id answers 404 identically.

Shared-file ordering: this issue also waits for #1801 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add `backend/packages/data/src/calendar/calendarCancellationImpact.ts` with a read function `readCalendarCancellationImpact(client, calendarId)` computing the three numbers above in one transaction with batched queries (no per-Event query).
2. Add `backend/packages/data/src/calendar/cancellationImpactRouteHandler.ts` with `createCalendarCancellationImpactRouteHandler(pool)` answering 200 with the response above, 400 `validation_failed` for an id that is not a UUID and 404 for an unknown, trashed or foreign calendar.
3. Declare the route in `customRoutes` of `backend/packages/data/src/calendar/calendarModuleManifest.ts` (name `calendarCancellationImpact`, `GET`, `/api/calendar/calendars/:id/cancellation-impact`, justification `single-consumer-read`) and re-export the handler from that file.
4. Add it to `backend/services/semprec-api/src/routeMatrix.ts` (tenant class), to `ROUTE_HANDLER_FILES` in `backend/services/semprec-api/src/__tests__/chokePointWriteBoundary.unit.test.ts` and to `backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts`.
5. Tests: a calendar with three live Events, two of which have invited people (Petr Novák invited to both, Jana Kovářová to one), answers `eventCount` 3, `cancellationCount` 3 and `recipientCount` 2; a participant edge without `invitation` is not counted; a trashed Event is not counted; a calendar with no Events answers zeros; a foreign or unknown id answers 404 identically; the route writes nothing.

## Scope

### In scope

- The read-only route and function that count the Events, cancellations and invited people affected by deleting one calendar.

### Out of scope

- Trashing and restoring the calendar and its Events: #1803.
- Sending the cancellations: #1774.
- The generic delete-impact preview: #1856.
- Adding these numbers to an agent's approval request for `item.delete`.
- Any confirmation flag on the delete request.

## Acceptance criteria

- When a calendar's live Events have invited people, then the route answers the number of Events, the number of cancellations that a deletion would send and the number of distinct invited people.
- When an Event has participants without an invitation, or is already in the trash, then it adds no cancellation.
- When the id is unknown, trashed or of another tenant, then the answer is 404 and identical in each case.
- When the route is called, then no data changes.
- The full backend `pnpm run verify` passes.
