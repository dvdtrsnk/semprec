## Context

Model tier rationale: One adapter method and an inline confirmation are specified exactly against the existing accounts panel.

A user can delete their own account after password re-authentication (the account page, #1083), and an admin can delete an account. Deletion:

- sets the tenant to `deleting` and revokes the user's sessions and push registrations at once;
- shreds the tenant key;
- leads to a purge of every row and file (#1055).

It cannot be undone, and the last active admin can never be deleted. #1049 added the admin route for it. This issue adds the action to the admin accounts panel.

#1079 delivered the admin page (`?page=admin`, rendered only for `role === "admin"`):

- `web/src/views/admin/AdminPage.tsx`, rendered from `RoutedContent` in `web/src/App.tsx` as `<AdminPage operations={…} />`;
- `web/src/views/admin/AccountsPanel.tsx`:
  - one row per account with Suspend (for `active`), Reactivate (for `suspended`) and Make admin / Make member (for both); no actions for `provisioning` or `deleting`;
  - a row's buttons are disabled while one of its actions is pending;
  - after a success the list reloads;
  - a failure shows `admin.accounts.lastAdmin` for the message `last_admin`, otherwise `admin.accounts.actionFailed` with the message, in a `role="alert"` element;
- `web/src/api/adminOperations.ts`, the `AdminOperations` adapter. Status mapping: `401/403/404/501` → `unavailable`, else `retryable`. A non-2xx's message is the adapter error body's `error.code`.

Backend contract (#1049). If the merged handler (`backend/services/semprec-api/src/adminHandler.ts`) differs, bind to it and say so in your PR description.

- `POST /api/admin/accounts/:userId/delete` (no body) → `202 { account: AdminAccountSummary }`, with `account.status === "deleting"`.
- `409` with code `last_admin` when the target is the last active admin.
- `409` with code `invalid_account_status` when the account is not `active` or `suspended`.
- `404` for an unknown user.

The admin route does not re-authenticate. An admin's own account is therefore deleted only from the account page, which asks for the password: this panel never offers Delete on the signed-in admin's own row.

## Task

Load `error-handling` (deletion refusals) and `canonical-keys` (labels).

1. **Adapter** — add `deleteAccount(userId: string): Promise<AdminAccountSummary>` to `AdminOperations` in `web/src/api/adminOperations.ts`. It sends `POST /admin/accounts/${encodeURIComponent(userId)}/delete`, parses `{ account }` with the existing summary schema, and uses the file's error mapping.
2. **Current user** — in `web/src/App.tsx`, pass `currentUserId={session.user.id}` to `AdminPage`. `AdminPage` forwards it to `AccountsPanel`.
3. **Delete action** — in `AccountsPanel.tsx`, offer **Delete** (`admin.accounts.delete`) on `active` and `suspended` rows whose `userId !== currentUserId`.
   - Clicking it replaces that row's actions with an inline confirmation:
     - `admin.accounts.deleteConfirm`, interpolating the email: "Permanently delete {email} and all of its data? This cannot be undone.";
     - **Delete permanently** (`admin.accounts.deleteConfirmButton`) and **Cancel**.
   - Only one row can be in confirmation at a time. Cancel restores the row and sends no request.
   - Confirming calls `deleteAccount`, and the row's buttons are disabled while it is pending.
   - On success, reload the list; the row then shows `deleting` with no actions.
   - On failure, close the confirmation, keep the list as it was, and show the panel's existing failure message (`admin.accounts.lastAdmin` for `last_admin`, otherwise `admin.accounts.actionFailed`).
4. **i18n** — add `admin.accounts.delete`, `admin.accounts.deleteConfirm` and `admin.accounts.deleteConfirmButton` to `en` and `cs` in `web/src/i18n/messages.ts`.
5. **Test stubs** — update every existing `AdminOperations` test stub for the new method.

## Acceptance criteria

- `deleteAccount("u 1")` issues `POST /api/admin/accounts/u%201/delete` with same-origin credentials and resolves to the parsed account on 202. A 409 `{ error: { code: "last_admin" } }` rejects as `retryable` with message `last_admin`. A 404 rejects as `unavailable` (web unit, `adminOperations.test.ts`).
- Delete is offered on `active` and `suspended` rows of other accounts. It is not offered on `provisioning` or `deleting` rows, nor on the signed-in admin's own row (web unit, `web/src/views/admin/__tests__/AccountsPanel.test.tsx`).
- Clicking Delete shows the confirmation naming the email and makes no request. Cancel restores the row without calling `deleteAccount` (web unit, `AccountsPanel.test.tsx`).
- Confirming calls `deleteAccount(userId)` once and reloads the list (web unit, `AccountsPanel.test.tsx`).
- A `last_admin` rejection shows `admin.accounts.lastAdmin`, any other rejection shows `admin.accounts.actionFailed` with its message, and the row keeps its previous status (web unit, `AccountsPanel.test.tsx`).
- `App` passes the session user's id through to the panel: with an admin session on the `admin` route, the admin's own row shows no Delete (web unit, `App.test.tsx` or `AccountsPanel.test.tsx` via `AdminPage`).
- Every new key exists in `en` and `cs`, and `pnpm run verify` passes in `web/`.
