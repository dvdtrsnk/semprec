## Context

Model tier rationale: Moves one existing handshake answer into a shared helper and uses it on the second Graph receiver.

Left over from throttling the Graph mail webhook (sp-8acebdc7-a9eb-4f52-8d7a-7b47f95680fc). `POST /api/mail/graph/webhook?validationToken=…` (`graphWebhookHandler.ts`) echoes the token at any length as `text/plain` without `X-Content-Type-Options: nosniff`. The Graph calendar webhook (`calendarWebhookHandlers.ts`) refuses a token over 1024 characters with 400 and sets `nosniff`, so a browser cannot sniff the reflected text as HTML.

Decision: one helper, `answerGraphValidationHandshake` in `graphNotificationBatch.ts`, answers the handshake for both Graph receivers exactly as the calendar receiver does today: 400 over 1024 characters, otherwise 200 `text/plain; charset=utf-8`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, body the literal token. It still runs after the per-address throttle and before the body is read.
