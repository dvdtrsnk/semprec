**Blocked by:** #155, #82, #83

## Context

Metadata is exposed (#155), and audited choke-point fixes now enforce relation ownership (#82) and archived-database immutability (#83). This slice projects the first half of the item lifecycle — create, detail with breadcrumb path, and versioned patch. #156 completes it with transactional trash (delete/restore) and the 30-day purge task; #157 builds queries and relations on the rows exposed here.

## Task

Implement the following item endpoints as thin mappings onto choke-point services:

- `POST /api/databases/:id/items`, requiring an `Idempotency-Key` header and returning 201 with the full row in the item envelope. Repeating the same key returns the original row without a second insert.
- `GET /api/items/:id` with optional `?include=path` for a breadcrumb: the server assembles the ancestor chain by recursively walking `parent_item_id`; the client never assembles hierarchy itself. Paths stay flat regardless of nesting depth — `/api/items/:id` works identically for a row in a top-level database and for one five levels deep inside inline databases.
- `PATCH /api/items/:id` with body `{ properties, ifVersion }`, merged by key; `computed` fields are protected (`computed_readonly`); a version mismatch returns 409 `version_conflict` containing `details.currentItem`. `updatedAt` from the response is the `ifVersion` token for the next update.
- Every mutation rejects writes into archived databases according to #83 and preserves owner/lock rules — all enforced by the choke-point, not re-implemented in the handler.

## Scope

### In scope

- Create with idempotency, detail with `?include=path`, patch with `ifVersion` merge, computed protection, and archived/owner/lock rejection.

### Out of scope

- Soft delete with cascade, symmetric restore, and the 30-day purge task — #156.
- Queries, relations, files, hard-delete endpoints, and generic batch writes.

## Acceptance criteria

- Repeating an idempotency key returns the original row without a second insert; a create without `Idempotency-Key` is rejected with `validation_failed`.
- `?include=path` returns the full ancestor chain for a nested row, assembled server-side.
- Version conflict returns the authoritative current item in `details.currentItem`; computed and archived writes are rejected with their error codes.
