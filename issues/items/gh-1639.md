## Context

Model tier rationale: Combines full-text search, accent-insensitive sender matching and thread aggregation inside the central list query with other filters, where a wrong join or predicate silently changes what mail the user finds.

`GET /api/mail/threads` (#1567, filters in #1633) does not search. Search code exists but nothing calls it: `parseMailSearchQuery` and `searchItems` in `backend/packages/data/src/mail/search.ts` support `from:`, `has:attachment`, `before:`, `after:` and `is:read|unread|flagged|unflagged`; contradictory operators throw a validation error; `from:` is an `ILIKE` on the `Emails.sender` property without accent folding; deleted items are not filtered; free text uses `websearch_to_tsquery('czech', ...)`, which has no word-prefix matching. The sender is in the index since #1591, and #1589 delivers the prefix query ("every word as a prefix, AND, parameters only") that the rest of search uses.

Decisions: a thread matches when any of its (non-deleted) messages matches; the result is ordered by `lastMessageAt` descending as in the list; contradictory operators (`is:unread is:read`) return an empty list, not an error; `from:` matches the name and address of `envelope.from` after folding accents and case; `q` combines with the other filters by AND; with Czech word search active, "koupelna" also finds "Koupelny" (an extension beyond plain prefix matching).

## Task

Load `io-hardening`, `state-writes` and `testing`.

1. Add a `q` query parameter to `GET /api/mail/threads` (trimmed; empty means no search). Parse it with `parseMailSearchQuery`; change the contradictory-operator case to return a parsed marker that yields an empty result instead of throwing for this route (the existing function keeps its other callers' behavior if any exist).
2. Add a `matchesSearch` predicate to `mail/mailThreadPredicates.ts` that selects messages: free text through the query builder of #1589 against `item_search_index.search_vector` (all words, each as a prefix); `from:` through `unaccent(lower(...))` on the name and address of `mail_message_meta.envelope.from`; `has:attachment` through `mail_attachments`; `before:`/`after:` on the message date; `is:` operators on `read`/`flagged`. Values are always bound parameters. Messages that are deleted are excluded.
3. Group matching messages into threads and return the whole thread's aggregates (not only the matching messages'), applying the other filters of #1633 too.
4. Add tests: `from:novak` finds "Petr Novák"; "nab" finds "Re: Nabídka na web"; "koupelny" finds "Koupelny"; `is:unread is:read` returns an empty list with 200; a deleted message does not match; combining `q` with `box` and `mailboxId`; accents and case do not matter.

## Acceptance criteria

- When `q=from:novak`, then the thread from "Petr Novák" is listed, and `q=koupelna` does not match "Siko Koupelny" unless Czech word search is active.
- When `q=nab`, then "Re: Nabídka na web" is listed, with and without Czech word search.
- When `q=is:unread is:read`, then the response is 200 with an empty `threads` array.
- When a message is deleted, then it does not make its thread match.
- Text, operators and the other filters combine with AND.
