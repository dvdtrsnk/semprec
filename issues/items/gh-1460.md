**Model tier:** medium

## Context

Model tier rationale: A signature change of the custom-route factory seam across the mount and the composition root with a small, known set of existing factories, but it is a shared seam that every later mail route depends on.

Module custom routes are mounted by `mountCustomRoutes` in `backend/services/semprec-api/src/adapter/customRouteMount.ts`. A route's `handlerExport` must resolve to a `CustomRouteHandlerFactory = (pool) => AdapterHandler`, so a module route receives only the database pool. The coming mail routes (#1686 connect a mailbox through OAuth, #1736 connect with a password, #1690 remove a mailbox, #1896 send a draft) need things that exist only in the composition root: the OAuth client configuration read from the environment, the clients that verify credentials and send mail, and the live-sync root that must be told to start or stop a mailbox's lifecycle. Today `serve.ts` builds `createDispatcher` (`backend/services/semprec-api/src/app.ts`), which mounts the custom routes, and later creates the live-sync root, so the root does not even exist when the routes are mounted.

Decision: the factory becomes `(pool, dependencies) => AdapterHandler`, where `dependencies` is a typed container created in `serve.ts` and passed through `createDispatcher` to `mountCustomRoutes`. The container is an interface of optional, lazily resolved members so a test supplies only what the route under test needs. Existing factories ignore the second argument.

Shared-file ordering: this issue also waits for #1456 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `testing`.

1. In `customRouteMount.ts` define `CustomRouteDependencies` with these members: `oauth` (client id and secret per provider and the redirect base URL, all optional), `mailServerClients` (verification and send clients, optional), `mailLiveSync` (an object with `startMailbox(tenantId, mailboxItemId)` and `stopMailbox(tenantId, mailboxItemId)`, optional), and `outboundHttp` (optional). Do not implement the members' behavior here; only the typed container and a `createCustomRouteDependencies()` helper that returns an empty one for tests.
2. Change `CustomRouteHandlerFactory` to `(pool: Pool, dependencies: CustomRouteDependencies) => AdapterHandler` and pass the container in `mountCustomRoutes`; update every existing factory type annotation (the modules with `customRoutes`: schema core, inbox, system databases, and others found by searching `handlerExport`) so they compile; behavior unchanged.
3. Thread the container from `serve.ts` through `createDispatcher` (`app.ts`) with an options field; `serve.ts` builds the container from environment values it already reads (OAuth client ids and secrets from `GMAIL_OAUTH_*` and `MS_GRAPH_OAUTH_*`, `APP_BASE_URL`) and, because the live-sync root is created after the dispatcher, passes a late-bound `mailLiveSync` proxy that resolves to the root once it exists (a request that arrives before then gets a clear error).
4. Tests: a test route factory receives the fake container given to `mountCustomRoutes`; a route that does not use it still works; a missing optional member produces a clear configuration error only when a route actually uses it.

## Scope

### In scope

- The dependency container type, the new factory signature, passing it from the composition root to the mount.

### Out of scope

- Any route that uses the container: #1686, #1736, #1690, #1896.
- The hosting of live-sync lifecycles by sync mode: #1550, #1739, #1745.
- Choosing which module registers which route (route ownership rules are unchanged).

## Acceptance criteria

- When a custom route factory is invoked by the mount, then it receives the pool and the dependency container given to the mount.
- When existing routes run, then their behavior is unchanged.
- When a route needs a member that the composition root did not configure, then it fails with a clear configuration error instead of a type error at startup.
- When a test passes a substitute container, then the route uses it.
