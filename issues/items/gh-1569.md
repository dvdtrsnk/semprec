**Model tier:** high

## Context

Model tier rationale: This opens authenticated connections to tenant-chosen hosts with real credentials, so the TLS fallback ordering, timeouts, error classification and absence of secret leakage all carry security weight.

Adding an iCloud or generic IMAP mailbox needs the server to prove the credentials work before saving anything (#1736). Later features will reuse the same check (reconnecting after a password change). Today there is no code that builds a connection from settings: `backend/packages/data/src/mail/imapFlowClient.ts` wraps an already connected ImapFlow client and `backend/packages/data/src/mail/smtpClient.ts` wraps an already authenticated nodemailer transport.

It builds on #1478, which connects to tenant-chosen hosts through the outbound address policy (`docs/adr/2026-10-16-connect-time-outbound-address-checks.md`); this issue must use that connection path and never open a socket itself. This issue only verifies; it saves nothing. #1736 calls it.

Decision: iCloud uses fixed hosts: IMAP `imap.mail.me.com:993` TLS and SMTP `smtp.mail.me.com:587` STARTTLS. For a generic host, IMAP tries 993 with TLS and then 143 with STARTTLS; SMTP tries 465 with TLS and then 587 with STARTTLS. A connection without encryption is never attempted. The first combination that passes is returned so it can be stored.

Decision: on iCloud, any login failure is reported as `mail_app_password_required`, because an ordinary account password produces the same authentication failure as a wrong one.

## Task

Load `error-handling`, `io-hardening` and `testing`.

1. Add `backend/packages/data/src/mail/mailCredentialVerification.ts` exporting `verifyMailCredentials({ provider: "icloud" | "generic", address, username, password, imapHost?, smtpHost? })`. It tries the candidate port and security combinations above, performs IMAP LOGIN and SMTP AUTH, with a 15 second timeout per connection attempt, using the policy-checked connection helpers from #1478. It returns `{ imap: { host, port, security }, smtp: { host, port, security } }` for the first working combination of each protocol.
2. Throw typed errors mapped to HTTP 400 codes added to `ITEM_ERROR_CODES` and `ITEM_ERROR_STATUS_BY_CODE` in `errorContract.ts`: `mail_auth_failed` (generic login failure), `mail_app_password_required` (iCloud login failure), `mail_server_unreachable` (DNS, refusal or timeout on all candidates) and `mail_tls_failed` (the server offers no usable TLS or STARTTLS, or the certificate is rejected).
3. Never include the password in any thrown message, log line or returned value, and close every opened connection on success and on failure.

## Scope

### In scope

- The verification function, the candidate ordering, timeouts and the four error codes.

### Out of scope

- Saving the mailbox, credential or server settings (#1736).
- The route and per-user throttle (#1736, #1750).
- Port or security overrides typed by the user; they are not offered.

## Acceptance criteria

- When a generic server accepts IMAP only on 143 with STARTTLS, then the returned IMAP settings are port 143 and `starttls`.
- When a server offers no encryption on any candidate port, then the error is `mail_tls_failed` and no plaintext login is attempted.
- When a generic login is rejected, then the error is `mail_auth_failed`; the same rejection on iCloud yields `mail_app_password_required`.
- When no candidate connects within 15 seconds each, then the error is `mail_server_unreachable`.
- When an error is thrown or logged, then it contains no password; all connections opened by the call are closed.
- A host that the outbound address policy refuses is never connected to.
