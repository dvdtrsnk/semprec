## Context

Model tier rationale: This opens authenticated connections to tenant-chosen hosts with real credentials, so the TLS fallback ordering, timeouts, error classification and absence of secret leakage all carry security weight.

Adding an iCloud or generic IMAP mailbox needs the server to prove the credentials work before saving anything (#1736). Later features will reuse the same check (reconnecting after a password change). The shared policy-checked factories now build connections from settings; this issue adds verification orchestration and bounded ownership inside those helpers.

It builds on #1478, which connects to tenant-chosen hosts through the outbound address policy (`docs/adr/2026-10-16-connect-time-outbound-address-checks.md`); this issue must use that connection path and never open a socket itself. This issue only verifies; it saves nothing. #1736 calls it.

Decision: iCloud uses fixed hosts: IMAP `imap.mail.me.com:993` TLS and SMTP `smtp.mail.me.com:587` STARTTLS. For a generic host, IMAP tries 993 with TLS and then 143 with STARTTLS; SMTP tries 465 with TLS and then 587 with STARTTLS. No LOGIN/AUTH credential is sent before verified TLS; STARTTLS may exchange its plaintext greeting and upgrade command. The first combination that passes is returned so it can be stored.

Decision: on iCloud, any login failure is reported as `mail_app_password_required`, because an ordinary account password produces the same authentication failure as a wrong one. Verification-only helper ownership and limited TLS diagnosis follow `docs/adr/2026-11-02-mail-credential-verification-owns-bounded-policy-connections.md`; normal sync/send/IDLE mappings stay unchanged.

## Task

Load `error-handling`, `io-hardening` and `testing`.

1. Add `backend/packages/data/src/mail/mailCredentialVerification.ts` exporting `verifyMailCredentials({ provider: "icloud" | "generic", address, username, password, imapHost?, smtpHost? })`. It tries the candidate port and security combinations above, performs IMAP LOGIN and SMTP AUTH, with a 15 second whole-attempt deadline (DNS through authentication), using a closed verification path owned by the policy-checked helpers from #1478. Own cancellation and socket teardown, fence late DNS/connect callbacks, and settle owned network operations before the next candidate/return. OS DNS cancellation is not promised. Apply the socket-ownership and STARTTLS teardown ADRs listed below. It returns `{ imap: { host, port, security }, smtp: { host, port, security } }` for the first working combination of each protocol.
2. Throw typed errors mapped to HTTP 400 codes added to `ITEM_ERROR_CODES` and `ITEM_ERROR_STATUS_BY_CODE` in `errorContract.ts`: `mail_auth_failed` (generic login failure), `mail_app_password_required` (iCloud login failure), `mail_server_unreachable` (DNS, refusal or timeout on all candidates) and `mail_tls_failed` (an unambiguous machine-readable TLS/required-upgrade failure available before helper mapping). Ambiguous socket/TLS errors, including erased SMTP certificate errors, remain `mail_server_unreachable`; never infer TLS from ESOCKET/ECONNECTION or response text alone. After a protocol exhausts candidates, prioritize observed authentication rejection, then definite TLS failure, then unreachable. Unknown failures stop verification as a fixed generic outward Error without raw cause/properties; retain exact primary/secondary values internally through settlement and safe diagnostic processing under the privacy-boundary ADR listed below.
3. Never include the password in any thrown message, log line or returned value, and close every opened connection on success and on failure, including deadline, late-connect and setup failures. Prove owned closure/settlement and safe application logs with finite local fake-server controls; do not replace the SMTP implementation or use private/global library interception.

## Acceptance criteria

- When a generic server accepts IMAP only on 143 with STARTTLS, then the returned IMAP settings are port 143 and `starttls`.
- When no candidate completes verified TLS, then verification fails and sends no plaintext login; definite TLS/upgrade refusals give `mail_tls_failed`, while ambiguous socket/TLS failures give `mail_server_unreachable`. Certificate validation remains enabled.
- When a generic login is rejected, then the error is `mail_auth_failed`; the same rejection on iCloud yields `mail_app_password_required`.
- When no candidate connects within 15 seconds each, then the error is `mail_server_unreachable`.
- When an error is thrown or logged, then it contains no password; all connections opened by the call are closed.
- A host that the outbound address policy refuses is never connected to.
