## Context

`web/src/views/agentPage/ToolsBlock.tsx`, `useMcpToolGrants` (lines 23-69): line 25 `const mounted = useRef(true);` and lines 30-35 register a cleanup-only effect that sets `mounted.current = false` on unmount. Lines 47 and 50 apply the `listMcpToolGrants` result only `if (mounted.current && …)`.

`web/src/main.tsx` line 67 renders the tree inside `<StrictMode>`. In development React StrictMode runs every effect twice on mount — mount, simulated unmount (cleanup), mount again — while `useRef` values persist across that cycle. So after the second mount `mounted.current` is `false` for the component's whole life, the load effect at lines 63-66 runs `load(false)` whose result is dropped at line 47, and the block stays on `LoadingState` forever on every `?page=agent&project=…&database=…` page in `pnpm dev`. The tests in `web/src/views/agentPage/__tests__/ToolsBlock.test.tsx` render without `StrictMode` (`renderBlock`, line 37), which is why they pass. A production build is unaffected (StrictMode double-invocation is development-only), so this is a dev-only stuck state, but it makes the AGENT page unusable in development and hides every later regression on it.

The `loadGeneration` counter (line 29) already guards out-of-order responses; the `mounted` ref only guards the post-unmount `setState`, which React 18+ no longer warns about anyway.

## Task

- In `useMcpToolGrants`, replace the `mounted` ref pattern with one that is StrictMode-safe: set `mounted.current = true` in the body of the same effect whose cleanup sets it to `false` (effect at lines 30-35 becomes `useEffect(() => { mounted.current = true; return () => { mounted.current = false; }; }, [])`). Keep the `loadGeneration` guard as is. Update the comment above the effect to say why the flag is set in the effect body (StrictMode's mount → cleanup → mount cycle keeps the ref).
- Test in `web/src/views/agentPage/__tests__/ToolsBlock.test.tsx`: add a case that renders `ToolsBlock` wrapped in React's `<StrictMode>` (import from `react`) with `listMcpToolGrants` resolving one row and asserts the row (`search_docs`) appears — this fails on `develop` (stays on the loading state) and passes after the fix. Also assert `listMcpToolGrants` was called (StrictMode may call it twice; assert `toHaveBeenCalled`, not a count).
