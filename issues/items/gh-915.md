## Context

On 2026-10-01, `integration-shard (1)` of CI run 36871665352 (PR #910) was cancelled at the job's 12-minute timeout, and it read like a hung integration test. It was not one. The step `Backend — install ffmpeg` ran from 13:50:32 to 14:02:29: apt reported `Fetched 62.8 MB in 11min 39s (89.9 kB/s)` from the runner's Azure Ubuntu mirror, so `test:integration` started with 33 seconds of job budget left. In those 33 seconds it completed `mailSync.test.ts` (121 tests, last one "(d) fetchFlagsChangedSince is skipped on the initial sync…", ✓ at 14:03:02) and was killed at 14:03:03 while the next file was running. The orphans killed at cleanup (node, sh, postgres) are the vitest run and its embedded PostgreSQL, still working when the timeout killed them. Shards 2 and 3 of the same run installed ffmpeg in 26–34 seconds.

Two things in `.github/workflows/ci.yml` let a slow mirror end the job this way:
- Every shard downloads ffmpeg's ~63 MB package closure from the mirror on every run, and the sharding (#657) triples those downloads.
- One job-level `timeout-minutes: 12` covers both the download and the tests, so time lost to the mirror comes out of the test budget, and the cancellation names neither step.

## Task

- In the `integration-shard` job of `.github/workflows/ci.yml`, cache the ffmpeg `.deb` files with `actions/cache/restore@v4` / `actions/cache/save@v4`, keyed per runner image (`ImageOS`, `ImageVersion`, `RUNNER_ARCH`). Point apt at the cached directory with `-o Dir::Cache::Archives=…`, so only a package the mirror has updated since gets downloaded. Save the cache right after the install step on a cache miss, so a shard whose tests fail still fills it.
- Give the two slow steps their own `timeout-minutes`: 13 for the ffmpeg install and 9 for `test:integration`. The install budget is 13 because the slowest uncached install seen took 12.5 minutes, so a cache miss on a slow mirror must still pass: 18 of the 599 installs on 2026-09-30 and 2026-10-01 took over 4 minutes, and 7 took over 10. Set the job timeout to the sum of the two budgets plus about a minute for setup (23), and write that derivation in the job's comment.
- Do not change the shard count, the required `integration` fan-in job, the triggers, the concurrency group or any permission.

## Acceptance criteria

- On a cache miss, each shard installs ffmpeg from the mirror as before and one of them saves the cache. On a hit, apt installs from the cached `.deb` files.
- A stalled ffmpeg install fails the step `Backend — install ffmpeg` after 13 minutes, and a stalled test run fails `Backend — test:integration (shard n/3)` after 9 minutes. Neither surfaces as a cancelled job.
- The required `integration` context still turns red when any shard fails or is cancelled.
