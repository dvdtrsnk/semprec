**Blocked by:** #1497
**Model tier:** low

## Context

Model tier rationale: A small, mechanical change to one notification payload and the values feeding it, following the failure kind that an earlier issue stores.

When a mailbox stops syncing, the check `mail:<mailboxItemId>` in `backend/packages/data/src/observability/observabilityCheckSystem.ts` alerts on any non-null `last_error` or an overdue `next_expected_activity_at`, and `notifyMailSyncStalled` writes a `mail_sync_stalled` notification whose payload is `{ mailboxItemId, lastError }`. `GET /api/notifications/unread` returns that payload, so the provider's error text reaches the client; a revoked token already produces such a notification today.

#1497 stores a fixed failure kind per mailbox. This issue replaces the text in the notification payload with that kind. The Semp problem for the same failure is #1506.

Decision: when the check alerts only because the sync is overdue and no failure kind is stored, the reason is `other`.

## Task

Load `io-hardening` and `testing`.

1. Make `listAllMailAccountSyncStates` rows carry the failure kind (from #1497) and change the `mail_sync_stalled` payload to `{ mailboxItemId, reason }` where `reason` is `reauthorization`, `connectionLimit` or `other`. `lastError` is removed from the notification payload.
2. Update the check docstrings and the existing tests that asserted `lastError` in the payload.

## Scope

### In scope

- The notification payload of `mail_sync_stalled`.

### Out of scope

- The `tenant_observability_checks` detail and the administrator health report, which keep their own fields and are not mail routes; changing them is not planned yet.
- Raising or resolving a Semp problem (#1506).
- Notification kinds, titles or localisation.

## Acceptance criteria

- When a mailbox with a stored failure kind starts alerting, then the `mail_sync_stalled` notification payload is `{ mailboxItemId, reason }` with that kind, and contains no `lastError`.
- When the check alerts only because the sync is overdue, then `reason` is `other`.
- `GET /api/notifications/unread` never returns provider error text for a mail notification.
