## Context

Model tier rationale: The voice session runs in `semprec-api` while the turn runs in `semprec-agents`, so this adds a new cross-process cancellation signal for one turn, with abort ownership and cleanup of a partly executed turn; at this uncertainty the higher tier is chosen.

In voice mode (#1734) speech from the user while Semp speaks only stops the audio; the agent turn keeps running and the next transcript waits in the thread's queue. The product decided that voice may cancel a running turn, but only when the user says so explicitly ("Stop", "Zruš"), and then as an ordinary cancellation of the turn.

Today a running agent turn can only be aborted for a whole tenant: `withInFlightRegistration` in `backend/services/semprec-agents/src/agentRunTasks.ts` registers an `AbortController` per job under its tenant in `InFlightAgentRuns` (`backend/services/semprec-agents/src/inFlightAgentRuns.ts`), and `serve.ts` aborts all controllers of a deactivated tenant from a Postgres notification listener (`startTenantDeactivationListener`). An aborted turn throws `AgentRunCancelledError`, which closes the run with the error code `cancelled` (#1446) and the reply with status `error` and `error_code` `cancelled` (#1907); dangling tool calls of the turn are paired immediately (#1568). A cancelled turn raises no Semp problem (#1931).

Decision: the stop command is recognized only on a final transcript that, after trimming, lower-casing and removing trailing punctuation, equals exactly one entry of a closed list `VOICE_STOP_COMMANDS = ["stop", "zruš"]`. Such a transcript is never stored as a thread message. Any other transcript, including a longer sentence that contains one of these words, is handled as before.

Decision: cancelling a turn never decides an approval request. A request the turn already created stays pending, and its write is executed only after the person approves it, as for any other request.

## Task

Load `state-writes`, `io-hardening`, `error-handling` and `testing`.

1. Add `backend/packages/data/src/semp/sempTurnCancellation.ts` with the channel name `semp_turn_cancel` and `requestSempTurnCancel(client, { tenantId, assistantMessageId })`, which sends a Postgres notification on that channel with the two ids as JSON payload. Export it from the package barrel.
2. In `semprec-agents`, extend `InFlightAgentRuns` with `registerTurn(tenantId, assistantMessageId, controller)` and `abortTurn(tenantId, assistantMessageId): boolean`; the queued turn handler of #1727 (`backend/services/semprec-agents/src/sempMessageTask.ts`) registers the controller of its job under the assistant message it answers, and unregisters on every path. In `serve.ts`, listen on `semp_turn_cancel` next to the tenant deactivation listener and call `abortTurn` for each notification; a notification for a turn not running in this process is ignored.
3. In the voice session handler of #1734 (`backend/services/semprec-api/src/voiceSessionHandler.ts`), add a pure `isVoiceStopCommand(transcript)` in a new `backend/services/semprec-api/src/voiceStopCommand.ts`. On a final transcript that is a stop command: do not create a message; stop speech output (abort the synthesis request, drop queued sentences, send `speaking` end); if the session's thread has an assistant message whose turn is running, call `requestSempTurnCancel` for it in the session's tenant. With no running turn, the command does nothing else.
4. Tests: "Stop" and "Zruš" (with any case and a trailing full stop) during a running turn end that turn with the reply in status `error` and `error_code` `cancelled`, and no thread message is created for the command; "stop the music" is stored as an ordinary message and cancels nothing; a stop command with no running turn creates no message and cancels nothing; a turn that created an approval request before the stop leaves that request pending and nothing is executed until it is approved; a notification for another tenant's message id aborts nothing; the cancelled turn's dangling tool call is paired and the thread wakes for the next message.

## Scope

### In scope

- Recognizing an explicit voice stop command, the cross-process cancellation of that thread's running turn, and stopping speech output.

### Out of scope

- Barge-in without a stop command, which only stops speech output: #1734.
- A stop button for typed chat or any HTTP cancellation route.
- Cancelling or rejecting approval requests created by the cancelled turn.
- Localized command lists beyond the closed list above.

## Acceptance criteria

- When the user says "Stop" or "Zruš" while Semp's turn is running, then the turn ends as an ordinary cancellation (reply `error` with `error_code` `cancelled`), speech output stops, and no message is stored for the command.
- When the user says a sentence that only contains one of these words, then it is stored as a normal message and the running turn continues.
- When the user says a stop command and no turn is running, then nothing is stored and nothing is cancelled.
- When the cancelled turn had created an approval request, then the request stays pending and its write is executed only after the person approves it.
- A cancellation request for a turn of another tenant never aborts anything.
