## Context

Model tier rationale: Removes one request parameter and one enum case with their mappings and tests in the shared Kotlin layer and the CoreKit bridge.

Since #2113 the backend's mail facets route takes no query parameters and answers `{ total, projects }`, yet the shared mail repository still sends `projectId` to it. Since #2112 the backend never produces the search subtitle kind `count`, yet `SearchSubtitleKind.COUNT` and its Apple mapping remain.

## Task

1. Stop sending `projectId` to the mail facets route and remove the parameter from the repository API, use case and ViewModel call sites that only carried it there.
2. Remove the `count` search subtitle kind from the shared vocabulary, its DTO mapping and the Apple bridge and views.

## Touches

- mobile/shared (MailRepositories, HttpMailRepository, MailThreads ViewModel call sites, SearchVocabulary, search DTO mapping) and commonTest
- mobile/apple/Modules/Core/CoreKit (search and mail bridges) and the Overview search views, with tests

## Scope

### In scope

- The parameter and the enum case.

### Out of scope

- Any other mail or search change.

## Acceptance criteria

- The mail facets request carries no `projectId`; a test asserts the request.
- No Kotlin or Swift source refers to the `count` subtitle kind.
- `mobile/scripts/verify architecture shared` passes and the Apple tests of the touched targets pass on an iOS simulator.
