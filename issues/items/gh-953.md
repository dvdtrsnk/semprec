## Behavior specification (approved)

Part of the multi-tenancy program specified in #950. Realtime delivery becomes tenant-routed:

1. Every NOTIFY payload carries the tenant of the code that published it; frames are delivered only to sockets of that tenant; a payload without a tenant is dropped and logged; the "no acting user ⇒ broadcast to every socket" fallback is removed.
2. Opening and editing a doc, and watching an agent run, are resolved inside the socket's tenant; a foreign doc or run behaves exactly like an unknown one; a forged update for another doc is never delivered.
3. The WebSocket upgrade and every unsafe HTTP method are refused when they carry an `Origin` that is not same-origin; a request without `Origin` (non-browser clients such as the native apps) is accepted.

## Decisions

- **Supersede the thin-user-scoped invalidations ADR?** → Yes: its broadcast fallback is the leak; the new ADR routes by tenant and keeps "thin invalidation, client refetches".
- **Must a request without `Origin` be refused?** → No: only a foreign `Origin` is refused. → Browsers always send `Origin` on cross-origin unsafe requests and WebSocket upgrades; non-browser clients (native apps, scripts holding a bearer token) send none and are not a cross-site request forgery vector.
- **Where does the payload tenant come from?** → From the publisher's scope at publish time, never from payload content supplied by a client.

## Out of scope

Admin teardown of a suspended tenant's sockets (#958); the isolation suite (#960).
