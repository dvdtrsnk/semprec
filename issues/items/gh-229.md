**Blocked by:** #117

## Context

Pi sessions are cheap objects but do not define Semprec's cross-agent lifecycle. Building on the lifecycle adapter and repair sweep from #117, this part implements supervisor→project-agent delegation as an in-process session with a process-memory registry, the busy-flag rejection of duplicate calls, and the 24-hour TTL for delegated sessions. The sibling part #118 applies the same registry and TTL to Semp's own conversation with the user, with pause-and-wake semantics. #119 later reconstructs sessions that were discarded by the TTL.

## Task

- **Delegation tool.** Implement `agentTool.delegate` in Semp's own manifest only; project agents never receive it (hardcoded absence, not a grant toggle) and therefore cannot delegate further or loop back. Run the target as an in-process `AgentSession`, never a subprocess, and return only the target's final assistant message to the supervisor — never the full transcript.
- **Registry.** Keep a process-memory registry of open delegated sessions keyed by `(supervisorRunId, targetProjectItemId)`, each entry holding the live `AgentSession`, its `agent_runs` id (created through #117 with `unit='session'`), a `busy` flag, and the last-activity timestamp.
- **Busy rejection.** Set `busy` true just before dispatch and false on response. A concurrent call onto a key that is already busy is never dispatched and returns immediately an error `tool_result` to Semp ("this project is already handling another request from this run, retry next turn") instead of blocking or overwriting.
- **TTL.** A further delegation onto the same key within 24 hours of the last activity reuses the same `AgentSession` (a new message into the same conversation). After 24 hours of inactivity (an in-process timer reset on every activity; no table or job) discard the in-memory object and close its session run (`status='done'`, `finished_at=now()`).

## Scope

### In scope

- Delegation tool, one-way topology, registry, busy behavior, and the delegated-session TTL.

### Out of scope

- Semp's user conversation and its pause/wake semantics (#118).
- Reconstruction of discarded sessions (#119), subprocess isolation, and an additional concurrency cap over pi's parallel calls.

## Acceptance criteria

- Two unrelated supervisor runs delegating to the same project never share a target session.
- A duplicate delegation onto a busy key fails immediately with a tool result, without blocking or overwriting the in-flight call.
- Project agents have no delegation tool in their tool array.
- A delegated session idle for 24 hours is removed from memory and its run row is closed as done; a delegation within 24 hours reuses the session.
