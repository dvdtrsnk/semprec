## Context

Model tier rationale: The change rewires the required-check gate of every pull request and the verify steps of four Relay workflows; a wrong condition or detector rule silently skips required verification, so the guards and their tests carry the risk.

Every pull request runs every platform pipeline. Of the last 29 merges into `develop`, 5 changed only mobile code and still ran the whole backend pipeline (one of them changed 19 files under `mobile/` and ran all 14 integration shards, 136 runner-minutes), and 22 did not need the web pipeline. Relay's `implement-issue`, `fix-review-findings`, `merge-pull-request` and `recover-blocked-issue` workflows and the agent instructions run the full backend and web verify for every change; only the two mobile CI jobs and Relay's `verify-mobile` already skip when nothing under `mobile/` changed. Within mobile, a change to one app also runs the other app's job, and the Android job cannot stand alone because detekt runs only in the macOS-only `shared` step.

The owner directed this change on 2026-11-24. It is maintainer-implemented, not dispatched to Relay: it edits the protected paths `.github/workflows/ci.yml` and `.relay/workflows/*`.

A pilot measured finer selection inside the backend integration tier first: the whole tier ran once with V8 precise coverage recorded per test file, and the last 20 backend merges were replayed against that map. Median selection was 100 % and the mean 92 %, because 11 of the 20 merges touch inputs coverage cannot see (i18n JSON, the baseline SQL, a `package.json`, `ci.yml`) and most others change module-level code that the seed and the choke point import almost everywhere. That selection is out of scope.

## Task

1. Add `.github/scripts/changed-areas.mjs`, a zero-dependency detector that maps a change to the areas `backend`, `web`, `android` and `apple`. It compares `git diff --no-renames <merge base of base and head> <head>`, classifies each path by the first matching rule (review-rules directories none; `backend/`, `deploy/` and `shared/` backend; `web/` web; `mobile/android/` android; `mobile/apple/` apple; the rest of `mobile/` both apps; the root Prettier files backend and web; `.github/scripts/changed-areas.mjs` and `.github/` outside `scripts/` and `ISSUE_FORMAT.md` every area; the write-safety checker and baseline backend; other `.github/scripts/`, `docs/`, `issues/`, `review-rules/`, `.bb/`, `.claude/`, `.relay/`, `assets/` and `README.md` none), counts a path no rule names for every area, and counts a comparison git cannot make for every area with a warning. It offers `--area <name>` (prints `true` or `false`), `--json` and `--github-output` (appends `<area>=true|false` to `GITHUB_OUTPUT` and a summary table to `GITHUB_STEP_SUMMARY`); usage errors exit 2. Add `.github/scripts/changed-areas.test.mjs`.
2. In `.github/workflows/ci.yml`, replace `mobile-changes` with a `changes` job that runs the detector for the pull request or push. Give `unit`, `integration-shard`, `dependency-check`, `e2e` and `pi-agent-contract`, and the backend steps of `ci` (write safety, install, lint, format check, build), the condition `github.event_name == 'push' || needs.changes.outputs.backend == 'true'`, and the web steps of `ci` the same condition on `web`. `ci` depends on `changes`, runs unless cancelled, and fails first when `changes` did not succeed or reported a value other than `true` or `false`; its repository scans run on every change. `integration` depends on `changes` and the shards and passes skipped shards only for a pull request whose `changes` succeeded with `backend` `false`. Run `mobile-android` for `android` and `mobile-apple` for `apple`, run `mobile/scripts/verify architecture shared apple` in `mobile-apple`, and add `gradle/actions/setup-gradle@v6` with `cache-provider: basic` to both mobile jobs.
3. Add `detektAll -PdetektAutoFix=false` to the `android` step of `mobile/scripts/verify`.
4. In the four Relay workflows, run the backend verify, `verify-web` and `verify-mobile` only when the detector, against a freshly fetched `develop`, reports their area; `verify-mobile` runs `architecture android`, `architecture shared apple` or the full `architecture shared android apple` for the areas reported. A failed fetch still fails the step. Replace `.github/scripts/mobile-gates.test.mjs` with `.github/scripts/area-gates.test.mjs`, which runs the real step scripts of `ci.yml` and of the four workflows.
5. Describe the rule: a new section in `docs/architecture/delivery-and-operations.md`, `docs/operations/required-checks.md`, a mobile ADR that supersedes `2026-10-25-conditional-mobile-verification-in-ci-and-relay`, `.bb/AGENTS.md`, the `implement-issue`, `mobile-verify` and `android-compose` skills, `mobile/docs/verify.md` and `mobile/review-rules/context.md`. In `review-rules/tasks/ci-workflows.md` item 2, name the area condition and its two guards as the one sanctioned skip; in `review-rules/tasks/repo-scripts.md`, add an item that makes a detector rule or comparison change that drops a needed area a high finding.

## Scope

### In scope

- The detector, its use in CI, Relay and the agent instructions, the Android and Apple split of the mobile jobs, the Gradle cache of the mobile jobs, and the documents and review rules that describe them.

### Out of scope

- Selecting tests inside the backend integration tier by import graph or coverage: the pilot above found no worthwhile reduction.
- Restructuring the seed, the choke point or the `@alldots/data` barrel to make such selection possible.
- Fixing the integration tests that time out intermittently (`lastContact`, `mailRestIndexSync`) or fail on macOS hosts only (`mcpConnectionFactory`).
- Changing branch protection or the set of required contexts.

## Acceptance criteria

- A pull request that changes only files under `mobile/` reports `backend=false` and `web=false`; `unit`, the integration shards, `dependency-check`, `e2e` and `pi-agent-contract` are skipped, `ci` skips its backend and web steps, and `integration` and every other required context report success.
- A push to `develop` or `main` runs every required job and every backend and web step of `ci`, whatever the detector reports.
- When the `changes` job fails or reports a value other than `true` or `false`, `ci` fails; `integration` fails for skipped shards unless the event is a pull request, `changes` succeeded and `backend` is `false`.
- A file moved from one area to another counts for both, a path no rule names counts for every area, and a comparison git cannot make reports every area as `true`.
- A change only under `mobile/apple/` skips `mobile-android`, a change only under `mobile/android/` skips `mobile-apple`, and any other change under `mobile/` runs both; `mobile-apple` runs the architecture rules and `mobile/scripts/verify android` runs detekt.
- Relay's backend, web and mobile verify steps print that their verification is not needed when their area is unchanged, run it when it changed, compare with the fetched `develop` rather than a stale local one, and fail when the fetch fails.
- `changed-areas.test.mjs` and `area-gates.test.mjs` cover these behaviours, and `run-repo-script-tests.mjs` runs them.
