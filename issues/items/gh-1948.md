**Blocked by:** #1733, #1927
**Model tier:** high

## Context

Model tier rationale: The work crosses the API, the agents runtime and the realtime stream, with ephemeral typing frames that must follow the same tenant and run scoping as durable events.

A user can drag a draft into the Semp chat, ask for a change, and Semp rewrites that same draft. The message carries a reference to the draft (an item of the Emails database that has a `mail_drafts` row). The chat message queue and turn runner are #1727, ref validation is #1682, and the expansion of refs into the turn context is #1733. The draft is changed with `mail.draft.update` (#1927). While the run writes, the client should show "Semp is writing the draft"; the realtime protocol already has the ephemeral frame `agent:delta` (`backend/packages/realtime/src/protocolV1.ts`).

Decision: the ephemeral frame carries the draft id and the text being written; the durable change is the normal draft update and its item invalidation, and the indicator ends with the run.

## Task

Load `state-writes`, `io-hardening`, `testing` and `canonical-keys`.

1. Draft ref expansion: register the mail module's expansion for an Emails item that has a `mail_drafts` row, through the extension point of #1733: the turn context gets the draft id, subject, recipients and body and the instruction that the draft is changed with `mail.draft.update`.
2. Delta frames: when `mail.draft.update` runs inside an agent run started from a chat turn, publish `agent:delta` frames for that run with the payload `{ kind: "mailDraftBody", draftId, body }` before the durable update is committed; large bodies use the existing chunking. Define the payload type next to the frame definitions in `protocolV1.ts`. Frames go only to the connections of the run's tenant and user, like other agent deltas.
3. The durable update sets `last_edited_by` to agent and publishes the draft item invalidation as usual; a failed update publishes no further frames and the run ends normally.
4. A draft that is sent, deleted or does not belong to the tenant is rejected with a not-found or conflict error and the run continues.

## Scope

### In scope

- Draft ref expansion, the draft body delta frames and their scoping.

### Out of scope

- The chat queue, turn running and ref validation themselves (#1727, #1682, #1733).
- The tool itself (#1927); sending (#1949).
- Client rendering of the indicator.

## Acceptance criteria

- A chat message referencing an open draft starts a run whose context contains that draft; the run's `mail.draft.update` changes that same draft.
- While the run writes, the user's connection receives `agent:delta` frames with `kind: "mailDraftBody"` and the draft id; another user or tenant receives none.
- A reference to a sent or deleted draft produces a not-found or conflict result for the tool and the run still finishes.
