## Behavior specification

Inbox to Journal and pages: journal entry and page proposals.

This batch was planned from the reviewed design of the iOS app: every issue below states the backend behavior the app needs that `develop` does not provide yet. The issues are linked as sub-issues; their order follows the dependency graph across all batches, foundations first.

Status: drafts awaiting the `/define-behavior` Phase 5 audit. No issue in this batch carries `spec:approved` or `agent:ready` yet.

## Decisions

Decisions adopted while drafting, and questions still open for the product owner (per chunk of the batch):

### Decisions: journal-inbox-1

#### Adopted decisions
- Where do project and area of a journal entry live (day level or block)? -> edges on the Journal day item -> the card shows them as day properties and the day already has an area relation.
- Is the area derived from the project (read-only when a project is chosen)? -> Decided by the product owner: yes; the area of a Journal entry is derived from its project (a derived value), so it is read-only while a project is chosen and changes only when the project changes. Without a project the area is the entry's own value. A `journalEntry` envelope with both is rejected (#1991); the tick drops the area when it proposes a project (#1982); confirm writes only the project edge then (#1981); #1595 and #1662 add Journal to the derived-area reads and the manual-area guard.
- Author of confirmed journal/page blocks: `ai_agent` or `user`? -> Decided by the product owner: the user, because the user confirmed the proposal; the record that Semp proposed the blocks is kept on the card (per-step `blockIds`, #1648). The listing of what Semp changed shows only writes Semp made on its own, as for items (#1680). #1681 (including the old `pageContent` shape) and #1981 write the blocks as `user`.
- "Under heading": end of section or right below the heading? -> end of the section (before next heading of same or higher level).
- Level of the inserted heading: one level below the section heading (max h3), else h2.
- Unknown entity kinds on read: shown, never executed; confirm and revise answer 409.
- Day not existing at confirm: created lazily via the period helper, entry appended at the end of the page.
- Stale heading at confirm: 409, card stays proposed.
- afterHeadingText with no match or target without a page: falls back to `end`.
- v2 pageContent restricts targets to page hosts (project, area, Journal day, Pages sub-page); old shape unchanged.
- The tick defaults a journal entry's date to the source Inbox item's date and supplies the Journal database as target.

#### Open questions for the product owner
- Exact set of "Pages" sub-page hosts that count as a page host (implementer must check which databases exist for Pages at implementation time; no dedicated Pages database was found in the checkout's ten-database list).

#### User-visible behavior
A voice note or text about a personal experience can be processed into a proposed Journal entry with day, text, optional project and area. Confirming it creates the day if needed and appends the text at the end of that day's page as the user's own text (the card records that Semp proposed it), linking the day to the chosen project, or to the chosen area when no project is chosen (with a project the area follows from it); confirming again changes nothing. Separately, a proposal that writes notes into a page can carry several lines of Markdown and a chosen place: start, end, or under a named heading (at the end of that section), with an optional new heading; the tick suggests the heading by its text and the server resolves it. Older app versions still display new card kinds without error.
