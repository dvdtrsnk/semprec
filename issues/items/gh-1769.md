**Blocked by:** #1727
**Model tier:** medium

## Context

Model tier rationale: A new queued task that makes an AI call outside any transaction and writes back only under a guard, touching the gateway's operation map, the queue catalog and the turn handler's enqueue point; each seam is an existing pattern, but exhausted budgets and duplicate jobs must degrade quietly.

New chats start without a name. The chat list should show a short title made from the conversation ("Plan for today" from "What is my plan today?"), generated once after the first answer; until it exists the client shows the start of the first message. Today `semp_threads.title` and `title_source` exist (#1367: `title` is NULL for chats until set, `title_source` is `auto` or `user`) but nothing fills the title, and a message turn (#1727) only stores the reply.

The AI gateway's `POST /internal/complete` (`backend/services/semprec-ai-gateway/src/completeHandler.ts`) accepts only operations listed in `OPERATION_REQUIRES_PROJECT_ITEM`, charges the tenant's AI budget and records `ai_gateway_calls.operation`. Its callers use the neutral `AiGatewayClientPort` (`backend/packages/shared/src/aiGatewayClient.ts`); the api process builds the HTTP client in `backend/services/semprec-api/src/projectAgentGuidanceComposition.ts`.

This issue adds a core task that generates the title through that port. Titles of automatic-task and Inbox-item threads are never generated: they follow the heartbeat name and the item text live (#1729).

Decision: the call is attributed to the operation `semp_thread_title` only, with no project item and no agent run. Carrying the run through the gateway would need a new trusted header and verification in the gateway; the operation name already makes the spend visible per activity.

Decision: the call never runs inside a database transaction (see `docs/adr/2026-09-10-bracket-non-transactional-calls-with-staleness-checked-transactions.md`): a short read, then the gateway call, then a guarded write. The title is written only if it is still NULL and `title_source` is still `auto`, so a title the user set meanwhile, or a duplicate job, is never overwritten.

Decision: a gateway error or an exhausted budget leaves the title NULL with no retry; the job ends successfully and nothing about the conversation is logged.

## Task

Load `ai-gateway`, `state-writes`, `io-hardening` and `testing`.

1. In `backend/packages/queue/src/index.ts` add `SEMP_THREAD_TITLE: "sempThreadTitle"` to `CORE_TASK_NAMES`, with `CORE_TASK_AFFINITY` `api` and `TASK_TENANCY` `tenant`.
2. In `completeHandler.ts` add `["semp_thread_title", false]` to `OPERATION_REQUIRES_PROJECT_ITEM` (projectItemId must be null) and update the comment of `operation` in `aiGatewayClient.ts`.
3. Add `backend/packages/data/src/semp/sempThreadTitle.ts` with the task handler: (a) in a short tenant-scoped read, load the thread and its first user message and first assistant reply, and the user's `locale`; stop if the thread is not a `chat`, has a title, or has `title_source` `user`; truncate each message to 1000 characters; (b) outside any transaction call `AiGatewayClientPort.complete` with operation `semp_thread_title`, a low temperature, a system prompt asking for a title of at most 60 characters in the user's language, and a response schema `{ title: string (1 to 60) }`; (c) normalize the result (single line, trimmed, no surrounding quotes, at most 60 code points; empty results are discarded); (d) in a short transaction `UPDATE semp_threads SET title = ... WHERE id = ... AND title IS NULL AND title_source = 'auto'`, and only if a row changed publish the thread invalidation used by the thread messaging path so clients refresh the list.
4. Register the handler in `createCoreTaskList` (`backend/packages/data/src/worker.ts`), taking the gateway client as an optional dependency that defaults to a no-op, and compose the real client for the api runtime in `backend/services/semprec-api/src/queueRuntime.ts`.
5. In the turn handler of #1727 (`backend/services/semprec-agents/src/sempMessageTask.ts`), enqueue the task in the transaction that marks the first assistant message of a `chat` thread `done`, with `jobKey` `sempThreadTitle:<threadId>`, `unsafe_dedupe` and `maxAttempts` 1, only while the thread has no title.
6. Tests: the first finished turn of a chat enqueues one job and the title is set once; a second job does not overwrite it; a user-set title (`title_source` `user`) is never overwritten; tick and item threads are never titled; an exhausted budget and a gateway error leave the title NULL without a retry; the gateway call happens with no open transaction (no connection held); the call is recorded with operation `semp_thread_title`; the user's locale is used; the logs contain no message text.

## Scope

### In scope

- Generating and storing the title of a chat thread once, through the gateway, with the guards above.

### Out of scope

- Renaming a thread by the user and its `title_source` `user` path; not in v1 (decided by the product owner).
- Titles for automatic-task and Inbox-item threads (resolved live by #1729).
- Attributing the title call to an agent run, and any other gateway change.
- Search over titles (#1737).

## Acceptance criteria

- When the first answer of a new chat is finished, then within the task a title of at most 60 characters in the user's language is stored and the thread list refreshes.
- When the job runs twice or the user already set a title, then the existing title is not changed.
- When the tenant's AI budget is exhausted or the gateway fails, then the title stays NULL, the job is not retried and the client keeps showing the start of the first message.
- When the title call is made, then `ai_gateway_calls` has a row with operation `semp_thread_title` and no project item.
- When the call is in flight, then no database transaction is held open.
