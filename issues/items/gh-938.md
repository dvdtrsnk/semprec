## Context

Harvest issue #934 collected findings about bare `as` casts of values that cross a boundary (repository rule 6: validate at the edge, then trust it inside).

- PR #839, `backend/packages/data/src/chokePoint/propertiesStore.ts:10`: `isUniqueViolation` casts `err: unknown` to `{ code?: string; constraint?: string }` instead of narrowing it.
- PR #839, `backend/services/semprec-api/src/__tests__/propertiesHandler.test.ts:444`: `(await res.json()) as { error: { code: string; details?: ... } }` in the test "returns 409 version_conflict naming 'key' when creating a property with a duplicate key (issue #672)" is an unchecked cast of an API response; a different shape fails with a `TypeError` rather than a clear assertion.
- PR #852, #852 and #852 (the same defect, reported three times), `backend/packages/data/src/__tests__/queueConcurrency.test.ts:69` (moved from lines 42 and 46): the `probe` task handler casts its `payload: unknown` with `(payload as { queue: string }).queue`.

## Task

1. In `propertiesStore.ts`, rewrite `isUniqueViolation` so it narrows `err` with `typeof`/`in` checks (object, `code` and `constraint` strings) instead of casting it. Export it, and keep its behaviour unchanged: it is true only for `code === "23505"` with the named constraint. Add `backend/packages/data/src/chokePoint/__tests__/propertiesStore.unit.test.ts` (the directory that already holds `chokePoint`'s other unit test, `hooks.unit.test.ts`) covering the inputs in the acceptance criteria.
2. In `propertiesHandler.test.ts`, replace the cast at line 444 (the duplicate-key test named above) by reading the body as `unknown` and asserting its shape with `expect(body).toMatchObject({ error: { code: "version_conflict", details: { field: "key" } } })` (or a small type guard), so a wrong response shape fails with an assertion message naming the received body.
3. In `queueConcurrency.test.ts`, replace the cast of `payload` in the `probe` handler with a guard that checks `payload` is an object whose `queue` is a string, and throws a descriptive error otherwise.

## Touches

- backend/packages/data/src/chokePoint/propertiesStore.ts (`isUniqueViolation` only)
- backend/packages/data/src/chokePoint/__tests__/propertiesStore.unit.test.ts (new)
- backend/services/semprec-api/src/__tests__/propertiesHandler.test.ts (the duplicate-key test only)
- backend/packages/data/src/__tests__/queueConcurrency.test.ts

## Scope

### In scope

The three replacements above, in the three named places.

### Out of scope

Every other finding of harvest issue #934 and anything adjacent to the lines named in the Task, even in the same file. The identical `isUniqueViolation` helpers in `databasesStore.ts` and `viewsStore.ts` are not flagged and stay as they are, and so do the other `(await res.json()) as { error: ... }` casts in `propertiesHandler.test.ts`.

## Acceptance criteria

- `isUniqueViolation` in `propertiesStore.ts` contains no `as` assertion and returns false for `null`, a string and an object without `code`, and true for `{ code: "23505", constraint }` with the matching constraint; `chokePoint/__tests__/propertiesStore.unit.test.ts` covers these inputs.
- `propertiesHandler.test.ts` has no `as { error:` cast at the duplicate-key assertion; a body of `{ error: null }` would fail with an assertion message rather than a `TypeError`.
- `queueConcurrency.test.ts` has no `payload as { queue: string }` cast; its existing test still passes.
