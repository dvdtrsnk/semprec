**Blocked by:** #161, #86

## Context

The durable event bridge is ready and #86 defines retained Yjs history across compaction. This slice implements the binary stream only for explicitly open documents.

## Task

Handle `doc:open`/`doc:close` subscription state per socket and binary frames encoded as 16-byte document UUID plus `y-protocols/sync` message. On open/reconnect, process SyncStep1 against `doc_snapshots.state_vector` and retained `doc_updates`, return SyncStep2, and then exchange Update messages. Persist every accepted client update as a new `doc_updates` row with authenticated origin before transactional NOTIFY; fetch referenced bytes by primary key and fan out only to other sockets with that document open. Use the historical-retention boundary from #86 when a requested base is no longer retained, then recover from the retained snapshot rather than silently omitting changes. Preserve Yjs commutativity/idempotence and do not embed blob bytes in documents.

## Scope

### In scope

- Explicit doc subscriptions, binary codec, persistence/fanout, state-vector resume and compaction boundary.

### Out of scope

- Presence/Awareness, document schema/editor behavior, and non-Yjs binary files.

## Acceptance criteria

- Two subscribed clients converge after concurrent/duplicate/out-of-order updates; an unsubscribed client receives none.
- Reconnect after offline edits exchanges only the necessary Yjs diff and retains all information.
- Every accepted client update is durable before peers receive it and records authenticated origin.
