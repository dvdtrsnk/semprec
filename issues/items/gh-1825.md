**Model tier:** high

## Context

Model tier rationale: Wide declaration surface across several module manifests and catalogs plus a locale-aware resolver wired into the card read contract, where a wrong condition or missing label silently changes what every card editor shows and what confirm will later enforce.

#1417 defines how a module declares an editor schema per card base kind (groups, controls, required flags, conditions, catalog keys for labels and placeholders) and declares the one for MCP server cards. The Inbox card list (#1807) returns each card with its base kind (the kind of thing the card creates; an invalid card carries the base kind it edits). This issue completes the read side: every card in the list carries an `editorSchema`, localized for the caller, and the other base kinds declare their schemas.

Decision: the card response carries a resolved, localized schema, never catalog keys: `editorSchema: { baseKind, groups: [{ key, fields: [{ key, control, inputType?, label, placeholder?, required?, when?, timeHiddenWhen?, optionsSource?, info? }] }] }`. The locale is the caller's `users.locale` (`ctx.identity.user.locale`), resolved with `resolveCatalogLabel` and the module's catalogs as in `createTranscriptSpeakersRouteHandler` (`backend/packages/data/src/transcription/transcriptionRouteHandlers.ts`), English fallback. The schema is part of the card's additive fields, so existing clients ignore it.

Decision: step fields live in the schema of the card's base kind as pseudo fields that carry a `when` on their step switch (for example, on a task or file card, `followupTask` toggle and `followDate` with `when followupTask equals true`), matching how the card shows them; the storage of those values is the business of the multi-step proposal work and is not decided here. The pseudo field keys come from a closed list; a module added later that brings its own step adds its keys by extending that list.

Decision: a card whose base kind has no declaration gets `editorSchema: null`; an `invalid` card gets the schema of the base kind it edits (a full task schema for an invalid task card).

## Task

Load `canonical-keys`, `testing` and `io-hardening`.

1. Add `backend/packages/data/src/inbox/editorSchema.ts` with `resolveEditorSchema(registry, baseKind, locale)`: finds the declaration via `getEditorSchemas()`, loads the declaring module's catalogs (`loadModuleCatalogs`, cached like the speaker catalogs), and returns the localized shape above, with `info` rows rendered from `infoKey` and `params`.
2. Add `editorSchema` to the card envelope produced by the card list handler in `backend/packages/data/src/inbox/inboxRouteHandlers.ts` (additive field; `null` when the base kind has no declaration).
3. Declare editor schemas, in the owning module manifests, for these base kinds. Fields: Required marks are in brackets.
   - `task` (Tasks): `name` [required], `date`+time as one `datetime` field with `timeHiddenWhen allDay equals true`, `allDay` toggle, `status`, project and area relations as `select` with `optionsSource`, `followupTask` toggle and `followDate` [required, only when `followupTask` is on].
   - `event` (Events): `name` [required], `date` with start and end time hidden by `allDay`, `type` seg.
   - `project` (Projects): `name` [required], `status` seg, `date` with `when status notEquals longTerm`, `color`.
   - `area` (Areas): `name` [required], `color`.
   - `company` (Companies) and `person` (People): `name` [required]; People `contact` select and, once People has separate phone and email value fields, one shown per contact choice.
   - `file` (Files): `file` [required], `name`, `type`, `date`, `followupTask` toggle with `followDate` [required when on].
   - `health` (Health records): `name` [required], `date`, `status`.
   - `journal`: `day` [required] and the entry text [required]; `page`: `page` [required], `placement`, `heading`, and the Markdown content [required].
   The schemas go into `backend/packages/data/src/seed/systemDatabasesModuleManifest.ts` for the ten system databases and use property keys that exist today; where a key is not yet a property (all-day switch, step switches) the pseudo field key from the closed list is used.
4. Add the Czech and English label, placeholder and info catalog entries for every declared field (for example the placeholders for address, phone, "no heading") in `backend/packages/data/src/seed/i18n/cs.json` and `en.json`.
5. Tests: the task card response contains `name` required and the date field with `timeHiddenWhen` on `allDay`; locale `cs` and `en` resolve different labels; an `invalid` task card returns the task schema; an undeclared base kind returns `null`; every catalog key referenced by a declaration exists in both catalogs.

## Scope

### In scope

- Declarations for the base kinds above and the localized `editorSchema` on every card of the card list.

### Out of scope

- Enforcing required fields and conditions on confirm and edit (#1928), normalizing hidden fields on confirm (#1934).
- Option lists for `select` and `multi` fields (#1959).
- Czech names of select options (a separate catalog alignment task).
- Transcript Event and speaker cards and the recording card: not planned yet; they are added together with the design of the recording card (decided by the product owner).
- Schemas for MCP cards (declared by #1417).

## Acceptance criteria

- When the card list returns a task card, then `editorSchema` has `name` with `required: true` and a date field with `timeHiddenWhen` equal to `{ field: "allDay", equals: true }`.
- When the caller's locale is `cs`, then labels and placeholders are Czech; when `en`, English; an unknown locale falls back to English.
- When a card is `invalid` for a task, then `editorSchema.baseKind` is `task` and it contains the full task fields (including the follow-up fields).
- When a project card is returned, then the date field carries `when` hiding it for status `longTerm`.
- When a card's base kind has no declaration, then `editorSchema` is `null`.
- Every catalog key referenced by a declaration exists in both `cs.json` and `en.json`.
