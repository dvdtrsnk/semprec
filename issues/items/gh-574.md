**Blocked by:** #569

## Context

The review follow-ups pipeline (epic #565) puts its logic under `.github/scripts/review-followups/`, each module with a sibling `*.test.mjs` written with `node:test` (#569 added the first one). Nothing runs those tests today:

- the backend `verify` script (`backend/package.json`) — what every implementer runs before a pull request, and what Relay's `implement-issue` workflow runs in its `verify-backend` step — covers only the backend workspace;
- the CI `ci` job runs `.github/scripts/check-review-scope.mjs` and `pnpm run check:write-safety`, but no `.github/scripts` test.

There is a precedent for running a repository script from the backend workspace: `"check:write-safety": "node ../.github/scripts/check-write-safety.mjs"` in `backend/package.json`, which is also part of `verify`.

One trap: `node --test` given a glob that matches no file exits 0 having run nothing (verified on Node 22). A typo in the pattern, or a moved directory, would silently turn the tests into decoration. The runner therefore fails when it finds no test file.

Wiring this runner into the CI `ci` job is a separate, maintainer-implemented issue in this batch, because `.github/workflows/**` is a protected path.

## Task

1. Add `.github/scripts/run-repo-script-tests.mjs`, a zero-dependency script with a header comment explaining the zero-files trap above:
   - it takes an optional directory argument, defaulting to the `.github/scripts` directory it lives in (resolved from its own location, not the working directory);
   - it collects every file under that directory, recursively, whose name ends in `.test.mjs`, skipping `node_modules`, and sorts the paths;
   - with no file found it prints an error naming the directory and exits 1;
   - otherwise it runs `node --test` on exactly those files as a child process with inherited stdio, and exits with the child's exit code (1 if the child was killed by a signal).
2. Add `.github/scripts/run-repo-script-tests.test.mjs` (`node:test`, `node:assert/strict`) that runs the script as a child process against temporary directories it creates, covering Acceptance criteria 1–4.
3. In `backend/package.json`, add the script `"test:repo-scripts": "node ../.github/scripts/run-repo-script-tests.mjs"`, and append `&& pnpm run test:repo-scripts` to `verify` directly after `pnpm run check:write-safety`.

## Touches

- .github/scripts/run-repo-script-tests.test.mjs (new)

## Scope

### In scope

- The runner, its test, and the two `backend/package.json` script entries.

### Out of scope

- The CI step in `.github/workflows/ci.yml` — a separate, maintainer-implemented issue in this batch.
- Adding tests for existing scripts (`check-protected-paths.mjs` keeps its `--self-test`).
- Any other change to `verify` or to the backend test tiers.

## Acceptance criteria

1. Against a temporary directory with no `*.test.mjs` file, the runner exits 1 and its output names that directory.
2. Against a directory containing one passing test file in a nested subdirectory, the runner exits 0.
3. Against a directory containing one passing and one failing test file, the runner exits non-zero.
4. A file named `x.test.js` or `x.mjs` is not collected; a file under a `node_modules` subdirectory is not collected.
5. `cd backend && pnpm run test:repo-scripts` runs the tests under `.github/scripts/` (at least #569's `markers.test.mjs`) and exits 0.
6. `backend/package.json`'s `verify` runs `test:repo-scripts` directly after `check:write-safety`; no other part of `verify` changes.
