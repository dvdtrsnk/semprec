**Model tier:** medium

## Context

Model tier rationale: One known mechanism (collation on text sort keys) whose risk is keeping the ORDER BY and the keyset predicate identical, which the existing pagination fixtures verify, plus a deploy-time collation availability check.

Text sorts in `backend/packages/data/src/views/sortCompiler.ts` use the database default collation (`postgres:16-alpine`, `deploy/docker-compose.yml`) and no `COLLATE` anywhere, so Czech names do not order by the Czech alphabet ("Chalupa" belongs after "Hrad", "Řeka" after "Rybník") and equal names have no stable secondary order beyond item id. Select and group ordering was handled in #1408, which this builds on in the same file. Time-based sorting by recurrence (#1905), system timestamp sorts (#1594) and the database session zone pin (#1596) build on it.

Decision: the collation follows the caller's `users.locale`: `cs` uses `"cs-x-icu"`, any other locale `"und-x-icu"`. Decision: when the title is not itself the sort key, ties are broken by title (same collation), then by id. Decision: if ICU collations are not present in the image, create them with `CREATE COLLATION ... provider = icu` activated on deploy, following `docs/adr/2026-09-23-host-asset-dependent-database-features-activate-on-every-deploy.md`.

## Task

Load `db-migrations` and `testing`.

1. Verify that `"cs-x-icu"` and `"und-x-icu"` exist in `pg_collation` in the test database and the deploy image. If they do not, add the activation step per the ADR above (a migration or deploy activation that creates them idempotently) and document the finding in the pull request.
2. In `sortCompiler.ts`, for sort keys of type `title`, `text` and `url` apply `COLLATE "<locale collation>"` to the key expression in `ORDER BY`. The collation name is chosen from a closed allow-list (never interpolate the raw locale string). Add a secondary sort by title then id when the title is not already a key.
3. Apply the identical `COLLATE` to the comparison operators inside `compileSortKeyset` (the `>` / `<` / `=` on the key expressions), otherwise paging skips or duplicates rows.
4. Pass the caller's locale into the sort compiler: resolve `users.locale` for the actor (`backend/packages/data/src/auth/usersStore.ts`) in `genericApplicationService.ts` and thread it through the query inputs to `queryItemsCore`; background callers without a user use `und-x-icu`.
5. Tests: with locale `cs`, titles sort "Chalupa" after "Hrad" and "Řeka" after "Rybník"; equal titles tie-break by title then id; three-page keyset pagination by title returns every row once and in order; locale `en` uses the other collation.

## Scope

### In scope

- Locale-based collation and title tie-break for text sorts, in both `ORDER BY` and the keyset predicate.

### Out of scope

- Option-order sorting of selects: #1408.
- Default sort and direction per collection: #1647.
- Sorting by time of creation: #1594.

## Acceptance criteria

- When a Czech user sorts titles ascending, then "Chalupa" comes after "Hrad" and "Řeka" after "Rybník".
- When two items have the same value in the sort key, then the one with the smaller title (then id) comes first.
- When the result is paged through three pages by title, then no row is missed or repeated.
- When the user's locale is not Czech, then the neutral collation is used.
