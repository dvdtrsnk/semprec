**Blocked by:** #108

## Context

Active modules must extend the queue and heartbeat scheduler without editing core enums.

## Task

Assemble runtime task names from immutable core names plus active module descriptors and register their payload schemas/handlers with the queue. Reject core overrides and duplicates. Extend scheduler validation with the union of core and active `heartbeatRuleKinds`; dispatch module-defined next-fire calculation through `nextFireAtExport`. Rebuild these consumptions consistently when activation state changes, without accepting a heartbeat/task whose module is inactive.

## Scope

### In scope

- Task merge/registration and heartbeat rule validation/next-fire dispatch.

### Out of scope

- Queue engine implementation and service runner ownership.

## Acceptance criteria

- Active module tasks enqueue and validate typed payloads.
- Conflicting task names fail deterministically.
- Module rule kinds schedule through their exported calculator.
- Deactivated rule/task definitions cannot be newly dispatched.
