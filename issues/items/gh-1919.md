**Model tier:** medium

## Context

Model tier rationale: A read-side extension of one existing endpoint with a localized title renderer keyed by problem kind, over existing fixtures and no writes, but the title table is wide and needs source lookups in batches.

The Semp status view has a collapsed section "Resolved in the last 7 days" with a count, listing lines such as "Gmail mailbox is syncing again" or "Task 'Client meeting summary' completed", newest first. Problems close through #1915 and through the producers of mailbox, transcription and reply problems; the stored problem keeps `resolved_at` and `resolution_kind` (#1459). Today the status endpoint (#1555) returns active problems only.

This issue adds `resolvedRecent` to `GET /api/semp-status`: problems whose `resolved_at` is within the last seven days, each with a localized `resolutionTitle`. The text is rendered at read time from the kind and the resolution kind with names read from the source (mailbox name, thread title, project name, transcript name), so the database holds no user text. #1945 adds the transcription titles.

Decision: titles are keyed by problem kind and resolution kind. The initial catalog (Czech and English): mail sync recovered ("Mailbox {mailbox} is syncing again"), reply recovered ("Task '{title}' completed"), heartbeat recovered ("Automatic task '{name}' ran successfully"), guidance drift resolved ("Instructions of project {project} match the permissions again", and for behavioral findings "Instructions of project {project} match what Semp does again"; the variant is read from the finding referenced by the problem), restore test passed ("Monthly backup restore test passed"), process recovered ("Semp is running again"), library automation recovered ("Automation of {database} works again"). A name that cannot be read (deleted source) is replaced by a neutral word, never left empty.

Decision: problems resolved with `sourceDeleted` are not returned. The list is capped at the 100 newest.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. In `backend/packages/data/src/semp/sempStatusReport.ts` (introduced by #1555) add `resolvedRecent`: `[{ id, category, resolutionTitle, resolvedAt }]`, ordered by `resolved_at` descending, for problems of the current tenant resolved in the last seven days with a resolution kind other than `sourceDeleted`.
2. Add the resolution title catalog to the status i18n files (`backend/packages/data/src/semp/i18n/status.cs.json`, `status.en.json`) and a renderer taking `(kind, resolutionKind, params, locale)`; fetch the names for all rows in batched queries.
3. Add an index on (`tenant_id`, `resolved_at`) for resolved rows if the listing needs it, in a migration `backend/packages/data/src/db/migrations/NNNN_semp_problems_resolved_idx.sql` (next free ordinal at commit time).
4. Tests: a problem resolved three days ago is returned with a localized title, one resolved eight days ago is not; the order is newest first; a `sourceDeleted` resolution is not returned; a problem that was resolved and then raised again appears in both lists with different ids; another tenant's problems are not returned; names are read in a constant number of queries.

## Scope

### In scope

- `resolvedRecent` in the status response with localized resolution titles, seven-day window and ordering.

### Out of scope

- Resolving problems (#1915 and the producers) and pruning after thirty days (#1558).
- The titles for transcription problems (#1945).
- Positive events that are not recoveries from a problem.
- The active problems and services parts of the response (#1555, #1561).

## Acceptance criteria

- When a mailbox problem is resolved by a successful sync, then it is absent from the active list and present in `resolvedRecent` with the title naming the mailbox.
- When a problem was resolved more than seven days ago, then it is not returned.
- When several problems are resolved, then the newest is first.
- When a problem was closed because its source was deleted, then it is not listed.
- When the tenant's user locale is Czech, then titles are Czech; no other tenant's problem is returned.
