## Context

Model tier rationale: A read-only aggregation route with an existing route pattern and tenant-isolation harness, but it composes six owners' functions across modules and must not add its own SQL.

The profile screen shows a count beside several rows: signed-in devices, e-mail accounts (with the names of the accounts that need to sign in again), recently deleted items and databases, problems reported by Semp, and this month's AI spend. Without one route the client would make five separate calls on every profile open. This issue adds `GET /api/account/summary`, a lightweight aggregate that only reads figures from the modules that own them.

Decision: the route stays separate from the overview route even though both expose a problem count; each serves one screen, and both read the same owner function so the numbers cannot diverge.

Today the account routes (`export`, `list exports`, `delete`) are in `createAccountRoutes` in `backend/services/semprec-api/src/accountHandler.ts`; routes are classified in `backend/services/semprec-api/src/routeMatrix.ts`; the handler-file mapping lives in `ROUTE_HANDLER_FILES` in `backend/services/semprec-api/src/__tests__/chokePointWriteBoundary.unit.test.ts`; isolation is proven in `backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts`. The AI usage report today is `GET /api/ai-usage` (`data/aiGateway/aiUsageReport.ts`); the spend that the gateway compares with the limit comes from #1456.

The figures come from these blockers, whose pull requests give the exact exported function names:
- active session count: #1583;
- mail account count and accounts needing sign-in again: #1688;
- trashed root items count and archived databases count: #1851 and #1873;
- active problem count: #1631;
- month-to-date AI cost in USD: #1456.

Shared-file ordering: this issue also waits for #1900 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `testing`.

1. Add `GET /api/account/summary` to `createAccountRoutes`. Response 200:
   `{ activeSessions: number, mailAccountCount: number, mailAccountsNeedingReauth: [{ id: string, name: string }], trashItems: number, trashDatabases: number, problemCount: number, aiCostMonthUsd: number }`.
2. Each field is the value returned by the owning module's server function listed above (the same functions their routes call), with `activeSessions` counted for the caller's own user, `trashItems` and `trashDatabases` taken from the totals of the two trash listings, `problemCount` the active count of the Semp status summary, and `aiCostMonthUsd` the month-to-date spend of the AI usage summary. Write no SQL of its own in this route; if an owner exposes only an HTTP-shaped function, call its underlying store function.
3. Run the independent reads concurrently on the request's tenant-scoped connection or pool as the neighboring routes do; the response is a single consistent JSON object with no partial results (an owner failure fails the request through the normal error path).
4. Register in `routeMatrix.ts` as `{ name: "account summary", method: "GET", path: "/api/account/summary", surface: "api", public: false, tenancy: "tenant" }`, add the entry to `ROUTE_HANDLER_FILES`, and add the isolation case to `tenantIsolationRoutes.test.ts`.
5. Tests: with 4 active and 1 revoked session, 5 trashed root items and 2 archived non-system databases the response has `activeSessions: 4`, `trashItems: 5`, `trashDatabases: 2`; `problemCount`, `aiCostMonthUsd` and the mail fields equal the values from the owners' own routes for the same data; an account that needs sign-in again appears in `mailAccountsNeedingReauth` with its name.

## Scope

### In scope

- The single read-only aggregate route and its tests.

### Out of scope

- The owners' own functions and routes (sessions, mail summary, trash listings, Semp status summary, AI usage summary); they come from the blockers.
- Any realtime invalidation of the summary.
- A time-zone row in the profile.
- Merging this route with the overview route.

## Acceptance criteria

- When the caller has 4 active sessions and 1 revoked one, 5 trashed root items and 2 archived non-system databases, then the response has `activeSessions: 4`, `trashItems: 5`, `trashDatabases: 2`.
- When data exists for problems, AI spend and mail, then `problemCount`, `aiCostMonthUsd`, `mailAccountCount` and `mailAccountsNeedingReauth` equal the values the Semp status, AI usage and mail summary owners return for the same tenant.
- When a second tenant has its own sessions, trash and accounts, then none of them affect the first tenant's response, and the isolation test covers the route.
- An unauthenticated request is rejected as for every other non-public route.
- The full backend `pnpm run verify` passes.
