## Task

Load `ai-gateway`, `io-hardening`, `error-handling`, `state-writes` and `testing`.

1. Implement the `VoiceSessionHandler` from #1546 in `semprec-api`: on `start`, open a speech-to-text stream through the gateway client; forward audio frames; relay partial and final transcripts to the client as `transcript` messages.
2. On each final transcript, create the thread message (and the thread, when none exists) through the #1620 code path with source `voice`, in the session's tenant and as the session's user. If the message store has no field for the origin of a message, add one in a migration.
3. After the message is queued, subscribe the session to that turn's run deltas (reuse the agent run watch from the realtime package), build sentences, and stream each to text-to-speech; forward audio frames in order with `speaking` start and end messages.
4. Handle barge-in: when speech-to-text reports new speech while audio is playing, stop playback (abort the synthesis request, drop queued sentences) and send `speaking` end; keep the agent turn running.
5. Handle failure and teardown: abort both streams on socket close or error; ensure no `ai_gateway_calls` row stays `reserved`; map gateway budget and capacity errors to `error` messages; never log transcripts, answer text or audio.
6. Tests with fake gateway streams: a spoken question yields partials, a final transcript, a thread message with source `voice` and speech output of the answer; a first transcript without a thread creates one; barge-in stops audio but not the turn; a second question during an answer waits in the queue; budget exhaustion ends the session with `budgetExceeded`; an approval request created in a voice turn appears as the usual card in the thread; closing the socket releases all streams.

## Scope

### In scope

- Speech-to-text to thread message, deltas to sentences to speech, barge-in, teardown and budget error handling.

### Out of scope

- The gateway streaming adapters: #1396 and #1399.
- The channel, its authentication and limits: #1546.
- Read-aloud of a stored message: #1626. Dictation into the message field runs on the device (#1372).
- Cancelling the running agent turn by an explicit voice stop command: #2019, which builds on this one.
- Attributing the speech calls of a voice session to the thread turn and run they serve: #2020, which builds on this one.

## Acceptance criteria

- When the user speaks a question, then partial transcripts stream to the client and the final transcript is stored as a message of the thread; from a new chat a thread is created.
- When the answer is generated, then speech begins before the whole answer exists.
- When the user speaks over the answer, then the audio stops and the turn keeps running.
- When the tenant budget is exhausted, then the session ends with `budgetExceeded`.
- When an action needs approval, then the approval card appears in the thread as for a typed message.
- When the socket closes, then no gateway stream or reservation is left open.
