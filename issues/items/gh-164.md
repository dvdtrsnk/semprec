**Blocked by:** #242, #163

## Context

Issue #242 made the server deterministic: dead connections are detected by ping/pong, LISTEN outages and shutdowns close every socket with 1012, and slow consumers are closed with 1013. Reconnect is therefore a normal operating state (a phone in a tunnel, a laptop waking up, a deploy), not an exception. This final slice of the batch implements the client side: reconnect with backoff and jitter, followed by every stream's own recovery path, and the end-to-end fault scenarios proving the whole protocol converges.

## Task

Implement the client reconnect and recovery contract for the `WS /api/sync` client:

- **Reconnect**: after a drop, reconnect with exponential backoff plus jitter, from 1 second up to a 30-second ceiling.
- **Per-stream recovery on every successful reconnect** — no universal cursor, each stream its own path:
  - Invalidations: the client holds the single "connection was interrupted" flag from #161 and refetches what it displays through REST (re-run the query for active views, keyset and bounded; `GET` the open item) before it starts trusting new invalidations.
  - Notifications: one-time fetch of unread rows (`read_at IS NULL`).
  - Yjs docs: send `SyncStep1` for each open document and receive exactly the missing diff.
  - Agent stream: `agent:watch` from the last known `eventId` (`afterEventId`).
- **Client-side fault scenarios**: network drop and reconnect, plus end-to-end runs against the server faults from #242 (LISTEN loss, deploy shutdown, slow consumer), each ending with REST, Yjs, agent events, and unread state converged.

## Scope

### In scope

- Reconnect/backoff/jitter, per-stream recovery orchestration, and client-side plus end-to-end fault-injection tests.

### Out of scope

- Server-side ping/pong, 1012/1013 closure, frame/subscription limits, coalescing — delivered by #242.
- Replaying missed NOTIFY events, per-type selective dropping, realtime metrics/alerting, or connection caps per session.

## Acceptance criteria

- Fault-injection tests for network drop, LISTEN loss, deploy shutdown, slow consumer, and reconnect end with REST/Yjs/events/unread state converged.
- Reconnect delays grow exponentially with jitter from 1 s and never exceed the 30 s ceiling.
- After reconnect, no new invalidation is applied before the active-state refetch completes, and each open doc and watched run resumes from its own cursor without duplicated or missing information.
