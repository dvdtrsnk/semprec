## Context

Model tier rationale: It connects the sync job to tenant-chosen IMAP hosts with decrypted passwords, so the address-checked connection, connection-limit handling, and resource cleanup must all be correct to avoid leaking sockets or reaching internal hosts.

After #1508, `backend/services/semprec-api/src/mailSyncAdapters.ts` provides the Gmail and Graph members of `MailSyncAdapterFactory`. IMAP-mode accounts (iCloud, any other IMAP provider) still get "No IMAP adapter configured". `createImapClient(mailboxItemId, credential)` must return a connected `ImapMailClient` (`ImapFlowMailClient` in `mail/imapFlowClient.ts`). The host, port, security and username come from `mail_account_server_settings` (#1473); the password is the decrypted credential the sync job passes in; the connection is opened by the address-checked factory from #1478, which maps refused and unreachable hosts to `mail_server_unreachable`.

`mailSyncJob.ts` already limits simultaneous connections per mailbox (`imapConnectionLimiter.ts`) and expects the factory to turn a provider's "too many connections" rejection into `MailConnectionLimitError` (`isImapConnectionLimitError` in `imapFlowClient.ts` documents this) so the job backs off instead of retrying at once. The IMAP IDLE transport (#1550), the app route that connects a password mailbox (#1736) and mail moves (#1746) build on this.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. In `mailSyncAdapters.ts` add `createImapClient(mailboxItemId, credential)`: read the settings with `getMailServerSettings`; when there are none, throw a clear configuration error that names the mailbox (not the password); open the connection with `openImapConnection` (#1478) using the stored host, port, security and username and the credential as the password; return the wrapped client.
2. When the connection attempt fails: `isImapConnectionLimitError` leads to `MailConnectionLimitError`; an authentication failure leads to `MailReauthorizationRequiredError`; an address refusal or unreachable host surfaces as `MailServerUnreachableError`.
3. The connection must be closed when the sync pass ends, success or failure. If `ImapMailClient` has no close operation, add `close()` to the interface and `ImapFlowMailClient` (logout then close quietly) and call it from the sync job in a `finally` around the reconcile pass; the pass must not leak sockets when it throws.
4. Passwords never appear in errors, logs or the stored `last_error`.
5. Tests with a local fake IMAP server (loopback allowed through the test seam): a pass ingests messages; a host resolving to an internal address is refused as unreachable (no connection made); server "Too many simultaneous connections" produces `MailConnectionLimitError`; bad credentials produce `needsReauthorization`; the socket is closed after both a successful and a failing pass; missing settings produce the configuration error.

## Acceptance criteria

- When an IMAP-mode account has stored settings and a valid password, then a sync pass downloads its mail.
- When the host resolves to 127.0.0.1 or a 10.x address, then no connection is made and the failure is reported as an unreachable server, indistinguishable from a closed port.
- When the server rejects the login, then the account is marked as needing reauthorization.
- When the server reports too many simultaneous connections, then the job backs off through `MailConnectionLimitError`.
- When a pass ends or throws, then the IMAP socket is closed.
- When logs and stored errors are inspected, then no password appears.
