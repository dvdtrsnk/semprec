**Blocked by:** #663

## Context

Review follow-ups harvested in #728. Four integration/unit test files in `backend/packages/data/src/__tests__/` carry dead code, a duplicated helper, or a pool leak:

- PR #301 — `migrate.test.ts:18`: `withScratchSchema` runs `adminPool.query(CREATE SCHEMA ...)` before the `try/finally` that calls `adminPool.end()` (lines 23-29), so a throw from `CREATE SCHEMA` leaks `adminPool`.
- PR #307 — `moduleDataMigration.test.ts:166`: the "is a no-op once the transition is already recorded" test destructures `databaseId` (line 150) only to suppress it with `void databaseId;`.
- PR #314 — `moduleRegistryDeactivation.test.ts:11` and `moduleRegistryLoadAll.unit.test.ts:25` each define the identical helper `function manifestPath(fileName) { return new URL(\`../${fileName}\`, import.meta.url).href; }`.
- PR #317 — `relations.test.ts:387`: `assertOwnerViolation` first awaits `expect(promise).rejects.toBeInstanceOf(ForbiddenError)`, then re-awaits the already-rejected promise inside a `try`, so `expect.unreachable(...)` can never run.

Issue #663 edits `moduleDataMigration.test.ts`; this issue starts from that file as #663 leaves it.

## Task

Tests only; no production code changes.

1. `migrate.test.ts`: restructure `withScratchSchema` so `adminPool.end()` runs whether or not `CREATE SCHEMA` succeeds — the outer `try/finally` that ends `adminPool` encloses the `CREATE SCHEMA` call; the `DROP SCHEMA` still runs only after the schema was created.
2. `moduleDataMigration.test.ts`: in the no-op test, stop destructuring `databaseId` from `seedDatabaseWithItems(2)` and delete the `void databaseId;` line.
3. Move `manifestPath` into a new module `backend/packages/data/src/testSupport/moduleManifestPath.ts` exporting `manifestPath(fileName: string): string`, resolving `fileName` against `backend/packages/data/src/` exactly as the current helper does. The module imports nothing that touches Postgres. Replace the local definitions in `moduleRegistryDeactivation.test.ts` and `moduleRegistryLoadAll.unit.test.ts` with an import of it.
4. `relations.test.ts`: replace the `try { await promise; expect.unreachable(...) } catch ...` block in `assertOwnerViolation` with a single assertion on the rejection — `await expect(promise).rejects.toMatchObject({ code: "owner_violation" })` — keeping the `toBeInstanceOf(ForbiddenError)` assertion.
