## Behavior specification

1. Generic relations enforce property ownership, declared cardinality, endpoint existence, endpoint database compatibility, and atomic creation of locked relation properties.
2. Archived databases reject every item mutation until restored.
3. Floating heartbeats derive their next occurrence from the action's actual execution time, while fixed calendar rules retain calendar anchoring and the sweep retains its row-lock guarantee.
4. The generated permission manifest is semantically compared with the project's hand-written agent guidance and actionable mismatches produce drift notifications.
5. Every document version inside the configured retention window remains reconstructible after any number of Yjs compactions.
6. Agent-created views retain the concrete creator identity; only that agent can mutate them until a user adopts the view.
7. The library-grid client renders blob covers and deterministic fallbacks and creates items through the generic item endpoint.
8. Agents and MCP callers receive the generic CRUD/query catalog through adapters over the same authenticated choke-point surface, with no second write path.
9. Mail search parses read/unread/flagged operators as structured predicates instead of feeding them to full-text search.
10. A concrete long-lived composition root starts graphile-worker with the core crontab and merged task handlers and shuts it down cleanly.

## Decisions

- Question: Should already-planned gaps be duplicated? Adopted answer: no. Existing issues #29, #37, #38, #40, #72, and #73 remain authoritative for their current scope. Reason: duplicate independently dispatchable specs would create competing implementations.
- Question: What counts as a severe audit gap? Adopted answer: the critical and high findings from the implementation audit, including the remaining structured mail-search portion not actually owned by #72. Reason: lower-severity library substitutions and literal DDL deviations do not justify autonomous implementation tickets here.
- Question: How should implementation be ordered? Adopted answer: one strictly sequential batch even when some fixes are logically independent. Reason: the repository dispatcher deliberately integrates one issue at a time.
- Question: What identity owns an AI-created view? Adopted answer: the concrete project agent identity supplied by the agent runtime, not the generic `ai_agent` enum value. Reason: the current enum cannot enforce "created by this agent".
- Question: Should historical-version reads be allowed to fail after compaction? Adopted answer: no, not for timestamps inside retention. Reason: retained version history is only useful if every retained timestamp can be reconstructed.
- Question: Which existing issue owns starting the core queue runtime? Adopted answer: none; #29 registers tasks and #40 provisions processes, but neither identifies a composition root that calls `run()` with `CORE_CRONTAB`. Reason: cron constants without a running worker never execute.
- Question: Which side is "one" for `one_to_many`? Adopted answer: normalized `property_id_a`/`item_a` is the one side; calls through the inverse property are reversed into that representation. Reason: constraints need one stable directional definition.
- Question: What is a floating heartbeat's execution time? Adopted answer: the first handler-attempt start persisted in a distinct occurrence row; retries reuse it. Reason: queue delay must count, retry delay must not reschedule repeatedly.
- Question: How is retained Yjs history represented? Adopted answer: mirror each update into a time-retained history log with checkpoint update-id boundaries; current compaction may delete only the current log. Reason: a checkpoint without its intermediate deltas cannot reconstruct arbitrary timestamps.
- Question: Which identity owns an AI view? Adopted answer: `creator_project_item_id`, derived from authenticated runtime context. Reason: project identity is stable across runs, unlike `agent_run.id`.
- Question: What do absent mail flags mean? Adopted answer: absent `read` means unread and absent `flagged` means unflagged. Reason: it preserves observable legacy behavior and makes all four operators total.
- Question: Which process runs core graphile-worker? Adopted answer: `semprec-api`, through `services/semprec-api/src/queueRuntime.ts`, exactly once. Reason: it is the always-on composition root already owning the shared application pool and lifecycle.
- Question: How are pre-fix Yjs documents handled? Adopted answer: migration creates a current-state cutover checkpoint and advertises history only from that timestamp; older requests return `history_not_retained`. Reason: updates deleted by past compactions cannot be reconstructed honestly.
- Question: What establishes the first web client? Adopted answer: the library-grid issue initializes a minimal React 19, TypeScript, and Vite package plus only the shared component/API/i18n foundations it consumes. Reason: no earlier issue selects a web framework, but the audited UI behavior must become implementable without inventing unrelated screens.
- Question: How do drift findings notify users? Adopted answer: wait for #36 and use its canonical transactional notification writer and fanout, with active/resolved kinds. Reason: writing against the temporary #21 table would bypass the final notification contract.
