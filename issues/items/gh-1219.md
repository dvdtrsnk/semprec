## Context

Model tier rationale: One existing integration assertion races asynchronous PostgreSQL session cleanup; the intended behavior and a bounded observation are explicit.

While unblocking the repository's PRs, backend verification and an isolated rerun both failed `tenantPurge.test.ts > destroys the lock connection when the unlock fails, so the purge lock does not leak`: the immediate `purgeLockIsFree` probe returned false. The test already confirms that the dedicated pooled client is released with an Error, which destroys the connection. PostgreSQL releases its session advisory locks when it processes that connection's closure, asynchronously to the JavaScript release call. An immediate probe can therefore race the correct cleanup.

## Task

1. In that test only, replace the immediate free-lock assertion with a bounded asynchronous poll (up to 5 seconds) of the existing `purgeLockIsFree` helper. Keep the assertion that release receives an Error, the expected unlock-failure log, and the tombstone assertion.
2. Prove the test still detects a leaked lock: temporarily return the lock connection to the pool alive instead of destroying it and confirm that the bounded assertion fails; revert the temporary production mutation before committing.
3. Run the tenant-purge integration suite and the backend/web verification pipelines.
