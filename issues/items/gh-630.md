## Context

`MIN_PASSWORD_LENGTH = 8` in `backend/packages/data/src/auth/authActions.ts` (line 35, a non-exported `const`) is enforced only by `createAccount` (lines 52-54), i.e. only through `POST /api/setup`. The password-reset consume path does not enforce it: `backend/services/semprec-api/src/authHandler.ts`, `POST /api/auth/password-reset/consume` branch, checks only that `newPassword` is a non-empty string (lines 205-207), and `resetPassword` in `backend/packages/data/src/auth/passwordResetActions.ts` (lines 118-132) hashes whatever it is given (line 129). A one-character password is accepted as the account's new password.

Sibling B5 of this batch edits `requestPasswordReset` in the same file; this issue edits `resetPassword` only.

## Task

- In `authActions.ts`, export the constant: `export const MIN_PASSWORD_LENGTH = 8;` (it is then available from `@semprec/data` through the existing `export * from "./auth/authActions.js"` barrel line — no barrel edit). Keep its docstring.
- In `passwordResetActions.ts`, `resetPassword`: import `MIN_PASSWORD_LENGTH` from `./authActions.js` and, **before** `consumePasswordResetToken` runs, throw `new ValidationError(\`'newPassword' must be at least ${MIN_PASSWORD_LENGTH} characters\`, { field: "newPassword" })` when `input.newPassword.length < MIN_PASSWORD_LENGTH`. The check runs first so a rejected password does not consume the single-use token (the guard runs before the write — `docs/adr/2026-09-10-side-effects-follow-the-commit.md`'s ordering rule); say so in the docstring. `ValidationError` is exported by `../errors.js`, which the file already imports `PasswordResetTokenError` from.
- The HTTP handler needs no change: `ValidationError` is a `ChokePointError` and the handler's `catch` already answers it as 400 `validation_failed`.
- Tests:
  - `backend/packages/data/src/__tests__/passwordResetActions.test.ts`, inside `describe("resetPassword")` (integration tier): a 7-character `newPassword` rejects with `ValidationError`; the same token then succeeds with an 8-character password (proving it was not consumed).
  - `backend/services/semprec-api/src/__tests__/authHandler.test.ts`, inside `describe("POST /api/auth/password-reset/consume")`: `newPassword: "short"` → 400 with `code: "validation_failed"`; a second consume with the same token and a valid password → 200.

## Scope

### In scope

- Enforcing `MIN_PASSWORD_LENGTH` in `resetPassword` for every caller.

### Out of scope

- `requestPasswordReset` and the reset mail's send timing — sibling issue B5 of this batch.
- Any additional password-complexity rule (the constant's docstring records the NIST SP 800-63B decision to impose none).
- The `POST /api/auth/login` branch of the handler — siblings B1 and B2.

## Acceptance criteria

- When `POST /api/auth/password-reset/consume` is called with a valid token and a `newPassword` shorter than 8 characters, the response is 400 with `code: "validation_failed"`, and the token is still unconsumed: a following consume with the same token and a valid password is answered 200.
- When `resetPassword` is called directly with a short password, it throws `ValidationError` before `password_reset_tokens.consumed_at` is set.
- `MIN_PASSWORD_LENGTH` is importable from `@semprec/data`; `createAccount`'s behaviour is unchanged.
