## Context

Model tier rationale: Changes the lifecycle of an existing aggregate: switching mail off must stop live sync and remove mail data atomically without touching the credential, under existing removal lock orders.

The Mailboxes item is the account (epic decision). Today mail sync always runs for every mailbox and removal deletes everything. This issue adds the service switches and the mail-off and mail-on behaviour; calendars are synced by later issues of this batch, which read `calendarsEnabled`.

Decision: `mailEnabled` defaults to true and `calendarsEnabled` to false for every existing and new mailbox.
Decision: an account may have both services off; it keeps its sign-in and stays until the user removes it.
Decision: the user-facing label of the Mailboxes database and the Overview row become "Internet accounts" / "Internetové účty"; keys stay.

## Task

Load `state-writes`, `db-migrations`, `error-handling`, `io-hardening`, `canonical-keys` and `testing`.

1. Add to the Mailboxes database (seed in `seed/seedEmailModule.ts`, baseline still editable) two user-owned checkbox properties `mailEnabled` (default true) and `calendarsEnabled` (default false), with en/cs labels.
2. Add an update hook in the mail module: when `mailEnabled` changes from true to false, in the same transaction mark the account's mail sync state inactive (`sync_paused_at` column on `mail_account_sync_state`), enqueue the existing chunked member cleanup used by mailbox removal for the account's Folders, Emails and Threads (not the item, credential or server settings), and after commit stop the account's live sync through `mailLiveSyncControl`. When it changes from false to true, clear `sync_paused_at` and enqueue `mailAccountSync` in the same transaction.
3. Make `mailAccountSync`, `mailAccountSyncSweep`, live sync discovery, send and draft send skip or refuse (`mail_disabled`) an account with `sync_paused_at` set.
4. Expose `mailEnabled` and `calendarsEnabled` in the `GET /api/mail/mailboxes` and `/:id` rows.
5. Rename the Mailboxes database label and the account summary copy to "Internet accounts" / "Internetové účty" in `mail/i18n` and the account summary i18n.
6. Update `docs/architecture/domain-mail-and-inbox.md` (Mailboxes and connections) with the switches and the mail-off lifecycle.

## Scope

### In scope

- The two switches, the mail-off and mail-on lifecycle and the label.

### Out of scope

- Calendar sync for `calendarsEnabled` (later issues of this batch).
- OAuth scopes for calendars (the OAuth issue of this batch).
- Client screens (the mobile issues of this batch).

## Acceptance criteria

- When Mail is switched off, then no mail sync job, IDLE connection, Gmail watch or Graph subscription runs for the account, its folders, e-mails and threads are removed, and its credential, server settings and item remain.
- When Mail is switched on again, then a sync job is queued in the same transaction and mail downloads as for a new account.
- When Mail is off, then sending a draft from the account answers `mail_disabled` and sends nothing.
- Existing mailboxes read `mailEnabled: true` and `calendarsEnabled: false`.
- The removal of an account still removes everything, including its switches.
