## Context

Model tier rationale: Changes the outcome of one route's post-commit step from an error to a logged failure behind a committed success, matching the password replacement.

Found in the end-to-end test campaign after PR #2089. `POST /api/mail/mailboxes/oauth/complete` for a reauthorization state (`createMailOauthCompleteRouteHandler`, `mail/mailOauthRouteHandlers.ts`) commits `replaceMailboxCredential` (new refresh token, granted scopes, cleared calendar refusal, queued syncs) and then awaits `mailLiveSync.restartAccount`. When the restart rejects, the route answers 500 although the new credential is in effect; the client shows a failed sign-in and the user signs in again for nothing. `PUT /api/mail/mailboxes/:id/password` already logs the same failure (`mailboxItemId`, `errorName`) and answers 200.

Every other route was checked for an awaited post-commit live-sync restart: the OAuth and password connect routes start nothing (discovery hosts a new account), Mail on only queues a pass (discovery hosts it again), Mail off stops the live sync in `runAfterCommit` and logs a failure, the Calendars switch only writes and queues jobs inside the update's transaction, and the removal cleanup's `liveSyncStop` step is time-limited and logged. Only the OAuth reauthorization has the defect.

Decision: a failed restart is logged (`mailboxItemId`, `errorName`, no message) and the route answers 200 with `{ mailboxId }`. The queued pass reads the new token; the hosted lifecycle picks it up at its next reconnect.
