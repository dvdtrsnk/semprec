**Model tier:** low

## Context

Model tier rationale: Adds one localized field to cards the list already builds, reusing the stored reason and the renderer of a blocker, in one read-model file and two catalog files, with no new storage or lifecycle.

A proposal card becomes `invalid` when it can no longer be used. #1482 stores a structured `invalidReason` (`{ code, field, itemId, label }`, codes `sourceDeleted`, `targetArchived`, `targetDeleted`) and adds `renderInvalidReason(reason, locale)` in `backend/packages/data/src/inbox/invalidReason.ts`, which renders the localized sentence; #1916 writes the target-side reasons. The card list `GET /api/inbox/cards` (#1807) returns invalid cards with `cardKind` `invalid`, but without the reason. The product owner decided that the card list shows a short reason, so the user knows why a card cannot be confirmed and the behavior stays predictable.

Decision: every card with status `invalid` carries `invalidReason: { code, field, itemId, label, text }`, where `text` is `renderInvalidReason` in the locale the list already uses for its labels (English fallback). A legacy invalid card without a stored reason carries `{ code: "unknown", field: "", itemId: null, label: "", text }` with a generic localized sentence that the proposal can no longer be used. Cards in other statuses carry no `invalidReason`.

## Task

Load `canonical-keys` and `testing`.

1. In `backend/packages/data/src/inbox/inboxCardsStore.ts`, for each `invalid` card parse the stored `invalidReason` with the schema exported by #1482 and add the field as decided, rendering `text` with `renderInvalidReason`.
2. Add the catalog entry for the generic sentence (`invalidReason.unknown`) to `backend/packages/data/src/inbox/i18n/en.json` and `cs.json`.
3. Tests: an invalid card with `targetArchived` returns the code, field, label and the localized `text` containing the label, in Czech and English; a legacy invalid card without a reason returns code `unknown` and the generic sentence; a `proposed` card has no `invalidReason`.

## Scope

### In scope

- The localized invalid reason on invalid cards of the card list.

### Out of scope

- Storing and rendering the reason (#1482) and writing the target-side reasons (#1916).
- Reasons on other read paths (`GET /api/items/:id`).

## Acceptance criteria

- Given an invalid task card whose project was archived, when `GET /api/inbox/cards` is read by a Czech user, then the card carries `invalidReason` with `code` `targetArchived`, `field` `project`, the project's label and a Czech `text` naming it; for an English user the `text` is English.
- Given a legacy invalid card without a stored reason, then its `invalidReason.code` is `unknown` and `text` is the generic localized sentence.
- A card that is not `invalid` carries no `invalidReason`.
