## Context

`backend/packages/data/src/__tests__/chokePoint.test.ts` (~710 lines) tests every domain of the old monolithic choke point in one file. The domains now live in separate modules (#507, #508, #511–#515), so each module should have a test file whose name says what it covers.

## Task

Move every test case out of `chokePoint.test.ts` into these new integration-tier files in the same directory, then delete `chokePoint.test.ts`:
- `databaseOps.test.ts`
- `propertyOps.test.ts`
- `relationPropertyOps.test.ts`
- `relationOps.test.ts`
- `itemWrites.test.ts`
- `itemReads.test.ts`
- `itemTrash.test.ts`

Assign each `it` to the file of the module that owns the method it primarily exercises: the method named in its title, or the first choke-point call its assertions depend on. Examples:
- the `findPropertiesByKey` block goes to `propertyOps.test.ts`;
- the `findItem` and `getItemPath` blocks go to `itemReads.test.ts`;
- the `item trash` block goes to `itemTrash.test.ts`;
- "relation mutations are rejected once either side's database is archived" goes to `relationOps.test.ts`;
- "creating and updating an item in an archived database is rejected" goes to `itemWrites.test.ts`.

Duplicate the shared `beforeEach` / setup helpers into each file that needs them. Test bodies and titles stay verbatim. `docs/adr/2026-09-11-iterative-parent-chain-traversal-in-choke-point.md` names "the cycle test in `chokePoint.test.ts`": list its new location (`itemReads.test.ts`) in the pull request description. The ADR body itself is not edited; the "where things moved" table in `docs/adr/2026-09-24-choke-point-composed-from-domain-modules.md` covers production code only.

## Touches

- backend/packages/data/src/__tests__/chokePoint.test.ts (deleted)
- backend/packages/data/src/__tests__/databaseOps.test.ts, propertyOps.test.ts, relationPropertyOps.test.ts, relationOps.test.ts, itemWrites.test.ts, itemReads.test.ts, itemTrash.test.ts (new files)

## Scope

### In scope
- Moving the tests and their setup.

### Out of scope
- Changing any assertion or adding tests.
- Splitting any other test file (`views.test.ts`, `relations.test.ts`, …).

## Acceptance criteria

- `pnpm run verify` in `backend/` passes.
- The set of test titles (`describe` + `it` paths flattened to the `it` title) across the seven new files equals the set in the deleted `chokePoint.test.ts`, with no title lost or duplicated. State the count in the pull request description.
- No `it` body differs from its original apart from indentation, which `git diff --color-moved` shows.
