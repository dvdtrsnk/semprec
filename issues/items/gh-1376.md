## Context

Model tier rationale: Two additive fields on an existing read model in one file, with no new route, table or authorization path.

`GET /api/ai-usage?from&to` (custom route in `backend/packages/data/src/chokePoint/schemaCoreModuleManifest.ts`, handler `backend/packages/data/src/aiGateway/aiUsageRouteHandler.ts`, report in `backend/packages/data/src/aiGateway/aiUsageReport.ts`) returns `rows`, `totalCostUsd`, `dailyCostUsd`, `dailyTokenUsage` and `budgets` for a range of at most 366 days, with days cut in the tenant's time zone from `getSystemTimezone`. A client cannot tell from the response when the account started, which it needs to offer "all time" and the list of months since the account began, and it does not receive the time zone that the days and months are cut in.

This issue adds the two facts. #1462 then builds the monthly series on `accountStartedAt`. The existing web page reads this endpoint, so every change is additive.

Decision: the account start is the earlier of the tenant's oldest user and the tenant's first AI call. The original tenant's `created_at` is the time of the tenancy migration, not the real start, so it is not used.

## Task

Load `testing`.

1. In `aiUsageReport.ts`, extend `AiUsageReport` with `accountStartedAt` (ISO 8601 string) and `timezone` (the IANA name already read by `getSystemTimezone`).
2. `accountStartedAt` is the minimum of `MIN(users.created_at)` over the users of the current tenant (`WHERE tenant_id = app_tenant_default()`) and `MIN(ai_gateway_calls.at)` of the current tenant (row-level security already limits the calls). When both are empty, fall back to the report's `from`, so the field is never null.
3. Extend `backend/packages/data/src/aiGateway/__tests__/aiUsageRouteHandler.test.ts` (or add `aiUsageReport.test.ts` next to it) with the cases below.

## Scope

### In scope

- The `accountStartedAt` and `timezone` fields on the existing response.

### Out of scope

- The monthly series and the `granularity` parameter: #1462.
- Any change to the existing fields, the range limit or the route registration.

## Acceptance criteria

- When the tenant's first AI call is older than its oldest user, then `accountStartedAt` is the time of that call.
- When the oldest user is older than any AI call, or there is no AI call, then `accountStartedAt` is that user's `created_at`.
- When the tenant's time zone setting changes, then `timezone` reflects it.
- Another tenant's users and calls never influence `accountStartedAt`.
- All previously returned fields are unchanged for the same input.
