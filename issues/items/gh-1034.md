**Blocked by:** #1025, #1033
**Model tier:** high

## Context

Model tier rationale: DNS rebinding protection, address classification and connect-time enforcement introduce a network mechanism across two transports.

Two features send server-side requests to user-supplied URLs.

**Remote MCP servers.** The factory builds `new SSEClientTransport(new URL(config.url), …)` and `new StreamableHTTPClientTransport(new URL(config.url), …)` (`backend/packages/data/src/mcp/mcpConnectionFactory.ts:170-173`) with no `fetch` option. The SDK (1.30.0) therefore uses Node's global `fetch`, which follows redirects. Every request of the transport and of its auth discovery goes through the transport's `fetch` option when one is given.

**Web push.** `sendWebPushNotification` (`backend/packages/data/src/push/webPushAdapter.ts:29-60`) calls `webpush.sendNotification(…, { vapidDetails })` with no `agent`. web-push 3.6.7 issues a single `https.request` and accepts an `agent` option that is an `https.Agent`.

`docs/adr/2026-09-27-ssrf-protection-for-stored-outbound-urls.md` validates the URL syntax when it is stored. It leaves DNS rebinding — a public name that resolves to an internal address — out of scope and names "send-time resolution" as a separate decision. With many users this becomes a real cross-tenant path: one user's stored URL can reach loopback services (Postgres, the AI gateway, other processes), link-local metadata or the private network.

Earlier issues provide:
- #1029 stores MCP remote URLs only when `isBaselineOutboundUrl` (`backend/packages/data/src/net/storedOutboundUrl.ts`) accepts them: `https:`, no userinfo, no port, and a DNS host that is not `localhost` or an IP literal. Web push endpoints already pass `validateWebPushEndpoint`.
- #1033 re-checks the stdio transport at spawn and added reasons to `McpConnectionError` (`backend/packages/data/src/mcp/mcpConnectionError.ts`).

There is no DNS or address helper anywhere in `backend/`.

Contract tests run real MCP servers on `http://127.0.0.1` (`backend/packages/data/src/testSupport/mcpContractServers.ts:268`, `:360`), so they need an explicit test-only policy.

## Task

Load `io-hardening` (outbound network calls), `error-handling` and `adr-conventions`.

1. **Address policy.** New `backend/packages/data/src/net/outboundAddressPolicy.ts`:
   - `isPublicAddress(address: string): boolean`, built on `node:net`'s `BlockList`. It denies:
     - IPv4: `0.0.0.0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16`, `172.16/12`, `192.0.0/24`, `192.0.2/24`, `192.168/16`, `198.18/15`, `198.51.100/24`, `203.0.113/24`, `224/4`, `240/4`;
     - IPv6: `::/128`, `::1/128`, `fc00::/7`, `fe80::/10`, `ff00::/8`, `2001:db8::/32`, `100::/64`;
     - IPv4-mapped (`::ffff:0:0/96`) and NAT64 (`64:ff9b::/96`) addresses, judged by their embedded IPv4.
   - `class OutboundAddressNotAllowedError extends Error`. Its message names the host, never the full URL or credentials.
   - `publicOnlyLookup`, a `dns.lookup`-compatible function. It resolves with `{ all: true }` and fails with `OutboundAddressNotAllowedError` if any returned address is not public. Otherwise it hands the socket exactly the vetted address, so there is no second resolution.
   - `createOutboundHttp(policy?)` returns:
     - `fetch`: a `FetchLike` using an `undici` `Agent({ connect: { lookup } })` dispatcher, with `redirect: "error"`;
     - `httpsAgent`: an `https.Agent({ lookup })`.

     It also rejects a URL whose host is an IP literal, since lookup is never called for those.
   - A module-level default policy (public-only), used whenever a caller passes none.
   - `allowLoopbackOutboundForTests(): () => void`. It switches that default to one that permits loopback and `http:`, and returns the restore function. It throws unless `process.env.NODE_ENV === "test"`, mirroring `clearHooksForTests` (`backend/packages/data/src/chokePoint/hooks.ts:63-69`). It is process-wide because contract servers are reached through `executeMcpInvocation` and the agent tools, which take no policy argument. Re-export it from `backend/packages/data/src/testSupport/mcpContractServers.ts`, which other packages' tests already import as `@semprec/data/testSupport/mcpContractServers`. Do not export it from `backend/packages/data/src/index.ts`.

   Add `undici` (`^8.9.0`, already resolved transitively in `backend/pnpm-lock.yaml`) to `backend/packages/data/package.json`.
2. **MCP.** For `sse` and `http`, `connectMcpServer` uses the module's current policy.
   - It first re-checks `isBaselineOutboundUrl(config.url)`, skipped only under the test policy. This covers rows stored before #1029.
   - It then passes the policy's `fetch` as the transport's `fetch` option.
   - A baseline failure, or an `OutboundAddressNotAllowedError` anywhere in the connect error's `cause` chain, becomes `McpConnectionError("address_not_allowed", …)`, after the transport is released as today. Add that reason.
3. **Web push.** `sendWebPushNotification` passes the policy's `httpsAgent` as web-push's `agent`. An `OutboundAddressNotAllowedError` yields `{ outcome: "permanent-failure", error }`, so the existing fan-out revokes the subscription exactly as for a 404/410.
4. **ADR.** Add `docs/adr/<YYYY-MM-DD>-connect-time-outbound-address-checks.md`, referencing `[[2026-09-27-ssrf-protection-for-stored-outbound-urls]]` without superseding it. It records:
   - connect-time resolution with a pinned, vetted address;
   - the denied ranges;
   - redirects refused;
   - the test-only loopback policy;
   - that host egress filtering (#1063) remains the second layer.
5. **Tests.** Every test file that starts an sse/http contract server calls `allowLoopbackOutboundForTests()` in `beforeAll` and restores it in `afterAll`:
   - `mcpConnectionFactory.test.ts`;
   - `mcpSync.test.ts`;
   - `backend/packages/agent-runtime/src/__tests__/mcpInvokeTool.test.ts`.

## Acceptance criteria

- **Address classification.** `isPublicAddress` is false for one address of every listed range, including `::ffff:127.0.0.1`, `::ffff:10.0.0.1` and `64:ff9b::a9fe:a9fe`, and true for `93.184.216.34` and `2606:2800:220:1::1`. (unit, `outboundAddressPolicy.unit.test.ts`)
- **Lookup refuses non-public results.** With `dns.lookup` stubbed:
  - a host resolving to `127.0.0.1` fails with `OutboundAddressNotAllowedError`;
  - a host resolving to one public and one private address fails;
  - a host resolving to public addresses only passes, and the connection uses the returned address.

  (unit)
- **Real fetch blocked.** `createOutboundHttp().fetch` to a hostname that resolves to loopback (a stubbed lookup pointing at a local HTTP server) fails without the server receiving a request. A 302 from an allowed server is not followed. (integration, `outboundAddressPolicy.test.ts`)
- **MCP refused before connecting.** `connectMcpServer` on a stored `http` item with `https://localhost.test/mcp`, or a URL whose name resolves to a private address, rejects with reason `address_not_allowed` and leaves no open socket. A legacy row with `http://127.0.0.1:…` is refused the same way under the default policy. (integration, `mcpConnectionFactory.test.ts`)
- **Contract tests still pass.** The existing sse/http contract tests pass under `allowLoopbackOutboundForTests()`. Calling it with `NODE_ENV=production` throws. (integration/unit)
- **Web push.** `sendWebPushNotification` to an endpoint whose host resolves to a private address returns `permanent-failure`, and no request leaves the process. (integration, `outboundAddressPolicy.test.ts`)
