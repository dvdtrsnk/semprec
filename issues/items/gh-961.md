## Behavior specification (approved)

Part of the multi-tenancy program specified in #950. Open the system to a second user only after everything is enforced and reviewed:

1. Security gate (maintainer): the strict release is deployed and the release before it is strict too; an external adversarial review of the policies, the definer and router functions and the isolation suites; restore and deletion replay rehearsed; budgets configured.
2. Invitation acceptance: a public, per-IP rate-limited endpoint; an unknown, expired, revoked or used token always gives the same 404; one transaction creates the tenant and the user and consumes the invite, then the tenant is provisioned and becomes active; this issue drops the single-tenant guard.
3. The web invitation acceptance page reads the token from the URL fragment and removes it from the address bar.

## Decisions

- **Why is the guard dropped in the acceptance issue and not earlier?** → So that no code path can create a second tenant before the gate is signed.
