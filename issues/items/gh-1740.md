## Context

Model tier rationale: Reuses an existing extractor behind the resolver from the previous issue, with a size cap and a clear fallback, over known blob and file stores.

#1733 expands message refs into the turn context but does not read file contents. A user can attach a Files item or an e-mail attachment to a message. The model should then see the document text.

Today `POST /api/files` (`backend/services/semprec-api/src/filesHandler.ts`, `ingestUploadedFile` in `backend/packages/data/src/blobs/fileUploadStore.ts`) stores and deduplicates a blob and extracts no text. `extractAttachmentText` (`backend/packages/data/src/mail/attachmentTextExtraction.ts`, PDF and DOCX only, with `isTextExtractableContentType`) is called only when mail is ingested (`mail/attachments.ts`), and its text goes only into the mail search index.

Decision: extract at turn time from the blob, with a size cap, and persist nothing. A permanent extraction for Files items is a separate mechanism that nothing needs yet. A file attached through the chat "+" button is uploaded with `POST /api/files` by the client and attached as an `item` ref to the resulting Files item, so it is covered.

Decision: reuse existing extractor exports and both configured blob roots under the batch reconciliation.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. In the ref expander from #1733, for a ref to a Files item or a `mailAttachment`, load the blob (`getBlob` and the blob storage read stream in `backend/packages/data/src/blobs/` and `mail/blobStorage.ts`).
2. If `isTextExtractableContentType` is true and the blob is within a size cap (named constant, 10 MB), call `extractAttachmentText` and add the text to that ref's section, subject to the per-ref character cap from #1733.
3. For a plain text content type within the cap, add the decoded text the same way. For any other type, or an oversize or failed extraction, keep only the metadata (name, type, size) and add a short note saying why no text is shown. An extraction failure never fails the turn.
4. Tests: a PDF and a DOCX fixture yield their text; an oversize file yields the note; an image or unknown type yields metadata only; a corrupt PDF yields the note and the turn proceeds.

## Acceptance criteria

- When extraction throws, then the turn still runs.
