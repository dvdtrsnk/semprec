## Context

Model tier rationale: bounded ephemeral PDF/DOCX/plain-text ref extraction with failure notes. #1733 expands refs; uploads deduplicate but do not extract, and mail uses the existing extractor only for search. At turn time read tenant-owned Files/mailAttachment bytes through both configured roots; chat uploads already use Files refs. Reuse extractAttachmentText/isTextExtractableContentType; no new producer, persistent Files text/indexing or ingest change.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. In the ref expander from #1733, for a ref to a Files item or a `mailAttachment`, load the blob (`getBlob` and the blob storage read stream in `backend/packages/data/src/blobs/` and `mail/blobStorage.ts`).
2. If `isTextExtractableContentType` is true and the blob is within a size cap (named constant, 10 MB), call `extractAttachmentText` and add the text to that ref's section, subject to the per-ref character cap from #1733.
3. For a plain text content type within the cap, add the decoded text the same way. For any other type, or an oversize or failed extraction, keep only the metadata (name, type, size) and add a short note saying why no text is shown. An extraction failure never fails the turn.
4. Tests: a PDF and a DOCX fixture yield their text; an oversize file yields the note; an image or unknown type yields metadata only; a corrupt PDF yields the note and the turn proceeds.
