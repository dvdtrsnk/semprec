**Model tier:** medium

## Context

Model tier rationale: One new read-only catalog operation across the established schema, binding, application-service and route seams, with a response assembled from existing readers and tenant and authentication fixtures to extend.

#1394 records the page operation family: pages are read and written through operations of the generic catalog. This issue adds the first one, `page.get` with `format: summary`: the read that shows a page's structure without changing anything. Clients use it for the project notes card (all root blocks rendered without syntax, a footer with block and subpage counts) and for the full-screen header (title, breadcrumbs).

Today no HTTP route reaches a page. `getDocByItemId` (`backend/packages/data/src/docs/docsStore.ts`) is internal, and a document is created lazily by `getOrCreateDoc` only. The block model of #1539 gives `readPageBlocks(doc)` with the read-time normalization. Breadcrumbs for an item in an inline database come from `getItemPath` (`chokePoint/itemReads.ts`), which `GET /api/items/:id?include=path` already uses.

Decisions:

- Decision: `page.get` never creates a document. A page without a document answers `docId: null`, `blocks: []`, `blockCount: 0`, `subpageCount: 0`.
- Decision: `subpageCount` is the number of `page` blocks among the page's root blocks (a page block always counts; trashed subpages are handled later by #1723).
- Decision: `text` of each block and the `headings` list need the inline Markdown conversion of #1608, which this issue does not wait for; both are returned as `null` / an empty list until that conversion exists, and the schema already declares them so clients do not need a second version. Likewise breadcrumbs of subpage items need the parent link of #1676 and the breadcrumb walk through it (#2014, split from #1676); for those items `breadcrumbs` is `null` until then.
- Decision: `lastEditedAt` and `lastEditedBy` are returned from the document row fields added by #1405 when they exist; before that issue lands they are `null`.
- Decision: optional `limit` caps the number of returned blocks (default: all root blocks); `blockCount` and `subpageCount` always describe the whole page.

Shared-file ordering: this issue also waits for #1587 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `testing`, `error-handling` and `io-hardening`. Follow the capability and approval classification and the route path recorded by the ADR of #1394.

1. Add `page.get` to `GENERIC_OPERATION_NAMES` and give it an input schema `{ itemId, format: "summary" | "markdown" (only "summary" is accepted in this issue; "markdown" is rejected with a validation error naming the field), limit? }` in `shared/src/genericOperations/schemas.ts`; add its output type to `port.ts`, its binding to `bindings.ts` and its metadata to `capabilities.ts` as a non-destructive read with the item-read capability (an agent-specific classification is refined later by #1844).
2. Add `getPage` to the application service (`application/src/genericApplicationService.ts`): resolve the live item (404 for a foreign tenant's or missing item), load its document by item id without creating it, run `readPageBlocks`, and build the response: `docId | null`, `kind`, `title`, `blocks` of `{id, type, indent, done, text, pageId?}`, `blockCount`, `subpageCount`, `headings`, `lastEditedAt`, `lastEditedBy`, `breadcrumbs`.
3. `title`: the root page title from the `meta` map of the document when set, otherwise the translated default "Notes" for a project (the default is never stored); use the existing i18n catalog mechanism of the docs module (`docs/i18n/cs.json`, `en.json`).
4. `breadcrumbs`: the `getItemPath` chain with elements `{itemId, title, databaseKey, journal?: {type, period}}`; `journal` is present for Journal items (properties `type` and `period`) so clients can label "Journal" or a day. Return `null` for an item whose parent chain is not an inline database path.
5. Add the route `GET /api/items/:id/page` (query: `limit`) in `semprec-api/src/itemsHandler.ts`, dispatching the operation through `dispatchGenericOperation`, plus its entry in `semprec-api/src/routeMatrix.ts` and the tenant isolation route test.
6. Make the MCP and agent-tool surface pick the operation up through `application/src/genericOperationGateway.ts` only where the existing exhaustive mapping requires an entry; do not add agent grants here.
7. Tests: no document yields `docId: null`, zero counts and creates no `docs` row; a document with 14 blocks of which two are page blocks yields `blockCount` 14 and `subpageCount` 2; `limit=5` returns 5 blocks with the whole-page counts; a Journal day item's breadcrumbs start with an element having `journal: {type: "day", period: "2026-10-16"}`; no session returns 401; an item of another tenant returns 404.

## Acceptance criteria

- When an item has no document, then `GET /api/items/:id/page` returns `docId: null`, `blockCount: 0` and no document row is created.
- When a page has 14 blocks including two subpage blocks, then the response has `blockCount` 14 and `subpageCount` 2.
- When `limit=5` is given, then 5 blocks are returned and the counts still describe the whole page.
- When the item is a Journal day, then the first breadcrumb element carries `journal` with `type: "day"` and the period.
- When the request has no session, then the response is 401; when the item belongs to another tenant, 404.
- Requesting `format: markdown` in this issue fails with a validation error.
