**Blocked by:** #574

## Context

#574 added `.github/scripts/run-repo-script-tests.mjs` and the backend script `test:repo-scripts`, which runs every `*.test.mjs` under `.github/scripts/` with `node:test`. It fails when it finds no test file, because `node --test` with a glob that matches nothing exits 0. It also added the script to backend `verify`, so implementers and Relay's `verify-backend` step run it. CI does not run it yet: the required `ci` job in `.github/workflows/ci.yml` runs `.github/scripts/check-review-scope.mjs` and `pnpm run check:write-safety`, but no `.github/scripts` test. So a pull request that breaks the review follow-ups scripts (epic #565) could still merge green if its author skipped `verify`.

**Protected path, maintainer-implemented.** `.github/workflows/**` is in `.relay/config.yml`'s `protected-paths`. Relay's `guard-paths` step refuses it, and the `protected-paths` check fails any App-authored pull request touching it. This issue is implemented by the maintainer, never dispatched to Relay, and must not be labelled `agent:ready`. It also changes the required `ci` job, and a merge that changes `.github/workflows/` fails the first push of every Relay run branched before it. So it merges only after epic #494 is closed.

## Task

This issue is maintainer-implemented (protected path).

In `.github/workflows/ci.yml`'s `ci` job, add one step directly after "Backend — check write safety" and before "Backend — install":

```yaml
      - name: Repo scripts — tests
        working-directory: backend
        run: pnpm run test:repo-scripts
```

Precede it with a comment in the style of its neighbours. The comment says that the step runs the `node:test` suites under `.github/scripts/` through `run-repo-script-tests.mjs`, which fails when it finds no test file. It also says the step needs no `node_modules`, which is why it runs before install, alongside the other dependency-free scripts.

## Touches

- .github/workflows/ci.yml (`ci` job, one step and its comment)

## Scope

### In scope

- The one step and its comment in the `ci` job.

### Out of scope

- Any other change to `ci.yml` (job ids, triggers, permissions, timeouts, other steps) or to other workflows.
- Changing required status checks or branch protection. `ci` is already required, and this step runs inside it.

## Acceptance criteria

1. The `ci` job contains the step `Repo scripts — tests` running `pnpm run test:repo-scripts` in `backend`, directly after "Backend — check write safety" and before "Backend — install".
2. A pull request whose `.github/scripts/**/*.test.mjs` fails makes the `ci` job fail. A pull request with passing tests leaves it green.
3. No other line of `ci.yml` changes except the added step and its comment. Job ids, `on:`, `permissions:`, `concurrency:` and `timeout-minutes` are unchanged.
4. The comment above the step describes what the step does and why it runs before install.
