## Context

Model tier rationale: The component extraction, adapter method and panel fields are enumerated exactly with existing schemas to reuse.

With more than one user, operational health splits in two, on the backend side:

- **Operator health is admin-only and content-free.** #1038 added `GET /api/admin/health`, an adapter route with `admin: true`; a member gets `403 { error: { code: "admin_required" } }`. It answers `200` with `OperatorHealthReport`:
  - `generatedAt: string`;
  - `processes: ProcessHealthStatus[]` — exactly the four fixed processes `api`, `agents`, `transcribe` and `ai-gateway`;
  - `alertingChecks: AlertingCheck[]` — the content-free global checks;
  - `queue: QueueHealthCounts` — global;
  - `tenants: { provisioning: number, active: number, suspended: number, deleting: number }`;
  - `tenantAggregates: { agentRunErrors7d: number, itemAutomationErrors: number, alertingTenantChecks: number }` — totals across all tenants, never per tenant.

  The three element types are today's shapes, already exported from `web/src/api/systemHealthOperations.ts`:
  - `processHealthStatusSchema` (`:15-24`);
  - `alertingCheckSchema` (`:28-32`);
  - `queueHealthCountsSchema` (`:36-40`).
- **`GET /api/system-health` keeps its exact response shape** (additive-only REST contract, `docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`), but #1052 narrowed every section's contents to the caller's own tenant:
  - `processes` now lists only the caller's `mailsync:<mailboxItemId>` processes, with no fixed processes;
  - `alertingChecks` lists only the caller's own checks;
  - `queue` counts only jobs enqueued in the caller's tenant.

The web System page (`?page=ai-usage`, `web/src/main.tsx:39-42`, `web/src/App.tsx:247-253`) still labels these sections as if they were system-wide. `web/src/views/systemStatus/SystemStatusPanel.tsx` renders them with:
- `systemStatus.processes.title` "Processes" (`:92-97`);
- `systemStatus.queue.title` "Job queue" (`:99-123`);
- `systemStatus.healthy` "All monitored components are healthy";
- `systemStatus.degraded` (`:77-79`).

All of these keys are in `web/src/i18n/messages.ts:95-117` (`en`) and `:282-304` (`cs`).

#1079 and #1081 delivered the admin page (`?page=admin`, admins only): `web/src/views/admin/AdminPage.tsx` rendering the admin panels (accounts, budgets and any other panel already merged), and `AdminOperations` in `web/src/api/adminOperations.ts`. Its error mapping is: `401/403/404/501` → `unavailable`; others → `retryable`, with the adapter error body's `error.code` as message.

If a merged handler's path or field differs from the contract above (`backend/services/semprec-api/src/adminHandler.ts`, `backend/packages/data/src/observability/systemHealthReport.ts`), bind to the merged code and say so in your PR description.

## Task

Load `canonical-keys` (labels) and `error-handling` (load failures).

1. **Shared rendering** — export `ProcessRow` (`SystemStatusPanel.tsx:12-31`) and extract the three queue rows (`:99-123`, with their degraded rules: overdue and permanent above zero are degraded, pending never is) into an exported `QueueCounts` component in the same file. `SystemStatusPanel` uses both unchanged; the health panel reuses them.
2. **Per-user wording** — reword the System page so it is clear every section is the user's own. No schema or structural change:
   - `systemStatus.processes.title` → "Mail synchronization";
   - `systemStatus.queue.title` → "Your background jobs";
   - `systemStatus.healthy` → "All your monitored services are healthy";
   - `systemStatus.degraded` → "{count} of your services degraded".

   Update both `en` and `cs`, and update the `SystemStatusPanel` doc comment (`:51-57`).
3. **Adapter** — add `getOperationsHealth(): Promise<OperationsHealth>` to `AdminOperations` (`GET /admin/health`). Its zod schema reuses the three exported element schemas from `systemHealthOperations.ts` and adds the `tenants` and `tenantAggregates` objects. The file's existing error mapping applies.
4. **Health panel** — add `web/src/views/admin/HealthPanel.tsx`, loading through `useAsyncResource` (`web/src/views/mailbox/useAsyncResource.ts`) with loading and error (with retry) states. It shows:
   - a healthy/degraded summary from `alertingChecks.length`;
   - the "as of" time (`formatDateTime`, `web/src/i18n/format.ts:3-8`);
   - the alerting checks (`checkKey` and changed time);
   - the processes through `ProcessRow`;
   - the queue through `QueueCounts`;
   - accounts by status (the four `tenants` counts);
   - the three `tenantAggregates` totals.

   It shows no `detail` contents and nothing beyond these fields. All labels use a new `admin.health.*` namespace.
5. **Mount** — render `<HealthPanel operations={…} />` in `web/src/views/admin/AdminPage.tsx` after the existing panels.
6. **Tests** — update every existing `AdminOperations` test stub for the new method.

## Acceptance criteria

- `getOperationsHealth` issues `GET /api/admin/health` with same-origin credentials and parses the documented body. A 403 rejects as `unavailable`. A body missing `tenantAggregates` rejects as `retryable` (web unit, `adminOperations.test.ts`).
- The health panel shows the degraded summary with the alerting-check count when checks are alerting, and the healthy summary otherwise. It shows each process's running, stale or not-reporting state and its version (web unit, `web/src/views/admin/__tests__/HealthPanel.test.tsx`).
- The health panel shows the queue with overdue and permanent marked degraded when non-zero and pending never marked, the four account-status counts and the three aggregate totals (web unit, `HealthPanel.test.tsx`).
- Given an alerting check whose `detail` holds a string, the rendered panel does not contain that string (web unit, `HealthPanel.test.tsx`).
- A failed health load shows the error state, and retry reloads it (web unit, `HealthPanel.test.tsx`).
- The admin page renders the health panel (web unit).
- The System status panel renders the reworded section titles and summaries in `en` and `cs`, and its existing behaviour cases keep passing: the degraded summary, the empty state, queue degraded marking and the error retry (web unit, `SystemStatusPanel.test.tsx`).
- Every new key exists in `en` and `cs`, and `pnpm run verify` passes in `web/`.
