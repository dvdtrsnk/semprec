**Blocked by:** #1393, #1610, #1667
**Model tier:** high

## Context

Model tier rationale: One transaction must create an item, its document and a block in another document, optionally also create a Journal period, under tenant isolation, with a new hidden system database created at runtime and a catalog operation that every transport exposes.

#1393 records that a subpage is an item of a hidden `pages` system database, with a document of kind `page`, a parent link in `parentItemId`, and a `page` block in the parent document whose `pageId` is the item id and whose text is the title. Nothing of that exists yet: there is no Pages database, no way to create a subpage, and no way to turn an existing block into one. Existing pieces: `getOrCreateDoc` (`backend/packages/data/src/docs/docsStore.ts`) creates the document of a live item idempotently; `mutateDocWithClient` (`docs/docPersistence.ts`) writes a document inside the caller's transaction; the shared block model with its multi-block operations (#1610) cannot convert a block to or from `page` and refuses those cases with a typed error; `ensureJournalPeriodDoc` (#1541) creates a Journal period entry and its page; `getItemPath` (`chokePoint/itemReads.ts`) follows `databases.parent_item_id` only; `page.get` (#1615) returns `breadcrumbs` as null for items outside an inline-database chain. Page operations are members of the generic catalog (#1394).

This issue adds the `pages` database and the `page.createSubpage` operation for one new subpage. Later issues build on it: converting selected blocks into subpages and the breadcrumb walk through `parentItemId` (#2013 and #2014, split out of this one), duplication (#1722), renaming (#1725), title mirroring (#1715), deletion and restore (#1723), and Markdown page replacement (#1765).

Decisions:
- The `pages` database is created on first use (inside the first `page.createSubpage`) under an advisory lock and is `schema_locked`; no seed and no backfill. It has two system-owned properties (owner process `pages`): `title` (title type) and `parentItemId` (text).
- A `page` block carries its title as plain `text` (see the amendment in #1393). The block-model validation and registry therefore accept `text` on `page` blocks and still reject inline attributes there; Markdown conversion (#1608) already writes the title as the link text.
- A host is any live item; its document is created if missing. Only Pages items and hosts with a full editor are meaningful; the server does not know which editor a client shows, so it only refuses a parent that is trashed or foreign.
- Agent classification of the operation is a non-destructive write on the item-write capability; #1844 refines it.

Shared-file ordering: this issue also waits for #1667 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `canonical-keys`, `db-migrations` and `testing`.

1. Block model: in the module directory fixed by the ADR of #1366, allow a plain-text `text` on `page` blocks in the type registry and in `validateBlockInput` (inline attributes on a page title are rejected). Keep every operation of #1610 refusing page conversions as it does today.
2. Add `backend/packages/data/src/docs/pagesDatabase.ts` exporting `PAGES_MODULE_ID = "pages"` and `ensurePagesDatabase(client)`: return the system database with that owner module id, or create it (name `null`, `key` `pages`, `system: true`, the two properties above, then `schema_locked`) under `pg_advisory_xact_lock` with a dedicated key, re-checking after the lock. Declare `{ key: "pages", name: "Pages" }` in `backend/packages/data/src/docs/docsModuleManifest.ts` with no order fields (so it is not client-visible) and add `database.pages.name` and the property labels to `docs/i18n/cs.json` and `en.json`.
3. Add `normalizePageTitle(raw)` and `PAGE_TITLE_MAX_LENGTH = 500` in `backend/packages/data/src/docs/pageTitle.ts`: line breaks become single spaces, the result is trimmed, a longer title is a `ValidationError` with `field: "title"`; an empty title is valid.
4. Add `page.createSubpage` to the generic catalog (name, strict input schema `{ parent: { itemId } | { journal: { type, period } }, afterBlockId?, title? }`, output `{ pages: [{ pageItemId, docId, blockId }] }` (an array so that the later block conversion can return several pages; here it has one element), port method, binding and metadata as a non-destructive write on the item-write capability), the application service method, and the route and method the ADR of #1394 records for it, with `routeMatrix.ts` and tenant-isolation entries.
5. In one transaction: resolve the parent (a live item; for `journal`, call `ensureJournalPeriodDoc` of #1541); `getOrCreateDoc(parent, "page")`; `ensurePagesDatabase`; walk `parentItemId` up from the parent and reject a cycle or a chain longer than 1000 with a `ValidationError`. Create one Pages item (`title` from `normalizePageTitle(title ?? "")`, `parentItemId`) through `createItemWithClient` with `allowedSystemKeys`, `getOrCreateDoc(pageItem, "page")`, and insert a `page` block (with `pageId` and the title as text) into the parent document after `afterBlockId` (end if absent; an unknown `afterBlockId` is a `ValidationError`) with `mutateDocWithClient` and the caller's origin. Return the created page.
6. Tests: a subpage under a project's notes creates the item, the document and the block at the right place and `docId` opens through `/api/sync`; a subpage under the empty day `2026-10-16` creates the day, its page and the subpage in one transaction (a failure leaves none); an unknown `afterBlockId`, a title over the limit, a trashed or foreign parent and a cycle are rejected; the first call creates the hidden database and two concurrent first calls create exactly one; a project with two page blocks in the root reports `subpageCount` 2.

## Scope

### In scope

- The hidden Pages database, `page.createSubpage` for one new subpage, and the page block title text.

### Out of scope

- Converting selected blocks into subpages (`fromBlockIds`): #2013.
- Breadcrumbs of subpages through `parentItemId`: #2014.
- Duplicating a page with its subtree: #1722.
- Renaming from the subpage screen: #1725; mirroring edited titles onto the Pages items: #1715.
- Trash, restore and orphan handling: #1723, #1749.
- Converting a page block to another type: #1876.
- Markdown conversion and the rule that light editors reject page blocks: #1608.
- Agent approval classification and database grants for page operations: #1844.

## Acceptance criteria

- When `page.createSubpage` is called under a project, then a Pages item, its document and a `page` block exist at the requested position and `semprec://page/<id>` can be opened over the sync socket.
- When it is called for the empty day `2026-10-16`, then the day, its page and the subpage are created in one transaction.
- When the parent is trashed, foreign, or would create a cycle, or `afterBlockId` is unknown, then the call is rejected and nothing is written.
- When a project's root holds two `page` blocks, then `page.get` reports `subpageCount` 2.
- When the first two subpages of a tenant are created concurrently, then exactly one `pages` database exists.
