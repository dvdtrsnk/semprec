## Context

Model tier rationale: Two reference checks and one first-write check are specified exactly in existing service seams.

Project agent guidance is markdown appended to a project agent's system prompt (`backend/packages/agent-runtime/src/projectAgentGuidanceSystemPrompt.ts:20-26`). Its owner is the only user who may edit it and the recipient of drift notifications. `project_agent_guidance.owner_user_id uuid NOT NULL REFERENCES users(id)` (`backend/packages/data/src/db/migrations/0033_project_agent_guidance.sql:11`) references the global `users` table.

`createProjectAgentGuidanceService` (`backend/packages/application/src/projectAgentGuidance/service.ts:54-119`):
- **Upsert, first write.** It is unchecked: `ownerUserId: existing ? existing.ownerUserId : actor.userId` (`:85`). Only a later write compares the owner (`:79-81`).
- **Transfer.** It requires the actor to be the current owner (`:101-106`). It then accepts any `newOwnerUserId` that `references.requireUser` finds (`:108-111`).

`guidanceReferenceStore.requireUser` and `requireUserLocale` (`backend/packages/data/src/projectAgentGuidanceStore.ts:94-103`) call `getUserById` on the global `users` table, so an existing user of any tenant passes. `runAgentGuidanceDriftAction` resolves the owner's locale through the same `requireUserLocale` (`backend/packages/application/src/projectAgentGuidance/driftAction.ts:87`) before notifying that owner.

With several tenants, guidance could be transferred to, or seeded with, a user of another tenant. That user would then receive the project's drift notifications: a cross-tenant leak, even though the guidance row itself is tenant-scoped by RLS.

What earlier issues provide:
- Each tenant has exactly one user (`users.tenant_id` is `UNIQUE`). RLS scopes `project_agent_guidance` to the current tenant.
- #1018 added `getTenantUserId(client)`, which runs `SELECT id FROM users WHERE tenant_id = (SELECT app_tenant_default())` and returns `null` when there is none. It also addresses tenant events to that user. `createUser` accepts `{ tenantId, role }` (#968).

## Task

Load `state-writes` (the check runs inside the service's serializable transaction) and `error-handling` (keep "not found" distinct from infrastructure failures).

1. **Tenant-bound references.** In `guidanceReferenceStore` (`projectAgentGuidanceStore.ts:94-103`), `requireUser(tx, userId)` and `requireUserLocale(tx, userId)` accept only the current tenant's user. They compare `userId` with `getTenantUserId(tx)`. A user of another tenant, a user without a tenant, or an unknown id throws `GuidanceReferenceNotFoundError` with the same message as today's unknown user. Any other error propagates unchanged.
2. **First write binds the owner.** In `upsertProjectAgentGuidance`, when there is no existing row, call `references.requireUser(tx, actor.userId)` inside the same transaction before `store.upsert`. Map `GuidanceReferenceNotFoundError` to `ProjectAgentGuidanceOwnerViolationError(input.projectItemId)` (403 `owner_violation`); other errors propagate. Writes to an existing row keep the existing owner comparison.
3. **Transfer.** No code change beyond step 1: `transferProjectAgentGuidance`'s existing `requireUser(newOwnerUserId)` now refuses any user other than the tenant's own, answering `validation_failed` `{ field: "newOwnerUserId", reason: "not_found" }` exactly as for an unknown id.
4. **Tests.**
   - Extend `backend/packages/application/src/projectAgentGuidance/__tests__/service.unit.test.ts` with fake ports.
   - Extend `backend/packages/data/src/__tests__/projectAgentGuidanceStore.test.ts` as integration tests. Run them inside `runInTenant(<sole tenant id>, …)` on a pool from `createPool`, with the test user bound to that tenant. "Another user" is a second `createUser` row that is not bound to it.

## Scope

### In scope
- Binding guidance ownership, its first write, transfers and the drift owner lookup to the current tenant's user.

### Out of scope
- `getTenantUserId` itself, and addressing other tenant events (#1018).
- A composite `(tenant_id, owner_user_id)` foreign key (#1066).
- An HTTP route for guidance; none exists today.
- Agent-run delegation targets (#1045).

## Acceptance criteria

- **Own guidance.** When the tenant's user upserts guidance for a tenant project with no guidance yet, the row's `owner_user_id` is that user. Later edits by the same user succeed. (unit, `service.unit.test.ts`; integration, `projectAgentGuidanceStore.test.ts`)
- **Foreign first write refused.** When an actor whose `userId` is not the tenant's user upserts guidance for a project with none, the call rejects with `owner_violation`, and no row and no drift heartbeat are written. (unit, `service.unit.test.ts`)
- **Foreign transfer refused.** Transferring guidance to a user who is not the tenant's user rejects with `validation_failed` `{ field: "newOwnerUserId", reason: "not_found" }`, identical to a random UUID, and the owner is unchanged. (unit, `service.unit.test.ts`)
- **Reference store.** `requireUser` and `requireUserLocale` resolve the tenant's user. For another existing user, they throw `GuidanceReferenceNotFoundError`. A dropped connection still surfaces as itself, not as not-found. (integration, `projectAgentGuidanceStore.test.ts`)
- **Drift suites pass.** `backend/packages/data/src/__tests__/guidanceDrift.test.ts` and `guidanceDriftIsolation.test.ts` pass unchanged. `driftAction.unit.test.ts` passes unchanged. (integration/unit)
