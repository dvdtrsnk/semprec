## Context

Model tier rationale: The header contract and guard SQL are given, but scoping whole requests in three handlers and three clients spans several seams.

Every model call leaves its process only as a loopback HTTP request to `semprec-ai-gateway`, authenticated with the shared `AI_GATEWAY_INTERNAL_TOKEN`. There are three clients:
- `createHttpAiGatewayClient` in `backend/packages/ai-gateway-client/src/httpAiGatewayClient.ts:89-130`, used for `POST /internal/complete`. Its headers are built at `:96-103`. Its callers:
  - the `core.agentGuidanceDrift` heartbeat action in `semprec-api` (`backend/services/semprec-api/src/projectAgentGuidanceComposition.ts:48-51`);
  - transcript summary and speaker suggestion in `semprec-transcribe` (`backend/services/semprec-transcribe/src/transcriptionTask.ts:845-850`).
- `createHttpAudioGatewayClient` in `backend/services/semprec-transcribe/src/audioGatewayClient.ts:177-201`, used for `/internal/diarize` and `/internal/transcribe`. Its headers are set in `post()` at `:141-158`.
- The agents' pi `streamFn`, which sends `POST <AI_GATEWAY_BASE_URL>/messages` (`backend/services/semprec-agents/src/modelComposition.ts:70-74`). `agentSessionComposition.ts:140-141` adds `x-semprec-agent-run-id` per run.

Every caller is a queue job, which #982's `registerTask` runs inside its envelope's tenant. #991 and #992 proved that the agents' sessions and the transcription pipeline keep that scope through every gateway call. So `currentTenantScope()` (`@semprec/shared`) returns `{ kind: 'tenant', tenantId }` at the moment of each call, but none of the clients sends it yet. The drift action is a heartbeat job too: no gateway call starts from an HTTP request.

The gateway handles three routes:
- `completeHandler.ts:179-335`: token check `:193-197`; reservation through `complete(pool, { agentRunId: null, projectItemId, … })` `:235-244`.
- `piMessagesHandler.ts:277-410`: token check `:330-334`; the run id is only UUID-checked from `x-semprec-agent-run-id` (`:151-159`, `:336`) before it reaches `complete(pool, { agentRunId, projectItemId: null, … })` (`:354-365`).
- `audioHandler.ts:135-189`, behind the token check at `:223-227`.

Each runs with no tenant scope. `@semprec/ai-gateway`'s reservation inserts the `ai_gateway_calls` row via `reserveGatewayCall` (`backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts:130-148`). It runs inside `reserve`'s transaction, under the global budget advisory lock (`backend/packages/ai-gateway/src/gateway.ts:53-66`). Settle (`aiGatewayCallsStore.ts:154-186`) and `failGatewayCall` (`:195-201`, autocommit) run on the same pool afterwards.

`ai_gateway_calls` is a tenant table: its `tenant_id` is `NOT NULL DEFAULT app_tenant_default()`. Without a scope, every row falls to the sole-tenant default. That stays correct only while one tenant exists, and is refused once enforcement is strict. Two attribution holes exist besides:
- `ai_gateway_calls.agent_run_id REFERENCES agent_runs(id)` (`backend/packages/data/src/db/migrations/0018_ai_gateway_calls.sql:10`). FK checks ignore RLS, so a run id of another tenant would be linked silently.
- `project_item_id` has no FK at all (`0034_ai_gateway_calls_project_operation.sql:1-8`).

Tenancy state this issue builds on:
- `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()` come from `@semprec/shared` (#978). `runInTenant` throws `TypeError` for a non-UUID. `withTransaction`, autocommit `pool.query` on a `createPool` pool and `pool.connect()` clients set the GUC `app.tenant_id` from the ambient scope.
- RLS policy `tenant_isolation` is `tenant_id = (SELECT app_tenant_default())`, where `app_tenant_default()` is `COALESCE(app_current_tenant(), app_sole_tenant())`.
- A query with no scope logs `tenant_scope_missing` under `SEMPREC_TENANT_SCOPE=warn` (the default until #1067) and throws `TenantScopeMissingError` under `strict`.
- `tenants(id, status ∈ provisioning|active|suspended|deleting, …)` is a global table. The gateway's `semprec_side` role can read it, and `agent_runs` and `items` too.

**The header contract.** A trusted internal caller sends `x-semprec-tenant-id: <uuid>`, taken only from its own current tenant scope, never from input. The gateway does the following:
- checks the bearer token first;
- validates the header and runs the rest of the request inside `runInTenant(<header>)`, so every row it writes is attributed by the column default;
- refuses a call whose tenant is not `active`, or whose run or project id is not visible in that tenant. A foreign id is refused exactly like an unknown id.

A request **without** the header is processed with no tenant scope, exactly as today. That covers the previous release's callers during a deploy and legacy-envelope jobs until #1061. In `warn` mode it falls to the sole tenant and is visible in `tenant_scope_missing` telemetry. Once `strict` is the default, it is refused.

## Task

Load `ai-gateway` (gateway contract), `io-hardening` (a new inbound header, validated after authentication), `state-writes` (the reservation insert and its in-transaction guard) and `error-handling` (refusal mapping, no row on refusal).

1. **Clients send the header.** Add `x-semprec-tenant-id` to the request headers when `currentTenantScope()` is `{ kind: 'tenant' }`, and send no such header otherwise. The scope value always wins over any caller-supplied value. Apply this in:
   - `httpAiGatewayClient.ts` (next to `x-trace-id`);
   - `audioGatewayClient.ts` (`post()`);
   - `modelComposition.ts` (`streamFn`, read at call time, merged into `options.headers`). Drop any caller-supplied `x-semprec-tenant-id` when there is no tenant scope.
   Follow the existing per-file header constant pattern (`agentSessionComposition.ts:32`, `piMessagesHandler.ts:40`). `projectAgentGuidanceComposition.ts` needs no change: it uses the shared client.
2. **Gateway caller tenant (`backend/services/semprec-ai-gateway/src/callerTenant.ts`, new).** Export two functions:
   - `readCallerTenantId(req): string | null`. Absent header → `null`. A value that is not one canonical UUID (including a repeated header, which Node joins with `, `) → `ValidationError("'x-semprec-tenant-id' must be a UUID", { field: "x-semprec-tenant-id" })`.
   - `runForCallerTenant<T>(tenantId: string | null, fn: () => Promise<T>): Promise<T>`. It runs `fn` inside `runInTenant(tenantId)`, or calls it directly when `null`.
3. **Handlers.** In each of `completeHandler.ts`, `piMessagesHandler.ts` and `audioHandler.ts`, call `readCallerTenantId` right after a successful token check, so a bad token still answers 401 first. Run the rest of the request inside `runForCallerTenant`: body read, validation, `complete`/`diarize`/`transcribe` and the response. Settle and fail then run in the same scope. Existing status mapping is unchanged.
4. **Attribution guard (`aiGatewayCallsStore.ts`, `reserveGatewayCall` only).** Make the insert conditional in one statement, still inside `reserve`'s transaction:
   `INSERT INTO ai_gateway_calls (…) SELECT … WHERE EXISTS (SELECT 1 FROM tenants WHERE id = app_tenant_default() AND status = 'active') AND ($4::uuid IS NULL OR EXISTS (SELECT 1 FROM agent_runs WHERE id = $4::uuid)) AND ($5::uuid IS NULL OR EXISTS (SELECT 1 FROM items WHERE id = $5::uuid)) RETURNING …`.
   - RLS makes the `agent_runs` and `items` probes tenant-local. Use `app_tenant_default()`, not `app_current_tenant()`, so a header-less legacy call keeps working.
   - When no row is returned, throw `new ForbiddenError("AI gateway call is not attributable to the caller's tenant", undefined, "attribution_refused")`. No details, so a foreign id and an unknown id give byte-identical bodies.
   - The handlers' existing `ChokePointError` mapping answers it as 403. The provider is never called and no row exists. Update the docstring.
5. **Tests.**
   - `backend/services/semprec-ai-gateway/src/__tests__/completeHandler.test.ts` sends `agent_guidance_drift` with the made-up `projectItemId` `11111111-…` (`VALID_BODY`, `:45`), which the guard now refuses. Seed a real Projects item instead (`seedSystem`, then a Projects item) and use its id. The same made-up id is posted by `shutdown.test.ts` (`VALID_BODY`, `:38`) and `audioConcurrencyLimit.test.ts` (`VALID_COMPLETE_BODY`, `:127`); replace it there the same way. Only those fixtures, and the places that build them, change.
   - Put the new gateway cases in `backend/services/semprec-ai-gateway/src/__tests__/callerTenant.test.ts` (new), driving all three routes through `createDispatcher` the way the existing route tests do. Put the store cases in `backend/packages/data/src/__tests__/aiGatewayCallAttribution.test.ts` (new). The existing `piMessagesHandler.test.ts`, `audioHandler.test.ts` and `aiGatewayCallsStore.test.ts` must pass unchanged: they send no tenant header and use real run ids.
   - Seed runs and Projects items in tenant zero (`SELECT app_sole_tenant()`, or `getTenantZeroId()` from #975's test support) inside `runInTenant`.
   - The unit-tier client tests use `runInTenant` from `@semprec/shared` with a random UUID; it touches no database.

## Scope

### In scope
- The `x-semprec-tenant-id` header in all three clients.
- Its validation and tenant entry in the three gateway routes.
- The tenant-active and attribution-visibility guard on the reservation.
- The tests.

### Out of scope
- Per-tenant and global budget caps, and the budget lock's scope (#1035). Today's settings-based caps are read unchanged, now within the caller's tenant.
- Admin-set caps (#1039) and the per-user usage report (#1048).
- Making `strict` the default, which refuses header-less calls (#1067).
- The gateway's own process heartbeat (`backend/services/semprec-ai-gateway/src/serve.ts:70-74`), whose ticks run in system scope since #990.
- The exhaustive two-tenant isolation suites (#1053, #1056).

## Acceptance criteria

- **Clients send the header (unit).** In `httpAiGatewayClient.unit.test.ts`, `audioGatewayClient.unit.test.ts` and `modelComposition.unit.test.ts`:
  - inside `runInTenant(T)`, the request carries `x-semprec-tenant-id: T`;
  - outside any scope and inside `runAsSystem`, the request has no such header;
  - in `modelComposition.unit.test.ts`, a caller-supplied `x-semprec-tenant-id` is replaced by the scope's value, or dropped when there is no tenant scope.
- **Attribution (integration, `callerTenant.test.ts`).** A request with tenant zero's id in the header produces exactly one row on each route:
  - the row has `tenant_id` = tenant zero;
  - a successful call leaves it `settled`; a provider failure leaves it `failed`.
- **Malformed header (integration, `callerTenant.test.ts`).** A header that is not a UUID gets 400 with no row written and the provider not called. With a wrong bearer token as well, the answer is 401.
- **Inactive or unknown tenant (integration, `aiGatewayCallAttribution.test.ts` and `callerTenant.test.ts`).** A header naming a random UUID, or tenant zero after its `status` was set to `suspended`, gets 403 `{ code: "attribution_refused" }` with no row written and the provider not called. Restore the status afterwards.
- **Unattributable ids (integration, `aiGatewayCallAttribution.test.ts` and `callerTenant.test.ts`).** Each of the following gets 403 `attribution_refused` with no row written and the provider not called:
  - pi-messages with an `x-semprec-agent-run-id` that is a random UUID;
  - complete (`agent_guidance_drift`) with a `projectItemId` that is a random UUID.
- **Foreign ids (integration, `callerTenant.test.ts`; second tenant from `createTestTenant(pool)`, dispatcher over `createRuntimeRolePool(pool, "semprec_side")`, both from #975's `@semprec/data/testSupport`).** A call with tenant A's header and tenant B's run id (pi-messages), or B's Projects item id (complete), gets a response byte-identical to the random-UUID case. Neither tenant gains a row.
- **Legacy caller (integration).** A request without the header still succeeds on each route, and its row carries tenant zero, the sole-tenant default (`callerTenant.test.ts`). The existing route and store test files pass, `completeHandler.test.ts`, `shutdown.test.ts` and `audioConcurrencyLimit.test.ts` with only their project fixtures changed.
- **Run attribution kept (integration, `callerTenant.test.ts`).** A pi-messages request with tenant zero's header and the id of a run in tenant zero records that `agent_run_id` on the row.
