## Context

Model tier rationale: A new tenant-scoped read route that merges several source databases into one ordered, localized list and must expose nothing across tenants, with ordering rules derived from relation edge counts.

When the user edits an Inbox proposal card, fields such as project, area, person, company or page open a picker of choices. Today the only way to build such a picker is the generic `POST /api/databases/:id/query`, which cannot express the card's rules: the card's current value first, the assistant's suggestion next, then the most used targets, a "none" choice in a fixed place, archived targets shown but not selectable, steps that would be created shown as "new - will be created", and a stable order. Areas had no color before #1515; People have no color or initials property at all. There is no usage tracking: items have no created timestamp and usage has to be counted from relation edges (`item_relations`).

This issue adds `GET /api/proposals/:id/options?field=<key>`, a custom route registered in the Inbox module manifest with justification `single-consumer-read` (it is shaped for exactly one consumer, the card editor's picker). Relation validation from #1426 defines the state of a target (archived, deleted; a `done` project is a valid target); this route uses the same evaluation for `disabled`. The recomputed suggestion used for ordering is the one on the card's envelope, as updated by recompute (#1955).

Decision: `field` is a closed set: `project`, `area`, `people`, `company`, `page`, `mcpProjects`. Any other value is a `ValidationError`. An optional `includeDone=true` lists `done` projects as ordinary, selectable choices; without it they are hidden (decided by the product owner: a done project is a valid target, the picker only hides it by default). The response is `{ options: Option[] }` with `Option = { id: string | null, ref?: string, label, color?, initials?, disabled, disabledReason?: "archived" | "deleted", hint?, suggested, none?: true }`.

Decision: order is: (1) the card's current value; (2) the suggested target (from the envelope); (3) number of edges of that relation pointing at the target, descending; (4) name, locale-aware ascending. The "none" choice is last for `project` and `company` and first for the others where a none choice exists. An archived or deleted target appears only when it is the card's current value (so an invalid card can show the archived project first, `disabled: true`, `disabledReason: "archived"`); otherwise it is omitted. A `done` project appears when it is the card's current value or when `includeDone=true`, and is then selectable (`disabled: false`). A step of the proposal that would create a new item (for example a new company) is listed with its `ref` instead of an `id`, `suggested: true` and the localized hint "new - will be created".

Decision: `initials` for people are derived on the server from the name (first letters of the first and last word); the color of a person is not stored or returned and the client derives it. Projects return `Projects.color`, areas return `Areas.color`. `mcpProjects` lists every project except the none choice. Pages lists projects, areas and subpages that can host page content (as defined by the page placement work in this program).

Shared-file ordering: this issue also waits for #1956 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Scope

### In scope

- The options route for `project`, `area`, `people`, `company`, `page` and `mcpProjects`, with ordering, disabled state, hints and tenant isolation.

### Out of scope

- Event candidates of recordings, transcript event candidates and speaker alternatives (carried as `candidates` on the card, not as options).
- Storing a color on People (decided: the client derives it).
- Validating the chosen option on edit or confirm (#1892, relation validation).
- Czech names of select options.

## Acceptance criteria

- When `options?field=project` is requested for an invalid card whose project is archived, then the archived project is first with `disabled: true` and `disabledReason: "archived"`, and the "none" choice is last.
- When the proposal has a step that creates a new company, then `options?field=company` includes an entry with `ref`, `suggested: true` and the localized hint "new - will be created".
- When a project is not the card's value and is archived, then it is not listed.
- When a project is `done` and not the card's value, then it is not listed without `includeDone=true`, and with `includeDone=true` it is listed with `disabled: false`.
- When two projects have different numbers of edges, then the one with more edges is first after the current and suggested values.
- When another tenant requests the options of this proposal, then it receives the same response as for an unknown proposal.
- When `field` is not in the allowed set, then the response is 400.
