**Blocked by:** #102

## Context

Processing must react to one changed item without periodically scanning the entire Inbox.

## Task

Register the Inbox database for `onItemEvent` create, update, and delete. Enqueue the existing heartbeat event task with `{ heartbeatId, itemId }`, action `semprec.tick`, and key `heartbeat-fire:${heartbeatId}:${itemId}` using replacement semantics for pending work. Rapid edits must collapse into one tick that reads current authoritative state. Keep event jobs distinct from scheduled occurrences and manual heartbeat triggers. Route the action to the queue affinity registered for its handler.

## Scope

### In scope

- Transactional event emission, per-item job identity, current-state processing, and registration.

### Out of scope

- Scheduler occurrences, periodic sweep, and the proposal computation itself.

## Acceptance criteria

- Create/update/delete enqueue the correct item context transactionally.
- Rapid pending updates collapse without losing the newest state.
- Different Inbox items never deduplicate each other.
- A rolled-back item mutation emits no job.
