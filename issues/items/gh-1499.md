## Context

Model tier rationale: Mechanical addition of one envelope field to three adapters with existing unit-test fixtures, but each adapter reads it from a different source format.

A reply should go to the sender's Reply-To address when the message has one. No adapter parses it: `MailEnvelope` in `backend/packages/data/src/mail/mailMessageMetaStore.ts` has only `from`, `to`, `cc` and `bcc`, and `FetchedMessage` (`backend/packages/data/src/mail/providerTypes.ts`) carries that envelope. The IMAP adapter (`imapFlowClient.ts`) builds it from the ImapFlow envelope, the Gmail adapter (`gmailRestClient.ts`) from headers and the Graph adapter (`graphRestClient.ts`) from the message resource. The envelope is stored as JSON in `mail_message_meta.envelope`, so no migration is needed.

The reply prefill that reads it is #1899.

Decision: messages synced before this change have no stored Reply-To; the reply falls back to From for them. No backfill.

## Task

Load `testing`.

1. Add optional `replyTo?: MailEnvelopeAddress[]` to `MailEnvelope`.
2. Fill it in `imapFlowClient.ts` (ImapFlow `replyTo`), `gmailRestClient.ts` (the `Reply-To` header; add it to the requested header list) and `graphRestClient.ts` (`replyTo` recipients), using the existing address-list helpers. A missing or unparsable header leaves it absent.
3. Make sure ingest stores the field unchanged in `mail_message_meta.envelope`.
