## Context

Model tier rationale: It changes cancellation semantics across every pipeline step that makes paid calls, with concurrency against deletion, retries and the failure path, so a gap would either bill for deleted data or leave jobs failing permanently.

Deleting a transcript or source must stop checkpointed transcription rather than leave automation pending or exhaust retries. Existing item reads include Trash: guards and failure recording must handle missing/deleted rows. Stop leaves automation error/deleted without an item-row write, notification or Semp problem and completes the job. Health excludes Trash; restore uses the existing rerun route. #1386 owns error codes, #1421 derived purge and #1945 problem closure. Only committed checkpoints are reusable; in-flight uncheckpointed work may repeat.

## Task

Load `state-writes`, `error-handling`, and `testing`.

1. Extend `requireTranscriptionUnlocked` (or a sibling used by every step's first transaction) to also load the transcript and the source Files item and throw a `TranscriptionStoppedError` when either has `deleted_at` set or is gone.
2. In the task wrapper catch `TranscriptionStoppedError`: in one transaction set `item_automation` to `error` with code `deleted` (without touching the `items` row, which may be in Trash) and end the job successfully; write no notification.
3. Make `recordTranscriptionFailure` fall back to this same path when the transcript is in Trash instead of attempting the `status` update.
4. In `getItemAutomationErrorCounts` count only automation rows whose item has `deleted_at IS NULL`.
5. Tests: deleting the transcript during diarize makes the next step skip the paid ASR call; no `automation_error` is written; `item_automation` is `error`/`deleted` and the job is not permanent; deleting the source file does the same; a deleted item does not count in `itemAutomationErrorsByDatabase`; rerun after restore works through actual authenticated HTTP restore/rerun, the real queued production transcription task and completion. Use the isolated child fixture of `docs/adr/2026-11-01-transcription-http-evidence-uses-an-isolated-producer.md`; assert stopped state, enqueue/consumption and only committed-checkpoint reuse, without cross-service imports or repeated-work guarantees for uncheckpointed calls.

## Acceptance criteria

- When a transcript is deleted during diarization, then the next step makes no paid call, no `automation_error` notification is written, `item_automation` is not left `pending`, and the job does not end as permanently failed.
- When the source Files item is deleted, then the pipeline stops the same way.
- When a transcript in Trash had an error, then it is not counted in `itemAutomationErrorsByDatabase`.
- When the item is restored and rerun is requested, then the pipeline runs again.
