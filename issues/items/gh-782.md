## Context

PR #350 (`serve.ts`) flagged that `Number(process.env.SMTP_PORT ?? "587")` silently
produces `NaN` when `SMTP_PORT` is set to a non-numeric string. `NaN` then flows into
`nodemailer.createTransport({ port: NaN, ... })` without error at startup; every
password-reset email send attempt then fails with a confusing socket-level error at
send time instead of a clear startup failure. `serve.ts` already validates its other
numeric env vars this way: `PORT` (lines 53-55, `Number.isInteger(port) && port > 0`)
and `MAX_FILE_SIZE_MB` (lines 78-81, `Number.isFinite(...) && > 0`), each throwing a
descriptive `Error` at startup on an invalid value.

## Task

In `backend/services/semprec-api/src/serve.ts`'s `buildPasswordResetMailer` function,
validate `SMTP_PORT` the same way `PORT` is validated: read
`process.env.SMTP_PORT ?? "587"` into a named variable, convert with `Number`, and
throw a descriptive `Error` (naming the invalid raw value) if the result is not
`Number.isInteger(...)` or is `<= 0`, before passing it to `createTransport`. This
validation only runs inside `buildPasswordResetMailer`, which itself only runs when
`SMTP_HOST`/`SMTP_FROM_ADDRESS` are both set — an install with no outbound SMTP
configured is unaffected, consistent with this function's existing "both optional at
startup" behavior.

## Touches

- backend/services/semprec-api/src/serve.ts (`buildPasswordResetMailer`)

## Scope

### In scope

- Validating `SMTP_PORT`'s numeric value before it reaches `createTransport`.

### Out of scope

- Validating any other `SMTP_*` env var.

## Acceptance criteria

- Starting the service with `SMTP_HOST`/`SMTP_FROM_ADDRESS` set and `SMTP_PORT=smtp`
  (non-numeric) throws a descriptive startup error instead of building a transporter
  with `port: NaN`.
- Starting the service with `SMTP_PORT` unset still defaults to port 587 and boots
  normally.
- Starting the service with a valid `SMTP_PORT` (e.g. `587` or `2525`) boots normally
  and uses that port.
