## Context

Model tier rationale: One new authenticated account route and one targeted update of a global identity row, with a reindex hook delivered by a blocker, so the seams are known but the locale side effects need care.

The person can see their language in the profile and wants to switch between Czech and English. `users.locale` (`cs` by default) is set only at creation (`createUser` in `backend/packages/data/src/auth/usersStore.ts`, always `cs` today) and no route changes it. It drives the localized names of collections in `/api/schema`, `/api/databases` and `/api/properties`, notification text (`data/notifications/notify.ts`), speaker labels in transcripts, the drift guidance, and the web client; the user object returned by the session endpoints carries it.

Account routes live in `createAccountRoutes` (`backend/services/semprec-api/src/accountHandler.ts`), run authenticated inside the session's tenant, and are classified in `backend/services/semprec-api/src/routeMatrix.ts`. `users` is a global identity table that the runtime role may `UPDATE`.

Decision: the single "language" setting is the language of the whole application, not only the assistant's, because `users.locale` already drives collection names, notifications and speaker labels. There is no separate assistant-language setting.

Decision: the route accepts only `locale` now. Any other key (including `displayName` and `avatarColor`) is rejected with 400, so later profile fields can be added without changing what a client may send today.

Decision: the new locale becomes visible to the web client through its existing refetch of the session; the realtime invalidation frame for the `account` scope is owned by #1946, which will publish after this route's commit.

Search labels of select and multi-select options are stored in the search index in the user's language, so a locale change needs those labels reindexed; the reindex entry point comes from #1652.

Shared-file ordering: this issue also waits for #1701 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `canonical-keys`, `error-handling` and `testing`.

1. In `usersStore.ts` add `updateUserLocale(client, userId, locale)` that updates only the row with that id and returns the updated `UserRow` (use the row type from #1387).
2. Add the supported locales as a constant in `backend/packages/data/src/auth` (`cs`, `en`) and export a guard.
3. Add `PATCH /api/account/profile` to `createAccountRoutes`: body `{ locale }`, the user id taken only from the authenticated identity, never from the body. `locale` must be present and one of `cs` or `en`; an empty body, a missing or unsupported value, or any extra key returns 400 `validation_failed` with the offending `field`. Response 200 `{ user }` with the same user shape as `GET /api/auth/session` (including `role`).
4. In the same transaction as the update, and only when the stored locale actually changed, trigger the locale-dependent reindex of select and multi-select option labels through the entry point delivered by #1652 (read its pull request for the exact function). Setting the same locale again does no reindex.
5. Register the route in `routeMatrix.ts` as `{ name: "update profile", method: "PATCH", path: "/api/account/profile", surface: "api", public: false, tenancy: "account" }`, add its handler mapping to `ROUTE_HANDLER_FILES` in `backend/services/semprec-api/src/__tests__/chokePointWriteBoundary.unit.test.ts`, and add the isolation case to `tenantIsolationRoutes.test.ts` proving that a request authenticated as tenant B changes only B's row and never tenant A's.
6. Tests: success for `en` and back to `cs`; `de`, empty body, empty string, extra key give 400; the following `/api/databases` response uses the new locale; the reindex is requested exactly when the locale changed.

## Scope

### In scope

- `PATCH /api/account/profile` for `locale`, the user-row update, and the reindex trigger on change.

### Out of scope

- Editing the display name (decided: it comes with the design of the editing screen) or an avatar colour (decided: deferred).
- The `account` invalidation frame and its delivery to the user's other devices: #1946.
- The language instruction in agent prompts: #1388 and #1358.
- Localizing outgoing e-mails.

## Acceptance criteria

- When a signed-in user sends `PATCH /api/account/profile` with `{ "locale": "en" }`, then the response is 200 with `user.locale: "en"` and a later `GET /api/auth/session` returns `en`.
- When the body is empty, `locale` is `de` or blank, or an extra key is present, then the response is 400 `validation_failed` and the row is unchanged.
- When the locale changes, then `/api/databases` and notifications created afterwards use the new language, and after the reindex has run, a search finds the English label of a select option.
- When tenant B's user calls the route, then tenant A's user row is unchanged.
- The full backend `pnpm run verify` passes.
