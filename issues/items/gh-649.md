## Context

The daily backup (`deploy/systemd/scripts/semprec-backup.sh:23-55`) snapshots the Postgres custom dump plus the MinIO `/data` volume (`minio_data_directory`, `restic backup "$DUMP_FILE" "$minio_data"`), and the monthly restore test (`deploy/systemd/scripts/semprec-restore-test.sh`) restores that snapshot, starts a disposable MinIO (`start_minio`, line 191), and verifies sampled `blobs` rows against objects read from the restored bucket (`check_blob_objects`, lines 231-255, `read_restored_object`, `restored_minio_data_directory`, `url_encode`). The application never writes to MinIO: there is no S3 client anywhere in `backend/` (`grep -rl "S3Client\|@aws-sdk\|minio" backend --include=*.ts` hits only `restoreTestResultArgs.ts`), and the sole `BlobStorageWriter` is `LocalFsBlobStorageWriter` writing under `FILES_STORAGE_DIR` and `MAIL_ATTACHMENTS_DIR`. So the backup preserves an always-empty bucket and none of the bytes the `blobs` rows reference, and the restore test passes vacuously ("restored blobs table has no hashed objects to compare" whenever no blob exists, and it would fail on the first real blob).

Sibling #645 fixes the directories: `/opt/semprec/data/files` (`FILES_STORAGE_DIR`) and `/opt/semprec/data/mail-attachments` (`MAIL_ATTACHMENTS_DIR`), both in `/opt/semprec/shared/.env`, which `semprec-backup.service` and `semprec-restore-test.service` already load (`EnvironmentFile=/opt/semprec/shared/.env`). A `blobs.storage_key` is the path relative to whichever of the two directories the writer was given (`blobStorage.ts:59`, `join(this.baseDir, storageKey)`); mail attachments use the mailbox item id as key prefix (`mailSyncJob.ts:243`), so a sampled key may live in either directory. restic stores absolute paths, so a restored snapshot places `/opt/semprec/data/files/<key>` at `$WORK_DIRECTORY/opt/semprec/data/files/<key>`.

## Task

1. **Backup** — in `semprec-backup.sh`: add `FILES_STORAGE_DIR` and `MAIL_ATTACHMENTS_DIR` to `require_environment`; delete `minio_data_directory` and the MinIO lines in `main`; run `restic backup "$DUMP_FILE" "$FILES_STORAGE_DIR" "$MAIL_ATTACHMENTS_DIR"` (both directories must exist — `[[ -d ]]` check with a clear error, since provisioning creates them). Update the header comment. In `semprec-backup.test.sh`: drop the MinIO `docker compose ps`/`docker inspect` mock branches and `TEST_MINIO_DIRECTORY`, export two temporary directories as the env vars, and assert the `restic backup` command line names the dump and both directories; keep the existing failure cases (`fail-pg-dump`, `fail-restic-backup`, `fail-restic-forget`) and add one for a missing storage directory.
2. **Restore test** — in `semprec-restore-test.sh`: remove `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_BLOB_BUCKET` from `require_environment` and add `FILES_STORAGE_DIR`, `MAIL_ATTACHMENTS_DIR`; delete `start_minio`, `restored_minio_data_directory`, `url_encode`, `read_restored_object`, the `MINIO_*` readonly constants/image and the MinIO teardown in `destroy_disposable_state`; rewrite `check_blob_objects` to read each sampled `storage_key` from `$WORK_DIRECTORY$FILES_STORAGE_DIR/$storage_key`, falling back to `$WORK_DIRECTORY$MAIL_ATTACHMENTS_DIR/$storage_key`, failing the check (`fail_check "restored snapshot has no file for a sampled blob"`) when neither exists, and comparing size and SHA-256 as today. Remove `start_minio` from `main`. Keep the `blobObjects` check name so `restoreTestResultArgs.ts`/the recorded result shape is unchanged. Update `semprec-restore-test.test.sh` accordingly (the fake restic restore must lay out the dump and the two directories under the work directory; cover the found-in-files, found-in-mail-attachments, and missing-file cases).
3. **Configuration and docs** — in `deploy/shared/.env.example`, rewrite the `MINIO_*` block (lines 80-87) to state that MinIO is not used by the application or the backup and is kept in `deploy/docker-compose.yml` only until a separate removal, and that `MINIO_BLOB_BUCKET` is no longer read by any script; in `deploy/README.md`, update the "Encrypted off-site backups" and "Monthly restore test" sections (lines 111-150) to name the two directories instead of the MinIO volume/bucket.
