## Context

PR #362 (`notificationFanoutJob.ts`) flagged that
`registration.channel === "web_push" ? sendWebPush(...) : sendApns(...)`
(lines 114-116) is a binary ternary over the `PushChannel` union
(`backend/packages/data/src/push/types.ts`, currently exactly
`"web_push" | "apns"`). This is correct today only because the union has exactly two
members; TypeScript raises no error if a third channel is ever added to
`PushChannel`, since the ternary's `else` branch silently absorbs it and routes it
through `sendApns`.

## Task

In `backend/packages/data/src/notifications/notificationFanoutJob.ts`, replace the
`registration.channel === "web_push" ? ... : ...` ternary with a
`switch (registration.channel)` (or equivalent `if`/`else if` chain) that dispatches
`"web_push"` to `sendWebPush` and `"apns"` to `sendApns` explicitly, with a `default`
branch that is provably unreachable today — assign it to a `never`-typed
exhaustiveness check (e.g. `const _exhaustive: never = registration.channel; throw new
Error(...)`) so adding a third `PushChannel` member becomes a compile error here
instead of a silent misroute.

## Touches

- backend/packages/data/src/notifications/notificationFanoutJob.ts (the channel
  dispatch inside the delivery loop)

## Scope

### In scope

- Making the existing two-channel dispatch exhaustive and compile-time-checked.

### Out of scope

- Adding a third push channel.

## Acceptance criteria

- A `web_push` registration is still routed to `sendWebPush` with unchanged
  arguments.
- An `apns` registration is still routed to `sendApns` with unchanged arguments.
- Adding a new member to the `PushChannel` union without updating this dispatch fails
  the TypeScript build (verified by the exhaustiveness check compiling only when
  every member is handled).
