## Context

Model tier rationale: One new human-only route over an existing, tested sync function, plus the route-matrix and tenant-isolation entries every route needs; the outbound connection and error mapping are already handled by the sync code.

`syncMcpServerTools` (`backend/packages/data/src/mcp/mcpSync.ts`) connects to a stored MCP server, lists its tools, validates the list and materializes `mcp_tool_registrations`, recording `syncStatus` (`ok` or `error`), `lastSynced` and `syncError` on the server item. It is exported from `backend/packages/data/src/index.ts` and deliberately has no agent or `/mcp` operation. Today nothing calls it: there is no HTTP route, so a user who connects a server has no way to load its tools. Outbound connections already go through the connect-time address check (`docs/adr/2026-10-16-connect-time-outbound-address-checks.md`) and a stdio server is refused unless the tenant allows it.

The "Tools" block of a project's AGENT page lives in `backend/services/semprec-api/src/mcpAgentPageHandler.ts` (`GET`/`PATCH /api/projects/:projectItemId/mcp-grants`, `PATCH /api/mcp-tool-registrations/:id`), mounted by `app.ts` as the fallback listener. MCP servers have no module manifest, so a manifest custom route cannot own a route for them; the route is added by hand next to the MCP grants routes and needs its entries in `backend/services/semprec-api/src/routeMatrix.ts` and `backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts`. The route is a prerequisite of #1976, which queues the same sync after an MCP server card is confirmed, and of the tool-label and default-classification work that runs during sync (#1979, #1983). It is ordered after #1963 because both add entries to the route matrix and the tenant isolation test.

Decision: the route runs the sync inline in the request (it is bounded by the connection factory's timeouts) and answers with the result; there is no job in this issue.

Decision: a connection failure answers 502 `{ error, reason }` where `reason` is the typed `McpConnectionError` reason, a tool-list validation failure keeps its 400 `validation_failed`, and in both cases `syncStatus: error` and `syncError` have already been recorded on the server item by the sync function.

Decision: only a signed-in human session can call it. Agents, run credentials and the `/mcp` endpoint have no path to it.

Shared-file ordering: this issue also waits for #1967 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `error-handling`, `io-hardening` and `testing`.

1. In `mcpAgentPageHandler.ts` add `POST /api/mcp-servers/:id/sync` (path regex like the existing ones, `:id` validated with `assertUuid`). It authenticates with `authenticateRequest`, runs inside `runInTenant(identity.tenantId, ...)`, and calls `syncMcpServerTools(pool, id, { actorId: identity.user.id })`.
2. Success returns 200 `{ toolCount, syncStatus: "ok" }`. A server id that does not exist in the caller's tenant (including another tenant's id) returns the same 404 as an unknown id.
3. Map `McpConnectionError` to 502 as in the Decision; keep the existing `ChokePointError` mapping for the rest. The response never contains a secret or the server's own error text.
4. Add the route to `ROUTE_MATRIX` in `routeMatrix.ts` (`surface: "api"`, `public: false`, `tenancy: "tenant"`) and a handler in the `tenantIsolationRoutes.test.ts` table that proves a foreign id answers like a random id and leaves tenant A's data unchanged.
5. Tests in `backend/services/semprec-api/src/__tests__/mcpAgentPageHandler.test.ts`: an unauthenticated call is refused; a call against a test MCP server with two tools returns `toolCount: 2` and creates two registrations; an unreachable server returns 502 and the item shows `syncStatus: error`; an unknown id returns 404.

## Scope

### In scope

- The human-only sync route, its matrix and isolation entries and tests.

### Out of scope

- Queueing a sync after a confirm (#1976).
- Default risk class and approval from tool annotations (#1979) and AI-suggested tool labels (#1983).
- Rate limiting or de-duplicating concurrent syncs of one server.
- Any change to `syncMcpServerTools`.

## Acceptance criteria

- When a signed-in user posts to `/api/mcp-servers/<id>/sync` for a reachable server, then the response is 200 with the tool count and the server item has `syncStatus: ok`.
- When the server cannot be reached, then the response is 502 with a typed reason and the item has `syncStatus: error`.
- When the id belongs to another tenant or does not exist, then the response is the same 404.
- The route appears in the route matrix and passes the tenant isolation test.
