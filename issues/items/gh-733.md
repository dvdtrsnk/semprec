## Context

Review follow-ups harvested in #728. Four merged pull requests left a branch of the code under test without a test case:

- PR #309 — `backend/packages/module-boundaries/src/__tests__/module-boundaries.unit.test.ts:72`: the test "allows a module reaching into its own internals" has a fixture (`fixtures/modules/alpha/src/usesOwnInternal.ts`), but there is no service counterpart. The `no-service-to-service` rule in `backend/dependency-cruiser.rules.json` exempts a service's own files through the `$1` backreference (`from: ^services/([^/]+)/src/`, `to: ^(?!services/$1/)services/[^/]+/src/`), and no test fails if that backreference breaks.
- PR #310 — `backend/packages/data/src/__tests__/filterCompiler.unit.test.ts:103` and `:118`: the `is_empty` and `in` tests pass a fresh `[]` literal to `compileFilterNode`, so the values bound into `params` are never asserted. Every other test in the file asserts them.
- PR #310 — `backend/packages/data/src/__tests__/filterCompiler.unit.test.ts:86`: the `relation_contains` test only uses `relationSide: "b"`. `compileRelationCondition` (`backend/packages/data/src/views/filterCompiler.ts:36-37`) flips `item_a`/`item_b` by side, and the `"a"` side is never compiled in a test.
- PR #318 — `backend/packages/data/src/__tests__/relationCardinality.test.ts:203`: the one_to_one concurrency test only races the same `item_b` with different `item_a`. The same `item_a` with different `item_b` is covered only serially (line 40).

Issue #653 deletes the `modules/` boundary rules and fixtures and edits `module-boundaries.unit.test.ts`, and #677 edits `filterCompiler.unit.test.ts`; this issue starts from the files as they leave.

## Task

Tests only; no production code changes.

1. Add the fixture `backend/packages/module-boundaries/src/__tests__/fixtures/services/svcA/src/usesOwnInternal.ts`, which imports from `./internal.js` (the existing `svcA` internal module), and a test "allows a service reaching into its own internals" in `module-boundaries.unit.test.ts` asserting that no violation has that file as its importer.
2. In `filterCompiler.unit.test.ts`, give each of the four `compileFilterNode` calls in the `is_empty` and `in` tests its own `params` array and assert its content: `["tags"]` and `["title"]` for the two `is_empty` calls, `["tags", ["a", "b"]]` and `["title", ["a", "b"]]` for the two `in` calls.
3. In `filterCompiler.unit.test.ts`, add a `relation_contains` test with `relationSide: "a"` asserting the SQL `EXISTS (SELECT 1 FROM item_relations r WHERE r.relation_definition_id = $1 AND r.item_a = items.id AND r.item_b = $2::uuid)` and the params `["rel-1", targetId]`.
4. In `relationCardinality.test.ts`, add a test "under concurrency, a losing racer against a one_to_one conflict (same item_a, different item_b) is rejected, not silently corrupted" that calls the existing `assertLosesRaceOnConflict` with winner `a1 → b1` and loser `a1 → b2` on a `one_to_one` relation.
