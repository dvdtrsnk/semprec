## Context

Model tier rationale: One mechanism (a nullable body column rendered at write time and carried to the two push adapters) across a migration, the notification writer and the producers, with existing notification and push fixtures.

A push for an approval request is a title only. `notifications` (migration 0030) has no body column; `writeNotification` in `backend/packages/data/src/notifications/notify.ts` renders only `notification.<kind>.title` from `backend/packages/data/src/notifications/i18n/{cs,en}.json`, and the APNs payload built in `backend/packages/data/src/push/apnsAdapter.ts` is `{ aps: { alert: { title } }, link_href, notification_id }`; the Web Push adapter sends title, link and id only. For approvals the title is `Nástroj „{toolName}“ vyžaduje schválení` (`notification.approval_pending.title`), which does not tell the person what the agent wants to do. The two producers are `preflightDestructiveApproval` (`backend/packages/application/src/genericOperationGateway.ts`) and `createApprovalGatedMcpInvokeTool` (`backend/packages/agent-runtime/src/mcpInvokeTool.ts`).

This issue gives notifications an optional rendered body and uses it for approvals: the title becomes a short fixed phrase ("Semp needs approval"), and the body states what Semp wants to do (from the localisable description snapshot of #1683) followed by one sentence about whether it can be undone (from #1730). It coordinates with the notification classification, preferences and push filtering of #1440, #1441, #1443 and #1466, none of which add a body. #1831 builds the actionable APNs category on top of it.

Decision: the body is rendered once at write time in the recipient's `users.locale`, so a stored notification is stable; it is a pure function of the description key and its parameters and never includes the argument values of an MCP call.

3. 4. Both producers pass action `bodyKey` / `bodyParams` and selected `bodySuffixKey` from the created request snapshot. Recognized generic operations use their existing reversible metadata; MCP has no Semprec undo and selects the cannot-undo sentence regardless of risk class (decision §8). The writer renders action and suffix once in the recipient locale; a request with no description writes no body.
5. Extend `NotificationPushPayload` in `pushSenders.ts` with `body: string | null`, fill it in `notificationFanoutJob.ts`, and send it as `aps.alert.body` in `sendApnsNotification` and as `body` in the Web Push payload (omitted when NULL).

## Scope

### In scope

- The `notifications.body` column, rendering at write time, the new approval title and body entries, and carrying the body in the APNs and Web Push payloads.

### Out of scope

- APNs category, approval request id in the payload and interruption level for approvals: #1831.
- Collapse id, thread id and expiration: #1829; badge: #1891.
- The link target of the notification: #1787.
- Bodies for other notification kinds.

## Acceptance criteria

- A new approval notification has a non-null `body` rendered in the recipient's locale; the title is the fixed "Semp needs approval" phrase (Czech for a Czech user).
- The body ends with the cannot-undo sentence when Semprec has no undo capability for that request; a recognized reversible generic operation ends with the undo sentence. MCP risk classes do not promise external undo.
- The body never contains an MCP argument value.
- The APNs payload has `aps.alert.body` and the Web Push payload has `body` when the notification has one, and neither when it does not.
- A notification of any other kind is written, stored and pushed exactly as before.
