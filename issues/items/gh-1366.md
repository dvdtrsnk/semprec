## Context

Model tier rationale: The change is a single decision document, but it fixes a persisted CRDT data contract and a module-placement choice that every later page issue builds on, so it needs more than mechanical care.

Semprec stores page content as Yjs documents (`docs`, `doc_snapshots`, `doc_updates`; added by #23). Today the only content model is `backend/packages/data/src/docs/blocks.ts`: a block is a `Y.Map` inside `doc.getMap('blocks')` with `sys:id`, `sys:flavour` (any string), `sys:children` (a plain JS array that is overwritten whole) and arbitrary scalar fields. There is no type registry, no ordering, no validation, and `listBlocks` returns map iteration order. `WS /api/sync` (`backend/packages/realtime/src/docSync.ts`) applies any Yjs update a client sends through `mutateYDoc`, so the server cannot reject a malformed block after the fact. Tests use a different convention (a root block `{id: 'root', flavour: 'page'}` plus `'paragraph'` blocks with a `content` field), which collides with the product's `page` block type (a subpage).

The product editor shows these block types: text, three heading levels, bullet, number, todo (with a done flag), quote and page (a subpage link). Every type has an indent level 0-5; bullet markers and numbering such as "1.1" are drawn by the renderer, not stored. Shift+Enter inserts a soft line break inside a block, text carries bold, italic, code and link formatting, and a document is never empty. The same page is routinely open on a phone, a Mac and the web at once, so concurrent editing must converge. On iOS and macOS the editor runs in a WKWebView with the same JavaScript/Yjs code as the web (decision of #23, point 7; no native JSON block API is built for any client).

This issue only records the decisions in an ADR. #1539 implements the shared model from it, #1394 builds the page operation ADR on top of it, and #1393 records where subpages live.

Decisions (the conservative option each time; the ADR records the alternative that was rejected):

- Decision: block order lives in a top-level shared type `doc.getArray('order')` (`Y.Array<string>` of block ids), not in a root block of the `blocks` map and not as a fractional index on each block. Top-level shared types merge by name, whereas two clients creating a root `Y.Map` under the same key concurrently makes Yjs discard one side together with the ids it inserted. The list is flat; hierarchy exists only through the per-block `indent`.
- Decision: the text of a block is a `Y.Text` with the attributes `bold`, `italic`, `code` and `link` (`{href}`). A soft line break is a `\n` character inside the `Y.Text`.
- Decision: every block type keeps its `indent` (0-5), also non-list types. Markdown cannot express indent on non-list blocks; how the Markdown format carries it is decided by #1608, not by the block model.
- Decision: the WebSocket sync path cannot reject part of a Yjs update, so validity is enforced at read time (normalization) and strictly on every server-side write.

## Task

Load `adr-conventions`. Add one ADR under `docs/adr/` named `YYYY-MM-DD-<slug>.md` (date = the day it is written, slug for example `block-model-for-page-documents`), with the frontmatter from `docs/adr/README.md` (`status: accepted`, `area: [backend, web, apple]`). Read the existing ADRs on docs first (`2026-09-12-per-process-doc-sync-subscription-registry.md`) and the ADRs below so it does not contradict them: `2026-09-10-no-speculative-generality-beyond-issue-scope.md`.

The ADR must record, each with the rejected alternative and the trade-off:

1. **Block type registry.** The closed set of type keys: `text`, `h1`, `h2`, `h3`, `bullet`, `number`, `todo`, `quote`, `page`. Field contract per block: `indent` (integer 0-5, default 0), `done` (boolean, meaningful only for `todo`), `text` (`Y.Text`, absent for `page`), `pageId` (string, only for `page`; its meaning is owned by #1393). The block keeps the keys `sys:id` and `sys:flavour` (the type key); `sys:children` is no longer written. The test-only convention (`root`, `page` as document root, `paragraph`) is abandoned.
2. **Document order.** `doc.getArray('order')` as above, why a fractional index was not chosen, and that a document with no entries is read as one empty text block without writing anything.
3. **Inline text model.** `Y.Text` attributes, soft break as `\n`, and that Markdown is only a serialization of this model (owned by #1608).
4. **Validation split.** Strict validation on every server-side write (unknown type key, indent outside 0-5, `done` on a non-todo, `pageId` on a non-page, malformed field types: rejected as a validation error, HTTP 400). Read-time normalization for what arrives through `WS /api/sync`: a duplicated id in `order` keeps its first occurrence; an unknown type key is read as `text` while the stored value stays untouched in Yjs (so a Markdown round trip can preserve it); `indent` is clamped to 0-5; `done` is read as false for non-todo; a block that exists in the map but not in `order` is appended at the end (several such blocks ordered by id, so every client derives the same order); an id in `order` with no block in the map is skipped; an empty document is one empty text block. Reading never modifies the Yjs state.
5. **Module placement.** Pure TypeScript over `yjs`, importable by the server and by the WebView editor. The ADR chooses between a root-level workspace shared with `web/` (today `web/` is a standalone pnpm project with its own lockfile and no `@semprec/*` packages, and `backend/pnpm-workspace.yaml` only covers `packages/*` and `services/*`) and a module outside `backend/`. Whichever is chosen, the module must not import `pg` or any Node-only dependency, and the ADR states the exact directory so #1539 can create it. If the module stays inside `@semprec/data`, the ADR must explain how the WebView editor consumes it without pulling in `pg`.
6. **Existing documents.** Production currently has no documents (the only producer is unreachable). The ADR states the product owner's decision: no sweep and no migration of existing documents; read-time normalization covers any older document. This is the only place the cleanup is recorded; no cleanup issue is planned.
7. **No native block API.** iOS, macOS and Android edit through the WebView; a native JSON block API is not built. Reversing that needs a new ADR.
8. **Concurrency.** The same page open on several devices of one user must converge; list the Yjs behaviors the model relies on (order merges as an array, same-id inserts collapse in normalization).

### Out of scope
