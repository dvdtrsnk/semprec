## Context

Model tier rationale: A new authenticated, long-lived binary WebSocket endpoint with tenant derivation from the session, session revocation, backpressure and shutdown handling is a new cross-process and authentication surface.

The client needs one authenticated channel to `semprec-api` for voice mode. Today the only WebSocket route is `WS /api/sync` (`backend/services/semprec-api/src/syncHandler.ts`, upgrade in `serve.ts`), authenticated by `authenticateRequest` with the same origin check as REST routes, which revalidates the session on a heartbeat and closes sockets of a deactivated tenant. Its protocol (`backend/packages/realtime/src/protocolV1.ts`) has no audio frames, and an overloaded socket is closed rather than buffered (ADR `2026-09-16-realtime-outage-and-backpressure-close-rather-than-buffer`, implemented by `sendWithBackpressure` in `packages/realtime/src/backpressure.ts`). The voice ADR written in #1371 fixes frame formats and limits.

This issue opens the channel and its control protocol, with a handler port that has no speech logic. #1734 plugs the speech and thread logic into it.

Decisions:
- Route: `WS /api/voice`, a second upgrade route beside `/api/sync`; any other upgrade path is still destroyed. The tenant and user come only from the authenticated session, never from frames.
- Binary frames carry audio as the ADR defines; text frames carry JSON control messages. Use the existing ADR closed sets: server `ready`, `transcript` partial/final, `speaking`, `error`, `end`; client `start` (required language, optional thread id), `stop`, `end`. No mute/unmute/closed control.
- Sessions are bounded: maximum duration, idle timeout and maximum frame size from the ADR; exceeding any closes the socket.
- A slow consumer is closed through `sendWithBackpressure`, never buffered.

Shared-file ordering: this issue also waits for #1543 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `error-handling` and `testing`. Add the route to `routeMatrix.ts` with surface `ws`, tenancy `tenant`, and add the tenant isolation test case; both are hotspot files.

1. Add `voiceChannel.ts` in `semprec-api` with an upgrade handler: origin check, `authenticateRequest`, a 401 or 403 on the raw socket before any WebSocket handshake for a bad credential or origin.
2. Define the control message schemas (zod, strict, canonical camelCase) in the shared package or beside the handler, and reject unknown or malformed text frames by closing the socket with a protocol-error code.
3. Define a `VoiceSessionHandler` port (`onStart`, `onAudio`, `onControl`, `onClose`) and a send API through `sendWithBackpressure`; voice enforces 256 KiB including pending send bytes before the unchanged shared gate. Without a configured handler the channel answers `error` and closes.
4. Revalidate the session periodically as `/api/sync` does, close with the session-revoked code when the session or tenant is deactivated, and close all voice sockets on graceful shutdown.
5. Register one API-owned channel beside sync in serve.ts, reuse the existing tenant listener, and close voice/sync before HTTP drain/pools. Follow the accepted single-owner voice ADR: one session per user in the supported single voice-owner deployment, release after active handler and cleanup settle; retain fail-closed admission on timeout/cleanup failure, reject late-auth upgrades after shutdown/deactivation, bound idempotent closure. No distributed admission guarantee or module lifecycle is invented; multiple voice-owning processes are unsupported. Forward stop only through the port; no speech or turn cancellation logic.
6. Tests: an unauthenticated upgrade gets 401 with no WebSocket; a foreign origin is refused; the tenant seen by the handler is the session's; an oversized frame, an unknown control type and an idle session each close the socket; an overloaded consumer is closed with the backpressure code; revoking the session closes the socket; no handler gives `error` then close.

## Acceptance criteria

- When a client without a valid session upgrades, then it gets 401 and no socket is created.
- When the session is revoked or the tenant deactivated, then the voice socket is closed.
- When a client stops reading, then the socket is closed with the backpressure code and nothing is buffered without bound.
- When a frame is oversized or a control message is unknown, then the socket is closed.
