## Context

`walkStoredEntries` (`backend/packages/agent-runtime/src/conversationReconstruction.ts:114-162`) rebuilds a dormant conversation on every wake by loading **every** `unit='session'` run of the conversation (`listSessionAgentRuns`, `backend/packages/data/src/agentRuns/agentRunsStore.ts:256-268`, no `LIMIT`) and **all** their events in one query (`listAgentRunEventsByRunIds`, `agentRunEventsStore.ts:128-138`), then walks them in order and, on each `compaction` event, throws away everything accumulated so far (`entries = parseCompactionPayload(...)`, line 140-146). The rows before the latest compaction checkpoint are therefore read, parsed and discarded on every wake; the cost grows with the conversation's whole lifetime even though only the tail after the last checkpoint is ever used. Both callers — `createReconstructDelegatedHistory` (`delegationRegistry.ts:34-41`) and Semp's own conversation (`sempConversation.ts`) — go through `reconstructConversationHistory`.

#647 makes these wakes happen in production; D1 edits both store files this issue edits. Sibling issue D3b of this batch adds the retention job that deletes the pre-checkpoint rows this issue stops reading.

## Task

1. **Store: one bounded query.** In `agentRunEventsStore.ts` add `listSessionAgentRunEventsFromLastCompaction(client: Pool | PoolClient, filter: SessionAgentRunsFilter): Promise<AgentRunEventRow[]>` (import the `SessionAgentRunsFilter` type from `./agentRunsStore.js`):
   ```sql
   WITH session_runs AS (
     SELECT id, wake_seq FROM agent_runs
     WHERE project_item_id = $1 AND unit = 'session' AND triggered_by = $2 AND parent_run_id IS NOT DISTINCT FROM $3
   ),
   latest_compaction AS (
     SELECT max(e.id) AS id FROM agent_run_events e JOIN session_runs r ON r.id = e.agent_run_id WHERE e.kind = 'compaction'
   )
   SELECT e.id, e.agent_run_id, e.kind, e.payload, e.at
   FROM agent_run_events e JOIN session_runs r ON r.id = e.agent_run_id
   WHERE e.id >= COALESCE((SELECT id FROM latest_compaction), 0)
   ORDER BY r.wake_seq ASC, e.id ASC
   ```
   Docstring: event ids are a global monotonic `bigserial` and one conversation is woken strictly sequentially, so every event after the latest checkpoint has a larger id than the checkpoint and every event before it a smaller one; the result starts with the `compaction` row itself (when any exists) so the caller's walk still resets on it. Uses `agent_runs_session_wake_idx` (migration 0017) and `agent_run_events_run_idx` (0015).
2. **Reconstruction reads only that.** In `conversationReconstruction.ts` `walkStoredEntries`: replace the `listSessionAgentRuns` + `listAgentRunEventsByRunIds` + grouping code (lines 115-138) with one call to the new function and a single loop over its rows (the loop body at 139-158 stays; `parseCompactionPayload(event.payload, event.agentRunId)` supplies the run id). Update the function's docstring to describe the checkpoint-bounded read.
3. **Remove the two now-unused store functions** `listSessionAgentRuns` (`agentRunsStore.ts`) and `listAgentRunEventsByRunIds` (`agentRunEventsStore.ts`) — `grep -rn` confirms `conversationReconstruction.ts` is their only production caller — and their two entries in `publicSurface.test.ts`'s `EXPECTED_RUNTIME_EXPORTS`; add the entry `"listSessionAgentRunEventsFromLastCompaction"`. Keep `SessionAgentRunsFilter` (still the filter type) and its docstring's reference updated.
4. **Tests**:
   - `backend/packages/data/src/__tests__/agentRunEventsStore.test.ts` (integration): three session runs for one filter with events, a `compaction` event on the second run → the new function returns the compaction row followed by the second run's later events and all of the third run's events, in `(wake_seq, id)` order, none of the first run's rows; with no compaction anywhere it returns every event of every session run in the same order; a run of another `triggeredBy`/`parentRunId`/`projectItemId` is never included. Remove or port any case that exercised `listAgentRunEventsByRunIds`.
   - `backend/packages/agent-runtime/src/__tests__/conversationReconstruction.test.ts`: the existing cases (including "resumes from a persisted compaction checkpoint" and "restarting the same walk twice ... produces an identical Entry[] tree") pass unchanged; add one case asserting that the `Entry[]` produced after a checkpoint is identical whether or not the pre-checkpoint rows still exist (delete them directly with `DELETE FROM agent_run_events WHERE id < <checkpoint id>` between the two walks).

## Acceptance criteria

- When a conversation with a persisted `compaction` checkpoint wakes, the reconstruction issues one events query whose result begins at that checkpoint's row; rows of earlier runs and earlier events are not read.
- When the rows preceding the latest checkpoint are deleted, the reconstructed `Entry[]` is byte-for-byte the same as before the deletion.
- When a conversation has no checkpoint, reconstruction produces the same `Entry[]` as today.
- `listSessionAgentRuns` and `listAgentRunEventsByRunIds` no longer exist in `@semprec/data`'s public surface.
