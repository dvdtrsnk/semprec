## Context

Model tier rationale: crash/shutdown cleanup spans durable messages, queue ownership and in-flight settlement.

Restart/shutdown repairs Semp message state; fast queue release and overlapping startups remain explicit deferred production concerns under the linked ADRs.

Preserve non-Semp repair behavior.

Build on queued turns and idle-session close. Shared error classification remains gh1907; manual retry remains gh1926.

Decision: cancel an overdue turn and persist its error; never resume its tool writes after restart.

Read docs/adr/2026-11-06-semp-recovery-does-not-infer-worker-death.md. Graphile0.17.3 locks name pool IDs and has no authoritative death registry here. Immediate dead-only release remains an explicit OPEN/NOT RUN production requirement; this local scope preserves all queue locks and library expiry. Add only nullable semp_messages.error_code text in the next free additive SQL migration.

Use docs/adr/2026-11-06-agents-startup-requires-a-quiesced-predecessor.md: one owning agents instance per database, externally quiesced predecessor; no fence is claimed. Pin repository TimeoutStopSec=120s, named cleanup margin=30s and a 90s turn deadline from shutdown entry.

## Task

Load `state-writes`, `db-migrations`, `error-handling` and `testing`.

1. In `startupRepair.ts` extend the per-tenant repair so that, in the same transaction that closes the orphaned runs, every Semp assistant message with status `running` is set to `error` with `error_code` `interrupted`, and its thread's last-activity time and a `sempThread` invalidation are updated using the helpers delivered by #1395 and the thread tables. A `running` message whose run is not orphaned (it was not a `running` `agent_runs` row) is still repaired, because the in-memory session is always empty after a start.
2. Preserve Graphile-owned job and queue locks at startup: do not infer death from locked_by, age, heartbeat absence, PID, or a missing DB connection, and do not call force_unlock_workers. Immediate dead-only release is deferred OPEN/NOT RUN pending a separately authorized reliable owner-death/fencing protocol; retain Graphile expiry unchanged.
3. In `shutdown.ts`, extend the stop sequence for running Semp turns: abort every in-flight turn that does not finish within the stop window (`TimeoutStopSec` minus a margin kept as a named constant), by aborting the in-flight controllers through `InFlightAgentRuns`, and write each aborted message as `error` with `error_code` `interrupted` before the pool is ended. A turn that finishes inside the window completes normally. Closing idle sessions is #1568 and must keep its position in the sequence. Observe actual per-Semp settlements in the existing in-flight owner; interrupted-write failure rejects shutdown after cleanup even if Runner.stop succeeds. Require successful chat-runner quiescence before consuming the cohort or closing sessions/pool; failed quiescence rejects shutdown under the reconciliation.
4. Tests: a `running` assistant message left by a simulated crash is `error` / `interrupted` after startup repair and the next message of the same thread is processed; queue/job lock identities and timestamps remain unchanged by startup repair; a shutdown with a slow turn aborts it and stores the error before the pool closes. Prove successful runner stop cannot hide a Semp terminal-write rejection, retaining primary and cleanup errors.

## Scope

### In scope

- Repair of `running` Semp messages at startup, preservation of unproven Graphile lane locks, and abort-and-record on shutdown.

### Out of scope

- Closing idle sessions on shutdown and pairing dangling tool calls (#1568).
- Classifying failures by the shared run error codes beyond writing `interrupted` (#1907).
- Raising a problem for the failed reply (#1931) and retrying or regenerating (#1926, #1930).
- Any change to non-Semp runs' repair behavior.

## Acceptance criteria

- After a restart in the middle of a turn, the assistant message has status `error` and `error_code` `interrupted`, and the next message sent to the thread gets a normal reply.
- Startup repair leaves existing Graphile queue/job locks unchanged. Immediate dead-only lane recovery remains OPEN/NOT RUN; no reduced-delay or live-worker death-detection claim is made.
- When shutdown begins during a turn that does not finish in time, the turn is cancelled and its message is `error` before the process exits; a turn that finishes in time is `done`.
- Repair is idempotent: running it twice changes nothing the second time.
