**Model tier:** high

## Context

Model tier rationale: This closes inference channels around an authorization boundary in the filter compiler and the rollup read path, where a missed operator or aggregation reveals sensitive data without returning a sensitive item.

#1810 refuses an agent the items of a sensitive database unless its project has a grant, and hides relation targets in such databases. The agent can still learn about sensitive records indirectly from a database it may read: a `relation_contains` filter over a relation into Health records answers "which projects are linked to record X", and a rollup that counts or aggregates Health records items exposes their number or values on a readable item.

Decision (decided by the product owner): filters and aggregations over a sensitive database are closed for an agent without read access to it, because sensitivity is inherited from the item.

## Task

Load `error-handling` and `testing`.

1. In the filter compiler (`views/filterCompiler.ts`), for an agent actor, refuse with `ForbiddenError` code `forbidden` any filter condition on a relation property whose target database is sensitive and not readable by the agent's project (per `assertAgentDatabaseAccess` of #1810), and any condition on a rollup property whose source database is such a database. This applies to `database.query`, `view.query` and `item.count`. The message names no item content.
2. In the item read paths covered by #1810, return a rollup property whose source database is sensitive and not readable by the agent as `null` with `hidden: true` instead of its value; sorting by such a property for an agent is refused like a filter.
3. Tests: an agent without a grant filtering Projects by `relation_contains` on the Health records relation gets 403; with a read grant the filter works; a project's rollup counting health records is returned hidden to the agent and in full to the human; sorting by it as the agent is refused; filters on relations into non-sensitive databases are unchanged.

## Scope

### In scope

- Refusing agent filters and sorts over relations and rollups into sensitive databases without read access, and hiding such rollup values from agents.

### Out of scope

- The base check and relation target hiding: #1810.
- Inherited sensitivity of linked files, transcripts and Inbox entries: #1999.
- Search filtering: #1842 applies the check itself.
- Human queries, which are unchanged.

## Acceptance criteria

- When an agent without access to Health records filters another database by a relation into Health records, then the result is 403 `forbidden`; with a read grant the same filter returns the matching rows.
- When an agent reads an item whose rollup aggregates Health records, then the rollup value is `null` with `hidden: true`; a human read returns the value.
- When an agent sorts by such a rollup, then the result is 403.
- Filters and rollups over non-sensitive databases behave as before.
