## Context

Model tier rationale: One known mechanism (App Intents) across defined seams: a new exported SDK entry over the outbox of sp-5809efdd-4261-49e1-96bc-a3b42602ec71, a CoreKit bridge, and an intent with an App Shortcut in the app target; no new persistence or authorization contract.

The owner wants to press the iPhone's Action button and capture into the Inbox without composing a shortcut: pick an Inbox type, type a text, and have it in the Inbox of the day, also without a connection. sp-5809efdd-4261-49e1-96bc-a3b42602ec71 delivered the capture outbox that never loses a capture. This issue exposes it to the system as an App Intent offered as an App Shortcut, which the Action button can run directly (Settings › Action Button › Shortcut › Alldots). The scan variant and background sending are later issues of this batch.

The Apple app's minimum is iOS 27 and macOS 26, so the App Intents APIs of iOS 26 (`requestChoice`, `supportedModes`) need no availability checks. App intents declared in the app target run in the app's own process, so they share its Keychain session and its `Application Support/Offline` data directory; CoreKit stays the only door to Kotlin (`apple-swiftui`).

## Task

1. Add an ADR under `docs/adr/` (load `adr-conventions`) deciding that system entry points of the Apple app (App Intents and App Shortcuts) live in the app target, run in the app's process, reach Kotlin only through a CoreKit bridge over a headless SDK entry that needs no scene, and do not start a window's warm-up or sync socket.
2. Export from `:shared:umbrella` an `InboxCaptureSDK(sessionStorage, dataDirectory)` that, over an `AuthenticatedApi` with the process's shared `OfflineLayer` of `dataDirectory`, answers the Inbox types (`GET /api/inbox-types`, so the kept answer serves it offline), adds a capture (text, day, time, type id or none, optional file bytes with name, media type and source) to the outbox of sp-5809efdd-4261-49e1-96bc-a3b42602ec71, and runs `send()`. A `401` there does not end the session; the next window handles it.
3. Add a CoreKit bridge `InboxShortcutCapture` (`@MainActor`) over that SDK with the Keychain session and the same offline directory `SharedScreenModelFactory` uses, mapping failures to `FailureKind`.
4. In the app target add `Sources/Intents/`:
   - `InboxTypeEntity` (`AppEntity`) with an `EntityQuery` whose suggested entities are the types the bridge answers, plus a "No type" entity that is always offered; when the types cannot be read the query answers only "No type".
   - `AddToInboxIntent` (`supportedModes` background): parameters type (`InboxTypeEntity`, asked for when unset), text (`String`, multiline, asked for when unset), day (`Date`, default today). It refuses an empty text, adds the capture with the device's local day and current time `HH:mm`, and answers a dialog that it is saved and will reach the Inbox when the device is online. When nobody is signed in it answers a dialog to sign in in the app. `authenticationPolicy` requires the device to be unlocked.
   - `AlldotsShortcuts` (`AppShortcutsProvider`) offering `AddToInboxIntent` with phrases containing `\(.applicationName)`.
5. Localize every title, description, dialog and phrase in English and Czech through the app's String Catalogs (`canonical-keys`), including an `AppShortcuts.xcstrings`.

## Scope

### In scope

- The SDK entry, the bridge, the intent with its type entity and App Shortcut, the ADR and the copy.

### Out of scope

- Capturing a scanned document (sp-1f163b60-cd6a-4f10-a92d-ccc37075ab3a) and sending in the background (sp-d6d6351a-9488-4b7d-89c4-b1f6157c0182).
- A Control Center or Lock Screen control, a widget extension, Siri-specific responses.
- Android.

## Acceptance criteria

- The Shortcuts app lists "Add to Inbox" for Alldots without composing anything, and the Action button can run it.
- Running it asks for the type from the types the app knows (also offline, from the kept answer) with "No type" always present, then for the text, and the capture is in the outbox with the local day and time and the chosen type (none for "No type").
- An empty text is refused, nobody signed in answers the sign-in dialog, and a capture made offline reaches the Inbox once the app is online.
- The bridge maps each failure of the SDK to its `FailureKind`, and the SDK test covers types offline from a kept answer and a capture written to the outbox.
