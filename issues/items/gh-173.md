## Context

Issue #243 delivered the runtime layer of the boundary matrix (the `semprec_data`/`semprec_side` roles). This slice delivers the static layer: dependency-cruiser previously only guarded `modules/X` ↛ `modules/Y`; here it is closed into a complete forbidden-dependency matrix between `packages/`, `modules/`, and `services/`. #174 builds on it; wiring the checks into a pipeline belongs to #188. This prerequisite intentionally precedes #91.

## Task

Extend `.dependency-cruiser.cjs` with the complete matrix — nine rules, with narrow documented entry exceptions:

- `no-module-to-module` (existing; keep it).
- `no-service-to-service`, `no-service-to-module`, `no-module-to-service` — the five processes talk only through Postgres, never by importing each other or module code across the service boundary.
- `core-knows-nobody` — core packages import no module or service code.
- `pi-only-in-agent-runtime` — pi-agent-core is imported only inside `packages/agent-runtime`.
- `agent-runtime-only-in-agents` — `packages/agent-runtime` is imported only by `semprec-agents`; the API process never runs the agent loop.
- `no-deep-imports` — packages are imported only through their entry points.
- `items-store-private` — the privileged SQL layer (the item store) is visible only inside `packages/data`; this is the CI half of the choke-point write control whose runtime half is #243.

Each rule has one failing fixture demonstrating it triggers, and the documented valid entry imports pass.

## Scope

### In scope

- The nine rules, their fixtures, and necessary documentation.

### Out of scope

- Runtime database roles — delivered by #243.
- CI execution — #188.
- No feature behavior changes.

## Acceptance criteria

- Each forbidden import has a failing fixture and valid entry imports pass.
- API cannot import the agent loop and pi-agent-core cannot escape agent-runtime.
- Code outside `packages/data` importing the item store fails `items-store-private`.
