## Context

This issue builds on #166; #168 is the next sequential slice of the `observability` batch.

## Task

Add `AsyncLocalStorage` trace context. Mint UUID `traceId` at HTTP/WS entry, scheduler ticks, new agent runs, and mail-sync cycles. Bind agentRunId, job name/id, and mailbox id when available. Define one zod queue envelope: `enqueueJob` auto-stamps the active trace and `registerTask` restores it; public job callers cannot provide it. Forward it as `x-trace-id` to the AI gateway and log it beside agent_run_id.

## Scope

### In scope

- Task deliverables, migrations, integration, automated tests, and necessary documentation.

### Out of scope

- No OpenTelemetry collector or distributed tracing stack.

## Acceptance criteria

- One cross-process flow retains one traceId.
- Every entry point creates a valid UUID.
- Public producers cannot omit or spoof the queue trace.
- Concurrent contexts remain isolated.
