**Blocked by:** #978

## Context

#978 added the tenant scope, exported from `@semprec/shared`:
- `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)` and `currentTenantScope()`.
- `runAsSystem` inside a tenant scope throws `TenantScopeConflictError`.
- Every `withTransaction`, `pool.query` and `pool.connect()` on a `createPool` pool sets the GUC `app.tenant_id` from the scope.
- With no scope, the call logs `tenant_scope_missing` in `warn` mode, or throws `TenantScopeMissingError` when `SEMPREC_TENANT_SCOPE=strict`.

From #968:
- the global table `tenants(id uuid PK, status text CHECK IN ('provisioning','active','suspended','deleting'), created_at, status_changed_at)`;
- `users.tenant_id uuid NULL UNIQUE REFERENCES tenants(id)` and `users.role` (`'admin' | 'member'`, default `member`);
- `app_sole_tenant()`, which returns the only tenant's id while exactly one `tenants` row exists, and NULL otherwise.

Today authentication knows nothing about tenants:
- `AuthenticatedIdentity` is `{ session, user }` (`backend/packages/data/src/auth/authActions.ts:192-195`).
- `verifySessionToken` (`authActions.ts:203-212`) checks the session and the user, then bumps `last_seen_at`.
- `authenticateRequest` (`backend/services/semprec-api/src/authHandler.ts:79-87`) is the one path from a request to an identity. It runs `verifySessionToken` in an unscoped `withTransaction`.
- Every adapter-mounted route runs `createAdapterRequestListener` (`backend/services/semprec-api/src/adapter/adapterRoute.ts:78-122`), which authenticates at `:85` and calls the handler at `:88`. That covers:
  - the generic database, property, view and item routes (`backend/services/semprec-api/src/app.ts:65-70`);
  - every module custom route (`app.ts:60` → `adapter/customRouteMount.ts:22-32` → `adapter/routeTable.ts:62`).
- The auth listener's own routes (`authHandler.ts:124-249`) touch only identity tables: `users`, `sessions`, `login_attempts`, `password_reset_tokens` and `push_subscriptions`. All are global tables.

Tests create users with `createUser` and no tenant binding. 25 test files authenticate such users. While only one tenant can exist, that is tenant zero. Step 2's fallback keeps those users authenticating into tenant zero exactly the way scope-less code already reaches tenant zero (row-level security's sole-tenant default). Once a second tenant exists, the fallback yields nothing. #1067 later makes `users.tenant_id` NOT NULL.

## Task

Load `io-hardening` (an authentication edge), `error-handling` (uniform 401 vs. real failures) and `state-writes` (the read inside `verifySessionToken`'s transaction).

1. **Tenant lookup.** In `backend/packages/data/src/tenancy/tenantsStore.ts` (created by #968, which today holds only `getSoleTenantId`), add `getUserTenantBinding(client, userId): Promise<{ tenantId: string; status: TenantStatus; role: UserRole } | null>`:
   - Declare `export type TenantStatus = "provisioning" | "active" | "suspended" | "deleting"` in the same file.
   - `UserRole` is the `"admin" | "member"` type #968 added to `backend/packages/data/src/auth/types.ts`.
   - It runs one query: `SELECT t.id, t.status, u.role FROM users u JOIN tenants t ON t.id = COALESCE(u.tenant_id, app_sole_tenant()) WHERE u.id = $1`.
   - Check `status` and `role` against their unions. An unknown value throws an `Error` naming the column. It is never mapped onto a 401.
2. **Identity and verification.**
   - `AuthenticatedIdentity` gains `tenantId: string` and `role: UserRole`.
   - `verifySessionToken` calls `getUserTenantBinding` after the user lookup, in the same transaction and before `touchSessionLastSeen`. It throws the same `UnauthorizedError()` as for a bad token when there is no binding or the status is not `active`. In that case `last_seen_at` is not bumped.
3. **`authenticateRequest`** runs its `withTransaction` inside `runAsSystem("authenticate")`.
4. **Auth listener** (`createAuthRequestListener`). The whole `handleRequest` body (login, password-reset request and consume, logout, revoke, session) runs inside `runAsSystem("auth")`.
   **Session response.** `GET /api/auth/session` returns `user` with `role` set from `identity.role`. This is an additive field. This issue adds no other field to any response.
5. **Adapter.** In `createAdapterRequestListener`, after the identity is resolved, run body parsing, parameter extraction and the handler call inside `runInTenant(identity.tenantId, …)`. The existing error mapping stays outside and unchanged. Because module custom routes and the generic resource routes compile to this listener, they all run in the caller's tenant.
6. **Tests.** Extend:
   - `backend/packages/data/src/__tests__/authActions.test.ts`;
   - `backend/services/semprec-api/src/__tests__/authHandler.test.ts`;
   - `backend/services/semprec-api/src/adapter/__tests__/adapterRoute.test.ts`.

   Add `backend/services/semprec-api/src/__tests__/adapterTenantScope.test.ts`. It drives the real dispatcher (`createDispatcher`) on a `createPool(process.env.TEST_DATABASE_URL)` pool.

   Suspending tenant zero in a test is `UPDATE tenants SET status = 'suspended'`, restored in `afterEach`. Integration files run sequentially (`backend/vitest.integration.config.ts`, `fileParallelism: false`).

## Scope

### In scope
- Tenant and role on the authenticated identity.
- The active-tenant requirement.
- System scope for session verification and the auth listener.
- Tenant scope for every adapter-mounted route.
- `role` in the session response.

### Out of scope
- Bespoke listeners (notifications, approvals, agent runs, MCP, files, blobs, schema, setup, healthz, Graph webhook) → #981.
- The WebSocket upgrade → #1025.
- Refusing login for a suspended tenant, and admin-only routes → #1041, #1037.
- Adding `tenantId` to `AuthenticatedActor` or `toActor`. The scope carries the tenant, and no consumer needs it on the actor.
- Making `users.tenant_id` NOT NULL → #1067.

## Acceptance criteria

All criteria are integration tests (`*.test.ts`).

- **Bound user.** `verifySessionToken` for a user bound to an active tenant returns `tenantId` equal to that user's `users.tenant_id` and `role` equal to `users.role`.
- **Unbound user.** A user with `tenant_id` NULL authenticates with `tenantId` equal to the sole tenant's id, because exactly one `tenants` row exists.
- **Non-active tenant.** When the user's tenant is `suspended`, `provisioning` or `deleting`, a request with a valid session to `GET /api/auth/session` and to `GET /api/databases` gets 401. Each body is byte-identical to that route's 401 for a garbage token, and the session's `last_seen_at` is unchanged.
- **Session response.** `GET /api/auth/session` returns `user.role` equal to `users.role`.
- **Adapter scope.** A handler mounted via `createAdapterRequestListener` observes `currentTenantScope()` equal to `{ kind: "tenant", tenantId: <caller's tenant> }`. Without credentials it gets 401, and the handler is not invoked.
- **Error mapping.** A `ChokePointError` thrown inside a mounted handler still maps to its status and body. An unexpected error still gives the generic 500.
- **Strict mode, adapter routes.** With `SEMPREC_TENANT_SCOPE=strict` and an authenticated session, every `surface: "api"`, `public: false` entry of `ROUTE_MATRIX` (`backend/services/semprec-api/src/routeMatrix.ts`) served by an adapter-mounted route (generic resource routes and module custom routes) returns the same status as under `warn`, never a 500.
- **Strict mode, auth routes.** With `SEMPREC_TENANT_SCOPE=strict`, every `/api/auth/*` route (login, password-reset request and consume, logout, revoke, session) returns the same status and body as under `warn`.
- **Lookup inside a tenant.** `authenticateRequest` called inside `runInTenant(...)` rejects with `TenantScopeConflictError`, which pins the "authenticate before entering a tenant" order.
