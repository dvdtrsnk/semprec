## Context

Model tier rationale: One additive enrichment of existing timeline Event items through a single batched lookup over the invitations database, using the existing timeline fixtures; no new write path or ownership contract.

#1944 lets the user answer an incoming invitation `accepted` or `tentative`; both create the same Event, linked from the invitation through its one-directional `event` relation, and the answer can be changed later. The calendar timeline (#1717, `GET /api/calendar/timeline`, `readCalendarTimeline` in `backend/packages/data/src/calendar/timelineRead.ts`) returns Event items but nothing about how the user answered.

Decision (product owner): an Event the user answered with "maybe" is shown in the calendar as unconfirmed attendance. The client never computes this; the timeline returns it.

## Task

Load `io-hardening` and `testing`.

1. In `readCalendarTimeline`, add `attendance` to every Event item, in the full and the `compact` shape: `"tentative"` when a live invitation with `status` `tentative` links to the Event through its `event` relation, otherwise `null`. Read it for all Events of the range in one batched query over the invitations database (#1901) in the caller's tenant scope; no per-item queries.
2. Tests (in `backend/packages/data/src/calendar/__tests__`): an Event created by answering `tentative` has `attendance` `"tentative"` in both shapes; after the answer is changed to `accepted` it is `null`; an Event without an invitation and an Event of an `accepted` invitation are `null`; a trashed invitation does not mark its Event; the number of queries does not grow with the number of Events; another tenant's invitations never mark this tenant's Events.

## Acceptance criteria

- Given the user answered "Sprint review" `tentative`, when the timeline for 22 Oct 2026 is read, then the Sprint review Event carries `attendance` `"tentative"`, also with `shape=compact`.
- When the user changes the answer to `accepted`, then the same Event carries `attendance` `null`.
- An Event without a linked invitation carries `attendance` `null`.
- The number of queries of the timeline read does not grow with the number of Events in the range.
