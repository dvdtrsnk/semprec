**Blocked by:** #499, #498

## Context

After #499, `backend/packages/data/src/chokePoint/chokePoint.ts` is grouped into per-destination blocks, but `createChokePoint()` still returns one 660-line object literal. This issue splits that literal into per-domain section factories that already carry their **final** names. Each factory sits in its destination's block, and `createChokePoint` combines them through a merge helper that detects key collisions.

After this issue, extracting a domain (issues #507–#516) moves one block out of the file and replaces it with an import of the same function name. The `mergeOps(...)` call in `createChokePoint` never changes again. Object spread would silently let a later section's method overwrite an earlier one with the same name; `mergeOps` turns that into an error.

This issue introduces the composition pattern, so it also adds the ADR recording it.

## Task

1. **`backend/packages/data/src/chokePoint/chokePointDeps.ts`** (new): `export interface ChokePointDeps { pool: Pool; computedKeyRegistry: ComputedKeyRegistry; viewTypeRegistry: ViewTypeRegistry; queueAffinity: ActionQueueAffinity }`. Import the types from where `chokePoint.ts` imports them today.
2. **Use `mergeOps`** from `backend/packages/data/src/chokePoint/mergeOps.ts` (#498): it merges the section objects and throws an `Error` naming any key that appears in more than one of them.
3. **Split the object literal** returned by `createChokePoint` into these functions. Each is a plain function in the named block of `chokePoint.ts` (last in that block), takes `deps: Pick<ChokePointDeps, …>` with exactly the fields its methods use, and returns an object literal with exactly the listed methods, moved verbatim:

| Function | Block | `Pick<ChokePointDeps, …>` | Methods |
|---|---|---|---|
| `createDatabaseOps` | `databaseOps.ts` | `"pool"` | `createDatabase`, `archiveDatabase`, `restoreDatabase`, `renameDatabase`, `getDatabase`, `listDatabases`, `createInlineDatabase` |
| `createPropertyOps` | `propertyOps.ts` | `"pool" \| "computedKeyRegistry"` | `listProperties`, `getProperty`, `getPropertyByKey`, `findPropertiesByKey`, `createProperty`, `renameProperty`, `updatePropertyConfig`, `changePropertyType`, `updateProperty`, `deleteProperty` |
| `createRelationPropertyOps` | `relationPropertyOps.ts` | `"pool" \| "computedKeyRegistry"` | `createRelationProperty` |
| `createRelationOps` | `relationOps.ts` | `"pool"` | `createRelation`, `updateRelation`, `deleteRelation` |
| `createItemWriteOps` | `itemWrites.ts` | `"pool" \| "queueAffinity"` | `createItem`, `updateItem` |
| `createItemReadOps` | `itemReads.ts` | `"pool"` | `getItem`, `findItem`, `findItemIncludingDeleted`, `getItemPath`, `listItems`, `countItems` |
| `createItemTrashOps` | `itemTrash.ts` | `"pool" \| "queueAffinity"` | `softDeleteItem`, `restoreItem`, `purgeExpiredTrashSubtree` |
| `createViewOps` | `viewOps.ts` | `"pool" \| "viewTypeRegistry"` | `createView`, `getView`, `listViewsByDatabase`, `listCuratedViews`, `patchView`, `deleteView`, `addViewItem`, `removeViewItem`, `reorderViewItem`, `listViewItems` |
| `createViewQueryOps` | `viewQueryOps.ts` | `"pool"` | `queryView`, `queryDatabaseItems`, `queryViewItems` |

   The `Pick` column is today's reading of which parameters each group uses. If a method in a group uses a parameter not listed, add that field to the group's `Pick` and note it in the pull request description. The method→group assignment itself is fixed. If a method exists that is not in this table, stop with `Relay-Step-Status: blocked` and name it.

4. **`createChokePoint`** keeps its exact signature and defaults. It builds `const deps: ChokePointDeps = { … }` from its parameters and returns `mergeOps(createDatabaseOps(deps), createPropertyOps(deps), createRelationPropertyOps(deps), createRelationOps(deps), createItemWriteOps(deps), createItemReadOps(deps), createItemTrashOps(deps), createViewOps(deps), createViewQueryOps(deps))`, one argument per line. `export type ChokePoint = ReturnType<typeof createChokePoint>` stays.
5. **Add the ADR** `docs/adr/2026-09-24-choke-point-composed-from-domain-modules.md` (load the `adr-conventions` skill first; `status: accepted`, `area: [backend]`). It records:
   - `createChokePoint` composes per-domain section factories through `mergeOps`, which rejects duplicate keys, and each factory receives a `Pick` of `ChokePointDeps`;
   - one module per domain under `chokePoint/`; domain modules never import one another (enforced by #496), and there are no import cycles in `chokePoint/` or `rollup/` (enforced by #497);
   - no barrel: callers import a symbol from the module that owns it, and `chokePoint.ts` only composes;
   - a lint cap of 900 lines per production file (#529 for `backend/`, #530 for `web/`);
   - a **"where things moved" table** that maps every top-level declaration of the pre-split `chokePoint.ts` to its destination file, taken from #499's table plus the rows `ChokePointDeps → chokePointDeps.ts`, `mergeOps → mergeOps.ts`, and the nine section factories → their block's file. Accepted ADRs that still cite `chokePoint.ts` (their bodies are immutable) stay traceable through this table, so it must be complete from the first version: the ADR body cannot be amended later.
