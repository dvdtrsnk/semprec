**Blocked by:** #699

## Context

`backend/services/semprec-transcribe/src/shutdown.ts` `createGracefulShutdown` (lines 4-24) awaits `options.queueRuntime.stop()`, which is graphile-worker's `Runner.stop()` — a *graceful* shutdown that waits for the in-flight job to finish. `deploy/systemd/semprec-transcribe.service` sets no `TimeoutStopSec`, so systemd's default (`DefaultTimeoutStopSec`, 90 s) applies: on every deploy restart with a transcription in flight, systemd SIGKILLs the process after 90 s. graphile-worker then treats the job as locked by a dead worker and only reclaims it once `locked_at` is four hours old (`sql/000018.sql` `remove_job`, `interval '4 hours'`); the recording's transcript sits in `processing` for four hours, and a multi-hour pipeline that is killed repeatedly across a few deploys never finishes.

The pipeline itself is checkpoint-safe: `createTranscriptionTask` (`backend/services/semprec-transcribe/src/transcriptionTask.ts` lines 796-870) runs `createTranscriptionSteps` in order (lines 672-690), each step is a no-op once its checkpoint exists, and `runAsrStep` (lines 372-444) checkpoints every 20-minute chunk (`writeComputed(... TRANSCRIPTION_ASR_COMPUTED_KEY ...)`) before starting the next. A retried job repeats at most the unfinished chunk. The bounded units of work are one ffmpeg run (`FFMPEG_TIMEOUT_MS` = 5 min, `mediaNormalization.ts` line 19) and one gateway call (`REQUEST_TIMEOUT_MS` = 10 min, `audioGatewayClient.ts` line 72); one ASR chunk is an extraction plus a call. graphile-worker 0.17 hands every handler `helpers.abortSignal`, which `Runner.stop()` aborts `gracefulShutdownAbortTimeout` (5 s) after it begins — the shutdown signal the task can observe between checkpoints. Re-adding a running job's `jobKey` clears the running row's key and queues a fresh job (`add_jobs`, lines 104-116): returning normally afterwards completes (deletes) the old row and leaves the fresh one, with `attempts = 0`, to resume after the restart — so an interrupted run consumes none of the job's three attempts. `enqueueTranscriptionJob` (`backend/packages/data/src/transcription/transcriptionJob.ts` lines 50-57) is that enqueue.

Depends on sibling issue F2b, which edits the same unit file's `[Unit]` section and adds the assertion block in `provision.test.sh` this issue extends.

## Task

1. **Unit** — in `deploy/systemd/semprec-transcribe.service` `[Service]`, add `TimeoutStopSec=960` after `RestartSec=5s` with a comment: one ASR chunk worst case = ffmpeg extraction (5 min cap) + gateway call (10 min cap) + checkpoint write, and the task exits at its next checkpoint once `runner.stop()` has begun. In `deploy/provision.test.sh`, add `grep -qx 'TimeoutStopSec=960' "$TEST_ROOT/systemd/system/semprec-transcribe.service"` directly after F2b's `StartLimit*` assertion loop.
2. **Task** — in `transcriptionTask.ts`:
   - Extend `TranscriptionJobHelpers` (lines 762-764) with `abortSignal?: AbortSignal` (optional so the existing tests' `{ job: {...} }` helpers keep compiling) and pass it into the step context as `TranscriptionStepContext.shutdownRequested: () => boolean` (`() => helpers.abortSignal?.aborted === true`).
   - Add `export class TranscriptionInterruptedError extends Error` (message names the file item id and the step index) thrown by a `throwIfShutdownRequested(context, where)` helper. Call it (a) in the main loop before each step (`for (const step of transcriptionSteps) { throwIfShutdownRequested(context, ...); await step(context); }`) and (b) in `runAsrStep` at the top of each chunk iteration, before `extractAudioChunkBytes`.
   - Export `enqueueTranscriptionJob` from `backend/packages/data/src/index.ts` by adding it to the existing `./transcription/transcriptionJob.js` export block (lines 127-132); add the name to `__tests__/publicSurface.test.ts` if it pins the list.
   - In the handler's `catch`, before the existing lock/budget branches: `if (err instanceof TranscriptionInterruptedError) { await withTransaction(pool, (client) => enqueueTranscriptionJob(client, { fileItemId })); logger.info({ transcriptId, fileItemId }, "Shutdown requested; re-enqueued the transcription to resume from its checkpoints"); return; }` — no `recordTranscriptionFailure` (the row stays `processing`, nothing failed), and the normal return lets graphile-worker complete the superseded row. Document this in the `createTranscriptionTask` docstring (lines 776-795).
3. **Tests** — `backend/services/semprec-transcribe/src/transcriptionTask.test.ts` (existing, integration):
   - "stops at the next ASR checkpoint when shutdown is requested and re-enqueues itself": a recording with three ASR chunks, a `gatewayClient.transcribe` fake that aborts an `AbortController` (passed as `helpers.abortSignal`) after the first chunk resolves; the task resolves without throwing; the ASR checkpoint holds exactly chunk 0; `graphile_worker.jobs` holds one `transcriptionJob` row for the file with `attempts = 0`; the Transcriptions row's `item_automation.status` is still `processing`/`pending` with no error; a second run with a fresh, unaborted signal transcribes chunks 1 and 2 only and finalizes.
   - "stops between steps when shutdown is requested": abort before the merge step (after ASR completes) — the summarize gateway fake is never called and one fresh job is queued.

## Scope

### In scope
- The stop bound, the between-checkpoint shutdown check, the self re-enqueue, and the tests.

### Out of scope
- Aborting an in-flight ffmpeg or gateway call early (they finish or hit their own caps; the bound accounts for that).
- `semprec-transcribe`'s `shutdown.ts` pool-end bound and signal wiring (unchanged).
- Pool timeouts (F2a) and restart limits (F2b).

## Acceptance criteria

- When `semprec-transcribe` receives SIGTERM while a multi-chunk ASR step is running, the process exits within one chunk's duration (never more than 16 minutes), the chunk that was in flight is checkpointed, and a fresh `transcriptionJob` for the same file is queued with `attempts = 0`; after the restart it resumes from the next chunk and the Transcriptions row never shows an error for the interruption.
- When SIGTERM arrives while no transcription is running, shutdown completes as before.
- `bash deploy/provision.test.sh` asserts `TimeoutStopSec=960` on the installed transcribe unit.
