## Context

Model tier rationale: One read-only route in an existing listener over an indexed column, with no new lifecycle or contract beyond input validation.

Silent pushes are throttled by iOS and may never arrive, so when the app opens it must reconcile: it asks which of the user's notifications were resolved since it last looked, and hides them. The column and its index come from #1463. Notification routes live in `backend/services/semprec-api/src/notificationsHandler.ts` (unread list, visit, mark all read).

Decisions: the route is `GET /api/notifications/resolved?since=<ISO time>`; `since` is required and must be an ISO-8601 timestamp (400 otherwise); it returns the ids of the caller's own notifications with `resolved_at > since`, oldest first, capped at 500 (a client that gets exactly 500 asks again with the last time); it returns ids only, plus `resolvedAt` per id.

Shared-file ordering: this issue also waits for #1555 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening` and `testing`.

1. Add `listResolvedNotificationIds(client, userId, since, limit)` to `notifications/notificationsStore.ts`.
2. Add the route to `notificationsHandler.ts` with validation and `NO_STORE` caching; response `{ resolved: [{ id, resolvedAt }] }`.
3. Add a `routeMatrix.ts` entry (tenancy `tenant`), an entry in `ROUTE_HANDLER_FILES` of `chokePointWriteBoundary.unit.test.ts`, and cover it in `tenantIsolationRoutes.test.ts`.
4. Add tests: only resolved notifications after `since` are returned; another user's are not; a missing or malformed `since` is 400; the cap.

## Scope

### In scope

- `GET /api/notifications/resolved` for the caller.

### Out of scope

- Setting `resolved_at`: #1463; silent pushes: #1826.
- Client behavior when it receives the list.

## Acceptance criteria

- When `since` is before a notification was resolved, then that notification's id is returned.
- When another user's notification was resolved, then it is not returned.
- When `since` is missing or not an ISO timestamp, then the response is 400.
