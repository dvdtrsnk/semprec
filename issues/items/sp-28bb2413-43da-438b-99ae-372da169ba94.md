## Context

Model tier rationale: Touches the shared collection ViewModel state, a new repository write, the CoreKit bridge, two
Apple feature screens and a shared DesignSystem component on iOS and macOS, with tests on every layer.

The server publishes `facetBarProperty` per database in `GET /api/schema` (sibling 01/04) and Projects declares
`tags`, a user-owned `multi_select`. The mobile filter sheet already lists every filterable `multi_select` with
facet counts and builds `FacetSelection.OneOf` (`in`) selections (`CollectionLayouts.kt filterProperties`,
`CollectionFilters.kt`). `FieldRowView` already edits a `multi_select` through `choiceMenu`. There is no client for
`POST /api/properties/:id/options` yet. Tasks has a capsule `FilterChip` (`mobile/apple/Modules/Features/Tasks`).
The collection engine is governed by
`docs/adr/2026-11-16-collection-screens-are-one-schema-driven-engine-and-file-previews-use-imageio-and-coregraphics.md`.

## Task

1. Shared: decode `facetBarProperty` into `CollectionDatabase`; when present, `CollectionViewModel` loads that
   property's facet with the screen and after each change of query, and exposes the bar (chips with label, color,
   count, selected) in its state. Toggling a chip changes the same `selections` the filter sheet edits.
2. Shared: a use case and repository write that adds an option to a property (`POST /api/properties/:id/options`)
   with a typed failure.
3. Apple: move the capsule chip into DesignSystem and use it from Tasks and from a new bar above the collection list,
   shown when the bar has at least one chip.
4. Apple: a Tags section in `ProjectSettingsSheet` choosing the project's tags, with creating a new tag by name;
   the project detail shows the tags as chips; the collection row subtitle includes the project's tags.
5. Copy keys in en and cs; accessibility identifiers for the bar, each chip and the tags section.

## Scope

### In scope

- The tag bar, tag editing with creating a tag, and showing tags in the detail and the row.

### Out of scope

- Android (it has no collection screens).
- Removing area code (sibling 03/04).
- Renaming, recoloring or deleting tags.

## Acceptance criteria

- With a schema whose Projects declares `facetBarProperty: "tags"`, the collection state carries one chip per tag
  with its facet count; a database without the declaration has no bar.
- Selecting two chips sends a query with `{type:"in", property:"tags", value:[a,b]}` combined by `and` with the
  active quick filter, and the filter sheet shows the same two as selected; clearing in the sheet unselects the chips.
- Adding a tag in project settings calls the options route, then sets it on the project; a refused add surfaces a
  failure and does not set a value.
- The project detail shows the project's tags; the row subtitle includes them.
- The bar is hidden when there are no tags.
- `mobile/scripts/verify` passes for the shared and Apple steps on iOS and macOS.
