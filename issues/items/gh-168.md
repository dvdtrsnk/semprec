## Context

This issue builds on #167; #169 is the next sequential slice of the `observability` batch.

## Task

Add `process_heartbeats(process text primary key,pid integer,version text,started_at timestamptz,beat_at timestamptz)`. Each process UPSERTs every 15 seconds from its event loop. Keys are api, agents, transcribe, ai-gateway, and mailsync:<mailboxItemId>. Derive expected rows as four fixed processes plus active mailboxes; stale means older than 60 seconds. Add unauthenticated `GET /healthz` returning only {"status":"ok"} with 200 when SELECT 1 and agents freshness pass, otherwise 503.

## Scope

### In scope

- Task deliverables, migrations, integration, automated tests, and necessary documentation.

### Out of scope

- No sd_notify/WatchdogSec.
- Mail progress is not inferred from process beat.

## Acceptance criteria

- All process types refresh their own identity row.
- Expected mail-sync rows follow mailbox activation.
- A frozen loop becomes stale.
- healthz checks only PostgreSQL and agents and leaks no detail.
