**Blocked by:** #1676
**Model tier:** high

## Context

Model tier rationale: One transaction creates several items and their documents and rewrites several blocks of another document in place, so a partial failure would leave pages without blocks or blocks pointing at missing pages; it extends a catalog operation that every transport exposes.

In the editor the user can restyle selected blocks into subpages: each selected block becomes its own empty subpage and its text becomes the subpage's name. #1676 adds the hidden `pages` database, plain-text `text` on `page` blocks in the block model, `normalizePageTitle`, and the catalog operation `page.createSubpage` (`backend/packages/data/src/docs/pageOperations.ts`) that creates one new subpage, with output `{ pages: [{ pageItemId, docId, blockId }] }`. The shared block model (#1610) refuses every conversion to or from `page` with a typed error, so this needs a dedicated operation step. This issue was split out of #1676 so that each issue carries one mechanism.

Decisions:
- `fromBlockIds` converts blocks in place: the block id stays, its type becomes `page`, its plain text becomes the title and the new page is empty. Blocks that are already `page` blocks are rejected.
- With `fromBlockIds`, `afterBlockId` and `title` are ignored; the pages are returned in document order.

## Task

Load `state-writes`, `error-handling`, `canonical-keys` and `testing`.

1. Block model: in the module directory fixed by the ADR of #1366, add `convertBlocksToPages(doc, ids, pageIdFor)` as a single Yjs transaction that changes the type of non-page blocks to `page`, sets `pageId` and keeps the plain text as the title. Keep every operation of #1610 refusing page conversions as it does today.
2. Extend the strict input schema of `page.createSubpage` with the optional `fromBlockIds: string[]` (at least one id, no duplicates); the output shape is unchanged.
3. In the operation of #1676, when `fromBlockIds` is present: in the same transaction, every id must be an existing non-page block of the parent document (otherwise a `ValidationError` on `fromBlockIds` and nothing is written); create one empty Pages item and its document per block, with the title from the block's plain text through `normalizePageTitle`, then convert all blocks with `convertBlocksToPages` in one `mutateDocWithClient` call with the caller's origin. Return the created pages in document order.
4. Tests: `fromBlockIds` with three selected text blocks creates three empty pages whose titles are the blocks' text, in one document write, and the block ids are unchanged; an already-page block, an unknown block id and a duplicate id are rejected with nothing written; a block whose text is longer than the title limit is rejected; a failure in the document write leaves no Pages item; another tenant's parent is rejected.

### Out of scope

- The Pages database and creating one new subpage: #1676.
- Breadcrumbs of subpages: #2014.
- Converting a page block back into another type: #1876.
- Agent approval classification of page operations: #1844.

## Acceptance criteria

- When `page.createSubpage` is called with `fromBlockIds` listing three text blocks, then they become three empty subpages whose titles are the blocks' text, the block ids stay the same, and the response lists the three pages in document order.
- When a listed block is already a `page` block, is unknown, or is listed twice, then the call is rejected and nothing is written.
- When the document write fails, then no Pages item and no document is created.
