**Blocked by:** #97

## Context

Users need to compose without losing reading context and reply with correct structured recipients and sender alias.

## Task

Add a floating, minimizable new-message window independent of inline thread reply. Support structured To/Cc/Bcc, reply, and reply-all from the stored envelope. Provide a plain From dropdown over registered aliases. Default it to the persisted receiving alias of the message being replied to, otherwise the current folder/account context, otherwise the primary address. Saving uses `email.draft.create`; sending uses `email.send`. Preserve unsent content when minimized, when send is rejected, and across reading-pane navigation.

## Scope

### In scope

- Compose lifecycle, recipients, sender selection, draft/save/send integration, and inline reply.

### Out of scope

- New SMTP behavior, contact autocomplete beyond existing People data, and rich signature management.

## Acceptance criteria

- Compose can be minimized and restored without data loss.
- Reply-all is derived from structured envelope fields.
- From defaults follow the specified fallback order and remain user-overridable.
- A rejected send leaves an editable draft and visible error.
