## Context

Model tier rationale: A manual-run route with an atomic check-and-enqueue against a queue whose job key does not merge with a running job, plus a new fire-job discriminator that changes who is recorded as the actor of a run, so races and attribution must be right.

`heartbeat.trigger` (`backend/packages/data/src/scheduler/heartbeatAgentTools.ts`) already lets an agent run an automation now: it looks the heartbeat up, rejects a disabled one and an `onItemEvent` one with a tool result (`HEARTBEAT_DISABLED_ERROR`, `HEARTBEAT_EVENT_TRIGGERED_ERROR`), and enqueues a fire job with `manualHeartbeatFireJobKey` (`schedulerStore.ts`, replace mode). That key merges repeated triggers only until the first job starts; for a running job the queue deletes the key and a second job is created (`jobKeyWasCleared` in `backend/packages/queue/src/index.ts`, comment at `manualHeartbeatFireJobKey`). `HeartbeatEventTriggeredError` (409 `heartbeat_event_triggered`) exists in `backend/packages/data/src/errors.ts` and the error contract but nothing throws it, and there is no code for a disabled heartbeat. The fire job payload parser in `scheduler/sweep.ts` requires exactly one of `occurrenceId`, `itemId`, `triggeredByRunId`. `coreAgentRunAction` (`scheduler/actions.ts`) creates the run with `parentRunId = context.triggeredByRunId`.

The product shows "Run again" in the automation's thread header and the failed-run retry (#1908) needs the same enqueue. This issue adds the HTTP route and extracts the shared enqueue so the agent tool, HTTP and retry use one implementation.

Decisions: the response is `202 {jobKey, activeRun}` with `activeRun` null until a worker creates the run; two taps while a run is active produce one run and a 409 `heartbeat_running` carrying the current `activeRun` in `details`; a disabled automation answers 409 `heartbeat_disabled`; a manual run from a person has no parent run and the actor is that person.

Shared-file ordering: this issue also waits for #1441 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `io-hardening`, `testing`, and `adr-conventions`.

1. Extract `enqueueManualHeartbeatFire` in `heartbeatAgentTools.ts` (lookup, enabled check, `onItemEvent` rejection, enqueue) and use it from the `heartbeat.trigger` tool unchanged in behavior.
2. In the same transaction as the enqueue, check whether a run of this heartbeat is running (an `agent_runs` row with this `heartbeat_id` and status `running`) or a fire job is already waiting; if so throw `HeartbeatRunningError` (409 `heartbeat_running`, `details.activeRun`). A disabled heartbeat throws a new `HeartbeatDisabledError` (409 `heartbeat_disabled`); an `onItemEvent` heartbeat throws the existing `HeartbeatEventTriggeredError`. Add the two new classes to `errors.ts`.
3. Add `heartbeat_disabled` and `heartbeat_running` to `ITEM_ERROR_CODES` and `ITEM_ERROR_STATUS_BY_CODE` (409 each) in `errorContract.ts`, additively.
4. Add a fourth fire-job discriminator `triggeredByUserId` to the payload parser in `sweep.ts` (still exactly one discriminator) and to `ActionContext`; `coreAgentRunAction` creates such a run with `triggeredBy: 'heartbeat'`, `parent_run_id` null and the actor set to the user.
5. Add `POST /api/heartbeats/:id/trigger` returning `202 {jobKey, activeRun}`; invalidate `sempThread` of the heartbeat's tick thread when the worker creates the run. Register as a custom route in `schemaCoreModuleManifest.ts` (`docs/adr/2026-09-11-module-manifest-custom-routes.md`), the route matrix, `ROUTE_HANDLER_FILES` and the tenant isolation test. A heartbeat of another tenant gives not found.
6. Tests: a second trigger while the first run is running gives 409 `heartbeat_running` and still one run; a disabled heartbeat gives 409 `heartbeat_disabled`; an `onItemEvent` heartbeat gives 409 `heartbeat_event_triggered`; the created run has `parent_run_id` null and the user as actor; the agent tool behaves as before.

## Scope

### In scope

- The shared enqueue, the route, the two new error codes, the `triggeredByUserId` discriminator and run attribution.

### Out of scope

- Retrying a failed run: #1908 (uses the shared function).
- The thread header fields `canTrigger` and `activeRun`: #1562.
- Listing and switching automations: #1910, #1551.
- Changing the queue so a running job also merges triggers.

## Acceptance criteria

- POST on an enabled automation returns 202 with `jobKey`; the worker creates a run with `parent_run_id` null.
- Two POSTs in a row while the first run is running result in one run and a 409 `heartbeat_running` with the current `activeRun` in `details`.
- POST on a disabled automation returns 409 `heartbeat_disabled`; the code is part of the closed error contract.
- POST on an `onItemEvent` automation returns 409 `heartbeat_event_triggered`.
- The agent tool `heartbeat.trigger` keeps its previous results.
