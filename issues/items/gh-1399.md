**Blocked by:** #1371
**Model tier:** high

## Context

Model tier rationale: A second streaming route through the gateway with interruptible output and cost reservation per text batch, sharing the accounting path with every other provider call.

Voice mode and read-aloud need text spoken back as audio. There is no text-to-speech anywhere in the backend today; the gateway serves `/internal/complete`, `/internal/pi/messages`, `/internal/diarize` and `/internal/transcribe` (`backend/services/semprec-ai-gateway/src/app.ts`), and accounting is in `backend/packages/ai-gateway/src/gateway.ts`. The decisions of the voice ADR written in #1371 (provider, output audio format, limits) apply.

This issue adds a streaming text-to-speech adapter and route to the gateway. #1734 uses it for spoken answers in voice turns and #1626 for reading a stored message aloud.

Decisions:
- Route: loopback `POST /internal/tts/stream`, internal token and caller tenant as for the other internal routes. The request carries one or more sentences of text and a voice name; the response streams audio chunks in the ADR's output format (chunked HTTP response), so the caller can start playback early.
- Cost is known up front from the number of characters: reserve a price estimate per request before calling the provider, settle with the actual audio seconds and cost (operation `voice_synthesize`). Text is not logged.
- Interruption: when the caller disconnects or aborts, the provider request is aborted and the row is settled with what was produced, or failed if nothing was.

## Task

Load `ai-gateway`, `io-hardening`, `error-handling` and `testing`.

1. Define a speech synthesis provider interface in `audioProviders/types.ts` (input text, voice, abort signal; output an async stream of audio chunks plus final duration) and implement it for the provider chosen in the ADR.
2. Add `/internal/tts/stream` to `GATEWAY_ENDPOINTS` and the dispatcher in `app.ts`, with a handler that validates the body (non-empty text up to a character limit from the ADR, known voice), checks token and tenant, applies a concurrency limit, and streams audio through the accounting helper.
3. Add a synthesis accounting helper in `packages/ai-gateway/src/gateway.ts` (reserve estimate, settle with real `audioSeconds` and cost, fail on error) using the existing lock and tenant-active check.
4. Add a client function for this route in `backend/packages/ai-gateway-client`.
5. Tests with a fake provider: audio chunks stream before the provider finishes; the reservation is settled with the real duration; a budget refusal returns the usual budget error before any provider call; an abort stops the provider and leaves no `reserved` row; invalid text or voice is a 400; the concurrency limit refuses the extra request.

## Scope

### In scope

- The streaming text-to-speech route, provider adapter, accounting and caller client.

### Out of scope

- Speech-to-text: #1396.
- The voice channel to the client: #1546.
- Splitting an answer into sentences and driving synthesis from a running turn: #1734.
- Caching synthesized audio of stored messages: #1626.

## Acceptance criteria

- When text is sent, then the first audio bytes are returned before the whole text is synthesized.
- When the tenant has no budget left, then the call is refused with the standard budget error and the provider is not called.
- When the caller aborts, then the provider request is aborted and no row stays `reserved`.
- The synthesized text never appears in logs.
