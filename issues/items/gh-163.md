**Blocked by:** #162, #121

## Context

Low-volume data and Yjs traffic are complete. Agent runs require a persistent turn-level cursor plus an intentionally ephemeral typing stream.

## Task

Implement `agent:watch { runId, afterEventId }` and `agent:unwatch`. Authorize the run, replay `agent_run_events` where `agent_run_id` matches and `id > afterEventId` in ID order, then switch atomically to live `agent:event` delivery without a replay/live gap. Emit committed turn-level events (`turn_start`, completed message, tool use/result, `turn_end`, run status) as thin NOTIFY references and fetch their durable row. Send `message_update` token deltas only through `semprec_agent_stream` as `agent:delta` to watching sockets, splitting encoded NOTIFY payloads below approximately 7,500 bytes. Do not persist deltas; the completed message event is the recovery copy. Thin run-status events may also use the implicit user channel.

## Scope

### In scope

- Watch lifecycle, authorization, cursor replay/live handoff, persistent events, ephemeral/chunked deltas.

### Out of scope

- Agent execution, event production semantics, or persistence of token deltas.

## Acceptance criteria

- Watching from a cursor yields every later durable event exactly in order with no replay/live gap.
- Unwatched or unauthorized runs leak neither events nor deltas.
- Losing deltas affects only typing animation; the final completed text recovers from `agent_run_events`.
