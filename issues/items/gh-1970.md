**Model tier:** high

## Context

Model tier rationale: It sends user documents to an external model through the gateway, adds a cache column with a single writer and changes the proposal computation's inputs and ordering, so privacy, cost control and idempotency all need to be exact.

A photo of an invoice ("Faktura za obklady, zaplatit do pátku") should become a proposal with the supplier, amount, dates and a file name filled in: "Siko Koupelny a.s., 4 820 CZK, due 23 October". Today nothing reads attachments. The proposal computation (#1434) receives text, the capture time and workspace context (#1987); #1965 makes a reduced JPEG of each image attachment; #1381 lets the gateway carry an image; #1392 registers the gateway operation `inbox_attachment_extraction` (it requires the Semprec project item for cost attribution).

This issue adds the extraction call, its cache, and its use as an input to the proposal computation. It is the only owner of invoice extraction. The fields it produces feed the proposal's file name and type, date, company and the due date of a follow-up task; they are generic document fields, so a step a later module adds can use them without a new extraction. The person can still edit every extracted field.

Decisions:
- Only image attachments with a reduced copy are extracted. PDFs and audio are skipped here.
- The structured output is `{ documentType: receipt | invoice | contract | businessCard | other, supplier, ico, amount, currency, issueDate, dueDate, suggestedFileName, suggestedFileType }`, each field nullable. Amounts are plain numbers and `currency` is an ISO code; dates are `YYYY-MM-DD`. The person's text is passed as a hint, together with the capture date and time zone from #1987 so "by Friday" resolves to a date.
- The result is cached on the attachment in a new column `extraction`, written only by the API runtime. A rerun for the same attachment and blob reuses it and makes no gateway call. A failed call is not cached.
- A gateway failure, including a budget rejection, is treated like any other compute failure (#1485); the proposal is not computed from a half-extracted state.
- The gateway call is made outside any database transaction.
- The tick does not start while an image attachment has no metadata yet (#1965); the metadata job re-triggers it when it finishes.
- A supplier is matched to an existing company only by the proposal computation (#1488); a new company is not created here.

## Task

Load `ai-gateway`, `state-writes`, `db-migrations`, `error-handling` and `testing`.

1. Migration `backend/packages/data/src/db/migrations/NNNN_inbox_attachments_extraction.sql (next free ordinal at commit time)`: add nullable `extraction jsonb` to `inbox_attachments`. Additive only.
2. Add `backend/packages/data/src/inbox/attachmentExtraction.ts` with the response schema (JSON Schema for the gateway and a matching validator), `extractAttachmentDocument(deps, attachment, hint, captureContext)` and a store function that writes `extraction` once. It reads the reduced blob from storage, sends it as an image block with operation `inbox_attachment_extraction`, temperature 0, the Semprec project item id, and validates the answer.
3. In the proposal computation of #1434, before the model call for an Inbox item, run the extraction for each eligible attachment (up to 4), outside the transaction, and pass the stored results to the computation as part of its input (#1987); when an eligible attachment has no metadata yet, skip the tick for now.
4. Tests with a stubbed gateway: for a photo with the answer `{ amount: 4820, currency: "CZK", dueDate: "2026-10-23" }` the computation input contains those values and the request to the gateway carries the image block and the person's text; a second run makes no gateway call; a failed call is not cached and records a compute failure; a PDF and an audio attachment make no call; a request for another tenant's attachment is impossible (the id is checked against the Inbox item's tenant); a photo without metadata postpones the tick.

## Scope

### In scope

- The extraction call for image attachments, its schema, cache column and use as proposal computation input.

### Out of scope

- The gateway's image transport: #1381; operation registration: #1392.
- Metadata and the reduced image: #1965.
- Matching a supplier to an existing company, new companies and relations: #1488.
- Using the amount to build a step of its own; a later module that needs one adds it.
- Extraction from PDFs and audio.
- Editing extracted fields by hand on the card.

## Acceptance criteria

- When a photo is attached and the stubbed gateway returns `amount` 4820, `currency` CZK and `dueDate` 2026-10-23, then the computation input carries those values and the gateway request contains the image and the person's text.
- When the extraction was already stored, then no second gateway call is made.
- When the gateway call fails, then nothing is cached and the compute failure is recorded.
- When the attachment is a PDF or audio, then no extraction call is made.
- When an image attachment has no metadata yet, then the tick waits and runs again after the metadata job.
