**Blocked by:** #1373, #1766
**Model tier:** medium

## Context

Model tier rationale: One column, one store function and one handler call, with sanitization rules to get right, across the migration, the single-writer store and the MCP handler.

Runs started through MCP (`triggered_by = 'mcp'`, authenticated with a run credential from `agent_run_mcp_credentials`) have no record of which client the person connected with: `agent_runs` (written only by `backend/packages/data/src/agentRuns/agentRunsStore.ts`, per the single-writer ownership ADR `docs/adr/2026-09-10-single-writer-ownership-model.md`) has no such column, and `initialize` is not handled today. After #1373 the handler answers `initialize` with the client's `clientInfo` in its params.

This issue stores the client's self-reported name on the run so clients can show "from Claude Desktop" next to a request or a run. The source recorded on approval requests (#1766) and the agent run detail (#1805) read it; a null name is shown by the client as a generic "MCP client".

Decision: the name is display text only. It is trimmed, stripped of control characters, truncated to 64 characters, never logged as content, and never used for authorization.

## Task

Load `db-migrations`, `state-writes`, `io-hardening` and `testing`.

1. Add `backend/packages/data/src/db/migrations/NNNN_agent_runs_mcp_client_name.sql` (next free ordinal at commit time): `ALTER TABLE agent_runs ADD COLUMN mcp_client_name text CHECK (mcp_client_name IS NULL OR char_length(mcp_client_name) <= 64)`.
2. In `agentRunsStore.ts` add `mcpClientName: string | null` to `AgentRunRow` (read in `AGENT_RUN_ROW_COLUMNS` and the mapper) and a new `setAgentRunMcpClientName(client, runId, name)` that sanitizes as above and writes the column; an empty result after sanitizing writes NULL.
3. In `mcpHandler.ts`, when `initialize` arrives with a run credential (actor has `runId`), call `setAgentRunMcpClientName` with `params.clientInfo.name` inside a transaction in the tenant scope. A repeated `initialize` overwrites the previous value. A non-string or missing name writes nothing. A human session (no `runId`) writes nothing.
4. No SQL on `agent_runs` in `mcpHandler.ts`.

## Scope

### In scope

- The `mcp_client_name` column, its store writer and reader, and the write on `initialize` for run-credential callers.

### Out of scope

- Exposing the name on approval requests as the source: #1766; on the run detail as trigger: #1805.
- The `initialize` response itself: #1373.
- Names for runs not started through MCP.

## Acceptance criteria

- After `initialize` with `clientInfo.name = "Claude Desktop"` using a run credential, the run's `mcp_client_name` is `Claude Desktop`.
- A second `initialize` with another name replaces it.
- A name longer than 64 characters is stored truncated to 64; a name of only control characters or whitespace leaves NULL.
- `initialize` with a human session changes no run and answers normally.
- A run credential can only write the name of its own run, never another run's, and never across tenants.
- The migration applies to a database with existing runs, leaving the column NULL for them.
