## Context

Model tier rationale: one mechanism (a conditional command step added to existing Relay workflows) across known seams; the host toolchain already passes `mobile/scripts/verify`, but the change-detection condition must not skip the step on a stale local `develop`, which needs care.

#1292 added the mobile platform under `mobile/` with one pipeline entry point, `mobile/scripts/verify` (see `mobile/docs/verify.md`). Relay's workflows verify a change with `pnpm run verify` in `backend/` and `web/` only, so a Relay run that changes `mobile/` reaches review and merge without ever building it. `.bb/skills/implement-issue/SKILL.md` and `.bb/AGENTS.md` tell the implementing agent to run the mobile pipeline itself, but no Relay step enforces it.

This issue changes `.relay/**`, a protected path. It is **maintainer-implemented and must not be dispatched to Relay**; it carries no `agent:ready`.

The Mac mini that runs Relay already has what the pipeline needs, and `mobile/scripts/verify` passes there: Xcode 27.1 in `/Applications`, which verify selects through `DEVELOPER_DIR`; JDK 21; the Android SDK; Tuist 4.213.0; SwiftLint 0.65.1.

## Task

Add a `verify-mobile` command step to each Relay workflow that has the `verify-backend`/`verify-web` pair: `implement-issue`, `fix-review-findings`, `merge-pull-request` and `recover-blocked-issue` in `.relay/workflows/`.

- Place it right after `verify-web`. On failure it goes to the same fix step with the same `max-rounds` as the existing verify steps.
- It runs `mobile/scripts/verify architecture shared android apple` from the worktree root. The device steps report NOT RUN; no device is reserved.
- It runs only when the branch changes a path under `mobile/` relative to its merge base with the remote `develop`, freshly fetched. Otherwise it passes without building anything, and its output says that no `mobile/` change was found. A stale local `develop` must never make it skip.
- Give it a timeout that covers a cold Gradle and Xcode build on the host, and note the measured cold duration in the step's comment.
- Update the workflows' `fix-verify` prompt text so that a failing `verify-mobile` sends the agent to `mobile/build/verify/<run>/` and the `mobile-verify` skill.

Then make every document that says no Relay verify step builds `mobile/` true again: `.bb/AGENTS.md`, `.bb/skills/implement-issue/SKILL.md` and `.claude/skills/finish/SKILL.md`.

### Touches

## Scope

### In scope
- The conditional `verify-mobile` step in the four workflows, its timeout and its fix routing.
- The prompt and document updates listed in Task.

### Out of scope
- Reserving devices in Relay runs. `--ios-simulator` / `--android-serial` stay manual, and the device steps report NOT RUN.
- The GitHub Actions mobile jobs (#1293).
- Any change to `mobile/scripts/verify` itself.

## Acceptance criteria
- A Relay run on an issue whose change touches `mobile/` runs `verify-mobile`. A failing mobile build routes to the fix step, and the next round re-runs `verify-mobile`.
- A Relay run whose change touches nothing under `mobile/` completes `verify-mobile` without invoking Gradle or xcodebuild, and its step output says so.
- With the local `develop` branch older than the remote one, a change under `mobile/` is still detected.
- A clean Relay run that touches `mobile/` reaches `review:ready` with `verify-mobile` passed. The run log shows the verify summary.
- No instruction file or skill still says that no Relay verify step builds `mobile/`.
