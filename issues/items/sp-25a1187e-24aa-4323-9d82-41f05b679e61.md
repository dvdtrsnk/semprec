**Model tier:** medium

## Context

Model tier rationale: One mechanism (downloading or reading an attachment and previewing it) across a shared repository, two screens' state and a SwiftUI preview; no new persistence contract.

The owner cannot open the attachments of Inbox items in the app: neither in the diary's Inbox section (captured in the app or through the Action-button shortcut) nor while processing Inbox cards. The server lists attachments with `blobId`, `name` and `mimeType` for diary entries and, after sp-24905ae8-d2fc-497d-ad29-5edd63187feb, for cards whose source is an Inbox item; `GET /api/blobs/:id` serves the bytes (`AuthenticatedApi.download` exists). An entry that waits in the device outbox (sp-256f9fba-cc77-4439-ba05-e29662015dbb, status `waiting`) has its file only on the device, in the outbox's `.bin`.

## Task

1. Decode the attachments of diary Inbox entries (`JournalInboxDto`) and of card sources (`InboxCardDtos`) with `blobId`, `name`, `mimeType`; expose them in `JournalInboxState` and in the card state as a list of attachments (id, name, media type).
2. Add a shared use case that answers a local file path for an attachment: for a server attachment it downloads `GET /api/blobs/:blobId` to the app's cache directory under the attachment's name (sanitized, with an extension for its media type when it has none), reusing an already downloaded file; for a `waiting` capture it copies the outbox's bytes there. Failures map to `FailureKind`; offline, a server attachment not downloaded before fails with `UNREACHABLE`.
3. Apple: tapping an attachment in the diary's Inbox row and in an Inbox card (the card's source section) opens it with SwiftUI's `quickLookPreview`; while it loads a progress indicator shows, and a failure shows the existing failure message. Several attachments are listed by name. Copy in English and Czech.

## Scope

### In scope

- Listing and opening attachments in the diary's Inbox and in Inbox cards, online and for waiting captures.

### Out of scope

- Thumbnails, editing or deleting attachments, Android UI.

## Acceptance criteria

- A diary Inbox entry with a PDF from the shortcut opens in Quick Look; so does a photo captured in the diary, and a file of a card whose source is an Inbox item.
- A `waiting` capture's file opens offline from the device.
- A second open of the same attachment does not download again; a download failure shows the failure message and nothing opens.
- Shared tests cover the download, the reuse, the waiting-capture copy, the offline failure and the name sanitizing; CoreKit tests cover the new mappings.
