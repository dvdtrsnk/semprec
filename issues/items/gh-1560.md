## Context

Model tier rationale: This changes which agent run events a compaction checkpoint and the retention job may delete, so a wrong grouping silently destroys another conversation's history; it is a wide destructive-data contract.

Thread-main conversations use #1452 thread_id rather than the shared project key. Delegated sessions inherit thread_id but remain separate by parent-run identity. Reconstruction, checkpoints and retention must not mix these groups; preserve non-thread behavior and the one existing tenant/thread/wake index. #1565/#1566 remain separate.

## Task

Load `state-writes`, `testing` and `db-migrations`.

1. Extend `SessionAgentRunsFilter` so a thread conversation is `{ threadId, triggeredBy: 'user', parentRunId: null }`. The existing project-item form stays valid for non-thread sessions. In `listSessionAgentRunEventsFromLastCompaction` (and every query that takes the filter) select by `thread_id` with predicates aligned to the existing tenant/thread/wake index and tenant RLS when `threadId` is given, otherwise as before. The planner chooses the physical plan; do not force it.
2. Reconstruction and `persistCompaction` accept the session filter. Use `withTransaction`, existing `getAgentRun(client,id,true)` and same-client insertion. Match the complete session key including `unit=session`; thread filters exclude delegates. Refuse mismatches without an event; missing/foreign targets are indistinguishable. Thread mains require a thread filter; omission keeps the legacy path for other runs, and supplied legacy filters exclude thread mains. Pass the filter from `SempConversation` and handle compaction rejection in its existing try/failRun: close the new run, preserve the original error and do not prompt. Initial status-publication failure stays deferred. Compute entries before locking; no provider work in the transaction.
3. Change `agentRunEventsRetention.ts`: group the main conversations of threads by `thread_id` (runs with `thread_id IS NOT NULL`, `triggered_by = 'user'`, `parent_run_id IS NULL`); group all other session runs as before by `(project_item_id, triggered_by, parent_run_id)` excluding those thread main conversations. Keep the rule that nothing after the last checkpoint of a group is deleted and nothing is deleted when a group has no checkpoint.
4. Tests (real database): two threads of one tenant each reconstruct only their own events; a checkpoint written in thread A does not hide, and retention does not delete, thread B's events or a delegated session's events; retention still removes old events before a thread's checkpoint and keeps everything after it; non-thread sessions behave as before. Event content is never logged.
