## Context

Model tier rationale: This introduces two new tenant-isolated tables with row-level security, composite foreign keys, grants and purge-order obligations, which is a new isolation contract that must be right the first time.

Semp (the assistant) has no notion of a conversation thread today. `backend/packages/agent-runtime/src/sempConversation.ts` keeps one in-memory conversation per tenant, and no service constructs it in production. Messages exist only as `agent_run_events` rows (migration `0015_agent_run_events.sql`), which `backend/packages/data/src/agentRuns/agentRunEventsRetention.ts` deletes after 30 days before the last compaction checkpoint. The text that wakes a conversation lives only in `agent_runs.task`. No table for threads or messages exists in migrations 0001-0086.

The product needs several parallel threads per user: free chats, a thread attached to one Inbox item, and a thread attached to one automatic task (heartbeat), each with a durable message history that survives event retention. This issue adds the two tables that hold them. It adds no behavior: nothing reads or writes the tables yet.

Later issues build on it: #1452 links agent runs to threads, #1543 serves thread detail and history, #1620 writes messages, #1395 publishes realtime invalidations, #1729 lists threads, #1557 writes tick threads, #1769 generates titles, #1772 posts system messages, #1744 attributes gateway calls to messages, #1932 lists answers, and #1854 adds threads to global search.

Decision: the table has no `user_id` column; the owning user is derived through `getTenantUserId`, as for other tenant-scoped tables.

## Task

Load `db-migrations`, `canonical-keys` and `testing`.

1. Add one migration creating `semp_threads`:
   - `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`, `tenant_id uuid NOT NULL DEFAULT app_tenant_default() REFERENCES tenants(id)`.
   - `kind text NOT NULL CHECK (kind IN ('chat','item','tick'))`.
   - `title text NULL` (set only for `chat`), `title_source text NOT NULL DEFAULT 'auto' CHECK (title_source IN ('auto','user'))`.
   - `subject_inbox_item_id uuid NULL` and `subject_proposal_id uuid NULL` (item threads only; no foreign key, because `items` is partitioned; the proposal id stays NULL until the capture has a proposal card and is filled in later).
   - `heartbeat_id uuid NULL` (tick threads only) with a composite foreign key `(tenant_id, heartbeat_id)` to `project_heartbeats`, `ON DELETE RESTRICT`, mirroring `agent_runs.heartbeat_id`.
   - `created_at timestamptz NOT NULL DEFAULT now()`, `last_activity_at timestamptz NOT NULL DEFAULT now()`.
   - A CHECK tying kind to its columns: `item` requires `subject_inbox_item_id` and no heartbeat, `tick` requires `heartbeat_id` and no subject, `chat` has neither.
   - `UNIQUE (tenant_id, id)`; partial unique indexes `(tenant_id, heartbeat_id) WHERE kind = 'tick'` and `(tenant_id, subject_inbox_item_id) WHERE kind = 'item'`; index `(tenant_id, last_activity_at DESC, id DESC)`.
2. In the same migration create `semp_messages`:
   - `id uuid` primary key, `tenant_id` as above, `thread_id uuid NOT NULL` with composite foreign key `(tenant_id, thread_id)` to `semp_threads (tenant_id, id)` `ON DELETE CASCADE`.
   - `role text NOT NULL CHECK (role IN ('user','assistant','system'))`, `text text NULL` (Markdown).
   - `system_key text NULL` and `system_params jsonb NULL`, used only for `system` messages (an i18n key, never user-facing text); CHECK that they are NULL for other roles.
   - `context jsonb NOT NULL DEFAULT '[]'` (the shape is defined by #1369; this issue stores it opaquely).
   - `reply_to_message_id uuid NULL` with a composite self-referencing foreign key `(tenant_id, reply_to_message_id)` to `semp_messages (tenant_id, id)`; an assistant message points at a user or system message.
   - `agent_run_id uuid NULL` with composite foreign key `(tenant_id, agent_run_id)` to `agent_runs`, `ON DELETE RESTRICT` (add `UNIQUE (tenant_id, id)` on `agent_runs` only if it does not already exist).
   - `event_from_id bigint NULL`, `event_to_id bigint NULL` (the `agent_run_events` range of the turn, always read together with `agent_run_id`).
   - `status text NULL CHECK (status IN ('queued','running','done','error'))`, used only for assistant messages.
   - `created_at`, `updated_at timestamptz NOT NULL DEFAULT now()`; `UNIQUE (tenant_id, id)`; index `(tenant_id, thread_id, created_at DESC, id DESC)`.
3. For both tables: `COMMENT ON TABLE ... IS 'semprec:tenancy=tenant'`, `ENABLE ROW LEVEL SECURITY` with the restrictive `tenant_isolation` and permissive `tenant_rows` policies exactly as in `0078_tenant_exports.sql`, grants per `docs/operations/database-roles.md`, and foreign keys created already valid (no `NOT VALID`; the tables are empty).
4. Register both tables in `backend/packages/data/src/tenancy/tenantPurgeOrder.ts` so tenant purge deletes messages before threads and runs after anything they reference; verify there is no foreign key cycle. Confirm tenant export follows the table comment, and extend its fixtures only if the export enumerates tables explicitly.
5. Tests: tenant A cannot read or write tenant B's threads or messages (RLS); a second tick thread for the same heartbeat and a second item thread for the same Inbox item are rejected; an item thread can be created with `subject_proposal_id` NULL; the kind/column CHECK rejects mismatches; deleting a thread cascades its messages; messages older than 30 days survive `agentRunEventsRetention`; the tenancy invariant tests pass for both tables.

Message text must never be written to logs; nothing in this issue logs it.

## Scope

### In scope

- The two tables, their constraints, indexes, RLS, grants, comments and purge-order registration.
- Schema-level tests.

### Out of scope

- The `agent_runs.thread_id` column: #1452.
- Any store, route, realtime message or job that reads or writes the tables: #1543, #1620, #1395.
- Full-text search indexes on messages and titles: #1783.
- Defining or validating the `context` shape: #1369, #1682.

## Acceptance criteria

- When a request runs as tenant A, then no `semp_threads` or `semp_messages` row of tenant B is visible or writable.
- When a second tick thread is inserted for the same heartbeat, or a second item thread for the same Inbox item, then the insert fails on the unique index.
- When an item thread is inserted with a null `subject_proposal_id`, then it succeeds.
- When a thread is deleted, then its messages are deleted; when an agent run referenced by a message is deleted, then the delete is refused.
- When the event retention job runs, then no `semp_messages` row is removed.
- The tenancy invariant checks and the tenant purge order test pass with both tables present.
