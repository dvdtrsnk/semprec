## Context
Review of pull request #418 found that `close()` in `backend/packages/realtime-client/src/syncClient.ts` (currently around lines 238-244) clears the reconnect timer and calls `socket.close()`, but never resets `reconnectAttempt` to `0`. Only `ws.onopen` resets it. If a caller calls `close()` and a later reconnect path reads `reconnectAttempt` before the next successful `onopen`, the stale attempt count from the previous connection's backoff is used.

## Task
- In `close()` in `backend/packages/realtime-client/src/syncClient.ts`, reset `reconnectAttempt` to `0` alongside clearing the reconnect timer and calling `socket.close()`.

## Touches
- backend/packages/realtime-client/src/syncClient.ts (the `close()` method only)
- backend/packages/realtime-client/src/__tests__/syncClient.unit.test.ts (one new test case for the reset)

## Scope
### In scope
- Resetting `reconnectAttempt` inside `close()`.

### Out of scope
- Any other reset or backoff logic in `syncClient.ts`.

## Acceptance criteria
- After calling `close()`, `reconnectAttempt` is `0`, verified directly or through its effect on the next reconnect delay.
