## Context

Model tier rationale: This adds a header contract between two services and a per-call capture of an HTTP response that must never be shared between concurrent runs, with an uncertain integration seam in the pinned pi client, so the higher tier is chosen.

Agent turns use the gateway pi-messages path rather than the gateway-client package. Its budget 403 must become the typed budgetExceeded run failure from #1446, distinct from modelError, without relying on response text or sharing response state between calls. Reply-turn use is #1907.

Decision: the signal is a response header, not the response text. The gateway adds `x-semprec-error-code: budget_exceeded` to the 403; the body is unchanged so existing consumers keep working.

## Task

Load `ai-gateway`, `error-handling`, `io-hardening` and `testing`.

1. In `piMessagesHandler.ts`, when the reservation raises `BudgetExceededError`, answer the existing 403 with the additional response header `x-semprec-error-code: budget_exceeded`. Extend that file's local `sendJson` with optional headers. Body and status do not change.
2. In `modelComposition.ts`, make the `streamFn` capture, for each call, the HTTP status and the `x-semprec-error-code` header of the gateway response (pi-ai's per-request response callback if the pinned version offers one, otherwise a wrapped `fetch` for the provider). The captured state belongs to one call: it must not live in a variable shared by concurrent sessions, and it is read back for exactly the assistant message that call produced. Header names are compared case-insensitively.
3. In `piAgentSession.ts`, make `assertModelSucceeded` throw `AiBudgetExceededError` when the failing assistant message came from a call whose captured status is 403 and whose captured header is `budget_exceeded`. In every other failure case keep throwing the `modelError` error from #1446.
4. Add `AiBudgetExceededError` (extends `AgentRunError`, code `budgetExceeded`, fixed message "AI budget exceeded", no provider or request text) to `backend/packages/data/src/agentRuns/agentRunErrorCodes.ts` and export it from the data barrel, so the existing classifier closes the run with `budgetExceeded` and reply-turn code can reuse the same class.

## Acceptance criteria

- When the gateway refuses a turn for an exhausted budget, then the 403 response has `x-semprec-error-code: budget_exceeded` and the same JSON body as before.
- When an agent run's turn is refused for the budget, then the run is closed `error` with `errorCode` `budgetExceeded`.
- When the model call fails with a 403 without that header, a 500, a network error or a provider error, then the run's code is `modelError`.
- When two sessions run concurrently and only one is refused for the budget, then only that run gets `budgetExceeded`.
- The thrown error has only the fixed safe message `AI budget exceeded`; the composed failed run stores `errorCode: "budgetExceeded"` and `result: "AI budget exceeded"`. Result and captured diagnostics contain no response body, request/user text, provider exception message or credential; diagnostics may carry the stable code, operational identifiers and fixed safe text. Other failures keep their existing result text.
