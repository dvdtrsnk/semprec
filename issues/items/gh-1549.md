## Context

Model tier rationale: One known mechanism (an additive select-option change on a schema-locked system database through seed, per-tenant cutover and i18n) with an existing cutover pattern to copy, but it changes persisted catalog data on every populated tenant.

The People database has a user-owned `relationship` select with the options `parent`, `therapist`, `closeFriend`, `girlfriend`, `client` and `neighbor` (`backend/packages/data/src/seed/seedTenDatabases.ts`, labels in `backend/packages/data/src/seed/i18n/cs.json` and `en.json`). The Inbox card for a new person, the card that asks who a transcript speaker is, and the People collection all need one shared list of relationships, and three values the card offers do not exist yet: colleague, craftsman and doctor. People is `schema_locked`, so a new select option reaches existing tenants only through a per-tenant cutover (the pattern is `runTranscriptsCatalogCutoverMigration`, registered in `backend/packages/data/src/db/tenantCutoverMigrations.ts`; see `docs/adr/2026-09-10-app-code-post-migration-steps.md`).

This issue owns the relationship list for every consumer. The Czech label of the existing `girlfriend` option is changed by #1413, which this issue builds on (both edit the same catalog file). Colors of select options are stored by #1584 and the display order of system select catalogs is set by #1578; both build on the list this issue finishes.

Decision: no further keys are added for "friend" and "family". The existing `closeFriend` and `parent` keep their meaning, and clients map their wording onto them. The list is exactly the six existing keys plus `colleague`, `craftsman` and `doctor`.

Decision: no People property for a person's job title is added. The default People schema is not extended and system collections get no custom properties in v1 (the module manifest owns the schema); a person's position can be written in the person's note.

Shared-file ordering: this issue also waits for #1545 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `canonical-keys` and `testing`.

1. In `seedTenDatabases.ts` extend the People `relationship` options to `parent`, `therapist`, `closeFriend`, `girlfriend`, `client`, `neighbor`, `colleague`, `craftsman`, `doctor` (new keys appended; keys are English camelCase).
2. Add `property.people.relationship.option.colleague`, `.craftsman` and `.doctor` to `seed/i18n/en.json` (Colleague, Craftsman, Doctor) and `seed/i18n/cs.json` (Kolega, Řemeslník, Lékař).
3. Add a per-tenant cutover in a new file `backend/packages/data/src/seed/peopleRelationshipOptionsCutoverMigration.ts`, following the lock, idempotency-check and update shape of `transcriptsCatalogCutoverMigration.ts`: it appends each missing option to `properties.config.options` of People `relationship` and does nothing when the People database does not exist yet or an option already exists. It never reorders or removes an option.
4. Register the cutover in `runTenantCutoverMigrations` in `db/tenantCutoverMigrations.ts`.
5. Tests: a populated tenant gains exactly the three options; a second run changes nothing; a fresh seed and a cutover tenant have the same option list; an item can be created with `craftsman`, `colleague` and `doctor`; the i18n coverage test (`systemI18nCatalogCoverage.test.ts`) passes.

## Scope

### In scope

- The three new options on fresh and populated tenants, with English and Czech labels.

### Out of scope

- The Czech label of `girlfriend` (#1413), option colors (#1584) and option order (#1578).
- Phone numbers on People (#1535).
- A job-title property on People (not in v1) and any client-side mapping of friend or family wording.

## Acceptance criteria

- When a populated tenant runs the cutover, then People `relationship` accepts `colleague`, `craftsman` and `doctor` and keeps the six existing options in their order.
- When the cutover runs a second time, then nothing changes.
- When an item is written with `relationship: craftsman`, then the write succeeds and the value reads back.
- Every new option has a label in both locales.
