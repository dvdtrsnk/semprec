## Context

Model tier rationale: A parameter passes through six existing layers (pipeline, client, gateway handler, provider types, pyannote, shared gateway package) with no new trust boundary, but every layer needs matching tests and the gateway stays the only provider caller.

A recording can carry the language and the number of speakers the user chose (on the Inbox recording card: Czech, English or auto-detect; 1, 2 or "3 or more", otherwise detect). Today the job payload is only `{ fileItemId }` (`transcription/transcriptionJob.ts`), and requeue and rerun rebuild it from `Transcripts.link`, so anything in the payload is lost. ASR chunk 0 always sends `language: undefined` (`runAsrStep` in `backend/services/semprec-transcribe/src/transcriptionTask.ts`) although the gateway accepts a language (`deepInfraWhisperProvider.ts`). The number of speakers exists nowhere: `DiarizeRequest` (`audioGatewayClient.ts`), `DiarizationRequest` (`services/semprec-ai-gateway/src/audioProviders/types.ts`), the body of `POST /internal/diarize` (`audioHandler.ts`), `diarize()` in `packages/ai-gateway/src/gateway.ts` and the pyannote request body `{ url: mediaKey }` (`pyannoteProvider.ts`).

This issue reads the parameters from the `recording_requests` row (#1574: `language` as ISO 639-1, `num_speakers_exact` or `num_speakers_min`) in the pipeline, so requeue and rerun keep them, sends the language with chunk 0, and passes the speaker count down to pyannote. The row is written only by the shared recording-intake function; this issue does not write it. The AI gateway stays the only caller of providers (`docs/adr/2026-09-10-ai-gateway-monopoly-on-provider-calls.md`). #1696 and #1978 build on it.

Decision: "3 or more" is a minimum of 3; no choice sends nothing and detection runs as today.

## Task

Load `ai-gateway`, `io-hardening` and `testing`.

1. In the ASR step read `language` from `recording_requests` for the Files item and send it with chunk 0; when it is null keep detection as today.
2. Add `numSpeakers: { exact: number } | { min: number }` to `DiarizeRequest`, `DiarizationRequest`, the `POST /internal/diarize` request schema (validated, positive integers, at most one form), `diarize()` of `@semprec/ai-gateway` and the pyannote request body; omit it when not set.
3. In the diarize step read the speaker count from `recording_requests` and pass it.
4. Tests in each package: language on chunk 0 only; exact 2 reaches pyannote as 2; minimum 3 as a minimum; nothing is sent without a choice; a rerun uses the same parameters.

## Scope

### In scope

- Language and speaker count from `recording_requests` through the pipeline and the gateway to the providers.

### Out of scope

- The table and intake: #1574.
- Writing the recording's project onto the transcript: #1696.
- The Inbox card that collects these choices: #1978.
- Normalizing the detected language: #1475.

## Acceptance criteria

- When a recording was confirmed with the language Czech, then the first ASR chunk is sent with `cs`.
- When "2 speakers" was chosen, then pyannote receives 2; for "3 or more" it receives a minimum of 3; with no choice nothing is sent.
- When a transcription is rerun, then the same parameters are used.
