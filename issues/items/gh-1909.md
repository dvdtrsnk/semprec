## Context

Model tier rationale: One new tenant-scoped read route over existing tables with a migration, but it composes several blocker-provided shared functions and needs the route-matrix and tenant-isolation fixtures extended, so it is a known mechanism across defined store/API seams rather than a mechanical change.

The project agent page needs a short list of the project's most recent agent runs: what ran, who or what triggered it, when, how long it took, what it cost and how it ended, so that a user can open a run or attach it to a chat. Today there is no way to list runs of a project. `backend/packages/data/src/agentRuns/agentRunsStore.ts` only has `listAgentRunsByHeartbeat` and `listRunningAgentRuns`; `services/semprec-api/src/app.ts` routes only the `/api/agent-runs/` prefix (with the trailing slash) to `agentRunHandler.ts`, and custom routes declared on module manifests are dispatched before it (`mountCustomRoutes` / `dispatchCustomRoute`). The only indexes on `agent_runs` that start with the project are `agent_runs_project_item_id_idx` (0001) and `agent_runs_session_wake_idx` (0017); none is ordered by `started_at`.

This issue builds the list route with one row per agent run. It builds on the display status and duration derivation and the project/trigger fields of the run detail (#1805, #1820), the localized error summary (#1824), the failed-tool-call derivation (#1890) and the per-run spend aggregation (#1822). Later issues refine the rows: #1914 collapses retried heartbeat attempts and #1932 turns a chat session into one row per answer.

Decisions:
- The route is a custom route (`single-consumer-read`, per `docs/adr/2026-09-11-module-manifest-custom-routes.md`) declared on the manifest of the module that owns `agent_runs` (`schemaCoreModuleManifest.ts`, whose migration `0001_core_schema.sql` creates the table). `app.ts` is not changed. Reads over agent runs stay with that module under the single-writer ownership ADR `docs/adr/2026-09-10-single-writer-ownership-model.md`.
- The list returns only runs whose `actor_user_id` is the authenticated session user and never runs with `triggered_by = 'supervisor'`.
- Filters other than the project and any pagination beyond `limit` are not part of the product design and are out of scope.

Shared-file ordering: this issue also waits for #1908 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `canonical-keys`, `db-migrations`, `io-hardening` and `testing`.

1. Add the migration `backend/packages/data/src/db/migrations/NNNN_agent_runs_project_started_index.sql` (next free ordinal at commit time): `CREATE INDEX agent_runs_tenant_project_started_idx ON agent_runs (tenant_id, project_item_id, started_at DESC, id DESC)`. Follow `db-migrations` for index creation on an existing table.
2. In `agentRunsStore.ts` add `listProjectAgentRuns(client, { projectItemId, actorUserId, limit })` returning agent run rows ordered `started_at DESC, id DESC`, excluding `triggered_by = 'supervisor'`, restricted to `actor_user_id = actorUserId`, bounded by `limit`.
3. Add a read function that attaches the cost: one batched aggregation over `ai_gateway_calls` with `agent_run_id = ANY($1::uuid[])` grouped by `agent_run_id` (summing `cost_usd`), reusing the per-run spend function from #1822 if it already accepts a list of ids, otherwise a single query, never one query per run. A run without calls has cost `0`.
4. Add the row projection and the route handler `createListAgentRunsRouteHandler(pool)` in a new file `backend/packages/data/src/agentRuns/agentRunsListRouteHandler.ts`, cast to the custom-route handler shape the same way `aiUsageRouteHandler.ts` is. Each row is `{ id, title, triggeredBy, triggerLabel, startedAt, durationMs, costUsd, displayStatus, errorSummary, attempt }` where:
   - `title` is the run's `task`; for a heartbeat run it is `project_heartbeats.name` of the run's `heartbeat_id`;
   - `triggeredBy` is the stored value (`user`, `heartbeat`, `mcp`); `triggerLabel` is its localized label: "Chat" for `user`, "Tik" for `heartbeat`, "MCP" for `mcp`, through the same server-side localization the error summaries from #1824 use;
   - `durationMs` and `displayStatus` come from the shared functions of #1805 and #1820, and the failed-tool-call signal of #1890 feeds `displayStatus` exactly as those functions define; do not reimplement them;
   - `errorSummary` is the bare localized reason from #1824 (for example "GitHub unavailable") for an errored run and `null` otherwise; the client composes any "failed - " prefix;
   - `attempt` is `1` here; #1914 fills it for retried heartbeat runs.
5. Parse `projectItemId` (required, uuid) and `limit` (default 20, maximum 100, positive integer) from the query string; reject others with `ValidationError` (see `io-hardening`, `error-handling`). Answer an unknown or foreign `projectItemId` with an empty list rather than an error, so that foreign ids are indistinguishable from empty projects.
6. Declare the route `GET /api/agent-runs` in the `customRoutes` of `schemaCoreModuleManifest.ts` with `justification: "single-consumer-read"` and export the handler from the `packages/data/src/index.ts` barrel.
7. Register the route in `services/semprec-api/src/routeMatrix.ts` (tenant scoped, not public), map it in `ROUTE_HANDLER_FILES` of `chokePointWriteBoundary.unit.test.ts`, and add its case to `tenantIsolationRoutes.test.ts` (a member of tenant B receives no run of tenant A).

## Scope

### In scope

- The migration, the store read, the batched cost attachment, the route handler and its registration, route matrix and isolation test entries.

### Out of scope

- Collapsing retried heartbeat attempts into one row and filling `attempt`: #1914.
- Chat sessions as one row per answer: #1932.
- Attaching a run to a chat message, and the ref shape: #1936.
- Filters, "show all" and pagination beyond `limit`.
- Changes to `app.ts`.

## Acceptance criteria

- When a project has four runs (a finished heartbeat run, a finished chat run, a heartbeat run waiting for approval, an errored heartbeat run with error code for an unavailable integration), `GET /api/agent-runs?projectItemId=<id>` returns four rows newest first, each with `title`, `triggerLabel`, `costUsd` and `displayStatus`; the waiting run has `displayStatus` `waiting_approval` and the errored run has `displayStatus` `error` with a localized `errorSummary` and no prefix.
- When a run has several gateway calls, its `costUsd` is their sum, and the list issues one aggregation query regardless of the number of rows.
- When `limit` is omitted the response has at most 20 rows; `limit=100` is accepted; `limit=101`, `limit=0` and a non-uuid `projectItemId` are rejected with a validation error.
- A run with `triggered_by = 'supervisor'` and a run whose `actor_user_id` is another user never appear.
- A user of another tenant receives an empty list for this project id, identical to the response for a random id.
- `EXPLAIN` of the list query on a seeded project uses `agent_runs_tenant_project_started_idx` (verified in a test or recorded in the pull request).
