## Context

`DelegationRegistry` (`backend/packages/agent-runtime/src/delegationRegistry.ts`) keeps one open `AgentSession` per `(supervisorRunId, targetProjectItemId)` and serializes turns through the entry's `busy` flag: `delegate()` (line 135-137) rejects with `BUSY_ERROR_MESSAGE` when `existing.busy` is set, and sets `busy = true` synchronously before its first `await` when it is not (line 140). The TTL expiry `expire()` (lines 242-253) breaks that protocol: it checks `if (!entry || entry.busy) return;`, then awaits `finishAgentRun(this.pool, entry.agentRunId, "done", null)` and `pushRunStatus(...)` with `busy` still `false`, and only deletes the entry after both writes. A `delegate()` call arriving during those awaits finds a free entry, sets `busy`, and runs a turn (`runAgentTurn` → `insertAndNotifyAgentRunEvent`) on a run that `expire` is finishing; `expire` then deletes the entry from under the in-flight turn, whose events land on a `done` run (rejected with `ConflictError` once D1 is in, i.e. the turn fails for the supervisor) and whose session is dropped from the registry.

`SempConversation.pause` (`backend/packages/agent-runtime/src/sempConversation.ts:231-245`) shows the intended shape: claim `busy` synchronously before the first `await`; clear the entry on success; on failure reset `busy = false` and reschedule the timer.

#647 makes this registry reachable from `semprec-agents` (agent sessions run through the runtime); D1 changes `finishAgentRun` to return whether the close won and adds the lost-close log line inside `expire`, which this issue restructures.

## Task

1. In `expire(entryKey)`:
   - Keep the early return for a missing or busy entry, then set `entry.busy = true` **before** the first `await` (same invariant as `SempConversation.pause`; say so in the docstring, replacing the sentence "A `busy` entry's own next `touch()` call reschedules a fresh timer past this fire, so this is a no-op for it" with an explanation that a concurrent `delegate()` now observes `busy` and is rejected with `BUSY_ERROR_MESSAGE` for the duration of the close).
   - On success (both writes done): `this.entries.delete(entryKey)` (unchanged).
   - On failure: log as today, set `entry.busy = false`, and reschedule `entry.ttlTimer = this.scheduleTtl(entryKey)` (unchanged apart from the reset).
   - Keep D1's `finishAgentRun` boolean handling (warn on a lost close, still record `run_status` and delete the entry).
2. **Test** (`backend/packages/agent-runtime/src/__tests__/delegationRegistry.test.ts`, integration, existing fake `createAgentSession` helpers): construct the registry with a short TTL (e.g. 30 ms), run one delegation so an entry exists, then in a separate connection open a transaction that holds `SELECT id FROM agent_runs WHERE id = $1 FOR UPDATE` on the entry's run (so `expire`'s `finishAgentRun` blocks), wait past the TTL, and while it is blocked call `delegate()` with the same key → the result is `{ ok: false, error: BUSY_ERROR_MESSAGE }` and the fake session's `send` was not called. Commit the blocking transaction, await the pending expiry (poll until the entry is gone), and assert the run is `done` with a `run_status: done` event and that a subsequent `delegate()` creates a fresh run instead of reusing the expired session. Add a second case: construct the registry over a pool wrapper whose `query` rejects once with `new Error("simulated outage")` for the first statement starting with `UPDATE agent_runs` and delegates everything else to the real pool; after the TTL fires, the entry is still present with `busy === false` and a rescheduled timer, and a later `delegate()` on the same key reuses the session (`send` is called on the same fake session).

## Scope

### In scope
- Claiming `busy` for the whole expiry close in `DelegationRegistry.expire`, and the two tests.

### Out of scope
- `SempConversation.pause` (already correct).
- `finishAgentRun`'s guard/return value (D1) and the registry's composition into `semprec-agents` (#647).
- Persisting registry entries across restarts.

## Acceptance criteria

- When `expire` is in the middle of finishing an idle delegated session's run, a concurrent `delegate()` for the same `(supervisorRunId, targetProjectItemId)` is rejected with `BUSY_ERROR_MESSAGE` and no turn is sent to the session.
- When the expiry close succeeds, the entry is removed, the run is `done`, and the next `delegate()` for that key starts a new run.
- When the expiry close fails, the entry stays registered with `busy === false`, a new TTL timer is scheduled, and the next `delegate()` for that key reuses the session.
