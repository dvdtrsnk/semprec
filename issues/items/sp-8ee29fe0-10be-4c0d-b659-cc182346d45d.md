## Context

Model tier rationale: Reuses the existing document scanner and PDF building in a second place; the work is moving them where a feature module can use them and wiring a new source into the capture row.

The diary's Inbox capture row (`mobile/apple/Modules/Features/Journal/Sources/Layers/PresentationLayer/Components/JournalCaptureRow.swift`) lets the person attach a file or a photo. The owner also wants to scan a document there. The Action-button shortcut already scans: `DocumentScanner.swift` (the one UIKit view controller of the app, ADR `docs/adr/2026-11-27-the-document-scanner-is-the-one-uikit-view-controller-of-the-apple-app.md`) and `ScanDocument.swift` (pages to one PDF named `Scan YYYY-MM-DD HH-mm.pdf`) live in the app target `mobile/apple/Projects/App/Sources/Intents/`, which a feature module cannot import.

## Task

1. Move `DocumentScanner` and `ScanDocument` (and their tests) to a core module that both the app target and the Journal feature may import (DesignSystem or a new small core module, whichever the module rules allow; record the module choice in the scanner ADR's narrowing only if a new module is created), keeping the iOS-only condition and the single UIKit exception.
2. Add "Scan document" to the capture row's attachment menu on iOS when `VNDocumentCameraViewController.isSupported`; it shows the scanner full screen and, on finish, attaches the PDF with source `camera` exactly as a picked file is attached; cancelling attaches nothing.
3. Copy and accessibility identifiers in English and Czech; update `mobile/scripts/architecture-policy.json` and `mobile/docs/architecture.md` for the move.

## Touches

- `mobile/apple/Projects/App/Sources/Intents/DocumentScanner.swift`, `ScanDocument.swift`, `ScanPresenter.swift` (imports), their tests
- the chosen core module under `mobile/apple/Modules/Core/`
- `mobile/apple/Modules/Features/Journal/Sources/Layers/PresentationLayer/Components/JournalCaptureRow.swift`, `JournalIdentifiers.swift`, the Journal String Catalog, the Journal `Project.swift`
- `mobile/scripts/architecture-policy.json`, `mobile/docs/architecture.md`

## Scope

### Out of scope

- Changes to the shortcut (a sibling issue of this batch), Android.

## Acceptance criteria

- On an iPhone the capture row's menu offers File, Photo and Scan document; a finished scan attaches one PDF with all pages and source camera, and the capture is sent like any other; cancelling attaches nothing.
- On macOS and without a scanner the menu has no Scan document.
- The shortcut's scan still works from the moved files; tests of the PDF building pass in their new module.
