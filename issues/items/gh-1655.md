## Context

Model tier rationale: First real outbound HTTP integration of the library job: it must keep SSRF, connect-time address and secret-leak guarantees while downloading remote images into blob storage, which is a security-sensitive contract.

The library metadata job calls a `LibraryMetadataFetcher` (`backend/packages/data/src/library/libraryMetadataJob.ts`). The default is `noopLibraryMetadataFetcher` (`backend/packages/data/src/worker.ts`), and `createApiQueueRuntime` in `backend/services/semprec-api/src/queueRuntime.ts` passes `undefined` for it, so no source is ever called. After #1575, the result type can carry `author`, `year`, `isbn`, `cover`, and the Books heartbeats are configured with `source: "openLibrary"`.

This issue implements the Books source: Open Library first, Google Books as fallback. It also introduces the shared result outcome and the fetcher dispatch that the Movies source (#1706) plugs into.

Egress: public APIs need no firewall rule (`deploy/nftables.conf` only denies private ranges for the service user; `docs/adr/2026-10-03-host-egress-filtered-by-service-uid.md`). Every remote URL that comes from a provider response (cover image URLs) must still pass the connect-time checks of `docs/adr/2026-10-16-connect-time-outbound-address-checks.md` (`createOutboundHttp()` in `backend/packages/data/src/net/outboundAddressPolicy.ts`) and the stored-URL rules of `docs/adr/2026-09-27-ssrf-protection-for-stored-outbound-urls.md` (`net/storedOutboundUrl.ts`).

Decision: when a result has several plausible matches, the fetcher picks the best one (title match, then author/year when the item has them) and returns up to three others as `candidates`; this issue does not store candidates (#1812 does).
Decision: an unknown author is left empty (no "Unknown author" text is stored); the client shows the placeholder.
Decision: no source rating for books is added; only movies have a source rating.

Unsupported configured sources follow docs/adr/2026-11-05-library-retries-require-a-supported-live-source-config.md: reject through a fixed typed error before producer/sweep/job automation side effects; this recognized configuration refusal is not gh1708 provider failure mapping. Existing legacy queued jobs retain bounded maxAttempts=3; unsupported live config cannot enqueue another daily metadata batch. No new durable status/code/flag is added; corrected live config resumes ordinary retry, and missing TMDB token remains sourceUnavailable.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Extend `LibraryMetadataFetchResult` with `status: "found" | "notFound" | "error"`, `errorCode?: "sourceUnavailable" | "rateLimited" | "invalidResponse"`, `source?: "openLibrary" | "googleBooks" | "tmdb"` and `candidates?: Array<{ title, author?, year?, coverUrl? }>` (max 3). The job keeps working for a result without `status` as `found`-if-anything-was-returned, so the no-op fetcher stays valid; recording the states is #1708.
2. Add `backend/packages/data/src/library/openLibraryFetcher.ts`: search by item `name` (and `author` when set), pick the best match, read author, first publish year and an ISBN, and the cover. HTTP goes through one small injected `fetch` so tests use recorded fixtures; a timeout and a response size cap apply; a non-JSON or schema-mismatching body is `invalidResponse`, HTTP 429 `rateLimited`, 5xx or network error `sourceUnavailable`, an empty result `notFound`.
3. Add `backend/packages/data/src/library/googleBooksFetcher.ts` with the same shape; the Books fetcher tries Google Books only when Open Library returns `notFound` or `error`, and reports the `source` that supplied the data.
4. Download the cover bytes through `createOutboundHttp()`: https only, no userinfo, size cap, content type must be an image, and an address in a private or link-local range (for example 169.254.0.0/16 or 10.0.0.0/8) is refused and treated as no cover (the rest of the result is kept). Return `cover` as typed bounded downloaded bytes with image MIME and optional safe source URL, not CreateBlobInput storage metadata. Materialize it through the library-owned prepared-cover handoff in docs/adr/2026-11-05-library-covers-stage-bytes-before-the-owned-item-transaction.md.
5. Add `backend/packages/data/src/library/libraryMetadataFetcher.ts`: a dispatcher choosing the fetcher by `config.source` (`openLibrary` now; `none` returns `{}`; unknown source throws a configuration error that is not retried forever). Export a factory the composition roots use.
6. Wire the dispatcher in `backend/services/semprec-api/src/queueRuntime.ts` in place of `undefined // libraryMetadataFetcher`, and in `worker.ts` for the standalone worker if it builds its own list.
7. Never put an exception message or URL with credentials into a result; no API key is needed for these two sources.
8. Tests against recorded fixtures (CI has no network): "Hovory k sobě" yields author "Marcus Aurelius", a year and a cover; a user-entered author is kept by the job; a not-found query yields `notFound`; a 503 fixture yields `sourceUnavailable`; a cover URL on 169.254.169.254 or 10.0.0.1 is refused; the fallback to Google Books is used when Open Library is `notFound`.

## Acceptance criteria

- When the Open Library fixture for "Hovory k sobě" is used, then the job stores author "Marcus Aurelius", a year, an ISBN and a cover blob for an item with empty fields.
- When the item already has a user-entered author, then the author is not changed.
- When the cover URL resolves to 169.254.0.0/16 or 10.0.0.0/8, then the download is refused and no blob is stored; other fields are still applied.
- When Open Library returns nothing and Google Books has a match, then the Google Books data is used and `source` is `googleBooks`.
- When a provider answers 5xx, then the result is `error` with `sourceUnavailable`; no exception text or URL appears in the result or the logs.
- When several matches exist, then the best is applied and at most three others are returned as `candidates`.
