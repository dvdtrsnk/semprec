## Context

Model tier rationale: One read route with a non-trivial query (cascade roots, archived databases, keyset paging) and a small migration, following the custom-route and tenant-isolation test patterns already in the repository; no write path and no new lifecycle.

Items are soft-deleted (`items.deleted_at`) and purged 30 days later by the daily sweep (`backend/packages/data/src/trash/purgeExpiredTrash.ts`, issue 156). A client can restore one item (`POST /api/items/:id/restore`) and can read the trashed items of one known database (`POST /api/databases/:id/query` with `inTrash: true`, which mixes live and trashed items), but nothing lists everything the user deleted across all databases, and nothing tells how many days remain before an item is purged. The "Recently deleted" screen needs exactly that: the newest deleted first, with where each item came from and the days left.

This issue adds `GET /api/trash/items`, a read-only custom route of the schemaCore module (`backend/packages/data/src/chokePoint/schemaCoreModuleManifest.ts`, justification `single-consumer-read`). It also makes the retention length a shared constant (`purgeExpiredTrash.ts` currently holds it as a local `DEFAULT_RETENTION_DAYS = 30`), because both the sweep and this listing must agree on when an item is purged. The route is ordered after #1837 only because both add a route to the same manifest and route matrix. The listing of archived databases (#1873), the purge of archived databases (#1875), the account summary counts (#1903) and the listing of trashed pages (#1855) build on it.

Decisions:

- Only roots of a delete cascade are listed. An item of an inline database (a database owned by another item through `databases.parent_item_id`) whose owner item was deleted at the same moment (same `deleted_at`) was trashed together with it and is not a separate row; an item trashed on its own, at a different time, is a root.
- Items of archived databases are not listed (archived databases appear in the database listing).
- `daysLeft` is the number of whole calendar days from today to the purge day, both taken in the tenant's time zone (System settings `timezone`): an item deleted today has 30, one deleted 26 days ago has 4, never below 0.
- `databaseName` is the stored name for a user database and the localized catalog name (the user's `users.locale`) for a system database; `databaseKey` and `ownerModuleId` are `null` where the database has none.

Shared-file ordering: this issue also waits for #1845, #1846 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `error-handling`, `db-migrations` and `testing`.

1. In `purgeExpiredTrash.ts` rename the local constant to an exported `RETENTION_DAYS` (value 30) and use it as the default of `purgeExpiredTrash`; export it from the package index if the other trash exports are.
2. Add the migration `backend/packages/data/src/db/migrations/NNNN_items_deleted_at_idx.sql (next free ordinal at commit time)` creating a partial index on `items (deleted_at DESC, id) WHERE deleted_at IS NOT NULL` (a partitioned table cannot be indexed concurrently; say so in the header and that new partitions inherit the index). Additive, safe to run twice.
3. Add `backend/packages/data/src/trash/trashRouteHandlers.ts` with `createTrashItemsRouteHandler(pool)` for `GET /api/trash/items?cursor&limit` (default limit 50, maximum 200; a non-integer or out-of-range limit and a malformed cursor are `400 validation_failed`). The query covers the tenant's databases only (row-level security), `deleted_at IS NOT NULL`, databases not archived, cascade roots only (see decisions), ordered by `deleted_at DESC, id`, with an opaque keyset cursor over `(deleted_at, id)`.
4. Response: `{ items: [{ item, databaseId, databaseKey, ownerModuleId, databaseName, deletedAt, purgeAt, daysLeft }], totalCount, nextCursor }` where `item` has the shape of the item envelope (`id`, `databaseId`, `properties`, `computed`, `updatedAt`, `deletedAt`), `purgeAt` is `deletedAt` plus `RETENTION_DAYS`, `totalCount` counts all roots matching the same predicate regardless of the cursor, and `nextCursor` is `null` on the last page. Resolve system database names with the module catalogs (`resolveDatabaseName` and the full module registry, loaded lazily once per process like the speaker label catalogs, and not cached on failure).
5. Register the route in `schemaCoreModuleManifest.ts` (name `listTrashItems`, `GET /api/trash/items`, `handlerExport: "createTrashItemsRouteHandler"`), re-export the handler in that file's export block, add `"list trash items"` to `backend/services/semprec-api/src/routeMatrix.ts`, `backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts` (case table and request list; a listing must contain tenant B's own rows and none of tenant A's) and `backend/services/semprec-api/src/__tests__/chokePointWriteBoundary.unit.test.ts` (handler file mapping).
6. Tests in `backend/packages/data/src/trash/__tests__/trashRouteHandlers.test.ts`: a deleted task and a deleted project with an inline database give two rows (not the inline database's items), newest first, with `daysLeft` 30 and 4 for items deleted today and 26 days ago; an item trashed alone inside an inline database whose owner is live is listed; an item deleted before its database was archived is not listed; a user database has `databaseKey` null and its stored name; paging by cursor returns every row once even with equal `deleted_at`; the purge sweep and the listing use the same retention constant.

## Scope

### In scope

- The cross-database listing of trashed cascade roots with purge day and days left, the shared retention constant and the supporting index.

### Out of scope

- Archived databases as trash: #1873; restoring in bulk: #1904.
- Trashed pages with their title and path: #1855.
- Who deleted an item: not stored (decided by the product owner); the write audit records who made the deletion.
- Permanent deletion on request or emptying the trash.
- Icons and colors of item types: the client reads them from database metadata.

## Acceptance criteria

- When a task and a project with an inline database are deleted, the listing contains exactly those two rows, newest first, with `daysLeft` computed by the rule above.
- An item deleted in a database that is then archived does not appear; a system database never appears as a row source of its own.
- An item of a user database has `databaseKey` null and `databaseName` equal to the stored name.
- Walking the pages with `nextCursor` returns every row once; `totalCount` is the same on every page.
- Another tenant's trash is never visible.
