**Model tier:** high

## Context

Model tier rationale: This combines a budgeted AI call outside the transaction with a staleness check, one transaction that writes an item, an edge and inherited values with provenance, and an error contract (409, exhausted budget), all on a user-facing write path.

A user can create a task from a mail thread. With no name given, the task name is derived from the conversation by AI. The task takes the project of the thread and the people of the conversation, both recorded as inherited values so that a later manual change ends following. Prerequisites: the relation Threads.tasks (#1612), the thread's project (#1869), the value-link store and break rules (#1403, #1516) and the propagation of link rules (#1593).

Decisions:
- The AI derives the name only; the due date is set only when the request carries `date`. A date mentioned in the conversation is not extracted.
- The project is a link rule declared by the mail module, source Threads.project, target Tasks.project, via Threads.tasks.
- Semp never creates a task from a thread silently (decided by the product owner): it proposes the task in the Inbox, the user can edit the proposal before confirming, and the confirm creates the task through the same transactional function as this route (#2035 proposes, #2034 confirms). Such a task inherits the project by the same rule, and its people are added by #1923 when a new participant appears.
- The people of the conversation are the union of `senderPeople` and `recipientsPeople` of the thread's messages minus persons that belong to the tenant's own mailbox addresses.

Shared-file ordering: this issue also waits for #1897, #1898 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `ai-gateway`, `state-writes`, `error-handling`, `io-hardening` and `testing`; follow `docs/adr/2026-09-10-bracket-non-transactional-calls-with-staleness-checked-transactions.md`.

1. Declare `POST /api/mail/threads/:threadId/tasks` in the `customRoutes` of `mail/mailModuleManifest.ts` (justification `transactional-semantics`), body `{ name?, date? }` (name non-empty up to 500 characters, date a calendar date), handler in `mail/mailThreadTaskRouteHandlers.ts`. Response 201 `{ id, name, date }` of the new task. Unknown or foreign `threadId` is a not-found error. The writer is the user.
2. Without `name`: take a snapshot of the thread (the ids of its not-deleted messages); outside any transaction call the ai-gateway with the tenant budget to produce a short task name from the conversation text (cut to a fixed size); then open the write transaction, re-read the snapshot and answer 409 `conflict` when it differs. An exhausted budget returns the gateway's budget error and creates no task.
3. In one transaction, in a function exported from `mail/threadTasks.ts` that takes the thread's Threads item, the name, the optional date and the writer (so the confirm of a thread task proposal can reuse it): create the Tasks item, the edge Threads.tasks from the thread's Threads item, and write Tasks.project and Tasks.people as inherited values with provenance per #1403 (the project through the link rule evaluated for this edge by the entry point of #1593; the people with the thread's Threads item as the source).
4. Declare the link rule Threads.project to Tasks.project via Threads.tasks in `mail/mailModuleManifest.ts`, so later changes of the thread's project reach the task.

## Scope

### In scope

- The create endpoint, the AI name with the staleness check, the transaction, and the project link rule.

### Out of scope

- Keeping people in sync with later participants (#1923); listing tasks in the thread detail (#1692).
- Extracting a due date with AI.
- Semp proposing a task from a thread as an Inbox proposal, and confirming such a proposal: #2035 and #2034. Semp does not create thread tasks directly.

## Acceptance criteria

- A call without `name` creates in one transaction a task named by the AI, the edge, the thread's project and the conversation's people, all as inherited values.
- If a message arrives or is deleted between the AI call and the write, the response is 409 and no task exists.
- With an exhausted tenant budget no task is created and the error is returned.
- A call with `name` and `date` makes no AI call and stores both.
- Changing the thread's project changes the project of the task until the task's project is changed by hand.
