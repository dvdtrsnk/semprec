**Blocked by:** #978

## Context

Every Semprec process logs through `createLogger` (`backend/packages/shared/src/logger.ts:98`). Its pino `mixin` (`logger.ts:108`, `mixin: () => getTraceContext() ?? {}`) stamps the active trace bindings on every record: `traceId`, plus whichever of `agentRunId`, `jobName`, `jobId` and `mailboxId` are bound (`backend/packages/shared/src/traceContext.ts:11-17`). Call sites never have to pass them. pino merges the call site's own object over the mixin result (`logger.ts:105-107`), so an explicit field wins.

#978 added the tenant scope in `backend/packages/shared/src/tenantScope.ts`:
- `currentTenantScope()` returns `{ kind: "tenant", tenantId } | { kind: "system", reason } | undefined`.
- `runInTenant(tenantId, fn)` and `runAsSystem(reason, fn)` enter a scope.
- The scope lives in its own `AsyncLocalStorage`, separate from the trace context.

Operators need every line written while serving a tenant to say which tenant it was. That is how a failure is attributed and how one tenant's noise is told from another's. Content is still never logged: identifiers are allowed, values are not, per the redaction contract at `logger.ts:6-13`.

The tenant id deliberately stays out of `TraceContext`. The tenant scope is the single source of truth for the tenant. A second copy in the trace bindings could disagree with it after a nested `runInTenant`, and `TraceContext` is also what crosses process boundaries as `traceId`. Tenant identity crosses only through the queue envelope (#982) and the gateway header (#993).

## Task

Load `error-handling`: the mixin runs on every log call and must never throw.

1. In `createLogger` (`backend/packages/shared/src/logger.ts`), extend the `mixin`. It still returns the active trace context. When `currentTenantScope()` is of kind `"tenant"`, it also returns `tenantId: <that tenant id>`. In a system scope or with no scope, it adds no `tenantId` key (and no other scope field).
2. Import `currentTenantScope` from `./tenantScope.js`. #978 made `tenantScope.ts` create its own logger lazily, so this import does not form a load-time cycle. Keep it that way: add no top-level call into `logger.ts` from `tenantScope.ts`.
3. Update the file's comment on the mixin (`logger.ts:104-107`) to name `tenantId` and where it comes from.
4. Tests in `backend/packages/shared/src/__tests__/logger.unit.test.ts`, using the existing `process.stdout.write` spy pattern from that file. Cover:
   - a record inside `runInTenant`;
   - a record inside `runAsSystem`;
   - a record outside any scope;
   - an explicit `tenantId` passed at the call site;
   - a record inside `withTraceContext` nested in `runInTenant`, which carries both `traceId` and `tenantId`.

## Touches

- backend/packages/shared/src/logger.ts (the `mixin` inside `createLogger` and its comment only)
- backend/packages/shared/src/__tests__/logger.unit.test.ts

## Scope

### In scope
- `tenantId` on every log record written inside a tenant scope, in every process that uses `createLogger`.

### Out of scope
- Changing `TraceContext` or `withTraceContext`. The tenant is not a trace binding.
- Propagating the tenant across processes: the queue envelope (#982) and the AI-gateway header (#993).
- Removing user content from existing log lines (#1074).
- Converting `console.*` calls to the logger (#1074).

## Acceptance criteria

- **Unit (`logger.unit.test.ts`):** a record emitted by a `createLogger(...)` logger inside `runInTenant(T)` carries `tenantId: T`.
- **Unit:** a record emitted inside `runAsSystem("x")` has no `tenantId` key.
- **Unit:** a record emitted outside any scope has no `tenantId` key, and is otherwise byte-for-byte the same shape as before this change.
- **Unit:** inside `runInTenant(T)`, `logger.info({ tenantId: U }, "m")` writes `tenantId: U`, because the call site wins over the mixin.
- **Unit:** inside `runInTenant(T)` wrapping `withTraceContext({ jobName: "j" }, …)`, the record carries `traceId`, `jobName: "j"` and `tenantId: T`.
- **Unit:** after `runInTenant(T)` returns, a record emitted by the same logger has no `tenantId`.
- **Unit:** importing `@semprec/shared`'s index in a fresh module context succeeds, so no import cycle throws at load.
