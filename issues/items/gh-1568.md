**Blocked by:** #1374, #1565
**Model tier:** high

## Context

Model tier rationale: It changes shutdown and startup-repair ownership of agent run state across processes and must keep a protocol invariant intact, so an error leaves threads that can never be woken again.

Two restart problems block durable threads.

First, after a restart `startupRepair.ts` (`backend/packages/agent-runtime/src/`) closes every `running` run except MCP runs as `error` with an `agent_run_error` notification. A thread session that is idle (its last event is `turn_end`) stays `running` for up to 24 hours, so every deploy would raise a false error notification for every thread active in that window.

Second, a turn that ends by error or cancellation can leave an unpaired `tool_use`; `validateProtocolInvariants` then throws and the thread cannot be woken. Today only startup repair fills the gap, in a shape (`error: true`, result a string, no `isError`) that `toPiMessages` rejects, so even a repaired thread cannot wake. #1374 defines the single regular tool result shape and fixes `startupRepair.ts` for it; this issue uses it for the in-flight cases.

Builds on #1565 (registry per thread) and #1374. #1732 and #1926 build on this.

Required shape of the synthetic result (from #1374): `{ toolCallId, name, isError: true, result: { content: [{ type: 'text', text }], details: { error: true } } }`.

## Task

Load `state-writes`, `error-handling` and `testing`.

1. Graceful shutdown in `services/semprec-agents/src/shutdown.ts` closes every idle thread session (last event `turn_end`) as `done`, without an `agent_run_error`. Startup repair applies the same rule for idle sessions it finds after a crash: close as `done`, no error notification; a session that was mid-turn is still closed as `error` with the notification as before.
2. When a turn ends with an error or is cancelled (the path through `lifecycleAdapter.ts`, `failRun`), pair every dangling `tool_use` of that turn immediately with a synthetic tool result in the shape above, so the thread can be woken again without waiting for a restart.
3. Tests: restarting with an idle thread session creates no `agent_run_error` and the thread wakes again afterwards; a turn cancelled mid-tool-call leaves a paired history, `validateProtocolInvariants` passes, and the next wake succeeds; a mid-turn session at restart is still closed as error with its notification; delegated and MCP runs behave as before.

## Touches

- backend/packages/agent-runtime/src/startupRepair.ts
- backend/packages/agent-runtime/src/lifecycleAdapter.ts (failed or cancelled turn closing)
- backend/services/semprec-agents/src/shutdown.ts
- backend/services/semprec-agents/src/serve.ts (only if the shutdown call needs wiring)
- tests: backend/packages/agent-runtime/src/__tests__/startupRepair.test.ts, lifecycleAdapter.test.ts, backend/services/semprec-agents/src/__tests__/startupRepairComposition.test.ts

## Scope

### In scope

- Idle thread sessions closed as `done` on shutdown and on repair.
- Immediate synthetic pairing of dangling tool calls on error or cancellation.

### Out of scope

- The synthetic result shape itself and the startup-repair rewrite to it: #1374.
- Re-queueing messages that were interrupted: #1732.
- Retry of a failed reply: #1926.

## Acceptance criteria

- When the agents service restarts with an idle thread session, then no `agent_run_error` notification is created for it and the thread can be woken afterwards.
- When a turn is cancelled or fails after a `tool_use` and before its result, then a paired synthetic result in the regular shape exists and the next wake succeeds.
- When a session was mid-turn at restart, then it is closed as `error` with its notification, as before.
