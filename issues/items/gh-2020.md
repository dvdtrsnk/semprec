**Blocked by:** #1626, #1734, #1744
**Model tier:** high

## Context

Model tier rationale: It changes the accounting rows of two long-lived gateway streams, including attributing speech-to-text rows after the audio was consumed, and a wrong attribution misstates usage per thread and run; at this uncertainty the higher tier is chosen.

The product decided that voice usage is attributed to the thread and the run it served, in the same way as every other gateway call, so that usage is recorded by one general mechanism. Today the gateway calls of an agent turn carry `ai_gateway_calls.agent_run_id` and, after #1744, `ai_gateway_calls.semp_message_id` (the assistant message the call answers; the thread is reached through that message), set from the request headers `x-semprec-agent-run-id` and `x-semprec-semp-message-id` in `backend/services/semprec-ai-gateway/src/piMessagesHandler.ts`. The voice rows written by the streaming speech-to-text route of #1396 (operation `voice_transcribe_stream`, one row per reserved chunk) and the text-to-speech route of #1399 (operation `voice_synthesize`) carry neither, so per-run and per-reply usage (#1822, #1889) never include speech.

Callers: the voice session of #1734 streams the user's speech to speech-to-text and the answer of a queued turn to text-to-speech; the read-aloud route of #1626 synthesizes one stored message.

Decision: the attribution unit is the Semp assistant message of the turn, as for the other calls of a turn. Text-to-speech of an answer, live or read aloud, carries that message's id and its run id. The speech of a spoken question carries the id of the assistant message created for the turn that the question started; the run id is not known yet when that speech is consumed, so these rows carry the message only, and the run is reached through `semp_messages.agent_run_id`.

Decision: speech that never becomes a message (muted, ended or a stop command) keeps no attribution and counts only in the tenant's totals.

The Voice activity in the AI usage report is a label of the two voice operations in the operation breakdown and is not part of this issue.

## Task

Load `ai-gateway`, `state-writes`, `io-hardening` and `testing`.

1. In the streaming text-to-speech route of #1399, read the optional headers `x-semprec-agent-run-id` and `x-semprec-semp-message-id` with the same validation as `piMessagesHandler.ts` (absent means null; present but not a UUID is a 400 `ValidationError` naming the field), and write both on the reserved and settled row.
2. In the streaming speech-to-text route of #1396, add an inbound JSON control message `{type: "attribute", sempMessageId}` (UUID, validated as in step 1). On it, set `semp_message_id` on every chunk row of this stream reserved since the stream opened or since the previous `attribute` message, in the tenant of the stream; rows of other tenants and streams are never touched.
3. In the voice session handler of #1734, after a final transcript was turned into a thread message, send `attribute` with the id of the assistant message created for that turn; when speaking the answer, pass the turn's run id and the assistant message id as the two headers of the text-to-speech request. In the read-aloud route of #1626, pass the id of the message read aloud and its run id.
4. Tests with fake providers: the text-to-speech rows of a spoken answer carry the answer's run id and message id; the speech-to-text chunk rows of one spoken question carry the assistant message id of the turn it started, and the rows of the next question carry the next turn's id; speech that ends without a final transcript leaves its rows unattributed; a read-aloud row carries the message id and its run id; a malformed header answers 400; the per-reply usage of #1889 for a voice turn includes its speech rows.

## Scope

### In scope

- Writing `agent_run_id` and `semp_message_id` on the voice rows of live voice and read-aloud, as decided above.

### Out of scope

- The Voice label and grouping in the AI usage report's operation breakdown (#1477).
- A thread id column on `ai_gateway_calls`; the thread is reached through the message, as for the other calls.
- Changing how voice budget is reserved or settled (#1396, #1399).

## Acceptance criteria

- When Semp speaks an answer in voice mode, then every text-to-speech row of it carries the turn's run id and the assistant message id.
- When the user asks a question by voice, then the speech-to-text rows of that question carry the assistant message id of the turn it started.
- When a stored message is read aloud, then its row carries that message's id and run id.
- When speech never becomes a message, then its rows carry no attribution and still count against the tenant budget.
- A row of another tenant or another stream is never changed by an `attribute` message.
