## Context

A web-push subscription's `endpoint` is an attacker-chosen URL the server later POSTs to. `registerPushSubscription` in `backend/packages/data/src/push/pushSubscriptionActions.ts` accepts any non-empty string for it (`nonEmptyString`, lines 16-21, used at line 67) and stores it through `upsertWebPushSubscription`. At notification fan-out, `sendWebPushNotification` in `backend/packages/data/src/push/webPushAdapter.ts` (lines 26-46) calls `webpush.sendNotification({ endpoint: target.endpoint, ... })` with a signed VAPID JWT, so the process makes an authenticated outbound request to whatever was registered. From the API host, loopback and private services are reachable that way: semprec-api itself (`127.0.0.1:8080`), MinIO (`:9000`/`:9001`), Postgres (`:5432`), the AI gateway. This is server-side request forgery from any authenticated session.

The existing tests register `https://push.example/1`-style endpoints, which pass the rule below. Sibling B11 of this batch edits `pushSubscriptionsStore.ts` (the upsert) — a different file.

## Task

- Create `backend/packages/data/src/push/webPushEndpointValidation.ts` exporting `validateWebPushEndpoint(endpoint: string): string`, returning the input unchanged (the stored value is the `ON CONFLICT (endpoint)` identity, so it is not normalised) when every rule holds, else throwing `new ValidationError("'endpoint' must be an https URL to a public push service host on port 443, without credentials", { field: "endpoint" })`. Rules, checked with `new URL(endpoint)` (a parse failure is the same `ValidationError`):
  1. `url.protocol === "https:"`.
  2. `url.username === "" && url.password === ""`.
  3. `url.port === ""` — only the default 443 (`URL` normalises an explicit `:443` away, so it is accepted; any other port is an internal-service signature and is rejected).
  4. `url.hostname` is not `localhost` and does not end with `.localhost`.
  5. `url.hostname` is not an IP literal at all: with IPv6 brackets stripped, `net.isIP(host) === 0` (`node:net`). Rejecting every literal, public ones included, closes loopback, RFC 1918, link-local (`169.254.0.0/16`, the cloud metadata address), CGNAT and IPv4-mapped IPv6 in one rule without maintaining a range table; every real push service (`fcm.googleapis.com`, `updates.push.services.mozilla.com`, `*.notify.windows.com`, `web.push.apple.com`) is a DNS name.
  Document in the file's docstring that a DNS name resolving to an internal address (rebinding) is not covered here and that egress filtering is the deployment's job.
- In `registerPushSubscription`, the `web_push` branch passes `endpoint: validateWebPushEndpoint(nonEmptyString(input.endpoint, "endpoint"))`. The APNs branch is untouched (a device token is not a URL).
- No barrel export: the validator is used only inside the `push/` module; nothing in `backend/packages/data/src/index.ts` changes.
- Tests:
  - New `backend/packages/data/src/push/__tests__/webPushEndpointValidation.unit.test.ts` (unit tier, no Postgres). Accepts: `https://fcm.googleapis.com/fcm/send/abc`, `https://updates.push.services.mozilla.com/wpush/v2/x`, `https://web.push.apple.com/QAbc`, `https://push.example:443/x` (returned unchanged, the explicit default port included). Rejects, each with `ValidationError` and `details.field === "endpoint"`: `http://push.example/1`, `https://127.0.0.1/x`, `https://[::1]/x`, `https://10.0.0.1/x`, `https://169.254.169.254/latest`, `https://[::ffff:127.0.0.1]/x`, `https://localhost/x`, `https://api.localhost/x`, `https://user:pw@push.example/x`, `https://push.example:9000/x`, `not a url`.
  - `backend/packages/data/src/__tests__/pushSubscriptions.test.ts`, inside `describe("registration validation")` (integration tier): registering `web_push` with `endpoint: "https://127.0.0.1:9000/minio"` rejects with `ValidationError` and no `push_subscriptions` row is written. The route mount already maps `ValidationError` to 400 (the existing route-level test "registers a web_push subscription bound to the caller's own session" in `push/__tests__/pushRouteHandlers.test.ts` covers the thin `POST /api/push-subscriptions` mapping and stays untouched).

## Scope

### In scope

- Validating `endpoint` at registration with the rule above.

### Out of scope

- Re-binding an active endpoint to another user on conflict — sibling issue B11 of this batch (`pushSubscriptionsStore.ts`).
- Re-validating endpoints already stored, or validating at fan-out time in `webPushAdapter.ts`.
- DNS resolution checks, egress filtering, or a private-range table.
- APNs device-token validation.

## Acceptance criteria

- When `POST /api/push-subscriptions` registers a `web_push` subscription whose endpoint is not `https:`, carries userinfo, names any port, or has a hostname that is `localhost`, `*.localhost` or an IP literal, the response is 400 `validation_failed` with `details.field === "endpoint"` and no row is written.
- When the endpoint is an `https://<dns-name>/...` URL with no port and no userinfo, registration succeeds exactly as today; every existing case in `pushSubscriptions.test.ts` and `pushRouteHandlers.test.ts` passes unchanged.
- The stored `endpoint` equals the submitted string byte for byte.
