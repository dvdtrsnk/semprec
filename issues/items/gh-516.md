## Context

`backend/packages/data/src/chokePoint/chokePoint.ts` grew to 2000 lines: one object returned by `createChokePoint()` carrying 45+ methods across eight domains, plus 41 top-level helpers. This batch splits it into per-domain modules without changing behavior (epic #494). `computeDestructiveResourceProjection` is the single authorization-and-projection function for approved destructive operations, spanning all domains. It stays one function in one module.

## Task

Move the following declarations from `chokePoint.ts` into `backend/packages/data/src/chokePoint/destructiveProjection.ts`, verbatim, per the move rules below:

- `ResourceSnapshotKind`, `ResourceSnapshot`, `DestructiveResourceProjection`, `DestructiveOperationCheck` (exported)
- `buildResourceSnapshot`, `detailsObject`
- `computeDestructiveResourceProjection` (exported)

Import `assertViewWritable` (and `Actor`) from `authorization.ts` (#501) and the edge-context helpers from `relationEdgeContext.ts` (#506).

ADRs that constrain this module (name them in its header comment):
- `docs/adr/2026-09-18-exactly-once-execution-of-approved-destructive-operations.md`

### Move rules (identical in every extraction issue of this batch)

- **Verbatim.** Names, signatures, JSDoc and inline comments, error classes and error codes, the order of checks, `actingUserId` forwarding, and every `runAfterCommit` / `notifyInvalidation` call stay exactly as they are. The only allowed edits are: import paths; adding `export` to a declaration that `chokePoint.ts` or another module named in this issue must now import; and the new file's header comment.
- **Only your own block of `chokePoint.ts`.** #499 grouped `chokePoint.ts` into contiguous blocks, each starting with a marker line `// ==== block: <destination file> ====`. Edit only the lines between this issue's marker and the next marker. Replace the moved code there with (a) an `import` of whatever the rest of `chokePoint.ts` still uses from the new file and (b) `export { … } from "<new file>"` for every moved symbol `chokePoint.ts` exported before, so no caller changes. Keep the marker line. Imports in the middle of the file are deliberate for the duration of this batch; #528 moves them to the top and removes the re-exports. Sibling issues are extracting the other blocks at the same time, so an edit outside your block turns parallel work into a rebase conflict.
- **One exception outside the block:** if the move leaves a binding of a top-of-file `import` in `chokePoint.ts` unused, remove that binding, and delete the line if no binding remains (lint requires it).
- **Public surface is frozen.** `backend/packages/data/src/__tests__/publicSurface.test.ts` (from #495) must pass without modification. Never edit it: a failure there means the move changed the public API, which is a defect in the move.
- **Boundaries.** `pnpm run check:boundaries` must pass (the rules from #496 and #497). A domain module never imports another domain module.
- **Header comment.** The new file starts with a comment stating what the module owns, what does not belong in it, and the ADRs listed in this issue that constrain it.
