## Context

Model tier rationale: Two additive select options applied through an existing per-tenant cutover pattern and the seed, with idempotency covered by the existing cutover fixtures and no new lifecycle, authorization or tenant contract.

Health records carry tags (`tags`, a multi-select) with four options today: blood tests, medication, epilepsy and dental hygiene (`backend/packages/data/src/seed/seedTenDatabases.ts`). The app's Inbox card for a health record offers two more, Blood pressure and Prevention, and proposes Blood pressure for a doctor's visit note. Without them the assistant can only propose a tag that is not in the catalog.

The Health records database is schema-locked, so existing tenants change only through a per-tenant cutover registered in `runTenantCutoverMigrations` (`backend/packages/data/src/db/tenantCutoverMigrations.ts`; see `docs/adr/2026-10-08-deploy-time-tenant-work-runs-as-the-runtime-role.md`). `backend/packages/data/src/transcription/transcriptsCatalogCutoverMigration.ts` is the pattern: a table lock, an idempotency check, then an update of `properties.config`. New tenants get their options from the seed. Labels come from `backend/packages/data/src/seed/i18n/cs.json` and `en.json`.

It builds on the reordered status catalog (#1578) and the aligned Czech labels (#1413) only because all three edit the same seed, cutover and catalog files. #1705 colors these options, #1990 grounds proposals in them, #1836 adds a link from tasks, and #1808 marks the database sensitive; they share the same files.

Decision: the two new options are appended after the existing four; the order of tags carries no meaning.

Shared-file ordering: this issue also waits for #1698 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `canonical-keys` and `testing`.

1. In `seedTenDatabases.ts` add the option keys `bloodPressure` and `prevention` to the end of the Health records `tags` option list.
2. Add the Czech and English labels in `seed/i18n/cs.json` and `seed/i18n/en.json`: `property.healthRecords.tags.option.bloodPressure` = "Krevní tlak" / "Blood pressure" and `property.healthRecords.tags.option.prevention` = "Prevence" / "Prevention".
3. Add `backend/packages/data/src/seed/healthRecordTagsCutoverMigration.ts`, a per-tenant function: resolve the tenant's Health records database by module id (do nothing when it does not exist), `LOCK TABLE properties IN EXCLUSIVE MODE`, read the `tags` property's `config.options`, append each of the two keys that is missing (keeping every stored option object and its order unchanged), and `UPDATE properties SET config = ...` only when something was appended. Register it in `runTenantCutoverMigrations`.
4. Tests: a new tenant has all six options; an existing tenant created before the change gains exactly the two options after the cutover; a second run changes nothing; stored filters and existing items with the old four keys are unaffected; `GET /api/schema` returns the Czech and English labels for the two new options.

## Acceptance criteria

- When `GET /api/schema` is requested for a new tenant, then `tags` lists Krevní tlak and Prevence (English Blood pressure and Prevention) next to the four existing options.
- When the cutover runs on an existing tenant, then the same two options appear; running it again changes nothing, and existing option keys, items and saved filters are unchanged.
- When a tenant has no Health records database yet, then the cutover does nothing.
