**Model tier:** medium

## Context

Model tier rationale: One extension of the thread detail read model with a batched query using the existing link shape, no new contract.

The thread detail (#1632) lists the thread's attachments but not which project each file has or whether it is inherited. After #1898 an attachment file has `Files.projects` that is normally inherited from the thread, and the value-link read shape of #1403 describes it (`valueKind` `inherited` | `inheritedBroken`, `sources`, `brokenBy`).

Shared-file ordering: this issue also waits for #2033 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `canonical-keys` and `testing`.

1. Extend each attachment of `GET /api/mail/threads/:threadId` with `project` (`{ id, name } | null`; a soft-deleted project reads as `null`) and `links` in the shape of #1403, with an entry for `project` only when the file has a value-link row.
2. Resolve the projects and links of all attachments of the thread in batched queries, not per file.
3. Add the cases to the tenant-isolation route test.

## Touches

- backend/packages/data/src/mail/mailThreadsStore.ts (detail attachments; created by #1632)
- backend/packages/data/src/mail/mailThreadRouteHandlers.ts (response mapping only)
- backend/services/semprec-api/src/__tests__/tenantIsolationRoutes.test.ts
- backend/packages/data/src/mail/__tests__/ (new tests)

## Scope

### In scope

- `project` and `links` on each attachment of the thread detail.

### Out of scope

- Inheriting the project (#1898).
- Company or people of an attachment; thread-level company, project and links (#1897).

## Acceptance criteria

- An attachment inheriting the thread's project returns the project and `links.project.valueKind` equal to `inherited`.
- After a manual change of the file's project, the response shows the new project with `inheritedBroken`.
- An attachment without any project returns `project` equal to `null` and no `links` entry.
