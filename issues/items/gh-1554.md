## Context

Model tier rationale: One idempotent backfill step and one property default declaration following the existing cutover pattern, with no new authorization, concurrency or isolation contract.

A new area created without an `active` value currently has no value for it, and the overview query "areas where `active` equals true" (the overview lists active areas only) therefore omits it. The product rule is that a new area is active unless said otherwise; the inbox card that creates an area writes `active` from its "show on overview" switch. Deactivating an area cascades nothing: its projects and other relations stay untouched.

#1389 makes the item create path apply a property's `config.default` when the caller omits the value. This issue declares that default on Areas.`active` and backfills areas that already exist without a value. It builds on #1515, which created the cutover file for the Areas properties and registered it in `runTenantCutoverMigrations` (`backend/packages/data/src/db/tenantCutoverMigrations.ts`).

Decision: "without a value" means the key is absent from the area's `properties` or is `null`. An explicit `false` is never changed.

## Task

Load `db-migrations`, `state-writes` and `testing`.

1. Declare `config: { default: true }` on the Areas `active` property in `seedTenDatabases.ts`, in the form #1389 defines for property defaults.
2. Extend the Areas cutover step (`backend/packages/data/src/seed/areasPropertiesCutoverMigration.ts`) to, for every maintained tenant (suspended ones included): set `config.default = true` on the existing `active` property under the same `LOCK TABLE properties IN EXCLUSIVE MODE` transaction, only when it is not already set; and set `active = true` on every area item (soft-deleted ones included) whose `active` is absent or `null`, using `migrateItemPropertyWithClient` from `backend/packages/data/src/chokePoint/itemMigrationWrites.ts` so no hooks run and no invalidations fire. A second run writes nothing.
3. Tests: a fresh area created without `active` reads back `active: true`; a pre-existing area with no value is backfilled; an area with `active: false` stays false; a second cutover run is a no-op (no `updated_at` change).

- The overview query (`active equals true`) returns a newly created area and a backfilled one.
