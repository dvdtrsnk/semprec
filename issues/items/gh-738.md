## Context

Review follow-ups harvested in #728, both from PR #327 and both a value accepted at an edge without the check its consumer relies on:

- `backend/services/semprec-api/src/serve.ts:50`: the `PORT` check rejects non-integers and values `<= 0` but not values above 65535, so `PORT=65536` passes it and fails later with Node's `ERR_SOCKET_BAD_PORT` from `server.listen()` instead of the service's own message.
- `web/src/api/aiUsageOperations.ts:38`: `aiUsageReportSchema` validates `from` and `to` as bare `z.string()`, while `web/src/views/aiUsage/UtilizationPage.tsx:174` slices them as ISO-8601 dates. The backend sends `Date.toISOString()` values (`backend/packages/data/src/aiGateway/aiUsageReport.ts:177-178`).

## Task

1. `serve.ts`: extend the `PORT` check to also reject values above 65535 with the existing message `PORT is not a valid port number: <raw value>`.
2. `aiUsageOperations.ts`: validate `from` and `to` in `aiUsageReportSchema` as ISO-8601 datetimes with `z.iso.datetime()` (zod 4, already a web dependency).

## Touches

- backend/services/semprec-api/src/serve.ts (the `PORT` check at lines 48-50 only)
- backend/services/semprec-api/src/__tests__/serveStartupConfig.test.ts (new)
- web/src/api/aiUsageOperations.ts (`aiUsageReportSchema` only)
- web/src/api/__tests__/aiUsageOperations.test.ts (new)

## Scope

### In scope

- The two checks above and their tests.

### Out of scope

- The `AI_GATEWAY_PORT` check in `semprec-ai-gateway` and every other env var check.
- `UtilizationPage.tsx`.

## Acceptance criteria

- A test in `serveStartupConfig.test.ts` loads `serve.ts` (dynamic import) with `PORT=65536` and the environment variables checked before it set, and the load rejects with `PORT is not a valid port number: 65536`.
- In `aiUsageOperations.test.ts`, `aiUsageReportSchema` accepts a report whose `from`/`to` are `new Date().toISOString()` values and rejects one whose `from` is `"27. 9. 2026"`.
