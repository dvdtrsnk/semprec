### Requirement gh-1461: [mail-threads 03/28] Keep drafts and sent mail out of unread counts

#### Context

Model tier rationale: Touches draft creation, the unread predicates and a per-tenant data backfill, each following an existing pattern, but the backfill must avoid creating provider write-back state, which needs careful verification.

Drafts and sent messages are currently counted as unread. `createEmailDraft` (`backend/packages/data/src/mail/draft.ts`) creates the Emails item without a `read` property, and `sendDraftEmail` (`mail/send.ts`) keeps that item. In the mailbox view an absent `read` counts as unread: the web filter in `web/src/views/mailbox/config.ts` uses `not_equals read true` (SQL `IS DISTINCT FROM`), and the `is:unread` search operator in `mail/search.ts` uses `coalesce((properties->>'read')::boolean, false)`. Changing `read` on an existing Emails item normally triggers `mailMessageFlagsItemUpdateHook`, which records a desired `\Seen` write-back to the provider in `mail_message_flag_sync_state` (`mail/mailMessageFlagSyncStore.ts`). Decision: `createEmailDraft` is the single owner of the rule "a draft is read"; a sent message is the same item, so it stays read. Unread aggregations ignore the Sent and Drafts folders by their `specialPurpose`. The thread list (#1567) builds on this rule.
