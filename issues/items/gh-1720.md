## Context

Model tier rationale: One endpoint that creates an item from a template in a transaction, relying on the series, lock-order and advance logic delivered by blockers.

A recurring task occurrence that has not happened yet is virtual (see #1672). The user must still be able to tick a future occurrence in advance, tick a past one afterwards, or move only that occurrence to another day or time, while the series stays unchanged. The generic item write cannot do this, because a virtual occurrence has no item to patch.

#1605 stores the series template and gives items `seriesId` and `occurrenceDate`; #1670 defines the advance after a completion and the lock order items, then `task_recurrence`. This issue adds the endpoint that turns one virtual occurrence into a real item.

Decision: if the occurrence is already materialized, the same endpoint updates that item instead of creating a second one (idempotent by `seriesId` plus `occurrenceDate`). Ticking an occurrence ahead of the current open one completes it without creating a next occurrence when the next date already exists, using the idempotency of #1670.

Shared-file ordering: this issue also waits for #1702, #1717 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `error-handling`, `io-hardening` and `testing`.

1. Add `POST /api/tasks/series/:seriesId/occurrences/:date` with body `{status?, completedOn?, date?, timeFrom?, timeTo?}`. `:date` is the `occurrenceDate` and must be a date the series rule produces on or after the series `anchor_date`; otherwise 400.
2. In one transaction lock the `task_recurrence` row `FOR UPDATE` after the items it touches, find an existing non-deleted item with the same `seriesId` and `occurrenceDate`, or create one as a copy of the series template with `occurrenceDate` set, then apply the body through the Tasks write path (status `done` triggers the advance hook of #1670). A `date`, `timeFrom` or `timeTo` in the body changes this occurrence only and never the template or other occurrences.
3. Respond with the item. Return 404 for an unknown or foreign series.
4. Register the route in `customRoutes` of the `systemDatabases` manifest, add it to `routeMatrix.ts` and extend the tenant isolation route test.

## Acceptance criteria

- POST for a future date with `status: "done"` creates an item with that `occurrenceDate` and status `done`; a second identical POST returns the same item and creates nothing new.
- After that, the projection of #1672 no longer returns a virtual occurrence for that date.
- POST with `date` and `timeFrom` moves only that occurrence; the series template and other occurrences are unchanged.
- Ticking a past missed occurrence does not create a new occurrence.
- A date the rule does not produce returns 400.
