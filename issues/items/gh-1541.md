**Model tier:** high

## Context

Model tier rationale: A concurrency-sensitive get-or-create of two rows (entry and page) keyed by a computed period, exposed over REST and reused internally, where tenant zone, key conversion and idempotent racing writers all have to be exactly right.

The first write into an empty day, week, quarter or year note (by the user, by Semp or from the Inbox) must create the period's entry and its page, and merely viewing an empty period must create nothing. Today `getOrCreateJournalItem(client, journalDatabaseId, type, referenceDate, timezone)` (`backend/packages/data/src/journal/journalStore.ts`) takes an instant, derives the key itself and creates the entry under a per-period idempotency key `journal:<db>:<type>:<period>`; races are resolved by the reservation in `idempotency_keys` (`chokePoint/itemsStore.ts`). Its only production caller is Inbox capture (`inbox/inboxStore.ts`). `docsStore.getOrCreateDoc(client, itemId, 'page')` (`backend/packages/data/src/docs/docsStore.ts`) needs a live item and converges concurrent creators with `ON CONFLICT`. The sync socket never creates a doc.

#1431 supplies key parsing. After this issue #1603 hooks Inbox re-linking into the new-entry path, #1981 confirms journal proposals into a page, #1676 creates subpages under a not-yet-existing period, and #1861 lets Semp write Journal periods; they all call the internal function defined here.

The '+' action of the Journal collection uses this route as well: the client lets the user pick a period (today by default) and calls it, which opens the existing entry or creates it, so '+' can never produce a duplicate.

Decision: writes are allowed for any period, past or future, without an upper limit; the range shown by a client switcher is a UI concern. The zone is always the tenant's, never taken from the client. The route is covered by the existing same-origin check on unsafe requests (ADR `docs/adr/2026-10-18-same-origin-check-on-unsafe-requests.md`).

Shared-file ordering: this issue also waits for #1537 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes`, `canonical-keys`, `io-hardening` and `testing`.

1. Add the internal `ensureJournalPeriodDoc(client, type, period)` in the journal module: parse the key with `parseJournalPeriodKey` (#1431), convert it to the reference instant (start of the period at 00:00 in the tenant zone from `getSystemTimezone`), verify that `computeJournalPeriodKey(type, reference)` gives the same key (otherwise `ValidationError`), look up the Journal database id (owner module `journal`), call `getOrCreateJournalItem` and `docsStore.getOrCreateDoc(itemId, 'page')`, and return `{ itemId, docId, period, range }`.
2. Add `PUT /api/journal/periods/:type/:period/doc`, a custom route with justification `transactional-semantics`, running `ensureJournalPeriodDoc` in one transaction and answering 200 `{ itemId, docId, period, range: { from, to } }`. Invalid type or key answers 400; no session 401.
3. Idempotency: repeated and concurrent calls for one period return the same `itemId` and `docId` and leave exactly one entry and one doc.
4. Declare the route in the system databases module manifest, add the handler and export, a `routeMatrix.ts` entry and a case in `tenantIsolationRoutes.test.ts`.
5. Realtime: the entry's item-create invalidation is sent by the choke point after commit; nothing is added for the doc, which is announced by its first sync write.
6. Tests: two concurrent PUTs for `day/2026-10-16` return equal ids with one row each; `week/2026-W53` creates `type = week`, `period = 2026-W53`; `day/2031-05-02` succeeds; an invalid key is 400; `week/2027-W01` and `day/2027-01-01` (week `2026-W53`) create the right keys; the returned `docId` opens through `/api/sync`; an Inbox capture still works.

## Scope

### In scope

- The idempotent get-or-create of a period entry and its page, as an internal function and as one route.

### Out of scope

- Refusing manual creation; #1428.
- Calling it from journal proposals (#1981), subpage creation (#1676) and Semp (#1861); each calls the internal function in its own issue.
- Reading a period without creating it; #1537.
- Restoring a trashed period and re-linking Inbox items; #1666 and #1603.

## Acceptance criteria

- When two concurrent PUT calls target `day/2026-10-16`, then both return the same `itemId` and `docId` and the database has one entry and one doc.
- When PUT targets `week/2026-W53`, then an entry with type `week` and period `2026-W53` exists and a second call returns the same `itemId`.
- When PUT targets `day/2031-05-02`, then it succeeds; an invalid key answers 400 and no session 401.
- When PUT targets `day/2027-01-01`, then the day entry is created for `2027-01-01` and week `2026-W53` is the week it belongs to; `week/2027-W01` creates `2027-W01`.
- When the returned `docId` is opened over `/api/sync`, then it opens.
