**Model tier:** low

## Context

Model tier rationale: Each section's new query predicate is specified and the response shape stays unchanged.

`GET /api/system-health` is served to every session. It is mounted as the schema-core custom route `systemHealthReport` (`backend/packages/data/src/chokePoint/schemaCoreModuleManifest.ts:78-87`) and backed by `createSystemHealthRouteHandler` (`backend/packages/data/src/observability/systemHealthRouteHandler.ts:12-17`), which calls `getSystemHealthReport(pool)` (`backend/packages/data/src/observability/systemHealthReport.ts:171-191`). In a multi-tenant deployment three of its sections are operator data, or leak other tenants' activity:

- `processes` (`:56-95`) lists the four fixed processes and every `mailsync:<mailboxItemId>` process;
- `alertingChecks` (`getAlertingChecks`, `:98-103`) lists every alerting row of the global `observability_checks` table. #999 added a `UNION ALL` with the caller's `tenant_observability_checks` rows;
- `queue` (`:113-127`) counts every job in `graphile_worker.jobs`, so one user could infer another's activity.

The other sections are tenant data that row-level security already narrows, because the custom route runs in the caller's tenant scope (#980): `itemAutomationErrorsByDatabase` (`:134-144`), `agentRunErrors7d` (`:146-151`) and `mailboxes` (`:153-162`, `listAllMailAccountSyncStates`).

#1038 moved the operator view into the admin-only `GET /api/admin/health` (`getOperatorHealthReport`). This issue makes the per-user report contain only the caller's own tenant.

**Response shape must not change.** The REST contract is additive-only (`docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`), and the web client parses all seven keys as required (`web/src/api/systemHealthOperations.ts:60-68`). Every key therefore stays, with the same types, and only its contents narrow. The web System page is reworded later (#1082).

Facts this issue relies on:

- The queue envelope is `{ traceId, tenantId: string | null, payload }`, stamped by `enqueueJob` from the enqueuing scope (#982). In `graphile_worker.jobs.payload` the tenant is therefore `payload->>'tenantId'`.
- `app_current_tenant()` returns the `app.tenant_id` GUC as a uuid. It returns NULL in system scope.
- Per-mailbox stall checks are rows of the tenant table `tenant_observability_checks` with `status ∈ ok|alerting` (#999).
- `getActiveMailSyncProcessNames` (`backend/packages/data/src/health/processHeartbeats.ts:99`) reads tenant tables, so under RLS it yields only the caller's mailboxes.

## Task

Load `io-hardening` (an existing route's exposure changes) and `error-handling`.

1. In `systemHealthReport.ts`, change `getSystemHealthReport(client)` so that, with the caller's tenant scope active:
   - `processes` holds one entry per name from `getActiveMailSyncProcessNames(client)`, built by the same freshness mapping as today. The four fixed process names are no longer included.
   - `alertingChecks` holds only the caller's alerting `tenant_observability_checks` rows, in the existing `AlertingCheck` shape (`checkKey`, `detail`, `changedAt`). Drop the `observability_checks` half of `getAlertingChecks`' `UNION ALL`. The operator report reads that table itself (#1038).
   - `queue` keeps the same three counts and predicates as `getQueueHealthCounts`, restricted to jobs whose `payload->>'tenantId' = app_current_tenant()::text`.
   - `itemAutomationErrorsByDatabase` and `agentRunErrors7d` keep their queries and rely on RLS. Add an explicit `tenant_id = app_current_tenant()` predicate to both (`ia.tenant_id` in the `item_automation` join) as a second, code-level guard. `mailboxes` keeps calling `listAllMailAccountSyncStates` unchanged, under RLS. Do not edit `mailAccountSyncStateStore.ts`.
   - If `app_current_tenant()` is NULL (no tenant scope), throw instead of returning a report. The handler always runs in tenant scope, so this only catches a wiring bug and must surface as a 500, never as an empty-looking report.
2. Update the docstrings of `getSystemHealthReport`, `createSystemHealthRouteHandler` and the manifest's `systemHealthReport` justification comment so they describe a per-tenant snapshot. Operator health is `GET /api/admin/health`.
3. Rewrite the affected cases in `backend/packages/data/src/__tests__/systemHealthReport.test.ts` against two tenants.

## Scope

### In scope
- The per-tenant contents of `GET /api/system-health`, with an unchanged response shape.

### Out of scope
- The operator report and `GET /api/admin/health` (#1038).
- Web changes to the System page (#1082).
- Moving or reclassifying observability checks (#999).
- Removing any response field. That would be a breaking contract change, and none is planned.

## Acceptance criteria

- With tenants A and B each having a mailbox with a sync heartbeat, B's report lists only B's `mailsync:<id>` process and none of the fixed `api`/`agents`/`transcribe`/`ai-gateway` processes (integration, `systemHealthReport.test.ts`, two tenants via `createTestTenant()` from #975).
- When A has an alerting `tenant_observability_checks` row and a global `observability_checks` row is alerting, B's `alertingChecks` is empty and A's contains only A's row (integration, `systemHealthReport.test.ts`).
- When A has two pending jobs, one overdue job and one permanently failed job enqueued in A's scope, and B has one pending job, A's `queue` is `{ pending: 2, overdue: 1, permanent: 1 }` as the existing predicates define them, and B's `pending` is 1. A job enqueued in system scope (`tenantId: null`) is counted for neither (integration, `systemHealthReport.test.ts`).
- When A has `item_automation` errors, an errored agent run and a mailbox with a `lastError`, none of A's database ids, counts, mailbox ids or error strings appear anywhere in B's serialized report (integration, `systemHealthReport.test.ts`).
- When `GET /api/system-health` is called by B's session, the response still has exactly the keys `generatedAt`, `processes`, `alertingChecks`, `queue`, `itemAutomationErrorsByDatabase`, `agentRunErrors7d` and `mailboxes`, with today's types (integration, `systemHealthRouteHandler.test.ts`).
- When `getSystemHealthReport` is called with no tenant scope active, it throws and returns no report (integration, `systemHealthReport.test.ts`).
