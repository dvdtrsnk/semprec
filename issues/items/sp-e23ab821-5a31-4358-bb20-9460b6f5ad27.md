## Context

Model tier rationale: A long-lived WebSocket in shared code with reconnection and backgrounding rules.

Clients learn about server changes only by polling or on appear; the backend publishes thin frames on `WS /api/sync`.

## Task

Load `kmp-shared`, `shared-viewmodel`, `apple-swiftui`, `mobile-navigation`, `canonical-keys`, `testing` and `mobile-verify`.

1. Shared: a sync socket client (Ktor WebSockets) authenticated like REST, reconnecting with backoff, paused in background.
2. A change bus in the shared data layer that maps frames (item/relation/notification) to repository revisions; calendar, mail account and invitation ViewModels reload on matching revisions instead of polling.
3. Remove the 10 s mail-account polling where the socket covers it.

## Touches

- mobile/shared/data/.../SyncSocket.kt (new)
- mobile/shared/domain/ (change bus)
- mobile/shared/presentation/ (calendar, accounts, invitations ViewModels)

## Scope

### In scope

- Socket, change bus and the three screens.

### Out of scope

- Other screens (they keep their refresh).

## Acceptance criteria

- A remote calendar change applied by the server appears in an open calendar within seconds without user action.
- The socket reconnects after the network returns.
