## Context

Model tier rationale: Two read-only agent tools that reuse the transcript read composition of the detail endpoint and follow the existing manifest-declared tool pattern (`heartbeatAgentTools.ts`); the points needing care are tenant scoping of the run and the size limit of a returned range.

Semp, the agent, can read any item through the generic `item.get`, but for a transcript that returns raw `computed` data: the segments carry anonymous keys (`SPEAKER_00`), the generated notes contain speaker tokens, and a long meeting is far too large to read whole. A user asking "what did we promise the client?" needs the speakers' real names, the notes, and the ability to read a specific stretch of the recording with some surrounding context.

This issue adds two read tools to the systemDatabases module: `transcript.get` (the transcript's header, speakers with names, summary, decisions, action items with owners, the Event, and the number of segments) and `transcript.segment.get` (a range of segments with speaker names and a few segments of context on both sides). They share the composition of the transcript detail endpoint (#1576), the rendering of meeting notes with speaker names (#1695) and the display-name function of #1830. The tools are declared in the module manifest next to the routes (`backend/packages/data/src/seed/systemDatabasesModuleManifest.ts`, `agentTools`, which is empty today); an agent tool handler has the signature `(currentRunId, args) => { error, result }` as in `backend/packages/data/src/scheduler/heartbeatAgentTools.ts`. Adding module-declared tools to agent sessions is a separate piece of the Semp chat work and is not part of this issue. Attaching a stretch of a transcript to a chat message is #1834.

Decisions:

- Both tools read only within the tenant of the calling run; a transcript of another tenant, an unknown id and a trashed transcript all give the identical "not found" error result.
- The size limit applies to the requested range: at most 200 segments or 15 minutes of recording, whichever is reached first, otherwise `validation_failed` with reason `rangeTooLarge`; the surrounding context (default 3 segments on each side, at most 3) is added on top.
- The tools write nothing. By the product owner: Semp has only read tools over transcripts; no write tool and no exception in the approval rules is added.

Shared-file ordering: this issue also waits for #1825 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Add `backend/packages/data/src/transcription/transcriptAgentTools.ts` with `createTranscriptGetTool(pool)` and `createTranscriptSegmentGetTool(pool)`, each `(currentRunId, args) => Promise<{ error: boolean; result: string }>` with `result` a JSON string, arguments parsed with strict zod schemas.
2. `transcript.get { transcriptId }` returns `{ transcriptId, displayName, date, durationSeconds, language, speakers: [{ speaker, label }], summary, decisions, actionItems: [{ id, text, ownerLabel, due }], event: { id, name, date } | null, segmentCount, speakerCount }`, built from the same read as the detail endpoint with speaker tokens in the notes replaced by names (full name for an owner, first name in running text). A transcript without notes yet returns `summary: null`, `decisions: []`, `actionItems: []`.
3. `transcript.segment.get { transcriptId, fromIndex | startsAt, toIndex | endsAt, context? }` accepts either an index range or a time range in seconds (not both; neither or both is `validation_failed`), returns `{ transcriptId, from, to, segments: [{ index, speaker, label, text, startsAt, endsAt, isContext }] }` with `isContext` true for the surrounding segments, ordered by index, and enforces the limit above.
4. Resolve the tenant from the run (the run's own tenant scope, like the other tools); never accept a tenant or project argument.
5. Declare both in `agentTools` of `systemDatabasesModuleManifest.ts` with `capability: "core.item.read"`, re-export the factories in the export block of that manifest file (the way `schemaCoreModuleManifest.ts` re-exports the heartbeat tools), and add the labels `agentTool.transcript.get.label` ("Load meeting transcript" / "Načtení přepisu schůzky") and `agentTool.transcript.segment.get.label` to `backend/packages/data/src/seed/i18n/{cs,en}.json`. The result of `transcript.get` carries `durationSeconds` and `speakerCount` so a client can render the step line of the run from it.
6. Tests in `backend/packages/data/src/transcription/__tests__/transcriptAgentTools.test.ts`: names instead of `SPEAKER_xx` in both tools; a 5:12 to 6:30 range with context; a 20-minute range returns `rangeTooLarge`; both ways of addressing a range; a foreign tenant's transcript, an unknown id and a trashed transcript give identical results; a transcript without segments; the manifest registry accepts the declarations (including the capability).

## Scope

### In scope

- The two read tools, their declaration, labels and tests.

### Out of scope

- Making module-declared tools available in agent sessions: a separate piece of the Semp chat work.
- Message refs to transcript segments and their expansion into a chat turn: #1834.
- Tools or approval rules for Semp writes over transcripts (speaker mapping, action item state, inherited values): not done (decided by the product owner: read tools only).
- Searching across transcripts.

## Acceptance criteria

- When Semp asks about what was promised in a meeting, `transcript.get` returns the notes and action items with the speakers' names, not `SPEAKER_xx`.
- `transcript.segment.get` for the range 5:12 to 6:30 returns the segments in it plus three on each side, with names; a 20-minute range returns `validation_failed` with reason `rangeTooLarge`.
- A transcript of another tenant, an unknown id and a trashed transcript all return the same error result.
- Neither tool changes any data.
