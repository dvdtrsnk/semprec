## Context

The batch splits `backend/packages/data/src/chokePoint/chokePoint.ts` into per-domain modules under `backend/packages/data/src/chokePoint/`. The split only stays a split if domain modules cannot quietly start importing one another again. This issue adds that guarantee as a dependency-cruiser rule before any domain module exists. The rule matches file names, so every module later issues create is covered from its first commit.

`pnpm run check:boundaries` (`depcruise --config .dependency-cruiser.cjs … modules services packages`, run by `pnpm run verify` and CI) enforces `backend/dependency-cruiser.rules.json`. `backend/packages/module-boundaries/src/__tests__/module-boundaries.unit.test.ts` tests rules against fixture trees in `backend/packages/module-boundaries/src/__tests__/fixtures/`.

## Task

Append the rule **`no-choke-point-domain-cross-import`** (severity `error`) to the `forbidden` array of `backend/dependency-cruiser.rules.json`. Give it a `comment` in the style of the existing rules, naming this batch.

- The domain modules are these files under `packages/data/src/chokePoint/`, matched with one explicit alternation, not a wildcard: `databaseOps.ts`, `propertyOps.ts`, `relationPropertyOps.ts`, `relationOps.ts`, `itemWrites.ts`, `itemReads.ts`, `itemTrash.ts`, `viewOps.ts`, `viewQueryOps.ts`, `destructiveProjection.ts`.
- A domain module must not import another domain module.
- Importing anything else stays allowed. That includes the shared modules (`authorization.ts`, `databaseGuards.ts`, `computedKeyRegistry.ts`, `relationEdgeContext.ts`, `chokePointDeps.ts`, `mergeOps.ts`, `viewTypeRegistry.ts`), the `*Store.ts` files, and anything outside `chokePoint/`.

Add fixture-based unit tests next to the existing ones in `module-boundaries.unit.test.ts`:
- a domain module importing another domain module is reported, naming the rule;
- a domain module importing a shared module or a store is not reported.

## Touches

- backend/dependency-cruiser.rules.json (one new entry appended at the end of `forbidden`)
- backend/packages/module-boundaries/src/__tests__/module-boundaries.unit.test.ts (new test cases)
- backend/packages/module-boundaries/src/__tests__/fixtures/ (new fixture subtree for these cases)

## Scope

### In scope
- The rule, its comment and its fixture tests.

### Out of scope
- The import-cycle rule (#497).
- Creating any domain module (later issues in this batch).
- Changing any existing rule, including `no-core-table-write-outside-choke-point` and `items-store-private`.

## Acceptance criteria

- `pnpm run verify` in `backend/` passes, including `check:boundaries` on the real tree.
- Both fixture cases pass. The rule's domain-module list is an explicit alternation of exactly the ten file names above.
