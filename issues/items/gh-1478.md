## Context

Model tier rationale: A new network-isolation contract for raw TCP/TLS connections to tenant-chosen hosts, where a mistake exposes loopback and internal services across tenants, and the refusal must be indistinguishable from an unreachable server.

HTTP clients to user-supplied URLs resolve once and connect only to a vetted address (`backend/packages/data/src/net/outboundAddressPolicy.ts`, `docs/adr/2026-10-16-connect-time-outbound-address-checks.md`). That ADR lists tenant-chosen IMAP and SMTP hosts as a known gap: they are raw TCP/TLS connections made by `imapflow` and `nodemailer`, which resolve the name by themselves, so a tenant could point a mailbox at `127.0.0.1`, a private address, or a public name that resolves to an internal address, and use the connection test as a network scanner. The ADR says a new raw-socket client to a tenant-chosen host adopts the policy lookup or records why it cannot.

This issue provides that for mail: a connection factory for IMAP and SMTP that resolves the host once through the policy, connects to exactly the vetted address, and keeps the original host name as the TLS server name. It is used by the IMAP sync transport (#1510), by the credential check before saving a mailbox (#1569) and by SMTP send (#1634).

Decision: a refused address is reported with the same error as an unreachable server, `mail_server_unreachable`, with no hint about the address, so a route that connects on a user's behalf cannot be used to map the network. The host name is logged, the resolved address is not returned.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. In `outboundAddressPolicy.ts` export the pinned lookup builder (`createPolicyLookup`) if it is not exported, and add `backend/packages/data/src/mail/mailServerConnections.ts`:
   - `openImapConnection(settings, credential, options)`: builds an `ImapFlow` whose `host` stays the original name for the TLS `servername` while the socket connects to the vetted address (use imapflow's `servername` option together with a pre-resolved host through the policy lookup, or a pre-created socket produced through the lookup, whichever the library supports without resolving twice); returns the wrapped `ImapFlowMailClient`.
   - `createSmtpTransporter(settings, credential)`: a nodemailer transporter with `secure`/`requireTLS` from the stored security mode, `tls.servername` set to the host, and a `lookup` option set to the policy lookup. SMTP is not sent in this issue; only the factory.
   - Both map `OutboundAddressNotAllowedError` (see `isOutboundAddressNotAllowed`) and ordinary connect failures (ECONNREFUSED, ETIMEDOUT, ENOTFOUND, TLS failures) to one `MailServerUnreachableError` with the code `mail_server_unreachable`; authentication failures stay distinguishable and are not mapped to it.
2. Add `MailServerUnreachableError` to `providerTypes.ts`.
3. Use the accepted dated record `docs/adr/2026-10-29-mail-connections-through-the-outbound-address-policy.md` documenting IMAP/SMTP adoption and referencing the original outbound-address ADR. Verify its contract against the implementation; preserve both accepted historical bodies rather than appending to the old ADR.
4. The test seam: reuse `allowLoopbackOutboundForTests()` so tests can connect to a fake local IMAP/SMTP server only when it is enabled.
5. Tests: a host that resolves to 127.0.0.1, 10.0.0.1, 169.254.169.254 and `::1` is refused and the thrown error is the same class and message as for a closed port; a name that resolves to a public address connects and the TLS server name is the original host; a single resolution happens (spy on the lookup); a certificate for another name is refused; authentication failure is not `mail_server_unreachable`.

## Acceptance criteria

- When the host is `127.0.0.1`, an address in 10.0.0.0/8, or a public name that resolves to an internal address, then no connection is made and the error is identical to the one for an unreachable server.
- When the host resolves to a public address, then the connection is made to that address and the TLS server name is the original host.
- When the name is resolved, then it is resolved exactly once per connection.
- When the server rejects the credentials, then the error is an authentication error, not `mail_server_unreachable`.
