## Context

Model tier rationale: Adding two optional properties to one system database follows the existing per-tenant cutover and seed pattern, with no new lifecycle or contract.

The Books database (seeded by `backend/packages/data/src/seed/seedLibraryModule.ts`) has `name`, `author`, `cover`, `rating` and `status`. Movies already have `year` and `type`. To fill book metadata automatically later (#1655) and to match the same book again, Books need a publication year and an ISBN. The ISBN is an internal matching key: optional, not shown as a main field. Both properties are user-owned (`owner: user`); the rule that lets automation fill them while they are empty is decided in #1575.

Existing tenants already have the Books database, and the seed never re-runs for them, so the properties are added by a per-tenant cutover, run once per tenant through `runTenantCutoverMigrations` in `backend/packages/data/src/db/tenantCutoverMigrations.ts` (`forEachMaintainedTenant`, runtime role; see `docs/adr/2026-10-08-deploy-time-tenant-work-runs-as-the-runtime-role.md`). The model to follow is `backend/packages/data/src/transcription/transcriptsCatalogCutoverMigration.ts`. A plain SQL migration that inserts property rows is not suitable: every tenant table now needs `tenant_id`.

This issue builds on #1361 because both edit the library i18n catalogs.

Shared-file ordering: this issue also waits for #1509 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `db-migrations`, `canonical-keys` and `testing`.

1. In `seedLibraryModule.ts` add to Books `year` (type `number`, owner `user`) and `isbn` (type `text`, owner `user`), after `author`, with `name: null` like the neighbors (names come from i18n).
2. Add the keys `property.books.year.name` and `property.books.isbn.name` to `backend/packages/data/src/library/i18n/cs.json` ("Rok", "ISBN") and `en.json` ("Year", "ISBN").
3. Add `backend/packages/data/src/library/libraryBooksYearIsbnCutoverMigration.ts`: for the tenant in scope, find the Books database by module id; create `year` and `isbn` if absent, using the same property-creation path as the transcripts catalog cutover (the database is `schema_locked`; use the sanctioned path for system databases). No-op when both exist or when there is no Books database. Register it in `tenantCutoverMigrations.ts` after the existing cutovers.
4. Bump the library module manifest version in `backend/packages/data/src/library/libraryModuleManifest.ts` (minor).
5. Tests in `backend/packages/data/src/__tests__/library.test.ts`: a fresh seed has both properties with the right types and owner; the cutover on a tenant seeded without them adds them; a second run changes nothing; a number value for `year` and text for `isbn` can be written, a text `year` is refused.
