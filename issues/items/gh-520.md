**Blocked by:** #515, #518

## Context

Since #515, `backend/packages/data/src/chokePoint/itemTrash.ts` holds the trash code. `softDeleteItem` is a thin `withTransaction` wrapper around `itemDeleteWithClient(client, …)`, which holds the logic. `restoreItem` instead keeps its whole cascade-restore logic inside the `withTransaction` callback, so the two halves of the same trash feature have different shapes.

`itemDeleteWithClient` is exported because `packages/application`'s gateway executes approved deletes through it. Nothing needs a restore inside a caller's transaction, so the new function stays **unexported**. Exporting it without a caller would be speculative generality (`docs/adr/2026-09-10-no-speculative-generality-beyond-issue-scope.md`).

## Task

Move the body of `restoreItem`'s transaction callback, unchanged, into a new unexported function `async function restoreItemWithClient(client: PoolClient, databaseId: string, itemId: string, actingUserId?: string): Promise<ItemRow | null>`. Place it directly after `itemDeleteWithClient`, and move the JSDoc that describes the restore semantics onto it. `restoreItem` becomes `return withTransaction(pool, (client) => restoreItemWithClient(client, databaseId, itemId, actingUserId));`, with a one-line JSDoc pointing to `restoreItemWithClient`.

## Touches

- backend/packages/data/src/chokePoint/itemTrash.ts (`restoreItem`, and the new function placed after `itemDeleteWithClient`)

## Scope

### In scope
- The extraction described above.

### Out of scope
- Exporting `restoreItemWithClient`, or adding it to `index.ts`.
- Any change to restore semantics.
- `collectItemSubtree` (#518).

## Acceptance criteria

- `pnpm run verify` in `backend/` passes. `src/__tests__/publicSurface.test.ts` passes unmodified, so `restoreItemWithClient` is not exported from `@semprec/data`.
- The existing restore tests in `chokePoint.test.ts` (or `itemTrash.test.ts` once #521 has merged) (the `item trash` describe block, including the concurrent-restore test) pass unmodified.
- `restoreItemWithClient` is not exported from `itemTrash.ts`.
