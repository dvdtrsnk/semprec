## Context

`backend/services/semprec-api/src/routeMatrix.ts` is issue #143's inventory of every route this service answers, and `backend/services/semprec-api/src/__tests__/routeMatrix.test.ts` drives every `surface: "api"` entry against the real dispatcher with no credentials (and again with a garbage bearer token), so a route that is not listed is simply not covered by the "rejects unauthenticated access" check. Three authenticated routes are missing from `ROUTE_MATRIX`:

- `POST /mcp` — dispatched in `backend/services/semprec-api/src/app.ts` line 118 to `createMcpRequestListener` (`backend/services/semprec-api/src/mcp/mcpHandler.ts`), which authenticates via a run credential or `authenticateRequest`.
- `POST /api/agent-runs/mcp-credentials` — `MCP_CREDENTIALS_PATH` in `backend/services/semprec-api/src/agentRunHandler.ts` line 36, gated by `authenticateRequest` at line 79.
- `POST /api/transcriptions` — the `createTranscription` custom route declared in `backend/packages/data/src/seed/systemDatabasesModuleManifest.ts` lines 73-81 and mounted through `mountCustomRoutes`, which authenticates every custom route. Its sibling `POST /api/transcriptions/:id/rerun` is already listed.

`backend/services/semprec-api/src/__tests__/chokePointWriteBoundary.unit.test.ts` keeps a `ROUTE_HANDLER_FILES` map keyed by `ROUTE_MATRIX` entry names and fails when the two sets differ ("maps every registered api route to the handler file that owns it"), so every new matrix entry needs a mapping there too.

## Task

- Add three `RouteMatrixEntry` objects to `ROUTE_MATRIX` in `routeMatrix.ts`, all `surface: "api"`, `public: false`:
  - `{ name: "mcp json-rpc endpoint", method: "POST", path: "/mcp" }`, placed next to the "agent run detail" entry;
  - `{ name: "mint mcp run credential", method: "POST", path: "/api/agent-runs/mcp-credentials" }`, placed right after "agent run detail";
  - `{ name: "create transcription", method: "POST", path: "/api/transcriptions" }`, placed right before "transcription rerun".
- Add the matching lines to `ROUTE_HANDLER_FILES` in `chokePointWriteBoundary.unit.test.ts`:
  - `"mcp json-rpc endpoint": "services/semprec-api/src/mcp/mcpHandler.ts"`
  - `"mint mcp run credential": "services/semprec-api/src/agentRunHandler.ts"`
  - `"create transcription": "packages/data/src/transcription/transcriptionRouteHandlers.ts"`
- No handler changes: all three routes already reject an unauthenticated request with 401 (the generated `routeMatrix.test.ts` cases prove it). If one of them does not, that is a finding to report on the pull request, not something to fix here.
- Add nothing else to the matrix; `GET /api/projects/:id/mcp-grants` and the other listed routes are already covered.
