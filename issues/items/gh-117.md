**Blocked by:** #228, #115, #83

## Context

Issue #228 persists the turn-level protocol log in `agent_run_events` and maps the lifecycle onto `agent_runs`. Two things remain before sessions can be resumed or observed: live progress must be pushed as it happens, and a process restart must leave the stored log in a state from which existing continuation paths work. This part adds the push hook and the startup orphan repair sweep. #118 relies on the sweep to leave delegated runs in a valid failed state, #119 relies on it to guarantee a protocol-valid history, and the realtime batch later consumes the pushed events.

## Task

- **Live push hook.** Push all live events (`turn_start`, `message_update` deltas, completed `message`, `tool_use`/`tool_result`, `turn_end`, run-status changes) through the adapter's event callback from #228 to the realtime push mechanism, so a watcher sees progress as it happens. `message_update` deltas remain WS-ephemeral: they produce a push and never a row in any persistent table.
- **Startup sweep.** At `semprec-agents` service startup, before the process accepts any new triggers (heartbeats, delegations, user messages):
  - Step 1 — close every `agent_runs` row with `status='running'` as `status='error'`, `finished_at=now()`, with reason `interrupted_by_restart` in the error field (the in-memory registry is always empty right after a restart, so every such row is orphaned).
  - Step 2 — for each such run, if its last `agent_run_events` row is a `tool_use` with no matching `tool_result`, append one synthetic `tool_result` describing the interruption so the stored log keeps the tool-calling invariant that every `tool_use` is paired.
- The sweep does not resume anything; recovery is left to the existing continuation paths (heartbeat retry on its next tick, Semp reacting to the error result on reconstruction, the next user message).

## Scope

### In scope

- The live push hook and the startup repair sweep.

### Out of scope

- The DDL, lifecycle adapter, and `unit` handling (#228).
- WebSocket replay protocol, session reuse, MCP, and persistent deltas.

## Acceptance criteria

- Deltas are observable live through the push hook but absent from PostgreSQL.
- Restart repair leaves no running orphan and no unmatched final tool use: after the sweep every previously `running` row is `error` with reason `interrupted_by_restart`, and every trailing `tool_use` has a `tool_result`.
- The sweep completes before any new trigger is accepted.
