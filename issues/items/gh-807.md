## Context
Review of pull request #419 found two defects around `web/src/views/systemStatus/SystemStatusPanel.tsx`:
- The agent-run-errors summary paragraph's `className` (currently around line 137) is `report.agentRunErrors7d > 0 ? "system-status__summary--degraded" : undefined`, which omits the base `system-status__summary` class in both branches. The queue summary paragraph (line 77) instead uses `"system-status__summary system-status__summary--degraded" : "system-status__summary"`, always including the base class.
- In `web/src/views/systemStatus/__tests__/SystemStatusPanel.test.tsx`, the test "does not show the empty state while a check is alerting, even with nothing monitored" (currently around line 94) asserts `queryByText(/nothing is being monitored/i)).toBeNull()`, but the component's actual empty-state text is "No system status data is available" (the `systemStatus.empty` message in `web/src/i18n/messages.ts`, rendered by `SystemStatusPanel.tsx` around line 70). The regex never matches anything the component renders, so the assertion is vacuously true and provides no regression protection for the empty state.

## Task
- In `SystemStatusPanel.tsx`, change the agent-run-errors summary paragraph's `className` to always include the base `system-status__summary` class, appending `system-status__summary--degraded` only when `report.agentRunErrors7d > 0`, matching the pattern used by the queue summary paragraph.
- In `SystemStatusPanel.test.tsx`'s test "does not show the empty state while a check is alerting, even with nothing monitored", replace the vacuous `expect(screen.queryByText(/nothing is being monitored/i)).toBeNull()` with `expect(screen.queryByText("No system status data is available")).toBeNull()`, asserting on the real empty-state text in place of the non-matching regex.

## Touches
- web/src/views/systemStatus/SystemStatusPanel.tsx (the agent-run-errors summary paragraph's `className` only)
- web/src/views/systemStatus/__tests__/SystemStatusPanel.test.tsx (the one assertion in the test named above only)

## Scope
### In scope
- The `className` expression named above and the one test assertion named above.

### Out of scope
- Any other paragraph, class, or test case in the system status panel.

## Acceptance criteria
- The agent-run-errors summary paragraph always renders with the `system-status__summary` base class, with `system-status__summary--degraded` appended only when `agentRunErrors7d > 0`.
- The corrected assertion, on its own (independently of the test's other assertions), fails if the panel renders the empty state for a report whose only content is `alertingChecks` (empty `processes` and `mailboxes`) — for example, if `alertingChecks` is dropped from the panel's `isEmpty` guard.
