## Context

Every domain has moved out of `backend/packages/data/src/chokePoint/chokePoint.ts` (#501–#516) and every caller inside `packages/data` imports from the owning module (#522–#527). `chokePoint.ts` still carries the transitional scaffolding from #499: block marker lines, mid-file imports, and re-exports. `backend/packages/data/src/index.ts` still re-exports the public symbols from `chokePoint.ts`. This issue removes the scaffolding so `chokePoint.ts` is only the composition root, as `docs/adr/2026-09-24-choke-point-composed-from-domain-modules.md` describes.

## Task

1. `chokePoint.ts` ends up containing only: the imports at the top of the file, `createChokePoint` (unchanged since #500), and `export type ChokePoint`. Remove every `// ==== block: … ====` marker, the scaffolding comment, every `export { … } from` re-export, and every import it no longer uses. Move the remaining imports to the top.
2. In `index.ts`, export every symbol it exports today from `./chokePoint/chokePoint.js` from its owning module instead: `itemWrites.ts`, `relationOps.ts`, `destructiveProjection.ts`, `databaseOps.ts`, `propertyOps.ts`, `viewOps.ts`, `itemTrash.ts`, `authorization.ts` (`Actor`). `createChokePoint` and `ChokePoint` stay exported from `chokePoint.ts`. Export exactly the same set of names.
3. If anything else in the repository (outside `index.ts`) still imports a moved symbol from `chokePoint.ts`, and that caller is not covered by #522–#527, redirect it here and list it in the pull request description.

## Touches

- backend/packages/data/src/chokePoint/chokePoint.ts
- backend/packages/data/src/index.ts (the choke-point export statements only)
