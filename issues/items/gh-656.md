## Context

`backend/packages/data/src/testSupport/globalSetup.ts` (used by `vitest.integration.config.ts` and `vitest.e2e.config.ts`) creates `mkdtemp(path.join(tmpdir(), "semprec-pg-"))`, starts an `EmbeddedPostgres` in it (lines 57-68) and returns a teardown closure (lines 84-87: `pg.stop()` then `rm(databaseDir, …)`). vitest calls that closure only when the run ends normally. A run killed by `Ctrl-C`, a `SIGTERM` from a supervisor, a Relay run hitting its budget, or a crash of the vitest main process never reaches it: the `postgres` child keeps running with its port and the data directory (~0.6-1.1 GB each after the migrations and Hunspell dictionaries) stays behind. On 2026-09-27 the development host's `/tmp` held 26 `semprec-pg-*` directories (17 GB), 5 of them with a `postmaster.pid`, 3 of those with a live postmaster from a run in another worktree. Nothing ever cleans them up; a dev box or a long-lived CI runner fills its temp disk. Sibling issue #657 of this batch shards the CI job — more processes per run, so the leak would multiply.

## Task

- New `backend/packages/data/src/testSupport/stalePostgresDirs.ts` exporting `sweepStalePostgresDirs(options: { tmpDir: string; now?: () => number; maxAgeMs?: number; isPidAlive?: (pid: number) => boolean }): Promise<string[]>`:
  - lists entries of `tmpDir` whose name starts with `semprec-pg-` and are directories;
  - a directory is stale when its `mtime` is older than `maxAgeMs` (default 24 h) **and** it has no live owner: either no `postmaster.pid` file, or the first line of that file is a pid for which `isPidAlive(pid)` is false (default: `process.kill(pid, 0)` returns without throwing → alive; `ESRCH` → dead; `EPERM` → treat as alive);
  - removes each stale directory with `rm(dir, { recursive: true, force: true })`, ignores a removal error for one directory (another process may be removing it) and continues, and returns the paths it removed;
  - never touches a directory younger than `maxAgeMs`, whatever its pid state (an `initdb` in progress has no `postmaster.pid` yet).
- In `globalSetup.ts` `setup()`: call `await sweepStalePostgresDirs({ tmpDir: tmpdir() })` first thing (before `choosePort`), log the removed paths with one `console.warn` line only when the list is non-empty; then register cleanup for an interrupted run: after `pg.start()`, install `process.once("SIGINT", onSignal)` and `process.once("SIGTERM", onSignal)` where `onSignal` runs the same teardown (`pg.stop()` then `rm(databaseDir, …)`, each in its own `try/catch` so a stop failure still removes the directory) and then re-raises with `process.kill(process.pid, signal)` so vitest's exit code is unchanged; the returned teardown closure removes both listeners before it stops the server, so a normal run tears down exactly once. Wrap the initialise/start/migrate sequence in a `try/catch` that stops and removes the directory before rethrowing, so a failure between `mkdtemp` and the return of `setup()` (a migration error, a port bind failure) leaks nothing either.
- Do not change `choosePort`, the migration sequence, `TEST_DATABASE_URL`, or the `persistent: false` option.
- Tests: new `backend/packages/data/src/testSupport/__tests__/stalePostgresDirs.unit.test.ts` (unit tier, no Postgres; it creates its own temp root with `mkdtemp` and fake directories): removes a 25 h-old directory with no `postmaster.pid`; removes a 25 h-old directory whose `postmaster.pid` names a pid for which the injected `isPidAlive` returns false; keeps a 25 h-old directory whose pid is alive; keeps a 1 h-old directory with no pid file; ignores a sibling entry not named `semprec-pg-*`; returns exactly the removed paths. Set ages with `utimes`. The interrupted-run teardown has no unit test (it needs a real signal and a real server); `pnpm run test:integration` and `pnpm run test:e2e` must still pass, which covers the normal path and the listener removal.

## Scope

### In scope

- Teardown of the embedded Postgres and its directory on `SIGINT`/`SIGTERM` and on a setup failure, plus the startup sweep of stale `semprec-pg-*` directories.

### Out of scope

- Sharding the integration tier or any `.github/workflows/ci.yml` change — #657.
- Parallelising test files (`fileParallelism`) or changing `testTimeout`/`hookTimeout`.
- Cleaning directories that other tools leave in `/tmp` (only the `semprec-pg-` prefix is swept).
- Killing a live postmaster that belongs to a stale directory — a live pid means "not ours to remove".

## Acceptance criteria

- When `pnpm run test:integration` is started and the vitest process receives `SIGINT` while tests are running, no `postgres` process from that run survives and its `semprec-pg-*` directory is gone once the process has exited; the exit status is the signal exit, not 0.
- When `setup()` fails after `mkdtemp` (e.g. a migration throws), the directory is removed and the server stopped before the error propagates.
- When `pnpm run test:integration` starts on a host whose temp dir holds a `semprec-pg-*` directory older than 24 h without a live postmaster, that directory is removed before the new server starts and a `console.warn` line names it; a directory younger than 24 h, or one whose `postmaster.pid` names a live process, is untouched.
- When `pnpm run test:unit` runs, every case in `stalePostgresDirs.unit.test.ts` passes without `TEST_DATABASE_URL`.
- A normal `pnpm run test:integration` / `pnpm run test:e2e` run still ends with no `semprec-pg-*` directory of its own left behind and no signal listener leaked (`process.listenerCount("SIGINT")` back to its pre-setup value after teardown).
