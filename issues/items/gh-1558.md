## Context

Model tier rationale: A small mechanical addition that follows the existing daily retention task pattern exactly (task name, cron entry, per-tenant delete), with no new lifecycle or contract beyond deleting rows past a fixed age.

Resolved problems stay in the store so the status view can list what was resolved in the last seven days (#1919). Without cleanup the table grows forever. This issue deletes resolved problems older than thirty days.

The repository already runs daily per-tenant retention tasks: `handleAgentRunEventsRetentionTask` (`backend/packages/data/src/agentRuns/agentRunEventsRetention.ts`) is declared in `CORE_TASK_NAMES` and `CORE_TASK_AFFINITY` (`backend/packages/queue/src/index.ts`), scheduled in `CORE_CRONTAB` and composed in `createCoreTaskList` (`backend/packages/data/src/worker.ts`), and iterates tenants with `forEachActiveTenant`. This issue adds one more task of the same shape. The store it prunes comes from #1459.

Decision: only rows with `resolved_at` older than thirty days are deleted; active problems are never deleted, however old. The window is a named constant.

## Scope

### Out of scope

## Acceptance criteria

- When the daily task runs, then problems resolved more than thirty days ago are deleted and problems resolved less than thirty days ago remain.
- When a problem is still active, then it is never deleted.
- When tenants A and B both have old resolved problems, then each is pruned within its own tenant scope.
- When the crontab is parsed, then it contains the new task once per day.
