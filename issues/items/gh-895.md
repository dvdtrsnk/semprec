## Context

Review follow-up from harvest issue #889. PR #564 (finding 6b849c5870), `backend/packages/data/src/chokePoint/propertyOps.ts:185`: in `createProperty`'s rollup branch, `(await propertiesStore.getProperty(client, property.id)) as PropertyRow` casts a `PropertyRow | null` to `PropertyRow` without a null check. The row was just created in the same transaction so it cannot be null in practice, but the cast bypasses the type guard (review rule: nothing crossing a boundary stays an unchecked `as`).

## Task

In `createProperty`'s rollup branch, remove the `as PropertyRow` cast on the `propertiesStore.getProperty` result and instead check it: when the result is `null`, throw an `Error` whose message names the property id and says the row created in this transaction could not be read back (an invariant breach, not a domain `NotFoundError`). Use the checked value as `finalProperty`.

Cover the new `null` branch with an integration test in a new file `backend/packages/data/src/__tests__/createRollupPropertyReadBack.test.ts`. Force the read-back to return `null` by mocking the store module the way `backend/packages/data/src/trash/__tests__/purgeExpiredTrash.test.ts` mocks `itemsStore.js`: `vi.mock("../chokePoint/propertiesStore.js", async (importOriginal) => { const actual = await importOriginal<typeof import("../chokePoint/propertiesStore.js")>(); return { ...actual, getProperty: vi.fn(actual.getProperty) }; })`, then `vi.mocked(propertiesStore.getProperty).mockResolvedValueOnce(null)` immediately before the rollup `chokePoint.createProperty` call. The test asserts that `createProperty` rejects with an `Error` whose message contains the created property's id (match the read-back wording, since the id is generated inside the call), that the rejection is not a `NotFoundError`, and that no rollup property with that key exists in the database afterwards (the transaction rolled back).

## Touches

- backend/packages/data/src/chokePoint/propertyOps.ts (the `finalProperty` lookup in `createProperty`'s rollup branch only)
- backend/packages/data/src/__tests__/createRollupPropertyReadBack.test.ts (new file: the one `null` read-back test)

## Scope

### In scope

The cast removal, the null check, and the one test that forces a `null` read-back through a `vi.mock` of `propertiesStore.js`.

### Out of scope

The other `getProperty` call sites, the non-rollup branch of `createProperty`, and any test seam other than the `vi.mock` of `propertiesStore.js` described in the Task (no new parameter, hook or export in production code to force a null read).

## Acceptance criteria

- `propertyOps.ts` contains no `as PropertyRow` cast in `createProperty`.
- When `getProperty` returns `null` after the rollup property was created, `createProperty` throws an `Error` naming the property id instead of dereferencing `null`, and the property is not persisted; the new test in `createRollupPropertyReadBack.test.ts` forces this with `vi.mock` of `../chokePoint/propertiesStore.js` and asserts it.
- Creating a rollup property still returns the final property and still enqueues the rollup backfill (the existing rollup `createProperty` tests in `backend/packages/data/src/__tests__/` pass unchanged), and `pnpm run verify` in `backend/` passes.
