## Context

Model tier rationale: A pure naming function in one file with an existing unit test file; the length limit and collision cases are deterministic and need no new lifecycle or persisted-data contract.

The model sees an MCP tool under the name `mcp_<toolName>` (`toModelToolName(`mcp_${grant.toolName}`)` in `backend/services/semprec-agents/src/agentSessionComposition.ts`, which maps characters outside `[A-Za-z0-9_-]` to `_` and cuts at 64). The server is not part of the name, so two servers that both expose `list_issues` (for example GitHub and Linear) collide. `withUniqueNames` then silently drops the second one with a log warning; neither the model nor the user ever learns that a granted tool is missing.

This issue gives every MCP tool a stable, server-qualified model name:

`mcp_<toolName>_<first 8 hex characters of the server item id>`

where the server id is the `mcpServerItemId` of the grant with dashes removed, lowercased, first 8 characters. The `toolName` part is sanitized with the existing character mapping and shortened so that the whole name is at most 64 characters (`mcp_` is 4, `_` plus 8 hex is 9, so at most 51 characters of tool name). The server name is deliberately not used: a slug of it would change when the server is renamed, and truncation would reintroduce collisions. The id is immutable, so the name survives a rename.

It builds on #1447, which edits the same function and removes inactive servers first. Sending the server and registration ids with each tool call event is a separate concern: #1424.

## Task

Load `testing`.

1. Add an exported pure function `mcpModelToolName(toolName, mcpServerItemId)` in `agentSessionComposition.ts` implementing the rule above, and use it in `createMcpTools` instead of `toModelToolName(`mcp_${grant.toolName}`)`. Generic operation tools keep `toModelToolName` unchanged.
2. Keep `withUniqueNames` as the final safeguard for the remaining collisions (two tools of one server whose sanitized and shortened names are equal) and keep its warning.
3. Unit tests for the cases in Acceptance criteria.

### Out of scope

- Migrating names stored in earlier run histories; old names simply stop matching.

## Acceptance criteria

- When GitHub and Linear both expose `list_issues` and both are granted, then both tools are in the catalog under two different names, and neither is dropped.
- When a server is renamed, then its tools keep exactly the same names.
- For every input, the name matches `[A-Za-z0-9_-]{1,64}`; a 120-character tool name yields a name of exactly 64 characters that still ends with `_` plus the 8 hex characters.
- When two tools of one server shorten to the same name, then the later one is skipped with the existing warning.
- Two servers with different ids produce different suffixes for the same tool name.
