## Context

Model tier rationale: One read-only route that counts existing data with existing functions, in the established custom-route pattern.

The app icon badge shows only things waiting for the user's decision: pending approvals, pending invitations and Inbox items. The client needs the three counts to show a badge and a preview. The count of pending approvals is derived from `listApprovalRequestsQueue(ownerUserId)` (`backend/packages/data/src/mcp/approvalRequestsQueue.ts`) and must equal the pending count served by #1786. The source of invitations does not exist yet (#1901 adds it; #1954 notifies about it), and the Inbox card count is delivered by #1823.

Decisions: the response is `{ pendingApprovals, pendingInvites, openInboxItems }`; all pending approval requests of the user's runs are counted, not only those from chat, the same count as the approval queue, so there is one source of the count (decided by the product owner); `pendingInvites` and `openInboxItems` are `0` until their sources provide a count, and the issues that introduce those counts wire them into this route; which counts enter the icon badge is decided by the user's switches (#1891), not here.

## Task

Load `testing`.

1. Add `countPendingApprovalRequests(client, ownerUserId)` in `mcp/approvalRequestsQueue.ts` (a `COUNT`, not the full queue).
2. Add `GET /api/badge-counts` as a custom route (justification `single-consumer-read`): handler `createBadgeCountsRouteHandler` in `notifications/badgeCountsRoute.ts`, declared in `chokePoint/schemaCoreModuleManifest.ts`; add a `routeMatrix.ts` entry (tenancy `tenant`), an entry in `ROUTE_HANDLER_FILES` of `chokePointWriteBoundary.unit.test.ts`, and coverage in `tenantIsolationRoutes.test.ts`.
3. Add tests: the count equals the number of pending requests of the caller's runs; decided requests are not counted; another user's requests and another tenant's are not counted; the other two fields are 0.

### Out of scope

## Acceptance criteria

- When the user has three pending approval requests, then `pendingApprovals` is 3.
- When a request is decided, then it is no longer counted.
- When another user or tenant has pending requests, then they are not counted.
- `pendingInvites` and `openInboxItems` are 0.
