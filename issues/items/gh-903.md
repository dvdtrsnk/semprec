## Context

Review follow-ups from harvest issue #889, in `backend/services/semprec-api/src/__tests__/`. The approval handler now ignores a body `decidedByUserId` and records the session user, and a dedicated test ("ignores a body decidedByUserId and records the session user as the decider") covers that:
- PR #712 (finding 426e574857), `approvalRequestsHandler.test.ts:102`: in "approves a pending request", `userId` from `createUser()` only feeds the ignored `decidedByUserId` body field.
- PR #712 (finding 32b37d1ce9), `approvalRequestsHandler.test.ts:194`: in "treats a repeated decision as a deterministic no-op ...", `userId` and `otherUser` only feed the ignored field in the two request bodies.
- PR #749 (finding b8873fd200), `approvalReplayComposition.test.ts:62`: `return { requestId: "", itemId: item.id }` follows `expect.unreachable(...)`, whose return type is `never`, so the line is unreachable.

## Task

1. In "approves a pending request", delete the `createUser()` call and the `decidedByUserId` property of the request body.
2. In "treats a repeated decision as a deterministic no-op ...", delete the `userId` and `otherUser` variables and the `decidedByUserId` property of both request bodies.
3. In `approvalReplayComposition.test.ts`, delete the `return { requestId: "", itemId: item.id }` line that follows `expect.unreachable("expected ApprovalRequiredError")`.

## Touches

- backend/services/semprec-api/src/__tests__/approvalRequestsHandler.test.ts (the two tests named above only)
- backend/services/semprec-api/src/__tests__/approvalReplayComposition.test.ts (the one line named above)

## Scope

### In scope

The three deletions.

### Out of scope

The other tests in `approvalRequestsHandler.test.ts` that send `decidedByUserId`, and any handler change.

## Acceptance criteria

- "approves a pending request" creates no extra user and sends no `decidedByUserId`, and still asserts `decidedBy` equals the session user.
- "treats a repeated decision ..." creates no `userId`/`otherUser` and sends no `decidedByUserId`, and still asserts the first decider is kept.
- `approvalReplayComposition.test.ts` has no statement after `expect.unreachable(...)` in that `try` block, and `pnpm run verify` in `backend/` passes.
