## Context

Model tier rationale: One new model call through the existing gateway contract applied to untrusted tool text, with a fill-only write and a non-fatal failure path, using established gateway client and structured-output fixtures.

When a sync discovers tools, their labels are empty until a person writes them (#1391 adds the column and the human write path). The project's tool list is much more useful with a short human label ("Read issues and pull requests") in Czech and English, so after a sync this issue asks the model to propose labels for the tools that have none.

The call goes through the AI gateway, the only process allowed to talk to providers (`/internal/complete`, `backend/services/semprec-ai-gateway/src/completeHandler.ts`). That handler accepts only operations listed in `OPERATION_REQUIRES_PROJECT_ITEM`; this issue adds `mcp_tool_label` there with `false`, because an MCP server is a system source and the call has no project item (`projectItemId: null`), like `transcript_summary`. The caller uses the neutral `AiGatewayClientPort` (`backend/packages/shared/src/aiGatewayClient.ts`); in the API process the HTTP implementation is composed as in `backend/services/semprec-api/src/projectAgentGuidanceComposition.ts`.

The labels are written by the sync flow of both entry points, the sync route #1972 and the queued sync after a confirmed MCP server proposal #1976: after the registrations are materialized, `suggestMcpToolLabels` runs for that server. It never fails the sync: if the gateway refuses (for example budget exceeded) or returns invalid output, it logs and leaves labels empty.

Rules:

- Only registrations of that server that are active and have `display_label IS NULL` are sent, in one call, with their tool name and description as data in the user message (never in the system prompt). Tool text is untrusted server content: the system prompt states that it is data to be described and not instructions.
- Response schema: `{ labels: [{ toolName, cs, en }] }`, each label a plain string of 1-120 characters without line breaks or markup; names not in the request are ignored.
- Each label is stored with `UPDATE ... SET display_label = $2 WHERE id = $1 AND display_label IS NULL`, so a label a person set in the meantime always wins and a later sync never overwrites a stored label.
- Decision: no suggestion is stored when the model returns only one language for a tool; both `cs` and `en` are required.

## Task

Load `ai-gateway`, `state-writes`, `io-hardening` and `testing`.

1. In `completeHandler.ts` add `["mcp_tool_label", false]` to `OPERATION_REQUIRES_PROJECT_ITEM`; update the operation lists in the doc comments of `completeHandler.ts` and `packages/shared/src/aiGatewayClient.ts`.
2. Create `backend/packages/data/src/mcp/mcpToolLabelSuggestion.ts` exporting `suggestMcpToolLabels(pool, gateway, mcpServerItemId)` implementing the rules above (system prompt, response schema, validation, fill-only write, non-fatal errors).
3. Call it from both sync entry points delivered by #1972 and #1976 after a successful sync, passing the API process's gateway client.
4. Tests: gateway handler accepts the new operation and rejects a non-null project requirement mismatch as it does for `transcript_summary`; suggestion fills only empty labels; refusal, timeout and invalid output leave the sync successful and labels unchanged; an injection-style tool description cannot add tools or change stored labels of other tools.

## Scope

### In scope

- The `mcp_tool_label` gateway operation, the suggestion function and its call after both sync entry points.

### Out of scope

- The label column and the human write path: #1391.
- Overwriting or regenerating an existing label.
- Labels in locales other than `cs` and `en`.
- Showing the label in any client.

## Acceptance criteria

- When a sync registers tools without labels and the gateway returns valid labels, then each such registration gets `{cs, en}` labels; registrations that already had a label keep theirs.
- When a person set a label while the call was running, then it is not overwritten.
- When the gateway refuses, times out or returns an invalid schema, then the sync still succeeds and labels stay empty.
- When a tool's description contains instructions, then they are not followed: output for names not in the request is ignored and only schema-valid strings are stored.
- The call is recorded in `ai_gateway_calls` with operation `mcp_tool_label` and no project item.
