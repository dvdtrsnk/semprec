**Blocked by:** #982

## Context

`semprec-agents` is a pure queue consumer (`backend/services/semprec-agents/src/serve.ts:20-57`). It runs three tasks, each wrapped in `registerTask` (`backend/packages/data/src/agentWorker.ts:24-42`):
- `agentRun` and `delegatedAgentRun`, through `createAgentRunTask` (`backend/services/semprec-agents/src/agentRunTasks.ts:72-98`);
- `heartbeatFireAgent`, whose `core.agentRun` action calls `createRunAgentForHeartbeats` (`agentRunTasks.ts:106-131`).

Active modules' agents-affinity tasks are wrapped the same way (`backend/packages/data/src/moduleTasks.ts:101-118`).

A job does all of its work on the one pool in the job's own async context:
- it reads the run (`agentRunTasks.ts:79`, `:112`);
- it composes the session's tools, MCP grants and guidance prompt (`backend/services/semprec-agents/src/agentSessionComposition.ts:118-144`);
- pi-agent-core then calls the tools and the gateway `streamFn` from inside `agent.prompt()` (`backend/services/semprec-agents/src/piAgentSession.ts:91-144`);
- the run's events and close go through `runAgentTurn`/`runAgentSessionForRun` (`backend/packages/agent-runtime/src/lifecycleAdapter.ts:91-202`).

None of that code creates a timer, registry or listener that would outlive the job.

Tenancy state this issue builds on:
- #978: `runInTenant(tenantId, fn)`, `runAsSystem(reason, fn)`, `currentTenantScope()` and `enforceTenantScope(site)` come from `@semprec/shared`.
  - `withTransaction` and every query on a `createPool` pool apply the scope through the GUC `app.tenant_id`.
  - A query with no scope logs `tenant_scope_missing` under `SEMPREC_TENANT_SCOPE=warn` (the default until #1067), or throws `TenantScopeMissingError` under `strict`.
  - Pooled connections are opened detached, so their socket callbacks never inherit a job's tenant.
- #982: the envelope carries `tenantId`, stamped by `enqueueJob` from the producer's scope. `TASK_TENANCY` marks `agentRun`, `delegatedAgentRun` and `heartbeatFireAgent` as `tenant`.
  - `registerTask` runs such a job inside `runInTenant(envelope tenantId)`, and completes it as a no-op for a `suspended`, `deleting` or unknown tenant.
  - A legacy envelope falls back to `app_sole_tenant()` until #1061.
  - `runWorker`, the returned runner's `stop()`, `ensureQueueSchema` and `grantQueueSchemaPrivileges` run inside `runAsSystem`.
- The process's remaining startup work enters its own scope: per-tenant startup repair (#988) and the heartbeat tick (#990).

So no production change is left for this process. What is missing is proof, in the agents composition itself, that a whole agent job runs in its envelope's tenant under `strict` enforcement:
- composition, tool and guidance reads;
- every gateway `streamFn` call;
- event writes and the run's close, on both the success and the failure path;
- the runtime's own start and stop.

#993 reads `currentTenantScope()` inside that `streamFn` to add the gateway tenant header. #1025 stamps NOTIFY payloads from the same scope. This issue pins the behaviour both rely on with a strict-mode test, so an unscoped query anywhere on the agent path fails CI.

## Task

Load `io-hardening` (a long-lived consumer and its shutdown path) and `error-handling` (the failure path must keep its scope).

1. **No production change.** `serve.ts`, `queueRuntime.ts`, `agentRunTasks.ts`, `agentSessionComposition.ts` and `lifecycleAdapter.ts` stay as they are. If a criterion below fails because a query on the agent path runs outside the job's scope, stop and report the call site with its `path:line`, without fixing it here. The fix belongs to whichever issue owns that path.
2. **Test.** Create `backend/services/semprec-agents/src/__tests__/agentsTenantScope.test.ts` (integration).
   - Mirror the setup of `backend/services/semprec-agents/src/__tests__/agentRun.e2e.test.ts:100-140`: `loadFullModuleRegistry`, a faux pi provider, and a `GatewayModel` whose `streamFn` records `currentTenantScope()` on every call before delegating.
   - Use a pool from `createPool(process.env.TEST_DATABASE_URL)`, so autocommit queries are scope-checked too.
   - Set `SEMPREC_TENANT_SCOPE=strict` for each case and restore it afterwards.
   - Tenant zero is the id returned by `SELECT app_sole_tenant()` in the test database.
   - Create fixtures and enqueue jobs inside `runInTenant(<tenant zero>, …)`: `seedSystem`, a user, `createAgentRun`.
   - Call `createAgentsQueueRuntime` and `runtime.stop()` from the test body with no ambient scope.

## Acceptance criteria

All integration tier, in `agentsTenantScope.test.ts`, with `SEMPREC_TENANT_SCOPE=strict` unless stated otherwise.
- **Runtime lifecycle.** `createAgentsQueueRuntime(pool, registry)` resolves and `runtime.stop()` resolves, both called with no ambient scope, without any `TenantScopeMissingError`.
- **`agentRun` job.** An `agentRun` job for a `running` run of tenant zero, enqueued inside tenant zero's scope, runs to completion:
  - the run row ends `done` with the faux model's text;
  - its graphile job row is gone;
  - every recorded `streamFn` call saw `{ kind: "tenant", tenantId: <tenant zero> }`.
- **`delegatedAgentRun` job.** The same holds for a `delegatedAgentRun` job.
- **`heartbeatFireAgent` job.** A `heartbeatFireAgent` job for the seeded `core.agentRun` heartbeat, enqueued inside tenant zero's scope, opens a run that ends `done`. Every recorded `streamFn` call saw tenant zero's scope.
- **Failure path.** When the faux model fails, the run ends `error` with exactly one `agent_run_error` notification. The scope recorded at the failing call is tenant zero's. Nothing on that path raises `TenantScopeMissingError`.
- **`warn` mode unchanged.** With `SEMPREC_TENANT_SCOPE=warn`, the existing `queueRuntime.test.ts`, `startupRepairComposition.test.ts` and `agentRun.e2e.test.ts` pass unchanged.
