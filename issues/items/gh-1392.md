## Context

Model tier rationale: Three entries in one existing allow-list map with the validation branches already in place, plus unit tests that follow the existing completeHandler tests.

`POST /internal/complete` of `backend/services/semprec-ai-gateway/src/completeHandler.ts` accepts only operations listed in the `OPERATION_REQUIRES_PROJECT_ITEM` map: `agent_guidance_drift` (project item required), `transcript_summary` and `transcript_speaker_suggestion` (no project item). The map value says whether the caller must send a `projectItemId`; the caller supplies the `responseSchema`, so the gateway needs no knowledge of the output shape. The Inbox needs three new operations: proposal computation for an Inbox item, extraction of data from an attachment, and the pick of the best Event for a transcript. Without them the gateway answers 400 `validation_failed` ("'operation' is missing or unsupported"). Registering all three in one issue keeps the single map from becoming an edit hotspot. The computation that calls them is built by later issues (#1434, #1970, #1848, #1975, #1870).

Decision: `inbox_proposal` and `inbox_attachment_extraction` require a `projectItemId` (the Semprec project that owns the tick, as `agent_guidance_drift` does), because both run inside the project-owned tick and their cost should be attributed to it. `transcript_event_pick` does not take a `projectItemId`, like `transcript_summary` and `transcript_speaker_suggestion`, because it runs in the transcription process, which has no project.

## Task

Load `testing` and `error-handling`.

1. In `completeHandler.ts` add to `OPERATION_REQUIRES_PROJECT_ITEM`: `["inbox_proposal", true]`, `["inbox_attachment_extraction", true]` and `["transcript_event_pick", false]`.
2. Update the operation list in the doc comment of `backend/packages/shared/src/aiGatewayClient.ts` (the `operation` and `projectItemId` fields) so it names the new operations and which are unattributed.
3. Tests in `backend/services/semprec-ai-gateway/src/__tests__/completeHandler.test.ts`: `inbox_proposal` and `inbox_attachment_extraction` without a `projectItemId` or with `null` return 400 `validation_failed`; with a valid project item they dispatch and record an audit row with that project item and the operation name; `transcript_event_pick` with `projectItemId: null` dispatches and records an unattributed audit row, and with a non-null `projectItemId` returns 400.
