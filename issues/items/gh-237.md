**Blocked by:** #132, #137, #143, #147

## Context

Several existing state transitions require user action but only persist error/source state. Today a minimal `notifications(id, kind, payload, created_at)` stub exists, written only by the heartbeat sweep when a heartbeat exhausts its retries. This slice replaces that stub with the durable, user-bound schema, defines the kind catalog, and ships the shared transaction-bound writer with its deduplication contract, using the exhausted-heartbeat write site as the one reference producer. #149 integrates the writer into every remaining source-event producer; #150–#152 add registrations, delivery, and live/read state.

## Task

Replace the notification stub with `notifications(id,user_id,kind,title,link_href,source_table,source_id,created_at,read_at)` and the unread partial index on `user_id` (`WHERE read_at IS NULL`). Stub rows (kind plus free-form payload, no user) are not carried over. Define the closed initial kind catalog: `approval_pending`, `agent_run_error`, `heartbeat_error`, `automation_error`, `mail_sync_error`, plus reserved `process_stale`, `queue_backlog`, `mail_sync_stalled`, and `backup_restore_failed`. Add a shared transaction-bound writer that runs on the caller's transaction client, produces the ready-made title localized through the #147 resolver and the user's `users.locale`, and the target link at insert time. Define and enforce in the database one deduplication contract so that replaying the same source transition (same `source_table`, `source_id`, `kind`, and transition instance) does not insert a second row; document how a producer identifies the transition instance. Integrate the writer at the exhausted-heartbeat-retries write site (`kind = 'heartbeat_error'`, replacing the stub insert) as the reference producer.

## Scope

### In scope

- Durable schema, kind catalog, the writer, source/link/title contracts, replay deduplication, and the heartbeat reference producer.

### Out of scope

- Integrating the writer at approval request creation, the `agent_runs` error transitions, item automation error, and mail sync error — delivered by #149.
- Implementing observability or restore-check producers; their kinds are reserved only.
- Push registration and delivery.

## Acceptance criteria

- Rolling back a heartbeat failure transaction also rolls back its notification; committing exposes both.
- Replaying the same exhausted-heartbeat transition does not duplicate the notification, and the deduplication is enforced by the database.
- Unread lookup uses the partial index and every row identifies a user and durable source.
- A `kind` outside the catalog is rejected.
