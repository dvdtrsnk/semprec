## Context

Model tier rationale: A small batched read route over relations already joined by the list query, with a bounded input and tenant-isolation test coverage.

The journal shows, per day, each event with a recording state such as "transcript ready". The transcript list from #1636 answers per event, but the journal needs counts for all events of a day in one call. `/api/transcripts/summary` would be captured by the `/api/transcripts/:id` route (`:id` matches `[^/]+`, first match wins in `adapter/routeTable.ts`), so the route is `/api/transcript-summaries`.

This issue adds `GET /api/transcript-summaries?eventIds=<uuid,...>` (at most 100 ids), a module-manifest custom route in the system-databases module with justification `single-consumer-read`, answering `{ [eventId]: { count, doneCount } }` for the given events in one call. Deleted transcripts are not counted; `count` is all live transcripts linked to the event and `doneCount` those with status `done`. Processing and error states are not shown by the journal. It builds on #1636 (same manifest and route file).

Shared-file ordering: this issue also waits for #1692 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `testing` and `error-handling`.

1. Add the handler and `customRoutes` entry for `GET /api/transcript-summaries` (validates `eventIds` as 1-100 distinct uuids, otherwise 400); add it to `routeMatrix.ts` and the tenant isolation route test.
2. Implement one SQL aggregation over `item_relations` and `items` limited to live events and transcripts of the caller's tenant; ids that are unknown or foreign are returned with `count` 0.
3. Tests: counts for a day's events in a single call, a trashed transcript is not counted, more than 100 ids returns 400, tenant isolation.

### Out of scope

- Counting processing or errored transcripts separately.

## Acceptance criteria

- When the events of a day are requested together, then `count` and `doneCount` are returned for each in one call.
- When an event id is foreign or unknown, then it is returned with `count` 0 and nothing about the other tenant is revealed.
- When more than 100 ids or an invalid id is sent, then the response is 400.
