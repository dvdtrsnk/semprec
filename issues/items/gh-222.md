**Blocked by:** #221, #90, #115, #175

## Context

Issue #221 made queue affinity explicit data and declared `heartbeatFireCore`/`heartbeatFireAgent` in the closed catalog, but the single overloaded `heartbeatFire` task still executes both deterministic core actions and agent sessions, so it cannot be hosted by two affinity-safe runtimes. This issue performs the split and migrates pending legacy jobs. #91 then hosts the two composition roots that run `heartbeatFireCore` in API and `heartbeatFireAgent` in agents.

## Task

Split the overloaded `heartbeatFire` task into `heartbeatFireCore` (`affinity: 'api'`) and `heartbeatFireAgent` (`affinity: 'agents'`). Heartbeat/action registration declares affinity; sweep, event, and manual enqueue resolve the registered action and choose the task name while preserving #84 payload/job-key semantics. Core deterministic actions including library processing use `heartbeatFireCore`; starting or continuing an agent session uses `heartbeatFireAgent`. Migrate pending legacy `heartbeatFire` jobs at install by inspecting their heartbeat action registration and re-enqueueing exactly once under the correct new name before removing the legacy handler. Remove the transitional `heartbeatFire` entry from `CORE_TASK_NAMES` introduced by #221; the catalog then matches the exhaustive sets of #221 exactly. The existing single-process test task list keeps executing both new handlers until #91 hosts them in separate runners.

## Scope

### In scope

- `heartbeatFireCore`/`heartbeatFireAgent` handlers, affinity on heartbeat/action registration, enqueue routing in sweep/event/manual paths, legacy job migration and legacy handler removal, and tests.

### Out of scope

- Descriptor `queueAffinity`, the closed catalogs, and ModuleRegistry validation, delivered by #221.
- The two graphile-worker composition roots, lifecycle, deployment ownership, and dual-runner integration tests, delivered by #91.
- New task business logic, a second crontab/scheduler, or in-process `setInterval`.

## Acceptance criteria

- Sweep, item-event, and manual triggers enqueue `heartbeatFireCore` for deterministic actions (including library processing) and `heartbeatFireAgent` for actions that start or continue an agent session, with #84 payload and job-key semantics unchanged.
- Install migration re-enqueues every pending legacy `heartbeatFire` job exactly once under the correct new name, leaves no legacy job behind, and a legacy job whose action registration cannot be resolved stops migration with an actionable error; legacy-job duplication is proven absent.
- The `heartbeatFire` name and handler no longer exist; both new handlers execute the previously covered heartbeat behavior with the existing heartbeat tests green.
