**Blocked by:** #1580, #1949, #1955
**Model tier:** high

## Context

Model tier rationale: This widens the authenticated MCP surface with module tools that can send mail, and the capability gate, run-credential restriction and human-session behavior are an authorization contract.

`POST /mcp` (`backend/services/semprec-api/src/mcp/mcpHandler.ts`) answers `tools/list` and `tools/call` only for the generic operations (names with the `semprec.` prefix) and returns "method not found" for anything else. A run credential (`agent_run_mcp_credentials`) restricts calls and routes them through approval; a human session acts as the user. The mechanism to expose module agent tools over MCP, with capability gating and credential restrictions, is #1580; the rules for classification and grants are in the ADR of #1385. The mail tools are #1927 and #1949, and the approval flow for sending is #1913.

Decision: the mail tools keep the names `mail.thread.get`, `mail.draft.create`, `mail.draft.update` and `mail.draft.send`; an MCP client that is the source of an approval request is named from its `initialize` client info by the work that owns the handshake, not here.

Shared-file ordering: this issue also waits for #1955 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. Using the mechanism of #1580, expose the four mail tools in `tools/list` and `tools/call` over `/mcp` for exactly the same capability grants as in an agent session (`mail.read`, `mail.draft`, `mail.send`).
2. A run credential: the calls run as the credential's agent in its project, and `mail.draft.send` without project permission creates the approval request of #1913 with source `mcp` instead of sending.
3. A human session: all four tools run as the user; `mail.draft.send` sends without approval.
4. A tool that is unknown or not granted returns "method not found" as today; input is validated with the same schemas as in the agent session.

## Scope

### In scope

- Exposing the four mail tools over MCP under the grants and credential rules.

### Out of scope

- The generic exposure mechanism (#1580); the ADR (#1385).
- Recording the MCP client name on the run (the `initialize` handshake work).
- The tool implementations (#1927, #1949) and the approval flow (#1913).

## Acceptance criteria

- An MCP client with a run credential in a project with the mail grants lists and calls `mail.draft.create`, creating a draft; in a project without the grants the tools are absent and a call returns "method not found".
- With a run credential, `mail.draft.send` in a project without permission creates an approval request with source `mcp` and nothing leaves.
- With a human session, `mail.draft.send` sends the draft as the user and creates no request.
