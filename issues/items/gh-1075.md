## Context

Semprec is becoming multi-user: every user gets their own isolated tenant, and no user may ever see anything of another user's data. In the web client, a session ends in two ways, and both keep the previous user's whole in-memory app alive:

- **Logout.** `SessionGate.onLogout` (`web/src/App.tsx:190-199`) awaits `auth.logout()` and then calls `setSession({ status: "anonymous" })`, which swaps the routed content for `LoginPage` in place.
- **A 401 mid-session.** Every session-bound adapter shares the fetch built by `createSessionFetch` (`web/src/main.tsx:32-36`, `web/src/api/sessionFetch.ts:6-15`), which dispatches an `"unauthorized"` event on any 401; `useSession`'s listener (`web/src/App.tsx:142-149`) turns an `authenticated` session into `anonymous`, again in place.

In both cases the URL stays as it was (`?view=<id>`, `?page=agent-run&id=<id>`, `?page=agent&project=<id>&database=<id>`; read once at composition time in `web/src/main.tsx:28-66`), and every object the composition root built for the previous user stays in memory (the route props carrying ids, the adapters, any React state above the gate). If another person then signs in on the same tab, they inherit the previous user's URL and state.

Decision for this program: a session end is a **full reload to a clean URL** (`window.location.replace("/")`), not an attempt to clear client state piece by piece — a reload cannot forget a piece of state. `App.tsx` already uses exactly this navigation for an authenticated user who opens `?page=login` (`web/src/App.tsx:184-188`). This is a new web-wide lifecycle rule (every later piece of client state relies on it instead of clearing itself), so it is recorded as an ADR.

Later web issues build on this: account deletion (#1083) ends the session through the same `ending` state, and the new admin and account adapters use the same session-bound fetch.

## Task

Load `adr-conventions` before starting (this issue adds an ADR); no other skill applies — no string, route or stored key is added.

1. **Session state** — in `web/src/App.tsx`, add a `{ status: "ending" }` variant to `SessionState` (`web/src/App.tsx:46-50`). `SessionGate` renders `<LoadingState />` for it: neither the header nor the routed content is rendered once a session is ending.
2. **Navigation** — in `useSession` (`web/src/App.tsx:118-157`), add one effect that calls `window.location.replace("/")` when `session.status` becomes `"ending"`. Do not call it from inside a state-updater function (React StrictMode may invoke updaters twice).
3. **Logout** — in `SessionGate.onLogout`, replace `setSession({ status: "anonymous" })` (`web/src/App.tsx:198`) with `setSession({ status: "ending" })`. The failure branch stays as it is: a rejected `auth.logout()` keeps the session and shows `login.logoutFailed`, with no navigation.
4. **401** — in the `"unauthorized"` listener (`web/src/App.tsx:144-146`), turn an `authenticated` session into `{ status: "ending" }` instead of `anonymous`. Any other current status stays unchanged, so an event while anonymous, loading or failed causes no navigation (no reload loop). The `skip` branch for the setup wizard stays as it is.
5. **Docstrings** — update the `useSession` and `SessionGate` doc comments (`web/src/App.tsx:112-117`, `159-164`) and `createSessionFetch`'s doc comment (`web/src/api/sessionFetch.ts:1-5`, which says the app "swaps its content for the login page") so they describe the reload. `createSessionFetch`'s behaviour does not change.
6. **ADR** — add `docs/adr/<YYYY-MM-DD>-web-session-end-reloads-to-a-clean-url.md` (date of your commit; format per `docs/adr/README.md`, `status: accepted`, `area: [web]`, `supersedes: []`). Context: more than one user can sign in on the same browser tab. Decision: logout and a mid-session 401 end in `window.location.replace("/")`; no component clears client state on logout. Rejected alternative: resetting state in place, because every new piece of state would need its own reset and a forgotten one leaks. Consequences: unsaved input and the current deep link are lost on a 401; new client state needs no logout cleanup.
7. **Tests** — update `web/src/__tests__/App.test.tsx`. Its existing cases "switches to the login page when an unauthorized event fires mid-session" (`:101-112`) and "logs out once and switches to the login page" (`:114-123`) assert the in-place swap; rewrite them to the new behaviour. Stub navigation the same way the existing "navigates to / …" case does (`vi.stubGlobal("location", { ...window.location, replace })`, `:167-173`).

## Acceptance criteria

- When an authenticated user clicks "Sign out" and `auth.logout()` resolves, `window.location.replace` is called exactly once with `"/"`, and neither the header nor the routed content is rendered afterwards (web unit, `web/src/__tests__/App.test.tsx`).
- When `auth.logout()` rejects, `window.location.replace` is not called, the header and the content stay, and the `login.logoutFailed` message is shown with `role="alert"` (web unit, `App.test.tsx`).
- When an `"unauthorized"` event fires while the session is authenticated, `window.location.replace` is called with `"/"`, and neither the routed content nor "Signed in as …" is rendered afterwards (web unit, `App.test.tsx`).
- When an `"unauthorized"` event fires while the login page is shown (anonymous session), `window.location.replace` is not called and the login page stays (web unit, `App.test.tsx`).
- When the setup wizard is rendered, an `"unauthorized"` event causes no navigation and `getSession` is never called (web unit, `App.test.tsx`).
- An authenticated user opening `?page=login` is still sent to `/` (the existing case keeps passing).
- `docs/adr/` contains the new ADR with valid frontmatter, and `pnpm run verify` in `web/` passes.
