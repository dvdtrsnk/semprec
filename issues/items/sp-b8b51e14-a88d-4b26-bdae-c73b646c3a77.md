## Context

Model tier rationale: An intermittent CI failure needs its cause found in a mail route's error path before it can be fixed without weakening the test.

`backend/packages/data/src/__tests__/mailDraftRoutes.test.ts` fails intermittently in CI integration shard 5 (pull requests #2111 and #2114). The test it names is "answers 409 mail_draft_not_editable for …". Vitest reports an error raised while the file runs: `MailDraftNotEditableError` (409 `mail_draft_not_editable`), thrown from `lockUnsentDraft` (`mail/draft.ts:346`) via `discardEmailDraft` (`draft.ts:425`), `runTransaction` (`db/pool.ts:455`) and `mailDraftRouteHandlers.ts:258`. Locally the file passes repeatedly, so the failure depends on timing.

## Task

1. Find why this refusal surfaces as an error outside the request that should answer it with 409. Candidates are a promise that is not awaited, a second concurrent discard, or a background task.
2. Fix the cause in production code if the leak is real, or in the test if it starts work it does not await. Keep the 409 contract.
3. Add a test that fails on the leak itself.

## Touches

- backend/packages/data/src/mail/ (draft, route handlers) or the test file, as the cause dictates
- backend/packages/data/src/__tests__/mailDraftRoutes.test.ts

## Scope

### In scope

- The intermittent leak and its regression test.

### Out of scope

- Other mail behavior.

## Acceptance criteria

- The refused discard answers 409 `mail_draft_not_editable`, and nothing else rejects or throws outside that request.
- The new test fails without the fix.
- `mailDraftRoutes.test.ts` passes 20 times in a row locally, including under parallel load.
