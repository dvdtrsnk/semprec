## Context

Model tier rationale: Touches draft creation, the unread predicates and a per-tenant data backfill, each following an existing pattern, but the backfill must avoid creating provider write-back state, which needs careful verification.

Drafts and sent messages are currently counted as unread. `createEmailDraft` (`backend/packages/data/src/mail/draft.ts`) creates the Emails item without a `read` property, and `sendDraftEmail` (`mail/send.ts`) keeps that item. In the mailbox view an absent `read` counts as unread: the web filter in `web/src/views/mailbox/config.ts` uses `not_equals read true` (SQL `IS DISTINCT FROM`), and the `is:unread` search operator in `mail/search.ts` uses `coalesce((properties->>'read')::boolean, false)`. A user's own drafts and sent mail therefore raise the unread count.

Changing `read` on an existing Emails item normally triggers `mailMessageFlagsItemUpdateHook`, which records a desired `\Seen` write-back to the provider in `mail_message_flag_sync_state` (`mail/mailMessageFlagSyncStore.ts`). A backfill must not do that: mail sync's sanctioned handoff is `convergeObservedEmailFlagsWithClient` (`chokePoint/itemWrites.ts`), which sets `skipMailDesiredStateRecording`.

Decision: `createEmailDraft` is the single owner of the rule "a draft is read"; a sent message is the same item, so it stays read. Unread aggregations ignore the Sent and Drafts folders by their `specialPurpose`. The thread list (#1567) builds on this rule.

Shared-file ordering: this issue also waits for #1457 because both edit the same registry, manifest, cutover, route matrix or hook files listed in Touches.

## Task

Load `state-writes` and `testing`.

1. In `createEmailDraft`, create the item with `read: true`.
2. In `mail/search.ts`, make the `is:unread` condition also require that the message is not linked to a folder whose `specialPurpose` is `sent` or `drafts`. Apply the same exclusion to the unread filter in `web/src/views/mailbox/config.ts` for views that are not scoped to a single folder; a folder-scoped unread filter is unchanged.
3. Add `runMailDraftsAndSentReadBackfill` in `mail/mailDraftsAndSentReadBackfill.ts` and call it per tenant from `runTenantCutoverMigrations` (`db/tenantCutoverMigrations.ts`): in keyset pages (one transaction per page), find Emails items in a Drafts or Sent folder whose `read` is not true and set `read: true` through `convergeObservedEmailFlagsWithClient`. It is idempotent.
4. Add tests: a new draft has `read: true`; a sent message is not matched by `is:unread`; after the backfill the old drafts and sent items are read and no row exists in `mail_message_flag_sync_state` for them; unread inbox messages are untouched; a second run changes nothing.

## Scope

### In scope

- New drafts being read, the unread exclusion for Sent and Drafts, and the one-time backfill of existing items.

### Out of scope

- Mail count summaries for overview and mailboxes: #1688.
- Filtering the thread list by unread state: #1633.
- Pushing read state to the provider; the backfill deliberately records no write-back.

## Acceptance criteria

- When a draft is created, then it has `read: true` and is not found by `is:unread`.
- When a draft is sent, then it is still not unread and is not counted by an unread filter that is not scoped to one folder.
- When the backfill runs, then existing drafts and sent messages become read and `mail_message_flag_sync_state` gets no new row.
- When the backfill runs again, then nothing changes.
