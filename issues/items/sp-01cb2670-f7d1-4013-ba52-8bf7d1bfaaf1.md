## Context

Model tier rationale: Changes what the password and OAuth connect routes write and which provider calls they make (an extra IMAP login with LIST, two Graph reads), with the no-I/O-in-transaction rule, failure handling that must not fail a verified connect, and the draft refusal's error contract.

Production evidence (dev VPS, a real Purelymail account, reproduced twice): right after `POST /api/mail/mailboxes` answered 201 the user composed. `POST /api/mail/drafts { mailboxId, … }` answered 400 `validation_failed` with `field: "mailboxId"`; a few minutes later the same request succeeded. The client cannot explain that error, and users add an account and write mail at once.

Root cause, from the code:

- **Folders exist only after a sync pass.** `createEmailDraftInMailbox` (`mail/draft.ts`) files the draft in the mailbox's Folder item whose `specialPurpose` is `drafts` (`findFolderBySpecialPurpose`) and throws `ValidationError("… has no Drafts folder yet - sync the account before drafting", { field: "mailboxId" })` without one. Folder items are written only by `ensureFolderItem` from the sync passes (`reconcileImapAccount`, `reconcileGmailAccount`, `reconcileGraphAccount`). The connect routes (`createPasswordMailbox`, `createConnectedMailbox`) only enqueue the first pass, which on the VPS ran minutes later behind the queue.
- **Sending has the same gap.** `sendDraftEmail` (`mail/send.ts`) refuses a mailbox without a `sent` Folder with 409 `mail_sent_folder_missing`, and the SMTP transport's Sent copy (`createSentCopySaver`, `mail/mailTransport.ts`) keeps no copy without one. A draft that could be created would still not send before the first pass.
- **Reply and forward drafts** start from a synced message, so their mailbox has had a pass; they share `createEmailDraftInMailbox` and get the same refusal otherwise. Updating a draft does not read folders.
- **The folder matters beyond filing.** The thread list (`only_drafts`, `delivered`, unread exclusion), the thread actions and link rules classify a message by its Drafts/Sent folder, so a draft without its Drafts folder would be misclassified everywhere. A Semprec draft is never uploaded to the server's Drafts folder; the folder item is local classification.

Decisions:

- **Connect writes the compose folders.** Each connect discovers the account's Drafts and Sent folders (and only those; every other folder is left to the first pass) and writes their Folder items with `ensureFolderItem`, with exactly the `providerId`, `name`, `behavior` and `specialPurpose` the first sync pass derives, in the same transaction that writes the mailbox. The pass then finds them by `providerId` and creates no duplicate; the job is enqueued in that transaction, so no pass can run before the folders commit.
  - IMAP (`POST /api/mail/mailboxes`, iCloud and generic): after the verification and outside any transaction, one connection to the verified IMAP endpoint lists the folders (`openImapConnection` → `listFolders` → `close`) under a whole-step deadline; the special-use mapping is the one `reconcileImapAccount` uses. The verification itself is unchanged. The opener is a new required route dependency `mailServerClients.openImap` (`openImapConnection` in `serve.ts`).
  - Gmail: the system labels `DRAFT` and `SENT` have fixed ids, and Gmail names system labels by their ids; no provider call.
  - Graph: `GET /me/mailFolders/drafts` and `/me/mailFolders/sentitems` (`$select=id,displayName`) after the identity read, outside any transaction, with the identity read's timeout and size cap.
- **A failed discovery does not fail the connect.** The login is already verified and the first pass discovers the folders anyway, so a failed or timed-out listing is logged (error name and code, mailbox-independent) and the mailbox is created without them.
- **A mailbox that has no Drafts folder is a clear conflict.** `createEmailDraftInMailbox` refuses it with 409 `mail_drafts_folder_missing` (`details.mailboxId`), the sibling of `mail_sent_folder_missing`, added to the REST error-code enum. Nothing is created.
- Reauthorization and password replacement keep their behaviour: the account has had its folders discovered by then or gets them from the queued pass.

## Task

Load `state-writes`, `io-hardening`, `error-handling`, `testing`.

1. `mail/folderDiscovery.ts`: `ensureComposeFolders(client, mailboxItemId, folders)` writes the given folders whose purpose is `drafts` or `sent` through `ensureFolderItem`; correct the comment of `findFolderBySpecialPurpose`.

5. `mail/draft.ts`: `MailDraftsFolderMissingError` (409 `mail_drafts_folder_missing`); `errorContract.ts` enum and status.
6. Update `docs/architecture/domain-mail-and-inbox.md` (password connect, OAuth connect, Drafts).

## Scope

### In scope

- Discovering and writing the Drafts and Sent folders on each connect (password, Gmail, Graph), the draft refusal code, tests, the architecture document.

### Out of scope

- Uploading Semprec drafts to the server's Drafts folder; drafts stay local until sent.
- Other special folders (Inbox, Archive, Trash, Junk) at connect; thread actions on synced mail are unchanged.
- Reauthorization, password replacement, the sync passes' own folder discovery, the queue's latency for the first pass.
- Any request against a real server.

## Acceptance criteria

- A generic password mailbox connected through the production connect handler against a loopback fake IMAP server (folders with `\Drafts` and `\Sent`) has its Drafts and Sent Folder items before any sync pass ran; a draft created through the draft route right after the connect exists in Drafts, and sending it through the send route (recording transport) moves it to Sent; the SMTP Sent-copy saver finds the Sent folder's path and appends there. A first sync pass afterwards creates no second Drafts or Sent folder.
- A connect whose folder listing fails (opener rejects) still answers 201 and writes the mailbox, logs the failure without user content, and a draft then answers 409 `mail_drafts_folder_missing` with `details.mailboxId`, creating nothing.
- A Gmail connect writes the `DRAFT` and `SENT` folders; an Outlook connect reads the two well-known folders and writes them with their Graph ids and display names; a failing Graph folder read still connects. A draft can be created and sent right after either connect, before any pass.
- A mailbox without a Drafts folder answers 409 `mail_drafts_folder_missing` (not `validation_failed`), and the code is in the REST error-code enum with status 409.
- The existing mailbox, OAuth, draft, send, sync and isolation test files stay green.
