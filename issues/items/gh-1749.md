**Blocked by:** #1723
**Model tier:** medium

## Context

Model tier rationale: A per-tenant background sweep over existing fan-out, chunking and trash seams, but it decides what to trash from document contents, so the orphan rule must be conservative.

A page is created together with its block and removed together with it by the operations of #1676 and #1723, but clients edit documents directly over the sync socket, which writes Yjs updates and runs no domain code. A block of type `page` deleted that way (for example by selecting and deleting it in the editor) leaves the Pages item and its document alive with nothing pointing at them. Per-tenant background work fans out with `forEachActiveTenant` (decision record `2026-10-06-system-work-fans-out-per-tenant`) and large sweeps run in chunked transactions (`2026-09-28-chunked-transactions-for-large-background-sweeps`); the core cron entries are in `CORE_CRONTAB` in `backend/packages/data/src/worker.ts` and the closed task names in `backend/packages/queue/src/index.ts`. #1723 provides the trash hooks that a swept page goes through.

This issue adds a daily sweep that sends orphaned pages to the trash, so they can be restored for 30 days like any deleted item.

Decisions:
- A live Pages item is an orphan when its parent has a document, that document holds no `page` block with its id, and the document's latest update is at least 1 hour old (an editor may be mid-edit).
- A page whose parent has no document, or whose parent is itself trashed, is not swept.
- Moving a page block into another document is not supported by the server (the parent link is not updated), so a moved page counts as an orphan of its old parent and is trashed; this is accepted for now and recoverable.
- The sweep trashes through the choke point's item delete, so the hooks of #1723 (children, anchors) run.

## Task

Load `state-writes`, `error-handling`, `io-hardening` and `testing`.

1. Add the core task `pageOrphanSweep` (system task, `api` affinity) in `backend/packages/queue/src/index.ts`, its handler registration in `backend/packages/data/src/worker.ts` and a daily cron line (for example `5 4 * * *`) in `CORE_CRONTAB`.
2. Implement `sweepOrphanedPages(pool)` in `backend/packages/data/src/docs/pageOrphanSweep.ts`: `forEachActiveTenant`, and per tenant, in chunks of at most 200 pages per transaction, group the live Pages items by `parentItemId`, load each parent's document once, read its blocks with `readPageBlocks`, apply the orphan rule above and trash each orphan with the choke point's item delete using writer kind `system`. A failure on one page is logged without content and does not stop the sweep.
3. Tests: a page whose block was removed through a document update is trashed by the sweep and can be restored (the block returns); a page with its block present is untouched; a parent edited less than an hour ago is skipped; a page whose parent has no document is untouched; a nested orphan is trashed with its children; a second run changes nothing; one tenant's sweep never touches another's.

## Scope

### In scope

- The daily per-tenant sweep that trashes pages that no document references.

### Out of scope

- Trash and restore hooks: #1723 and #1763.
- Updating the parent link when a page block is moved to another document: not planned yet; it waits for a product decision.
- Permanent deletion of swept pages: the normal 30-day purge applies.

## Acceptance criteria

- When a page block is removed from its parent through a document update and the sweep runs, then the Pages item and its nested pages are in the trash and can be restored within 30 days.
- When a page's block is present, or the parent was edited within the last hour, then the page is untouched.
- When the sweep runs twice, then the second run changes nothing.
- When two tenants have orphans, then each tenant's sweep trashes only its own.
