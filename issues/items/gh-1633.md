## Context

Model tier rationale: Extends one existing list query with composable filters over known tables, with predicates that other routes will reuse, so correctness of the shared predicate module matters but the seams are defined.

#1567 lists every thread. The Mail screen needs filters: "All" and "Unread", "Flagged", one per account, and a click on a folder. Today a client can only filter single messages through `POST /api/databases/:id/query` (`relation_contains` on `Emails.folder`, `equals` on `read` and `flagged`). Folders are Folders items with a `specialPurpose` (`inbox|sent|junk|trash|drafts|archive|all|none`, filled by `mail/folderDiscovery.ts`).

The counting route (#1688) and the folder counts (#1689) must use exactly the same predicates, so the predicates live in one module shared by all three. Project, area and person filters are added by #1638, text search by #1639, and the Semp draft box by #1694.

Decisions: filters combine with AND; `box` defaults to `inbox`; a `folderId` replaces `box`; an unknown or foreign `folderId` answers 404, identically; an invalid `box` value is a validation error. Threads only in the Junk or Trash folder never appear without a `folderId`.

## Task

Load `state-writes`, `canonical-keys` and `testing`.

1. Extract the thread predicates into `backend/packages/data/src/mail/mailThreadPredicates.ts` as SQL builders over the aggregate of #1567: `inbox` (the thread has a non-deleted counted message in a folder with `specialPurpose` `inbox` of any account), `flagged` (a flagged message anywhere outside Junk and Trash), `inFolder(folderId)` (a message in that folder, also Junk and Trash), `unread`, `inMailbox(mailboxId)`.
2. Add the query parameters to `GET /api/mail/threads`: `box` (`inbox` default, `flagged`), `folderId`, `unread=true`, `mailboxId`. Unknown `box` values, including `sempDrafts`, which is not available yet, are a 400 validation error naming the field.
3. Without `folderId`, a thread whose messages are only in Junk or Trash is excluded.
4. `unread=true` keeps threads that are unread by the rule of #1567; `mailboxId` keeps threads with a counted message in that mailbox.
5. Add tests for each filter and for combinations (unread and a mailbox; a folder id that is Junk; a thread only in Spam absent from the default list and present with its folder id; unknown folder id 404).

- The Semp draft box: #1694.

## Acceptance criteria

- When `box` is omitted, then only threads with a non-deleted message in some inbox folder are returned.
- When `box=flagged`, then flagged threads outside Junk and Trash are returned.
- When `folderId` names the Spam folder, then a thread that is only in Spam is returned; without it, that thread is absent.
- When `unread=true` and `mailboxId` are combined, then both apply.
- When `folderId` is unknown or another tenant's, then the response is 404.
