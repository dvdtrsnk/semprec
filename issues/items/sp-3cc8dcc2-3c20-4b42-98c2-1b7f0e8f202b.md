## Context

Model tier rationale: A new provider API whose delta queries are bounded by a date window and differ from Graph mail delta.

Microsoft accounts with `Calendars.ReadWrite` sync through Microsoft Graph.

## Task

Load `state-writes`, `db-migrations`, `error-handling`, `io-hardening`, `canonical-keys` and `testing`.

1. `listCalendars` from `/me/calendars` (name, hexColor/color, canEdit → read-only).
2. `fetchChanges` with `/me/calendars/{id}/calendarView/delta` over the sync window, storing the deltaLink; on `syncStateNotFound` resync the window.
3. Map Graph events (start/end with timeZone, isAllDay, seriesMaster with recurrence pattern → RRULE, exceptions and occurrences, reminderMinutesBeforeStart, attendees, organizer, isCancelled/@removed → deletion). Series masters are fetched by id when only instances arrive.
4. `putEvent` with If-Match (PATCH /me/events/{id}, POST /me/calendars/{id}/events), `deleteEvent`.
5. Token refresh and status mapping as for mail Graph.

## Touches

- backend/packages/data/src/calendar/sync/adapters/graph/*.ts (new)
- backend/packages/data/src/__tests__/graphCalendarAdapter.test.ts (new, recorded responses)

## Scope

### In scope

- Graph listing, delta fetch, mapping and writes.

### Out of scope

- Graph change notifications (live updates issue).

## Acceptance criteria

- A recurrence pattern "every 2 weeks on Mon and Wed until a date" maps to the equivalent RRULE and back.
- A calendar with canEdit false is read-only.
- A removed instance becomes an EXDATE.
