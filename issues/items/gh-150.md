**Blocked by:** #149

## Context

Notifications are durable but external delivery requires registrations whose lifecycle cannot outlive the authenticated device session.

## Task

Create `push_subscriptions` with user, nullable session, channel (`web_push` or `apns`), platform (`web`, `ios`, `macos`), web fields (`endpoint`,`p256dh`,`auth_secret`), APNs fields (`device_token`,`apns_environment`), timestamps, and `revoked_at`. Add active unique indexes for endpoint and device token plus channel-specific validation. Implement authenticated registration and explicit revocation endpoints. In the same transaction as manual logout or remote session revocation, revoke all subscriptions with that session ID. Provide one repository operation for provider invalidation: web 404/410 and APNs 410/`BadDeviceToken` revoke the exact registration. A re-registration may reactivate by replacing the revoked row without violating active uniqueness.

## Scope

### In scope

- Schema, validation, authenticated lifecycle endpoints, session cascade, provider invalidation contract.

### Out of scope

- Sending push messages, delivered by #151.
- Browser permission prompts and complete notification UI.

## Acceptance criteria

- Invalid channel/field/platform combinations are rejected.
- Logout atomically revokes only registrations tied to that session; other device sessions continue receiving.
- Active endpoint/device tokens are unique, while a previously revoked value can register again.
