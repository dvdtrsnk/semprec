## Context

Model tier rationale: A pure lookup function plus two locale catalogs and a build-copy line, all following the existing per-area `i18n/` catalog pattern, with no persisted data, tenant or authentication contract.

Usage views show which model produced a cost. Today the backend has no display name for a model: `ai_gateway_calls.model` holds the raw provider id (for example the agent model from the `AGENT_MODEL` environment variable read in `backend/services/semprec-agents/src/modelComposition.ts`, `whisper-large-v3` from the audio transcription provider, `pyannote-3` from the diarization provider), and `getAiUsageReport` in `backend/packages/data/src/aiGateway/aiUsageReport.ts` returns it unchanged. The id of the agent model changes with every model version, so a per-id mapping would rot; the name has to be derived from the model family.

This issue adds the one shared place that turns a stored model id into a localized display name. #1822 uses it for the per-run usage breakdown and #1472 uses it for the per-model breakdown of the AI usage report, so both views show the same names.

Decision: only the families the product names today are mapped (Claude Sonnet, Claude Haiku, Whisper, speaker diarization). Any other id, including other Claude families, is returned as the raw id until a later issue adds a family; this is the conservative reading of "unknown id returns the raw id".

## Task

Load `canonical-keys` and `testing`.

1. Add `backend/packages/data/src/aiGateway/i18n/cs.json` and `en.json` with these canonical English keys (ADR `docs/adr/2026-09-10-english-canonical-keys-with-i18n-labels.md`):
   - `model.claudeSonnet` (cs "Claude Sonnet", en "Claude Sonnet")
   - `model.claudeHaiku` (cs "Claude Haiku", en "Claude Haiku")
   - `model.whisper` (cs "Whisper", en "Whisper")
   - `model.diarization` (cs "Diarizace", en "Diarization")
2. Add `backend/packages/data/src/aiGateway/modelDisplayNames.ts` exporting:
   - `getModelDisplayCatalogs()`: lazily loads the two catalogs once per process with `loadModuleCatalogs(import.meta.url)` from `@semprec/module-registry`, the same way `notifications/notify.ts` does.
   - `resolveModelDisplayName(catalogs, locale, modelId)`: a pure, synchronous function. It maps the id by family with ordered patterns: `/^claude-sonnet/` to `model.claudeSonnet`, `/^claude-haiku/` to `model.claudeHaiku`, `/(^|\/)whisper/` to `model.whisper` (matches both `whisper-large-v3` and `openai/whisper-large-v3`), `/^pyannote/` to `model.diarization`. It resolves the key with `resolveCatalogLabel` and `toManifestLocale(locale)` (requested locale, then `en`, then the key). An id that matches no pattern returns the raw `modelId` unchanged. Matching is case-sensitive on the stored id and does not depend on the provider.
3. Export both from `backend/packages/data/src/index.ts`.
4. In the data package build script, use `mkdir -p dist/aiGateway/i18n && cp src/aiGateway/i18n/*.json dist/aiGateway/i18n/` so first and repeated builds refresh the flat runtime catalogs. Change only this area's copy command; preserve other build steps.
5. Add `backend/packages/data/src/aiGateway/__tests__/modelDisplayNames.unit.test.ts` as a unit test of `resolveModelDisplayName` (no database): several versions of a Sonnet id and a Haiku id map to the same name; the whisper ids and `pyannote-3` map to their names; cs and en differ for the diarization name; an unknown locale falls back to en; an unknown id (for example `gpt-x`) is returned raw.

- When the locale is neither `cs` nor `en`, then the English name is returned.
