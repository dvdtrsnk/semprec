## Context

`backend/modules/` was reserved for "vertical slices" when the workspace was scaffolded, but every module since #29 has been written under `backend/packages/data/src/<domain>/` with its own `*ModuleManifest.ts` (`mail/mailModuleManifest.ts`, `inbox/inboxModuleManifest.ts`, `docs/docsModuleManifest.ts`, `library/libraryModuleManifest.ts`, `views/viewsModuleManifest.ts`, `seed/systemDatabasesModuleManifest.ts`, `chokePoint/schemaCoreModuleManifest.ts`). That is the architecture, not a transitional state (decision recorded on this batch's epic). Today `backend/modules/` contains only a one-line `README.md`, yet the layout still carries the placeholder everywhere:

- `backend/dependency-cruiser.rules.json`: the rules `no-module-to-module`, `no-service-to-module` and `no-module-to-service` match no file; `core-knows-nobody`'s `to.path` is `^(modules|services)/[^/]+/src/` and the second `no-deep-imports` entry's `from.path` is `^(modules|services)/[^/]+/src/` — their `modules` alternatives match nothing either.
- `backend/pnpm-workspace.yaml` declares `modules/*`; `backend/package.json`'s `check:boundaries` script scans `modules services packages`; `backend/vitest.unit.config.ts`, `vitest.integration.config.ts` and `vitest.e2e.config.ts` include `modules/*/src/**/*…test.ts` globs.
- `packages/module-boundaries/src/__tests__/fixtures/modules/{alpha,beta}/src/*` and eleven cases in `packages/module-boundaries/src/__tests__/module-boundaries.unit.test.ts` exist only to exercise the dead rules (the fixtures under `modules/beta/src/` also serve the `no-core-table-write-outside-choke-point`, `items-store-private` and `no-deep-imports` cases, which must survive).
- `README.md` line 44 ("`backend/modules/` — vertical slices … created incrementally"), `.bb/AGENTS.md` line 5 ("`backend/` is a pnpm workspace (`packages/`, `modules/`, `services/`)"), `backend/review-rules/context.md` line 4 and `backend/review-rules/scope.md` (`modules/**/*.ts`) describe `modules/` as a live part of the layout.

A later refactor that reads the boundary rules or the workspace file would otherwise plan around a layer that does not exist. Sibling issue #659 of this batch adds a new rule to `dependency-cruiser.rules.json` and new cases to the same unit test; it is sequenced after this issue for that reason.

## Task

- In `backend/dependency-cruiser.rules.json`: delete the `no-module-to-module`, `no-service-to-module` and `no-module-to-service` rules; change `core-knows-nobody`'s `to.path` to `^services/[^/]+/src/`; change the second `no-deep-imports` entry's `from.path` to `^services/[^/]+/src/`. Update each affected rule's `comment` so it no longer mentions modules. Every other rule stays byte-identical.
- Delete `backend/modules/README.md` (and with it the directory). Remove the `modules/*` line from `backend/pnpm-workspace.yaml`. Change `check:boundaries` in `backend/package.json` to `depcruise --config .dependency-cruiser.cjs --output-type err services packages`. Remove the `modules/*/src/**/…` include entry from each of the three `backend/vitest.*.config.ts` files.
- In `packages/module-boundaries/src/__tests__/`:
  - Move the fixtures that exercise surviving rules out of `fixtures/modules/beta/src/` into `fixtures/services/svcB/src/` with the same file names: `badCoreTableWrite.ts`, `badCoreTableWriteDatabases.ts`, `badCoreTableWriteProperties.ts`, `badDeepPackageImport.ts`, `usesShared.ts`. Fix their relative import paths so each still resolves to the same target (`packages/data/src/chokePoint/itemsStore.ts` etc.).
  - Delete the rest of `fixtures/modules/` (`alpha/*`, `beta/src/index.ts`, `badImport.ts`, `badCrossCategoryImport.ts`, `goodImport.ts`, `usesOwnInternal.ts`, `usesServicePublicEntry.ts`) and `fixtures/packages/shared/src/badModuleImport.ts` and `fixtures/services/svcB/src/badModuleImport.ts`.
  - In `module-boundaries.unit.test.ts`: every `checkModuleBoundaries(fixturesDir, ["modules", "services", "packages"])` becomes `checkModuleBoundaries(fixturesDir, ["services", "packages"])`. Delete the cases "rejects a module reaching into another module's internals", "rejects a module reaching into a service's internals", "rejects a service reaching into a module's internals", "rejects a module importing a service's public entry point", "allows imports of another module's public entry point", "allows a module reaching into its own internals" and "rejects a core package importing module code". Retarget the remaining cases that named a `modules/beta/src/…` importer to the moved `services/svcB/src/…` path: the `it.each` for `no-core-table-write-outside-choke-point`, "allows importing a neutral shared package", "rejects code outside packages/data importing the item store", and "rejects a module reaching past a package's entry point" (rename it "rejects a service reaching past a package's entry point"; it now proves the surviving `services` half of the second `no-deep-imports` entry).
- Documentation: in `README.md` replace the `backend/modules/` bullet with one sentence stating that vertical slices live in `backend/packages/data/src/<domain>/` with a `*ModuleManifest.ts` each; in `.bb/AGENTS.md` line 5 change the workspace list to "(`packages/`, `services/`)"; in `backend/review-rules/context.md` line 4 change `(`packages/*`, `modules/*`, `services/*`)` to `(`packages/*`, `services/*`)`; in `backend/review-rules/scope.md` remove the `modules/**/*.ts` include line.
- Do not edit any file under `docs/adr/` — `2026-09-10-single-writer-ownership-model.md` mentions `modules/*` in its body, and an accepted ADR's body is a frozen historical record. No new ADR: removing an unused placeholder is not a new pattern.
- Tests: the edited `packages/module-boundaries/src/__tests__/module-boundaries.unit.test.ts` (unit tier, no Postgres) is the test for this issue; every remaining case must pass against the moved fixtures. `pnpm run check:boundaries` must pass with the two scan roots.
