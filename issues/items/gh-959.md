## Behavior specification (approved)

Part of the multi-tenancy program specified in #950. The web client for more than one user:

1. Logout and any 401 reload the app to a clean URL, so nothing of the previous user survives in memory or in the address bar.
2. A password-reset page; the emailed link carries the token in the URL fragment.
3. The session exposes the user's role; admins get pages for accounts (including deleting another account), invitations, AI budgets and operations health; members never see them (the server enforces it regardless).
4. The System page shows only the user's own status.
5. An account page offers export and deletion (deletion asks for the password).

All labels go through the i18n catalog; each page talks to the API through its own operations adapter.

## Decisions

- **Full reload instead of clearing client state?** → It is impossible to forget a piece of state with a reload.
