## Context

`PATCH /api/approval-requests/:id` lets the caller assert who decided. `backend/services/semprec-api/src/approvalRequestsHandler.ts`, `createApprovalRequestsRequestListener`: line 73 `await authenticateRequest(pool, req);` discards the returned identity; lines 95-98 require a body field `decidedByUserId`; line 106 passes it as `decidedByUserId` to `decideAndEnqueueApprovalRequest` (`backend/packages/data/src/mcp/approvalDecisionAction.ts`), which writes it to `approval_requests.decided_by`. The handler's own docstring (lines 55-57) documents this as deliberate. Three defects follow:

1. Attribution is client-controlled: any authenticated session can record any `users.id` as the decider.
2. Lines 43-47 and 109-115 catch the Postgres foreign-key violation (`23503`) and answer `400 { error: "No user with id '<id>'" }` — a user-id existence oracle.
3. The PATCH response (lines 118 and 127) is the full `ApprovalRequest` row including `payload` — for an MCP-invoke request that is `payload.args`, the argument *values* that `listApprovalRequestsQueue` (`backend/packages/data/src/mcp/approvalRequestsQueue.ts`, `safeSummaryOf`, lines 11-15 and 40-55) deliberately reduces to `argKeys` on `GET /api/approval-requests` because that is where credentials live.

The web client (`web/src/api/approvalQueueOperations.ts` lines 90 and 135, and `web/src/main.tsx` line 45 reading `?user=`) still sends `decidedByUserId`; it parses only `id`, `status`, `decidedAt`, `decidedBy` from the PATCH response (`decidedApprovalRequestSchema`, lines 71-76). Removing the client field is the web epic's work; this issue must keep accepting it silently until then.

Sibling B7 later validates the `:id` segment in this handler; sibling B8 later changes its `catch` block.

## Task

- In `approvalRequestsHandler.ts`:
  - `const identity = await authenticateRequest(pool, req);` and pass `decidedByUserId: identity.user.id` to `decideAndEnqueueApprovalRequest`.
  - Delete the `decidedByUserId` body validation (lines 95-98). A `decidedByUserId` field in the body is ignored — not a 400 — because rejecting a field an already-deployed client sends would break it (`docs/adr/2026-09-11-additive-only-rest-contract-no-url-versioning.md`). Say so in the docstring, and note that the web client stops sending it in a later batch.
  - Delete `FOREIGN_KEY_VIOLATION_ERRCODE`, `isForeignKeyViolation` and the `try`/`catch` around the `withTransaction` call (lines 43-47, 100-115); the session user always exists, so the branch is dead once the id comes from the session.
  - Both 200 responses (the decided row, and the "already decided" re-read) return the projection below instead of the raw row. The 404 for an unknown id and the body-`decision` validation stay as they are.
  - Update the docstring (lines 49-67) to describe the session-derived decider and the redacted response.
- In `backend/packages/data/src/mcp/approvalRequestsQueue.ts`, add and export `ApprovalRequestDecisionView` and `toApprovalRequestDecisionView(request: ApprovalRequest): ApprovalRequestDecisionView` returning exactly `{ id, status, decidedAt, decidedBy, executionStatus, toolName, riskClass, requestedAt, agentRunId, safeSummary }`, with `safeSummary` built by the existing `safeSummaryOf`. `payload`, `resourceSnapshot`, `executionResult`, `executionError` and `executedAt` are not in it. Re-export both from `backend/packages/data/src/index.ts` on the two existing `approvalRequestsQueue.js` export lines (currently 326-327) — do not add a new export line elsewhere in the barrel.
- Tests in `backend/services/semprec-api/src/__tests__/approvalRequestsHandler.test.ts` (integration tier). Extend the file's `authHeader()` helper (or add a sibling helper) so a test can learn the session user's id. Then:
  - Replace "returns 400 for a missing decidedByUserId" with: a PATCH whose body is only `{ decision: "approved" }` → 200 and `decidedBy` equals the session user's id.
  - Replace "returns 400 for a decidedByUserId that references no user" with: a PATCH with `decidedByUserId: randomUUID()` → 200 and `decidedBy` equals the session user's id, not the body value.
  - Update "treats a repeated decision as a deterministic no-op" so the expected `decidedBy` is the first session's user id.
  - Add: the 200 body of a decision for a pending MCP-invoke request whose `payload.args` is `{ query: "hi" }` has no `payload` key, `JSON.stringify(body)` does not contain `"hi"`, and `body.safeSummary.argKeys` equals `["query"]`.

## Scope

### In scope

- Deriving `approval_requests.decided_by` from the authenticated session.
- Ignoring (not rejecting) a body `decidedByUserId`.
- Removing the FK-violation oracle.
- The redacted PATCH projection and its tests.

### Out of scope

- Removing `decidedByUserId` and the `?user=` parameter from the web client (`web/src/api/approvalQueueOperations.ts`, `web/src/main.tsx`) — the web epic; until it lands the backend keeps accepting the field silently.
- Validating that `:id` is a UUID (a non-UUID currently reaches Postgres as a 500) — sibling issue B7 of this batch.
- The shape of the handler's `catch` block error body — sibling issue B8.
- Any per-user authorization of which approvals a session may decide (a later, multi-tenant batch).

## Acceptance criteria

- When an authenticated session PATCHes a pending request with `{ decision: "approved" }`, the row's `decided_by` and the response's `decidedBy` equal that session's `users.id`.
- When the body also carries `decidedByUserId` (any string, including a random UUID), the response is still 200 and `decidedBy` is the session user's id; no 400 is produced for the field's presence or value.
- When a PATCH decides a request whose `payload.args` holds a value, the 200 body contains no `payload` key and the value string does not appear anywhere in the response; `safeSummary.argKeys` lists the argument names.
- `GET /api/approval-requests` is unchanged; every existing case in `approvalRequestsHandler.test.ts` not named above still passes unchanged.
- `grep -n "23503\|No user with id" backend/services/semprec-api/src/approvalRequestsHandler.ts` returns nothing.
