## Summary

This batch fixes the 13 findings from harvest issue #775's triage that verified as
`valid` against `develop` HEAD, in 10 issues (one per identified mechanism):
an error-masking bug in mcpSync's client close, missing SMTP port validation, a
wasted-I/O ordering bug in module loading, a foreign-key constraint that doesn't
match its own migration's documented behavior, a non-exhaustive push-channel
dispatch, an incomplete type guard on a conflict error's item fields, two
now-unreachable defensive branches, three test assertion gaps, a TOCTOU gap between
two independently-committed operations in the properties PATCH handler, and a
missing partition-key predicate in a trash-purge test helper.

## Decisions

- Findings `02b0e36d2c` (`inboxRouteHandlers.ts`) and `0fd1308774` (`routeTable.ts`)
  were bundled into one issue (07) — both are the same mechanism (delete a branch
  proven unreachable by the caller's own contract) applied at two independent call
  sites, not two different mechanisms.
- Findings `ad37e1b2ec` (`authHandler.test.ts`), `f0cf65f554`
  (`mcpInvokeTool.test.ts`), and `142bbb1b94` (`propertyOps.test.ts`) were bundled
  into one issue (08) — each is a small, independently-reviewable test-assertion gap
  in an unrelated file; batching several one-line test fixes under one issue follows
  this pipeline's own convention of not drafting one issue per one-liner, as the
  prior `followups-728` batch's issues also did.
- Finding `2800fbf07b` (`purgeExpiredTrash.test.ts`) was kept as its own issue (10)
  rather than folded into issue 08, since it is a test-helper implementation defect
  (a missing `WHERE` predicate causing partition-scan overhead), not a missing
  assertion — a different mechanism from the other three test findings.
- Finding `7a622eed65` (`propertiesHandler.ts`, issue 09) is scoped to only the
  `PATCH` handler's gap, per the finding's own text — the review also noted (but did
  not flag as this finding) that the same shape exists on `DELETE /api/properties/:id`
  and on `POST /api/databases/:id/properties`; both are explicitly out of scope for
  issue 09 since only `PATCH` was reported.
- Finding `e47cb6b1ed` (`0031_push_subscriptions.sql`, issue 04) is fixed with a new
  additive migration rather than editing the original migration file, per this
  project's migrations-are-additive rule.
