## Context
Review of pull request #386 found that `backend/packages/realtime/src/__tests__/syncServer.test.ts`'s "createSyncServer heartbeat fallback" describe block declares `syncServer` and `httpServer` as uninitialized `let` variables and its `afterEach` hook unconditionally calls `await syncServer.close()` before `httpServer.close()`. If `createSyncServer` throws during the test body, `syncServer` is still `undefined` and `afterEach` throws a `TypeError`, which masks the real failure reported by the test.

Review of pull request #410 found that `backend/packages/realtime/src/__tests__/backpressure.unit.test.ts` only covers `ws.bufferedAmount` values of `1_000` (below the threshold) and `MAX_BUFFERED_BYTES + 1` (above the threshold), leaving the boundary case `ws.bufferedAmount === MAX_BUFFERED_BYTES` — where `backend/packages/realtime/src/backpressure.ts`'s strict `>` comparison must NOT trigger backpressure — untested.

## Task
- In `backend/packages/realtime/src/__tests__/syncServer.test.ts`'s "createSyncServer heartbeat fallback" describe block, guard the `afterEach` hook so it only closes `syncServer` and `httpServer` when they were actually assigned (e.g. check for truthiness, or wrap each `close()` call so one throwing does not skip the other), so a failure inside `createSyncServer` surfaces as its own test failure instead of being masked by a `TypeError` in cleanup.
- In `backend/packages/realtime/src/__tests__/backpressure.unit.test.ts`, add a test case asserting that when `ws.bufferedAmount === MAX_BUFFERED_BYTES` exactly, the backpressure check does not trigger (matching the strict `>` comparison in `backend/packages/realtime/src/backpressure.ts`).

## Touches
- backend/packages/realtime/src/__tests__/syncServer.test.ts
- backend/packages/realtime/src/__tests__/backpressure.unit.test.ts

## Scope
### In scope
- The `afterEach` cleanup guard in the named describe block of `syncServer.test.ts`.
- One additional boundary-value test case in `backpressure.unit.test.ts`.

### Out of scope
- Any other describe block or test file in the realtime package.
- Changes to `backend/packages/realtime/src/backpressure.ts` itself.

## Acceptance criteria
- The `afterEach` hook of the "createSyncServer heartbeat fallback" describe block only calls `close()` on `syncServer` and `httpServer` when each was actually assigned, so an unassigned `syncServer` (when `createSyncServer` throws) no longer raises a `TypeError` that masks the original failure. This criterion is checked by reading the hook, not by a committed test — no test has to force `createSyncServer` to fail.
- A new test in `backpressure.unit.test.ts` exercises `ws.bufferedAmount === MAX_BUFFERED_BYTES` and asserts the backpressure check does not trigger at that exact value.
