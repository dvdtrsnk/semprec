## Context

Model tier rationale: The same wiring pattern as the Gmail transport, now established in the same file with its fixtures; only the provider endpoints and credentials differ.

After #1505, `backend/services/semprec-api/src/mailSyncAdapters.ts` builds a `MailSyncAdapterFactory` with a Gmail member and is passed to the api queue runtime. Graph-mode accounts still fail with "No Graph adapter configured". `GraphRestClient` (`backend/packages/data/src/mail/graphRestClient.ts`) takes the same kind of `getAccessToken` function. The Microsoft OAuth client (`MS_GRAPH_OAUTH_CLIENT_ID`, `MS_GRAPH_OAUTH_CLIENT_SECRET`) is in `deploy/shared/env/api.env.example` and read by no code. Microsoft rotates the refresh token on every refresh, which #1481 persists.

Later issues that need a Graph client build on this one: #1745 (subscriptions), #1686, #1746, #1753. #1510 adds IMAP to the same factory afterwards.

Decision: same missing-configuration behavior as Gmail: `createGraphClient` stays undefined and the process logs one warning at startup.

## Task

Load `io-hardening`, `error-handling` and `testing`.

1. In `mailSyncAdapters.ts` add `createGraphClient(mailboxItemId, credential)`: `new GraphRestClient(getAccessToken)` with `getAccessToken` calling `refreshAndPersistAccessToken` (#1481) with `MICROSOFT_TOKEN_URL` and the Graph client id and secret read from `MS_GRAPH_OAUTH_CLIENT_ID` and `MS_GRAPH_OAUTH_CLIENT_SECRET`; the refresh sends no `scope` (the granted scopes are kept). The in-memory access-token cache is per client object, like Gmail.
2. 400/401 refresh responses become `MailReauthorizationRequiredError`; tokens and secrets never appear in errors or logs. Apply the bearer-sync privacy ADR below.
3. Update the Graph keys' comment in `deploy/shared/env/api.env.example`.
4. Tests with a fake Graph server: a Graph-mode account pass ingests messages through delta; a refresh that returns a rotated refresh token leaves the new token stored and the next pass uses it; a rejected token gives `needsReauthorization`; missing client configuration gives one startup warning and the existing adapter message.

## Acceptance criteria

- When the Graph OAuth client is configured, then a sync pass of a Graph-mode account downloads its mail (fake provider).
- When Microsoft returns a rotated refresh token, then it is stored and the next pass succeeds.
- When the stored refresh token is rejected, then the account needs reauthorization.
- When the OAuth client is not configured, then the process starts and logs one warning.
- When errors or logs are inspected, then no token or client secret appears.
