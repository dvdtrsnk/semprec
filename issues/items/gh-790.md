## Context

PR #382's `purgeExpiredTrash.test.ts` flagged that its `ageDeletion` test helper
(lines 33-38) runs `UPDATE items SET deleted_at = ... WHERE id = $1` with no
`database_id` predicate. `items` is `PARTITION BY LIST (database_id)`, and the
primary key is `(database_id, id)`; without `database_id` in the `WHERE` clause,
Postgres cannot prune to a single partition and instead scans every partition to
find the matching `id`, even though the query still returns the correct row.

## Task

In `backend/packages/data/src/trash/__tests__/purgeExpiredTrash.test.ts`'s
`ageDeletion` helper, add a `databaseId` parameter and include
`AND database_id = $3` in the `UPDATE`'s `WHERE` clause, updating every call site in
this file to pass the item's `databaseId`.

## Touches

- backend/packages/data/src/trash/__tests__/purgeExpiredTrash.test.ts (`ageDeletion`
  and its call sites)

## Scope

### In scope

- Adding the `database_id` predicate to `ageDeletion`'s `UPDATE` and threading the
  parameter through its call sites in this file.

### Out of scope

- Any other test helper or production code.

## Acceptance criteria

- `ageDeletion`'s `UPDATE` statement includes `database_id` in its `WHERE` clause.
- Every existing test in this file that calls `ageDeletion` still passes, now passing
  the item's `databaseId`.
