### Requirement gh-1608: [block-editor 05/13] Serialize and parse page blocks as canonical Markdown with shared fixtures

#### Context

Model tier rationale: A new persisted text format with a hand-written parser and serializer must round-trip exactly, escape correctly, and be reproduced by a second runtime (the WebView editor), so ambiguity or an escaping gap silently corrupts user content.

Every editor hands its content to the host as Markdown, and Semp, the web client and the desktop client read and write pages as Markdown; the app itself never shows Markdown syntax. Today the backend has no Markdown parser or serializer: a block's text is a plain field in `backend/packages/data/src/docs/blocks.ts`, and the only text-in-Markdown storage is the `project_agent_guidance.markdown` column. #1539 adds the shared block model (type registry, order array, `Y.Text` with `bold`, `italic`, `code`, `link` attributes). This issue adds the conversion between that model and canonical Markdown, in the same shared module so the server and the WebView editor run identical code.

The canonical format:

- One non-empty line is one block (no CommonMark soft line wrapping or lazy continuation: two lines from Semp are two blocks). A blank line is written between blocks except between adjacent list items.
- Block markers: `# `, `## `, `### ` for h1-h3; `- ` bullet; `1. ` number (always written as `1.`); `- [ ] ` and `- [x] ` todo (on read also `[X]` and `* ` bullets); `> ` quote; two spaces of indentation per level for bullet, number and todo; a subpage with encoded ID as `[Title](semprec://page/<id>)` alone on its line.
- Inline: `**bold**`, `_italic_` (and `*italic*` inside a word), `` `code` ``, `[text](url)` (a URL without a scheme gets `https://` on read). An ordinary soft break is `<br>`; code-marked LF is `<code><br></code>`. Crossed bold and italic inside a word is written as `<strong>` and `<em>`; on read, inline HTML `strong`, `b`, `em`, `i` and `br` are accepted. Inline semprec://page/ links use [text](<semprec://page/id>); unwrapped standalone syntax denotes a page block.
- Characters `\ * ` [ ] <` and `_` at a word edge are escaped when written.

Decisions:

- Decision: line-start markers that appear in plain text (for example `16. 10. jsme...`, `# not a heading`, `- not a list`, `> not a quote`, `[ ] x`) are escaped on write (`16\. 10. jsme...`, `\# ...`, `\- ...`, `\> ...`, `\[ \]`) and unescaped on read, so a text block never changes type through a round trip or through text written by an agent. A naive serializer would not escape such prefixes; the WebView editor must adopt the same rule from the shared fixtures.
- Decision: the lossy parts (an unknown block type, and the indent of blocks that are not bullet, number or todo, which the model keeps for every type) are preserved as a comment line before the block: `<!-- semprec:block id=<id> type=<key> indent=<n> -->`. Without the comment, a block of an unknown type reads as `text` and indent on a non-list block reads as 0.
- Decision: an optional serializer mode writes the id comment before every block, for agents that need to address blocks by id (the Markdown page reads of #1678 can use it); the default mode writes no ids.
- Decision: the page block title is not stored in the model. The serializer takes a caller-supplied title resolver (`resolvePageTitle(pageId)`), writing an empty title when none is supplied; the parser reads only the id from the link and discards the title.
- Decision: no Markdown library is added. The format is a deliberate line-oriented subset and the code must run in a browser WebView.

### Requirement gh-1418: [calendar-events 03/12] Add a calendar time module for today, ends and day bounds in the tenant time zone

#### Context

Model tier rationale: One new pure module over luxon with defined inputs and outputs and existing time-zone fixtures, but daylight-saving edge cases are subtle and many later issues depend on its exact semantics.

The calendar needs one shared definition of today, now, the boundaries of a day and a week, and when an Event or Task ends, all in the tenant's time zone. Today the pieces are scattered: `systemSettings.timezone` (read by `getSystemTimezone` in `backend/packages/data/src/systemSettings.ts`, default Europe/Prague) is used by task recurrence (`backend/packages/data/src/tasks/nextDueDate.ts`, luxon), heartbeats and AI budgets, and `backend/packages/data/src/timezone.ts` holds only `assertValidTimezone`. Date filters and sorts cast to `timestamptz` in the database session zone (`views/filterCompiler.ts`, `views/sortCompiler.ts`), which is a separate concern handled by #1596. `timezone.ts` sits outside the domains, so the choke point may import it (`backend/dependency-cruiser.rules.json`, rule `chokepoint-knows-no-domain`), and the new module must live beside it for the same reason.

Events and Tasks are stored as wall-clock values in the tenant's zone: a `date`, an optional `endDate`, and `timeFrom` and `timeTo` as `"HH:MM"` (see #1416). Invitations, shared calendars and ICS imports carry an instant plus an IANA zone and are converted to wall-clock on acceptance or import (that conversion belongs to those issues). Changing the tenant's zone does not change stored wall-clock values; reminders are recomputed.

Several issues use this module: the calendar timeline (#1717), tasks inside events (#1780), reminders (#1719), relative date filters (#1522), invitations (#1944), subscribed events (#2004), sleep nights (#1792), the schema projection's tenant block (#1531), recording matching (#1813) and the Events migration (#1797).

Decisions:
- A Task has no default end. A Task with `timeFrom` and no `timeTo` is a short task at its start time: its effective end equals its start, and the calendar client draws it as a short block. No end and no length is stored or computed that the user did not enter; there is no default Task length constant.
- Daylight saving follows luxon defaults: a non-existent wall-clock (29 March 2026, 2:30 in Europe/Prague) moves forward; an ambiguous one (25 October 2026, 2:30) takes the earlier offset. A day has 23, 24 or 25 hours for "lasts" and "ended" computations.

### Requirement gh-1610: [block-editor 06/13] Add atomic multi-block operations to the shared block model

#### Context

Model tier rationale: Every operation must stay correct under concurrent edits from several devices (CRDT move, duplicate-id cleanup, preserved inline attributes), which is difficult concurrency semantics with a persisted-data contract.

#1539 provides the shared block model: the type registry, the top-level `doc.getArray('order')`, blocks as `Y.Map` values with a `Y.Text`, read-time normalization and a single-block write primitive. Today `backend/packages/data/src/docs/blocks.ts` only has `putBlock`, `getBlock`, `listBlocks` and `deleteBlock` one block at a time, and the legacy `sys:children` array is overwritten whole, so a concurrent move loses one side. Nothing operates on several blocks or on the order.

The editor needs these edits: Enter splits a block, Backspace at the start joins it to the previous one (never into or from a subpage block), Delete at the end joins the next one, multi-line paste inserts several blocks, a selection can be restyled, indented, duplicated, deleted or dragged to a new position keeping its order, changing a block's type resets its done flag, and a document is never left empty. Server/WebView share this module: successful nonempty operations use one Yjs transaction; empty input is no-write.

A move is expressed as delete plus insert of the ids inside one transaction. Two clients moving the same block concurrently can therefore leave its id twice in `order`; the read-time normalization of #1539 keeps the first occurrence, and these operations remove every occurrence when they delete or move an id, and tidy duplicate ids when they write.

Refuse page split/merge/duplicate/type conversion as Tasks specify. Valid page-reference insert/move/indent/delete need no database work. Page-item creation/duplication/conversions stay with #1676/#2013/#1876 and trash/restore with #1723; server exposure remains via page operations (#1765/#1679), not individual helpers.

#### Task

Load `testing`. Implement in the shared block model module (location per the ADR from #1366), next to the code of #1539. Each function takes a `Y.Doc` and an optional transaction origin, and performs all its changes inside a single `doc.transact`.

1. `insertBlocks(doc, afterId | null, blocks)`: validates the blocks with the strict validation of #1539, assigns ids to blocks that have none, refuses an id that already exists, and inserts them after `afterId` (`null` means at the start) in the given order. An unknown `afterId` is an error. Materializes the synthetic empty block of an empty document when it inserts the first real block.
2. `splitBlock(doc, id, offset)`: splits the block's `Y.Text` at `offset`; both parts keep their inline attributes (bold, italic, code, link). The new block follows the original, keeps its type and indent, and has `done` false. Refuses `page` blocks and offsets outside the text.
3. `mergeBlocks(doc, id)`: joins block `id` into the block before it (the editor's Backspace at the start; the editor's Delete at the end calls it with the next block's id). The earlier block keeps its id, type and indent; the text and attributes of the later one are appended. Refuses with the typed error `page_block_not_mergeable` when either block is a `page` block, and with `no_previous_block` when there is none.
4. `moveBlocks(doc, ids, afterId | null)`: moves the blocks to after `afterId`, keeping their current relative document order (not the order of the `ids` argument). Removes every occurrence of each id from `order` and inserts each once. `afterId` must not be one of the moved ids.
5. `setType(doc, ids, type)`: changes the type of each block, sets `done` to false for every block it touches, and drops `done` for non-todo targets. Refuses any case where the source or target type is `page` with the typed error `page_conversion_required`.
6. `setIndent(doc, ids, delta)`: adds `delta` to each block's indent, clamping to 0-5.
7. `duplicateBlocks(doc, ids)`: inserts copies with new ids right after the last selected block, preserving text and attributes and the relative order. Refuses `page` blocks with `page_conversion_required`.
8. `deleteBlocks(doc, ids)`: removes the blocks from the map and every occurrence of their ids from `order`. If the document would become empty, leaves exactly one empty `text` block.
9. Invariants: a successful non-empty operation leaves at least one block and drops repeated ids from `order` (first occurrence kept) in the same transaction; none calls the database. An empty blocks/ids input is an explicit no-write no-op: no order tidying and no materialization of the synthetic empty document. Existing input validation still applies. Test empty-input no-mutation separately from each non-empty operation's invariant and caller-origin transaction checks.
10. Tests (Yjs only): concurrent insertion of a block after the same block on two clients gives the same order with both blocks; concurrent move of one block to two places leaves the block in the document exactly once after reading, and `deleteBlocks` then removes every occurrence; `moveBlocks` of three non-adjacent blocks places them after the target in the same relative order; `deleteBlocks` on all blocks leaves one empty text block; `mergeBlocks` into or from a `page` block fails; `setType` from `todo` to `text` sets `done` false; `setIndent` beyond 5 ends at 5; `splitBlock` in the middle of bold text keeps bold on both parts.

#### Context
