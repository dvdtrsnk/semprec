## Context

`.github/workflows/code-review.yml` runs on `synchronize` and `ready_for_review` and uses one `concurrency` group per pull request with `cancel-in-progress: true`. Relay pushes a new head while a pull request is a draft and marks it ready right after, so both events start a run in the same second. When the draft-payload run starts second, it cancels the real review and then skips its own job. The required `review` check ends `cancelled` and Relay's merge run falls into a fix round (PR #534: twice in one hour, ~30 minutes each).

This touches a protected path (`.github/workflows/**`): it is maintainer-implemented, not dispatched to Relay.

## Task

Split the workflow's concurrency group by draft state (`code-review-<pr>-draft` / `code-review-<pr>-ready`), keeping `cancel-in-progress: true`, with a comment explaining why. A newer ready run must still cancel an older ready run of the same pull request.

## Touches

- .github/workflows/code-review.yml (the `concurrency` block only)

## Scope

### In scope
- The `concurrency` block.

### Out of scope
- Any other trigger, job or step of the workflow.

## Acceptance criteria

- A draft-payload run can no longer cancel a ready run of the same pull request: they are in different concurrency groups.
- Two ready runs of the same pull request still share a group, so the older one is cancelled.
- A `workflow_dispatch` run falls into the ready group.
