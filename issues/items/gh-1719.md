## Context

Model tier rationale: One pure function over the shared calendar time module with a clear rule table and existing time-zone fixtures, but daylight-saving and all-day edge cases make the exact semantics load-bearing for two later issues.

Reminders for Events and Tasks need one definition of "when does this fire". Today no such definition exists: `Tasks.notifications` is a checkbox with no behavior (`backend/packages/data/src/seed/seedTenDatabases.ts`), Events have no reminder properties, and the notification system (`backend/packages/data/src/notifications/notify.ts`) only knows system alerts. #1416 adds the Event fields and #1714 guarantees their values are valid. The calendar time module from #1418 (`backend/packages/data/src/calendarTime.ts`) converts wall-clock dates and times to instants in the tenant's time zone. The calendars database from #1600 carries a per-calendar `notify` switch.

This issue adds the single pure function that turns one item into a fire instant (or "no reminder"). #1858 calls it to build a feed for the phone's local scheduler, and any future server-side push would call the same function.

Rules, as product behavior:
- A timed Event fires at its start minus `travelMinutes` minus `alertMinutes`.
- An all-day Event (no `timeFrom`) fires at 09:00 of its first day minus `alertMinutes`; with 1 day before it fires at 09:00 the previous day, with 15 minutes at 08:45. `travelMinutes` is ignored for all-day Events.
- A Task with `notifications` on fires at its `timeFrom`; without a time, at 09:00 of its `date`. A Task has no alert offset.
- A birthday entry fires at 09:00 of its date. A holiday entry fires only when its calendar's `notify` is on.
- Nothing fires for: an item in the trash, a Task whose status is `done` or `wontDo`, a cancelled occurrence, or an item whose calendar has `notify` false. A hidden calendar still fires; only `notify` mutes.
- Wall-clock to instant follows the daylight-saving rules of #1418.

Decisions:
- The 09:00 all-day hour is a fixed constant defined here, `ALL_DAY_REMINDER_HOUR = 9`; there is no setting for it.
- A Task carried over to a later day (by #1884) reminds only on its stored `date`, not every day. Reason: a carried-over task is already visible in Today as "moved from ...", so a daily reminder would be redundant.
- The system Tasks calendar's `notify` flag never mutes Tasks; `Tasks.notifications` is the only switch for a Task. Reason: the Tasks calendar is seeded with `notify` false by default and would otherwise silence every task reminder.

## Task

Load `testing`.

1. Create `backend/packages/data/src/calendar/reminderFireTime.ts` exporting `ALL_DAY_REMINDER_HOUR` and a pure function `computeReminderFireAt(input, zone)` returning an ISO instant string or `null`. `input` is a discriminated union by `kind`: `event` (`date`, `timeFrom?`, `alertMinutes?`, `travelMinutes?`), `task` (`date`, `timeFrom?`, `notifications`, `status`), `birthday` (`date`), `holiday` (`date`), each with `calendarNotify: boolean`, `trashed: boolean` and `cancelled: boolean`. It uses `wallClockToInstant` from `calendarTime.ts`.
2. Export the reason a reminder is suppressed through a second function `reminderSuppression(input)` returning a string code or `null`, so tests and later callers can tell "no alert set" from "muted".
3. Tests with a fixed zone Europe/Prague: a meeting at 10:00 with `alertMinutes` 15 and `travelMinutes` 30 fires at 09:15 local; an all-day Event with `alertMinutes` 1440 fires at 09:00 the previous day, with 15 at 08:45; a Task with notifications on and `timeFrom` 14:00 fires at 14:00, without a time at 09:00; trashed, `done`, cancelled and `calendarNotify` false return `null`; a reminder across 29 March 2026 moves forward and across 25 October 2026 resolves to one instant.

## Scope

### In scope

- The pure fire-time function, its suppression rules and its tests.

### Out of scope

- Reading items from the database and listing reminders in a window: #1858.
- Scheduling, pushing or delivering anything: #1879. A server-side push that sends reminders itself is deferred and not in v1; the phone schedules reminders from the feed.
- Expanding recurring series into occurrences: #1877 for Events and #1672 for Tasks; callers pass one occurrence at a time.
- Generating birthday and holiday entries: #1800 and #1804.
- Changing the seeded `notify` values of system calendars.

## Acceptance criteria

- When an Event at 10:00 on a day has `alertMinutes` 15 and `travelMinutes` 30, then the fire instant is 09:15 Europe/Prague that day.
- When an all-day Event has `alertMinutes` 1440, then it fires at 09:00 the previous day; with `alertMinutes` 15 at 08:45 the same day; `travelMinutes` changes neither.
- When a Task has notifications on and `timeFrom` 14:00, then it fires at 14:00; with no time at 09:00.
- When the item is trashed, the Task is `done`, the occurrence is cancelled, or the calendar's `notify` is false, then the result is `null`; a hidden calendar with `notify` true still fires.
- When the system Tasks calendar has `notify` false and a Task has notifications on, then the Task still fires.
- When the wall-clock time falls in the missing hour of 29 March 2026 or the repeated hour of 25 October 2026, then exactly one valid instant is returned.
