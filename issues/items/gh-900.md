## Context

Review follow-up from harvest issue #889. PR #757 (finding e4d31e2a6d), `backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts:165`: `settleTokenGatewayCall` guards with `result.rowCount === 0` (and `settleAudioGatewayCall` at line 184 of the same file has the identical guard), but `pg` types `QueryResult.rowCount` as `number | null`; for a `null` the guard is false and the function falls through to `requireSingleRow` on an empty row list, which throws instead of returning the documented `null` for "no `reserved` row matched".

## Task

Change the guard in both `settleTokenGatewayCall` and `settleAudioGatewayCall` so a `null` or `0` `rowCount` returns `null` (for example `if (!result.rowCount) return null;`), the same one-line change in each. Add two tests to `backend/packages/data/src/__tests__/aiGatewayCallsStore.test.ts`: one that calls `settleTokenGatewayCall` and one that calls `settleAudioGatewayCall`, each with a stub client whose `query` resolves `{ rows: [], rowCount: null }`, each asserting the result is `null`.

## Touches

- backend/packages/data/src/aiGateway/aiGatewayCallsStore.ts (the guards in `settleTokenGatewayCall` and `settleAudioGatewayCall` only)
- backend/packages/data/src/__tests__/aiGatewayCallsStore.test.ts (two new test cases)

## Scope

### In scope

The guard change in both settle functions and their two tests.

### Out of scope

Any other `rowCount` check in the file, and any other change to the two settle functions.

## Acceptance criteria

- `settleTokenGatewayCall` and `settleAudioGatewayCall` each return `null` when the client's `query` resolves `{ rows: [], rowCount: null }`, each covered by its own new test.
- Both still return `null` when no `reserved` row matches (`rowCount` 0) and still return the settled row when one does; the existing tests pass.
