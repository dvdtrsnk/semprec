## Context

Model tier rationale: It decides which of a user's records leave the database for a model call, including the rule that sensitive databases are excluded without a grant, and it bounds the request under a hard size limit; a mistake leaks data or breaks every proposal.

The computation built by #1434 sends the model the item's text and the target database's properties, and nothing else. It cannot resolve "tomorrow at 9", cannot pick an existing project, person or company by id, and cannot say "you had no meeting then". This issue adds the facts and the workspace context a good proposal needs, bounded so the request stays under the gateway's 1 MiB body limit (`MAX_BODY_BYTES` in `backend/services/semprec-ai-gateway/src/completeHandler.ts`; the gateway also reserves the budget by text length).

The Inbox item carries `date` and `time` (the user's wall clock at capture) and, after #1964, `captureChannel`; the text of a voice note is stored in `transcribedText` by #1980. The tenant timezone is read by `getSystemTimezone` (`backend/packages/data/src/systemSettings.ts`). Databases can be marked sensitive (#1808, for example health records), and per-database grants for a project are enforced in the data layer by #1810. The tick belongs to the Semprec project (`ActionContext.projectItemId`, passed into the computation by #1434), and that project has no grants by default. The context for a recompute includes the previous proposal state stored on the card (`aiProposal`, `history`, `userEditedKeys`, declared by #1451), so a recompute respects what the user edited. Duration hints for events come from #1993, ARES and duplicates from #1989 and #1992, and grounding in option catalogs from #1990.

Decision: the request gets these facts: `text` (the item's `text`, else `transcribedText`), `captureDate`, `captureTime`, `captureChannel` (if set), `timezone`, `today` (the current date in the tenant timezone), and the instruction to resolve relative dates and times against the capture date and time and to write absolute values (`YYYY-MM-DD`, `HH:mm`).

Decision: the workspace context lists, with ids, at most 20 entries per kind (constant `CONTEXT_LIMIT_PER_KIND`): active projects (name, status, area id; only status `inProgress` or `longTerm`, so a `done` or `archived` project is never proposed as a default target), areas (name), people (name, relationship), companies (name, registration number) and events whose date lies between one day before and fourteen days after the capture date (name, type, date), newest relevance first (projects and others by most recent update, events by soonest). Names are cut at 100 characters.

Decision: the context is read through the grant-enforcing data-layer path as the Semprec project. A sensitive database (health records and any other marked one) contributes nothing unless a grant for that project exists; no placeholder or count is sent either.

Decision: a hard budget of 900 KiB is applied to the serialized request. When it is exceeded, entries are dropped in this order until it fits: events, companies, people, areas, projects, always the oldest first within a kind; the item text is never cut here.

## Task

Load `ai-gateway`, `io-hardening`, `canonical-keys` and `testing`.

1. Add `backend/packages/data/src/inbox/proposalWorkspaceContext.ts` with `readProposalWorkspaceContext(client, { projectItemId, captureDate, limitPerKind })` returning the five lists above as plain data. It reads only, and all reads go through the grant-enforcing path of #1810 as `projectItemId`; export it from `backend/packages/data/src/index.ts`.
2. Add `backend/services/semprec-api/src/proposalContext.ts` that assembles the request facts and the context, applies the size budget, and returns the object the computation serializes. Extend `proposalComputation.ts` of #1434 to call it (the read happens in a short read transaction before the gateway call; the call itself stays outside any transaction), to include the context in the user message and to add the resolution instruction to the system message.
3. For a recompute, add the existing card's `aiProposal`, its `history` and its `userEditedKeys` to the request when they are present, so the model does not overwrite keys the user edited.
4. The output stays `properties`, `reason`, `confidence`; ask for rewritten Markdown only inside text properties, never in other value types. The result still goes through `assertValidProposalEnvelope`.
5. Tests with a stubbed gateway: a capture on 2026-10-16 at 08:12 in `Europe/Prague` yields a request with `captureDate` `2026-10-16`, `captureTime` `08:12`, `timezone` `Europe/Prague` and the stub's `2026-10-17`/`09:00` result is stored; a tenant with 500 projects sends at most 20 and a body under 1 MiB; without a grant the request contains no health record and with a grant for the Semprec project it does; trashed and archived items and `done` projects are not included; a recompute carries `aiProposal` and `userEditedKeys`; a voice-note item with only `transcribedText` uses it as `text`.

## Scope

### In scope

- Capture facts, timezone and today, the bounded and grant-filtered workspace context, the size budget and the recompute state in the request.

### Out of scope

- The computation and registration of the tick (#1434) and failure recording (#1485).
- Attachment content (#1970), past Event durations (#1993), option catalogs (#1990), registry verification and duplicate detection (#1989, #1992).
- Managing grants (#1841) and marking databases sensitive (#1808).
- Relations and multi-step output (#1488, #1492).

## Acceptance criteria

- When an item captured on 2026-10-16 at 08:12 in the Europe/Prague timezone is computed, then the gateway request carries `captureDate` `2026-10-16`, `captureTime` `08:12` and `timezone` `Europe/Prague`, and the card stores the values the model returns.
- When the workspace has 500 projects, then the request lists at most 20 and its body is under 1 MiB.
- When no grant exists for the Semprec project, then the request contains no record of a sensitive database such as health records.
- When a card is recomputed, then its previous proposal and the keys the user edited are in the request.
- The context read writes nothing.
