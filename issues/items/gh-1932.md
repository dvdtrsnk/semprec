## Context

Model tier rationale: Replaces the row identity of the run list for chat sessions with per-message rows, joining runs, Semp messages, attempt chains and cost attribution, with several distinct edge cases (retries, tick-thread turns, system-triggered turns, interim fallback), so the uncertainty is highest of the four and the higher tier is chosen.

A chat with Semp is one `unit = 'session'` agent run per project, so in the run list (#1909) a long conversation would be one row with the first task as title and the cost and duration of the whole session. The product shows each answer of the agent as its own entry: what the user asked, how long that answer took and what it cost. The conversation messages are stored in `semp_threads` and `semp_messages` (#1367); an assistant message stores its duration (#1860), a failed reply can be retried and the attempts of one answer share a reply identity (#1926), and gateway calls are attributed to the message they answer (#1744).

Decisions:
- A row for a chat answer represents one assistant message. Retried attempts of the same answer collapse into one row showing the latest attempt, with `attempt` set to its number.
- `title` is the text of the user message the assistant message replies to (`reply_to`). When the reply is to a system message with no text (a system-triggered turn such as the outcome of an approval), the title is a localized label chosen by the system message's `system_key` (for example for keys under `approval.outcome.*`), with a generic localized fallback for unknown keys.
- A turn in a heartbeat tick thread (a follow-up question or the continuation after an approval outcome) is a session run triggered by the user, and its `triggerLabel` is "Tik" according to `semp_threads.kind` of the thread, not "Chat".
- Until a project has any Semp messages for a session run (runs written before messages existed), that session run stays one row with the title of its first task.
- Other runs (heartbeat, MCP) remain one row each as in #1909 and #1914.

## Task

Load `canonical-keys`, `error-handling` and `testing`.

1. Extend the list query behind `GET /api/agent-runs` (`listProjectAgentRuns` in `backend/packages/data/src/agentRuns/agentRunsStore.ts`): for runs with `unit = 'session'` and `triggered_by = 'user'` that have assistant messages in `semp_messages`, produce one row per assistant message (collapsing attempts of one answer to the latest), ordered together with the other rows by the row's start time then id, descending, and bounded by the same `limit` after expansion.
2. Row fields for an answer row: `id` and `agentRunId` are the run id (`id` stays unique per row by also returning `messageId`); `messageId` is the assistant message id; `startedAt` is the message's start; `durationMs` is the message's stored duration; `costUsd` is the sum of `ai_gateway_calls.cost_usd` where `semp_message_id` is the message id (one batched aggregation for all answer rows, with the run-level aggregation for non-answer rows); `displayStatus`, `errorSummary` and `attempt` are those of the answer, derived from the latest attempt with the shared functions already used by the list.
3. Compute `title` per the decisions above and `triggerLabel` from the thread kind (tick-thread turn: "Tik"; otherwise "Chat"), localized through the mechanism used by #1909; add the system-trigger title labels to the localization catalogs.
4. Rows of runs without messages keep the single-row behavior.
5. Update the response type so that `messageId` is present on answer rows and `null` on others.

## Scope

### In scope

- One row per assistant answer for chat and tick-thread session runs, with per-answer duration, cost, status, attempt and title.

### Out of scope

- The attachment ref that carries `messageId`: #1936.
- Creating Semp messages, retries and the duration/cost attribution themselves: #1367, #1860, #1926, #1744.
- Listing the individual earlier attempts of an answer.
- Filters and pagination.

## Acceptance criteria

- When a session run holds three user messages answered by three assistant messages, the list contains three rows for it, each with the title of its question, its own duration and its own cost, and none carries the session's total.
- When an answer was retried twice (three attempts), the list has one row for it with `attempt` 3 and the latest attempt's status.
- When an assistant message replies to a system message about an approval outcome, the row's title is the localized label for its `system_key`.
- A turn in a heartbeat tick thread has `triggerLabel` "Tik"; a turn in a normal chat has "Chat".
- A session run with no Semp messages is returned as a single row titled with its first task.
- `limit` counts rows after expansion, and a run or message of another tenant is never returned.
