## Decisions

- Clustering follows the code the fixes touch and the open issues they must wait for, not one issue per finding: test-only fixes are grouped by kind (missing cases vs. dead/duplicated code), and the `pg` dependency removal stays alone because its lockfile edit must wait for five other issues that nothing else in the batch needs.
- The drift-check comment is corrected rather than the transaction made REPEATABLE READ: the finding is about the comment's claim, and the transaction's stated purpose (atomic check and report) holds under READ COMMITTED.
- The duplicate worker instance id message (PR #300) is rejected as invalid: `ModuleRegistry` refuses a worker name claimed twice, so the cross-worker collision the finding describes cannot happen.
- `Emails.attachments` staying `one_to_many` (PR #318) is rejected as invalid: each attachment gets its own File item; only that pull request's description was stale.
- The missing service-to-module public-entry test (PR #309) is not worth doing: #653 deletes the modules boundary rules it would test.
