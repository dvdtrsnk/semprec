## Context

The first-account bootstrap token travels in the page URL: the operator opens `/?page=setup&token=<setupToken>` (`backend/services/semprec-api/src/routeMatrix.ts` lines 97-105), `web/src/main.tsx` lines 55-61 read `params.get("token")` into the `setup` route, and `web/src/views/setup/SetupWizard.tsx` sends it as `Authorization: Bearer` (`web/src/api/setupOperations.ts` lines 55-63, whose docblock at lines 9-13 explains why the browser carries it). Nothing ever removes it from the address bar: it stays in the tab's history entry, in the browser's history/autocomplete, in any bookmark or screenshot, and it is sent as the `Referer` of the `POST /api/setup` request and of the `?page=login` link the success state renders (line 40) — the referrer is same-origin, so it lands in the backend/Caddy access logs with the token as a query string. The token is single-purpose (the API answers 404 once a user exists, `setupHandler.ts`), but until the wizard is completed it is a live credential.

`grep -rn "replaceState" web/src` is empty.

## Task

- In `SetupWizard.tsx`, add a mount effect (`useEffect(() => { … }, [])`) that, when `window.location.search` contains a `token` parameter, builds a URL without it (`const url = new URL(window.location.href); url.searchParams.delete("token"); window.history.replaceState(window.history.state, "", url);`) — the `page=setup` parameter stays so a reload still shows the wizard (with the "no longer valid" state, since the token is gone, which is the honest outcome). The component keeps using the `token` prop it received; nothing re-reads the URL. Explain in the component docblock why the token is stripped (history, referrer, access logs).
- Test in `web/src/views/setup/__tests__/SetupWizard.test.tsx`: before rendering, `window.history.replaceState(null, "", "/?page=setup&token=abc")`; after render, `window.location.search` is `?page=setup` and `window.history.length` did not grow (replace, not push); submitting still calls `setupAccount` with the `token` prop `abc`. Restore the URL in `afterEach`.

## Scope

### In scope

- Stripping `token` from the address bar once the wizard has it, and its test.

### Out of scope

- Moving the token out of the URL entirely (a paste field instead of a link) — a UX change beyond the finding; the initial page request still carries it once, which only a different delivery would avoid.
- `main.tsx`'s routing and `setupOperations.ts` — unchanged.
- The login page the success link points at — sibling issue G3 of this batch.

## Acceptance criteria

- When `/?page=setup&token=abc` is opened, the wizard renders and the address bar reads `/?page=setup` before any user action; the browser's back button does not return to a URL containing the token.
- When the form is submitted, the request still carries `Authorization: Bearer abc` and the `Referer` header of that request contains no `token=`.
- Every existing case in `SetupWizard.test.tsx` passes; `pnpm run verify` in `web/` passes.
