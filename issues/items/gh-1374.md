## Context

Model tier rationale: A single-file change that makes an existing synthetic event match an already-defined payload shape, with an existing test file to update and no new lifecycle, authorization or schema contract.

When the agents process restarts, `repairInterruptedRuns` in `backend/packages/agent-runtime/src/startupRepair.ts` closes every orphaned run. If a run's last event is an unmatched `tool_use`, it appends a synthetic `tool_result` so every call has a result. That synthetic row is built by spreading the `tool_use` payload and adding `kind`, `error: true` and `result: "<text>"`. It differs from the result a tool call normally produces (`{toolCallId, name, result: {content[], details}, isError}` from `toAgentMessage` in `backend/services/semprec-agents/src/piAgentSession.ts`):

- it has no `isError`, and `result` is a plain string instead of `{content, details}`;
- it repeats the call's `arguments`.

Consequences: any reader that decides "this step failed" from `isError` or `result.details.error` misses an interrupted call, and the conversation rebuild in `backend/services/semprec-agents/src/piConversationHistory.ts` (`toToolResultMessage`) rejects the row because it requires a boolean `isError` and `result.content`. Interrupted calls must read like any other failed call.

Decision: the failure is recorded as `isError: true` with `result.details.error: true`, the same as a tool that returned an error result, so every reader needs only one rule. Rows already stored in the old synthetic shape are not rewritten; readers that need them still accept a top-level `error: true` (that tolerance belongs to the readers, not this issue).

Later issues build on this: the per-reply failure detection #1890, the step projection #1847, retrying a failed reply #1926 and pairing dangling calls on shutdown #1568.

## Task

Load `testing` and `error-handling`.

1. In `startupRepair.ts`, change the synthetic `tool_result` to exactly: `{kind: "tool_result", toolCallId, name, result: {content: [{type: "text", text: <interruption message>}], details: {error: true}}, isError: true}`. Copy `toolCallId`, `name` and, when present on the `tool_use`, the identity fields `operation`, `mcp`, `targetDatabaseId`, `targetItemId` from the `tool_use` payload; do not copy `arguments` or any other field. Keep the existing interruption message text (it names `interrupted_by_restart`).
2. Keep the existing defensive handling of a `tool_use` payload that is not an object; a missing `toolCallId` or `name` must still produce a well-formed row (empty identity fields are not invented, the `name` falls back to an empty string only if the stored payload had none).
3. Update `backend/packages/agent-runtime/src/__tests__/startupRepair.test.ts` (and the per-tenant test if it asserts the old shape): the repaired row has `isError: true`, `result.content[0].text` containing the interruption reason, `result.details.error === true`, no top-level `error` or string `result`, and the stored history passes `conversationReconstruction`'s protocol check and `piConversationHistory`'s tool result conversion.

## Scope

### In scope

- The shape of the synthetic `tool_result` written for an unmatched `tool_use` at startup repair.

### Out of scope

- Rewriting synthetic rows already stored in the old shape.
- Pairing dangling calls when an idle thread session is closed on shutdown: #1568.
- Reading or projecting failed steps: #1890, #1847.
- Recording `operation` / `mcp` on regular tool events: #1424 (this issue only copies those fields when they are present).

## Acceptance criteria

- When a run is interrupted with a trailing `tool_use`, then startup repair appends a `tool_result` with `isError: true`, `result.content` text naming the restart interruption, `result.details.error: true`, and the same `toolCallId` and `name` as the call.
- The repaired row has no `arguments`, no top-level `error` and no string `result`.
- When the `tool_use` carried `operation` or `mcp`, the synthetic result carries the same values.
- A run repaired this way can be reconstructed into a conversation without error.
- A run whose last event is not an unmatched `tool_use` gets no synthetic row, as before.
