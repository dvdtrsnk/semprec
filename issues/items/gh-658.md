## Context

Every bespoke request listener in `backend/services/semprec-api/src/` carries its own private copy of the same three or four helpers, byte-identical modulo a `headers` argument and the size cap:

- `sendJson(res, status, body)` — 13 definitions: `adapter/adapterRoute.ts` line 55, `agentRunHandler.ts` 7, `approvalRequestsHandler.ts` 14, `authHandler.ts` 27 (the only one taking an optional `headers` record, used for `Set-Cookie` at lines 176 and 219), `blobsHandler.ts` 18, `filesHandler.ts` 27, `graphWebhookHandler.ts` 23, `healthzHandler.ts` 6, `mcpAgentPageHandler.ts` 14, `mcp/mcpHandler.ts` 37, `notificationsHandler.ts` 14, `schemaHandler.ts` 7, `setupHandler.ts` 21.
- `readJsonBody(req)` with a module-level `MAX_BODY_BYTES` and a private `class PayloadTooLargeError extends Error {}` — 7 definitions: `adapter/adapterRoute.ts` 38 (1 MiB; its `PayloadTooLargeError` at line 30 is the only exported one), `agentRunHandler.ts` 18 (64 KiB), `approvalRequestsHandler.ts` 24 (1 MiB), `authHandler.ts` 99 (64 KiB), `mcpAgentPageHandler.ts` 24 (1 MiB), `mcp/mcpHandler.ts` 55 (1 MiB; throws its own `JsonParseError` instead of `ValidationError` so the caller can answer JSON-RPC `-32700`), `setupHandler.ts` 31 (64 KiB). `graphWebhookHandler.ts` line 11 has the raw variant `readBody(req): Promise<Buffer>` (256 KiB) with the same loop.
- `extractBearerToken(req)` — `setupHandler.ts` line 7 (returns `""` when absent, no trim) and `mcp/mcpHandler.ts` line 80 (returns `null` when absent or empty, trims).

`adapter/adapterRoute.ts` keeps its copies module-private on purpose (docstring, lines 22-26) so a route handler cannot bypass its auth gate — that argument covers `requireAuthenticatedIdentity` and the response mappers, not the body reader and the JSON writer, which every bespoke listener re-implements anyway. Fourteen copies mean a fix to any of them (a size cap, a content-type, the empty-body rule) is a fourteen-file change, and the copies have already drifted (`PayloadTooLargeError` is eight distinct classes, so an `instanceof` across modules is false). #637, #638 and #639 edit these same handler files (path validation, error bodies, `resolveActor` in `mcpHandler.ts`); this issue is sequenced after all three so the edits do not collide.

## Task

- New `backend/services/semprec-api/src/adapter/http.ts` exporting:
  - `class PayloadTooLargeError extends Error {}` (the one class every listener catches).
  - `sendJson(res: ServerResponse, status: number, body: unknown, headers?: Record<string, string>): void` — `writeHead(status, { "Content-Type": "application/json; charset=utf-8", ...headers })` then `end(JSON.stringify(body))`.
  - `readRawBody(req: IncomingMessage, options: { maxBytes: number }): Promise<Buffer>` — the existing chunk loop; throws `PayloadTooLargeError("Request body exceeds the maximum allowed size")` once `size > maxBytes`.
  - `readJsonBody(req: IncomingMessage, options: { maxBytes: number }): Promise<unknown>` — `readRawBody`, then `{}` for an empty body, else `JSON.parse`; a parse failure throws `new ValidationError("Request body is not valid JSON")` (from `@semprec/data`).
  - `extractBearerToken(req: IncomingMessage): string | null` — `mcpHandler.ts`'s semantics (trimmed token, `null` when the header is absent, not `Bearer `, or empty).
  - No default cap: `maxBytes` is a required option, because the caps deliberately differ per listener.
- Replace every copy listed in Context with an import from `./adapter/http.js` (or `../adapter/http.js` from `mcp/`), keeping each listener's cap as a module-level constant passed in (`MAX_BODY_BYTES` stays where it is; only the function bodies go). Specifically:
  - `adapter/adapterRoute.ts`: import `readJsonBody`, `sendJson`, `PayloadTooLargeError` from `./http.js`; re-export `PayloadTooLargeError` from `adapterRoute.ts` so any existing importer keeps working; delete the local copies and trim the docstring sentence that lists `readJsonBody` among the module-private helpers.
  - `graphWebhookHandler.ts`: `readBody` becomes `readRawBody(req, { maxBytes: MAX_BODY_BYTES })`.
  - `mcp/mcpHandler.ts`: delete `JsonParseError`; in the body-reading `try/catch` (lines 151-164) map `err instanceof ValidationError` to the existing `rpcError(null, -32700, "Parse error")` response (that `try` block calls nothing else that throws `ValidationError`).
  - `setupHandler.ts`: `bootstrapFirstAccount(pool, options.setupToken, extractBearerToken(req) ?? "", …)`. The one behaviour delta in this issue: a setup token sent with surrounding whitespace is now trimmed before comparison (it was rejected before); accepted, and stated in the pull request description.
  - `authHandler.ts`: its `extractToken` (line 55, cookie-or-bearer with a channel) stays — it is not a duplicate; only `sendJson` and `readJsonBody` move.
- Tests:
  - New `backend/services/semprec-api/src/adapter/__tests__/http.unit.test.ts` (unit tier, no Postgres; build requests with `node:stream`'s `Readable` cast to `IncomingMessage` and a stub `ServerResponse` that records `writeHead`/`end`): `sendJson` writes the status, the JSON content type and the merged extra headers; `readJsonBody` returns `{}` for an empty body, the parsed value for valid JSON, throws `ValidationError` for `{not json`, throws `PayloadTooLargeError` when the body exceeds `maxBytes` by one byte and resolves at exactly `maxBytes`; `readRawBody` returns the concatenated bytes; `extractBearerToken` returns `null` for no header, for `Basic x` and for `Bearer  ` (spaces only), and the trimmed token for `Bearer  abc `.
  - Every existing handler test (`__tests__/agentRunHandler.test.ts`, `approvalRequestsHandler.test.ts`, `authHandler.test.ts`, `filesAndBlobsHandler.test.ts`, `graphWebhookHandler.test.ts`, `healthzHandler.test.ts`, `mcpAgentPageHandler.test.ts`, `schemaHandler.test.ts`, `setupHandler.test.ts`, `adapter/__tests__/adapterRoute.test.ts`, `mcp/__tests__/mcpHandler.test.ts`, `mcp/__tests__/mcpGenericOperationsContract.test.ts`) passes **unchanged** — the 413 cases, the invalid-JSON 400 cases and the MCP `-32700` case are the behaviour guard for this refactor. Add no case to them.

## Scope

### In scope

- One helper module and the replacement of every private copy with an import, with identical status codes, caps, content type and error mapping.

### Out of scope

- Routing the bespoke listeners through `createAdapterRequestListener`, or unifying their `{ error, code, details }` bodies with the adapter envelope.
- Changing any cap, any error message, `authHandler.ts`'s `extractToken`, or `filesHandler.ts`'s streamed upload path (it reads no JSON body).
- The error-body projection (`toPublicErrorBody`, #638), UUID validation (#637) and the `/mcp` cookie rejection (#639) — already merged when this issue starts; do not restructure their code.
- `services/semprec-ai-gateway` and `services/semprec-transcribe`, which have their own handlers.

## Acceptance criteria

- When `grep -rn "function sendJson\|function readJsonBody\|function readBody\|class PayloadTooLargeError\|class JsonParseError\|function extractBearerToken" backend/services/semprec-api/src --include=*.ts --exclude-dir=__tests__` runs, every match is in `adapter/http.ts`.
- When a request body exceeds a listener's cap by one byte, the response is 413 with the same body as before this issue (`{ error: "Request body exceeds the maximum allowed size" }` for the bespoke listeners, `{ error: { code: "payload_too_large" } }` for adapter routes); at exactly the cap it is accepted.
- When `POST /mcp` receives a body that is not JSON, the response is still 200 with `rpcError(null, -32700, "Parse error")`; when it exceeds 1 MiB, still 413.
- When `POST /api/setup` receives the correct token with a trailing space, the request succeeds (the one stated delta); with no `Authorization` header, the response is unchanged from today.
- `pnpm run test:unit` runs `http.unit.test.ts` green, and every listed existing handler test passes without modification.
