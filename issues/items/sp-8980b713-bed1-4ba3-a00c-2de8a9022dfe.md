## Context

Model tier rationale: A new network protocol client against user-supplied hosts with discovery, XML parsing and iCalendar round-tripping.

iCloud and generic accounts authenticate with the stored app-specific or plain password. iCloud CalDAV lives at `caldav.icloud.com` (redirecting to a partition host); generic servers expose `/.well-known/caldav`.

Decision: generic accounts store an optional `caldav_url` in `mail_account_server_settings`; when empty, discovery starts at `https://<mail domain>/.well-known/caldav`.

## Task

Load `state-writes`, `db-migrations`, `error-handling`, `io-hardening`, `canonical-keys` and `testing`.

1. The CalDAV protocol through the `tsdav` library (add it to `backend/packages/data` at an exact version) instead of a hand-written WebDAV client. Every `tsdav` request goes through a custom fetch built on `createOutboundHttp()` (https only, timeout 20 s, body cap 10 MiB, redirects followed only to https hosts that pass the outbound policy, at most 3); no `tsdav` call may reach the network through its default fetch. `tsdav` responses are validated at the adapter edge before use. Discovery: current-user-principal, calendar-home-set, calendar listing (displayname, calendar-color, current-user-privilege-set for read-only, supported components VEVENT only).
2. Changes through `tsdav`'s sync-collection (RFC 6578) with the stored sync-token; on an invalid token or a server without sync-collection, compare `getctag` then list etags and fetch changed hrefs with calendar-multiget.
3. iCalendar parsing and serialization with `ical.js`: VEVENT fields, TZID and VTIMEZONE, RRULE, EXDATE, RECURRENCE-ID overrides, VALARM (first display alarm → `alertMinutes`), attendees and organizer kept in the payload snapshot.
4. `putEvent` with If-Match (update) or If-None-Match: * (create) and `deleteEvent` with If-Match.
5. Add `caldav_url` to the password connect route body for generic accounts; verify it at connect when Calendars is requested.
6. Use the account's credential with actor `sync_worker`, purpose `calendar_sync`.

## Scope

### In scope

- CalDAV discovery, incremental sync, iCalendar mapping and writes.

### Out of scope

- Push from CalDAV servers (none for third parties; polling only).

## Acceptance criteria

- Against the fake server, an account lists its calendars with names, colours and read-only flags.
- A changed event is fetched through sync-collection; a server without it falls back to ctag and etags.
- A recurring event with TZID, EXDATE and an override round-trips byte-equivalently in the fields the app models.
- A 412 on put is reported as a conflict to the caller, not as a failure.
- An address refused by the outbound policy and an unreachable server answer the same error.
- A redirect from the fake server to an address the outbound policy refuses is not followed, which proves `tsdav` uses the injected fetch.
