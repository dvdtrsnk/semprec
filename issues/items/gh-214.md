**Blocked by:** #84, #115, #121, #137, #152

## Context

The generated permission manifest and owner-process drift checks do not detect contradictions between mechanically enforced permissions and hand-written project-agent guidance. Issue #29 deliberately excludes this semantic comparison, while issue #33 supplies only the generic system-prompt extension point. There is currently no canonical hand-written guidance source at all.

This first of three parts therefore defines the canonical guidance source, its shared ports, the neutral application service with ownership authorization, and the projection of the guidance into the agent system prompt, together with the package-boundary rules the later parts depend on. #215 adds the AI gateway structured completion endpoint and client port; #85 builds the drift-detection action, findings, and notifications on both.

## Task

Add `project_agent_guidance(project_item_id uuid primary key, owner_user_id uuid not null references users(id), markdown text not null, updated_at timestamptz not null)`. The migration and SQL implementation belong to `packages/data`; `packages/agent-runtime` may import only the injected interface below, never `pg`, a pool singleton, or the concrete store. `project_item_id` is validated through the item data layer as an existing item in the system Projects database because partitioned `items` cannot supply a direct FK. Empty/whitespace-only `markdown` is rejected. This row is the sole canonical hand-written guidance source and its `owner_user_id` is the notification recipient (#85 uses it as such).

Define shared `ProjectAgentGuidance`, command inputs, and generic transaction ports in `packages/shared/src/projectAgentGuidance.ts`: `TransactionRunner<Tx> = { withTransaction<T>(options: { isolation: 'repeatable_read' | 'serializable' }, work: (tx: Tx) => Promise<T>): Promise<T> }`, whose concrete data runner executes `BEGIN ISOLATION LEVEL REPEATABLE READ` or `BEGIN ISOLATION LEVEL SERIALIZABLE` accordingly; `ProjectAgentGuidanceStore<Tx>` exposes `load(tx, projectItemId)`, `upsert(tx, row)`, and `transfer(tx, projectItemId, newOwnerUserId)`; `GuidanceReferenceStore<Tx>` exposes `requireProjectsItem(tx, projectItemId)`, `requireUser(tx, userId)`, and `requireUserLocale(tx, userId): Promise<string>`; `GuidanceHeartbeatStore<Tx>` exposes `upsertDriftHeartbeat(tx, projectItemId): Promise<void>`. These shared interfaces are generic and never name `pg`. `packages/data/src/projectAgentGuidanceStore.ts` supplies the concrete `PoolClient` implementations of the guidance and reference stores and the migration; stores use the supplied transaction and never open one. The concrete `GuidanceHeartbeatStore` (the `core.agentGuidanceDrift` heartbeat, its unique index, and its exact persisted fields) is delivered by #85; in this part the `semprec-api` composition root injects a documented no-op `GuidanceHeartbeatStore` implementation so the service already performs the heartbeat upsert call inside its transaction, and service tests use a recording fake to prove the call happens within the same transaction as the guidance write.

In `packages/application/src/projectAgentGuidance`, export generic `createProjectAgentGuidanceService<Tx>({ store, references, heartbeats, transactions })`, returning methods `loadProjectAgentGuidance(projectItemId)`, `upsertProjectAgentGuidance(actor, { projectItemId, markdown })`, and `transferProjectAgentGuidance(actor, { projectItemId, newOwnerUserId })`. The `semprec-api` composition root injects `TransactionRunner<PoolClient>` and concrete stores; each mutating service call owns exactly one transaction covering reference validation, guidance write, and heartbeat upsert. `actor` is server-derived authenticated user context. Upsert may create only with `ownerUserId = actor.userId`, and may update only when actor is the current owner; transfer is allowed only to the current owner and requires an existing target user. Missing project/user returns `400 validation_failed` with `{ field: 'projectItemId' | 'newOwnerUserId', reason: 'not_found' }`; a non-owner returns `403 owner_violation` with `{ field: 'ownerUserId', projectItemId }`; blank guidance returns `400 validation_failed` with `{ field: 'markdown', reason: 'blank' }`. No REST endpoint is added. #33's `resourceLoader.systemPromptOverride` calls the injected service loader and appends `markdown` verbatim under the fixed heading `## Project-specific guidance`; no other file, generated AGENT.md section, or callback output qualifies as hand-written guidance.

Package placement is boundary-critical: the persistence migrations/stores stay in `packages/data`; all generic ports stay in `packages/shared`; `createProjectAgentGuidanceService` (and, in #85, `createAgentGuidanceDriftAction`) live in the new neutral `packages/application/src/projectAgentGuidance`, which may import shared ports but neither `services/*` nor `packages/agent-runtime`. `semprec-api` composes the service from application/data dependencies. `packages/agent-runtime` contains only the #33 `systemPromptOverride` adapter and is imported exclusively by `semprec-agents`; it receives a `loadProjectAgentGuidance` port from that process composition root. Dependency-cruiser tests enforce these directions.

## Scope

### In scope

- Canonical project-guidance persistence, shared ports, the transaction runner port, the application service with authorization, and the system-prompt projection.
- Package placement rules and their dependency-cruiser tests.

### Out of scope

- `AiGatewayClientPort`, `packages/ai-gateway-client`, and the gateway `POST /internal/complete` route with its budget/attribution rules; #215 delivers these.
- The `core.agentGuidanceDrift` action, the concrete drift-heartbeat store with its unique index/backfill, findings, fingerprints, notification payload/kinds/`createNotification`, and the two-phase comparison flow; #85 delivers these.
- `owner_process` or heartbeat-action registration drift, owned by #29.
- Editing AGENT guidance automatically.
- Any REST endpoint for guidance.

## Acceptance criteria

- `loadProjectAgentGuidance` is the only hand-written guidance projection used by the system prompt; generated AGENT.md content is never appended as guidance, and the guidance markdown appears verbatim under `## Project-specific guidance`.
- Guidance create/update/transfer authorization and all failure responses match the exact service contracts above.
- Dependency tests prove agent-runtime has no database import and that `packages/application` imports neither `services/*` nor `packages/agent-runtime`; the data store uses the supplied transaction and each service mutation commits guidance plus the heartbeat upsert call atomically through the injected `GuidanceHeartbeatStore`.
- The concrete `TransactionRunner<PoolClient>` opens transactions at the requested isolation level.
- A project item outside the system Projects database, a missing user, or blank markdown is rejected with the exact codes and payloads above.
