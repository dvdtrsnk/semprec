## Context

Review follow-ups from harvest issue #889. After `chokePoint.ts` was split into per-area modules, four doc comments kept wording that was only true before the split:
- PR #537 (finding f413af582d), `backend/packages/data/src/chokePoint/databaseOps.ts:18`: the JSDoc on `databaseArchiveWithClient` says it is "kept alongside the other four `*WithClient` exports", but the five destructive `*WithClient` functions now live in five different files (`databaseOps.ts`, `viewOps.ts`, `propertyOps.ts`, `itemTrash.ts`, `relationOps.ts`).
- PR #542 (finding 714b990c5e), `backend/packages/data/src/chokePoint/databaseGuards.ts:12`: the JSDoc on `assertDatabaseNotArchived` says "Used directly by every mutation below", but the file holds only this function. The same JSDoc names `assertDatabaseWritableForCreate` without saying where it is, but that function lives in `itemWrites.ts`, not in this file.
- PR #544 (finding 2529f09845), `backend/packages/data/src/chokePoint/computedKeyRegistry.ts:21`: the JSDoc on `assertNoComputedKeyCollision` says "see computedKeyRegistry.ts", which is the file it is in.
- PR #551 (finding a54c723e71), `backend/packages/data/src/chokePoint/relationEdgeContext.ts:23`: the JSDoc on `SystemRelationWriteContext` says "see `assertRelationSideCreatable`/`assertRelationPropertyWritable` below", but `assertRelationSideCreatable` lives in `relationPropertyOps.ts`.

## Task

Edit exactly these four doc comments as follows, changing no code:
1. `databaseOps.ts` `databaseArchiveWithClient` JSDoc: replace "kept alongside the other four `*WithClient` exports" with wording that says it is one of the five approval-gated destructive `*WithClient` exports, one per operation, each exported from its own operation module (`databaseOps.ts`, `viewOps.ts`, `propertyOps.ts`, `itemTrash.ts`, `relationOps.ts`).
2. `databaseGuards.ts` `assertDatabaseNotArchived` JSDoc: replace "Used directly by every mutation below" with "Used directly by every item and relation mutation", keeping the rest of the sentence, and where that sentence names `assertDatabaseWritableForCreate`, add "(in `itemWrites.ts`)" after it, since that function lives in `itemWrites.ts`, not in this file.
3. `computedKeyRegistry.ts` `assertNoComputedKeyCollision` JSDoc: drop the self-referential "see computedKeyRegistry.ts" and instead point to the `ComputedKeyRegistry` type declared above it in the same file.
4. `relationEdgeContext.ts` `SystemRelationWriteContext` JSDoc: replace the "below" cross-reference so it names `assertRelationSideCreatable` in `relationPropertyOps.ts` and `assertRelationPropertyWritable` in this file, without the word "below" for the former.
