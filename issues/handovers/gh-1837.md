## What was delivered

`GET /api/overview` (tenant scoped, not public, read only) answers the Overview screen with one body and no counting logic of its own; every number comes from the function of its owner.

- `inboxPending`: `countOpenInboxCards` (the function behind `GET /api/inbox/cards/count`) for the session user.
- `mailUnread`: `getMailSummary(...).unreadInbox`.
- `tasksToday`: `countTasksToday` (open tasks of the Today list only).
- `problemCount`: `getSempStatusSummary(...).activeCount`.
- `collections`: `{ databaseId, ownerModuleId, itemCount }` per client-visible system database that has an owning module, from one `countItemsBatch` call with `collection: true`; the Projects entry is counted with the gh-1760 active-project filter.
- `areas`: `{ id, activeProjectCount }` per non-null group of the Projects count grouped by area with `ACTIVE_PROJECTS_FILTER`; an area without an active project has no entry.
- `journalTodayItemId`: id of the live Journal day item whose period key is today's date in the tenant time zone (`getSystemTimezone`, `computeJournalPeriodKey`), looked up through `findJournalPeriodEntries`; `null` when it does not exist. The route never creates it and a trashed day item is not returned.

## Deviations and spec seams

1. `getOverviewSummary` takes `{ ownerUserId, now? }` as a second argument: the Inbox count needs the session user (pending approvals), which the owner route reads from the session. No request input is read.
2. Three owner functions were exported with the keyword only (see above), outside Touches.
3. The route entry lives in a new slice `routeMatrix/overview.ts`, appended in `routeMatrix.ts`, following the sibling slices.
4. `collections` lists system databases with an owning module that are client-visible (so `ownerModuleId` is always a string); user-created databases are not listed. `areas` has no entry for an area without an active project.
5. A tenant whose Journal or Projects database is missing makes the summary throw, as `countTasksToday` does for Tasks.
6. The summary reads in several transactions, so two numbers may be read at slightly different moments (documented in the docstring).
7. The tests assert the exact `problemCount` of a fresh tenant (it includes the missing AI budget problem) instead of giving the tenant a budget row.
8. The commit trailer of the candidate names Claude Sonnet 5.5 instead of the line the task text names.
