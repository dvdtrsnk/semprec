## Summary

New blobs are now stored under a `<tenantId>/` storage-key prefix, and content-hash dedupe now works per tenant without relying on the legacy global index (#1008).

### Changes
- **`tenantBlobStorageKey(client, key)`** (`blobsStore.ts`): runs `SELECT app_tenant_default()::text AS tenant_id` and reads it as a typed row. That is the same function that fills `blobs.tenant_id`, so a key's prefix always matches its row's tenant. It returns `<tenantId>/<key>`, or throws a plain `Error` when no tenant is in scope. It is added to the runtime export list in `publicSurface.test.ts`.
- **Writers:**
  - `ingestUploadedFile` resolves the key before streaming, so a missing tenant fails before any byte is written.
  - `ingestAttachments` resolves the key on its transaction client.
  - The transcription prepare step resolves the normalized-audio key inside its snapshot transaction and passes it to `normalizeAudio`.
- **Dedupe:** `findOrCreateBlob` keeps its bare `ON CONFLICT DO NOTHING`. I rewrote its inline comment and the docstrings of `findOrCreateBlob` and `getBlobByContentHash`: dedupe is per tenant, every unique index on `blobs` acts as an arbiter, and RLS limits the read-back to the tenant in scope. There are no hand-written `tenant_id` predicates.
- **`transcriptionTask.test.ts`:** the key assertions, the `readNormalizedLeftovers` lookup and directory read, the mid-normalization hook, and the concurrent-run fixture now all use `<tenantId>/transcriptions/`.

### New tests (`blobsPerTenant.test.ts`)
- An upload with `storageKeyPrefix: "files"` gets a key starting `<tenant zero>/files/`, and its bytes are written under exactly that key.
- When `app_tenant_default()` returns `NULL` (a proxied pool), the upload is rejected before any `writeStream` call.
- A mail attachment's blob key starts with `<tenant>/<mailboxItemId>/`.
- These run in rolled-back transactions on the owner pool, as `semprec_data`, with a second tenant and `blobs_content_hash_uq` dropped:
  - `tenantBlobStorageKey` returns `<B>/files/x` with tenant B in scope, and rejects when `app.tenant_id` is empty.
  - Within one tenant, the same hash returns the same row without the legacy index.
  - Across two tenants, the same hash gives two rows, each with its own `tenant_id` and key prefix. `getBlobByContentHash` returns only that tenant's own row.
- A legacy blob with an unprefixed key is still returned by `getBlob`, and `LocalFsBlobStorageWriter.readStream` reads its bytes.

`fileUploadStore.test.ts`, `mailSync.test.ts`, `filesAndBlobsHandler.test.ts` and `transcriptionTask.test.ts` pass with no changes beyond the updated transcription prefixes listed above.
