# gh-1513 — [account 09/15] Collect the display name at setup and invitation acceptance

Repository-Issue: gh-1513

Implementation commit: `b160c0c3` (`feat(auth): collect an optional display name at setup and invitation acceptance (gh-1513)`). No migration: the `users.display_name` column comes from gh-1387 (migration 0124).

## Delivered behavior

- `normalizeDisplayName(value: unknown): string | null` in `backend/packages/data/src/auth/displayName.ts`, with the exported constant `DISPLAY_NAME_MAX_LENGTH = 80`. It is exported from the data barrel (`index.ts`). The constant stays out of the barrel, so it is not on the frozen public surface.
  - An absent or `null` value gives `null`.
  - A string is trimmed. The trimmed value must be 1 to 80 code points, must not be blank, and must not contain a NUL character. Anything else throws `ValidationError` with `details: { field: 'displayName' }`.
  - The NUL refusal is not in the Task. Postgres `text` cannot store NUL, so without it a name such as `"Da\u0000vid"` would pass the validator and fail the insert as an internal error, not a 400.
- `CreateUserInput.displayName?: string` (`auth/usersStore.ts`) is written to `users.display_name` in `createUser`. Omitted gives the column default, NULL.
- `POST /api/setup` (`services/semprec-api/src/setupHandler.ts`) validates `displayName` after the email and password checks and before `runAsSystem` and `bootstrapFirstAccount`. It passes the result through `BootstrapFirstAccountInput.displayName` and `createAccount`.
- Invitation acceptance (`tenancy/acceptInvitation.ts`, `AcceptInvitationInput.displayName?: unknown`):
  - `acceptInvitation` validates the name after the password check and before `findUsableInvite`. A refused name therefore never reaches the lookup, the transaction or the token consumption.
  - The validated name goes to `createInvitedUser`, and from there to `createUser`, in the same transaction that creates the tenant and marks the invitation accepted.
  - `invitationHandler.ts` (`parseAcceptBody`) passes the raw `displayName` through, untouched, to the store, which is the single validation point. A validation failure releases the throttle reservation, as the handler already does for every non-`NotFoundError` failure.
- Account export (`tenancy/tenantExportJob.ts`, `accountEntry`): `account.json` is `{ email, displayName, locale, role, createdAt }`, with `displayName` `null` when unset. The export `formatVersion` stays 1, because the change is additive.

## Notes for dependants

- **Raw-SQL fixtures remain.** `backend/packages/data/src/__tests__/authActions.test.ts` and `backend/services/semprec-api/src/__tests__/authHandler.test.ts` (both from gh-1387) still set `display_name` with a direct `UPDATE`. They are outside this issue's Touches, so they are unchanged. Now that a production write path exists, they can switch to `createUser` with `displayName`.
- **Export format document.** `docs/adr/2026-10-17-tenant-data-export-archive.md` still lists `account.json` as `{ email, locale, role, createdAt }`. Its body is frozen as an accepted ADR, so it is not edited here. The field is additive and `formatVersion` stays 1. If the archive format is to be documented as versioned, that needs a new ADR.
- **Web client.** `web/src/api/invitationOperations.ts` still sends only `{ token, password }`, and the Task does not change the web client. The name can be set through the API only, for now.
- **Setup ordering.** Setup validates `displayName` before the token and the bootstrap check, as it already does for `email` and `password`. A malformed name gets 400 whether or not setup is open, so the response reveals nothing about setup state. A well-formed body after bootstrap still gets 404.
- **Invitation ordering.** `acceptInvitation` validates the name before the lookup, as it does the password. A malformed name gets 400 for any token, so the status does not distinguish usable from unusable tokens.
- **Out of scope, not built:** editing the name after creation, and showing it in the administrator account list. The column and the read paths are gh-1387's.
