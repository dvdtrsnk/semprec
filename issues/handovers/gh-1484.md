# gh-1484 — OAuth authorization code exchange with PKCE

Repository-Issue: gh-1484

## Delivered behavior and production wiring

- `mail/oauthTokenExchange.ts`: `exchangeAuthorizationCode({ tokenUrl, clientId, clientSecret, redirectUri, code, codeVerifier })` POSTs the `authorization_code` grant form (with `code_verifier`, 15 second timeout) and returns `{ accessToken, expiresAt, refreshToken }`. It throws a plain `Error` when `access_token`, numeric `expires_in` or a non-empty `refresh_token` is missing. `refreshAccessToken` is unchanged.
- `mail/providerTypes.ts`: new `MailAuthorizationCodeRejectedError` (400/401) and `MailAdminConsentRequiredError` (400/401 with `error=consent_required`, or `invalid_grant` whose description names AADSTS65001/AADSTS90094). Both carry `providerError` (the provider's short `error` code, or `null` when it is not a plain lowercase token). The two classes are independent: an admin-consent failure is not an instance of the rejected error.
- Messages contain only the status and the provider error code; the response body and description are never copied. Other statuses throw `OAuth code exchange failed with status N`.
- Not wired anywhere yet: #1686 calls it outside its database transaction, maps `MailAdminConsentRequiredError` to `mail_admin_consent_required`, and stores the refresh token. Not exported from the `@semprec/data` barrel.
