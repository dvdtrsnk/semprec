# Handover for gh-1610

Added the atomic multi-block operations to `@semprec/block-model` (`shared/block-model/`), next to the single-block write primitive of gh-1539. No database access, no new dependency.

**What changed**
- `shared/block-model/src/blockOperations.ts` (exported from `src/index.ts`): `insertBlocks`, `splitBlock`, `mergeBlocks`, `moveBlocks`, `setType`, `setIndent`, `duplicateBlocks`, `deleteBlocks`, the `BlockOperationError` class with a typed `code`, and `NewBlockInput` (a `BlockInput` whose `id` is optional).
- Every function takes `(doc, ..., origin?)`, validates against the current normalized state first (a refusal changes nothing), then does all its changes in one `doc.transact(fn, origin)`.
- Inside that transaction `order` is tidied: repeated ids keep the first occurrence, ids without a block are dropped, blocks missing from `order` are appended in ascending id order (the order readers already see).

**Tests**
- `shared/block-model/src/__tests__/blockOperations.test.ts`: concurrent insert after the same block, concurrent move leaving a duplicate id that reads once and is removed entirely by `deleteBlocks`, move of three non-adjacent blocks, delete-all leaving one empty text block, merge refusals with an unchanged state vector, `todo` to `text`, indent clamping, split keeping bold, duplicate, and order tidying.
- Run with `./node_modules/.bin/vitest run` in `shared/block-model/` (or `pnpm --filter @semprec/block-model run test` in `backend/`).

**Notes for dependants**
- Error codes (`BlockOperationError.code`): `block_not_found`, `invalid_after_id`, `duplicate_block_id`, `offset_out_of_range`, `invalid_delta`, `no_previous_block`, `page_block_not_splittable`, `page_block_not_mergeable`, `page_conversion_required`. Invalid block content in `insertBlocks` throws `BlockInputError` from gh-1539. Mapping to HTTP is the caller's job.
- `page_conversion_required` is thrown by `setType` (source or target `page`) and `duplicateBlocks`. `splitBlock` on a page uses `page_block_not_splittable` (the issue named no code). `deleteBlocks` and `moveBlocks` accept page blocks; trashing pages on delete is gh-1723.
- Unknown ids raise `block_not_found` in every operation (also in `deleteBlocks`); an empty `ids` list is a no-op. `afterId` that is unknown, or among the moved ids, raises `invalid_after_id`; a document with no real blocks accepts only `afterId = null`.
- `insertBlocks`, `splitBlock` and `duplicateBlocks` return the new ids; ids are generated with the global `crypto.randomUUID()`.
- `duplicateBlocks` keeps `done` and `indent` of the source. `setType` sets `done` false even when the type does not change and deletes `done` for non-todo targets.
- Only targeted checks were run (the package tests and `tsc --noEmit`); no full verify. No `@semprec/data` barrel change was needed because the module lives in `@semprec/block-model`.
