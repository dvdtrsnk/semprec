## What was delivered

An approval step of `GET /api/agent-runs/:id/steps` carries `approvalState` (`pending`, `executing`, `executed`, `failed`, `conflict`, `rejected`) and, for a conflict, `conflictReason` (an `approval.conflict.*` key), computed at read time from the approval request row. Nothing is written to the run, so the same step reads as pending, executing and executed as its request moves on.

- `listApprovalRequestStatesByIds` (`mcp/approvalRequestsStore.ts`) reads the requests of a page in one batched query selecting id, status, execution_status and execution_result_jsonb, no payload. It is deliberately not exported from the data barrel.
- `approvalStepState` (in `agentRunStepPages.ts`) maps request status, execution status and result to the state; the failed-versus-conflict split uses `approvalConflictReason` from gh-1437 (`approval.outcome.failed` only for outcomeKind `callFailed`).
- Step state: `waitingApproval` while pending, `error` for failed and conflict, `ok` otherwise. A request that cannot be read (missing, other tenant, non-uuid id) leaves the step with its call's state and no `approvalState`; the page is still returned.
- Review fix: `recordApprovalRequestOutcome` is now exported from `@semprec/data` (and listed in the frozen list of `publicSurface.test.ts`) so the API test writes the failed outcome through the production write.

## Deviations and spec seams

1. `approvalState` and `conflictReason` are omitted from the JSON when absent, following the Task wording "approvalState absent".
2. The decision wins over the execution status: a rejected request marked `legacy_terminal` by the execution-protocol cutover reads `rejected`, not `conflict`; a pending request is `pending` whatever its execution status.
3. An approved request with execution_status `not_approved` (no real row) gives no `approvalState`.
4. `listApprovalRequestStatesByIds` is new (no batched read existed) and not exported from the barrel, because only the projection in the same package uses it.
5. "Cannot be read" means not found, other tenant or a non-uuid id; a row with a corrupt status value still throws (`assertKnownValue`) rather than being swallowed.
6. The step summary of an approval step keeps "Approval requested" and is computed from the call's own state, not the derived one.
