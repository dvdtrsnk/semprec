## What was delivered

- An item ref to an `Emails` item with a `mail_drafts` row expands into the turn context as the draft (id, subject, from, recipients, mode, thread id, last editor, sent state, body) plus the instruction to change it with `mail.draft.update`. A sent draft says it can no longer be changed; a trashed draft and a message without a draft row keep the generic expansion. The read writes nothing.
- The body is budgeted so the 8000-character per-ref cap never cuts it silently (fix round): `readMailDraftRefDetails` cuts the body at 5000 code points and within a serialized budget of 7200 UTF-16 units (escapes counted, never splitting a surrogate pair), sets `bodyTruncated` and an instruction not to rewrite a draft from cut text, puts `body` and `bodyTruncated` before the recipient lists, and caps the recipient lists at 2000 units shared (`recipientsOmitted` counts the rest). The instruction also tells the agent to read a trailing `[truncated]` (a turn-share cut with many refs) as a cut body.
- While `mail.draft.update` runs in a run that belongs to a Semp thread, it publishes an ephemeral `agent:delta` payload `{ kind: "mailDraftBody", draftId, body }` after the draft is confirmed open and unsent and before the durable update is written, through a new data hook that `wireRealtimeHooks` connects to `publishAgentRunDelta` (existing chunking, tenant envelope, run-owner watch scoping). A refused update (sent, discarded, no draft row, foreign draft, invalid arguments, now also a blank subject) publishes nothing; a delta that cannot be published is logged with the run id only and does not fail the update.

## Deviations from the specification and spec seams

1. The "extension point of #1733" is the ref-kind chain of `readSempRefContext`, not a registry; the mail expansion is called from its Emails branch. `refExpansion.ts` in `semprec-agents` is unchanged.
2. `packages/data` cannot import `@semprec/realtime`, so the tool publishes through the new data hook; `MailDraftBodyDelta` is defined in `protocolV1.ts` and the tool builds a literal of the same shape (the hook event carries `delta: unknown`); the end-to-end test asserts the exact frame.
3. "A run started from a chat turn" is implemented as a run that has a Semp thread id; an MCP run has none and publishes no frames.
4. Beyond the Task: the body cut and `bodyTruncated` (extended by the fix round into the serialized budget above) and the blank-subject refusal.
5. Chat runs belong to the Semprec project, which in the current tree owns no mail databases and so holds no `mail.draft` capability; the criterion that the run's `mail.draft.update` changes the same draft is proven with a fixture that transfers the mail databases to the Semprec project. Composing grants into chat sessions is not part of this Task and was not changed.
6. No ADR: the hook follows the existing per-process realtime hook pattern.

## Criteria NOT RUN or BLOCKED

None. The chat-session capability in deviation 5 is proven only with the fixture grant; whether a production chat session holds the mail capabilities is outside this source.
