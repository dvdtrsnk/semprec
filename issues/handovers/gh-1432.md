# gh-1432 — validate Inbox capture fields and link the Journal day in a create hook

Repository-Issue: gh-1432

## Delivered behavior

- `backend/packages/data/src/inbox/inboxCreateHook.ts` (new): `inboxItemCreateHook`, an `ItemCreateHook`. For a database whose `ownerModuleId` is `inbox`, it requires `date` to be a real calendar date written `YYYY-MM-DD`, and `time` to be `HH:mm` on a 24-hour clock from `00:00` to `23:59`. A missing or malformed value throws `ValidationError` (HTTP 400, code `validation_failed`, `details.field` set to `date` or `time`). `date` is checked first. Then the hook resolves the system timezone (`getSystemTimezone`), the Journal database by module id and the item's `journalDay` property, gets or creates the day with `getOrCreateJournalItem`, writes the system-owned `journalDay` edge under the Inbox relation context, and calls `enqueueJournalInboxRecompute`.
- `backend/packages/data/src/domainWriteHooks.ts`: registers the hook with `registerItemCreateHook`, after the Journal hook.
- `backend/packages/data/src/inbox/inboxStore.ts`: `createInboxItemWithClient` keeps only the optional `type` edge. Its `journalDatabaseId` and `timezone` inputs are removed. It still passes `date` and `time` through verbatim, but no longer validates them.
- Every Inbox item create is covered by this one hook: the generic `POST /api/databases/:id/items`, the application gateway used by agents and `/mcp` (`item.create`), and any `createItemWithClient` caller. No seed writes an Inbox item.
- No migration, no schema change and no new error code.

## Behavior notes

- The hook runs after the real insert, inside the create transaction. A refusal rolls back the row and its idempotency reservation.
- The hook does not run on an idempotency replay, so a replayed create keeps the one `journalDay` edge it already has.
- The day key is the date itself. `period` is the calendar date in the system timezone, and midnight of that date yields the same key in any zone. The timezone changes only the reference instant, so no test can observe a different day from a different zone.
- Only creates are checked. Editing `date` or `time` of an existing Inbox item neither re-validates nor re-links it (out of scope).
- The helper still writes the `type` edge after the hook. On an idempotency replay the helper runs that edge write again, as it did before this change. No test here covers that path.

## Tests

- `backend/packages/data/src/__tests__/inboxCreateHook.test.ts` (new, real Postgres, 13 cases): a generic create with a valid date and time gets one `journalDay` edge to the day of that date and queues that day's recompute. Seven refused inputs (a missing date, `abc`, `2026-W35`, `2026-02-30`, a missing time, `24:00`, `abc`) are each refused on the named field, with no Inbox item and no Journal item left behind. An idempotent replay keeps one item and one edge. An agent-tool writer and a `/mcp` writer each link a valid create and refuse a missing date. A create in Projects is not checked and creates no Journal item. An Inbox-owned write into a database with no `journalDay` property is refused with `NotFoundError`.
- Not covered: the not-found branch for the seeded Journal module. Reaching it means removing the seeded Journal database.
- Existing callers were moved to the reduced helper signature in 15 test files. `inboxTick.test.ts`'s local wrapper no longer takes a Journal id.

## Notes for dependants

- The capture route (#1961) calls `createInboxItemWithClient` with `inboxDatabaseId`, `date`, `time`, and optionally `text`, `type`, `idempotencyKey` and `queueAffinity`. It must not pass `journalDatabaseId` or `timezone`. A missing or malformed `date` or `time` now comes back from inside the transaction as the hook's `ValidationError`, not from a check before the insert.
- The trashed-day relink (#1603) can rely on a `journalDay` edge existing for every Inbox item created through the choke point.
