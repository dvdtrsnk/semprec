# Handover for gh-1405

Documents now record when and by whom they were last edited. Checked in `backend/`: `docs.test.ts` (43 tests) passes, and lint, format check, build and `check-migration-numbering` pass. The full `pnpm run verify` was not run, as instructed. `web/` is untouched.

**What changed**
- **Migration `0088_docs_last_edited.sql`:** adds nullable `docs.last_edited_at timestamptz` and `docs.last_edited_by text` with `CHECK (last_edited_by IN ('user', 'ai_agent', 'system'))`. There is no backfill. The existing table-level row-level security policies and grants cover the new columns, so none were changed.
- **`appendDocUpdateWithClient`:** in the same transaction as the `doc_updates` insert, it runs `UPDATE docs SET last_edited_at = <inserted created_at>, last_edited_by = <createdBy>`. It checks the affected-row count with `requireAffectedRows`. This covers `mutateDocWithClient`, `mutateDoc` and the WebSocket path, which calls `mutateYDoc` (`mutateDoc`).
- **`DocRow`:** gains `lastEditedAt` (ISO string; equals `createdAt` when the column is NULL) and `lastEditedBy` (`CreatedBy | null`, validated with `assertKnownValue`). `docsStore.ts` selects the columns in every read and in the `getOrCreateDoc` insert.

**Tests** (in `docs.test.ts`, "last edited tracking")
- A `user` write sets `last_edited_by = 'user'` and `last_edited_at` equal to the `doc_updates` row's `created_at`.
- An `ai_agent` write sets `'ai_agent'`.
- A sync-style `mutateDoc` update with origin `user` moves `last_edited_at` forward.
- A no-op mutation leaves both columns unchanged.
- A doc with NULL columns reads `lastEditedAt === createdAt` and `lastEditedBy === null`; a `system` write then reads `'system'`.
