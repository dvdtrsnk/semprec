# gh-1461 — [mail-threads 03/28] Keep drafts and sent mail out of unread counts

Repository-Issue: gh-1461

This completion is proposed on an isolated implementation branch; it becomes canonical only after reviewed integration. No PR has been published by this worker.

## Delivered behavior

- **Draft** (`mail/draft.ts`, `createEmailDraft`): the Emails item is created with `read: true`. Sending (`mail/send.ts`) keeps the same item, so it stays read.
- **Unread search** (`mail/search.ts`, `searchItems`): `is:unread` also requires that the message has no folder edge to an item whose `specialPurpose` is `drafts` or `sent`. The folder must belong to the tenant's Folders database (`databases.owner_module_id = 'folders'`). `is:read` is unchanged.
- **Unscoped unread filter** (`web/src/views/mailbox/config.ts`, `unreadOutsideDraftsAndSentFilter`): for a list of folders, one `not_equals read true` node plus one `relation_not_contains` node per Drafts or Sent folder in the list. `unreadFilter` (folder-scoped) is unchanged.
- **Backfill** (`mail/mailDraftsAndSentReadBackfill.ts`, `runMailDraftsAndSentReadBackfill`): keyset pages of 200 items, one transaction per page. Each page selects Emails items that are not read and have a Drafts or Sent folder edge, locked `FOR UPDATE OF i`, and writes `read: true` through `convergeObservedEmailFlagsWithClient`. No `mail_message_flag_sync_state` row is written. A tenant without an Emails or Folders database is skipped.
- **Wiring** (`db/tenantCutoverMigrations.ts`): the backfill runs once per maintained tenant, last in `runTenantCutoverMigrations`.
- **Shared constant** (`mail/messageFlags.ts`, `DRAFTS_AND_SENT_SPECIAL_PURPOSES = ["drafts", "sent"]`): used by the search, the backfill and the web helper's comment.
- **No migration.** The change is a draft default, a search condition, a web helper and a per-tenant data cutover.

## Deviations and conflicts

1. **Web item has no unscoped call site at the tip.** The Task asks for the exclusion in the unread filter "for views that are not scoped to a single folder". At `cc9633b2`, `unreadFilter` is the only unread filter in `web/src`, and it is always folder-scoped. Per the Task, that filter is unchanged. I added `unreadOutsideDraftsAndSentFilter` as the unscoped form. It has no caller yet, so the reviewer should decide whether it is kept for #1633 or #1688, or dropped.
2. **`searchItems` has no production caller at the tip.** Only tests call it. The `is:unread` exclusion is correct for any caller, but no product path uses it yet.
3. **Drafts are not indexed by `createEmailDraft`.** `draft.ts` does not write an `item_search_index` row, so a draft is returned by search only after something indexes it. The tests index the draft explicitly, so that the `is:unread` assertion can fail for the right reason.
4. **Backfill side effects.** The write goes through the normal update path, so the update heartbeats and the change invalidation fire for each item it changes, as they do for mail sync convergence. Only the flag-sync write-back is skipped.
5. **Send path not run.** `sendDraftEmail` needs SMTP adapters, so the test mirrors its folder move (Drafts out, Sent in) with the production relation writers instead of calling it.
6. **Czech Hunspell assets are missing in the local embedded Postgres.** The existing warning appears in test output. The assertions use the fallback text configuration and do not depend on it.

## Notes for dependants

- **#1633 (unread filter in the thread list) and #1688 (mail count summaries)**: they can use `unreadOutsideDraftsAndSentFilter` (web) and the `is:unread` rule in `searchItems` (backend). They should not re-implement the Drafts and Sent exclusion. `DRAFTS_AND_SENT_SPECIAL_PURPOSES` is the single list.
- **Folder-scoped unread counts are unchanged.** A Sent or Drafts folder's own unread count still counts messages with no `read` property, such as a Sent message synced from the provider that was never read. Only the unscoped views and `is:unread` leave those folders out.
- **Backfill is one-time per tenant but idempotent.** A second run selects nothing, so later deploys do not touch read state again.
