## Summary

Implements issue #705: production Inbox ticks now serialize on a dedicated `semprec-tick` graphile-worker queue, and per-process job concurrency is raised from graphile-worker's implicit default of 1.

**Changes:**
1. **`backend/packages/data/src/inbox/inboxTickKeys.ts`** (new) — leaf module holding `SEMPREC_TICK_ACTION_ID`/`SEMPREC_TICK_QUEUE_NAME`, breaking the value-import cycle that otherwise blocked `scheduler/actions.ts` from importing them. `inboxTickAction.ts` now re-exports both.
2. **`scheduler/actions.ts`** — `createActionQueueAffinity()` is now the production routing table: `new Map([[SEMPREC_TICK_ACTION_ID, SEMPREC_TICK_QUEUE_NAME]])` instead of an empty map.
3. **`scheduler/schedulerStore.ts`** — `triggerOnItemEventHeartbeats`'s default `queueAffinity` parameter now uses `createActionQueueAffinity()` instead of `new Map()`, so direct-write paths that pass no map also route ticks correctly.
4. **`backend/packages/queue/src/index.ts`** — added `QUEUE_CONCURRENCY_DEFAULT = 4` and `resolveQueueConcurrency(env)`; `runWorker` now defaults `concurrency` (graphile-worker's actual option name — the issue text said `concurrentJobs`, which doesn't exist on `RunnerOptions`/`WorkerPoolOptions` in the installed graphile-worker version, so I used the real field) from it, with an explicit caller-supplied value still winning.
5. **`semprec-transcribe/src/queueRuntime.ts`** — passes `concurrency: 1` explicitly (CPU/disk-bound ffmpeg/ASR pipeline).
6. **`deploy/shared/.env.example`** — documents `QUEUE_CONCURRENCY=4` in the existing Listeners section.
7. Tests: new unit tests for `resolveQueueConcurrency`, a new real-Postgres integration test proving `semprec-tick` jobs serialize while unaffinitized jobs run concurrently, and `inboxTick.test.ts` updated (inverted the "no affinity" case, added a case covering `createChokePoint`'s production defaults for update/delete).
