## Summary

Implements module-contract issue #110: deriving the desired set of active module worker instances and reconciling them through an injected supervisor port.

- Added `backend/packages/data/src/moduleWorkers.ts`:
  - `deriveDesiredWorkerInstances(moduleRegistry, getActiveRowIds)` derives a deterministic map of desired worker instance identities from `ModuleRegistry.getWorkers()` plus a caller-injected `WorkerActiveRowIdsSource`. Each worker yields either a singleton instance (`<workerName>`) or one instance per active row (`<workerName>@<rowId>`, e.g. `semprec-mailsync@<mailboxId>`), with validation against blank or duplicate row ids.
  - `createModuleWorkerInstanceReconciler(moduleRegistry, getActiveRowIds, supervisor)` diffs the freshly derived desired set against previously hosted instance ids and emits `start`/`stop` calls only for what changed — order-independent and idempotent.
  - `WorkerSupervisorPort` is the only integration point for actually hosting a process; this layer stays free of systemd and queue Runner ownership, per the issue's scope.
- Exported the new API from `backend/packages/data/src/index.ts`.
- Added 12 unit tests in `backend/packages/data/src/__tests__/moduleWorkers.test.ts` covering singleton vs. per-row derivation, inactive-module exclusion, blank/duplicate row-id rejection, and reconciler add/remove/idempotency/deactivation behavior.
