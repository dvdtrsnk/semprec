# Handover for gh-1534

Added the numeric filter conditions `lt`, `lte`, `gt` and `gte` with shape `{ type, property, value: number }`.

- **Schemas:** the four types are in `FILTER_CONDITION_TYPES`, `FilterCondition` and the zod schema of both `views/filterTree.ts` and `shared/genericOperations/filterSort.ts`. `value` is `z.number().finite()`, so a string, null, `NaN` or `Infinity` fails with a 400 on `filter`.
- **Compiler:** `filterCompiler.ts` accepts them for `number` properties and for numeric rollups (read from `computed`); any other type throws `ValidationError` with the property as `field`. The SQL is `CASE WHEN jsonb_typeof(col -> $key) = 'number' THEN (col ->> $key)::numeric <op> $N::numeric ELSE false END`. A `CASE` is used rather than `AND` because Postgres does not guarantee `AND` evaluation order, so a stored non-number cannot reach the cast. A missing or non-number value is `false`, so `not` of the condition matches those items.
- **Numeric rollups:** `FilterProperty` has a new optional `numericRollup`, set by `buildFilterProperties` from `sortKeyCast(property) === "::numeric"` (the same decision as sorting: any aggregation but `earliest`/`latest`).
- **Tests:** `shared/.../filterSort.unit.test.ts` (schema accepts finite numbers, rejects the rest) and `data/src/__tests__/numericFilter.test.ts` (database-backed, run and passing: `prepMinutes lte 30`, `rating gte 4`, stored non-number, 400s for value, date and text properties, numeric sum rollup and a rejected `latest` rollup). Targeted tsc, eslint and prettier pass.
- **Notes for dependants:** no new package exports, so `publicSurface` is unchanged. Facets (#1759) and manifest quick filters (#1647) can reuse the conditions through `compileFilterNode` unchanged; the optional `context` argument is not needed by these conditions.
