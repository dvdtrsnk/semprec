## What was delivered

- `POST /api/mail/mailboxes/oauth/start` (mail module custom route `mailOauthStart`, justification `transactional-semantics`). Body `{ provider: "gmail" | "outlook" }`, strict. It stores a new-account one-time state (gh-1483, no mailbox id) for the calling user and answers 200 `{ authorizeUrl }` and nothing else. The URL carries `response_type=code`, the client id, the redirect URI, the scopes, the state and the S256 code challenge. Google: `gmail.modify` and `gmail.send`, with `access_type=offline` and `prompt=consent`. Microsoft through `/common`: `Mail.ReadWrite`, `Mail.Send`, `offline_access`, `User.Read`.
- `GET /api/mail/oauth/callback`, public, dispatched by hand in `backend/services/semprec-api/src/app.ts` for GET only. It takes no pool, reads no cookie and no `Authorization` header, writes nothing and logs nothing. It answers 200 `{ state, code }`, or 200 `{ state, providerError }` when the provider reported an error such as a cancelled consent, with `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`. A missing or malformed `state`, a malformed `error`, or neither an `error` nor a bounded `code` answers 400 `validation_failed`.
- `POST /api/mail/mailboxes/oauth/complete` (custom route `mailOauthComplete`, justification `transactional-semantics`). Body `{ state, code }`, strict. In this order:
  1. One transaction consumes the state for the calling user and commits. An unknown, used or expired state and a state of another user or tenant answer the same 400 `validation_failed` with `details.field` `state`. A state that carries a mailbox id (reauthorization) is consumed and answers 400 as well, until #1742 adds that branch.
  2. Outside any transaction the code is exchanged (gh-1484) and the provider is asked for the account's own address and aliases: Gmail `users.getProfile` and `settings.sendAs`; Graph `GET /me?$select=mail,userPrincipalName,proxyAddresses`, where the SMTP entries of `proxyAddresses` become the aliases. Each lookup has a 15 s timeout and a 1 MiB cap; at most 100 aliases are kept.
  3. One transaction creates the Mailboxes item (name `Gmail` or `Outlook`, `provider`), writes its addresses through `writeMailboxAddresses` (gh-1454), stores the refresh token as `oauth2_refresh_token` with `storeCredential`, creates the sync state (`gmail_api` or `graph_api`) with `provider_account_address`, and for Gmail `gmail_watch_email_address`, and calls `enqueueMailAccountSync`. It answers 201 `{ mailboxId }`.
- Duplicate address: the partial unique index `mail_account_sync_state_tenant_provider_address_uq` decides it inside the write transaction, which rolls back whole. The route answers 409 `provider_account_already_connected` with `details.mailboxId`, read in a further transaction.
- Provider failures: a Microsoft tenant that needs administrator approval answers 400 `mail_admin_consent_required`, a new entry of `ITEM_ERROR_CODES` and `ITEM_ERROR_STATUS_BY_CODE`. A code the token endpoint refuses as `invalid_grant` answers 400 `validation_failed` with `details.field` `code`. Every other failure, a refusal of the OAuth client itself (`invalid_client`) included, propagates, so the adapter logs it and answers a generic 500. Nothing is created in any of these cases and the state stays consumed.
- The new ADR `docs/adr/2026-11-10-mailbox-oauth-connect-consumes-its-state-before-the-provider-call.md` records how the complete route departs from the bracket ADR the Task names (the state is consumed and committed before the provider call, both transactions run at READ COMMITTED, nothing is re-validated because the unique index decides the duplicate) and the handoff that makes the connect flow a second writer of `gmail_watch_email_address`.

## Contracts dependents build on

- Exports added to `@semprec/data` (`backend/packages/data/src/index.ts`) and to the mail module manifest: `createMailOauthStartRouteHandler(pool, dependencies)` and `createMailOauthCompleteRouteHandler(pool, dependencies)`. Both are in the expected list of `publicSurface.test.ts`.
- `dependencies` is `MailOauthRouteDependencies` (exported from `mail/mailOauthRouteHandlers.ts`, not from the barrel): `{ oauth?: { gmail?, msGraph?, redirectBaseUrl? }, outboundHttp?: typeof fetch }`. `semprec-api`'s `CustomRouteDependencies` is assignable to it. `serve.ts` fills `oauth` from `GMAIL_OAUTH_CLIENT_ID` and `GMAIL_OAUTH_CLIENT_SECRET`, `MS_GRAPH_OAUTH_CLIENT_ID` and `MS_GRAPH_OAUTH_CLIENT_SECRET`, and `APP_BASE_URL` as `redirectBaseUrl`. It sets no `outboundHttp`, so production calls the provider with the global `fetch`.
- Redirect URI to register at both providers: `<APP_BASE_URL>/api/mail/oauth/callback` (`deploy/shared/env/api.env.example` says so). A deployment without the provider's client or without the base URL answers a generic 500 on both POST routes; on complete the state is already consumed by then.
- Route matrix entries, in the slice `backend/services/semprec-api/src/routeMatrix/mail.ts`: `mail oauth start` and `mail oauth complete` (tenancy `tenant`) and `mail oauth callback` (public, tenancy `anonymous`, with a `publicReason`). Each has its `ROUTE_CASES` case in `tenantIsolationRoutes.test.ts` and its `ROUTE_HANDLER_FILES` mapping in `chokePointWriteBoundary.unit.test.ts`.
- Error contract for clients and for #1742: 400 `validation_failed` with `details.field` `provider`, `state` or `code`; 400 `mail_admin_consent_required`; 409 `provider_account_already_connected` with `details.mailboxId`, which is `null` when no mailbox of the tenant records the address any more; a generic 500 for a provider outage, a refused OAuth client and a missing configuration.
- The app hands only `{ state, code }` to the complete route. After `{ state, providerError }` there is nothing to complete: the complete route refuses that body before the state is consumed, and the unused state expires.
- For #1742 (reauthorization): the start route always passes `mailboxItemId: null`. A state with a mailbox id is consumed and refused by the complete route. The ADR says its decision does not cover a branch that decides its write from tenant state read before the provider call.
- New store functions in `mail/mailAccountSyncStateStore.ts`, not in the barrel: `findMailboxByProviderAccountAddress(client, address)` returns the item id of the caller's tenant's mailbox that records the normalized address, or `null`; `recordGmailWatchEmailAddress(client, itemId, address)` stores the normalized address in `gmail_watch_email_address` and requires the sync state row to exist. The connect flow is its only caller; the watch lifecycle (`recordGmailWatchRegistration`) owns the column afterwards.
- `exchangeAuthorizationCode` (`mail/oauthTokenExchange.ts`) takes an optional `fetchImpl`.
- No table, no migration, no job name, no generic operation, no MCP tool and no hook registration was added. The routes write `mail_oauth_states`, `items` (Mailboxes), `external_credentials` and `mail_account_sync_state`, and enqueue the existing mail account sync job. The handler does not call the live-sync control: the mailbox is hosted on the live-sync root's next discovery pass.

## Deviations from the specification and spec seams

1. The three route entries are in the slice `routeMatrix/mail.ts`, not in `routeMatrix.ts`, which concatenates the slices.
2. Files beyond the issue's `Touches`: `mail/mailAccountSyncStateStore.ts`, `mail/oauthTokenExchange.ts`, `mail/providerTypes.ts`, `mail/mailboxAddresses.ts`, `seed/seedEmailModule.ts`, `deploy/shared/env/api.env.example`, the ADR, and the tests `mailOauthHttp.test.ts`, `oauthTokenExchange.test.ts`, `errorContract.unit.test.ts`, `chokePointWriteBoundary.unit.test.ts` and `publicSurface.test.ts`.
3. The Task says to follow the bracket ADR for the call outside the transaction. The route keeps only its rule that no transaction is open across the provider call. The rest is recorded in the new ADR.
4. The 409 reuses the existing code `provider_account_already_connected` and names the mailbox in `details.mailboxId`.
5. Aliases of an Outlook account come from `proxyAddresses` of `GET /me?$select=...`. The Task names "Graph `/me`" only; the default property set lists no aliases.
6. "A provider refusal creates nothing" holds for every refusal, but only `invalid_grant` is answered as the caller's 400. A refused OAuth client or a malformed token request is a fault of the deployment and answers a logged generic 500.
7. The handler does not call `reconcileOnce()`, which the Task allows: the composition root's `mailLiveSync` member is a proxy that is not wired yet.
8. On complete, a reauthorization state and a missing OAuth configuration are detected only after the state was consumed, so the user starts over.
9. The callback answers JSON. How the app receives it (native hand-off) is the open product question the issue names.
10. The source's commits are not contiguous on the branch (see the first paragraph). History was not rewritten, because the review and fix records name these hashes.

## NOT RUN and BLOCKED

- NOT RUN: a live sign-in against Google or Microsoft. Every criterion was proven against fake provider responses and the embedded test Postgres. Microsoft does not document how a personal Outlook.com account answers `$select=proxyAddresses`; the two answer shapes the tests use (the default property set without the selected field, an empty list) are reported in two Microsoft Q&A threads and were not observed. If a personal account answered that request with an error, connecting it would answer 500 and create nothing. Only a real sign-in can prove the personal-account half of the third acceptance criterion.
- NOT RUN: the whole integration tier. The program runs it after every eight landed chains and before every publication.
- NOT RUN: `install --frozen-lockfile`, because the merge changes neither the lockfile nor any `package.json`.
- NOT RUN at landing: the fixer's check that the three new token-endpoint tests fail under the old condition, and its three repeated runs of the two concurrency tests. They are the fixer's evidence.
- NOT RUN by anyone: the case of the recheck's new low finding (a code that is a substring of the provider's error token); it was read from the code.

One focused recheck read `2afb9bd8..ccd02702`, ran no test, and returned verdict pass with nothing unresolved and one new low finding.

Follow-ups and open points, none of them done:

- Recheck, low, not fixed: `exchangeAuthorizationCode` replaces the provider's short error code with `null` when the presented code, the verifier or the client secret is a substring of it. A caller who posts their own unused state with a code such as `a` or `grant` therefore gets 500 `internal_error` and an error-level log record instead of 400. No provider issues such a code, nothing is created and no secret is logged. Proposed: carry the classification taken before the redaction and branch on that, with a test row for the code `a`.
- A fallback to plain `GET /me` when the `$select` request fails would remove the dependency on the undocumented personal-account behaviour.
- A Mailboxes item soft-deleted through the generic item delete keeps its `mail_account_sync_state` row, so until #1690 and #2031 land the 409 can name a mailbox that is in the trash. Once #1690 deletes sync state, `details.mailboxId` can be `null`.
- Security reviewer, design point fixed by the issue's Decision: the callback shows `{ state, code }` to whichever browser arrives. A later app hand-off must forward the callback result only to the signed-in user's own complete call.
- Requirements reviewer: the callback drops `error_description`, so on that path the app cannot tell administrator consent from a cancelled consent. The mapping to `mail_admin_consent_required` exists only for the token endpoint, as the Task says.
- The security reviewer noted that the Microsoft address (`mail`, else `userPrincipalName`) can be set freely by an Entra tenant administrator. It labels and de-duplicates a mailbox inside the caller's own tenant only.
- `serve.ts` injects no `outboundHttp`; `mailLiveSync` is still a proxy that throws.
