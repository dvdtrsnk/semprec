## Summary

This implements issue #211: normalizing the relation edge contract in the generic data engine's choke-point.

- Standardized `RelationEdge`, `CreateRelationInput`, and `UpdateRelationInput` types, with `callerItemId` (renamed from `itemId`) identifying the caller's own side of the relation definition.
- Added `updateRelationWithClient`/`updateRelation`: replaces metadata in full (never merges), and returns `404 not_found` with `{ resource: 'relationEdge', relationPropertyId, callerItemId, targetItemId }` if the normalized edge doesn't exist. Endpoints are immutable — moving an edge requires delete + create.
- `createRelationWithClient` stays idempotent on the normalized `(relationDefinitionId, itemA, itemB)` tuple, replacing metadata wholesale (including back to `{}` when omitted); `deleteRelationWithClient` stays idempotent regardless of prior edge existence.
- Added endpoint validation: both the caller and target item must exist, must not be soft-deleted, and must belong to the databases declared by the relation property's own config (`relationDefinitionId`/`targetDatabaseId`) — rejecting dangling, reversed, or cross-database endpoints with `validation_failed`. A relation property whose config lacks valid `relationDefinitionId`/`targetDatabaseId` is rejected the same way.
- Renamed every `itemId` call site across mail ingest/draft/send/attachments/folder-discovery/reconcile (Gmail/Graph/IMAP)/person-linking, `tasks/advanceTaskRecurrence`, and inbox modules to `callerItemId`.
- Added `backend/packages/data/src/__tests__/relations.test.ts` with real-Postgres integration tests covering all the contract points above plus invalid-endpoint cases.

**Verification:** `pnpm -r run build` compiles all 7 backend packages cleanly; the full backend test suite (`pnpm exec vitest run`) passes 326/326 tests across 25 files, including the 13 new relation-edge tests.
