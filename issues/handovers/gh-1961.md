## What was delivered

`POST /api/inbox/items` captures an Inbox item with its optional type in one transaction. Body `{ text, date, time, typeId? }`, strict (an unknown key is a 400 on the key). An `Idempotency-Key` header that replays a live item answers that item again (201, as the generic create does), whatever type the replay names and even when its type was archived since. Otherwise an active Inbox item type is required for `typeId` (archived, trashed, foreign-tenant, unknown or not-a-type id is a 400 with field `typeId`, nothing written) and `createInboxItemWithClient` writes the item, its `type` edge and (through the gh-1432 create hook) the `journalDay` edge; the day is the item's `date`. The response is 201 with the item.

## Tests

`inboxRouteHandlers.test.ts` (`createCaptureInboxItemRouteHandler`) covers: the item with its journalDay and type edges and 201; an untyped item; `ValidationError` with the failing field for missing, non-string or malformed date and time, bad text, bad typeId and unknown keys, with nothing written; the same Idempotency-Key giving one item, one type edge and one journalDay edge; a replay after the type was archived; a Trash-held key creating a new item; no type edge when the helper replays a reserved key; archived, trashed, unknown and not-a-type ids refused on `typeId`. `tenantIsolationRoutes.test.ts` case `capture inbox item` runs over HTTP as tenant B's member on the runtime role: a foreign type answers like a random id (400, nothing written in either tenant), the own capture is 201 with its type and journalDay edge. The worker's mutation checks (replay first, requireLive, type check, text trim, created-only type edge) each made a test fail.

## Deviations from the specification and spec seams

1. The active-type check is the shared `lockActiveInboxType` called by the handler, not a check inside `inboxStore.ts`; `inboxStore.ts` changed only so a replay writes no type edge. `inboxTypeChange.ts` is not in Touches (rename and export only).
2. `requireLive: true` on the replay lookup (a trashed reservation creates a new item).
3. The replay check precedes the type check, so a replay of a key whose type was archived since answers the original item.
4. Date and time format validation is left to the gh-1432 create hook (the handler only checks that they are strings); a replay answers 201.
5. Spec seam: the route entry is in `routeMatrix/inboxItems.ts`; the `ROUTE_HANDLER_FILES` mapping was added.
6. No maximum length on `text` beyond the adapter's 1 MiB body cap.
