## Summary

This adds `.github/scripts/review-followups/validate.mjs`. It is a zero-dependency ES module and command-line tool that checks the proposal file written by the triage agent before anything is published to GitHub. Its header comment is now the reference description of the proposal format.

### Exports

- **`VERDICTS`**: a frozen list of `already-fixed`, `invalid`, `not-worth` and `already-tracked`.
- **`validateProposal(input, proposal)`**: takes any parsed JSON value and returns every violation it finds, never throwing. Each violation names the draft id, `rejected[i] (pr, key)` or `finding (pr, key)` it concerns. It checks:
  - top-level fields, the `version` and `harvestIssue` values, and that `advisories` is an array of strings;
  - that every object has exactly its expected fields;
  - that draft ids are kebab-case and unique, and each finding reference has a valid `pr` and `key` shape;
  - rejection verdicts and reasons, and that `trackedBy` is present only for `already-tracked`;
  - completeness: every input finding appears exactly once, and nothing appears that isn't in the input;
  - `[followups-<H> NN/MM]` draft titles;
  - the Blocked-by first line: `none`, or `#N` other than the harvest issue, or `{{draft:id}}` pointing to an earlier draft only;
  - that the seven required headings each appear exactly once, in order;
  - `{{draft:}}` placeholders: unknown, self-referencing or malformed ones are reported, and the epic body may contain none;
  - that no draft or epic body contains a `<!-- crb-followup` marker or exceeds 60,000 characters;
  - that the epic is present exactly when there are two or more drafts, its title ends in `— epic`, and its body links `#<H>` not followed by a digit;
  - that a draft whose `## Touches` names a protected path has `maintainer-implemented` in its `## Task`.
- **`main(argv)`**: runs the command `node validate.mjs --input <file> --proposal <file>`. For a valid proposal it prints one `ok …` line with the counts and exits 0. For an invalid one it prints each violation as a `- …` line on stdout and exits 1. A missing or unknown argument, an unreadable file, invalid proposal JSON or an input file that `parseInputFile` rejects each exit 1 with one line on stderr.

### Choices worth reviewing

- **Completeness is skipped when `issues` or `rejected` isn't an array.** Otherwise every input finding would also be reported missing, burying the real problem.
- **Placeholders on the Blocked-by line are checked only by the Blocked-by rule.** That rule is stricter (the draft must come earlier), so the placeholder check covers only the lines after it, which avoids reporting the same problem twice.
- **A protected path counts only when it starts a path token.** For example, `docs/.relay/x.md` is not a protected path.
- **Error handling in the command-line tool is narrow.** It catches only file-system errors, `SyntaxError` from the proposal JSON, and the plain `Error` that `parseInputFile` throws for a bad input file. Anything else is treated as a bug and still crashes.

### Tests

`validate.test.mjs` uses `node:test` and has 62 tests covering all 14 acceptance criteria. The command-line tests run the script in a child process against temporary files, with no network. All 389 tests in `.github/scripts/review-followups/*.test.mjs` pass.

These tests are not wired into CI; that wasn't part of this issue.
