## What changed
Only `backend/packages/data/src/__tests__/rollup.test.ts` changed.

- `drainQueue` still does at most 10 passes (`DRAIN_PASS_LIMIT = 10`) and still returns as soon as the job count reads `"0"`. If all ten counts are non-zero it now throws `drainQueue: incomplete drain, <n> job(s) still remaining after the 10-pass limit`, where `<n>` is the last count it saw. Before this change it returned normally, and callers carried on against a partly drained queue.
- The pass step (`runOnce` with the core task list) and the count query against `graphile_worker._private_jobs` now sit in a local `DrainSteps` object. `drainQueue(steps = realDrainSteps)` uses the real steps by default. The new boundary checks pass in their own `vi.fn` steps as an argument. Nothing module-level or global is patched, so nothing needs restoring, and the real-queue rollup tests call `drainQueue()` against the real queue exactly as before.
- New local `describe("drainQueue")` checks:
  - **`0fd59cf5ef` / `83423d66a6`:** ten non-empty counts (`5 … 1`) make the call reject with the exact message naming the 10-pass limit and the last remaining count (`1`). `runPass` and the count are each called exactly 10 times. The scripted count also throws if it is called an 11th time, so an eleventh pass cannot happen.
  - **`0a5b2aeb6c`:** an empty count on the first pass succeeds after one pass. An empty count on the tenth pass succeeds after exactly ten passes.

The pass limit, production queue and recompute code are unchanged, and no shared drain utility was added (all out of scope).
