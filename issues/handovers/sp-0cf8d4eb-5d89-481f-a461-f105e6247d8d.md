# Handover: tell calendars of the same name apart by their account in the new item picker

Implementation commits `023533d5b` and `3cffc9cc5` on `feat/internet-accounts`.

**Shared (KMP).**
- Data: the calendars query expands the account relation with the Mailboxes `addresses` (`{"include":{"relations":{"account":["addresses"]}}}`). `CalendarRelationTarget` decodes `title` and `properties`; a hidden target has neither. `CalendarInfo` gains `accountName` (the title, `null` when blank) and `accountAddress` (the first non-blank entry of `addresses`, split on new lines and commas), both only for an account calendar. The timeline window reads calendars without the expansion, so its calendars carry neither.
- New item: `NewItemState.groups` (`NewItemCalendarGroup(account: NewItemAccount?, calendars)`) replaces the flat list; `calendars` is the computed flattened list. The own calendars come first, then one group per account in the order its first calendar is listed; calendars the server names no account for share a group with an empty id. Only `takesNewEvents` calendars are offered, so read-only, system and subscribed ones are left out, and no group is empty. `NewItemCalendar.qualifier` is `NONE` for a unique name (trimmed, case-insensitive), `OWN` for an own one, `ACCOUNT_NAME` when the account's name is unique among the offered accounts, and `ACCOUNT_ADDRESS` when that name is missing or shared and there is an address.
- Calendars sheet: `CalendarAccountSection.address` is the account's primary address from the internet accounts list.

**Apple.**
- CoreKit has the values and mappings, with the Swift qualifier case `unqualified` for Kotlin `NONE` so it does not clash with `Optional.none`.
- The new item calendar row is a `Menu` with an inline `Picker`, one `Section` per group, each calendar with a colour dot drawn with `symbolRenderingMode(.palette)`. Section titles come from `NewItemOptions.title(of:)`: the existing `calendars.group.own`, or "name · address", either alone when the other is missing, or `calendars.account.unnamed` when both are. The row shows the chosen calendar's dot and `NewItemOptions.label(of:)`, for example "Osobní · iCloud". No new copy key.
- `CalendarAccountHeader` shows the address in a caption under the account name.

**Android.** It has neither the new item sheet nor the calendars sheet, so nothing changed there.

**Not changed.** The event details sheet has no calendar picker today, so it was left alone.
