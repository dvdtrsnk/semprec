## What was delivered

The alternative matches that a library metadata run finds for a Books or Movies item are kept, and the user can pick one as the manual cover.

- Table `library_cover_candidates` (migration `0156`): `item_id`, `idx` (0 to 2), `tenant_id`, `source`, `title`, `subtitle`, `image_url`, `fetched_at`; primary key `(item_id, idx)` scoped by the server-generated item id as `item_automation` is (listed in `PERMANENT_EXCEPTIONS` of `tenancyCatalog.test.ts`); tenancy comment `semprec:tenancy=tenant`, RESTRICTIVE `tenant_isolation` and PERMISSIVE `tenant_rows` policies, DML grant to `semprec_side` as `0078_tenant_exports`. There is no foreign key to `items` (partitioned).
- Store (`library/coverCandidatesStore.ts`): replace, list, get, delete. At most three entries; an entry whose image URL is not a safe https URL (http, userinfo, port, IP literal, localhost, unparseable) or has no cover URL is dropped and the kept ones are numbered from 0.
- Job (`library/libraryMetadataJob.ts`): every run that does not fail replaces the item's set from `result.candidates` (cleared on not found, kept on error and when the automation row is locked), after the automation and item row locks.
- Routes (`library/libraryCoverCandidateRouteHandlers.ts`), all session-authenticated, tenant-scoped, REST custom routes of the library manifest (version 1.3.0):
  - `GET /api/items/:id/cover-candidates` lists the stored candidates and makes no outbound request.
  - `POST /api/items/:id/cover-candidates/refresh` enqueues the metadata job like retry, answers 202 and keeps the manual cover; a locked automation row is set to pending.
  - `POST /api/items/:id/cover-candidates/:index/select` downloads the candidate image through `downloadLibraryCoverOutcome` and `createOutboundHttp` with no transaction open, stages the blob, re-checks the candidate under the item row lock, and in one transaction writes `coverOverride`, `coverSource: "candidate"` and `coverRemoved` as the user. A later job run does not replace the chosen cover.
- Errors of select: an unknown index or an item of another tenant is 404 (identical to a random id); a refused address (169.254.0.0/16, 10.0.0.0/8 and other non-baseline hosts) or an unusable image is 400 on field `index` and nothing is written; an unavailable host (timeout, network, status) is 502 `upstream_unavailable` via the new `UpstreamUnavailableError`; a set replaced during the download is 409 `cover_candidates_changed`. Every non-download logs `itemId`, `index` and the failure kind only, never a URL.
- Cleanup: `libraryCoverCandidatesPurgeHook` (item purge hook registered at the end of `domainWriteHooks.ts`) deletes the rows when an item is permanently deleted, whatever its database. Tenant export and purge are catalog-driven and cover the table.

## Deviations and spec seams

1. Task step 3 says to delete candidates in `deleteItemDependents`. `itemTrash.ts` may no longer import a new listed-domain module (rule `item-trash-domain-imports-are-purge-only`, ADR `2026-11-10-item-purge-domain-hooks`), so the deletion is an item purge hook; `itemTrash.ts` is unchanged.
2. Route entries are in the slice `routeMatrix/library.ts`, not `routeMatrix.ts`.
3. Tenant export and purge are catalog-driven, so no code in `tenancy/` changed; the table is registered in `tenancyCatalog.test.ts` and seeded in `tenantPurge.test.ts` and `tenantExport.test.ts`.
4. Tests are in a new file `libraryCoverCandidates.test.ts` instead of `library.test.ts`; `library.test.ts` is unchanged.
5. The candidate subtitle is author and year joined with a comma; the candidate source is `result.source`, else the configured source; an entry without a cover URL is dropped because `image_url` is NOT NULL.
6. The select route takes an injectable downloader and storage (`createLibraryCoverCandidateSelectHandler`); the mounted factory uses the production ones. The happy path therefore runs with an injected download, the refusal path with the real one.
7. Select reports 400 for a refused address or an unusable image and 502 for an unavailable host (review fix; the first version answered 400 for every failure). A redirect (`redirect: error`) maps to 502 network rather than 400.
8. The migration ordinal moved from 0155 to 0156 at landing.
