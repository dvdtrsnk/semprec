## What changed
- **Status writer:** `transitionTenantStatus` in `tenantsStore.ts` is one conditional `UPDATE … RETURNING`. On zero rows, a missing tenant gives `NotFoundError` and an existing one gives 409 `invalid_account_status`.
- **Guard:** `lockAdminMembership`, `assertAnotherActiveAdminRemains` and `LastAdminError` (409 `last_admin`) are in `accountsAdminStore.ts`.
- **Mutations:** `suspendAccount`, `reactivateAccount` and `changeAccountRole` each take the advisory lock, then read the target `FOR UPDATE`, then apply the guard (only when the target is an active admin), then write and record the audit row. Suspend also revokes the user's sessions and push registrations. An unchanged role returns the account with no audit row.
- **Login and reset:** `login` gives a user with no tenant binding or a non-active tenant the same `UnauthorizedError` as a wrong password, and records a failed attempt. `requestPasswordReset` takes the unknown-email path for them. `resetPassword` throws `PasswordResetTokenError("invalid")` after consuming the token, so the caller's rollback leaves the token unconsumed.
- **Routes:** `POST …/suspend`, `POST …/reactivate` and `PUT …/role` are `admin: true`, with route-matrix entries, `ROUTE_HANDLER_FILES` entries and the new runtime exports. A bad `role` is 400 `validation_failed` on field `role`.
- **Tests:**
  - Store tests, including two admins demoting each other concurrently on two connections (exactly one succeeds, the other gets `last_admin`) and the same for suspending.
  - Login and reset-refusal tests.
  - Handler tests for every acceptance criterion. These cover the 401 for the old token after suspension, the unchanged-role no-op, 404 for an unknown id, 403 for a member and 401 for an anonymous caller.
