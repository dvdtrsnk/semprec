# Handover for gh-1450

The outcome of the last connection a tool call made to each MCP server is now recorded in its own tenant table, `mcp_server_connection_state` (migration `0099_mcp_server_connection_state.sql`). The `mcpServers` item and the sync's `syncStatus`/`syncError` are untouched.

- **Table:** primary key `(tenant_id, mcp_server_item_id)`, `last_connected_at`, `last_error_reason` (CHECK against the values of `MCP_CONNECTION_ERROR_REASONS`), `updated_at`. Classified `semprec:tenancy=tenant`, with the RESTRICTIVE `tenant_isolation` and PERMISSIVE `tenant_rows` policies and grants to `semprec_side`. There is no foreign key on the server id (an `items` partition row).
- **Store:** `mcp/mcpServerConnectionStateStore.ts`, exported from `@semprec/data`: `recordMcpConnectionSuccess(pool, serverItemId)`, `recordMcpConnectionFailure(pool, serverItemId, reason)` (single auto-committed upserts, `last_connected_at` kept on failure) and `getMcpConnectionStates(client, serverItemIds)`, which returns `{ mcpServerItemId, lastConnectedAt, lastErrorReason, updatedAt }` and has no entry for a server never called.
- **Recording:** `executeMcpInvocation` records a success right after `connectMcpServer` resolves, so a later `tools/call` error still counts as connected. It records a failure only when the connect itself throws `McpConnectionError`; any other connect error records nothing. Both writes go through `recordConnectionOutcome`, which logs `logger.warn` with the error name and server id and never rethrows or changes the result.
- **Not recorded:** a sync's connections (out of scope), and a call cancelled by the run's signal is recorded like any other connect outcome.

Tests: `mcpToolExecution.unit.test.ts` (success, reason, `tools/call` failure counts as success, non-connection error records nothing, both recording failures leave the result unchanged), `mcpServerConnectionState.test.ts` (clear on success, keeps `last_connected_at`, every reason accepted and an unknown one refused by the CHECK, survives a caller rollback, tenant isolation on a `semprec_data` pool), `tenancyCatalog.test.ts` (table listed), `publicSurface.test.ts` (three exports).

Notes for #1455: read through `getMcpConnectionStates` inside the caller's tenant scope. Timestamps come back as the driver's values, as with the other stores. A connected server with `last_error_reason` NULL and a `last_connected_at` is connected; an unreachable one has a reason; no row means no tool call has connected yet.
