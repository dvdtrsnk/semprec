## Summary

Fixed `useMcpToolGrants` in `web/src/views/agentPage/ToolsBlock.tsx`: the `mounted` ref was only initialized to `true` via `useRef(true)` and reset to `false` by a cleanup-only effect. Under React StrictMode's development-only mount → cleanup → mount cycle, that cleanup fires once while the ref persists across remounts, leaving `mounted.current` permanently `false` — so every `load()` result was dropped and `ToolsBlock` stayed stuck on `LoadingState` in `pnpm dev`.

Fix: set `mounted.current = true` in the body of the same effect whose cleanup sets it to `false`, so the second mount resets it. Updated the comment to explain why, per the issue's spec. Added a regression test rendering `ToolsBlock` under `<StrictMode>` that fails on the old code (confirmed via a stash-based revert check) and passes with the fix.

`pnpm run verify` in `web/` passes (lint, format, build, all 182 tests). No backend changes were needed since this issue is scoped entirely to `web/`.
