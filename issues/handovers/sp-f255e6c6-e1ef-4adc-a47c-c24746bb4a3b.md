# Handover: make the offline restore work on a fresh cluster and never import the key of a deleting tenant

Delivered on chain `e1-245-backup-restore`, candidate commit `71afa79db34b8364d1442522f1ebf0fce6b2aa5b`, landed by a `--no-ff` merge (`5479387c468d1dc60a76319897019d8a55a2e466`) on `feature/backend-parallel` as a single-chain landing.

**What changed.**
1. The monthly restore test (`deploy/systemd/scripts/alldots-restore-test.sh`) creates `alldots_side`, `alldots_data` (member of `alldots_side`) and `alldots_router` in its disposable cluster (`CLUSTER_ROLES_SQL`, function `create_cluster_roles`) before `pg_restore`, so a dump that holds `CREATE POLICY ... TO alldots_side` or an object owned by `alldots_router` restores. A failing role statement fails the run with the check `clusterRoles` and `pg_restore` is not called. `clusterRoles` is added to `RESTORE_TEST_FAILED_CHECKS` in `backend/packages/data/src/observability/restoreTestResultArgs.ts`, in script order.
2. `importStagedTenantKeys` (`tenancy/restoreTenantKeys.ts`) no longer imports the key of a tenant whose status is `deleting` or that has a row in `tenant_deletions`; both conditions sit inside the single `INSERT ... SELECT` that runs under the tenant context, with the existing row-count check.
3. The ledger validator prints a fixed line per failure class. New `tenancy/restoreLedgerFailure.ts` exports `restoreLedgerFailureMessage(error: unknown): string`; `validateRestoreLedger.ts` exports `RestoreLedgerMismatchError`; `validateRestoreLedgerCli.ts` prints the classified line and still exits 1. No id, SQL text or error message is printed.
4. `deploy/README.md` gains the marked block `restore-database-command` (roles with passwords through `psql \getenv`, owner-role check before role creation, `pg_restore` with owners and privileges, both blob directories, the newest key dump selected by path, the key restore CLI last) plus the `clusterRoles` step and the key-import rule in the monthly section.
5. New ADR `docs/adr/2026-11-15-a-restore-creates-the-cluster-roles-before-the-dump-and-imports-no-key-of-a-deleting-tenant.md` (accepted, backend), extending the three restore ADRs without editing them.

**Contracts dependents build on.** `RESTORE_TEST_FAILED_CHECKS` accepts `clusterRoles`. `restoreLedgerFailureMessage` and `RestoreLedgerMismatchError` are internal to `@alldots/data` (not exported from the barrel). The runbook block is extracted by tests through its `restore-database-command:start/end` markers, so the markers must stay. The block takes `ALLDOTS_RESTORE_SNAPSHOT` (a hex restic snapshot ID), `ALLDOTS_RESTORE_MAIN_DUMP`, `ALLDOTS_RESTORE_KEY_DUMP`, `ALLDOTS_RESTORE_OWNER` and the connection through `PGHOST`/`PGUSER`/`PGPASSWORD`. No route, table, migration, operation or job name changed.

**Files.** `backend/packages/data/src/tenancy/{restoreLedgerFailure,restoreTenantKeys,validateRestoreLedger,validateRestoreLedgerCli}.ts`, `backend/packages/data/src/observability/restoreTestResultArgs.ts`, `deploy/systemd/scripts/alldots-restore-test.sh`, `deploy/README.md`, the ADR above.

**Tests.** `tenancy/__tests__/restoreLedgerFailure.unit.test.ts` (every class, aggregate and cause walks, cycle, bound, precedence, no input text in output); `__tests__/restoreTestResultArgs.unit.test.ts` (`clusterRoles`); `__tests__/backupKeyRestore.test.ts` (monthly script with a catalog holding a `alldots_side` policy and a `alldots_router`-owned function; real migrated catalog restored into a role-less cluster fails naming `alldots_side` and succeeds after `CLUSTER_ROLES_SQL`; deleting and tombstoned tenant keys skipped; the compiled validator prints exact lines for privilege, mismatch, wrong password, closed port and an invalid ledger); `deploy/systemd/scripts/alldots-restore-test.test.sh` and `alldots-restore-activation.test.sh` (role statement before `pg_restore`, failing role statement, the extracted README block run with shims). The worker's mutation runs failed the tests as intended.

**Deviations and spec seams.** (1) The two shell tests need GNU `sed -i` and `stat --format`; on macOS they were run with GNU shims first on `PATH`, the tests are unchanged. They did not appear in the output of `test:repo-scripts` on this tree, so they were run by hand. (2) Precedence of ledger failure classes inside an `AggregateError`: mismatch, then privilege, then unreachable; the Task states none. (3) The runbook block takes the selected main snapshot ID and writes the main dump with `restic dump` so the dump and both blob directories come from one snapshot, and runs the owner check before role creation. (4) One extra test beyond the Task list (compiled validator CLI) covers the printed-line criterion end to end. (5) The role-less restore test uses a second docker fixture and a recreated database for the second attempt, because a failed `--exit-on-error` restore leaves partial objects.

**Criteria NOT RUN or BLOCKED.** None. All six criteria were seen passing, either in the landing gate or in the by-hand run of the two shell tests. The runbook block was exercised only with shims (no real restic, pg_restore or production cluster); the gh-1086 rehearsal on a real cluster stays with that release gate.

**Review.** Requirements and tests lens: clear. Rules and architecture lens: clear. Security lens: clear. No findings, no fix round. Reviewers read statically and ran no tests.

**Follow-ups.** None from review. Running the shell tests on macOS needs GNU sed and stat.
