## What was delivered

- Core task `remindersResync` (API affinity, tenant tenancy), handler registered in `worker.ts`. `enqueueRemindersResync` enqueues one debounced job per tenant (job key `reminders-resync:<tenantId>`, mode replace, run at now + 30 s) in the write's own transaction, so a rolled-back write leaves no job.
- `handleRemindersResyncTask` sends one silent push `{ kind: "remindersResync" }` to the active iOS APNs registrations of the tenant's user; with no registered device (or only macOS, Web Push or revoked registrations, or a tenant without a user) the job completes and no push is attempted; a permanent APNs failure revokes the registration; a transient failure raises an `AggregateError` after all registrations were tried.
- Hooks in `calendar/remindersResyncHooks.ts` (registered last in `domainWriteHooks.ts`, after the sleep resync hooks of gh-1838 and the gh-1882 entries): a create, update, delete or restore of an Event or Task that changes a fire-time key (start, offset, switch, status), a change of a calendar's `notify`, the trash and restore of an Event, a Task or a calendar, and a change of the System settings time zone enqueue the job. A write that names a fire-time key with its current value, a name-only change and a Task create that only carries the defaulted status enqueue nothing.
- ADR `docs/adr/2026-11-14-a-reminders-change-enqueues-one-debounced-resync-job-per-tenant-in-its-write-transaction.md` extends the sleep resync decision.
