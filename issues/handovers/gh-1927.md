## What was delivered

- The mail module manifest declares the capabilities `mail.read` and `mail.draft` and three agent tools without approval, implemented in the new `mail/mailAgentTools.ts` and re-exported from `mailModuleManifest.ts`.
- `mail.thread.get` (read, capability `mail.read`): `getMailThreadDetail` rendered as JSON text (subject, participants, senderPerson, company, project, messages with emailId, mailboxId, folderPurpose, isOwn, from, to, cc, date, plain `bodyText` cut to 20000 characters per message and 200000 in total, newest first, attachment names). The id of a merged-away thread returns the current thread; an unknown and a foreign thread answer the same 404.
- `mail.draft.create` (write, capability `mail.draft`): mode `new` from the mailbox's primary address, or `reply`, `replyAll`, `forward` through `createPrefilledEmailDraft` of gh-1899 with mailbox and from derived from the source message (the source is `sourceEmailId`, else the newest message of `threadId` that is neither a draft nor sent by the user). `to`, `cc`, `bcc` and `subject` given for those modes replace the computed values (fix round). Written as `agent` with the run id and the run's Semp thread id on the `mail_drafts` row, acting for the run's user. A forward's attachments are capped by `MAX_FILE_SIZE_MB` in a mailbox without a provider limit (fix round). A second unsent agent draft of the thread is a 409.
- `mail.draft.update` (write): body and optional subject of an open draft, `last_edited_by` agent; refuses sent (409), discarded and non-draft items.
- The run, its project and its user come from the stored run only: an unknown run is 404 and a run without a project 403. Argument schemas are strict; the field schemas of the draft routes moved to `mailDraftFields.ts` and are shared. Labels `agentTool.<name>.label` are in both mail catalogs.
