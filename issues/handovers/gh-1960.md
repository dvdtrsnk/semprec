## What was delivered

The system task `calendarSubscriptionSweep` (api affinity, system tenancy, crontab `25 * * * *`) downloads the feeds of subscription calendars once an hour. Per active tenant (`forEachActiveTenant`, each tenant in its own scope, failures collected and rethrown at the end) it lists live subscription calendars that have an address (cap 100, longest-unrequested first), judges each address again with `isBaselineOutboundUrl` (skipped under the test policy), and requests it once through `createOutboundHttp` with `If-None-Match` / `If-Modified-Since` when validators are stored, a 20 s timeout, a 5 MiB cap and no redirects. 304 is a success without a consumer call; 200 goes to the consumer registered with `registerCalendarFeedConsumer` inside a tenant transaction together with the validator write. A failure is recorded as a short code (`urlNotAllowed`, `addressRefused`, `redirect`, `timeout`, `tooLarge`, `httpStatus`, `networkError`, `consumerFailed`), never touches validators or earlier data, and logs carry ids, codes and error class names only (no feed content, address or query string). With no consumer registered a 200 is recorded as fetched and the validators are NOT stored, so a feed is imported once a consumer exists. Validators are bound to the address they came from (`feed_url_hash`), and every write after the request runs under the calendar row lock and is dropped when the calendar was trashed, purged, is no longer a subscription or has another address.

## Deviations from the specification and spec seams

1. The Task says to delete the row in `deleteItemDependents`; the boundary rule `item-trash-domain-imports-are-purge-only` and the ADR on item purge domain hooks require a registered purge hook, so `itemTrash.ts` is unchanged.
2. "In chunks": one bounded query lists the calendars of a tenant (cap 100), each calendar is settled in its own transactions; no transaction spans a request.
3. The data barrel is at the 900-line cap, so the export is one `export *` line (it also exports `CALENDAR_FEED_LIMITS`).
4. The handler takes an optional `CalendarFeedLimits` argument (defaults are the issue's limits) for the timeout and body-limit tests.
5. With no consumer, a 200 stores no validators (above). A skipped baseline failure is recorded as `urlNotAllowed`.
6. The test policy skips the baseline re-check (as `mcpConnectionFactory` does), so stored test URLs are set with raw SQL; subscription calendars cannot be trashed through the choke point, so tests trash and purge them with raw SQL.
7. The calendar manifest does not declare the task (a core task).
8. Files outside Touches that inventory tests require: the queue unit tests, `queueRuntime.test.ts`, `tenantIsolationJobs.test.ts`, `rowLevelSecurity.test.ts`, `publicSurface.test.ts`, `calendarFeedStatePurgeHook.ts`.
9. Added by the fix round: `feed_url_hash` in the not yet landed migration 0172 (a null legacy hash only costs one full request).
