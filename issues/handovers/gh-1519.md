# Handover for gh-1519

User and agent item writes now require a non-blank title. The work is committed locally; I did not push or open a PR.

- **Change:** `chokePoint/itemWrites.ts` has one helper, `assertTitlePresent`, used by `createItemWithClient` and `updateItemWithClient`. It finds the database's property of type `title` with `owner: "user"` in the property list the function already loaded (no new query). It throws `ValidationError` with `field` equal to that key when the value is not a string or is blank after trimming. Stored titles are not trimmed.
- **When it applies:** only when `writer.writerKind` is `user` or `agent`. Internal (`system`, the default) writers are unchanged. The Transcripts database (`TRANSCRIPTS_MODULE_ID`) is exempt for every writer. A database with no user-owned title property is unaffected.
- **Create:** the check runs inside the `insertItemWithReplay` property resolver, right after #1389's defaults are merged and before the insert, so a rejection rolls back the transaction (no row, no idempotency reservation, no event). An idempotency replay returns the existing item before the check.
- **Patch:** checked only when the patch mentions the title key; a patch of other properties is unaffected.
- **Tests:** a new `title validation on item writes` block in `data/src/__tests__/itemWrites.test.ts` covers blank, null and missing titles for user and agent, no row left behind, whitespace kept as written, patch to blank, patch of another key, internal writers, a database without a title property, and Transcripts. The whole file passes (41 tests). Typecheck, eslint and prettier pass on the touched files.
- **Not run:** the application and API test suites. Any of them that create items as a user or agent without a title in a database with a user-owned title property will now get 400; Relay's verify will show them. The internal callers listed in the issue run with the system writer and are not affected by construction.
