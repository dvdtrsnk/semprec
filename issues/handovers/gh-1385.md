**What it decides**
- **Classification:** every module tool declares a risk class from the shared closed set and an approval mode (`none`, `always`, `unlessProjectPermitted`). The set currently holds `destructive`; the ADR adds `outbound`. An unclassified tool is not composed, because there is no default of `none`.
- **Grants:** a tool appears in a run only when the run's project holds the grant of its capability (read grants for read tools, write grants for write tools, per #1810). An ungranted tool is absent, not denied.
- **MCP:** same classification and grants for a run credential; a human session acts with the user's permissions without approval, and its writes are recorded as `writerKind: 'agent'` without run ids, bound to that user (#1415). Exposure itself stays with the #1580 addendum.
- **Mail send:** an agent or a run-credential MCP client creates an `outbound` approval request instead of a 403, also when the run's project has `emailSendAutonomous`. A human-session MCP client sends as the user without approval. The thread's project never affects the decision.
