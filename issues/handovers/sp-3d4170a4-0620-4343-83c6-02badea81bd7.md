# Handover: pin pg_temp last in every SECURITY DEFINER search_path and refuse any other shape at deploy

Delivered on chain `e1-237-db-roles`, candidate commit `aee71db88be0ba1e1b2ba805f4aae99245c904de`, landed by a `--no-ff` merge (`7149e60a3f90125aea50d464367687e13be63f27`) on `feature/backend-parallel` as the second chain of a train with `e1-235-value-link-locks` and `e1-244-purge`. The segment commit of this source is `84747058a1094f9d3a1065bfd32ebcfc3b455ad8`; the review fix is `bd74b93190d3d077e1f70358a0142e160dcbd903`.

**What changed.**
1. Migration `0176_definer_search_path_ends_with_pg_temp.sql` runs `ALTER FUNCTION ... SET search_path = pg_catalog, public, pg_temp` on the seven SECURITY DEFINER functions: `create_items_partition(uuid)`, `drop_items_partition(uuid)`, `route_graph_subscription(text)`, `route_gmail_address(text)`, `ai_global_spend()`, `ops_health_counts()`, `ai_tenant_spend()`. Only `proconfig` changes: no body, owner, grant or signature.
2. `findDefinerFunctionViolations` (`backend/packages/data/src/db/tenancyInvariants.ts`) now covers the definer functions of every schema except `pg_catalog` and `information_schema`, parses the function's `search_path` and reports a `definerFunction` violation for: `pg_temp` not last or listed twice, `pg_temp` before the end, a listed schema that does not exist (`pg_temp` and `pg_catalog` excepted), and a listed schema other than `pg_temp` in which PUBLIC, `alldots_data` or `alldots_side` may CREATE (`pg_catalog` included, after the review fix). The existence check uses `to_regnamespace(quote_ident(element))`; empty elements are dropped when parsing; schema details are emitted once per distinct element.
3. `docs/operations/database-roles.md` is updated and a new ADR `docs/adr/2026-11-15-security-definer-search-path-ends-with-pg-temp.md` (accepted, backend) records the rule.

**Contracts dependents build on.** Every future SECURITY DEFINER function must pin `search_path = pg_catalog, public, pg_temp` (or another list that ends with `pg_temp` and names only existing schemas the runtime roles cannot create in); `verifyTenancy` and the deploy check refuse any other shape. No route, table, operation or job name changed.

**Files.** `backend/packages/data/src/db/migrations/0176_definer_search_path_ends_with_pg_temp.sql`, `backend/packages/data/src/db/tenancyInvariants.ts`, `docs/operations/database-roles.md`, the ADR above, and the proconfig expectations of `accountsAdminStore`, `gmailAddressRouting`, `graphSubscriptionRouting`, `operatorHealthReport`, `itemsPartitionTenancy`, `tenantAiBudgetsAdmin` tests.

**Tests.** `__tests__/tenancyInvariants.test.ts` (migrated database has no violation; `create_items_partition(uuid)` with the search_path of finding R2-DB-1 gives exactly one violation `search_path does not end with pg_temp` and `verifyTenancy` returns 1, the ALTER committed and restored in `finally`; a describe block on every shape of the path including `pg_catalog` writable). `__tests__/definerSearchPathEscalation.test.ts` (new; exploit replay as `alldots_data` through `createRuntimeRolePool` with `pg_temp.text` and `pg_temp.uuid` domains for both partition functions, plus control cases on the unfixed search_path that must reject with `escalated as` the owner). Existing ownership tests were updated for the new proconfig.

**Deviations and spec seams.** (1) Schema details for a non-existing or writable schema are emitted once per distinct element (the spec's "each at most once per function" read per detail text). (2) Empty elements of a search_path are dropped when parsing. (3) The existence check goes through `quote_ident` so the stripped name of `"$user"` resolves without a syntax error. (4) The escalation test logs in through `createRuntimeRolePool` (production constructor, per-run random password, `session_user` asserted to be `alldots_data`) instead of copying the identity test's own pool. (5) The embedded Postgres of the test host is 18.4, production is 16. (6) The verifyTenancy case and the control cases temporarily commit an `ALTER FUNCTION` on the shared test database and restore it in `finally`, so they rely on integration files running one at a time.
