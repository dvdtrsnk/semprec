## Decisions and limits

- Row and cursor expressions are constructed together; the cursor reuses the row expression's bound option array. Values, keys, and arrays remain SQL parameters.
- PostgreSQL `array_position` returns a one-based index. The Task calls it zero-based but explicitly mandates that expression; this implementation uses the mandated expression. Only relative ordering is consumed, and no position is exposed in the unchanged cursor token.
- An unknown or empty value has SQL NULL position. `IS NOT DISTINCT FROM` preserves equality among those rows and explicit null/missing values, while strictly-after compares only non-null positions.
- Legacy malformed option entries are narrowed before their keys are used; absent/non-array option lists yield an empty key array. No new persisted validation policy or data migration is introduced.
- Existing grouping fixture now declares done/open options to preserve its group/date regression meaning under option-order semantics. Fixture writes use the production choke point.
- Multi-select sorting, catalog option reordering, Czech collation/title tie-breaks and group-direction changes remain outside this implementation.
