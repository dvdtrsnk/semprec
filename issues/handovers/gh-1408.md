# Handover for gh-1408

## Summary

A `select` sort key now orders by the position of the stored value in the ordered `config.options` keys, in `backend/packages/data/src/views/sortCompiler.ts`:

- `sortKeyExpression` (shared by `compileSort` and `compileSortKeyset`) emits `array_position($N::text[], properties ->> $K)` for a select, with the option-key array bound as one parameter. `ORDER BY` stays `... NULLS LAST` in both directions, so empty and removed-option values sort last; ties still break by id.
- `compileSortKeyset` compares against the position of the cursor value, computed with the same array (`array_position($M::text[], $V::jsonb #>> '{}')`). A cursor value that is null or not in the options takes the null branch (decided in TypeScript).
- `viewQuery.ts` is unchanged: the cursor token format and `castableTo` need no adjustment. A group property is just the first sort spec, so grouped views follow option order too.
- `array_position` is one-based; only the relative order matters, so this is equivalent to the issue's zero-based wording.

## Tests

`viewQueryPagination.test.ts`: new "select option-order sort" block covering ascending and descending order with empty and unknown values last, three-page keyset paging in both directions, and a grouped view paged through its cursor. The existing "groupBy status" fixture now declares `config.options` (`done`, `open`) so its expected order is unchanged. The pool `afterAll` moved to file level so several describe blocks can share the pool.

## Notes for dependants

- A select with no (or malformed) `config.options` has no positions, so all its rows tie and fall back to id order.
- Multi-select is intentionally unchanged.
- #1524 (Czech collation) and #1532 (group direction) build on `sortKeyExpression`; group direction on grouped views is still always ascending.
- Local verification caveat: the embedded Postgres could not start for part of the session (exhausted SysV shared memory slots on the host). `viewQueryPagination.test.ts` passed 14/14 before a prettier-only reformat; `rollupViewFilters`, `viewQueryTotalCount`, `relationPathFilter` and `publicSurface` could not be run. Lint, prettier and the data package build pass.
