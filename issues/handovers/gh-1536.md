# gh-1536 — Tasks title, date and time validation

Repository-Issue: gh-1536

## Delivered behavior

- `backend/packages/data/src/timezone.ts`: `normalizeWallClockTime(value, { field, allow2400? })`. Accepts `H:MM` and `HH:MM` and returns zero-padded `HH:MM`. `""`, `null` and `undefined` return `null`. `24:00` is accepted only with `allow2400`. Any other value throws `ValidationError` (400, `validation_failed`) naming `field`. Exported from the package barrel (`backend/packages/data/src/index.ts`) and listed in `publicSurface.test.ts`.
- `backend/packages/data/src/tasks/taskPreWriteTransform.ts` (renamed from `tasksItemPreWriteTransform.ts`, history kept): the Tasks transform, registered in `domainWriteHooks.ts` under `TASKS_MODULE_ID`. It judges the resulting state of a create or a patch and enforces:
  - `name`, when sent, is non-blank after trimming. The value is not rewritten.
  - `date` is `YYYY-MM-DD` and a real calendar day. `""` and `null` switch it off.
  - `timeFrom` and `timeTo` are normalized by the helper. `timeTo` also accepts `24:00`.
  - A start time needs a date. An end time needs a start time and must be later than it. An equal end time is refused on `timeTo`, not cleared.
  - A date switched off sets `timeFrom`, `timeTo` and `time` to `null` in the same write. A start or end time sent in that write is refused.
  - `time` is derived by `deriveTaskTime` from the normalized values.
- `backend/packages/data/src/chokePoint/itemWrites.ts` is unchanged in this issue. The Tasks branches it no longer has were removed by gh-1422, which this issue builds on. Its one remaining Tasks mention is a doc comment about the recurrence module.
- `docs/adr/2026-10-29-tasks-date-and-time-rules-in-pre-write-transform.md` (new, accepted). It amends rule 5 of `2026-10-29-item-pre-write-transforms-per-module-registry` (on update, `time` is stored when `date` is named as well) and records the file rename. Neither accepted ADR body was edited.

## Behavior notes

- On update the time rules run only when the patch names `date`, `timeFrom` or `timeTo`, and the name rule only when it names `name`. An unrelated write (a status change, for example) to a stored row that predates these rules still succeeds. Stored invalid values are repaired by gh-1657, not here.
- A create runs the time rules always. Its name rule runs only when the create sends a `name`. A missing name stays with the existing title rule in `itemWrites.ts`.
- Clearing a start time while the stored end time stays is refused with `timeTo`, because an end time needs a start time. Clear both in one write.
- The recurrence advance (`tasks/advanceTaskRecurrenceWithClient.ts`) copies `name`, `timeFrom` and `timeTo` into the next instance through `createItemWithClient`, so the same rules apply to it. A stored row that breaks them makes its `done` write fail and roll back until gh-1657 repairs it.

## Notes for dependants

- Events (gh-1598) reuses `normalizeWallClockTime` from the package barrel. It takes `allow2400` only for an end time, as this issue does.
- The Tasks transform is the only Tasks date and time check. The completion day (gh-1544), the first planned day (gh-1602) and `missed` (gh-1668) each add their own step to the same transform, not a new registration.
- The title rule for system writers is not part of this issue. The generic title rule in `itemWrites.ts` exempts system writers, while the Tasks name rule does not, so a blank `name` sent by a system writer is refused here.
- A transform that rejects a stored row blocks the write that touches it. gh-1657 must repair stored Tasks values before the rule is relied on for recurrence.
