# gh-1449 — [agent-md 02/07] Move project agent guidance out of the projects.agents property

## Delivered behavior

- **Canonical Markdown** (`backend/packages/shared/src/projectAgentGuidance.ts`): `PROJECT_AGENT_GUIDANCE_SECTION_KEYS` (`purpose`, `allowed`, `notAllowed`, `generalInstructions`), `PROJECT_AGENT_GUIDANCE_HEADINGS` (`## Purpose`, `## Allowed`, `## Not allowed`, `## General instructions`), the type `ProjectAgentGuidanceSections` and `composeProjectAgentGuidanceMarkdown(sections)`. Each section is trimmed, empty sections are omitted, sections are joined by one blank line and the document ends with one newline. All sections empty renders as the empty string. The package barrel already re-exports the file.
- **Legacy conversion** (`backend/packages/data/src/projectAgentGuidance/legacyAgentsConversion.ts`):
  - `legacyAgentsTextToSections(text)` splits on line-start labels (`Purpose:`, `Allowed:`, `Not allowed:`, `General instructions:`), case-sensitive, one optional space after the colon. Text before the first label and text with no label go to General instructions. A repeated label appends to its section.
  - `seedProjectAgentGuidanceFromLegacyText(client, { projectItemId, ownerUserId, text })` composes the Markdown and skips it with a warning (`project_agent_guidance_too_large`, tenant id and project id only) above `MAX_PROJECT_AGENT_GUIDANCE_MARKDOWN_BYTES`. It writes nothing when the sections are all empty. Otherwise it runs `INSERT ... ON CONFLICT (project_item_id) DO NOTHING`. Only when a row was inserted does it call `guidanceDriftHeartbeatStore.upsertDriftHeartbeat` on the same client. It resolves `true` when it inserted.
- **Per-tenant cutover** (`backend/packages/data/src/projectAgentGuidance/projectAgentGuidanceCutoverMigration.ts`): `runProjectAgentGuidanceCutoverMigration(pool)` runs in one transaction in the tenant's scope. It resolves the tenant's user (none: returns), resolves the Projects database (none: returns), then converts every non-deleted Projects item whose `agents` is a non-blank string. It is registered in `runTenantCutoverMigrations` after the events step.
- **System project seeding** (`backend/packages/data/src/projectAgentGuidance/seedSystemProjectAgentGuidance.ts`):
  - `seedSystemProjectAgentGuidance(client, userId)` resolves each system project from the system database that owns it, by `owner_module_id` (never by name), then the project's `owner_project_item_id`. It skips a project that is missing, deleted or not `systemActive`. It runs through the legacy conversion, so existing rows are never changed.
  - `seedAccountSystemProjectGuidance(pool, tenantId, userId)` (internal, not exported from the barrel) runs the above in `runInTenant(tenantId, …)` and `withTransaction`. On failure it logs `project_guidance_seeding_failed` with the tenant id only and rethrows.
- **Seed text map** (`backend/packages/data/src/seed/systemProjectAgentGuidance.ts`): `SYSTEM_PROJECT_AGENT_GUIDANCE_SEED_TEXTS`, keyed by `SYSTEM_SETTINGS_MODULE_ID`, `MCP_SERVERS_MODULE_ID`, `MAILBOXES_MODULE_ID`, `BOOKS_MODULE_ID`, `MOVIES_MODULE_ID`. The seed files `seedSystem.ts`, `seedMcpModule.ts`, `seedEmailModule.ts` and `seedLibraryModule.ts` import their `agents` value from it. The texts are byte-identical to the former inline literals, checked against the base commit. The seeded property value is unchanged.
- **Account creation**: `bootstrapFirstAccount` seeds after its account transaction commits. `acceptInvitation` seeds after its successful `provision` step. Both use `seedAccountSystemProjectGuidance`.
- **Exports**: `legacyAgentsTextToSections`, `seedProjectAgentGuidanceFromLegacyText`, `runProjectAgentGuidanceCutoverMigration` and `seedSystemProjectAgentGuidance` are exported from the data package index and listed in `EXPECTED_RUNTIME_EXPORTS`.

## Deviations from the Task

- **Account seeding happens after the commit, not inside the account transaction.** The setup route calls `bootstrapFirstAccount` under `runAsSystem("setup")`. A system-scope transaction sets `app.tenant_id` to empty, so under row-level security it cannot read the tenant's system databases. The Task allowed the after-commit branch for that case. The failure log and rethrow follow the Task's wording.
- **Consequence on failure:** a seeding failure after the account exists leaves that account with no guidance rows. `/api/setup` then answers 404, so it cannot be retried. The next deploy's cutover recovers it, because the seed `agents` properties still exist until #1611.
- **Added (not in the Task):** an all-empty conversion writes nothing; the oversize log reads the tenant id with `app_tenant_default()`; `seedAccountSystemProjectGuidance` is a helper with two callers.
- **Added test file:** `backend/packages/shared/src/__tests__/projectAgentGuidanceMarkdown.unit.test.ts`, for the canonical composition.
