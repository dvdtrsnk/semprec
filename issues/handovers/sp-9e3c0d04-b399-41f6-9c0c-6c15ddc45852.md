# Handover: Offer Scan among the shortcut types without an Open When Run toggle

ADR: `docs/adr/2026-11-28-a-capture-intent-runs-in-the-background-and-opens-the-app-only-through-a-second-intent.md`
(new; narrows `2026-11-27-the-document-scanner-is-the-one-uikit-view-controller-of-the-apple-app.md`: no content
choice and no `continueInForeground`). A system entry point declares one mode; opening the app is a second,
non-discoverable foreground intent returned through `.result(opensIntent:dialog:)`.

**Intents** (`mobile/apple/Projects/App/Sources/Intents/`):
- `AddToInboxIntent.swift`: `supportedModes = .background`; parameters `type`, `text`, `day` (`content` and
  `InboxContent.swift` removed). `perform() -> some IntentResult & ProvidesDialog & OpensIntent`: sign-in check, type
  (asked when unset), then `static scanIntent(for:day:)`: "Scan" answers `.result(opensIntent: ScanIntoInboxIntent(day),
  dialog: "intent.addToInbox.scan.opening")`; any other pick runs the text capture as before (`InboxShortcutCapture.shared`,
  `sendBriefly`, `CaptureSending.shared.captureAdded()`). `sendBriefly` is now internal so the scan intent uses it.
- `ScanIntoInboxIntent.swift` (new): `supportedModes = .foreground(.immediate)`, `isDiscoverable = false`,
  `requiresLocalDeviceAuthentication`, one parameter `day`. Without `ScanDocument.isScannerSupported` it answers
  `scan.unavailable`; otherwise `ScanPresenter.shared.scan(Request(day:))` → `.saved` (sendBriefly, `scan.saved`),
  `.cancelled`, `.failed` (`signIn` for unauthorized, else `scan.failed`).
- `InboxTypeEntity.swift`: `Kind` = `.scan` | `.noType` | `.type(label:emoji:)`; `InboxTypeEntity.scan` (id `scan`) and
  `.noType` (id `noType`); `typeId` is nil for both.
- `InboxTypeQuery.swift`: `static offered(_ types:, scannerSupported: = ScanDocument.isScannerSupported)` = Scan (when
  supported) + No type + the server's types (none when the read failed); `entities(for:)` and `suggestedEntities()`
  use it.
- `ScanPresenter.swift`: `Request(day:)` only; `Capture` is `(day, time, file)`; the default writes the capture with
  `text: ""` and `typeId: nil`. `captured` still calls `CaptureSending.shared.captureAdded()`.

**SDK finding (iOS 27 SDK, extracted `Metadata.appintents/extract.actionsdata`).** Before (build 84 sources):
`AddToInboxIntent` `supportedModes: 9`, `systemProtocols: [ForegroundContinuable]`, `openAppWhenRun: false`. After:
`AddToInboxIntent` `supportedModes: 1`, `systemProtocols: []`, `openAppWhenRun: false`, `outputFlags: 5`;
`ScanIntoInboxIntent` `supportedModes: 2`, `openAppWhenRun: true`, `isDiscoverable: false`. Same values in the macOS
build. That Shortcuts shows no toggle is the reading of these fields, not yet seen on a device.

**Copy / policy.** Removed `intent.inboxContent.{name,text,scan}`, `intent.addToInbox.content(.request)`. Added
`intent.inboxType.scan` (Scan / Naskenovat), `intent.addToInbox.scan.opening` (Opening the scanner. / Otevírám
skener.), `intent.scanIntoInbox.title` (Scan into Inbox / Naskenovat do Inboxu); `intent.addToInbox.description`
reworded. `appleOnly` list in `mobile/scripts/architecture-policy.json` updated. App Shortcut phrases unchanged (they
never mentioned the content). `mobile/docs/architecture.md` scanner row names `ScanIntoInboxIntent`.

**Open points.**
- The hand-over dialog (`scan.opening`) exists because both result branches must have one concrete type
  (`IntentResultContainer<Never, Never, Never, IntentDialog>`); on a device it may show before the app opens.
- Not verified on a device: no toggle in Shortcuts, the system running the opened intent with the app in front, and
  the scanner from the Action button. The simulator has no scanner, so it never offers Scan.
- A shortcut saved with "Scan" on an iPhone resolves the entity only where the query offers it, so on a Mac or a
  device without the scanner the type is asked again.
