## Summary

Implemented issue #737's two review follow-ups:

1. **`backend/packages/data/src/moduleWorkers.ts`** — `reconcileOnce()` on `createModuleWorkerInstanceReconciler` now serializes passes via a promise queue: a call made while an earlier pass is running starts its own pass only after the earlier one settles (fulfilled or rejected), and each call's returned promise reflects the outcome of its own pass. Updated the `reconcileOnce` doc comment on `ModuleWorkerInstanceReconciler` to describe this. Added two unit tests: overlapping calls result in exactly one `start` per desired id, and a first call's rejection doesn't block or fail the second call's own pass.
2. **`backend/packages/data/src/manifest/driftCheck.ts`** — removed the comment sentence falsely claiming the manifest read and orphan check see "one schema snapshot" under `withTransaction`'s READ COMMITTED isolation, keeping the sentence about the orphan check + notification being atomic.
3. **`backend/packages/agent-runtime/src/lifecycleAdapter.ts`** — added during code review of this PR: `runAgentSessionForRun` closed the `agent_runs` row (`finishAgentRun`/`finishAgentRunWithErrorNotification`) *before* writing the matching terminal `run_status` event, and the two writes share no transaction when the caller passes a bare pool. A poller could observe the row as `done`/`error` before its final `run_status` event committed — this is what made `services/semprec-agents/src/__tests__/agentRun.e2e.test.ts` flake in CI. Reordered both the success and error paths so the `run_status` event commits first, and added `lifecycleAdapter.test.ts` coverage (spying on `pool.query`) that asserts the terminal `run_status` insert happens before the corresponding `agent_runs` status update on both paths. Follow-up from review: on the error path, `pushRunStatus` and `finishAgentRunWithErrorNotification` now run in separate try/catch blocks — a failure specific to the `agent_run_events` write (e.g. a constraint violation) is logged and no longer prevents `finishAgentRunWithErrorNotification` from closing the `agent_runs` row, preserving the pre-existing guarantee that the row closes unconditionally on any non-connection failure. Added a test asserting the row still closes as `error` when the `run_status` write itself fails.
