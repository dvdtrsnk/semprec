# Handover for gh-1356

The password-reset and invitation emails are now rendered from a catalog in the recipient's language. Branch `wf/gh-1356`; no link, token, rate-limit or send-timeout behavior changed.

**What changed**
- **Catalog:** `data/src/auth/i18n/{cs,en}.json` with `mail.passwordReset.subject|text|html` and `mail.invite.subject|text|html`, using `{url}` placeholders. English reproduces the previous wording exactly.
- **Renderer:** `auth/authMailCatalog.ts` exports `renderAuthMail(kind, locale, url, escapeHtml)`. It loads the catalogs once per process (a failed load is not cached), resolves with `toManifestLocale` and `resolveCatalogLabel`, and escapes the URL only for the `html` template. Each mailer passes its own `escapeHtml`.
- **Mailer inputs:** `SendPasswordResetEmailInput` and `SendInviteEmailInput` gained a required `locale: string`. Any other implementation or fake of those interfaces must supply it.
- **Call sites:** `requestPasswordReset` passes `user.locale`; `createInvite` passes the inviting admin's locale via `getUserById`, or `en` if that row cannot be read. The lookup only runs when a mailer is configured.
- **Build:** `packages/data/package.json` `build` copies `src/auth/i18n` to `dist/auth/i18n` (verified after `pnpm run build`).

**Tests**
- New `authMailCatalog.unit.test.ts`: Czech and English rendering of both emails, the URL appearing once in the text body, HTML escaping of the URL in the html body, English fallback for an unknown locale, and `$` sequences in the URL staying literal.
- `passwordResetActions.test.ts`: the mailer receives the requesting account's locale (`cs` and `en`).
- `invites.test.ts`: the mailer receives the admin's locale (default `cs`, and `en` after the admin switches).
- The fallback to `en` when the admin row is unreadable has no dedicated test.

**Notes for dependants**
- Invitation acceptance and collecting an invitee's language remain out of scope.
