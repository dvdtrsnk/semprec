# Handover: Open Inbox attachments in the diary and on Inbox cards

**Shared.** `InboxAttachment(id, name, mimeType, source, location)` (`shared/domain/.../InboxAttachment.kt`) with
`InboxAttachmentLocation.Blob(blobId)` or `.WaitingCapture(captureId)`. `JournalInboxEntry.attachments` replaces
`attachmentName`/`attachmentCount`; `InboxOrigin.Capture.attachments` is new. Both are decoded from
`InboxAttachmentDto` (`InboxCardDtos.kt`; `attachmentId`, `blobId`, `name`, `mimeType`, `source`): a server entry's
attachment without `blobId` is left out; an entry with status `waiting` maps its one file to `WaitingCapture(<entry
id>)`. The capture projection now also writes `mimeType` and `source` of the capture's file.

`OpenInboxAttachment` names the file with `attachmentFileName(name, mimeType, source)` (last path part, control /
bidi / reserved characters and leading dots removed, at most 100 characters; without a name `Photo` for
`camera`/`photoLibrary`, `Scan` for `scan`, else `Attachment`; an extension of the media type is appended when the
name has none of its extensions) and asks the `InboxAttachmentFiles` port. `FileInboxAttachmentFiles`
(`shared/data`) writes under `<cacheDirectory>/inbox-attachments/<accountKey>/`: `blobs/<blobId>/<name>` downloaded
once with `GET /api/blobs/:id` (100 MB cap, 10 min timeout, through the new `maxBytes`/`requestTimeoutMillis` of
`AuthenticatedApi.download`) and answered from disk afterwards, also offline; `captures/<captureId>/<name>` copied
from the outbox `.bin` on every open (`CaptureOutbox.files` is now visible inside the module for that). Ids that are
not `[A-Za-z0-9-]{1,64}` are `INVALID_DATA`. `HomeSDK` deletes the folder on every end of the session. No cache
directory: `UNAVAILABLE`.

Presentation: `AttachmentState(id, name, mediaType)` in `JournalInboxState.attachments` and
`InboxOriginState.attachments`; `AttachmentPreviewState(attachmentId, phase OPENING|OPEN|FAILED, path, failure)` in
`JournalState.attachment` and `InboxState.attachment`; actions `OpenAttachment(entryId|cardId, attachmentId)` and
`CloseAttachment`. `AttachmentPreviews` (internal) runs one open at a time; a newer open or a close supersedes it; an
unknown id fails as `NOT_FOUND`. The diary finds the entry in the Inbox last shown (also while a reload after a write
runs) or in a kept neighbour.

**Apple.** CoreKit `InboxAttachment`, `AttachmentPreview`/`AttachmentPreviewPhase` (`.open(URL)`), mappings in
`SharedAttachmentValues.swift`. Journal: `JournalInboxRow` lists the attachments as buttons
(`journal.inbox.attachment.<id>`), `JournalAttachmentPreview` modifier (`quickLookPreview` + failure alert) on
`JournalScreen`. Inbox: `InboxSourceView` lists them (`inbox.attachment.<id>`), `InboxAttachmentPreview` on
`InboxDeckView`. New copy keys (appleOnly in the policy): `journal.attachment.failed`, `journal.attachment.opening`,
`inbox.attachment`, `inbox.attachment.failed`, `inbox.attachment.opening`. `QuickLook` added to
`apple.systemModules` (SwiftUI's `quickLookPreview` is the `_QuickLook_SwiftUI` cross-import overlay). Android
unchanged (it renders neither screen).

**Deviations.** The issue says `UNREACHABLE`; `FailureKind` has no such case, so offline is `UNAVAILABLE` (its
documented meaning). The fallback file names are English literals in shared code, as the coordinator asked; Quick
Look shows them as the title.
