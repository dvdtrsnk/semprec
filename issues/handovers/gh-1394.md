# Handover for gh-1394

Added `docs/adr/2026-10-28-page-operation-family.md` (status accepted, area backend). No code, no existing ADR touched.

**What it records**
- Nine operations in the generic catalog with HTTP method and path each: `page.get` (`GET /api/items/:id/page`), `page.ensure` (`PUT` same path), `page.replace` (`PUT .../page/content`), `page.insert` (`POST .../page/blocks`), `page.createSubpage` (`POST .../page/subpages`), `page.duplicate` (`POST .../page/duplicate`), `page.rename` (`PATCH .../page/title`), `page.restoreVersion` (`POST .../page/restore`, `{itemId, at}`), `page.changes` (`GET .../page/changes`). The catalog count grows by one per implemented operation.
- Catalog chosen over docs-manifest custom routes (rejected: the manifest forbids CRUD routes and a second validation path would appear).
- New capabilities `core.page.read` and `core.page.write` (rejected: reusing `core.item.*`). Destructive with approval: `page.replace`, `page.restoreVersion`; everything else non-destructive.
- `page.get` never creates a document (`docId: null`); `page.ensure` is idempotent. Summary fields with the issue that fills each. Title in `Y.Map` `meta` key `title`, "Notes" default not stored. Errors 401/404/400/409. No native block API.

**Notes for dependants**
- The first implementing issue (#1615) adds the two capability ids to `CAPABILITY_IDS`; tests asserting the capability list or the catalog size must be updated there.
- The ADR chose paths the issue did not specify (`/content`, `/blocks`, `/subpages`, `/duplicate`, `/title`, `/restore`) and `expectedLastEditedAt` as the 409 check for replace; the implementing issue fixes the exact encoding.
- The assignment of summary fields (`lastEdited`, `breadcrumbs`, `subpageCount`) to later issues is mine; change it through a new ADR if wrong.
- Prettier was not run.
