## What was delivered

- A user-owned `url` property `subscriptionUrl` on the Calendars database: declared in the fresh seed (`seed/seedCalendars.ts`, `CALENDAR_PROPERTIES`) and added to existing tenants by a per-tenant cutover, with label `property.calendars.subscriptionUrl.name` in `calendar/i18n/cs.json` and `en.json`, and a manifest version bump from 1.0.0 to 1.1.0.
- A pre-write transform `calendarSubscriptionUrlTransform` with its proposal preparation `prepareCalendarSubscriptionUrl`, registered under `CALENDARS_MODULE_ID` in `domainWriteHooks.ts`. It acts only when `subscriptionUrl` is in the patch: `webcal://` (case-insensitive) is rewritten to `https://`, the result must pass `isBaselineOutboundUrl` (https, DNS host, no credentials, no port), a non-null value is allowed only when the calendar kind is `subscription` (taken from the patch, else the stored row, else absent on create, which is refused), `null` and the empty string clear the value, a non-text value is refused. Every refusal is a 400 `validation_failed` on the field `subscriptionUrl` and stores nothing. REST, `/mcp`, agent tools and proposals all reach it because it is a choke-point transform.
- The cutover `runCalendarSubscriptionUrlCutoverMigration` takes `LOCK TABLE properties IN EXCLUSIVE MODE`, is idempotent, covers suspended tenants, skips a tenant without a Calendars database, and inserts the same column values as a fresh seed (name NULL, config `{}`, owner user). It is registered in `runTenantCutoverMigrations` after the entries on the tree, before the area-note cutover.

## Entry points and contracts dependents build on

- `CALENDAR_SUBSCRIPTION_URL_KEY` (`"subscriptionUrl"`), `calendarSubscriptionUrlTransform`, `prepareCalendarSubscriptionUrl` (`calendar/calendarSubscriptionUrlTransform.ts`), `runCalendarSubscriptionUrlCutoverMigration` (`calendar/calendarSubscriptionUrlCutoverMigration.ts`).
- The stored value is the https form (after the `webcal://` rewrite) of exactly what the client sent; the transform does not trim (fix round, per the stored-URL ADR). A padded or whitespace-only address is refused by the baseline check; `null` and `""` clear. A whitespace-only value is therefore refused, not cleared.
- Later sources of the calendar-ics series read `subscriptionUrl` of a `subscription` calendar; fetching it is out of scope here.

## Deviations from the specification and spec seams

1. The Calendars database is owned by module id `calendars` (`CALENDARS_MODULE_ID`), not `calendar`; the transform is registered under it like the existing calendar pre-lock hooks.
2. Calendar labels live in the module catalog `calendar/i18n/*.json`, not `seed/i18n/*.json`.
3. The invitations database of #1901 did not exist when the chain was built; the property was appended to the Calendars `CALENDAR_PROPERTIES` list, with no ordering dependency on it. #1901 is on the tree now and the merge needed no change.
4. Tests live in `calendar/__tests__/`; an additional application-package test covers the `/mcp` acceptance criterion because the data package cannot import application.
5. The transform also supplies the proposal-time preparation; without it every Calendars proposal would fail with "cannot be safely prepared".
6. Registering a transform means every Calendars update now takes the item row lock before the transform (after the module pre-lock hooks, so the lock order is unchanged).
7. The worker's first version trimmed the address; the fix round removed the trim, so only the issue-mandated `webcal://` rewrite deviates from "stored exactly as sent" of the stored-URL ADR, and the file header says so.
8. In `domainWriteHooks.ts` the gh-1925 comment and registration sit between the existing `#1778` comment and its `registerItemCreateHook` lines (style only).
