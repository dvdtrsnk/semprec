## What was delivered

A Semp turn that throws now stores `status` `error`, `error_code` (the closed run error set) and `error_params` in the same UPDATE, and the history renders a localized message from them.

- `classifySempTurnFailure({ error, signal, steps })` (`semp/sempReplyErrors.ts`) takes the code from the typed error (`agentRunErrorCodeOf`: budgetExceeded, modelError, cancelled, internal) or from the abort signal (cancelled, or interrupted for the shutdown abort), never from message text. `failedStep` is the label of the last error step; `connectorName` and `timeoutMs` come from that step.
- `finishSempMessageTurn` (`semp/sempMessagesStore.ts`) now takes `errorCode` and `errorParams` for an error outcome instead of the `interrupted` boolean. The handler (`semprec-agents/src/sempMessageTask.ts`) logs only `threadId`, `assistantMessageId`, `agentRunId` and `errorCode`.
- `semp/i18n/{cs,en}.json` gained `reply.failure.*` texts per error code and per incomplete reason. `renderSempReplyFailure(code, params, locale)` renders them.
- `listSempThreadMessages` (`sempThreads/sempThreadsStore.ts`) returns `error: { code, message }` for a failed reply, in the tenant user's locale from the same statement. `SempThreadMessage` (`packages/shared/src/sempThreadMessage.ts`) gained the optional `error` field. `incompleteReason` and `outcome` are gh-1890's and unchanged.

## Deviations and spec seams

1. The mapper is `listSempThreadMessages`; there is no `sempMessagesHandler.ts`.
2. `semp_messages.error_code` and `semp/i18n/{cs,en}.json` already existed, so the migration adds only `error_params` and the checks, and the texts are added under `reply.failure.*`.
3. `incompleteReason` is as delivered by gh-1890 (absent when complete, with an `outcome` field); the stored step key is `errorCode`, not `failureKind`.
4. `failedStep` takes the step label (`agentStep.title.*`), because the failed step's detail is the constant `agentStep.summary.failed`.
5. The `interrupted` boolean of `finishSempMessageTurn` was replaced by `errorCode`/`errorParams`; the shutdown abort still stores `interrupted`. `errorCode` stays optional so the disabled-continuation close and the startup repair keep storing NULL or `interrupted`.
6. The MCP-timeout criterion is proven with stored events in the production shape, not a live 15 s or 60 s MCP timeout inside a live Semp turn.
7. The review fix split the migration: validation moved to `0161` so the ACCESS EXCLUSIVE lock of `0160` holds no scan.

## Not run, BLOCKED

No acceptance criterion is FAIL or BLOCKED. A live MCP timeout inside a live Semp turn was not run (see deviation 6). Not run by the landing: `install --frozen-lockfile` (lockfile unchanged), the whole integration tier, the worker's mutation checks, web and mobile.
