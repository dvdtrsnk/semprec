Remote MCP servers (`sse`/`http`) and web push now resolve the target host once, at connect time. If any resolved address is in a denied range, the request is refused, and the socket connects only to the address that was checked. Everything is committed on this branch. The full pipeline passes locally: backend lint, format, build, unit (985), the checks, integration (2751), e2e (18), and the web verify (226). I ran the backend integration tier on its own, outside a single `pnpm run verify` call, because it takes longer than one command's time limit.

## What changed

- **Address policy** (new `net/outboundAddressPolicy.ts`):
  - `isPublicAddress` uses a `node:net` `BlockList` with every IPv4 and IPv6 range listed in the issue. IPv4-mapped and NAT64 addresses are judged by the IPv4 address inside them.
  - `OutboundAddressNotAllowedError`: its message names only the host.
  - `publicOnlyLookup`: resolves with `{ all: true }`, refuses unless every address is allowed, and hands the socket the checked address (or the checked list when the socket asks for all of them).
  - `createOutboundHttp(policy?)` returns:
    - a `FetchLike` built on `undici`'s `fetch` with a pinned-lookup `Agent` and `redirect: "error"`;
    - an `https.Agent` with the same lookup;
    - `close()`, which destroys both connection pools.

    Both clients refuse an IP-literal host, since lookup never runs for one. The `fetch` also refuses any protocol other than `https:`.
  - A module-level default policy (public-only), plus `allowLoopbackOutboundForTests()`. That function throws unless `NODE_ENV=test`, and it is re-exported only from `testSupport/mcpContractServers.ts`.
  - `undici@^8.9.0` is added to `@semprec/data` and to the lockfile importer.
- **MCP** (`mcpConnectionFactory.ts`):
  - For `sse`/`http`, the factory re-checks `isBaselineOutboundUrl` before decrypting the credential (skipped under the test policy), then passes the policy's `fetch` to the transport.
  - A baseline failure or a policy refusal becomes `McpConnectionError("address_not_allowed")`, after the transport and the pools are released. That reason is added to `mcpConnectionError.ts`.
  - `handle.close()` now also destroys the pools.
- **Web push** (`webPushAdapter.ts`): sends through the policy's `httpsAgent`. A refusal returns `permanent-failure`, so the existing fan-out revokes the subscription.
- **ADR**: `docs/adr/2026-10-16-connect-time-outbound-address-checks.md` references `[[2026-09-27-ssrf-protection-for-stored-outbound-urls]]` without superseding it.
- **Tests**:
  - `outboundAddressPolicy.unit.test.ts`:
    - address classification for every range, plus the cases from the acceptance criteria;
    - the lookup refusing loopback and mixed results, passing public-only results and handing over the checked address;
    - a resolution failure passing through unchanged;
    - the `NODE_ENV=production` guard;
    - refusals of protocols, IP literals and unsupported bodies;
    - the `https.Agent` refusing a literal host.
  - `outboundAddressPolicy.test.ts`:
    - a real `fetch` to a name resolving to loopback is refused, and the local server sees no connection;
    - the same name connects when the policy allows it;
    - a 302 is not followed;
    - web push to a private, a loopback and an IP-literal endpoint returns `permanent-failure`.
  - `mcpConnectionFactory.test.ts`:
    - `https://localhost.test/...` is refused for both `http` and `sse`, and so is a name resolving to a private address;
    - a legacy `http://127.0.0.1` row is refused under the default policy with no handshake, no open socket and no `credential_access_log` row;
    - a mixed private/loopback answer under the test policy is refused with zero connections;

## Deviations from the issue

- **How MCP detects a refusal.** The issue says to map an `OutboundAddressNotAllowedError` found in the connect error's `cause` chain. For `sse` that does not work: the SDK's `EventSource` turns a failed request into a plain message string before `connect()` rejects, so the refusal is no longer in the chain. Instead, the factory wraps the policy `fetch` and checks the `cause` chain of the error that `fetch` throws. This covers both transports with a single code path. The ADR records this.
- **Request and response conversion.** `undici@8` and Node's global `fetch` type the same web types from two different packages, so one cannot be passed as the other without a cast. The `fetch` copies the method, headers, body and abort signal into `undici`'s request type. It rebuilds the response as a global `Response`, handing over the body stream unchanged. It refuses any body other than a string or `URLSearchParams`, which are the only bodies the MCP SDK sends.
- **`close()` on `OutboundHttp`.** The issue does not list it. I added it so that each MCP connection and each web push send destroys its own pools and leaves no pooled socket behind.
- **Files not in the issue's Touches list.** `testSupport/dnsLookupStub.ts` replaces `dns.lookup` per hostname and passes every other name to the real resolver, which the `pg` pool also uses. Three test files share it. The `undici` version is the one already in the lockfile.
- **Test hostnames.** `https://localhost.test/mcp` would not resolve on its own and would fail as `handshake_failed`. To make the acceptance criterion's case meaningful, the tests stub that name to `127.0.0.1`.
