# gh-1496 — map Gmail labels to real folders only

Repository-Issue: gh-1496

## Delivered behavior and production wiring

- `reconcileGmailAccount` creates Folder items only for labels with `type` `user` and for `INBOX`, `SENT`, `SPAM`, `TRASH`, `DRAFT`. `UNREAD`, `STARRED`, `IMPORTANT`, `CHAT` and `CATEGORY_*` are no longer folders and no longer map message edges.
- Every Gmail API mailbox gets a synthetic Archive folder through `ensureFolderItem` (provider id `semprec:archive`, name `Archive`, behavior `label`, `specialPurpose` `archive`). A message with none of `INBOX`, `SPAM`, `TRASH`, `SENT`, `DRAFT` gets its edge, including a message with no labels at all (previously not ingested). A message with only a user label is in that folder and in Archive. The existing "drop edges for labels no longer carried" loop removes the Archive edge on moving to the inbox and the `INBOX` edge on archiving. Constants `GMAIL_ARCHIVE_PROVIDER_ID` and `GMAIL_PLACEMENT_LABEL_IDS` are exported from `mail/gmailReconcile.ts`.
- Core task `mailGmailPseudoFolderCleanup` (`CORE_TASK_NAMES.MAIL_GMAIL_PSEUDO_FOLDER_CLEANUP`, api affinity, `system` tenancy, handler in `worker.ts`). `mail/gmailPseudoFolderCleanupJob.ts`: `forEachActiveTenant`, per `gmail_api` mailbox and per pseudo-folder, keyset pages of 200 message edges with one transaction per page; each edge is removed and the message gets the Archive edge when it is left without an edge to INBOX/SPAM/TRASH/SENT/DRAFT; a last transaction removes the folder's mailbox edge and soft-deletes the folder (`itemDeleteWithClient`). Idempotent. `enqueueMailGmailPseudoFolderCleanup(pool)` (exported from the barrel) is called in `runMigrationsCli.ts` under the fixed job key `mail-gmail-pseudo-folder-cleanup`.

## Notes for dependants

- The cleanup recognises pseudo-folders by provider id (`UNREAD`, `STARRED`, `IMPORTANT`, `CHAT`, `CATEGORY_*`) because it has no Gmail client to read a label `type`; user labels (`Label_*`) are never touched.
- The cleanup archives any message left without a placement folder, which is slightly broader than "left with no folder edge" (a message with only a user label also gets Archive, matching the reconcile rule).
- Folder counts (#1689) and archive/trash actions (#1917) can rely on the Archive folder having `specialPurpose` `archive`; display names are still the stored English `Archive`.
- `SYSTEM_TASKS` in `tenantEnvelope.unit.test.ts` and the `publicSurface.test.ts` export list were updated for the new task and export.
