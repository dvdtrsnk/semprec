Closes #982

The queue envelope now carries the tenant, and the task runner restores it per job. `pnpm run verify` passes in `backend/` (lint, format, build, unit, integration, e2e). I did not run it in `web/`, which this change doesn't touch.

All the source changes are in `backend/packages/queue/src/index.ts`:

- **Envelope:** `queueJobEnvelopeSchema` gains `tenantId: z.string().uuid().nullable().optional()`. A legacy envelope still parses, and the previous schema ignores the extra key.
- **Catalog:** `TaskTenancy` and `TASK_TENANCY` are added, keyed over core and agent task names. The 11 listed sweeps are `system` and everything else is `tenant`. A task name outside the catalog counts as `tenant`.
- **`enqueueJob`:** the top-level `tenantId` comes only from `currentTenantScope()`.
  - Tenant scope stamps its id, and system scope stamps `null`.
  - With no scope it calls `enforceTenantScope("enqueueJob")`: `null` in warn mode, and in strict mode it throws before any SQL.
  - `payload.tenantId` is never read.
- **`registerTask`:** inside the restored trace:
  - **System tasks:** run in `runAsSystem("task:<name>")` and ignore the envelope's `tenantId`.
  - **Tenant tasks:** take the envelope's tenant. A legacy or `null` envelope or a raw payload falls back to `app_sole_tenant()` and logs `tenant_task_without_tenant`. A NULL result throws, so the job is retried.
  - **Inactive tenants:** tenant status is checked next. A missing, `suspended` or `deleting` tenant gets an info log and a no-op that completes the job. `active` and `provisioning` run the handler in `runInTenant`.
  - **Supersession:** the existing catch still wraps all of it.
- **Runner and schema scope:** `runWorker` and `runOnce` start graphile-worker inside `runAsSystem("queue-worker")`. The runner `runWorker` returns has its `stop()` wrapped in the same scope. `ensureQueueSchema` and `grantQueueSchemaPrivileges` run in `runAsSystem("queue-schema")`.

Tests:
- **New unit test:** `tenantEnvelope.unit.test.ts` covers the stamping, tenant and system tasks, the sole-tenant fallback, supersession, the catalog and rollback safety.
- **New integration test:** `queueTenantEnvelope.test.ts` runs `runOnce` on a real pool. It covers the stored `tenantId` and `app_current_tenant()` in the handler, a suspended tenant, an unknown tenant, and strict-mode `ensureQueueSchema`, `runWorker` and `stop()`.
- **Updated fake helpers:** `traceEnvelope.unit.test.ts` and `moduleTasks.unit.test.ts` now have a `query` on their fake helpers. The envelope-shape assertion in `traceEnvelope.unit.test.ts` now expects `tenantId: null`.

`queueSupersession.test.ts` and the other queue-driven suites passed with no edits.
