## Changes
- **`web/vite.config.ts`**: the five-entry `server.proxy` table is replaced by two entries:
  - `/api`, with `ws: true`, so every REST route and the `/api/sync` WebSocket upgrade reach the backend.
  - `/mcp`, the MCP JSON-RPC endpoint.

  Both keep the `SEMPREC_API_URL` override and the default `http://localhost:3001`. The header comment now names these two prefixes as the backend's URL space, says `/healthz` isn't needed in development, and says `deploy/Caddyfile` carries the same list for production, added by sibling issue G2. `web/src/main.tsx` is not touched (that belongs to G3).
- **`web/src/__tests__/viteConfig.test.ts`** (new, Vitest + jsdom): each test deletes `SEMPREC_API_URL` in `beforeEach`, calls `vi.resetModules()`, then imports `../../vite.config.js`. It asserts:
  - the proxy keys are exactly `["/api", "/mcp"]`, so a third key fails the test;
  - `/api` is exactly `{ target: "http://localhost:3001", ws: true }`, so dropping `ws: true` fails it;
  - `/mcp` is exactly `{ target: "http://localhost:3001" }`.

  The previous value of the variable is restored in `afterEach`.

## Deviation: the test mocks `vite` and the React plugin
Importing the real `vite` under jsdom breaks esbuild: it fails with `new TextEncoder().encode("") instanceof Uint8Array is incorrectly false`. To keep the test in the jsdom tier as the issue asks, it replaces `defineConfig` with an identity function (which is all it does in Vite) and stubs `@vitejs/plugin-react`. The test therefore checks the config object the file exports, not Vite's own handling of it.
