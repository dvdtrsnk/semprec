## What was delivered

Every tenant gets the starting set of seven Inbox item types (Idea, Task, Event, Thought, Mood, Note, Contact), each created once per default, never restored after the user deleted or renamed it.

- Table and seeder (`inbox/defaultInboxTypes.ts`): `DEFAULT_INBOX_TYPES` (key, emoji, processing method, optional target database), `SEEDED_DEFAULT_INBOX_TYPES_KEY = "seededDefaultInboxTypes"`, `SEEDED_DEFAULT_INBOX_TYPES_NAME` and `seedDefaultInboxItemTypes(client, defaults?)`. The seeder locks the System settings item row (`FOR UPDATE`), reads the marker, creates each default whose key is missing through `createItemWithClient` (so the type write hook validates it) with `status` `active`, skips a default whose target database is absent without recording it, and appends the created keys to the marker through `updateItemWithClient` in the same transaction. It resolves to the keys it created. It does nothing when the tenant has no Inbox item types database, throws when the System settings database lacks the marker property or the marker is not a list of strings.
- Names: from the Inbox catalog keys `seed.inboxTypes.<key>.name` (`inbox/i18n/en.json`, `cs.json`), chosen by the locale of the tenant's user: `en` gives English, a tenant without a user or with `cs` gives Czech, a locale without a catalog falls back to English. The language is fixed at creation.
- Cutover (`inbox/defaultInboxTypesCutoverMigration.ts`): `runDefaultInboxTypesCutoverMigration(pool)` takes `LOCK TABLE properties IN EXCLUSIVE MODE`, adds the marker property to the System settings database with raw SQL when missing (no-op when the tenant has no System settings database), then runs the seeder in the same transaction. Registered in `runTenantCutoverMigrations` after the journal-method step and before the area-note step.
- `provisionTenant` seeds after the system seed and the module data migrations. `seedSystem.ts` declares the marker (system-owned `json`, owner process `inbox`) with an empty list.
- ADR `docs/adr/2026-11-15-default-inbox-types-are-seeded-once-per-default-under-the-settings-row-lock.md` records the per-key marker (why a single flag or an existence check was rejected), the inbox-owned property hosted on System settings, the settings-row lock as the serialization point, the skip-without-recording rule and the contract for a module that adds a default.

## Entry points and contracts dependents build on

- `DEFAULT_INBOX_TYPES`, `seedDefaultInboxItemTypes`, `SEEDED_DEFAULT_INBOX_TYPES_KEY` from `packages/data/src/inbox/defaultInboxTypes.ts`, and `runDefaultInboxTypesCutoverMigration` from `inbox/defaultInboxTypesCutoverMigration.ts` (none added to the package barrel).
- A module that brings its own default Inbox type appends one row to `DEFAULT_INBOX_TYPES` and one pair of names to the Inbox catalogs; existing tenants then receive exactly that type once at the next deploy. The marker stores the key only; the type does not.
- The marker is a property of the System settings item: key `seededDefaultInboxTypes`, owner `system`, owner process `inbox`, value a list of keys. The key is written only when a type was created.
- Deploy order matters: the cutovers run before the seed CLI, so the marker property exists when `provisionTenant` or the seeder runs; both throw when it is missing.
- No new route, operation, table, migration or job name. `GET /api/inbox-types` now returns the seven types for a provisioned tenant.

## Deviations from the specification and spec seams

1. Spec seam: the Task and the table name the processing method `journalEntry`; the code delivered by gh-1975 names it `journal`, so Thought and Mood use `journal`.
2. Emoji for the described characters: light bulb U+1F4A1, check mark U+2705, calendar U+1F4C5, thought balloon U+1F4AD, smiling face U+1F60A, memo U+1F4DD, bust in silhouette U+1F464.
3. Names live in the Inbox catalog (`seed.inboxTypes.<key>.name`), not in the table, per the i18n rule; the files `inbox/i18n/en.json` and `cs.json` are beyond the Task's Touches list.
4. The marker property has owner `system` and owner process `inbox` (the drift check treats an empty owner process as an orphan). Its English name is hardcoded, as in the `seedSystem` and transcripts-cutover precedent.
5. `seedDefaultInboxItemTypes` takes an optional table parameter so a test can add a row; the cutover takes none.
6. `provisionTenant` and `seedDefaultInboxItemTypes` throw when the System settings database lacks the marker property.
7. The issue record still carries the label `agent:blocked` from an earlier attempt; the worker does not edit `issues/`.
