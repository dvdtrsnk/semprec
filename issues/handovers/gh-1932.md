## What was delivered

- `GET /api/agent-runs` lists a chat session run (unit `session`, triggered by `user`) that holds assistant messages as one row per answer instead of one row for the whole run. A chat run without assistant messages stays one row titled with its first task.
- An answer retried several times is one row that carries the latest attempt (`attempt`, start, duration, cost, status, error summary). A queued retry that has no run yet does not replace the earlier attempt's row.
- Title of an answer row: the user message text, or `systemReplyTitle` of the `system_key` for a reply to a system message (approval outcome), with a generic label for an unknown key, else the run's task. Trigger label: from the thread kind (a heartbeat tick thread uses the existing heartbeat label, `Tik` in cs and `Tick` in en; a chat uses `Chat`). Display status and error summary follow the message through the shared `deriveRunDisplayStatus` / `agentRunErrorFields`; pending approvals are attributed per reply.
- `limit` counts rows after the expansion.

## Entry points and contracts dependents build on

- `listProjectAgentRuns` (`agentRuns/agentRunsStore.ts`) returns `ProjectAgentRunListEntry` (`AgentRunRow` plus `answer: ProjectAgentRunAnswer | null`); one statement builds the page: the runs branch (index-ordered scan with the occurrence collapse, minus session runs that own assistant messages) merged with the answers branch (latest attempt per `reply_to_message_id` among the list's chat runs), ordered by start, run id, message id and cut at `limit`.
- Every list row of the route now carries `agentRunId` and `messageId` (`messageId` is `null` on a row that is not an answer; the several rows of one chat run share `agentRunId`).
- New exports of `@semprec/data`: `getSempMessageCosts(client, messageIds)` (`aiGateway/aiGatewayCallsStore.ts`, one statement, an entry for every id, `reserved` counted at the estimate, `failed` at 0), `systemReplyTitle` (`agentRuns/agentRunDetail.ts`), and the types `ProjectAgentRunAnswer`, `ProjectAgentRunListEntry`.

## Deviations from the specification and spec seams

1. No catalog changed: the title labels (`agentRun.replyTitle.*`) and trigger labels already exist in `agentRuns/i18n/{cs,en}.json` from gh-1889 and gh-1909; the Touches name `seed/i18n`.
2. The batched cost by `semp_message_id` was not provided by gh-1744, so `getSempMessageCosts` was added to `aiGatewayCallsStore.ts`.
3. The gh-1909 and gh-1914 expectations gained `agentRunId` and `messageId: null`; the index-plan test of gh-1914 was rewritten, because the answers branch sorts by a computed start. It now asserts no Seq Scan, WindowAgg, Aggregate or Unique and no Sort between the project index scan and its nearest Limit.
4. Where the spec is silent: an answer row's start is the first event of the message's turn (the message `created_at` when retention removed it); attempts collapse by (thread, `reply_to_message_id`) over assistant messages that started a run of the list; a run whose only messages were superseded by an attempt in another run has no row; `triggeredBy` stays the stored user. The answers are sorted by their start, which no index covers, so the project's session-run answers are read for that sort.
