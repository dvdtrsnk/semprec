# Handover for gh-1444

MCP invocation failures now carry a machine-readable reason. `McpInvokeResult` has an optional `failure: { failureKind, mcpServerItemId?, timeoutMs? }`, and the agent tool result `details` carries the same data. The result text the model sees is unchanged, and no exception message is copied into `failure`.

- **Connection reason:** `connect_timeout` is added to `MCP_CONNECTION_ERROR_REASONS`. `withTimeout` in `mcpConnectionFactory.ts` rejects with a private `ConnectTimeoutError`, which `connectMcpServer` maps to `McpConnectionError("connect_timeout", ...)` with a transport-name-only message. `address_not_allowed` keeps precedence.
- **Auth on connect:** `McpConnectionError` gets an optional numeric `httpStatus`. It is set to 401 or 403 on `handshake_failed` when the SDK's `StreamableHTTPError` or `SseError` reports that status. The status is a number only, so no message leaks.
- **Default timeout:** `MCP_DEFAULT_CONNECT_TIMEOUT_MS` (15 s) now lives in `mcpConnectionError.ts`, so `mcpToolExecution.ts` reports the timeout in effect without importing the (mockable) factory. Callers that override `connectTimeoutMs` through `executeMcpInvocation` do not exist, so the default is the value in effect.
- **Classification:** `MCP_FAILURE_KINDS` and `McpFailureKind` (and `McpInvokeFailure`) are exported from `@semprec/data`.
  - `timeout`: `McpError` with `RequestTimeout` (60 s) or `connect_timeout` (15 s).
  - `auth`: `credential_decryption_failed`, or a 401 or 403.
  - `connection`: any other `McpConnectionError`.
  - `toolError`: an `isError: true` result, or any other thrown error.
  - A call cancelled by `signal` returns the cancelled text with no `failure`.
- **Unavailable:** `resolveMcpInvocation` marks the unknown, inactive or revoked rejection as `unavailable` with no `mcpServerItemId`. The argument-validation rejection is not marked. `noLongerAvailableOutcome` in `approvalRequestExecution.ts` is `unavailable` with the payload's `mcpServerItemId`.
- **Tool result:** `createMcpTools` writes `details: { error, failureKind, mcpServerItemId, connectorName, timeoutMs }`, omitting absent keys. The non-object-arguments early return and successful calls carry no classification keys.

Tests: `mcpToolExecution.unit.test.ts` (every kind, cancellation, no leak of the message), `agentSessionComposition.unit.test.ts` (details with and without keys, success), `mcpConnectionFactory.test.ts` (a stdio `sleep` server with `connectTimeoutMs: 200` raises `connect_timeout`), `publicSurface.test.ts` (`MCP_FAILURE_KINDS`). One existing stdio env-names test in `mcpConnectionFactory.test.ts` fails on this macOS host for a reason unrelated to this change (extra inherited env names).

Notes for dependants (#1890, #1860, #1907): read `details.failureKind` from stored tool results. `unavailable` may lack `mcpServerItemId` when the registration was not resolved. `approvalRequestsStore.ApprovalRequestOutcome` was not widened, so the failure is not persisted on approval rows.
