## What was delivered

Results of the global search carry an excerpt in `snippet`.

- `search/searchSnippet.ts` exports `buildSearchSnippetSql`: `CASE WHEN body matches the combined czech and czech_simple vector against the builder's tsquery THEN left(ts_headline('czech_simple', body, <czech_simple prefix part>, 'StartSel="", StopSel="", MaxFragments=1, MaxWords=25, MinWords=8'), 160) ELSE NULL END`. Every value is an existing bind parameter of the #1589 builder; no bind parameter is added and no SQL is built from the query text.
- `searchItemsQuery.ts` reads the excerpt in one extra statement over `item_search_index` for the ids of the returned page only (after limit and cursor), and maps it to `snippet` of item-backed results in every item group. The chat group keeps `snippet: null`.
- A result found only through its title, or whose words are split between title and body, gets `snippet: null`. The excerpt has no highlight markup, is plain text and has at most 160 characters. A Journal day's excerpt comes from its Inbox entries as well as its page.

## Entry points and contracts dependents build on

- `buildSearchSnippetSql` takes the builder's output and its first bind position; it derives the czech_simple prefix part from the same bound words. It throws `RangeError` for a query without a word; the messages carry no query text.
- No route, operation, table, migration or job name is added; the generic-operation schema is unchanged (the doc comment of `snippet` in `shared/genericOperations/schemas.ts` now names the item's page and, for a Journal day, its Inbox entries).
- The data barrel is unchanged.

## Deviations from the specification and spec seams

1. The #1589 builder returns one combined sql and the bound words, not a separate prefix part, and `itemSearchQuery.ts` is not in Touches; `buildSearchSnippetSql` derives the prefix part from the same bound words.
2. The excerpt is read by one extra statement for the returned page rather than joined into the page query, so the headline is built for the returned rows only.
3. `searchSnippet.test.ts` is an integration-tier file and also holds the pure checks.
4. Fixtures write pages through `writePageTextBlocks` and run `handleItemSearchPageTextTask` directly instead of draining the queue.
5. gh-1859 is a Shared-file ordering blocker with no handover on the tip; nothing of it was needed.
6. A body that matches only through czech lemmas (Hunspell active) and not through the czech_simple prefix gets the start of the body as excerpt, as the Task's headline recipe implies; documented in the builder docstring.
