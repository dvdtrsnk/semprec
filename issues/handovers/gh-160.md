## Summary

Implements `WS /api/sync`'s authenticated multiplexed lifecycle for issue #160:

- **`createSyncServer`** (`backend/packages/realtime/src/syncServer.ts`): authenticates every WS upgrade with a caller-supplied `authenticate` callback (same session cookie/Bearer path as HTTP routes), rejecting invalid credentials with a raw HTTP 401 before any socket is created. Tracks one identity per socket, validates inbound/outbound protocol-v1 frames against a closed catalog (`protocolV1.ts`) — dropping anything malformed or unknown without affecting other connections — and owns exactly one dedicated Postgres `LISTEN` connection per process, closing every socket for a `session_revoked` NOTIFY with close code 4401. A heartbeat re-validates each session as a fallback.
- **`syncHandler.ts`** in `semprec-api` wires this to the service's real `authenticateRequest`/`isSessionActive`; `serve.ts` mounts it at `WS /api/sync` and wires the realtime hook pipeline.
- **`sessionsStore.ts`** fires the new `session_revoked` hook (deferred until commit via `runAfterCommit` when inside a transaction) on `revokeSession`, `revokeSessionForUser`, and `revokeAllSessionsForUser` — covering logout, remote device revocation, and password-reset cascades.

Nothing from the issue's "Out of scope" list (stream handlers, post-connect auth messages, connection-per-traffic-type design) was built.
