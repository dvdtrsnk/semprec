# Handover: Send waiting Inbox captures from background tasks

ADR: `docs/adr/2026-11-27-apple-app-sends-waiting-inbox-captures-from-background-tasks.md` (BGTaskScheduler tasks send
the outbox through the shared SDK; a background `URLSession` is rejected for now; all of it is owned by the app's
`CaptureSending`).

**Kotlin (exported).** `InboxCaptureSDK.capturesWait(): Boolean` (suspend) = `OfflineLayer.capturesWait()` =
`CaptureOutbox.waits()`: counts the JSON files of the owner signed in now (not the `waiting` StateFlow, which is "as
last counted"); `false` with nobody signed in or no person kept, and on an unexpected exception; cancellation rethrown.
Tests in `CaptureOutboxTest` (2 new) and `InboxCaptureSDKTest`.

**CoreKit.** `InboxShortcutCapture.capturesWait() async -> Bool` (false when the call throws). `public static let
shared`, the one bridge of the process; the public `init()` became private, the internal test initializer stays. The
intent, the type query, `ScanPresenter.inbox`, `CaptureSending` and the background tasks all use `shared`.

**App** (`mobile/apple/Projects/App/Sources/Background/`):
- `WaitingCaptures.swift`: `@MainActor protocol WaitingCaptures` (`send()`, `capturesWait()`); `InboxShortcutCapture`
  conforms.
- `CaptureSending.swift`: `CaptureSending.shared`, both platforms. `appBecameActive()` sends through the bridge;
  `appMovedToBackground()` and `captureAdded()` call `backgroundTasks.scheduleIfWaiting()` on iOS, nothing on macOS.
  All of it goes through the one bridge of the process, `InboxShortcutCapture.shared` (follow-up commit, decided by the
  coordinator), injected as `captures` so tests pass a double.
- `CaptureBackgroundTask.swift` (iOS): protocols `CaptureBackgroundTask` (over `BGTask`) and `CaptureTaskScheduler`
  (over `BGTaskScheduler.submit`), so tests run without the system.
- `CaptureBackgroundTasks.swift` (iOS): identifiers `cz.alldots.app.inboxCaptures.send` (processing,
  `requiresNetworkConnectivity`) and `.refresh` (app refresh), no earliest date. `register()` (main queue handlers),
  `scheduleIfWaiting()`, `run(_:)`: send, then `capturesWait()` when the send did not confirm all sent; none waiting
  -> complete(success: true); waiting -> schedule both, complete(false); expiration -> cancel the send task, schedule
  both, complete(false). A `Completion` object completes once. A refused `submit` is dropped with a reason comment
  (the app has no logger), the other request is still submitted.

**Wiring.** `AppDelegate.didFinishLaunching` registers the tasks. `AlldotsApp` observes the app-wide `scenePhase`:
`.active` -> `appBecameActive()`, `.background` -> `appMovedToBackground()`. `AddToInboxIntent` (text) calls
`captureAdded()` after `sendBriefly` (the 3 s wait is kept). `ScanPresenter` takes a `captured` hook (default
`CaptureSending.shared.captureAdded()`) and calls it after a kept scan, after resuming the intent. Journal:
`JournalScreenFactory.journal(... onCaptured:)` -> `JournalCaptureViewModel(model:onCaptured:)`, called on each
`captured` effect; `JournalTab` passes `CaptureSending.shared.captureAdded()`. The feature does not import
BackgroundTasks.

**Config.** Info.plist in `Project.swift`: `BGTaskSchedulerPermittedIdentifiers` (both ids) and `UIBackgroundModes`
`audio, fetch, processing, remote-notification`. The bundle id is `cz.alldots.app`, so the issue's identifiers carry its
prefix (Apple does not require one). `BackgroundTasks` added to `apple.systemModules`; `mobile/docs/architecture.md`
lists the iOS-only files.

**Open points.**
- Not verified on a device: that the system actually runs either task (it can be forced from the debugger with
  `_simulateLaunchForTaskWithIdentifier`), and how long an offline capture waits in practice. On the simulator
  `submit` is refused, which the code drops.
- A capture JSON the outbox cannot read is counted, so it keeps both tasks scheduled; an expiry or an expiration after
  completion schedules once more even when nothing waits (documented in the ADR).
- One `InboxCaptureSDK` and one HTTP client now serve the whole process (`InboxShortcutCapture.shared`); it lives as
  long as the process, so its sender stays attached to the layer when no window exists (a window still replaces it).
- The scan branch schedules before the intent's brief send, so the tasks may be scheduled for a capture the brief send
  then delivers; that run finds nothing and completes with success.
