## Validate web-push endpoints at registration (#631)

The server POSTs to a web-push `endpoint` with a signed VAPID JWT, and the caller chooses that URL. Until now any non-empty string was stored, so an authenticated session could make the API send requests to loopback and private services such as MinIO, Postgres or the API itself. This PR rejects those endpoints at registration.

### Changes
- **New `backend/packages/data/src/push/webPushEndpointValidation.ts`**: `validateWebPushEndpoint(endpoint)` parses the value with `new URL` and requires all of the following:
  - the protocol is `https:`
  - there is no userinfo
  - there is no explicit port (`:443` is accepted because `URL` drops the default port)
  - the host is not `localhost` or `*.localhost`
  - the host is not an IP literal (`net.isIP` on the host with brackets stripped)

  If any rule fails, including a parse failure, it throws `ValidationError(..., { field: "endpoint" })`, which the route turns into a 400 `validation_failed`. On success it returns the input unchanged, because the stored value is the `ON CONFLICT (endpoint)` identity. The docstring says DNS rebinding is not covered here and that egress filtering is the deployment's job.
- **`registerPushSubscription`**: the `web_push` branch now passes `endpoint: validateWebPushEndpoint(nonEmptyString(input.endpoint, "endpoint"))`. The APNs branch is unchanged, and nothing is added to the barrel export.

### One addition beyond the literal rule
`URL` keeps the trailing root dot on a DNS name, so `https://localhost./x` and `https://api.localhost./x` would have passed rule 4 while still pointing at loopback. The validator removes one trailing dot before the `localhost` check, and the unit tests cover both forms. IPv4 shorthands such as `2130706433` are already converted to dotted-quad by `URL` and rejected as IP literals; there is a test for that too.

### Tests
- **New `push/__tests__/webPushEndpointValidation.unit.test.ts`** (unit tier):
  - Every accept case from the issue returns the input unchanged, including the explicit `:443`.
  - Every reject case from the issue, plus the extra cases above, throws `ValidationError` with `details.field === "endpoint"` and the exact message.
- **`pushSubscriptions.test.ts`, inside `describe("registration validation")`**: registering `https://127.0.0.1:9000/minio` rejects with a `ValidationError` on the `endpoint` field, and `push_subscriptions` stays empty.
