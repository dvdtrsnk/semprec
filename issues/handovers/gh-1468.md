# gh-1468 — plain-text preview and ingest time for mail messages

Repository-Issue: gh-1468

## Delivered behavior and production wiring

- Migration `0102_mail_message_meta_preview_ingested_at.sql` adds nullable `preview_text text` and `ingested_at timestamptz` to `mail_message_meta`. No SQL backfill.
- `mail/mailPlainText.ts` exports `htmlToPlainText` (the former private `htmlToSearchText`, now imported by `ingest.ts`), `buildMailPreview` (collapses whitespace, at most 200 UTF-16 units, never splits a surrogate pair) and `buildMailPreviewFromBody(bodyText, bodyHtml)` (text part, else converted HTML). These are not re-exported from the `@semprec/data` barrel.
- `mailMessageMetaStore.ts`: `MailMessageMetaRow` has `previewText: string | null` and `ingestedAt: Date | null`; `UpsertMailMessageMetaInput` accepts both. On conflict the existing non-null value wins (`COALESCE(mail_message_meta.x, EXCLUDED.x)`).
- `ingestEmailMessage` and the `sendDraftEmail` claim upsert both set `previewText` and `ingestedAt` (`new Date()`). A later Sent-folder ingest of a sent message keeps the claim's values.
- Core task `mailMessagePreviewBackfill` (`CORE_TASK_NAMES.MAIL_MESSAGE_PREVIEW_BACKFILL`, api affinity, `system` tenancy, handler in `worker.ts`). It runs `forEachActiveTenant` and walks `item_id` keyset pages of 200, one transaction per page, over rows where `preview_text IS NULL OR ingested_at IS NULL`; `ingested_at` comes from `items.updated_at`, `preview_text` from the item's `body` property, each only while still NULL. Idempotent.
- `enqueueMailMessagePreviewBackfill(pool)` (exported from `@semprec/data`) is called by `db/runMigrationsCli.ts` after the queue schema exists, under the fixed job key `mail-message-preview-backfill`.

## Notes for dependants

- #1567 can read `preview_text` and `ingested_at` from `mail_message_meta`; both can be NULL until the backfill has run on a tenant, so sort with `COALESCE(Emails.date, ingested_at)` defensively.
- The backfill uses the item `body` as-is: for a message sent from Semprec with an HTML body, the backfilled preview of a pre-existing row would contain tags. Rows written after this change get a tag-free preview from the send claim.
- Tests that add a task to `CORE_TASK_NAMES` must also update `SYSTEM_TASKS` in `packages/queue/src/__tests__/tenantEnvelope.unit.test.ts` and `tenantIsolationJobs.test.ts`.
