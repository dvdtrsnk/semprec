## Register the seeded heartbeat action handlers in both queue runtimes (#641)

Both production queue runtimes now register handlers for the heartbeat actions routed to them. Seeded heartbeats no longer fail on every fire with `No handler registered for heartbeat action '<id>'`. One exception is intended: `semprec.tick` still fails with that error, because it needs an LLM proposal computation that doesn't exist yet.

The backend verify pipeline passes, though two load-sensitive tests needed a rerun (details under Verification). `web/` was not touched, so I didn't run its verify.

### Changes
- **API runtime.** New `createApiActionRegistry(pool, moduleRegistry)` in `services/semprec-api/src/actionRegistryComposition.ts`. It registers every seeded api-affinity action:
  - `core.driftCheck` (locale left unset, so it reads `users.locale` live)
  - `moduleRegistry.checkDrift`, using `KNOWN_HEARTBEAT_ACTION_IDS` and `KNOWN_OWNER_PROCESS_IDS`
  - the two library-metadata actions
  - the two mail person-linking actions
  - the two transcription actions
  - `core.agentGuidanceDrift`, a handler that calls `createAgentGuidanceDriftActionForApi` with the heartbeat's `projectItemId`. It is built once, when the registry is created.

  `createApiQueueRuntime` now uses this registry, and its docstring no longer claims the registry is empty. The "Not yet wired" docstring in `projectAgentGuidanceComposition.ts` now names this caller. **`semprec-api` now needs `AI_GATEWAY_INTERNAL_TOKEN` at startup** and refuses to start without it; the error names the variable.
- **Agents runtime.** New `createAgentsActionRegistry(pool, runAgent)`, which registers only `core.agentRun`. Also new: `unwiredRunAgent`, a placeholder that rejects with `semprec-agents has no agent session runtime wired`. `createAgentsQueueRuntime` gains an optional third argument, `AgentsQueueRuntimeOptions { runAgent? }`, defaulting to `unwiredRunAgent`. `serve.ts` is unchanged; #647 will pass the real function.
- **`KNOWN_OWNER_PROCESS_IDS`** in `manifest/knownActionIds.ts` lists every `owner_process` value the seeds and migrations write:
  - `emails`, `folders`, `inbox`, `processingProposals`
  - `TRANSCRIPTION_OWNER_PROCESS`: this is the only `ownerProcess` the ten-database specs declare, which I checked by searching every `ownerProcess:` in the seeds and every `owner_process` write in migrations.
- **`@semprec/data` barrel.** Added `createFilesTranscriptionTriggerAction`, plus `export *` of `libraryMetadataActions` and `personLinkingActions`, all kept together at the transcription export.
  - **Beyond the Task:** I also exported the `FILES_TRANSCRIPTION_TRIGGER_ACTION_ID` and `TRANSCRIPTION_REQUEUE_SWEEP_ACTION_ID` constants on the same line. The registry is keyed by those constants, and without this they weren't reachable from outside the package.
- **`publicSurface.test.ts`.** The frozen export list now includes the new names. **Unrelated fix:** it also adds `toApprovalRequestDecisionView`. `develop` already exports it (added with #629) but never froze it, so this test fails on `develop` as it stands. This follows how 925282d handled `MIN_PASSWORD_LENGTH`.
