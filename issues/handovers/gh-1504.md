# Handover for gh-1504

Structured metadata for Semprec-owned mail drafts is stored. Nothing calls it outside the tests; the HTTP interface is #1867.

## What was added
- **Migration `0107_mail_drafts.sql`**: table `mail_drafts` keyed by `email_item_id` (no foreign key to `items`), with `tenant_id`, row-level security, the tenancy comment and the `semprec_side` grant. CHECKs: `mode` in `new`, `reply`, `replyAll`, `forward`; `created_by` and `last_edited_by` in `user`, `agent`; the three recipient columns are jsonb arrays. Partial unique index `mail_drafts_one_unsent_agent_per_thread_uq` on `(tenant_id, thread_id)` where `created_by = 'agent' AND sent_at IS NULL AND thread_id IS NOT NULL`. `thread_id`, `mailbox_item_id` and the other item ids have no foreign keys.
- **Store `mail/mailDraftsStore.ts`**: `insertMailDraft`, `getMailDraft`, `updateMailDraft` (patch; `undefined` leaves a field alone, `null` clears a nullable one; always sets `lastEditedBy`), `markMailDraftSent`, all exported from `@semprec/data`. Rows read back are validated (`assertKnownValue`, `assertShape`). Recipients are `{ name, address }` with `name` an empty string when absent, in the stored order.
- **`MailDraftThreadConflictError`** (a `ConflictError`, status 409) is thrown by `insertMailDraft` when the one-per-thread index is violated; nothing else is re-labelled.
- **`createEmailDraft`**: new optional `metadata` (the insert input without `emailItemId`) writes the `mail_drafts` row on the same client, so the item, the Drafts edge and the row commit or roll back together when the caller holds a transaction. It also always sets `date` on the Email item (`input.date`, default now). Without `metadata` behaviour is unchanged apart from `date`.
- `tenancyCatalog.test.ts` (tenant table list, primary-key-without-tenant exception) and `publicSurface.test.ts` (five names) updated.

## Tests
`mailDraftsStore.test.ts` (atomic create and rollback on a conflict, plain draft without a row, second agent draft rejected, user and thread-less drafts unlimited, same thread in another tenant, new agent draft after mark-sent, recipient order, partial update and the missing or sent draft), plus `tenancyCatalog`, `publicSurface`, `mailSend` and `migrationCompatibility` pass. Lint, format, typecheck and migration numbering pass. I did not run the full verify.

## Notes for dependants
- `updateMailDraft` and `markMailDraftSent` act only on unsent rows and throw `NotFoundError` otherwise; callers add their own version checks (#1867).
- A failed insert aborts the surrounding Postgres transaction; map `MailDraftThreadConflictError` after the rollback, not inside it.
- Provider drafts have no row and stay read-only. The draft is not uploaded to the provider.
