## Summary

Implements the outbound MCP-invoke adapter for issue #128:

- `resolveGrantedMcpTool` (`packages/data`) re-derives grant/registration/server state for a `(projectItemId, mcpToolRegistrationId)` pair at invoke time, from server-derived run context only.
- `resolveMcpInvocation` / `executeMcpInvocation` / `createMcpInvokeTool` (`packages/agent-runtime`) validate call arguments against the tool's synchronized JSON Schema, open a connection through the #231 connection factory, invoke over the configured stdio/SSE/HTTP transport, map the result to an `AgentTool`-shaped `{error, result}`, and always close the connection afterwards.
- Unknown, inactive, ungranted, spoofed, or schema-invalid calls are rejected before any transport is touched.
- Resolution is split from execution so a future approval-queue composition root can gate on `target.requiresApproval` / `target.riskClass` without this adapter implementing any waiting itself.
- The shared stdio/sse/http MCP contract test servers were extended with an identical `tools/call` handler so all three transports are exercised by the same test matrix.
