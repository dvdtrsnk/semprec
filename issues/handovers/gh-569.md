## What the module exports
- **`LABELS`** (frozen) and **`PUBLISHER_LOGIN = "bb-agent-relay[bot]"`**.
- **Render and parse functions for the four markers:** finding, harvest, epic and result.
  - A marker only counts when it is the entire line. Trailing whitespace and `\r` are trimmed first; leading whitespace is not. A marker quoted inside a table cell, a JSON string or a sentence is ignored.
  - Parsing uses anchored regexes, so a malformed line is ignored. That covers a wrong version, a missing field, an uppercase key, a key of 9 or 11 characters, leading zeros, and `prs` lists that are unsorted or contain duplicates.
  - Numbers beyond `Number.MAX_SAFE_INTEGER` are also rejected.
- **Render functions throw a `TypeError`** on any argument outside the grammar. `renderHarvestMarker` also throws on an empty, unsorted or duplicate list.
- **`findingId({ pr, key })`** returns `"<pr>:<key>"`.
- **`computeLedger(issues)`** is pure and returns `harvested`, `terminal`, `harvestedPrs` and `epics`:
  - Only issues labelled `followups:harvest` or `followups:issue` contribute.
  - Comments count only on harvest issues, only when `PUBLISHER_LOGIN` wrote them, and only when they carry a result marker.
  - When two epics name the same harvest, the lower issue number wins, whatever order the issues arrive in.
  - Whether an issue is open or closed makes no difference.
  - It checks the shape of its input and throws a `TypeError` on a malformed issue or comment. The issues come from GitHub, so they are a boundary (rule 4 of the repository-scripts review rules).

## Two choices the issue left open
- An issue with **both** pipeline labels is treated as a `followups:issue` for `terminal`: its body findings go into `terminal` as well as `harvested`.
- `harvestedPrs` collects every harvest marker in a harvest body, not just the first. `parseHarvestMarker` itself returns the first marker, as the issue specifies.
