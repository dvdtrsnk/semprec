# Handover for gh-1399

Added streaming text-to-speech to `semprec-ai-gateway`: a loopback route `POST /internal/tts/stream`, an OpenAI adapter, an accounting helper in `packages/ai-gateway` and a caller function in `packages/ai-gateway-client`.

- **Route** (`ttsStreamHandler.ts`, wired in `app.ts` and `serve.ts`): `/internal/tts/stream` is in `GATEWAY_ENDPOINTS`. Bearer token (401), optional `x-semprec-tenant-id` (400 when malformed, as on the other HTTP routes). Body `{text, voice}` capped at 32 KiB (413); `text` non-empty and at most 4000 characters (`MAX_TTS_TEXT_CHARS`), `voice` one of the provider's `voices` (400 `validation_failed`). The response is chunked raw PCM s16le mono 24 kHz (`audio/L16; rate=24000; channels=1`), written as the provider produces it.
- **Errors**: 403 `budget_exceeded` before any provider call; 502 `provider_failed` when the provider cannot start or produces no audio; 503 `tts_capacity_exhausted` (+ `Retry-After: 1`) over `MAX_CONCURRENT_TTS_STREAMS` (8), checked after auth and before the body is read. A provider failure after audio was sent ends the response without the chunked terminator (the caller's read fails) and settles the audio produced.
- **Accounting**: `synthesizeSpeech(pool, ctx, produce)` in `packages/ai-gateway/src/gateway.ts` runs the existing reserve step (lock, tenant-active, caps) at `ctx.estimatedCostUsd`, then settles with the `{audioSeconds, costUsd}` that `produce` returns. `produce` resolves with what was produced also on disconnect; zero seconds, or a rejection, marks the row `failed`. Rows have operation `voice_synthesize`. The estimate is `chars / 10` seconds at the configured hourly price (10 chars per second is deliberately below real speech rates, so it is an upper bound); the settle uses the provider's `durationSeconds()` (bytes / 48000). Rows carry no thread, turn or run id yet (as for #1396); #1734 must add attribution.
- **Disconnect**: the request signal aborts the provider fetch and the read; the row is settled with what was produced or failed.
- **Provider**: `audioProviders/openAiSpeechSynthesisProvider.ts` (`gpt-4o-mini-tts`, `response_format: pcm`, 30 s header timeout, 5 min total, 32 MiB audio cap). Voices are OpenAI's built-in ones: alloy, ash, ballad, coral, echo, fable, nova, onyx, sage, shimmer, verse. It reuses `OPENAI_API_KEY`; new required env `AI_GATEWAY_OPENAI_TTS_PRICE_PER_AUDIO_HOUR` (added to `ai-gateway.env.example`, the startup and runtime-role tests). The adapter was not run against the live OpenAI endpoint.
- **Czech listening test not performed.** The ADR makes this adapter's provider provisional until a Czech listening test; I could not run one. Before shipping, someone must run it; if ElevenLabs wins, a new ADR supersedes the provider choice and only the adapter file changes.
- **Client**: `synthesizeSpeech(config, {text, voice, signal})` resolves after the headers with an `AsyncIterable<Uint8Array>` of PCM chunks. Failures are `AiGatewayFailedError` with `budget_exceeded`, `timeout` or `http`; a stream over 32 MiB is `invalid_response`. Stopping the iteration early cancels the request.
- **Dispatcher**: `createDispatcher` takes the TTS options as an optional fifth argument so existing suites that never reach the route are unchanged; `serve.ts` always passes it. Without it the route answers 404.
- **Shared code**: `audioHandler.ts` now exports `readJsonBody(req, maxBytes)`, `PayloadTooLargeError`, `sendJson` and `abortOnDisconnect` for the new handler.
- **Tests**: `ttsStream.test.ts` (first chunk before the provider finishes, settle with real duration, reserved estimate, budget refusal without a provider call, abort leaves no `reserved` row and settles/fails correctly, provider failure cases, concurrency limit, validation, auth, no text in logs), `tenantIsolationGateway.test.ts` now covers the new endpoint, `synthesizeSpeech.unit.test.ts` for the client.
- **Not covered**: the 30 s drain timeout for a caller that stops reading has no test.
- **For dependants**: #1734 calls `synthesizeSpeech` per sentence inside the tenant scope and forwards the PCM chunks as `0x02` frames; #1626 can do the same for a stored message. Each call is one row, so a long answer is several rows.
