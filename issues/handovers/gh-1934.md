## What was delivered

- Confirming a proposal no longer writes the properties the card editor hides. `normalizeHiddenFields` in `inbox/editorSchema.ts` drops, schema-driven, every property whose hidden rule holds: a Task confirmed with `allDay` true stores empty `timeFrom` and `timeTo`, an Event stores `null` for both (also when the envelope carried none), a Project with status `longTerm` stores no date.
- The time part of a datetime field whose `timeHiddenWhen` holds is not written, including a time of day inside the date value itself: a wall-clock or offset value is reduced to its calendar date, an instant (Z or offset) is read in the tenant zone through `dateWithoutTimeOfDay` (new, `calendar/eventTime.ts`), so the Events pre-write transform finds a date-only date and cannot re-derive `timeFrom` and `timeTo`. A value that is not a readable date is left alone.
- `inbox/proposalHiddenFields.ts` (new sibling of `proposalActions.ts`): `normalizeEnvelopeForWrite` normalizes the properties of the envelope and of its primary step, and reads the tenant zone lazily, only when a time-hiding field carries an instant; `assertCardIsNotStdioMcpServer` refuses a card whose stored connection is stdio with a validation error on `transport` before anything is created.
- `normalizeMcpServerProperties` in `mcp/mcpServerProposal.ts` stores an `http` or `sse` connection as `{ transport, url }` without the `command` the envelope carried; a bare-name card is stored unchanged.
- All of it is wired into `confirmProposalWithClient`, inside the confirm's own transaction after `lockLiveProposal`, before any write.

## Entry points and contracts dependents build on

- `normalizeHiddenFields(...)` in `inbox/editorSchema.ts` takes a fifth parameter `hiddenTimeIsNull` (the Events rule; the four-argument form cannot tell Events from Tasks).

- `dateWithoutTimeOfDay` in `calendar/eventTime.ts` uses the same classification and tenant-zone conversion as `deriveEventTimeProperties`.

## Deviations from the specification and spec seams

1. The Task puts the MCP rules under base kind `mcp`, but `deriveInboxCardKind` maps `mcpServers` to a clarify card (no module produces the `mcp` kind in this tree), so `loadCardEditorRules` returns no schema for it and the values edit refuses pseudo keys on it. The MCP rules are keyed on the target database (owner module `mcpServers`) and read `connectionConfig` of the envelope, not the schema's transport and url pseudo fields.
2. The stdio refusal runs before `assertValidEnvelopeForCard`, so a stored stdio envelope answers on `transport`; this changed the field asserted by the existing test `mcpServerWriteHook.test.ts` 'refuses an admin confirming a stored stdio envelope' from `connectionConfig` to `transport` (that file is not in the Touches list). Creating or editing a stdio card still answers `connectionConfig`.
3. `normalizeHiddenFields` has the fifth parameter `hiddenTimeIsNull` (see above).
4. `normalizeEnvelopeForWrite` lives in the new sibling `proposalHiddenFields.ts` because `proposalActions.ts` is at the line cap.
5. Only the primary step of a multi-step card is normalized; a secondary step is not.
6. Deviation 6 of the worker (the time of day inside an Event date left to #1598/#1663) was withdrawn by the fix round: the reduction to the calendar date is now done for every field whose `timeHiddenWhen` holds. Event time derivation and validation stay with #1598/#1663.
7. The Touches line names `editorSchema.test.ts`; the existing file is `editorSchema.unit.test.ts`.
8. No ADR was added: `2026-10-25-server-driven-inbox-editor-schema` already records that hidden fields are not written, and `2026-10-16-stdio-mcp-confined-to-admin-tenants` that a stored stdio envelope is refused again at confirm.
