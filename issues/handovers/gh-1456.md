# gh-1456 — [agent-usage 03/12] Report spend against caps with the exhausted cap and its reset time

Repository-Issue: gh-1456

## Delivered behavior and production wiring

- `getAiUsageSummary(client)` in `backend/packages/data/src/aiGateway/aiUsageSummary.ts` returns `{hasBudget, spentTodayUsd, spentMonthUsd, dailyCapUsd, monthlyCapUsd, exhausted, resetsAt}`. It reads the budget row (`getCurrentTenantAiBudget`), the system timezone (`getSystemTimezone`) and the spend (`getGatewaySpend`). The spend is the function the gateway enforces with, so the figures are the ones that refuse. The module is exported from the data barrel (`index.ts`).
- `exhausted` is `monthly` when a non-null monthly cap is reached (`spent >= cap`), else `daily` when a non-null daily cap is reached, else null. The gateway's own comparison is used. A null cap is never reached.
- `resetsAt` is computed in SQL with the same `AT TIME ZONE` expressions `getGatewaySpend` truncates its windows with: local midnight of the next day for `daily`, the first instant of the next month for `monthly`, both in the tenant's timezone. It is set only while a window is exhausted, otherwise null.
- `createAiUsageSummaryRouteHandler(pool)` in `aiUsageRouteHandler.ts` runs `getAiUsageSummary` inside `withTransaction` and answers `200` with the summary. It reads no request input; the tenant is the one the session scope resolves.
- Registered as the custom route `aiUsageSummary`, `GET /api/ai-usage/summary`, justification `single-consumer-read`, in `schemaCoreModuleManifest.ts`. Listed in `routeMatrix.ts` as `ai usage summary` (tenancy `tenant`, authenticated), mapped to its handler file in `chokePointWriteBoundary.unit.test.ts`, and driven by a case in `tenantIsolationRoutes.test.ts`.
- No migration, no schema change, no write. The existing `GET /api/ai-usage` and its `budgets` field are unchanged.

## Decisions

- **`monthly` takes precedence over `daily`** when both caps are reached, because it blocks longer (decision 1 of the issue).
- **Operator-wide caps are never read or reported.** The summary has no access to the gateway's global caps, so a refusal caused only by them leaves `exhausted` null.
- **A tenant without a budget row reports `hasBudget` false, both caps null, `exhausted` null, `resetsAt` null.** Its spend is still reported, because the spend figures come from `ai_gateway_calls` and not from the budget row.
- **A null cap stays null, never 0.** The `budgets` field of `/api/ai-usage` keeps its own convention (0 for a tenant without a row) and is not changed.
- **The route runs in one transaction**, so the spend windows and the reset instant are computed from the same `now()`. The pool-only form would issue four statements, each with its own `now()`.
- **The gateway refusal is not re-tested in this package.** The acceptance criterion "the next gateway call is refused" is the gateway's existing `assertWithinBudget` (`backend/packages/ai-gateway/src/gateway.ts`), already covered by `gateway.test.ts` (`tenantDaily`, `tenantMonthly` and `noTenantBudget` refusals). This change does not alter the gateway.

## Notes for dependants

- **#1871 (Semp status problem)** reads `exhausted` and `resetsAt`. A window reset is when `resetsAt` passes; a refusal is not reported by this route, so the status needs its own refresh trigger (#2023, #2024).
- **#1903 (account summary)** reads `spentMonthUsd`. It is the same figure the gateway enforces with.
- **`hasBudget` must be checked before the caps.** A null cap with `hasBudget` true means "no per-tenant cap in that window". A null cap with `hasBudget` false means the tenant has no row, and the gateway refuses every call. The two states look alike in the caps alone.
- **The reset instant is a timestamp string** (`toISOString()` of the database instant). Any caller that formats it must use the tenant's timezone, which the response does not carry. The `/api/ai-usage` report carries `timezone`; this route does not.
