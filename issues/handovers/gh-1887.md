## What was delivered

`GET /api/semp/threads/:id/messages` now returns the stored steps of an assistant reply and attaches the live approval state to each step that carries an `approvalRequestId`.

- Stored steps are read back from `semp_messages.steps` through a checked parser (`parseStoredSempReplySteps` in the new `packages/data/src/semp/sempStoredSteps.ts`), not a cast. The key is omitted when the column is NULL. A malformed or unknown stored value throws (`Malformed semp_messages.steps in database row` or `Unknown step kind/status in database row`) and fails the page read.
- `attachLiveStepApprovals` (`mcp/approvalRequestsQueue.ts`) collects the `approvalRequestId` of every step of the page, reads the requests in ONE owner-scoped query, and sets `approval: { status, executionStatus, conflictReason }` on each such step. `conflictReason` is `approvalConflictReason` of gh-1437 (a closed translation key, or null). The input is not mutated; a step without a request id gets no `approval` key; a page without approval steps issues no query.
- `listApprovalRequestStatesByIdsForOwner` (`mcp/approvalRequestsStore.ts`) is the batched read: parameterized `$1::uuid[]` ids and `$2` owner, joined on `agent_runs.actor_user_id` (the rule of `getApprovalRequestForOwner`), RLS scopes the tenant. The existing `listApprovalRequestStatesByIds` of gh-1862 is kept and shares a row mapper with it.
- A missing request, a request of another user and a request of another tenant are all absent from the query result and give `approval: null`, indistinguishable.
- Only the three fields are returned; payload, arguments and execution result are never returned. The stored step summary is never rewritten.
- Handler: `sempThreadsHandler.ts` reads the page with `listSempThreadMessages` (which now selects `semp_messages.steps` and returns it through the checked parser, `sempThreadsStore.ts`) and calls `attachLiveStepApprovals(client, page.rows, ctx.identity.user.id)` in the same transaction.

## Entry points and contracts dependents build on

- Barrel (`@semprec/data`): one runtime export added, `attachLiveStepApprovals` (`publicSurface.test.ts` carries it in sort order). `listApprovalRequestStatesByIdsForOwner` and `parseStoredSempReplySteps` are module-internal to `packages/data` and not exported from the barrel. The type-only exports of `approvalRequestsQueue` were folded into its value export block (inline type specifiers) to keep `index.ts` under the 900-line cap; the set of exported names is unchanged.
- Response shape: an assistant message may carry `steps` (the stored `SempReplyStep` summary of gh-1860), each step with an approval request id also carries `approval: { status, executionStatus, conflictReason } | null`. Clients learn of changes through the gh-1789 invalidation and refetch.
- No route, operation catalog entry, table, migration or job was added; the existing messages route gained an additive `steps` key, so no route matrix, `ROUTE_CASES` or `ROUTE_HANDLER_FILES` change was needed.
