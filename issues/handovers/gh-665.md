I blocked deleting a property while a rollup still aggregates it, and committed the change on this branch (`a2f8899`). `pnpm run verify` in `backend/` finished with exit code 0. I didn't run `web/` verify because the diff doesn't touch `web/`.

**Why:** deleting a non-relation property ran no dependency check, even when a rollup used it as its `targetPropertyKey`. The rollup's `rollup_dependencies` row was left pointing at a key no property has. After that, the rollup summed an empty value on every item without any error. If someone recreated a property under that key, writes to it would start recompute jobs for the rollup.

**Change:**
- **`rollup/mirror.ts`:** new `assertSourceDeletable(client, sourceDatabaseId, sourcePropertyKey)`. It looks up the rollups that depend on the property and, if there are any, throws `ValidationError("Cannot delete a property that dependent rollups still aggregate", { dependentRollups })`. That is the same 400 `validation_failed` shape and `dependentRollups` detail that `assertRelationDeletable` already returns for relations.
- **`chokePoint/propertyOps.ts`:** `propertyDeleteWithClient` calls the new guard for every non-relation property before `propertiesStore.deleteProperty`. It runs in the caller's transaction, so the check and the delete can't be split by another write. It covers `DELETE /api/properties/:id` and the approved-operation executor.
- As with relations, the user deletes the rollup first. Removing a property does not also remove the rollups that use it.

**Test** (`__tests__/propertyOps.test.ts`, integration): a Projects database has a `sum` rollup over the `amount` property of a Tasks database.
- Deleting `amount` fails with `ValidationError`, `details` is `{ dependentRollups: [rollup.id] }`, and the `amount` row is unchanged.
- An unrelated `note` property in Tasks can still be deleted.
- After the rollup is deleted, deleting `amount` succeeds.

The full backend run had one error Vitest couldn't tie to a test: a Postgres connection shut down by an administrator command while `czechHunspellSearch.test.ts` was running. That file has nothing to do with this change, and all tests passed (157 files, 1907 tests).
