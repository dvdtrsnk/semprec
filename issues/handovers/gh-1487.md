# Handover for gh-1487

`GET /api/blobs/:id` now serves a blob's bytes from either storage root, so a mail attachment (stored under `MAIL_ATTACHMENTS_DIR`) downloads, and so does an upload deduplicated with an attachment. The work is committed locally; I did not push or open a PR.

- **Helper:** `backend/packages/data/src/blobs/openBlobFromRoots.ts` exports `openBlobFromRoots({ primary, alternate, storageKey, range? })`, which returns an opened readable stream or `null`. It tries `primary`, and only on `ENOENT` the same key in `alternate`. Any other read error is thrown with no second attempt. It also exports `primaryRootForBlob(client, blobId)`, which answers `"mailAttachments"` when the blob has a `mail_attachments` row for the tenant in scope and `"files"` otherwise. Both are exported from `@semprec/data` together with the `BlobRootName` and `OpenBlobFromRootsInput` types.
- **Export:** `tenantExportJob.ts` drops its private `openBlob` and calls the helper. It still picks the primary root with its existing cursor `EXISTS` query, so the archive is unchanged.
- **API:** `createBlobsRequestListener` options are now `{ files, mailAttachments }`. The stream is opened before any header is written: neither root has the file gives 404 `not_found`, and any other read error gives 500 `internal_error`. `createDispatcher` takes an optional `mailAttachmentStorage` and falls back to `blobStorage` when it is absent, so existing tests need no change. `serve.ts` builds it from `MAIL_ATTACHMENTS_DIR`.
- **Tests:** `blobsPerTenant.test.ts` gains five cases:
  - an attachment served from the mail root, whole and ranged;
  - a deduplicated attachment blob whose bytes are only in the files root;
  - an upload whose bytes are only in the mail root;
  - neither root has the file, which answers 404;
  - an `EACCES` read error answers 500 and the other root's `readStream` is not called.
  The foreign-tenant case now also asserts that the mail root is not opened. `blobsHandlerAbort.test.ts` passes both roots.
- **Sent folder:** a `mail_attachments` row has no folder, so a Sent-synced attachment has the same shape as an inbox one. The test does not model folders separately.
- **Checks:** `blobsPerTenant`, `blobsHandlerAbort`, `filesAndBlobsHandler` pass. `tenantExport` passes except one assertion on the 7-day `expires_at` offset (a 1-hour difference, likely a DST artifact of this host). That assertion does not touch blob reading. Typecheck, eslint and prettier are clean on the touched files.
- **For #1491:** reuse `openBlobFromRoots` and `primaryRootForBlob` from `@semprec/data` to read attachment bytes when building outgoing MIME.
