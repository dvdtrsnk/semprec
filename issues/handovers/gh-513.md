This moves the relation edge writes out of `chokePoint.ts` into the new file `backend/packages/data/src/chokePoint/relationOps.ts`, with no change in behavior. It closes #513 (part of epic #494).

Skills loaded: only `implement-issue`. This is a verbatim move, so there are no new writes, edges, failure paths, keys or schema changes for the topic skills to cover. No ADR is needed because the pattern is the one this extraction batch already uses.

- It imports the edge-context helpers from `relationEdgeContext.ts` and `enqueueRollupRecomputeForEdge` from `rollup/recompute.ts`. It does not import `assertDatabaseNotArchived`, because the moved code never calls it directly.
- In `chokePoint.ts`, the `// ==== block: relationOps.ts ====` block keeps its marker line and now holds only the `createRelationOps` import plus re-exports of every symbol that file exported before. No caller has to change.
- `ItemRelationRow` is no longer used in `chokePoint.ts`, so I removed it from the top-of-file `../types.js` import. Prettier then put that import on one line.

**One edit outside this issue's block:** lint failed (`no-unused-vars`) because nothing in `chokePoint.ts` uses `type RelationEdgeContext` any more. That binding sits in the `relationEdgeContext.ts` block's import, not in a top-of-file import. The move rules only allow removing unused top-of-file bindings, so I applied that rule to this import as well. Lint cannot pass otherwise. It is a one-line change and nothing else in that block was touched. It could cause a small merge conflict if another open PR edits that same import.
