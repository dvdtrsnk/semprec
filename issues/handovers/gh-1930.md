## What was delivered

- `POST /api/semp/threads/:id/messages/:messageId/regenerate`: `regenerateSempReply` (`semp/sempMessagesStore.ts`), under the thread and message row locks, checks in order `regenerate_not_latest`, `regenerate_after_writes` (stored changes not an empty list, a stored step with an approval request, or an approval request of the run tied by `tool_call_id` to a step or a `tool_use` in the reply's event range) and `regenerate_after_compaction` (a compaction event of the thread's conversation above `event_to_id`). It then inserts the next attempt, sets `replaced_by_message_id` on the old reply and enqueues the turn in the same transaction; 202 `{ messageId }`.
- A replaced reply is hidden from the model: `listSessionAgentRunEventsFromLastCompaction` (`agentRuns/agentRunEventsStore.ts`) leaves the whole event range of every replaced reply out of a thread's reconstructed history, before the replay bounds. A range cut from a tool call fails the existing protocol check.
- The live session is dropped by the turn handler through `SempConversation.ensureFresh`, because `replacedBy` is part of the message token (`getSempMessageToken`); the stale session is paused and a new wake is opened.
- History returns `replaced` on assistant messages. Migrations `0169` (nullable column and the composite tenant foreign key `semp_messages_replaced_by_fkey`, NOT VALID) and `0170` (validates it).
- ADR `docs/adr/2026-11-14-a-regenerated-semp-reply-is-hidden-from-the-model-by-its-event-range.md` records the history-hiding contract.
- The fix round runs the Inbox send guard for a thread of an Inbox item, so a decided proposal answers 409 `proposal_locked`.

## Deviations from the specification and spec seams

1. Same handler seam as gh-1926: `sempThreadsHandler.ts`, `routeMatrix/semp.ts`.
2. Task step 3: the skip is applied in the SQL of `listSessionAgentRunEventsFromLastCompaction`, which the reconstruction consumes; `conversationReconstruction.ts` only got a docstring.
3. Task step 4: `sempConversation.ts` is unchanged. The API process cannot reach the agents process's session registry; the turn handler drops the session through `ensureFresh` because `replacedBy` is part of the message token.
4. Two migrations (add the column and the foreign key NOT VALID, then validate), precedent `0160`/`0161`; the ordinals at the landing are `0169` and `0170`.
5. Where the Task is silent: a done reply stored with `changes` NULL is treated as not known to have made no changes (`regenerate_after_writes`); an approval request is tied to the reply by `tool_call_id`, and one without a tool call id belongs to no reply; a done reply without `reply_to_message_id`, run or event range is `regenerate_not_latest`; an unknown or invisible thread or message is 404.
6. ADR added for the history-hiding contract.
7. `retrySempReply` was refactored onto the shared helpers without a behaviour change.
