## What changed

**`backend/packages/agent-runtime/src/sempConversation.ts`**
- **State:** `entry` and `waking` are replaced by `conversations: Map<tenantId, { entry, waking }>`. The busy check, wake, reuse and failure paths all read and write only the caller's tenant's state. A tenant's key is deleted once it goes back to `{ entry: null, waking: false }`.
- **Scope check:** `send()` reads `currentTenantScope()` synchronously, before any `await`. It throws `"SempConversation.send must run inside a tenant scope"` unless the scope is `{ kind: 'tenant' }`. No run is created and the resolver is not called in that case.
- **Project resolution:** the `projectItemId` option is replaced by `resolveProjectItemId(pool)`. It is called once per wake, inside the caller's tenant scope, before `reconstructHistory` and `createAgentRun`. Its result is used for both.
- **Timers:** `scheduleTtl(tenantId)` fires `runInTenant(tenantId, () => this.pause(tenantId))`. `pause` and `touch` work on that tenant's entry only. `pause` keeps its retry on failure.
- **`clear()`:** it now clears every tenant's timer and state.
- **Docs:** the class doc is rewritten to describe one conversation per tenant, multiplexed by the scope's tenant id, with tenants never waiting on each other.

**`sempConversation.test.ts`**
- The existing 13 cases now use `resolveProjectItemId` and run their `send()` calls inside `runInTenant(tenantZero, …)`.
- A new two-tenant suite uses `createTestTenant`, `getTenantZeroId`, a `semprec_data` runtime-role pool, and a user bound to each tenant. It has six cases, one per acceptance criterion:
  - scope required (no scope and system scope);
  - no cross-tenant busy;
  - per-tenant reuse;
  - per-tenant history;
  - TTL pause;
  - resolver scope.
