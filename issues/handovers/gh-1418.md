# Handover for gh-1418

Added `backend/packages/data/src/calendarTime.ts`, a pure luxon module beside `timezone.ts`, exported from the data package index. It imports nothing from domains.

- **Functions:** `today`, `now`, `dayBounds`, `weekBounds` (Monday to Sunday), `eventEnd`, `taskEffectiveEnd`, `isEnded`, `wallClockToInstant`, `instantToWallClock`. Each takes the zone and an optional `Date` clock. Invalid zones, dates and times throw `ValidationError`.
- **Loader:** `getCalendarClock(client)` reads the zone once through `getSystemTimezone` and returns the helpers bound to it, plus `zone`.
- **Semantics for dependants:**
  - Bounds are half-open: `end` is the start of the next day or week (a day is 23, 24 or 25 hours via `end.diff(start)`).
  - Returned instants are luxon `DateTime` values in the tenant zone.
  - `eventEnd` without `timeTo` is the last millisecond of the last day (`endDate ?? date`); with `"24:00"` it is the following midnight.
  - `taskEffectiveEnd` uses `timeTo`, else `timeFrom` (start equals end, no default length), else the end of the day. Events never use it.
  - `isEnded` is true when `end` is at or before the clock.
  - DST follows luxon defaults: a non-existent wall-clock moves forward, an ambiguous one takes the earlier offset.
- **Tests:** `src/__tests__/calendarTime.unit.test.ts` (15 cases with a fixed clock, covering every acceptance criterion and the loader). Targeted lint, prettier, tsc and the unit test pass; full verify was not run.
