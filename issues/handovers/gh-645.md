## Changes
- **Provisioning** (`deploy/provision.sh`): creates `$SEMPREC_ROOT/data` (`0755 root:root`) and two directories under it, `files` and `mail-attachments` (both `0750 semprec:semprec`). They sit next to `shared` because `shared` is `0700 root:root` and the services couldn't reach anything inside it. `ensure_directory` now takes an optional owner (default `root`). It still skips directories that already exist, so running provision again leaves them and their contents alone.
- **Provision test** (`deploy/provision.test.sh`): the `install` mock now logs each call to `$TEST_STATE/commands`. The test checks that:
  - both directories exist with mode `750`;
  - `install -d -o semprec -g semprec -m 0750 …/opt/semprec/data/{files,mail-attachments}` was logged;
  - a second run keeps a file already stored in each directory and issues no command for `/opt/semprec/data`.
- **Configuration** (`deploy/shared/.env.example`): a new `# ---- Blob storage ----` section after `SEMPREC_MIGRATE_DATABASE_URL`. It sets `FILES_STORAGE_DIR=/opt/semprec/data/files` (written by `semprec-api` and `semprec-transcribe`) and `MAIL_ATTACHMENTS_DIR=/opt/semprec/data/mail-attachments` (written by `semprec-api`'s mail sync). The `MINIO_*` block is unchanged.
- **Code defaults**: new `resolveBlobStorageDir(envVarName)` in `mail/blobStorage.ts`:
  - if the variable is set and not empty, it returns it;
  - under `NODE_ENV=test` it returns the old `/tmp` path;
  - otherwise it throws `` `${envVarName} is not set` ``.

  All four `/tmp` defaults now use it: `serve.ts`, the transcribe `queueRuntime.ts`, `transcriptionTask.ts`, and `worker.ts`'s `mailBlobStorage`.
- **Exports**: added to the `./mail/blobStorage.js` export line in `index.ts`. I also added it to the frozen list in `publicSurface.test.ts`, which the issue didn't mention; that test fails on any new export otherwise.
- **Tests**: new `blobStorageDir.unit.test.ts` (no Postgres). It covers the test-mode `/tmp` defaults, an empty value counting as unset, a set variable being returned under both `test` and `production`, and the error naming the variable under `production`. `process.env` is restored after each case.
