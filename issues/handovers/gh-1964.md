## What was delivered

The Inbox database (`inbox`, schema-locked) gains three properties:

- `captureChannel`: user-owned `select` with the option keys `typed`, `voice`, `share`.
- `sourceApp`: user-owned `text`, the displayed app name.
- `addedAt`: system-owned `date` with `includeTime`, owner process `inbox`, the server time at which the item was accepted.

A fresh seed declares them (`PropSpec` and `createProps` in `seedInboxPipeline.ts` gained `ownerProcess`). A per-tenant cutover, `runInboxCapturePropertiesCutoverMigration`, adds the missing ones to a populated tenant with raw SQL under the `properties` table lock, with the same shape, owner and owner process as the seed; it is idempotent per property key (an existing property is left as it is) and does nothing in a tenant without an Inbox database. Existing items keep the three properties empty; nothing is backfilled.

`POST /api/inbox/items` now requires `captureChannel` (one of `typed`, `voice`, `share`) and accepts an optional `sourceApp`. A missing or unknown channel (also a non-string, null or empty one) is 400 `validation_failed` with `details.field` `captureChannel`. `sourceApp` must be a string without NUL, is trimmed, and is refused (400, field `sourceApp`) when longer than 80 characters after trimming; a value that is blank after trimming is not stored. `createInboxItemWithClient` writes `captureChannel`, `sourceApp` and `addedAt`; `addedAt` is the server clock (`new Date().toISOString()`) at the moment of the write, independent of the sent `date` and `time`, and is written through `allowedSystemKeys: ["addedAt"]` with `systemOwnerProcess` `inbox`. The generic item create leaves `addedAt` empty and neither the generic create nor the generic update lets a user write it (`owner_violation`, field `addedAt`); a user may still change `captureChannel` and `sourceApp` through the generic update.

## Deviations from the specification and spec seams

1. A new sibling module `inbox/captureSource.ts` holds the field validation, because `inboxRouteHandlers.ts` has a 900-line cap and the validation is shared by the seed, cutover, store and handler. It is not in the Task's Touches.
2. A `sourceApp` that is blank after trimming is not stored rather than refused (the spec is silent). Its length is counted in UTF-16 units, like the other limits of the module.
3. `addedAt` is stamped with `new Date()` (no injected clock) and is written for every item `createInboxItemWithClient` creates; `captureChannel` is optional on the helper but required on the route.
4. The existing tests listed under Files were edited, since the route now requires the channel and the seed shape grew. No assertion was weakened.
5. The criterion "a user cannot set `addedAt` through the generic item update" is tested at the choke-point call the PATCH route reaches (`createItemWithClient`, `updateItemWithClient`, `chokePoint.updateItem`), not over HTTP: the data package has no dispatcher. The check is the choke point's owner check on `property.ownerProcess`.
6. The Inbox module manifest version was not bumped (not asked).
