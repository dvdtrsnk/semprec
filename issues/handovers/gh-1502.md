# Handover for gh-1502

Bulk mail is now detected at ingest and stored as `mail_message_meta.is_bulk`. Nothing consumes the flag yet; #1552 gates agent runs on it.

- **Migration:** `0103_mail_message_meta_is_bulk.sql` adds `is_bulk boolean NOT NULL DEFAULT false`. It is additive and rollback-safe. There is no backfill, so rows ingested earlier stay `false`.
- **Detector:** `mail/bulkMail.ts` exports `detectBulkMail` and the `BulkMailHeaders` type. It returns true for `List-Unsubscribe` or `List-Id` present, `Precedence` of bulk, list or junk (trimmed, case-insensitive), `Auto-Submitted` present with a value other than `no`, or a sender local part matching `no-reply`, `do-not-reply`, `mailer-daemon` or `notification(s)`. It never throws; non-string values count as absent.
- **Adapters:** `FetchedMessage.bulkHeaders` (the four raw values, `null` when absent) is filled by IMAP (four headers added to the fetch list), Gmail (payload headers) and Graph (`internetMessageHeaders`, already selected). The reconcile callers spread the message into `ingestEmailMessage`, so `IngestEmailMessageInput.bulkHeaders` arrives without further wiring.
- **Store:** `upsertMailMessageMeta` takes optional `isBulk` (default false) and `MailMessageMetaRow.isBulk` is returned. The `ON CONFLICT DO UPDATE` does not touch `is_bulk`, and ingest computes it only on the first-ingest path, so a repeated sync never changes it.
- **Tests:** `mail/__tests__/bulkMail.unit.test.ts`; header capture in `gmailRestClient.unit.test.ts` and `graphRestClient.unit.test.ts`; `mailSync.test.ts` ingests each acceptance case and checks a repeat ingest leaves the flag unchanged. IMAP header capture has no unit test, because `parseFetchedMessage` is private and no existing harness drives it.
- **For #1552:** read `isBulk` from `MailMessageMetaRow`. Other writers (send, legacy migration) leave it false.
