## What was delivered

The Semp message ref kind `transcriptSegment` is validated, expanded for the model and labelled in the thread history.

- `transcription/transcriptSegmentRef.ts` exports `validateTranscriptSegmentRef` (the per-ref decision), `validateTranscriptSegmentRefs` (reads the segments of every distinct transcript of a message in one statement and decides each ref in memory), `expandTranscriptSegmentRef` (the segments of the stretch plus three on each side, with the speakers' names, for the model context; the stored message holds only the ref, and the expanded text is kept out of the stored message and out of every log) and `labelTranscriptSegmentRefs` (history labels of many refs: name, date and first live Event name of all distinct transcripts in one statement plus one each for locale and time zone, composed in memory with `resolveTranscriptDisplayName`; no segments, speakers or notes are read).
- `transcriptAgentTools.ts` exports `readTranscriptSegmentRange`, `windowTranscriptSegments` and `isTranscriptSegmentRangeFailure`, extracted from `transcript.segment.get` and reused by the ref; the tool's answer is unchanged.
- `validateSempMessageRefs` (error context `context[i]` unchanged), `readSempRefContext` and `resolveSempHistoryContexts` call the kind's functions, as for `sleepNight`.
- Validation rejects with 400 naming the index: a non-transcript item, another tenant's item, an inverted range, a range of no length, a negative or non-finite bound, a range over 15 minutes or over 200 segments. A transcript in the Trash is accepted (shown as recoverable in history; after purge as no longer existing); a range past the end is accepted and clamped when expanded. Renaming the transcript changes the label in history; a transcript named by its Event keeps that label live, trashed and restored, and falls back to the date once the Event is trashed.

## Entry points and contracts dependents build on

- Barrel exports `expandTranscriptSegmentRef`, `labelTranscriptSegmentRefs`, `validateTranscriptSegmentRef`, `validateTranscriptSegmentRefs`.
- Details shape of an expanded ref: `{ transcriptId, startsAt, endsAt, from, to, speakers, segments }` with `index`, `label` and `isContext` per segment; a trashed transcript is expanded with state `trashed`, speaker keys as labels and no speaker mapping. The history label is `Name m:ss-m:ss`; the history keeps the generic state and database key.
- Statement bounds, tested: one statement for the segments of any number of refs of a message (16 refs, 1 statement; 0 for an empty or unusable-range list) and the same statements for a history page of 36 segment refs over 3 transcripts as for a page of one. Decided in `docs/adr/2026-11-13-transcript-segment-refs-resolve-in-batches-and-are-labelled-by-display-name.md`, which narrows the title-property label rule and the batching rule of the accepted ADR `2026-11-06` for this kind only.

## Deviations from the specification and spec seams

1. The Task says the item must be a live transcript, while the acceptance criteria accept a trashed one; the criteria were followed (existing behaviour kept).
2. The Task says `0 <= startsAt <= endsAt`; the shared ref schema (issue 1682) and `transcript.segment.get` refuse `endsAt == startsAt`, so a range of no length is refused too.
3. The message-ref machinery has no per-kind hook registry; the kind is registered by direct calls in the switch, as `sleepNight` is.
4. The worker's deviations 4 (one statement per ref in validation) and 7 (history label resolution reads the detail composition once per ref) are superseded by the review fix: both are batched now (see above).
5. A trashed transcript is expanded with speaker keys as labels and no speaker mapping (`readTranscriptDetail` refuses trashed transcripts); its display name is built from its own name and date and the live Event name.
6. The expansion no longer returns null for a range past the end (clamped, empty segments), and the details shape changed from `{ segments, speakers }`; the existing `sempRefHistory`, `sempMessageRefs`, `sempRefReadContext`, `refExpansion` and `publicSurface` expectations were updated accordingly.
