## Summary

Failed logins are now saved to the database, so the lockout from #232 finally works through `POST /api/auth/login`. Closes #628.

Before this change, the handler ran `login()` inside `withTransaction`. Each failed attempt wrote its `login_attempts` row and then threw `UnauthorizedError`, and the throw rolled the row back. As a result `getFailureStreak` always read 0 over HTTP and password guessing was never throttled.

## Changes

- **`backend/packages/data/src/auth/authActions.ts`**: `login(pool: Pool, input)` now takes a `Pool`, the same pattern as `requestPasswordReset`.
  - `getFailureStreak`, the lockout decision, the user lookup, password verification and both `succeeded: false` records now run directly on `pool` with auto-commit. A failed attempt stays saved even though `UnauthorizedError` is thrown right after it.
  - The success path runs inside one `withTransaction(pool, ...)`: `createSession` plus the `succeeded: true` record that resets the streak. The session row and the success row still commit or roll back together.
  - Unchanged: the return type, the single error message for every failure, and the dummy-hash timing equalisation.
  - The docstring now explains why failures are recorded outside the transaction.
- **`backend/services/semprec-api/src/authHandler.ts`**: the login branch calls `await login(pool, {...})` directly. The `as string` / `as SessionPlatform` casts were removed because they became redundant: the validated `body` fields now narrow directly, and `@typescript-eslint/no-unnecessary-type-assertion` flags the casts. The `ip:` expression is unchanged (that is B2's scope). `withTransaction` is still imported for the other routes.
- **`backend/services/semprec-api/src/__tests__/authHandler.test.ts`**, inside `describe("POST /api/auth/login")`:
  - `LOCKOUT_THRESHOLD` wrong passwords followed by the correct one returns 401. `login_attempts` then holds `LOCKOUT_THRESHOLD + 1` rows with `succeeded = false`, and no session is created.
  - `LOCKOUT_THRESHOLD - 1` wrong passwords followed by the correct one returns 200. `login_attempts` holds `LOCKOUT_THRESHOLD - 1` failures and exactly one success, and exactly one session exists for the user. This covers the second acceptance criterion.

No other call site needed editing: all existing callers already pass a `Pool`, and `pnpm -r run build` passes.
