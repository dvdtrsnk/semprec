# Handover for gh-1430

Proposal history entries can now carry what kind of event they record.

- **Schema:** `proposalHistoryEntrySchema` in `inboxTickAction.ts` gained optional `kind` (closed ten-value enum), `keys` (string array of `ref.key` values), `threadId` and `messageId`. `author` and `message` stay required. The `ProposalHistoryEntry` type picks up the new fields.
- **Helper:** `appendHistoryEntry(history, message, author = "ai", extra?)` spreads `extra` into the new entry. Without `extra` the entry is exactly `{ author, message, at }`. Malformed stored history is still treated as empty.
- **Round trip:** legacy entries without `kind` re-serialize byte-identically on append, and entries with the new fields survive further appends.
- **Tests:** three new cases in `proposalActions.test.ts` (legacy round trip, `userEdit` with `keys` across two appends, `threadRevision` ids). `proposalActions` and `publicSurface` pass; the existing malformed-history test is unchanged and passes.

Notes for dependants:

- The kind enum values are not exported at runtime, because `publicSurface.test.ts` freezes the runtime export list and this issue touches neither. Use `NonNullable<ProposalHistoryEntry["kind"]>` for the type. A later issue that needs the value list must export it and update the frozen surface test.
- No existing writer passes `kind` yet; each later issue sets its own.
- Pass only defined fields in `extra`; an explicit `undefined` is dropped at JSON serialization.
