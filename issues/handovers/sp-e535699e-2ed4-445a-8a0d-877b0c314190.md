# Handover: make the local blob writer consume its source before it creates the directory

Delivered on chain `e1-243-blob-writer`, candidate commit `5f3278f510e265929d4f61b4cb6d7d246101e8a1`, landed by a `--no-ff` merge on `feature/backend-parallel` as the second chain of a train with `e1-236-mail-sync` and `e1-246-mail-oauth`.

**What changed.** `LocalFsBlobStorageWriter.writeStream` in `backend/packages/data/src/mail/blobStorage.ts` now builds the hasher and a `PassThrough` and starts `pipeline(source, hasher, staged)` before its first `await`. `mkdir`, the file pipeline and the wait for the intake run in the `try`. The `catch` destroys `staged` with the caught error (wrapped when it is not an `Error`), waits for the intake without letting its rejection replace the error, runs the existing delete cleanup (a cleanup failure is logged) and rethrows the first error. A child process whose stdout ends while the directory is still being created therefore stores its whole output instead of an empty file. The writer contract is documented on `BlobStorageWriter.writeStream` and in the new ADR `docs/adr/2026-11-15-a-blob-writer-consumes-its-source-from-the-tick-it-is-called.md`; `streamFfmpegToStorage` in `services/semprec-transcribe/src/mediaNormalization.ts` got one comment.

**Contracts dependents build on.** Every `BlobStorageWriter.writeStream` implementation consumes and observes its source from the tick it is called, rejects with the source's own error when the source fails, destroys the source with the error when its own setup fails, and leaves no bytes behind. The ADR binds the future object-storage writer. No interface signature, route, table, migration, operation or job name changed.

**Files.** `backend/packages/data/src/mail/blobStorage.ts`, `backend/services/semprec-transcribe/src/mediaNormalization.ts` (comment only), the ADR above, `backend/packages/data/src/mail/__tests__/blobStorageStreamAttach.unit.test.ts` (new), `backend/services/semprec-transcribe/src/mediaNormalizationSlowStorage.test.ts` (new).

**Tests.** `blobStorageStreamAttach.unit.test.ts`: a real child that exits while `mkdir` is pending; the source has an error listener and flows while `mkdir` is pending; the source's own error with no file and no uncaught exception; the `mkdir` error destroys the source with that same error; `MaxBytesExceededError`; a 4 MiB source with a late `mkdir` stored completely with the right hash. `mediaNormalizationSlowStorage.test.ts`: `normalizeAudio` through a real writer with a `mkdir` held 1.5 s stores non-empty audio. The worker checked that four of six unit cases and the transcribe case fail against the old `blobStorage.ts`. Existing `blobStorage.unit.test.ts` and the `tenantExport.test.ts` storage-initialization case pass unchanged.

**Deviations and spec seams.** No code seam. The unit test mocks `node:fs/promises` as `stalePostgresDirs.unit.test.ts` does. The `maxBytes` and large-source cases open the `mkdir` gate after a settle turn instead of waiting for the source to close, so they also pass at the old code, as the criteria state. The transcribe test uses a 1 s generated ogg fixture and a 1.5 s timer gate. No test was added to the two wrappers the Task names out of scope.

**Criteria NOT RUN or BLOCKED.** None.

Both fixed in `5f3278f510e265929d4f61b4cb6d7d246101e8a1` (comment move only). No security review. No recheck round (comment-only fix). Both reviewers read statically.

**Follow-ups.** None required. A non-`Error` rejection (the wrapping branch) has no dedicated test, and when both the source and `mkdir` fail the `mkdir` error is the one rethrown; neither is covered by a Task step or criterion.
