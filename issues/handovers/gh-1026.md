## What changed
- **Tenant threaded into doc sync** (`docSync.ts`, `syncServer.ts`):
  - `handleOpen`, `handleBinaryFrame` and `fanOutDocUpdate` now take `tenantId`, and all their database work (`getDocById`, `loadYDoc`, `mutateYDoc`, `getDocUpdateById`) runs inside `runInTenant(tenantId, …)`.
  - The frame dispatch passes `identity.tenantId`; the `doc_update` envelope case passes the envelope's tenant.
- **Subscriptions keyed by tenant**: `subscribersByDoc` is keyed `${tenantId}:${docId}`. A reference stamped with one tenant only reaches sockets that opened that doc under the same tenant.
  - The 32-document cap and the rate limit are unchanged.
  - `handleClose` and `handleSocketClosed` keep their signatures. The registry remembers each socket's tenant (a socket has one for its whole life) so they can find the key.
- **Foreign doc behaves like an unknown doc**: another tenant's doc is invisible under RLS, so `handleOpen` takes the existing not-found path. The reservation is released and nothing is sent. A later binary frame for it is dropped by the opened-doc check.
- **Update bound to its doc**: `getDocUpdateById(pool, docId, updateId)` now filters on `doc_id = $2`. A reference whose update belongs to another doc resolves to `null` and takes the existing full-resync branch. The barrel export and `publicSurface` name list are untouched.

## Tests
- `docSync.test.ts` covers, on a runtime-role pool with two tenants:
  - a foreign doc behaving like an unknown id (no frame, no `doc_updates` row written);
  - same-tenant open, persistence with the right `tenant_id`, and delivery to a peer;
  - no cross-tenant fan-out, while the correct tenant still delivers;
  - a forged cross-doc reference giving a full resync with none of the other doc's bytes.
- The compaction-recovery test and the other existing tests pass with the new signatures.
- `syncServer.test.ts` has a new `describe` for the envelope path: a `doc_update` envelope stamped with another tenant reaches no socket, and the correct tenant's does.

## Notes
