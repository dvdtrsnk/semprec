## What was delivered

- `transcription/transcriptEventMatch.ts`: the candidate rule of `matchTranscriptToEvent` is now strict interval overlap in the tenant time zone. For each live Event of type `standup` or `meeting` that has `date` and `timeFrom`, the interval is `[date + timeFrom, (endDate ?? date) + timeTo]`, converted with the existing calendar clock (`getCalendarClock` / `wallClockToInstant` of `calendarTime.ts`, which already handles DST gaps and overlaps). An Event is a candidate when its start is before the recording end and its end is after the recording start; touching boundaries do not overlap. An Event without `timeTo` is a point at its start. All-day Events (no `timeFrom`), type `event`, a `24:00` start, an end before the start and any value `wallClockToInstant` refuses with a `ValidationError` are skipped. Any other failure propagates.
- Candidates are ordered by interval start, then id. `MATCH_WINDOW_LEAD_MS`, `DATE_ONLY_RE` and the Event use of the old `parseDateWithTime` are removed; the transcript's own UTC date is still parsed by `parseRecordingStart`.
- Outcomes (`linked`, `suggested`, `alreadyLinked`, `alreadySuggested`) and idempotency are unchanged. The card's create-Event envelope `date` is now the recording's date in the tenant zone as `YYYY-MM-DD` (it was a UTC instant, no longer a valid Events date). The card history line now reads `N Events overlapped the recording's time interval, so none was linked; proposed a new Event.`
- JSDoc of `matchTranscriptToEvent`, the outcome docs and the `runMatchStep` comment in `semprec-transcribe/src/transcriptionTask.ts` describe overlap.

## Deviations from the specification and spec seams

1. `listOverlappingEventIds` is exported from the module (not from the barrel) so the ordering contract and the rethrow branch can be tested directly.
2. The strict rule is applied uniformly: an Event without `timeTo` whose start equals the recording start or end is not a candidate (the Task says only "falls inside the recording interval").
3. An Event whose end is before its start, or whose `timeFrom` is `24:00`, is skipped as unparsable (not named in the Task).
4. The tenant zone is read once for every non-converged match (see above); previously it was read only when an Event needed it.
5. Events that still carry an instant `date` (before #1598) are no longer matched; #1797 migrated them, and the test for the old behaviour was replaced by a skipped-value case.
6. The dead `1 Event` arm of the history message was dropped.
7. `transcriptProposalActions.test.ts` is outside Touches: its create-Event envelope helper had to follow the new date-only envelope, otherwise the case "rejects a link target in the wrong database" failed.
8. No change to the calendar time module was needed: `wallClockToInstant` already exists.
