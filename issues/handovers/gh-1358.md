# Handover for gh-1358

`ProposalComputationInput` has a new required field, `locale`: the language the proposal's person-facing texts must be written in. The Inbox tick (`createSemprecTickAction`) fills it from `users.locale` and falls back to `cs` when the tenant has no bound user.

- **Read:** `readTickSnapshot` calls `getTenantUserLocale(client)` inside the existing repeatable-read read transaction, just before it returns the snapshot. It defaults `null` to `cs` and stores the result in `TickSnapshot.locale`. Paths that end the tick without an AI call do not read it.
- **Unchanged:** the fingerprint (`computeInboxFingerprint`) and the locked, unchanged and stale-source behaviors. A locale change does not invalidate an existing proposal; only the next computed one uses the new locale.
- **Tests:** `inboxTickProposal.test.ts` has two new cases. A tenant user with locale `en` makes `computeProposal` receive `en`. A tenant with no user makes it receive `cs`. Existing test doubles needed no change. `inboxTick.test.ts` passes unchanged.
- **For dependants:** any real `ComputeSemprecProposalFn` implementation must read `input.locale` when writing the texts (the LLM prompt is out of scope here). Tests must run the tick inside `runInTenant(...)` to resolve a user's locale; without a tenant scope the lookup returns `null`, so the tick uses `cs`.
