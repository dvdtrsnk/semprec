## What was delivered

- `retireSupersededSempDrafts(client, { threadId, ownMessageDate, excludeDraftItemId? })` in `mail/draftRetirement.ts` lists the unsent agent drafts of the thread (also those whose thread was merged into it through `mail_thread_aliases`) whose source message is older than `ownMessageDate`, locks each (Emails item, then `mail_drafts` row), re-checks it under the lock, retires it with the system writer through the choke point trash and deletes its `mail_drafts` row (the shared steps are `trashLockedDraft` in the new `mail/mailDraftTrash.ts`, also used by `discardEmailDraft`), returns the retired item ids and announces the thread once when it retired any.
- Kept: a draft of the user, a draft the user edited (`last_edited_by` must be `agent`, fix round), the excluded draft, a sent or claimed draft, a draft without a source message or with an unreadable source date, a draft of another thread or tenant, a draft in the Trash, and a draft whose source is as new as or newer than the message.
- Called by `sendDraftEmail` in its finalizing transaction (excluding the sent draft, `ownMessageDate` = send time) and by `ingestEmailMessage` for a newly stored message that is the user's own: the sender is one of the registered addresses of the mailbox being ingested, or the message is filed in the Sent folder; a message filed in the Drafts folder is never a sent message (fix round). A message that converged onto an existing item retires nothing.
- ADR `docs/adr/2026-11-14-retiring-an-outdated-semp-draft-takes-the-steps-of-a-discard-as-the-system.md`.

## Entry points and contracts dependents build on

- `retireSupersededSempDrafts` (imported by path from `mail/draftRetirement.ts`; not exported from `index.ts`); `trashLockedDraft` in `mail/mailDraftTrash.ts`; `isOwnMessage` in `mail/ingest.ts` (uses `IngestEmailMessageInput.mailboxAliases`).
- Attach and detach of a draft file now record `last_edited_by` like an update does.
- Retiring deletes the `mail_drafts` row as a discard does (ADR 2026-11-13 on discarded drafts), because an unsent agent row would hold the thread under the one-per-thread index; the gh-1694 handover said the row may stay.
- The thread invalidation of a retirement is a second, identical announcement when the caller announces the same thread for its own reason.
