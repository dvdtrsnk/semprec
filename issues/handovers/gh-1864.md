## What was delivered

- The `mail` thread group of global search (`search` operation, `GET /api/search`, MCP search tool): `mailGlobalSearchGroup` in `data/src/mail/mailGlobalSearchGroup.ts`, a `ThreadSearchGroup` registered in `domainWriteHooks.ts` through `registerThreadSearchGroup` (before the `chat` group, so the answer keeps the order of `SEARCH_GROUP_TYPES`).
- One entry per mail thread, total counts threads (not messages). The entry is represented by the thread's last live message: `threadId`, `itemId`, `databaseId`, `databaseKey` of that Emails item, the subject as `title`, subtitle parts `sender` (name from the envelope, `itemId` of the People item when the sender is a stored person and the actor may read People) and `date` (the thread's last message instant), and a `snippet`.
- The snippet is the `ts_headline` fragment of the newest message whose own stored body matches the words (at most five candidates per thread are examined), else the preview of the last message capped at 160 characters.
- The thread search of gh-1639 is reused: the same copy CTEs, `matchesSearch` operators (`from:`, `before:`, `after:`, `has:attachment`, `is:`), order (newest first) and cursor as the thread list. A text with no condition, contradictory operators or an invalid date match nothing. Deleted messages, and threads that exist only in Junk, Trash or Drafts, are not found.
- Actor rule: a person sees the group; an agent run gets it only when the Emails database is readable for its project (archived Emails database yields nothing). The sender's People item id is left out for an agent whose project cannot read the People database.

## Deviations from the specification and spec seams

1. The contribution seam is the search group registry (ADR 2026-11-13), so the group registers in `domainWriteHooks.ts`, not in `mailModuleManifest.ts`; no export in `index.ts`.
2. The Task names `itemId`/`databaseId`/`databaseKey` beside `threadId`, while `SearchThreadResultSchema` was strict with `threadId` only; a `SearchMailResultSchema` was added as a union member.
3. The `date` part value is the thread's `lastMessageAt` instant as the Task says, although the schema comment for kind `date` describes `YYYY-MM-DD`.
4. Interpretations where the Task is silent: threads only in Junk, Trash or Drafts are not found; an invalid `before:`/`after:` operand or a text with no condition matches nothing instead of failing or matching everything; the sender value falls back to the address when the name is empty and the part is omitted without a `From`; the agent rule and the sender item id follow the item groups' `listUnreadableDatabaseIds` practice.
5. Behaviour-preserving refactor outside `Touches`: `mailThreadListQuery.ts` exports the CTE, cursor parser and date check, used by `mailThreadRoutes.ts`; `searchItemsQuery.ts` docstrings updated.
6. The accent fold of `from:` on uppercase non-ASCII letters depends on the database locale (`lower()` under the C locale); not changed, the test uses ASCII uppercase.
