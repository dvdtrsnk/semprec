## What changed

`backend/packages/agent-runtime/src/sempConversation.ts`. The only change is to how `send` picks its state synchronously:

- **Finding `9ab71bfd46`:** the derived `const entry = state?.entry ?? null` and the redundant `if (state && entry)` guard are gone. The busy/waking/dropped rejection now reads `state?.entry?.busy || state?.waking || state?.dropped` and still runs before any dispatch. The continuation branch is `if (state?.entry) { const entry = state.entry; ... }`. This narrows `state` and gives a non-null `entry` taken from that narrowed state. No casts or non-null assertions were added. The continuation body itself is unchanged.
- **Finding `7ed04754a3`:** a new wake now always allocates a fresh `{ entry: null, waking: false }` TenantConversation, which is then marked `waking = true` for the reservation. The old `state ?? ...` fallback is gone. This branch is reached only when there is no state, or the state has no entry and is neither waking nor dropped. `releaseIfIdle` already deletes that kind of idle state, so no lifecycle behaviour changes.

`releaseIfIdle`, `dropTenant`, the TTL and retry policy, and the state variants are untouched.
