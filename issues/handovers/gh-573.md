This adds `.github/scripts/review-followups/github.mjs`, the GitHub access layer the review follow-ups scripts (harvest, triage `prepare`, triage `publish`) will share. It is a zero-dependency ES module that reaches GitHub only through `fetch` and `GITHUB_API_URL` / `GITHUB_GRAPHQL_URL` / `GITHUB_TOKEN` / `GITHUB_REPOSITORY`, so it works both on GitHub Actions and behind Relay's loopback token proxy. Tests are in `github.test.mjs` next to it.

## Changes
- **Transport** — `createGitHubClient({ apiUrl, graphqlUrl, token, repository, fetchImpl })` returns `{ repository, request, paginate, graphql }`:
  - `request` sends the four headers; `Content-Type` only when there is a body. It returns the parsed JSON, or `null` on 204.
  - Any non-2xx response throws an error with the method, path, status and at most 300 characters of the response text. The token is replaced with `[redacted]` before the text is cut, even when the response echoes it back.
  - `paginate` follows `rel="next"` links and throws on a page that is not an array, on any non-2xx page, or after 100 pages.
  - `graphql` returns `data` and throws on a non-2xx response, on a non-empty `errors` array (its first message is included), or when `data` is missing.
- **`clientFromEnv`** — `GITHUB_API_URL` defaults to `https://api.github.com` with trailing slashes removed, and `GITHUB_GRAPHQL_URL` defaults to `<apiUrl>/graphql`. It throws naming `GITHUB_TOKEN` or `GITHUB_REPOSITORY` when either is missing, or when `GITHUB_REPOSITORY` is not `owner/name`.
- **Read endpoints** — all ten from the Task. Each returns exactly the listed shape, and every field it reads is checked (integer, string, array…); an unexpected shape throws instead of being passed on (repo-scripts rule 4).
  - `listReviewThreads` returns authors in REST form: a `Bot` author gets `[bot]` appended and a `null` author becomes `ghost`. It throws when a thread has more than 100 comments.
  - `listTreePaths` throws on `truncated: true`.
- **Write endpoints** — `createIssue`, `addLabels`, `removeLabel`, `closeIssue`, `createComment`, `addSubIssue`.
  - `removeLabel` treats a 404 as done. It is the only non-2xx the module does not throw on, and the reason is documented at the function: a re-run after a crash must not fail on a label that is already gone.
  - Issue numbers and `childId` must be positive integers, checked before any request is sent.

## Decisions a reviewer should see
- **`paginate(path, { pick })`**: a commit's files come back as pages of an *object* (`{ files: [...] }`), not an array. `getCommitFiles` therefore passes `pick` to take the array out of each page but still follows the `Link` header. The spec's `paginate(path)` signature is unchanged.
- **Next link on another origin**: `paginate` throws instead of following it, so the bearer token is only ever sent to the configured API.
  - **Open risk**: I could not check whether Relay's proxy rewrites GitHub's `Link` headers. If it doesn't, pagination through the proxy will fail with this error (it would also fail without the check, with a 401 from GitHub using the placeholder token). If the proxy leaves them unrewritten, the proxy issue should rewrite them.
- **Timeout**: every request has a 30-second timeout (`AbortSignal.timeout`), per `io-hardening`.
  - **No response-size cap**: a recursive tree of the repository is legitimately large, and the only server is the configured GitHub API.
- **No retries or back-off**: out of scope in the issue.
