# Handover for gh-1412

Item envelopes now carry an additive top-level `blobs` field with the size, type and filename of the blob behind every `file`/`image` property. `properties` is unchanged. The work is committed locally; I did not push or open a PR.

- **Data helper:** `packages/data/src/blobs/blobMetadata.ts` exports `loadBlobMetadataForItems(client, items)` (and types `BlobMetadata`, `ItemBlobMetadata`) from the data barrel. It resolves property types for the items' databases in one query (`listPropertiesByDatabases`), collects the `blobId` of each `file`/`image` property, and reads `blobs` once with `id = ANY($1::uuid[])` under the caller's tenant scope (RLS hides other tenants' rows). Returns `Map<itemId, Record<propertyKey, { blobId, byteSize: number, mimeType, filename: string | null }>>`; a missing or invisible blob, or a non-UUID `blobId`, is skipped. No `blobs` query is sent when no item has a blob.
- **Filename:** derived from the last storage-key segment `<uuid>-<safe filename>` (`filenameFromStorageKey`); `null` for any other shape. No schema change.
- **Envelope:** `ItemEnvelope.blobs?` is omitted (not `{}`) when empty. `toItemEnvelope` stays synchronous and blob-free (used by the version-conflict `currentItem`); `toItemEnvelopes(pool, items)` and `toItemEnvelopeWithBlobs(pool, item)` in `adapter/itemEnvelope.ts` add the field with one lookup per response. `toItemQueryEnvelope` is now `async` and takes `pool`. They must run inside the tenant scope.
- **Wiring:** `itemsHandler.ts` (create, get, patch, delete, restore, `database.query`; for `?include=path` the field is added for the item itself, not the breadcrumb), `viewsHandler.ts` (`view.query`; `createViewRoutes` now takes `pool`), `filesHandler.ts` (upload response), and `adapterRoute.ts` (item results are converted to the envelope inside the tenant scope; `sendItemResponse` removed).
- **Docs:** the repository has no OpenAPI document or response schema for the item envelope; the `ItemEnvelope` interface docstring is the description and now documents `blobs`.
- **Tests:** `blobs/__tests__/blobMetadata.test.ts` (file and image, null filename, missing/non-UUID blob, 50 items with exactly one `blobs` query, another tenant's blob on a `semprec_data` runtime-role pool); API cases in `filesAndBlobsHandler.test.ts` (upload response, GET, database query, no `blobs` key for an item without a file). `publicSurface.test.ts` has the new export name.
- **Not covered:** `relation.list` and `include=relations` results do not carry `blobs` (out of scope, #1518). `view.query` and the version-conflict envelope are not exercised by a dedicated blobs test.

Notes for dependants:

- #1518 can reuse `toItemEnvelopes(pool, items)` for related items; it is one lookup however many items.
- An upload with an unrecognised type is stored as `application/octet-stream`, so `mimeType` reflects the detected type, not the request header.
