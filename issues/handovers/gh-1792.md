## What was delivered

- `resolveSleepNights({ settings, plans, nights, from, to, timezone })` in `backend/packages/data/src/sleep/resolveSleepNights.ts`: a pure function without I/O that returns the planned nights of the inclusive range `from`..`to` in ascending order.
- For each date of the range:
  - the wake day is the weekday (`mon`..`sun`) of the following morning;
  - the plan is the first plan, ordered by `position` and then by `id` (compared by code unit), whose `wakeDays` contain it;
  - the exception of that night overrides the plan field by field; a null field follows the plan;
  - a night with neither a plan nor an exception that overrides a field is left out;
  - a night without a plan whose exception overrides a field starts from 23:00, 07:00 and no alarm, with `planId` and `planName` null.
- Each returned night is `{ night, planId, planName, bedTime, wakeTime, alarm, changed, bedAt, wakeAt, durationMinutes, prepReminderAt }`:
  - `changed` is true when the exception has at least one non-null field;
  - `bedAt` is on `night` when `bedTime` is 12:00 or later, otherwise on the day after; `wakeAt` is on the day after; both are ISO strings with the zone's offset, converted with `calendarTime.wallClockToInstant`;
  - `durationMinutes` is the difference of the wall-clock times, not elapsed time, and 0 when the wake time is not after a bedtime that lies after midnight;
  - `prepReminderAt` is `bedAt` minus `settings.prepReminderMinutes`, or null when `settings.prepReminder` is false.
- `ValidationError` for a `from` or `to` that is not a real `YYYY-MM-DD` date (field `from` or `to`), for `from` after `to` (field `from`) and for an invalid zone (field `timezone`).
- No migration, route, generic operation, job name, write hook, tenant cutover entry, module manifest entry, stored key or i18n key was added.

## Contracts dependents build on

- Runtime export of `@semprec/data` added by this source: `resolveSleepNights` (in the expected list of `publicSurface.test.ts`). Type exports: `ResolveSleepNightsInput`, `ResolvedSleepNight`, `SleepNightsSettings`, `SleepPlan`, `SleepNightException`.
- Input types:
  - `SleepNightsSettings`: `{ prepReminder: boolean; prepReminderMinutes: number }`;
  - `SleepPlan`: `{ id, name, wakeDays: readonly string[], bedTime, wakeTime, alarm: boolean, position: number }`, non-deleted plans only;
  - `SleepNightException`: `{ night, bedTime: string | null, wakeTime: string | null, alarm: boolean | null }`.
- **The caller maps an absent property to null.** `changed` and the omission test `!== null`, while the values fall through with `??`. The types forbid `undefined`; a loader that passes it would get a night that follows the plan and is still marked changed, and a planless night that exists. This concerns the loader of gh-1809.
- **An exception with every field null counts as no exception** (first fix round). On a planned night it changes nothing and `changed` is false; on a night without a plan the night is absent, exactly as without the item. gh-1835 resets a night with a PUT of all nulls and keeps the item, so after a reset on a planless night the resolver returns no night.
- **The resolver always computes nights**, also when the settings say the plan is switched off. It does not read `enabled`; callers decide.
- The size of the range is not bounded here. The route (gh-1809) owns the range rule.
- Daylight saving follows `calendarTime.wallClockToInstant`: a wall-clock time that does not exist moves forward (02:30 on 2027-03-28 in Europe/Prague becomes 03:30+02:00, the same instant `computeNextFireAt` gives) and an ambiguous one takes its earlier occurrence.
- **Rendering of offset zero.** The fixed zones `UTC` and `GMT` render `Z`; an IANA zone at offset zero, such as `Etc/UTC`, renders `+00:00`. Every other zone carries a numeric offset. A client must not compare these strings as text.
- With two exception objects for one night the later one in input order is used. gh-1784 is to keep one per night.
- The input arrays are not mutated; the plans are sorted on a copy.
- The weekday keys `mon`..`sun` and the field names equal the property keys and select options seeded by gh-1776 (`seedSleepModule.ts`).

## Deviations from the specification and spec seams

1. **The Context decision and Task step 2 disagree on one case, and the Task was followed.** The Context says "a night with an exception but no plan uses the base"; Task step 2 says "an exception with all fields null changes nothing". For a planless night whose exception has every field null the delivered code leaves the night out. The worker first implemented the Context reading; the requirements reviewer raised it as a medium finding and the first fix round changed it. The record still carries the Context sentence. The fixer suggests it say "an exception that overrides a field".
2. Names the Task leaves open: the types `ResolveSleepNightsInput`, `ResolvedSleepNight`, `SleepNightsSettings`, `SleepPlan` and `SleepNightException`; the `ValidationError` names the field `from`, `to` or `timezone`, and `from` after `to` names `from`.
3. Two more `ValidationError`s than the Task lists: a bedtime or wake time that `wallClockToInstant` refuses (its own error, field `time`) and an instant luxon cannot render (field `instant`, reachable only with an absurd `prepReminderMinutes`). Both are tested.
4. Two exceptions for one night: the later in input order wins. The Task does not say; no test pins it.
5. The dates of the range are iterated as UTC calendar days and only the wall-clock conversion uses the tenant zone.
6. `publicSurface.test.ts` is outside `Touches`; the barrel change requires it.
