## What was delivered

- `searchMailContacts` in `backend/packages/data/src/mail/personEmailIndexStore.ts` binds the search text itself as `$1`. The statement builds the pattern once, in a CTE `needle AS MATERIALIZED`: `unaccent($1::text)` first, then `replace()` of the backslash, of `%` and of `_` in the folded text (the backslash first), then `%` on both sides. The `contacts` CTE cross-joins `needle` and uses `needle.pattern` as the right side of both `ILIKE ... ESCAPE '\'` comparisons, the name and the address. Nothing is concatenated into the statement.
- A search text of which folding leaves nothing returns no contacts: the `needle` CTE has `WHERE folded.text <> ''`, so it yields no row and the cross join yields no contact. A lone combining mark such as U+0301 is such a text.
- `escapeContactSearchPattern` is removed from `personEmailIndexStore.ts`, and its unit test file `backend/packages/data/src/mail/__tests__/mailContactsSearch.unit.test.ts` is deleted. No reference to either remains under `backend/`.
- Three new cases in `backend/packages/data/src/__tests__/mailContactsRoute.test.ts`, through `createMailContactsRouteHandler` on the pool of the runtime role `semprec_data`. The thirteen existing cases of the file are unchanged.

What a caller sees: a `q` of U+FF05 or U+FE6A (which `unaccent` folds to `%`), of U+FF3F (to `_`) or of U+FF3C, U+FE68 or U+2216 (to a backslash) now matches only contacts whose name or address contains that ASCII character. Before, such a `q` returned every contact of the caller's tenant, matched any one character, or escaped the character after it. The read always ran in the session's tenant scope, so this corrects a wrong suggestion list, not a leak.

## Contracts dependents build on

- `searchMailContacts(client: Queryable, query: string, exclude: string[], limit: number): Promise<MailContact[]>` keeps its signature, but the meaning of `query` changed: it is the raw search text, not a `LIKE` pattern. A caller must not escape it and must not add `%`. Its only caller is `createMailContactsRouteHandler` in `backend/packages/data/src/mail/mailContactsRoute.ts`, which passes the trimmed `q`. The function is not exported from the package barrel.
- `escapeContactSearchPattern` no longer exists. It was never exported from `@semprec/data`.
- An empty fold returns `[]`. This differs on purpose from the Semp thread list (`sempThreadsListStore.ts`), where a NULL pattern means "no filter": the Task of this source requires "no contacts". The route still answers an empty or whitespace-only `q` without calling the store; a `q` of combining marks alone is not empty after the JavaScript `trim()`, reaches the store and gets `[]` from the `needle` guard.
- The statement relies on the `unaccent` extension, as before, and on `standard_conforming_strings`, as the `ESCAPE '\'` of the same statement already did.
- `GET /api/mail/contacts` is otherwise unchanged: validation, limits, ordering, the `exclude` handling and the response shape `{ contacts: [{ personId, name, email, relationship }] }`. `mailContactsRoute.ts` is not in the diff.
- No route, no generic operation, no MCP tool, no table, no migration, no job, no barrel export, no error code, no module manifest entry and no entry in `domainWriteHooks.ts`, `tenantCutoverMigrations.ts` or the route matrix was added or changed.
- No shared escape helper for the other `LIKE` call sites was added; the Task puts it out of scope. `views/filterCompiler.ts` escapes its pattern and does not fold it, so it does not have this defect.
