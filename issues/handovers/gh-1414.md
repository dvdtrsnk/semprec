# gh-1414 — Pass a per-tenant context to module data migration converters

Repository-Issue: gh-1414

This completion is proposed on an isolated implementation branch; it becomes canonical only after reviewed integration. No PR has been published by this worker.

## Delivered behavior

- `ModuleDataMigrationConverter` is `(properties, context) => properties`, and `ModuleDataMigrationConverterContext` is `{ timezone: string; itemId: string; log: (reason: string) => void }`. Both types are declared once in `module-registry/src/registry.ts` and exported from `@semprec/module-registry`. `ModuleDataMigrationDefinition.converter` uses the new type. `@semprec/data` re-exports the converter type from `migrationJob/moduleDataMigration.ts`, so existing imports keep working.
- A converter that declares only `properties` compiles and behaves as before. `backfillTaskTimeProperties` and every existing test converter are unchanged.
- `runModuleDataMigration` reads the tenant's time zone once per run that converts items, with `getSystemTimezone`, after the per-tenant advisory lock is taken and before the first batch. A run that finds the transition already recorded, or already held by another runner, reads nothing.
- Every item gets its own context: `timezone` of that run, `itemId` of the row, and `log(reason)`. `log` writes one `info` entry on the `migration-job` logger carrying `itemId` and `reason`. The runner adds no property value to the entry.
- The write path is unchanged: the same direct `UPDATE items` guarded by `properties IS DISTINCT FROM`, and the same two-pass, locking and resumability behavior.
- New ADR `docs/adr/2026-10-29-module-data-migration-converter-context.md` (`status: accepted`, `area: [backend]`) extends `[[2026-09-28-two-pass-skip-locked-module-data-migration]]`. That ADR is not edited.
- No migration, no manifest declares a new data migration, and no stored data changes beyond what the existing Tasks migration already does.

## Notes for dependants

- #1797 reads `context.timezone` and calls `context.log`. A `reason` must be a short code. The runner cannot check its text, and a converter that builds `reason` from a property value breaks the no-value rule.
- A retry reads the zone again. If the tenant changed its zone after an earlier attempt committed some batches, pass 2 converts all rows with the new zone, including rows converted earlier with the old one. A zone-dependent converter must define its result for that case; the ADR's Consequences say so.
- The context is read-only and has no database access. A converter that needs a further read is a new design and needs its own ADR.
- `module-registry/src/index.ts` (two type export lines) is not in the Touches list. It is required so that `@semprec/data` can import the converter types.
