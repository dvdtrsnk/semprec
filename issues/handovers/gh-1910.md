## What was delivered

- `GET /api/projects/:id/heartbeats`, a `single-consumer-read` custom route of the schema core manifest (route name `listProjectHeartbeats`, handler export `createProjectHeartbeatsRouteHandler` in the new `scheduler/projectHeartbeatsRoute.ts`). The body is `{ rows }` with the project's `origin = 'user'` heartbeats, oldest first, each `{ id, name, rule, ruleLabel, enabled, nextFireAt, lastOccurrence, threadId }`.
- `lastOccurrence` is `{ at, status: 'ok' | 'waiting_approval' | 'failed', errorSummary }` or `null`. It is taken from the display status (`deriveRunDisplayStatus` through the run detail, including the incomplete reply of gh-1890) of the latest run of the latest occurrence whose latest run has finished; `errorSummary` comes from `agentRunErrorFields` (gh-1824). `threadId` is the tick thread or `null`.
- `ruleLabel` is rendered by the new `scheduler/heartbeatRuleLabel.ts` in the user's language from the new catalog keys `heartbeat.rule.*` and `heartbeat.weekday.*` of the seed i18n catalogs (kinds: weekly with day ranges, dailyTime, everyNDays with a separate Czech form `everyNDaysFew` for 2..4, interval, onItemEvent per event, and a "Custom schedule" fallback).
- 404 for a missing, trashed, foreign or non-project id (identical bodies), 400 for a non-UUID id, 401 without a session.

## Deviations from the specification and spec seams

1. The route entry is in a new slice `routeMatrix/projectHeartbeats.ts`, because no slice fits a `/api/projects/:id/heartbeats` path.
2. Rule-label formatting is in the sibling module `heartbeatRuleLabel.ts` (not in Touches) so it is unit-testable.
3. The response envelope is `{ rows: [...] }`, like `/api/projects/:id/database-grants`.
4. The rules store a wall-clock time that the scheduler reads in the system timezone, so `ruleLabel` states it unchanged; no instant is converted and the label text cannot differ by zone. The Czech weekday range renders `Po-Pá v 8:30` (accented) where the Task writes `Po-pa v 8:30`.
5. "Latest occurrence" is read as the latest occurrence (by `scheduled_for`) whose latest run (highest attempt) is not running; occurrences without a run or with a running run are passed over, and `lastOccurrence` is `null` when none qualifies. Heartbeats fired by `onItemEvent` or manually create no occurrence row, so they always report `null`.
6. Rule labels for kinds the Task does not name (dailyTime, everyNDays, interval, onItemEvent, custom fallback) were added with their keys.
7. One defensive throw in the route (a run missing after being named in the same transaction) has no test of its own.
