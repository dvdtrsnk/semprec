# Handover for gh-1373

`POST /mcp` now completes the standard MCP handshake. The change is confined to `backend/services/semprec-api/src/mcp/mcpHandler.ts`.

- **`initialize`:** handled after authentication and inside the tenant scope, like `tools/list`. It echoes the client's `protocolVersion` when it is `2025-06-18`, `2025-03-26` or `2024-11-05`, and otherwise answers `2025-06-18`. The result is `capabilities: { tools: {} }` and `serverInfo: { name: "semprec", version }`, where `version` is read once at module load from the API service's `package.json`. Missing, null or non-object `params`, or a non-string `protocolVersion`, answer `-32602`. It stores nothing and the response is the same for a run credential and a human session.
- **Notifications:** any request without an `id` (after authentication and the `jsonrpc`/`method` validation) answers HTTP 202 with an empty body, whatever its method. A request with `id: null` is still a request.
- **Non-POST:** answers 405 with `Allow: POST` (it was 404). This check still runs before authentication, as before.
- **Tests (`mcp/__tests__/mcpHandler.test.ts`):** the old 404 test now asserts 405 and the `Allow` header. New cases cover each supported version, the unsupported fallback, the five malformed-params shapes, the unauthenticated 401 for `initialize` and for a notification, a human-session `initialize` that leaves `items` and `sessions` row counts unchanged, and a 202 notification followed by `tools/list` returning the same tools.

Notes for dependants (#1788): `initialize` params beyond `protocolVersion` are not read yet. The new branch sits in `handleRequest`'s `serve` closure, where `actor` is available.

Verification: `tsc`, eslint and prettier are clean, and `mcpHandler.test.ts` passes 30/30. I did not run the full `verify`.
