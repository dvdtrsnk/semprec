# Handover: sync Microsoft calendars

Implementation commit `ecb84412d` on `feat/ia-graph`, merged into `feat/internet-accounts` in `1decd3983`. This file was rewritten from the implementing agent's final report after the original was committed with another issue's text; the later write-back issue (sp-f10163b5-5504-4460-afbb-8d4131f04088) changed some contracts noted below.

**What changed.** A Microsoft Graph adapter under `backend/packages/data/src/calendar/sync/adapters/graph/`, registered for sync mode `graph_api` in `adapters/index.ts`.
- Every request asks for UTC (`Prefer: outlook.timezone="UTC"`, plain-text bodies). An event's zone comes from Graph's original-zone fields (a series' recurrence zone first), mapped from Windows ids to IANA in `graphTimeZones.ts`; an IANA name passes through; an unknown or custom zone becomes `Etc/UTC`. Since the write-back issue, a Windows zone the tenant's IANA zone shares is read as the tenant's zone.
- Fetching is `calendarView/delta` over the engine's window widened by a day on each side in UTC; the cursor is the round's `deltaLink` with the window it was made for. A changed window (daily), an expired link (410) and an incremental round with removals start a full round, because a removal names only an instance.
- Each series seen in a round is read by id with its instances: the master's `patternedRecurrence` becomes the RRULE (daily, weekly, absolute/relative monthly and yearly, interval, days, index, end date / count / no end; `firstDayOfWeek` written only when it changes occurrences), a rule occurrence in the window without an instance or with a cancelled one becomes an exception date, an `exception` instance becomes an override with `recurrenceId`.
- Writes: `PATCH /me/events/{id}` with `If-Match`; `POST /me/calendars/{id}/events` with a `transactionId` derived from calendar and fields. A 412 is the shared `CalendarSyncEventConflictError` (since the write-back issue). An RRULE no Graph pattern expresses is refused (`GraphCalendarWriteUnsupportedError`); since the write-back issue a timed event without a zone is written in the tenant zone and a new override is made by patching the occurrence found through `instances`.
- Errors and limits: 30 s per request plus the pass deadline, 16 MiB body cap, every link (including stored cursors) must point at `graph.microsoft.com/v1.0`; 429/503/504 honour `Retry-After` up to 30 s, at most 3 attempts; 401 → `needsReauthorization`, 403 → `needsConsent`; errors carry only the status; nothing is logged.
- Tokens: mail's `refreshAndPersistAccessToken`; the pool and the Microsoft OAuth client are bound by `setGraphCalendarSyncRuntime`, set in `services/semprec-api/src/queueRuntime.ts` when `MS_GRAPH_OAUTH_CLIENT_ID`/`_SECRET` are configured (exported through `calendar/sync/adapters/composition.ts`); without them every `graph_api` pass fails as `unexpected`.

**Tests.** `backend/packages/data/src/__tests__/graphCalendarAdapter.test.ts`: 55 tests against recorded-shape Graph responses through an injected fetch plus one real sync pass on Postgres through the production registry, covering the three acceptance criteria ("every 2 weeks on Mon and Wed until 30 Nov" ↔ `FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE;UNTIL=20261130T225959Z`; `canEdit: false` → read-only; a removed instance → exception date). Related integration set 680/680 at the time; unit 4799/4801 with two load timeouts that passed alone.

**Open items only real Microsoft can settle.** Whether delta returns full event objects; whether all-day events come back converted to UTC (both handled); what delta reports for a deleted single occurrence or an edited series; whether real deltaLinks fit the 2048-character cursor limit (a longer one is not stored, so the next pass re-reads everything); whether Graph accepts IANA zone names on writes for zones the reverse table lacks and `recurrence` in a PATCH; how long Graph remembers a `transactionId`; the hex colours for Graph's named calendar colours are approximations.
