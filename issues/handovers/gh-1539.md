# Handover for gh-1539

Added the shared block model as the new pnpm package `@semprec/block-model` in `shared/block-model/` (only dependency `yjs`), as `docs/adr/2026-10-28-block-model-for-page-documents.md` fixes.

**What changed**
- `shared/block-model/src/blockTypes.ts`: `BLOCK_TYPES`, `BLOCK_TYPE_RULES` (`hasText`/`hasDone`/`hasPageId`), `MIN_INDENT`/`MAX_INDENT`, `INLINE_ATTRIBUTES`, `isBlockType`.
- `shared/block-model/src/pageBlocks.ts`: `getOrderArray`, `getBlocksMap`, `readPageBlocks`, `validateBlockInput`, `writeBlock`, `BlockInputError`. Barrel in `src/index.ts`.
- `backend/packages/data/src/docs/assertValidBlockInput.ts` (exported from `@semprec/data`): maps validation issues to `ValidationError` (400) with `details: { issues }`.
- `docs/blocks.ts` (legacy flat-map API): module comment only.
- Wiring: `backend/pnpm-workspace.yaml` lists `../shared/block-model`; `@semprec/data` depends on it with `workspace:*`; `pnpm-lock.yaml` updated; `test:unit` in `backend/package.json` also runs the package's vitest. `publicSurface.test.ts` lists `assertValidBlockInput`.

**Tests**
- `shared/block-model/src/__tests__/pageBlocks.test.ts` (concurrent first insert, normalization with byte-identical state, missing-from-order, synthetic block, validation, writeBlock) and `imports.test.ts` (source imports only `yjs` and `./`, no `Buffer`).
- `backend/packages/data/src/__tests__/assertValidBlockInput.unit.test.ts`.

**Notes for dependants**
- The ADR says "`link:`/`file:` dependency"; this uses a pnpm workspace entry instead, so the backend resolves one single `yjs` copy (a linked package with its own `node_modules` would load a second `yjs` and break `instanceof Y.Map`). `web/` is still to be wired (standalone project): it must resolve `yjs` to its own copy for the same reason.
- `PageBlock.text` is a `TextRun[]` (`{insert, attributes?}`) delta, not a `Y.Text`; `id` is `null` only for the synthetic block (`synthetic: true`).
- `writeBlock` takes `type` (stored as `sys:flavour`), reuses an existing block `Y.Map` and `Y.Text`, replaces text content, deletes fields the new type does not carry, never writes `sys:children`, and appends to `order` only if the id is absent. It throws `BlockInputError` (carries `issues`); it does not map to HTTP.
- `validateBlockInput` treats any defined `done` on a non-todo, any defined `text` on a page and any defined `pageId` on a non-page as an issue, even a falsy value.
- The block-model tests are not under the backend vitest tiers; run them with `pnpm --filter @semprec/block-model run test` in `backend/`.
- Only the targeted checks were run (package tests, `tsc` of both packages, depcruise, prettier, eslint on touched backend files, `publicSurface`); no full verify.
