Added the ADR `docs/adr/2026-10-28-semp-thread-turns-run-on-a-per-tenant-chat-lane.md`. No source file changed, so no backend or web checks apply; `node .github/scripts/adr.mjs --all --json` validates the frontmatter. I did not run Prettier because it is not installed in the repository root here.

**What the ADR decides**
- Semp thread turns are enqueued with `queueName = tenantLane('semp-chat')`, which gives FIFO per tenant. Tick lanes are untouched.
- Outside a tenant scope the producer throws; it never falls back to an unnamed queue.
- A `sempMessage` job uses `maxAttempts: 1` and `jobKeyMode: 'unsafe_dedupe'` keyed per assistant message. Retrying a failed reply is a manual user action.
- The ADR does not supersede `2026-10-08-per-tenant-queue-lanes`; it only links it and has an empty `supersedes`.
- One queue per thread, no queue name and the tick lane are recorded as rejected alternatives.
