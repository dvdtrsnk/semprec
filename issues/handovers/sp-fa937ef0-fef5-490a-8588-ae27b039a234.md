# Handover: end a sync socket cleanly, sign out on a refused handshake and keep a 401 whose body breaks off

Commit on `fix/ia-edge`: `a44954ee4`. Nothing was run against a real server or device.

**Changes** (`mobile/shared/data`).
- `ApiClient.openSocket`: the socket's `SupervisorJob` is completed right after the socket starts, so it ends with the socket instead of staying an active child of the client per reconnect.
- `ApiClient.send`, `upload`, `download`: `prepareRequest { … }.execute { … }`, so the status decides the failure before any body is read (`http.request` saved the whole body first, and a broken body turned a `401` into `UNAVAILABLE`). An error body that cannot be read is `null` (`errorBody`, cancellation rethrown).
- `AuthenticatedApi.openSocket`: a socket that failed before it opened is followed by `GET /api/auth/session` through `send`, whose `401` runs `onSessionRejected`; it returns `null` (nothing reconnects) when the session was refused that way or by close code 4401. The handshake status is not read from the engine's exception, because OkHttp and Darwin report a refused upgrade differently. `SESSION_PATH` moved to `AuthenticatedApi`'s companion and `HttpAuthRepository.restore` uses it.
- `SyncSocket.run`: stops on `null` only.

**Tests.** `AuthenticatedApiChangesTest`: a `401` whose body channel is cancelled is `Failure(UNAUTHORIZED, 401)` from `send`, `upload` and `download`, and rejects the session three times. `SyncSocketTest` (JVM, loopback Ktor server): a handshake and a session check answered `401` reject once and no second handshake follows; a `503` handshake with a valid session is retried and rejects nothing; three sockets opened and ended on one OkHttp client leave the engine job's active descendants unchanged. The three behaviour tests fail with the code of the base commit (the leak test sees 4 instead of 1).
