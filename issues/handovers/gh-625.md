## Changes
- **`backend/services/semprec-ai-gateway/src/audioHandler.ts`**
  - Adds the constants `DIARIZE_OPERATION = "transcription_diarize"` and `TRANSCRIBE_OPERATION = "transcription_transcribe"`.
  - Passes them as `operation` in the `GatewayCallContext` given to `diarize()` / `transcribe()`.
  - `agentRunId` and `projectItemId` stay unset. The only caller, `semprec-transcribe`, runs as a queue job outside any agent run or project.
  - The docblock on `createAudioRequestListener` now says the route's `operation` is recorded and `agent_run_id` / `project_item_id` stay null.
- **`backend/services/semprec-ai-gateway/src/__tests__/audioHandler.test.ts`**: the two "records the audio call" tests now also check `operation` (`transcription_diarize` / `transcription_transcribe`) and that `agent_run_id` and `project_item_id` are still NULL.
- **`backend/packages/ai-gateway/src/types.ts`**: comment-only change, not in the issue's Touches list. The `GatewayCallContext.projectItemId` doc said every caller except `/internal/complete` leaves out both `projectItemId` and `operation`. That stops being true with this change, so it now says the audio routes set only `operation`. Nothing else changed there; `aiGatewayCallsStore.ts` is untouched as the issue asks.

`POST /internal/complete` is unchanged: its existing test still expects the caller's `operation` (`agent_guidance_drift`).
