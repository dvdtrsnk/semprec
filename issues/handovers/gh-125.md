## Summary

Implements issue #125: "Synchronize tools only on human request."

- **`mcpSync.ts`** (new): `syncMcpServerTools` opens a connection through the #231 connection factory, calls `tools/list`, strictly validates the response (rejects blank or duplicate tool names), and transactionally materializes registrations into `mcp_tool_registrations` (#124):
  - New tool names get the table's default `requires_approval=true`/`risk_class='unclassified'`.
  - Existing human classification (risk class, approval) is preserved across a re-sync while schema/description refresh.
  - Tools the server stops advertising become `active=false` rather than being deleted, preserving audit identity.
  - Records `syncStatus`/`lastSynced`/`syncError` (all `owner: 'system'`, new schema fields) on the server item on both success and failure, using the safe-error shape from `McpConnectionError`/`ValidationError` — never a raw underlying message.
  - The connection is always closed via `finally`, on both success and failure.
  - Not exposed as any AgentTool/MCP operation — only reachable by an authenticated human caller.
- Added `deactivateMcpToolRegistrationsNotIn` to `mcpToolRegistrationsStore.ts`.
- Extended the shared #231 contract test servers (stdio/sse/http) with a configurable, mutable `tools/list` response so reconciliation (add/update/deactivate) could be exercised across repeated syncs. Along the way, found and fixed a real bug in `startHttpContractServer`: it reused a single `StreamableHTTPServerTransport` for the server's whole lifetime, which only supports one session — fixed by keying a transport per session, per the SDK's own multi-session pattern.
