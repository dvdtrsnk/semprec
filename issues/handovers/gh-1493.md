# gh-1493 — keep merged thread ids resolvable

Repository-Issue: gh-1493

## Delivered behavior and production wiring

- Migration `0111_mail_thread_aliases.sql` creates the tenant table `mail_thread_aliases` (`tenant_id`, `from_thread_id`, `to_thread_id`, `created_at`; primary key `(tenant_id, from_thread_id)`; `CHECK (from_thread_id <> to_thread_id)`; composite FK `mail_thread_aliases_to_thread_tenant_fkey` on `(tenant_id, to_thread_id)` to `mail_threads (tenant_id, id)` with `ON DELETE CASCADE`; index on `(tenant_id, to_thread_id)`; tenancy comment, both RLS policies, `semprec_side` grants). `from_thread_id` has no foreign key because the merge deletes that row.
- `reassignThread` (`mail/mailMessageMetaStore.ts`) returns early when both ids are equal; otherwise it moves the messages, upserts the alias `from -> to`, repoints every alias that targeted `from` to `to`, then deletes the old `mail_threads` row. Callers must run it in one transaction (`resolveThreadId` already does).
- `resolveMergedThreadId(client, threadId)` returns the alias target, else the id itself when a live `mail_threads` row exists, else `null`, in one query. Exported from the `@semprec/data` barrel (`reassignThread` is not).
- Merges before this migration are not backfilled.
