# Handover for gh-1481

Rotated OAuth refresh tokens are now persisted. `refreshAndPersistAccessToken` in `backend/packages/data/src/mail/mailOAuthAccess.ts` is the entry point the Gmail and Graph sync transports (#1505, #1508) should use to build their `getAccessToken` function. I did not push or open a PR.

The targeted tests pass: `mailOAuthAccess.test.ts` (7) and `publicSurface.test.ts`. Lint, prettier and the data package typecheck pass. I did not run the full `pnpm run verify`.

- **`AccessToken`:** `oauthTokenExchange.ts` now returns an optional `refreshToken`, set only when the provider sent a non-empty `refresh_token`. `refreshAccessToken` keeps its inputs, and its messages still carry only the status.
- **`refreshAndPersistAccessToken(pool, { mailboxItemId, tokenUrl, clientId, clientSecret, scope?, purpose })`:** inside one `withTransaction` it takes `SELECT ... FOR UPDATE` on the mailbox's `external_credentials` row, reads the token with `getDecryptedCredential` (actor `sync_worker`, the caller's `purpose`), calls the provider, and stores a rotated token with `storeCredential` (`oauth2_refresh_token`). It returns `{ accessToken, expiresAt }` only after the commit.
- **Failure behaviour:**
  - A 400/401 from the provider throws `MailReauthorizationRequiredError` and the stored token is untouched.
  - A failing store rolls back, logs `mailboxItemId` and the error name, and throws a generic error with the original as `cause`.
  - A mailbox with no stored credential throws before any provider call.
- **Concurrency:** a second caller blocks on the row lock and then reads the token the first one stored. The provider call runs while the lock and the pooled connection are held, bounded by the 15 s fetch timeout. The issue's Decision asks for this; releasing the lock first would let the second caller present the token the first is about to retire.
- **Tests:** `mailOAuthAccess.test.ts` uses a fake token endpoint that records every refresh token it receives. Cases:
  - rotation, then the next refresh uses the new token;
  - no rotation leaves the credential unchanged;
  - two concurrent refreshes present `rt-1` and `rt-2` exactly once each;
  - 400 and 401 map to reauthorization;
  - a missing credential;
  - a failed persist, which keeps the old token and leaks no token into the error or the captured logs.
- **`publicSurface.test.ts` (outside the issue's Touches list):** I added `refreshAndPersistAccessToken` to the frozen export list.
- **For dependants:**
  - The caller needs to be in the right tenant scope, since `withTransaction` uses the ambient scope.
  - Callers should treat `MailReauthorizationRequiredError` as the signal to set `needsReauthorization`.
  - Cache the access token until `expiresAt`. Every call hits the provider and rotates.
