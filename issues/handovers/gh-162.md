## Summary

Implements issue #162: synchronizing open Yjs documents over `WS /api/sync` with state-vector recovery.

- Adds `docSync.ts`: per-process `doc:open`/`doc:close` subscription registry and the y-protocols/sync handshake over the binary channel. On open/reconnect the server proactively sends its own SyncStep1; accepted client updates are persisted through the existing `mutateYDoc` write path (durable, authenticated `created_by = 'user'` origin, before the after-commit NOTIFY) and fanned out only to sockets that have that document open.
- When a `doc_update` NOTIFY references a `doc_updates` row that a concurrent compaction has already merged into `doc_snapshots` and deleted, falls back to a full SyncStep2 resync rather than dropping the change — satisfying the compaction-boundary recovery requirement from #86.
- Wires this into `syncServer.ts`'s existing frame dispatch and NOTIFY listener; adds `getDocUpdateById`/`getDocById` to fetch referenced bytes by primary key.
- New tests cover all three acceptance criteria: convergence of two subscribed clients under concurrent/duplicate/out-of-order updates with delivery scoped to subscribers only, reconnect-after-offline-edits exchanging just the missed diff, and durability-before-fanout with authenticated origin — both via direct-registry tests (`docSync.test.ts`) and full WS round-trip tests (`syncServer.test.ts`).

Full `pnpm run verify` (lint, format, build, unit/integration/e2e tests, boundary/write-safety checks) passes clean: 1142 integration tests + 5 e2e tests, no regressions.
