# gh-1401 — Upload standalone image blobs and collect unused ones

Repository-Issue: gh-1401

## Delivered behavior and production wiring

- `POST /api/blobs` (`services/semprec-api/src/blobUploadHandler.ts`, dispatched in `app.ts`, listed as `upload blob` in `routeMatrix.ts`): authenticated like `/api/files`, raw streamed body, `maxFileSizeMb` enforced from `Content-Length` (413 `payload_too_large`) and by the streaming counter. `Content-Type` is required and must be `image/<subtype>` (parameters are stripped and the type lowercased); anything else is 400 with field `Content-Type`, checked before a byte is read so nothing is stored. Response `{ blobId, byteSize, mimeType }`: 201 for a new blob, 200 when identical bytes already had a blob in the tenant. The stored `mimeType` is the declared image type (the byte sniffer only knows jpg, png, heic).
- `ingestUploadedBlob` (`blobs/fileUploadStore.ts`): same streaming, dedup and duplicate-bytes cleanup as `ingestUploadedFile`, no item. Key is `<tenantId>/blobs/<uuid>` under `FILES_STORAGE_DIR`.
- `deleteBlobIfUnreferenced` also counts any item (live or trashed, visible databases) whose property of type `image` holds `{ blobId }`. Property keys come from the `properties` table (`type = 'image'`), not a hardcoded list.
- `blobsUnreferencedSweep` (`CORE_TASK_NAMES.BLOBS_UNREFERENCED_SWEEP`, api affinity, `system` tenancy, crontab `50 4 * * *`, handler in `worker.ts` using the files storage): `blobs/unreferencedBlobSweep.ts` runs `forEachActiveTenant`, pages (200, keyset by id) over blobs with a `<tenant>/blobs/` key created more than 24 hours ago, calls `deleteBlobIfUnreferenced` in its own transaction per blob and removes the bytes after that transaction. A failed row delete is logged and skipped, then the sweep throws so the job retries; a failed byte delete is logged only.

## Notes for dependants

- #1564 adds Inbox attachments as a further reference inside the same `NOT EXISTS` list in `deleteBlobIfUnreferenced`.
- The sweep only considers blobs whose key has the `blobs/` segment. A standalone blob later claimed by a Files item or an image property is protected by the reference rule, not by its key.
- Known edge: an old unreferenced blob re-uploaded with identical bytes is returned by dedup with its original `created_at`, so the sweep can remove it before the client attaches it. Attaching immediately after upload (#1963, #1707) avoids it.
- The oldest-age cutoff is the constant `MIN_AGE_MS` in `unreferencedBlobSweep.ts`; `sweepUnreferencedBlobs` takes `now` for tests.
