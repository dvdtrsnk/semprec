Per-mailbox liveness now runs inside each tenant, and the global plane no longer sees mailbox ids. `pnpm run verify` in `backend/` exited 0. I did not run `web/`'s verify, since `web/` is untouched. The change is committed locally on the branch.

**What changed in `observabilityCheckSystem.ts`**
- **Global family:** `checkProcessHeartbeats` now evaluates only the four fixed processes. `processHeartbeats.ts` is unchanged, and the global rows and `process_stale` payloads keep their shape.
- **Legacy purge:** each system pass now calls `deleteOrphanedObservabilityChecks(client, "process:mailsync:", [])` next to the `mail:` purge, so old global mailbox rows disappear on the next tick.
- **Tenant liveness:** a new `checkMailSyncLiveness` runs in the `forEachActiveTenant` callback after the stall checks.
  - It keeps the non-fixed statuses, which are that tenant's active mailboxes.
  - It deletes orphaned `process:mailsync:` tenant rows and upserts each check as `alerting` (stale) or `ok`.
  - It notifies `mail_sync_stalled` with payload `{ mailboxItemId, beatAt }`, `sourceTable: "tenant_observability_checks"` and the tenant row's id.
  - A process name that isn't `mailsync:<uuid>` throws rather than being skipped. One tenant's failure is rethrown together with the others by the helper, as before.
- **Docstrings:** the handler's and `checkProcessHeartbeats`' docstrings now say liveness is global for the four fixed processes and per tenant for mailboxes.

**Tests**
- `observabilityCheckSystem.test.ts` gains three cases:
  - **Global plane and alert-once:** no mailbox id reaches `observability_checks`, there is no `process_stale`, the four fixed checks are `ok`, and the tenant check alerts once, including across a second run.
  - **Missing heartbeat and recovery:** a missing heartbeat alerts with `present: false`, a fresh one flips to `ok`, and a later fault notifies again.
  - **Orphans and legacy rows:** a soft-deleted mailbox loses its tenant row, and a legacy global `process:mailsync:` row is deleted.
- New `tenantMailSyncLiveness.test.ts` covers two tenants (each with its own row, `tenant_id` and notification), a suspended tenant that isn't evaluated, and `SEMPREC_TENANT_SCOPE=strict` with no `TenantScopeMissingError`.

**Test setup notes**
- `upsertProcessHeartbeat` always writes `beat_at = now()`, so the tests backdate a heartbeat with a direct `UPDATE`.
- The soft-delete case marks `items.deleted_at` directly rather than going through the choke point.
