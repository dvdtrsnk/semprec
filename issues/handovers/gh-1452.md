# Handover for gh-1452

`agent_runs` now carries a nullable `thread_id` linked to `semp_threads`. Committed locally on `wf/gh-1452`; not pushed.

- **Migrations:** `0096_agent_runs_thread_id.sql` adds the column, the composite key `agent_runs_thread_id_fkey` on `(tenant_id, thread_id)` with `ON DELETE SET NULL (thread_id)` (added `NOT VALID`) and `agent_runs_thread_wake_idx` on `(tenant_id, thread_id, wake_seq)`. `0097_validate_agent_runs_thread_fkey.sql` validates the key. The constraint is named `*_fkey`, not `*_tenant_fkey`, for the same tenancy-catalog reason as in gh-1367.
- **Store:** `CreateAgentRunInput.threadId` is optional and `AgentRunRow.threadId` is new. When `parentRunId` is set and `threadId` is not passed, `createAgentRun` copies the parent's `thread_id`; an explicit `threadId` wins. The parent is now fetched once and used for both the actor and the thread. No change in `agent-runtime` or the MCP run path.
- **Tests:** `agentRuns/__tests__/agentRunsThreadId.test.ts` (new) covers storing and reading the thread, inheritance and override, NULL for MCP runs, thread deletion (`thread_id` NULL, `tenant_id` kept) and a cross-tenant thread refused with 23503. Also run: `sempThreadsSchema` and `tenancyCatalog` tests, migration numbering, tsc for `@semprec/data`. The full verify was not run.
- **For dependants:** callers must pass `threadId` themselves for chat/item runs (#1727) and heartbeat runs (#1557). Use the existing index for thread-scoped run reads; do not add another thread index.
