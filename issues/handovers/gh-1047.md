## Summary

Heartbeat fires that start an agent session (`core.agentRun`) now enqueue onto a per-tenant lane, `agent-run:<tenantId>`. Graphile Worker runs jobs on one queue name strictly one at a time, so each tenant runs at most one agent heartbeat at a time. Other tenants are unaffected, and non-agent fires keep their queue name.

**Changes (branch `bb/relay-1047-mt-agents-08-08-cap-concurrently-runn-thr_q3egdam7h6-1`):**
- `scheduler/actions.ts`: new exported `resolveAgentRunLane(actionId)`. It returns `tenantLane("agent-run")` when the action resolves to `heartbeatFireAgent`, and `undefined` otherwise.
- `scheduler/schedulerStore.ts`: the onItemEvent enqueue uses the agent lane first, then the existing affinity expression. The sweep enqueue gets `queueName: resolveAgentRunLane(row.action_id)`.
- `scheduler/heartbeatAgentTools.ts`: the manual `heartbeat.trigger` enqueue gets `queueName: resolveAgentRunLane(heartbeat.actionId)`.
- Job keys, `maxAttempts` and `jobKeyMode` are unchanged.
- `__tests__/publicSurface.test.ts`: `resolveAgentRunLane` added to the frozen export list. The issue asks for a new export, so this list change is expected.
- `__tests__/agentRunLane.test.ts` (new): covers per-tenant lanes, a non-agent action, and the no-scope case.
