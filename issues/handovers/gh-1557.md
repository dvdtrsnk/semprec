# Handover for gh-1557

Heartbeat runs of `core.agentRun` now land in their tick thread. Committed locally on `wf/gh-1557`; not pushed.

- **No migration.** `semp_threads.heartbeat_id` and the partial unique index `semp_threads_tick_heartbeat_uq (tenant_id, heartbeat_id) WHERE kind = 'tick'` already exist from `0087` (gh-1367), so the issue's step 1 needed nothing. The upsert's `ON CONFLICT (tenant_id, heartbeat_id) WHERE kind = 'tick'` rides that index.
- **Store:** new `semp/sempTickThreadStore.ts` (internal, not exported from the package index): `getOrCreateTickThread(client, heartbeatId)` returns `{ id, tenantId }` via `DO UPDATE SET last_activity_at = now() RETURNING`; `finishTickRunWithMessage(client, { thread, agentRunId, outcome })` closes the run (`done`, or `error` through `finishAgentRunWithErrorNotification`) and inserts the assistant message in the caller's transaction, then bumps `last_activity_at` and calls `publishSempThreadInvalidation`. `event_from_id`/`event_to_id` are MIN/MAX of the run's `agent_run_events` (NULL when the run emitted none). If the run was already closed by another writer, no message is written.
- **Action:** `coreAgentRunAction` creates the thread and the run (with `threadId`) in one transaction and publishes an invalidation at start. Success writes a `done` message with `text` = the result. A final-attempt failure (`isFinalAttempt !== false`) writes an `error` message with NULL text and no code; a non-final attempt only closes the run, no message. No change to `agentRunsStore.ts` was needed (`threadId` came with gh-1452).
- **Tests:** `__tests__/heartbeatTickThread.test.ts` (new): three runs, one thread, three messages, six invalidations; non-agent heartbeat has no thread; three attempts with the last failing give one error message; a failing message insert (missing thread) leaves the run `running` and publishes nothing. `scheduler.test.ts` also passes. Run unsandboxed (embedded Postgres needs shared memory). Full verify not run.
- **For dependants:** #1907 fills the message error code (no column exists on `semp_messages` yet; add it there). #1860 fills steps and approval links. The invalidation uses the thread's own `tenant_id`. If the done-transaction fails, the action's existing catch closes the run as `error` as before (and then writes the error message on the final attempt).
