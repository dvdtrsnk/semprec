Runs started with an MCP run-credential now get closed once that credential expires. Until now nothing ever finished them, so they stayed `running` forever. Closes #643.

## Changes

- **New task `mcpRunCredentialExpirySweep`**, owned by the `api` runtime. It is added to `CORE_TASK_NAMES` and `CORE_TASK_AFFINITY` in `backend/packages/queue/src/index.ts`.
- **Handler** in `backend/packages/data/src/mcp/mcpRunCredentialExpiry.ts`: `handleMcpRunCredentialExpirySweepTask(pool)`. In one transaction it:
  - finds every run where `triggered_by = 'mcp'`, the status is still `running` and the credential's `expires_at` has passed;
  - locks those runs with `FOR UPDATE OF r SKIP LOCKED`, so an overlapping sweep skips them instead of waiting;
  - for each one, calls `finishAgentRun(..., "done", "MCP run-credential expired at <ISO>")`, which checks that exactly one row was updated;
  - appends a `run_status`/`done` event with `insertAndNotifyAgentRunEvent`, and the watcher notification is sent only after the commit.

  It returns `{ finishedRunIds }`. The status is `done`, so no `agent_run_error` notification is written. Expired credential rows are kept as an audit trail, and the new module is not exported from the package's `index.ts`.
- **Registration** in `backend/packages/data/src/worker.ts`: the task is scheduled hourly at ten past (`10 * * * *` in `CORE_CRONTAB`) and has a handler entry in `createCoreTaskList`. The api runtime picks it up through `createApiCoreTaskList` with no change to `queueRuntime.ts`.
- **Tests:**
  - A new integration test, `mcpRunCredentialExpiry.test.ts`, covers four cases:
    - An expired credential's run ends as `done` with `finished_at` set, a result naming the expiry and one `run_status`/`done` event. `resolveMcpRunCredential` returns `null` and no `agent_run_error` notification is written.
    - Running the sweep a second time returns `[]` and changes nothing.
    - A run whose credential is still valid stays `running`.
    - A running `heartbeat` run with an expired credential is left alone.
  - `taskAffinity.unit.test.ts` covers the new name and its affinity.
  - `queueRuntime.test.ts`: the new task is in `EXPECTED_CRONTAB_IDENTIFIERS`.
