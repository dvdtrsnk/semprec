## Summary

Closes #113 — enforces module and service import boundaries via dependency-cruiser.

- Added `backend/dependency-cruiser.rules.json` (shared rule set) and `backend/.dependency-cruiser.cjs` (config) defining `no-module-service-internal-cross-import`: a module or service under `modules/X/**` or `services/X/**` may only be imported by another module/service through its public entry point (`src/index.ts`); `packages/*` shared code stays unrestricted.
- Exposed the check as `pnpm run check:boundaries` (backend), which scans the real `modules`/`services` directories and reports actionable diagnostics (importer, imported path, violated rule) with a non-zero exit code on violation.
- Added a new `@semprec/module-boundaries` package wrapping the dependency-cruiser Node API, with fixture modules/services and a vitest suite proving: forbidden module↔module, service↔service, and cross-category internal imports are rejected, while public-entry, same-module-internal, and neutral shared-package imports pass — and that the violation report names importer, imported path, and rule.
