## Why

`integration-shard (1)` of CI run 36871665352 (PR #910) was cancelled at the job's 12-minute timeout. It looked like a hung integration test, but the tests were not the problem. `Backend — install ffmpeg` ran from 13:50:32 to 14:02:29 (`Fetched 62.8 MB in 11min 39s (89.9 kB/s)`), so `test:integration` started with 33 seconds of budget left. It finished `mailSync.test.ts` at 14:03:02 and was killed one second later in the next file. The step timings of every `integration-shard` job on 2026-09-30 and 2026-10-01 show this is recurrent: 18 of 599 ffmpeg installs took more than 4 minutes, and 7 took more than 10.

## What

In `integration-shard` only:
- The ffmpeg `.deb` files are cached (`actions/cache/restore@v4` + `actions/cache/save@v4`) under a key per runner image (`ImageOS`, `ImageVersion`, `RUNNER_ARCH`). apt installs from that directory via `-o Dir::Cache::Archives=…`, so a cache hit downloads only packages the mirror has updated since. The save runs right after the install on a miss, so a shard whose tests fail still fills the cache.
- `Backend — install ffmpeg` gets `timeout-minutes: 13` (the slowest uncached install seen took 12.5 minutes), and `Backend — test:integration (shard n/3)` gets `timeout-minutes: 9` (a shard takes 2–5 minutes). The job timeout is their sum plus about a minute of setup: 23. A stalled mirror or a stalled test run now fails under its own step name, and mirror time no longer comes out of the tests' budget.

Unchanged: the shard count, the `integration` fan-in job (still red on any failed or cancelled shard), the triggers, the concurrency group and the permissions.

## On naming a hung test

The integration config already sets `testTimeout: 30_000` and `hookTimeout: 60_000`, so a test or hook stuck on an unresolved promise fails within a minute under its own name. The default reporter prints each file as it finishes, which is how the log of run 36871665352 shows `mailSync.test.ts` completing. The new 9-minute step budget covers what those timeouts cannot catch: a blocked event loop, or a vitest process that does not exit. No reporter change is part of this PR.
