# Handover: send every calendar sync request from the mobile app and coalesce only concurrent ones

Commit on `fix/followup-caldav`: `9334b657e`.

**Changes.**
- `SyncAccountCalendars.kt` (`shared/domain`): the 60 s pause and its `TimeSource`/`interval` parameters are gone. Each call takes a ticket and runs its round under a `Mutex`. A round serves every call counted before it started, so calls made while one is under way wait and are sent by exactly one more round. A round that is cancelled, or whose accounts could not be read, marks nobody served.
- `CalendarViewModel.kt` KDoc and `mobile/docs/architecture.md` describe the server coalescing instead of the client pause.
- No exported type changed and neither app constructs the use case: Android and Apple code are unchanged. The account screen's explicit "Sync now" (`syncRequested`) was already unthrottled apart from its in-flight guard.

**Tests** (commonTest):
- `SyncAccountCalendarsTest`: three calls send three rounds; three calls waiting on a running round are served by one more round; a cancelled round's waiting call sends its own; a refused sync does not stop the others or the next call; unread accounts let the next call through.
- `CalendarListViewModelTest`: every pull to refresh asks.
- `CalendarServerChangesTest`: refreshing the calendar and the list each ask, and a server change never does.
- Against the old implementation, 6 of them failed (4 domain, 2 presentation).
