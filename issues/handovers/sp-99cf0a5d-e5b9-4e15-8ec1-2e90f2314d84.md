# Handover: take the rows of the tasks whose value links an Event feeds before the value links it detaches when the Event is trashed

Delivered on chain `e1-235-value-link-locks`, candidate commit `17f18117e8647eb2aff441bc0a52f89cef9f712c`, landed by a `--no-ff` merge (`87698f26ef3b9c6b461cc3d9794cebac49b194dc`) on `feature/backend-parallel` as the first chain of a train with `e1-237-db-roles` and `e1-244-purge`. The segment commit of this source is `a8e22e5c3d3750053bd079a6459eedd3ccc96572`; it follows the segment of `sp-04496878-7bbb-4cae-94e4-55e4bad15335` in the same chain.

**What changed.**
1. New helper `lockItemRowsOfLinksSourcedFromItem(client, sourceItemId, ownerModuleId)` in `backend/packages/data/src/chokePoint/valueLinksStore.ts`. In one statement, in item id order, it locks (`SELECT i.id FROM items i JOIN databases d ... ORDER BY i.id FOR UPDATE OF i`) the rows of the items of the owner module that have a value link with an item source naming the trashed item. The statement is tenant scoped (`i.tenant_id`, `l.tenant_id`, `s.tenant_id = app_tenant_default()`, `d.tenant_id = i.tenant_id`), parameterized and returns nothing.
2. `valueLinkSourceDeleteHook` calls it with `TASKS_MODULE_ID` before `deleteValueLinkSourcesBySourceItem`, so the trash of an Event holds the task rows before the links it detaches, as the propagation of `taskProjectFromEvent` does (row, then link). The hosted-tasks hook then finds already locked the rows of the hosted tasks that are also sourced from the Event and locks the rows of the other hosted tasks itself. `domainWriteHooks.ts` and `eventHostedTasksHooks.ts` are untouched.
3. New ADR `docs/adr/2026-11-15-the-trash-of-an-event-takes-the-rows-of-the-tasks-it-hosts-before-the-value-links-it-detaches.md` (accepted, backend, standalone). It states that the registration position of the hooks is part of the contract: source detach, company release, then the hosted-tasks hook.

**Contracts dependents build on.** `lockItemRowsOfLinksSourcedFromItem` in the choke point (exported from `valueLinksStore.ts`, not from the package barrel). The delete hook order of the Event's trash in `domainWriteHooks.ts` (detach, company release, hosted-tasks hook) must stay; the new test fails if the hosted-tasks hook is registered ahead of the detach. No route, table, migration, operation or job name changed.

**Files.** `backend/packages/data/src/chokePoint/valueLinksStore.ts`, `backend/packages/data/src/valueLinks/valueLinkSourceDeleteHook.ts`, the ADR above.

**Tests.** `backend/packages/data/src/tasks/__tests__/eventTrashHostedTaskLockOrder.test.ts` (new, four cases on runtime-role pools: propagation first and trash first with the third transaction holding the task row, both commit; the trash waiting for a held link already holds the task row, probed with `FOR UPDATE NOWAIT` (55P03) and the task returns to its day; the Event also sources a smaller task that it does not host, third transaction holds that task's project link, both commit). The worker verified the first two fail on the tree without the change and that the last one fails when only the registration of `eventHostedTasksDeleteHook` is moved ahead of `valueLinkSourceDeleteHook`.

**Deviations and spec seams.** (1) The Task lists the Event's delete hooks as source detach, hosted-tasks hook, company release; in `domainWriteHooks.ts` the company release is registered before the hosted-tasks hook, so the ADR states the order the code has. (2) The statement additionally carries the tenant scope the other statements of the store use, the helper lives in `valueLinksStore.ts` and returns void, and the owner module id is a parameter so the choke point does not import the Tasks module id. (3) The hook runs the statement for every trashed item (it is keyed on the trashed item, not its type). (4) The ADR's file name keeps the Task's wording although the review made the decision text narrower (see below).

**Criteria NOT RUN or BLOCKED.** None. The ADR lists the trash of a non-Event item as not measured.

**Review.** Requirements and tests lens: one low finding (the ADR and the hook docstring said the hosted-tasks hook finds the rows of every hosted task locked, which is false for a hosted task that is not sourced from the Event). Rules and architecture lens: clear. The finding was confirmed and fixed in the ADR (title, decision, hook order item 3, a new "not measured" bullet), the hook docstring and a test header comment (commit `17f18117e8647eb2aff441bc0a52f89cef9f712c`); documentation and comments only, no recheck.

**Follow-ups.** None from review.
