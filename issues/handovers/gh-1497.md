# Handover for gh-1497

Mail sync now records, per mailbox, when it last synced successfully, since when it has been failing, why, and whether the first full pass finished. Nothing is exposed over HTTP yet (#1572 serves it).

- **Migration:** `0115_mail_sync_status_tracking.sql` adds nullable `last_successful_sync_at`, `failing_since`, `initial_sync_completed_at` and `last_failure_kind` (CHECK: `reauthorization`, `connectionLimit`, `other`) to `mail_account_sync_state`. It backfills accounts with `last_error IS NULL` (success and initial sync from `last_activity_at`) and failing accounts (`failing_since` from `last_activity_at`, kind `other`). Additive and rollback-safe.
- **Store:** `MailAccountSyncStateRow` gains `lastSuccessfulSyncAt`, `failingSince`, `initialSyncCompletedAt` and `lastFailureKind` (validated against the exported `MAIL_SYNC_FAILURE_KINDS`, type `MailSyncFailureKind`). `recordImapActivity`, `recordGmailActivity` and `recordGraphActivity` set the success timestamp, set the initial sync once (`COALESCE`) and clear `failing_since` and the kind. `recordSyncError` and `recordConnectionLimitBackoff` now take the failure kind, keep an existing `failing_since` and leave the success timestamp alone.
- **Job:** `mailSyncJob.ts` maps `reauthorizationRequired`, `connectionLimit` and `unexpected` to `reauthorization`, `connectionLimit` and `other`. `Mailboxes.syncStatus` is written only when it differs from the value the prologue read, so repeated identical passes cause no item update.
- **Tests:** `mailSync.test.ts` (the issue's `mailSyncJob.test.ts` and `mailAccountSyncStateStore.test.ts` do not exist; sync job tests live there) gets one test walking success, repeat success (item `updated_at` unchanged), `other`, `reauthorization`, `connectionLimit` and recovery. Three observability test files pass the new kind argument to `recordSyncError`.
- **Notes for dependants:** `syncStatus: 'never'` is still not written; derive it when serving. Removing a mailbox (#1690) deletes the state row, which carries these columns. `invalidateGmailHistory` and `invalidateGraphDeltaLink` set `last_error` but deliberately do not touch the new columns.
