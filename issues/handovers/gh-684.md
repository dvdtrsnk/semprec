## Summary

Closes #684. An agent run can now be finished only once, and a finished run accepts no more transcript events apart from its final `run_status` event. Backend `pnpm run verify` passes (exit 0: lint, format, build, and the unit, integration and e2e tests). `web/` was not touched.

### Changes
- **`finishAgentRun`** (`agentRunsStore.ts`): the `UPDATE` now only changes a row whose status is still `running`, and the function returns `Promise<boolean>`.
  - It returns `true` when this call closed the run.
  - If the run was already finished, it returns `false` and leaves the first status, result and `finished_at` as they were.
  - If the run id does not exist, a `SELECT` on the same client finds no row and it throws `NotFoundError`.
  - The `requireAffectedRows` import is no longer used and was removed.
- **`finishAgentRunWithErrorNotification`** returns the same boolean and writes the `agent_run_error` notification only when its close succeeded. The docstring's "a run finishes at most once" statement is now enforced by the store.
- **`DelegationRegistry.expire` / `SempConversation.pause`**: if the run was already finished by another writer, they log `logger.warn({ agentRunId }, ...)`. They still record `run_status` and remove the in-memory entry.
- **`insertAgentRunEvent`** (`agentRunEventsStore.ts`):
  - **Status guard:** it now uses `INSERT ... SELECT ... FROM agent_runs WHERE id = $1 AND (status = 'running' OR $2 = 'run_status')`, so the check and the write are one statement. If no row is inserted, it looks up the run: an unknown id throws `NotFoundError`, and a finished run throws `ConflictError` with the message the issue specifies.
    - The parameters carry explicit casts (`$1::uuid`, `$2::text`) because each one appears both in the select list and in the `WHERE` clause.
  - **Size cap:** a module-private constant `MAX_AGENT_RUN_EVENT_PAYLOAD_BYTES = 1 MiB` bounds the payload. The payload is serialized once and its UTF-8 byte length measured. An oversized payload throws `ValidationError` naming the kind, the size and the cap, before any query runs. `insertAndNotifyAgentRunEvent` gets both behaviours unchanged.
- **`repairInterruptedRuns`**: the synthetic `tool_result` is now written before the run is closed as `error`, so it still targets a running row. The numbered docstring was updated to match. Both writes stay in the existing transaction.

### Tests
- **New `agentRunsStore.test.ts`:**
  - Closing a running run returns `true` and sets status, result and `finished_at`.
  - A second close (`done` then `error`, and the reverse) returns `false` and leaves the first status, result and `finished_at`.
  - An unknown id throws `NotFoundError`.
- **`agentRunErrorNotification.test.ts`:**
  - Closing an already-`done` run returns `false`, keeps it `done` and writes no notification.
  - The existing replay case now also checks the `true`/`false` return values.
- **`agentRunEventsStore.test.ts`:**
  - `ConflictError` with no row inserted, for a `done` run and for an `error` run.
  - A `run_status` event on a finished run is stored.
  - `NotFoundError` for an unknown run id.
  - A payload one byte over 1 MiB throws `ValidationError` and inserts nothing; a payload exactly at the cap is stored.
- **`startupRepair.test.ts`:** passes unchanged with the new order.

`lifecycleAdapter.ts`, `scheduler/actions.ts`, the `busy` claim in `expire`, and the `withTransaction` bracketing were all left alone, as the issue's Out of scope requires. No new public export was added.
