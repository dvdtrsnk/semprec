## What was delivered

- `POST /api/mail/drafts`, `GET /api/mail/drafts/:id`, `PATCH /api/mail/drafts/:id` and `DELETE /api/mail/drafts/:id`, registered in the mail manifest and the route matrix.
- Create (`createEmailDraftInMailbox` in `mail/draft.ts`): checks the mailbox, the sender address (403 `from_address_not_registered` when it is not an address of the mailbox, aliases accepted in any letter case), the thread (alias translation), the source message and the Drafts folder (400 when the mailbox has none), then writes the Emails item, the edge to the Drafts folder and the `mail_drafts` row in one transaction. It is attributed to the writer and acting user of the call.
- Read (`readEmailDraft`): the draft as the compose window shows it, joined from the Emails item and its `mail_drafts` row; 404 for an item without a row.
- Update (`updateEmailDraft`): locks the Emails item then the `mail_drafts` row, then refuses in this order: 404, 409 `mail_draft_not_editable`, 409 `mail_draft_already_sent`, 409 `version_conflict` (against the item's `updatedAt`, the `ifVersion`), 400 for a mailbox or thread move, 403 `from_address_not_registered`, 404 source. It records `last_edited_by` from the writer kind and always rewrites subject, sender, recipients and body so `updatedAt` moves.
- Discard (`discardEmailDraft`): trashes the Emails item and deletes the `mail_drafts` row (so the unique index on unsent agent drafts does not keep the thread occupied by a trashed draft), then announces.
- Every successful change publishes the thin `mailThread` invalidation for the draft's thread (translated, once, after the commit); a draft without a thread announces nothing.
- Input hardening: strict zod bodies, caps (address 320, subject 998, body 500000, 100 recipients per list), no control characters in header values, no NUL or lone surrogate in the body, 404 for malformed ids.

## Entry points and contracts dependents build on

- Routes: `mailDraftCreate`, `mailDraftRead`, `mailDraftUpdate`, `mailDraftDiscard`, handler exports `createMailDraftCreateRouteHandler`, `createMailDraftReadRouteHandler`, `createMailDraftUpdateRouteHandler`, `createMailDraftDiscardRouteHandler` (`mail/mailDraftRouteHandlers.ts`, exported from `@semprec/data`), registered in `mailModuleManifest.ts` and in `routeMatrix/mail.ts` with four `ROUTE_CASES` cases (`mail draft create`, `mail draft read`, `mail draft update`, `mail draft discard`) and four `ROUTE_HANDLER_FILES` mappings.
- Wire shape: `from` is a plain address string in request and response, recipients are `{ address, name? }` in the request and `{ name, address }` in the response, `attachments` is `[]`. The version is the Emails item's `updatedAt` (the response's `updatedAt`), not `mail_drafts.updated_at`.
- Operations in `mail/draft.ts`: `createEmailDraftInMailbox`, `readEmailDraft`, `updateEmailDraft`, `discardEmailDraft`; `CreateEmailDraftInput` gained optional `writer`, `actingUserId`, `humanWriterUserId` and `queueAffinity` (absent keeps the system behaviour for existing callers). `mail/mailDraftsStore.ts` gained `getMailDraft(..., forUpdate)` and `deleteMailDraft`.
- Errors: `MailDraftAlreadySentError` and `MailDraftNotEditableError` (409, codes `mail_draft_already_sent` and `mail_draft_not_editable`), exported from `@semprec/data` and registered in `adapter/errorContract.ts`. Sending (#1896) must raise them and must follow the refusal order and the item-then-row lock order stated in the ADR `2026-11-13-a-discarded-mail-draft-loses-its-row-and-draft-writers-lock-the-item-before-the-row`.
- Table `mail_drafts` is not changed; no migration, job name or operation is added.

## Deviations from the specification and spec seams

1. The route entries are in `routeMatrix/mail.ts`, not `routeMatrix.ts`.
2. Decisions the Task left open: the version is the item's `updatedAt`; PATCH accepts `mailboxId` and `threadId` only when equal to the draft's (400 otherwise, the store has no thread update and a mailbox move needs a folder move); a draft without a thread announces nothing; GET of an Emails item without a `mail_drafts` row is 404; a mailbox without a Drafts folder is 400 (as `send.ts` does for Sent); an unknown mailbox, thread or source message is 404; discard deletes the `mail_drafts` row, so a draft restored from the trash is a plain read-only message.
3. Edits beyond Touches: `mailDraftsStore.ts`, `errorContract.unit.test.ts` fixtures, `publicSurface.test.ts`, the `chokePointWriteBoundary` mapping. The registered-address check duplicates five lines of `send.ts` (left untouched, out of Touches).
4. Landing reconciliation, not a change of the chain's logic: after the merge the barrel `index.ts` counted 905 lines against the 900-line ESLint `max-lines` cap. The four draft route handlers are re-exported with one `export * from "./mail/mailDraftRouteHandlers.js"` line (the module exports exactly those four), which keeps the public surface unchanged.
