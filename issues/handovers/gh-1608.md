# Handover for gh-1608

Added canonical Markdown for page blocks to `@semprec/block-model` (`shared/block-model/`), still with `yjs` as the only dependency and no Markdown library.

**What changed**
- `shared/block-model/src/markdown.ts` (exported from the barrel): `serializeBlocks(blocks, { resolvePageTitle, withIds })`, `parseMarkdown(md, { allowPage, createId })`, `stripMarkdown(md, maxChars)`, plus the types `SerializableBlock`, `ParsedBlock`, `SerializeOptions`, `ParseOptions`.
- `shared/block-model/fixtures/markdown.json`: shared vectors (`vectors` for both directions or one, `rejections` for parse failures). The WebView editor can load the same file.
- `pageBlocks.ts`: `BlockIssue.code` gained `page_not_allowed`.

**Tests**
- `shared/block-model/src/__tests__/markdown.test.ts` runs every vector in both directions plus the round trip (parse, serialize back to the canonical text, parse again), the `allowPage: false` rejection, id handling, list spacing, type-key sanitizing and `stripMarkdown`. Run with `pnpm --filter @semprec/block-model run test` in `backend/`.
- Only targeted checks were run (package tests, `tsc`, prettier); no full verify. ESLint does not cover `shared/`.

**Notes for dependants**
- `parseMarkdown` returns `ParsedBlock[]` (`text` is always `TextRun[]`, `id` always set). Ids come from a `semprec:block` comment, otherwise from `createId` (default `b1`, `b2`, ...; a repeated or already used id is replaced). Callers that persist must pass a real id generator.
- An unknown block type is read as `type: <key>` from the comment, which `writeBlock` rejects; a caller must decide what to do with it (it is not coerced to `text` here). The comment type applies only to a plain text line; a marker line (`## ...`) always wins, and only the indent comes from the comment for non-list blocks.
- The default mode writes a comment only for an unknown type, for a non-list block with indent not 0, and for an empty `text` block (a comment line alone is the only way to carry it). `withIds` writes a comment before every block. The synthetic block of an empty document (`id: null`) is skipped.
- Crossed bold and italic, and any bold/italic span with whitespace at its edge, are written as `<strong>`/`<em>`; a bold or italic span is split at link boundaries so a link is always outermost.
- Normalization: leading and trailing whitespace of a block line is dropped, and number blocks are always written as `1.`. Unpaired `*`, `**` and `_` stay literal on read. A link destination containing whitespace, parentheses, `<`, `>` or `\` is written as `<...>`.
- Known gap: a text block whose whole content is a link to `semprec://page/<id>` is read back as a page block.
- `stripMarkdown` joins blocks with one space, drops page links, and truncates by code points.
