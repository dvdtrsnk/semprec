## What was delivered

- `replacePageMarkdown` in `backend/packages/data/src/docs/pageMarkdown.ts`: one transaction that locks the host item, then the rows of its live subpages in id order (`lockLiveChildPageIds`, the same order as a direct trash), loads the page document and compares `docEtag` with the caller's token (`PageVersionConflictError` carries the current token). Markdown is parsed and checked like an insert (item links verified on the tenant-scoped write client before any document is created); every page link must name a live subpage of the host. Subpages whose link vanished are trashed through `itemDeleteWithClient` before their block is removed (the trash hook records the position), subpages whose link caption changed are renamed through `renamePageWithClient`, and the body changes through the id-preserving `planBlockDiff` (new `backend/packages/data/src/docs/pageBlockDiff.ts`: equal head and tail, LCS of the changed stretch, applied as one document update).
- Review fixes inside that function: `planBlockDiff` returns `placeAfter` and `applyBlockDiff` re-points the recorded position of every trashed page whose neighbour the same diff deleted, so Undo of a trashed subpage puts its block back in place even when the PUT rewrote the block before it; for an item without a document the token is compared again inside the `mutateDocWithClient` callback on the document loaded under its row locks, so a document created concurrently cannot be overwritten with a stale token.
- Handler `createPageReplaceRequestListener` in `backend/services/semprec-api/src/pageMarkdownHandler.ts`, mounted in `app.ts`: 428 without `If-Match`, 400 for a malformed `If-Match`, a content type other than `text/markdown` or a non UTF-8 body, 413 over 1 MiB, 404 for a foreign or unknown item (same answer), 409 with the current ETag, 200 with the new ETag and `{ trashedPages }`.
- Application service and gateway: `genericApplicationService.ts` and `genericOperationGateway.ts` map the origin to `user` for a person and `ai_agent` for an agent actor.

## Contracts dependents build on

## Deviations from the specification and spec seams

1. The Task lists `packages/data/src/__tests__/docs.test.ts` for the replace cases; they are in the new `pageReplace.test.ts` (`docs.test.ts` is unchanged).
2. The Task lists `routeMatrix.ts`; the route entry is in the slice module `routeMatrix/items.ts`.
3. Task step 6 says the origin is `ai_agent` for an agent run credential. `page.replace` is REST-only, so over HTTP, MCP and the agent tools a run credential gets 404; the gateway can hold only destructive operations with an approval snapshot and replay, and that approval is #1844 (out of scope). The application service still maps an agent actor to `ai_agent` (tested). Recorded in the new ADR.
4. `parseCheckedMarkdown` gained the optional `allowPage` option.
5. The earlier ADR `2026-10-28-page-operation-family` names `PUT /page/content` with `expectedLastEditedAt`; the issue's `page.md` and `If-Match` design is followed and the difference is recorded in the new ADR.
6. A page link is read by the Markdown parser as a block with only a page id, so link captions are recovered by a second parse with page link lines rewritten to ordinary links (`captionsOf` in `pageMarkdown.ts`).
7. The gateway test that hard-coded `core.schema.write` for every REST-only operation was generalised and gained page.replace listing and refusal cases.
