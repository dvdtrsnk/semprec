## What was delivered

`GET /api/trash/items` (`createTrashItemsRouteHandler`, `trash/trashRouteHandlers.ts`), a schemaCore custom route with the justification `single-consumer-read`. It lists the trashed cascade roots of the tenant, newest first: an item in an inline database whose owner was deleted at the same `deleted_at` is not a row, items of archived databases are not listed, a system database never appears as a row of its own.

- Paging: `limit` 1..200 (default 50), an opaque strict cursor over `(deleted_at, id)` at microsecond precision; a non-integer or out-of-range limit and a malformed cursor give 400 `validation_failed`. `totalCount` covers all roots and comes from the same REPEATABLE READ snapshot as the page.
- Each row has `databaseKey`, `ownerModuleId`, `databaseName` (the stored name for a user database; for a system database the catalog name in the user's locale, with catalogs loaded lazily once per process and not cached when the load fails), `purgeAt` (`deletedAt` plus `RETENTION_DAYS` times 24 h) and `daysLeft` (calendar days in the tenant's zone, never below 0).
- The retention constant is now the exported `RETENTION_DAYS` (30), shared by the purge sweep and the list.
- Migration `0163_items_deleted_at_idx.sql` (renumbered from `0154` at the merge): partial index `items_deleted_at_idx ON items (deleted_at DESC, id) WHERE deleted_at IS NOT NULL`, `IF NOT EXISTS`, additive.

1. The constant already existed as the exported `TRASH_RETENTION_DAYS`; it was renamed to `RETENTION_DAYS` as the Task says and the import in `approvalDescription.ts` updated (one file beyond Touches).
2. The route matrix entry lives in a new slice module `routeMatrix/trash.ts`, because no slice fits `/api/trash`.

4. A second test file covers the lazy catalog load and the not-cached-on-failure branch, which needs its own module-level mock.
5. `purgeAt` is `deletedAt` plus 30 times 24 h like the sweep's cutoff, while `daysLeft` counts calendar days in the tenant zone from the deletion day.
6. The query plan with the new index was not measured (no EXPLAIN run). The cascade-epoch comparison is by `deleted_at` equality, the limit documented in `itemTrash.ts`.
7. At the merge the migration ordinal `0154` was not above the highest ordinal on the tree (0162), so only this chain's own file was renamed to `0163`; the file holds no reference to its ordinal.
