# Handover: answer an accepted SMTP send before its Sent copy and drain those copies at shutdown

Commit on `fix/followup-mail-latency`: `fd46fb6b5`. Nothing was run against a real server.

**Root cause.** The send route waited for the SMTP account's Sent copy after the server accepted the message. The copy opens its IMAP connection only inside the account's connection slot (limit 2 for Purelymail); the IDLE connection holds one slot and a running sync pass the other, so a reply sent while a pass ran waited for that pass, then for connect, APPEND and LOGOUT. No sync pass is awaited by the send itself and no lock is held across the provider call. The SMTP submission stays synchronous, as documented: its refusal is the answer and the claim decides exactly-once.

**Changes.**
- `mail/mailTransport.ts`: `DetachedSentCopies` / `createDetachedSentCopies()`; `createSmtpMailTransport(..., detached)` hands an accepted send's copy to it and answers at once (refusals still wait so the unused connection is closed first); `createMailTransportFactory` option `detachedSentCopies`. Exported from `index.ts`.
- `semprec-api`: `serve.ts` creates one and passes it to `createDispatcher` (`AppOptions.detachedSentCopies`, used for the custom routes' send transports: draft send route, approved agent send, MCP draft send) and to the shutdown; `shutdown.ts` drains it after `mailLiveSync.stop()` and before `queueRuntime.stop()`, at most `SENT_COPY_DRAIN_TIMEOUT_MS` (30 s), logging copies still running. Queue-job senders (invitations) keep waiting for the copy.
- Docs: `domain-mail-and-inbox.md` (Sending, shutdown order), `edges-io-and-errors.md` (Shutdown), `agents-approvals-and-ai.md` (API shutdown).

**Measured with fakes** (SMTP 1.5 s, IMAP connect 0.5 s, APPEND 0.2 s, LOGOUT 0.1 s, limit 2 with IDLE holding one slot): no contention 1.80 s → 1.50 s; a pass holding the second slot for 3 s 3.80 s → 1.50 s. The copy then completes in the background.

**Tests.** `__tests__/smtpTransport.test.ts`: `answers an accepted send while the account's connection slots are taken, then appends the copy once one frees` (blocks until the slot frees before the change), `keeps a detached copy's failure off the send and logs it with the fixed stage`, `closes the overlapped connection of a refused submission before answering, even with detached copies`. `services/semprec-api/src/__tests__/shutdown.unit.test.ts`: drain order and bound, a timed-out drain logged with every later step still run; `shutdown.test.ts` passes the new member. `publicSurface.test.ts`: the new export.

**Behaviour to know.** A process crash after the response and before the APPEND loses the provider's Sent copy (the Semprec item is in Sent from the finalization); before, a crash in that window also lost the finalization. The route wiring through `createDispatcher` is covered by types only: the stored settings accept only standard ports, so no test drives the production factory to a fake SMTP server.
