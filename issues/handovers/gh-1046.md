## Summary

Project agent guidance ownership is now bound to the tenant's user. This closes a cross-tenant path where a guidance owner or drift-notification recipient could be a user of another tenant.

**Changes (one commit, `7b76455e`):**
- **`projectAgentGuidanceStore.ts`:** `requireUser` and `requireUserLocale` resolve only the current tenant's user, compared against `getTenantUserId`. A user of another tenant, a user with no tenant, or an unknown id throws `GuidanceReferenceNotFoundError`. Other errors propagate unchanged.
- **`service.ts`:** on a first write, `upsertProjectAgentGuidance` calls `references.requireUser(tx, actor.userId)` inside the same serializable transaction. Not-found maps to `ProjectAgentGuidanceOwnerViolationError` (403 `owner_violation`). Infrastructure errors propagate. Writes to an existing row keep the existing owner comparison. Transfer needed no code change, because its existing `requireUser` now refuses foreign users as `validation_failed` `not_found`.
- **Unit tests (`service.unit.test.ts`):** a foreign first write is refused with no row and no heartbeat. A tenant user's first write succeeds. An infrastructure error on the owner check propagates. A transfer to a foreign user is refused and the owner is unchanged.
- **Integration tests (`projectAgentGuidanceStore.test.ts`):** these run inside tenant zero using the existing `createTenantZeroUser` and `withTenantTransaction` helpers. They cover the tenant's user, a foreign existing user for both functions, an unknown id, and a dropped connection surfacing as itself.

**Skills loaded:** `implement-issue` as the contract. `state-writes` and `error-handling` because the check runs inside a serializable transaction and must keep "not found" distinct from infrastructure failures.
