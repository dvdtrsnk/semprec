## What was delivered

- `sweepOrphanedPages(pool)` in `backend/packages/data/src/docs/pageOrphanSweep.ts`. It walks the active tenants with `forEachActiveTenant`. Per tenant it lists live Pages items in keyset chunks of at most 200, ordered by (parent, id), whose parent has a page document that has been idle for at least one hour. Each chunk runs in one transaction: it locks the page rows `FOR UPDATE` in id order, loads each parent's document once (the idle time is read again after the document lock), and trashes every page whose block is missing through `itemDeleteWithClient` as writer kind `system`. The page-trash hooks therefore own the block removal and the subtree trash; the sweep issues no direct UPDATE or DELETE.
- A page is left alone when its block is present, when the parent's document was edited less than an hour ago, when the parent has no document or holds a canvas instead of a page, or when the parent is in the Trash.
- A chunk that fails is rolled back and retried page by page; a failing page is logged by id and error class name only. `assertSweepNotFailedEntirely` makes the run reject when every page examined for a tenant failed, so a systematic fault is visible to the queue.
- Core task `pageOrphanSweep` (`CORE_TASK_NAMES.PAGE_ORPHAN_SWEEP`), affinity `api`, tenancy `system`, cron line `5 4 * * *`, handler registered in `backend/packages/data/src/worker.ts`.

## Deviations from the specification and spec seams

1. No ADR was added: the lock order (page row, then parent document) is the one in the trashed-pages ADR, and the fan-out and chunking ADRs cover the rest.
2. A failure on one page is absorbed by rolling the chunk back and retrying per page instead of by savepoints, because a savepoint rollback would leave the after-commit callbacks of the rolled-back page registered.
3. Known limit: the sweep locks a page row and then its parent's document (the order of a page trash), whereas `pageTitleMirror` locks the document and then page rows. A concurrent run can end in `40P01`, which the chunk fallback and the next daily run absorb. This inversion already exists between the page trash and the mirror and is recorded in the trashed-pages ADR.
4. The test inventories of the queue package and of `semprec-api` (task affinity, tenant envelope, crontab identifiers, tenant isolation of jobs) were brought in line with the new task; they are outside the Touches list.
