## What was delivered

A Companies proposal whose ICO is a well-formed number is checked against the public ARES register after the model answered, and the registered name replaces the model's spelling.

- `services/alldots-api/src/aresClient.ts`: `AresClient` interface (`lookup`), the HTTP implementation `createAresHttpClient({ fetch? })` (fixed base URL `ARES_BASE_URL`, `GET /ekonomicke-subjekty/<ico>`, 3 s deadline `ARES_TIMEOUT_MS` covering the body read, 64 KiB body cap `ARES_MAX_RESPONSE_BYTES`, `redirect: error`, zod schema for `ico` and `obchodniJmeno`, an answer for another number refused, 404 gives `null`) and the typed `AresLookupError` with a `reason` (`invalidIco`, `timeout`, `network`, `status`, `tooLarge`, `malformed`). The global fetch is resolved at call time.
- `proposalComputation.ts`: when the target is Companies (by the item type, by the best recognition candidate, or by the input module) and the ICO is a well-formed number (spaces removed, left-padded to eight digits, no check digit), the client is called after the model result with no database transaction open. A hit sets `properties.name` and the normalized eight-digit `properties.ico`; `null` or any error leaves the computed values and is logged by reason only (no number, no register answer). For a multi-step answer the ICO is read from, and the name patched into, the primary operation (the first create into Companies, the step the stored card takes its properties from), together with the top-level properties; an ICO that exists only at the top level triggers no lookup.
- The client is a required argument of `createProposalComputation`; `actionRegistryComposition.ts` passes `createAresHttpClient()`.
