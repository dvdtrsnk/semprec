## Authorize agent-run watching inside the socket's tenant

Closes #1027.

**What changed**
- `agentRunWatch.ts`: each watcher records the tenant of the socket that registered it. `watch` runs `getAgentRun`, the replay query and the catch-up fetches inside `runInTenant(tenantId)`. The existing `actorUserId === userId` check still decides ownership. A foreign run, an unknown run and another user's run all take the same silent path.
- `forwardEvent(tenantId, runId, eventId)` and `forwardDelta(tenantId, message)` deliver only to watchers of the publisher's tenant. A replaying watcher queues an id only from its own tenant. The event row fetch runs inside the tenant scope.
- `syncServer.ts`: passes `identity.tenantId` to `watch`, and `envelope.tenantId` into `enqueueAgentEvent` and `forwardDelta`. The delta path no longer wraps the call in `runInTenant`, since it reads no rows.
- `syncServer.test.ts`: new block on the two-tenant runtime-role harness. It covers a foreign-tenant socket getting nothing, as for an unknown run; own runs (user- and heartbeat-triggered) getting replay, then live events and deltas in order; and forged envelopes stamped with another tenant being dropped. I also renamed the heartbeat test's "earliest" account to the tenant's user.
