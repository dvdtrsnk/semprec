## What changed
- **Migration `0068_agent_run_mcp_credentials_tenant.sql`:** adds `tenant_id uuid NOT NULL DEFAULT app_tenant_default() REFERENCES tenants(id)` and restates the `semprec:tenancy=global` comment. The previous release's inserts omit the column and still work.
- **Store (`mcpRunCredentialsStore.ts`):**
  - `createMcpRunCredential` copies the tenant from the run in one `INSERT … SELECT`.
  - New `getMcpRunCredentialTenantByTokenHash` reads only the global tables and requires an unexpired credential and an active tenant.
  - The active lookup now also requires `c.tenant_id = r.tenant_id` and returns `tenantId`.
  - Neither raw lookup is exported from `@semprec/data`.
- **Resolution (`mcpRunCredentialAction.ts`):** `resolveMcpRunCredential(pool, token)` reads the token's tenant in `runAsSystem("mcp:runCredentialTenant")`. It then reads the credential and its run under RLS inside that tenant. Unknown, expired, run-not-running and inactive-tenant tokens all return `null`.
- **Mint guard:** `mintMcpRunCredential` now takes a `PoolClient`. After the capability check it requires a live item in the Projects database, otherwise it throws `NotFoundError("Project not found")` with no details. A missing Projects database stays a plain `Error`.
- **Handlers:**
  - `agentRunHandler.ts` validates `projectItemId` with `assertUuid`.
  - `mcpHandler.ts` calls `resolveMcpRunCredential` inside the existing system-scope wrapper and uses `credential.tenantId`. The interim `getUserTenantBinding` lookup is gone.

## Tests
- The existing callers are updated to the new signatures and seed a real Projects item. I also updated three callers outside the issue's file list that would no longer compile: `leastPrivilegeRoles`, `mcpRunCredentialExpiryPerTenant` and `bespokeListenerTenantScope`.
- Test helper `createTestProjectItem` is exported from `@semprec/data/testSupport`. It creates the Projects database first if the tenant was not seeded, so it works for a second tenant.
- `agentRunHandler.test.ts` now covers the mint guard:
  - A non-UUID id gets 400.
  - A random UUID, a Tasks item and a soft-deleted Projects item each get 404 and create no run or credential row.
  - A live Projects item gets 201.
- `mcpHandler.test.ts` checks that a `tools/call` runs inside the credential's tenant scope. It also checks that unknown, expired, finished-run and suspended-tenant tokens all get the same 401 as an unknown token.
- New `mcpRunCredentialTenant.test.ts` in the data package covers:
  - the column, its default and the table comment;
  - the stored tenant matching the run's;
  - each credential resolving into its own tenant;
  - suspended-tenant refusal;
  - a foreign Projects item being refused;
  - the old-release insert shape still working.
- New `mcpRunCredentialTenancy.test.ts` uses two tenants on a `semprec_data` pool:
  - Tenant B minting with tenant A's Projects id gets a response identical to the random-UUID case.
  - `item.get` with a foreign id equals `item.get` with an unknown id.
  - `database.query` on tenant A's Projects database never returns tenant B's rows.
