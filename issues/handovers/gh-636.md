## Send the password-reset mail after the response is committed (#636)

`requestPasswordReset` no longer waits for the reset email to send before it returns. A known email now answers as fast as an unknown one, so response time no longer reveals which emails are registered.

The two touched test files pass (42 tests). The full backend `pnpm run verify` did not pass: one test failed and there was one unhandled error, both in code this change doesn't touch (details below). `web/ verify` was not run because nothing under `web/` changed.

### Changes
- **`backend/packages/data/src/auth/passwordResetActions.ts`**
  - The file now imports `runAfterCommit` from `../db/pool.js`.
  - Inside the `withTransaction` callback, after `createPasswordResetToken`, a `runAfterCommit` callback starts `mailer.sendPasswordResetEmail(...)`. Nothing awaits it; a failed send is logged with the same `console.error` as before.
  - Because the send only starts after `COMMIT`, a rolled-back token transaction sends no email.
  - The old block after the transaction (the `if (!created) return;` check and the awaited send) is removed, and the transaction callback now returns `void`.
  - The docstring is rewritten: the token commits first, the email goes out after `COMMIT` without being awaited, and a send failure is logged but never reaches the caller (per `docs/adr/2026-09-10-side-effects-follow-the-commit.md`). The false claim "no distinguishable timing-free signal" is removed.
- The HTTP handler is unchanged.

### Tests
- **`passwordResetActions.test.ts`**, in `describe("requestPasswordReset")`:
  - A fake mailer whose send stays pending until the test calls `release()`: `requestPasswordReset` resolves for a known email while the send is still pending, and the recorded `to` is the user's email.
  - A mailer whose send rejects: `requestPasswordReset` still resolves `undefined`, the failure is logged via `console.error`, and `countRecentPasswordResetTokens` is 1.
- **`authHandler.test.ts`**, in `describe("POST /api/auth/password-reset/request")`: a listener built with the same kind of pending mailer answers a known email with 200 `{ ok: true }` before `release()` is called.
- Existing cases in both `describe` blocks are unchanged and still pass. The only other edits to these test files are the new imports the tests need.
