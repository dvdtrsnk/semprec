## What was delivered

The voice notes of an Inbox item now become its system-owned text property `transcribedText`, without ever touching the person's `text`.

- `Inbox.transcribedText`: a `text` property, owner `system`, owner process `transcribe` (`TRANSCRIPTION_OWNER_PROCESS`), added to `seedInboxPipeline.ts` for new tenants, with the labels "Přepis" (cs) and "Transcribed text" (en) in the Inbox catalogs under `property.inbox.transcribedText.name`. Existing tenants get it from the new per-tenant cutover `seed/inboxTranscribedTextCutoverMigration.ts` (`runInboxTranscribedTextCutoverMigration`, raw INSERT after `LOCK TABLE properties IN EXCLUSIVE MODE`; skips a missing Inbox database and an existing property), registered in `runTenantCutoverMigrations` after the gh-1977 entry and before the area-note cutover that stays last.
- Core task `inboxVoiceNoteTranscribe` (`CORE_TASK_NAMES.INBOX_VOICE_NOTE_TRANSCRIBE`, affinity `transcribe`, tenancy `tenant`). The metadata job of gh-1965 enqueues it in the same transaction that records a voice note's metadata (job key `inbox-voice-note:<inboxItemId>`, replace mode, tenant lane, 3 attempts); a rollback of the metadata write rolls the job back too. A recording (120 seconds or longer) enqueues nothing.
- Handler `semprec-transcribe/src/inboxVoiceNoteTranscribe.ts`, registered on the existing short-model-task runner of `queueRuntime.ts`: reads the item's `voiceNote` attachments in position order (`readInboxVoiceNotes`), downloads each outside any transaction, calls `audioGatewayClient.transcribe` with the probed length, joins the trimmed non-empty transcripts with a blank line and writes `transcribedText` through `updateItemWithClient` as the `transcribe` owner process (`recordInboxTranscribedText`) under the item row lock. An unchanged text writes nothing; a changed voice-note set (read again under the lock) fails the run for retry; a gateway failure or budget refusal fails the job for retry and never alters text.

## Deviations from the specification and spec seams

1. The Task's Touches names only service files for the producer side; the job key, payload schema, enqueue helper, the read of the voice notes and the guarded write live in a new data-package module `inbox/inboxVoiceNote.ts`, because `tenantLane` and `INBOX_MODULE_ID` are not exported from the data barrel and the Inbox tables are written through the owning module's store.
2. The handler is registered on the existing short-model-task runner (no fifth runner); the `queueRuntime.test.ts` expectation was updated.
3. Beyond the Task, an ADR records the contract.
4. A voice note over `MAX_VOICE_NOTE_BYTES` (32 MiB) is skipped and logged by attachment id (io-hardening size cap; not in the Task).
5. A voice note with no positive probed length is not transcribed (the gateway requires `audioSeconds > 0`).
6. With no voice note left the job writes nothing: an already stored transcript of a deleted note stays, and deleting an attachment enqueues no job (noted in the ADR).
7. The commit trailer names Claude Sonnet 5.5 (the session attribution) instead of the model named in the task text, as the gh-1965 handover also recorded.
8. The existing property-list assertion in `inboxPipeline.test.ts` was updated for the new property.
