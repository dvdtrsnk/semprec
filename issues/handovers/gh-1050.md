Closes #1050

The agents process now cancels a deactivated tenant's running agent runs, and those runs close as `error`. The change is committed. The only checks I ran were lint, `format:check`, the `semprec-agents` build and the dotted test files below; I did not run the full `pnpm run verify` or the `web/` checks.

- **Cancellable turn** (`lifecycleAdapter.ts`):
  - `runAgentTurn` and `RunAgentSessionInput` take an optional `signal`.
  - An already-aborted signal throws before the first message is read. An abort during a wait or a record stops the loop, and either way the session iterator's `return()` runs. The turn then throws the new `AgentRunCancelledError`.
  - `AgentRunCancelledError` has the message `"account deactivated"` and is exported from the package index.
  - The existing catch in `runAgentSessionForRun` closes the run as `error` with its notification, unchanged.
- **Registry** (`inFlightAgentRuns.ts`): `createInFlightAgentRuns()` returns `register(tenantId, controller)` (which gives back an unregister function) and `abortTenant(tenantId)` (which returns the count aborted).
- **Registration** (`agentRunTasks.ts`): `createAgentRunTask` and `createRunAgentForHeartbeats` take the registry as a new last parameter. They read the tenant from `currentTenantScope()`, register a controller, pass its `signal` down and unregister in `finally`. Outside a tenant scope they throw before composing a session.
- **Wiring**: `serve.ts` creates one registry, passes it to both factories and starts `startTenantDeactivationListener` after the queue runtime. `createGracefulShutdown` takes the listener and closes it before `queueRuntime.stop()`. A failing `close()` is logged with only the error name and shutdown carries on.

Decisions and caveats:
- **Cancel semantics:** on cancellation `return()` is not awaited. An async generator queues `return()` behind a `next()` it is still awaiting, so awaiting would hold the run open until a slow session yields. A failing `return()` is logged and never replaces the cancellation error.
- **Registration scope:** in `createAgentRunTask` the registration covers the whole job, including session composition. A deactivation during composition therefore shows up as an already-aborted signal when the turn starts.
- **Changed existing tests:** `agentRun.e2e.test.ts` called the task handler outside any tenant scope, which now throws. I wrapped those three calls in `runInTenant(getTenantZeroId(), …)`. Both existing test files that build the factories were also updated for the new parameter.

Tests added:
- `lifecycleAdapter.test.ts` has six new cancellation cases: abort while waiting, already aborted, abort during record, normal completion with a signal, a failing `return()`, and the full close through `runAgentSessionForRun`.
- `inFlightAgentRuns.unit.test.ts` and `shutdown.unit.test.ts` cover the registry and the shutdown order and failure handling.
- `agentRunCancellation.test.ts` uses two tenants, the real listener and `suspendAccount`. It checks that tenant B's run ends `error` with its notification and tenant A's ends `done`, and that the registry is empty afterwards. It also covers the heartbeat path and both outside-tenant-scope throws.
