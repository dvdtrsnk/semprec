# gh-1416 — Add calendar properties to the Events schema

## Delivered behavior

`seedTenDatabases.ts` gives the Events database nine more properties: `endDate` (date), `timeFrom`, `timeTo` (time), `time` (time, system-owned, locked), `place` (text), `url` (url), `description` (longText), `alertMinutes` and `travelMinutes` (number); all other ones are user-owned. `name`, `type` and `date` (with `includeTime: true`) are unchanged.

`runEventsCalendarPropertiesCutoverMigration` (`calendar/eventsCalendarPropertiesCutoverMigration.ts`) inserts the absent properties with direct SQL into an existing Events database (the schema is locked), under `LOCK TABLE properties`. It is idempotent, a no-op without an Events database, and is registered in `runTenantCutoverMigrations`. Definitions equal the seed's (NULL name, empty config).

cs/en catalogs have `property.events.<key>.name` for all nine keys.

## Tests

`calendar/__tests__/eventsCalendarPropertiesCutoverMigration.test.ts`: fresh seed types/owners/locked and untouched `date` config; cutover on a database with the nine properties removed restores a schema identical to a fresh seed, second run changes nothing; no-op without an Events database. Ran together with the `tenDatabases` and `smoke` tests (pass); lint, prettier and tsc pass. Full verify NOT RUN.

## Notes for dependants

- Nothing normalizes, derives or validates the new values yet (#1598, #1663). Existing Events items are not backfilled (#1797).
- An Event without `timeFrom` is all-day; there is no `allDay` property.
