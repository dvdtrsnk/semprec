## Summary

Implements the sync core of the email module (spec section 6, first half): a bidirectional sync engine between a real mailbox and our DB, where the provider's server stays the source of truth.

- Three sync adapters over one shared target schema — IMAP (via imapflow), Gmail REST API, and Microsoft Graph REST API — differing only in how they detect/apply changes, not in the data model they write to.
- State-conflict handling: IMAP UIDVALIDITY resets + CONDSTORE/QRESYNC (falling back to a full UID diff on servers without it), Gmail `historyId` 404 invalidation, Graph `deltaLink` 410/resyncRequired — each triggers a full resync and clears the stale cursor.
- JWZ-style conversation threading with self-healing dummy containers for out-of-order delivery.
- Deterministic People↔email-address linking via `person_email_index`, enforced unique at the DB level.
- Reversible credential encryption (`@semprec/credentials` + `external_credentials`/`credential_access_log`), narrow decrypt accessor, generic across mail and future consumers (MCP).
- MIME attachment classification (real vs. inline-cid rendering asset), content-hash dedup via `blobs`, and memory-safe streaming: all three adapters stream attachment bytes part-by-part rather than buffering a whole message/attachment-set in memory.
- HTML body sanitization (remote-image blocking, explicit `style` property allowlist) and Postgres full-text search over message content.
- `Mailboxes.syncStatus` (ok/error/needsReauthorization) is written by the sync worker on every pass.

## Process note

This PR's first commit was inherited from a prior agent run that crashed mid-turn before ever opening a PR or being reviewed. This run cherry-picked that work, then ran two independent strict review passes against it (scope, correctness, security, architecture) and fixed everything both passes found, including:
- attachment ingestion previously buffered whole messages/attachment sets in memory (the exact OOM risk the spec calls out) — rewritten to stream part-by-part for all three adapters
- the Graph adapter never actually fetched attachments at all — implemented
- `Mailboxes.syncStatus` was defined in the schema but never written by any code path — wired up
- an HTML-sanitizer gap let a CSS `url(...)` tracking pixel through a `style` attribute — closed, then a follow-up regex bypass in that same fix was found and closed
- a pre-existing bug in `findOrCreateBlob`'s `ON CONFLICT` clause (didn't match its own partial unique index) — caught by finally exercising the attachment-ingest path end-to-end for the first time
- attachment bytes written to disk before a later step in the same sync pass fails no longer leak — cleaned up on rollback
