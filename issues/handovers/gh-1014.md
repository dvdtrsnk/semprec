Registering a push endpoint or APNs device token that another account holds now moves it silently to the registering account. The route answers 200 `{ subscription }` exactly as it does for a fresh endpoint. The 31 integration tests in the two data-package test files I touched pass, and `build`, `lint`, `format:check`, `check:write-safety` and `check:boundaries` pass. I did not run the full `verify` pipeline or anything in `web/`; Relay's verify step covers those.

**Change** (`backend/packages/data/src/push/pushSubscriptionsStore.ts`)
- `upsertWebPushSubscription` and `upsertApnsSubscription` first revoke any active row for the same endpoint or token owned by another user. They then run the existing upsert unchanged, so the caller's own active row is still refreshed in place with the same `id`.
- If the upsert returns no row, a concurrent registration by another account got in between. Both statements are repeated once; a second miss throws a plain `Error` that names the race and no account.
- Given a bare `Pool`, both functions open the transaction themselves (`withTransaction`). Displacement and upsert always commit together, so a failed insert never leaves the previous owner revoked.
- Both `ConflictError` throws and their docstrings are gone, replaced by the new contract.
- The two channels share a small private helper, `displaceAndUpsert`, for the retry logic.
- The displacement `UPDATE` returns its `rowCount` so the write-safety check passes without a baseline change. Zero rows is the normal case there.

**Tests**
- `pushSubscriptions.test.ts`:
  - The two "rejects another user's registration" tests are replaced by rebind tests for web push and APNs.
  - Each checks that the new row has a new id and the new owner's keys.
  - Each checks that the old row is revoked with its keys unchanged, and that exactly one active row exists.
  - Two atomic-displacement tests, one per channel, use a test-created insert trigger for account B. They run against both a transaction client and a bare `Pool`, and in each case A's row is still active afterwards.
- `pushRouteHandlers.test.ts`: a registration of a held endpoint and of a fresh endpoint both return 200 with the same body shape. Neither body contains A's id or user id.
