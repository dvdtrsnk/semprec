This change enforces the 8-character minimum password length when a password-reset link is used, and closes #630. A shorter password is now rejected and the reset link still works afterwards.

## Changes
- **`backend/packages/data/src/auth/authActions.ts`**: `MIN_PASSWORD_LENGTH` is now exported, so other code can import it from `@semprec/data`. Its docstring is unchanged and `createAccount` behaves as before.
- **`backend/packages/data/src/auth/passwordResetActions.ts`**: `resetPassword` throws a `ValidationError` (`field: "newPassword"`) when `newPassword` is shorter than `MIN_PASSWORD_LENGTH`. The check runs before `consumePasswordResetToken`, so a rejected password leaves the single-use token unconsumed, and the docstring says so. The HTTP handler is unchanged: it already answers `ValidationError` with 400 `validation_failed`.
- **Tests**:
  - `passwordResetActions.test.ts`: a 7-character password is rejected with `ValidationError` and the token's `consumed_at` stays `NULL`. The same token then works with an 8-character password.
  - `authHandler.test.ts`: `newPassword: "short"` gets 400 `validation_failed`, then a second consume with the same token and a valid password gets 200.
  - `publicSurface.test.ts`: this file is not in the issue's Touches list. Its frozen export list has to include `MIN_PASSWORD_LENGTH` because the acceptance criteria require it to be importable from `@semprec/data`. Without this line that test fails.
