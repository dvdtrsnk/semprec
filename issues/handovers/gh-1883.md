## What was delivered

- Heartbeat action `core.journalWeeklyCleanup`. The handler reads, without writing and without a model call, every Journal period (type and key) that has more than one live entry (capped at 50 periods per run), then delegates to the `core.agentRun` handler with `action_config.task` followed by those periods under a localized heading. It never calls `mergeJournalDuplicates`; the task text sends each merge through the approval-gated `page.mergeJournalDuplicates` operation.
- Heartbeat "Weekly journal cleanup": weekly rule, Sunday 21:00, on the Semprec project, task text from `journal/i18n/cs.json` and `en.json` by the tenant user's locale (Czech while the tenant has no user). Created for new tenants in `seedSystem` and for existing tenants by `runJournalWeeklyCleanupCutoverMigration`, both idempotent by heartbeat name and action id; the cutover does nothing for a tenant without a Semprec project.
- The action starts an agent session, so it routes onto `heartbeatFireAgent` and the per-tenant agent-run lane (`AGENT_SESSION_ACTION_IDS` in `scheduler/actions.ts`) and is registered in the agents runtime registry, not the api runtime registry.
- Failure of the duplicate search (or catalog load): the handler opens the agent run itself in the tick thread through `coreAgentRunAction` with the bare task and an agent step that throws the search error, so an `agent_runs` row with status `error` exists, chained to earlier attempts, and the handler rejects with the search's own error. A failure to record that run is logged and never replaces the search error. A missing or empty task is refused before any run.
