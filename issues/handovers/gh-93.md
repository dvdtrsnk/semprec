## Summary

- Persists `deliveredToAddress` at ingest (`mail_message_meta.delivered_to_address`) using the exact precedence order: highest `Delivered-To` occurrence → `X-Original-To` → `Envelope-To` → first registered `Mailboxes.addresses` alias matching structured To/Cc → mailbox primary (first) address. Resolved once, centrally, in `mail/ingest.ts`; never recomputed downstream.
- Detects `multipart/report; report-type=delivery-status` DSN/bounce mail (`mail/dsn.ts`) across all three adapters (IMAP BODYSTRUCTURE, Gmail/Graph raw `Content-Type` header) and tags it `messageKind: 'dsn'` with `dsnOriginalMessageId` (from References/In-Reply-To) — still threaded normally via `threading.ts`, just distinguishable from an ordinary human reply.
- `People.emails`/`person_email_index` deterministic linking already existed (issue #26) — this PR only adds regression tests confirming normalization/determinism, per the acceptance criteria.
- Adds a resumable legacy-Emails backfill job (`migrationJob/mailLegacyEmailMigration.ts`, task `mailLegacyEmailMigration`) that parses raw MIME via an injected fetcher when available (`migrationStatus: 'done'`), otherwise reconstructs `envelope`/`threadId`/`messageId` as far as possible from legacy `sender`/`recipients` display text (`migrationStatus: 'partial'`). Idempotent via a `LEFT JOIN mail_message_meta ... WHERE item_id IS NULL` filter — a retry never reprocesses an already-migrated row. Guards against a recovered Message-ID colliding with an already-synced duplicate item by falling back to a synthetic id rather than silently stealing that item's row.
- New additive-only migration `0007_mail_delivered_to_and_dsn.sql` (nullable/defaulted columns + a partial index on `mail_message_meta`, a table this PR didn't create).
