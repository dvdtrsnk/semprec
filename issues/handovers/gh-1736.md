## What was delivered

- `POST /api/mail/mailboxes`, a custom route of the mail module (`mailboxPasswordConnect`, justification `transactional-semantics`), handler `createMailboxPasswordConnectRouteHandler(pool, dependencies)` in `backend/packages/data/src/mail/mailboxPasswordRouteHandlers.ts`. It needs a session; the tenant is the session's.
  - Body `{ provider: "icloud" | "generic", address, password, imapHost?, smtpHost?, username? }`, parsed with a strict zod schema (an unknown key is refused).
  - `imapHost` and `smtpHost` are required for `generic`, validated by `normalizeMailServerHost` (a DNS name; no IP literal, no local name), and refused for `icloud`.
  - `address`: one address without whitespace, `@` or comma in either part, at most 320 characters, trimmed; no control character (`\p{Cc}`) and no unpaired surrogate.
  - `username`: optional, at most 320 characters, not blank, the same character rule; it defaults to the address as typed.
  - `password`: 1 to 1024 characters, any character.
- The flow, in this order:
  1. The body is validated.
  2. The verification is read from the container member `mailServerClients.verifyPassword`. A composition root that set none fails the request with a plain error, which the adapter answers as a generic 500.
  3. One READ COMMITTED transaction reads the duplicate rule. A held address answers 409 before any mail server is contacted.
  4. Outside any transaction the verification checks the login on IMAP and SMTP.
  5. One READ COMMITTED transaction reads the duplicate rule again and writes: the Mailboxes item through `createItemWithClient` (name from the mail catalog in the caller's `users.locale`, `provider`), the address through `writeMailboxAddresses`, the password through `storeCredential` (`app_password` for iCloud, `plain_password` for generic), the verified IMAP and SMTP endpoints and the user name through `upsertMailServerSettings`, the sync state through `ensureMailAccountSyncState` with mode `imap`, the address through `recordProviderAccountAddress`, and the first sync through `enqueueMailAccountSync(client, id)`.
- The duplicate rule (`mailboxHoldsAddress`): the normalized address is the `provider_account_address` of a sync state row of the tenant, or an entry of the `addresses` list of any Mailboxes item of the tenant (split by `parseAddressListProperty`, compared after `normalizeEmailAddress`). A Mailboxes item in the trash counts.
- `serve.ts` sets `mailServerClients: { verifyPassword: verifyMailCredentials }`, so production runs the verification of gh-1569.
- The catalog keys `mail.mailbox.defaultName.icloud` and `mail.mailbox.defaultName.generic` in `backend/packages/data/src/mail/i18n/cs.json` (`iCloud`, `Jiný účet`) and `en.json` (`iCloud`, `Other account`).
- The route matrix entry `{ name: "mailbox password connect", method: "POST", path: "/api/mail/mailboxes", surface: "api", public: false, tenancy: "tenant" }` in `backend/services/semprec-api/src/routeMatrix/mailMailboxes.ts`, its `ROUTE_CASES` case in `tenantIsolationRoutes.test.ts` and its `ROUTE_HANDLER_FILES` mapping to `packages/data/src/mail/mailboxPasswordRouteHandlers.ts`, all in the same merge.
- The ADR `docs/adr/2026-11-10-password-mailbox-connect-rechecks-its-duplicate-rule-at-read-committed.md` (accepted, area backend): both transactions run at READ COMMITTED and the reads of the rule take no row lock. It narrows `docs/adr/2026-09-10-bracket-non-transactional-calls-with-staleness-checked-transactions.md` for this one route.

## Contracts dependents build on

For gh-1750 (throttle of the verification, capability blocker) and gh-1742 (reauthorize a mailbox, which names this source as a shared-file-ordering blocker only).

- Answers of the route:
  - 201 with the created Mailboxes item in the usual item envelope.
  - 400 `validation_failed`, with `details.field` when one field is at fault. No message repeats a value of the body.
  - 400 with the verification's own code: `mail_auth_failed`, `mail_app_password_required`, `mail_server_unreachable`, `mail_tls_failed`. Nothing is stored.
  - 409 `provider_account_already_connected`, the code alone. The body has no `details.mailboxId`; the OAuth connect route of gh-1686 answers the same code with it.
  - 500 `internal_error` on a dispatcher whose container has no `mailServerClients.verifyPassword`, and for any verification failure that is not one of the four refusals.
  - 401 without a session.
- Order inside the handler, for gh-1750: `parseConnectRequest`, then `requireVerifyPassword`, then the catalog read, then the first read of the duplicate rule, then the verification. The Task of gh-1750 reserves its slot after the body validation and before the verification; the early 409 sits between those two points, so gh-1750 decides on which side of it the reservation goes.
- From the `@semprec/data` barrel: `createMailboxPasswordConnectRouteHandler`. The type `MailboxPasswordRouteDependencies` is exported from the module, not from the barrel; `CustomRouteDependencies` of `semprec-api` is assignable to it.
- Container member (`backend/services/semprec-api/src/adapter/customRouteMount.ts`): `MailServerClients.verifyPassword?: (input: VerifyMailCredentialsInput) => Promise<VerifiedMailServerSettings>`. This replaces the shape `(settings, password) => Promise<void>` that gh-1460 had left for this issue. It is read per request, after the body validation, and never while the factory runs.
- A test that drives the route with a valid body passes the member. `tenantIsolationRoutes.test.ts` builds its dispatcher with `customRouteDependencies: { ...MAIL_OAUTH_DEPENDENCIES, ...MAILBOX_PASSWORD_DEPENDENCIES }`; a later source that needs another member adds it to that object. `MAILBOX_PASSWORD_DEPENDENCIES` refuses the password `REFUSED_MAILBOX_PASSWORD` with `MailAuthFailedError` and accepts every other one.
- Rows a password mailbox consists of, all written in one transaction: one Mailboxes item, one `external_credentials` row (`app_password` or `plain_password`), one `mail_account_server_settings` row, one `mail_account_sync_state` row with sync mode `imap` and `provider_account_address`, and one queued job `mailAccountSync` with job key `mail-account-sync:<mailbox id>`.

- The isolation case leaves one mailbox in tenant A and two in tenant B, created through the route, and three queued `mailAccountSync` jobs. Later cases of that file see them; the file passes as a whole (246 tests).

## Deviations from the specification and spec seams

1. Spec seam: the route entry is in the slice module `backend/services/semprec-api/src/routeMatrix/mailMailboxes.ts`, not in `routeMatrix.ts`.
2. The mailbox name is not the literal `iCloud` or `Jiný účet` of Task step 3. It is the catalog entry `mail.mailbox.defaultName.<provider>` in the caller's `users.locale`: a Czech user gets the Task's literals, a user with an English or unknown locale gets `Other account` for the generic provider.
3. The duplicate rule is also read before the verification. A held address answers 409 without the password being sent to a server, so a wrong password for a held address answers 409 and not the verification's code.
4. Both transactions run at READ COMMITTED, not at the repeatable read of the bracket ADR, and the reads of the rule take no row lock. The new ADR records it. The address-list half of the rule is read again and not serialized against a concurrent writer.
5. A Mailboxes item in the trash counts as holding its addresses.
6. The 409 body carries the code only, no `details.mailboxId`. The Task asks for 409 and nothing more.
7. The four verification refusals are plain errors with a code; the route maps them to `ChokePointError(400, code)`, the status the error contract assigns them.
8. Validation beyond the Task's wording: unknown keys, a comma in the address, the length bounds, control characters and unpaired surrogates in the address and the user name.
9. Changed by the fix round, so the worker's report no longer describes it: the route has no verification of its own. `mailServerClients.verifyPassword` is a member the composition root sets (`serve.ts`), and a mount without it answers a generic 500, as `docs/adr/2026-10-29-custom-route-composition-root-dependencies.md` decides. The handler throws a plain `Error`, not `CustomRouteConfigurationError`, because `packages/data` cannot import the adapter's helper.
10. Files outside `Touches`: the two mail catalogs, `customRouteMount.ts` and its test, `serve.ts`, `chokePointWriteBoundary.unit.test.ts`, `publicSurface.test.ts`, `mailSyncAdapters.test.ts`, the two route matrix slices, the ADR, and the three comments named under Files.
11. The ADR is dated 2026-11-10, the day an interrupted earlier run created the file; the commits are from 2026-11-11.
