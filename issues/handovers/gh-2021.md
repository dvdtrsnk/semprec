## What was delivered

- `toApprovalRequestArgumentValues(args)` in `backend/packages/data/src/mcp/approvalRequestArguments.ts` (pure; exported from the `@semprec/data` barrel with the type `ApprovalRequestArgumentValues`). It returns `{ arguments, argumentsTruncated }`:
  - the value of a key that contains `password`, `secret`, `token`, `apikey`, `api_key`, `authorization`, `cookie` or `credential`, case-insensitively and at any depth, is replaced by `[redacted]` (redaction is applied before bounds and does not count as truncation);
  - a string is cut to 2000 UTF-16 code units without leaving a lone high surrogate;
  - a value nested deeper than 32 levels is replaced by `null` (the walk is bounded);
  - the JSON of the arguments is capped at 16384 UTF-8 bytes: whole entries are kept in order first, then a partial container; an array keeps a prefix and ends at the first element kept in part;
  - `argumentsTruncated` is true when a string was shortened, a value was cut for its depth, or an entry did not fit the byte cap.
- `GET /api/approval-requests/:id` adds `arguments` and `argumentsTruncated` for an `mcpInvoke` request and omits both for a generic-operation request. A foreign, unknown or other-tenant id still answers the same 404 before any value is read.
- The list, the count, the PATCH answer, the description, the notification body and the push payload carry no argument value (the push body is built from the notification body).
- ADR `docs/adr/2026-11-12-mcp-argument-values-leave-the-server-only-in-the-owners-request-detail.md` (accepted, backend) records the owner-only detail as the one place argument values leave the server, with the redaction list, bounds, drop order and the meaning of `argumentsTruncated`; the module header and the handler JSDoc point to it.

## Deviations from the specification and spec seams

2. The Task does not say what "cap at 16 KiB" does to an oversized object or how deep the walk may go. Decided in the module and the ADR: entries that do not fit are dropped, whole entries preferred over partial ones; depth limit 32 replaced by `null`; non-JSON leaves become `null`.

4. The key list is exactly the one the Task prescribes, so a hyphenated key such as `x-api-key` is not matched (noted by the security reviewer; specified behaviour).
