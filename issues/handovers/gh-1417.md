# gh-1417 — Record the server-driven editor schema in an ADR and add it to module manifests

Repository-Issue: gh-1417

This completion is proposed on an isolated implementation branch; it becomes canonical only after reviewed integration. No PR has been published by this worker.

## Delivered behavior

- New ADR `docs/adr/2026-10-25-server-driven-inbox-editor-schema.md` (`status: accepted`, `area: [backend]`). It records the owner (the manifest of the module that owns the card's target database), the base-kind key, the field shape, the rule that a field hidden by a condition is neither validated nor written, the rule that required-ness is an error on confirm and a warning on edit, localized text from catalogs, and the collision rule. Enforcement is delivered by #1928 and #1934.
- `backend/packages/module-registry/src/manifest.ts`: optional `editorSchemas: Record<baseKind, EditorSchemaDescriptor>` on `ModuleManifest` and in `moduleManifestSchema`, with `groups` of `{ key, fields }`. It exports the constants `EDITOR_FIELD_CONTROLS` and `EDITOR_FIELD_INPUT_TYPES` and the types `EditorSchemaDescriptor`, `EditorGroupDescriptor`, `EditorFieldDescriptor`, `EditorFieldCondition`, `EditorFieldControl`, `EditorFieldInputType` and `EditorFieldValue`.
- The schema rejects `timeHiddenWhen` on a non-`datetime` control, `inputType` on a non-`text` control, and an empty group. It also rejects `options` on a non-`seg` control, an `info` control without `infoKey`, a condition with neither or both of `equals` and `notEquals`, and any unknown field attribute.
- `ModuleRegistry.loadModule` rejects a module whose base kind a previously loaded module already declares. The error names both module ids. The check runs before anything commits, next to the custom-route check, and covers loaded modules whether or not they are active.
- `ModuleRegistry.getEditorSchemas()` returns `{ moduleId, baseKind, schema }[]` for active modules. Each schema is a deep copy.
- `backend/packages/data/src/inbox/inboxModuleManifest.ts` declares base kind `mcp` with the six fields `name`, `transport`, `url`, `command`, `credential` and `mcpProjects`, in groups `server` and `projects`.
- `backend/packages/data/src/inbox/i18n/en.json` and `cs.json`: ten `editor.mcp.*` label and placeholder entries each.

## Decisions taken where the issue left room

- Conflict: the Task's field shape (item 2) has no static option list, but item 4 declares `transport` as a `seg` control with options `http` and `stdio`. The closest reading is an optional `options` attribute, accepted only on `seg`. It is the only addition beyond the listed shape.
- An `info` control requires `infoKey`. The Task ties `infoKey` to info rows, so this is the stated rule made checkable.
- Groups carry a `key` and `fields` only. The Task specifies no group label, so none is declared.
- The collision check covers every loaded module, active or not. The Acceptance criterion names active modules. Owners are fixed at load time, as for custom routes, so the stricter check also satisfies the criterion.

## Notes for dependants

- #1825 reads `getEditorSchemas()` and resolves labels and placeholders through the declaring module's catalogs. The `seg` option values `http` and `stdio` have no catalog labels, and the Task's catalog scope does not add any. #1825 or a later issue must decide whether they are translated.
- The manifest checks `key` only for being non-empty. #1825 must check each key against the owning database: a property, a relation, or one of the pseudo keys listed in the ADR.
- Nothing evaluates `required`, `when` or `timeHiddenWhen` yet. A declaration is inert until #1928 and #1934.
- The schema does not check that a `when` or `timeHiddenWhen` names a field of the same schema. A condition on a missing field is accepted. #1928 and #1934 should decide how to treat it.
- Declaring a second module for an existing base kind fails the whole registry load at startup. Any future card kind needs its own base-kind claim in its owning manifest.
