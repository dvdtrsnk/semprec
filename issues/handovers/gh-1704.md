## What was delivered

- `PATCH /api/account/profile` in `createAccountRoutes` (`backend/services/semprec-api/src/accountHandler.ts`). The body is a JSON object with exactly one key, `locale`, whose value is `cs` or `en`. The account is the authenticated one (`ctx.identity.user.id`); the body cannot name another.
  - Any key other than `locale` (`displayName`, `avatarColor`, `userId`, anything else) answers 400 `validation_failed` with `details.field` set to that key. The extra-key check runs before the locale check.
  - A missing, `null`, non-string, blank, upper-case or unsupported `locale` answers 400 `validation_failed` with `details.field` `locale`. A body that is not a JSON object, or malformed JSON, answers 400 `validation_failed` without a field.
  - In one `withTransaction` of the session's tenant it calls `updateUserLocale`; when a row came back it calls `enqueueTenantSearchReindex(client)` on the same client; otherwise it reads the row with `getUserById` and throws `NotFoundError` when it is gone; then it reads `getSelfPersonId`.
  - It answers 200 `{ user }`, where `user` is the object `GET /api/auth/session` returns: the public user fields (`id`, `email`, `displayName`, `locale`, `createdAt`, no password hash), `role` from the identity and `personId`.
- `backend/packages/data/src/auth/locales.ts` (new): `SUPPORTED_LOCALES = ["cs", "en"] as const`, the type `SupportedLocale` and the guard `isSupportedLocale(value: unknown): value is SupportedLocale`. Exported from the data barrel.
- `updateUserLocale(client, userId, locale: SupportedLocale): Promise<UserRow | null>` in `backend/packages/data/src/auth/usersStore.ts`. One statement, `UPDATE users SET locale = $2 WHERE id = $1 AND locale IS DISTINCT FROM $2 RETURNING ...`. It returns the updated row only when it changed the stored value, and `null` when it wrote nothing: the stored locale already is `locale`, or no user has that id.
- The route matrix entry `{ name: "update profile", method: "PATCH", path: "/api/account/profile", surface: "api", public: false, tenancy: "account" }` in `backend/services/semprec-api/src/routeMatrix/account.ts`, its isolation case in `tenantIsolationRoutes.test.ts` and its `ROUTE_HANDLER_FILES` mapping to `services/semprec-api/src/accountHandler.ts`.

## Contracts dependents build on

- A locale change is visible at once to everything that reads `users.locale`: the tests show `/api/databases` naming collections in the new language and a notification written afterwards in the new language, while a notification written before stays as it was.
- The search index follows asynchronously. A changed locale queues one tenant-wide rebuild in the transaction of the update: the core task `itemSearchBackfill` with `onlyMissing: false`, job key `item-search-backfill:<tenantId>:all:all:start`, through `enqueueTenantSearchReindex` of gh-1652 and the search lane's pre-commit flush. Setting the stored locale again queues nothing. Until that job has run, search documents hold select and multi-select option labels in the previous language.
- `updateUserLocale` returning `null` does not mean "no such user". A caller that needs the row reads it in the same transaction, as the handler does.
- Under READ COMMITTED two overlapping changes to the same value yield one returned row and one rebuild; when the first rolls back, the second gets the row.
- The route accepts only `locale` today. Later profile fields are added to the route by widening the accepted keys; a client that sends another key now gets 400.
- The route publishes no realtime frame. The `account` invalidation frame and its delivery to the user's other devices are gh-1946, which publishes after this route's commit.
- Other answers: 401 without a session, 404 for another method on the path, 413 for a body over the adapter's cap, 404 `not_found` when the account's row is gone by the time the handler runs.
- Runtime exports added to `@semprec/data`: `SUPPORTED_LOCALES`, `isSupportedLocale`, `updateUserLocale` (and the type `SupportedLocale`). They are in the sorted expected list of `publicSurface.test.ts`.
- No SQL migration (`users.locale` exists since migration 0025), no table, no column, no generic operation, no MCP tool, no new job name, no stored key, no write hook and no ADR was added.

## Deviations from the specification and spec seams

1. Spec seam: the route entry is in the slice module `backend/services/semprec-api/src/routeMatrix/account.ts`, not in `routeMatrix.ts`.
2. `updateUserLocale` returns `UserRow | null` and its `UPDATE` carries `AND locale IS DISTINCT FROM $2`, where the Task says it returns the updated `UserRow`. The write itself decides "the stored locale actually changed", with no read before it. Its `locale` parameter is typed `SupportedLocale`.
3. The response `user` also carries `personId`, because `GET /api/auth/session` returns the public user fields plus `role` and `personId` and the Task asks for that shape.
4. Test locations: `Touches` names `backend/packages/data/src/__tests__` for store and route tests. The route tests are in `backend/services/semprec-api/src/__tests__/accountProfile.test.ts`, because a package cannot import the service; the guard's unit test is beside the guard.
5. `backend/packages/data/src/__tests__/publicSurface.test.ts` is not in `Touches`; the three new runtime exports required it.
6. Isolation case in the shared two-tenant fixture: the caller is a member of a third tenant created inside the case, not tenant B, so B's shared user row is not changed. It asserts that A's and B's user rows and queued jobs are unchanged and that A's user id in the body is refused exactly as a random id. The variant authenticated as B on two fresh tenants is the test "changes only the caller's row and queues only the caller's tenant's rebuild" in `accountProfile.test.ts`.
7. An extra key is checked before `locale` and its name is returned as `details.field`.
8. The `not_found` branch cannot be reached deterministically through the dispatcher, which refuses a session without a user row with 401 first. Its test calls the route handler from `createAccountRoutes` directly with such an identity.
9. Acceptance criterion 3 asks that "a search finds the English label of a select option". No HTTP route or MCP tool searches non-Email items on this tree, so the test runs the production `buildItemSearchQuery` expression against `item_search_index` in the tenant scope on the runtime-role pool, after running the queued job with the production API task list's handler.
