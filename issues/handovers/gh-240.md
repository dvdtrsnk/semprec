## Summary

Implements issue #240: exposes database and property metadata operations over the generic REST layer.

- `GET/POST /api/databases`, `GET/PATCH/DELETE /api/databases/:id` — `DELETE` archives rather than hard-deleting; a `system: true` database returns 403 (`forbidden`) on archive.
- `POST /api/databases/:id/properties`, `PATCH/DELETE /api/properties/:id` — enforce `schema_locked` (database) and `locked` (property) as 403 with matching error codes; `schema_locked`/`property_locked` are now their own error classes (still 403, per the #238 contract) instead of a generic `ForbiddenError`.
- Changing a property's `type` via `PATCH` returns 202 after enqueueing the existing `migration_status` job (#21) — the endpoint never migrates inline.
- All routes are thin mappings onto `createChokePoint`'s service calls, resolve display names/labels through the #35 localized-metadata catalog, authenticate via the existing adapter, and never return 204 on a successful mutation.
- Extracted a shared `routeTable.ts` (`RouteDefinition`/`mountRoutes`) so these new generic resource routes and the #239 module custom routes share one path-compiling/dispatch implementation instead of duplicating it.

New tests: `databasesHandler.test.ts` (7 tests) and `propertiesHandler.test.ts` (9 tests) cover CRUD/archive/lock/type-migration paths, including the forbidden system-database archive, `schema_locked`/`property_locked` 403s, the 202-plus-exactly-one-enqueued-job assertion for a type change, and that no successful mutation returns 204. `routeMatrix.ts`/`chokePointWriteBoundary.unit.test.ts` were extended to cover the 8 new routes end-to-end (auth-required, choke-point-only writes).

Verified: `backend`'s full `pnpm run verify` (lint, format, build, unit/integration/e2e tests — 961 + 5 tests) and `web`'s full `pnpm run verify` (lint, format, build, 139 tests) both pass with no regressions.
