# Handover: one mail sync pass per mailbox with a coalesced follow-up, and a quiet IMAP pass that skips unchanged folders

Commits on `feat/internet-accounts`: `319b5758a` (lease and folder change detection), `b0bb4af24` (single-flight and IDLE tests), `fd107126f` (architecture document), `3eaba37b3` (affected-row checks, restore-hook test). Nothing was run against Purelymail or any other real server.

**Root causes.**
- Concurrent passes of one account: every trigger already used `enqueueMailAccountSync` with the job key `mail-account-sync:<mailbox>` (IDLE, Gmail and Graph push, sweep, flag write-back through `mailMessageFlagSyncStore`, move write-back through `mailThreadActions`, Mail switch, sign-in, unfinished backfill). graphile-worker coalesces a repeat enqueue only onto a job that waits; for a running job it clears its key and inserts a new job, which another worker (concurrency 4) starts at once. The comment in `imapConnectionLimiter.ts` claiming the job key serialized passes was false.
- Growing durations (9.8 → 28.5 s): those concurrent passes queued in the per-account IMAP connection limiter (two connections for a generic provider, one held by IDLE), each behind the previous.
- 6.5 s quiet pass: per folder imapflow sent SELECT four times (`selectFolder`, then `mailboxOpen` again in each fetch), plus UID SEARCH, FETCH of all flags and UID SEARCH ALL. Seven round trips per folder with nothing changed.
- Found on the way, not changed: production imapflow is created without `qresync: true`, so QRESYNC is never ENABLEd and `fetchVanishedSince` on a QRESYNC server returns no VANISHED data (expunges there are missed). Follow-up below.

**Changes.**
- `mail_account_sync_state.pass_lease_token`, `pass_lease_expires_at`, `pass_rerun_requested` (baseline). A job claims the lease before its credential read (`claimMailSyncPass`, row `FOR UPDATE`); when a live pass holds it the job sets the rerun flag and ends without a provider call. `enterSyncPass` renews the lease in each write transaction (re-taking it only when no live pass holds it) and ends the pass when another holds it. A `finally` releases the lease and, when a rerun was requested, enqueues exactly one follow-up in the same transaction; a release failure is logged and the 5-minute lease expires. An unfinished backfill requests a rerun instead of enqueueing. Lease rather than a graphile named queue: a crashed holder of a named queue blocks it for graphile's 4-hour stale-lock reset.
- `mail_folder_sync_state.message_count`. On a CONDSTORE server `ImapFlowMailClient.listFolders` asks STATUS (UIDVALIDITY, UIDNEXT, HIGHESTMODSEQ, MESSAGES) with LIST (inline on LIST-STATUS, else one STATUS per folder). A folder whose four values equal its stored state is skipped: no SELECT, fetch or write transaction. In a changed folder the client selects once (`ensureSelected`), the UID search runs only when UIDNEXT passed the cursor, the flag fetch only when HIGHESTMODSEQ moved (always without CONDSTORE), the vanished check only when UIDNEXT or the count changed.
- The folder list is not cached: LIST detects added and removed folders and carries the STATUS in the same round trip.
- Write-back: a flag or move write-back still enqueues the coalesced pass; that pass now touches only changed folders plus its STOREs. The move drain still opens one owned connection per claimed move (out of scope).

**Measured** (loopback IMAP protocol server `testSupport/fakeImapServer.ts`, real imapflow + `ImapFlowMailClient`, 80 ms before every response, six folders INBOX/Sent/Drafts/Archive/Trash/Junk with 20 messages, quiet pass after a synced state):

| server | before | after |
|---|---|---|
| CONDSTORE + LIST-STATUS | 49 commands (SELECT 24, SEARCH 12, FETCH 6, LIST 2, LSUB, LOGIN, ENABLE, LOGOUT), 4.09 s | 7 commands (LOGIN, ENABLE, LIST ×2, LSUB, LOGOUT), 0.60 s |
| CONDSTORE, no LIST-STATUS | 49 commands, 4.06 s | 13 commands (+ STATUS ×6), 1.09 s |
| no CONDSTORE | 48 commands, 4.01 s | 17 commands (SELECT ×6, FETCH ×6), 1.54 s |

A server-side flag change selects only that folder (SELECT 1, FETCH 1). A user read write-back pass sends SELECT 1 + STORE 1 and fetches no folder. IDLE: with a pass running (held in Archive) and 80 ms per client call, a delivery to INBOX signalled through the enqueue is visible 0.84–0.89 s later; the follow-up starts when the running pass releases and only touches INBOX (SELECT, UID search, CHANGEDSINCE flag fetch, UID list). The two LISTs are imapflow's own (main listing plus its INBOX fixup). At the VPS's RTT (~150 ms) a CONDSTORE quiet pass is roughly the connection setup plus 6–7 round trips; Purelymail's capabilities (CONDSTORE, LIST-STATUS) were not checked.

**Tests.** `imapQuietPass.test.ts` (command counts and wall-time bounds per capability set, flag change, write-back), `mailSyncSingleFlight.test.ts` (real graphile runner at concurrency 4: 5 triggers during a pass → exactly one follow-up, a trigger during the follow-up → one more, max one active pass; busy job makes no provider call and the release enqueues one keyed job; dead holder's lease claimed after expiry; a pass whose lease was taken writes nothing; IDLE-triggered import latency and folders touched). `FakeImapAccount` gained optional CONDSTORE mod-sequences, per-call latency, a call log and a gate. Changed existing tests: fakes report `messages`; fakes that returned messages with a UIDNEXT that did not cover them now report a consistent UIDNEXT; the write-back echo test observes flags through the flag fetch; the connection-limit test holds the slot with another holder (two passes of one mailbox can no longer contend); the removal race test expects no provider call (the claim waits for the removal and finds the row gone); the restore-hook default-row test allows `pass_rerun_requested = false`.

**Verified.** `pnpm run lint`, `format:check`, `pnpm -r run build`, `test:unit` (4805), `check:write-safety` (baseline refreshed for two re-worded folder-state UPDATEs), `check:boundaries`; 255 integration files matching mail, imap, idle, thread, inbox, smtp, queue, observability, isolation, tenant, admin, overview, summary, sync: all green after the restore-hook fix. Not run: full `test:integration`, `test:e2e`, web and mobile pipelines, anything against a real server.

**Follow-ups.**
- Enable QRESYNC on the sync connection (`qresync: true`) or drop the QRESYNC branch: today VANISHED is never received.
- The move drain opens a connection per move; a write-back of N moves costs N connection setups.
- Without CONDSTORE every pass still fetches all flags of every folder.
- Log IDLE signal and pass start/end timestamps on the VPS to split Purelymail's delivery delay from pass time.
