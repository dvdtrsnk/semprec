Closes #993

Propagate the caller's tenant scope to the AI gateway and attribute calls only to visible runs and Projects items in that tenant. Requests without the tenant header retain the legacy behavior.

- The completion, audio, and agent clients send `x-semprec-tenant-id` from the current tenant scope. The agent client replaces caller-supplied copies of the header and removes them outside tenant scope.
- Gateway handlers authenticate before validating the header, then run request processing, provider calls, settlement, and failures in the caller's scope. Malformed headers return 400, while invalid credentials still return 401 first.
- Reservation uses one conditional insert to require an active tenant and visible attribution ids. Unknown and foreign ids produce the same 403 response, without inserting a call or invoking a provider.
- Completion, shutdown, and audio concurrency fixtures use a production `createPool` pool and seed real Projects items inside tenant zero's `runInTenant` scope. The shared fixture selects the Projects database in the current tenant explicitly.
- Gateway request and store attribution fixtures seed through the `semprec_data` runtime role, so each tenant gets its own Projects database under RLS. The store test also asserts that the foreign item and its database both belong to tenant B. Foreign-id comparisons use `semprec_side`.

Tests cover all four gateway routes, legacy calls without the header, client header replacement/removal, active and inactive tenants, settled and failed calls, run/project attribution, and indistinguishable foreign and unknown ids through a non-superuser pool.
