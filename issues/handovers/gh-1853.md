# gh-1853 handover: Expand a sleepNight context ref into the agent turn

Delivered on the integration branch by the merge of chain `e1-107-shared` (single member gh-1853), candidate `72244b260655a92b0adcc0c32327a53cfcf2fa5c`. The merge was automatic, with no conflict and no migration.

## What was delivered

A Semp message can carry the virtual ref `{ kind: "sleepNight", night: "YYYY-MM-DD" }`, and the agent turn that receives it sees that night.

- Shared schema (`shared/src/sempMessageRef.ts`): a strict `sleepNight` variant whose `night` must be a real calendar date, the labeled variant (label is the night date), the entry in the kind list, and the dedup identity `sleepNight:<night>`. An invalid date such as `2026-13-01` fails the schema, so both message routes answer 400 with field `context[i]` and store nothing. No existence check is made for the night (the ref is virtual).
- `validateSempMessageRefs` (data) marks the ref valid without any query; `sempRefHistory.ts` gives it an active virtual resolution so a stored `sleepNight` does not throw in the thread read.
- Expansion: `readSempRefContext` (data, `semp/sempRefReadContext.ts`) delegates a `sleepNight` ref to the new sibling `semp/sempSleepNightContext.ts`, which resolves the night with `loadSleepNights` and renders night, plan name, bedtime, wake time, alarm, changed, duration, bedtime-reminder time, plan item id and exception item id, or `no sleep planned for this night`. It requires a REPEATABLE READ transaction; `refExpansion.ts` (agents service) opens one for this ref.
- Access rule: the night is read when the turn attached it (`attachedThisTurn`, passed as true only by `sempMessageTask.ts` for the starting turn's own stored refs) or when the agent's project holds read access on all three sleep databases (`assertAgentDatabaseAccess`). Otherwise a `ForbiddenError` becomes the section `sleepNight: unavailable (no access).`, nothing is read from the sleep databases, the other refs expand and the turn continues. A tenant without the sleep module or settings gets `sleepNight: no longer exists or is unavailable.`
- One-run read access: `openTurnReadAllowances` (`sempTurnReadAllowances.ts`) now also opens, for the attached nights, the live settings item, all live plans and the live night item of each attached night (via `listSleepNightReadItemIds`), in the same allowance table and with the same lifetime as the item refs of #1849. Night items of other nights stay closed; nothing is writable.
- The expanded text is not stored: the label is the night date, so `agent_runs.task` and run events contain the ref but no sleep content.
- ADR `docs/adr/2026-11-13-a-sleep-night-ref-opens-the-sleep-data-for-one-turn.md` records the decision.

## Entry points and contracts dependents build on

- Ref kind `sleepNight` with field `night` (zod strict, real date); identity `sleepNight:<night>`.
- New export from `@semprec/data`: `listSleepNightReadItemIds`, plus the type `SempRefReadOptions` (carries `attachedThisTurn`) next to `readSempRefContext`. Both in `publicSurface.test.ts` (the export in sorted order).
- No route, table, migration, job name or hook was added. The existing routes `POST /api/semp/threads` and `POST /api/semp/threads/:id/messages` accept the new ref.
- Callers of the ref expander that do not pass `attachedThisTurn` (the history reconstruction) are treated as later turns and need a sleep grant.

## Deviations and spec seams

1. The sleepNight branch lives in the data package (`sempSleepNightContext.ts`, called from `readSempRefContext`) instead of inside `refExpansion.ts`; the latter only chooses REPEATABLE READ, passes `attachedThisTurn` and renders the no-access section. This keeps `loadSleepNights` out of the barrel and follows `taskOccurrence`.
2. The `refExpansion` test file named in Touches is a unit file without Postgres; the expansion behaviour is tested in the new integration file `sleepNightRefExpansion.test.ts`.
3. The one-run access of #1849 cannot be consulted by the prompt expander (the run row does not exist yet), so it reads on the fact that the refs are those of the starting turn; the allowance rows for the same refs are opened in `onTurnStart`. A ref in an earlier message needs a grant. Recorded in the ADR.
4. The label of a sleepNight ref is the night date, not the plan name, so no sleep content is stored with the context.
5. The exception item id comes from a separate query (`loadSleepNights` does not return it); with two items for one night the highest id is named, as the resolver lets the later one win. The write hook refuses a second live exception, so this is unreachable through production writes.
6. Files outside Touches were needed: `sempRefHistory.ts`, `sempMessageRefs.ts`, `sempRefReadContext.ts`, `sempMessageTask.ts`, `sempTurnReadAllowances.ts`, `index.ts`, `publicSurface.test.ts`, `sempThreadsHandler.test.ts`, `sempMessageRefs.test.ts` and the ADR.
