## What was delivered

- `POST /api/mail/threads/:threadId/archive` and `POST /api/mail/threads/:threadId/trash`, response `{ threadId, moved }`. Both resolve merged ids under the tenant mail-thread guard (404 for an unknown, foreign or live-message-less id, 400 for a non-UUID id).
- Archive moves the counted copies that are in a folder with `specialPurpose` inbox; trash moves every counted copy not already in Trash. The target is the folder with the matching `specialPurpose` in the copy's own mailbox (for a Gmail API mailbox the synthetic Archive). 409 `mail_archive_folder_missing` and 409 `mail_trash_folder_missing` when a mailbox that has a copy to move lacks the folder, 409 `mail_thread_already_trashed` when every counted copy is in Trash or Junk. All 409 decisions are taken before the first write and change nothing.
- Per copy, in one transaction: the desired move is recorded with `recordDesiredMailMessageMove` (before the edge is replaced, so an IMAP source is verified against the current edge), all `Emails.folder` edges are deleted and the target edge is created as the Emails module (`EMAILS_RELATION_CONTEXT`) without metadata. One `enqueueMailAccountSync` per touched mailbox; one `mailThread` invalidation after the commit.
- New 409 `mail_move_source_unverified` (not in the issue): a copy that cannot be addressed at its provider (IMAP edge without UID, no provider message id, mailbox without sync state) fails the whole call before any write. When an earlier desire of the copy is still outstanding its recorded source is kept (`hasPreservedMailMoveSource`).
- ADR `docs/adr/2026-11-14-a-mail-thread-move-records-the-desired-move-before-it-replaces-the-folder-edge.md` records the protocol (guard first, sources of all copies before the first write, desire before the edge, UID-less target edge, the 409, the preserved-source exception, single owner of the keep rule).

## Deviations from the specification and spec seams

1. Route entries are in the slice module `routeMatrix/mail.ts`, not `routeMatrix.ts`.
2. `backend/packages/data/src/index.ts` gets no export line: the file is at the 900-line `max-lines` cap, so the handlers are reachable through `mailModuleManifest.ts` as for the flag route.
3. "Counted messages" is read as the copies the thread list counts; copies with a Drafts folder edge or an unsent draft are never moved. A copy in Inbox plus Drafts (no provider produces it) is therefore left in place and keeps the thread in `box=inbox`; the reviewer's low finding was resolved by rewording, not by changing the rule.
4. Trash moves a Junk copy of a mixed thread to Trash and does not move a copy already in Trash; the 409 applies when every counted copy is in Trash or Junk. A thread of drafts only answers `moved: 0`.
5. Archive of a thread with no Inbox copy answers 200 `moved: 0` and still sends the invalidation (no 409 in the Task).
6. `moved` counts copies (move rows); a message delivered to two mailboxes counts twice.
7. The Task puts `recordDesiredMailMessageMove` after the edge replacement; the handover of gh-1746 requires the IMAP source to be verified against the current edge, so the desire is recorded first (ADR).
8. New 409 `mail_move_source_unverified`, not listed in the issue (ADR).
9. Gmail messages with user labels lose all local folder edges on archive and trash as the Task says; the next provider sync restores label edges.
