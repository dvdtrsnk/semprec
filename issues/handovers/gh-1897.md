## What was delivered

- The mail thread list rows (`POST /api/mail/threads`) and the thread detail header (`POST /api/mail/threads/:threadId`) carry `company` and `project` as `{ id, name }` or `null` (an item in the Trash reads `null`, a nameless item has an empty name) and a `links` object. `links` holds the value-link entry of `company` and `project` only where a link row exists for that property; a thread with no links has `links: {}`. A link on any other property key is not reported.
- Names come from lateral joins in the page statement of `listMailThreads` (target items pinned to the system database by `owner_module_id`, tenant scoped, `deleted_at` filtered). Links come from one `getValueLinksForItems` call for the whole page, so the number of statements does not grow with the page size.
- The detail reuses the list query inside its own REPEATABLE READ transaction and copies `project`, `company` and `links` from the list header. A thread with no Threads item yet answers `null` and `{}`.
