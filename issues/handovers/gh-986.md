**What changed**
- **`handleItemTrashPurgeSweepTask`** in `backend/packages/data/src/trash/purgeExpiredTrash.ts` now calls `forEachActiveTenant(pool, …)` and runs `purgeExpiredTrash` inside each tenant's scope. Row-level security narrows the candidate query, subtree walk and blob reference check to that tenant, so I added no `tenant_id` predicates.
- **Failures:** a failure that escapes one tenant's pass fails only that tenant. `forEachActiveTenant` rethrows all of them together once every tenant has been attempted, so the job is retried.
- **`purgeExpiredTrash` body** is unchanged, including the per-candidate and per-blob "log and skip" handling. Both docstrings are rewritten: `purgeExpiredTrash` purges the trash visible in the current scope, and the handler calls it once per active tenant.
- **`worker.ts`** is untouched; both crontab registrations already go through the handler.

**Tests**
The new `backend/packages/data/src/trash/__tests__/purgeExpiredTrashPerTenant.test.ts` uses the runtime-role pool with tenant zero and a second tenant. It calls the handler inside `runAsSystem`, as the task runner does. It covers these cases:
- **Per-tenant purge:** each tenant's 31-day-old item is removed and its 1-day-old item kept.
- **Blob bytes:** tenant B's unreferenced blob row is gone, and `storage.delete` ran with its key after the transaction committed. Tenant zero's live blob is untouched.
- **Inline database:** tenant B's emptied inline database and its `items_p_*` partition are dropped, and tenant zero's databases stay.
- **Per-candidate failure:** an expired item in an archived database is logged and skipped. Tenant B's other expired item and tenant zero's expired item are still purged.
- **Inactive tenant:** a suspended tenant's expired item is not purged.
