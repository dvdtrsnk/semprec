## What was delivered

- Module agent tools declared with `requiresApproval` (plus optional `snapshotExport`) are composed into agent sessions but, when called, create a `moduleTool` approval request (description, tool call id, snapshot hash, thread activity bump, `approval_pending` notification linked by source, realtime event) and return a pending-approval result without running the handler.
- After approval the `approvalExecute` handler claims the request, resolves the tool through `ModuleRegistry`, recomputes the snapshot, records a `sourceChanged` conflict when it differs, otherwise runs the handler once and records the outcome, posts the system message and publishes the realtime event. Rejected, missing-tool, unreadable-snapshot and failing-handler cases are recorded outcomes.
- Gated tools are opt-in for callers and stay absent over `POST /mcp`.
- The detail read `GET /api/approval-requests/:id` returns argument values for `mcpInvoke` requests only; a `moduleTool` detail stays value-free. Module tool failures are logged as class name and short code only (`describeModuleToolFailure`).
- ADR `2026-11-12-module-agent-tools-that-require-approval-run-through-a-moduletool-request`.

## Contracts dependents build on

- Module tool descriptor fields `requiresApproval` and `snapshotExport` (`module-registry/src/manifest.ts`); `ModuleRegistry.getAgentToolDefinitions` / `resolveModuleAgentToolsForRun` take an `includeApprovalGated` opt-in (the session composition and the executor opt in, `mcpHandler` does not).

- No migration, no route, no job name (the existing `approvalExecute` task is used).

## Deviations from the specification and spec seams

1. Snapshot and request creation live in `packages/data`, not only in `agentSessionComposition.ts`, because the claim, notification and realtime event belong to the approval pipeline.
2. The `includeApprovalGated` opt-in is not in the Task; without it a gated tool would have been offered over `POST /mcp` and run directly (gh-1957 owns MCP).
3. Spec seam with ADR `2026-11-04-owned-databases-admit-safe-module-agent-tools`: `requiresApproval` is the opt-in switch; approval modes `always` / `unlessProjectPermitted` without the flag stay absent. Recorded in the new ADR.
4. The `approval_pending` notification goes to the actor of the requesting run.
5. New outcome kind `sourceChanged`; the web catalog `web/src/i18n/messages.ts` is out of scope and still needs `approval.moduleTool`.
6. The Semp thread list reported every non-generic pending approval as `mcpInvoke`; it now reports `moduleTool`.
7. The stale-claim sweep text still says "MCP tool call" (stored only, never exposed).
8. New tests are in new files so they use the runtime-role pool and two tenants.
9. The worker's commit trailer follows that session's attribution line.
