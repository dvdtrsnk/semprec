## Summary

Implements issue #90 — structured mail read and flag search. The mail-query parser (`backend/packages/data/src/mail/search.ts`) now supports `is:read`, `is:unread`, `is:flagged`, and `is:unflagged` operators, compiled directly over issue #97's canonical `read`/`flagged` boolean item properties rather than being left in free text.

- Missing `read`/`flagged` properties on legacy rows default to `false` (unread/unflagged), matching `messageFlagProperties`'s own documented default.
- Identical repeated operators (`is:unread is:unread`) collapse harmlessly.
- Contradictory operators (`is:read is:unread`, or the flagged equivalent) throw a `ValidationError` (`validation_failed`) with `details: { field: 'is:read'|'is:flagged', conflict: [...] }`.
- The read and flagged dimensions compose independently with AND, and compose correctly with the existing `from:`/`has:attachment`/`before:`/`after:` operators and free text.

Added parser unit tests (contradiction, collapse, composition) and a real-Postgres integration test covering legacy/read/flagged/read+flagged rows and their composition with `from:`.
