# gh-1507 — Suggest recipients from People

Repository-Issue: gh-1507
Implementation commit: `5c7c857877112883e7ae5729876e5a5125ad0a8c`.

## Delivered behavior

- Registers the authenticated tenant route GET /api/mail/contacts in the mail manifest and route matrix, with single-consumer-read justification. The response is `{ contacts: [{ personId, name, email, relationship }] }`.
- Searches live People names and individual addresses from their emails text, case- and diacritic-insensitively using unaccent and parameterized ILIKE. LIKE percent, underscore and backslash are escaped literally.
- Splits newline/comma address lists, normalizes case and surrounding whitespace, removes duplicate person/address rows, excludes the tenant's live mailbox addresses and normalized exclude entries, then sorts by name/address with person id as a deterministic tie-breaker.
- Empty/whitespace q returns no rows. Default limit is 10, positive integer limits above 50 are clamped to 50. Invalid limits return validation_failed. Query length is capped at 256 and exclude text at 16384 characters.
- Reads the People emails property directly, so suggestions do not depend on asynchronous person-email index refresh. No person, index or mailbox writes are introduced.
