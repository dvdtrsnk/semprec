# Handover for gh-1503

The `mail_sync_stalled` notification from the `mail:<mailboxItemId>` check no longer carries provider error text.

- **Payload:** `checkMailSync` in `observabilityCheckSystem.ts` now writes `{ mailboxItemId, reason }`, where `reason` is the stored `lastFailureKind` (`reauthorization`, `connectionLimit` or `other`, from #1497) and `other` when the check alerts only because the sync is overdue. `lastError` is gone from the notification payload. `listAllMailAccountSyncStates` already returned `lastFailureKind` after #1497, so the store is unchanged.
- **Unchanged:** the `tenant_observability_checks` detail and the administrator health report keep `lastError`. The process-liveness `mail_sync_stalled` payload (`mailboxItemId`, `beatAt`) is untouched.
- **Tests:** `observabilityCheckSystem.test.ts` asserts the exact payload for an overdue mailbox (`other`), a `reauthorization` mailbox with no `boom` text, and the tenant-scoped stall (`other`). `tenantMailSyncLiveness.test.ts` needed no change (it never asserted `lastError`).
