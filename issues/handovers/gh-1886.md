## What was delivered

- A new calendar timeline source `taskOccurrences`, registered in `CALENDAR_TIMELINE_SOURCES` (`calendar/timelineSources.ts`) after `taskTraces`. It reads `projectTaskOccurrences` (gh-1672) and returns one `kind: "task"` entry per occurrence, with `seriesId`, `occurrenceDate`, `done`, `overridden`, the id `<seriesId>@<date>` and `readOnly: true` for a virtual occurrence, or the item id (and `readOnly: false`) for a stored one. A virtual entry takes its times from the series template (all-day when the template has none).
- The core Tasks source (`readTaskTimelineItems`) skips every Task with a `seriesId` (SQL condition in `TASK_CANDIDATES_SQL`), so a series row is never returned next to its occurrences.
- Stored occurrences are read through the exported `toShownTaskItems` (the `hiddenUntil`, completed-in-Event, display day and `carriedFrom` handling moved out of `readTaskTimelineItems`), with project and people.
- The fix round (`7d4aecbf2`): the occurrence source also returns stored Tasks whose `seriesId` no `task_recurrence` row with an anchor date projects (`readOrphanedSeriesTaskRows` in `timelineRead.ts`): the history of a series that was restarted (new `series_id`) or whose row was removed (trash purge), as ordinary items with their own `seriesId` and `occurrenceDate`, `overridden: true`, `readOnly: false`; `wontDo` is left out. The orphan set is the exact complement of the projection's series set, so nothing is returned twice or hidden.
- The compact shape carries `seriesId` and `occurrenceDate` (and `status` for done).

## Deviations from the specification and spec seams

1. The Task names `timelineRead.ts` only for the core-source exclusion; the hiddenUntil, completedInEvent, display-day and carriedFrom code moved into the exported `toShownTaskItems` (behaviour-preserving), and `readSchedule` and `readCalendarIds` are exported.
2. A virtual entry carries project null, people [], hostEvent null and a constant epoch `updatedAt` (no row exists).
3. A stored occurrence with status `wontDo` is left out, like any `wontDo` Task in the core source, and its date is not shown as virtual.
4. A stored occurrence is placed by its `occurrenceDate` (display day), also when its own date was moved.
5. `readCalendarTimeline` does not bound its range and the projection refuses more than 400 days, so the source projects in consecutive windows of 400 days; statements grow with the range length, not with the number of series.
6. The history of a series that no longer projects (restarted or removed row) is returned by the orphan path added in the fix round; this goes beyond the literal Task text (which says to skip every Task with a `seriesId`) and follows ADR 2026-10-25, "Series edits and deletion". No ADR was added or narrowed (both reviewers and the recheck agreed none is needed).
7. No ADR added otherwise: the source follows ADR 2026-11-10 (list of sources) and ADR 2026-10-25 (recurrence model).
8. The worker's commit trailer names Claude Sonnet 5.5.
