## Summary

Implements issue #229 in `backend/packages/agent-runtime`:

- **`delegationRegistry.ts`** — `DelegationRegistry`, a process-memory registry of open supervisor→project-agent delegated sessions keyed by `(supervisorRunId, targetProjectItemId)`. A first delegation onto a key opens an `agent_runs` row (`unit='session'`, `triggeredBy='supervisor'`) and an in-process `AgentSession`; a further delegation within 24 hours reuses the same session as a new turn. A duplicate call onto a key already mid-turn is rejected immediately with a fixed busy `tool_result` message, never blocking or overwriting the in-flight call. Busy-check and reservation of a brand-new key both happen synchronously (before any `await`), which closes the race where two concurrent calls onto the same new key would otherwise both try to create a session. After 24 hours of inactivity an in-process timer discards the entry and closes its run as `done` — no backing table or job.
- **`delegateTool.ts`** — `createDelegateTool` wraps the registry as the `agentTool.delegate` handler, returning only the target's final message (or the busy error) as a `tool_result`-shaped value. Restricting this tool to Semp's own manifest is left to the not-yet-built composition root (#91), the same pattern `startupRepair.ts` used for its own missing caller.
- **`lifecycleAdapter.ts`** — extracted the turn-processing loop into a reusable `runAgentTurn`, so `runAgentSession` (one turn, closes the run) and the new registry (many turns, closes only on TTL) share identical event bookkeeping.
- **`types.ts`** — added an optional `AgentSession.send()` continuation method for reusing an open session across turns.
