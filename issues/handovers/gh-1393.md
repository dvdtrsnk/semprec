# Handover for gh-1393

Added `docs/adr/2026-10-29-subpages-are-items-of-a-hidden-pages-database.md` (status accepted, area backend). No code, no schema, no route. The block-model ADR and the page-operation-family ADR are unchanged.

**What it records**
- Storage: one hidden system database `pages` per tenant (owner module id `pages`), created on first use under an advisory lock, with no seed and no backfill. Each subpage is one item with a `page` document, addressed as `semprec://page/<itemId>`. The item link `semprec://items/<uuid>` is unchanged.
- Parent link: the system-owned text property `parentItemId` names the host item or parent page. Breadcrumbs walk it; they do not use `getItemPath`, which follows database parents.
- Page block: type `page` with `pageId` and a `text` field that holds the title as plain text, with no inline attributes. This amends the field contract of `2026-10-28-block-model-for-page-documents` (which gives `page` blocks no `text`) as a standalone ADR. That ADR is neither edited nor superseded.
- Title source: the text of the `page` block in the parent is the source. The `title` property of the Pages item is a mirror, written by `page.rename` and by a post-commit job debounced by 10 seconds (the design note of #1322).
- Narrowing: for a subpage, `page.rename` writes the parent block text and the mirror, not `meta.title` of its own document. Section 6 of `2026-10-28-page-operation-family` still applies to pages that are not subpages.
- Single owner: `title` and `parentItemId` are system-owned with owner process `pages`. Both writers of `title` must name that process.
- Lifecycle: create, duplicate and rename are generic page operations. Delete is the generic `item.delete`, so an agent's delete waits for approval. Restore is the generic item restore. Deleting a host trashes its subpages. A sweep trashes orphans left by a block removed through the sync socket.
- Hosts: full editors can hold subpages. A light editor (#1675) rejects `page` blocks.
- Limits: no depth limit, a page is never its own ancestor, and duplication is capped by #1722.

**Notes for dependants**
- #1676 creates the `pages` database and its two system-owned properties, `title` (title type) and `parentItemId` (text), with owner process `pages`. The first subpage creation runs under the advisory lock.
- #1676 and the block-model validation must accept `text` on `page` blocks and still reject inline attributes there.
- `page.rename` (its own issue in the family table) must follow the subpage narrowing above, not write `meta.title` for a subpage.
- The mirror lag is the debounce interval plus the job's run time. Trash, export, item reads, search and breadcrumbs read the mirror and do not load the parent document.
- The page-family ADR (section 6) and this ADR conflict for subpage titles. This ADR resolves it by narrowing, not by editing the family ADR.
- No migration is added. The docs module manifest does not declare the `pages` database yet; the ADR says it will, with no overview and no switcher order.
