# Register the iPhone for push and handle calendar notifications — handover

## What was built

- Shared layer (`mobile/shared`): `HttpPushRepository` (`POST /api/push-subscriptions` as `channel: apns`,
  `POST /api/push-subscriptions/:id/revoke`, `GET /api/calendar/reminders?from&hours=48`, `GET /api/badge-counts`);
  use cases `RegisterPushSubscription`, `RevokePushSubscription`, `LoadDeviceReminders` (none while the `reminders`
  switch is off), `LoadAppBadge` (sum of the counts whose badge switch is on); `DeviceNotifications` (presentation)
  which also decides tap targets (`invitation_id` → Invitations, `event_id` → event, `task_id` → task) and recognises
  the `kind: remindersResync` silent push; `DevicePushSDK` (one per process). `ApnsEnvironment` and
  `PushSubscriptionStorage` live in core.
- Sign-out: `HttpAuthRepository` gained `endingSession`, run after the device forgets the session and before
  `/api/auth/logout`, with calls that still carry the ending token; `HomeSDK` uses it to revoke the stored subscription.
- Notification settings: turning a switch on (or the problem level up from off) emits
  `NotificationSettingsEffect.RequestPermission`; the Account feature routes it through
  `AccountRouting.requestNotificationPermission()`.
- Apple: CoreKit `SharedDeviceNotifications` / `DeviceNotificationService`, `DefaultsPushSubscriptionStorage`. App
  target: `AppNotifications` (process-wide), `AppDelegate` (`#if os(iOS)`, via `UIApplicationDelegateAdaptor`, no UIKit
  import), `NotificationCenterDelegate`, `SystemNotificationCenter` (local reminders, badge), `NavigationContext.open(_:)`
  and `whenShown(_:route:)` (waits for the Calendar stack when a tap launched the app). Entitlements
  `Alldots-iOS.entitlements` (`aps-environment` = development in Debug, production in Release), `UIBackgroundModes`
  `remote-notification`, `AlldotsApnsEnvironment` = sandbox/production. Policy: `UserNotifications` system module,
  two app copy keys (`reminder.event.body`, `reminder.task.body`).

## Deviations and open items

- The backend's APNs environment values are `sandbox`/`production` (not `development`); the entitlement uses
  `development`/`production` as Apple requires.
- "Ask when an account with Calendars is connected" is not wired: the iOS internet-accounts screen with the
  Calendars switch (internet-accounts 13/18) does not exist yet. That issue should route its Calendars-on effect to
  `AppNotifications.shared.requestPermission()` through its router, as the notification settings do.
- Real push delivery was not verified: it needs a signed device build with the Push capability in its provisioning
  profile and the server's APNs key. A revoke that fails (offline sign-out) leaves the server row active; logout does
  not revoke push rows server-side (possible backend follow-up). Local reminders are not shifted around the sleep
  window. Invitation action buttons (Accept/Maybe/Decline categories) are not registered.
