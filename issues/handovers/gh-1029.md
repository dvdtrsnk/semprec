- **Create hook:** `hooks.ts` has a third registry, `registerItemCreateHook` and `runItemCreateHooks`, and `clearHooksForTests` clears it. `createItemWithClient` runs it after a real insert and before the heartbeat trigger. It does not run on an idempotency-key replay, and a rejection rolls the insert back.
- **URL rule:** the new `net/storedOutboundUrl.ts` exports `isBaselineOutboundUrl`, moved from `validateWebPushEndpoint`. That function now delegates to it, with the same message and `field`.
- **Storable config:** `assertStorableMcpConnectionConfig` checks the shape, then requires a baseline URL for `sse` and `http`. Every failure throws `ValidationError` with `{ field: "connectionConfig" }`. `assertValidMcpConnectionConfig` stays shape-only for the connection factory.
- **Write hook:** `mcpServerWriteHook.ts` holds the create and update hooks, registered in `domainWriteHooks.ts`. They act only on the `mcpServers` database when `connectionConfig` is in the written properties. This covers REST, `/mcp`, the AgentTools and the proposal confirm path.
- **Proposals:** `assertValidMcpServerProposalProperties` now calls the storable check. The credential denylist is unchanged.
- **ADR:** `docs/adr/2026-10-09-item-create-domain-hooks.md`.
- **Fixture:** `createGrantedTool` in `mcpInvokeTool.test.ts` now uses a raw `INSERT INTO items`, since its `http://127.0.0.1` contract servers would be refused. No other fixture needed changing.
