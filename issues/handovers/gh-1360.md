# gh-1360 implementation handover

## What changed

- `ResolvedProperty` (`manifest/catalogResolution.ts`) now carries `id`, `type`,
  `filterable` and an always-present typed `config` (`ResolvedPropertyConfig`).
  `resolveProperty` takes an optional `relationDefinitions` map (property id to
  `RelationDefinitionRow`).
- `config`: relation `{ targetDatabaseId, cardinality }` (`{}` without a readable
  definition or a string target), date `{ includeTime }` (false by default), number
  `{ filterPresets }` when stored, otherwise `{}`. A stored `default` is still
  projected into `config.default` for select, multi_select, checkbox, number, text
  and date, so existing clients keep working. Select options stay in `options`.
- `filterable`: select, multi_select, relation, date, checkbox; number only with a
  non-empty `config.filterPresets`; everything else false.
- `generateSchemaProjection` loads relation definitions for all relation properties
  of all databases with one `getRelationDefinitionsByPropertyIds` call.
- `generatePermissionManifest` now picks the old fields explicitly, so the manifest
  shape is unchanged (no id, type, filterable or typed config leak into it).

## Tests

- `catalogResolution.unit.test.ts`: config and filterable per type, relation with and
  without a definition.
- `manifest.test.ts`: `generateSchemaProjection` end to end (select, relation x3,
  date with and without includeTime, number with and without presets, text), and
  exactly one `relation_definitions` query.
- `schemaHandler.test.ts`: Projects `status` has type, id, filterable, options.

## Notes for dependants

- `config` is now never absent on a projected property; `config.default` coexists with
  the typed keys (date: `{ includeTime, default }`).
- `filterPresets` is passed through unvalidated; #1622 owns validation and localization.
- `GET /api/databases/:id/properties` and `GET /api/properties` are unchanged
  (they only read `name` and `options` from `resolveProperty`).
