## What the module exports
- **`TRUSTED_REVIEW_BOT_LOGINS`**: a frozen array of `github-actions[bot]` and `bb-agent-relay[bot]`.
- **`MEMORY_MARKER_PREFIX`**: `"<!-- crb-memory:v1:z:"`.
- **`selectMemoryComment(comments)`**: returns the newest comment that a trusted bot wrote and that contains the prefix. "Newest" is by `createdAt`; when two are equal, the higher `id` wins. It returns `null` when no comment qualifies.
- **`decodeMemory(body)`**: reads the payload the same way the bot writes it (after the prefix, up to the next `-->`, trimmed). It then checks it is standard base64, inflates it with `zlib.inflateSync`, decodes it as UTF-8 and parses it as JSON.
  - If any stage fails, the error names that stage (`extract`, `base64`, `inflate`, `utf-8` or `json`) and keeps the original error as its `cause`.
  - UTF-8 decoding is strict, so bad bytes throw instead of being silently replaced.
- **`parseMemory(value, prNumber)`**:
  - The pull request number is read from `pr_number`, or from `mr_iid` when `pr_number` is absent. If it does not match `prNumber`, the error names `pr_number`.
  - Each finding is checked field by field, and a bad field produces an error naming it, e.g. `findings[0].line`.
  - It returns `{ findings }` with the 11 fields in camelCase.
  - Fields it does not return (`runs`, `note`, `events`, `notes`, `verdict_*`, or anything new the bot adds) are ignored whatever their shape.

## Tests
The tests cover every Acceptance criterion:
- **Selection:** newest wins, an untrusted author is ignored, a trusted comment without the prefix is ignored, empty or unqualified lists give `null`, and equal `createdAt` goes to the higher `id`.
- **The #551 payload:** it decodes to `pr_number` 551 with the quoted finding, and parses to its camelCase form.
- **Decode failures:** no prefix, a non-base64 character, base64 that is not zlib data, raw deflate data, and zlib data that is not JSON.
- **Pull request number:** a wrong `pr_number`, a legacy `mr_iid`, and neither field present.
- **Invalid findings:** a missing key, an eleven-character key, `line: "27"`, `severity: "info"`, `status: "closed"` and `path: ""` all throw.
- **Tolerated shapes:** an extra unknown field and a malformed `events` entry do not throw.

I also added a few cases beyond the criteria: invalid UTF-8, a negative `line`, an uppercase key, a value that is not an object, `findings` that is not an array, and a finding that is not an object. There is also one check per string field.
