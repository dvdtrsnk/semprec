## What was delivered

The generic operation `search` and the REST route `GET /api/search` for global search over `item_search_index`.

- Input (strict): `q` (1 to 200 characters), `scope` (non-empty list of unique group types, default every group), `perGroupLimit` (1 to 50, default 4), `cursor` (accepted only with a scope of exactly one group).
- Output: groups in the fixed order of the group types (task, event, project, area, contact, journal, file; `mail` and `chat` are in the schema and filled by later issues). A group without a match is missing. Each group has the real `total`, up to `perGroupLimit` results and an opaque `nextCursor` (`null` when nothing follows). `contact` holds People and Companies. A result carries structured `subtitleParts` (task date, time range, project, recurrence; event people; company marker; and so on). An Inbox entry is found through the text of its Journal day and is never returned itself.
- Never returned: items in the trash, projects with `systemActive`, items of an archived database, items of a user-created collection, Health records and anything of another tenant. An agent run is also not given items of a database its project may not read, and linked items in an unreadable database are not shown in a subtitle.
- Only the length of `q` and the counts of the answer are logged; no refusal message repeats `q`.

## Deviations and spec seams

1. The candidate's commit trailer names Claude Sonnet 5.5 instead of the line the task text names.
2. `genericOperationGateway.ts` is in Touches but needed no change: the gateway dispatches every catalog operation through the bindings.
3. `packages/application` was documented as built only over `createChokePoint`; it now also calls `searchItemGroups` and `createDocStore` from the `@semprec/data` barrel, and the service docstring says so.
4. The route entry is in the new slice `routeMatrix/search.ts`; the MCP probe gained an optional `foreignIds` argument (at the merge this was folded into the tip's equivalent `moreIdsOfA`).
5. Interpretations where the spec is silent: `timeRange` is `HH:mm-HH:mm`; a recurrence value is the stored preset, else the kind of a fixed rule, else `floating`; a company is kind `relationship` with value `company`; an event names at most 5 people; the area count excludes trashed and system projects.
6. Every searchable database is a non-sensitive system database that is always open to agents, so the grant filter only bites when a database is flagged sensitive; the tests flip `databases.sensitive` with a raw statement.
7. The thread-backed result shape (`threadId`, `title`, `subtitleParts`, `snippet`) is defined for mail and chat although nothing fills it here.

## Follow-ups from review

All three reviewers (requirements, rules, security) reported verdict clear with no finding. Two points of the merge for later sources:

- The chain was cut before gh-1999 (inherited sensitivity) and gh-2000 landed. `searchItemGroups` filters unreadable databases (`listUnreadableDatabaseIds`) but does not call the inherited-sensitivity filter (`inheritedSensitivityDeniedSql`, `sensitiveSourceDatabaseIdsByItem`) that item lists use, so a Files item that is linked to an item of a sensitive database is not hidden from an agent in search results. The landing did not test this and no source covers it yet. The `files` group is the only searchable group of an inheriting database.
- An external AI client on `/mcp` (gh-1998) has no project, so `agentProjectItemId` is absent for it and search does not apply the external-client reader. All searchable databases are non-sensitive, so the reader would hide none of them.
- The security reviewer noted that a Journal day carries the text of an Inbox entry, so an agent with Journal read but a revoked Inbox grant can match Inbox words through its Journal day; this is the explicit design of the Task.
