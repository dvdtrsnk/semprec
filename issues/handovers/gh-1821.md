# gh-1821 handover: Serve agent run steps over REST with a step-aligned cursor

Delivered on the integration branch by merge `73a3698e77c80f42cc6102076c4c831c4527eb3d` of chain `e1-083-semprec-api`, candidate `d7d8bb4a800003e437875607172436d6b24ca510`.

## What was delivered

`GET /api/agent-runs/:id/steps?after=<eventId>&limit=<n>` in `backend/services/semprec-api/src/agentRunHandler.ts`. It answers `{steps, nextCursor, truncatedHistory}`. `after` is validated as 1 to 19 digits not above the bigint maximum (default `"0"`), `limit` as an integer 1..500 (default 100); a repeated, empty, zero, non-numeric, fractional or too large value is a 400 `validation_failed` that names the field and never echoes the value. An unknown run, another tenant's run and a run of another `actorUserId` answer the same 404 as the run detail, before any event is read. The route runs in `runInTenant` and one `withTransaction`.

A `Step` is `{stepId, kind, state, at, durationMs, toolCallId, operation, mcp}`; `kind` is `start | plan | tool | answer | end | error`, `state` is `running | ok | error`. Arguments, results, message text and thinking are never returned.

The grouping and the cursor are a pure function, `buildAgentRunStepPage` in `backend/packages/data/src/agentRuns/agentRunStepPages.ts` (no database). A `tool_use` and its `tool_result` (matched on `toolCallId`) are one tool step; a call without a result is `running` and `nextCursor` stays before it, so the next request returns it complete. Overlapping (parallel) calls form one block that is never split. A page never ends between a call and its result.

## Entry points and contracts dependents build on

- `@semprec/data` runtime exports: `AGENT_RUN_STEP_DEFAULT_LIMIT` (100), `AGENT_RUN_STEP_MAX_LIMIT` (500), `buildAgentRunStepPage`, `isAgentRunStepReadSettled`, and from `agentRunEventsStore.ts` (through `export *`) `listAgentRunEventsForStepPage` and `isAgentRunHistoryTruncated`. All are in the frozen list of `publicSurface.test.ts`.
- `listAgentRunEventsForStepPage`: bounded read (2*limit+100 rows, plus one to detect more) of the step-producing kinds only; `turn_start`, `turn_end`, `compaction` and `user_message` are excluded in SQL.
- Route matrix entry in `routeMatrix/agentRuns.ts` (`tenancy: "tenant"`), `ROUTE_HANDLER_FILES` mapping and an isolation case. No table, migration, job name or operation is added.
- Cursor contract: `nextCursor` is the id of the last event of the last closed step of the page. It is `null` only when the read is exhausted and the run is settled, or the page reached the `end`/`error` step with nothing more to read. For a running run and for a run that finished less than 60 s ago the cursor stays non-null (a terminal `run_status` is stored after the row is closed). A settled run (status not `running`, `finished_at` at least 60 s old) that is read to its end returns `null` also for an empty page, and an unanswered tool call of a settled run becomes an `error` step.
- Failure detection of a tool step reads the raw payload: `isError === true`, `result.details.error === true`, or a legacy top-level `error: true`. The typed parser from gh-1424 (in `@semprec/shared`) only supplies `operation` / `mcp`, because it rejects legacy rows.
- `truncatedHistory` is true when the first stored event is not the opening `run_status` running, and for a finished run with no events at all.
- Presentation fields (localized titles, approval steps, `messageId` scoping) are left to gh-1847, gh-1862 and gh-1889 and extend this `Step` shape.

## Tests

## Deviations and spec seams

- The route entry is in `routeMatrix/agentRuns.ts`, not `routeMatrix.ts` (the preparation issue split that file).
- The Task is silent on overlapping tool calls: they form one block that is not split, so a page holds more than `limit` steps only when the first block is larger than `limit`; closed steps after a still-running call wait for the next request; a result whose call is gone is a tool step of its own.
- `nextCursor` is the request's `after` when no step is returned and the first step is running or the page is empty. When a full SQL read holds steps but no cursor point (a block of overlapping calls or an unanswered call spanning more than about 100 events), `buildAgentRunStepPage` throws, a logged 500 rather than a silent stall; dangling calls are closed by the lifecycle adapter and startup repair, so no trigger was found.
- Review fix: the 60 s settle grace (see the cursor contract) is a deliberate deviation from deciding the end on `run.status` alone.
- Files outside Touches: `publicSurface.test.ts`, `agentRunEventsStore.test.ts`, `bespokeListenerTenantScope.test.ts`, all mechanical consequences of the new route and exports.
- Shared-file ordering blocker gh-1812 is not landed (the chain landed ahead of it under the ADR of 2026-11-11); when it lands its entries in shared files go before this chain's entries. The merge had no conflict.
