# Handover: report a mailbox stalled only when no pass runs or recently succeeded, and at most once per mailbox per episode

Commit on `feat/internet-accounts`: `1eda0a57e`. Nothing was run against Purelymail, the VPS or any other real server.

**Root cause.**
- `mail:<id>` (`checkMailSync`) alerted as soon as `next_expected_activity_at < Date.now()`. An IMAP pass that ends unfinished (the ten-message budget, a folder moved on) records `next_expected_activity_at = now()` and asks for a rerun; the release enqueues the follow-up, which runs for seconds. A minute tick in that window alerted, notified `mail_sync_stalled` and raised the `mailSyncError` Semp problem, although a pass held the lease or had just ended. The e2e's steady deliveries, flags and moves make such passes frequent. The VPS's `semp_problem` can only come from this family.
- `process:mailsync:<id>` (`checkMailSyncLiveness`) alerted on a stale or missing live-sync heartbeat whatever the passes did, and notified on its own: one mailbox, two notifications in one tick. The evidence does not show why the VPS heartbeat was stale (not hosted yet, the lifecycle retired and re-hosted after up to one 60 s discovery, Mail switched off and on); the check no longer depends on it while passes succeed.
- `transitionCheckIn` locked a missing row `FOR UPDATE`, which locks nothing: concurrent check runs each reported the first transition and each notified (reproduced: four overlapping runs wrote four `process_stale` notifications for one admin).

**Changes.**
- `mail/mailAccountSyncStateStore.ts`: `lockMailAccountStallState(client, itemId, graceMs)` locks the sync state row and returns it with `passRunning` (unexpired lease), `overdue` (`next_expected_activity_at` older than the grace) and `recentlySynced` (`last_successful_sync_at` within it), computed with the database's `now()`.
- `observability/observabilityCheckSystem.ts`: `MAIL_SYNC_STALL_GRACE_MS` = 10 minutes. While a pass holds the lease both mailbox checks keep their status (`ok` without one): no alert, no recovery. `mail:` alerts on `last_error` or overdue past the grace; the heartbeat check on a stale heartbeat only without a successful pass in the grace. Both checks lock the sync state row first; a check that flips to alerting notifies only when the mailbox's other check is not alerting. Only `mail:` raises the problem, as before.
- `observability/observabilityChecksStore.ts`: `transitionCheckIn` inserts a missing row (`ON CONFLICT DO NOTHING`) before locking it and then updates it, so a first transition happens once for global and tenant checks; `getTenantObservabilityCheckStatus` reads another check's status.

**Tests.** `mailSyncStallCheck.test.ts` (production `mailAccountSync` handler, fake IMAP account, runtime role, own tenant): a pass leaving backfill with its follow-up queued and a stale heartbeat writes nothing; a pass held at its folder listing with `next_expected_activity_at` an hour overdue and a stale heartbeat writes nothing, nor after it finished; a mailbox whose passes stopped (with a dead holder's expired lease) gets one notification and one problem over repeated ticks; heartbeat first and overdue later still one notification; four overlapping runs on a stalled mailbox write one notification and one problem; four overlapping runs on a stale `api` heartbeat write one `process_stale` per admin. All six fail against the previous check code (the first two with both checks alerting, the rest with 2 or 4 notifications). Changed existing tests: the two overdue fixtures in `observabilityCheckSystem.test.ts` are an hour overdue instead of a minute.

**Verified** (backend/): `pnpm run lint`, `pnpm -r run build`, `test:unit` (4805 + 172), `check:write-safety`, `check:boundaries`; `format:check` fails only on three calendar timeline files with uncommitted changes of a concurrent session, the files of this change are formatted. Integration: 37 files (observability, tenant liveness, tenant observability checks, Semp problems, notifications, mail sync, single flight, IMAP, mailbox, `tenantIsolationJobs`, `tenantIsolationRoutes`, `mailSyncAdapters`), 1281 tests green. Not run: full `test:integration`, `test:e2e`, web and mobile pipelines.
