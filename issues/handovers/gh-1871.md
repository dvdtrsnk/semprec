## What was delivered

- `GET /api/semp-status` derives at most one AI budget problem on every read and stores nothing. `readSempStatusReport` in `backend/packages/data/src/semp/sempStatusReport.ts` calls the new module-private `readAiBudgetProblem(client, language)` inside the report's own transaction. That function reads `getAiUsageSummary(client)` (gh-1456, unchanged) and returns `aiBudgetMissing` while the tenant has no `tenant_ai_budgets` row (`hasBudget` false), `aiBudgetExhausted` while a cap of the tenant's own is reached, and `null` otherwise. The exhausted problem is selected by `resetsAt !== null`; the summary sets `resetsAt` and `exhausted` together.
- The problem is listed first, before the stored `semp_problems` rows, and counts in `activeCount`. Its fields: `id` (below), `category` `agents`, `severity` `critical`, `title`, `text`, `shortText`, `since` `null`, `mergedCount` 1, `projectName` `null`, `source` `{ table: "tenant_ai_budgets", id: null }`, `affectedService` `agents`, `actions` `[]`.
- Texts are catalog entries in `backend/packages/data/src/semp/i18n/cs.json` and `en.json`: `status.aiBudgetMissing.title|text|shortText` and `status.aiBudgetExhausted.title|text|shortText` (six new keys per locale; both catalogs have the same 46 keys). The exhausted `text` and `shortText` take `{resetTime}`.
- `{resetTime}` is the summary's `resetsAt` written by Luxon in the tenant's time zone and the user's catalog language: `DateTime.fromISO(resetsAt, { zone, locale }).toLocaleString({ dateStyle: "long", timeStyle: "short" })`, with `zone` from `getSystemTimezone(client)` passed through `assertValidTimezone`. The language is `cs` when the tenant user's locale is `cs` and `en` otherwise, as for every other status text.
- `GET /api/semp-status/summary` (`sempStatusSummary.ts`) has no code change, only two docstrings. Through the shared report read it now counts the budget problem and makes it the banner, with `problemId` and `instanceId` equal to the derived id and `impactKey` `agentsNotRunning`.
- The contract of a status problem without a row is recorded in the new ADR `docs/adr/2026-11-10-semp-status-problems-derived-at-read-time.md`.

## Contracts dependents build on

- Problem ids: `aiBudgetMissing` and `aiBudgetExhausted:<resetsAt>`, where `<resetsAt>` is the ISO 8601 reset instant of the exhausted window exactly as `getAiUsageSummary` reports it. A status problem `id` is therefore an opaque string and no longer always a UUID. For a derived problem `since` and `source.id` are `null`.
- The identity of an exhausted budget is its window, not one exhaustion. An exhaustion that ends and returns before the reset instant (a reservation settles below its estimate or fails, or an administrator raises a cap that is then reached again) keeps its id, so the summary's `instanceId` does not change and a notice a client hid stays hidden for the rest of that window. The next exhausted window has another id.
- Order and count: the derived problem is always first and is included in `activeCount`. It is `critical` with category `agents`, so it is the summary's banner for as long as it lasts, ahead of any stored critical `mail` or `agents` problem.
- `readSempStatusReport(pool)` still returns `{ report, problemKinds }`. `problemKinds` holds the stored problems only; a derived problem has no entry, which is why its `impactKey` is the category fallback.
- Only the tenant's own caps produce a problem. `getAiUsageSummary` does not read the operator-wide caps, so a refusal they cause lists no problem for any tenant.
- The `services` list is unchanged: it takes `state` and `since` from the stored problems only. A tenant with a budget problem still reports the `agents` service as `ok`.
- A stored zone that Luxon cannot read makes the status read throw `ValidationError` with `details.field` `timezone`, and only while a window is exhausted; without an exhausted window the zone is not validated by this code. The settings writer refuses such a zone, so only a write past it can store one.
- Nothing notifies a connected client that a budget problem appeared or ended. gh-2023 and gh-2024 are to publish the status invalidation; until they land a client sees the change on its next read.
- Test fixtures: a tenant without a `tenant_ai_budgets` row now always lists `aiBudgetMissing` first and counts it. A test that reads the Semp status or its summary for another reason gives its tenant a budget row first (`setTenantAiBudget`; a row without caps is enough).
- No export was added to or removed from the package index, and `backend/packages/data/src/index.ts` is unchanged. No route, no table, no migration, no generic operation, no job name and no hook was added or changed. `aiUsageSummary.ts` and the gateway sources are unchanged.

Follow-ups and open decisions recorded by the worker, the reviewers, the fixer and the recheck, none of them done:

- Decision for the controller: the `agents` service stays `ok` while the same response lists a critical problem with `affectedService` `agents`. gh-1561 decided that a service is in error when an active problem exists for it; its `since` is a stored problem's `first_seen_at`, which a derived problem does not have.
- Decision for the controller: the budget problem always owns the summary banner, ahead of a more recently seen stored critical problem, where gh-1631 breaks ties by the latest `last_seen_at`.
- The same unguarded `Intl.DateTimeFormat` call with the tenant's zone remains in `backend/services/semprec-agents/src/sempMessageTask.ts:130` and `backend/services/semprec-transcribe/src/transcriptSummary.ts:100`. They belong to other sources.
- Postgres reads `UTC+2` as a POSIX zone two hours west of UTC and Luxon reads it two hours east (measured by the fixer: `resetsAt` `02:00Z` for a `UTC+2` tenant). The gateway's day and month windows of a fixed-offset tenant therefore start at the opposite offset. The status shows the real reset instant in the tenant's zone, which is not local midnight for such a tenant. Proposed: one reading of fixed-offset zones for `getGatewaySpend`, the summary's reset instant and Luxon, or a stricter `assertValidTimezone`.
- `assertValidTimezone` also accepts `local`, `system` and `default`, which Luxon resolves to the server's zone.
- The delivery record `sp-16d8729d` orders gh-2023 and gh-2024 before gh-1871, but gh-1871 declares only gh-1555 as blocker and needs neither. Both are still open.
- No web or mobile code reads `/api/semp-status` at this commit. A client that assumes a UUID `id` or a non-null `since` must change when it starts to.
