# gh-1429 implementation handover

## Behavior and interfaces

`item.patch` returns the existing item fields plus `previous: Record<string, unknown>`.
The pre-image comes from the existing `SELECT ... FOR UPDATE` in
`itemsStore.updateItemProperties`, on the same client and transaction as the update.
Only patched keys appear; absent own properties become `null` (including names inherited
from Object.prototype). No history or field-change tool result is stored.

`itemsStore.UpdateItemResult` extends `ItemRow`. `updateItemWithClient` and the public
`createItemWriteOps.updateItem` carry that result through `withTransaction`. Hooks still
receive the plain item. The public result filters to the original caller patch keys,
excluding internally derived Tasks `time` unless it were caller-patched (the existing
writability guard rejects that). The facade in `chokePoint.ts` infers its update type
from these ops and needed no independent declaration change.

`ItemPatchOutput` in shared `genericOperations/schemas.ts` mirrors the additive shape;
`port.ts` selects it for `OutputByOperation["item.patch"]`, and application
`patchItem` explicitly returns that type via the existing choke point. The production
gateway/bindings already return the result without projection. The REST handler retains
`toItemEnvelope`, whose explicit six-field projection strips `previous`; the handler
comment documents this and its HTTP test asserts the exact response shape.

The concurrency test holds the first write transaction open, starts a second patch on
another pool, observes its backend blocked via `pg_blocking_pids` with a 5-second
poll deadline, then commits the first and checks Original -> First -> Second
pre-images and final persisted state. The version-conflict test verifies a rejected
promise without a successful result, unchanged row and no invalidation. A gateway
refusal also verifies unchanged persisted properties/version. Runtime-role isolation
checks foreign and random item ids both reject with NotFoundError, leave the owner row
unchanged, and allow the owner to receive its pre-image.

The first sandboxed integration attempt could not allocate Postgres shared memory;
the allowed unsandboxed scoped runs used a real ephemeral Postgres. The first such
run caught a new gateway fixture missing required ifVersion (fixed), plus two failures
in untouched REST cases (SSH banner received by fetch; unknown-item 401 rather than
404). The later whole-file run passed those same REST cases without changes. These
earlier failures remain in the worker evidence and are not claimed diagnosed or fixed.
Missing native Czech Hunspell assets emitted existing fallback warnings. No tests or
verification gates were weakened.
