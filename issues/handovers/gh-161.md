## Summary

This implements issue #161: standardizing transactional NOTIFY on the `semprec_events` channel and bridging it to WebSocket clients.

**Key changes:**
- All choke-point writes (items, databases, properties, views) fire a thin `notifyInvalidation` event via `runAfterCommit` — never before commit, never on rollback — carrying only `scope`/`databaseId`/`itemId`/`op`/`updatedAt`, never full row content.
- Document writes emit `docId`/`updateId`; notification commits emit `userId`/`notificationId` — no raw Yjs updates or pre-rendered notification content travel over NOTIFY.
- The `WS /api/sync` sync server (from issue #160) now fans out: item/schema invalidations broadcast as thin references to every connected socket (Semprec is a one-/two-user system, so no per-row filtering), while notifications fetch the full current row via `getNotificationById` and deliver it only to sockets authenticated as that notification's own user.
- Rollup and journal-inbox recompute re-fetch `updatedAt` after `writeComputed` (which doesn't bump it) before announcing an invalidation.
- Deleted `wsServer.ts`, a previously-unmounted duplicate broadcast mechanism (confirmed dead code by reading `serve.ts`), and ported its proven broadcast/user-scoping logic into `syncServer.ts` instead.

**Verification:** `backend/pnpm run verify` (lint, format, build, 93 test files / 1127 tests, e2e) and `web/pnpm run verify` (lint, format, build, 139 tests) both pass in full.
