## Delivered behavior

No code, schema or route changed. One new ADR:

- **`docs/adr/2026-10-29-calendars-are-not-shared-between-tenants.md`:** `status: accepted`, `area: [backend]`, `supersedes: []`. Sections Context, Decision, Alternatives rejected and Consequences. It references `[[2026-10-03-tenant-isolation-through-row-level-security]]`, `[[2026-10-07-cross-tenant-router-functions]]` and `[[2026-10-05-per-tenant-envelope-encryption]]` by slug. No existing ADR file was modified.
- **Decision:** calendars, events and invitations are private to their tenant. This version has no cross-tenant calendar sharing, no "shared with" subtitle and no shared-calendar notice. Email invitations (iMIP) and ICS subscriptions stay inside one tenant.
- **Rejected variant A (mirroring events into the recipient's tenant):** the ADR records what it would require. That means a new ADR superseding the "no sharing" part of the tenant isolation ADR, a channel that the router-functions ADR does not provide, a copy written by a job in the recipient's tenant, decisions on read and write rights and private fields, and behavior when sharing is removed.
- **Consequences:** linking a People entry to a Semprec user, sharing a calendar with a grantee, mirroring events and notifying grantees are not built and not planned. Each waits for a new ADR that supersedes the relevant part of the tenant isolation ADR.

## Deviations from the Task and the issue text

- The issue Context says "accounts are always created as new tenants". The repository does not support that without qualification. `bootstrapFirstAccount` (`backend/packages/data/src/auth/authActions.ts`) binds the first admin to the existing sole tenant, the row that migration `0056_tenants.sql` inserts, and creates no tenant. `acceptInvitation` is the only production code that creates a tenant for an account, and each accepted invitation gets a new tenant. The ADR states this precise rule.
- The issue Context says the router-functions ADR lets code cross tenants "only" through `SECURITY DEFINER` functions. The ADR narrows this. Router functions map external identifiers to tenants and answer cross-tenant aggregates. Other cross-tenant system work runs inside each tenant in turn, as `backend/review-rules/rules.md` requires.
- The file date is `2026-10-29`, the date the ADR was written. The Touches list named `<date of the pull request>`.
