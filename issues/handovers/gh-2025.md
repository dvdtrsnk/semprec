## What was delivered

The tenant-wide `mcpServers` realtime scope end to end and its publisher, sent when a server-wide MCP change alters the effective tools of every project that has grants on the server. No per-project `projectAgent` frame is published.

- `InvalidationEvent` gained `{ scope: "mcpServers" }`; `RealtimeMessage` and `parseRealtimeMessage` accept it with no user and no ids; `OutboundFrame` gained `{ type: "invalidate"; scope: "mcpServers" }`; `syncServer.ts` sends it to every socket of the envelope's tenant; `parseServerFrame` parses it, keeps nothing but `type` and `scope`, and drops an unknown scope.
- `mcp/mcpServersInvalidation.ts` exports `publishMcpServersInvalidation(client)`, which defers `notifyInvalidation({ scope: "mcpServers" })` with `runAfterCommit`; it must run inside the tenant's scope.
- `mcpServerItemUpdateHook` (`mcp/mcpServerWriteHook.ts`) publishes when the item belongs to the MCP servers database and the patch names `active`, whether or not the value changed. A patch without `active`, and an item of another database, publish nothing.
- `syncMcpServerTools` (`mcp/mcpSync.ts`) publishes inside the transaction that writes the registrations, after the server item update. A failed synchronization (connection, validation, refused response, or a rolled-back registration transaction) publishes nothing. The sync's own item patch does not name `active`, so the hook does not publish a second time.

## Entry points and contracts dependents build on

- Wire frame: `{"type":"invalidate","scope":"mcpServers"}`, no ids and no other field, to every socket of the tenant. The client refreshes the project summaries it has open.
- `publishMcpServersInvalidation(client)` is exported from `mcp/mcpServersInvalidation.ts`, not from the `@semprec/data` barrel (`index.ts` is at its line cap). The existing hook entry in `domainWriteHooks.ts` is unchanged; no hook was registered or reordered by this source.
- No `projectAgent` frame is sent for a server-wide change; a client that needs per-project data refetches after the one `mcpServers` frame.
- No table, migration, route, operation or job name was added.
