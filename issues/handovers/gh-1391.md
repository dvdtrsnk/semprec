# Handover for gh-1391

Each MCP tool registration now carries a user-editable, localized display label. The grants listing returns it as a plain string in the requesting user's language. Implemented in commit a72b5e03; I did not push or open a PR.

- **Migration:** `0093_mcp_tool_display_label.sql` adds nullable `display_label jsonb` with a check that it is `NULL` or a JSON object. It is additive.
- **Store:** `setMcpToolDisplayLabel(client, id, label | null)` in `mcpGrantsAdminStore.ts` (still off the package barrel). Only keys `cs` and `en` are allowed. Each value is trimmed, non-empty and at most 120 characters, and at least one key is required. It throws `ValidationError` otherwise and `NotFoundError` for an unknown id. `McpToolRegistration` gained `displayLabel`, and the `McpToolDisplayLabel` type is exported from the barrel (type only).
- **Wrapper:** `reclassifyMcpTool` accepts `displayLabel` (object or `null`) next to `riskClass` and `requiresApproval`. An input with none of the three still throws `ValidationError`.
- **Listing:** `listMcpToolGrantsForProject(client, projectItemId, locale)` now takes the locale (a required third argument). It returns `displayLabel: string` using the chain: locale label, other locale label, tool name. A locale other than `cs` is treated as `en`.
- **Handler:** `PATCH /api/mcp-tool-registrations/:id` accepts `displayLabel`. A non-object, non-null value gets 400 naming `displayLabel`. Content errors come from the store as 400. `GET` passes `identity.user.locale`.
- **Sync:** `upsertMcpToolRegistration` is unchanged and does not write `display_label`. A test covers a re-sync.
- **Tests:** new `mcpToolDisplayLabel.test.ts` (fallback chain, validation matrix, clear, 120-character boundary, not found, sync, DB check). New cases in `mcpAgentPageHandler.test.ts`. Existing `mcpAgentPageGrants.test.ts` calls now pass a locale.

Notes for dependants (#1983, #1455): to fill labels only where none exists, write through a path that checks `display_label IS NULL` inside the same statement. The listing's new `locale` argument is required.
