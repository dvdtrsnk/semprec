## Changes
- **New `backend/services/semprec-api/src/clientIp.ts`**: `clientIpFromRequest(req, { trustProxy })`.
  - With `trustProxy` on, it returns the last comma-separated `X-Forwarded-For` entry, trimmed. Caddy's `reverse_proxy` appends that entry itself; the earlier ones come from the client and are never used.
  - It falls back to `req.socket.remoteAddress ?? "0.0.0.0"` when the flag is off, the header is missing, or the last entry is empty.
  - The value is only trimmed, never parsed.
- **`authHandler.ts`**: `AuthRequestListenerOptions` gains `trustProxy?: boolean` (default `false`), and the login branch passes `ip: clientIpFromRequest(...)`.
  - A comment at that line records the throttle-key rule: the streak stays scoped per `(email, ip)`, with no per-email aggregate lock. Such a lock would bring back the owner lockout.
  - No data-layer change.
- **`app.ts`**: `AppOptions.trustProxy?: boolean` is passed through to `createAuthRequestListener`.
- **`serve.ts`**: `const trustProxy = process.env.TRUST_PROXY === "1"`, passed to `createDispatcher`. Any other value, including unset, means `false`.
- **`deploy/shared/.env.example`**: a new `# ---- Reverse proxy ----` section documenting `TRUST_PROXY=1`, which every deployment provisioned from `deploy/` must set.

Only the login route uses the helper. Password-reset request and `POST /api/setup` are unchanged (out of scope).

## Tests
- **New `clientIp.unit.test.ts`** (unit tier):
  - flag off ignores the header
  - the last hop is returned, never an earlier one
  - a missing header falls back to the socket address
  - the hop is trimmed
  - an empty last hop falls back to the socket address (an extra case beyond the issue's list)
  - a missing socket address gives `0.0.0.0`
- **`authHandler.test.ts`**: the `beforeEach` listener now uses `trustProxy: true`. The existing cases send no forwarded header, so they behave as before.
  - New case: `LOCKOUT_THRESHOLD` wrong passwords from `X-Forwarded-For: 203.0.113.9`. After that, the correct password from `198.51.100.4` gets 200, and from `203.0.113.9` gets 401.
