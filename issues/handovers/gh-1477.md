# gh-1477 — AI usage by operation

Implemented from integration tip 883d84fb1216972e0506d4dbdddb9ac99173a883.

`GET /api/ai-usage` now returns `byOperation` (backend/packages/data/src/aiGateway/aiUsageReport.ts): `[{operation, label, costUsd, share, callCount}]` over `[from, to)`, failed calls excluded from cost and count. A NULL operation is `other`. `agent_behavior_drift` merges into `agent_guidance_drift`; `voice_transcribe_stream` and `voice_synthesize` merge into `voice`. The query groups by raw operation and the merge happens in TypeScript (`MERGED_OPERATIONS`), so a new alias is one map entry plus catalog keys. Order: `costUsd` descending, then `operation`. `share` is `costUsd` over the sum of the entries (equal to `totalCostUsd`), 0 for all entries when the total is 0.

`resolveOperationLabel(catalogs, locale, operation)` in modelDisplayNames.ts: requested locale, en, raw key. Catalog keys `operation.<key>` were added to aiGateway/i18n/{cs,en}.json, including the alias keys and `operation.voice`.

Tests: new `usage by operation (gh-1477)` block in aiUsageRouteHandler.test.ts (merge, NULL, unknown key, locales, failed call excluded, sums, zero total), `resolveOperationLabel` cases in modelDisplayNames.test.ts; exact-shape expectations in aiUsageReport.test.ts and aiUsageRouteHandler.test.ts gained `byOperation`. 44 tests in aiGateway pass; tsc, eslint, prettier clean.

Notes for dependants:
- The web client schema (web/src/api/aiUsageOperations.ts) was not changed; `byOperation` is not consumed there yet.
- A new operation needs its own `operation.<key>` label in both catalogs, otherwise the raw key is shown.
- Full verify: NOT RUN; no migration.
