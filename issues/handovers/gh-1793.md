## What was delivered

- Seed: Books and Movies seed the user-owned properties `coverOverride` (image), `coverRemoved` (checkbox) and `coverSource` (select `candidate|userPhoto|userImage`). `LibraryModuleContract` has the optional `coverOverrideKey`, `coverRemovedKey` and `coverSourceKey`, filled by the seed so the library-grid view config exposes them. The system-owned `cover` stays system-owned; the metadata job never writes the override properties.
- Cutover: `runLibraryCoverOverrideCutoverMigration` (`library/libraryCoverOverrideCutoverMigration.ts`), registered in `tenantCutoverMigrations.ts` after the sleep cutover and before the area-note cutover. It adds the three properties to existing Books and Movies databases idempotently and adds the three view keys to existing library-grid views through `viewsStore.listViewsByDatabase` and `viewsStore.patchView` (absent keys only, stored values win, the view-type config schema validates the result).
- Write rules: `libraryCoverPreWriteTransform` and `prepareLibraryCoverWrite` (`library/libraryCoverHooks.ts`), registered with `registerItemPreWriteTransform` for `BOOKS_MODULE_ID` and `MOVIES_MODULE_ID` in `domainWriteHooks.ts`, run on create and update and as a proposal-time preparation for agent patches. They validate shape (`coverOverride` has a UUID `blobId`, `coverSource` is one of the options, `coverRemoved` is boolean) and combinations (`coverRemoved: true` with a non-null `coverOverride` is refused, a `coverOverride` needs a `coverSource`) with a 400 naming the field, and add `coverRemoved: false` when an override is set over a stored removal. Blob existence is checked by the existing blob reference hook (same 400 on `coverOverride` for a missing blob or a blob of another tenant). `deleteBlobIfUnreferenced` needed no change: it already counts every image property, so purging a Files item with the same bytes keeps the blob.
- Route: `POST /api/items/:id/automation/retry` (route case `library automation retry`, `routeMatrix/library.ts` `LIBRARY_ROUTES`, handler `createLibraryAutomationRetryRouteHandler` in `library/libraryAutomationRouteHandlers.ts`, declared in the library manifest `customRoutes`, transactional-semantics, manifest version 1.2.0). In one transaction as the user writer it clears the override properties through `updateItemWithClient`, resets the automation row to `pending` from any status including locked and failed (`resetItemAutomationToPending` in `itemAutomationStore.ts`), enqueues the metadata job with the config of the database's seeded heartbeat, and publishes the item invalidation after commit. It answers 202. A malformed id is 400 on `id`; a foreign, unknown, trashed or non-library item is 404, identical to a random id. A trashed item is refused from the unlocked read before any lock is taken (lock order: automation row before item row, as the job does; the item row stays locked first by the purge).
- cs/en labels for the properties and options.

## Deviations from the specification and spec seams

1. Task step 2 asks for an item update hook; an update hook runs after the row is written and cannot add `coverRemoved: false`, so the rules are a pre-write transform per module with a proposal-time preparation (agent patches go through `prepareUserItemPatch`). It also runs on create. Existence of the blob is checked by the existing blob reference hook, not duplicated.
2. The route entry lives in a new slice `routeMatrix/library.ts` appended to `ROUTE_MATRIX`, with its `ROUTE_CASES` case and `ROUTE_HANDLER_FILES` mapping.
3. The cutover also adds the three keys to existing library-grid views (stored values win), so tenants seeded before get the same view config as a fresh seed. After review it goes through `viewsStore` rather than raw SQL.
4. The runtime-pool tests are in a new file `libraryCoverRetry.test.ts`; `library.test.ts` holds the seed-shape, job and purge tests.
5. New store function `resetItemAutomationToPending` because `setItemAutomationLocked` only unlocks.
6. No ADR: the transform registry is covered by 2026-10-29-item-pre-write-transforms-per-module-registry and ownership by the single-writer ADR.
7. The retry route has no agent tool.
