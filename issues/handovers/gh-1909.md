## What was delivered

- `GET /api/agent-runs?projectItemId=<uuid>&limit=<1..100, default 20>` as a `single-consumer-read` custom route of the schema core manifest (route name `listAgentRuns`, handler export `createListAgentRunsRouteHandler` in the new `agentRuns/agentRunsListRouteHandler.ts`). The body is `{ rows: [...] }`; each row is `{ id, title, triggeredBy, triggerLabel, startedAt, durationMs, costUsd, displayStatus, errorSummary, attempt }`, newest first (`started_at DESC, id DESC`).
- Only the session user's own runs of that project are read, never `triggered_by = 'supervisor'` runs. All reads run in one `REPEATABLE READ` tenant-scoped transaction. A project of another tenant answers an empty list, like a random id.
- Cost is the sum of the run's gateway calls, read for all listed runs with one statement over `ai_gateway_calls` (`getAgentRunCosts`). `displayStatus` uses `deriveRunDisplayStatus` with `getAgentRunReplyOutcome` (gh-1890); `durationMs` uses the now exported `durationMsOf`; `errorSummary` uses `agentRunErrorFields` (gh-1824) and is set only when the display status is `error`.
- Trigger labels come from the new catalog keys `agentRun.trigger.user|heartbeat|mcp` (cs: Chat, Tik, MCP; en: Chat, Tick, MCP) in `agentRuns/i18n/{cs,en}.json`.
- Migration `0166_agent_runs_project_started_index.sql` adds `agent_runs_tenant_project_started_idx`.

## Deviations from the specification and spec seams

1. `createListAgentRunsRouteHandler` is exported from `index.ts` (Task step 6) and from `schemaCoreModuleManifest.ts`, because the module registry resolves `handlerExport` from the manifest module. `publicSurface.test.ts` (not in Touches) lists the new barrel exports.
2. The trigger labels live in `agentRuns/i18n/{cs,en}.json` (the catalogs gh-1824 reads), not `seed/i18n/` as Touches names.
3. `durationMsOf` of `agentRunDetail.ts` was exported (its parameter narrowed to a `Pick`) so the list reuses it.
4. `getAgentRunCosts` is a new batched function, because `getAgentRunUsage` takes one run id. It needs no status filter: `failGatewayCall` zeroes the cost of a failed call.
5. The response envelope is `{ rows: [...] }`; the Task does not name it.
6. `AGENT_RUN_ERROR_CODES` has no code for an unavailable integration, so the four-run test closes the errored run with `modelError`; the "GitHub unavailable" summary comes from the gh-1890 incomplete-reply path and has its own test (en and cs).
7. A run closed as `done` reads its reply with one statement per run (`getAgentRunReplyOutcome`), up to `limit` statements; cost, heartbeat names and pending approvals are one statement each. The acceptance criterion counts only the `ai_gateway_calls` aggregation.
8. The migration uses `IF NOT EXISTS` and no `CONCURRENTLY`, because migration files run in a transaction.
9. The Shared-file ordering blocker gh-1908 was landed before this train. At the landing merge the route entry sits after `restoreTrash` in the manifest, and ordinal 0166 is above the tip's highest (0165), so nothing was renumbered.
