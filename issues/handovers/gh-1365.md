# Handover for gh-1365

Added `docs/adr/2026-10-25-task-and-event-recurrence-model.md` (accepted, area backend). No code, migration or seed changes.

**What it records**
- Model: one rule and one template per series; occurrences with state are real items of Tasks or Events; future stateless occurrences are projected only.
- Rejected alternative: owner-user `recurrence` property with all-virtual occurrences, because generic queries, counts and search work on stored items only.
- Shared identifiers `seriesId` and `occurrenceDate`; virtual id `<seriesId>@<occurrenceDate>`.
- `task_recurrence`: one row per series (`series_id`, `anchor_date`, `template`), `item_id` overwritten on advance.
- `seriesId`, `occurrenceDate`, `recurrence` are `system`-owned Tasks properties written only by the Tasks module.
- Lock order: items first, then `task_recurrence`.
- Series edit and delete consequences; done, wontDo and missed occurrences are never rewritten.
