**Changes**
- **Envelope:** both publishers in `pgNotifyPublisher.ts` now send `{ tenantId, message }`, with the tenant computed in the same statement from the publisher's scope. `session_revoked` takes the tenant of the session's user instead. Chunking and the 7,500-byte constants are unchanged.
- **Parsing:** `parseRealtimeEnvelope` and `parseAgentStreamEnvelope` return `null` unless `tenantId` is a UUID and the inner message is valid.
- **Delivery:** `SyncIdentity` gains `tenantId`, filled from `identity.tenantId` in `syncHandler.ts`. `broadcast` and `sendToUser` are replaced by `sendToTenant(tenantId, frame, userId?)`. Invalidations and notifications use it, and `session_revoked` closes only sockets matching both session and tenant.
- **Drop and log:** an envelope that fails to parse is dropped with one `realtime_message_without_tenant` warning carrying only the channel and type.
- **Scopes:** the LISTEN connection opens under `runAsSystem("realtime:listen")`. Each envelope is handled under `runInTenant`. `authenticate` runs under `runAsSystem("realtime:upgrade")` and heartbeat revalidation under `runAsSystem("realtime:revalidate")`.
- **Dependency, comment, ADR:**
  - `@semprec/shared` is added to the realtime package and the lockfile.
  - The comment in `realtimeHook.ts` is rewritten.
  - The new ADR is `2026-10-16-tenant-scoped-realtime-fan-out.md`.
  - The old ADR changed only in `status` and `superseded-by`.

**Tests:** I updated the existing payload assertions in `realtime.test.ts`, `lifecycleAdapter.test.ts` and `transcriptionTask.test.ts`. I replaced the broadcast test in `syncServer.test.ts` and added tests for each acceptance criterion in the issue (delivery, notification and revocation isolation, drop-and-log, delta cap, parsing, strict mode).

**Things to know**
- `publishRealtimeMessage` for `session_revoked` now casts the session id with `$3::uuid`, so a non-UUID session id makes the query throw. Real session ids are UUIDs, but two old `syncServer` tests published fake ids like `"session-a"`. I changed them to publish a hand-built envelope instead. Publisher coverage for revocation now lives in `realtime.test.ts`, which uses real sessions.
- The strict-mode test uses fake timers for `setInterval` only, so I didn't have to add a heartbeat-interval option to `createSyncUpgradeHandler`.
