## Strip non-primitive error details in bespoke handlers

Closes #638

Every bespoke handler and every MCP JSON-RPC error path now filters a caught `ChokePointError`'s `details`. A nested object, array or string no longer reaches the client; a flat record of primitives still passes through unchanged. `error` and `code` are not touched. `pnpm run verify` in `backend/` did not pass in one clean run on this loaded machine; the failures and reruns are listed under Verification.

### Changes
- **`adapter/errorContract.ts`**:
  - `safeDetails` is renamed to `publicErrorDetails` and exported; its body and docstring are unchanged, and `toErrorResponseBody` calls the new name.
  - New `toPublicErrorBody(err)` returns `{ error: err.message, code: err.code, details: publicErrorDetails(err.details) }`. This keeps the bespoke handlers' existing top-level shape, per the additive-only REST contract ADR.
- **The seven bespoke handlers** (`authHandler`, `setupHandler`, `notificationsHandler`, `approvalRequestsHandler`, `agentRunHandler`, `mcpAgentPageHandler`, `schemaHandler`): each `catch` now sends `toPublicErrorBody(err)` instead of the verbatim object.
- **`mcp/mcpHandler.ts`**:
  - The outer `catch` sends `toPublicErrorBody(err)`.
  - The `-32001`, `-32602` and `-32000` JSON-RPC errors now carry the filtered details. `ApprovalRequiredError`'s `{ approvalRequestId, link }` and `ValidationError`'s `{ field }` are flat, so they pass through unchanged.

### Where this differs from the issue text
The Task asks for `publicErrorDetails(err.details)` at the three JSON-RPC lines. The acceptance criteria and the new source-scanning test require that no handler file contains `err.details` at all, so both can't hold. The MCP handler uses `toPublicErrorBody(err).details` instead. It runs the same filter on the same input, satisfies the grep criterion, and needs no new export.

### Tests
- **`errorContract.unit.test.ts`**:
  - `toPublicErrorBody` keeps the message and code, and passes `{ field: "x" }` through.
  - It returns `details: undefined` for `{ current: { id } }`, for an array and for a string.
  - `publicErrorDetails` is exported and filters the same way the existing "drops details that aren't a flat record" case expects.
- **New `__tests__/bespokeHandlerErrorBodies.unit.test.ts`**: reads the eight handler files with `node:fs` and asserts each calls `toPublicErrorBody(err)` and never contains `err.details`.
