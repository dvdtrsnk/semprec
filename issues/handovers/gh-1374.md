# Handover for gh-1374

Startup repair now writes the synthetic `tool_result` for an unmatched `tool_use` in the regular tool result shape. Targeted checks run: prettier, eslint, `tsc` for `@semprec/agent-runtime`, the two `startupRepair*` integration test files and the `piConversationHistory` unit test. The full `pnpm run verify` was not run.

**What changed in `startupRepair.ts`**
- The row is now `{kind: "tool_result", toolCallId, name, result: {content: [{type: "text", text}], details: {error: true}}, isError: true}`.
- `toolCallId`, `name` and, when present on the `tool_use`, `operation`, `mcp`, `targetDatabaseId` and `targetItemId` are copied. `arguments` and any other field are not.
- A non-object `tool_use` payload still yields a well-formed row: `name` is `""` and `toolCallId` is omitted rather than invented.
- The interruption text is unchanged and still names `interrupted_by_restart`.

**Tests**
- `startupRepair.test.ts` asserts the exact stored payload, covers the non-object fallback and the heartbeat case with the new shape, and checks that `reconstructConversationHistory` accepts the repaired history.
- `piConversationHistory.unit.test.ts` converts the new shape through `toPiMessages`.
- `startupRepairPerTenant.test.ts` needed no change.

**Notes for dependants**
- Rows already stored in the old shape (top-level `error: true`, string `result`, no `isError`) are not rewritten. Readers must keep tolerating a top-level `error: true`.
- A failed step can now be recognised from `isError` or `result.details.error` alone.
