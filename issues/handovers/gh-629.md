`PATCH /api/approval-requests/:id` now always records the logged-in user as the decider, and its response no longer includes the request's argument values. Closes #629.

## What changed

**`backend/services/semprec-api/src/approvalRequestsHandler.ts`**
- The decider now comes from the logged-in session: the handler passes the user id from `authenticateRequest` to `decideAndEnqueueApprovalRequest`.
- A `decidedByUserId` field in the request body is ignored, not rejected. The web client still sends it, and the additive-only REST contract ADR says a field a deployed client sends must not start failing. The docstring says the web client stops sending it in a later batch.
- Removed `FOREIGN_KEY_VIOLATION_ERRCODE`, `isForeignKeyViolation` and the `try`/`catch` that answered `400 No user with id '…'`. The session user always exists, so that branch could not run anymore, and it let a caller check whether a user id exists.
- Both 200 responses (a fresh decision and the "already decided" re-read) now return `toApprovalRequestDecisionView(...)` instead of the stored row. The 404 for an unknown id and the check on `decision` are unchanged.
- Updated the docstring to match.

**`backend/packages/data/src/mcp/approvalRequestsQueue.ts`**
- Added `ApprovalRequestDecisionView` and `toApprovalRequestDecisionView`. The view returns exactly `{ id, status, decidedAt, decidedBy, executionStatus, toolName, riskClass, requestedAt, agentRunId, safeSummary }`, with `safeSummary` built by the existing `safeSummaryOf`.
- `payload`, `resourceSnapshot`, `executionResult`, `executionError` and `executedAt` are left out.

**`backend/packages/data/src/index.ts`**
- Both new names are re-exported on the two existing `approvalRequestsQueue.js` export lines. Prettier wraps the type export across several lines.

**`backend/services/semprec-api/src/__tests__/approvalRequestsHandler.test.ts`** (integration tier)
- New `authSession()` helper returns the session headers and the user id; `authHeader()` now uses it.
- "returns 400 for a missing decidedByUserId" is replaced: a body of only `{ decision: "approved" }` returns 200, and both `decidedBy` and the `decided_by` column equal the session user.
- "returns 400 for a decidedByUserId that references no user" is replaced: a random-UUID `decidedByUserId` returns 200, and `decidedBy` is the session user, not the body value.
- The repeated-decision test now expects the first session's user id.
- New test: deciding an MCP-invoke request with `args: { query: "hi" }` returns a body with no `payload` key, no `"hi"` anywhere, and `safeSummary.argKeys` equal to `["query"]`.
- **One change beyond what the issue lists:** in "approves a pending request" I changed the expected `decidedBy` to the session user. It used to check the id sent in the body, which the new behaviour correctly ignores, so it could not pass unchanged. It still sends `decidedByUserId`. The web client and the `:id` UUID validation (B7) are not touched, as the issue's out-of-scope list says.
