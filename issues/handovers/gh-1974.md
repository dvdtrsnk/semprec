## What was delivered

When an Inbox item typed to the Recipes database is computed, a recipe writer reads a recipe from the first `https:` link of the item text, or from the first photo attachment, and the card proposes a new Recipes item.

- Link: the URL must pass the stored-URL baseline (`isBaselineOutboundUrl`), then the page is fetched through `createOutboundHttp` (10 s deadline, 2 MiB cap, `text/html` allow-list, no redirects, connect-time address policy). Its readable text goes to the gateway operation `inbox_proposal` with a `{ name, ingredients, steps, prepMinutes, servings, photoUrl }` response schema.
- Photo: the reduced copy of the first photo attachment is sent as an image block.
- Result: `name`, `prepMinutes`, `servings`, `sourceUrl` (link only) and `photo` (the attachment's own blob, else the page's `og:image`, fetched with the same checks, sniffed as JPEG or PNG and stored through `ingestUploadedBlob`), plus `pageSections` (Ingredients bulleted, Method numbered).
- Confirm writes the sections to the created item's page in the confirm transaction (authored by the confirming user, block ids from `proposalBlockId`); undo removes them with the created item.
- A page with no recipe, an incomplete or schema-mismatched answer, a gateway failure (`AiGatewayFailedError`), an unreachable, non-HTML, too large or unfetchable page gives no recipe: the writer answers `null` and the computation goes on as for any other database. Any other error propagates.
- The `recipes` database gains the user-owned `url` property `sourceUrl` and `recipeSourceUrlWriteHook` (create and update, `ValidationError` on field `sourceUrl`, so HTTP 400 with `details.field` `sourceUrl`). `recipes` is appended to `INBOX_TYPE_MODULE_TARGET_DATABASES`, so it is a type target (seed option, existing option cutover, write-hook existence check, recognition targets, option labels).
- Two ADRs: `docs/adr/2026-11-15-a-database-proposal-may-carry-page-sections-for-the-item-its-confirm-creates.md` (the envelope field and the Revising rule) and `docs/adr/2026-11-15-an-open-proposal-keeps-the-blobs-its-envelope-names.md` (the blob lifecycle of an open card).

## Deviations from the specification and spec seams

1. No proposal-writer registry exists in `inboxTickAction.ts` (the tick takes an injected computation function), so the writer is registered in the semprec-api composition; `inboxTickAction.ts` only gained a validation call.
2. The Task's `seed/i18n` files are not used: Recipes labels live in `recipes/i18n` (handover gh-1707); the Inbox option label and page headings are in `inbox/i18n`.
3. The database envelope could not carry page content, so confirm in `proposalActions.ts` changed (the Touches allow it): optional `pageSections` (plain text, not Markdown), ADR added.
4. Extraction failure falls back as: `proposeRecipe` answers `null` and the computation goes on as for any other database. A recognition run of an untyped item is not served by the writer; the typed recompute after the type is bound is.
5. The outbound client refuses every redirect (ADR 2026-10-16), so a page that redirects counts as unreachable.
6. The model's `photoUrl` is honoured only when it equals the `og:image` URL of the fetched page; JPEG and PNG only (WebP and GIF are not stored). An attached photo's own blob wins over a page photo. The page photo blob is created at computation time; after review the unreferenced-blob sweep keeps it while an open card names it (ADR 2026-11-15). Cleanup of blobs of abandoned cards is otherwise left to the existing sweep (#1401 is not needed for that).
7. A recipe needs a name, at least one ingredient and one step to count as read.
8. The gateway operation `inbox_proposal` is reused; no gateway change.
9. Files beyond Touches: `recipePageFetch.ts`, `proposalPageSections.ts`, `proposalBlobReferences.ts`, `recipesSourceUrlCutoverMigration.ts`, `testSupport/recipeInboxFixtures.ts`, two ADRs, `blobs/blobsStore.ts`, `proposalThreadRevision.ts`. The cutover is code-level, not a SQL migration.
10. Existing tests adapted: `recipesModule` (data and api), `recipesModuleManifest.unit`, `tenantCutoverMigrations`, `publicSurface`, `inboxTypeWriteHook`, `inboxRecognition.unit`.
11. At the merge: `createProposalComputation` gained the `aresClient` parameter of gh-1987 beside the chain's `recipe` ports (both kept); `recipeProposalComputation.test.ts` passes a stand-in `aresClient` that knows no company.
12. The worker's deviation text that cites #1401 for blob cleanup lives in `worker.json`, outside the repository, and was not changed.
13. The commit trailers on the chain name Claude Sonnet 5.5 (the session attribution).
