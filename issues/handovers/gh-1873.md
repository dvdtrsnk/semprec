## What was delivered

- `GET /api/trash/databases`: the tenant's archived user databases (`archived_at` set, `NOT system`) as `{ databases: [{ id, key, name, liveItemCount, archivedAt, purgeAt, daysLeft }], totalCount }`, ordered by `archived_at DESC, id`, at most 500 rows with the real total in `totalCount`. The rows, the total and every count are read in one REPEATABLE READ transaction. `liveItemCount` is `itemsStore.countItems` (soft-deleted items are not counted). A system database never appears, even one whose `archived_at` was set by raw SQL. A restored database leaves the list.
- In this source `purgeAt` and `daysLeft` are `null`. gh-1875, landed in the same chain, fills them from the stored deadline (see its handover); in the merged tree they are real values for every database archived by this release and for those the sweep has stamped.
