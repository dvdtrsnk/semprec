# gh-1472 — AI usage by model

Implemented from integration tip ec41851e0de8339efcfb07ef0c83e08f799fd8ee.

`GET /api/ai-usage` now returns `byModel` (backend/packages/data/src/aiGateway/aiUsageReport.ts): one entry per `(provider, model)` over `[from, to)` with `provider, model, displayName, callCount, costUsd, inputTokens, outputTokens, audioSeconds, operations`. It is a separate grouped query (no run unit), failed calls excluded, same audio-operation classification as `rows` (`AUDIO_OPERATIONS`). Token fields are null for an audio-only model, `audioSeconds` is null for a token-only model, numbers otherwise (0 while reserved). `operations` is the sorted distinct list of operation keys, a NULL operation as `other`. Order: `costUsd` descending, then `model`, then provider. `displayName` comes from `resolveModelDisplayName` (gh-1442) with the catalogs loaded once per process. `rows` and all other fields are unchanged.

`AiUsageReportInput` gained an optional `locale` (default `en`). `aiUsageRouteHandler.ts` passes `toManifestLocale(ctx.identity.user.locale)`; its duck-typed context now requires `identity.user.locale`.

Tests: new `usage by model (gh-1472)` block in aiGateway/__tests__/aiUsageRouteHandler.test.ts (invocation + session + no-run merge, failed call excluded, operations once with `other`, cost sum equals total, Sonnet display name per locale, unknown id raw, Whisper audio only). Existing exact-shape expectations gained `byModel`; handler calls in tests pass `identity`. The three touched test files pass (42 tests); tsc, eslint, prettier clean.

Notes for dependants (#1477):
- A model used for both audio and token operations would report both unit groups in one entry; none exists today.
- The web client schema (web/src/api/aiUsageOperations.ts) was not changed; `byModel` is not consumed there yet.
- The cs and en Sonnet names are identical, so the locale test cannot tell the catalogs apart for Sonnet.
- Full verify: NOT RUN; no migration.
