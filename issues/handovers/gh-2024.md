## What was delivered

A new tenant task `aiBudgetReset` that refreshes the Semp status of a tenant at the reset instant of an exhausted budget window, so clients drop the `aiBudgetExhausted` problem without polling.

- `CORE_TASK_NAMES.AI_BUDGET_RESET = "aiBudgetReset"` in `packages/queue/src/index.ts`, affinity `api` (`CORE_TASK_AFFINITY`), tenancy `tenant` (`TASK_TENANCY`), registered in `createCoreTaskList` (`packages/data/src/worker.ts`); the API process list derives from the affinity table.
- `packages/data/src/aiGateway/aiBudgetResetJob.ts`: `aiBudgetResetJobKey(tenantId, resetsAt)` = `aiBudgetReset:<tenantId>:<ISO instant>`; `enqueueAiBudgetReset(client, resetsAt)` (tenant from the active scope, a system or missing scope is refused before any query, `runAt = resetsAt`, job key mode `preserve_run_at`, payload `{}`); `handleAiBudgetResetTask(pool, payload)` (strict empty payload, publishes the `sempStatus` invalidation through `publishSempStatusInvalidation` in a transaction, so after commit).
- The gateway's announcement (gh-2023) enqueues the job for an exhausted cap window (daily: next local midnight; monthly: first local midnight of next month; both caps: the monthly one), after the rollback, from the gateway process on its `semprec_side` pool. A missing budget row gets no job; an operator-wide refusal gets none. An enqueue failure is logged with `{ tenantId, errorName }`, swallowed, independent of the publish step, and releases the window so the next refusal retries.

## Entry points and contracts dependents build on

- Task name `aiBudgetReset`, job key `aiBudgetReset:<tenantId>:<resetsAt ISO>`, payload `{}` (any key is rejected), run time = the reset instant of `getAiUsageSummary().resetsAt`.

## Deviations and spec seams

1. The registration is the `createCoreTaskList` entry in `worker.ts`; there is no per-process list edit.
2. The barrel exports only `enqueueAiBudgetReset`.
3. The task-affinity unit test and the `tenantIsolationJobs` case were added because the inventory tests require one case per api task.
4. The gateway can enqueue, so the fallback of enqueueing from the API process was not built; the pull request should say so.
5. The database clock cannot be moved, so the "reset passed" case moves the exhausted day's spend two days back with one commented raw UPDATE, which is where it sits after the reset.
6. The ADR written with gh-2023 was extended in this segment instead of being superseded (it is unmerged to `develop`, so editing it is not an append-only violation).
