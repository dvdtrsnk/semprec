# Handover for gh-1565

The Semp conversation registry is keyed by `(tenantId, threadId)`. Committed locally on `wf/gh-1565`; not pushed.

- **Registry:** `SempConversation` (`agent-runtime/src/sempConversation.ts`) keeps one `ThreadConversation` per `tenantId:threadId`. `busy`, `waking`, `dropped` and the TTL timer are per thread. A turn in thread A never yields `SEMP_BUSY_ERROR_MESSAGE` for thread B; a second concurrent turn in the same thread still does.
- **API change:** `send(task, thread, options?)` now takes a `SempThread`: `{ threadId, kind: 'chat' | 'item' }` or `{ threadId, kind: 'tick', projectItemId }`. Chat and item threads use `options.resolveProjectItemId` (the Semprec project); a tick thread uses its own `projectItemId` (the heartbeat's project) and the resolver is not called. The wake run is created with `threadId`. Exported new types: `SempThread`, `SempThreadWake`.
- **Reconstruction port:** `ReconstructConversationHistory` is now `(pool, { threadId, projectItemId })`; `createReconstructConversationHistory` reads with the #1560 thread filter (`{ threadId, triggeredBy: 'user', parentRunId: null }`), so reconstruction and compaction are per thread.
- **TTL:** the timer re-enters the tenant with `runInTenant` when it fires and is cleared on drop, on a broken turn and on `clear()`.
- **dropTenant:** drops every thread conversation of the tenant (idle ones are closed as `error` at once, in-flight ones when they settle, failed closes retry); other tenants are untouched.
- **Tests:** `agent-runtime/src/__tests__/sempConversation.test.ts` (existing tests now send in a real `semp_threads` row; new `per-thread registry` block: parallel threads, same-thread busy, tick project, per-thread TTL, timer in tenant context, tenant-wide drop incl. an in-flight thread). Agent-runtime package tests, eslint and tsc pass. Full verify was not run.
- **For dependants:** #1727 must supply the `SempThread` (including the heartbeat project item id for tick threads) and use real thread rows, since `agent_runs.thread_id` has a foreign key. Nothing in production calls `send` yet.
