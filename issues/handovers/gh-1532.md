# Handover for gh-1532

## Summary

Grouped views accept an optional `groupDirection: "asc" | "desc"` (default `asc`).

- `views/viewConfig.ts`: the zod schema and `ViewConfig` carry the field; any other value fails `parseViewConfig` with a `ValidationError`.
- `views/viewQuery.ts`: `buildSortSpecs` uses the effective direction for the leading group sort. `sortCompiler.ts` is unchanged: it already handles direction, and `NULLS LAST` keeps items without a group value last in both directions. The sort within a group is unchanged.
- Keyset cursor: a sorted token carries `g: "desc"` only when the group direction is `desc`; decoding requires `g ?? "asc"` to equal the query's effective direction, otherwise `Invalid cursor`. Tokens issued before this change stay valid for `asc` views.
- An ad-hoc `sort` passed to a query replaces the view's grouping, so it is always decoded under `asc`.

## Tests

`viewQueryPagination.test.ts`, block "groupDirection (issue #1532)": reversed option order with `desc`, no-value items last, paging with limit 2 returns every item once, absent/`asc` keeps option order, cursors refused across directions both ways, unknown value rejected.

## Notes for dependants

- No Journal grouped view is seeded (out of scope); a view only needs `groupBy: "type", groupDirection: "desc"`.
- The cursor direction tag is only meaningful for the leading group key.
