# Handover for gh-1728

Creating an approval request now raises the requesting run's thread activity. Committed locally on `wf/gh-1728-n2`; not pushed.

- **Code:** `createPendingApprovalRequest` (`approvalRequestsStore.ts`) runs, after a fresh insert, `UPDATE semp_threads SET last_activity_at = GREATEST(last_activity_at, now()) WHERE id = (SELECT thread_id FROM agent_runs WHERE id = $1)` on the same `Queryable`, so it shares the caller's transaction. A run without a thread matches no row. A replayed `tool_call_id` (the `ON CONFLICT DO NOTHING` path) does not bump. `genericOperationGateway.ts` and `mcpInvokeTool.ts` are unchanged.
- **Tests:** new describe in `__tests__/approvalRequestsStore.test.ts` covers the generic-operation and MCP payloads, a run without a thread, rollback, a delegated run (thread inherited from the parent) and a transaction that started before a newer committed activity. `approvalRequestsQueue.test.ts` was run unchanged. Tsc for `@semprec/data` and prettier were run; full verify was not.
