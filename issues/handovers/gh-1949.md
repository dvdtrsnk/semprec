## What was delivered

- The agent tool `mail.draft.send { draftId }`, declared in the mail module manifest (capability `mail.send`) with its handler `createMailDraftSendTool` in `mail/mailAgentTools.ts`. It never sends: it checks the run (404 unknown run, 403 run without a project), calls `requestMailSendApproval` of gh-1913 with the run as `ai_agent` actor and answers with the sentence of a deferred tool that names the pending approval request. The owner's approval of that request makes the gh-1913 executor send as the user. A sent, discarded, unknown or other-tenant draft is refused by `prepareSend` (409 `mail_draft_already_sent`, 409 `mail_draft_not_editable`, 404). A repeated call for a draft that already has a pending request returns that request and files no second one.
- A module tool handler may now return `approvalRequestId`; `ResolvedModuleAgentTool.invoke` (`agentTools/moduleAgentTools.ts`) forwards it and `createModuleTools` (`semprec-agents/src/agentSessionComposition.ts`) writes it into the step `details`, so the run timeline sees an approval step (fix round).
- Labels `agentTool.mail.draft.send.label` in both mail catalogs.
- ADR `docs/adr/2026-11-14-the-mail-send-tool-is-declared-without-deferral-and-files-its-own-approval-request.md`.

## Entry points and contracts dependents build on

## Deviations from the specification and spec seams

1. The Task says `requiresApproval` exactly as defined in #1913, but #1913 delivered no descriptor and its ADR rejects deferring the send through the module registry; with `requiresApproval: true` the session would file a generic approval first and the handler a second one for one send. The tool is declared `approval: none` and files the gh-1913 request itself; this narrows sections 1 and 4 of ADR 2026-10-28 for this one tool and is recorded in the new ADR.
2. Criterion 2 ("a run in a project with permission sends the draft once") is read against the delivered v1 rule that no permission lets an agent send without approval: with `emailSendAutonomous` the call still files a request and sends nothing; after the owner approves and the executor delivers, exactly one message is sent and a repeated call is a 409. The literal "with permission the tool sends directly" does not exist in v1 and was not built.
3. The handler calls `requestMailSendApproval` (the function `sendDraftEmail` calls first for an `ai_agent` actor) instead of `sendDraftEmail`, because `AgentSendEmailInput` demands the whole send input that the agent path never reads.
4. The pending sentence of `moduleToolPendingApprovalText` (semprec-agents, not importable from data) is copied into `mailAgentTools.ts`.
5. Edits outside Touches: mail catalogs (labels required by `systemI18nCatalogCoverage`), the capability list of the manifest, two existing tests whose tool lists changed, the ADR, and the fix round's `approvalRequestId` forwarding.
