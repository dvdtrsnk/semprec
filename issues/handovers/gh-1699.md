## What was delivered

- Two catalog operations, `property.option.add` and `property.option.update`, that change `config.options` of a `select` or `multi_select` property also on a schema-locked database. They skip the database-level `schema_locked` check and nothing else. Every other schema change of a locked database still answers `SchemaLockedError`: creating, retyping and deleting a property and `property.patch` of a `config`, the option array included. No operation removes an option, reorders options or changes an option key.
- Two REST routes: `POST /api/properties/:id/options` (body `{ label, color? }`, 201) and `PATCH /api/properties/:id/options/:key` (body `{ label?, color? }`, 200). Both answer the option as `{ key, label, color? }`.
- The key of a new option is derived by the server from the label: Unicode NFKD, combining marks removed, every character outside `A-Z`, `a-z`, `0-9` separates words, ASCII camelCase ("Dentální hygiena" gives `dentalniHygiena`, "3D tisk" gives `3dTisk`). When no word remains the key is `option`. A key the property already holds gets the lowest free integer from 2 up (`bylinky2`). A rename keeps the key and the position.
- The label is stored without surrounding whitespace and has 1 to 60 UTF-16 code units. A label that holds U+0000 or a UTF-16 surrogate without its pair is refused. All of these answer 400 `validation_failed` naming `label`.
- A label that another option of the same property already has is refused with 409 and the new additive error code `option_label_exists`, whose `details.key` is the existing option's key. Compared are the stored label and the Czech and English catalog labels of each other option, after NFD normalization, removal of combining marks, trimming and lower-casing ("léky" equals Medication). The raw key an option without any label is displayed by is not compared.
- An add to a property that already holds 100 options answers 400 `validation_failed` with `details.reason` `option_limit`. An update is not limited.
- A property that is not a `select` or `multi_select` answers 400 `validation_failed` with `details.field` `propertyId`. A property that is itself `locked` answers `PropertyLockedError`. An unknown option key answers 404 `not_found` with `details` `{ resource: "propertyOption", propertyId, key }`. An update with neither `label` nor `color` answers 400 `validation_failed` with `details.reason` `empty_patch`, after the not-found checks. Another tenant's property id answers exactly like an unknown id.
- Each operation runs in one `withTransaction` at READ COMMITTED, reads the property row with `SELECT ... FOR UPDATE`, checks on that row and writes the whole `config` back with one checked `UPDATE`. Two concurrent adds both end up stored; of two concurrent adds of one label the later one is refused with the earlier one's key.
- In the same transaction each operation queues the search reindex of the database (as every property write does since gh-1652). After the commit it sends `notifyInvalidation({ scope: "schema", databaseId, userId })` through `runAfterCommit`.
- Both operations are REST-only: `GenericOperationGateway` lists them under no grant and refuses a call like an unknown operation, so no AgentTool and no MCP tool exists for them (MCP answers -32601 Unknown tool). The assistant is to propose a new option on an Inbox proposal that a person confirms (gh-1994).
- The `:key` segment of the update route is percent-decoded once before the lookup. A segment that is not valid percent-encoding of UTF-8 answers 400 `validation_failed` naming `key`.
- ADR `docs/adr/2026-11-10-select-options-change-on-a-schema-locked-database.md` (accepted, area backend) records the exception to the lock, the key, label, limit and lock rules, what happens after the write, and the transports.

1. Route entries: the Task names `routeMatrix.ts`. The two entries are at the end of the slice `routeMatrix/properties.ts`, with their `ROUTE_CASES` and `ROUTE_HANDLER_FILES` rows.
2. `chokePoint.ts` and `packages/data/src/index.ts`, both in `Touches`, are unchanged (see the contracts above).
3. "Keep them out of the agent tool and MCP exposure lists": no static exposure list exists. The exclusion is `REST_ONLY_OPERATION_NAMES`, read by `isGranted` in the gateway. `createGenericOperationAgentTools` still builds a tool object for every catalog name; the gateway refuses the two. The ADR records this as a narrowing of "one dispatch path, three transports".
4. The label rule needs the Czech and English catalogs, and the choke point is built from a pool alone, so `propertyOps.ts` builds one catalog resolver per process. Recorded in the ADR.
5. Beyond the Task text: both operations queue the search reindex of the database, because search documents contain option labels. Recorded in the ADR.
6. `property.option.update` reads the caller's locale (`findUserLocale`, English fallback) for the returned label of an option that stores none, so `chokePoint.updatePropertyOption` takes a locale argument.
7. Details the issue left open: `option_limit`, the 404 for an unknown option key, `empty_patch`, the label measured in UTF-16 code units after trimming, digits kept in keys, and both the stored and the catalog labels compared. The ADR states the limit, the label and the key rules. It does not state the 404 for an unknown option key or `empty_patch`; both follow the existing `property.patch` conventions.
8. Review fix inside the segment: the label refinement uses a Unicode-mode regular expression on the Surrogate category instead of the proposed `isWellFormed()`, which does not type-check under the repository's TypeScript lib ES2022.
9. Files outside `Touches` that the change needed: `errors.ts` in data and in shared, `errorContract.ts` and its unit test, `catalogResolution.ts` and its unit test, `requestValidation.ts` and its unit test, `publicSurface.test.ts`, `chokePointWriteBoundary.unit.test.ts`, `jsonSchema.unit.test.ts`, `propertiesHandler.test.ts`, `genericApplicationService.test.ts`, `genericOperationGateway.test.ts`, the two agent-runtime tool tests, `mcpGenericOperationsContract.test.ts`, `mcpAgentPageHandler.test.ts`, `sempThreadPrompt.test.ts`, the new `propertyOptionsCatalogLoad.test.ts`, and the four files whose comments state the operation count.
