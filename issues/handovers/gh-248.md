## Retry policy
- `transcriptionJob` keeps `max_attempts: 3` and graphile-worker's default exponential backoff.
- Each retry resumes from the checkpoints left by #182 and #183, so a gateway call that was already paid for is never repeated.
- The policy is now documented on `enqueueTranscriptionJob`.

## `item_automation` state machine (`transcriptionTask.ts`)
- **Start of each attempt:** after step 0 has created the Transcriptions row, one transaction sets the row back to `pending`, adds 1 to `attempts` and stamps `last_attempt_at`. If the row is `locked`, the handler stops there and processes nothing.
- **Locked rows:** the lock is checked again between steps, so a lock set mid-run stops the pipeline before its next step. The step already running still finishes its own writes. The pipeline never sets `locked` itself.
- **Transient failure:** only `item_automation.error` is written. The row stays `pending` / `processing`, and the error is rethrown so graphile-worker retries.
- **Permanent failure** (last attempt used up, or a budget rejection from the gateway): one transaction re-checks the lock, then:
  - sets `item_automation.status = 'error'` with the error text;
  - sets `status = error`;
  - writes an `automation_error` notification through `writeNotification`, keyed `attempt:<N>` on the cumulative attempt count. That gives exactly one notification per permanent failure, and a later permanent failure gets its own.
  - If this transaction fails, it is rolled back and logged, and the original error is still the one raised.
- **Budget rejection:** it counts as permanent on the attempt where it happens. After the error is recorded, the job completes instead of retrying, because the gateway would reject the remaining attempts too.
- **Success:** the finalize step sets `done` and clears `error`. A re-run on a row that is already `done` puts `item_automation` back to `done`; without that, the attempt-start step would leave it stuck at `pending`.

## Budget rejection detection
- The gateway answers a budget rejection with `403` and `code: "budget_exceeded"`.
- The audio client now throws `AudioGatewayBudgetExceededError` for that response.
- `AiGatewayFailedError` gains a `budget_exceeded` reason, which the HTTP completion client now sets for that response.
- Any other `403`, or a body that can't be parsed, is still reported as a plain HTTP failure.

## Store (`itemAutomationStore.ts`)
- `startItemAutomationAttempt`: returns `null` when the row is `locked` or missing.
- `recordItemAutomationFailure`: records a failure without adding to `attempts`; returns `false` when the row is `locked`.
