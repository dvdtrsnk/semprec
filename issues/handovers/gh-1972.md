## What was delivered

A signed-in human session can post to `POST /api/mcp-servers/:id/sync`. The handler runs `syncMcpServerTools(pool, id, { actorId })` inline in the caller's tenant scope and answers 200 `{ toolCount, syncStatus: "ok" }`. Agents, run credentials and `/mcp` have no path to it.

## Entry points and contracts dependents build on

- Route `POST /api/mcp-servers/:id/sync` in `services/semprec-api/src/mcpAgentPageHandler.ts` (new path regex `MCP_SERVER_SYNC_PATH`, `:id` through `assertUuid`, `authenticateRequest`, `runInTenant(identity.tenantId, ...)`). Success: 200 `{ toolCount, syncStatus: "ok" }`.
- `McpConnectionError` maps to 502 `{ error: "Could not connect to the MCP server", reason }`, where `reason` is the typed reason of the error; the error's own message, the HTTP status and any server text are never sent. A tool-list validation failure keeps its 400 `validation_failed`; an unknown id, an id of another tenant and an id of a non-server item answer the same 404 through the unchanged `ChokePointError` mapping. In the connection and validation cases `syncMcpServerTools` has already recorded `syncStatus: error` and `syncError` on the server item. A malformed id answers 400 naming `id`; a method other than POST answers 404 and syncs nothing.
- Route matrix: new slice `routeMatrix/mcpServers.ts` (`MCP_SERVERS_ROUTES`, entry "mcp server sync", `surface: api`, `public: false`, `tenancy: tenant`), spread into `ROUTE_MATRIX` at the end of `routeMatrix.ts`.
- No new table, job name, operation or export; `syncMcpServerTools` is unchanged. The dependents #1976 (queue the same sync after a server card is confirmed) and #1979, #1983 (tool labels and default classification during sync) build on this route and on `syncMcpServerTools`.
