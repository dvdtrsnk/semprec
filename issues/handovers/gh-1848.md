# gh-1848 handover: Recommend the Event for an ambiguous transcript by content

Delivered on the integration branch by the merge of chain `e1-101-semprec-transcribe` (single member gh-1848), candidate `2079c3348dfede5646eee26f9c5d36ef042724c7`, landed in a train with the chains `e1-093-realtime` and `e1-102-library`. The merge was automatic, with no conflict and no migration.

## What was delivered

When a recording overlaps two or more Events, the match step of `semprec-transcribe` asks the model which Event it was and proposes the answer on the transcript card. The step never writes an Event edge itself.

- Gateway: the operation `transcript_event_match` is registered as unattributed (`OPERATION_REQUIRES_PROJECT_ITEM` false), so a call carries `projectItemId: null`; a call with a project item id is refused with 400 `validation_failed`. The call is recorded in `ai_gateway_calls` and counted by the usage report (`byOperation`). The usage-report label belongs to #1477 and was not touched.
- Worker, request and parse (`services/semprec-transcribe/src/eventRecommendation.ts`): `buildEventRecommendationRequest` (temperature 0, notes title, summary and short summary with speaker tokens replaced, each candidate with id, name, date, times, project name and participant names, the user's UI locale) and `parseEventRecommendationContent` (`{ eventId: string | null, reason: string }`, a malformed answer throws).
- Worker, step (`eventRecommendationStep.ts`, `runEventMatch`, the bracketed step 6): a repeatable-read snapshot decides whether a call is due, the gateway call runs outside any transaction, and one locked transaction matches again, creates the card and writes the `eventRecommendation` checkpoint on the source Files item. A failed call or a malformed answer fails the step and the job retries; a transcript that is finished or locked meanwhile gets no card and no checkpoint.
- Data, match (`transcription/transcriptEventMatch.ts`): `matchTranscriptToEvent` keeps its string outcomes and returns `{ outcome: "ambiguous", candidates }` for two or more overlapping Events; it no longer creates the card for them. `createTranscriptEventCard` creates it (relation envelope to the recommended candidate, else the new-Event envelope, complete context, history line, idempotency key `transcript-suggestion:<id>`); `readEventRecommendationContext` reads the candidates with project and participant names, the rendered meeting notes and `users.locale`.
- Card context schema: `transcription/transcriptEventCardContext.ts` (`transcriptEventCardContextSchema`) defines the event-role shape: candidates, `reason` (nullable), `recommendedEventId` (nullable) and the recording facts, with a quote cut by code point.
- ADR `docs/adr/2026-11-13-transcription-recommends-the-event-of-an-ambiguous-recording.md` records the paid call in the match step, the recommendation shaping only a card, the checkpoint as a gate and the unchanged card production sites.

## Entry points and contracts dependents build on

- Gateway operation name `transcript_event_match`, unattributed. Computed key `TRANSCRIPTION_EVENT_RECOMMENDATION_COMPUTED_KEY` (stored key `eventRecommendation`, value `{ recommendedEventId, reason }`), declared, registered in `seedSystem` and exported.
- New exports from `@semprec/data`: `createTranscriptEventCard`, `readEventRecommendationContext`, `TRANSCRIPTION_EVENT_RECOMMENDATION_COMPUTED_KEY` and the types `AmbiguousTranscriptEventMatch`, `EventRecommendation`, `EventRecommendationContext`, `TranscriptEventCandidate`. `publicSurface.test.ts` lists the runtime exports in sorted order.
- Card shape for a client or for #1870: with a recommendation the envelope is `{ entityKind: "relation", target: <Event id>, properties: { propertyKey: "event" } }`, otherwise the new-Event envelope; `context.candidates`, `context.reason`, `context.recommendedEventId` and the recording facts carry the display data. A null `eventId` from the model keeps the model's reason with `recommendedEventId` null; an id that is not a candidate drops the whole answer, so both are null; a blank reason is null.
- The `event` edge is written only by the user's confirmation of the card. `listOverlappingEventIds` stays as a thin exported wrapper over the new internal `listOverlappingEvents`, so the contract of gh-1813 holds.
- The checkpoint is a gate: with the checkpoint present and the card gone (purged from the Trash), a later run makes no call and creates the card without a recommendation.
- No route, table, migration, job name or hook was added.

## Deviations and spec seams

1. The Task says the context schema is the one defined by #1451, but #1451 declared `context` only as an opaque json property, so the event-role shape is defined in the new `transcriptEventCardContext.ts` (not in Touches).
2. `transcriptionTask.ts` had 895 of 900 counted lines (ESLint max-lines), so the step lives in the sibling `eventRecommendationStep.ts` and `runMatchStep` is a thin adapter; no exemption was added.
3. `matchTranscriptToEvent` keeps its string outcomes and adds the `ambiguous` object, so about 70 existing assertions stay valid. The only test edits it caused are the old "two Events overlap" assertions and a type-only change of the match helper in `transcriptTrashedEventEdge.test.ts`.
4. Barrel exports go beyond the computed key (the card creator, the context reader and four types) because the worker needs them.
5. `createTranscriptEventCard` reads `durationSeconds` and `segments` from the transcript's computed values (NotFoundError when missing) and throws ConflictError when the card already exists.
6. A transcript with no speech and two overlapping Events still pays one call; the Task carves out only zero or one candidate. A concurrent second run that took its snapshot before the first committed may pay again; the ADR records this as accepted and the locked transaction leaves one card.
7. The choke point gives every Event a default `timeTo`, so a candidate's `timeTo` is null only for an Event stored before that rule; a test builds one with raw SQL.
8. The worker's commit trailer names Claude Sonnet 5.5 instead of the model the prompt names.
