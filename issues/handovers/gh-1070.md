## What changed

- **Sandbox user:** `provision.sh` creates `semprec-mcp` once, before `apply_nftables`. It has its own group and is not in `semprec`. `jq` is added to the package list.
- **Launcher** (`deploy/bin/semprec-mcp-launch`, installed `0755` to `/usr/local/libexec/`):
  - reads one header line and never consumes a byte after its newline;
  - checks the header with `jq`, then `exec`s the command with exactly the base environment plus the header's `env`;
  - on any refusal it exits 64, runs nothing, and never prints the header.

  Two `jq` traps are handled: on jq 1.6, `contains("\^@")` is true for every string, and `$` also matches before a trailing newline. A raw NUL byte, which bash `read` would silently drop, is refused too.
- **systemd:**
  - new `semprec-mcp-launch.socket` and `semprec-mcp-launch@.service` units;
  - `provision.sh` installs and verifies both, and enables the socket;
  - the api and agents units gain `Wants=`, `After=` and the `SEMPREC_MCP_LAUNCH_SOCKET` variable.
- **Egress:** a new `semprec_mcp_egress` chain in `nftables.conf` accepts replies and DNS, then logs and rejects both blocked address sets. It has no loopback exception.
- **Client transport:** `SandboxedStdioClientTransport` connects to the socket and sends the header. Afterwards nothing it holds still contains the header with the credential. `close()` waits at most 2 s before destroying the socket.
- **Factory:** after #1033's spawn-time check:
  - if the socket variable is set, it uses the socket;
  - otherwise, under `NODE_ENV=test`, it keeps the in-process spawn;
  - otherwise it refuses with the new reason `stdio_sandbox_unavailable`, before the credential is decrypted.
- **Docs:** a "stdio MCP sandbox" section at the end of `deploy/README.md`, and the ADR `docs/adr/2026-10-17-stdio-mcp-servers-run-in-a-socket-activated-sandbox.md`.

## Decisions and deviations

- **Header size limit:** the line may hold 65536 bytes before its newline. Exactly 65536 is accepted, 65537 is refused.
- **Test-only paths:** the sandbox home and the launcher install path are `readonly` constants that the shell tests rewrite with `sed`, as `provision.test.sh` already does for its other paths.
- **Extra README checks:** besides the commands the issue lists, the host check also has a `systemctl status` line for the socket and a `journalctl` check for denials.
- **Local development:** any process outside tests that has no socket, including local development, now refuses `stdio` connects. This follows from the Task, and the ADR records it.
