## Summary

Implements issue #141: per-platform session token delivery and the native WKWebView bridge contract.

- **Web logins** (`platform: "web"`) now deliver the token only via an `httpOnly`, `Secure`, `SameSite=Lax` cookie — the JSON response body no longer contains it at all.
- **iOS/macOS logins** return the token in the JSON body (for Keychain storage) and set no cookie.
- `authenticateRequest` now tracks which channel (cookie vs. `Authorization: Bearer`) supplied a token and rejects it with the same generic 401 if that channel doesn't match the session's declared platform — a web session can't be replayed as a bearer token, and a native session can't be presented as a cookie.
- Defines the native shell bridge contract (`NATIVE_SESSION_BRIDGE_HANDLER_NAME`, `NativeSessionBridgeReply` in `@semprec/data`, expanded in `apple/auth-bridge.md`) describing how the future native iOS/macOS app and the embedded web editor should use `WKScriptMessageHandlerWithReply` so the embedded editor reuses the native session instead of calling `/api/auth/login` itself. Neither the Swift app nor the web-side consumer exists yet, so this ships the contract both will implement against.
