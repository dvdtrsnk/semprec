# Handover for gh-1377

`recordRestoreTestResult` now stores `ranAt` (ISO 8601 UTC) in the `detail` of the `backup:restoreTest` check for both passed and failed runs, and `readRestoreTestOutcome` reads it back. No migration and no change to the restore-test script.

**What changed in `restoreTestResult.ts`**
- `ranAt` is parsed from the run id (`YYYYMMDDTHHMMSSZ-<pid>`). A run id that does not match, or encodes an impossible calendar time, falls back to the recording time.
- `readRestoreTestOutcome(detail, status)` returns `{ lastTestAt, ok }`. `lastTestAt` comes from `detail.ranAt`, else from `detail.runId`, else `null`. `ok` is true when the status is `ok`. It never returns `failedCheck`.

**Tests**
- `restoreTestResult.test.ts` gains cases for a passed run storing `ranAt` and a second run updating it while `changed_at` stays, a failed run with `ok: false` and no `failedCheck`, a legacy row with only `runId`, and an unparsable or impossible run id falling back to the recording time.
- Two existing `detail` assertions became `toMatchObject` because `detail` now also carries `ranAt`.

**Notes for dependants (#1561)**
- Call `readRestoreTestOutcome(row.detail, row.status)` on the global `backup:restoreTest` row and serve only `lastTestAt` and `ok`.
- `detail.failedCheck` stays operator-only.
