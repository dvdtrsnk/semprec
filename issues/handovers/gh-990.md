## Changes
- **`mailLiveSyncRoot.ts`**:
  - The signature is now `createMailLiveSyncRoot(pool, lifecycleFactory, options)`.
  - `reconcileOnce()` runs inside `runAsSystem("mail:liveSync", …)`. The discovery interval inherits that scope.
  - Discovery calls `forEachActiveTenant`. In each tenant's scope it resolves that tenant's Mailboxes database in the first page's transaction, then pages `listItems` and seeds each account under its own `SAVEPOINT`, as before.
  - A tenant's failure is reported as `("*", "discover", err)` and the tenant is recorded as failed. It does not abort the pass or trigger the helper's rethrow. A failure of the tenant enumeration itself still rejects `reconcileOnce`.
  - `HostedEntry` carries `tenantId`. `lifecycle.start()` and `lifecycle.stop()` run in `runInTenant(entry.tenantId, …)`. The per-account heartbeat starts after `start()` resolves, in the root's system scope.
  - After a pass, hosted entries whose account was not discovered are stopped, unless their tenant is in the failed set. A tenant that is no longer active is not enumerated, so its lifecycles stop on the next pass. Docstrings are rewritten.
- **`processHeartbeats.ts`**: each tick's UPSERT runs in `runAsSystem("processHeartbeat", …)`. A synchronous throw from entering the scope reaches `onError` and does not escape the timer callback.
- **`serve.ts`**: removed the boot-time Mailboxes id and the two imports only it used, and updated the comment.

## Tests
- **`mailLiveSyncRoot.test.ts`** and **`mailLiveSyncComposition.test.ts`** use the new signature.
  - The rollback-failure case now expects `reconcileOnce()` to resolve and adds the `("*", "discover", rollbackErr)` report.
  - The interval connect counts are now 2 and the page-discovery count is 4.
- **`mailLiveSyncRootPerTenant.test.ts`** (new, two-tenant runtime-role harness) covers every acceptance case:
  - per-tenant hosting scope, `tenant_id` on the sync state, and the job envelope's `tenantId`;
  - failure isolation for a tenant with no mail databases;
  - a failed tenant keeping its lifecycles and not restarting after repair;
  - deactivation stopping the lifecycle in B's scope and stopping its heartbeat;
  - heartbeat ticks under strict mode.

## Test adjustments beyond the issue
- In the interval tests, the connect count is now read after `root.stop()`. The enumeration's query does real I/O, so reading it right after `advanceTimersByTimeAsync` was racy.
- In the "resets the started guard" test, the injected first connect failure now hits the tenant enumeration's callback-style `pool.query()` connect, so it invokes the callback with the error. Otherwise the test would hang.
- Tenant B's fixture mailbox is created with empty properties, because that tenant's Mailboxes database has no property definitions.
