## What was delivered

- ADR `docs/adr/2026-11-12-per-database-agent-grants.md` (accepted, backend): the decision, the rejected gateway pre-check and the rejected per-database capability ids, the exception for the purge cleanup in `itemTrash.ts` (the decision row belongs to the choke point's own authorization check; `agentGrants/` is deliberately not a domain folder of the two dependency-cruiser rules), and the list of paths that are not yet filtered.
- Migration `0154_agent_database_grants.sql`: tenant table `agent_database_grants` (PK `(tenant_id, project_item_id, database_id)`, `access` in `none | read | write`, composite tenant foreign key `agent_database_grants_database_fkey` to `databases`, restrictive `tenant_isolation` policy, grants as `project_mcp_grants`, tenancy comment). Additive; `project_item_id` has no foreign key because `items` is partitioned.
- `agentGrants/agentDatabaseGrantsStore.ts`: `getAccess`, `parseAgentDatabaseAccess`, `deleteAgentDatabaseGrantsForProject` (purge cleanup). `agentGrants/agentDatabaseGrantsAdminStore.ts`: `setAgentDatabaseGrant`, `removeAgentDatabaseGrant`, not in the barrel and not re-exported from `testSupport`.
- `agentGrants/agentDatabaseAccess.ts`: `assertAgentDatabaseAccess(client, { agentProjectItemId, databaseId, access })` reads the database row and the decision in one statement and locks the decision row `FOR SHARE`, so a revoke waits for the write's transaction; `assertWriterDatabaseAccess(client, writer, databaseId, access)` (no-op for a writer without `agentProjectItemId`: a person, the system, an `/mcp` call on a human session); `listUnreadableDatabaseIds(client, agentProjectItemId)`. The decision: a sensitive database is `none` without a row, a user-created database is `write` without a row, a non-sensitive system database is always open; `write` includes `read`; the refusal is a `ForbiddenError` (`forbidden`) naming the database id and the required access only.
- Enforcement in the transaction of the guarded operation: item get and list (`findItem`, `getItem`, `listItems`), `database.query`, `view.query` (a curated view drops items of unreadable databases from the page, the cursor and `totalCount`, also for `inTrash`), `relation.list`, item create (also the idempotent replay), patch, delete and restore (cascade databases too), relation put, update, set and delete (both endpoint databases), `link.relink` and `link.unlink` (write access right after the item lookup), and the destructive-operation projection for `item.delete`, `relation.delete` and `link.unlink` (refused at request time with no approval request; a revoked grant ends an approved request as a conflict). `item.delete` projection checks every cascade database (`itemSubtreeAccess.ts`).
- Hiding: `database.get` of an unreadable database is forbidden; `database.list` and `generateSchemaProjection` (new option `agentProjectItemId`, wired in `semprec-agents` `agentSessionComposition.ts`) omit it; a relation target in an unreadable database comes back as `{ id, hidden: true }` (top level and inside a projected relation property), and `relation.list` returns `{ relationPropertyId, propertyKey, targetItemId, hidden: true }` for such a target, with no `targetDatabaseId` and no edge metadata.
- Purge of a Projects item deletes its grants in `deleteItemDependents`.
