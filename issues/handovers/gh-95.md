## Summary

- Add `email.draft.create` (`mail/draft.ts`): the generic item-create path for an Email draft, AI-callable with no authorization check ("drafting is safe for agents").
- Add `email.send` (`mail/send.ts`): checks authorization *before* any SMTP call or draft mutation — a `user` actor always may send; an `ai_agent` actor may only send if the Email project's generated permission manifest carries `capabilities.email.send.autonomous`, else 403 with the draft left completely unchanged and no approval-queue row created. Guards against a retried/duplicated call re-sending an already-sent draft.
- On authorized send: submits over SMTP (`mail/smtpClient.ts`, `NodemailerSmtpClient`, mirroring `ImapFlowMailClient`'s "wrap an already-authenticated transport" shape) exactly once, then finalizes the existing draft item into the mailbox's Sent folder and generates/stores its Message-ID via `mail_message_meta` — reusing `ingestEmailMessage`'s existing `message_id`-keyed dedup so a later IMAP/Gmail/Graph sync pass that observes the same Message-ID in the real Sent folder converges onto the same item instead of duplicating it.
- `capabilities.email.send.autonomous` is sourced from a new `Projects.emailSendAutonomous` property (`owner:'system'`, no declared writer anywhere in the code — granting it is a deliberate direct-DB-access action, not something reachable through any generic/agent-writable path), surfaced through `generatePermissionManifest`.
