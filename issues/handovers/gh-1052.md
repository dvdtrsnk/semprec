## Narrow `/api/system-health` to the caller's tenant (#1052)

The per-user health report now contains only the caller's tenant. The response keys and types are unchanged. The operator report (`getOperatorHealthReport`) is untouched.

**What changed in `systemHealthReport.ts`**
- `getSystemHealthReport` first asserts an active tenant scope and throws if there is none, so a wiring bug surfaces as a 500 rather than an empty-looking report.
- `processes` holds only the caller's mailbox processes (`getActiveMailSyncProcessNames`). The four fixed processes are gone.
- `alertingChecks` reads only the caller's `tenant_observability_checks` rows. The `observability_checks` half of the `UNION ALL` is dropped.
- `queue` counts only jobs whose envelope `tenantId` is the caller's. The operator report keeps its global counts through a `tenantOnly` flag.
- `itemAutomationErrorsByDatabase` and `agentRunErrors7d` gain an explicit `tenant_id = app_current_tenant()` predicate as a second guard on top of RLS.
- `mailboxes` is unchanged and still relies on RLS.
- Docstrings in the report, the route handler and the manifest comment now describe a per-tenant snapshot.
