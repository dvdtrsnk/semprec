# Handover for gh-1568

Idle thread sessions are closed as `done` (shutdown and startup repair), and a failed or cancelled turn pairs its dangling tool calls at once. Committed locally on `wf/gh-1568-n2`; not pushed. Targeted checks run: prettier, eslint, `tsc` for `agent-runtime` and `semprec-agents`, the `shutdown` unit test and the `startupRepair*`, `lifecycleAdapter*`, `sempConversation` and `startupRepairComposition` integration tests. The full `pnpm run verify` was not run.

**What changed**
- `danglingToolCalls.ts` (new, agent-runtime): `findDanglingToolUses(events)` returns every `tool_use` payload without a `tool_result` (paired by `toolCallId`; ids-less calls by order), and `syntheticToolResult(toolUse, text)` builds the regular #1374 error result shape. Startup repair now pairs every dangling call of a run, not only a trailing one.
- `startupRepair.ts`: an idle thread session (`threadId` set, `triggeredBy: 'user'`, last event `turn_end`) is closed as `done` with a `run_status` event and no `agent_run_error`. A mid-turn session is still closed as `error` with its notification. `repairInterruptedRuns` now returns `{ repairedRunIds, closedIdleRunIds }`; `closedIdleRunIds` holds the idle sessions. New export `closeIdleThreadSessions(pool)` runs the same close for every active tenant and returns `{ closedRunIds }`.
- `lifecycleAdapter.ts`: new `pairDanglingToolCalls(client, runId, failure)`, called before the error close by `runAgentSessionForRun` and by `SempConversation`'s `failRun`. The synthetic text says the turn was `cancelled` or `failed`. A failure to pair is logged and never replaces the turn's own error.
- `services/semprec-agents`: `createGracefulShutdown` takes a required `closeIdleThreadSessions` option, called after the queue stopped and before the pool ends (a failure is logged and does not block `pool.end()`); `serve.ts` passes the agent-runtime function.

**Notes for dependants**
- `delegationRegistry.ts` has its own `failRun`; it was not changed (delegated runs are not woken threads). Call `pairDanglingToolCalls` there if that is wanted.
- No production code opens thread sessions yet (#1727), so the shutdown sweep finds nothing until that lands.
- #1732 can use `closedIdleRunIds`/`closedRunIds` to tell clean closes from interrupted turns.
