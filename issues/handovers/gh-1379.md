# Handover for gh-1379

Added the accepted ADR `docs/adr/2026-10-25-undoing-a-confirmed-proposal-reverses-its-recorded-writes.md`. It is documentation only; no code, schema or test changed. No existing ADR body was edited; the ADR narrows the "a confirmed or rejected card never changes again" rule by naming the reopen routes as the only exit from `confirmed`.

**What the ADR records**
- **Mechanism:** a confirmed card is reopened in one transaction, driven by the per-step results and origin rows recorded at confirm; the card returns to `proposed` with its original effective envelope and history gains a `reopened` entry.
- **Reversal rules:** created items are soft-deleted; a file moved into Files stays there and is named in the undo result; relation edges between pre-existing items are deleted for good; patched items get their previous values back; inserted page blocks are removed by ids derived from the proposal; a stored MCP credential is deleted.
- **Precondition:** every created or changed item must still have the `updatedAt` stored in the card's results, otherwise 409 `version_conflict` naming the changed item and nothing is overwritten.
- **Follow-ups:** queued jobs started by a confirmation are cancelled and their output removed (#1984).
- **Limits:** no time limit; approval requests are outside the mechanism and the exactly-once decision is unchanged.
- **Rejected:** forbid undo; undo only before follow-ups; a time window.

**Tests:** none apply.

**Notes for dependants**
- #1943 implements the undo and must follow this contract literally; #1984 owns job cancellation; #1937 owns reopening a rejected card.
