## What was delivered

- The tenant table `transcript_action_item_states`, migration `backend/packages/data/src/db/migrations/0148_transcript_action_item_states.sql`: `tenant_id uuid NOT NULL DEFAULT app_tenant_default() REFERENCES tenants(id)`, `transcript_item_id uuid NOT NULL`, `action_item_id integer NOT NULL CHECK (action_item_id >= 0)`, `state text NOT NULL CHECK (state IN ('added','noted','dismissed'))`, `task_item_id uuid NULL`, `owner_person_id uuid NULL`, `updated_at timestamptz NOT NULL DEFAULT now()`, primary key `(tenant_id, transcript_item_id, action_item_id)`. Table comment `semprec:tenancy=tenant`, row-level security with the restrictive `tenant_isolation` and the permissive `tenant_rows` policy. Grants: `SELECT, INSERT, UPDATE, DELETE` to `semprec_data`, `SELECT` to `semprec_side`. An open action item has no row. `action_item_id` is the item's position in the stored `computed.meetingNotes.actionItems` array.
- The store `backend/packages/data/src/transcription/transcriptActionItemStates.ts`:
  - `listActionItemStates(client, transcriptId): Promise<TranscriptActionItemStateRow[]>`, ordered by action item id.
  - `setActionItemState(client, input: SetActionItemStateInput): Promise<TranscriptActionItemStateRow>`, an upsert that returns the stored row. A row that already holds the same state, task and owner is left untouched, `updated_at` included.
  - `clearActionItemState(client, transcriptId, actionItemId): Promise<void>`. The row must exist (`requireAffectedRows`).
  - Both writers lock the transcript's item row first (`itemsStore.lockItemById`) and throw `NotFoundError` when the row does not exist.
- The route `PUT /api/transcripts/:id/action-items/:actionItemId/state` with body `{ state: "noted" | null }`, handler `createTranscriptActionItemStateRouteHandler(pool)` in `backend/packages/data/src/transcription/transcriptionRouteHandlers.ts`, a custom route of the systemDatabases module (`setTranscriptActionItemState`, justification `transactional-semantics`). One transaction locks the transcript's item row, reads the notes and the stored state, and writes.
  - `noted` stores the row with `owner_person_id` set to the live person the transcript's `speakers` edges map the item's `ownerSpeaker` to, or NULL. `task_item_id` is NULL.
  - `null` deletes the row; for an open item it writes nothing.
  - Answer 200 `{ actionItemId, state }`, `state` being `"noted"` or `null`.
- The permanent purge deletes a purged item's rows: one inline statement in `deleteItemDependents` (`backend/packages/data/src/chokePoint/itemTrash.ts`), `DELETE FROM transcript_action_item_states WHERE tenant_id = app_tenant_default() AND transcript_item_id = $1`. Its fingerprint `packages/data/src/chokePoint/itemTrash.ts::3b153099e2ec` is one new line of `.github/scripts/write-safety-baseline.json`.
- The route matrix entry `{ name: "transcript action item state", method: "PUT", path: "/api/transcripts/<EXAMPLE_ID>/action-items/0/state", surface: "api", public: false, tenancy: "tenant" }` in `backend/services/semprec-api/src/routeMatrix/transcripts.ts`, its `ROUTE_CASES` case in `tenantIsolationRoutes.test.ts` and its `ROUTE_HANDLER_FILES` mapping to `packages/data/src/transcription/transcriptionRouteHandlers.ts`, all in the same merge.
- The ADR `docs/adr/2026-11-11-transcript-action-item-states-serialize-on-the-transcript-row.md` (accepted, area backend): the side table, the transcript row lock as the lock of every state of that transcript, and the inline purge delete.

## Contracts dependents build on

gh-1756 names this source as a `Shared-file ordering` blocker only. gh-1767 (task creation from an action item, the state in the transcript detail endpoint) builds on the table and the store; it declares gh-1765 as its blocker, not this source.

- Answers of the route:
  - 200 `{ actionItemId, state }`. A second identical call answers the same and rewrites nothing; a repeated `noted` rewrites the row only when the owner it resolves differs from the stored one.
  - 400 `validation_failed` with `details.field`: `id` for a non-UUID transcript id; `actionItemId` for anything but a canonical decimal from 0 to 2147483647 (`-1`, `01`, `1.5`, `1e2`, the empty string and `2147483648` are refused); `state` for a body whose `state` is neither `"noted"` nor `null`. All three are checked before any database read.
  - 400 `validation_failed` with `details { field: "state", reason: "alreadyAdded" }` for `noted` and for `null` on an item whose stored state is `added`. Undoing an added item belongs to gh-1767.
  - 404 `not_found` with `details { resource: "transcriptActionItem", transcriptId, actionItemId }`, the same for an unknown transcript id, another tenant's id, a transcript in the Trash, a tenant without a Transcripts database, a transcript without meeting notes and an `actionItemId` the notes do not have.
  - 401 without a session, with `Cache-Control: no-store` (`routeMatrix.test.ts` and `cacheControl.test.ts`, by the matrix name).
- The lock rule of the ADR. The row lock of the transcript's item is the lock for every state of that transcript. A later writer of this table, the task creation of gh-1767 included, takes it before it reads the notes or the stored state, in the same transaction, and writes through the store. Taking the lock a second time in one transaction does not wait. A caller that locks further items in that transaction decides their order itself.
- `setActionItemState` accepts all three states and a `taskItemId`. This source passes `noted` and `taskItemId: null` only. It does not check that the notes have an item at `actionItemId`; the caller does. `added` has no production writer yet (gh-1767); `dismissed` has none and is reserved.
- `task_item_id` and `owner_person_id` are plain ids without a foreign key. A purge of the task or the person a row names leaves that id in the row; a reader resolves the id and treats an item it does not find as absent.
- A state write changes no item, bumps no item version and sends no realtime invalidation. No route returns the states: the read in the transcript detail endpoint belongs to gh-1767.
- A transcript in the Trash keeps its rows; only the permanent purge removes them. The tenant export and the tenant erase select their tables by the tenancy comment, so both cover this table (the reviewers read `tenantExportJob.ts` and `tenantPurgeJob.ts`). `tenantExport.test.ts` and `tenantPurge.test.ts` pass on the merged tree, but no test of the export or the erase names this table.
- Exports: `listActionItemStates`, `setActionItemState`, `clearActionItemState` and the types `TranscriptActionItemState`, `TranscriptActionItemStateRow`, `SetActionItemStateInput` from `transcription/transcriptActionItemStates.ts`. The handler is re-exported from `seed/systemDatabasesModuleManifest.ts` only. Nothing was added to the `@semprec/data` barrel; `publicSurface.test.ts` is unchanged. The manifest version is unchanged.
- Inventories a later tenant table must update again: `TENANT_TABLES` of `tenancyCatalog.test.ts`, the pinned count of tenant-classified tables in `rowLevelSecurity.test.ts` (now 65), and `READ_ONLY_FOR_SIDE_TABLES` of `leastPrivilegeRoles.test.ts` (this table is in it, because `semprec_side` has `SELECT` only). ## Deviations from the specification and spec seams

1. Spec seam: the route entry is in the slice module `backend/services/semprec-api/src/routeMatrix/transcripts.ts`, not in `routeMatrix.ts`.
2. Spec seam: the Task asks for a case and a "request list" entry in `tenantIsolationRoutes.test.ts`. No `ownerProbes()` entry was added. The shared fixture transcript of tenant A has no meeting notes, so A's own request would answer the same 404 as a random id. The case seeds its own transcripts with notes for A and B and carries the positive control itself (A's and B's own follow answer 200).
3. The purge delete is one inline statement in `deleteItemDependents`, as the Task says, not a call into the store: the boundary rule `item-trash-domain-imports-are-purge-only` refuses a new transcription import in `itemTrash.ts`. The statement adds `tenant_id = app_tenant_default()` to the Task's `WHERE transcript_item_id = $1` (the primary key prefix; the same rows under row-level security).
4. Outside `Touches`: one line of `.github/scripts/write-safety-baseline.json` for that delete (a sweep where zero affected rows is the usual outcome); the three inventory tests the new tenant table requires; one test in `purgeExpiredTrash.test.ts` (Task step 2); the ADR.
5. The route handler locks the transcript row itself before its guard reads, and the store writers lock it again in the same transaction. The Task places the lock in the writers only, which would leave the `added` guard reading outside the lock.
6. `setActionItemState` returns the stored row and does not rewrite an identical row. Its input carries `taskItemId` (the table's column; this source passes NULL).
7. `clearActionItemState` requires the row to exist; the route skips the delete for an open item.
8. The 404 details are `{ resource: "transcriptActionItem", transcriptId, actionItemId }` for all cases. `actionItemId` must be a canonical decimal from 0 to 2147483647.
9. The handler is re-exported from the manifest module only, not from `packages/data/src/index.ts`; the manifest version is unchanged.
10. A state write sends no realtime invalidation and no route returns the states.
