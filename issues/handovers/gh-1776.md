## What was delivered

- The module `sleep` (`backend/packages/data/src/sleep/sleepModuleManifest.ts`): `id: "sleep"`, `version: "1.0.0"`, `name: "Sleep"`, `removable: false`, `systemProject: true`, no capabilities and no agent tools. It declares three databases as `{ key, name }` without `overviewOrder` or `switcherOrder`: `sleepSettings` ("Sleep settings"), `sleepPlans` ("Sleep plans"), `sleepNights` ("Sleep nights").
- Catalogs `backend/packages/data/src/sleep/i18n/cs.json` and `en.json`, 36 keys each with identical key sets: `database.<key>.name`, `property.<key>.<property>.name`, `property.sleepSettings.alarmSound.option.<morning|birds|piano|vibrateOnly>`, `property.sleepPlans.wakeDays.option.<mon..sun>`, and the seeded plan names `seed.sleepPlans.weekdays.name` ("Pracovní dny" / "Weekdays") and `seed.sleepPlans.weekend.name` ("Víkend" / "Weekend").
- The database keys in `backend/packages/data/src/seed/sleepModuleKeys.ts`: `SLEEP_SETTINGS_MODULE_ID = "sleepSettings"`, `SLEEP_PLANS_MODULE_ID = "sleepPlans"`, `SLEEP_NIGHTS_MODULE_ID = "sleepNights"`.
- The seed `seedSleepModuleInTransaction(client, projectsDatabaseId, viewTypeRegistry)` (`backend/packages/data/src/seed/seedSleepModule.ts`), which `seedSystem` calls once for a new tenant, after the calendars and recipes seeds. In the caller's transaction it:
  - inserts the system project item `Sleep` into Projects (`systemActive: true`, no `agents` text);
  - creates the three databases with `name: null`, `key = ownerModuleId`, `system: true`, owned by that project, each with its properties (every property `name: null`, the label comes from the catalog) and one default `table` view named after the manifest database name;
  - sets `schema_locked` on the three, one checked `UPDATE` per database;
  - inserts one settings item and two plans. No night item is seeded.
- Registration: `sleep` in `ALL_MODULE_IDS` and `MANIFEST_PATHS` of `manifest/fullModuleRegistry.ts`; the barrel export `sleepModuleManifest`; `sleep` in the domain lists of the rules `chokepoint-knows-no-domain` and `item-trash-domain-imports-are-purge-only` in `backend/dependency-cruiser.rules.json`; a copy step for `src/sleep/i18n` in the build script of `backend/packages/data/package.json`.
- No migration, route, generic operation, job name, write hook, tenant cutover entry, agent tool or ADR was added.

## Contracts dependents build on

- Runtime export of `@semprec/data` added by this source: `sleepModuleManifest` (in the expected list of `publicSurface.test.ts`). `seedSleepModuleInTransaction`, the three `SLEEP_*_MODULE_ID` constants and `SLEEP_DATABASE_DESCRIPTORS` are not exported from the barrel; code inside the package imports them from their files.
- Database keys and properties (canonical English camelCase keys, all owner `user` unless stated):
  - `sleepSettings`: `name` (title); `enabled`, `prepReminder`, `muteSemp`, `alarmSnooze`, `showInCalendar` (checkbox); `goalMinutes`, `prepReminderMinutes` (number); `alarmSound` (select: `morning`, `birds`, `piano`, `vibrateOnly`); `systemActive` (checkbox, owner `system`, locked, no `owner_process`).
  - `sleepPlans`: `name` (title); `wakeDays` (multi_select: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`); `bedTime`, `wakeTime` (time); `alarm` (checkbox); `position` (number).
  - `sleepNights`: `night` (date, the calendar day of the evening, `YYYY-MM-DD`); `bedTime`, `wakeTime` (time); `alarm` (checkbox). An unset value means "follow the plan".
- Seeded items of a new tenant:
  - one settings item: `enabled`, `prepReminder`, `muteSemp`, `alarmSnooze`, `showInCalendar` true, `goalMinutes` 480, `prepReminderMinutes` 30, `alarmSound` `morning`, `systemActive` true, no `name` value;
  - plan `weekdays`: `wakeDays` mon to fri, `bedTime` 23:00, `wakeTime` 06:45, `alarm` true, `position` 0;
  - plan `weekend`: `wakeDays` sat and sun, `bedTime` 00:00, `wakeTime` 08:30, `alarm` false, `position` 1.
- **Plan names are user data.** They are taken from the catalog at seed time in the tenant user's `users.locale` (`cs` when the tenant has no user yet) and stored as plain titles. A later change of the locale does not rename them; the schema labels do follow the locale.
- **The settings item cannot be deleted.** `DELETE /api/items/:id` answers 403 with `details.field: "systemActive"` through the existing guard of `chokePoint/itemTrash.ts`, and a user write of `systemActive` is refused. Plans and nights go to the trash normally. Nothing yet keeps the settings item unique or validates values; that is gh-1784 and gh-1799.
- **The three databases are in neither client list.** They resolve `clientVisible: false`, `overviewOrder: null`, `switcherOrder: null` and, since gh-2002, `overviewHidden: false`. `GET /api/databases` and `GET /api/databases/:id` return them as locked system databases with those values; the worker reports that the list has them in its name-sorted tail.
- **Existing tenants do not get the module.** `seedSystem` returns early for a seeded tenant. The module is active for every tenant through the registry, but a tenant seeded before this source has no sleep database, no Sleep project and no settings item until gh-1779 delivers them. The rules reviewer checked by reading that the readers of `registry.getDatabases()` look descriptors up by the key of rows that exist, so such a tenant's reads do not fail. No test of this source targets that state.
- The Sleep project has no `agents` text and no entry in `SYSTEM_PROJECT_AGENT_GUIDANCE_SEED_TEXTS`, so account creation writes no guidance row and no drift heartbeat for it, like the Calendar project. The guidance row counts of existing tests are unchanged.
- `sleepSettings.systemActive` has no `owner_process`, so the daily core drift check (`findOrphanedOwnerProcessProperties`) lists it, as it lists other system-owned properties without an owner process (for example `books.cover`). `KNOWN_OWNER_PROCESS_IDS` is unchanged.
- Mirrored lists that the next module or barrel export will meet: the module lists of `moduleRegistryLoadAll.unit.test.ts`, `coreModuleManifests.unit.test.ts` and `systemI18nCatalogCoverage.test.ts`, the system database key list of `smoke.test.ts` and the export list of `publicSurface.test.ts` now contain sleep. A chain that lands another module in between conflicts there; both sides are kept.

## Deviations from the specification and spec seams

1. The HTTP criteria (`GET /api/databases`, `DELETE /api/items/:id`, `GET /api/schema`) are tested in `services/semprec-api/src/__tests__/sleepModule.test.ts`, outside the folder `Touches` names, because semprec-api serves the routes.
2. `packages/data/package.json` is outside `Touches`: without the copy step the built package has no sleep catalog and the seed would store the raw key as the plan name.
3. `sleep` is added to `chokepoint-knows-no-domain` as the Task says and also to `item-trash-domain-imports-are-purge-only`, whose domain list mirrors the first by the rule's own comment.
4. The catalogs also carry `property.sleepPlans.wakeDays.option.mon..sun`, which the Task does not list; `systemI18nCatalogCoverage.test.ts` requires a label for every seeded option.
5. The Sleep project item has no `agents` text. The Context says the pattern creates one; the Task names none and the Decisions say the project carries its agent text later.
6. Values the Task leaves open: the manifest database names "Sleep settings", "Sleep plans", "Sleep nights" (also the names of the default views); all Czech and English labels; the project item name is the literal `Sleep` and is not localized; the settings item has no `name` value; the seed function takes exactly `(client, projectsDatabaseId, viewTypeRegistry)`.
7. The seed is called after the recipes seed, which follows the calendars seed; the Task says "after the calendars seed".
8. The seed is not idempotent on its own; its docstring says so. `seedSystem` calls it once behind its already-seeded guard. The model tier rationale of the record says the work "must be idempotent", but no Task step and no criterion asks for it; gh-1779 has to bring its own guard for existing tenants.
9. `publicSurface.test.ts` and four mirrored module lists in existing tests are outside `Touches`; the registration requires them.
10. Since the second fix round the two tests of the criterion on `GET /api/databases` also state `overviewHidden: false`, the field of gh-2002. The record of gh-1776 does not name it.
