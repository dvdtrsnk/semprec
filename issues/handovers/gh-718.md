## Changes

- **`web/src/api/authOperations.ts`** (new): `sessionUserSchema`, `SessionUser` and `createAuthOperations({ baseUrl, fetchImpl? })`, which returns:
  - `login()`: sends `POST /auth/login` with `{ email, password, platform: "web" }` and same-origin credentials. A 401 throws `OperationError("unavailable", …, 401)`. Other non-OK statuses throw `retryable` with the server's `{ error }` message. Network and parse failures are also `retryable`.
  - `getSession()`: a 401 resolves `null`; any other failure throws `retryable`.
  - `logout()`: 200 and 401 both resolve; anything else throws `retryable`.
  - It never reads or stores the token, because the cookie is `HttpOnly`. `readErrorMessage` is copied from `setupOperations.ts` rather than imported, as the issue asks.
- **`web/src/api/sessionFetch.ts`** (new): `createSessionFetch(onUnauthorized, fetchImpl)` calls `onUnauthorized()` on a 401 and returns the response unchanged.
- **`web/src/views/login/LoginPage.tsx` + `login.css`** (new): email and password form.
  - While a login is in flight, the fields and button are disabled and the button reads `login.submitting`.
  - A 401 shows `login.error.invalid` in a `role="alert"` paragraph and keeps the form usable.
  - Any other failure shows `login.error.failed` with the message.
  - Success calls `onLoggedIn(user)`.
- **`web/src/App.tsx`**: new props `auth`, `sessionEvents` and `login?: true`. A `SessionGate` holds the state `loading | anonymous | authenticated | failed`:
  - On load it calls `getSession()`. A failure shows `ErrorState` with a retry that runs the check again.
  - An `"unauthorized"` event while signed in switches to the login page.
  - When signed in, it renders an `app-header` with "Signed in as {email}" and a "Sign out" button. A rejected logout keeps the session and shows `login.logoutFailed` in a `role="alert"` element.
  - A signed-in user on `?page=login` is sent to `/` with `window.location.replace("/")`.
  - The setup route renders `SetupWizard` exactly as before, with no header, and never calls `getSession()`.
  - The existing route switch moved unchanged into a `RoutedContent` component.
- **`web/src/main.tsx`**:
  - Creates `sessionEvents` and one session-aware `fetchImpl`, and passes it to the generic, AI usage, system health, MCP agent page, approval queue and agent run adapters.
  - Auth and setup keep the plain `fetch`, so a failed login's 401 does not bounce the app.
  - Routes `?page=login`.
  - Removes the stale comment about a dev-proxy bearer secret and replaces the "no auth/current-user concept" docblock sentence with one describing the session bootstrap. The `?page=approvals&user=` sentence is left for G7.
- **`web/src/i18n/messages.ts`**: the `login.*` keys in both `en` and `cs`.
- **`web/src/styles/app.css`**: `.app-header` rules only.
