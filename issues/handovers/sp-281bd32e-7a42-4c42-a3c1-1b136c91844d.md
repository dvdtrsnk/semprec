# Handover: calendar scopes and consent for OAuth accounts

Implementation commit `4edf22849` on `feat/ia-oauth` (from `feat/internet-accounts`).

**What changed.**
- Scopes per service live in `mail/oauthServiceScopes.ts` (`PROVIDER_SETTINGS` no longer holds scopes). Mail: Gmail `gmail.modify`, `gmail.send`; Microsoft `Mail.ReadWrite`, `Mail.Send`, `offline_access`, `User.Read`. Calendars adds `https://www.googleapis.com/auth/calendar` / `Calendars.ReadWrite`. The mail scopes are part of every sign-in (identity lookup; the one stored credential keeps serving mail sync).
- Baseline (edited in place): `mail_oauth_states.services text[] NOT NULL` (non-empty subset of `mail`, `calendars`), `mail_oauth_states.redirect_target text` (`NULL` or `app`), index `mail_oauth_states_state_hash_idx`, `mail_account_sync_state.granted_scopes text[]` (NULL = never recorded), router function `route_mail_oauth_state(text)` with column grants to `semprec_router` on `mail_oauth_states(tenant_id, state_hash, used_at, expires_at)`.
- `granted_scopes` is written by `recordGrantedOauthScopes` (`mailAccountSyncStateStore.ts`) in the connect transaction and in `replaceMailboxCredential` (under the existing sync-state-row lock), replacing the previous grant. Source: the token response's space-separated `scope` (deduplicated, ≤ 64 entries of ≤ 512 chars, non-string = error); without `scope` the requested scopes are recorded (RFC 6749 §5.1).

**Contracts.**
- `POST /api/mail/mailboxes/oauth/start` body `{ provider: "gmail"|"outlook", services?: ("mail"|"calendars")[] (1–2, default ["mail"], must include "mail"), redirectTarget?: "app" }`, strict. Response unchanged `{ authorizeUrl }`. Refusals 400 `validation_failed` with `details.field` `provider` | `services` | `redirectTarget`. New mailbox: `mailEnabled: true`, `calendarsEnabled` = whether `calendars` was asked for.
- `POST /api/mail/mailboxes/:id/reauthorize` body `{ services?, redirectTarget? }` (strict; empty body = `{}`). Asks for mail + calendars when the mailbox's `calendarsEnabled` is on + the body's services. Refusals 400 with `details.field` `services` | `redirectTarget` | `body`. Wrong account still 400 `mail_reauth_wrong_account` (credential and granted scopes unchanged).
- `POST /api/mail/mailboxes/oauth/complete` unchanged in shape.
- `GET /api/mail/mailboxes` and `/:id` rows gain `calendarStatus`: `off` (Calendars switched off) | `needsConsent` (a `gmail_api`/`graph_api` account whose recorded grant lacks the calendar scope; no recorded grant counts as lacking) | `pending` (otherwise, IMAP accounts included). Computed by the exported `calendarStatusOf({ calendarsEnabled, syncMode, grantedScopes })` in `mail/oauthServiceScopes.ts`; Graph's resource-qualified names (`https://graph.microsoft.com/Calendars.ReadWrite`) in any case count. The calendar sync issues should reuse it (and replace `pending` with their own state). Switching Calendars on writes nothing else; the client calls reauthorize with `services: ["mail","calendars"]`.
- `GET /api/mail/oauth/callback`: query validated first (400 before any DB read). Then `resolveMailOauthRedirectUrl(pool, state)` (exported from `@semprec/data`) routes the open (unused, unexpired) state's tenant through `route_mail_oauth_state`, reads `redirect_target` in that tenant. `app` → 302 `Location: semprec://oauth?state=…&code=…` or `semprec://oauth?state=…&error=…` (no-store, no-referrer, nosniff). Any other state (no target, unknown, used, expired, or a hash open in two tenants) → the unchanged JSON echo. The URL is a constant chosen by the stored target; nothing from the request but `state`/`code`/`error` reaches it. A lookup failure → 500 `internal_error`, logged with error name and code only.

**Tests.** `mailOauthRoutes.test.ts` new describe "OAuth scopes per service" (26 tests: authorize scopes and stored services per provider, validation tables for start and reauthorize, connect storing granted scopes, Google granular consent leaving needsConsent, scope-less response fallback, Graph-qualified scopes, non-string scope creates nothing, switching Calendars on a mail-only account → needsConsent with mail sync untouched (no pause, same jobs, same credential), IMAP → pending, reauthorization replacing credential + scopes and leaving needsConsent, reauthorize scope unions, wrong account). `mailOauthStatesStore.test.ts`: router function privileges (definer, owner, search_path, EXECUTE only `semprec_data`, column grants), resolution across tenants from no scope, null for plain/used/expired/unknown/duplicate-hash states, CHECK constraints. `mailOauthHttp.test.ts`: 302 for an app state (extra query params ignored; state still completes; used state echoes JSON), 302 for a provider error, 500 path with a refused connection; the existing "no statement" assertions now allow only the state lookup statements. A mutation (calendar status ignoring the grant) fails 4 tests.

**Deviations.**
- `services` on start must include `mail`: a calendars-only new account would need an identity lookup without mail scopes (Gmail's profile needs a Gmail scope) and creation with Mail off; not built.
- `redirectTarget` is also accepted by reauthorize (the Task names only start): the app's consent flow for an existing account returns through the same sheet and needs it.
- The app redirect also carries a provider error (`&error=`), not only state and code, so a cancelled consent returns to the app.
- The callback now reads the database (new router function, `docs/operations/database-roles.md` row, privilege test); its route-matrix `publicReason` and the isolation-test comment were updated to say so. The callback has no rate limit (two indexed reads per request, like the Graph webhook).
- Beyond Touches: `mail/oauthServiceScopes.ts` (new, reusable status), `oauthTokenExchange.ts` (scope parsing), `mailAccountSyncStateStore.ts` (writer), `index.ts` + `publicSurface.test.ts` (export), `app.ts` (pool to the callback), `routeMatrix/mail.ts`, `docs/operations/database-roles.md`, `.github/scripts/write-safety-baseline.json` (fingerprint of the consume `UPDATE`, whose `RETURNING` changed), fixtures in `itemForeignKeys.test.ts`, `tenantIsolationJobs.test.ts`, `mailboxRestoreHook.test.ts`.
- Token refresh (`refreshAndPersistAccessToken`) is unchanged: no caller passes `scope`, so Microsoft returns tokens for the whole grant; refresh responses do not update `granted_scopes`.
