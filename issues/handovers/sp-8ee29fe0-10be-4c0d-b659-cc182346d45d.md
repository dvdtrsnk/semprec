# Handover: Scan a document in the diary capture row

ADR: `docs/adr/2026-11-27-the-document-scanner-is-the-one-uikit-view-controller-of-the-apple-app.md` (unchanged: the
scanner moved into an existing module, DesignSystem, so the ADR's narrowing records no new module; its body still names
the old path in the app target, and an accepted ADR body is not edited).

**Move (DesignSystem, `mobile/apple/Modules/Core/DesignSystem/`).** DesignSystem depends on nothing and every feature and
the app may import it, so no policy target changed.
- `Sources/DocumentScanner.swift` (`git mv`, still wrapped whole in `#if os(iOS)`, the only `VisionKit` import, UIKit
  through `import SwiftUI`): now `public`, takes `onFinish([PDFPage])`, `onCancel`, `onFail` closures instead of the
  app's `ScanPresenter`; `public static var isSupported`.
- `Sources/ScanDocument.swift` (`git mv`): `public enum`; `file(pages:scannedAt:)` returns the neutral
  `ScanDocument.File(filename, mimeType, base64)` (no source, no CoreKit); `isScannerSupported` (iOS: the scanner's
  `isSupported`; macOS: false).
- `Sources/View+DocumentScanner.swift` (new): `documentScanner(isPresented:onFinish:onFail:)`, a `fullScreenCover` with
  the scanner on iOS that closes itself on every outcome and calls `onFinish` only with at least one page; nothing on
  macOS.
- `Tests/ScanDocumentTests.swift` (`git mv` from the app's tests): the source assertion moved to `ScanPresenterTests`,
  which already asserted it.

**App.** `ScanPresenter.finish` maps `ScanDocument.File` to `InboxShortcutCapture.File(..., source: .camera)`;
`ScanPresentation` builds `DocumentScanner(onFinish: presenter.finish(pages:), onCancel: presenter.cancel, onFail:
presenter.fail)`; `AddToInboxIntent` imports DesignSystem for `DocumentScanner.isSupported`. Behaviour unchanged.

**Journal.** `JournalCaptureRow`'s attach menu (Photo, File) gets "Scan document" (`journal.capture.scan`, icon
`doc.viewfinder`, identifier `journal.capture.scan`) when `ScanDocument.isScannerSupported`; the row's
`documentScanner` modifier shows the scanner. `JournalCaptureViewModel.attachScan(_:scannedAt:) -> Bool` builds the PDF
and sends the same `.attach(filename:mimeType:base64:source: .camera)` as a picked file; false (PDF not made) shows the
row's existing "could not be read" alert, as does a scanner failure. Cancel attaches nothing. Sending is unchanged (the
attachment goes with the next submit).

**Copy / policy / docs.** `journal.capture.scan` en "Scan document", cs "Naskenovat dokument", in the Journal catalog and
in the Journal `appleOnly` list of `mobile/scripts/architecture-policy.json`. `mobile/docs/architecture.md` row for the
scanner now names the DesignSystem files and both callers; `mobile/apple/review-rules/tasks/apple-multiplatform.md`
item 6 lists DesignSystem's `DocumentScanner.swift` among the allowed UIKit files.
