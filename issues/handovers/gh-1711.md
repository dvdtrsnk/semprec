# gh-1711 — Journal entry summary title

Repository-Issue: gh-1711

## What changed

- `backend/packages/data/src/journal/journalSummary.ts` (new):
  - `JOURNAL_SUMMARY_COMPUTED_KEY` (`journalSummary`) and `JOURNAL_SUMMARY_MAX_CHARS` (80).
  - `computeJournalSummary(markdown)`: parses the page's canonical Markdown (#1608) with `parseMarkdown`. It takes the plain text of the first block that has text, collapses whitespace and cuts the result to 80 code points. It returns `null` when no block has text, including empty input.
  - `recomputeJournalSummary(client, databaseId, itemId, summary)`: locks the item row (`FOR UPDATE`), leaves a missing or soft-deleted item unwritten, skips the write when the stored value equals `summary`, and otherwise writes through `writeComputedAndAnnounce`, which announces after the commit.
- `backend/packages/data/src/search/pageTextJob.ts`: the `itemSearchPageText` handler (#1658) now loads the owner item with a `LEFT JOIN` to its page doc. For a Journal entry (`owner_module_id = journal`) it calls `recomputeJournalSummary` in the same transaction as the page-text and index writes, with the Markdown it already serialized. A Journal entry with no page doc gets `null`. Non-Journal items, Emails items, soft-deleted items and missing items behave as before.
- `backend/packages/data/src/seed/seedSystem.ts`: `JOURNAL_SUMMARY_COMPUTED_KEY` is added to the computed-key registry on every startup, next to `inboxItems`, so a property with that key is refused.
- No migration, no backfill, no new export from the data package index.

## Notes for dependants

- Reading of the Task's "first non-empty line": the summary is the first block that has text, after the block parser has removed the markup. A page-link block has no text, so it is passed over rather than shown as its title. A heading that comes after other text is not preferred, because the first block with text wins.
- Timing: the summary is written by the page-text job, so it appears about 30 seconds after the first edit of a burst, the same delay as the page text. An unchanged first line writes nothing and announces nothing.
- `null` versus absent: the first recompute of an entry stores `null` for an entry with no text, so the key is present and reads as `null`. Entries that existed before this issue have no `journalSummary` until their next page edit; there is no backfill.
- The derived-property ADR (`2026-09-19-derived-system-properties-computed-inline-at-choke-point.md`) computes `owner: 'system'` properties inside the item write. This key derives from the page document, which an item write does not read, so it follows the page-text job from #1658 instead. The write still goes through the choke point (`writeComputedAndAnnounce`).
- `recomputeJournalSummary` and `computeJournalSummary` are not exported from the data package index. Other code should go through the page-text job rather than calling them.
- The stored `name` (emoji and period key) is unchanged, and this issue does not change any client. Czech labels for Journal properties remain #1413's.
