# Handover for gh-1403

Value links now have storage and a read side. Two tenant tables hold them, and `item.get`, `database.query` and `view.query` return an additive `links` field behind `include: ["links"]` (REST: `?include=links` on `GET /api/items/:id`, an `include` array in the two query bodies). The work is committed locally; I did not push or open a PR.

Nothing in product code writes a link row yet. Rows exist only through `insertValueLink`, used by test fixtures until #1593.

- **Migration:** `0089_value_links.sql` creates `value_links` and `value_link_sources`. Both carry the tenancy comment, `tenant_id` default, RLS with `tenant_isolation` and `tenant_rows`, and DML grants to `semprec_side` (`semprec_data` inherits them). `value_links` has `UNIQUE (tenant_id, item_id, property_key)`, `UNIQUE (tenant_id, id)` and a state CHECK (`on` needs `broken_by` and `broken_at` NULL, `broken` needs both set). Sources reference the link through `(tenant_id, link_id)` with `ON DELETE CASCADE`, have a kind CHECK, an index on `(tenant_id, source_item_id)` and one partial unique index per kind. There is no foreign key to `items`; cleanup is #1656.
- **Store:** `chokePoint/valueLinksStore.ts` has `insertValueLink` (link plus sources, run it in one transaction), `listValueLinksByItemIds` and `listValueLinkSourcesByLinkIds`, one query each, rows validated through `dbRowValidation.ts`. `insertValueLink` and its input type are exported from the data barrel.
- **Read:** `chokePoint/valueLinkReads.ts` `getValueLinksForItems(client, itemIds)` returns a `Map<itemId, Record<propertyKey, entry>>`. It runs five queries however many items or sources there are (links, sources, visible databases, source items, database labels). A trashed or missing source item is left out of `sources`; the entry is still returned. A source title is the value of the source database's `title` property, or `""` if it has none. `databaseKey` is the database's `owner_module_id` (null when unset). The facade method is `chokePoint.getValueLinksForItems(itemIds)`.
- **Database labels:** `databasesStore.listDatabaseLabelsByIds` is new, one query returning `owner_module_id` and the `title` property key per database.
- **Wire shape:** `include` is `z.array(z.enum(["links"]))` on the three input schemas; `Item.links?` mirrors the data types in `shared` (`ItemLink`, `ItemLinkSource`). The application service attaches `links` (an empty object when an item has none) only when `include` contains `links`. `GET /api/items/:id` parses `include` as a comma-separated list, so `path,links` returns both; unknown tokens there are ignored as before. In the `path` branch the links are read with a second call after `getItemPath`, for the item itself only (not for the breadcrumb items).
- **Tests:** `valueLinksStore.test.ts` (CHECKs, uniqueness per kind, cascade, per-tenant uniqueness), `valueLinkReads.test.ts` (one and two sources, broken, no row, senderDomain, trashed/missing source, constant query count, two-tenant isolation on a runtime-role pool including a source id of another tenant), the `include=links` cases in `itemsHandler.test.ts` (get, `path,links`, database.query, view.query, invalid include), schema unit cases, and `value_links`/`value_link_sources` added to `TENANT_TABLES` in `tenancyCatalog.test.ts` (outside the Touches list; needed or the catalog test fails). Tenant purge and export are catalog-driven and pick the tables up unchanged.
- **Not covered:** MCP gets `include` through the shared operation schemas; I tested the schemas, not an MCP end-to-end call.
- **Unrelated failure seen:** `tenantExport.test.ts` "archives exactly tenant A's data" fails here on an expiry check that is off by exactly one hour (7 days ahead crosses the DST change on this host). It does not touch this diff; I left it alone.
