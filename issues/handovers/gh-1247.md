## What changed
Only `backend/packages/data/src/__tests__/tenantScopePool.test.ts` changed, and only the test "rejects a scoped pool.query syntax error with the Postgres error and leaves a clean connection" (review finding `5af39c2f2e` from PR #1114):

- The test reads the backend PID from the existing single-connection pool (`newPool(1)`) before the scoped failure.
- The scoped `SELEKT 1` must still reject with Postgres code `42601`.
- When the connection is reused, it must report the same PID, must not carry the tenant setting, and `app_current_tenant()` must be NULL.
- A separate connection (the shared test pool) checks that backend in `pg_stat_activity`: it must show `state = 'idle'` and `xact_start IS NULL`. Postgres updates the state before it sends ReadyForQuery, so the row is current once the reuse query has returned.
- The unused `txid_current_if_assigned() IS NULL AS status` column and its incorrect `status: string` type are removed.
- New local control: on the same backend (PID asserted) the test opens `BEGIN READ ONLY` and asserts that `txid_current_if_assigned()` is still NULL. The same observer must then report `idle in transaction` with a non-null `xact_start`. This shows the observer can tell an open transaction from an idle backend, and that an unassigned transaction ID alone would not have caught it. The control always rolls back. If the ROLLBACK fails, the client is released with that error so `pg` destroys the connection. If the control assertions failed, that error is the one reported, not the rollback error.

No production code, other pool tests or tenant-scope contract changed.
