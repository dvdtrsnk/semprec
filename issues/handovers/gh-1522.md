# Handover for gh-1522

Added the `date_relative` filter condition `{ type, property, endProperty?, preset }`, evaluated in the tenant time zone at query time.

- **Schemas:** `date_relative` is in `FILTER_CONDITION_TYPES`, `FilterCondition` and the zod schema of both `views/filterTree.ts` and `shared/genericOperations/filterSort.ts` (identical; both also export `DATE_RELATIVE_PRESETS`). `preset` is a named preset or `{ fromDays, toDays? }` (integers within +/-36500, `fromDays <= toDays`); anything else fails schema validation with a 400.
- **Ranges:** `views/relativeDates.ts` (`resolveDayRange`, `FilterCompileContext { zone, now }`) turns a preset into inclusive `YYYY-MM-DD` bounds using `calendarTime` (`today`, `weekBounds`) from gh-1418. A missing side is unbounded. `beforeNow` has day bound D-1 for date-only values and compares timestamps as instants against `now`.
- **Compiler:** `compileFilterNode(node, properties, params, context?)` has a new optional fourth argument. `date_relative` without a context throws `ValidationError`; a non-date or unknown `property`/`endProperty` throws `ValidationError` with that property as `field`. The SQL binds the zone, property keys and day bounds as parameters (no clock call). A stored value becomes a day via `CASE`: a `YYYY-MM-DD` string is used as written, anything else is `::timestamptz AT TIME ZONE $zone`; null or empty never matches (the condition is `start IS NOT NULL AND ...`, so `not` of it matches those items). With `endProperty` the interval `[property, COALESCE(endProperty, property)]` must intersect the range.
- **Callers:** `resolveFilterCompileContext(client, node, now?)` (exported from `filterCompiler.ts`, not from the package index) reads `getSystemTimezone` only when the tree contains `date_relative`. `viewQuery.ts` (`QueryViewOptions.now`) and `itemReads.ts` (`ListItemsInput.now`, `CountItemsInput.now`) use it. `now` defaults to the current time; it is the injectable clock for tests. HTTP routes do not expose `now`.
- **Tests:** `src/__tests__/relativeDateFilter.unit.test.ts` (ranges for Thursday 22 Oct 2026, Prague midnight vs UTC, compiled parameters, schema validity in both copies; run and passing) and `src/__tests__/relativeDateFilter.test.ts` (database-backed: thisWeek/nextWeek/range, `endProperty`, timestamp day in the tenant zone, `beforeNow`, stored view changing on the next day, `past` ignoring undated items, 400s). No Postgres was available in the worker, so the database-backed file was only type-checked and linted, not run. Targeted lint, prettier and tsc pass.
- **Notes for dependants:** numeric conditions (#1534) and facets (#1759) should pass the same `context` argument through `compileFilterNode`. Adding `date_relative` did not change `publicSurface` (no new package exports).
