# Handover: mail to oneself as received, restore to the folder it left, overlapped Sent copy, immediate IMAP IDLE

Commits on `feat/internet-accounts`: `a55d71b5b` (F13), `9c4651008` (F18), `458133573` (F14), `d6f32abe4` (F15), `6e3d39a50` (F19, admin health test). Nothing was run against Purelymail or any other real server; every finding was reproduced with `testSupport/fakeImapAccount.ts` (in-memory IMAP account behind `ImapMailClient`: folders, UIDs, flags, APPEND, MOVE) driven through the real draft, send, sync-job and thread-route entry points (`__tests__/mailSelfAddressed.test.ts`).

**F13 root cause.** A message Alldots sends to its own account is one Emails item: the send claim, the Sent copy the saver appends and the copy delivered to INBOX share one Message-ID per mailbox. It is both "own" (sender is a mailbox address) and in Sent, and every classification used `NOT own AND NOT has_sent`, so read/flag selected nothing yet answered 200, the list never showed it unread, and archive/trash/restore refused it with 409 `mail_move_source_unverified` (two edges with a UID). Each pass also let the `\Seen` Sent copy overwrite the delivered copy's flags.

**F13 changes.** `mailThreadCopyCtes` gains `received` (Inbox or Junk, or a copy beside a Sent copy with a UID, or foreign sender and not in Sent); `copy_stats.unread` and the actions' `incoming` read it. `read:false`/`flagged:true` without a received message answer 409 `mail_thread_no_received_message` and write nothing; `read:true`/`flagged:false` no-ops stay 200. IMAP moves of an item that is also in another folder take the provider message outside Sent and keep the Sent copy's edge and UID. `applyObservedMailMessageFlags` takes the observed folder and ignores the Sent copy beside a delivered copy (one extra argument in `imapReconcile.ts`, the only line touched in the perf agent's pass). Behaviour change: an own-address message delivered to an Inbox now counts as unread (summary fixture and three existing tests updated accordingly).

**F18 root cause and change.** Restore sent every non-received copy to Sent; mail to oneself delivered to INBOX without a Sent copy is, once archived/trashed, own and in no Inbox, so restore moved it to Sent ("neither INBOX nor Archive"). A completed move overwrites `source_evidence`, so the origin was lost. New baseline column `mail_message_move_sync_state.restore_purpose` (`inbox`/`sent`), written by archive/trash desires (kept from an earlier desire when the copy leaves neither, cleared by any other desire); restore returns there, else falls back to received → Inbox, own → Sent.

**F14.** Sending stays synchronous per the architecture (claim → provider send → finalization, 4xx failures, no retry); exactly-once unchanged. Root cause: two connection setups in sequence (SMTP, then a fresh IMAP connection for the Sent copy). The `SentCopySaver` now starts with the submission and receives `accepted: Promise<boolean>`; the APPEND runs only on acceptance, a refused submission closes the opened connection unused, and the send settles only after that connection closed. Test with 300 ms per setup: 303 ms after (sequential before: ≥ 600 ms; the old code fails the overlap assertion). Real expectation: about one IMAP connect+login less (~1 s at Purelymail's RTT); SMTP itself and the APPEND/LOGOUT remain.

**F15.** v0.3.1 measured 6.4 s after the perf agent's fetch-outside-transaction pass. Remaining defect found and fixed: imapflow starts IDLE only after `autoIdleDelay` (15 s) without a command, and a server reports a delivery unasked only inside IDLE, so every IDLE (re)connect had a 15 s blind window. The IDLE connection now uses `autoIdleDelay` 0 (it issues no other command, no extra load). Loopback IMAP test with real imapflow (`imapIdleLatency.unit.test.ts`): delivery right after SELECT signalled after 15 003 ms before, 1.8 ms after. Signal → enqueue is immediate; the rest of the 6.4 s is Purelymail delivery/IDLE push plus one pass (connect, LIST, every folder); not measurable without the real server.

**F16.** Threading is correct; no code change. The reply resolves to the original thread via In-Reply-To/References and each message's INBOX and Sent copies converge on one item, so the thread holds exactly 2 messages (original, reply), each in INBOX and Sent; no "Re:" thread. The expected "≥3" counted the Sent copy as its own message. Regression test added.

**F19.** `adminHandler.test.ts` inserted a global `mail:` check row that no current writer produces (only an older version could leave one); the fixture is removed, the content-free assertions stay.

**Follow-ups.**
- Mail to oneself on IMAP is two provider messages in one item; archive/trash move only the delivered copy, the Sent copy stays in Sent (two desired moves per item would be needed).
- Search `is:unread` (`excluded_from_unread`) still leaves every Sent-folder copy out, so self-addressed mail is not found as unread by search.
- On a refused SMTP submission the send now waits for the Sent-copy connection to open and close (bounded by the IMAP connect timeout and the account's connection slot).
