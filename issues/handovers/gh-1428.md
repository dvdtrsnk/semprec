# gh-1428 — refuse Journal entries outside the journal store

Repository-Issue: gh-1428

## Delivered behavior

- `backend/packages/data/src/journal/journalWriteHook.ts` (new): `journalItemCreateHook`, an `ItemCreateHook`. For a database whose `ownerModuleId` is `journal`, it throws `ForbiddenError` (HTTP 403, code `forbidden`, `details.field` set to the first missing key) when the written properties lack a non-blank `type` or `period`. `type` is checked before `period`.
- `backend/packages/data/src/domainWriteHooks.ts`: one line registers the hook with `registerItemCreateHook`.
- Every create into the Journal database is covered by this one hook: the generic REST `POST /api/databases/:id/items`, the application gateway used by agents and `/mcp` (`item.create`), and any `createItemWithClient` caller. `getOrCreateJournalItem` writes all three keys and passes. Inbox capture reaches the Journal only through `getOrCreateJournalItem`, so it passes too.
- No migration, no schema change and no new error code. A Journal-specific code such as `journal_entry_incomplete` was not added, because `DOMAIN_ERROR_CODES` in `backend/packages/shared/src/genericOperations/errors.ts` is a closed set.
- Task item 4 (fixture fixes) needed no change. No existing test creates a Journal item without `type` and `period`.

## Behavior notes

- The hook runs after the real insert and inside the create transaction, so a refusal rolls back the row and its idempotency reservation. A corrected retry with the same `Idempotency-Key` creates the entry.
- The hook does not run on an idempotency replay, consistent with `docs/adr/2026-10-09-item-create-domain-hooks.md`.
- Journal's `type` and `period` have no default, so the hook sees exactly the keys the caller or `getOrCreateJournalItem` stored.
- The hook covers create only. A patch is not checked by this hook. The generic patch path already refuses `type` and `period` because both are `owner: 'system'`, unless a caller passes `allowedSystemKeys`.
- `name` (the Journal title) is not checked here. Titles are out of scope (#1711).

- Mutation check: with the registration line removed, the 7 refusal cases of `journalWriteHook.test.ts` fail and the 4 allowed-path cases pass. The registration was restored before the commit.

## Notes for dependants

- The lazy Journal create route (#1541) must write `type` and `period` through `getOrCreateJournalItem`. A create that writes other keys is refused with 403.
- Any new Journal creator must write `type` and `period`, with or without an `allowedSystemKeys` grant. The hook checks the written properties, not the grant.
- The error is `forbidden` with `details.field`, not a Journal-specific code. Clients that match on the code must match on `forbidden` and read `details.field`.
