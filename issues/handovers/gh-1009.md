## Authorize blob downloads in scope before the conditional branch (#1009)

`GET /api/blobs/:id` now reads the blob and its download filename in one transaction in the caller's tenant, before any conditional branch. A foreign blob id answers exactly like an unknown one, whatever `If-None-Match` or `Range` the request carries.

### Changes
- **`blobsHandler.ts`:** `resolveDownloadFilename` is replaced by `resolveDownload(pool, blobId)`. It runs `getBlob`, then the Files database and `findFileItemByBlobId`, in one `withTransaction`. It returns `{ blob, filename }`, or `null` when the blob is not visible; `null` throws the existing `NotFoundError`. The `304` and `416` branches now come after the lookup. The filename fallback to `blob.id` is unchanged, and no hand-written `tenant_id` predicates were added.
- **Docstring:** the listener's docstring now says the caller's tenant decides what may be seen, before any conditional branch.
- **`blobsPerTenant.test.ts` (new):** two tenants on the runtime `semprec_data` pool, six tests covering the acceptance criteria. Foreign ids with `If-None-Match` and with `Range` return the same 404 as a random UUID. A plain foreign request returns that same 404 and never calls `readStream`. The caller's own blob gets 200, 304, 206 and 416. Content-Disposition uses the caller's own Files item name. A blob with no Files item in the caller's tenant falls back to its id, even when tenant B has an item naming it.

### Choices I made
- **Test setup for tenant B:** `seedSystem` cannot run once a second tenant exists, because its module data migrations need a tenant scope. So tenant zero is seeded first, and tenant B's Files database (with `name` and `file` properties) is created through `createChokePoint`.
- **Test helper:** the uploads use `ingestUploadedFile` and the blobs use `LocalFsBlobStorageWriter`, the same path `POST /api/files` takes.
