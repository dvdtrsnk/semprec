# Handover for gh-1524

## Summary

Text sorts now follow the caller's locale and break ties by title.

- `sortCompiler.ts`: a closed `SortCollation` type (`"cs-x-icu"` | `"und-x-icu"`), `collationForLocale(locale)` (`cs`, also `cs-CZ`, gives the Czech collation; anything else or no locale gives `und-x-icu`) and `DEFAULT_SORT_COLLATION`. `sortKeyExpression` appends `COLLATE "<name>"` to keys of type `title`, `text` and `url`; the collation name only ever comes from the closed type, never from the raw locale string. `compileSort` and `compileSortKeyset` take the collation as a last (optional, default neutral) parameter and the keyset's cursor-bound side carries the identical `COLLATE`, so `ORDER BY` and the paging predicate agree.
- `viewQuery.ts`: `QueryViewOptions`, `DatabaseQueryInput` and `ViewQueryInput` gain `locale?: string` (set by the application layer, never read from a request body). `queryItemsCore` appends the database's `title` property as a last ascending sort key (`withTitleTieBreak`) whenever a sort exists and the title is not already a key; the item id stays the final tie-break. The title is part of the sort tuple, so it is part of the keyset cursor (a sorted cursor issued before this change is rejected as an invalid cursor because its value count differs).
- `viewQueryOps.ts`: new choke-point method `findUserLocale(userId)`; `genericApplicationService.ts` resolves it for the actor in `queryView` and `queryDatabase` and passes it as `locale`. Callers without a locale (background code) get `und-x-icu`.
- ICU availability (Task step 1): `postgres:16-alpine` ships ICU and its initdb imports the `*-x-icu` collations into `pg_collation`, so no migration or activation step was added. The embedded test database did NOT qualify at first: on a host with the C locale initdb creates a `SQL_ASCII` database, and ICU collations do not exist for that encoding. `testSupport/globalSetup.ts` now initialises with `--encoding=UTF8`.

## Tests

`viewQueryPagination.test.ts`, new block "text sort collation and title tie-break": `cs` orders Hrad, Chalupa, Rybnik, Reka after the Czech alphabet; `en` and no locale use the neutral order; ties on a `text` key break by title then id; three-page keyset paging by title; descending text key with title tie-break paged once each; `findUserLocale`. `publicSurface.test.ts` lists `findUserLocale`.

## Notes for dependants

- Only `title`, `text` and `url` sort keys are collated. `compileSort` / `compileSortKeyset` default to the neutral collation when no collation is passed.
- Neutral ICU ordering puts "Reka" before "Rybnik" (it is not a Czech-aware order); that is the expected `en` result.
- The title tie-break only applies to sorted queries. An unsorted query still orders by id.
- A deploy database created with a non-UTF8 encoding would not have usable ICU collations; the production image is UTF8.
