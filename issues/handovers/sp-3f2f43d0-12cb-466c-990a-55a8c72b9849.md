# Handover: answer a committed OAuth reauthorization with 200 when the live sync restart fails

Commits on `fix/followup-mail-edges`: `48890f24e` (route, data test, docs) and `fb0bec3f1` (REST adapter test). Nothing was run against a real server.

**Root cause.** `POST /api/mail/mailboxes/oauth/complete` for a reauthorization state awaited `mailLiveSync.restartAccount` after `replaceMailboxCredential` committed; a rejected restart answered 500 for a token that was already stored and in effect.

**Changes.**
- `mail/mailOauthRouteHandlers.ts`: a failed restart is logged (`Restarting the mail live sync after a reauthorization failed`, `mailboxItemId`, `errorName`) and the route answers 200 `{ mailboxId }`, as the password replacement does.
- `docs/architecture/domain-mail-and-inbox.md`: OAuth connect and reauthorization.

**Other routes checked.** Only the password replacement and the OAuth reauthorization await `restartAccount`. The connect routes start nothing (discovery hosts a new account), Mail on queues a pass, Mail off stops the live sync in `runAfterCommit` and logs a failure, the Calendars switch writes and queues inside the update's transaction, and the removal cleanup's `liveSyncStop` is time-limited and logged. No other change was needed.

**Tests.**
- `packages/data/src/__tests__/mailOauthRoutes.test.ts`: "answers 200 when the restart after the commit fails, with the token replaced, the sync queued and the failure logged without a secret" replaces "propagates a failed restart as an unexpected error" (fails before the fix: the handler rejected).
- `services/semprec-api/src/__tests__/mailOauthHttp.test.ts`: "answers 200 when the restart fails after the commit, with the new token stored and no request error logged" replaces the adapter-level 500 expectation.

**Left.** Nothing.
