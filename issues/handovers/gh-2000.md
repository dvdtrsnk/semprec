## What was delivered

An agent whose project has no access to a sensitive database can no longer learn about its records through a database it may read.

- Filter compiler: `compileFilterNode` takes an optional `closedDatabaseIds` set. It refuses with `ForbiddenError` (`forbidden`, 403, naming the property key and database id, no item content) any condition on a relation property whose target database is closed (`relation_contains`, `relation_not_contains`, `relation_is_empty`, `relation_is_not_empty`, both hops of `relation_path_contains`) and every operator on a rollup whose source database (`rollup_dependencies.source_database_id`) is closed, also nested under `and`, `or` and `not`.
- Sort: a sort, or a view's stored sort or groupBy, by a rollup over a closed database is refused alike (`views/viewQuery.ts`).
- Rollup reads: a rollup over a closed database is read by an agent as `computed[key] = { value: null, hidden: true }` in `getItem`, `findItem`, `listItems`, `database.query` and `view.query` (curated views included), whether or not a value exists; a person or an agent with a grant reads the value.
- The closed set comes from `listClosedSensitiveDatabaseIds` (`agentGrants/closedSensitiveAggregationAccess.ts`): sensitive databases whose effective access for the agent's project is none, using the same SQL expression as the point check `assertAgentDatabaseAccess`; it is read in the caller's tenant transaction.
- Wiring: `database.query`, `view.query` (stored filter and sort included), the choke point `listItems` with an agent reader, and `item.count` (`CountItemsBatchOptions.agentProjectItemId`, set by `genericApplicationService` from the agent's project).
- Fix round: `item.count` groupBy by a relation into a closed database is refused (`countItemsEntry`, also without a filter); `database.facets` (`DatabaseFacetsOptions.agentProjectItemId`, set by the application layer) compiles the filter, `extra.open` and every per-facet probe with the closed set and refuses a relation facet or a path facet whose first or second hop targets a closed database; the write responses of an agent (`createItem`, `createItemWithRelations`, `updateItem` including the current item of a version conflict, `softDeleteItem`, `restoreItem`) hide closed rollup values through `hideClosedRollupValuesForWriter`.
- New ADR `docs/adr/2026-11-13-an-agent-may-not-filter-sort-or-aggregate-a-sensitive-database-it-cannot-read.md` documents the decision and the channels not covered.

## Entry points and contracts dependents build on

- `compileFilterNode(..., closedDatabaseIds?)` in `views/filterCompiler.ts`; callers that do not pass the set fail open by design (persons, the system and the external `/mcp` client are unchanged). A new agent-facing read path that compiles a filter must resolve the set with `listClosedSensitiveDatabaseIds(client, agentProjectItemId)` and pass it.
- `views/closedDatabaseRefusal.ts` (`closedDatabaseRefusal`), `rollup/rollupSources.ts` (rollup source databases) and `views/filterProperties.ts` (rollup `sourceDatabaseId`, second-hop `targetDatabaseId`) are module-internal; none is exported from the `@semprec/data` barrel, so `publicSurface.test.ts` is unchanged.
- Option fields: `CountItemsBatchOptions.agentProjectItemId`, `DatabaseFacetsOptions.agentProjectItemId`.
- Hidden rollup shape: `{ value: null, hidden: true }`.
- No route, operation catalog entry, table, migration or job.

## Deviations and spec seams

1. The filter compiler is synchronous, so the closed set is resolved before compilation in the choke point and passed in; the sort refusal sits in `views/viewQuery.ts`.
2. Files outside the Touches list, all declared: `agentGrants/agentDatabaseAccess.ts`, `agentGrants/closedSensitiveAggregationAccess.ts`, `views/viewQuery.ts`, `views/filterProperties.ts`, `views/closedDatabaseRefusal.ts`, `rollup/rollupSources.ts`, `genericApplicationService.ts`, the ADR (and in the fix round `facetQuery.ts` and the write stores).
3. "Sensitive and not readable" is read literally: a user-created non-sensitive database with an explicit `none` grant is not in the closed set (tested).
4. The rule applies to an agent's project only; an external AI client on `/mcp` and a person are unchanged (an external client is refused a sensitive database by the database alone, issue 1998).
5. `item.count` does not access-check the counted database itself (the ADR of 1810 leaves counts to other issues).
6. A stored view whose own filter or sort reaches a closed database is refused to the agent, by design of the Task.
