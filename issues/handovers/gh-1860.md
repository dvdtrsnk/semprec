## What was delivered

A finished Semp turn now stores a typed summary on the assistant message, so it survives the 30-day retention of the run events.

- Migration `0158_semp_messages_steps.sql` adds the nullable columns `semp_messages.steps jsonb`, `duration_ms integer` and `tokens jsonb`. The chain wrote it as `0157`; that ordinal was taken on the tip by `0157_semp_messages_search_vector.sql`, so the queue runner renamed the chain's own file to `0158`. Nothing referenced the old name.
- `semp/sempReplySteps.ts`: pure projector `projectSempReplySteps` over the events of one turn, built on `semp/sempReplyToolCalls.ts` (`pairSempToolCalls` pairs `tool_use` and `tool_result` on `toolCallId`). A step has `kind` (`tool` | `model`), `toolCallId`, `toolName`, `operation`, `label` and `detail` (`{ key, params }` with `agentStep.*` i18n keys of the agent-run catalog, never localized text), `status` (`ok` | `wait` | `error`), `startedAt`, `durationMs`, `approvalRequestId`, `errorCode` and `tokens`. `sempTurnDurationMs` is the time from the first `turn_start` to the last `turn_end`, or to the last event when a later round never ended; `null` without a `turn_start`.
- `semp/sempReplyTargets.ts` resolves item names and the database module and `sensitive` flag in the caller's tenant scope; `semp/sempReplySummary.ts` (`buildSempReplySummary`) assembles `{ steps, durationMs, tokens, changes }`. Tokens are the sum of the settled `ai_gateway_calls` attributed to the message (`sumSettledSempMessageTokens` in `aiGatewayCallsStore.ts`).
- A step on a redacted result, on an item of a sensitive database, or on a target that cannot be placed in the tenant scope stores no name, no changes and no params.
- `finishSempMessageTurn` writes `steps`, `duration_ms`, `tokens` (and `changes` of gh-1885) in the same UPDATE as the final status. `sempMessageTask.ts` builds the summary inside the done transaction. On a failed turn it reads the summary in a transaction of its own before storing the error state; a read failure is logged (ids and error class only) and does not block the error state.
- A failed generic operation now returns `details.errorCode` equal to `ChokePointError.code` (`genericOperationAgentTools.ts`, `agentSessionComposition.ts`); the shared `ToolResultDetails` parser keeps `errorCode` and `failureKind`.

## Entry points and contracts dependents build on

- From `@semprec/data` (frozen in `publicSurface.test.ts`): `buildSempReplySummary`, `projectSempReplySteps`, `listSempTurnEvents` (`agentRunEventsStore.ts`), `sumSettledSempMessageTokens`, the types `SempReplySummary` and `SempReplyStep`.
- Table columns `semp_messages.steps`, `duration_ms`, `tokens`. Stored step keys are English camelCase; labels are i18n keys, rendered by the client from the `agentStep.*` catalog.
- `finishSempMessageTurn(client, id, outcome)` takes an optional `summary` in both outcomes; a caller without one leaves the columns NULL (the startup repair that marks a message `interrupted` stores none).
- `details.errorCode` on a failed generic operation tool result. No route, operation or job name was added.

## Deviations and spec seams

1. The Task says the session composition returns only `{ error }`; on the base it already passed `approvalRequestId`, `changes`, `failureKind` and `sensitive`, so only `errorCode` was added.
2. The spec names the keys `step.itemPatch` and `step.modelSummary`; after gh-1847 they do not exist. Labels and details reuse the `agentStep.*` catalog keys; a unit test pins the operations with a summary entry to the keys in `en.json` and `cs.json`.
3. pi emits `turn_start` and `turn_end` per model round, so `duration_ms` runs from the first `turn_start` to the last `turn_end` of the Semp turn (to the last event when a later round never ended).
4. Message events carry no token usage today; a model step reads `usage.input` and `usage.output` only when a message event has them, so the step `tokens` is not set by the current producers (a unit test covers a synthetic event).
5. A turn that ended in an error stores no `event_to_id` (unchanged); its events are read from `event_from_id` to the end of the run.
6. Files outside the Touches list: `sempReplyToolCalls.ts`, `sempReplyTargets.ts`, `sempReplySummary.ts`, `aiGatewayCallsStore.ts`, `agentRunEventsStore.ts`, `databasesStore.ts` (`DatabaseLabelRow.sensitive`), `agentRunStepPages.ts` (`toolResultFailed`, `boundValue`, `isRedactedResult` exported), shared `toolEventPayload.ts`.
7. Reconciled at the merge: the merge kept the tip's `search_vector` assignment of gh-1783 in the same UPDATE as the new columns of `finishSempMessageTurn`, and folded three type-only exports of `index.ts` into their value exports to stay under the 900-line cap.
