## Summary

Implements issue #91: two affinity-safe graphile-worker composition roots over the same Postgres-backed queue.

- **`services/semprec-api/src/queueRuntime.ts`**: installs `CORE_CRONTAB`, hosts core/data handlers plus every `queueAffinity: 'api'` module task, runs the one-time `heartbeatFire` legacy-queue migration.
- **`services/semprec-agents/`** (new service): installs no crontab, hosts the closed `heartbeatFireAgent`/`agentRun`/`delegatedAgentRun` catalog plus `queueAffinity: 'agents'` module tasks.
- Both composition roots inject a process-owned `Pool`, run idempotent migrations, call `run()` exactly once, expose an idempotent `stop()` that never closes the pool, and wire their own SIGTERM/SIGINT handling (intake → runner → pool).
- `assertTaskListMatchesAffinity` proves each runtime's registered handlers exactly match its resolved affinity set before startup completes, failing actionably on a missing, duplicate, or cross-affinity handler.
- Added integration tests booting both compositions against ephemeral Postgres: affinity isolation (a job outside a runtime's affinity is never claimed), exactly-one-crontab installation, startup failure on a colliding module task name, and idempotent shutdown.
- Updated `deploy/README.md` to describe `semprec-agents` as the second systemd-managed process sharing the queue's network/secrets contract.
