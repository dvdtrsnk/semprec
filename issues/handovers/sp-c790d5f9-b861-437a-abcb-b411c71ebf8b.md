# Handover: skip a mail sync trigger that cannot lock a running pass's sync state row and record failures only from the lease holder

Commit on `fix/ia-mail`: `479cabcfe`. Nothing was run against a real server.

**Root cause.** `claimMailSyncPass` read the sync state row `FOR UPDATE` without a bound. A Gmail or Graph pass keeps that row locked for its whole reconcile transaction (the lease renewal in `enterSyncPass` and `recordGmailActivity`/`recordGraphActivity`), so every trigger during it waited up to the pool's 60 s statement timeout, and the resulting `57014` was recorded by the catch block as the mailbox's sync error (`syncStatus` `error`, Semp problem, notification) by a job that never held the lease.

**Changes.**
- `mail/mailAccountSyncStateStore.ts`: `claimMailSyncPass(..., { maxWaitMs })` sets a transaction-local `lock_timeout`, restores it after the grant, and throws `MailboxSyncBusyError` on `lock_not_available`.
- `db/tenantAdvisoryGuard.ts`: `isLockNotAvailable` exported.
- `mail/mailSyncJob.ts`: the claim waits at most `MAILBOX_SYNC_PASS_WAIT_MS` (5 s); a contended claim is skipped like a held mailbox guard. A job that fails before it holds the lease logs `Mail sync failed before holding the pass lease` (ids, failure kind, error name) and rethrows without recording anything.
- `docs/architecture/domain-mail-and-inbox.md`: the pass lease paragraph.

**Behaviour to know.** A trigger that gave up after 5 s is not recorded as a rerun of the running pass; the sweep picks up an account that is still due, as for a held mailbox guard. A failure before the lease (a schema check, a statement timeout) no longer sets `syncStatus` `error`; graphile-worker retries the job.

**Tests** (`__tests__/mailSyncSingleFlight.test.ts`): a trigger while another transaction holds the row returns after about 5 s with no provider client and an unchanged outcome (timed out at 30 s before the fix); a job whose claim hits a 1.5 s statement timeout rethrows `57014` and records nothing after the row is free again (recorded `error` before the fix).
