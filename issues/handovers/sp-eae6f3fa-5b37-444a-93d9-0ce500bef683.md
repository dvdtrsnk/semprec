# Handover: answer a committed password replacement with 200 when the live sync restart fails

Commit on `fix/ia-mail`: `0aa970e7e`. Nothing was run against a real server.

**Root cause.** `PUT /api/mail/mailboxes/:id/password` awaited `mailLiveSync.restartAccount` after its transaction committed; a rejected restart answered 500 for a password that was already stored and in effect.

**Changes.**
- `mail/mailboxPasswordRouteHandlers.ts`: a failed restart is logged (`Restarting the mail live sync after a password replacement failed`, `mailboxItemId`, `errorName`) and the route answers 200 with the item.
- `docs/architecture/domain-mail-and-inbox.md`: password sign-in again.

**Tests** (`__tests__/mailboxPasswordRoutes.test.ts`): a restart that rejects with the password in its message → 200, new password stored, sync queued, failure logged without the password (500 before the fix).

**Left.** The OAuth sign-in again (`mailOauthRouteHandlers.ts`) still answers 500 after its commit when the restart fails; that is documented in `domain-mail-and-inbox.md` and asserted by `mailOauthRoutes.test.ts` ("propagates a failed restart as an unexpected error"), so changing it is a separate decision.
