## What was delivered

- `POST /api/mail/threads/:threadId/flag`, custom route `mailThreadFlag` (justification `transactional-semantics`), handler `createMailThreadFlagRouteHandler` in `mail/mailThreadRoutes.ts`. Body: strict object `{ flagged: boolean }`, otherwise 400. Answers `200 { threadId, flagged }`.
- It takes the mail-thread guard through `resolveMailThreadForAction`, then locks the copies in item id order. `flagged: true` flags the copies of the last incoming message; `flagged: false` clears every live copy, own, Sent and Drafts mail included. A copy whose locked value already matches is skipped, a copy trashed or gone in the gap is skipped. Writes go through `updateItemWithClient` as the session user, so the flag hook records the desired state, and one `mailThread` invalidation is announced after the commit.
- The answer's `flagged` is the thread's state after the writes (`readMailThreadFlagged`, new helper in `mail/mailThreadActions.ts`, reading `copy_stats` in the same transaction). A thread without a live message answers 404 like the read route.
