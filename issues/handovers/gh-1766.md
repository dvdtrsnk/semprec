## What was delivered

- Every row of `GET /api/approval-requests` and both 200 answers of `PATCH /api/approval-requests/:id` carry `source`: `{ kind, threadId, threadTitle, heartbeatId, heartbeatName, mcpClientName }`. Every earlier field keeps its value.
- The source is derived when the request is read, in `loadApprovalSources` (`backend/packages/data/src/mcp/approvalRequestsQueue.ts`). Nothing is stored; `approval_requests` has no new column.
- A run that has a thread takes the source from the thread: a chat or item thread is `chat`, a tick thread is `tick` with the thread's heartbeat, also when a chat run started the heartbeat. `threadId` is set and `threadTitle` comes from `loadSempThreadTitleResolver` of gh-1729 in the caller's `users.locale`.
- A run without a thread takes the kind from `triggered_by` of its root run: `mcp` is `mcp`, `heartbeat` is `tick` with the root run's heartbeat, anything else is `chat`. `mcpClientName` is always `null`; gh-1788 records it.
- `getRootAgentRuns` (`backend/packages/data/src/agentRuns/agentRunsStore.ts`) follows `parent_run_id` for all given runs at once, one query per level, and stops at a run without a parent, at a parent that is not visible, and after `AGENT_RUN_ROOT_MAX_HOPS` (32) hops.
- Threads, heartbeats and the Inbox items of item threads are each read once per list, so the number of statements does not grow with the number of requests.
- No migration, table, column, route, generic operation, job name, hook, tenant cutover entry, module manifest entry, stored key or i18n key was added.

## Contracts dependents build on

- `ApprovalRequestSource` (type, exported from `@semprec/data`):
  - `kind`: `"chat" | "tick" | "mcp"` (`ApprovalRequestSourceKind`);
  - `threadId`, `threadTitle`: `null` for a run without a thread; `threadTitle` is also `null` for a chat thread without a title and for an item thread whose Inbox item is in the Trash, gone or without text (the rule of the thread list);
  - `heartbeatId`, `heartbeatName`: set for a `tick` source, `null` otherwise and for a heartbeat-triggered root run that names no heartbeat; the name is the current `project_heartbeats.name`;
  - `mcpClientName`: `null` until gh-1788.
- `ApprovalRequestQueueEntry.source` and `ApprovalRequestDecisionView.source` are required members.
- **Signature change:** `listApprovalRequestsQueue(client, ownerUserId, locale)` and `toApprovalRequestDecisionView(client, request, locale)` take the caller's `users.locale` as a new third argument, because the title of an item thread is a localized template. The only production caller, `backend/services/semprec-api/src/approvalRequestsHandler.ts`, passes `identity.user.locale`. A new caller must pass a locale.
- New runtime exports of `@semprec/data`, through the existing `export *` of `agentRunsStore.ts`: `getRootAgentRuns(client, runs): Promise<Map<runId, AgentRunRow>>` and `AGENT_RUN_ROOT_MAX_HOPS`. Both are in the expected list of `publicSurface.test.ts`.
- The run returned for a chain that stopped at the hop limit or at an invisible parent still names a parent; the kind is taken from that run.
- On `PATCH`, the source is computed inside the transaction of the decision, after the owner-scoped decision returned a request. An unknown, foreign or other-tenant id still answers the same 404 before any new read.
- gh-1785 (landed in the same merge) derives the same kind in SQL for its filter; a test asserts that both derivations agree. A change of the rule changes both places.
- gh-1786, gh-1787, gh-1807 and gh-1913 read the source; gh-1788 fills `mcpClientName`.

## Deviations from the specification and spec seams

1. The new third argument `locale` of the two functions, and the handler file outside `Touches` that passes it.
2. `getRootAgentRuns` and `AGENT_RUN_ROOT_MAX_HOPS` became public exports through the existing `export *`, so `publicSurface.test.ts` (outside `Touches`) lists both.
3. The walk ends by a hop limit of 32, as the Task says (a depth guard), not by the visited set of `docs/adr/2026-09-11-iterative-parent-chain-traversal-in-choke-point.md`. The limit also ends a parent cycle; a cycle costs 32 reads.
4. Decided where the Task is silent: the null title cases above; a heartbeat-triggered root run that names no heartbeat is `tick` with null heartbeat fields; a root run triggered by a user or a supervisor is `chat`.
5. One docstring line in `sempThreadsListStore.ts` (outside `Touches`) now says the approval source calls the resolver.
6. **Spec seam, open for the controller.** For a run without a thread, Task step 2 decides by the root run. A heartbeat run without a thread whose parent chain ends at a chat run is therefore `chat`, while the Context of gh-1766 says a heartbeat started from a chat is still a tick. The acceptance criterion speaks only of tick threads, the code follows the Task step, and no test pins that case. Such rows can exist: the scheduler creates heartbeat runs with a parent run, and migration 0096 left `thread_id` NULL on earlier runs.
