## What the route does
- **Auth:** the bearer token is compared in constant time before the body is read; a bad or missing token gets 401.
- **Body:** capped at 4 MiB (413 above that) and checked with zod; a bad field gets 400 `validation_failed` with the field name.
- **Run attribution:** the optional `x-semprec-agent-run-id` header must be a UUID and sets the row's `agent_run_id`; without it the column is NULL.
- **Model:** only Anthropic models from pi-ai's built-in catalog are accepted; anything else gets 400 `unknown_model`.
- **Accounting:** every request goes through `complete()` with `operation: "agent_turn"`, so it gets exactly one `ai_gateway_calls` row. The row is `reserved` before the provider is contacted, then `settled` with the streamed token counts and `usage.cost.total`, or `failed` at cost 0.
- **Streaming:** the reply is sent as SSE `PiMessagesEvent` frames ending in exactly one `done` or `error`. A provider `error` event, or a client disconnect (which aborts the provider stream), leaves the row `failed`.
- **Budget:** when the daily or monthly cap is reached, the route answers 403 `budget_exceeded` before calling the provider and writes no row.
- **Wiring:** `app.ts`, `startupConfig.ts` and `serve.ts` pass the new options through; the `.env.example` comment for `AI_GATEWAY_INTERNAL_TOKEN` now lists `semprec-agents`. There is no new environment variable and no change to `shutdown.ts`.

## Where this departs from the issue text
- **`streamSimple` instead of `stream`:** the production stream function is `streamSimple` from `@earendil-works/pi-ai/compat`. Only that entry point turns the protocol's `reasoning` option into Anthropic thinking; `stream` would drop it silently.
- **`toolChoice` limited to `"auto"` or `"none"`:** pi's Anthropic transport can't turn the protocol's other values into a valid request. They would fail at the provider after the budget is already reserved, so they get a 400 up front.
- **Serializer reads a few fields from `partial`:** a tool call's `id` and name at `toolcall_start`, and the text and thinking signatures at `*_end`, are only kept there. The wire protocol needs them, and Anthropic needs the thinking signature back when a turn is replayed.
- **No 502 `provider_failed` branch:** the response head is written before the provider is called, so provider failures always come after it. A reservation failure (a database error) gets a 500.
- **Disconnect detection uses `res.on("close")`, not `req.on("close")`:** on current Node, the request's `close` fires as soon as the body has been read, not when the client leaves.
- **More test files updated than the issue lists:** `audioConcurrencyLimit.test.ts` and `shutdown.test.ts` also call `createDispatcher`, so they needed the new parameter. `startupConfig.unit.test.ts` now sets `ANTHROPIC_API_KEY` and tests the new options.
