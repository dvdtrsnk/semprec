# Handover: detect messages deleted or moved on the IMAP server through QRESYNC VANISHED and a message-count check

Commit on `feat/internet-accounts`: `4ce2a4ccb`. Nothing was run against Purelymail or any other real server.

**Root cause.** `buildImapFlow` created imapflow without `qresync: true`, so QRESYNC was never ENABLEd. `ImapFlowMailClient.fetchVanishedSince` checked the advertised capability rather than the enabled one, so on Purelymail it sent `UID FETCH 1:* (UID) (CHANGEDSINCE m)` without `VANISHED`, got no VANISHED response and returned `[]`. The pass took `[]` to mean nothing had vanished and recorded the folder's new `message_count`/`highestmodseq`. From then on STATUS matched the stored state, the quiet-pass skip left the folder alone, and nothing looked at the expunged message again. IDLE did signal (`expunge`) and did enqueue the pass; that pass went down the same path. Two more gaps: on CONDSTORE-only servers every delivery also ran `UID SEARCH ALL`, and an Emails item whose last folder edge was removed stayed live, so it still counted in its thread (`messageCount`, `unread`, `flagged`).

**Changes.**
- `mail/mailServerConnections.ts`: `qresync: true` on every connection, including sync, IDLE and the move drain. imapflow only ENABLEs what the server advertises.
- `ImapMailClient.fetchVanishedSince` is replaced by `fetchChangesSince(path, modseq)`. It sends one `UID FETCH 1:* (UID FLAGS) (CHANGEDSINCE m VANISHED)`, gated on `client.enabled`, and returns `{ flags, vanished }` or `null`. It shares the flag fetch's 100k result cap (VANISHED UIDs count toward it) and its per-step timeout.
- `fetchImapFolder` decides by message count. If `stored count − reported vanished below the stored UIDNEXT + new UIDs found` equals EXISTS, it trusts the reported vanished list (none without QRESYNC). Otherwise it does the full `UID SEARCH ALL` diff. It also falls back to the diff after a UIDVALIDITY change, after a partial batch, or when no count is stored. A delivery alone sends no full UID list on any server.
- `applyImapFolder` returns the Emails items it removed an edge from. The pass's final transaction (and `reconcileImapFolder`'s own transaction) trashes each item left with no folder edge and no unsettled or protected move. It uses `itemDeleteWithClient` as the system writer plus `deleteMailMessageMetaOfRemovedItem`, the same path as the Mail-off removal.
- A move by another client: both folders are processed in one pass, so the target UID is ingested onto the same item (Message-ID dedup) before the trash decision runs. The item keeps its read state and links.
- Fakes: `FakeImapServer` gained QRESYNC (ENABLE, `VANISHED (EARLIER)` from expunge tombstones), IDLE with VANISHED/EXPUNGE/EXISTS pushed to an idling session, `expunge`/`move`/`isIdling`, and one text/plain body per message (ENVELOPE, BODYSTRUCTURE, header fields, TEXT, RFC822.SIZE). `createSyncedLoopbackMailbox` and `PURELYMAIL_CONTENT` are now shared in `testSupport/imapMailboxFixture.ts`, and the loopback client enables QRESYNC. The other test fakes follow the interface rename.
- `docs/architecture/domain-mail-and-inbox.md`: deleted-message detection and the removal of a message whose last copy is gone.

**Measured** on the loopback server at 40 ms per response, with Purelymail's capabilities and no LIST-STATUS. Pass after one INBOX expunge:

| server | commands |
|---|---|
| QRESYNC | LOGIN, ENABLE, LIST ×2, LSUB, STATUS ×6, SELECT 1, FETCH 1, LOGOUT |
| CONDSTORE only | the same + SEARCH 1 (UID SEARCH ALL) |
| neither | LOGIN, LIST ×2, LSUB, SELECT ×6, FETCH ×6, SEARCH 1, LOGOUT |

A second pass over the same state sends only the quiet-pass commands and removes nothing more. The QRESYNC quiet pass equals the CONDSTORE one (13 commands at 80 ms). On a CONDSTORE-only server a delivery sends only the new-UID SEARCH. With IDLE on INBOX, an expunge is trashed and gone from the inbox list about 0.75 s later (asserted < 1.2 s).

**Tests.** `imapServerDeletions.test.ts` covers:
- expunge at the next pass for QRESYNC, CONDSTORE-only and plain servers, with command counts, the trash, the inbox listing and idempotence;
- a delivery on a CONDSTORE-only server;
- a two-message thread keeping `messageCount` 1;
- another client's INBOX→Archive move on the same item;
- an expunge during IDLE.

`imapQuietPass.test.ts` adds the Purelymail QRESYNC row. Changed existing test: `mailSyncSingleFlight` IDLE test, where the follow-up after a delivery no longer calls `fetchAllUids`.

**Verified.** `pnpm run lint`, `format:check`, `pnpm -r run build`, `check:write-safety`, `check:boundaries`, `test:unit`, and the integration files matching mail, imap, idle, thread, observability, isolation, inbox, smtp, mailbox, tenant and relationInvalidation. Two unrelated tests timed out only while the integration run loaded the host and passed alone: `tenantIsolationRealtime.test.ts` (one binary-frame case) and four registry-load unit tests (`collectionMetadata`, `facetQuery`, `recipesModuleManifest`, `sleepModuleManifest`). Not run: the full `test:integration`, `test:e2e`, web and mobile pipelines, and anything against a real server.

**Follow-ups.**
- QRESYNC SELECT parameters (`SELECT … (QRESYNC (uidvalidity modseq))`) would fold the flag and vanished data into the SELECT and save the FETCH.
- Gmail-over-IMAP label edges of a message that vanished from All Mail are kept (the item is therefore not trashed).
- An edge removal that leaves other copies publishes no `mailThread` invalidation.
- A move whose target UID falls beyond the pass's 10-message budget is shown as a removal plus a new item in the next pass.
- If a pass fails between a folder batch and its final transaction, the item it removed an edge from is left folderless (as before this change).
