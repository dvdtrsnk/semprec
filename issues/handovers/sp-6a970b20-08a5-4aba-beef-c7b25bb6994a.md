# Handover: let several processes install the queue schema at once

Commit on `fix/followup-queue-grants`: `e936c9153`.

**Changes.**
- `queue/src/index.ts`: `grantQueueSchemaPrivileges(client)` takes a `PoolClient` inside a transaction and takes `pg_advisory_xact_lock(2335, 0)` before the grants and policies.
- `data/src/db/queueSchema.ts`: `installQueueSchema(pool)` runs `ensureQueueSchema`, then the grants in one `withTransaction`, under `runAsSystem("queue-schema")`; exported from `@semprec/data`.
- Callers of the old `ensureQueueSchema` + `grantQueueSchemaPrivileges` pair call `installQueueSchema`: the api, agents and transcribe queue runtimes, `runMigrationsCli.ts`, `globalSetup.ts` and eleven tests.
- Docs: lock class 2335 in `tenancy-and-security.md`; the concurrent start in `migrations-and-seeding.md`; `operations/migrations.md`, `operations/database-roles.md`.

**Other startup steps checked.** graphile-worker's `runMigrations` (in `ensureQueueSchema` and in `runWorker`) treats a clash as another process's migration and the search task registration is `ON CONFLICT DO NOTHING`; in 60 concurrent rounds neither failed. Its migrations run in their own transactions, so they cannot take a transaction lock from outside; no change. Data migrations run only in the deploy CLI.

**Tests.** `queueSchemaConcurrentInstall.test.ts`: six pools run `installQueueSchema` at once on an empty database, five rounds; all succeed and `semprec_side` has schema usage, `_private_jobs` INSERT, `add_job` EXECUTE and the four `semprec_side_all` policies. With the lock line removed the file failed 10 of 10 runs (`tuple concurrently updated`); with it, it passed 10 of 10.
