# Handover: re-add removed accounts, sign password accounts in again, report a missing credential as reauthorization

Implementation commits `33d9c0495`, `160c8633f` and the test-fixture follow-up after them on `feat/internet-accounts`. Nothing was run against production or any remote host.

**Design.**
- Duplicate rule: `mailboxHoldsAnyAddress` (`mail/mailboxAddresses.ts`) is held when a sync state row records the address as `provider_account_address` or a **live** Mailboxes item lists it. The password connect uses it in its pre-check and in-transaction re-check. A removal deletes the sync state row (and credential, settings), so a trashed mailbox holds nothing; the OAuth connect keeps deciding through the address unique index, which no trashed mailbox occupies.
- Restore: `mailboxItemRestoreHook` refuses with `ProviderAccountAlreadyConnectedError` (409 `provider_account_already_connected`) a mailbox one of whose addresses another live mailbox lists or records; the restore rolls back.
- `PUT /api/mail/mailboxes/:id/password` (`createMailboxPasswordReplaceRouteHandler`, manifest route `mailboxPasswordReplace`, mounted with the connect, `transactional-semantics`). Read account (404 / 409) → throttle `mailboxCredentialVerification` → `verifyPassword` against the stored hosts (iCloud: fixed hosts) → with Calendars on, `verifyCalDav` at `https://caldav.icloud.com/` (iCloud) or the stored `caldav_url` (generic; none → no CalDAV check) → one transaction: unlocked read, `ensureMailAccountSyncState`, lock sync state row, lock Mailboxes item, re-check, `storeCredential` (`app_password` / `plain_password`), `upsertMailServerSettings` with the verified endpoints and the user name, `clearMailSyncFailure`, `clearCalendarSyncReauthorization`, enqueue `mailAccountSync` and (Calendars on) `calendarAccountSync` → after the commit `mailLiveSync.restartAccount`. `syncStatus` is not written (the queued pass is its writer). `ICLOUD_CALDAV_URL` moved to `caldavConnectVerification.ts` and is shared with the adapter.
- Missing credential: the mail sync pass throws `MailReauthorizationRequiredError` for every status (`last_failure_kind` `reauthorization`, `syncStatus` `needsReauthorization`, critical Semp problem, no `mail_sync_error` notification). `listAccountsDueForSync` skips `last_failure_kind = 'reauthorization'`. The IMAP IDLE discovery ends without retry on `MailReauthorizationRequiredError`; `semprec-api`'s `getCredential` throws it for a missing credential (one `IMAP IDLE lifecycle failed` warning per lifecycle start). The job still rethrows, so graphile retries one job at most 3 times (`maxAttempts: 3`), unchanged.

**Route contract (as implemented).** `PUT /api/mail/mailboxes/:id/password`, session auth. Body JSON, strict: `{ "password": string (1..1024), "username"?: string (non-blank, ≤ 320, no control characters) }`; `username` omitted keeps the stored one. 200 body: the item envelope, the same shape the password connect answers with 201 (top-level `id`, `properties`, …). The password is in no response or log line.

**Error codes** (body `{ "error": { "code", "details"? } }`):

| Status | Code | Connect `POST /api/mail/mailboxes` | Replace `PUT …/:id/password` |
|---|---|---|---|
| 400 | `validation_failed` (`details.field` when one field is at fault; also malformed JSON) | yes | yes |
| 400 | `mail_auth_failed` | yes | yes |
| 400 | `mail_app_password_required` (iCloud login refused) | yes | yes |
| 400 | `mail_server_unreachable` | yes | yes |
| 400 | `mail_tls_failed` | yes | yes |
| 400 | `caldav_auth_failed` | yes (body with `caldavUrl`) | yes (Calendars on) |
| 400 | `caldav_server_unreachable` | yes | yes |
| 400 | `caldav_server_invalid` | yes | yes |
| 401 | `unauthorized` | yes | yes |
| 404 | `not_found` (unknown, malformed, foreign or trashed id) | — | yes |
| 409 | `provider_account_already_connected` | yes | — |
| 409 | `mailbox_not_password` (Gmail/Outlook, no IMAP/SMTP settings, or sync mode not `imap`) | — | yes |
| 413 | `payload_too_large` (> 1 MiB) | yes | yes |
| 429 | `rate_limited` (`Retry-After` header) | yes | yes |
| 500 | `internal_error` (configuration or unexpected failure) | yes | yes |

A restore of a mailbox through the generic item restore answers 409 `provider_account_already_connected` when a live mailbox holds its address.

**Deviations.**
- The calendar status after a password replacement is `never` (no `idle`/`pending` status exists); the queued pass sets `ok` or a failure.
- `Mailboxes.syncStatus` stays `needsReauthorization` until the queued mail pass completes (one owner, the sync worker).
- Existing tests that used a missing credential only as a shortcut to an ordinary sync failure now store a credential and use an adapter failing with a plain error, assertions unchanged: four in `mailSync.test.ts`, two in `observabilityCheckSystem.test.ts` (stall-check merge; escalation of the stall problem, where the real `MailReauthorizationRequiredError` pass still escalates it to critical with production code unchanged), one in `sempProblemNotification.test.ts` (push after four failures, which counts `mail_sync_error` notifications of ordinary failures). The trashed-address duplicate test is replaced by re-add/restore tests.
- The sweep exclusion applies to every reauthorization failure, OAuth ones included; their sign-in queues the next pass, as before.
