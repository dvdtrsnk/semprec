## Summary

Admins can now create, list and revoke account invitations through three routes: `POST /api/admin/invites`, `GET /api/admin/invites` and `POST /api/admin/invites/:id/revoke`. An invitation grants nothing yet, because accepting one ships with #1087.

- **Migration `0077_invites.sql`** adds the global `invites` table. Only the token hash is stored. `semprec_side` gets SELECT and `semprec_data` gets DML. The ordinal was checked against `origin/develop` and is still free.
- **Store `tenancy/invites.ts`** normalizes and validates the email. It takes a per-address advisory lock and refuses an address that already has an account. It supersedes earlier pending invites for that address and inserts the new one. The invite mail is dispatched after commit.
- **Mailer `tenancy/inviteMail.ts`** follows `NodemailerPasswordResetMailer`, with the same timeout and HTML escaping.
- **Composition**: `serve.ts` builds one shared SMTP transport for both mailers. `AppOptions.inviteMailer` is optional and omitted when SMTP is unset.
- **Routes** run in one transaction with `recordAdminAction`. The audit rows hold the invite id only, never the email or token.
- **Tests**: `invites.test.ts` (new, 11 cases) and 6 new route cases in `adminHandler.test.ts`. They cover the acceptance criteria, including the mailer-rejection log check and the `semprec_side` privilege refusal.

## Deviations and decisions

- **Revoke locks, then updates.** The spec asked for one `UPDATE … RETURNING`. I used `SELECT … FOR UPDATE` to classify the row, then an `UPDATE` wrapped in `requireAffectedRows`. This makes the write-safety rule hold and gives the same 404/409 outcomes.
- **Write-safety baseline, one line.** The supersede `UPDATE` in `createInvite` legitimately matches zero rows for a first invite. I recorded its fingerprint in `.github/scripts/write-safety-baseline.json`. `--update-baseline` would also have dropped eight unrelated entries, so I reverted that and added only this one line.
- **`EMAIL_PATTERN`** is now exported from `authActions.ts`, as the spec asked. It is not copied.
- **`inviteUrl` in the 201 response** is the one place the raw token is returned. Store and mailer log lines carry the invite id only.
