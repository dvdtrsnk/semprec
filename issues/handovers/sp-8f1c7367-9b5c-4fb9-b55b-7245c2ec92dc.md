**What changed.**
1. 2. `docs/operations/database-roles.md` (Identity tables, Extending the grants) records the rule: a table that holds a bearer credential, a session secret, a delivery endpoint or a row that makes an actor is granted to `alldots_data` and nothing to `alldots_side`; a new identity-plane table gets SELECT for `alldots_side` only when a side process reads it.
3. New ADR `docs/adr/2026-11-15-the-side-role-cannot-create-an-actor-or-read-credentials.md` (accepted, backend) with the accepted remainder: the tables the rule does not cover.

**Contracts dependents build on.** After this migration the side-role processes (`alldots-ai-gateway`, `alldots-restore-test`) can neither write the four tables nor read the eight credential, token and admin tables.
