The deploy seed now provisions each tenant's system databases inside that tenant's own scope, on a pool that runs as `semprec_data`. The change is committed as `4900b8a2`. The new tests and the other checks I ran pass, but I did not run `pnpm run verify` or the e2e tier; Relay's step does that.

**What changed**
- **Pool role:** `createPool(url, { role: "semprec_data" })` passes `-c role=semprec_data`. A test confirms `current_user` is `semprec_data` and `row_security_active('public.databases')` is true.
- **`seedSystem`:** it resolves the tenant with `app_tenant_default()` and throws if there is none. It locks on `pg_advisory_xact_lock(2331, hashtext(tenant id))`, reads `tenants … FOR SHARE`, and refuses a missing or `deleting` tenant. The "already seeded" check now includes `AND system`. The signature is unchanged.
- **`provisionTenant`**, **`assertRowSecurityActive`** and **`forEachMaintainedTenant`** are in the new `tenancy/provisionTenant.ts`:
  - **`provisionTenant`:** it seeds the tenant, runs the module data migrations, then moves a `provisioning` tenant to `active`. A `suspended` tenant stays suspended; `deleting` and unknown tenants throw.
  - **`assertRowSecurityActive`:** it throws on a role RLS doesn't apply to, such as the owner pool.
  - **`forEachMaintainedTenant`:** it visits `provisioning`, `active` and `suspended` tenants. It continues past a failing tenant and then throws one `AggregateError` listing the failed ids.
- **`runSeed` and the CLI:** `runSeed` returns one `{ tenantId, outcome }` per tenant and runs in `runAsSystem("deploy seed", …)`. The CLI uses the `semprec_data` pool and prints one line per tenant in the stated format. I added a small `formatSeedLine` helper so a test can cover those lines.
- **Exports and docs:** `provisionTenant` is exported and added to the public-surface test. `docs/operations/seeding.md` is rewritten, and the new ADR is `2026-10-08-deploy-time-tenant-work-runs-as-the-runtime-role.md`.

**Tests**
- A new `provisionTenant.test.ts` covers the acceptance cases. They are tenant isolation, the second-call, concurrent-call, suspended, deleting/unknown and owner-pool cases, and `module_migrations` visibility. They also cover `seedSystem` without a scope while two tenants exist, and `runSeed` over zero, B, C and D, including the `AggregateError` case.
- `runSeedCli.test.ts` now runs on the `semprec_data` pool with the new return shape, and the race case is kept.
- In the full integration run, 2396 of 2398 passed. One failure was my own CLI-spawn test, which I replaced with the `formatSeedLine` test. The other, `agent-runtime/lifecycleAdapter.test.ts`, passes when run alone, so it looks flaky.
- Boundaries, write-safety, lint and Prettier are clean, and the build passes.

**Deviations from the issue and a gap**
- **RLS check placement:** `provisionTenant` runs `assertRowSecurityActive` inside `runInTenant` instead of before it. A scope-less `pool.query` logs a `tenant_scope_missing` warning, and the outcome is the same because it still happens before any write.
- **Printed CLI lines:** the CLI's printed output is covered only through `formatSeedLine`, not by running `runSeedCli.js`. Plain `node` can't run the built CLI here, because `@semprec/shared` resolves to TypeScript source.
