- **`getItemsByIds` and `getItemsByIdsIncludingDeleted`:** both keep the early `[]` for empty input, then add `AND database_id = ANY($2::uuid[])`, bound to the helper's result.
- **`findItemsDeletedBefore`:** it adds the same predicate as parameter `$5`. The keyset order and paging are unchanged.
- **Docstrings:** I updated all three, plus the stale "scans every partition" text on `getItemsByIds`.

**Tests:** `packages/data/src/__tests__/itemLookupPruning.test.ts` runs the two-tenant cases in one rolled-back transaction as `semprec_data`. It records the SQL each function sends and runs `EXPLAIN (FORMAT JSON)` on it. It covers:
- **Pruning:** in tenant B's scope each plan scans only B's `items_p_*` partition, and no row from tenant zero comes back.
- **Mixed ids:** given one id of B's and one of tenant zero's, the two id lookups return only B's item.
- **Paging:** `findItemsDeletedBefore` returns B's trashed rows in `(database_id, id)` order, and a page cursor resumes correctly.
- **Empty tenant:** a tenant with no databases gets `[]` from all three, with a `One-Time Filter: false` plan and no partition scanned.
- **Single tenant:** with one tenant and no scope, results match the old behavior.
- **Empty input:** `getItemsByIds([])` and `getItemsByIdsIncludingDeleted([])` return `[]` without querying.
