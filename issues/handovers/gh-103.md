## Summary

Implements issue #103: dispatches deduplicated Inbox item events.

- Registers three `onItemEvent` heartbeats on the Inbox database (create/update/delete), each dispatching a new `semprec.tick` action.
- Reuses the existing `triggerOnItemEventHeartbeats`/`heartbeatFireJobKey` machinery (already wired into the generic choke-point create/update/delete paths), so each event type gets its own heartbeat row and thus its own job key — different items and different event kinds never collide, and `job_key_mode: "replace"` collapses rapid repeat edits to the same item into a single pending job.
- The `semprec.tick` handler (`inbox/inboxTickAction.ts`) re-reads the item by id at run time rather than trusting the job payload, so a collapsed job always reflects current state. Actual fingerprinting/proposal computation is out of scope (issue #223).
- Added a small "queue affinity" concept (action id → graphile-worker `queue_name`), threaded through the choke point's create/update/delete paths, so `semprec.tick` (or any future action) can request serialized execution.
- New test file `inboxTick.test.ts` covers: heartbeat registration, transactional per-event enqueue, cross-event/cross-item non-collision, rapid-update collapsing with latest-state reads, rollback emitting no job, and queue-affinity routing.
