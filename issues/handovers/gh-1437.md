# Handover for gh-1437

`ApprovalRequestDecisionView` now carries `conflictReason: { key: string } | null`, a translation key that says why an approved request was not carried out. It is `null` unless `executionStatus` is `conflict`. The execution result itself stays out of every view. I did not push or open a PR.

- **Classifier:** `approvalConflictReason(executionStatus, executionResult)` is in the new `mcp/approvalConflictReason.ts` and is exported from `@semprec/data` (with the `ApprovalConflictReason` type). It only reads discriminators and never copies text.
  - Generic operations (`error.code === "version_conflict"`): no `details.reason` gives `approval.conflict.changed`. `not_found` gives `deleted`, `owner_violation` gives `provenanceChanged`, `database_archived` gives `archived`, and any other reason gives `approval.conflict.other`.
  - MCP `outcomeKind`: `toolUnavailable` gives `approval.conflict.toolUnavailable`, `callFailed` gives `approval.outcome.failed`, `staleClaim` gives `approval.conflict.other`.
  - Legacy plain-string MCP rows and unrecognised shapes give `approval.conflict.other`.
- **MCP outcome write:** `ApprovalRequestOutcome` has an optional `outcomeKind`. When it is set, `recordApprovalRequestOutcome` writes `{ text, outcomeKind }` to `execution_result_jsonb`; otherwise it writes the plain text as before. `settleStaleApprovalRequestClaim` always writes `{ text, outcomeKind: "staleClaim" }`.
- **Call sites in `approvalRequestExecution.ts`:** the revoked-grant and inactive-registration outcome is `toolUnavailable`, and a failed tool call is `callFailed`.
- **No outcome kind:** the "no generic-operation replay handler configured" outcome and successful MCP outcomes have none, so they stay plain strings. That row therefore maps to `approval.conflict.other`. `genericOperationGateway.test.ts` still asserts the plain string.
- **Queue entries:** `ApprovalRequestQueueEntry` is built from pending requests only and has no `executionStatus`, so it did not get the field. Only the decision view did.
- **Tests:** a new `approvalConflictReason.unit.test.ts` covers every mapping and the fallbacks. `approvalRequestExecution.test.ts` asserts the stored shapes and the resulting keys for stale claim, revoked grant, inactive registration and inactive server. It also has a new `callFailed` case that uses `__forceError`. `approvalRequestsQueue.test.ts` covers the decision view for `changed`, `archived` and `null`, and checks that no argument or resource value leaks. `publicSurface.test.ts` lists the new export.
- **Verification:** the targeted integration and unit tests, tsc, eslint and prettier pass. I did not run the full verify.

For dependants (#1887, #1862): call `approvalConflictReason(row.executionStatus, row.executionResult)` on the raw row for step state. Do not re-implement the mapping.
