# gh-1402 — library rating validation

Repository-Issue: gh-1402

## Delivered behavior

- New `backend/packages/data/src/library/libraryRatingHooks.ts` with three choke-point hooks, registered in `domainWriteHooks.ts`:
  - item create and item update hooks for databases owned by the Books or Movies module: a present `rating` must be an integer 0 to 5 (`null` clears and is accepted), otherwise `ValidationError` with `field: "rating"`. The update hook checks only keys present in the patch, so an unrelated patch on an item with an already stored invalid rating still succeeds.
  - relation edge write hook for the Movies `watchedWith` relation: a present `metadata.rating` must be an integer 1 to 5, otherwise `ValidationError` with `field: "metadata.rating"`. Other metadata keys and edges without a rating are untouched. The owner module is read from `databases` inside the edge write transaction.
- Other modules' databases are unaffected (tested with a probe database owning a `rating` property).
- No migration of already stored values; no new route (the existing PUT edge route reaches the hook through the choke point).

## Tests

`packages/data/src/__tests__/library.test.ts`, new `library rating validation` suite: 7, 2.5, -1, "4", NaN rejected on create and update for Books and Movies; 0, 1, 5, null accepted; patch-only validation; watchedWith 9, 0, 2.5, "4" rejected, 1 and 4 accepted, non-rating metadata and no metadata accepted; non-library database unaffected.

Checks run: prettier, eslint, `tsc --noEmit` for the data package, and the library integration file (23 tests) against real Postgres (needed an unsandboxed run). Full backend/web verify NOT RUN (owned by integration). The 400 mapping is by `ValidationError` status; no HTTP-level test was added.

## Notes for dependants

- #1622 (number filters, "no rating" preset) can rely on stored ratings being integers 0 to 5 for new writes; older stored values may be invalid.
