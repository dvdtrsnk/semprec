## What was delivered

A person's global search now returns a `chat` group of Semp threads.

- `search/sempThreadSearch.ts` exports `searchSempThreads`, registered as the chat contributor in `searchItemGroups` (`search/searchItemsQuery.ts`). A thread matches when its title (the stored title of a chat thread, the Inbox item text of an item thread) or its preview window (the first 140 code points of the last message with text) matches the shared combined lemma-or-prefix tsquery of #1589, computed on the fly. Title and preview are matched each alone; words split between the two do not match (pinned by a test).
- Result rows carry `threadId`, the title resolved in `users.locale`, the date and time parts of the last activity in the system time zone, and `snippet: null`. Order is newest activity first, ties broken by thread id; the group has the real total and `perGroupLimit` entries without scope.
- Scope `["chat"]` pages with the thread-list cursor (`last_activity_at` with microseconds plus id), parsed by the existing `parseSempThreadListCursor`; other scopes keep the item cursor. A cursor that is not a thread-list cursor is refused with the generic `ValidationError` for every actor and every query (review fix: the chat cursor is parsed up front in `searchItemGroups` and the parsed value is passed on).
- New optional `SearchItemGroupsInput.humanActor` (default deny), set by `genericApplicationService.ts` through the existing `humanWriterUserIdOf` (a REST session that is not acting for an agent). An agent run and an MCP session get no chat group.
- The title text is capped at 1000 code points before vectorising, so a huge Inbox item text cannot fail the search with the 1 MiB tsvector limit.

## Entry points and contracts dependents build on

- `searchItemGroups(pool, input)` accepts `humanActor`; the chat group exists only when it is true and `chat` is in scope. The function is internal to the data package: nothing is added to the data barrel (`index.ts`, `publicSurface.test.ts` unchanged).
- Kinds searched: `chat` and `item` threads, tenant scope, ticks excluded (as the thread list default). The thread tables have no hidden or archived column, so "hidden" is read as tick.
- No route, operation, table, migration or job name is added. The shared generic-operation schema is unchanged (a doc comment of the chat group in `shared/genericOperations/schemas.ts` was corrected).

## Deviations from the specification and spec seams

1. The Touches list names only `sempThreadSearch.ts` and `searchItemsQuery.ts`; the human-actor rule needed the actor kind inside the data function, so `genericApplicationService.ts` passes the new `humanActor` and the gateway test was added.
2. The issue says the match rule is that of the thread list and also the combined #1589 query on title and preview. The thread list now also matches message text (#1783) with ILIKE substrings; the Task's own text (title or preview, combined lemma-or-prefix query) was followed.
3. "Hidden thread" is read as tick thread.
4. The chat cursor of scope `["chat"]` is the thread-list cursor, not the item cursor.
5. Not exported from the data barrel (the contributor is internal).
6. Title text is capped at 1000 code points (not in the issue).
7. Hunspell assets are not available on the delivery host (the czech configuration falls back to `simple`), so lemma matching was not exercised, only accent folding and prefix matching.
