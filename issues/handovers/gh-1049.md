**Data layer** (`backend/packages/data/src/tenancy/deleteAccount.ts`, exported from `index.ts`):
- **`beginTenantDeletion`:**
  - It throws unless the scope is exactly the tenant being deleted.
  - Then, in one transaction, it moves the tenant from `active` or `suspended` to `deleting`.
  - It revokes every session and push registration of the tenant's users.
  - It deletes the `tenant_keys` row, so `scheme = 'tenant'` credentials can no longer be decrypted.
  - It publishes the deactivation NOTIFY.
- **`deleteOwnAccount`:**
  - It applies `login`'s lockout check and password verification.
  - A locked pair or a wrong password records a failed attempt and throws `ReauthenticationFailedError` (403 `reauthentication_failed`).
  - Otherwise it runs the last-admin guard and then `beginTenantDeletion`. No audit row is written.
- **`deleteAccountAsAdmin`:**
  - Deleting your own id throws `SelfDeletionRequiresReauthenticationError` (403) before any query.
  - Otherwise it runs the same guard and deletion, records `accountDeletionRequested`, and returns the account summary.

**Routes:**
- `POST /api/account/delete` takes `{ password }` and answers 202 `{ status: "deleting" }`. A missing or empty password is 400 with field `password`.
- `POST /api/admin/accounts/:userId/delete` is admin-only and answers 202 `{ account }`.
- Both are in the route matrix and in `ROUTE_HANDLER_FILES`, and the new exports are in `EXPECTED_RUNTIME_EXPORTS`.

**Tests:**
- `deleteAccount.test.ts` has 19 tests. They cover:
  - the two-tenant success path with key shredding and the NOTIFY;
  - a wrong password, and lockout, including a different IP not being locked out;
  - the last-admin guard, with and without a second active admin;
  - admin self-deletion, an already-deleting account and an unknown user;
  - login after deletion;
  - `beginTenantDeletion` called from a system scope, another tenant's scope and a wrong status.
- `accountHandler.test.ts` and `adminHandler.test.ts` have new cases for the two routes. I also added `delete` to the existing 404/400/403/401 route loop in `adminHandler.test.ts`.

**Deviations and notes:**
- I changed `getAccountSummary` in `accountsAdminStore.ts` from private to exported, because the admin route needs the summary after the commit. That file isn't in the issue's Touches list, and the export adds one name to the public surface.
- `beginTenantDeletion` reads the delete's `rowCount` and logs `tenant_deletion_begun` with a `keyDeleted` flag, to satisfy the write-safety check. A zero-row delete is still legitimate.
- The self-deletion path does not record a successful attempt, since the issue doesn't ask for one.
- Credentials sealed under the master key are not shredded, as the issue states. The docstring says so.
