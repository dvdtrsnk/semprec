## What was added
- **Migration `0078_tenant_exports.sql`**: the table from the issue, with row-level security, both policies, the grant, and a partial unique index allowing at most one pending or running export per tenant.
- **Store `tenancy/tenantExportsStore.ts`**:
  - `requestTenantExport` inserts and enqueues the `tenantExport` job (key `tenantExport:<id>`, `maxAttempts: 1`) in the caller's transaction. If an export is already active it returns that one with `created: false`.
  - Listing, the downloadable lookup, and the status writers, each of which only moves the row from its expected previous status and fails otherwise.
  - `deleteExpiredTenantExports` for the sweep.
- **Job `tenancy/tenantExportJob.ts`**:
  - Builds the ZIP with `yazl` in one `repeatable_read` transaction. Entries are added one at a time, in order:
    - `account.json` (no password hash);
    - `tables/<table>.jsonl` for every tenant table except `external_credentials`, `tenant_keys` and `tenant_exports`, read 500 rows at a time;
    - `blobs/<id>` from the mail or files root;
    - `manifest.json` last.
  - A missing blob file goes into `missingBlobIds`; any other read error fails the export.
  - On failure it deletes the partial file, marks the export `failed` and rethrows the original error.
  - On shutdown it deletes the partial file, sets the export back to `pending`, queues the job again under the same key and returns normally.
  - The expiry sweep runs per active tenant, deletes the rows, then deletes the files after the commit; a failed file delete is logged and skipped.
- **Queue wiring**: the two new task names with their runtime and tenancy settings, both handlers in `createCoreTaskList` with a new trailing `filesBlobStorage` parameter, and the cron line `40 4 * * * tenantExportExpirySweep`.
- **API `accountHandler.ts`**:
  - `POST /api/account/exports` answers 202 when it creates an export and 200 when one is already active.
  - `GET /api/account/exports` lists the caller's unexpired exports.
  - `GET /api/account/exports/:id/download` answers the same 404 body for a missing, foreign, not-ready or expired id, and streams the file with the four required headers.
  - All three are mounted in the dispatcher, added to the route matrix and mapped to their handler file.
- **Dependency**: `yazl` and `@types/yazl`, with the lockfile updated.
- **ADR** `docs/adr/2026-10-17-tenant-data-export-archive.md`: how the table set and exclusions are chosen, the archive layout and `formatVersion`, one snapshot per export, the 7-day expiry, and why `yazl`.

## Gaps to decide on
- **A killed process leaves its export stuck in `running`.** Nothing moves it on, so that tenant cannot request another export until the row is cleaned up. The ADR states this; a sweep for stale `running` exports would be a separate issue.
- **A non-uuid id without a session gets 400, not 401**, because the issue orders `assertUuid` before `authenticateRequest`.
- **`blobCount` in the manifest counts the `blobs/` entries actually in the archive**; ids whose file was missing are only in `missingBlobIds`.
