## What was delivered

`GET /api/proposals/:id/options?field=<project|area|people|company|page|mcpProjects>[&includeDone=true]` returns the choices of one field of an Inbox proposal card in one fixed order: the card's current value first, then the assistant's suggestion, then targets by the number of edges of the card's own relation (most first), then by name; a "none" choice in a fixed place (last) for project, area and company only. Archived or trashed targets that are not the card's value are not listed; the card's own archived or trashed value is listed first with `disabled: true` and `disabledReason` `archived` or `deleted`; done projects are hidden unless `includeDone=true` or they are the card's value; a step that would create the item is listed with its `ref`, `suggested: true` (when not yet linked) and the localized hint "New - will be created" (en and cs catalog keys `options.none.<field>` and `options.newStep.hint`). A card of another tenant, a trashed card and an unknown id answer the same 404.

## Deviations from the specification and spec seams

1. `listProposalOptions` has a sixth parameter `includeDone` (the route needs it).
2. Spec seam: the route entry sits in `routeMatrix/proposals.ts`, not `routeMatrix.ts`; the `ROUTE_HANDLER_FILES` mapping was added.
3. The handler is exported by the module manifest, not the data barrel (`index.ts` not touched).
4. Choices where the issue is silent: the none choice exists for project, area and company only (people is a multi field, page is required, mcpProjects has none); the current value is read from the stored effective envelope plus the user's manual values, the suggestion from `aiProposal`; an item counts as the field's value when the primary step's relation (any key) or the editor value under the field's own key names it and it lives in the field's source database; a step that creates the item is the current value when the primary step links `{ref}` to it, otherwise suggested; usage is the number of edges of the relations between the card's destination database and the source database, counted on the source side, and is zero for page and mcpProjects and for a destination with no such relation (a Tasks card has no relation to Areas, so areas order by name); mcpProjects and page apply the same archived/deleted/done rules as project; the page field lists Projects, Areas and non-trashed subpages; the hint text is "New - will be created"; `includeDone` other than `true` is a 400.
5. The archived/deleted evaluation was moved into `relationTargetBlock` so the route uses "the same evaluation" as relation validation. The Touches list omits `relationsStore.ts`, `relationOps.ts` and `relationTargetState.ts`; Task step 1 requires them.
6. No cap on the number of options: every live item of the source databases is listed.
