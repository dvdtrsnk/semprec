## What was delivered

- `GET /api/transcript-summaries?eventIds=<uuid,...>` answers `{ [eventId]: { count, doneCount } }` with one key per requested id, in one call. `count` is the number of live transcripts linked to the event through the Transcripts `event` relation; `doneCount` is the subset whose status is `done`.
- Only live Events and live transcripts of the tenant in scope are counted. An id that is unknown, another tenant's, in the Trash or a live item that is not an Event answers `{ count: 0, doneCount: 0 }`. A foreign id and a random id get the same status, body and headers.
- `eventIds` is one comma-separated query parameter of 1 to 100 distinct UUIDs. A missing, repeated or empty parameter, an empty entry (a trailing comma), more than 100 ids, an entry that is not a UUID and an id given twice (compared without regard to letter case) answer 400 `validation_failed` with `details.field` equal to `eventIds`. The refusal happens before any statement runs.
- Each answer is keyed by the id exactly as the caller wrote it, so an upper-case id keeps its upper-case key.
- The counts come from one SQL statement inside `withTransaction`: it resolves the Transcripts `event` relation from the catalog and aggregates `item_relations` joined with `items`. Every table reference is filtered by `tenant_id = app_tenant_default()`.
