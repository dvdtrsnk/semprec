## Summary

Adds `deploy/deploy.sh <tag>`, which deploys one release tag as an immutable directory under `/opt/semprec/releases/<tag>` and then atomically repoints the `current` symlink at it (issue #190).

The script runs these steps in order:

1. **Validates the tag.** It must match `vMAJOR.MINOR.PATCH`. It must be an annotated tag fetched from `origin` without force, and it must point at a commit on `main`. `releases/<tag>` must not already exist, because releases are immutable. A lock file stops two deploys from running at once.
2. **Stages the release.** `git archive` exports the tagged commit into a hidden `releases/.<tag>.partial.*` directory. It is an export, not a checkout, so nothing can be pulled into it. The backend is installed with `pnpm install --frozen-lockfile --package-import-method=copy` and built with `pnpm -r run build`, and a non-secret `release.env` is written containing `APP_VERSION=<tag>`.
3. **Runs forward migrations** while the old release keeps serving traffic. They run in a transient `systemd-run` unit that loads `/opt/semprec/shared/.env` itself and connects with the new `SEMPREC_MIGRATE_DATABASE_URL`. The script never reads, copies or prints the shared `.env`.
4. **Activates.** The staging directory is renamed to `releases/<tag>`, and then `current` is replaced with a single `rename(2)` (`ln -sfn` + `mv -T`).
5. **Restarts** `semprec-ai-gateway`, `semprec-api`, `semprec-agents`, `semprec-transcribe` and every active `semprec-mailsync@` instance. It prints the `APP_VERSION` of each running process and fails unless they all report the deployed tag.

Any failure in steps 1–3 removes the staging directory and exits non-zero. `current` and the services are left untouched.

The five service units now load `EnvironmentFile=/opt/semprec/current/release.env` after the shared `.env`, so each process's version comes from the release it runs from.

## Acceptance criteria → tests

`deploy/deploy.test.sh` is a hermetic test. It uses real git repositories (a bare origin, tags on `main` and off `main`) and mocks `pnpm`, `systemd-run` and `systemctl`:

- **Successful deploy reports one version across processes:** all four services plus the mailsync instance are restarted, and each one reports the deployed tag. The mocked restart builds each process's environment from `current/release.env`, so this check really depends on the symlink.
- **A failure before activation leaves `current` and the services unchanged:** a build failure and a migration failure each leave `current` on the previous release. No `releases/<tag>` directory and no partial directory remain, and no `systemctl restart` is issued. Malformed, lightweight, off-`main`, missing and already-deployed tags are all rejected.
- **`current` never targets a partial build:** the `pnpm` and `systemd-run` mocks record a violation if `current` resolves to the directory being prepared. I confirmed this check fails the test by moving the swap ahead of the build in a scratch copy of the script.
- **All process types restart and shared secrets persist:** the shared `.env` checksum is unchanged after every run, no release contains a `.env`, and the deploy output never includes the secret value.

`provision.test.sh` now also checks that every unit loads `release.env`.

## Operator notes

- **Existing hosts:**
  - Rerun `provision.sh` to install the updated units.
  - Add `SEMPREC_MIGRATE_DATABASE_URL` to the existing shared `.env` by hand; provisioning never rewrites that file.
- **Failure after the switch:** if a service fails to restart or reports a different version, the deploy exits non-zero, but `current` already names the new release. It does not roll itself back; rollback mode is #191.
