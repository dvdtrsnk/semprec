## What was delivered

An external AI client on `/mcp` (the human-token branch of `resolveActor`) is refused sensitive databases by default, with the same database-level decision the agent grants of gh-1810 make for a Semp run.

- `AuthenticatedActor.externalClient` (`packages/shared/src/genericOperations/actor.ts`) is set only in the human-token branch of `resolveActor` in `mcp/mcpHandler.ts`; `writerIdentityOf` carries it to `WriterIdentity.externalClient`. A run credential, a REST session and an agent tool do not carry it; the input schemas reject an actor field.
- `DatabaseReader` (an agent project id string, or `{ externalClient: true }`) and `readerOfWriter` are exported from `@semprec/data`. `assertReaderDatabaseAccess` decides the external client by the database alone: a sensitive database is refused for read and write and no grant applies; `assertWriterDatabaseAccess` and `listUnreadableDatabaseIds` handle it. A run credential keeps the behavior of gh-1810 unchanged.
- Covered paths (the marker only, in the transaction of each operation): item get/find/list, `database.query`, `view.query` (a curated view drops sensitive members), `relation.list` and hidden edges, expansion hiding of relation targets (`{ id, hidden: true }`), value-link sources, `database.get` (forbidden), `database.list` and the schema projection (new `externalClient` option), item create/patch/delete/restore with cascade, relation writes on both endpoints, link unlink/relink; after the review also `item.count`, `database.facets`, the property operations, view operations, `viewItem` operations, `database.patch/archive/restore`, `database.create` under an item, and all page operations (`page.get`, changes, ensure, createSubpage, insert, duplicate, rename, restoreVersion, replace). `chokePoint/readerObjectAccess.ts` holds the id-to-database resolution. `resolvePageOwnerDatabase` is the single page-owner resolver: `assertAgentPageAccess` takes a `DatabaseReader`, and `page.get` hides a breadcrumb ancestor in an unreadable database for an external client as for an agent.
- ADR `docs/adr/2026-11-13-an-external-ai-client-on-mcp-is-refused-sensitive-databases.md` records the decision (it delivers what the gh-1810 ADR deferred; the gh-1810 ADR body is unchanged).

## Entry points and contracts dependents build on

- From `@semprec/data`: `readerOfWriter`, types `DatabaseReader` and `ExternalClientReader` (and the frozen export list of `publicSurface.test.ts`). `ListItemsInput.agentProjectItemId` was renamed `reader`; the read paths take a `DatabaseReader`, so callers that pass a project id string keep working.

- REST for the same token is unchanged: it reads and lists sensitive databases as before. No route, table, job or migration was added.

## Deviations and spec seams

1. Over `/mcp` a refusal is the JSON-RPC error with `data.code: forbidden` in an HTTP 200 response, not an HTTP 403; the Task limits the `mcpHandler.ts` change to the actor marker. The error itself is status 403 (asserted at the gateway level).
2. The read paths of gh-1810 took `agentProjectItemId?: string`; they now take a `DatabaseReader`.
3. Files outside the Task's Touches list were changed: the choke point read and relation files, `writerKind.ts`, `shared/genericOperations/actor.ts` (the actor type lives there, not in `port.ts`), the data barrel and `publicSurface.test.ts`.
4. The schema projection got an `externalClient` option with no production caller.
5. The worker first held that `/mcp` serves no schema or page operation; the security review showed the generic gateway dispatches them for a human token, and the fix round covered them. Operations that the gateway serves over REST only (`property.option.*` and `page.replace` over the generic operations) are not reachable from `/mcp`; the data-layer `replacePageMarkdown` reads its reader from its writer.
6. Behavior change in the last fix: the page of an item in a non-sensitive database nested under a sensitive record is now decided by its own database, as every item read is, and the sensitive ancestor is hidden in the breadcrumbs; subpages of a sensitive record stay refused. `viewItem` and `database.create` under an item still walk the ancestor path, so the two checks differ there (the ADR says so).
7. The commit trailers of the source commits name Claude Sonnet 5.5 rather than the line the task text names.
