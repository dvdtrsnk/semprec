## Delivered behavior

Property create and config patch validate `config.default`: select/multi_select accept a single option key, checkbox a boolean, number a finite number, text a string, and date only `today` with includeTime disabled or absent. Unsupported types and null defaults are rejected with `validation_failed` on `config`.

`createItemWithClient` fills only keys absent from the input. Explicit values (including null, false, zero and empty strings) survive. The shared item store invokes the create-properties resolver after idempotency reservation, so a replay returns before defaults or timezone reads, including when requests race for the same key. No default logic was added to item patch. Inputs are copied rather than mutated. Multiple `today` defaults in one insert use the same date, resolved through `getSystemTimezone` and Luxon as YYYY-MM-DD.

Fresh seeds configure exactly Projects.status=inProgress, Tasks.status=notDone, Areas.active=true, Files.date=today, Books.status=toRead and Movies.status=planned. The registered runtime-role per-tenant cutover adds only absent default keys, skips missing database/property records and preserves all existing config keys/defaults. It does not backfill item values. `resolveProperty` exposes stored defaults in optional `config.default` for the six supported types; schema HTTP tests verify Projects and the unresolved Files token. The broader #1360 projection remains separate.

## Follow-on facts

Defaults apply to new items through the shared choke point, not pre-existing item rows or raw seed-only `insertItem` callers. Multi-select defaults are the single string required by this issue, not arrays. `today` stays a token in schema/config. Existing tenants need the registered deploy-time `runTenantCutoverMigrations` invocation before creates can use the six shipped defaults. Missing-property cutover skips do not create a schema.
