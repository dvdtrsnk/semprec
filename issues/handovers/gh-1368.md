# Handover for gh-1368

The `mcpInvoke` safe summary of an approval request now carries `mcpServerName` and `mcpToolName`, in both the pending queue list and the PATCH decision view. The `genericOperation` variant and every previous field are unchanged. Argument values are still never exposed.

Targeted checks pass: build, lint, prettier, and the integration tests `approvalRequestsQueue`, `approvalRequestsHandler` and `publicSurface` (32/32). I did not run the full `pnpm run verify`.

- **Name resolution:** the names are resolved at read time with two batched reads: `getItemsByIds` for the server items' `name`, and a new `getMcpToolRegistrationsByIds` in `mcpToolRegistrationsStore.ts` for the registrations' `tool_name`. A deleted server or a missing registration gives `null` for that field, and the response stays 200. `safeSummaryOf` stays pure and takes the resolved names as input.
- **API change:** `toApprovalRequestDecisionView` is now `async` and takes a `Queryable` as its first argument, `(client, request)`. The PATCH handler calls it inside the same transaction as the decision. Dependants that call it must pass a client.
- **Tests:**
  - `approvalRequestsQueue.test.ts` covers four cases: names present for every `triggeredBy` value, the decision view, a soft-deleted server (`mcpServerName` null, tool name kept), and a missing registration (`mcpToolName` null).
  - The existing fixtures that use random ids now expect `null` names.
  - `approvalRequestsHandler.test.ts` asserts the null names over HTTP with a 200.
