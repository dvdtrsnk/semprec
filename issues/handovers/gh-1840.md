## What was delivered

Two module agent tools of the sleep module, with the capabilities `sleep.read` and `sleep.write` declared in its manifest:

- `sleepNightsGet { from, to }`: the nights of a range (at most 62), the same answer as `GET /api/sleep/nights`.
- `sleepNightSet { night, ...fields }`: creates or updates one night's exception through `upsertSleepNight`, written at once with no approval (`approval: none`, `riskClass: write`) as writerKind `agent` with the run id, the project item id and the run's user, never as a human writer, and never deleting. The existing gh-1838 write hooks enqueue `sleep-resync:<tenantId>` in the write transaction.

Both tools take the project and the user from the stored run (no argument names a project, run or tenant), check the project's database grants in the transaction of the call (read on nights, settings and plans for the get; write on nights plus read on settings and plans for the set, so a call that changes nothing is refused too) and answer a JSON error result `{status, error, message, field?}` for any `ChokePointError` (403 forbidden, 400 validation_failed, 404 not_found). Other errors propagate. Success results are marked sensitive.

## Deviations and spec seams

1. The tool names are the literal `sleepNightsGet` / `sleepNightSet` from the issue; the handler exports are `createSleepNightsGetTool` / `createSleepNightSetTool`, because the export name `sleepNightsGet` is already the GET route factory in the same manifest module.
2. Capability presence follows the interim predicate named above.
3. `sleepNightSet` checks the write grant on nights and the read grant on settings and plans itself before `upsertSleepNight`, because the choke point checks the write grant only when it writes.
4. Success results carry `sensitive: true` per `docs/adr/2026-11-13-sensitive-tool-results-are-marked-by-the-tool-and-stored-redacted.md`; tool arguments stay stored as written until #2001.
5. The strict argument schemas check only types; the date and time forms are judged by the handler, which answers a 400 naming the field.
6. The session-level test stores grants with the statement of `setAgentDatabaseGrant`, as `sleepResyncWritePaths.test.ts` does, because the admin store is not exported.
