## What was delivered

Two read-only agent tools of the systemDatabases module, in `transcription/transcriptAgentTools.ts`:

- `transcript.get` (`createTranscriptGetTool`): returns the header, the speakers with labels, summary, decisions, action items with owner labels, the Event, `segmentCount` and `speakerCount`, composed through `readTranscriptDetail`, so speaker names, notes with names and the display name of gh-1830 are the same as in the detail endpoint.
- `transcript.segment.get` (`createTranscriptSegmentGetTool`): takes exactly one complete index pair (`fromIndex`, `toIndex`) or time pair (`startsAt`, `endsAt`), limit 200 segments or 15 minutes (`rangeTooLarge`), `context` default 3 and at most 3 added on top with `isContext`.
- Both run in the caller's tenant scope (fail closed without one), require a run of that tenant, check that the transcript is live, and write nothing. Both are declared in `seed/systemDatabasesModuleManifest.ts` `agentTools` with capability `core.item.read`, approval none, risk class read.

## Entry points and contracts dependents build on

- Factories `createTranscriptGetTool(pool)` and `createTranscriptSegmentGetTool(pool)`, each `(currentRunId, args) => { error, result }` with a JSON result; strict zod schemas `transcriptGetArgsSchema` (`transcriptId`) and `transcriptSegmentGetArgsSchema`; constants `TRANSCRIPT_SEGMENT_RANGE_MAX_SEGMENTS`, `TRANSCRIPT_SEGMENT_RANGE_MAX_SECONDS`, `TRANSCRIPT_SEGMENT_CONTEXT_DEFAULT`, `TRANSCRIPT_SEGMENT_CONTEXT_MAX`. The factories and schemas are re-exported in the manifest file's export block (the registry resolves handlers through it); they are not in the data barrel.
- Error results are JSON strings: `{error: not_found}`, `{error: run_not_found}`, `{error: validation_failed, reason: invalidArguments | rangeRequired | rangeInverted | rangeTooLarge, message, fields?}`. A foreign tenant's transcript, an unknown id and a trashed transcript all give `not_found`.
- Labels `agentTool.transcript.get.label` and `agentTool.transcript.segment.get.label` in `seed/i18n` cs and en. No table, route or job name was added. Session wiring, refs and search are out of scope and not delivered.

## Deviations and spec seams

1. The issue fixes only `validation_failed` with `rangeTooLarge`; the other reasons and `run_not_found` are additions compatible with it.
2. `from` and `to` in the segment result are the first and last index of the requested stretch without its context, null when it holds no segment; an index range past the end is clamped, a time range selects segments that overlap it strictly and must have a positive length.
3. A half pair counts as neither. The count limit applies to the requested index span and to the matched segments of a time range; the 15 minute limit to the requested seconds and, for an index range, to the span of its existing segments.
4. The tools read the whole detail composition (including playback and automation lookups) because the Task asks for the same read as the detail endpoint.
5. The commit trailer of the source commit names Claude Sonnet 5.5.
