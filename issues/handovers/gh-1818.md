## What was delivered

- `buildNewMeetingEnvelope` (`transcription/transcriptEventMatch.ts`) builds the envelope of a proposed new meeting: name from the catalog key `transcript.newMeeting.name` rendered in `users.locale` for the recording's local day and month, type `meeting`, wall-clock `date`, `timeFrom` and `timeTo` in the tenant time zone, `endDate` only when the recording crosses local midnight, and `relations.project` when a project applies.
- `readRecommendedEventProjectId` resolves the project of a recommended Event (a missing, trashed, foreign-database or project-less Event gives none). It has no production caller (see deviations).
- `confirmProposalWithClient` (`inbox/proposalActions.ts`) now writes in one transaction: the Event, its envelope relations, an Events `people` edge for every person a `Transcripts speakers` edge maps at that moment except the tenant's own person (`transcription/transcriptEventParticipants.ts`, `addSpeakersAsEventParticipants`; the edges are recorded in the card history `addedRelations` like the speaker-card confirm), and then the transcript event edge. The transcript row is locked before its speakers are read, and the person ids are written in sorted order.
- `assertValidEnvelopeForCard` checks a revised create-Event envelope of an event-role transcript card with the Events create rules (`assertEventCreateRules`, extracted from the Events create hook in `calendar/eventValidationHook.ts`, which still calls it) after the Events time transform. The tenant zone is read with `readProposalTimezone`, and only when the date carries an offset. The project must exist through the existing envelope relation check.
- `transcription/transcriptionLabels.ts` (`renderTranscriptionLabel`) renders the transcription catalog with placeholders.

## Entry points and contracts dependents build on

- Catalog keys (cs and en, `transcription/i18n`): `transcript.newMeeting.name` ("Meeting {day}/{month}" in en; the `de` locale falls back to English).
- No route, operation, table, migration or job name was added. The confirm and revise routes keep their contracts; a missing project answers 400 `validation_failed` with the card left proposed.
- gh-1830 builds on this: the proposed meeting is named after the transcript's name, else the rendered notes title, else this source's day-and-month name, and `buildNewMeetingEnvelope` throws on an empty name.

## Deviations and spec seams

1. Spec seam: the Task makes the call sites pass the recommended Event's project, but gh-1848 gives a recommended card a relation envelope that links the existing Event, so a card carries no project from the match. After review the always-null call was replaced by `projectId: null`, and the docstrings of `createTranscriptEventCard` and `readRecommendedEventProjectId` say that no card creation proposes a project. The resolver and the builder's project parameter are implemented and tested directly. A project reaches a card only through a user revise. The conflict between Task step 2 and gh-1848 still has to be recorded in the issue by its owner.
2. Files outside Touches: `calendar/eventValidationHook.ts`, `transcriptEventParticipants.ts`, `transcriptionLabels.ts` (siblings).
3. The confirm write order changed as the Task states: envelope relations and participants precede the transcript event edge.
4. A recording whose end is not later than its start on the wall clock (shorter than a minute, or ending in a repeated DST hour) proposes `timeTo` one minute after `timeFrom`; a recording ending exactly at local midnight gets `endDate` on the next day with `timeTo` 00:00. The repeated-DST-hour branch has no test of its own.
5. The commit trailer of the source commit names Claude Sonnet 5.5.
