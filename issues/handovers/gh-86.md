## Summary

Implements the per-document doc-history retention cleanup from issue #86, which #216 deliberately deferred: `doc_history_updates` was mirrored on every append but never deleted.

- `rebaselineDocHistory` (`backend/packages/data/src/docs/docHistory.ts`): per-document, single-transaction re-baseline at the retention cutoff. Reconstructs the exact document state at `cutoff = transaction_timestamp() - make_interval(hours => 24 * retentionDays)` from the current rolling baseline plus `doc_history_updates`, installs it as a new NULL-expiry baseline checkpoint, advances `docs.history_available_from` to `cutoff`, then deletes the history updates and older checkpoints (including the preceding NULL-expiry baseline) the new baseline makes redundant. No-op if `cutoff` doesn't advance past the doc's current `history_available_from`. Runs under the same `doc_snapshots` row lock append/compaction already use, so it can't race either.
- `runDocHistoryRetentionSweep`: per-doc sweep mirroring the existing compaction sweep pattern (failure-isolated per doc), wired into `handleDocHistoryCleanupTask` ahead of the existing expiry-based `cleanupExpiredDocHistory`, which is now correctly subordinate to it.
- New tests in `docs.test.ts` covering the no-op case, exact cutoff reconstruction/redundant-data deletion, the sweep, and the concurrency-exclusion lock, following the repo's frozen-clock UTC convention.
