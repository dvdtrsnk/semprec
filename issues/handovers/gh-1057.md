This exports the gateway endpoint table and adds a two-tenant isolation suite over all four endpoints. The suite found one real leak: a suspended tenant id could be told from an unknown one. Following #1057's Task step 4, the handlers were not changed in this pull request; #1191 (PR #1194, now merged into `develop`) fixed the leak in the gateway. This branch has `develop` merged in, and the suspended/unknown case is a normal passing test.

**`app.ts`**
- It now exports `GATEWAY_ENDPOINTS` and `GatewayEndpoint`, and `createDispatcher` routes through a `Record<GatewayEndpoint, handler>`.
- The two audio paths share one handler that keeps the concurrency limit and its 503. Any other path still gets the 404.

**`tenantIsolationGateway.test.ts`** (new)
- **Setup:** `SEMPREC_TENANT_SCOPE=strict` is set in `beforeAll` and restored in `afterAll`. The dispatcher runs on a `semprec_side` pool with counting fake providers, and tenant reads go through a `semprec_data` runtime-role pool.
- **Fixture:** tenants A and B are provisioned with `provisionTenant`, each with a project item, an agent run and a budget row. Tenant C has no budget row. A fourth tenant has a budget row, as a provisioned-then-suspended tenant would, and is suspended.
- **Exhaustiveness:** a `CASES` table is declared `satisfies Record<GatewayEndpoint, GatewayCase>`, so adding a path without a case fails the build. A test also checks that the table keys equal `GATEWAY_ENDPOINTS`.
- **Per endpoint:**
  - A's call writes exactly one row, visible only in A, with the right run or project id.
  - A malformed header gets 400.
  - A missing header gets a non-2xx response.
  - A suspended tenant and an unknown tenant are both refused with `403 attribution_refused`, with no row and no provider call.
  - "answers a suspended tenant exactly like an unknown tenant": the two responses are byte-identical (status, headers except `date`, body).
  - B's own exhausted cap refuses B while A still succeeds.
  - The refusal bodies for an own cap, a missing budget row and the global cap are byte-identical.
- **Foreign ids:** for the complete and pi-messages endpoints, B naming A's id gets exactly what B naming a random UUID gets (`403 attribution_refused`). No row is written in any tenant and no provider is called.

**The leak the suite found, and its fix**
Before #1191, a suspended tenant passed the budget gate (it has a budget row) and was refused by `reserveGatewayCall`'s `status = 'active'` predicate with `403 attribution_refused`, while an unknown tenant had no budget row and was refused by `assertWithinBudget` with `403 budget_exceeded`. #1191 added `assertGatewayTenantActive` before the budget gate in the gateway's `reserve()`, so both now get the same `403 attribution_refused`, and this suite asserts it.

Spend is seeded with raw SQL on the admin pool, because the gateway cannot produce a controlled cost. A comment beside the SQL says so.
