## Parse JSONB-backed values in `packages/data` instead of casting them (#655)

Six places in `packages/data` read JSONB values with a cast and never checked them. Each one is now validated where it is read, so a malformed stored value fails with a named error instead of carrying a wrong type further into the code. The one exception is proposal history, where the reader already promised to tolerate bad data.

### Changes
- **`mail/personLinkingActions.ts`** — Added `personEmailReindexActionConfigSchema` and `linkEmailToPeopleActionConfigSchema` (zod). The two exported config types now come from them via `z.infer`, with the same names as before. Both `as unknown as` casts are now `safeParse`. On failure the handler throws `Malformed action config for <actionId>: …`, so the heartbeat sweep records a normal heartbeat failure instead of a `NotFoundError` from a query run with `undefined`.
- **`rollup/config.ts` `applyRollupConfig`** — `relationPropertyKey` and `targetDatabaseId` are now checked with `typeof` instead of cast. A non-string key finds no relation property, so `validateRollupConfig` throws its usual `ValidationError`.
- **`inbox/inboxTickAction.ts`** — New exports `proposalEnvelopeSchema` and `parseStoredProposalEnvelope(value, proposalId)`:
  - `null` or `undefined` → `null`.
  - Anything else malformed throws `Malformed proposal envelope on proposal <id>`.

  `ProposalEnvelope` and `ProposalHistoryEntry` are now `z.infer` types with the same shape as before. `appendHistoryEntry` parses the stored history with `z.array(proposalHistoryEntrySchema)`. If that fails, including for a non-array, it starts from an empty history, which is what its doc comment already promises.
- **`inbox/proposalActions.ts`** — The two stored-envelope reads (transcript card role check and confirm) now use `parseStoredProposalEnvelope`. The `Proposal has no computed envelope to confirm` branch is unchanged.
- **`systemSettings.ts`** — Both readers now query `properties` as `Record<string, unknown>` and pass it through a new private `toSettingsProperties`, which uses `assertShape`:
  - `timezone` must be absent or a string.
  - Each budget must be absent, `null` or a finite number.
  - Anything else throws `Malformed system settings properties in database row`.

  Public signatures and defaults are unchanged: `Europe/Prague`, a daily budget of 50, and explicit `null` meaning uncapped.
