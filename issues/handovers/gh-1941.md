## What was delivered

- `coreAgentRunAction` takes `CoreAgentRunDependencies { answerExpectedGate, runProjectResolvers }`. The config key `runProject: { resolver: "mailThreadProject" }` moves an item-triggered run to the `Threads.project` of the message's thread (a live project, else the heartbeat's own project, in practice the Email project); the run row and the agent session use it, and a retry keeps the retried run's project.
- `scheduler/answerExpectedFilter.ts` (config key `answerExpectedFilter`): after the sender gate it plans the run in a repeatable-read transaction (the message is the newest incoming message of its thread, no draft exists for the same thread and source message, the open agent draft was not edited by the user), asks the AI gateway outside any transaction (feature key `mailAnswerExpected`, schema `{ expectsReply: boolean }`, the newest 5 messages cut to 1500 characters, the sender), plans again after the answer and appends a task note naming `mail.draft.create` or the open draft id for `mail.draft.update`. `false`, an invalid answer or `budget_exceeded` start no run and write no error row; other gateway failures propagate to the queue.
- `mail.draft.create` in reply and reply-all mode refuses a thread that has an open agent draft with 409 `mail_agent_draft_exists` naming `draftId` (`mailDraftsStore` `findOpenAgentDraftOfThread` and `hasDraftOfSourceMessage`, alias-aware). A forward keeps the draft store's 409.
- `mail.draft.update` refuses, with 409 `mail_draft_edited_by_user` and no write, a run started by a heartbeat (directly or through a delegation) when the draft's last editor is the user; the check is made under the draft's locks. A run a person asked for (a chat turn, an MCP client) may still rewrite it (fix round).
- The seeded `newEmail` heartbeat gets `answerExpectedFilter` and `runProject`; the Email project's guidance names `mail.thread.get`, `mail.draft.create`, `mail.draft.update` and `mail.draft.send`.
- Cutovers `runNewEmailDraftCutoverMigration` (adds the two keys when missing, idempotent) and `runEmailGuidanceCutoverMigration` (rewrites the Email guidance only when it equals the stored conversion of a previously seeded text), registered in `runTenantCutoverMigrations` after the gh-2034 and gh-1901 entries and before the area-note cutover.
- semprec-agents passes an `AiGatewayClientPort` (`createAiGatewayClientForAgents` over `@semprec/ai-gateway-client`, a new workspace dependency and lockfile importer entry) into `createAgentsActionRegistry`; the gateway allow-list gained `mailAnswerExpected`.
- ADR `docs/adr/2026-11-14-a-heartbeat-agent-run-takes-composition-root-dependencies-and-may-run-in-the-project-of-its-item.md`.

## Deviations from the specification and spec seams

1. The original Email guidance seed lives in `seed/systemProjectAgentGuidance.ts`, not `seed/seedEmailModule.ts`.
2. `coreAgentRunAction` cannot import the mail module (`scheduler/actions.ts` is imported by `chokePoint/hooks.ts` and `chokePointDeps.ts`, which closed a `no-choke-point-rollup-cycle`); the resolver table and the gate are injected (`CoreAgentRunDependencies`) and composed by `mail/newEmailAgentRun.ts`, recorded in the ADR.
3. The guidance cutover accepts the stored conversion of both texts the Email project was ever seeded with, since both are unedited seeds.
4. `newEmailDraftCutoverMigration` also adds `answerExpectedFilter` (the Task's cutover step names only `runProject`); without it existing tenants would never run the gate.
5. The one-draft-per-thread guard applies to reply and reply-all; a concurrent create still ends in the draft store's 409 through the unique index.
6. New gateway operation `mailAnswerExpected` and a workspace dependency of semprec-agents on `@semprec/ai-gateway-client`.
7. The task note appended to the run's task is how "the task names its draft id" is delivered; the seeded task text is unchanged.
8. Existing tests changed: `newEmailHeartbeat.test.ts`, `systemProjectAgentGuidanceSeeding.test.ts`, `publicSurface.test.ts`, `actionRegistryComposition.test.ts`, `completeHandler.test.ts`.
9. The user-edit refusal of `mail.draft.update` was added by the fix round and applies only to heartbeat-started runs; a heartbeat fired manually by a person is also treated as a heartbeat run (safe side).
10. The shared-file ordering blocker gh-1939 is not landed; its entries in `db/tenantCutoverMigrations.ts` and `domainWriteHooks.ts` go before the two gh-1941 entries when it lands.

## Criteria NOT RUN or BLOCKED

None by evidence row. Limitation stated in the code and the ADR (not a criterion failure): a run in a thread's own project holds the mail tools only when that project holds the mail capabilities, which today follow from owning the mail databases (`generatePermissionManifest`); per-database project grants (#1810) are not in the tree, so for a thread in an ordinary user project the agent runs without `mail.draft.*`. A test pins the real module tool list for that case. Nothing ran against a live model, gateway provider or mail account.
