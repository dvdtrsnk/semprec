# Handover for gh-1478

Connections to tenant-chosen IMAP and SMTP hosts now go through the outbound address policy. The name is resolved once, the socket connects only to the vetted address, and the TLS server name stays the host. Nothing calls the factories yet outside the tests.

## What was added
- **`backend/packages/data/src/mail/mailServerConnections.ts`**:
  - `openImapConnection(settings, credential, options?)` builds an `ImapFlow` with `tls.lookup` set to the policy lookup and `tls.servername` set to the host. It calls `connect()`, and resolves with an `ImapFlowMailClient` on success.
  - `createSmtpTransporter(settings, credential, options?)` returns a `MailSmtpTransporter` (`verify`, `sendMail`, `close`). Its nodemailer transport opens each socket through `getSocket`: `net.connect({ host, port, lookup })`, handed over connected. nodemailer then runs TLS (`security: tls`, `secure`) or STARTTLS (`security: starttls`, `requireTLS`) with the host as the server name.
  - `settings` is `{ endpoint: MailServerEndpoint, username }`. `credential` is `{ password }`: tenant hosts take an app-specific password, since the settings store holds no OAuth token. `options.policy` is optional and defaults to `currentOutboundAddressPolicy()`.
- **Error mapping.** Every refusal and every connect or TLS failure rejects with `MailServerUnreachableError` (`code: "mail_server_unreachable"`, added to `providerTypes.ts`). The error has no cause and no address in its message. The host name and the error's name and code are logged; the resolved address is never logged or returned. Authentication failures are not mapped: imapflow's `authenticationFailed` and nodemailer's `EAUTH` pass through unchanged.
- **IP literals.** A literal host never reaches the lookup, so both factories refuse one before any socket opens unless the policy allows literals. The default policy allows none.
- **`backend/packages/data/src/net/outboundAddressPolicy.ts`**: `createPolicyLookup` is exported. Nothing else in that module changed.
- **Exports** from `backend/packages/data/src/index.ts`: `openImapConnection`, `createSmtpTransporter`, `MailServerUnreachableError`, and the types `MailServerConnectionSettings`, `MailServerConnectionOptions`, `MailServerCredential`, `MailSmtpTransporter`. The three runtime names are listed in `publicSurface.test.ts`.
- **ADR `docs/adr/2026-10-29-mail-connections-through-the-outbound-address-policy.md`** (`accepted`). It delivers the known gap in [[2026-10-16-connect-time-outbound-address-checks]] and references it. The connect-time ADR is unchanged.

## Tests
`mailServerConnections.test.ts` (integration tier, 24 cases) uses a DNS stub, fake IMAP and SMTP servers on loopback, and test certificates made with `openssl` at run time. It passes with `publicSurface.test.ts`. The cases cover:
- Refused addresses (`127.0.0.1`, `10.0.0.1`, `169.254.169.254`, `::1`) and IP literals under the default policy. The refusal is the same error class and message as a closed port, has no cause, and no connection reaches the fake server.
- The host name is resolved exactly once per connection (the stub's call log).
- Success over TLS: the server sees the host name as SNI, and the login completes.
- A certificate for another name is refused, and the handshake never completes. The same handshake succeeds with the certificate for the host.
- A rejected login is not `mail_server_unreachable`.
- A public name: the lookup passed to `tls.connect` vets `93.184.216.34` and keeps the host name as the server name.
- SMTP `verify` and `sendMail` map the same way; SMTP `verify` succeeds over implicit TLS.
- STARTTLS, both protocols: the server refusing the upgrade (SMTP) or not offering it (IMAP) maps to `mail_server_unreachable`.

Coverage gaps: a successful STARTTLS upgrade is not exercised, because the fake servers do not perform one; only the refusal path is. The literal check was confirmed by disabling it, which made both literal tests fail.

## Notes for dependants
- **#1510 (IMAP sync), #1569 (credential check), #1634 (SMTP send)**: open connections only through these factories. Do not construct `ImapFlow` or a nodemailer transport for a tenant host. Keep the mapped error as it is: do not re-label it, attach a cause, or echo the host's address in a response. The status mapping of `mail_server_unreachable` belongs to #1569.
- **`MailSmtpTransporter.sendMail` returns `Promise<void>`.** It is not a drop-in for `Pick<Transporter, "sendMail">` in `mail/smtpClient.ts`, whose `sendMail` resolves `SentMessageInfo`. #1634 adapts it when it wires `NodemailerSmtpClient`.
- **SMTP error codes.** nodemailer overwrites the code of socket and TLS errors with `ESOCKET` or `ECONNECTION`, so the TLS cause is not visible on SMTP. A connection reset after the message was sent maps to `mail_server_unreachable` too. Treat that outcome as "delivery unknown", not "not sent".
- **Logging.** imapflow's logger is disabled in the factory, because its console output carries protocol traffic. Add logging in the caller with ids and counts only.
- **Not in scope:** OAuth2 for tenant hosts, and any IMAP or SMTP route. Host egress filtering stays the second layer.
