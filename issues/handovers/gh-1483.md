# gh-1483 — one-time OAuth states for mailbox connection

Repository-Issue: gh-1483

## Delivered behavior and production wiring

- Migration `0110_mail_oauth_states.sql` creates the tenant table `mail_oauth_states` (RLS policies and grants as `tenant_exports`): `id`, `tenant_id`, `user_id` (plain FK plus the `(tenant_id, user_id)` composite twin required by the tenancy catalog), `provider` (`gmail`|`outlook`), nullable `mailbox_item_id` (no foreign key, like `mail_drafts`), `state_hash`, `code_verifier_ciphertext`, `code_verifier_nonce`, `created_at`, `expires_at` (default now + 10 minutes) and nullable `used_at`. The unique index on the state hash is `(tenant_id, state_hash)`, because the catalog requires tenant-leading unique indexes.
- `mail/mailOauthStatesStore.ts`: `createMailOauthState(client, { userId, provider, mailboxItemId })` returns `{ state, codeChallenge }` (S256). Only the SHA-256 hex hash of `state` is stored; the verifier is sealed under the tenant data key with associated data `semprec:mail-oauth-state:v1:<tenantId>:<rowId>`. `consumeMailOauthState(client, { state, userId })` is one `UPDATE ... RETURNING` guarded by hash, user, `used_at IS NULL` and `expires_at > now()`; it returns `{ provider, mailboxItemId, codeVerifier }` or `null`. If a found verifier cannot be opened it throws, so the caller's transaction rolls the consumption back.
- `mail/mailOauthStatesSweep.ts`: `handleMailOauthStatesSweepTask(pool)` runs `forEachActiveTenant`, one transaction per tenant, deleting expired rows and rows used over an hour ago. Registered as `CORE_TASK_NAMES.MAIL_OAUTH_STATES_SWEEP` (`mailOauthStatesSweep`, api affinity, `system` tenancy), crontab `*/10 * * * *` and a handler in `worker.ts`.
- `mail_oauth_states` is in `EXPORT_EXCLUDED_TABLES`.
- Not exported from the `@semprec/data` barrel (no other mail store of this kind is needed there until #1686 imports it).
