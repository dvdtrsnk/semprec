# Handover for gh-1359

Archived databases are now invisible to rollups, and archiving or restoring a database recounts the rollups that aggregate it. Targeted checks run: the rollup, database operation and public surface tests, eslint, prettier and `tsc` on `packages/data`. The full `pnpm run verify` was not run.

**What changed**
- **`rollup/recompute.ts`:** `recomputeRollupCell` skips targets whose database has `archived_at IS NOT NULL` (`NOT EXISTS` on `databases`), so an archived source database aggregates as `count` 0 and `null` for the other aggregations.
- **`rollup/dependencies.ts`:** new `findDependenciesBySourceDatabase(client, sourceDatabaseId)`. It is exported through `index.ts`, so the frozen list in `publicSurface.test.ts` gained the name.
- **`chokePoint/databaseOps.ts`:** `databaseArchiveWithClient` and `restoreDatabase` call a private helper that enqueues `enqueueRollupBackfill` for every dependent rollup property, in the same transaction. Zero dependencies enqueues nothing. The job key is per property, so a repeated request does not queue a second job. The approved `database.archive` path uses `databaseArchiveWithClient` and behaves the same.

**Tests**
- `rollup.test.ts` has a new "archived source databases" block:
  - count and sum drop on archive and return on restore;
  - one full job per dependent property, and none for a database no rollup aggregates;
  - no second job on a repeated archive;
  - the approved-operation path via `databaseArchiveWithClient`.
- A test calling `databaseArchiveWithClient` directly must wrap it in `inTenantZero`, otherwise the queued jobs land on a lane the test worker does not drain.

**Notes for dependants**
- Other readers (inline relation expansion, related counts, collection counts, search) still need their own archived-database filter, as the issue states.
