# Handover for gh-1510

IMAP-mode mailboxes sync now. `createMailSyncAdapters` fills `createImapClient`: it reads the mailbox's stored server settings (gh-1473), opens the connection through the address-checked factory (gh-1478), and maps the failures the sync job acts on. The sync job closes the connection after every pass, on success and on failure. The same change fixes a deadlock in `ImapFlowMailClient.fetchMessagesSince` that stopped every pass from completing; see below.

## What was added
- **`backend/services/semprec-api/src/mailSyncAdapters.ts`**: `createImapClient` is always present, since it needs no OAuth key.
  - `openMailboxImapClient` reads `getMailServerSettings`. A mailbox with no IMAP endpoint fails with `Mailbox <id> has no IMAP server settings; set the IMAP host before syncing it`. Otherwise it calls `openImapConnection` with the stored endpoint, the stored username and the decrypted password.
  - `classifyImapConnectError` maps two failures, and passes every other error through unchanged (including `MailServerUnreachableError` from gh-1478):
    - `isImapConnectionLimitError` becomes `MailConnectionLimitError`, with the message "The IMAP server reports too many simultaneous connections for this account".
    - imapflow's `authenticationFailed` becomes `MailReauthorizationRequiredError`, with the message "The IMAP server rejected the stored login; reauthorize the mailbox".
- **`ImapMailClient.close()`** (`imapReconcile.ts`): a required method on the interface.
- **`ImapFlowMailClient.close()`** (`imapFlowClient.ts`): sends LOGOUT, waits up to `IMAP_LOGOUT_TIMEOUT_MS` (10 s), then closes the socket whether or not LOGOUT answered. It never rejects.
- **`mailSyncJob.ts`**: the IMAP branch closes the client in a `finally` around `reconcileImapAccount`. The pass's own error still propagates.
- **Exports** from `@semprec/data`: `MailConnectionLimitError`, `MailReauthorizationRequiredError`, `isImapConnectionLimitError` and the type `ImapMailClient`. `testSupport` exports `stubDnsLookup`. `publicSurface.test.ts` lists the three runtime names.

### Fix in `ImapFlowMailClient.fetchMessagesSince`
The loop parsed each message inside the `for await` over `client.fetch`, and parsing downloads the body. imapflow keeps a FETCH open until its consumer has read every untagged response, so the body download queued behind that FETCH and never ran. The first run of the new test hung for five minutes until the job was aborted. The loop now collects the raw responses and parses them after the FETCH ends. The raw responses hold only envelope, structure and header data, so the buffer is header-sized. No test had run this method against a server before this issue. The acceptance criterion "a sync pass downloads its mail" cannot be met without this change, so it is in this commit. A reviewer may prefer it split out.

### Changes outside the Touches list
- `mailSync.test.ts`: every typed `ImapMailClient` fake in the file gains `close: async () => {}`, since the interface now requires it.
- `index.ts`, `testDb.ts` and `publicSurface.test.ts`: needed for the exports and the test seam above.

## Tests
`services/semprec-api/src/__tests__/mailSyncAdapters.test.ts`, `describe("IMAP-mode accounts (issue #1510)")`, seven cases (one `it.each` over two addresses). The fake is a TLS IMAP server on loopback that answers CAPABILITY, LOGIN, LIST, LSUB, SELECT, UID SEARCH, UID FETCH, NOOP and LOGOUT. Its certificate is made with openssl at test time. Connections are redirected to the fake's port through a wrapper on `tls.connect`, which keeps the host name for SNI and the lookup. `stubDnsLookup` resolves the host to the chosen address. The cases:
- A pass ingests both messages from the stored settings, and the socket closes after LOGOUT.
- A host resolving to `127.0.0.1` or `10.0.0.1` fails with the `mail_server_unreachable` message, and the server accepts no TCP connection.
- A rejected login marks the account `needsReauthorization`, and the recorded error contains neither password.
- A BYE of "Too many simultaneous connections" gives `error` with the connection-limit message, and `next_expected_activity_at` is in the future.
- A SELECT the server refuses makes the pass throw, and the socket still closes. The recorded error contains no password.
- A mailbox with no IMAP settings gets the configuration error, which names the mailbox.

Also passing: `mailSync.test.ts` (130 tests), `mailServerConnections.test.ts`, `publicSurface.test.ts`, `imapFlowClientReplyTo.unit.test.ts`, `imapIdleClient.unit.test.ts`. The write-safety check reports the baseline unchanged, and the dependency-boundary check finds no violations. Lint, format and both typechecks pass on the touched files. The full `pnpm run verify` was not run. `web/` and `mobile/` are not touched.

Coverage gaps:
- The fake does not advertise STARTTLS, so `security: starttls` for IMAP (`doSTARTTLS` in `openImapConnection`) is not exercised end to end.
- No test message carries an attachment, so the attachment download path through this client is not exercised.
- The fake does not implement IDLE.

## Notes for dependants
- Every `ImapMailClient` must implement `close()`. A fake that omits it fails to typecheck.
- `fetchMessagesSince` must not issue a command inside its FETCH loop. Keep the order: collect the FETCH responses, then parse them.
- The sync job closes its client once per pass. Code that opens an IMAP client elsewhere (IDLE #1550, the credential check #1569, flag moves #1746) must close it itself.
- `classifyImapConnectError` maps only imapflow's `authenticationFailed` and the connection-limit reason. The credential check (#1569) should map its failures to the same two classes, so an account that fails verification reads the same as one that fails sync.
- The `last_error` of a rejected login is the fixed text in this file, not imapflow's message.
- `createImapClient` reads the settings through the api `pool` under the ambient tenant scope that the sync job provides. A caller outside the job needs its own tenant scope.
- Known gap, not fixed here: `fetchMessagesSince` holds every response of a mailbox in memory before it parses them, and has no cap on the message count. The gh-1505 and gh-1508 handovers record the same class of gap for their clients. The header buffer added here is bounded per message, not per mailbox.
- Each IMAP step is bounded: the connect and greeting timeouts from gh-1478, the 30 s partial-fetch and flag-fetch step timeouts, and the 10 s LOGOUT timeout.
