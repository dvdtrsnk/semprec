## What was delivered

The calendar timeline (`GET` timeline route, compact shape, Journal day source) now expands a recurring Event series into one entry per occurrence in the requested range.

- `expandEventOccurrences(client, eventsDatabaseId, seriesRows, { from, to, timezone })` (`calendar/eventOccurrences.ts`): per live series, a virtual entry (id `<seriesId>@<date>`, `readOnly: true`, `overridden: false`, the series' details with that occurrence's `date` and `endDate`, no transcript) for every rule date that has no occurrence item; the occurrence item itself (real id, `overridden: true`) when its own days overlap the range, so a moved occurrence is shown once where it is; nothing for a date whose occurrence item is in the Trash; at most `MAX_OCCURRENCES_PER_SERIES` (100) entries per series, earliest first. `readLiveEventSeries` batch-loads the series. The number of statements does not depend on the number of series (tested).
- A real occurrence entry carries the transcript of its Event, read with the exported `readEventTranscripts` in one statement; virtual entries have `transcript: null`.
- New timeline source `calendar/timelineEventOccurrenceSource.ts`, registered after the sleep source (`timelineSources.ts`). The core Events source of `timelineRead.ts` skips an Event that is a recurring series or has a `seriesId`; an Event whose stored recurrence is not a rule, or whose `seriesId` is JSON null with a rule, stays a stored Event shown once.
- Entries are typed `CalendarEventOccurrence` (carries `seriesId`, `occurrenceDate`, `overridden`); the compact shape of an occurrence carries `seriesId` and `occurrenceDate`.

## Deviations from the specification and spec seams

1. Signature seam: the Task writes `expandEventOccurrences(series, from, to)`; the function needs the client, the Events database id and the time zone, so it takes `(client, eventsDatabaseId, seriesRows, { from, to, timezone })`.
2. A real occurrence item is placed by its own days, not by its rule date, so a moved occurrence appears where it is, once (recorded in the ADR; the issue does not say).
3. The new module `calendar/eventSeries.ts` is outside Touches; it is shared by the core exclusion, the expansion and the materialization.
4. An Event whose stored recurrence is not a rule stays a stored Event, otherwise it would vanish from the timeline.
5. `timelineRead.ts` exports more internals; `CalendarTimelineCompactItem` gets optional `seriesId` and `occurrenceDate`.
6. The Task text "a range of 93 days returns at most 100 entries": the function does not clamp the range (the route bounds it, per the timeline ADR) and caps entries per series at 100.
7. `timelineSleepSource.test.ts` keyed on the whole source list; its assertion became `slice(0, 5)`.
