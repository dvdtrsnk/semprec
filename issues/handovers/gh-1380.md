# Handover for gh-1380

Added the ADR `docs/adr/2026-10-25-thread-may-split-an-inbox-source.md` (accepted, area backend). Documentation only; no code or tests changed. Prettier could not be run in the sandbox (registry blocked).

**Decisions recorded**
- The thread's agent tool never creates cards; it calls the Inbox-module action `splitInboxSourceWithClient` in a user-context request. This is a narrow named exception to "tick is the only producer of `kind: inbox` cards"; the older ADRs are not edited.
- The first card stays the primary card, the only one the tick recomputes. Siblings carry the system property `splitFromProposalId`; `findExistingProposal` and the tick ignore them. Siblings are recomputed only on explicit request.
- Limits: one in-flight split per primary card (row lock), refused when the primary is `confirmed` or `rejected`, at most 10 cards per split in total (primary plus 9 siblings), siblings pass normal envelope validation.

**For dependants (#1939, #1938)**
- Implement `splitFromProposalId`, the tick filter and the action as specified; the maximum of 10 counts the primary card.
