## What was delivered

- `tasks/eventHostedTasksHooks.ts`: `eventHostedTasksDeleteHook` (item delete hook) recomputes the host state of every live task the trashed Event hosts, in task id order, in the cascade's transaction; the `Events.hostedTasks` edges stay. `eventHostedTasksRestoreHook` (item restore hook) locks every live hosted task row first (task id order), then deletes the `hostedTasks` edge of each task that is still live, as the Tasks process (`ownerProcess: tasks`), so the edge hook of gh-1780 recomputes the task. Both are gated on the system Events database and registered at the end of `domainWriteHooks.ts`.
- `countTasksReturningFromEvent(client, eventId)`: the number of live hosted tasks that are not completed in the Event, the number that return to their day when the Event is deleted; it reads through the same reader as the counts of gh-1801 and answers the same for a live and a trashed Event. It answers 0 for an Event with no task, an id that names no Event, a tenant without the relation and another tenant's Event.
- `readHostedTasks` and `HostedTask` are now exported from `tasks/taskStateInEvent.ts`.
- Review fix: the restore hook locks the tasks before deleting any edge (task then edge, the order of the host-event routes), so a concurrent `PUT`/`DELETE /api/tasks/:id/host-events/:eventId` cannot deadlock with it (the new test fails with `40P01` without the fix).
- New accepted ADR `docs/adr/2026-11-13-event-trash-and-restore-write-the-tasks-they-host.md`: trashing an Event is a recompute trigger that keeps the edges; restoring it deletes the edges of live tasks, task row first.

## Contracts dependents build on

- Trashing an Event returns each hosted task to the day of the host Event added before it, or to its own date, and clears `hiddenUntil` when no live host Event remains; the edges stay, so the deletion confirmation can show `countTasksReturningFromEvent` (barrel export of `@semprec/data`) before and after the delete.
- Restoring an Event does not link its tasks again: the edges of its live tasks are deleted and `addedAt` is discarded; an edge to a task in the Trash stays. Putting a task back is a new `PUT /api/tasks/:id/host-events/:eventId`.
- The `completedInEvent` edges are never touched by either hook. An Event with no hosted task causes no extra task write on delete or restore.
- No route, table, migration or job.

## Deviations from the specification and spec seams

1. The Task did not name the side of the restore deletion: it deletes the edge through the Events-side property `hostedTasks` (caller is the Event, target the task) with the Tasks process context.
2. Only edges to live tasks are removed ("each such edge" of the live hosted tasks); an edge to a trashed task stays.
3. The delete hook recomputes in task id order (the order `taskHostEventScheduleItemUpdateHook` already uses).
4. The existing gh-1764 test "leaves a trashed event out of the list, lists it again once restored, and removes its edge" asserted that a restored Event is listed again; it was brought in line with this source's product decision (restore removes the edge) and renamed.
5. An ADR was added after review; the original worker had judged the hooks covered by `2026-11-07-item-delete-and-restore-domain-hooks.md`.
6. The commit trailers of the worker name Claude Sonnet 5.5 (the attribution the harness gave it).
