# Handover for gh-1362

Doc updates sent over `WS /api/sync` can now be acknowledged once stored. `pnpm run lint`, `format:check`, `build` and the touched test files pass in `backend/`; `web/` is untouched.

**What changed**
- **`protocolV1.ts`:**
  - `OutboundFrame` gains `{ type: "doc:ack"; docId; clientUpdateId }`.
  - New `CLIENT_UPDATE_ID_MAX_LENGTH` (64) and `isClientUpdateId` (1 to 64 chars of `[A-Za-z0-9_-]`).
  - `appendClientUpdateId(payload, id)` appends a trailing `varString` after the update bytes (for clients and tests).
  - `readClientUpdateId(decoder)` returns the id or `null`, never throwing. It checks the declared length against the remaining bytes, so a truncated id is `null` rather than a shorter id.
  - All four are exported from `@semprec/realtime`.
- **`docSync.ts`:** `handleBinaryFrame` reads the optional id for SyncStep2 and Update after the update bytes. After `mutateYDoc` resolves it sends `doc:ack` to the sending socket only, via `sendWithBackpressure`. A replay that added nothing is acked too. Frames dropped before persistence (unopened doc or foreign tenant, rate limit, malformed) and a throwing `mutateYDoc` get no ack. SyncStep1 is unchanged.
- **`realtime-client`:** `parseServerFrame` validates `doc:ack` (string `docId`, valid `clientUpdateId`); `syncClient` dispatches it to the new optional `onDocAck(docId, clientUpdateId)`.

**Tests**
- `protocolV1.unit.test.ts`: helper round trip, invalid, truncated and bad-varint ids.
- `docSync.test.ts`: ack after the row is readable, sender only (the peer gets the update through fan-out), replay acked without a second row, no id and malformed ids persisted without ack, unopened doc, other tenant and rate limit get no ack, a throwing persist gets no ack.
- `syncClient.unit.test.ts`: `doc:ack` dispatched, malformed ones dropped.
- `tenantIsolationRealtime.test.ts` (semprec-api): `doc:ack` added to the exhaustive outbound-type table, with a case showing the ack reaches A1 and never B1.

**Notes for dependants**
- A client builds an update frame as `appendClientUpdateId(<y-protocols Update/SyncStep2 message>, id)`; an id-less frame behaves as before. Generating ids and the "Saving..." indicator are not implemented.
- Any exhaustive `Record<OutboundFrame["type"], ...>` elsewhere now needs a `doc:ack` entry.
