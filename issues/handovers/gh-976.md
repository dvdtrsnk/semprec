  - As `semprec_data`, the full flow works: `bootstrapFirstAccount`, `login`, `verifySessionToken`, `logout`, `requestPasswordReset` with a fake mailer, `resetPassword` with the captured token, and a login with the new password.
  - A failed login as `semprec_data` records its `login_attempts` row, which shows the sequence access still works.
  - `semprec_data` still holds `SELECT`, `INSERT`, `UPDATE` and `DELETE` on all five tables after `REVOKE semprec_side FROM semprec_data` in a rolled-back transaction, so the grant is direct.
- **`leastPrivilegeRoles.test.ts`**: the grant-coverage assertion now treats the five identity tables as read-only for `semprec_side`, like the choke-point tables. It still requires full DML for `semprec_side` on every other table.
