## What was delivered

- Module task `mailTriageThreadProject` (payload `{ threadItemId }`, queue affinity `api`), declared in `mail/mailModuleManifest.ts` `taskNames`, payload schema export `mailTriageThreadProjectPayloadSchema`, handler export `handleMailTriageThreadProject`.
- `ingestEmailMessage` enqueues it in the ingest transaction when the new message is the first inbound message of its thread: delayed 60 s, per-thread job key with `preserve_run_at`, tenant lane queue, max 3 attempts. `enqueueThreadLinkRulesForFirstInbound` (gh-1869) now returns the thread item id (or null) so ingest does not repeat the first-inbound query.
- The run (`mail/threadProjectTriage.ts`): a repeatable-read read transaction decides eligibility (thread live, no `Threads.project` edge, no `value_links` row for project in any state, has a first inbound message) and reads the subject, sender, the first inbound text (HTML converted to visible text, whitespace collapsed, cut to 4000 characters, read from at most 500,000 stored characters) and up to 50 candidate projects (status `inProgress` or `longTerm`, live, most recently changed first). Outside any transaction it asks the AI gateway under operation / feature key `mailThreadProject` with `projectItemId` null. The answer is validated with zod `{ projectId: uuid | null, confidence: number }` and accepted only for a candidate at confidence >= 0.8. A read-committed transaction takes the mail thread guard and the Threads item lock, re-checks the skip conditions and writes the `Threads.project` edge with `createRelationWithClient` as writer `{ writerKind: "agent" }` (no run, no acting user, no value link); the existing `threadValueEdgeChangedHook` publishes the `mailThread` invalidation after commit.
- An exhausted tenant AI budget returns silently (outcome `budgetExhausted`, no notification); an invalid or empty answer leaves the project empty; gateway timeout and http failures propagate for the queue retry; a chosen project that left the live items between answer and write drops the answer.
- The api queue runtime binds the pool and gateway (`setThreadProjectTriageRuntime`, exported from `@semprec/data`) before the worker runs and unbinds them on stop and on start failure; the handler throws a plain Error when unbound.
- The AI gateway accepts the new operation with no project item (`services/semprec-ai-gateway/src/completeHandler.ts`, documented in `packages/shared/src/aiGatewayClient.ts`).
- ADR `2026-11-14-a-queue-task-may-write-a-user-owned-relation-edge-as-an-agent-with-no-run`: a queue task may write one reversible relation edge as a run-less agent writer; no approval; it never ends a value link (pre-check under the lock); never carries autonomous-send permission or another grant; how later flagged cases treat the identity.
