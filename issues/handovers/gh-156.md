## Summary

Implements issue #156: transactional item trash, restore, and the 30-day purge task.

- **`DELETE /api/items/:id`**: soft-deletes an item and cascades to every inline database it owns and their rows, recursively, in one transaction. Idempotent on repeat calls, rejects the whole cascade if any database in the subtree is archived, and always returns the full authoritative row (never 204).
- **`POST /api/items/:id/restore`**: symmetric restore of the same subtree, with the same idempotency and archived-database rejection semantics.
- **30-day trash purge**: a new `graphile-worker` task (`itemTrashPurgeSweep`, daily at 03:45) permanently deletes items whose `deleted_at` is older than 30 days together with their cascade subtree, stopping at any branch that is live or trashed more recently than the cutoff.
- Added `collectItemSubtree` (choke-point, BFS with cycle guard) and supporting store functions (`listDatabasesByParentItem`, `getAllItemsInDatabase`, `findItemsDeletedBefore`, `hardDeleteItem`, `getItemsByIdsIncludingDeleted`).
- Full test coverage: choke-point cascade/idempotency/archived-rejection tests, HTTP-level route tests, and a dedicated purge-task test suite.

`pnpm run verify` passes cleanly in both `backend/` and `web/`.
