# Handover: turn the mailbox into an internet account with Mail and Calendars switches

Implementation commit `b12fdf56a` on `feat/internet-accounts`.

**What changed.**
- Mailboxes has two user-owned checkboxes, `mailEnabled` and `calendarsEnabled` (`seed/seedEmailModule.ts`, labels "Mail"/"Pošta" and "Calendars"/"Kalendáře" in `mail/i18n`). Unset reads as the default: Mail on, Calendars off (`isMailEnabled`, `areCalendarsEnabled` in `mail/mailboxServiceHooks.ts`). The OAuth and password connect flows write both explicitly (`NEW_MAILBOX_SERVICE_SWITCHES`). The database label is "Internet accounts" / "Internetové účty"; keys and routes are unchanged.
- `mail_account_sync_state.sync_paused_at timestamptz` (baseline edited in place). Set means Mail is off.
- Switching Mail off (any choke-point update that patches `mailEnabled`): `mailboxServiceItemUpdatePreLockHook` takes the mailbox sync guard (≤ 15 s, else 409 `mailbox_sync_busy`) and then the sync state row `FOR UPDATE` before the update locks the Mailboxes item, the order of a removal. `mailboxServiceItemUpdateHook` decides by the locked row, so a repeated write is a no-op. Off, in the write's transaction: `pauseMailAccountSync` sets `sync_paused_at` (seeding a row for a never-connected mailbox) and resets the account to never synced (Gmail history id, Graph delta link, initial-sync mark, next expected activity and failure record cleared); folder sync states are deleted; the mailbox's Semp problem is resolved as `sourceDeleted`; the `mailboxRemoval` task is queued with `purpose: "mailOff"` (key `mailbox-mail-off-<id>`, same lane as a removal). After the commit the live sync is stopped through the stop bound with `bindMailboxServiceLiveSyncStop` (`alldots-api/serve.ts` binds `mailLiveSyncControl.control.stopMailbox`).
- The mail-off job (`mail/mailboxRemovalJob.ts`): per chunk, mail-thread guard → paused sync state row `FOR SHARE` → live Mailboxes item `FOR SHARE`; trashes the account's Emails then Folders with `deletedAtExact` = the pause time, and deletes each trashed Email's meta row with a thread no other message names (`deleteMailMessageMetaOfRemovedItem`, the renamed purge helper: Threads item trashed, `mail_threads` row deleted). An account no longer paused, or a trashed or gone mailbox, ends the job.
- Switching Mail on: `resumeMailAccountSync` clears the pause and `mailAccountSync` is enqueued in the same transaction; discovery hosts the live sync on its next pass. Because the meta rows were released and the cursors reset, the mail is ingested anew as for a new account.
- Skips and refusals: the sync pass returns before decrypting the credential and again under the guard (`enterSyncPass`); `listAccountsDueForSync` excludes paused rows (sweep); live-sync discovery leaves paused accounts out, so a hosted one is stopped by the next pass; `getActiveMailSyncProcessNames` expects no heartbeat for a paused account; `sendDraftEmail` refuses with `MailDisabledError` (409 `mail_disabled`) before the reauthorization/sender/Sent-folder checks and again in the claim transaction, which reads the sync state row `FOR SHARE` first.
- `GET /api/mail/mailboxes` and `/:id` rows carry `mailEnabled` and `calendarsEnabled` (booleans).
- `docs/architecture/domain-mail-and-inbox.md`: new "Internet accounts and service switches" subsection, pass/discovery/send/removal-job amendments and the new lock orders.

**Contracts dependents build on.**
- `Mailboxes.calendarsEnabled` (user-owned checkbox; `areCalendarsEnabled(properties)` gives the effective value). Nothing in the mail module reacts to it; the calendar issues own its lifecycle.
- `Mailboxes.mailEnabled` and `mail_account_sync_state.sync_paused_at`: the effect lives in the state row; read `MailAccountSyncStateRow.syncPausedAt`, not the property, to decide whether mail work may run.
- Store functions `pauseMailAccountSync`, `resumeMailAccountSync`, `lockMailAccountSyncPaused` (share lock + boolean), `lockMailAccountSyncPause` (share lock + pause epoch) in `mail/mailAccountSyncStateStore.ts`.
- Error `MailDisabledError` / code `mail_disabled` (409, `details.mailboxId`).
- `enqueueMailboxMailOff`, `mailboxMailOffJobKey`; `handleMailboxRemovalTask` payload `{ mailboxItemId, purpose?: "mailOff" }`.
- `bindMailboxServiceLiveSyncStop(stop | undefined)` exported from `@alldots/data`.
- Lock orders: Mail switch: sync guard → sync state row → Mailboxes item. Mail-off chunk: mail-thread guard → sync state row (share) → Mailboxes item (share) → members. Send claim: sync state row (share) → Emails item → `mail_drafts` row → mail-thread guard.

**Tests.** New `backend/packages/data/src/__tests__/mailboxServices.test.ts` (10 tests, runtime-role pool, two tenants): the switch defaults and values in list/detail rows (table of three); off pauses, resets the state, deletes folder sync states, queues exactly the mail-off job and calls the bound stop after the commit, and a repeated off changes nothing; with Mail off the sync pass opens no IMAP connection, the sweep enqueues nothing, a real live-sync root unhosts the account on its next pass and does not host it again, the job removes all Emails, Folders, threads and Threads items while credential, server settings, item and sync mode remain; on queues `mailAccountSync` in the same transaction and a production sync pass downloads the two messages again as new items with folders and threads; a draft send answers 409 `mail_disabled` with nothing sent and no claim, and sends with Mail on; a concurrent test shows a switch waits for a claim that read Mail on; removal of an account with Mail off still deletes credential, server settings and sync state and trashes the item with its switches; another tenant's switch answers not found and pauses nothing. A mutation (no meta release) fails 2 of them. Updated expectations: `mailSync.test.ts` (Mailboxes property keys), `publicSurface.test.ts` (new export).

**Deviations and spec seams.**
- Threads: the existing removal job does not remove Threads; for Mail off they go with the release of each trashed Email's meta row. Without that release a resumed sync converges onto the trashed Emails (ingest dedups by `mail_message_meta`) and the mail would not come back, which the acceptance criterion forbids. Consequence: a mail-off Email restored by hand from the trash comes back without a meta row.
- The provider-side Gmail watch and Graph subscription are not cancelled: their renewal loops stop with the lifecycle and they expire; a notification that still arrives only enqueues a pass that skips. Cancelling would need the OAuth client configuration, which a generic item write does not have, and Gmail `users.stop` acts on the whole account (possibly shared).
- Beyond the Touches list: `health/processHeartbeats.ts` (no heartbeat is expected for an unhosted paused account, else the health check alerts), the two connect flows (write the defaults), `mailMessageMetaStore.ts`/`mailPurgeHook.ts` (rename for reuse), `index.ts` and `alldots-api/serve.ts` (binding).
- "Account summary i18n": the backend has no account-summary copy (`tenancy/profileAccountSummary.ts` returns figures only); the label lives in the clients, which are out of scope. Only `mail/i18n` was changed.
- In a process without the binding (the worker, e.g. an approved agent write) the live sync is stopped by the next discovery pass (≤ 60 s) instead of right after the commit.

**Not changed.** Calendar invitation sends (`calendar/eventInvitationJob.ts`, `invitationReplyJob.ts`) still use the account's transport with Mail off; the Task names only send and draft send. An agent's send request still creates an approval; executing it with Mail off ends as `callFailed` and sends nothing.
