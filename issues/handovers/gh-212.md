## Summary

Implements issue #212: relation-definition ownership and protected system entry points, building on #211's normalized relation edge contract.

- `CreateRelationPropertyInput` now carries independent `owner`/`ownerProcess`/`locked` per side (source and `inverse`), with `ownerProcess` required exactly when `owner: 'system'`.
- New `SystemRelationWriteContext { ownerProcess }` gates `createRelationPropertyWithClient`, `createRelationWithClient`, `updateRelationWithClient`, `deleteRelationWithClient`. Only the property named by `relationPropertyId` authorizes an edge write; a public caller (no context) or a mismatched system context is rejected `owner_violation`.
- The public facade (`createRelationProperty`/`createRelation`/`updateRelation`/`deleteRelation`) never passes a context, so it can never touch an `owner: 'system'` relation property.
- Relation-property creation now applies `locked` only after both sides' schema/config is fully written, so `locked: true` never leaves an externally visible unlocked intermediate state.
- Migrated every internal relation writer (seeds, mail ingest/draft/send/attachments/folderDiscovery/imap-gmail-graph reconcilers/personLinkingActions, `tasks/advanceTaskRecurrence`) onto the protected entry points with their registered process identity.
- Added real-Postgres integration tests for public rejection, matching/mismatching `ownerProcess`, mixed-owner paired definitions, and atomic locked one-way/paired creation.
