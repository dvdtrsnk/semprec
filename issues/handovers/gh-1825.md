## What was delivered

- `resolveEditorSchema(registry, baseKind, locale)` in `inbox/editorSchema.ts`: finds the declaration through `getEditorSchemas()`, reads the declaring module's catalogs through the registry (`getCatalogs`) and returns `{ baseKind, groups: [{ key, fields: [{ key, control, inputType?, label, placeholder?, required?, when?, timeHiddenWhen?, optionsSource?, options?, info? }] }] }` in the caller's locale with English fallback and the catalog key as the last fallback; info rows are rendered from `infoKey` and params.
- `createInboxCardsRouteHandler` adds `editorSchema` (null when no module declares the base kind) to every card, resolved once per base kind per request from a process-wide full module registry (shared with the existing catalog resolver in `inboxRouteHandlers.ts`).
- The system databases declare editor schemas for task, event, project, area, company, person, file, health, journal and page in the new `seed/systemDatabasesEditorSchemas.ts`, wired as `editorSchemas` of the `systemDatabases` manifest, with 47 Czech and English label and placeholder entries in `seed/i18n/cs.json` and `en.json`.
- ADR `docs/adr/2026-11-12-inbox-editor-schema-pseudo-keys-area-and-markdown.md` (added by the review fix) appends the pseudo field keys `area` (task card; Tasks has no area property) and `markdown` (page content of journal and page cards) to the closed list of the editor-schema ADR.

## Deviations from the specification and spec seams

1. The declarations live in a sibling module, not inline in the manifest.
2. Catalogs are read through `registry.getCatalogs(moduleId)` (caches per module) instead of calling `loadModuleCatalogs` directly.
3. The resolved field also passes through declared static options of a `seg` control (not translated; out of scope).
4. Control choices where the Task left room: select for task status, health status, person contact and file type; seg for event type and project status; tile for the file field; the `area` control for Markdown fields; the `allDay` toggle also declared on events; People declares only `contact`; page placement offers start and end only.
5. The resolver test is `editorSchema.unit.test.ts` (unit tier) instead of `editorSchema.test.ts` of the Touches list.
6. `inboxRouteHandlers.ts` keeps one process-wide module registry that the existing catalog resolver is also built from.
