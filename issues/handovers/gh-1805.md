## Contracts dependents build on

Response of `GET /api/agent-runs/:id`: every field of `AgentRunRow` as before (including the top-level `mcpClientName` of gh-1788), plus:

- `title: string`: the heartbeat's name for a run that names a heartbeat, otherwise the run's task.
- `projectName: string | null`: null without a project, for a project in the Trash and for a name that is not text.
- `heartbeatName: string | null`: the name of the run's own `heartbeat_id`. A follow-up turn in a tick thread names no heartbeat and has null.
- `durationMs: number | null`: `finishedAt - startedAt` only for a finished invocation run not triggered by `mcp`; null while running and for every MCP run.
- `trigger: { kind, threadId, mcpClientName }`: `kind` is `tick` for `triggeredBy` heartbeat and for a user-triggered run whose thread is a tick thread, otherwise the run's `triggeredBy` (a delegated run inside a tick thread is `supervisor`). `mcpClientName` is the stored name for an MCP run and null for any other run, even when a name is stored.
- `approvals: { count, pending, approved, rejected, requestIds }`: `requestIds` ordered by `requested_at`, then id; the three counts add up to `count`.
- gh-1822 (same chain) adds `usage` to the same response.

`getAgentRunDetail` does not check the actor; the handler is its only caller and checks first. It runs four statements for a run with a project (two of `getItemsByIds`, one LEFT JOIN over `project_heartbeats` and `semp_threads`, one aggregate over `approval_requests`), independent of the number of requests.

A run of another tenant, a run of another actor and an unknown id answer the same 404 body with the same headers.

## Deviations from the specification and spec seams

1. The actor-mismatch run of the isolation case cannot be produced by a write (one user per tenant, `agent_runs_actor_user_id_tenant_fkey`, `actor_user_id` NOT NULL). The case creates it on the admin connection with `SET LOCAL session_replication_role = replica` and deletes it; the assertion goes through the real route on the runtime role.
2. The "current web response schema" of the contract criterion is a copy of `agentRunSchema` from `web/src/api/agentRunOperations.ts` inside the backend test, because the backend cannot import the web package. It was identical at the candidate; it will not notice a later change of the web schema. No web test was run.
3. Decisions where the Task is silent: the semantics of `durationMs`, `trigger.kind`, `title`, `heartbeatName` and the order of `requestIds` listed above.
4. "One grouped query" is one aggregate statement with FILTER counts and `array_agg`, without GROUP BY, so a run without requests also yields one row.
5. `agentRunHandler.unit.test.ts` is not in `Touches`; Task step 1 asks for it. `publicSurface.test.ts` is outside `Touches`.
