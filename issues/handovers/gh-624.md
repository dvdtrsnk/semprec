## Drain timeout
- `shutdown.ts` now exports `COMPLETE_ROUTE_TIMEOUT_MS = 60_000` and `AUDIO_ROUTE_TIMEOUT_MS = 600_000`. Each has a comment naming the client `REQUEST_TIMEOUT_MS` it mirrors.
- `SHUTDOWN_DRAIN_TIMEOUT_MS = Math.max(...)` of the two, so it is now 600 000 ms. The old comment claimed a single caller and said systemd's 90 s default was enough; the rewritten one drops both claims and points to the unit file.
- `deploy/systemd/semprec-ai-gateway.service` gets `TimeoutStopSec=660`: the 600 s drain, 5 s to close the database pool, plus margin. `deploy/provision.test.sh` asserts it.

## Client disconnect aborts the provider call
- **Request types:** `StructuredCompletionRequest`, `DiarizationRequest` and `TranscriptionRequest` each gain an optional `signal?: AbortSignal`.
- **Handlers:** `completeHandler.ts` and `audioHandler.ts` create an `AbortController` per request and abort it on `res` `close` only when `!res.writableFinished`, so a normal completion never aborts. When the provider call rejects, the handler checks for an abort first. If there was one, it logs one info line (`provider`, `model`, `path`) and writes nothing to the response. The reservation is already `failed` by then (the #620 fail path).
- **Provider adapters:** the Anthropic, DeepInfra and all four pyannote `fetch` calls use `AbortSignal.any([AbortSignal.timeout(55_000), request.signal])`. An abort still comes out as `ProviderCallError` or `AudioProviderCallError` with `AbortError` in the message.
- **Pyannote polling:** the loop checks `request.signal?.aborted` before and after each sleep. On an abort it throws `AudioProviderCallError("pyannoteAI diarization aborted by the caller")`, so it stops within one poll interval.
- **Addition not in the Task:** the handlers also abort right away if the response is already `destroyed` when the listener is attached. Without this, a client that drops in the short gap after the body is read would leave the provider call running.

## Tests
- **New `drainTimeout.unit.test.ts`:** the drain equals `Math.max` of the two route constants and is `>= AUDIO_ROUTE_TIMEOUT_MS`. The expected value in `shutdown.test.ts` is updated to 600 000.
- **Handler integration tests** (`/internal/complete`, `/internal/diarize`, `/internal/transcribe`): a client aborts while the fake provider is waiting. Each checks that the provider sees an aborted signal, exactly one disconnect info log is written, the `ai_gateway_calls` row is `failed`, nothing is logged at error level, and there is no `unhandledRejection`. A second test per route checks that a normal completion leaves the signal unaborted.
- **Anthropic and DeepInfra unit tests:** when the caller's signal is aborted before the call, `fetch` receives an already-aborted signal and the adapter rejects with its provider error class.
- **Pyannote unit tests:** an abort mid-sleep rejects at the next poll boundary with no further `fetch`. When the caller's signal is aborted before the call, the first `fetch` receives an aborted signal and the call rejects.
