# gh-1460 — [mail-accounts 02/30] Pass composition-root dependencies to module custom routes

Repository-Issue: gh-1460

## Delivered behavior and production wiring

- `CustomRouteDependencies` in `backend/services/semprec-api/src/adapter/customRouteMount.ts` is the typed container. Every member is optional: `oauth` (`gmail` and `msGraph` OAuth clients, `redirectBaseUrl`), `mailServerClients` (`verifyPassword` and `send`), `mailLiveSync` (`startMailbox` and `stopMailbox`), and `outboundHttp` (a `typeof fetch`). The members hold no behavior of their own. `createCustomRouteDependencies()` returns the empty container.
- `CustomRouteHandlerFactory` is now `(pool, dependencies) => AdapterHandler`. `mountCustomRoutes(pool, definitions, dependencies)` calls every factory with the same container object. The existing factories keep their `(pool)` form, which TypeScript accepts, so no manifest or handler file changed.
- `requireCustomRouteDependency(dependencies, member)` returns a configured member. An unconfigured member throws `CustomRouteConfigurationError`, a plain `Error`. The adapter logs it as an unexpected error and answers `500 internal_error`. No domain status is mapped onto it.
- `createDispatcher` takes an optional `customRouteDependencies` field in `AppOptions` (`backend/services/semprec-api/src/app.ts`). Without it, the factories receive the empty container.
- `serve.ts` builds the container before `createDispatcher` runs:
  - `oauth.gmail` and `oauth.msGraph` come from `readOAuthClient`, which is now exported from `mailSyncAdapters.ts`, reading `GMAIL_OAUTH_CLIENT_ID`/`_SECRET` and `MS_GRAPH_OAUTH_CLIENT_ID`/`_SECRET`. An unset or empty key leaves the client out.
  - `oauth.redirectBaseUrl` is `APP_BASE_URL` (`appBaseUrl`).
  - `mailLiveSync` is a placeholder proxy. Its `startMailbox` and `stopMailbox` reject with `CustomRouteConfigurationError`, because the live-sync root exposes only `start`, `stop`, `reconcileOnce` and `stopTenant`. The proxy is not bound to the root.
  - `mailServerClients` and `outboundHttp` are not set. Nothing configures them yet.
- Type-only barrel export `MailSendAdapterFactory` in `backend/packages/data/src/index.ts`, so the container can name the send seam that `sendDraftEmail` already takes.
- ADR `docs/adr/2026-10-29-custom-route-composition-root-dependencies.md` (new). It extends [[2026-09-11-module-manifest-custom-routes]], which is unchanged.
- No route reads a member yet. Nothing in the manifests changed, and no migration was added.

## Decisions

- **A member is read per request, not at mount.** A route calls `requireCustomRouteDependency` inside its handler. A call made while the factory runs would fail the whole mount at startup for one missing member.
- **The configuration error is a plain `Error`**, not a `ChokePointError`, because a missing deployment setting is not the caller's input or a domain failure. The adapter's existing unexpected-error path handles it, so it is logged and answered with the generic 500.
- **`mailLiveSync` is a placeholder, as the approved spec says.** The root has no per-mailbox method to bind to, so nothing is forwarded yet.
- **`mailServerClients.send` reuses `MailSendAdapterFactory`** from `mail/send.ts`. The verification member, `verifyPassword(settings, password)`, takes the `MailServerSettingsInput` the mail module already exports. Its shape is a first guess that the connect-with-password issue (#1736) may narrow.
- **The mount's `dependencies` argument is required.** Only `createDispatcher` supplies a default, and that default is the empty container.
- **Test location.** The issue's Touches names `backend/services/semprec-api/src/__tests__/customRouteMount.test.ts`. The existing test is `backend/services/semprec-api/src/adapter/__tests__/customRouteMount.test.ts`, and the approved spec names that path. The new tests stay in that file.
- **Two files outside the Touches list changed.** `mailSyncAdapters.ts` (export of `readOAuthClient` and `OAuthClient`) and `packages/data/src/index.ts` (one type-only export line). Both are needed by the approved spec or the container's typing.

## Tests

  - A route that needs `oauth` reads the substitute container it was mounted with, and returns its `redirectBaseUrl`.

## Notes for dependants

- **#1686, #1736, #1690 and #1896** receive the container as the factory's second argument. Read each member with `requireCustomRouteDependency` inside the handler. Do not read a member in the factory body, because the mount runs at startup.
- **`mailLiveSync` is a placeholder.** The issue that adds per-mailbox control to the live-sync root (#1550, #1739 or #1745) must replace the proxy in `serve.ts` with the real control.
- **`serve.ts` sets only `oauth` and `mailLiveSync`.** A route issue that needs `mailServerClients` or `outboundHttp` adds that member in `serve.ts` and in the typed container.
- **`oauth.gmail` and `oauth.msGraph` are absent when their keys are unset.** The warning comes from `createMailSyncAdapters`, once per process. This change does not log it again.
- **Every factory receives the same container object.** A route must not mutate it.
