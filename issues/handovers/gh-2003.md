# gh-2003 handover: Report how many invited people a calendar deletion will send cancellations to

Delivered on the integration branch by merge `6be79b5d53187e4434cebd8b518f507afda4ae3d` of chain `e1-100-calendar`, candidate `d316fff7638a19015a988e8a3db103b826d10b75`. The chain has one member and landed alone; the gate ran on the merged tree. The merge was automatic, with no conflict and no migration.

## What was delivered

A read-only route `GET /api/calendar/calendars/:id/cancellation-impact` that answers `{ eventCount, recipientCount, cancellationCount }` for one calendar, so that a client can state in the deletion dialog how many Events and how many invited people a deletion affects.

- `eventCount`: the live Events on the calendar's `Calendars.events` edges (the Events that the deletion of gh-1803 trashes).
- `cancellationCount`: the participant edges of those Events (`Events.people`) whose metadata carries an invitation, one cancellation each.
- `recipientCount`: the distinct invitation emails among those edges, compared after `toLowerCase` (no trimming).
- 200 for any live calendar of the Calendars system database, including a system or a subscription calendar. 400 `validation_failed` on `id` for a non-UUID. 404 `not_found`, one code path and an identical body, for an unknown, trashed, foreign-tenant or non-calendar id.
- The route writes nothing; the delete request gets no confirmation flag.
