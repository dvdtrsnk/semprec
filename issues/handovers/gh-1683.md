# gh-1683 implementation handover

## Behavior and interfaces

An approval request now snapshots a localisable description when it is created.

- Migration `0117_approval_requests_description.sql`: nullable `approval_requests.description jsonb`
  (expand-only, no backfill, no CHECK). Rows created earlier stay NULL.
- `ApprovalDescription { key, params: Record<string, string | number | null>, endsInheritance? }` and
  `ApprovalRequest.description: ApprovalDescription | null` in `approvalRequestsStore.ts`, validated when the row
  is mapped (malformed JSON throws "Malformed description in database row"). `CreatePendingApprovalRequestInput.description?`
  is written by `createPendingApprovalRequest`.
- `mcp/approvalDescription.ts` (template contract documented in its header): `buildDestructiveApprovalDescription(client, check)`
  for the five destructive generic operations (templates `approval.itemDelete`, `approval.propertyDelete`,
  `approval.databaseArchive`, `approval.viewDelete`, `approval.relationDelete`) and
  `buildMcpInvokeApprovalDescription(serverName, toolName)` (`approval.mcpInvoke`, no argument values). Both are exported
  from `@semprec/data`.
- Call sites: `preflightDestructiveApproval` builds the description on the same transaction client right before the
  insert; `createApprovalGatedMcpInvokeTool` passes the server item's `name` and the tool name.
- `description` is on `ApprovalRequestQueueEntry` and `ApprovalRequestDecisionView` (`null` for old rows).
- Catalog entries for all six templates are in `web/src/i18n/messages.ts` (en and cs); the push renderer does not read
  templates from `notifications/i18n` yet.
- `TRASH_RETENTION_DAYS` (30) is now exported from `trash/purgeExpiredTrash.ts` and used as `restorableDays`.

## Param semantics

- `databaseKey` is the canonical key (null for user-created databases); `databaseName` is `name`, falling back to `key`.
- `itemName` / `fromItemName` / `toItemName` come from the item's `name` property and are null when it has none.
- `linkedCount` = all relation edges of the item; `affectedCount` for a property = live items with a non-null value
  at that key, for a database archive = live items in it.
- `projectName` is present only when the item's database has an `ownerProjectItemId` whose item has a name.
- `viewName`'s `databaseName` is null for a curated view without a database.
