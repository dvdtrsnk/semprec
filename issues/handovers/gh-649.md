## Summary

Closes #649. The daily backup now saves the two blob storage directories instead of the MinIO volume. The application never writes to that volume, so it was always empty. The monthly restore test now checks sampled `blobs` rows against the files restored from those directories. Before, it compared them with a disposable MinIO copy of an empty bucket, so it passed without testing anything.

Skills loaded: none of the topic skills apply. The change is only deploy shell scripts and docs, with no state writes, routes, migrations, keys or model calls. The failure paths follow the existing `fail_check` / `exit 1` style of these scripts.

### Backup (`semprec-backup.sh`)
- `FILES_STORAGE_DIR` and `MAIL_ATTACHMENTS_DIR` are now required, and each must be an existing directory. If one is unset or missing, the script exits non-zero and names the variable before any `restic` call.
- `minio_data_directory` and its `docker compose ps` / `docker inspect` calls are removed. The script now runs `restic backup "$DUMP_FILE" "$FILES_STORAGE_DIR" "$MAIL_ATTACHMENTS_DIR"`.
- New header comment.

### Restore test (`semprec-restore-test.sh`)
- Removed: the `MINIO_*` variables from `require_environment`, `start_minio`, `restored_minio_data_directory`, `url_encode`, `read_restored_object`, the MinIO image and container constants, and the MinIO teardown. `FILES_STORAGE_DIR` and `MAIL_ATTACHMENTS_DIR` are now required.
- `check_blob_objects` (still reported as `blobObjects`) looks each sampled `storage_key` up under `$WORK_DIRECTORY$FILES_STORAGE_DIR/` first, then under `$WORK_DIRECTORY$MAIL_ATTACHMENTS_DIR/`. If neither has the file, it fails with "restored snapshot has no file for a sampled blob". Size and SHA-256 are compared as before.
- The recorded result shape and `restoreTestResultArgs.ts` are unchanged; that file is out of scope. Its allowed-values list still contains `minioStart`, which the script can no longer produce.

### Tests
- **`semprec-backup.test.sh`:**
  - Two temporary directories are passed in as the env vars.
  - The test asserts that the `restic backup` command line names the dump and both directories, and that the only `docker` call is the `pg_dump` exec.
  - The existing failure cases are kept. New cases cover each variable being unset and each directory being missing: each must exit non-zero, name the variable, and make no `restic` call.
- **`semprec-restore-test.test.sh`:**
  - The fake `restic restore` writes the dump and both directories under the target by absolute path.
  - The passing run finds its sampled blobs in both directories and asserts `compared 3 restored blob files`.
  - New failure cases, each recorded as `blobObjects`: a file missing from `files`, a file missing from `mail-attachments`, a size mismatch, and a same-size hash mismatch.
  - The missing-configuration case now drops `FILES_STORAGE_DIR`.
- I checked that the tests catch real breakage: with the mail-attachments fallback removed, the restore test fails; with the hash comparison removed, it also fails; with the directory check removed, the backup test fails.

### Docs
- **`deploy/shared/.env.example`:** the MinIO block now says MinIO is not used by the application or the backup. The `minio` service stays in `docker-compose.yml` only until a separate removal, and no script reads `MINIO_BLOB_BUCKET` any more.
- **`deploy/README.md`:** the backup and restore-test sections now name the two directories instead of the MinIO volume and bucket.

After this change, nothing under `deploy/systemd/scripts/` contains `minio` (case-insensitive).
