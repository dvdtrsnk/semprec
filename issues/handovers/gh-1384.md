# gh-1384 handover

## What changed

- `resolveThreadId` (`backend/packages/data/src/mail/threading.ts`) now first selects the distinct non-null `thread_id`s of `mail_message_meta` rows with the same `message_id` (any mailbox), ordered by `thread_id`. They seed the found-thread set, so the lowest same-message thread is the merge target; ancestor and descendant lookups and `reassignThread` merging are unchanged.
- Doc comment updated accordingly.

## Tests

`backend/packages/data/src/mail/__tests__/threadingCrossMailbox.test.ts` covers: a copy joins the other mailbox's thread; a copy joins the ancestor thread of the other copy; bridged threads merge and the emptied `mail_threads` row is deleted; different ids stay separate. The threading tests in `mailSync.test.ts` still pass.

## Notes for dependants

- Existing stored data is not repaired (#1570). Callers must still call `resolveThreadId` before inserting the new `mail_message_meta` row.
