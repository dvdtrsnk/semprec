# Handover: Add to Inbox as an App Shortcut for the Action button

ADR: `docs/adr/2026-11-27-apple-system-entry-points-run-in-the-app-over-a-headless-sdk.md` (App Intents live in the
app target, run in the app's process, reach Kotlin only through a CoreKit bridge over a headless SDK entry, never
start a warm-up or a sync socket, and their `401` does not end the session).

**Kotlin, exported from `:shared:umbrella`** (`mobile/shared/umbrella/src/commonMain/kotlin/cz/alldots/app/sdk/InboxCaptureSDK.kt`):
- `class InboxCaptureSDK(sessionStorage: SessionStorage, dataDirectory: String)`: an `AuthenticatedApi` over
  `OfflineLayer.shared(dataDirectory)` with `onSessionRejected = {}` and `takesOverSender = false`: its sender is
  attached only when no window has attached one (`OfflineWrites.attachIfNone`), and a window created later replaces
  it. Tests: window first, SDK first then window (both send through the window's sender, whose `401` signs out), and
  no window (the SDK's sender sends; its `401` keeps the session).
- `fun signedIn(): Boolean` (a session is stored).
- `suspend fun types(): InboxCaptureTypesAnswer` = `Loaded(types: List<InboxCaptureTypeState>)` | `Refused(failure: Failed)`;
  `GET /api/inbox-types` through the offline layer, so a kept answer serves it without the server.
- `suspend fun capture(text, day /* YYYY-MM-DD */, time /* HH:mm */, typeId: String?, file: InboxCaptureFileInput?): InboxCaptureAnswer`
  = `Kept` | `Refused(failure: Failed)`. `INVALID_DATA` (nothing kept) for a blank text without a file, a day that is
  no calendar day or a file whose Base64 does not decode; `UNAUTHORIZED` with nobody signed in or no person kept;
  `UNAVAILABLE` when the outbox could not write. `InboxCaptureFileInput(filename, mimeType, base64, source: InboxCaptureAttachmentSource)`
  is already there for the scanner issue; the Swift bridge does not pass a file yet.
- `suspend fun send(): Boolean` = `OfflineLayer.sendCaptures()` (new public passthrough to `CaptureOutbox.send()`).
  Cancelling it stops only the wait.
- Every call answers a value; an unexpected exception is a failure with no kind; cancellation is rethrown.

**Swift bridge** (`mobile/apple/Modules/Core/CoreKit/Sources/Shared/InboxShortcutCapture.swift`, `@MainActor public final class`):
- `public convenience init()` (Keychain session, `OfflineDirectory.path()`); internal
  `init(sessionStorage: any SharedSDK.SessionStorage, dataDirectory: String)` for tests.
- `public var isSignedIn: Bool`
- `public func types() async -> InboxShortcutCapture.Types` (`.loaded([InboxCaptureType])` | `.failed(Failed)`)
- `public func capture(text: String, day: String, time: String, typeId: String?) async -> Failed?` (nil = kept)
- `public func send() async -> Bool`
- Mappings `static func types(_:)` and `static func capture(_:)`, tested branch by branch in
  `Tests/InboxShortcutCaptureTests.swift`. The scanner issue extends `capture` with the file (map to
  `SharedSDK.InboxCaptureFileInput`).
- `OfflineDirectory.path()` (`Sources/Shared/OfflineDirectory.swift`) is now the one place that makes
  `Application Support/Offline`; `SharedScreenModelFactory` uses it too, so both name the same `OfflineLayer`.

**Intents** (`mobile/apple/Projects/App/Sources/Intents/`):
- `InboxTypeEntity.swift`: `AppEntity`; `InboxTypeEntity.noType` (id `noType`, not a UUID; `typeId` is nil for it).
- `InboxTypeQuery.swift`: `EntityQuery`; suggested entities are "No type" first, then the bridge's types; only
  "No type" when they cannot be read.
- `AddToInboxIntent.swift`: `supportedModes = .background`, `authenticationPolicy = .requiresLocalDeviceAuthentication`;
  optional parameters `type`, `text` (multiline), `day` (nil = today). Flow: sign-in check (dialog `intent.addToInbox.signIn`),
  `$type.requestValue` / `$text.requestValue` when unset, `capture(text:day:time:typeId:)` with `IsoDay.string(from:)` and
  `ClockTime.string(from: .now)`, then `send()` for at most 3 s (`sendingWait`) and the dialog `intent.addToInbox.saved`.
  `INVALID_DATA` throws `$text.needsValueError` (re-asks the text), `UNAUTHORIZED` answers the sign-in dialog, anything
  else `intent.addToInbox.failed`.
- `AlldotsShortcuts.swift`: `AppShortcutsProvider` with three phrases containing `\(.applicationName)`.
- The scanner issue adds its own intent (or a parameter) beside these files and passes the file through the bridge;
  the background issue replaces the 3-second wait (`sendBriefly`) with real background sending.

**Copy.** Dotted keys `intent.inboxType.*`, `intent.addToInbox.*` in `Projects/App/Resources/Localizable.xcstrings`;
phrases in the new `AppShortcuts.xcstrings`, keyed by the English phrase with `${applicationName}` (App Intents
requires the phrase literal itself, so they cannot be dotted keys). All listed in `appleOnly` of the `Alldots` entry
of `mobile/scripts/architecture-policy.json`.

**Known consequences / open points.**
- Without a window in the process, the intent's sender carries the layer's rounds and its `401` signs nobody out; the
  next window's own call ends a refused session.
- The query's failure is not surfaced (only "No type" is offered), as the issue asks; nothing is logged (the app has
  no logger).
- `entities(for:)` resolves a type saved in a shortcut only when the types can be read (from the server or a kept
  answer); otherwise it answers no entity for it. Not verified on a device how the system then treats the parameter.
- Second process (extension) coordination of the outbox remains as the outbox handover describes.

appears to wait for linkd on this host. Watch for it in CI. iOS simulator tests, UI tests and a device run of the
intent (Shortcuts app, Action button) were NOT RUN.
