## Contracts dependents build on

- Import `ROUTE_MATRIX`, `RouteMatrixEntry`, `ROUTE_TENANCIES` and `RouteTenancy` from `routeMatrix.js`, as before. Nothing outside `routeMatrix.ts` imports a slice.
- A new entry goes at the end of the slice of its path family in `backend/services/semprec-api/src/routeMatrix/<family>.ts`. When no slice fits (for example `/api/events`, `/api/calendar`, `/api/trash`, `/api/sleep`, `/api/inbox`, `/api/search`, or a `/api/projects` sub-resource other than agent-guidance and mcp-grants), add a slice module and append one import line and one spread line at the end of `routeMatrix.ts`.
- A slice module exports exactly one `RouteMatrixEntry[]` named `<FAMILY>_ROUTES`, imports the type with `import type { RouteMatrixEntry } from "../routeMatrix.js"` and, when it interpolates an id, `EXAMPLE_ID` from `./exampleId.js`. A value import from `routeMatrix.ts` into a slice would be a runtime cycle; only the type-only import is allowed.
- The order of the existing entries is fixed: `tenantIsolationRoutes.test.ts` runs its cases in `ROUTE_MATRIX` order against fixtures seeded once. An entry appended to a slice in the middle of the matrix runs between existing cases of that file.
- A route entry, its `ROUTE_CASES` isolation case and its `ROUTE_HANDLER_FILES` mapping still land together. Those two inventories were not touched.
- Two chains that append to the same slice, or that both add a slice, conflict at the same lines. Keeping both sides is correct; `routeMatrixInventory.unit.test.ts` then fails and names a duplicate `name` or a duplicate `method` plus `path`.
- ESLint `max-lines` (900 counted lines) is unchanged and has no exemption. Counted lines now: `routeMatrix.ts` 88, largest slice `items.ts` 107.

The slices evaluate it when they load and `routeMatrix.ts` imports the slices, so it moved unchanged to `routeMatrix/exampleId.ts`, a helper module that is not a slice. `Touches` names `routeMatrix/` for slice modules only. Both reviewers judged the helper necessary.
2. The type stays in `routeMatrix.ts`. The build and `check:boundaries` accept the type-only import from the slices, so the fallback of Task step 2 was not used.
3. File comment: besides the one added sentence, two location references that the move made false were corrected (the setup wizard now reads "in `routeMatrix/auth.ts`", the healthz entry "in `routeMatrix/healthz.ts`").
4. Slice naming where the fixed order interleaves families, each stated in the slice's doc comment: `auth.ts` also holds `/api/setup`, its wizard view and `/api/invitations/accept`; `properties.ts`, `views.ts` and `items.ts` also hold their creation routes under `/api/databases/:id/`; `items.ts` also holds the two query entries; the `/api/mail` family is in two slices, `mailMailboxes.ts` and `mail.ts`.
