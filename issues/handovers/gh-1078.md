The backup now writes a deletion ledger, the restore test checks it, and a new replay CLI re-applies the deletions to a restored database. All of it is committed on this branch; the push, the review and the full `pnpm run verify` are left to Relay.

**What I changed**
- **Backup** (`semprec-backup.sh`): after the key dump, it queries `tenant_deletions` with `psql`. It writes `tenant-deletions.ledger` through a temporary file and `mv`. The ledger goes into the same `restic backup` call as the dump. A failed query stops the backup before restic runs and leaves no partial ledger file.
- **Restore test**: `deletionLedger` is added to `RESTORE_TEST_FAILED_CHECKS` and runs after the postgres-contents checks. It fails when:
  - the ledger is missing,
  - a line is not a lowercase uuid (checked before any line reaches SQL),
  - a ledger id is still in the restored `tenants`,
  - the ledger line count differs from `tenant_deletions`.

  An empty ledger with an empty table passes.
- **Ledger parser**: `parseTenantDeletionLedger` in `tenantDeletionLedger.ts` ignores blank lines, de-duplicates, and throws naming the 1-based line number. The error does not echo the offending line.
- **Replay**: `replayTenantDeletions` in `tenantPurgeJob.ts` handles each id in its own tenant-scoped transaction. It takes the admin-membership lock first, then reads the tenant row `FOR UPDATE`.
  - It reports `absent` or `alreadyDeleting` and leaves those tenants alone.
  - It refuses any other status as `unexpectedStatus`.
  - For an `active` tenant, a `LastAdminError` is reported as `lastAdmin` and the tenant stays unchanged.
  - Otherwise it calls `beginTenantDeletion`. Any other error propagates.
- **CLI** (`replayTenantDeletionsCli.ts`): it needs `DATABASE_URL` and one ledger path. It parses before connecting and exits 2 on bad input. It runs under `runAsSystem("tenantDeletionReplay", …)` and prints the four counts plus the refused ids. It exits 1 if anything was refused and always ends the pool. I capped the ledger file at 8 MiB.
- **Runbook** (`deploy/README.md`): I extended the backup and restore-test sections and added "Re-applying account deletions after a restore". It states the 24-hour RPO limit and the 12-month snapshot retention.
