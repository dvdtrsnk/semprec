## What was delivered

- Events gain a user-owned `json` property `recurrence` (`seedTenDatabases.ts`, labels `property.events.recurrence.name` in `seed/i18n/cs.json` and `en.json`) holding a fixed rule of the shared vocabulary (`weekdays`, `monthDates`, `nthWeekday`). The stored value is the bare rule, no mode wrapper.
- `calendar/eventRecurrenceRule.ts`: `parseEventRecurrenceRule(raw)` (fixed-rule schema, `400 validation_failed` with field `recurrence`) and `eventRecurrenceOccursOn(rule, seriesStartDate, date)` (reuses `occurrenceDatesInRange` of `tasks/nextDueDate.ts`; the start date is an occurrence only when the rule matches it). Also `EVENT_RECURRENCE_PROPERTY_KEY` and the type `EventRecurrenceRule` (the fixed rule without `yearDates`).
- `calendar/eventRecurrenceHook.ts`: `eventRecurrenceItemCreateHook` and `eventRecurrenceItemUpdateHook`, registered in `domainWriteHooks.ts`; a refusal runs in the write's transaction and leaves the row unchanged, so REST, the Semp/agent gateway and MCP are all covered. A patch that does not name `recurrence` is not judged; a non-Events database is untouched.
- `calendar/eventsRecurrenceCutoverMigration.ts`: `runEventsRecurrenceCutoverMigration(pool)` inserts the same definition by direct SQL under `LOCK TABLE properties IN EXCLUSIVE MODE`, idempotent, skipped for a tenant without Events. Registered in `runTenantCutoverMigrations` after the sensitive databases step (gh-1808) and the Tasks Today view step (gh-1798), before the area-note step that stays last.
- ADR `docs/adr/2026-11-13-an-event-recurrence-rule-is-a-user-owned-json-property.md`: the Events storage that `2026-10-25-task-and-event-recurrence-model` left to this issue.

## Deviations from the specification and spec seams

1. Spec seam: the recurrence-model ADR leaves the Events storage to this issue; the issue's own wording (user-owned, validated, field `recurrence`) was followed and recorded in a new ADR.
2. Spec seam: the fixed-rule schema now also contains `yearDates` (added by gh-2010 after this issue was written) while the issue says a yearly rule is not built, so `parseEventRecurrenceRule` refuses `yearDates` with the same `400`; a floating rule is refused too. The reason in the ADR was reworded by the review fix to the issue's "not built".
3. `null` is refused on create and update ("anything else is rejected", "a series is ended by deleting it"); there is no way to remove a rule through a write.
4. `eventRecurrenceOccursOn` is literal to the Task: the start date is an occurrence only when the rule matches it.
5. The property is declared after `icalSequence`; the People properties of gh-1795 are in the tree now but were not when the chain was cut (not a blocker of this source).
6. The schema parse drops unknown keys but the stored value is not rewritten.
7. No preset is built.
8. One extra test file beyond Touches: `services/semprec-api/src/__tests__/eventRecurrenceWritePaths.test.ts`, required by the Task for Semp and MCP.
9. At the merge, `publicSurface.test.ts` and `tenantCutoverMigrations.ts` conflicted with other sources' entries and were resolved by keeping both sides in sorted and blocker order.
