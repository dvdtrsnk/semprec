## Delivered behavior and production wiring

- `getMailboxRemovalImpact(client, mailboxItemId)` in `backend/packages/data/src/mail/mailboxRemovalImpact.ts` returns `{ messages, drafts, threads, attachmentsKept }`, or `null`. It is exported from the data barrel (`index.ts`) together with the `MailboxRemovalImpact` type.
- The four counts come from one SQL statement, so they read one snapshot. Its inputs are the Folder edges (`Folders.mailbox`), the Email edges (`Emails.folder`), `mail_message_meta.thread_id` and `mail_attachments.message_item_id`. The relation definitions are found by property key on the module-owned database, as migration 0053 finds them.
- `createMailboxRemovalImpactRouteHandler(pool)` (same file) is the custom route `mailboxRemovalImpact`, `GET /api/mail/mailboxes/:id/removal-impact`, justification `single-consumer-read`. It is declared in `mail/mailModuleManifest.ts` (`customRoutes`), and the manifest file re-exports the handler so the registry can resolve it. The REST adapter authenticates the route and runs it in the session's tenant scope.
- Answers: `200` with the four counts. An unknown mailbox, a foreign mailbox, a soft-deleted mailbox, a tenant without a Mailboxes database and a malformed id all answer `404 not_found` with no details, so the bodies are identical.
- No migration, no schema change, no write.

## Decisions

- **Membership is the Folder edge.** An Email belongs to a mailbox when it is in one of the mailbox's non-deleted Folders. `mail_message_meta.mailbox_item_id` is not used, because the Task names `mail_message_meta` only for the thread id.
- **A draft is not a message.** An Email in a Drafts folder and in another folder of the mailbox counts as a draft, once.
- **Soft-deleted folders are not the mailbox's folders.** An Email that sits only in a soft-deleted folder is not counted. `findFolderBySpecialPurpose` makes the same choice.
- **A thread is decided by its live messages.** A thread counts when it has at least one member and every non-deleted message of the thread is a member. A live message in no folder of this mailbox therefore blocks the count. #2029 soft-deletes messages in the mailbox's folders, so such a message is not removed, and the thread is expected to survive the removal.
- **Deleted mailbox is 404.** This follows `send.ts`, which treats a removed mailbox as not found.
- **Malformed id is 404.** The Task names only the 404 outcome, so a malformed id gets the same answer as an unknown one. `triggerHeartbeat` answers 400 instead; a reviewer may prefer that.
- **Tenant without a Mailboxes database is 404.** No mailbox can exist there, so the route does not resolve the Folders and Emails databases. `adapterTenantScope` found the earlier version answering 500 for such a tenant.

## Tests

`backend/packages/data/src/__tests__/mailboxRemovalImpact.test.ts` (new, 9 tests, integration tier, runtime `semprec_data` pool, production writers for every fixture):

- Counts the non-deleted messages, drafts and attachments, and nothing of another mailbox. Soft-deleted messages and drafts are excluded.
- An Email in two folders is counted once. An Email in an inbox and a Drafts folder counts as a draft only.
- A thread that holds a message of another mailbox is not counted. The shared thread is asserted to exist first.
- A thread whose other-mailbox message is soft-deleted is counted.
- A message that sits only in a soft-deleted folder is not counted.
- An unknown mailbox and a soft-deleted mailbox answer `null`.
- A tenant without a Mailboxes database answers `null`, and the handler answers `NotFoundError`.
- Another tenant's mailbox answers `null`. Under that tenant's scope the raw `items` row is invisible (RLS), not only absent by database id.
