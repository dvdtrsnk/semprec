### Exports
- **`HARVEST_CAP = 30`**
- **`pendingWork(openIssues)`** returns, in ascending order, the open issues that hold back a harvest: any `followups:harvest` issue, and any issue with both `followups:issue` and `spec:proposed`.
- **`candidatePullRequests(pullRequests, { minPr })`** keeps pull requests with `number >= minPr` that lack `followups:harvested`, sorted ascending.
- **`classifyPullRequest({ pr, memoryFindings, threads, treePaths, ledger })`**:
  - It considers only `open` findings that are not already in `ledger.harvested`.
  - A finding's thread is found only when its `discussionId` is all digits, by matching the thread's root comment `databaseId`.
  - The only skip: a resolved thread with a reply (not the root comment) from a `TRUSTED_REVIEW_BOT_LOGINS` author whose trimmed body is exactly `Fixed.`.
  - Every other finding becomes a finding record without the two hint fields. `descriptionTruncated` is true when the description ends with `…`. `discussionId` is `""` when it is not numeric. `threadResolved` and `replies` come from the matched thread (at most the last three replies). `pathExists` is `treePaths.has(path)`.
  - Reply excerpts are cut at 200 code points, the same unit `records.mjs` checks.
  - `memoryFindings === null` returns two empty lists.
- **`createHarvestPlan({ cap })`** returns `{ offer, plan }`:
  - An `alreadyRecorded` pull request goes to `labelOnly` and its findings are ignored.
  - A pull request with no harvested findings is always taken and does not count towards the cap; its skipped findings are kept.
  - The first pull request with harvested findings is always taken, whatever its count.
  - A pull request that would push the total over the cap is refused, and every later `offer` also returns `"stop"` without changing the plan.
  - `plan()` returns `{ prs, labelOnly, harvest, skipped, stoppedAt }`.
