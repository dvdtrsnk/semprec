## What was delivered

`confirmProposalWithClient` writes a `journalEntry` card in its own transaction through the new `inbox/journalEntryConfirm.ts`:

- The day and its page come from `ensureJournalPeriodDoc(day)`; `insertPageMarkdown` (the `page.insert` owner) appends the Markdown at the end, authored `user`, with block ids `proposalBlockId(proposalId, index)` (UUID v5), so a repeated write cannot add the blocks twice.
- The day gets a `project` edge (and no own area edge) or, with only an `areaId`, an `area` edge. Both ids in one envelope: only the project edge. The edge is written with `writeRecordedEdge` into a recorder that `confirmProposalWithClient` stores in `writtenRelations`, so the undo reverses an inserted edge and keeps one the day already had.
- `resultItemId` is the day item, `resultLabel` the `YYYY-MM-DD` key, and the primary #1648 result lists exactly the inserted block ids.
- `assertJournalEntryReferencesLive` re-checks the Journal database, area and project before any write and answers 409 with the card left proposed (a trashed or archived project or area, a Journal database that is no longer the card's target). A confirmed card is replayed by the existing early return; a failing step rolls the caller's transaction back, so no partial page content remains.
- Undo: `undoConfirmedProposal.ts` classifies a `journalEntry` result as `pageContent`: reopening deletes the inserted blocks under the day's `updatedAt` and liveness precondition, a re-confirm then works, an earlier entry's blocks stay, a trashed day answers 409. The day itself stays (ADR `docs/adr/2026-11-14-undoing-a-journal-entry-confirmation-leaves-its-day.md`).
- An archived project is judged by `relationTargetBlock` (the relation write's own rule): 400 when the envelope is written or revised, 409 with nothing written at confirm.
