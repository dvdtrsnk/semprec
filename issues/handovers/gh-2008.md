## What was delivered

Every timeline item of the calendar read has an `attendance` field. `readCalendarTimeline` sets it to `"tentative"` on an Event that a live invitation of status `tentative` links to through `Invitations.event`, and to `null` otherwise (Events without an invitation, Events of an accepted, declined or trashed invitation, Tasks, virtual occurrences, derived entries). The compact shape carries it too.

## Entry points and contracts dependents build on

- Type: `CalendarTimelineItem.attendance: "tentative" | null` in `calendar/timelineSources.ts`; `CalendarTimelineCompactItem` picks it. Sources that build items by hand (`timelineTaskOccurrenceSource.ts`, `timelineSubscribedEventSource.ts`) set it to `null`.
- Reader: `readTentativeEventIds(client, eventIds)` in `calendar/timelineRead.ts`, one batched query (`TENTATIVE_EVENTS_SQL`) run after the lookup of the Invitations database, in the caller's tenant scope, over all stored Event ids of the range. It runs nothing for a range without a stored Event id, ignores virtual occurrence ids (`<seriesId>@<date>`), and returns an empty set for a tenant without an Invitations database. The read writes nothing.
- Relation direction: `Invitations.event` is property A of its definition, the invitation is in `item_a` and the Event in `item_b`.
- No route, table, migration or job name is added; the existing timeline and agenda routes return the field.

## Tests

`timelineAttendance.test.ts` (runtime role pool, two tenants; answers made through the real respond route handler of gh-1944): tentative marks the Event in the full and the compact shape; a change to accepted gives null; Events without an invitation, of an accepted invitation and Tasks give null; only the tentative Event is marked when others share the day; a trashed invitation does not mark its Event; another tenant's invitations never mark this tenant's Events (including a direct `readTentativeEventIds` call with the foreign Event id); the number of statements is the same for one and for several Events, and a range without a stored Event sends no attendance statement; virtual occurrences and a tenant without an Invitations database do not fail the read.
