# gh-1387 — Store a display name on users

Repository-Issue: gh-1387

Implementation commit: `1eb407c1` (`feat(auth): store an optional display name and return role from login`). Migration `0124_users_display_name.sql`, nullable column, no default, no backfill, no grant change.

## Delivered behavior

- `users.display_name text NULL` (migration 0124). Existing accounts keep `NULL`. The runtime role's table-level privileges on `users` (0057) cover the column.
- `UserRow` (`backend/packages/data/src/auth/types.ts`) has `displayName: string | null`. `PublicUser` inherits it.
- The column is read at every site that builds a user object:
  - `auth/usersStore.ts`: `createUser` (`RETURNING`), `getUserByEmail`, `getUserById`, all through `mapRow`.
  - `tenancy/tenantsStore.ts`: `getUserByEmailWithTenantStatus` (the `SELECT` and the `UserRow` it builds).
- Every response that returns a `PublicUser` now carries `displayName`: login, session, and the setup and invitation-accept responses. Each is `null` until a write path sets the name (#1513).
- `login` returns `role` (`LoginResult.role`). It is taken from the `lockUserTenantBinding` result already read inside the login transaction, so there is no extra query.
- `POST /api/auth/login` returns `user: { ...result.user, role }` in both the web body and the native body. This is the same shape `GET /api/auth/session` returns.
- `GET /api/admin/accounts` is unchanged: `accountsAdminStore.ts` is not touched. The tenant export (`tenancy/tenantExportJob.ts`) names its columns, so the export is unchanged too.

## Tests

- `backend/packages/data/src/__tests__/authActions.test.ts`:
  - The existing "creates a session" test now asserts `displayName: null` and `role: "member"`.
  - New `display name and role (issue #1387)` block:
    - `createUser` returns a `null` displayName for an account created without one.
    - `login` and `verifySessionToken` return a name stored on the account.
    - `login` returns `role` for an admin and for a member.
- `backend/services/semprec-api/src/__tests__/authHandler.test.ts`:
  - Web login body: `displayName` is `null` and `role` is `member`.
  - Native login body: `displayName` is `null` and `role` is `member`.
  - Native login body for an admin with a stored name: `displayName` is `"Ada Lovelace"` and `role` is `admin`.
  - `GET /api/auth/session` returns `displayName: null` for an account without a name, and the stored `displayName` once one is set.
- The stored name is set with a direct `UPDATE users SET display_name`, because no write path exists until #1513. Each test that does so says why in a comment.
