# gh-1262 — Remove the sole-tenant fallback from user and session tenant resolution

Repository-Issue: gh-1262

Implementation commit: `48a357c3` (`refactor(tenancy): remove the sole-tenant fallback from user and session resolution`). No migration and no schema change. `users.tenant_id` is already NOT NULL (migration 0085, #1067), so every `COALESCE(tenant_id, app_sole_tenant())` could only ever return `tenant_id`.

## Delivered behavior

- Tenant resolution reads `users.tenant_id` alone at every site the issue names:
  - `tenancy/tenantsStore.ts`: `getUserTenantBinding` (`JOIN tenants t ON t.id = u.tenant_id`); `getUserByEmailWithTenantStatus` (the `LEFT JOIN` is kept, so a missing tenant row still yields `tenantStatus: null`); `lockUserTenantBinding` (`SELECT tenant_id, role ... FOR KEY SHARE`, typed `string`, guard `if (!userRow)`).
  - `tenancy/accountsAdminStore.ts`: `ACCOUNT_SELECT`, `assertAnotherActiveAdminRemains`, `lockTarget`.
  - `tenancy/deleteAccount.ts`: `beginTenantDeletion` (the users-of-tenant read), `lockUserAndGuardLastAdmin`, `deleteAccountAsAdmin` (the target's tenant read, typed `string`).
  - `tenancy/tenantPurgeJob.ts`: `finalise` (the identity-row read) and `replayOneTenant` (the admin read).
  - `packages/realtime/src/pgNotifyPublisher.ts`: the session-to-tenant subquery in the `session_revoked` NOTIFY.
- `services/semprec-api/src/adminHandler.ts`: the AI budget route reads `tenant_id` typed `string`. The `tenantId === null` branch and its `ValidationError` are removed. The `ValidationError` import stays, because `requireCapField` still uses it.
- Docstrings that described the fallback as transitional are rewritten: `getUserTenantBinding`, `getUserByEmailWithTenantStatus`, `listAccounts`.
- `backend/review-rules/context.md`: the tenancy sentence now states that `users.tenant_id` is NOT NULL and that `app_tenant_default()` is strict. It also drops the single-tenant-guard clause, which migration 0123 (gh-1087) had already made false.
- Not changed: `getSoleTenantId` and `bootstrapFirstAccount`, `app_sole_tenant()` itself, `globalSetup.ts`, the `strictDefault` check in `db/tenancyInvariants.ts`.
