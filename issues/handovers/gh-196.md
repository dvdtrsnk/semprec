## Summary

Implements issue #196: bounded IMAP IDLE live reconciliation.

- **`backend/packages/data/src/mail/imapIdleLifecycle.ts`** — transport-agnostic orchestration for the `MailAccountLifecycle` that `mailLiveSyncRoot.ts` hosts per active `"imap"`-mode account. Runs one long-lived, self-healing IDLE loop per folder (Inbox and an All-Mail-equivalent folder): a hard-cycle deadline recycles a healthy connection on a fixed cadence, connect/session failures back off with a capped exponential delay (never a tight loop, never a permanent give-up), every connect-through-close round holds its slot in the same `ImapConnectionLimiter` `mailSyncJob.ts` reconcile passes already share (so IDLE sessions and sync passes stay under one provider connection budget), and a signal (EXISTS/EXPUNGE/flags) only ever re-enqueues through the existing idempotent `enqueueMailAccountSync` jobKey — never mutating a message directly.
- **`backend/packages/data/src/mail/imapIdleClient.ts`** — the imapflow-backed transport: renews IDLE well under the ~30-minute point most servers close it at (imapflow's own `maxIdleTime`), sets a socket timeout comfortably above that, relies on imapflow's built-in TCP keepalive, and resolves Inbox + an All-Mail-equivalent folder by special-use, falling back to plain `INBOX` when neither is advertised.
- Full unit test coverage in `imapIdleLifecycle.test.ts` and `imapIdleClient.test.ts` against fake transports/clients (no live server needed), covering renewal/recycling, bounded backoff, per-account connection-limit enforcement, folder-failure isolation, signal-triggered dedup, and clean shutdown.

No composition-root wiring was added — matching the rest of this codebase, no real IMAP transport is wired into a worker process yet (`backend/services/` is still a placeholder).
