## Changes

- **Migration `0048_create_items_partition_function.sql`** (new): adds `create_items_partition(database_id uuid)`, a `SECURITY DEFINER` plpgsql function with `SET search_path = pg_catalog, public`.
  - It runs `CREATE TABLE public.%I PARTITION OF public.items FOR VALUES IN (%L)` through `format()`, with the same `items_p_<hex>` name the application built before, so existing partitions keep their names.
  - It is owned by the migrating role (the owner of `items`). `EXECUTE` is revoked from `PUBLIC` and granted only to `semprec_data`; `semprec_side` gets nothing.
  - The header comment gives three things:
    - why the function exists;
    - that it takes the same `ACCESS EXCLUSIVE` lock on `items` for the caller's transaction as the inline DDL did;
    - the rule that any further DDL the API role needs goes through a function of this shape, never a schema grant.
  - It only adds things, so it needs no exemption marker.
- **The new partition is written as `public.%I`, not the bare `%I` the issue's snippet shows.** The pinned `search_path` puts `pg_catalog` first, so the bare name tried to create the table in `pg_catalog` and failed with `permission denied to create "pg_catalog.items_p_…"`. Adding `public.` keeps the name and schema identical to the partitions that already exist. The migration header explains this.
- **`databasesStore.createDatabase`**: the `format(...)` + `client.query(ddl)` pair is replaced by `SELECT create_items_partition($1::uuid)`. The `UUID_RE` sanity check stays, with its comments updated.
- **`leastPrivilegeRoles.test.ts`**:
  - `semprec_data`: a new test calls `createChokePoint(dataPool).createDatabase` and then `createItem` through the same choke point. It asserts both succeed and that `pg_class` contains `items_p_<hex>` for the new id.
  - `semprec_side`: a new test checks that calling `create_items_partition` is rejected with `permission denied`.
- **`docs/operations/database-roles.md`**: a new "DDL the API role needs" section covers the function, who owns it and who may call it, and the rule that DDL goes through a `SECURITY DEFINER` function, never a schema grant.
