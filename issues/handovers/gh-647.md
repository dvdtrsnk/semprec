## What changed

**New files in `services/semprec-agents`**
- **`piAgentSession.ts`**: `createPiAgentSessionFactory` builds one pi `Agent` per session and turns pi's events into the runtime's own event types, keeping each tool call paired with its result by id.
  - pi reports a failed model call as a final assistant message with `stopReason` `error`/`aborted`, not as a thrown error. The session turns that into a thrown error so the run closes as `error`.
  - A tool that throws stops the prompt and fails the run with the tool's own error. A tool that *returns* an error result (like the generic-operation tools do) is passed back to the model as normal input.
- **`modelComposition.ts`**: `createGatewayModel(env)` sets up the one model this process uses, pointed at `AI_GATEWAY_BASE_URL` and authenticated with `AI_GATEWAY_INTERNAL_TOKEN`. It throws naming whichever of the three variables is missing, so the process refuses to start. Each model call has a 10-minute timeout.
- **`agentSessionComposition.ts`**: `createAgentSessionFactoryForRun` builds one run's session:
  - the run's granted generic-operation tools;
  - one approval-gated tool per granted MCP registration (only when the run has a project);
  - the project's agent guidance added to a fixed English base prompt;
  - an `x-semprec-agent-run-id` header on every gateway request.
- **`agentRunTasks.ts`**:
  - `createAgentRunTask` handles both queued job types. A job for a run that is missing or not `running` is logged and writes nothing. If building the session fails, the run is closed as `error` rather than left `running`.
  - `createRunAgentForHeartbeats` is the function `coreAgentRunAction` calls to run the session for a heartbeat.

**Changes to existing files**
- **Wiring**: `queueRuntime.ts` accepts the new handlers as options; each one left out keeps its old placeholder, so existing tests are unchanged. `serve.ts` passes the real ones.
- **`packages/agent-runtime`**:
  - `runAgentSessionForRun` is split out of `runAgentSession` with the same behaviour; the existing `lifecycleAdapter.test.ts` passes unmodified.
  - The barrel now exports `runAgentTurn`, `pushRunStatus` and `extractResultSnapshot`.
  - `piProviders.ts` and its test are deleted.
- **Config and dependencies**:
  - The `pi-only-in-agent-runtime` dependency rule now also allows `services/semprec-agents`.
  - The two pi packages are pinned at 0.85.1 and the lockfile is updated.
  - A new `# ---- Agent runtime ----` section at the end of `deploy/shared/.env.example` adds `AI_GATEWAY_BASE_URL` and `AGENT_MODEL`.

## Where I departed from the issue text
- **`streamFn`**: the `@earendil-works/pi-ai` package root has no standalone `streamSimple`, and `createProvider` takes stream functions, not the string `"pi-messages"`. So the provider uses `piMessagesApi()` from the package's declared `./api/*` subpath, and `streamFn` is the model collection's own `streamSimple`.
- **Tool names**: model providers only accept tool names made of `[A-Za-z0-9_-]`, up to 64 characters. Dotted operation names like `item.create` are rewritten to `item_create`. MCP tools are named `mcp_<tool>`, and if two share a name the later one is dropped and logged.
- **Resuming a session**: `initialState.messages` holds this runtime's stored events, not pi messages, so it can't be passed straight to pi. A session asked to resume from non-empty history throws instead of guessing a conversion. Resuming belongs to conversation hosting, which the issue lists as out of scope.
- **Smaller event payloads**: `turn_end` stores only its kind, because the turn's message and tool results are already stored as their own events. Streaming updates are only the text, thinking and tool-call deltas.
- **README**: I also edited `packages/agent-runtime/README.md`, which isn't in the issue's file list, because it still pointed at the deleted `piProviders.ts`.
