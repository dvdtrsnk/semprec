Implements issue #158: streamed, deduplicated file uploads and authenticated blob downloads.

- `POST /api/files` streams the raw body (Content-Type + X-Filename), enforcing `maxFileSizeMb` both via a Content-Length precheck and an always-on streaming byte counter (so chunked/unknown-length requests can't bypass the cap), hashing with SHA-256 while streaming. Overflow aborts and leaves no partial blob or row.
- Blob creation and the Files item insert happen in one transaction, deduplicating on the blobs table's unique `content_hash`; concurrent identical uploads converge on a single blob and the lowest-id Files row.
- `GET /api/blobs/:id` is authenticated and supports byte ranges (206/416), conditional requests (`ETag=content_hash`, `If-None-Match` → 304), and a hardened `Content-Disposition` (RFC 6266/5987-safe filename encoding, `X-Content-Type-Options: nosniff`), with `?disposition=inline` honored only for a fixed safe MIME allowlist.
- Both routes are added as bespoke request listeners (like the existing `notificationsHandler`/`setupHandler`) since the generic JSON adapter buffers bodies and can't stream.
