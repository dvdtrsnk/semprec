## What was delivered

- `assertSelectValuesKnown(properties, patch, stored, writer)` in `chokePoint/itemWrites.ts`. For a user or agent writer a `select` value must be `null` or a key of `config.options`; a `multi_select` value must be `null` or an array of such keys (`[]` clears). A violation is a `ValidationError` with `field` = the property key; an unknown option is named in the message, a wrong shape is described by the expected shape. System writers are not checked.
- Called by `createItemReportingReplay` (after the title rule, on caller and transform values; keys filled in from `config.default` are excluded, `stored` is `null`) and by `updateItemWithClient` (after the stored row is locked and the pre-write transform ran, on the final patch). On update a key whose value deep-equals the stored one is skipped, so a client that sends back a whole record with an old unknown value does not fail. The item row is locked whenever a non-system writer patches a select or multi_select key.
- The temporary `alarmSound` check and `ALARM_SOUNDS` were removed from `sleep/sleepWriteHooks.ts`; the generic check covers the sleep select cases.
- A malformed stored option config throws a plain `Error` (server error), like `assertMarkdownValues`.

## Contracts dependents build on

- Every user or agent item create and update (REST, agent `item.patch`, MCP) answers an unknown select option with HTTP 400 `validation_failed` and `details.field` = the property key; MCP answers JSON-RPC -32602 with the same message and `data {field}`.
- No new export, route, table, operation or job name; no migration.

## Deviations from the specification and spec seams

1. On update the call is after the item row lock and the pre-write transform, not right after `assertWritableProperties`, because it needs the stored row and ADR 2026-11-12 (module locks before the row lock) forbids locking the row earlier. It checks the final patch.
2. On create the check runs after transform and defaults, beside the title rule; config defaults are excluded because `assertValidDefault` stores a `multi_select` default as a bare option key.
3. `assertUserItemPatchValid` / `prepareUserItemPatch` (Inbox proposal preparation) are deliberately unchanged: that is gh-1814.
4. A test file outside the Touches folder (`selectValueWritePaths.test.ts`) covers REST, gateway and MCP.
5. No ADR.
