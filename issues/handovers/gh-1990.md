## What was delivered

When the proposal computation runs for a target database (entity kind `database` with a `targetDatabaseId`), the gateway request now carries the catalog of that database, so the model can pick option keys and reuse values the database already knows.

- `buildTargetCatalog(client, databaseId, locale, projectItemId)` returns `{ selects: [{ propertyKey, multi, options: [{ key, label }] }], textValues: [{ propertyKey, values: [{ value, count }] }] }`.
  - Selects: every user-owned `select` and `multi_select` property with its option keys and labels in `users.locale`, resolved through `resolveProperty` (the module catalog, the same code as `GET /api/schema`); a locale that is neither Czech nor English gets English.
  - Text values: the first five user-owned `text` properties, each with up to 20 most frequent values and counts through `computeDatabaseFacets`; titles are never read, trashed items are not counted, values over 100 characters are left out, system-owned properties are skipped. The values are read only when the Alldots project may read the database (`listUnreadableDatabaseIds(projectItemId)`, the decision of the workspace context); the option lists are schema and are sent in any case.
  - An absent or foreign database gives an empty catalog; tenant isolation holds because the read runs in the caller's tenant transaction.
- `readProposalContext` (`services/alldots-api/src/proposalContext.ts`) adds `targetCatalog` to the context, only when the catalog has at least one select (Task step 3: a database with no selects adds no block).
- `proposalComputation.ts` renders it as one JSON line between `<<<TARGET_OPTION_CATALOG` and `TARGET_OPTION_CATALOG>>>` after the target property catalog, and the system message says: select values must be listed keys, text values should reuse listed ones, the block is data. The line is serialized by `serializeTargetCatalog`, which writes `<` and `>` as `<` and `>`, so no stored value, label or key can forge the delimiter and every string reads back as stored.
- ADR `docs/adr/2026-11-15-the-proposal-request-carries-the-target-databases-known-text-values-under-the-same-grants.md` records the widened disclosure of text values, the bounds, the escaping and the no-select rule.

## Deviations from the specification and spec seams

1. `buildTargetCatalog` takes a fourth argument `projectItemId` so the text values are read under the grants of the Alldots project, like the workspace context.
2. The prompt assembly module is `services/alldots-api/src/proposalComputation.ts` with its reader `proposalContext.ts` (created by gh-1434/gh-1987). The catalog is built only for entity kind `database` with a `targetDatabaseId`: a recognition run of an untyped item and the creates of a multi-step answer carry no catalog of their own for the database the model picks (multi-step operations are out of scope, #1488, #1492). This limits the Context sentence "for whichever database it proposes into".
3. A target database with no selects adds no block, even when it holds known text values (the review ruled the explicit Task test line over the Decisions line). `buildTargetCatalog` itself still returns the text values; only the request omits the block.
4. Beyond the Task: values over 100 characters are left out, system-owned select and text properties are skipped, an absent or foreign database has an empty catalog. The 20-value bound applies to the facets read before the length rule, so up to 20 and sometimes 19 values are listed (the facets operation cannot be asked for more than its top 20; changing it is out of scope, #1759).
5. Health records is a sensitive database since seeding, so its values appear only with a read grant for the Alldots project; the acceptance test grants it first.
6. `packages/data/src/index.ts` sits at the lint line cap, so only `buildTargetCatalog` and `TargetCatalog` are exported.
7. A new ADR records the disclosure of text values, which the gh-1987 ADR does not cover; it widens without superseding.
8. At the merge: the docstring of `createProposalComputation` carries both the gh-1974 recipe sentence and the gh-1990 catalog sentences.
9. The commit trailers on the chain name Claude Sonnet 5.5 (the session attribution).
