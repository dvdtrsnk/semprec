## What was delivered

A permanent transcription failure is now a Semp problem, and the report has a transcription service entry.

- `recordTranscriptionFailure` (services/semprec-transcribe) raises `transcription:<transcriptId>` (category `transcription`, kind `transcriptionFailed`, severity `warning`, source `item_automation`) after the notification, in the same transaction, with occurrence key `attempt:<attempts>`. A second permanent failure merges into the active problem (`occurrence_count` 2). A transient failure, a transcript that is already done and a tenant without a user raise nothing.
- `runFinalizeStep` resolves the problem as `recovered` inside the finalize transaction, after the item is marked done; the title in the recent history is `Transcript '{name}' completed` (cs: `Přepis „{name}“ byl dokončen`).
- A new item delete hook `transcription/transcriptProblemDeleteHook.ts`, registered at the end of `domainWriteHooks.ts`, resolves the active problem as `sourceDeleted` (silent: not listed in history) when a Transcripts row is trashed.
- The Semp report gains the service `transcription` ("Meeting transcripts" / "Přepisy schůzek") with `detail { queued, running }` from `semp/sempTranscriptionQueue.ts` (one tenant-scoped query over the graphile-worker tables for the `transcriptionJob` task). `state` is `error` with the problem's `since` while a problem is active, otherwise `ok`.

- Hook order: the hook is registered last in `domainWriteHooks.ts`; gh-1919 registers no hook, so there is no order to keep between the two.
- No route, operation, table or migration is added.

## Deviations from the specification and spec seams

1. No transcript delete hook of #1601 exists (its transcript hook handles Events), so the hook is new.
2. `packages/data/src/index.ts` is at the 900-line ESLint cap, so no barrel export was added: the key builder lives in `@semprec/shared` and the producer calls in a sibling module of the transcribe service.
3. `queued` excludes jobs that used up their attempts (the predicate of the system health report); `running` is `locked_at IS NOT NULL`.
4. The service entry has `lastActivityAt` null (the Task defines none).
5. The title name is the Transcripts item's own `name` property, as the existing active-problem text reads it; a transcript the user never named reads `Transcript '(unnamed)' completed`, because the display-name chain would need per-transcript lookups and break the constant-query rule.
6. A permanent failure of a transcript that is already done, or in a tenant without a user, raises no problem (the existing early returns).
7. Restoring a trashed transcript raises no problem (out of scope).
