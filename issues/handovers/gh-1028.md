**What changed**
- **Decide** (`approvalRequestsStore.ts`): the `UPDATE` now also requires `EXISTS` a run with `actor_user_id = $3`, so the ownership check is part of the same statement.
- **Owner-scoped reads**: `listPendingApprovalRequests` joins to `agent_runs` and filters by owner. The new `getApprovalRequestForOwner` returns the row only for its run's actor. `listApprovalRequestsQueue` takes the owner id.
- **Wrapper** (`approvalDecisionAction.ts`): `decideAndEnqueueApprovalRequest` returns `{ outcome: "decided" | "unchanged", request }` or `null`. The re-read happens in the same transaction, and the second transaction in the handler is gone.
- **Handler** (`approvalRequestsHandler.ts`): `GET` passes the session user. `PATCH` returns 200 for both outcomes, and `null` returns the same 404 body as an unknown id.
- **Exports**: `DecideAndEnqueueResult` is exported as a type. `decideApprovalRequest` and `getApprovalRequestForOwner` stay unexported.
- **Tests**: all the sites the issue lists now decide as the run's actor. I added the not-owned ≡ unknown, store-guard, owner-listing and repeat-decision cases.

**Choices I made that you should check**
- The issue asked for the decide `UPDATE` with no pre-check. The write-safety check then flagged that its zero-row result was never read. I read `rowCount` explicitly and return `null` on zero rows, rather than using `requireAffectedRows`, because zero rows is a valid outcome here.
- The cross-tenant acceptance criterion has no test. The issue asked for the two-tenant runtime-role harness of #975. I did not write that test, so this criterion is unverified. The new same-tenant tests cover the owner logic only.
- A repeat PATCH by a non-owner used to return 200 with the current state. It now returns 404, which is what the issue specifies.
- One unit test (`moduleRegistryLoadAll`) timed out once under load. It passed when rerun alone, and the full verify then passed.
