## What changed

Every gateway reservation is now checked, under the unchanged global advisory lock, against the tenant's own caps and an operator-wide safety cap. Verify has not been run end to end. I ran lint, the format check, the build, the unit tests, the migration-numbering, write-safety and boundary checks, and the affected integration suites, and all passed.

- **Migration `0073_ai_global_spend.sql`** (re-runnable):
  - Gives `semprec_router` column-level `SELECT (at, cost_usd)` on `ai_gateway_calls`.
  - Adds `ai_global_spend()`, a `SECURITY DEFINER` function owned by `semprec_router` that sums spend over all tenants in UTC. `PUBLIC` has no `EXECUTE`; `semprec_side` does.
  - Adds the `ai_gateway_calls (tenant_id, at)` index.
  - Re-syncs every `tenant_ai_budgets` row with `updated_by IS NULL` from its settings item, using #1004's mapping. Tenants without a settings item are skipped.
- **Data package:**
  - Added `getGlobalGatewaySpend`.
  - Removed `getAiBudgetsWithTimezone` and its tests.
  - Updated the `publicSurface` exports.
- **`ai-gateway` package:**
  - Added `GlobalAiCaps` and a required `globalCaps` on `GatewayCallContext`.
  - `assertWithinBudget` refuses when the tenant has no budget row.
  - It also refuses on the tenant daily or monthly cap (tenant timezone, own rows), then on the global daily or monthly cap (UTC, all tenants).
  - Every refusal throws `BudgetExceededError("AI budget exceeded")`. Each one logs `{ limit }` once at `warn`, with no amounts.
- **Gateway service:** the three handlers take `globalCaps` and pass it into the call context. `startupConfig` requires `AI_GLOBAL_DAILY_CAP_USD` and `AI_GLOBAL_MONTHLY_CAP_USD` as positive numbers and fails startup naming the variable.
- **Docs:**
  - Both env templates document the two variables as required.
  - A new ADR supersedes `2026-09-27-ai-budget-reservations-under-a-global-advisory-lock`, and only that ADR's frontmatter was edited.
  - The cost-control bullet in `.bb/skills/ai-gateway/SKILL.md` is updated.
- **Tests:**
  - **Two-tenant gateway tests** cover tenant daily and monthly caps, no budget row, no tenant scope, `NULL` caps, global daily and monthly caps, and both window boundaries.
  - **Handler tests:** a handler-level test checks that the 403 body is byte-identical for the global cap and the tenant's own cap, on all four routes.
  - **Data tests:** new data-package tests cover the router function and the migration re-sync.
  - **Startup config:** unit tests cover the new variables.
  - **Fixtures:** existing fixtures now use `tenant_ai_budgets` rows and `globalCaps`. The unknown-tenant cases in `callerTenant.test.ts` now expect `403 budget_exceeded`.

## Before promoting this release

A deploy without `AI_GLOBAL_DAILY_CAP_USD` and `AI_GLOBAL_MONTHLY_CAP_USD` leaves the gateway unable to start. Set both before promoting.
