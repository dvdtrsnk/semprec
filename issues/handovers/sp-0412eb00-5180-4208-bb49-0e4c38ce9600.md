# Handover for sp-0412eb00-5180-4208-bb49-0e4c38ce9600

Implementation commit: 6cb9a473b (branch `bb/napl-novat-offline-first-synchronizaci-v-kmp-thr_6535e6iusa`).

`AuthenticatedApi` hands every read of the offline set (`OfflineRoutes`) to a process-wide `OfflineLayer`
(`OfflineLayer.shared(directory)`), which keeps each answer as a JSON file under `<dataDirectory>/offline/<account>/answers/`
(FNV-1a file names, an index, at most 500 answers, none over 1 MiB, a 100-entry memory LRU).

- A kept answer is fresh when this process kept it after the last change signal and less than 5 minutes ago; a fresh
  answer is returned without a request. Change signals: successful writes, the sync socket connecting, every frame.
- A stale read goes out; a success is kept, `404` removes the kept answer, and no answer, a `5xx` or a `429` returns
  the kept answer. A request without an answer makes the process offline: kept answers are returned at once and one
  probe goes out at most every 15 s. An answer that ends the offline state makes everything stale and tells every
  window through `ItemChanges`.
- Every end of the session clears the store; a late answer for an ended account is dropped.
- The Apple app passes `Application Support/Offline` (excluded from backups); the memory session store passes nothing.
- Decision: `docs/adr/2026-11-23-mobile-keeps-the-answers-of-the-offline-set.md`.

Tests: `OfflineStoreTest`, `OfflineLayerTest`, `AuthenticatedApiOfflineTest` (every kept route, freshness, stale reads,
offline answers, the probe, `404`, the session end) and the `SyncSocketTest` case for connects and frames.
