# Handover for gh-1634

`sendDraftEmail` now builds the complete message with `buildOutgoingMime` and submits its raw bytes through a `MailTransport` chosen by the mailbox's sync mode. The SMTP transport serves `imap` mailboxes. Nothing supplies the factory from a composition root yet, so no route sends mail (#1896).

## What was added
- **`backend/packages/data/src/mail/mailTransport.ts`** (new):
  - `MailTransport` with `send({ raw, envelope: { from, recipients }, providerThreadId? })` resolving `{ providerMessageId? }`, and `MailTransportFactory` with `forMailbox(mailboxItemId, syncMode)`.
  - `createMailTransportFactory(pool)`. For `imap` it reads the stored SMTP endpoint (no endpoint is `ValidationError` with `details: { field: "smtp" }`), decrypts the app password with `actorType` and `purpose` both `smtp_send`, and returns the SMTP transport. Any other sync mode rejects with a plain `Error`; #1637 and #1753 add their branches there.
  - `createSmtpMailTransport(mailboxItemId, settings, credential, open?)`, exported for the protocol tests. Each send opens a transporter through `createSmtpTransporter` and closes it on every path out.
- **Errors** (`providerTypes.ts`, exported from `index.ts`): `MailSendAuthFailedError` (`mail_send_auth_failed`) and `MailRecipientRejectedError` (`mail_recipient_rejected`). Neither message contains the server's response or the password. A 535 or another `EAUTH` maps to the first. An `EENVELOPE` on `RCPT TO` with a 5xx maps to the second, and so does any partial refusal (the server accepted the message for some recipients). `MailReauthorizationRequiredError` is not used here.
- **`smtpClient.ts`**: `sendRaw({ raw, envelope })` with the 30 second deadline. A timeout rejects with `MailServerUnreachableError`. `NodemailerSmtpClient` now takes a `MailSmtpTransporter`. `sendMail(OutgoingMailMessage)` is still there but `sendDraftEmail` no longer calls it.
- **`mailServerConnections.ts`** (outside the Touches list, needed by the Task): `sendMail` resolves `{ refusedRecipientCount }` instead of `void`, so a refused recipient is visible. `close()` now destroys every socket the transporter holds, including one still connecting. nodemailer's own `close()` does not end an in-flight send, which the timeout path depends on.
- **`outgoingMime.ts`**: optional `html` input, sent as a `multipart/alternative` part beside the text. Without it, HTML drafts would lose their HTML.
- **`send.ts`**: `MailSendAdapterFactory` is now `{ transports?, attachmentStorage? }`. The sync mode comes from `mail_account_sync_state`, or from `defaultSyncModeForProvider` of the mailbox's `provider` property (`generic` if absent). The transport and MIME build sit inside the block that undoes the send claim on failure. The envelope sender is `from.address`, and the recipients are `envelopeRecipients`, which include bcc.
- **`testSupport/mailSendFakes.ts`** (new, test-only): `recordingTransport`, `transportFor`, `sendAdapters`.

## Behaviour changes to `sendDraftEmail`
- The access log records `smtp_send` as both actor and purpose. It used to record `email_send`.
- A missing credential is found after the claim is taken, so the claim is undone. The earlier code threw before the claim.
- A draft with no text body sends an empty `text/plain` part next to its HTML.
- The message has no `Date` header. nodemailer never added one on the old path either, so this is not a regression. RFC 5322 requires `Date`, and a follow-up should decide where it is added (`outgoingMime.ts` is the natural place).

## Tests
- `smtpTransport.test.ts` (integration tier, 20 cases) runs against a loopback TLS fake SMTP server with a certificate made by openssl at test time, and a DNS stub. It covers raw submission with the bcc envelope, 535 (the password is absent from the error), a refusal of every recipient, a partial refusal, a 451 refusal and a refused sender (both pass through unchanged), a refused connection, a loopback name refused before any connection, close ending an in-flight send, close during connect, the three close paths of `createSmtpMailTransport`, the 30 second deadline with fake timers, and the factory's database branches (decrypt purpose, policy refusal, no settings, IMAP-only, no credential, sync mode without a transport).
- `mailSend.test.ts`: HTML part, bcc in the envelope but not in headers, claim undone when the transport cannot be built, sync-mode routing (sync-state row, provider default, generic default), and the missing-transports and missing-attachment-storage errors. The existing send tests keep their assertions. Only the factory shape changed, plus the message-id check, which now reads the raw bytes.
- Mutation checks: removing the `EAUTH` mapping, removing the partial-refusal throw, widening the 5xx gate to 4xx, changing the deadline to 60 seconds and removing the socket destroy. Each was caught by its matching test, and each file was restored and checked byte for byte.
- Not covered: a real 30 second deadline through `createSmtpMailTransport` (the deadline is tested with fake timers on `NodemailerSmtpClient`); a `MailRecipientRejectedError` through `sendDraftEmail` (only the transport produces it); a successful STARTTLS send (the fake server refuses STARTTLS).
- Ran: `pnpm run lint`, `pnpm run format:check`, `pnpm -r run build`, `check:write-safety`, `check:boundaries`, and vitest on the six touched test files (95 tests, all passing). The full `verify` was not run.

## Notes for dependants
- **#1637 and #1753**: implement `MailTransport` and add a branch to `forMailbox`. `providerThreadId` in the message is theirs. The SMTP transport ignores it.
- **#1896 (send route)**: a successful SMTP send returns no `providerMessageId`. Map `MailSendAuthFailedError` and `MailRecipientRejectedError` to their statuses. `MailServerUnreachableError` is mapped by #1569. Read the partial case with care: the accepted recipients already have the message, and `sendDraftEmail` undoes the claim, so a retry would resend to everyone. A connection reset after the server took the message also reads as unreachable, and the claim is undone the same way. Treat that as "delivery unknown".
- **Composition root**: nothing supplies `transports` or `attachmentStorage` yet. Until one does, `sendDraftEmail` throws `No SMTP adapter configured for this composition root`.
- **Credential purpose**: `smtp_send` is now the purpose of the send. Any tooling that filters `credential_access_log` by `email_send` must change.
- **Dead production code**: `NodemailerSmtpClient.sendMail` and `OutgoingMailMessage` have no production caller. Remove them in #1637 or #1753 if those have no use for them.
