# Handover for gh-1423

One closed risk class set now covers generic operations, MCP approval snapshots and `approval_requests`.

**What changed**
- **Shared list:** `capabilities.ts` exports `RISK_CLASSES` (`unclassified`, `read`, `write`, `destructive`, `outbound`, `breaksLink`), `RiskClass` and `isRiskClass`, available through the `@semprec/shared` barrel.
- **Operation metadata:** `OperationMetadata.riskClass` is a non-null `RiskClass`. The nine reading operations are `read`, the other non-destructive ones `write`, the five approval-gated ones `destructive`. `nonDestructive(capability, "read" | "write")` takes the class explicitly. `requiresApproval` is unchanged.
- **Gateway:** `preflightDestructiveApproval` no longer uses a non-null assertion on `riskClass`.
- **Migration `0094_approval_requests_risk_class_check.sql`:** backfills unknown `approval_requests.risk_class` values to `unclassified`, then adds `approval_requests_risk_class_check`.
- **Store:** `rowToApprovalRequest` validates `risk_class` with `assertKnownValue(RISK_CLASSES, ...)`; `ApprovalRequest.riskClass`, `CreatePendingApprovalRequestInput.riskClass` and the queue entry and decision view are typed `RiskClass`.
- **MCP snapshot:** `createApprovalGatedMcpInvokeTool` maps a registration class outside the list to `unclassified` before inserting.
- **Web:** `riskClass.*` labels for all six values in cs and en (`web/src/i18n/messages.ts`). Nothing renders them yet; the existing `agentPage.tools.riskClass.*` keys and the approval queue row are untouched.

**Tests**
- `operationCatalog.unit.test.ts`: the exact six values, `isRiskClass` accepts exactly them, and every operation is read, write or destructive per its capability and approval flag.
- `approvalRequestsStore.test.ts`: the database rejects an unknown class; the migration SQL, re-run after dropping the constraint, backfills a legacy `high` row to `unclassified`, keeps `destructive`, and re-establishes the CHECK.
- `mcpInvokeTool.test.ts`: a registration class of `high` becomes `unclassified` on the request, `outbound` is kept.
- `i18n.test.ts`: cs and en labels exist for all six.
- Existing tests that inserted `moderate`, `high` or `low` approval requests (`approvalRequestsQueue.test.ts`, `approvalRequestsHandler.test.ts`) now use values from the set.

**Notes for dependants**
- `mcp_tool_registrations.risk_class` is still free text with default `unclassified`, and `setMcpToolRiskClass` still accepts any string (#1979). The web tools block still offers `low`/`moderate`/`high`; a tool set to one of those snapshots as `unclassified` into an approval request.
- Producing `outbound` and `breaksLink` requests is #1713 and #1913; a new class must extend `RISK_CLASSES` and the migration's CHECK list in a new migration.
- `mail/send.ts` is unchanged.
