# Handover for gh-1566

Every user turn (the wake text and each follow-up) is now persisted as a `user_message` agent run event and replayed into the model history. Committed locally on `wf/gh-1566`; not pushed.

- **Kind:** migration `0112_agent_run_events_user_message_kind.sql` replaces `agent_run_events_kind_check` (pattern of `0016`). `user_message` is added to `AgentMessageKind` (`types.ts`), `AGENT_MESSAGE_KINDS` (`conversationReconstruction.ts`), `AgentRunEventKind` / `AGENT_RUN_EVENT_KINDS` (`agentRunEventsStore.ts`) and `PERSISTED_EVENT_KINDS` (`lifecycleAdapter.ts`). Reconstruction, `listAgentRunEvents` / `listAgentRunEventsAfter` (so `agent:watch` replay) and startup repair read it without throwing.
- **Payload:** `{ kind: 'user_message', text, context }` where `context` is `UserTurnContextRef[]` (`{ label, ...ref fields }`, exported from `@semprec/agent-runtime`). Only the ref objects and their send-time labels are stored, never expanded content.
- **Write order:** `promptMessages` in `piAgentSession.ts` yields the `user_message` first and starts `agent.prompt` only after the consumer resumed the generator, i.e. after the lifecycle adapter persisted it. Wake turn: `AgentSessionOptions.context` (optional). Follow-ups: `AgentSession.send(task, context?)`. Existing callers pass no context, so they store `context: []`.
- **History:** `toPiMessages` converts `user_message` to a pi user message with the text only (refs not expanded; #1733). Earlier history is not backfilled.
- **System messages:** `PiAgentSessionFactoryOptions.pendingSystemMessages?: () => readonly string[]` is called once per turn and its strings are prepended to the prompt text (joined by a blank line). The stored `user_message.text` is the user's text only, so replayed history does not contain the system messages. Absent in production composition for now (#1772 supplies it).
- **Tests:** new cases in `piAgentSession.unit.test.ts`, `piConversationHistory.unit.test.ts`, `conversationReconstruction.test.ts` (question, answer, follow-up order) and `agentRunEventsStore.test.ts` (CHECK accepts the kind, list and replay). The existing event order test now starts with `user_message`. Logs: no new log statements; message text and refs are not logged. Full verify was not run.
- **For dependants:** #1727 and #1738 pass `context` through `AgentSessionOptions` / `send`; the caller must supply labels at send time. A `user_message` event also appears as the first persisted event of existing sessions, so consumers counting events by kind should expect it.
