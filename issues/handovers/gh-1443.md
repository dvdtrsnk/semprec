# gh-1443 — Filter push fan-out by preferences and set the interruption level

Repository-Issue: gh-1443

## Delivered behavior and production wiring

- `pushInterruptionLevelFor(policy, preferences)` in `backend/packages/data/src/notifications/notificationFanoutJob.ts` (exported, pure). It returns `null` for no push, or the APNs interruption level:
  - `policy.push` false (`info`) returns `null`, whatever the other inputs.
  - Approvals follow `approvals`: `time-sensitive` when on, `null` when off.
  - Invitations and reminders follow `invites` and `reminders`: `active` when on, `null` when off. No kind uses these categories yet.
  - Problems follow `problemsLevel` by severity first: `off` passes nothing, `critical` passes critical, `all` passes critical and warning. Then `problemsSummary`: on gives `time-sensitive` for critical and `passive` for warning; off gives `active` for both.
- `handleNotificationFanoutTask` reads the notification, then `getNotificationPreferences(client, userId)` (the stored row or the defaults) and `policyForKind(kind)`, all before any registration is loaded. A `null` decision returns with no `push_deliveries` row claimed and no send. The notification row is untouched, so the in-app list still shows it.
- `NotificationPushPayload` (`backend/packages/data/src/push/pushSenders.ts`) gains `interruptionLevel?: NotificationInterruptionLevel`. The job sets it on every send it makes.
- `sendApnsNotification` (`backend/packages/data/src/push/apnsAdapter.ts`) emits `aps["interruption-level"]` only when the payload carries one. Without it APNs delivers at `active`. `webPushAdapter.ts` serializes its three fields explicitly and does not read the level.
- No schema change, no migration, no new write. The job only reads.
- `pushInterruptionLevelFor` is a new runtime export of `@semprec/data` (through `export *` of `notificationFanoutJob.ts`). `publicSurface.test.ts` lists it.

## Tests

- An approval with approvals off is stored, nothing is sent, and no `push_deliveries` row exists.
- An approval with approvals on is sent with `interruptionLevel` `time-sensitive`.

## Notes for dependants

- A `heartbeat_error` or any other warning is no longer pushed under the default preferences. Anything that expects a push for a warning must set `problemsLevel` to `all` first.
- The summary switch never blocks a push. It only lowers warnings to `passive` and critical problems to `active`.
- The job reads preferences on every run, including retries. If a preference is turned off between a transient failure and the retry, the remaining pending registrations are not sent. That is the intended behaviour: the change applies to pushes not yet sent.
- A new kind must have a `NOTIFICATION_KIND_POLICY` entry (gh-1440), or the build fails. An invitation or reminder kind also needs an end-to-end fan-out test.
- The level is set only by the job. `sendApnsNotification` omits `interruption-level` when the payload has none, but the job always sets one today.
- Web Push ignores the level. A web-only field must be added to `webPushAdapter.ts` explicitly; the payload is not forwarded as a whole.
- Not in this change: the once-per-problem push (#1466), the collapse id, thread id and expiration (#1829), the app icon badge (#1891) and the sleep-window hold (#1794).
- Migration ordinal: none. This change adds no migration.
