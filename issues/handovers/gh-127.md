## Summary

Implements issue #127: management of project-level MCP tool grants (the "Tools block").

- **Backend** (`@semprec/data`): `mcpAgentPageGrants.ts` adds the read model (`listMcpToolGrantsForProject`, joining registrations with server identity and this project's grant, default unchecked) and write wrappers (`setProjectMcpGrantForAgentPage`, `reclassifyMcpTool`). These wrappers live inside the package so the admin-only mutations in `mcpGrantsAdminStore.ts` stay unreachable from `agent-runtime`'s public import surface — an existing security boundary in this codebase.
- **HTTP API** (`semprec-api`): `mcpAgentPageHandler.ts`, bearer-token authenticated, exposing GET/PATCH for project grants and PATCH for tool reclassification, routed alongside the existing AI-usage handler.
- **Frontend**: `mcpAgentPageOperations.ts` (zod-validated client) and `ToolsBlock.tsx`, a self-contained component grouping tools by server with a checkbox bound to the project's grant, plus risk-class/requires-approval controls. Covers loading, empty, error, transport-offline, mutation-error, and concurrent-refresh states with i18n labels in both catalogs (`en`/`cs`).

Note: no standalone "AGENT page" with guidance/heartbeats blocks exists yet in `web/src`, so this lands as a tested, drop-in component ready to be composed into that page once it's built, rather than fabricating the rest of that page's scope.
