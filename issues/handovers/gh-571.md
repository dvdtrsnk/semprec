## Summary

Adds `.github/scripts/review-followups/input-file.mjs`, which defines the format of the triage input file for the review follow-ups pipeline (epic #565). It is a zero-dependency ES module. Its header comment is the reference description of the file, and it exports two functions:

- **`renderInputFile(input)`** takes the whole file object (including `version: 1`) and returns JSON with two-space indentation and a trailing newline. It validates the input first and throws on any violation.
- **`parseInputFile(text)`** parses the text and validates everything. If the text is not JSON, the error says it "does not parse as JSON". Otherwise the `Error` names the first offending field, e.g. `input file field "findings[1]" repeats pr 301 key 0123456789`.

Both functions share one validator, so the renderer can't write a file the parser would reject.

What the validator checks:
- **Top level:** the file has exactly `version` (must be `1`), `harvestIssue` (positive integer), `findings`, `prSummaries` and `openIssues`.
- **`findings` entries:** each entry must have the three extra fields: `fullText` and `suggestedFix` (string or `null`), and `threadReplies` (an array of `{ author: non-empty string, body: string }`, nothing else). With those three removed, the rest must pass #570's `validateFindingRecord`. That call also rejects any extra field, and its message is prefixed with the entry's path, e.g. `findings[0]`. No two entries may share `(pr, key)`.
- **`prSummaries`:** each entry is exactly `{ pr, body }`, with at most one per `pr`.
- **`openIssues`:** each entry is exactly `{ number, title, labels: string[], touches }`, with no duplicate `number`.

## Tests

`input-file.test.mjs` uses `node:test` and `node:assert/strict`, with no network access. `node --test .github/scripts/review-followups/input-file.test.mjs` runs 69 tests and all pass. They cover:
- **Round trip:** a full file and a file with empty lists both come back unchanged, and the output uses two-space indentation and ends in a newline.
- **Invalid inputs:** one shared table holds every case from criterion 2 (and every other branch of the validator). Each case is run through both `renderInputFile` and `parseInputFile`, and the test checks the error names the field.
- **Bad text:** non-JSON text and a non-string argument.

I did not run `pnpm run verify` in `backend/` or `web/`, because this change touches only `.github/scripts/`; Relay's own step runs it. Both new files pass `prettier --check` (the formatter rewrapped the test file once before the commit).
