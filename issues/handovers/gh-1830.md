## What was delivered

- `transcription/transcriptDisplayName.ts`: `resolveTranscriptDisplayName` (the user's name, else the live linked Event's name, else the translated "Recording D. M. HH:MM" from the date in the tenant zone; blank values count as absent) and `resolveTranscriptSuggestedName` (the generated notes title, only without a name and without a live Event). Template `transcript.displayName.recorded` in the transcription catalog (cs, en). Both resolvers are exported from the `@semprec/data` barrel (and listed in `publicSurface.test.ts`).
- The detail projection (`transcriptDetail.ts`) and the list projection (`transcriptListQuery.ts`, tenant zone read in the same single SQL statement) return `displayName` and `suggestedName`.
- The create step (`services/semprec-transcribe/src/transcriptionTask.ts`) no longer copies the file name and writes `Transcripts.name` only from `recording_requests.name` (`readRecordingRequest` in `transcription/recordingIntake.ts` now returns `name`).
- `matchTranscriptToEvent` and `createTranscriptEventCard` name the proposed meeting after the transcript's name, else the rendered notes title, else the translated "Meeting D. M." fallback; `buildNewMeetingEnvelope` throws on an empty name.
- Per-tenant cutover `transcription/transcriptNameBackfillCutoverMigration.ts` (`runTranscriptNameBackfillCutoverMigration`) clears `Transcripts.name` where it equals the source `Files.name` (keyset pages, choke-point item update, idempotent). It is registered in `db/tenantCutoverMigrations.ts` after the entry of gh-1817 and before the area-note cutover that stays last.
