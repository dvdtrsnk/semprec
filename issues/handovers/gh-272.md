## Summary

Fixes issue #272's two post-merge review findings on `mailLiveSyncRoot.ts`:

1. **Double-start guard**: `start()` now captures a generation counter synchronously before its initial `await reconcileOnce()`. A second `start()` call (sequential or unawaited/concurrent) returns immediately instead of scheduling a second interval. `stop()` bumps the generation and clears the `started` flag, so if `stop()` runs while a `start()` is still awaiting its initial reconcile, that call detects it's been superseded and skips scheduling its interval when it resumes — this also correctly handles the `start()` → `stop()` → `start()` ordering.
2. **Batched discovery**: `discoverActiveAccounts()` now reads a page and seeds every account's `mail_account_sync_state` inside a single `withTransaction` (one transaction per page instead of N+1). Each account's seeding runs under its own `SAVEPOINT`, rolled back on failure, so one account's error is still reported via `onLifecycleError`, doesn't drop the rest of the page from the active set, and doesn't abort the shared transaction.

Added tests in `mailLiveSyncRoot.test.ts` covering: sequential double-start, unawaited concurrent double-start, `stop()`-during-`start()` interleaving (including the `start→stop→start` ordering), and batched/savepoint-isolated discovery (verified via a proxy pool that rewrites one account's seed statement into a server-rejected query, confirming the failure genuinely aborts and recovers at the Postgres level, not just locally).
