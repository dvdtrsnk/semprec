## Contracts dependents build on

- **`setAgentRunMcpClientName(client: PoolClient, runId: string, name: string): Promise<void>`**, exported from the `@semprec/data` barrel through the existing `export *` of `agentRunsStore.ts` and listed in `publicSurface.test.ts`. It removes control characters (Unicode category Cc only), trims, cuts to the first 64 code points, trims the whitespace the cut left at the end, and writes NULL when nothing is left. It throws `NotFoundError` when the UPDATE matched no run in the current tenant scope (another tenant's run reads like an unknown run).
- **`AgentRunRow.mcpClientName`** is on every row the store returns. `GET /api/agent-runs/:id` returns the row, so its response carries a top-level `mcpClientName` from this source on.
- **Who can be named.** Only the run of the credential that made the handshake: the run id and the tenant come from the resolved run credential, never from the request. A human session, a missing `clientInfo` and a non-string name write nothing; the `initialize` answer is unchanged in every case. A second `initialize` replaces the name.
- **The name is untrusted display text.** Format characters such as zero-width joiners, bidirectional overrides (U+202E) and U+2028/U+2029 are kept. A client that renders the name must treat it as untrusted text (security reviewer).
- **Failure of the write fails the handshake**: HTTP 404 through the handler's outer catch if the run vanished after the credential resolved, 500 on a database error.

## Deviations from the specification and spec seams

1. Order of sanitizing: control characters removed, trim, cut to 64 code points, trim again. A long name with whitespace at position 64 is stored with fewer than 64 characters. Characters are counted as code points, as `char_length` does.
2. `setAgentRunMcpClientName` throws `NotFoundError` when no run matched (the convention of `finishAgentRun`).
3. `packages/data/src/index.ts` needed no edit; `publicSurface.test.ts` and `agentSessionComposition.unit.test.ts` are outside `Touches` and follow from the Task.
4. An existing `mcpHandler` test that compared the whole persistence snapshot after a run-credential `initialize` now expects exactly the run's `mcp_client_name` to differ.
5. The liveness of the credential is checked at authentication, before the write's transaction; the UPDATE does not repeat `status = 'running'`, so a name can land on a run that finished in the gap (rules reviewer, not a finding).
