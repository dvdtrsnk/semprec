# Handover for gh-1375

Guidance drift findings are now fingerprinted by their subject only, so an AI that rewords `claim`, `guidanceExcerpt` and `manifestFacts` keeps the same finding from night to night. The work is committed locally; I did not push or open a PR.

- **Shared (`guidanceDrift.ts`):** `fingerprintGuidanceDriftSubject(projectItemId, kind, subject)` is the SHA-256 hex of `canonicalizeJson({ projectItemId, kind, operation, mcpTool, databaseId })`, where exactly one of `operation` and `mcpTool` is a string and the other `null`. New types: `GuidanceDriftKind`, `GuidanceDriftPermissionSubject`, `GuidanceDriftBehaviorSubject` and the union `GuidanceDriftSubject`. `fingerprintGuidanceDriftContradiction` is removed.
- **Payload:** `GuidanceDriftContradiction` gains `kind: "permission"` and `subject: GuidanceDriftPermissionSubject | null`. `validateGuidanceDriftContradiction` reads a row without them as `kind: "permission"`, `subject: null` and rejects an unknown kind or a malformed subject. The store's `mapRow` needed no change.
- **Action (`driftAction.ts`):** the response schema requires `subject { operation, databaseId | null }`, and the system instruction tells the AI to copy both from the manifest. A contradiction without a subject throws before the write transaction, so no finding changes. Contradictions that share a subject collapse to one: higher severity wins, equal severity falls back to the smaller claim so the result does not depend on report order.
- **Tests:** shared unit tests cover fingerprint inequality across project, kind, operation, MCP tool and database, field order independence, and legacy and invalid payloads. Action unit tests cover reworded claims staying one finding with an advancing `lastSeenAt`, severity dedupe in both orders, and the missing subject failure. Fixtures in the data and notifications tests gained `kind` and `subject` (type only).
- **Checks run:** prettier, eslint, tsc for shared, application, data and notifications, and the unit tests in shared and application. The data and notifications tests need Postgres and were not run.

Notes for dependants:

- #1629 adds the `behavior` variant. The `GuidanceDriftContradiction` payload type is `kind: "permission"` only, so widening it is that issue's change. `GuidanceDriftBehaviorSubject` and the fingerprint's `mcpTool` branch already exist.
- The action's `dedupeBySubject` casts `contradiction.subject` to the permission subject. It is safe only because `validateContradictions` rejects a null subject first.
- Old findings written before this change are resolved by the next nightly run, and the new ones open. No migration was written.
