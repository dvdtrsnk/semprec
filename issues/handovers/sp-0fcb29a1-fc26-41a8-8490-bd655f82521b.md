# Handover for sp-0fcb29a1-fc26-41a8-8490-bd655f82521b

Implementation commit: b906b7b50.

- `NoteMerge` (`:shared:domain`) merges base, local and remote canonical Markdown three ways: blocks by their canonical
  Markdown with LCS fixed points, conflicting stretches paired by position (fields from the side that changed them,
  text by character with inline styles, surrogate pairs kept whole), delete-vs-change keeps the change, additions kept
  local first, the local side past 4,000,000 table cells; `adopt` keeps editor ids of unchanged blocks.
- `KeptPages`/`OfflinePages` keep each page (`<account>/pages/<fnv>.json`: base, `ETag`, local text). Reads and writes
  of `HttpJournalRepository` (and so the note editor) go through them under one lock. A write carries the Markdown it
  was edited from (`base`, a new parameter of `NotePageRepository.replace` and `JournalRepository.replacePage`) and is
  merged with the device's text first when that moved on; `409`/`412` merge with the server's page up to three rounds;
  no answer/`5xx`/`429` keep it on the device; `404` forgets the page. A saved page stays fresh and makes the other kept
  answers stale. Waiting pages are written after every finished replay; a page of an item the device made waits for
  the server's id.
- `SyncFrame` keeps `doc` frames, `SyncSocket` raises them on `PageChanges`, merges are announced too, and the editor
  rereads in place (ids kept) unless a change waits; `NotePageStore` shows `Merged`, treats `Kept` as saved.
- Decision: `docs/adr/2026-11-23-note-edits-merge-three-ways-and-wait-on-the-device.md` (narrows §4 of the native editor
  ADR). Decision record `issues/decisions/sp-0fcb29a1-fc26-41a8-8490-bd655f82521b.md` (the `base` of a write, `404`,
  the lock, the in-place reread, the corrected Touches).

Tests: `NoteMergeTest` (20), `OfflinePagesTest` (33), `HttpJournalRepositoryOfflineTest`, `NoteEditorOfflineTest`, the
`doc` frame cases in `SyncFrameTest` and `SyncSocketTest`.

Known limits: both versions of words changed on both sides stand side by side; an editor that keeps a made id does not
reread on the server's frames for the server id until it is reopened.
