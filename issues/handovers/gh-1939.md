## What was delivered

- A system-owned text property `splitFromProposalId` on the Processing proposals database (seed, English and Czech property names, and the cutover step for existing tenants).
- `splitInboxSourceWithClient` (`inbox/proposalSplit.ts`): in one transaction it row-locks the primary card, locks the source, proves the card against the subject item, and validates every envelope before the first write. The first entry revises the primary card as a thread revision; every other entry becomes a sibling card (kind `inbox`, status `proposed`, `aiProposal` equal to `proposal`, `aiVersion` 1, a `threadRevision` history entry, a `sourceInbox` edge to the same source, `splitFromProposalId` set to the primary's id). 2 to 10 cards per split. A confirmed, rejected or source-deleted primary, a sibling given as primary, a card of another item and any invalid envelope refuse the whole split and write nothing. Nothing is created in a target database.
- The agent tool `inbox.proposal.split` of the Inbox module (`createInboxProposalSplitTool`, args schema `inboxProposalSplitArgsSchema`, English and Czech labels). Thread id, message id and subject item come from the run, never from the arguments.
- `findExistingProposal` of the tick skips cards that carry `splitFromProposalId`, so a source edit recomputes only the primary card.

## Entry points and contracts dependents build on

- Tool name `inbox.proposal.split`; arguments `{ proposalId, ifVersion, cards, message? }` (strict). `ifVersion` is the primary card's `updatedAt` and is required on the tool, optional on the action (see deviation 1).

- Lock order of the split: card, source, then the source edge (ADR `docs/adr/2026-11-14-a-source-split-locks-the-card-then-the-source-then-the-source-edge.md`). A later writer that holds the edge and then waits for the source would cycle with it; follow the ADR.

## Deviations from the specification and spec seams

1. The tool adds a required `ifVersion` to the Task's `{ proposalId, cards, message? }`, following `inbox.proposal.revise` and ADR 2026-11-13 (the first entry replaces the whole envelope; a stale composition would overwrite a manual edit). The review flagged it as low; the fixer rejected it and the new ADR states it.
2. The cutover is a separate step file and no SQL migration was needed.
3. A split of a card that itself carries `splitFromProposalId` is refused (siblings point at the primary card).
4. The lock order was corrected in the fix round (the first version took the source after holding the edge `FOR SHARE`, reproduced as a real `40P01`); recorded in the new ADR.
