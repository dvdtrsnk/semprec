In the rollup serialisation test, the fixed 200 ms sleep is gone. The test now waits until the database shows the recompute is blocked on the holder's row lock. I committed the change on this branch. I ran only `rollup.test.ts` (11 of 11 passed), plus eslint and prettier on it. I did not run `pnpm run verify`, so Relay's verify step is the first full run.

The change is in `backend/packages/data/src/__tests__/rollup.test.ts` and follows the pattern in `moduleDataMigration.test.ts`:
- **Import:** `vi` is added to the `vitest` import.
- **Holder pid:** right after the holder's `SELECT ... FOR UPDATE`, the test reads the holder's backend pid with `SELECT pg_backend_pid() AS pid`.
- **Wait:** after `recomputeRollupCell` starts, `vi.waitFor` (10 s timeout, 20 ms interval) counts `pg_stat_activity` rows where `pg_blocking_pids(pid)` contains the holder's pid. It expects exactly 1.
- **Failure message:** if that never happens, the test fails with "recompute never blocked on the holder's row lock".
- **Unchanged:** `expect(settled).toBe(false)` stays after the wait, and nothing else in the test was touched.

`pnpm install --frozen-lockfile` was needed first because the worktree had no `node_modules`. It changed nothing tracked.
