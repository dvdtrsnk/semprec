Gmail Pub/Sub messages now go through one dispatcher that routes each address to every matching mailbox. It is committed locally as `5534cefc` and not pushed.

I did not run the full `pnpm run verify` or anything under `web/`. What I did run came back clean:
- **Integration:** the three relevant files (`gmailWatchLifecycle`, `gmailAddressRouting`, `graphSubscriptionRouting`) pass, 27 tests.
- **Unit:** the whole suite passes, 840 tests.
- **Static checks:** lint, prettier check, migration numbering, write-safety, boundaries and the build all pass.

Remaining `verify` steps (the full integration and e2e suites, `web/`) are left to Relay's verify step.

What changed:
- **Migration `0070_gmail_watch_address_routing.sql`:**
  - Adds the nullable `gmail_watch_email_address` column and a non-unique partial index on it.
  - Grants `semprec_router` column-level `SELECT`.
  - Adds `route_gmail_address(text)`. It is `SECURITY DEFINER`, owned by `semprec_router`, with a pinned `search_path`, and `EXECUTE` goes to `semprec_data` only. It returns `gmail_api` rows only.
- **Store:**
  - `recordGmailWatchRegistration` now also writes the normalized address and checks the affected-row count with `requireAffectedRows`.
  - New `routeGmailAddress` normalizes the address and validates both uuids of each returned row.
- **Per-mailbox lifecycle:**
  - Keeps the immediate sync enqueue on `start()` and the renewal loop; the pull loop and its options are gone.
  - Renewal records `normalizeEmailAddress(getAccountEmailAddress(...))`.
  - `getAccountEmailAddress` is documented as the credential's own Google account address, never `Mailboxes.addresses`.
  - `onError`'s phase is `"watch"` only.
- **Transport:** `pull()` and `acknowledge(ackIds)` no longer take a mailbox id.
- **`createGmailPubSubDispatcher(pool, transport, options)`:**
  - One loop runs under `runAsSystem("mail:gmailPubSubDispatcher", …)`.
  - Each message is routed in its own transaction, and each target's sync is enqueued inside `runInTenant`. A failed target is reported via `onError(target, "enqueue", err)` and the other targets still run.
  - A message is acknowledged only if every target succeeded. A message with no target is acknowledged too. A routing failure leaves it unacknowledged.
  - All ack ids of one pull go out in a single `acknowledge` call.
  - Pull failures back off with the capped growing delay and reset after a success.
- **Docs:** one row added to the router-functions table in `docs/operations/database-roles.md`. Prettier also reformatted the rest of that file, so the diff there is a few lines larger than one row.
- **Tests:**
  - `gmailWatchLifecycle.test.ts`: pull cases rewritten against the dispatcher, plus address persistence, the missing-row `"watch"` error, fan-out, partial failure, unknown address, backoff and `stop()`.
  - New `gmailAddressRouting.test.ts`: function shape and grants, `semprec_side` getting `42501`, routing under an unrelated tenant, two-tenant dispatch with a single ack, and a strict-scope run.

I did not wire the dispatcher or the Gmail transport into `semprec-api`, as the issue says.

The existing `Mailboxes`-based malformed-entry handling in `gmailPubSubClient.ts` is untouched.
