# Handover: Capture a scanned document from Add to Inbox

ADR: `docs/adr/2026-11-27-the-document-scanner-is-the-one-uikit-view-controller-of-the-apple-app.md` (the system
document scanner is the app's one UIKit view controller, iOS only; the app side writes the scan's capture).

**Intent** (`mobile/apple/Projects/App/Sources/Intents/`):
- `InboxContent.swift`: `AppEnum` with `text` and, on iOS only (`#if os(iOS)`), `scan`.
- `AddToInboxIntent.swift`: `supportedModes = [.background, .foreground(.dynamic)]`; parameters `type`, `content`,
  `text`, `day`. Flow: sign-in check, type (asked when unset), content (asked when unset; on macOS, with `text` as the
  only case, not asked). `text` runs as before (`captureText`). `scan` (iOS): `DocumentScanner.isSupported` false
  answers `intent.addToInbox.scan.unavailable` before opening the app; otherwise `continueInForeground(alwaysConfirm:
  false)`, then `await ScanPresenter.shared.scan(Request(typeId:, text: text ?? "", day:))`, then
  `.saved` → `sendBriefly` + `intent.addToInbox.scan.saved`, `.cancelled` → `intent.addToInbox.scan.cancelled`,
  `.failed` → `intent.addToInbox.signIn` for `unauthorized`, else `intent.addToInbox.scan.failed`. The text is not
  asked for a scan; a set `text` parameter is kept beside the PDF.
- `ScanPresenter.swift`: `@MainActor ObservableObject`, `static let shared`; `@Published request`, `@Published scene`
  (the claiming scene's UUID). `scan(_:)` waits on a checked continuation; a new request ends a waiting one as
  `.cancelled`. `claim(scene:)` first claim wins. `finish(pages: [PDFPage])` closes the scanner at once, no page →
  `.cancelled`, builds the PDF, then writes the capture in an app task (`Capture` closure, default
  `InboxShortcutCapture().capture(...)`) and answers `.saved` or `.failed(Failed)`; day = request day or the finish
  day, time = finish time. `cancel()`, `fail()` (`Failed(kind: nil)`, the scanner's error is not kept: no logger).
- `ScanDocument.swift`: `file(pages:scannedAt:)` → `InboxShortcutCapture.File` (`Scan YYYY-MM-DD HH-mm.pdf`,
  `application/pdf`, `.camera`), one `dataRepresentation()` and one Base64 encoding; nil with no page.
- `DocumentScanner.swift` (`#if os(iOS)`, only `VisionKit` import): `UIViewControllerRepresentable` over
  `VNDocumentCameraViewController`; pages made `PDFPage(image:options: [.compressionQuality: 0.8])` one at a time in
  an autorelease pool; delegate via `@preconcurrency` conformance.
- `ScanPresentation.swift`: view modifier on `AppScene` (`.modifier(ScanPresentation(presenter: .shared))`); on iOS a
  `fullScreenCover` shown while `presenter.scene == ` this scene, claiming on request change and on `scenePhase`
  becoming active; nothing on macOS.

**CoreKit bridge**: `InboxShortcutCapture.capture(text:day:time:typeId:file:)` now takes `File?`
(`InboxShortcutCapture.File(filename, mimeType, base64, source: InboxCaptureSource)`), mapped by the internal
`static func file(_:) -> sending SharedSDK.InboxCaptureFileInput`. No Kotlin change.

**Copy / policy.** New keys `intent.inboxContent.{name,text,scan}`, `intent.addToInbox.content(.request)`,
`intent.addToInbox.scan.{saved,cancelled,unavailable,failed}` (en + cs, `appleOnly` in the policy);
`intent.addToInbox.description` and `NSCameraUsageDescription` (Project.swift and InfoPlist.xcstrings) now mention the
scan. `PDFKit` and `VisionKit` added to `apple.systemModules`. `mobile/docs/architecture.md` lists the scanner among
the app's UIKit files. The file name `Scan …pdf` is the literal the issue specifies, not localized.

**Open points / for the next issues.**
- Not verified on a device: the foreground transition, the scanner cover, the PDF from real camera pages (size and
  memory of a long scan), and how the system shows the dialog after `continueInForeground`. The simulator has no
  scanner (`isSupported` is false), so there it can only answer "not available".
- If the run's continuation is never resumed (the claiming window closed under the scanner), the next scan request
  ends it as cancelled; a pending request whose scene went away is otherwise not detected.
- `ScanDocument.file` returning nil because PDFKit wrote no data maps to `.failed(Failed(kind: nil))`; that branch has
  no test (PDFKit cannot be made to fail from a test).
- The background sending issue (sp-d6d6351a-9488-4b7d-89c4-b1f6157c0182) replaces `sendBriefly` for both contents.
