# Handover: keep the Sent copy of an SMTP send durable

Commit on `fix/followup-mail-latency`: `e12b509d4`. Nothing was run against a real server.

**Why.** The detached Sent copy of sp-d4a5d05a-622e-45a1-9e0d-a881db6f2d93 lived only in the API process: a crash or restart between the SMTP acceptance and the APPEND lost the provider's Sent copy. No stored raw MIME existed to reuse (only attachments are blobs), so the accepted bytes are stored.

**Changes.**
- Baseline: tenant table `mail_sent_copies` (id, mailbox, Message-ID, raw bytes, `failed_at`; unique per tenant, mailbox and Message-ID; cascades with the mailbox item; RLS; left out of the tenant export).
- `mail/mailTransport.ts`: the SMTP transport opens no IMAP connection and answers an accepted send with `needsSentCopy: true`; the Sent-copy saver, `createDetachedSentCopies`, `AppOptions.detachedSentCopies`, the `serve.ts` wiring and the shutdown drain are gone (shutdown order and its docs are back to the earlier ones).
- `mail/mailSentCopies.ts`: `recordPendingSentCopy` (row + `mailSentCopy` job, key `mail-sent-copy:<copyId>`, 8 attempts) on the caller's transaction; `sendDraftEmail` calls it in its finalization (draft route, approved agent send, MCP send). The invitation jobs call `recordPendingSentCopyAfterSend` right after the acceptance (own transaction, retried, never thrown so the invitation is not sent again, logged as an error if it still fails).
- `handleMailSentCopyTask` (`worker.ts`, api affinity, tenant task): under the account's IMAP slot, `SEARCH HEADER Message-ID` in Sent (`ImapFlowMailClient.hasMessageWithId`, which fails when the search did not run), APPEND with `\Seen` only when absent, delete the row. Inactive mailbox (gone, trashed, Mail off): row deleted without APPEND, logged. Any other failure: row kept, rethrown for graphile-worker's backoff; the final attempt marks the row failed and raises `mailSentCopyFailed` (`mail:sentCopy:<mailbox>`, warning, en/cs copy, resolved title). The next appended copy of the mailbox re-queues the failed ones; the problem resolves when none is left.
- Docs: `domain-mail-and-inbox.md` (Sending, Sent copy, shutdown order), `data-model-and-writes.md` (foreign key table).

**Tests** (`__tests__/mailSentCopyJob.test.ts`, real Postgres, fake IMAP account): the send commits one row with the accepted bytes and one keyed job with the tenant envelope and 8 attempts, with no IMAP call; with only the committed row and job left (crash between accept and APPEND), a worker run appends the copy once with `\Seen` and removes row and job; a run repeated after an APPEND whose deletion did not commit only searches and appends nothing, and a further run finds no row; a refused APPEND keeps the row, the final attempt marks it failed and raises one problem, the next appended copy re-queues it and the problem resolves once it is in; a trashed mailbox's copy ends without APPEND. Adjusted: `smtpTransport` (an accepted send answers `needsSentCopy` while both IMAP slots are taken), `mailSend` and `mailComposeAfterConnect` (the copy goes through the job), `tenantIsolationJobs` (the new task's case), catalog, RLS, item foreign key and public-surface lists.

**Behaviour to know.** The response still returns right after the acceptance and the finalization. A crash between the acceptance and the finalization's commit still loses the copy, as it leaves the claim unfinalized; after that commit the copy is durable. Failed copies are never dropped; they wait, marked failed, for the next successful copy of their mailbox (or the operator).

**Review round** (commits `78b57829f`, `45f8772de`).
- A finalization that fails after the acceptance records the copy with `recordPendingSentCopyAfterSend` before its error is answered (test: the draft vanishes between acceptance and finalization; the route rejects and one row with its runnable job exists).
- `requeueFailedSentCopies` removes a job that used up its attempts and enqueues a fresh one; it runs after an appended copy and after every completed IMAP sync pass of the mailbox (tests exhaust the job's attempts and assert attempts 0 afterwards, for both triggers).
- `dropSentCopiesOfMailbox` drops every copy of a gone, trashed or Mail-off mailbox and resolves its problem; Mail off calls it in its transaction (tests for the trash path with a failed copy beside a pending one, and for Mail off).
- The problem's source is the mailbox's `mail_account_sync_state` row, as for `mailSyncError`.
- `hasMessageWithId` is raced against the APPEND's 60 s timer.
- Invitation and reply jobs through an SMTP-shaped transport each record one copy with its keyed job (`eventInvitationJob.test.ts`, `invitationReply.test.ts`).
