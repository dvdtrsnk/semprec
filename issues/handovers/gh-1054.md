I added `backend/services/semprec-api/src/__tests__/tenantIsolationRealtime.test.ts`, a two-tenant realtime isolation suite with 24 tests that all pass. It found no leak and changes no production code.

**Setup**
- `SEMPREC_TENANT_SCOPE` is set to `strict` in `beforeAll` and restored in `afterAll`.
- Tenants A and B come from `createTestTenant` and `provisionTenant` on a `semprec_data` runtime-role pool. A's user and B's user each have a database, an item with a doc, and an agent run with an event.
- The server is built from `createDispatcher` and `createSyncUpgradeHandler` over that pool, with `wireRealtimeHooks`, as `serve.ts` composes them.
- Each test logs in fresh sessions and opens A1, A2 and B1, all with a same-origin `Origin`. The revocation case ends A's second session, so reusing sessions across tests would break.

**Absence checks**
- To prove B1 received nothing, the test waits for A's expected delivery, publishes a sentinel schema invalidation in B, and asserts the frames B1 got before the sentinel are `[]`. There are no sleeps.
- I mutated `sendToTenant` in `syncServer.ts` so it ignored the tenant. 9 tests failed, so the checks can fail. I reverted the mutation.

**Case tables**
- Four tables use `satisfies Record<…>`, one each over `RealtimeMessage["type"]`, `AgentStreamMessage["type"]`, `InboundFrame["type"]` and `OutboundFrame["type"]`. The outbound table maps each frame type to the case that produces it, and a test re-runs that case and checks it produced that type. There is also one binary-frame case.
- Deleting an entry fails `tsc` with a missing-property error. I did not separately try adding a union member without a case.

**NOTIFY cases**
- Invalidation, item and schema scope: from a REST write by A's user, and from a background write inside `runInTenant(A)` with no acting user.
- `doc_update`, `agent_run_event` and `agent_run_delta` reach A1 only.
- `notification_created` and `notification_read_state` reach A1 and A2.
- `session_revoked` closes A2 with code 4401 while A1 and B1 stay open.
- Three raw `pg_notify` payloads with no usable `tenantId` reach no socket: an envelope without the field, one with `null`, and a bare message.

**Inbound cases**
- For `doc:open` and `agent:watch`, B1 naming A's ids behaves like a random UUID, and B1 can still use its own doc and run afterwards.
- After `doc:close` and `agent:unwatch` from B1, A1 still receives A's updates and events.
- Binary frames prefixed with A's doc id, sent without `doc:open` and after a refused one, write no `doc_updates` row for A's doc. A positive control shows A1's own frame is stored.

**Checks**
- ESLint, Prettier, `pnpm run build` for `semprec-api`, `check:boundaries` and `check:write-safety` pass.
