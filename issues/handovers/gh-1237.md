## What changed

In both module-manifest unit test files, the cold module-graph import of each manifest (vite transform plus evaluation) is now done once, in a `beforeAll` with an explicit 30 s hook timeout. A one-line comment next to the hook gives the measured time and the margin:

- `backend/packages/data/src/__tests__/moduleRegistryLoadAll.unit.test.ts`: warms all 7 manifests.
- `backend/packages/data/src/__tests__/libraryMailInboxModuleManifests.unit.test.ts`: warms the library, mail and inbox manifests.

The per-test 30 s timeouts from the first commit are removed. Every test is back on vitest's 5 s default, and the global unit timeout is unchanged. No assertion changed. `ModuleRegistry.loadModule()` still runs the import and the full validation; the import is now served from the module cache.

## Why

Step 1 of the issue's measurement showed that schema parsing, catalog reads and registry projection take only a few milliseconds. All the cost is the one-time import of each manifest's module graph, so this work is inherent (Task step 3).

Before this change, that cost fell on whichever test loaded a given manifest first. So it depended on test order and on `-t` filtering, and each manifest paid its own cold import. In the library/mail/inbox file the mail test is second, not first, and the Inbox test also paid its own import with no explicit timeout. Moving the import into `beforeAll` makes the cost independent of order and filtering, and gives it one explicit, sized budget.

After:

- every test: 4-50 ms, whether run as a full file or alone with `-t "Inbox pipeline"`, `-t "mail sync"`, `-t "library manifest"` or `-t "excludes"`

Hook budget: 30 s, about 3x the 10.7 s worst measured for all 7 graphs. The 3-manifest file loads a subset of those graphs.
