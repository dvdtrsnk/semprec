## Summary

Implements issue #112: registers `moduleRegistry.checkDrift`, a standalone heartbeat action that periodically detects live mechanical manifest drift that startup-time validation cannot catch:

- Diffs distinct live `project_heartbeats.action_id` values against the registry's active heartbeat action ids.
- Diffs distinct system-owned `properties.owner_process` values against active process/module ids.
- Publishes findings through a resolve-capable extension of the existing `notifications` table (migration `0011_finding_resolution.sql` adds nullable `dedupe_key`/`resolved_at` columns plus a partial unique index on `(kind, dedupe_key) WHERE resolved_at IS NULL`).
- Concurrent runs cannot create duplicate active findings (insert races safely resolve via `ON CONFLICT ... DO NOTHING`), and a repaired drift auto-resolves on the next successful run (`resolveFindingsNotIn`).
- Deliberately mechanical only — never compares AGENT.md prose to permissions.
