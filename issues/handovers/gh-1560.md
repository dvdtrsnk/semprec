# Handover for gh-1560

A thread's main conversation is now keyed by `agent_runs.thread_id` for reconstruction, compaction checkpoints and retention. Committed locally on `wf/gh-1560`; not pushed.

- **Filter:** `SessionAgentRunsFilter` (`agentRunsStore.ts`) is now a union: the existing `{ projectItemId, triggeredBy, parentRunId }` form and the new `{ threadId, triggeredBy: 'user', parentRunId: null }`. `listSessionAgentRunEventsFromLastCompaction` selects `thread_id = $1 AND unit = 'session' AND triggered_by = 'user' AND parent_run_id IS NULL` for the thread form (uses `agent_runs_thread_wake_idx`), so a delegated session (inherited `thread_id`, non-null `parent_run_id`) never matches. The project-item form now also excludes thread main-conversation runs, so the two keys never overlap.
- **Reconstruction:** `reconstructConversationHistory` / `walkStoredEntries` pass the filter through unchanged, so they accept the thread form with no code change. `persistCompaction(pool, agentRunId, entries)` already writes onto the given run, so a checkpoint belongs to that run's thread; callers must pass a run of the same thread they reconstructed.
- **Retention:** `agentRunEventsRetention.ts` groups thread main conversations by `thread_id` and every other session run by `(project_item_id, triggered_by, parent_run_id)` excluding them. Checkpoint rule unchanged: nothing at or after the latest checkpoint is deleted, no checkpoint means no deletion.
- **Tests:** `agentRuns/__tests__/agentRunEventsThreadConversation.test.ts` (new; two threads, delegated session, checkpoint isolation, retention cases, non-thread behaviour) and a thread case in `agent-runtime/src/__tests__/conversationReconstruction.test.ts`. Existing retention and events-store tests pass. Full verify was not run.
- **For dependants:** #1565 and #1566 should build the thread filter with `triggeredBy: 'user'`, `parentRunId: null`; runs of a thread must be created with `threadId` (#1452) or they fall into the project-item grouping.
