## Summary

`resolveActor` previously fell through to `authenticateRequest(pool, req)` whenever no MCP run-credential resolved from the bearer token — including when there was no bearer token at all — and `authenticateRequest`'s `extractToken` reads the `semprec_session` cookie in that case. This let a browser session cookie authenticate `POST /mcp`, contradicting `extractBearerToken`'s own documented contract.

Now `resolveActor` throws `UnauthorizedError` (imported from `@semprec/data`) immediately when `extractBearerToken` returns `null`, before any session lookup. A present bearer token still tries the run-credential lookup first, then falls back to `authenticateRequest` unchanged. The listener's docstring was updated to state this explicitly. A new integration test logs in a `platform: "web"` user, sends `POST /mcp` with only the `Cookie` header set and no `Authorization` header, and asserts 401.
