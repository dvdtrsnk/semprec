# Handover for gh-1459

The tenant table `semp_problems` and the two store functions `raiseProblem` and `resolveProblem` now exist and are exported from `@semprec/data`. No producer calls them yet. The work is committed locally on `wf/gh-1459`; I did not push or open a PR.

The targeted integration tests pass: `semp/__tests__/sempProblemsStore.test.ts` (new, 11 tests), `tenancyCatalog` and `publicSurface`. Prettier, eslint, `tsc --noEmit` for the data package and migration numbering also pass. I did not run the full `pnpm run verify`.

- **Migration:** `0095_semp_problems.sql`, additive and rollback-safe. `semprec:tenancy=tenant`, RLS (`tenant_isolation`, `tenant_rows`) and DML grants to `semprec_side`. Categories and severities are CHECK constraints; a second CHECK ties `resolved_at` and `resolution_kind` together (both set or both NULL).
- **Indexes:** partial unique `semp_problems_active_dedupe_uq` on `(tenant_id, dedupe_key) WHERE resolved_at IS NULL`, and `semp_problems_tenant_active_idx` on `(tenant_id, last_seen_at DESC, id DESC)` for active listing.
- **Foreign keys:** `user_id` has the plain reference to `users(id)` plus the validated twin `semp_problems_user_id_tenant_fkey` on `(tenant_id, user_id)`. The tenancy catalog test requires the plain sibling for every `*_tenant_fkey`, so I bumped its twin count from 31 to 32. `project_item_id` and `source_id` carry no foreign key (`items` is partitioned; `source_id` points into whichever table `source_table` names).
- **`raiseProblem`:** one `INSERT ... ON CONFLICT (tenant_id, dedupe_key) WHERE resolved_at IS NULL DO UPDATE`. It first takes a transaction-scoped advisory lock on the tenant and key, so the prior severity it reads is consistent with the row it updates and two racing escalations report `escalated` once. The lock is released with the caller's transaction. A call without `occurrenceKey` always counts and keeps the stored `last_occurrence_key`.
- **`resolveProblem`:** returns whether a row changed; an unknown `resolutionKind` throws `ValidationError`. The accepted kinds are the non-exported constant `SEMP_PROBLEM_RESOLUTION_KINDS` (`recovered`); #1915 extends it.
- **Tenant scoping:** both functions filter by `app_tenant_default()` in SQL besides RLS, so they are also tenant-safe on a superuser connection. The caller must have a tenant scope set on its transaction.
- **Public surface:** `raiseProblem` and `resolveProblem` were added to `publicSurface.test.ts`. The category and severity types are exported as types only.

Notes for dependants:

- Call `raiseProblem` in the same transaction as the source row, next to `writeNotification`; act on `outcome` (`created`, `merged`, `escalated`) for the push (#1466).
- `dedupeKey` is scoped to the tenant, not to the category, so producers must put a category or kind prefix in it.
- The new `calendar` category needs a migration that widens the category CHECK.
