## What was delivered

An explicit "this recording belongs to no Event" choice is remembered on the recording request and honoured by the transcription's Event match.

- Envelope: a recording card accepts the boolean property `noEvent` (`RECORDING_PROPERTY_KEYS`, the strict schema, `RecordingCardProperties.noEvent`, which is true only for `true`). `false`, `null` and an absent property mean that nothing was chosen. `noEvent: true` together with an `eventId` is refused on the field `noEvent`; a non-boolean `noEvent` is refused.
- Store (`transcription/recordingIntake.ts`): `RECORDING_EVENT_DECISION_NO_EVENT = "noEvent"`, `setRecordingEventDecision(client, fileItemId, decision)` (tenant-scoped UPDATE of `recording_requests.event_decision`, managed transaction required, one affected row required) and `readRecordingEventDecision(client, fileItemId)` (`"noEvent"` for that stored value only, `null` for the default `'none'`, any other value and a missing request).
- Confirm (`inbox/recordingCardConfirm.ts`): `confirmRecordingCard` calls the setter right after `recordRecordingIntake`, in the same transaction, only when `noEvent` is true. A confirm without the choice writes nothing and never clears a stored decision.
- Match (`transcription/transcriptEventMatch.ts`): `readOpenMatch` first reads the decision of the transcript's source Files item (the link of the transcript, through `readTranscriptionSourceFileItemId`) and returns the new outcome `noEventChosen`, before the transcript's edges and before `alreadyLinked` and `alreadySuggested`. `matchTranscriptToEvent` then writes nothing (no edge, no card, and an existing edge or card is left as it is) and `readEventRecommendationContext` returns null, so no paid recommendation call is made. `runEventMatch` already treats a string outcome as finished, so `eventRecommendationStep.ts` and `transcriptionTask.ts` are unchanged.
- ADR `docs/adr/2026-11-15-the-value-no-event-of-a-recording-requests-event-decision-is-the-explicit-no-event-choice.md` records the value, its writer and reader, and that a decision stored after a transcript was already matched does not undo that match.
