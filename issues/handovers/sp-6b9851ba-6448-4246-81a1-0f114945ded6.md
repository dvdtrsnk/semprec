# Handover: remove a mailbox's Emails whose last folder copy vanished before a pass decided them

Commit on `fix/followup-mail-edges`: `b6ed894b6`. Nothing was run against a real server.

**Root cause.** `MAILBOX_REMOVAL_MEMBERS_CTE_SQL` found an Email only through an edge to one of the mailbox's live Folders. An Email whose last copy an IMAP pass removed (edge deleted, `folder_copy_removed_at` set) and that no pass had decided yet had no such edge, so a removal or a Mail-off left it live, listed in its thread, and (Mail-off) with its meta row; no later pass decides it, because the removal deletes the sync state and Mail-off the folder sync states.

**Changes.**
- `mail/mailboxRemovalImpact.ts`: the CTE also takes the live Emails whose meta row names the mailbox, carries the mark and has no edge to any live Folder (`folderless_members`). The impact report and the job share it, so the confirmation counts them too.
- `docs/architecture/domain-mail-and-inbox.md`: the `mailboxRemoval` job's members.

**Tests** (`__tests__/mailboxRemovalJob.test.ts`): "removal / mailOff also trashes the mailbox's Emails whose last folder copy vanished before a pass decided them, and keeps another mailbox's" — the marked Email is counted by the impact report and trashed (with the mailbox's deletion time; for Mail-off its meta row deleted), a marked Email that kept another copy is trashed as a member, a marked Email of another mailbox stays live. Both cases fail before the fix (impact `messages: 2`, Email left live).

**Left.** Emails without a meta row cannot be attributed to a mailbox once edge-less; the IMAP pass decides those in its own transaction, as before.
