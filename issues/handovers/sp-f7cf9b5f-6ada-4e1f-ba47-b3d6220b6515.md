# Handover: debounced manual calendar sync requests coalesce into one deferred pass

Implementation commit `62f4810eb` on `feat/internet-accounts`. No schema change. Nothing was run against a real server.

**Defect (F17).** `recordManualCalendarSyncRequest` was a conditional upsert that recorded nothing within 60 s of the previous request. The route then queued nothing and answered 202 `queued: false`, so a "sync now" sent 10 s after the first was dropped until the next sweep (up to 5 min).

**Design.**
- `manual_sync_requested_at` is the run time of the latest requested pass, decided by one upsert under the account row's share lock (`ON CONFLICT … DO UPDATE SET … = CASE`):
  - none in the last 60 s: `now()`, and the pass runs at once;
  - inside the window of a started pass (`now - 60 s < t <= now`): `t + 60 s`, a deferred pass;
  - a deferred pass still ahead (`t > now`): kept as `t`, and that pass serves the request.
- `recordManualCalendarSyncRequest` returns `{ runAt, deferred }`. `enqueueCalendarAccountSync(client, id, runAt?)`: an immediate pass replaces the waiting job's time as before. A deferred one is queued under the same key with `run_at` and `jobKeyMode: "preserve_run_at"`, so a pass still waiting to run (not yet fetched) keeps its earlier time and serves the request. graphile-worker gives a running job's key to a new job, so a request during a running pass still gets its own pass.
- 202 `{ id, queued: true, runAt }` (ISO). The lock-not-available path is unchanged: it queues at once without recording, with `runAt` the transaction's `now()`.
- At most one manual pass per 60 s window; no request is dropped.

**Tests.** `calendarAccountSync.test.ts`:
- one request queues at once; a request 1 s later answers and queues `runAt` = first + 60 s; a third inside the window keeps that one job and time; a request after the window queues at once again;
- a pass still waiting serves a debounced request at its own time;
- the lock-held path still answers at once and records nothing.

`tenantIsolationRoutes.test.ts` checks the new body shape.

**Verified.** In `backend/`: lint, format:check, `pnpm -r run build`, check:write-safety and check:boundaries pass. test:unit: 5 manifest-registry tests timed out at 5 s under host load (load average ~20) and passed on rerun. The calendar sync / CalDAV integration files plus `tenantIsolationRoutes.test.ts` all pass (12 files, 709 tests).

**Follow-ups.** The web and mobile apps ignore `runAt`; showing it is not built.
