`semprec-agents` now runs `repairInterruptedRuns` at startup, before its queue runner is installed, and the repair no longer closes runs with `triggered_by='mcp'`. Closes #642.

Skills loaded: `state-writes`, because the repair writes run state, events and notifications; and `error-handling`, because a failed repair has to stop startup.

## Changes

- **Dependency**: `backend/services/semprec-agents/package.json` now depends on `@semprec/agent-runtime`, and `pnpm-lock.yaml` is refreshed. `pnpm install --frozen-lockfile` succeeds. The existing dependency-cruiser rule `agent-runtime-only-in-agents` already allows this service to import it, and it goes through the package's public `index.ts`.
- **`startupRepair.ts`**: runs with `triggeredBy === "mcp"` are filtered out after `listRunningAgentRuns`, which itself is unchanged. They are not closed, get no synthetic `tool_result` and are not in `repairedRunIds`. The docstring explains why: such a run only backs an MCP run credential, and its credential's expiry sweep closes it, not a restart. It also replaces the old "no caller exists yet" paragraph with the real caller.
- **`serve.ts`**: between `loadFullModuleRegistry()` and `createAgentsQueueRuntime(...)`, it awaits `repairInterruptedRuns(pool)` and logs `repairedRunCount`. Because the call is awaited first, no job can be claimed while the repair is running. A repair failure is not caught: it reaches `installFatalHandlers`, which exits non-zero before the queue runner starts. The shutdown sequence is unchanged.

## Tests

- **`startupRepair.test.ts`** (new case): one sweep over a `running` `mcp` run and a `running` `heartbeat` run, both ending in `tool_use`.
  - The `mcp` run stays `running` with only its original event and gets no notification.
  - The `heartbeat` run becomes `error` / `interrupted_by_restart`, gets a matching `tool_result` with `error: true`, and gets exactly one `agent_run_error` notification.
- **`services/semprec-agents/src/__tests__/startupRepairComposition.test.ts`** (new): calls `repairInterruptedRuns` and then `createAgentsQueueRuntime`, in the order `serve.ts` does.
  - The orphan with a trailing `tool_use` is repaired and paired; the `mcp` run stays `running` with no new events.
  - The runtime handle is only created after the repair resolves.
