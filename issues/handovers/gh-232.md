## Summary

Implements issue #232: records every login attempt with a normalized email and applies exponential lockout before password verification.

- **`emailNormalization.ts`** — trims and lowercases the email once at `login()`'s entry, used consistently for the user lookup and every recorded attempt.
- **`loginLockout.ts`** — `lockoutDurationSeconds`: zero below a 5-failure threshold, then doubles per failure past it (30s, 60s, 120s, ...), capped at 1 hour.
- **`loginAttemptsStore.ts`** — new `getFailureStreak` counts consecutive failures for an email+IP pair since their last success, so a successful login naturally resets the lockout.
- **`authActions.ts`** — `login()` checks the active lockout window before calling `verifyPassword`; while locked, even a correct password is rejected with the same generic `UnauthorizedError`, and the rejection is itself recorded as a failed attempt (extending the lockout on repeated retries).

Added unit tests for the lockout math and email normalization, plus integration tests covering: normalized-email recording, threshold rejection, no lockout below threshold, email+IP scoping, exponential growth, reset-after-success, and lockout lifting once the window elapses.
