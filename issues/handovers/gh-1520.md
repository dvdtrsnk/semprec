## Delivered behavior

- Registers projectWriteTransform under PROJECTS_MODULE_ID at the existing composition point. The generic pre-write mechanism covers creates and updates, with no new registry, writer, transaction or migration.
- Computes the resulting status from the incoming status when supplied, otherwise the locked stored row. An incoming pinned:true with resulting done/archived is refused with ValidationError, status 400, field pinned. Refusal takes precedence over automatic unpinning.
- A write supplying a terminal status unpins a stored pin by adding pinned:false to that same write, so the returned row contains the result. Explicitly clearing pinned to null alongside a terminal status still unpins a stored true value. No automatic repair is applied to an unrelated patch over a legacy terminal/pinned row.
- Pinning inProgress/longTerm, including changing a terminal status back to one of them in the same patch, remains allowed. Other owner modules are unaffected.
- No deadline, completion-date, overview ordering, system-project hiding or persisted-data backfill change is included.
