## What was delivered

- `POST /api/mail/threads/:threadId/read` with the strict body `{ read: boolean }` (400 otherwise, also for a thread id that is not a UUID). It answers `{ threadId, unread }` with the translated (current) thread id.
- `read: true` marks every incoming copy of the conversation (in every mailbox) read; `read: false` marks only the copies of the last incoming message unread. Incoming means: not own, not in Sent, not in Drafts. Messages the user sent, mail in Sent and mail in Drafts are never written.
- Each target copy is locked in item id order (`lockItemForObservedMailFlags`), skipped when its locked read value already matches or when it is gone or trashed, and written through `updateItemWithClient` as the session user, so the Emails flag hook records the desired state and queues the mailbox sync. The call announces exactly one thin `mailThread` invalidation after the commit (`runAfterCommit`), none after a rollback.
- The route takes the mail-thread guard (`lockMailThreadMutation`) first, so it serializes with the IMAP, Gmail and Graph reconcilers and ingest (ADR `2026-11-13-mail-thread-actions-take-the-thread-guard-before-their-item-locks`).

## Entry points and contracts dependents build on

- Route: `mailThreadRead`, `POST /api/mail/threads/:threadId/read`, handler export `createMailThreadReadRouteHandler` (`mail/mailThreadRoutes.ts`, exported from `@semprec/data`), registered in `mailModuleManifest.ts` (justification `transactional-semantics`) and in `services/semprec-api/src/routeMatrix/mail.ts` with its `ROUTE_CASES` case `mail thread read` and its `ROUTE_HANDLER_FILES` mapping.
- Shared helpers for later thread actions in `mail/mailThreadActions.ts`: `resolveMailThreadForAction` (takes the thread guard, translates a merged thread id, 404 for an unknown or foreign thread), `listMailThreadActionMessages` (every live copy with an incoming classification plus the last incoming message id), `readMailThreadUnread` (the `copy_stats` value the thread detail reports) and `announceMailThreadChanged`. Later thread actions call `resolveMailThreadForAction` first.
- The `unread` in the answer equals the thread detail's value (Drafts copies included), not the list's (the list excludes drafts); the docstring says so.
- No table, migration, job name or operation is added.
