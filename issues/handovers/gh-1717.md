## What was delivered

- `GET /api/calendar/timeline?from=YYYY-MM-DD&to=YYYY-MM-DD[&shape=compact]`, the first custom route of the calendar module: `customRoutes` entry `calendarTimeline` in `backend/packages/data/src/calendar/calendarModuleManifest.ts` (method `GET`, path `/api/calendar/timeline`, `handlerExport: "createCalendarTimelineRouteHandler"`, justification `single-consumer-read`). The manifest file re-exports the handler factory. The manifest version did not change.
- `createCalendarTimelineRouteHandler(pool)` in `backend/packages/data/src/calendar/timelineRouteHandler.ts`. It reads the query string from `ctx.req.url`, validates it and answers `{ status: 200, body }` with the body of the read, inside `withTransaction(pool, ...)`.
  - `from` and `to` must be calendar dates that exist (`isCalendarDate`), `to` must not be before `from`, the range with both days included is at most 93 days, and `shape` is absent or `compact`.
  - Anything else throws `ValidationError`, which the adapter answers as 400 `validation_failed` with `details.field` naming the parameter: `from` or `to` for a bad or missing date, `to` for an inverted range and for a range longer than 93 days, `shape` for any other shape. `shape=full` spelled out is refused. A request without a query string, or without a URL, is refused on `from`.
- `readCalendarTimeline(client, { from, to, shape })` in `backend/packages/data/src/calendar/timelineRead.ts`, `shape` being `"full"` or `"compact"`. It returns `{ timezone, today, now, from, to, items }`: `timezone` is the tenant zone, `today` the current day in it and `now` the time module's wall clock `{ date, time }`, all from `getCalendarClock`. It reads every source of `CALENDAR_TIMELINE_SOURCES` with one shared context, concatenates the items and sorts them once. The read writes nothing.
- The source list in `backend/packages/data/src/calendar/timelineSources.ts`: the types `CalendarTimelineItem`, `CalendarTimelineContext` (`{ from, to, timezone, today, now }`) and `CalendarTimelineSource` (`{ id, readItems(client, context) }`), and the ordered list `CALENDAR_TIMELINE_SOURCES` with the two core sources `events` (`readEventTimelineItems`) and `tasks` (`readTaskTimelineItems`), both defined in `timelineRead.ts`.
- Item shape (`CalendarTimelineItem`): `kind` (`event` or `task`), `id`, `databaseId`, `title`, `type` (the Event type, `null` for a Task), `date`, `endDate` (an Event's stored last day, else `null`), `timeFrom`, `timeTo`, `effectiveTo`, `hasEnd` (a `timeTo` is stored), `allDay` (no `timeFrom`), `calendarId`, `status` (a Task's status, `null` for an Event), `place` (an Event's place, `null` for a Task), `project` (`{ id, name, color }` or `null`), `people` (`[{ id, name }]`), `updatedAt` (ISO string of the stored `updated_at`) and `readOnly` (`false` for a stored item).
  - `effectiveTo` is `null` for an all-day item, the stored `timeTo` when there is one, the `timeFrom` of a timed Task without a `timeTo`, and for a timed Event without a `timeTo` the time of `eventEnd` (the last minute of its last day, `23:59`). A stored time is returned as stored, also `24:00` and also a time that the tenant zone skips on a daylight-saving day. This is the state after the fix commit.
  - `calendarId` of an Event is the target of its `calendar` edge as stored (also when that calendar is trashed), or the id of the live default calendar when it has no edge; of a Task, the id of the live calendar with system key `tasks`. It is `null` when the tenant has no such live calendar or no calendars database. No edge is written.
  - `project` is the first live target of the item's `project` relation; `people` are the live targets of `people` in edge order. A trashed project or person is left out.
- The compact shape (`CalendarTimelineCompactItem`): `id`, `kind`, `title`, `calendarId`, `allDay`, `date`, `endDate`, `timeFrom`, `status`, `updatedAt`, `readOnly`, in the same order as the full shape. It is a projection after the merge.
- Selection. An Event is returned when its `date` is on or before `to` and its last day (`endDate`, else `date`) is on or after `from`, once, with its range. A Task is returned when its `date` is inside the range and its status is not `wontDo`; a done Task is returned with status `done`. A trashed item is never returned. A row without a `date` (absent, `null` or empty) is not selected. Hidden calendars are not filtered.
- Order: by the item's `date`, then all-day Events, Tasks without a time, timed Events, timed Tasks, then `timeFrom`, then title (an `Intl.Collator` in the language of the tenant's user narrowed to `cs` or `en` by `toManifestLocale`, `cs` when the tenant has no user), then id.
- Tolerant read. Stored days are compared as text and never cast. A row whose stored `date`, `endDate`, `timeFrom` or `timeTo` is not valid is left out, the answer stays 200, and one line is logged at warn with `itemId`, `databaseId` and `property` (never the stored value) through the new logger `backend/packages/data/src/calendar/logger.ts` (`createLogger("calendar")`).
- Statement count. Each core source sends one statement for the candidate rows of its database, one for their relation edges, one batched read of the linked projects and people (`getItemsByIds`) and the calendar lookup; the number does not depend on the number of items.
- Registration: the route matrix slice `backend/services/semprec-api/src/routeMatrix/calendar.ts` (`CALENDAR_ROUTES`) with the entry `{ name: "calendar timeline", method: "GET", path: "/api/calendar/timeline?from=2026-10-16&to=2026-10-16", surface: "api", public: false, tenancy: "tenant" }`, imported and spread last in `ROUTE_MATRIX` of `routeMatrix.ts`; the `ROUTE_HANDLER_FILES` mapping of "calendar timeline" to `packages/data/src/calendar/timelineRouteHandler.ts`; the `ROUTE_CASES` case "calendar timeline" in `tenantIsolationRoutes.test.ts`; the barrel export of `createCalendarTimelineRouteHandler` in `backend/packages/data/src/index.ts` and its name in the expected list of `publicSurface.test.ts`.
- ADR, new: `docs/adr/2026-11-10-calendar-timeline-merges-a-list-of-sources.md` (one read, the source list, batched sources, unreadable rows skipped, what the server does not do, derived entries).

## Deviations from the specification and spec seams

Declared by the worker; the requirements reviewer assessed the first five and reported none as a finding.

1. The route entry is in the new slice module `routeMatrix/calendar.ts`, with one import and one spread in `routeMatrix.ts`, as the slice rule of `routeMatrix.ts` prescribes for a new path family. `Touches` names `routeMatrix.ts` only.
2. Not in `Touches`: `calendar/logger.ts`. The Task requires a log line for a skipped row and the calendar module had no logger.
3. Not in `Touches`: the `export` keyword on `isCalendarDate` (`eventValidationHook.ts`) and on `readTime` (`eventTime.ts`). Context says the format checks reuse the validators of #1663 and #1536; both were module-private.
4. Not in `Touches`: the ADR.
5. `timelineRead.ts` and `timelineSources.ts` import each other, which follows from the file layout the Task prescribes.
6. Readings of points the specification leaves open:
   - `now` is the time module's `{ date, time }`.
   - `shape` accepts only `compact`; `shape=full` is 400.
   - Titles are collated in `cs` or `en` only; a user with another locale gets English order.
   - The day of an item is its `date`, so a multi-day Event that began before the range sorts first.
   - A calendar edge is returned as stored, also when its calendar is trashed.
   - Only formats decide validity: a stored `endDate` before `date`, or a `timeTo` without a `timeFrom`, is returned as stored.
   - A row whose `date` (or an Event's `endDate`) does not start with `YYYY-MM-DD` cannot be placed, so it is fetched and logged on every read, whatever the range. A row whose value starts with a day but is not valid as a whole (an Event date that still carries a time, before #1797 converts it) is fetched and logged only when that day is in the range.
   - The compact shape still looks up projects and people, because sources are not told the shape.
7. In tests, invalid stored values, a tenant without a calendars database and trashed system calendars are produced by raw SQL on the admin pool, each with a comment saying why no write path produces them.
8. After the fix commit a stored `timeTo` is `effectiveTo` as stored. The mapping of an end instant on the next day to `24:00` went away with the instant; a stored `24:00` is returned as `24:00`.
