## What was delivered

Two user-session REST routes that let a person decide which databases an agent project may use. They are `customRoutes` of the `schemaCore` manifest (justifications `single-consumer-read` for the list and `transactional-semantics` for the patch).

- `GET /api/projects/:id/database-grants`: lists the sensitive databases and the user-created databases of the tenant with the project's current access (`none`, `read` or `write`). A sensitive database without a stored decision shows `none`, a user-created one `write`, and a stored row wins. Open (non-sensitive) system databases are not listed. Archived databases are listed like active ones. Names resolve in the caller's locale through the module catalog.
- `PATCH /api/projects/:id/database-grants`: strict body `{ databaseId, access }` (UUID, closed enum). The default access of that database removes the stored row; any other value is stored. A non-sensitive system database answers 400; an unknown or trashed project, an item that is not a project, and another tenant's project or database answer 404 alike. The answer is the same entry for the changed database as the list shows.
- An agent run credential and an unauthenticated caller are refused with 401 by the session gate before the handler.

## Entry points and contracts dependents build on

- `setAgentDatabaseGrantForProjectSettings` is exported from the `@semprec/data` barrel (`agentGrants/agentDatabaseGrantsForProject.ts`). It checks the project, locks the project row and the database row `FOR SHARE` in the write's transaction, removes the stored row for the default access and stores any other value through the admin store. It is the only path from the handlers to `agentDatabaseGrantsAdminStore.ts`; the raw admin store stays off the barrel.
- `agentGrants/agentDatabaseGrantsRouteHandlers.ts` holds the two handlers, re-exported by `chokePoint/schemaCoreModuleManifest.ts`.
- `agentGrants/agentDatabaseAccess.ts` gained `defaultAgentDatabaseAccess(database)` and the list query `listProjectDatabaseAccess`, which uses the SQL expression of the point check so the list and the enforcement cannot disagree.
- List body: `{ rows: [{ databaseId, key, name, sensitive, system, access }] }`.
- Route matrix: entries in the new slice `routeMatrix/databaseGrants.ts` (`DATABASE_GRANTS_ROUTES`), the `ROUTE_HANDLER_FILES` mapping and the `ROUTE_CASES` isolation cases `project database grants` and `project database grant set`.
- No table, migration, operation or job name was added.
