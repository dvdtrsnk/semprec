# Handover for gh-1455

The grants listing now reports an effective flag and a server state per row, and the GET handler returns `counts`. No migration.

- **Listing:** `listMcpToolGrantsForProject` left-joins `mcp_server_connection_state` in the same query. Each row gained `effective` (`granted` and the server item active; the listing only holds active registrations) and `server: { state, lastConnectedAt, lastErrorReason }`. `state` is `offline` when the server item is inactive or `last_error_reason` is set, else `connected` (a server never called has null `lastConnectedAt`). `lastConnectedAt` is an ISO UTC string formatted in SQL. All earlier fields are unchanged.
- **Counting rule:** `countEffectiveMcpGrants(rows)` returns `{ effective, total }` (total = rows listed). Exported from `@semprec/data`; the project summary (#1935) should call it on the listing's rows. A failed connection of an active server does not remove effectiveness.
- **Handler:** `GET /api/projects/:id/mcp-grants` returns `{ rows, counts }`.
- **Types:** `McpToolGrantServerState` is exported (type only).

Tests: new cases in `packages/data/src/__tests__/mcpAgentPageGrants.test.ts` (3 of 5, inactive server, handshake_failed then success, empty) and extended `mcpAgentPageHandler.test.ts`; `publicSurface.test.ts` lists the new export. The data tests live in `src/__tests__/` because the existing file is there, not in `mcp/__tests__/` as the issue's Touches suggested.
