# Handover: let a newly connected mailbox draft and send before its first sync pass

Commit on `feat/internet-accounts`: `2b18bee11`. Nothing was run against Purelymail, the VPS or any other real server.

**Root cause.** Folder items were written only by the sync passes (`ensureFolderItem` in `reconcileImapAccount`, `reconcileGmailAccount`, `reconcileGraphAccount`). The connect routes only enqueued the first pass, which on the VPS ran minutes after the 201. Until then `createEmailDraftInMailbox` found no `drafts` Folder and threw `ValidationError(field: mailboxId)` (400 `validation_failed`), and `sendDraftEmail` would have refused 409 `mail_sent_folder_missing`, with the SMTP Sent copy skipped for want of a Sent path. Reply and forward drafts start from synced mail and share the same creation path; draft updates read no folder.

**Changes.**
- `mail/folderDiscovery.ts`: `ensureComposeFolders(client, mailboxItemId, folders)` writes the `drafts`/`sent` folders among the given `ProviderFolder`s through `ensureFolderItem`.
- `mail/imapReconcile.ts` `imapProviderFolder`, `mail/graphReconcile.ts` `graphProviderFolder`: the pass's own folder mapping, now shared with the connects, so the first pass finds the connect's items by `providerId`. `mail/gmailReconcile.ts` `GMAIL_SYSTEM_FOLDERS` (system labels, named by their ids as Gmail does).
- `mail/mailboxPasswordRouteHandlers.ts`: after verification and outside any transaction the connect opens one connection to the verified IMAP endpoint through the new required member `mailServerClients.openImap` (`openImapConnection` in `serve.ts`), lists the folders and closes it, under a 15 s deadline (on expiry the connection is closed; a connection that opens later is closed at once). `createPasswordMailbox` writes the Drafts and Sent folders in the mailbox's transaction, before the first sync job is enqueued. A failed listing is logged (`stage`, `errorName`) and the mailbox connects without them.
- `mail/mailOauthRouteHandlers.ts`: a new Gmail connect writes `DRAFT`/`SENT`; a new Outlook connect reads `GET /me/mailFolders/drafts` and `/sentitems` (`$select=id,displayName`, the identity reads' timeout and cap) outside the transaction; a failed read is logged per folder and that folder is left to the first pass. Reauthorization is unchanged.
- `mail/draft.ts`: `MailDraftsFolderMissingError` → 409 `mail_drafts_folder_missing` with `details.mailboxId`; added to the REST error-code enum (`errorContract.ts`).
- `docs/architecture/domain-mail-and-inbox.md`: password connect, OAuth connect, Drafts.

**Tests.** New `mailComposeAfterConnect.test.ts` (runtime role, own tenant): a generic password mailbox connected through the production handler against the loopback `FakeImapServer` has its Drafts and Sent folders, drafts through the draft route, sends through the send route (moved to Sent), the SMTP Sent-copy saver appends to the Sent path, and a first pass over the wire then writes the other four folders and no second Drafts/Sent; a rejecting opener still connects (201), logs without password or address, and a draft answers 409 `mail_drafts_folder_missing` creating nothing; a container without `openImap` fails before any verification; Gmail and Outlook connects draft and send before any pass (Graph ids and display names); a failing Graph Drafts read still connects with Sent only. The first case fails with the connect's folder write removed. Changed: `mailDraftRoutes` (409 instead of 400), `mailOauthRoutes` (Graph folder routes; one job assertion now tolerates the search reindex jobs of the new folders), the password-connect test containers (`openPurelymailAccount`, production `openImapConnection` in `mailSyncAdapters`).

**Verified** (backend/): `pnpm run lint`, `pnpm run format:check`, `pnpm -r run build`, `test:unit` (4816 + 172), `check:write-safety`, `check:boundaries`. Integration: 29 files (the new one, mailbox password/OAuth routes, drafts, draft send, prefill, attachments, mail send, SMTP/Gmail/Graph transports, mail sync, fan-out, single flight, stall check, IMAP quiet pass/deletions/IDLE, folder list, mailbox views/services/restore, `gmailLabelFolders`, and in semprec-api `mailboxCredentialThrottle`, `tenantIsolationRoutes`, `mailSyncAdapters`, `customRouteMount`), all green. Not run: full `test:integration`, `test:e2e`, web and mobile pipelines.

**Follow-ups.**
- A server without SPECIAL-USE whose Drafts folder imapflow cannot recognise by name never gets a Drafts folder, from the connect or the passes; drafting there stays 409 `mail_drafts_folder_missing`. The web/mobile clients do not translate that code yet.
- A connect whose listing failed leaves drafting refused until the first pass; the queue's latency for that pass is unchanged.
