## What was delivered

- `POST /internal/tts/stream` of the AI gateway reads the optional headers `x-semprec-agent-run-id` and `x-semprec-semp-message-id` and reserves the `voice_synthesize` row with both. A malformed value answers 400 `validation_failed` naming the header, with no row and no provider call; a run or message the tenant cannot see answers the one 403 `attribution_refused`, with no row. Absent headers mean null, as before. Validation is shared with the pi route: the two extractors moved unchanged from `piMessagesHandler.ts` into the new `services/semprec-ai-gateway/src/attributionHeaders.ts`.
- The speech-to-text stream accepts the control message `{type:"attribute", sempMessageId}`. It sets `ai_gateway_calls.semp_message_id` on the chunk rows reserved since the stream opened or since the previous attribute message, in one tenant-scoped all-or-nothing statement. A message the tenant cannot see closes the stream with 1008 and no detail, leaving the rows unattributed; a malformed frame closes it as `invalid_frame`.
- The voice session (`voiceSessionHandler.ts`) sends `attribute` once a final became a Semp message, and passes the turn's run id and assistant message id to text-to-speech. The read-aloud route (`sempSpeechHandler.ts`) passes the message and the run that produced it.
- `getAgentRunUsage` with a message now also counts calls without a run id when `semp_messages.agent_run_id` of the message is the run, so the per-reply usage of gh-1889 for a voice turn includes the speech-to-text rows. Usage of a whole run (no message) is unchanged and does not include speech-to-text rows.
- Speech that never becomes a message keeps null attribution and still counts in the tenant's spend.
- ADR `docs/adr/2026-11-13-voice-speech-rows-are-attributed-to-the-semp-assistant-message-of-the-turn.md` records the attribution protocol.
