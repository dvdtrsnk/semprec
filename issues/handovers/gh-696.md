Implemented issue #696: MCP tool schemas are now validated at sync time and compiled once per registration.

**Changes:**
- New `backend/packages/data/src/mcp/mcpToolSchemaPolicy.ts` — `assertAcceptableMcpToolSchema` rejects a non-object schema, a schema over 64 KiB, any non-local `$ref`, or any `pattern`/`patternProperties` regex that's invalid or not provably safe (`safe-regex`), mirroring the AI gateway's existing `schemaValidation.ts` policy.
- `mcpSync.ts`'s `validateListedTools` now calls that policy per tool before any registration is written; a violation fails the whole sync with `syncStatus: 'error'`, exactly like a duplicate name.
- Added `safe-regex@^2.1.1` + `@types/safe-regex` to `backend/packages/data/package.json`, updated `backend/pnpm-lock.yaml` via `pnpm install`.
- `mcpToolInvocation.ts`'s `McpToolInvocationTarget` gained `toolSchemaUpdatedAt`, sourced from `mcp_tool_registrations.updated_at`.
- `mcpInvokeTool.ts`: replaced the shared module-level `Ajv` instance with a `Map<mcpToolRegistrationId, {updatedAt, validate}>` cache bounded to 256 entries (insertion-order eviction). A cache miss or an `updatedAt` mismatch triggers a fresh compile on a brand-new `Ajv` instance (so a schema's own `$id` never collides across registrations); a failed compile caches `null` so it isn't retried every call.
- Tests added per the issue's spec in `mcpSync.test.ts` (backtracking pattern, remote `$ref`, oversized schema all rejected; benign pattern syncs), `mcpToolSchemaPolicy.unit.test.ts` (new), and `mcpInvokeTool.test.ts` (compile-once via `Ajv.prototype.compile` spy, recompile after a re-sync with correct re-validation, `$id` schema validates on both calls).
