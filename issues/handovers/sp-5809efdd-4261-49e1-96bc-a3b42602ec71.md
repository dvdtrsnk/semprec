# Handover: Inbox captures wait in a device outbox that never loses them

Implementation commit `7e4292a85`. ADR: `docs/adr/2026-11-27-inbox-captures-wait-in-a-device-outbox-that-outlives-the-session.md` (narrows the write-queue ADR for Inbox captures).

**Internal API for the next issues (all `internal` to `:shared:data`, nothing exported yet).**
- The outbox is `OfflineLayer.captures: CaptureOutbox` (`CaptureOutbox.kt`); one layer per data directory and process via `OfflineLayer.shared(directory)`. Without a data directory there is no outbox and `HttpInboxCaptureRepository` sends at once, as before.
- Add a capture: `suspend fun add(session: StoredSession, capture: InboxCapture): RepositoryResult<Unit>`. Success once the files are written (a round then starts in the background); `Failure(UNAUTHORIZED)` with nothing written when no person is kept for the session (`OfflineStore.people`, written at sign-in and session restore); `Failure(UNAVAILABLE)` when a file could not be written. `HttpInboxCaptureRepository.capture` calls it with `api.session()`; an App Intent can go through the repository the same way.
- Send now: `suspend fun send(): Boolean` runs a round, or joins the one under way, and answers whether no capture of the owner signed in is left. It answers `false` when nobody is signed in or no person is kept for the session (nothing could be confirmed sent). Rounds go through the sender of the window attached last (`OfflineLayer.writes.sender()`), so a window (an `AuthenticatedApi` with that layer) must exist.
- `fun sendSoon()` starts a round in the background; `val waiting: StateFlow<Int>` counts the captures of the owner signed in, and is added to `OfflineStatus.waiting`.
- Owner key: `suspend fun ownerOf(session: StoredSession): String?` = hex SHA-1 of `"<serverUrl>\n<personId>"`, the person kept for the session; stable across sign-ins of one person.
- `QueueSender` gained `session(): StoredSession?` and `upload(path, RawBody)`; `AuthenticatedApi`'s sender implements both (a `401` signs the window out, as for `send`).

**Directory layout.** `<dataDirectory>/captures/<owner>/<captureId>.json` (`KeptCapture`: version, id, text, day, time, typeId, file {name, mimeType, source}, blobId, uploadedAt, attempts, nextAttemptAt, createdAt) and `<captureId>.bin` for a file. Bytes first, then JSON, each written beside its target and moved over it (`writeCacheBytes`/`writeCacheFile`; new binary actuals `readCacheBytes`/`writeCacheBytes` for Apple, Android, JVM). `captureId` is a random UUID and the `Idempotency-Key`. `captures/` is a sibling of `offline/`, so `OfflineLayer.clear()` and keeping another account's answers never touch it. A `.bin` without its JSON is deleted at the next listing; a JSON that cannot be read stays and is counted but never sent.

**Sending rules as built.** Creation order, one at a time, one round at a time per outbox. File upload unless a blob id is recorded, then the item. No answer ends the round and retries it after 1 s doubling to 60 s with jitter (`nextReplayDelayMillis`); a `5xx`, `429` or `401` ends the round until the next trigger (this is the issue's wording: only a round without an answer gets the backoff). A refusal naming `typeId` (`error.details.field`) resends at once without the type and writes it; one naming the blob (`details.field == "attachments"` or a `details.blobId`) re-uploads once per delivery; any other refusal counts `attempts` and sets `nextAttemptAt` to now + 1 h. A missing `.bin` for a capture never uploaded leaves it waiting untouched. Triggers: `add`, the layer reached again, `OfflineLayer.connected()`, `OfflineLayer.warmUpWith()`. A success deletes the files and makes `OfflineLayer.changes` emit.

**For the background-sending issue.** The file lock is in-process only (`KeptCaptures`); a second process writing the same directory (an app extension) is not coordinated, and a listing in one process could delete the `.bin` another process has written but not yet followed with its JSON. A refused capture is retried only by a trigger after its hour passed; there is no timer for it.
