# Handover for gh-1395

Semp thread invalidations now travel over realtime. Nothing calls the new hook yet. The work is committed locally on `wf/gh-1395`; I did not push or open a PR.

Targeted checks run in `backend/`: prettier and eslint on the touched files, `tsc --noEmit` for `data`, `realtime`, `realtime-client` and `semprec-agents`, and the unit tests of `realtime-client` and `realtime` (`serverFrame.unit.test.ts` is new). The integration tests (`syncServer.test.ts`, `realtimeWiring.test.ts` in `semprec-agents`, `publicSurface.test.ts`) were written but **not run**: this host has no Postgres. The full `pnpm run verify` was not run, and `web/` is untouched.

**What changed**
- `protocolV1.ts`: `OutboundFrame` gains `{ type: "invalidate", scope: "sempThread", threadId }`.
- `pgNotifyPublisher.ts`: `RealtimeMessage` gains `{ type: "invalidation", scope: "sempThread", threadId }`. `parseRealtimeMessage` accepts it only with a uuid `threadId`. `publishRealtimeMessage` takes an optional third argument `tenantId` that pins the envelope tenant explicitly (cast to `uuid` in SQL). Without it the tenant still comes from the pool scope.
- `syncServer.ts`: a `sempThread` invalidation goes to every socket of the envelope's tenant, with no acting-user narrowing and no replay.
- `data/src/realtimeHook.ts`: new `SempThreadInvalidationEvent`, `setSempThreadInvalidationHook` and `publishSempThreadInvalidation(client, tenantId, threadId)`, which registers the publish through `runAfterCommit`, so a rollback sends nothing.
- `wireHooks.ts`: wires that hook to `publishRealtimeMessage(pool, message, event.tenantId)`. Both `semprec-api` and `semprec-agents` already call `wireRealtimeHooks`, so the hook works in either process.
- `realtime-client/src/serverFrame.ts`: `parseServerFrame` parses the new frame and returns `null` for a missing or non-string `threadId`. `syncClient` already forwards every `invalidate` frame to `onInvalidate`, so no change there. `index.ts` needed no export.
- `publicSurface.test.ts` lists the two new `@semprec/data` exports.

**Tests**
- `syncServer.test.ts`: tenant A socket receives the frame and tenant B socket does not; a rolled-back transaction sends nothing (a committed sentinel proves ordering); malformed envelopes (non-uuid or missing `threadId`) reach no socket.
- `semprec-agents/src/__tests__/realtimeWiring.test.ts`: a write on the agents pool publishes the committed thread with the given tenant id on `semprec_events`, and the rolled-back one is absent.
- `serverFrame.unit.test.ts`: parse and ignore cases.

**Notes for dependants**
- Call `publishSempThreadInvalidation(client, tenantId, threadId)` inside the same transaction as the thread or message write, with the thread's own `tenantId`. Delivery is best effort and unreplayed; the client refetches the thread on reconnect.
- The `tenantId` argument is trusted code input, not read from any message body. Pass the tenant of the row you wrote.
- A hook failure is logged and swallowed, like the other hooks; it never fails the write.
