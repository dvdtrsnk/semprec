## What was delivered

`PUT /api/sleep/nights/:night` sets or resets one night's exception. `sleepNightPut` (a `(pool) => handler` factory, as `customRouteMount.ts` requires) is in `sleep/sleepRouteHandlers.ts` and declared in the sleep manifest as a custom route with justification `transactional-semantics`.

- The date and the strict body `{ bedTime?, wakeTime?, alarm? }` are validated before any read; `400 validation_failed` names `night` or the key. Times are normalized (`6:45` becomes `06:45`); an empty string, `24:00` and `7:5` are refused.
- In one transaction: the per-night advisory lock (`lockSleepNight`, exported from `sleepWriteHooks.ts`, extracted from `assertNightIsFree` with the same key and statement), then the non-deleted night exception locked `FOR UPDATE`. The exception is created through `createItemWithClient` when absent and a provided field is non-null (the provided fields are stored, nulls included), patched through `updateItemWithClient` (no `ifVersion`) with only the fields that differ, or nothing is written.
- The answer is `{ night }` from `loadSleepNights` for that date (null when neither a plan nor an exception applies), read at READ COMMITTED so the read sees an exception another PUT committed meanwhile.
- Review fix: `sleepNightUpdatePreLockHook` (in `sleepWriteHooks.ts`, registered for `SLEEP_NIGHTS_MODULE_ID` in `domainWriteHooks.ts` with `registerItemUpdatePreLockHook`) takes the night lock before the row lock when a generic update patch names a calendar-date `night`, the same order as the PUT, so a PUT and a generic PATCH cannot deadlock.

## Entry points and contracts dependents build on

- Route `PUT /api/sleep/nights/:night`, route matrix entry `sleep night put` (`routeMatrix/sleep.ts`, example path `/api/sleep/nights/2026-10-16`), tenant scoped, not public. Response `{ night: SleepNight | null }`.
- `lockSleepNight(client, night)` exported from `sleep/sleepWriteHooks.ts`; `sleepNightUpdatePreLockHook` exported from the same file. Neither is in the `@semprec/data` barrel.
- Stored exception keys stay `night`, `bedTime`, `wakeTime`, `alarm` (null means follow the plan). No table, migration, operation or job name was added.
- An all-null PUT on an existing exception keeps the item with all three fields null; on a night without an item it creates nothing.

## Deviations and spec seams

1. The Task calls `sleepNightPut` the handler; it is the factory.
2. The route entry is in the slice `routeMatrix/sleep.ts` with its `ROUTE_HANDLER_FILES` mapping and `ROUTE_CASES` case.
3. `lockSleepNight` was extracted in `sleepWriteHooks.ts` (not in Touches) so the hooks and the route share one definition; the statement text is unchanged.
4. The answer is read at READ COMMITTED, not REPEATABLE READ (documented in both docstrings).
5. A create stores the provided fields, null ones included; a patch carries only the differing fields.
6. A time is normalized before it is compared and stored.
7. Tests outside Touches: `sleepModuleManifest.unit.test.ts` and the new `sleepNightPut.test.ts`.
8. #1828 (Shared-file ordering) was open when the worker ran; it is delivered on the tip now.
