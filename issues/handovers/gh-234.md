## Summary

Implements issue #234: the `/setup` wizard page in the web client, driven by the #233 bootstrap API.

- **`setupOperations.ts`** (`web/src/api/setupOperations.ts`): the HTTP binding for `POST /api/setup`, sending `{email, password}` with the setup token as an `Authorization: Bearer` header (the token comes from the wizard's own `?token=` query param, not a server-side secret). A 404 response — either "already bootstrapped" or "wrong token", indistinguishable by design — classifies as `unavailable`; a 400's validation message is surfaced for inline display.
- **`SetupWizard.tsx`** (`web/src/views/setup/SetupWizard.tsx`): form → not-found / success states. The not-found state renders with no form, per the acceptance criteria. Success links onward to `?page=login` without creating a session itself. No account-creation logic lives in this component — only the #233 API inserts users.
- Wired into the app's existing query-param routing (`?page=setup&token=...`) in `main.tsx`/`App.tsx`, matching the codebase's router-less convention (no react-router in this repo).
- A dev-proxy entry for `/api/setup` in `vite.config.ts` that deliberately does *not* attach the stopgap `SEMPREC_API_TOKEN` — this endpoint's bearer token is the operator's URL-provided setup token, not a shared server secret.
- i18n strings (English + Czech) and tests for both the operations module and the component (form submit, success, not-found, validation error).

This branch also picked up `develop`'s already-merged #233 work via fast-forward, since #233 merged after this branch was created and the wizard has nothing to call without it.
