# Handover for gh-1398

Semp thread sessions are now bound to their run, and a turn reports when it starts. This changes no queue behavior. The consumer is the queued turn task (#1727).

- **`SempConversationOptions`:** `createAgentSession` is replaced by `createAgentSessionForRun: (run: AgentRunRow) => Promise<CreateAgentSession>`. A waking `send()` calls it with the new run row after the run is `running` and before the first prompt. A rejection closes the run as errored through `failRun`. A continuation reuses the open entry's session, so the factory is not called again.
- **`send(task, { signal, onTurnStart })`:** the new trailing argument is exported as `SempSendOptions`, and `SempTurnStart` is the callback payload `{ agentRunId, firstEventId }`. `signal` goes to the session options and to `runAgentTurn`. An abort closes the run as errored and drops the entry like any broken turn. `onTurnStart` is awaited once per turn, right after the first persisted event the turn stores. A throw closes the run through `failRun` and propagates, and the generator is not pulled again.
- **`runAgentTurn`:** a sixth optional `onFirstEvent(eventId)` parameter, awaited after the first persisted-kind event insert. `message_update` deltas do not count. `pushRunStatus` still returns `void`.
- **Not changed:** `createAgentSessionFactoryForRun` already has the `(pool, registry, gateway, run)` shape, so the consumer can pass `(run) => createAgentSessionFactoryForRun(pool, moduleRegistry, gateway, run)`. Nothing in `services/semprec-agents` constructs a `SempConversation` yet, so no edits were needed in `agentRunTasks.ts`, `agentWorker.ts` or `queueRuntime.ts`.
- **Tests:** `sempConversation.test.ts` was moved to the new option and gained cases for the run row passed to the factory, the signal reaching the session, `onTurnStart` on a wake and on a continuation (larger first event id), an abort on a wake and on a continuation, a throwing `onTurnStart`, and a rejecting factory. `lifecycleAdapter.test.ts` covers `onFirstEvent`. These tests plus the `agent-runtime` suite and `agentRunCancellation` pass (192 tests), and build, lint and prettier are clean. I did not run the full verify.
- **Notes for dependants:** `firstEventId` is the id of the first event the turn stores. For a wake that is the `turn_start` row after the `running` status event, and the id is a bigint string. A turn that stores no persisted event never calls `onTurnStart`.
