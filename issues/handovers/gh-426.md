## Summary

Closes #426. `semprec-ai-gateway` previously had no `SIGTERM`/`SIGINT` handler, so a restart could kill the process between a provider call returning and its `ai_gateway_calls` row being written, silently under-counting spend against the daily/monthly budget cap.

Added `backend/services/semprec-ai-gateway/src/shutdown.ts`, wired into `serve.ts`, implementing a fixed-order graceful shutdown:
1. `server.close()` — stop accepting new connections.
2. Poll `server.closeIdleConnections()` until drained or `SHUTDOWN_DRAIN_TIMEOUT_MS` (60s, matching the client's own request timeout) elapses.
3. On timeout, `server.closeAllConnections()` to force-close any still-hanging request.
4. Stop the process heartbeat — deliberately *after* the drain, not before.
5. `pool.end()`, bounded by `POOL_END_TIMEOUT_MS` (5s) against a hung/unreachable database.

`shutdown()` is idempotent and never rejects; both signals are registered with `on` (not `once`) so a repeated signal during a long drain doesn't fall through to Node's default fatal action.

Documented the ordering rationale — and the rejected alternative of a shared shutdown helper with `semprec-api`/`semprec-agents` — in `docs/adr/2026-09-17-shutdown-ordering-with-late-heartbeat-stop.md`.

Added integration tests (`shutdown.test.ts`) covering drain/timeout/idempotency/error paths against stub and real `http.Server`/Postgres, and unit tests (`registerShutdownSignals.unit.test.ts`) for signal wiring.
