## What was delivered

- Cause: the `mail_draft_not_editable` route test in `backend/packages/data/src/__tests__/mailDraftRoutes.test.ts` started the update and the discard of a provider draft together and attached a handler to the discard only after the update settled. When the discard's refusal arrived first, Node reported it as an unhandled rejection, which Vitest attributed to the file. Production code was not at fault: the discard route rejects inside its own request with 409 `mail_draft_not_editable`.
- Fix: each refused request in that test now starts only after the previous one was handled.
- Regression guard: the test collects every unhandled rejection while the refusals run (a `process` `unhandledRejection` listener, removed in `finally`) and fails when any appears. Reverting to the eager start fails the guard within 40 repeats locally.

## Contracts dependents build on

- `unhandledRejectionsDuring(work)` in `mailDraftRoutes.test.ts` is local to that file; nothing else changed. The 409 contract of the draft routes is unchanged.
