# Handover: List the attachments of Inbox item sources on Inbox cards

**Shape.** The `inboxItem` variant of `resolvedSource` on every proposal card of `GET /api/inbox/cards` now carries
`attachments`, always present (`[]` for an item without attachments):

```json
{
  "kind": "inboxItem",
  "id": "<uuid>",
  "text": "string | null",
  "date": "string | null",
  "time": "string | null",
  "type": { "id": "<uuid>", "name": "string", "emoji": "string" },
  "attachments": [
    {
      "attachmentId": "<uuid>",
      "blobId": "<uuid>",
      "name": "string | null",
      "mimeType": "string",
      "byteSize": 52000,
      "pageCount": null,
      "thumbnailBlobId": "<uuid> | null",
      "source": "camera | scan | photoLibrary | files | share"
    }
  ]
}
```

Each element is exactly `JournalInboxAttachmentSummary` (`backend/packages/data/src/inbox/journalInboxCompute.ts`), in
the diary's order (attachment `position`). `name` is `null` for captured attachments (bare uuid storage keys);
`thumbnailBlobId` is `null` until the metadata job records one and is never the original blob; `pageCount` is currently
always `null`. Bytes are fetched with `GET /api/blobs/:id` using `blobId` or `thumbnailBlobId`. Transcript and run
sources are unchanged.

**Backend.** `listInboxAttachmentSummaries(client, inboxItemIds)` in `journalInboxCompute.ts` builds the summaries
from `listInboxAttachments` with one query; the Journal day compute and `buildProposalCards` in `inboxCardsStore.ts`
both use it, the latter once per page in the cards' transaction and tenant scope. No route matrix or web type
described the card shape, so neither changed.

**Tests** (`backend/packages/data/src/inbox/__tests__/inboxCardsStore.test.ts`, "the resolved source"): two
attachments with every field and the order, `[]` for an item without attachments, one attachment query for a page of
one and of three cards (counted through a proxy client), and two tenants on the `alldots_data` runtime role each
seeing only its own item's attachments.

**Mobile** decodes `resolvedSource` in `mobile/shared/data/.../InboxCardDtos.kt`; the sibling issue of this batch adds
the field there.
