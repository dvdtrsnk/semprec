## What was delivered

- `sendDraftEmail` (`mail/send.ts`) no longer refuses or sends for an agent. For an `ai_agent` actor (`{ agentRunId, toolCallId? }`) it creates one pending outbound approval request and returns it, whatever `emailSendAutonomous` the run's project, the draft's thread or a heartbeat project holds; it reads only `draftItemId` and the actor. A `user` actor (also an MCP client with a human session) sends as before. `assertEmailSendAuthorized` and its 403 are removed.
- The request (`mail/mailSendApproval.ts`, `requestMailSendApproval`): tool `mail.draft.send`, risk class `outbound`, payload `{ draftId, draftHash, mailboxId, to, subject, body }` (`MailSendApprovalRequestPayload`), resource snapshot sha256 = `draftHash`, description `approval.emailSend` with `{ mailboxName, recipientCount }` (no recipient, no subject), and an `approval_pending` notification in the same transaction. Everything is read from the stored draft under the Emails item lock and the `mail_drafts` row lock (`prepareSend`). The hash covers mailbox, From, To, Cc, Bcc, subject, body and attachments (name, content type, blob id).
- At most one pending request per draft (`findPendingMailSendApprovalRequest`, under the item lock, no unique index). Deciding one request, approved or rejected, closes the other pending requests of the draft as rejected with `{ supersededBy }` (`supersedePendingMailSendApprovalRequests`, called from `decideAndEnqueueApprovalRequest`).
- Execution (`mail/mailSendApprovalExecution.ts`, `executeClaimedMailSendApproval`), dispatched by `approvalRequestExecution.ts` on the new payload kind: claim, recompute the draft hash, send through `sendDraftEmail` as the user, record the outcome. The hash is checked a second time in the send's claim transaction (`beforeClaim`) under the locks. A changed, gone or sent draft, or a claim held by another send, ends in conflict / `sourceChanged` with nothing sent; other failures are `callFailed`, logged by class name and code. A claim whose delivery died is settled by the existing stale-claim sweep.
- The core task list takes the mail send transports (13th argument of `createCoreTaskList` / `createApiCoreTaskList`); the API queue runtime builds them once and shares them with `setEventInvitationDelivery`. A worker without them fails closed with `toolUnavailable` and sends nothing.
- ADR `2026-11-14-an-agents-mail-send-is-an-approval-request-of-its-own-kind-sent-as-the-user`.

## Entry points and contracts dependents build on

- `sendDraftEmail` has two overloads: a user actor returns `SendEmailResult`, an agent actor `{ agentRunId, toolCallId? }` returns the `ApprovalRequest`. `SendEmailActor`'s agent variant no longer carries a `PermissionManifest`.
- Approval request payload kind `MailSendApprovalRequestPayload` (discriminated by the top-level `draftHash`), tool name `mail.draft.send`, risk class `outbound`; a `moduleTool` request for every reader that sorts by kind (queue safe summary, Semp thread list `sourceKind`) but executed by its own executor, not through `ModuleRegistry`. Not exported from the `@semprec/data` barrel.
- Description key `approval.emailSend` with params `{ mailboxName, recipientCount }` in `seed/i18n` and `notifications/i18n`, en and cs.
- `prepareSend`, `PreparedSend` and `sentThreadOf` moved unchanged from `mail/mailDraftSend.ts` to `mail/mailDraftSendInput.ts`; `computeMailDraftHash` is the exported hash.
- gh-1949 declares the agent-facing send tool with `requiresApproval` and calls `sendDraftEmail` with an agent actor.
