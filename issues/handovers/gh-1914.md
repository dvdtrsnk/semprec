## What was delivered

- `listProjectAgentRuns` returns, for a heartbeat occurrence, only its latest attempt: the highest `attempt`, ties by the later `started_at`, then the greater id (this extends the `(attempt, started_at)` order of `getLatestRunOfOccurrence` with the id). It is a `NOT EXISTS` probe of `agent_runs_occurrence_idx` inside the ordered scan of `agent_runs_tenant_project_started_idx`, applied before `LIMIT`, so `limit` counts rows after the collapse and no sort, window or grouping runs over the project's history. A run with no occurrence is always a row.
- `listRunsOfOccurrences` (new store function) reads all attempts of the listed occurrences in one statement.
- The list row's `attempt` is the run's `attempt` column. For an occurrence row `costUsd` is the sum of all attempts and the row gains `attempts: [{ id, attempt, startedAt, durationMs, costUsd, displayStatus }]` ascending by attempt; a row without an occurrence has no `attempts` key. Every cost (each attempt, the sum, the cost of a plain run) goes through one rounding function (15 significant digits), so a single-attempt row equals its entry.
- Costs of all rows and attempts come from the same single `getAgentRunCosts` statement of gh-1909.

## Deviations from the specification and spec seams

1. The latest attempt is chosen by highest attempt, then later `started_at`, then greater id, rather than by "not the `retry_of_run_id` of any other row": the two agree for a chain, and the chosen rule also yields exactly one row when the scheduler's unchained fallback leaves two runs with the same attempt.
2. `costUsd` of an occurrence is summed in JavaScript and rounded to 15 significant digits so that 0.1 + 0.2 is 0.3.
3. New store function `listRunsOfOccurrences` is not named in the Task; `publicSurface.test.ts` (outside Touches) lists it.
4. Each attempts entry carries its own `displayStatus`, derived like the row's; an attempt closed as `done` reads its reply with one statement, an errored attempt none.
