## Summary

Fixed `DelegationRegistry.expire()` in `backend/packages/agent-runtime/src/delegationRegistry.ts` to claim `entry.busy = true` synchronously before its first `await`, mirroring the correct pattern already used by `SempConversation.pause()`. Previously `expire()` only checked `entry.busy` but never set it, so a `delegate()` call arriving while `expire()` was mid-flight closing the run could reuse a session whose run was concurrently being finished as `done` — causing the reused turn's events to be rejected once written against a terminal run, and dropping the session from the registry under the in-flight caller.

Changes:
1. **`expire()`**: sets `entry.busy = true` right after the initial guard, before calling `finishAgentRun`. On success, the entry is deleted as before. On failure, resets `busy = false` and reschedules the TTL timer (previously it only rescheduled, leaving `busy` untouched — moot before this fix since it was never set, but now required for correctness). Updated the docstring to describe the new invariant instead of the now-inaccurate "busy entry's own touch() reschedules" sentence.
2. **Tests** added to `delegationRegistry.test.ts`:
   - Holds a `SELECT ... FOR UPDATE` lock on the run row from a second connection so `expire()`'s `finishAgentRun` blocks mid-close; asserts a concurrent `delegate()` is rejected with `BUSY_ERROR_MESSAGE` and never calls `session.send`, then verifies the run reaches `done` and a subsequent `delegate()` starts a fresh run.
   - Wraps the pool so its first `UPDATE agent_runs` query rejects once; asserts the entry survives with a rescheduled timer and a later `delegate()` reuses the same session (`send` is called).

Verified: `pnpm run verify` passes in both `backend/` (lint, format, build, unit/integration/e2e tests, migration/boundary checks) and `web/` (lint, format, build, tests) — all green.
