## Behavior and production wiring

The public agent-runtime barrel exports `ToolUseEventPayload`, `ToolResultEventPayload`,
`ToolEventMetadata`, the MCP identity type and `parseToolEventPayload`. The parser validates
required fields, canonical dotted operation names, MCP identity fields, string target ids
and operation/MCP exclusivity. It accepts legacy rows without inventing metadata from the
model-facing name and returns null for malformed JSON payload shapes or non-tool kinds.
Arguments and results remain unknown values rather than unchecked casts.

`createAgentSessionFactoryForRun` attaches dotted generic-operation identity or MCP grant
identity when constructing tools. It builds the model-name metadata map from the actual
`withUniqueNames` survivors, so a discarded collision cannot overwrite the retained server's
registration identity. It passes that map to the production pi session factory.

`piAgentSession` enriches both tool event kinds and snapshots string item/database ids from
call arguments at tool start. A prompt-local map keyed by toolCallId repeats that snapshot
on the matching result and deletes the entry. Missing or non-string ids stay absent; result
text is never used for target discovery. Tools absent from the metadata map retain their
legacy payloads. The existing lifecycle adapter passes these messages unchanged to the
existing data-owner writer; no schema, authorization, model gateway or writer changes were
made. The existing 1 MiB write cap still rejects oversized payloads.
