## What was delivered

`GET /api/items/:id/origin` answers, for an item created by confirming an Inbox proposal, `{ proposalId, inboxItemId, capturedAt, captureTimeBasis, captureChannel, sourceText, siblings: [{ itemId, label }] }`.

- `capturedAt` is nullable; `captureTimeBasis` is `inboxCapture`, `unknown` or `legacyUnverified` exactly as the `item_origins` row records it. A null time is never formatted as a date; a legacy row keeps `legacyUnverified` with its stored time.
- `sourceText` is the `text` property of the live source Inbox item (an empty string for a photo-only capture, since gh-1963 stores no separate captured-upload text). It is `null` for a transcript origin, and when the Inbox item is trashed, gone or has no text.
- `siblings` are the live items of the same `proposal_id`, the item itself excluded, trashed items excluded, oldest first (ties by id), each labelled by the database's title property or, when there is none or it is empty, by the item id.
- 404 `not_found` with one constant message (`Item origin not found`, no id in it) for an unknown id, another tenant's item, a trashed item and an item with no origin row (created by hand or by an agent). A non-UUID id is 400 `validation_failed` on `id`, checked before any tenant-dependent lookup.

The read is SELECT only, in one `withTransaction` in the tenant scope taken from the session, through `getItemsByIds` (live items in the tenant's visible databases) and `item_origins` under RLS.

## Deviations from the specification and spec seams

1. The route entry lives in the slice `routeMatrix/items.ts`, not in `routeMatrix.ts` (the established slice pattern).
2. The isolation case is keyed `item origin`; `ROUTE_HANDLER_FILES` maps it to `inboxRouteHandlers.ts`.
3. gh-1963 stores no separate captured-upload text, so `sourceText` is the live source Inbox item's `text` property (see above).
4. A non-UUID id answers 400 `validation_failed` (field `id`), as the sibling handlers of the file do, not 404.
5. The guard in `readItemOrigin` that throws a plain error on an unknown `capture_channel` or `capture_time_basis` is defensive typing at the DB boundary; check constraints make it unreachable, so it has no test.
6. Siblings of one confirm share `created_at` (transaction time), so their order is by id within it; no test pins the order and no criterion requires it.
7. The Task lists three production files; the tests are in the new `itemOriginRoute.test.ts` rather than an existing file.
