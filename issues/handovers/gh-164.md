## Summary

Implements the `WS /api/sync` client reconnect and per-stream recovery contract from issue #164.

**New package `@semprec/realtime-client`:**
- `backoff.ts` — exponential backoff with full jitter, 1s floor, 30s ceiling, doubling per attempt.
- `syncClient.ts` — reconnect loop driving each stream's own recovery on every successful connect: resubscribes every open Yjs doc and watched agent run from its own last cursor (no universal cursor), gates new `invalidate` frames behind a one-shot active-state refetch, delivers notifications immediately (never gated), and treats a 4401 session-revoked close as terminal (no further retries).
- `docSession.ts` — per-document y-protocols/sync handshake (SyncStep1/Step2/Update), re-run identically on every reopen so a resume after reconnect exchanges only the missing diff.
- `serverFrame.ts` — validates every inbound text frame against protocol-v1's closed `OutboundFrame` catalog before it's trusted, mirroring the server's own boundary validation.
- Small addition to `@semprec/realtime`: exported `SESSION_REVOKED_CLOSE_CODE` and a few protocol-v1 helpers this new client needs.

**Tests:** unit tests for backoff math and the sync client's reconnect/recovery logic against fake sockets and fake timers, plus a new e2e suite (`services/semprec-api/src/__tests__/reconnect.e2e.test.ts`) exercising four real fault scenarios end-to-end — raw network drop, LISTEN connection loss (#242's fault), controlled server shutdown (deploy), and slow-consumer backpressure close — each verifying REST state, Yjs state-vector equality, the agent-event stream, and unread notifications all converge after reconnect.
