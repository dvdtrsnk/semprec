## What was delivered

Persisted agent events no longer carry sensitive values through tool call arguments, assistant text or compaction input. The live session in memory, the `onEvent` stream and the value `runAgentTurn` returns are unchanged. The marker is `[redacted: sensitive]` from #1827.

- A "turn" is one `runAgentTurn` call. The call keeps a per-call redactor (`createSensitiveTurnRedactor`); its flag is set when the call stores a `tool_result` that carried the #1827 mark. A later `runAgentTurn` call on the same run starts without the flag.
- After the flag is set, every later `tool_use` is stored with the marker as arguments (name, call id, operation and targets stay, so the call still pairs with its result), and every later assistant message is stored with its text and text blocks as the marker, thinking dropped and toolCall blocks keeping id and name with `{ "redacted": marker }` as arguments.
- An `item.create` or `item.patch` is redacted from the start when its target database, or the database of its target item, is sensitive, whether or not a result is marked yet. The lookup goes through the choke point in the caller's tenant scope and fails closed: no target, an unresolved target, a failed lookup (logged with operation, run and error class only) and a PoolClient handle all count as sensitive.
- The assistant message that precedes such a call is redacted when stored. The session attaches `toolCallTargets` (call id, operation, target database and item per generic-operation toolCall block) to the `message` event; the redactor runs the same lookup per block and stores qualifying blocks with redacted arguments. The steering field is never stored.
- Replay: `walkStoredEntries` in `conversationReconstruction.ts` redacts the toolCall blocks whose call id belongs to a `tool_use` stored with the marker, so resume and compaction never see them. Compaction is computed from the reconstructed history only, and the stored checkpoint holds no value.
- Run row: `agent_runs.result` is written from the stored (redacted) last message by `runAgentSessionForRun`, the queued `agentRun` job and the heartbeat `runAgent`, through the new `runAgentTurnWithStoredForm`. After a sensitive read the run's result is the marker.

## Entry points and contracts dependents build on

- `@semprec/agent-runtime` now exports `runAgentTurnWithStoredForm` (returns the live last message and the stored form, `AgentTurnOutcome`) and, in `types.ts`, the `ToolCallTarget` type. `runAgentTurn` keeps its signature and return value.
- `sensitiveTurnRedaction.ts`: `createSensitiveTurnRedactor(client, agentRunId)`. It lists the content-bearing write operations; a new content-bearing write operation must be added to that list, or its arguments are stored in full until its result is marked.
- `sensitiveMessageRedaction.ts`: `redactToolUse`, `redactAssistantMessage`, `toolCallTargetsOf`, `storedAssistantMessage`, `redactReplayedToolCalls`. `sensitiveToolResult.ts` exports one more function for the shared marker.
- A session (services/semprec-agents `piAgentSession.ts`) that maps tool names to operations carries `toolCallTargets` on its `message` events. A session that does not attach them still gets redacted replay.
- Tables, routes, operations and job names: none added. ADR `2026-11-13-tool-call-arguments-and-assistant-text-after-a-sensitive-read-are-stored-redacted`.

## Deviations and spec seams

1. Touches extended: two sibling modules instead of inline code in `lifecycleAdapter.ts`, a one-function export in `sensitiveToolResult.ts`, a doc comment in `types.ts`, `index.ts`, the `semprec-agents` files above and an ADR.
2. "Turn" is one `runAgentTurn` call, not a pi turn_start/turn_end pair, because the final answer arrives in a later pi turn than the results it quotes.
3. Tool calls issued in parallel with a call whose result is marked are stored before the mark exists, so they are stored in full unless they are themselves a sensitive write.
4. The text and thinking blocks of the assistant message that carries a first sensitive write call stay in full when no result is marked yet; the decision redacts assistant text only after a marked result and does not classify text by content.
5. The live reply stays unredacted, so a delegating agent receives the delegate's live reply as the result of its delegation tool call, which is stored as that tool result (not covered by the #1827 mark). `SempConversation` and `DelegationRegistry` replies are live replies. Recorded in the ADR.
6. Events and run results stored before this change are not rewritten (out of scope).
7. Baseline failure not caused by this chain: `services/semprec-agents` `sempTurnReadAllowances.test.ts` "lets the agent read the attached record in that turn without a grant ..." fails on the base commit too (the worker verified it in a scratch worktree at 16fa9ce7c); the stored result of a health read is already the #1827 marker. It is not part of this landing's gate and was not run by the queue runner.
