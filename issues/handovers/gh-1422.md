# gh-1422 — per-module pre-write property transform

Repository-Issue: gh-1422

## Delivered behavior

- `backend/packages/data/src/chokePoint/hooks.ts`: `registerItemPreWriteTransform(moduleId, transform)`, `hasItemPreWriteTransform(moduleId)`, `runItemPreWriteTransforms(moduleId, context)` and the types `ItemPreWriteTransformContext` / `ItemPreWriteTransform`. Registering the same `(moduleId, transform)` twice is a no-op, a module's transforms run in registration order, each on the previous output, and `clearHooksForTests` clears the registry.
- `backend/packages/data/src/chokePoint/itemWrites.ts`:
  - Create: the owning module's transforms run after `assertWritableProperties` and before `insertItemWithReplay`. The transformed properties are inserted and passed to the create hooks. On an idempotency replay the existing row is returned and the transform result is discarded. A default no longer overwrites a key the caller or a transform set.
  - Update: when the owning module has a transform, the row is locked with `lockItemById` first (`NotFoundError` for a missing or trashed row), then the transforms run. The transformed patch goes to `updateItemProperties`, the update hooks, the value-link break, the rollup dependency loop and the timezone check. A database without a transform takes no extra lock.
  - Ownership check on keys a transform adds (keys absent from the caller's patch): unknown key → `ValidationError`; rollup → `403 computed_readonly`; relation → `ValidationError`; `owner: 'system'` with an `ownerProcess` that is neither null nor the transform's module → `403 owner_violation`.
  - The inline Tasks branches and the `TASKS_MODULE_ID` / `deriveTaskTime` imports are removed from `itemWrites.ts`.
- `backend/packages/data/src/tasks/tasksItemPreWriteTransform.ts` (new): Tasks `time`. A create always stores it; an update stores it only when the patch names `timeFrom` or `timeTo`, computed from the patch merged over the locked row. Registered in `domainWriteHooks.ts` under `TASKS_MODULE_ID`.
- `docs/adr/2026-10-29-item-pre-write-transforms-per-module-registry.md` (new, accepted, supersedes `2026-09-19-derived-system-properties-computed-inline-at-choke-point`). The superseded ADR changed only its frontmatter (`status: superseded`, `superseded-by`). The 2026-09-30 ADR is cross-referenced and not edited.
- `.bb/skills/state-writes/SKILL.md` §2: the derived-field paragraph now names the transform mechanism.

## Behavior notes

- `previous` on the update result is still keyed by the caller's keys only. `itemWrites.test.ts` pins this for Tasks `time`.
- Every Tasks update now takes the item row lock, not only updates naming `timeFrom`/`timeTo`. Stored values are unchanged.
- The Tasks `time` key is now a written key for the rollup dependency loop and the value-link break. Neither has an effect today: no value link can sit on a system key, and no rollup is known to depend on `time`.

## Notes for dependants

- Register a transform from your own module file and add one line in `domainWriteHooks.ts`. Do not add a branch to `itemWrites.ts`.
- A transform runs on a create replay too, before the idempotency check. Keep it deterministic and free of side effects. A transform that throws on a replay turns the replay into that error.
- A transform may add a key the caller did not send. A key it adds with `owner: 'user'` is not checked by the ownership rule, and the value-link handoff check covers caller keys only. A dependant that adds user-owned keys must account for both.
- A transform that leaves out a key the caller sent does not write that key.
- `ownerProcess` conflict: the spec calls `ownerProcess` a process name, never a module id. Seeded Emails keys (`seedEmailModule.ts`) name a module id (`emails`, `folders`). The enforcement accepts a key whose `ownerProcess` equals the transform's module, so those seeds are not refused. A dependant must not assume a module-id `ownerProcess` is always a violation.
- `writer` is in the transform context. No rule in this issue reads it.
- Transcripts is still exempt by name in `assertTitlePresent` inside `itemWrites.ts`. Moving that exemption was out of scope.
- `docs/adr/2026-09-19-derived-system-properties-computed-inline-at-choke-point.md` already fails `prettier --check` at the base commit (a `*emphasis*` in the frozen body). This change leaves that body untouched, so the root `format:check` failure on that file predates this issue.
