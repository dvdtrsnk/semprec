## What was delivered

- `GET /api/semp/threads`, the first route of `createSempThreadRoutes` in `backend/services/semprec-api/src/sempThreadsHandler.ts`. It needs a session, validates the query, and reads in one `withTransaction` under the caller's tenant scope with the caller's `users.locale`.
  - `kind`: a comma-separated subset of `chat`, `item`, `tick`; default `chat,item`. A value repeated in the list is taken once.
  - `subjectInboxItemId`: a UUID; only the thread of that Inbox item.
  - `limit`: an integer from 1 to 100; default 50.
  - `cursor`: the `nextCursor` of an earlier page.
  - Answer 200 with `{ rows, nextCursor }`, ordered by `last_activity_at DESC, id DESC`; `nextCursor` is null on the last page.
- `listSempThreads(client, input)` in `backend/packages/data/src/semp/sempThreadsListStore.ts` (new): one list query plus one read of the Inbox database, one read of the project items of the page and the catalog load of the title template. It writes nothing.
- Row shape `{ id, kind, title, preview, lastActivityAt, hasPendingApproval, pendingApproval, heartbeat, subject }`:
  - `title`: a chat thread has its stored `semp_threads.title` (null until one is generated); a tick thread has the current `project_heartbeats.name`; an item thread has the catalog template `semp.thread.itemTitle` of the caller's locale filled with the current `text` of its Inbox item, and null when that item is in the trash, gone or has blank text. Nothing is stored.
  - `preview`: the last message of the thread that has text or a system key, read through a `LATERAL` subquery ordered by `created_at DESC, id DESC`. Text is reduced with `stripMarkdown` of `@semprec/block-model` and cut to 140 Unicode code points plus `…` when it goes on. A system message gives `{ key, params }`. Null when no message has text or a system key.
  - `lastActivityAt`: the millisecond ISO string of `last_activity_at`.
  - `hasPendingApproval` and `pendingApproval`: `{ description, sourceKind }` of the newest pending `approval_requests` row of a run whose `agent_runs.thread_id` is the thread (a delegated run carries its parent's thread id); `description` is the snapshot of gh-1683 or null for a request stored without one; `sourceKind` is `genericOperation` when the stored payload has `operationName`, otherwise `mcpInvoke`.
  - `heartbeat`: `{ id, name, projectItemId, projectName }` for a tick thread, otherwise null; `projectName` is null when the project item has no name, is in the trash or is gone.
  - `subject`: `{ inboxItemId, proposalId, exists }` for an item thread, otherwise null. The two ids are `subject_inbox_item_id` and `subject_proposal_id` of the thread; `exists` is read live and is false when the Inbox item is in the trash or gone.
- The catalog key `semp.thread.itemTitle` in `backend/packages/data/src/seed/i18n/cs.json` (`Úprava: {itemName}`) and `en.json` (`Edit: {itemName}`).
- The route matrix entry `{ name: "semp thread list", method: "GET", path: "/api/semp/threads", surface: "api", public: false, tenancy: "tenant" }` in `backend/services/semprec-api/src/routeMatrix/semp.ts`, its `ROUTE_CASES` case in `tenantIsolationRoutes.test.ts` and its `ROUTE_HANDLER_FILES` mapping to `services/semprec-api/src/sempThreadsHandler.ts`, all in the same merge.

- Tenancy: every table the query reads is a tenant table under row-level security and every join carries `tenant_id`. An Inbox item or a cursor of another tenant answers exactly like a random id. A tenant has one user, so another user is another tenant.
- Preview bound, stated in the corrected Task: the query reads at most the first 1000 code points of the stored text (`left(m.text, 1000)` and a flag for a longer text). A message longer than that always gets the ellipsis, also when those 1000 code points show 140 code points or fewer without Markdown, and Markdown syntax that the window cuts off before it closes can stay in the preview as written. `stripMarkdown` takes super-linear time on unmatched markers, so a caller that changes the window keeps a bound (CONTROLLER.md, "Open items").
- `kind` filters on the stored `semp_threads.kind` only.
- No SQL migration, no table, no column, no index, no job name, no write hook and no write of any kind was added. One catalog key was added.

## Deviations from the specification and spec seams

1. Decided, not a deviation any more: the subject is `{ inboxItemId, proposalId, exists }`. The worker did not deliver `label`, `proposalTarget` and `capturedAt` because a thread stores no such snapshot; `issues/decisions/gh-1729.md` corrected Task step 2 to this shape and moved the three fields to Out of scope.
2. Decided, not a deviation any more: the preview is built from the first 1000 code points of the stored text. The same decision put the bound into Task step 2 and the fourth acceptance criterion instead of reading the whole message, because `stripMarkdown` takes quadratic time on a run of unmatched `[`.
3. Spec seam: the route entry is in the slice module `backend/services/semprec-api/src/routeMatrix/semp.ts`, not in `routeMatrix.ts`. Two inventory files outside `Touches` changed because their suites require it: `chokePointWriteBoundary.unit.test.ts` and `publicSurface.test.ts`.
4. Reading of the Task: the preview is the last message that has text or a system key, not literally the last row. The send route stores a queued assistant message without text right after the user's message and a failed reply keeps none, so the literal reading would blank every chat that waits for or failed its answer.
5. Reading of the Task: `pendingApproval.sourceKind` is `genericOperation` or `mcpInvoke`, derived from the stored payload by the rule of `safeSummary.kind` in `GET /api/approval-requests`. The Task does not define the values and the epic gh-1304 lists them as an open question.
6. Decided where the Task is silent: an item thread whose Inbox item is in the trash, gone or has blank text has title null; the item text is inserted whole, not cut and with its Markdown; `exists` is false for an Inbox item in the trash as well as a missing one; a parameter given twice, an empty `kind` entry and a `kind` in another letter case are 400.
7. `loadSempThreadTitleResolver` and `mapSempThreadSubject` are exported from the module, not from the barrel, and have no second caller yet.
8. The isolation case creates one Inbox item and its item thread in each tenant inside the case; the rows stay for the later cases of that file, which passes as a whole.
