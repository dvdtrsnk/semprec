# Handover for gh-1440

Every notification kind now has a category, an optional severity (problems only) and a push-eligibility flag. Nothing consumes the map yet.

**What changed in `notificationKinds.ts`**
- New exports: `NOTIFICATION_CATEGORIES` (`approvals`, `invites`, `reminders`, `problems`), `NOTIFICATION_SEVERITIES` (`critical`, `warning`, `info`), the types `NotificationCategory`, `NotificationSeverity` and `NotificationKindPolicy`, `NOTIFICATION_KIND_POLICY` and `policyForKind(kind)`.
- `NOTIFICATION_KIND_POLICY` is a `Record<NotificationKind, NotificationKindPolicy>`, so adding a kind to `NOTIFICATION_KINDS` without a policy fails the build.
- Mapping: `approval_pending` is approvals; `mail_sync_error`, `mail_sync_stalled`, `backup_restore_failed` and `process_stale` are problems/critical; `agent_run_error`, `heartbeat_error`, `automation_error`, `agent_guidance_drift` and `queue_backlog` are problems/warning; `agent_guidance_drift_resolved` is problems/info with `push: false`. All others have `push: true`.
- `publicSurface.test.ts` has the five new runtime names added to its frozen list (updated by hand; that test needs embedded Postgres, which the sandbox could not start, so it was not run, but the list was checked to stay sorted).

**Tests**
- New `notificationKindPolicy.unit.test.ts` (4 tests, passing): every kind has a policy and no extra keys exist, severity only on problems, `push` is false exactly for info, and the listed kinds have the listed classification.

**Notes for dependants**
- #1441 and #1443 should read the map through `policyForKind`. The `invites` and `reminders` categories exist but no kind uses them yet; the issues adding invitation, reminder, reauthorization and transcript kinds must add their policy entries.
- Narrow on `policy.category === "problems"` to read `severity`.
