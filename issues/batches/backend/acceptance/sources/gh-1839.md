## Specification

The record is `issues/items/gh-1839.md`. Worker summary: Adds the catalog operation relation.related (49th operation, capability core.item.read, non-destructive) and GET /api/items/:id/related, which returns a bare array of { databaseKey, databaseId, count, via, filter }. packages/data/src/chokePoint/relatedOps.ts counts, in one SQL statement over properties, relation_definitions and item_relations, the distinct live records of every database whose relation property points at the viewed record's database (both sides of a definition, one-way relations from the target side), and builds the relation_contains filter that selects them. relatedRoutes.ts replaces the direct row of a database with a counted filter route: for an area the manifest area filters of #1597 (Tasks/Files/Health records/Events through the project, own area only without a project, Projects/Companies by own area), for a company Tasks/Events/Files/Health records through its projects with the own company only for an event or file without a project, for a project the recordings set on it or on its events, for an area the Threads database through the thread's project. relatedContributors.ts is the empty contributor registry (registerRelatedRowContributor). Rows are ordered by the record type's relatedOrder (omit keys skipped), then other system databases by display order, then user-created databases by name; archived, empty, internal (system, not client-visible, other than Threads) databases are left out, and for an agent the databases its project may not read are omitted and a read of a record in an unreadable database is forbidden. Unknown, trashed and other-tenant ids answer null, mapped to the item not-found. CollectionMetadataResolver gained two optional methods (relatedOrder, areaFilter) that createCollectionMetadataResolver implements.

Deviations declared by the worker: (1) Spec seam, route matrix: the route entry is in routeMatrix/items.ts (name 'list related collections'), with its ROUTE_CASES case and owner probe in tenantIsolationRoutes.test.ts and its ROUTE_HANDLER_FILES mapping in chokePointWriteBoundary.unit.test.ts. (2) The Task lists no resolver change, but the application service gets manifest data only through CollectionMetadataResolver, so it gained two optional methods relatedOrder and areaFilter (collectionMetadata.ts, not in Touches); a resolver that omits them declares no related order and no area filter, so the ~35 test doubles of the resolver stay unchanged. (4) 'Internal and system-process databases' is implemented as: a system database whose resolved metadata is not client-visible, with the Threads database exempt, because the mail manifest does not make Threads client-visible but the related orders and Task step 5 require its row. (5) The Threads database already exists in the seeded schema (project, company, tasks relation properties), so Task step 5 is implemented against it; its area row uses the fixed path thread.project -> project.area because the manifests declare no area filter for Threads. (6) A relation that the viewed record's database holds with no property on the other database (a one-way relation read from its origin side, e.g. an Email's sender person) gives no row, because no filter of the other database could select the counted records and the issue requires count == number selected by the filter. (8) A person's recordings count both Transcripts.speakers (one-way) and Transcripts.people, because Task step 3 counts every relation. (9) Recordings of a project: the filter is transcripts with the project set or whose event has the project (via direct). (10) The area filters are expanded and counted at read time without the extra probe compile of resolveDatabaseAreaFilters; a broken declaration surfaces as the 400 the query use gives (gh-1597 handover). (11) The Task says 'output schemas in schemas.ts': outputs are TypeScript types in rows.ts/port.ts in this catalog, so there is no zod output schema. (12) Direct rows of a database named in a route are replaced by the route's count; a route with zero records removes the direct row (a file with an own area but a project of another area is not in the area). (13) Contributor rows replace the generic row of the same database.
