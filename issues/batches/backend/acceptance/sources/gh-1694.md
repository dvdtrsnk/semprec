- Both first-round reviewers, for the controller and the owner to confirm: the box and its count require a counted message outside Junk and Trash, as the flagged box does. This follows Task step 3 ("the same visibility rule as the other boxes") and the decision of gh-1633 that a thread only in Junk or Trash never appears without a `folderId`. Read literally, the second acceptance criterion would also list a Junk-only or Trash-only thread that has an agent draft. The behaviour has its own test (row 3 below). This receipt records the reading; it does not confirm it for the owner.
- Fixer and recheck, for gh-1941 or gh-1902, or for the merge code of gh-1493 and the storage of gh-1504: `reassignThread` does not re-point `mail_drafts.thread_id`. After a merge of two threads that each hold an unsent agent draft the surviving thread logically has two, and `mail_drafts_one_unsent_agent_per_thread_uq` does not stop a new agent draft for the survivor when the existing one names the merged-away id.
- Worker, not checked against the specifications of gh-1902 and gh-1941: that partial unique index does not look at the item's `deleted_at`, so a soft-deleted, unsent agent draft still occupies the one-per-thread slot.
- Rules reviewer: no production code creates an agent draft at this commit (gh-1941 is open), so nothing outside the tests reaches the true branch yet.
- Fixer and recheck: no query plan was measured for the new predicate. From reading, the recheck expects one alias index probe and one draft probe per alias for each thread.
