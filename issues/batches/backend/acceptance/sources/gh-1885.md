## Specification

The record is `issues/items/gh-1885.md`. Worker summary: migration adds the nullable `semp_messages.changes`; a pure projector over the paired tool calls with a mapping table keyed by generic operation (`item.create` created, `item.patch` updated with `before`, `item.delete` deleted, `item.restore` restored, `relation.put` and `relation.delete` updated on `callerItemId`); failed, approval-pending and unfinished calls make no entry; several changes of one item are merged; the database of an entry is the one the item is found in under the tenant scope; `before` is dropped for a redacted result, a sensitive database or an unplaceable database; `changes` is written in the same `UPDATE` as the status and is `[]` for a finished turn that changed nothing. The review fix keeps the id of a created item in the redacted result (`details.createdItemId`, new ADR `2026-11-13-a-redacted-create-result-keeps-the-id-of-the-item-it-created`) and names the calling item of a relation call as the target of its events.

Deviations and spec seams declared by the worker: (1) the `inbox.proposal.revise` to `revised` mapping is not implemented, because the tool belongs to gh-1906 (open, absent from the tree); (2) the original deviation that an `item.create` in a sensitive database makes no entry was removed by the review fix; (3) the database of an entry comes from the tenant-scoped lookup, never from the result text; (4) relation operations are resolved through `callerItemId` and `relationPropertyId` and a new batch lookup `listPropertiesByIds`; (5) merge rule where the Task is silent: an item the reply created stays `created` and has no `before` unless later deleted.
