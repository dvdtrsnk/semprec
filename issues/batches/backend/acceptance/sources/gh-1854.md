## Specification

The record is `issues/items/gh-1854.md`. Worker summary: search/sempThreadSearch.ts (searchSempThreads) is registered as the chat contributor of searchItemGroups. A person's search returns a chat group of the tenant's chat and Inbox item threads whose title or preview window (first 140 code points of the last message with text) matches the shared combined lemma-or-prefix tsquery, newest activity first, with the real total, perGroupLimit, thread-list-format cursor for scope [chat], title resolved in users.locale, date and time parts of last activity in the system time zone, snippet null. New SearchItemGroupsInput.humanActor (default deny) is set by the application service for REST sessions not acting for an agent; agent runs and MCP sessions get no chat group. Title text is capped at 1000 code points before vectorising.

Deviations declared by the worker: (1) spec seam: Touches lists only sempThreadSearch.ts and searchItemsQuery.ts, but the human-actor rule needed the actor kind inside the data function, so genericApplicationService.ts passes a new optional humanActor, with a gateway test and a comment-only correction in shared/genericOperations/schemas.ts; (2) the thread list also matches message text (#1783) with ILIKE substrings, the Task's own text (title or preview, combined lemma-or-prefix query) was followed; (3) "hidden thread" is read as tick thread; (4) the cursor of scope [chat] is the thread-list cursor; (5) not exported from the data barrel; (6) the title text is capped at 1000 code points before vectorising; (7) Hunspell assets are unavailable on this host (czech falls back to simple), so lemma matching was not exercised.
