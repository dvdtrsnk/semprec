## Specification

The record is `issues/items/gh-1774.md`. No decision record exists. Worker summary: `calendar/icalendarWriter.ts` serializes iTIP REQUEST and CANCEL; `calendar/eventInvitationJob.ts` holds the payload schema, `enqueueEventInvitation` (commit-coupled, job key `event-invitation:<eventId>:<personId>:<method>:<sequence>`), the Event snapshot for CANCEL and the handler of the task `calendarSendEventInvitation` (the message built with `buildOutgoingMime`, sent through the transport of the mailbox's sync mode, then `invitation.sentAt` written on the participant edge as the system writer under the Event row lock); `calendar/eventInvitationHooks.ts` registers an Events update hook (changed `icalSequence`, REQUEST for each sent, not declined invitation) and an Events delete hook (CANCEL with a snapshot), with no restore hook; the task is declared in the calendar manifest `taskNames` (queue affinity `api`) and `createApiQueueRuntime` binds the mail transports before the runner starts and unbinds them on stop or a failed start.

Deviations and spec seams declared by the worker: (1) a module task handler receives only `(payload, helpers)`, so the pool and mail transports reach it through a per-process binding (`setEventInvitationDelivery`), recorded in the ADR `2026-11-12-module-queue-tasks-read-their-composition-root-dependencies-from-a-binding`; (2) the Task's payload has no sequence, so `enqueueEventInvitation` takes one for a REQUEST only to build the job key and the handler sends the live sequence; (3) a recipient the server refused also ends the job with a reason code (beyond the Task's permanent list), and so, after the last fix, does a `sentAt` refusal that retrying cannot change; (4) subject and body come from new catalog keys `calendar.invitation.*` in cs and en; (5) the delete hook throws `validation_failed` for an Event without a UID or readable date; (6) an Event with `timeFrom` and no `timeTo` ends at the midnight ending its last day; (7) the enqueue on invite and on removal of one person is gh-1790 (Out of scope), applying replies is gh-1950, so the first REQUEST has no production producer yet; (8) the Task names no ADR, one was added for (1). The fix rounds replaced the first version's swallowed `sentAt` failure with bounded retries and a rethrow, and added `MailTransportUnavailableError` (`mail/providerTypes.ts`).

Findings and dispositions:

- Medium (requirements): a mailbox with no usable transport (Gmail or Graph without an OAuth client, a missing stored SMTP credential, an unknown sync mode) was retried instead of ending with a reason code. Fixed in `80563519d`: `MailTransportUnavailableError` thrown by `createMailTransportFactory`, mapped with `ValidationError` to the reason `noTransport`; tests with the real factory for a Gmail REQUEST and a Graph CANCEL, a plain factory error still rethrows.
- Medium (rules): a failed `sentAt` write after a sent REQUEST was swallowed and the job reported success, so later Event changes skipped that person. Fixed in `80563519d`: the write is retried twice (200 ms, 1 s) with each failure logged, then rethrown so the queue retries; a trashed Event during the send returns false instead of failing.
- Medium (rules): `sentAt` was written without checking the Event was still at the sent sequence, so a change during the send was never followed by an updated REQUEST. Fixed in `80563519d`: under the Event row lock the same transaction queues a REQUEST at the current sequence when it is higher (not for a declined invitation, a trashed Event, or an edge that already had `sentAt`).
- Medium (recheck of round 1): a deterministic refusal of the `sentAt` write (a trashed Person, an archived database) was rethrown, so every queue retry sent the invitation again. Fixed in `74c0a12f5`: a `ValidationError` or `NotFoundError` from the edge write is logged and answered as "nothing to mark"; other errors are retried and rethrown; test "ends the job with one message and a logged reason when the Person is trashed while the message was on its way".
