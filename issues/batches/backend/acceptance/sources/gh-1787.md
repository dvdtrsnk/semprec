## Specification

The record is `issues/items/gh-1787.md` on the integration tip; `issues.mjs complete` accepted it against its file hash `86109df81e9d83ba9745220275f4d7c275e43b6685353304df88eff7ce3992f7`. No decision record exists for this source.

**Spec seam on the Task, for the controller.** Task step 1 says the function uses "the source recorded on the request by #1766". gh-1766 records nothing on the request; it derives the source from the run when a request is read. The source therefore adds `getApprovalRequestSourceKind(client, agentRunId)` in `backend/packages/data/src/mcp/approvalRequestsQueue.ts`, a file outside `Touches`, and both producers call it inside the transaction that creates the request. All three reviewers confirmed the seam in the code and did not rate it a defect.

**Spec seam on the kind of a run without a thread, for the controller and the owner.** By the rule of gh-1766 a run without a thread whose root run a person or a supervisor started is `chat`. Its notification therefore links to the Semp chats page although no thread holds the request. This is the open seam of point 6 of the gh-1766 handover, not a new rule of this source. The existing producer tests use such runs and now expect the chat link.

**Open before release, from the record's Decision.** The page names `semp-chats` and `inbox` and the parameters `tab` and `approvalRequestId` must be confirmed with the clients. Nobody did that; the scope of this source is backend only.
