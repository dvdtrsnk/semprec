## Specification

The record is `issues/items/gh-1799.md`. No decision record exists for this source. Worker summary: added `keepWakeDaysInOnePlan` to `sleep/sleepWriteHooks.ts`, registered as create and update hook in `domainWriteHooks.ts` after the gh-1784 validation hooks. After a plan write with non-empty merged `wakeDays`, the other live plans of the database holding any of the days are selected `FOR UPDATE` ordered by id in a repeated statement and lose the days through `updateItemWithClient` without `ifVersion`; a plan keeps `wakeDays` `[]` when it loses all. A `40P01` raised by that select is rethrown as `ConflictError` (409); other errors pass through. A per-client `WeakSet` makes the nested removal skip the hook. An ADR records the lock and deadlock contract.

Deviations and spec seams declared by the worker: (1) the Context says there is no pre-write hook before the row lock, but the ADR `2026-11-12-an-update-takes-the-module-locks-before-it-locks-the-row` added a pre-lock registry since; the Task prescribes row locks and a `40P01` to 409 mapping, so the registry is not used. (2) The loop ends after two consecutive empty statements, not one (the single-empty variant fails the deterministic concurrency test). (3) A per-client guard so the nested removal does not cascade. (4) Nested removals use the system writer. (5) New ADR `2026-11-12-a-sleep-plan-takes-its-wake-days-from-the-other-plans-under-row-locks` and a test outside Touches, `services/semprec-api/src/__tests__/sleepWritePaths.test.ts`. (6) Known limit: two transactions putting the same free day into two plans are not serialized. (7) gh-1795 was noted as not landed; it is landed on the integration tip.
