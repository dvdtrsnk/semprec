## Specification

The record is `issues/items/sp-1272c2b9-82dd-4fde-b6ef-103f53945435.md`. Worker summary: new `ensureMailAccountSyncStateOfLiveMailbox` in `mail/mailAccountSyncStateStore.ts` returns an existing row with no lock, otherwise runs `SELECT id FROM items ... deleted_at IS NULL FOR SHARE SKIP LOCKED` and then `ensureMailAccountSyncState`, or returns `null` having written nothing; `discoverActiveAccounts` calls it with the page's Mailboxes database id and leaves a `null` result out without `onLifecycleError`. A new ADR records the decision. Worker deviation: the Task says discovery "cannot be part of a cycle"; the item lock statement never waits, but the insert can wait for another transaction's uncommitted insert of the same `item_id`, and `replaceMailboxCredential` inserts a missing row before it locks the item, so in that one interleaving discovery and a reauthorization can deadlock until Postgres aborts one statement. The ADR states this and the code was not changed (the Task fixes the design and puts the connect flows out of scope). Seam: the issue names an existing pool wrapper that intercepts `SAVEPOINT discover_account`; none existed, so the worker wrote a new one in the test.
