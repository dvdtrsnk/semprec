## Specification

The record is `issues/items/gh-1889.md`. Worker summary: `GET /api/agent-runs/:id` and `/steps` take an optional `messageId` (one UUID, else 400 naming the field); `resolveAgentRunReply` loads the assistant message in the caller's tenant (404 for another run, another tenant, a user message or an unknown id) and resolves a retried reply to its latest attempt; the detail of a session run then carries the reply's title, start, stored duration, approvals, usage and a display status from the reply's own outcome; the steps are read inside the reply's event range with unchanged cursor and pairing rules and `truncatedHistory` when the reply's first event is gone; a heartbeat run answers the whole run.

## Deviations

(1) No attempt column on `semp_messages` (gh-1926 not landed): "latest attempt" is the newest assistant message of the run and thread with the same `reply_to_message_id`. (2) A reply with no stored `event_to_id` ends before the first event of the next reply, or at the end of the run. (3) Approval attribution is the union of `tool_use` events in the reply's range and the `toolCallId` of the stored steps; a request without a tool call id belongs to no reply. (4) A heartbeat run ignores the scope once the message is verified. (5) The resolver lives in `agentRunDetail.ts`; the barrel line became `export *` because `index.ts` is at the 900-line lint cap. (6) Files outside Touches: `agentRunReplyFixtures.ts`, `agentRunHandler.unit.test.ts`, `agentRunEventsStore.test.ts`, `agentRunUsage.test.ts`, `publicSurface.test.ts`, the agentRuns i18n catalogs, `agentRunStepProjection.ts`, `aiGateway/agentRunUsage.ts`, `testSupport/testDb.ts`.
