## Deviations

Spec seams: (1) the DTO builder and the discard are in mail/draft.ts, not mailDraftRouteHandlers.ts, so the attachment list and the discard cleanup are wired there; the two new handlers are in mailDraftRouteHandlers.ts. (2) To avoid an import cycle with draft.ts the queries and the discard cleanup are in the extra module mail/mailDraftAttachmentFiles.ts, and the attach and detach operations in mail/mailDraftAttachments.ts (Touches). (3) Route entries are in routeMatrix/mail.ts. (4) The generic mailbox limit MAX_FILE_SIZE_MB reaches the data package through the custom-route container: customRouteMount.ts gained maxFileSizeBytes and createDispatcher in app.ts sets it from its maxFileSizeBytes option (not in Touches). (5) MailAttachmentTooLargeError lives in draft.ts next to the other draft errors and is exported from index.ts by adding it to an existing export statement; index.ts is at the 900-line cap and the new route handlers are exported through the existing export * of mailDraftRouteHandlers.js. publicSurface.test.ts lists the three new names. (6) Interpretations: a megabyte is 1024*1024 bytes; a file 'attached nowhere else' is a file with no relation edge to any item other than the draft (nothing records where a Files item came from, and no migration is allowed), recorded in the new ADR docs/adr/2026-11-14-a-mail-draft-attaches-copies-of-held-files-and-trashes-the-files-that-are-its-own.md; the POST answers 200 with the draft view; detach leaves the Files item and attaching a file already on the draft is an idempotent no-op; the HTTP test mailDraftAttachmentsHttp.test.ts was added in semprec-api to cover the composition wiring and the 413 mapping.
