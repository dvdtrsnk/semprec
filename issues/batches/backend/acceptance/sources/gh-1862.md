## Specification

The record is `issues/items/gh-1862.md`. No decision record exists. Worker summary: an approval step carries `approvalState` (pending, executing, executed, failed, conflict, rejected) and, for a conflict, `conflictReason`, computed at read time by `approvalStepState` from the request rows read in one batched query per page (`listApprovalRequestStatesByIds`, no payload). Step state is waitingApproval while pending, error for failed and conflict, ok otherwise; an unreadable request leaves the step with its call's state and no approvalState. The failed versus conflict split uses `approvalConflictReason` from gh-1437.

Deviations and spec seams declared by the worker: (1) the two fields are omitted from the JSON when absent; (2) the decision wins over the execution status (a cutover-rejected `legacy_terminal` request reads rejected; a pending request is pending); (3) an approved request with execution_status not_approved gives no approvalState; (4) `listApprovalRequestStatesByIds` is not exported from the barrel; (5) "cannot be read" means not found, other tenant or non-uuid id, and a corrupt status value still throws; (6) the summary of an approval step is computed from the call's own state. The review fix exports `recordApprovalRequestOutcome` from the barrel and adds it to the frozen export list.
