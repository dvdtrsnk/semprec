## Specification

The record is `issues/items/gh-1825.md`. No decision record exists for this source. Worker summary: resolveEditorSchema(registry, baseKind, locale) in inbox/editorSchema.ts finds the declaration through getEditorSchemas(), reads the declaring module's catalogs through the registry (getCatalogs) and returns { baseKind, groups: [{ key, fields: [{ key, control, inputType?, label, placeholder?, required?, when?, timeHiddenWhen?, optionsSource?, options?, info? }] }] } in the caller's locale with English fallback and the catalog key as the last fallback; info rows are rendered from infoKey and params. createInboxCardsRouteHandler adds editorSchema (null when undeclared) to every card, resolved once per base kind per request from a process-wide full module registry (shared with the existing catalog resolver). The ten system databases declare editor schemas for task, event, project, area, company, person, file, health, journal and page in the new seed/systemDatabasesEditorSchemas.ts, wired as editorSchemas of the systemDatabases manifest, with 47 Czech and English label and placeholder entries in seed/i18n/cs.json and en.json.

Deviations and spec seams declared by the worker: (1) The declarations are in a new sibling module seed/systemDatabasesEditorSchemas.ts (not inline in systemDatabasesModuleManifest.ts) to keep the manifest small; the manifest gets one import and one editorSchemas line. (2) Catalogs are read through registry.getCatalogs(moduleId), which wraps loadModuleCatalogs and caches per module in the registry, instead of calling loadModuleCatalogs directly. (3) The resolved field also passes through the declared static options of a seg control (the MCP card declares transport options; the page card declares placement start and end); the Task's shape lists no options. Options are not translated (out of scope). (4) Decisions where the Task left room: control choices (task status, health status, person contact, file type are select; event type, project status are seg; the file field is a tile; Markdown fields are the area control, which is the text area; the pseudo key markdown is added for the journal and page content); the allDay toggle is also declared on events, because timeHiddenWhen names it; People declares only contact, the per-contact phone and email fields wait for separate value fields as the Task says; Tasks has no area property, so the area field is a select with optionsSource area and a pseudo key; page placement offers start and end only. (5) The test file for the resolver is editorSchema.unit.test.ts (unit tier, no database) instead of editorSchema.test.ts of the Touches list. (6) inboxRouteHandlers.ts now keeps one process-wide module registry (getModuleRegistry) that the existing catalog resolver is also built from.
