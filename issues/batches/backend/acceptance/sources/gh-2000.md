## Specification

The record is `issues/items/gh-2000.md` (model tier high). Worker summary: the filter compiler refuses with `ForbiddenError` (403) any condition on a relation into, or a rollup over, a sensitive database the agent's project has no access to (all relation operators, both hops of a path, every rollup operator, nested under and/or/not); a sort or a view's stored sort or groupBy by such a rollup is refused; rollups over a closed database are read by an agent as `{ value: null, hidden: true }`; wired for `database.query`, `view.query`, the choke point `listItems` and `item.count`; the fix round added `item.count` groupBy by a relation into a closed database, `database.facets` and the write responses of an agent. A new ADR documents the decision.

Deviations and spec seams declared by the worker: (1) the compiler is synchronous, so the closed set is resolved in the choke point and passed in; the sort refusal is in `views/viewQuery.ts`; (2) several files outside the Touches list (listed in the handover); (3) "sensitive and not readable" is read literally, so a user-created non-sensitive database with a `none` grant is not closed; (4) the rule applies to an agent's project only, an external AI client and a person are unchanged; (5) `item.count` does not access-check the counted database itself; (6) a stored view whose own filter or sort reaches a closed database is refused to the agent; (7) the ADR lists as not covered the count and facets of a closed database itself, search and related items, and the non-service `chokePoint.queryView`.
