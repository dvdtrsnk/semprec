## Specification

Worker summary: Every card with status invalid carries invalidReason { code, field, itemId, label, text } in inboxCardsStore.ts: the stored reason is parsed with invalidReasonSchema (gh-1482) and text is renderInvalidReason in the locale of the list (English fallback). A card with no stored reason, or one that does not parse, carries { code: unknown, field: '', itemId: null, label: '', text } with the generic sentence from the new catalog entry invalidReason.unknown (en and cs). Cards in other statuses, approvals and transcript cards have no invalidReason key.

Deviations and spec seams declared by the worker: (1) invalidReason.ts is outside Touches: the parameter type of renderInvalidReason is widened to accept the code unknown so the generic sentence goes through the same function. (2) A stored reason that does not parse is treated like a missing one (unknown) so the card stays in the list; the Task names only the missing case. (3) The new field is optional on the InboxCard type and absent, not null, on other cards.
