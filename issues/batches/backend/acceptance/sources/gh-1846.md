## Specification

The record is `issues/items/gh-1846.md`. Worker summary: Added heartbeat.create, heartbeat.update and heartbeat.setEnabled to the schemaCore manifest with requiresApproval and a snapshotExport each. Handlers and snapshots are in the new scheduler/heartbeatWriteAgentTools.ts; the run scope helpers moved unchanged to scheduler/heartbeatRunScope.ts (plus findHeartbeatInScope and findLiveProject); the per-tool approval description is built by scheduler/heartbeatApprovalDescription.ts and used by createModuleToolApprovalRequest. Create writes origin user, action core.agentRun, action_config.task, in a live Projects item inside the run's scope. Update and setEnabled lock the row, require it inside the run's heartbeat scope and origin user, and apply in one transaction. The snapshot hashes name, rule, action_config and enabled (create: the project's existence); execution is exactly once through the gh-1791 claim. After commit projectAgent (once) and, when the heartbeat has a tick thread, sempThread are announced. Added findTickThread to sempTickThreadStore, templates in notifications/i18n and seed/i18n, labels in chokePoint/i18n.

Deviations and spec seams declared by the worker: (1) the factories are in the sibling `heartbeatWriteAgentTools.ts`, not `heartbeatAgentTools.ts`; (2) `schedulerStore.ts` needed only `isProjectReachableByChatRun` and the update tool announces `projectAgent` itself for a name or task alone; (3) the approval description is built in `createModuleToolApprovalRequest`, outside Touches, and the templates are also in `notifications/i18n`; (4) the scope follows the read scope of the heartbeat tools (project run: own project only; chat run: every project minus the sensitive exclusion), stricter than the literal text for non-chat runs; (5) a refused snapshot creates no approval request and the session reports 'Module tool failed.'; (6) `heartbeat.create` has a snapshot of the project's existence; (7) `sempThread` is announced only when a tick thread exists; (8) the original description left out the task text, which the review fix added; (9) existing tests brought in line (`coreModuleManifests.unit.test.ts`, `publicSurface.test.ts`); two ADRs were added by the fix round.
