## Specification

The record is `issues/items/gh-1835.md`. Worker summary: PUT /api/sleep/nights/:night (sleepNightPut in sleepRouteHandlers.ts, declared in the sleep manifest as transactional-semantics). The date and the strict body { bedTime?, wakeTime?, alarm? } are validated before any read (400 validation_failed naming night or the key). In one transaction it takes the per-night advisory lock (lockSleepNight, extracted from assertNightIsFree with the same key and statement), locks the non-deleted night exception FOR UPDATE, creates it with createItemWithClient when absent and a provided field is non-null, patches the differing fields with updateItemWithClient without ifVersion, or writes nothing, then answers { night } from loadSleepNights for that date (null when neither plan nor exception applies). Route matrix entry, ROUTE_HANDLER_FILES mapping and a tenant isolation case added.

Deviations and spec seams declared by the worker: 1. The Task calls sleepNightPut the handler; it is the factory (pool) => handler that customRouteMount.ts requires, as for sleepNightsGet. 2. Spec seam: the route entry is in the slice routeMatrix/sleep.ts (name 'sleep night put'), with its ROUTE_HANDLER_FILES mapping and ROUTE_CASES case. 3. The lock key of #1784 was extracted into the exported lockSleepNight in sleepWriteHooks.ts (statement text unchanged, no test keys on it) so the hooks and the route share one definition; sleepWriteHooks.ts is not in Touches. 4. The answer is read with loadSleepNights at READ COMMITTED, not REPEATABLE READ: a snapshot taken before the advisory lock could not see an exception another PUT committed meanwhile. The docstrings of both functions say so. 5. A create stores the provided fields, null ones included (Task: 'night plus the provided fields'); a patch carries only the fields that differ. 6. A time is normalized before it is compared and stored (6:45 is 06:45); an empty string and 24:00 are refused. 7. Tests outside Touches: sleepModuleManifest.unit.test.ts (custom route list) and the new file sleepNightPut.test.ts. 8. #1828 (Shared-file ordering blocker) is open; it was not needed.
