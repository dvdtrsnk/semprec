## Specification

The record is `issues/items/gh-1905.md`. Worker summary: Events gain the system-owned, locked date property nextOccurrenceDate (seed, cs/en label, cutover). computeNextOccurrenceDate gives the first rule day on or after today in the tenant zone, else the last occurrence, else the Event's own date. A pre-write transform registered under the events module computes it on create and when date, endDate or recurrence is in an update (with a preparation for proposals). The daily heartbeat action calendar.refreshNextOccurrence (validated action_config, batches of 200 locked rows, paged by id, system writer through updateItemWithClient) moves stale values on; it is seeded in seedCalendarsInTransaction, listed in the calendar manifest heartbeatActions, in KNOWN_HEARTBEAT_ACTION_IDS and registered in the api action registry. The cutover inserts the definition by direct SQL, backfills every Event in batches of 500 without moving updated_at, and creates the heartbeat. ADR 2026-11-14 records the decision.
