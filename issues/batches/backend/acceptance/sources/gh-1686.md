Observations recorded without a finding, none of them changed:

- Requirements reviewer: `mail_admin_consent_required` is produced only when the token endpoint reports administrator consent. The callback passes a bare `providerError` on and drops `error_description`, so on that path the app cannot tell administrator consent from a cancelled consent. This matches the Task.
- Requirements and rules reviewers: a soft-deleted mailbox keeps its `mail_account_sync_state` row, so reconnecting its account answers 409 naming a mailbox in the trash until #1690 and #2031 land. Once #1690 deletes sync state, `details.mailboxId` of the 409 can be `null`.
- Requirements and rules reviewers: `serve.ts` sets no `outboundHttp`, so production uses the global `fetch` against fixed provider URLs.
- Security reviewer, design point fixed by the issue's Decision: the callback shows `{ state, code }` to whichever browser arrives. A later app hand-off must forward the result only to the signed-in user's own complete call, which the user binding of the state then enforces.
- Security reviewer: the Microsoft address can be set freely by an Entra tenant administrator; it labels and de-duplicates a mailbox inside the caller's own tenant only and feeds no cross-tenant key.
- Recheck: a fallback to plain `GET /me` when the `$select` request fails would remove the dependency on the undocumented personal-account behaviour.
