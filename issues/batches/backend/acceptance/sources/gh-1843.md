## Specification

The record is `issues/items/gh-1843.md`. Worker summary: POST /api/events/series/:seriesId/occurrences/:date (systemDatabases customRoute materializeEventOccurrence, transactional-semantics) turns one occurrence of a recurring Event into an Events item, or returns the item that already stands for it (201 created, 200 afterwards, a trashed item is returned and not recreated). formatOccurrenceId/parseOccurrenceId; materializeEventOccurrence(client, {seriesId, occurrenceDate, options}) takes a tenant-scoped advisory lock keyed by tenant, series and date, looks up an existing occurrence item (live or trashed), locks and reads the series Event (404 for unknown, foreign, trashed or non-series), checks eventRecurrenceOccursOn (400 validation_failed on date), creates the copy through createEventInCalendar (or createItemWithClient when the series has no calendar edge) with the system-owned seriesId and occurrenceDate, and copies the edges (invitations dropped). The Events database gets the system-owned properties seriesId (text) and occurrenceDate (date), owner process calendar, in the seed and through a cutover for existing tenants. ADR 2026-11-13-an-event-occurrence-is-an-events-item-named-by-its-series-event-and-date records series identity, ownership and the lock.

Deviations declared by the worker: 1. Spec seam: the Task says an occurrence item is 'an Events item with seriesId and occurrenceDate' but no earlier source gives Events those properties (the ADR of gh-1817 leaves them to the materialization). They are added here: system-owned properties seriesId (text) and occurrenceDate (date), owner process calendar, declared in seedTenDatabases.ts, labels in seed/i18n cs.json and en.json, and a cutover calendar/eventsOccurrenceCutoverMigration.ts registered after the gh-1817 recurrence step and before the area-note step. None of these files is in the Touches list. 2. The Event series has no row of its own, so seriesId of an Event series is the id of the series Event (recorded in the new ADR). 3. Route entry is in routeMatrix/events.ts (slice seam), not routeMatrix.ts. 4. The helpers of duplicateCalendarItem.ts are exported (EVENT_PROPERTY_KEYS, EVENT_CALENDAR_RELATION_KEY, liveEdgesOf, copiedProperties, copiedEndDate, copyEventEdges); copiedEndDate now takes (source, copyDate, requestedEndDate) and the Event edge copy of duplicateCalendarItem moved into the exported copyEventEdges with no change of behaviour (duplicateCalendarItem.test.ts passes). copyEdges' userId accepts undefined so a system writer can copy. 5. A non-UUID series id is 400 on seriesId (as the Tasks occurrence route does), not 404. 6. An Event with a stored recurrence that is not a rule, or an Event that already has a seriesId (an occurrence item with a rule patched onto it), is 'not a recurring Event' and answers 404. 7. The advisory lock key includes the tenant so a foreign request never waits on another tenant's work; the series row is then locked FOR UPDATE. 8. New ADR 2026-11-13-an-event-occurrence-is-an-events-item-named-by-its-series-event-and-date.md (series identity, ownership of the two properties, advisory lock).
