## Specification

The record is `issues/items/gh-1880.md`. Worker summary: The core Tasks source selects and places a Task by taskDisplayDay (item date = display day), drops a Task whose stored hiddenUntil is later than the read instant and a Task with a completedInEvent edge. A new step attachTaskInEventState (calendar/timelineTaskInEvent.ts) runs after the sources: Event entries (stored, real and virtual occurrences) get tasks and counts from the new batched readEventsTasks, Task entries get hostEvent {id,title,ended,date,timeFrom,timeTo,state}. Compact shape carries counts only. New ADR.

Deviations declared by the worker: (1) readEventTasks/eventTaskCounts of gh-1801 are single-event or counts-only, so the Task's 'batched reader' did not exist for tasks per event: taskStateInEvent.ts exports a new readEventsTasks(client, eventIds, now) (buildEventTasks takes now as a parameter; eventTaskCounts and readEventTasks use it, behaviour unchanged); file is outside Touches. (2) CalendarTimelineContext gets a required field at: Date (the read instant) so hiddenUntil and ended compare with the same instant as today/now; the one test that builds a context by hand (eventOccurrences.test.ts) and the context assertion in timelineRead.test.ts were updated. (3) New sibling module calendar/timelineTaskInEvent.ts (post-sources step, needed because Events come from two sources); readCalendarTimeline calls it, which the 2026-11-10 ADR decision 2 ('does not change the merge') did not foresee: documented in the new ADR docs/adr/2026-11-13-the-timeline-adds-task-in-event-state-after-its-sources-are-read.md. (4) Interpretations: Task 'compact shape' gets counts only (null for a Task), no tasks/hostEvent; hostEvent is the last live host event that has a date (the one computeTaskHostState takes its day from); an Event or Task entry a source made up (readOnly, no occurrence) is left unchanged; a virtual occurrence carries the tasks of its series Event, a real occurrence those of its own item; a Task item keeps its own timeFrom/timeTo while its date is the display day; an unreadable display day is logged with property date; a hiddenUntil that is not an instant does not hide. (5) New fields hostEvent/tasks/counts are on every stored item (null for non-applicable) so the agenda route, which returns timeline items, now carries them too. (6) Existing tests adapted to deliberate behaviour: timelineRead.test.ts (done tasks are completed on the test day via a fake clock because a done task is now shown on completedOn; strict item schema and expected items gain the three fields; compact expectation gains counts; a 'tasks date abc' case also stores effectiveDate abc since effectiveDate now outranks date), timelineRoute.test.ts (strict schemas), eventOccurrences.test.ts (compact counts), journalDayEvents.test.ts (statement-count test: the day compared with the birthday day also holds an Event, since a day with Events sends one more statement than a day without any).
