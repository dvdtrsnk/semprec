## Specification

The record is `issues/items/gh-1855.md`. Worker summary: `GET /api/trash/items` skips a Pages item whose `parentItemId` names an item (page or host) with the same `deleted_at`, in the shared `ROOTS_WHERE` so rows, paging cursor and `totalCount` stay consistent. Rows of the Pages database get `page: { title, path }`, the path being `[{ itemId, title, trashed }]` from the host to the parent, read in one recursive statement per page of results (trashed ancestors included, visited-set guard, title from the database's title-typed property) in the same REPEATABLE READ snapshot. After review the walk is bounded at `MAX_SUBPAGE_CHAIN` (1000), cutting at the root end.
