## Specification

Worker summary: `heartbeat.list` and `heartbeat.history` resolve a read scope (`resolveHeartbeatReadScope`) from the persisted `agent_runs.thread_id`; a run of a Semp thread of kind `chat` (delegated runs inherit the thread) reads the heartbeats of every project of the tenant minus projects holding a read/write grant on a sensitive database that the run's project lacks; tenant-scope list entries carry `projectItemId` and `projectName`; history in tenant scope is one scoped query so unknown, foreign-tenant and excluded ids give the same not-found error; `heartbeat.trigger` is unchanged. Deviations and spec seams declared by the worker: "holds a grant" is a stored `agent_database_grants` row with access `read` or `write` (a `none` row is no grant on either side); the tenant-wide queries are in `schedulerStore.ts` as the Touches line says; project names are read through `getItemsByIds`; fixture raw SQL is limited to one item-kind `semp_threads` insert (the run-finishing UPDATE was replaced by `finishAgentRun` in the fix round). No spec seam moved.
