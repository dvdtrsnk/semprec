## Specification

The record is `issues/items/gh-1780.md`. No decision record exists for this source.

Deviations and spec seams the worker declared:

1. The systemDatabases manifest version is already 1.5.0, above the 1.3.0 the Task names; it is not lowered, and the transition 1.2.0 to 1.3.0 is added (precedent gh-1657).
2. `firstPlannedDay(stored, today)` is extracted unchanged from `taskSinceRule`, because the gh-1602 rule needs a patch naming a different date.
3. `backfillTaskEffectiveDate` treats an empty-string date like no date.
4. Existing tests brought in line with the new stored values: `tasksDayRollover.test.ts`, `taskHostEventRoutes.test.ts`, `taskHostEventOccurrenceRoutes.test.ts`, `normalizeTaskDatesAndTimes.test.ts`.
5. The transform reads host events only for a write naming `date`; a create reads none.
6. The worker's commit trailer used the system attribution instead of the Fable line.
7. Known limitation recorded in ADR `2026-11-12-task-host-state-is-recomputed-in-the-writing-transaction`: Events are read without a lock, so a concurrent uncommitted Event change can leave the stored state stale until the next trigger; the backfill reads no Event.

New ADR in this segment: `docs/adr/2026-11-12-task-host-state-is-recomputed-in-the-writing-transaction.md`.
