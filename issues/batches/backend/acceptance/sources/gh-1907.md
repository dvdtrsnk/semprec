## Specification

The record is `issues/items/gh-1907.md`. Worker summary: a Semp turn that throws stores status error with `error_code` (closed run error set) and `error_params` {connectorName?, failedStep?, timeoutMs?} in the same UPDATE as the status (`finishSempMessageTurn`). `classifySempTurnFailure` (new `semp/sempReplyErrors.ts`) takes the code from the typed error (`agentRunErrorCodeOf`: budgetExceeded, modelError, cancelled, internal) or the abort signal (cancelled, or interrupted for the shutdown abort), never from text. The handler logs only threadId, assistantMessageId, agentRunId and errorCode. The Semp i18n catalogs (cs/en) gained `reply.failure.*` texts and `renderSempReplyFailure(code, params, locale)`; `listSempThreadMessages` returns `error {code, message}` for a failed reply in the tenant user's locale from the same statement.

Deviations and spec seams declared by the worker: (1) the mapper is `listSempThreadMessages`, there is no `sempMessagesHandler.ts`. (2) `error_code` (0139) and the i18n catalogs already existed; the migration adds only `error_params` and the checks. (3) `incompleteReason` is as delivered by gh-1890; the stored step key is `errorCode`, not `failureKind`. (4) `failedStep` takes the step label. (5) The `interrupted` boolean of `finishSempMessageTurn` was replaced by `errorCode`/`errorParams`; one call in `sempMessageSearch.test.ts` dropped `interrupted: false`. (6) `errorCode` stays optional in the writer; a failed message with NULL code reads `internal`. (7) Commit trailer as above. (8) The MCP timeout criterion is tested with stored events in the production shape, not a live 15 s or 60 s MCP timeout.
