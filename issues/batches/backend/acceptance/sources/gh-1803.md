## Specification

The record is `issues/items/gh-1803.md`. No decision record exists for this source. Worker summary: `calendarItemDeleteHook` and `calendarItemRestoreHook` (`calendar/calendarTrashHooks.ts`), registered in `domainWriteHooks.ts`. Delete refuses a system or subscription calendar (403 `forbidden`) and the last own calendar (409 `last_own_calendar`), hands the default mark to the oldest other live own calendar, and trashes every live Event of the calendar through the choke point with the calendar's exact deletion epoch; restore brings back the Events of that epoch and clears a stale `isDefault`. `ConflictError` takes an optional code. ADR `2026-11-12-deleting-a-calendar-takes-the-default-mark-lock-and-its-events-into-its-epoch`. The review fix added delete and restore pre-lock registries (`chokePoint/hooks.ts`, run in `itemTrash.ts` before the row lock) and Calendars pre-lock hooks that take the default-mark lock first.

Deviations and spec seams declared by the worker (full list in the handover): (1) the choke point refuses to update a trashed row, so the trashed default keeps `isDefault: true` until a restore clears it; (2) the lock-order deadlock risk declared by the worker was removed by the review fix; (3) the successor and the restored calendar are written as the system writer; (4) six existing test places that trashed the default calendar generically now use a raw `UPDATE`; (5) a default calendar trashed before this source with no other default cannot be restored; (6) two extra test files and, by the fix, three choke-point files outside Touches; (7) blocker gh-1799 was not needed.
