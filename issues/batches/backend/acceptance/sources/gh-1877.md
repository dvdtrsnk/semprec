## Specification

The record is `issues/items/gh-1877.md`. Worker summary: expandEventOccurrences(client, eventsDatabaseId, seriesRows, {from, to, timezone}) in calendar/eventOccurrences.ts expands the live recurring series into timeline entries: a virtual entry (id <seriesId>@<date>, readOnly true, overridden false, series details with the occurrence's date/endDate, no transcript) per rule date without an occurrence item, the occurrence item (real id, overridden true) when its own days overlap the range, nothing for a date whose item is in the Trash, at most 100 entries per series (earliest first). readLiveEventSeries batch-loads the series. The new source calendar/timelineEventOccurrenceSource.ts is registered after the sleep source. The core Events source of timelineRead.ts skips an Event that is a recurring series (calendar/eventSeries.ts readEventSeries) or has a seriesId. Entries carry seriesId, occurrenceDate and overridden (type CalendarEventOccurrence); the compact shape of an occurrence carries seriesId and occurrenceDate. ADR 2026-11-13-the-timeline-expands-an-event-series-into-virtual-and-real-occurrences.md.

Deviations declared by the worker: 1. Signature seam: the Task writes expandEventOccurrences(series, from, to); the function needs the database client, the Events database id and the zone, so it is expandEventOccurrences(client, eventsDatabaseId, seriesRows, {from, to, timezone}) with seriesRows from readLiveEventSeries (the batch load named in step 1, kept in eventOccurrences.ts). 2. A real occurrence item is placed by its own days (overlap with the range), not by its rule date, so a moved occurrence is shown where it is, once; recorded in the new ADR. The issue does not say what happens to an item moved out of or into the range. 3. New small module calendar/eventSeries.ts (readEventSeries), shared by the core exclusion, the expansion and the materialization (gh-1843 code now uses it instead of a private function); it is not in Touches. 4. The core Events source skips an Event with a seriesId or a readable rule; an Event whose stored recurrence is not a rule stays a stored Event (otherwise it would vanish from the timeline). 5. timelineRead.ts exports StoredRow, Schedule, effectiveTo and toTimelineItems (context narrowed to {timezone}) for the new modules; CalendarEventOccurrence is added to CalendarTimelineEntry and CalendarTimelineCompactItem gets optional seriesId/occurrenceDate. 6. The Task text 'a range of 93 days returns at most 100 entries': the function does not clamp the range (the route bounds it, per the timeline ADR) and caps entries per series at 100, earliest first. 7. timelineSleepSource.test.ts: the assertion of the whole source list became slice(0, 5) because the list now ends with eventOccurrences (a test that keys on the list). 8. New ADR 2026-11-13-the-timeline-expands-an-event-series-into-virtual-and-real-occurrences.md.
