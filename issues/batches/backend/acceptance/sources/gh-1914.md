## Specification

The record is `issues/items/gh-1914.md`. Worker summary: listProjectAgentRuns now returns for a heartbeat occurrence only its latest attempt (highest attempt, ties by later started_at, then greater id; the order getLatestRunOfOccurrence uses) through a NOT EXISTS probe of agent_runs_occurrence_idx inside the ordered scan of agent_runs_tenant_project_started_idx, before LIMIT, so limit counts rows after the collapse and no sort, window or grouping runs over the project's history. A run with no occurrence id is always a row. New listRunsOfOccurrences reads all attempts of the listed occurrences in one statement. The handler fills attempt from the run's attempt column, sets costUsd of an occurrence row to the sum of all its attempts (rounded to 15 significant digits to drop float noise) and adds attempts: [{ id, attempt, startedAt, durationMs, costUsd, displayStatus }] ascending by attempt, using the same single getAgentRunCosts statement over all rows and attempts and the same display-status derivation per attempt. A row without an occurrence has no attempts key.

## Deviations

1. The row's start is the latest attempt's started_at, and the latest attempt is chosen by the highest attempt, ties by later started_at then greater id, rather than by 'not the retry_of_run_id of any other row': the two agree for a chain and the chosen rule also yields exactly one row when the scheduler's unchained fallback leaves two runs with the same attempt (gh-1458 handover). 2. costUsd of an occurrence is summed in JavaScript and rounded to 15 significant digits so that 0.1 + 0.2 is 0.3. 3. New store function listRunsOfOccurrences (not named in the Task) reads all attempts in one statement; it is exported by the barrel's export * and is listed in publicSurface.test.ts (outside Touches). 4. A row's attempts list includes the displayStatus of each attempt, derived like the row's own; an attempt closed as done reads its reply with one statement, an errored attempt reads none.
