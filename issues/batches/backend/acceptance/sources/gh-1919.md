## Specification

The record is `issues/items/gh-1919.md`. Worker summary: GET /api/semp-status now returns resolvedRecent: [{ id, category, resolutionTitle, resolvedAt }] for the tenant's problems resolved within 7 days, newest first (resolved_at DESC, id DESC), capped at 100, without sourceDeleted resolutions. Titles are rendered at read time by renderResolutionTitle(catalogs, kind, resolutionKind, params, locale) from catalog keys status.resolved.<resolutionKind>.<kind> (cs and en: mail, reply, heartbeat, guidance permission and behavior variants, backup, process, library), with names read in batched queries (items via getItemsByIds, heartbeats, reply thread titles, databases, guidance finding payload kind); an unreadable name becomes the neutral word (unnamed) / (bez názvu), a kind or resolution kind without an entry gets the generic title. Migration 0162 adds the partial index (tenant_id, resolved_at DESC, id DESC) WHERE resolved_at IS NOT NULL.

Deviations declared by the worker: Seams: (1) the status catalogs are semp/i18n/cs.json and en.json, not status.cs.json/status.en.json (loadModuleCatalogs reads one cs.json and en.json per module directory); entries are status.resolved.* . (2) renderResolutionTitle takes the loaded ModuleCatalogs as its first parameter ((catalogs, kind, resolutionKind, params, locale)) because catalogs load asynchronously and are already loaded once per report. (3) The reader and the renderer are sibling modules semp/sempStatusResolved.ts and semp/sempResolutionTitles.ts (the renderer has no Postgres import so it has a unit test); sempStatusReport.ts only calls readSempResolvedRecent. (4) The initial catalog has no entry for agentRun problems; a resolved agentRun (and any unlisted kind) gets the generic title 'A problem was resolved' / 'Problém byl vyřešen' instead of being dropped. (5) The recovery title for reply uses the thread title read through semp_messages; the reply producer does not exist in the tree yet, so its test fixture is a synthetic row like the existing sempStatusReport test. (6) readSempStatusReport (and therefore the summary endpoint) always runs the resolved read; with nothing resolved it costs one statement.
