Deviations declared by the worker: (1) The Task says the item must be a live transcript, while the acceptance criteria and the test list accept a trashed one; the criteria were followed (existing behaviour kept). (2) The Task says 0 <= startsAt <= endsAt; the shared ref schema (issue 1682) and transcript.segment.get both refuse endsAt == startsAt, so the validator refuses a range of no length too. (3) The message-ref machinery has no per-kind hook registry, it is a switch per kind; the kind was registered the way sleepNight is: validateSempMessageRefs, readSempRefContext and resolveSempHistoryContexts call the kind's function. (4) The batched existence statement for segment refs was replaced by one statement per ref in the validator; the statement-count test in sempMessageRefs.test.ts was brought in line (8 to 9 statements, 2 for segment refs). (5) A transcript in the Trash is expanded with state trashed, speaker keys as labels and no speaker mapping (readTranscriptDetail refuses trashed transcripts); its display name is built from its own name and date, without the Event. (6) The expansion no longer returns null for a range past the end (clamped, empty segments) and the details shape changed from {segments, speakers} to {transcriptId, startsAt, endsAt, from, to, speakers, segments with index, label, isContext}; the history label of a ref is now 'Name m:ss-m:ss'. (7) History label resolution reads the detail composition once per segment ref (no batching).

The worker's deviations 4 (one statement per ref in validation) and 7 (label resolution reads the detail composition once per ref) are superseded by the review fix: both are batched now.
