## Specification

The record is `issues/items/gh-1956.md`. Worker summary: a module tool may declare `mcp: { humanHandlerExport }`; a run credential sees such a tool when its run's project holds the module capability, a human `/mcp` session sees it when its module is active and runs it as the session's user; `mail.thread.get`, `mail.draft.create`, `mail.draft.update` and `mail.draft.send` declare it, `mail.thread.proposeTask` does not. The human send calls `sendMailDraft` without an approval request; a run credential's send still files the request (source `mcp`). After review the credential's own list became an upper bound for module tools: the mint accepts the capability ids of the active modules. New ADR `2026-11-14-mail-tools-over-mcp-run-as-their-run-or-as-the-session-user`.
