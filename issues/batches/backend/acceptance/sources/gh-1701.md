Observations of the security reviewer, recorded without a finding and not changed:

- The lockout read and the failed-attempt write are separate auto-committed statements, so parallel requests of one session can each read a streak below the threshold and each reach `verifyPassword`. The Task prescribes this sequence and `deleteOwnAccount` has it. The reviewer did not measure the achievable burst and names a follow-up issue over the three re-authentication paths as the place for it. No such issue was filed.
- A `login` that verified the old password before the change commits and enters its transaction afterwards still creates a session that survives the change. The gap is in `login`, predates this source and exists equally against `resetPassword`.
- Marking the reset tokens before the user row is locked is neutral for security. This observation was made on the implementation commit; finding 2 later changed the marking.
- `changePassword` did not re-check the tenant status or the calling session under the lock. The tenant status is now re-read (finding 1). A revocation of the calling session alone, in flight, is still not re-checked; the reviewer states that no access is gained.

Deviations the worker and the fixer declared: the route entry is in the slice module `routeMatrix/auth.ts`; the tokens are marked before the user-row lock and again under it, where Task step 3 lists the marking last; the tenant status is re-read in the transaction; `consumeAllPasswordResetTokensForUser` returns the number of tokens it marked and a second store function exists; an empty-string password field answers 400 `validation_failed`; the docstring of `ReauthenticationFailedError` in `tenancy/deleteAccount.ts`, a file outside `Touches`, was extended; the isolation case authenticates a member of a third tenant; a change that overlaps a reset or another change of the same user can answer 403 although the password was right. The requirements reviewer accepted those present at the implementation commit. No decision record `issues/decisions/gh-1701.md` exists.
