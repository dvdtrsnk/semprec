## Specification

The record is `issues/items/gh-1906.md`. Worker summary: Added the inbox.proposal.revise module agent tool (strict args { proposalId, entityKind?, target?, properties, message? }; approval none, riskClass write, no capability) next to inbox.proposal.get. It resolves the thread, actor and running assistant message from the persisted run, answers any card that is not the thread's own like a missing one (also for another tenant's card or run, a chat thread run, a run without a thread, a tenant without the Processing proposals database), refuses NUL characters, revises through reviseProposalWithClient (new sixth parameter revisedBy, default user, so the route is unchanged) writing { author: ai, kind: threadRevision, threadId, messageId, message }, publishes the inboxCards invalidation after the commit and answers { proposalId, revised: true }. A locked card or an invalid envelope gives an error result and writes nothing. The own-card edge is read FOR SHARE in the write's transaction after the card is locked. The outdated manifest comment is corrected; i18n labels en/cs; public surface updated. gh-1938 later moved the tool's call to reviseProposalFromThreadWithClient (second segment).

(7) The step mapping of the reply (gh-1885 revised kind) is not added, as the Task says; the result is JSON { proposalId, revised: true }. (8) The reset entry for dropped manual values keeps author user.

(9) Added in the fix round: the required argument `ifVersion` and the `version` in the tool's answer extend the Task's argument list; they answer a gh-1938 review finding on a data-loss race.
