## Specification

The record is `issues/items/gh-1875.md`. Worker summary: Migration 0164_databases_purge_at.sql (nullable purge_at, partial index). DatabaseRow.purgeAt; archiveDatabase stamps purge_at = now() + RETENTION_DAYS*24 h, restoreDatabase clears it. New trash/purgeArchivedDatabases.ts: purgeExpiredArchivedDatabases(pool, storage, alternateStorage?) assigns missing deadlines (system databases excluded), selects expired archived user databases, and per database purges in separate transactions: chunks of at most 500 items (inline databases owned by the chunk's items first, depth first, with a cycle guard) through hardDeleteItemsOfDatabase + deleteItemDependents + item purge hooks, blob bytes removed after each commit best-effort from both storage roots; last transaction removes dependent rollup properties and the paired relation properties of other databases (bypassing the schema lock, documented), dropDatabaseWithPartition, schema invalidations after commit. Every transaction takes FOR NO KEY UPDATE on the expired archived root and stops when a restore committed first. Wired into handleItemTrashPurgeSweepTask after purgeExpiredTrash per tenant; a failure of one stage or database is logged with tenant/database ids and error class, does not skip the rest, and fails the task at the end. GET /api/trash/databases returns the stored purgeAt and daysLeft (calendar days in the tenant zone, floor 0). ADR docs/adr/2026-11-13-archived-databases-are-purged-after-the-trash-retention-period.md.

## Deviations

(1) RETENTION_DAYS moved into the new root-level module backend/packages/data/src/trashRetention.ts and re-exported from trash/purgeExpiredTrash.ts (public surface unchanged): the dependency rule chokepoint-knows-no-domain forbids databasesStore.ts importing trash/. (2) The deadline is now() + RETENTION_DAYS * 24 hours (make_interval hours), the same 24-hour days as an item's purgeAt, so it does not move with daylight saving; the Task says 'days'. (3) purgeExpiredArchivedDatabases takes an optional third argument alternateStorage, like purgeExpiredTrash, so blob bytes are removed from both storage roots as docs/adr/2026-11-01-trash-purge-coordinates-roots-and-transactions.md requires. (4) Item purge hooks (runItemPurgeHooks) run for each deleted item with the item as its own rootItemId, beyond the Task's deleteItemDependents, because the library cover-candidate hook applies to items of any database. (5) New store functions live in the owning stores: databasesStore (assignMissingPurgeDeadlines, listExpiredArchivedDatabaseIds, lockExpiredArchivedDatabase, listInlineDatabaseIds), itemsStore (listItemIdsForPurge, hardDeleteItemsOfDatabase), propertiesStore (deletePropertiesOfPurgedDatabase, no schema-lock check, documented), relationsStore (listPairedPropertiesOfOtherDatabases), and a new rollup/purgeDependencies.ts (not in dependencies.ts, whose exports are re-exported whole from the package index). (6) The REST envelope toDatabaseEnvelope now takes Omit<DatabaseRow, 'purgeAt'> in services/semprec-api/src/adapter/databaseEnvelope.ts, since the shared generic-operations Database type has no purgeAt; the envelope is unchanged. (7) Two test fixtures that build a DatabaseRow literal gained purgeAt: null. (8) The write-safety baseline .github/scripts/write-safety-baseline.json got 4 hand-edited fingerprints (two replaced for the changed archive/restore UPDATE texts, two new for the bulk DELETEs where zero rows is valid). (9) No rollup-of-rollup closure: validateRollupConfig forbids a rollup that targets a rollup or relation. (10) The purge does not take the tenant advisory lock of purgeExpiredTrashSubtree and does not queue a search reindex of other databases; the ADR states both. (11) After the deadline a restore between two chunks is not protected (the ADR records it as accepted). (12) The migration ordinal is 0164, the next free ordinal on this branch.
