## Specification

The record is `issues/items/gh-1813.md`. No decision record exists for this source. Worker summary: `transcriptEventMatch.ts` now applies strict interval overlap in the tenant zone. For each live Event of type `standup` or `meeting` with `date` and `timeFrom` the interval is `[date + timeFrom, (endDate ?? date) + timeTo]`, converted with the existing calendar clock (`getCalendarClock`, `wallClockToInstant`, DST handled by `calendarTime.ts`). An Event without `timeTo` is a point at its start; all-day Events, type `event`, a `24:00` start, an end before the start and values `wallClockToInstant` refuses are skipped. Candidates are ordered by interval start, then id (`listOverlappingEventIds`, module-level export, not in the barrel). The old lead window, `DATE_ONLY_RE` and the Event use of `parseDateWithTime` are removed. Outcomes and idempotency are unchanged; the create-Event envelope date is the recording's date in the tenant zone as `YYYY-MM-DD`; the card history line and the JSDoc describe overlap.

Deviations and spec seams declared by the worker (full list in the handover): (1) `listOverlappingEventIds` is exported from the module for direct tests; (2) the strict rule is applied uniformly, so an Event without `timeTo` that starts exactly at the recording start or end is not a candidate; (3) an Event whose end is before its start, or whose `timeFrom` is 24:00, is skipped as unparsable; (4) the tenant zone is read once for every non-converged match, so an invalid zone raises `ValidationError` before any write on the linked and suggested paths; (5) Events with an instant `date` (before #1598) are no longer matched; (6) the dead `1 Event` arm of the history message was dropped; (7) `transcriptProposalActions.test.ts` was touched outside Touches (its envelope helper follows the date-only envelope); (8) `transcriptionTask.ts` changed only in one comment; no calendar time module change was needed.
