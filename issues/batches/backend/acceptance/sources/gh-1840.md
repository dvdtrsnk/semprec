## Specification

The record is `issues/items/gh-1840.md`. Worker summary: added the `sleepNightsGet` and `sleepNightSet` module agent tools (`sleep/sleepAgentTools.ts`) with the capabilities `sleep.read` and `sleep.write` declared in the sleep manifest. `upsertSleepNight(client, {night, fields}, writeOptions)` was extracted from `sleepNightPut`. Both tools take project and user from the stored run, check the project's database grants in the transaction of the call and answer a JSON error result for any `ChokePointError` (403, 400, 404). `sleepNightSet` writes as `writerKind` agent with the run id, runs without approval and enqueues `sleep-resync:<tenantId>` through the gh-1838 hooks.

Deviations declared by the worker: (1) handler exports are `createSleepNightsGetTool` / `createSleepNightSetTool` because `sleepNightsGet` is already the GET route factory; (2) capability presence follows the interim predicate of `docs/adr/2026-11-04-owned-databases-admit-safe-module-agent-tools.md`; (3) `sleepNightSet` checks write on nights and read on settings and plans itself, so a call that changes nothing is refused too; (4) success results are marked sensitive, arguments stay stored as written until #2001; (5) `parseNightPutBody` and `SleepNightFields` are exported, strict schemas check types only; (6) the error result shape follows the transcript tools; (7) the session-level test stores grants with the statement of `setAgentDatabaseGrant`; (8) the manifest unit test assertion that the sleep module has no agent tools was replaced.
