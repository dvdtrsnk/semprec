## Deviations

Spec seams: (1) route entry is in a new slice routeMatrix/projectHeartbeats.ts (no slice fits a /api/projects/:id/heartbeats path), appended in routeMatrix.ts. (2) Pure rule-label formatting is in a sibling new module scheduler/heartbeatRuleLabel.ts (not in Touches) so it is unit-testable. (3) Response is { rows: [...] } like its sibling /api/projects/:id/database-grants; the Task did not state the list envelope. (4) Timezone: rules store a wall-clock time that computeNextFireAt reads in the system timezone, so ruleLabel states it unchanged; no instant is converted and the label text cannot differ by zone. Czech weekday range renders 'Po-Pá v 8:30' (accented, correct Czech) where the Task writes 'Po-pa v 8:30'. (5) 'Latest occurrence' is read as the latest occurrence (by scheduled_for) whose latest run (highest attempt) is not running; occurrences without a run or with a running run are passed over, and lastOccurrence is null when none qualifies; the Task only allows ok/waiting_approval/failed. (6) Rule label for kinds not in the Task: dailyTime, everyNDays (n=1 reads as daily), interval, onItemEvent per event and a 'custom schedule' fallback for unparseable/module kinds, all with new keys heartbeat.rule.* / heartbeat.weekday.* in seed/i18n cs and en.
