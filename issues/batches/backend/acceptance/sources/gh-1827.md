## Specification

The record is `issues/items/gh-1827.md`. Worker summary: content-bearing generic operations (item.get/create/patch/delete/restore, database.query, view.query) mark their successful tool result as sensitive when a database of the answer or the queried database has sensitive = true (flag read through the choke point after the call, in the caller's tenant scope; an unknown database or a failed lookup counts as sensitive, the latter logged with operation, run id and error class only). The composition root carries the mark in the pi result details. runAgentTurn stores a marked tool_result as `[redacted: sensitive]` without the mark and with only the changed keys of details.changes; onEvent and the live stream see the real result. Reconstruction needed no change. After review the mark also covers relation targets expanded through include.relations (and projected relation properties), and an ADR records the mechanism.

Deviations and spec seams declared by the worker: (1) `agentSessionComposition.ts` and the tests in `agentSessionComposition.unit.test.ts`, `piConversationHistory.unit.test.ts`, `agentRun.e2e.test.ts` are outside Touches; (2) the redaction lives in the new `sensitiveToolResult.ts`, not exported from the package index; (3) `conversationReconstruction.ts` is unchanged; (4) `details.changes` of a marked item.patch keep only their keys; (5) the sensitivity lookup is a separate read after the operation answered, sound while the flag is never turned off; (6) originally relation targets inside a non-sensitive item were not examined, later fixed (finding 1); (7) originally no ADR, later added (finding 3); (8) the commit trailer is the one the task text names.
