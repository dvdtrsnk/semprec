## Specification

The record is `issues/items/gh-1851.md`. Worker summary: Added GET /api/trash/items (createTrashItemsRouteHandler) as a schemaCore custom route with justification single-consumer-read. It lists the trashed cascade roots of the tenant (an item in an inline database whose owner has the same deleted_at is not a row; items of archived databases are not listed), newest first, with keyset paging over (deleted_at, id) at microsecond precision, totalCount over all roots from one REPEATABLE READ snapshot, databaseKey, ownerModuleId, databaseName (stored name for a user database, catalog name in the user's locale for a system database, catalogs loaded lazily once per process and not cached on failure), purgeAt and daysLeft in the tenant's zone. The retention became the exported RETENTION_DAYS shared by the sweep and the list. Migration 0154 adds the partial index items_deleted_at_idx.

Deviations declared by the worker: Seams: (1) the retention constant already existed as the exported TRASH_RETENTION_DAYS (not a local DEFAULT_RETENTION_DAYS) and is used by mcp/approvalDescription.ts; it was renamed to RETENTION_DAYS as the Task says and the import in approvalDescription.ts was updated (one extra file). (2) The route matrix entry lives in a new slice module backend/services/semprec-api/src/routeMatrix/trash.ts (TRASH_ROUTES) appended in routeMatrix.ts, because no slice fits /api/trash. (3) publicSurface.test.ts expected export list gained RETENTION_DAYS in sort order. (4) Beyond the Task's test file a second test file trashRouteHandlersCatalogLoading.test.ts covers the lazy catalog load and the not-cached-on-failure branch, which needs its own module-level mock. Notes: item has the six fields the Task lists (no createdAt). purgeAt is deletedAt plus RETENTION_DAYS times 24 h like the sweep's cutoff, while daysLeft counts calendar days in the tenant zone from the deletion day. The query plan with the new index was not measured (no EXPLAIN run). The pre-existing cascade-epoch comparison is by deleted_at equality, the same limit documented in itemTrash.ts.
